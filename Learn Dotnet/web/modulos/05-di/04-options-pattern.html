Options Pattern: IOptions<T>

Módulo 5 · Inyección de Dependencias30 min

1 · Introducción

Las aplicaciones .NET necesitan configuración. Leer IConfiguration directamente en cada servicio es frágil y difícil de tipar. El Options Pattern encapsula la configuración en objetos fuertemente tipados y la inyecta como dependencia.

  • Qué vamos a aprender: IOptions<T>, IOptionsSnapshot<T>, IOptionsMonitor<T>, opciones con nombre, validación, PostConfigure y ValidateOnStart.
  • Problema que resuelve: evitar mágic strings de configuración, centralizar la validación y permitir cambiar valores sin modificar servicios.
  • Cuándo se utiliza: siempre que un servicio necesite parámetros de configuración (URLs, timeouts, credenciales, flags de features).
Errores típicos: leer IConfiguration["Clave:Subclave"] en cada método, no validar la configuración, usar IOptionsMonitor cuando no se necesita recarga en caliente, o confundir IOptions con IOptionsSnapshot.

2 · Teoría

2.1. ¿Por qué no usar IConfiguration directamente?

IConfiguration devuelve strings. No hay IntelliSense, no hay validación en tiempo de compilación y los valores se reparten por todo el código. El Options Pattern convierte la configuración en un POCO fuertemente tipado.

2.2. Las tres interfaces

InterfazCarga configuraciónCambia en runtimeUso típico
IOptions<T>Una vez al inicioNoConfiguración estática, Singletons
IOptionsSnapshot<T>Una vez por scopeSí, entre scopesConfiguración por request
IOptionsMonitor<T>En cada accesoSí, con notificadoresConfiguración que cambia en caliente

2.3. Named options

Permiten registrar varias configuraciones del mismo tipo. Útil cuando un servicio necesita múltiples endpoints, conexiones o políticas con la misma estructura.

2.4. Validación

.NET ofrece tres niveles de validación:

  • Data Annotations: decorar la clase con [Required], [Range], [StringLength], etc.
  • Validate: reglas programáticas con builder.Services.AddOptions<T>().Validate(...).
  • FluentValidation: integrar con librerías externas para reglas complejas.

2.5. PostConfigure

Permite modificar las opciones después de que se carguen desde configuración. Útil para derivar valores, ajustar URLs o completar propiedades calculadas.

2.6. ValidateOnStart

Con ValidateOnStart, la configuración se valida al arrancar la aplicación. Si es inválida, el proceso falla rápido en lugar de descubrir el problema en medio de un request.

3 · Ejemplo mínimo

Configuración simple para una API externa.

// appsettings.json
{
  "ExternalApi": {
    "BaseUrl": "https://api.example.com",
    "TimeoutSeconds": 30,
    "ApiKey": "mi-api-key-secreta"
  }
}
// ExternalApiOptions.cs
public class ExternalApiOptions
{
    public const string SectionName = "ExternalApi";

    public string BaseUrl { get; set; } = string.Empty;
    public int TimeoutSeconds { get; set; } = 10;
    public string ApiKey { get; set; } = string.Empty;
}

// Program.cs
var builder = WebApplication.CreateBuilder(args);

builder.Services.Configure<ExternalApiOptions>(
    builder.Configuration.GetSection(ExternalApiOptions.SectionName));

builder.Services.AddSingleton<ExternalApiClient>();

var app = builder.Build();

app.MapGet("/status", (ExternalApiClient client) => client.GetStatus());
app.Run();

// ExternalApiClient.cs
public class ExternalApiClient
{
    private readonly ExternalApiOptions _options;

    public ExternalApiClient(IOptions<ExternalApiOptions> options)
    {
        _options = options.Value;
    }

    public string GetStatus()
    {
        return $"Conectado a {_options.BaseUrl} con timeout de {_options.TimeoutSeconds}s";
    }
}

4 · Ejemplo real

En un CMS profesional, la configuración de JWT, caché y rate limiting se tipa, valida y se expone con named options.

// JwtOptions.cs
public class JwtOptions
{
    public const string SectionName = "Jwt";

    [Required]
    public string Issuer { get; set; } = string.Empty;

    [Required]
    public string Audience { get; set; } = string.Empty;

    [Required]
    [MinLength(32)]
    public string SecretKey { get; set; } = string.Empty;

    [Range(1, 1440)]
    public int ExpirationMinutes { get; set; } = 60;
}

// CacheOptions.cs
public class CacheOptions
{
    public const string SectionName = "Cache";
    public string Provider { get; set; } = "Memory";
    public int DefaultExpirationMinutes { get; set; } = 5;
}

// Program.cs
var builder = WebApplication.CreateBuilder(args);

builder.Services.AddOptions<JwtOptions>()
    .Bind(builder.Configuration.GetSection(JwtOptions.SectionName))
    .ValidateDataAnnotations()
    .ValidateOnStart();

builder.Services.AddOptions<CacheOptions>()
    .Bind(builder.Configuration.GetSection(CacheOptions.SectionName))
    .ValidateDataAnnotations()
    .PostConfigure(options =>
    {
        if (options.DefaultExpirationMinutes < 1)
        {
            options.DefaultExpirationMinutes = 1;
        }
    });

// Named options: dos endpoints de envío de email
builder.Services.Configure<EmailOptions>("Transactional", builder.Configuration.GetSection("Email:Transactional"));
builder.Services.Configure<EmailOptions>("Marketing", builder.Configuration.GetSection("Email:Marketing"));

builder.Services.AddScoped<EmailService>();

var app = builder.Build();

app.MapGet("/send", (EmailService service) => service.Send());
app.Run();

// EmailService.cs
public class EmailService
{
    private readonly EmailOptions _transactional;
    private readonly EmailOptions _marketing;

    public EmailService(
        IOptionsSnapshot<EmailOptions> transactional,
        IOptionsSnapshot<EmailOptions> marketing)
    {
        _transactional = transactional.Get("Transactional");
        _marketing = marketing.Get("Marketing");
    }

    public string Send()
    {
        return $"Transactional: {_transactional.FromAddress}, Marketing: {_marketing.FromAddress}";
    }
}

public class EmailOptions
{
    [Required]
    [EmailAddress]
    public string FromAddress { get; set; } = string.Empty;

    public string SmtpServer { get; set; } = string.Empty;
    public int Port { get; set; } = 587;
}
Decisión: usa IOptions<T> para configuración inmutable usada por Singletons; IOptionsSnapshot<T> para valores que pueden cambiar entre requests; IOptionsMonitor<T> para reaccionar a cambios en caliente con OnChange.

6 · Errores habituales

Error 1: Leer IConfiguration directamente

// INCORRECTO: strings dispersos, sin validación, sin IntelliSense
public class EmailService
{
    public EmailService(IConfiguration configuration)
    {
        _smtpServer = configuration["Email:SmtpServer"]!;
        _port = int.Parse(configuration["Email:Port"]!);
    }
}

// CORRECTO: POCO fuertemente tipado e inyectado
public class EmailService(IOptions<EmailOptions> options)
{
    private readonly EmailOptions _options = options.Value;
}

Error 2: No validar la configuración

// INCORRECTO: la aplicación arranca con valores vacíos y falla en runtime
builder.Services.Configure<JwtOptions>(
    builder.Configuration.GetSection(JwtOptions.SectionName));

// CORRECTO: valida al inicio
builder.Services.AddOptions<JwtOptions>()
    .Bind(builder.Configuration.GetSection(JwtOptions.SectionName))
    .ValidateDataAnnotations()
    .ValidateOnStart();

Error 3: Usar IOptionsMonitor en cada servicio

// INCORRECTO: overhead innecesario si la configuración no cambia en caliente
public class EmailService(IOptionsMonitor<EmailOptions> options) { ... }

// CORRECTO: usa IOptions si no necesitas recarga dinámica
public class EmailService(IOptions<EmailOptions> options) { ... }

Error 4: No usar ValidateOnStart con IOptions

// INCORRECTO: la validación solo ocurre al resolver el servicio
builder.Services.AddOptions<JwtOptions>()
    .Bind(configuration.GetSection(JwtOptions.SectionName))
    .ValidateDataAnnotations();

// CORRECTO: fuerza validación al arrancar
builder.Services.AddOptions<JwtOptions>()
    .Bind(configuration.GetSection(JwtOptions.SectionName))
    .ValidateDataAnnotations()
    .ValidateOnStart();

7 · Ejercicio guiado

Crea una API minimal que exponga configuración de conexión a base de datos.

  1. Crea una clase DatabaseOptions con ConnectionString, CommandTimeoutSeconds y RetryCount.
  2. Añade la sección a appsettings.json.
  3. Registra las opciones con validación de Data Annotations y ValidateOnStart.
  4. Crea un endpoint /db/config que devuelva la configuración.
  5. Prueba qué ocurre si eliminas la connection string del archivo.
// DatabaseOptions.cs
public class DatabaseOptions
{
    public const string SectionName = "Database";

    [Required]
    public string ConnectionString { get; set; } = string.Empty;

    [Range(1, 300)]
    public int CommandTimeoutSeconds { get; set; } = 30;

    [Range(0, 10)]
    public int RetryCount { get; set; } = 3;
}

// Program.cs
var builder = WebApplication.CreateBuilder(args);

builder.Services.AddOptions<DatabaseOptions>()
    .Bind(builder.Configuration.GetSection(DatabaseOptions.SectionName))
    .ValidateDataAnnotations()
    .ValidateOnStart();

var app = builder.Build();

app.MapGet("/db/config", (IOptions<DatabaseOptions> options) =>
{
    return Results.Ok(options.Value);
});

app.Run();

Reto: Sistema de notificaciones con named options

Implementa un servicio que pueda enviar notificaciones por diferentes canales según named options:

  • Crea NotificationOptions con Enabled, Endpoint y ApiKey.
  • Registra tres named options: Sms, Email y Push.

9 · Resumen

  • El Options Pattern convierte configuración en POCOs fuertemente tipados.
  • IOptions<T> es para configuración inmutable; IOptionsSnapshot<T> para valores por scope; IOptionsMonitor<T> para recarga en caliente.
  • Usa builder.Services.Configure<T>() o AddOptions<T>().Bind() para registrar las opciones.
  • Valida la configuración con Data Annotations, Validate o ValidateOnStart.
  • Usa PostConfigure para ajustar valores después de la carga.
  • Las named options permiten múltiples configuraciones del mismo tipo.
  • Evita leer IConfiguration directamente en la lógica de negocio.

10 · Preguntas frecuentes

¿Cuál es la diferencia entre IOptions y IOptionsSnapshot?

IOptions<T> carga la configuración una vez al inicio y no cambia durante la vida de la aplicación. IOptionsSnapshot<T> recarga la configuración cada vez que se crea un nuevo scope, típicamente en cada request HTTP.

¿Cuándo usar IOptionsMonitor?

Cuando necesitas detectar cambios de configuración en caliente. Expose el método OnChange para suscribirte a eventos. Ten cuidado con la gestión de suscripciones para evitar fugas de memoria.

¿IOptions<T>.Value es un Singleton?

El objeto IOptions<T> suele ser Singleton y Value se calcula una vez. Sin embargo, el POCO de opciones puede inyectarse también directamente, aunque no es recomendable perder la abstracción.

¿Puedo usar Options Pattern sin ASP.NET Core?

Sí. Microsoft.Extensions.Options es un paquete independiente. Puedes crear un ServiceCollection, configurar opciones, construir un ServiceProvider y resolver IOptions<T> en cualquier aplicación .NET.

¿Qué pasa si la validación falla con ValidateOnStart?

La aplicación lanza OptionsValidationException durante la fase de inicio, antes de aceptar requests. Esto permite detectar errores de configuración de forma temprana y segura.
