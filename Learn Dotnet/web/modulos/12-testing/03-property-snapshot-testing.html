Property-Based y Snapshot Testing

Módulo 12 · Testing35 min

1 · Introducción

Hasta ahora hemos escrito tests con datos concretos: 2 + 3 = 5, email válido, etc. Pero eso solo prueba puntos aislados. ¿Y si existen valores que no hemos considerado?

En esta lección veremos dos técnicas complementarias:

  • Property-Based Testing: generamos cientos de entradas aleatorias y verificamos que ciertas propiedades siempre se cumplen.
  • Snapshot Testing: capturamos la salida completa de una operación y la comparamos con una versión aprobada previamente.
¿Para qué sirven? Property-based testing encuentra esquinas inesperadas. Snapshot testing detecta cambios accidentales en respuestas complejas, reportes o contratos.

Usaremos FsCheck para .NET en el primer caso y Verify en el segundo.

2 · Teoría

2.1 Property-Based Testing con FsCheck

En lugar de escribir un ejemplo concreto, describes una propiedad matemática o de dominio que siempre debe cumplirse. FsCheck genera automáticamente valores, ejecuta el test y, si falla, encoge el caso hasta encontrar la entrada mínima que reproduce el error.

Ejemplos de propiedades:

  • La suma es conmutativa: a + b == b + a.
  • Reversing una lista dos veces devuelve la lista original: Reverse(Reverse(list)) == list.
  • Serializar y deserializar un objeto devuelve el mismo valor: roundtrip(x) == x.

FsCheck se integra con xUnit a través de [Property]. El método devuelve una propiedad o simplemente un bool.

2.2 Generadores y shrinkers

FsCheck incluye generadores para tipos primitivos, colecciones, strings, etc. También puedes crear generadores personalizados con Gen y Arb. El shrinker reduce el valor de fallo para facilitar el diagnóstico.

2.3 Snapshot Testing con Verify

Verify serializa un objeto a texto (JSON, XML, etc.) y lo guarda en un archivo .verified. En la siguiente ejecución compara el resultado con el archivo aprobado. Si hay diferencias, genera un archivo .received y el test falla. El desarrollador revisa y renombra .received a .verified si el cambio es intencional.

2.4 ¿Cuándo usar cada uno?

TécnicaCuándoEjemplo
Property-BasedReglas universales, invariantes, algoritmosordenar, sumar, serializar, hash
SnapshotSalidas grandes que evolucionan lentamenterespuestas API, reportes, mensajes
Unitario clásicoComportamientos específicos de negociocrear un post, aplicar descuento

3 · Ejemplo mínimo

Crea un proyecto de test con FsCheck:

dotnet new xunit -n PropertyTests -o PropertyMini/tests/PropertyTests
dotnet add PropertyMini/tests/PropertyTests package FsCheck.Xunit

Test de propiedad:

using FsCheck.Xunit;
using FluentAssertions;
using Xunit;

namespace PropertyTests;

public class MathProperties
{
    [Property]
    public void Addition_IsCommutative(int a, int b)
    {
        // La propiedad: a + b debe ser igual a b + a para cualquier par de enteros
        (a + b).Should().Be(b + a);
    }

    [Property]
    public void ReversingTwice_ReturnsOriginal(int[] values)
    {
        // FsCheck generará arrays con longitud y contenido variado
        var reversed = values.Reverse().ToArray();
        var reversedAgain = reversed.Reverse().ToArray();

        reversedAgain.Should().Equal(values);
    }
}

Ejecuta:

dotnet test PropertyMini/tests/PropertyTests
Tip: por defecto FsCheck genera 100 casos. Si quieres más, puedes configurar el número de iteraciones con [Property(MaxTest = 1000)].

4 · Ejemplo real

4.1 Property-based: roundtrip de JSON

Validamos que serializar y deserializar un objeto de dominio nunca pierde datos.

using FsCheck;
using FsCheck.Xunit;
using System.Text.Json;
using FluentAssertions;

namespace Cms.Tests;

public class JsonRoundtripTests
{
    private static readonly JsonSerializerOptions Options = new(JsonSerializerDefaults.Web);

    [Property]
    public void PostDto_Roundtrip_PreservesData(string title, string content, Guid authorId)
    {
        // FsCheck generará strings, incluidos vacíos, Unicode, nulos, etc.
        var original = new PostDto(title, content, authorId);
        var json = JsonSerializer.Serialize(original, Options);
        var roundtrip = JsonSerializer.Deserialize<PostDto>(json, Options);

        roundtrip.Should().BeEquivalentTo(original);
    }

    public record PostDto(string Title, string Content, Guid AuthorId);
}

Este test detectaría problemas como propiedades no serializables, naming incorrecto o ciclos de referencia.

4.2 Snapshot: respuesta de API

dotnet add Cms.Api.Tests package Verify.Xunit
dotnet add Cms.Api.Tests package Verify
using VerifyTests;
using VerifyXunit;
using Xunit;

namespace Cms.Api.Tests.Posts;

[UsesVerify]
public class PostResponseSnapshotTests
{
    private readonly PostResponse _response = new(
        Id: Guid.Parse("11111111-1111-1111-1111-111111111111"),
        Title: "Post de ejemplo",
        Content: "Contenido",
        AuthorId: Guid.Parse("22222222-2222-2222-2222-222222222222"),
        CreatedAt: DateTimeOffset.Parse("2026-07-29T10:00:00Z"));

    [Fact]
    public Task PostResponse_MatchesApprovedSnapshot()
    {
        return Verify(_response);
    }

    public record PostResponse(
        Guid Id,
        string Title,
        string Content,
        Guid AuthorId,
        DateTimeOffset CreatedAt);
}

La primera ejecución genera PostResponseSnapshotTests.PostResponse_MatchesApprovedSnapshot.verified.json. Si en el futuro la estructura cambia, el test fallará y generará un archivo .received.json. Revisas las diferencias y, si son correctas, renombras el archivo recibido.

Cuidado: nunca aprobar snapshots automáticamente en CI. El flujo de aprobación debe ser manual y consciente.

5 · Buenas prácticas

  • Property-based: escribe propiedades claras e independientes del valor exacto. Ejemplo: “el resultado de ordenar debe estar ordenado”.
  • Property-based: usa generadores personalizados para datos de dominio (emails, DNI, etc.) y evita valores absurdos que no tienen sentido en tu contexto.
  • Snapshot: estabiliza datos no deterministas (GUIDs, fechas, hashes) usando valores fijos o ignorando campos con Scrubbers.
  • Snapshot: almacena los archivos .verified en el control de versiones.
  • Snapshot: no uses snapshots para lógica numérica; usa aserciones concretas.
  • Combinar ambos: usa property-based para invariantes y snapshot para contratos grandes. Son complementarios, no excluyentes.
  • CI: los tests de snapshot deben ejecutarse en CI para detectar regresiones, pero los archivos recibidos deben ignorarse en .gitignore.

6 · Errores habituales

6.1 Propiedad sin verdadero valor universal

// ❌ Mal: solo reescribe el ejemplo concreto con datos aleatorios
[Property]
public void Discount20Percent_Returns80(int amount) =>
    amount * 0.8m.Should().Be(80); // falla para casi todos los valores
// ✅ Bien: propiedad general
[Property]
public void Discount20Percent_ReducesBy20Percent(decimal amount)
{
    if (amount < 0) return; // precondición
    var result = DiscountService.Apply(amount, 0.20m);
    result.Should().Be(amount * 0.80m);
}

6.2 Snapshot con datos cambiantes

// ❌ Mal: el snapshot contendrá una fecha distinta cada día
return Verify(new ReportResponse(DateTimeOffset.UtcNow));
// ✅ Bien: fija o reemplaza valores no deterministas
return Verify(new ReportResponse(DateTimeOffset.Parse("2026-07-29T10:00:00Z")))
    .ScrubMember("createdAt");

6.3 Aprobar snapshots sin revisar

# ❌ Mal: copiar automáticamente .received a .verified
find . -name "*.received.*" -exec rename 's/.received/.verified/' {} \;
# ✅ Bien: revisar diff manualmente y aprobar conscientemente
git diff *.verified.json

6.4 Depender solo de property-based para todo

// ❌ Mal: intentar probar una regla de negocio matizada con datos aleatorios
[Property]
public void TaxCalculator_IsCorrect(...) // demasiado abstracto
// ✅ Bien: usar tests concretos para reglas de negocio y property-based para invariantes
[Theory]
[InlineData("ES", 100, 21)]   // regla concreta
public void CalculateVat_ForSpain_Returns21Percent(...) { ... }

[Property]
public void Roundtrip_PreservesData(...) { ... }

7 · Ejercicio guiado

Vamos a escribir una propiedad para un servicio de ordenación.

Paso 1: servicio

namespace Ordering;

public static class Sorter
{
    public static List<T> Sort<T>(List<T> items) where T : IComparable<T> =>
        items.OrderBy(x => x).ToList();
}

Paso 2: tests de propiedad

using FsCheck.Xunit;
using FluentAssertions;
using Ordering;

namespace Ordering.Tests;

public class SorterProperties
{
    [Property]
    public void Sort_PreservesLength(List<int> values)
    {
        var sorted = Sorter.Sort(values);
        sorted.Should().HaveCount(values.Count);
    }

    [Property]
    public void Sort_IsAscending(List<int> values)
    {
        var sorted = Sorter.Sort(values);
        for (int i = 0; i < sorted.Count - 1; i++)
        {
            sorted[i].Should().BeLessOrEqualTo(sorted[i + 1]);
        }
    }

    [Property]
    public void Sort_Idempotent(List<int> values)
    {
        var sorted = Sorter.Sort(values);
        var sortedTwice = Sorter.Sort(sorted);
        sortedTwice.Should().Equal(sorted);
    }
}

Paso 3: ejecuta

dotnet test Ordering.Tests

Añade un test snapshot para una respuesta que contenga una lista ordenada. Fija los GUIDs y fechas.

9 · Resumen

  • Property-based testing con FsCheck genera datos aleatorios y comprueba propiedades universales.
  • Sirve para invariantes: conmutatividad, idempotencia, roundtrip, orden.
  • Snapshot testing con Verify captura la salida completa y la compara con una versión aprobada.
  • Úsalo para respuestas API, reportes y mensajes complejos.
  • Combina ambos: property-based para lógica, snapshot para contratos estables.

10 · Preguntas frecuentes

¿Los tests property-based son realmente aleatorios?

Sí, pero FsCheck usa una semilla determinista por defecto, lo que permite reproducir un fallo. Si encuentras un caso, puedes ejecutarlo de nuevo con la misma semilla.

¿Qué pasa si FsCheck genera un valor que no es válido para mi dominio?

Puedes filtrar casos con Prop.ForAll y .When, o mejor aún, crear un generador personalizado que solo produzca valores válidos.

¿Los archivos snapshot deben subirse a git?

Sí, los .verified deben estar en el repositorio. Los .received deben estar en .gitignore.

¿Puedo usar Verify con XML, texto o imágenes?

Sí, Verify soporta múltiples serializadores. Por defecto usa JSON, pero puedes configurar otros formatos.

¿Reemplazan estos tests a los unitarios?

No. Cada técnica cubre un riesgo distinto. Los unitarios verifican comportamientos concretos; property-based, invariantes; snapshot, cambios en salidas complejas.

¿Cómo ignoro campos en snapshot?

Usa Verify(obj).ScrubMember("NombrePropiedad") o IgnoreMember para excluir miembros no deterministas.
