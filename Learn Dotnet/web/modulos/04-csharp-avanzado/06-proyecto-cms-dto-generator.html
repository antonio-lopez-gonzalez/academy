Proyecto CMS: Source Generator de DTOs

Módulo 4 · C# Avanzado50 min

1 · Introducción

En esta lección del proyecto CMS creamos un Source Generator que genera automáticamente DTOs (Data Transfer Objects) a partir de las entidades de dominio Post, Category y User. Aprenderemos a integrar el generador en la arquitectura limpia del CMS y a usarlo desde la capa de aplicación.

¿Por qué generamos DTOs? Porque en un CMS profesional las entidades de dominio contienen lógica de negocio, navegación y datos internos que no deben exponerse directamente en la API. Los DTOs aplanan, transforman y protegen los datos. Generarlos automáticamente reduce el boilerplate y garantiza que los contratos de la API se mantengan sincronizados con el dominio.

¿Qué DTOs generaremos? Por cada entidad marcada con [GenerateDto] produciremos:

  • Un DTO de lectura (PostDto).
  • Un DTO de creación (CreatePostDto).
  • Un DTO de actualización (UpdatePostDto).

Errores típicos: exponer entidades de dominio directamente, generar DTOs con tipos incorrectos, no actualizar el generador cuando cambian las entidades, olvidar la referencia como analyzer.

2 · Teoría

2.1. Ubicación del generador en Clean Architecture

En Clean Architecture, el dominio no debe depender de nada. El generador inspecciona las entidades del dominio y produce DTOs que normalmente vivirán en la capa de aplicación o en un proyecto compartido. El generador mismo es un proyecto aparte, referenciado como analyzer desde el proyecto de aplicación.

proyecto-final/
├── src/
│   ├── Cms.Domain/              ← entidades con [GenerateDto]
│   ├── Cms.Application/         ← usa los DTOs generados
│   ├── Cms.Infrastructure/      ← EF Core, repositorios
│   ├── Cms.Api/                 ← expone DTOs en endpoints
│   └── Cms.Generators/          ← Source Generator (netstandard2.0)
└── tests/

2.2. Pipeline de Roslyn para este generador

El generador sigue este pipeline:

  1. Generar el atributo [GenerateDto] en tiempo de compilación.
  2. Detectar todas las clases con ese atributo usando ForAttributeWithMetadataName.
  3. Para cada clase, obtener sus propiedades públicas desde el SemanticModel.
  4. Generar tres archivos: {Entity}Dto, Create{Entity}Dto y Update{Entity}Dto.
  5. Colocar los DTOs en el namespace Cms.Application.Dtos.

2.3. Decisiones de diseño

Dto de lectura: incluye todos los campos públicos, incluyendo navegación (por ejemplo, CategoryName como string).

Dto de creación: incluye campos editables, excluye IDs generados y propiedades de auditoría (CreatedAt).

Dto de actualización: similar a creación pero incluye el ID para identificar el recurso.

Para simplificar, en este proyecto usamos una lista configurable de propiedades a excluir por tipo de DTO. En un sistema real podrías añadir atributos como [DtoIgnore], [DtoReadOnly] o [DtoKey].

4 · Ejemplo real

Implementación completa del generador. Inspecciona entidades con [GenerateDto], obtiene propiedades públicas desde el modelo semántico y genera DTOs de lectura, creación y actualización.

using Microsoft.CodeAnalysis;
using Microsoft.CodeAnalysis.CSharp;
using Microsoft.CodeAnalysis.CSharp.Syntax;
using System.Collections.Generic;
using System.Linq;
using System.Text;

namespace Cms.Generators;

[Generator]
public class CmsDtoGenerator : IIncrementalGenerator
{
    public void Initialize(IncrementalGeneratorInitializationContext context)
    {
        // 1. Generar el atributo para que el usuario pueda aplicarlo
        context.RegisterPostInitializationOutput(ctx =>
        {
            ctx.AddSource("GenerateDtoAttribute.g.cs", SourceText.From(GenerateDtoAttributeSource, Encoding.UTF8));
        });

        // 2. Pipeline incremental: detectar clases con el atributo
        IncrementalValuesProvider<ClassDeclarationSyntax> entityClasses = context.SyntaxProvider
            .ForAttributeWithMetadataName(
                fullyQualifiedMetadataName: "Cms.Generators.GenerateDtoAttribute",
                predicate: (node, _) => node is ClassDeclarationSyntax,
                transform: (ctx, _) => (ClassDeclarationSyntax)ctx.TargetNode);

        // 3. Combinar con el modelo semántico para obtener tipos reales
        IncrementalValuesProvider<(ClassDeclarationSyntax Class, SemanticModel SemanticModel)> entitiesWithModel =
            entityClasses.Combine(context.CompilationProvider)
                .Select((pair, _) =>
                {
                    var (classSyntax, compilation) = pair;
                    var model = compilation.GetSemanticModel(classSyntax.SyntaxTree);
                    return (classSyntax, model);
                });

        // 4. Generar código
        context.RegisterSourceOutput(entitiesWithModel, (spc, source) =>
        {
            GenerateDtos(spc, source.Class, source.SemanticModel);
        });
    }

    private static void GenerateDtos(SourceProductionContext context, ClassDeclarationSyntax classSyntax, SemanticModel model)
    {
        var classSymbol = model.GetDeclaredSymbol(classSyntax);
        if (classSymbol is null) return;

        var className = classSymbol.Name;
        var namespaceName = classSymbol.ContainingNamespace.ToDisplayString();

        var properties = classSymbol.GetMembers()
            .OfType<IPropertySymbol>()
            .Where(p => p.DeclaredAccessibility == Accessibility.Public)
            .ToList();

        var readProperties = properties;
        var createProperties = properties.Where(p => p.Name != "Id" && !IsAuditProperty(p)).ToList();
        var updateProperties = properties.Where(p => !IsAuditProperty(p)).ToList();

        context.AddSource($"{className}.Dto.g.cs", SourceText.From(
            BuildDto(className, "Dto", readProperties, includeId: true, flattenNavigation: true), Encoding.UTF8));

        context.AddSource($"{className}.CreateDto.g.cs", SourceText.From(
            BuildDto(className, "CreateDto", createProperties, includeId: false, flattenNavigation: false), Encoding.UTF8));

        context.AddSource($"{className}.UpdateDto.g.cs", SourceText.From(
            BuildDto(className, "UpdateDto", updateProperties, includeId: true, flattenNavigation: false), Encoding.UTF8));
    }

    private static bool IsAuditProperty(IPropertySymbol property) =>
        property.Name is "CreatedAt" or "UpdatedAt" or "CreatedBy" or "UpdatedBy";

    private static string BuildDto(string entityName, string suffix, IEnumerable<IPropertySymbol> properties, bool includeId, bool flattenNavigation)
    {
        var builder = new StringBuilder();
        builder.AppendLine("namespace Cms.Application.Dtos;");
        builder.AppendLine($"public sealed class {entityName}{suffix}");
        builder.AppendLine("{");

        foreach (var property in properties)
        {
            var typeName = property.Type.ToDisplayString();
            var propertyName = property.Name;

            if (flattenNavigation && property.Type.TypeKind == TypeKind.Class && propertyName != "Id")
            {
                // Para lectura, aplanamos navegación a string (ej: Category -> CategoryName)
                builder.AppendLine($"    public string {propertyName}Name {{ get; set; }} = string.Empty;");
                continue;
            }

            var defaultValue = GetDefaultValue(typeName);
            builder.AppendLine($"    public {typeName} {propertyName} {{ get; set; }} = {defaultValue};");
        }

        builder.AppendLine("}");
        return builder.ToString();
    }

    private static string GetDefaultValue(string typeName) => typeName switch
    {
        "string" => "string.Empty",
        "System.Guid" => "System.Guid.Empty",
        "System.DateTime" => "System.DateTime.MinValue",
        "int" => "0",
        "bool" => "false",
        "decimal" => "0m",
        _ => "default!"
    };

    private const string GenerateDtoAttributeSource = @"
namespace Cms.Generators;

[AttributeUsage(AttributeTargets.Class, Inherited = false, AllowMultiple = false)]
public sealed class GenerateDtoAttribute : Attribute { }
";
}

5 · Buenas prácticas

  • Ubica el generador en un proyecto separado con target netstandard2.0.
  • Genera siempre el atributo para evitar dependencias circulares.
  • Usa el modelo semántico para tipos reales; no confíes solo en el syntax tree.
  • Excluye propiedades de navegación complejas en DTOs de creación/actualización.
  • Asigna nombres únicos a los archivos generados ({Entity}.{Suffix}.g.cs).
  • Coloca los DTOs generados en un namespace consistente (Cms.Application.Dtos).
  • Versiona y documenta el generador como parte del contrato del CMS.

6 · Errores habituales

6.1. Referenciar el generador como ensamblado normal

// ❌ MAL: el generador no se ejecutará como analyzer
<ProjectReference Include="..\Cms.Generators\Cms.Generators.csproj" />

Correcto:

// ✅ BIEN: OutputItemType Analyzer y no referenciar el ensamblado
<ProjectReference Include="..\Cms.Generators\Cms.Generators.csproj" OutputItemType="Analyzer" ReferenceOutputAssembly="false" />

6.2. Generar propiedades sin conocer el tipo semántico

// ❌ MAL: usar el texto del syntax tree como tipo
string typeName = property.Type.ToString(); // puede ser "DateTime" sin namespace

Correcto:

// ✅ BIEN: usar el symbol para el display string completo
string typeName = property.Type.ToDisplayString(); // "System.DateTime"

6.3. Exponer campos sensibles en DTOs

// ❌ MAL: PasswordHash no debe salir en el DTO de lectura
public class UserDto
{
    public string PasswordHash { get; set; } // peligroso
}

Correcto:

// ✅ BIEN: excluir campos sensibles con reglas o atributos
public class UserDto
{
    public Guid Id { get; set; }
    public string Email { get; set; }
    public string DisplayName { get; set; }
}

7 · Ejercicio guiado

Extiende el generador para añadir un atributo [DtoIgnore] que excluya propiedades de todos los DTOs generados.

  1. Genera el atributo DtoIgnoreAttribute junto con GenerateDtoAttribute.
  2. En el pipeline, filtra las propiedades que no tengan el atributo.
  3. Marca PasswordHash en User con [DtoIgnore].
  4. Verifica que el DTO de lectura no incluye la propiedad.

Fragmento:

private static bool HasDtoIgnore(IPropertySymbol property) =>
    property.GetAttributes().Any(a => a.AttributeClass?.Name == "DtoIgnoreAttribute");

var properties = classSymbol.GetMembers()
    .OfType<IPropertySymbol>()
    .Where(p => p.DeclaredAccessibility == Accessibility.Public)
    .Where(p => !HasDtoIgnore(p))
    .ToList();

8 · Reto

Implementa un segundo generador que, a partir de los DTOs generados, cree métodos de extensión de mapeo:

public static class PostMapper
{
    public static PostDto ToDto(this Post post) => ...;
    public static Post ToEntity(this CreatePostDto dto) => ...;
}

El generador debe inspeccionar propiedades coincidentes por nombre y generar el mapeo automáticamente. Considera qué hacer con propiedades de navegación y campos sensibles.

9 · Resumen

  • El Source Generator del CMS genera DTOs de lectura, creación y actualización desde entidades.
  • Usa el modelo semántico de Roslyn para obtener tipos reales.
  • El generador vive en Cms.Generators y se referencia como analyzer.
  • Los DTOs generados se colocan en Cms.Application.Dtos.
  • Es clave no exponer campos sensibles ni propiedades de navegación complejas.
  • El generador reduce boilerplate y mantiene la API sincronizada con el dominio.

10 · Preguntas frecuentes

¿Por qué no usar AutoMapper?
AutoMapper es válido, pero requiere configuración en runtime y reflection. El generador produce código C# estático, verificado por el compilador y sin overhead de startup.
¿Dónde quedan los DTOs generados físicamente?
En el directorio obj/Debug/net8.0/generated del proyecto que consume el analyzer. No se añaden al repo, pero se pueden inspeccionar durante el desarrollo.
¿El generador puede fallar silenciosamente?
Sí, si el código generado no compila, verás errores en el proyecto consumidor. También puedes emitir diagnostics desde el generador con context.ReportDiagnostic.
¿Cómo evito que el generador se ejecute en cada pulsación de tecla?
Usando IIncrementalGenerator y ForAttributeWithMetadataName, el motor solo re-ejecuta cuando cambian las clases marcadas.
¿Puedo generar DTOs para records?
Sí, pero debes adaptar el predicate para detectar RecordDeclarationSyntax además de ClassDeclarationSyntax.
