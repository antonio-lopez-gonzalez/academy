Span<T>, Memory<T> y stackalloc

Módulo 4 · C# Avanzado35 min

1 · Introducción

En esta lección aprenderemos a trabajar con memoria de forma eficiente en C# moderno. Veremos Span<T>, Memory<T>, ReadOnlySpan<T> y stackalloc. Estos tipos permiten procesar arrays, cadenas y buffers sin generar allocations innecesarias en el heap.

¿Por qué existen? Porque muchas operaciones cotidianas (parsear un CSV, procesar un stream, leer una línea de un fichero) crean miles de objetos intermedios que el GC debe limpiar. En aplicaciones de alta frecuencia (APIs, gateways, trading, juegos) esto se traduce en pausas del recolector.

¿Cuándo se utilizan? Cuando necesitas:

  • Procesar subcadenas o subarrays sin copiar datos.
  • Evitar allocations en el hot path de una aplicación.
  • Trabajar con buffers de pila de forma segura.
  • Consumir APIs de bajo nivel (red, criptografía, binarios) de forma eficiente.

Errores típicos: confundir Span<T> con Memory<T>, usar stackalloc con tamaños grandes, intentar almacenar un Span<T> en un campo de clase.

2 · Teoría

2.1. ¿Qué es Span<T>?

Span<T> es un tipo ref struct introducido en C# 7.2. Representa una ventana contigua de memoria de cualquier origen: un array, la pila, memoria nativa o incluso una cadena (como ReadOnlySpan<char>). Al ser un ref struct, solo puede vivir en la pila, nunca en el heap. Eso garantiza que no se escapará fuera del ámbito donde la memoria subyacente sigue siendo válida.

// Span puede apuntar a un array existente
int[] numbers = [1, 2, 3, 4, 5];
Span<int> slice = numbers.AsSpan(1, 3); // 2,3,4 sin copiar

2.2. ¿Qué es Memory<T>?

Memory<T> es la versión "heap-safe" de Span<T>. Puede almacenarse en campos de clase, capturarse en lambdas y await, y pasarse a métodos asíncronos. Internamente contiene un objeto que administra la memoria subyacente (array, string o memoria nativa) más un índice y longitud.

// Memory puede usarse en async y guardarse en clases
byte[] buffer = new byte[1024];
Memory<byte> memory = buffer.AsMemory(0, 256);

2.3. stackalloc

stackalloc reserva memoria en la pila del método actual. Es ultrarrápido porque no consulta al GC, pero la memoria se libera automáticamente al salir del método. Solo debe usarse con tamaños pequeños y controlados; si excedes el tamaño de la pila o usas un tamaño dinámico no validado, obtendrás StackOverflowException.

2.5. Comparación con otros lenguajes

En Java, ByteBuffer ofrece una ventana similar pero sin la integración del compilador. En Rust, los slices (&[T]) son el equivalente conceptual más cercano, pero con verificación de ownership en tiempo de compilación. En C/C++ usas punteros crudos, con todo el riesgo de dangling pointers y buffer overflows. Span<T> intenta ofrecer la velocidad de C++ con la seguridad de C#.

2.6. Slicing sin allocation

El método .Slice(start, length) crea un nuevo Span<T> con un offset y longitud distintos, pero ambos apuntan a la misma memoria subyacente. No hay copia de bytes. Esto es clave para parsear protocolos, logs, CSVs o headers HTTP.

3 · Ejemplo mínimo

Creamos un proyecto de consola para experimentar con Span<T>, stackalloc y ReadOnlySpan<char>.

dotnet new console -n SpanMemoryDemo -o ejemplos/m04-csharp-avanzado/span-memory-demo/src/SpanMemoryDemo

Reemplazamos Program.cs:

// Ejemplo mínimo: Span<T>, ReadOnlySpan<char> y stackalloc
using System;

// 1. Slicing de un array sin copiar
int[] data = [10, 20, 30, 40, 50];
Span<int> middle = data.AsSpan(1, 3);
middle[0] = 99; // modifica el array original
Console.WriteLine(string.Join(", ", data)); // 10, 99, 30, 40, 50

// 2. Subcadena sin allocation usando ReadOnlySpan
string text = "Hola, mundo";
ReadOnlySpan<char> span = text.AsSpan(6, 5);
Console.WriteLine(span.ToString()); // mundo

// 3. stackalloc: buffer de pila
Span<byte> buffer = stackalloc byte[64];
for (int i = 0; i < buffer.Length; i++)
{
    buffer[i] = (byte)i;
}
Console.WriteLine(buffer[10]); // 10

Ejecutamos:

dotnet run --project ejemplos/m04-csharp-avanzado/span-memory-demo/src/SpanMemoryDemo

Explicación línea por línea:

  • data.AsSpan(1, 3): crea una ventana que empieza en el índice 1 y tiene 3 elementos. No copia.
  • middle[0] = 99: al modificar el span, modificamos el array original.
  • text.AsSpan(6, 5): slice sobre la cadena inmutable. ReadOnlySpan<char> impide escritura.
  • stackalloc byte[64]: reserva 64 bytes en la pila. Se libera al salir del método.

4 · Ejemplo real

Implementamos un parser de CSV muy básico que usa ReadOnlySpan<char> para evitar Substring. Luego medimos con BenchmarkDotNet la diferencia.

// Parser CSV con Span (sin Substring)
public static class CsvParser
{
    public static List<string[]> Parse(ReadOnlySpan<char> csv)
    {
        var rows = new List<string[]>();
        while (csv.Length > 0)
        {
            // Buscar el siguiente salto de línea
            int lineEnd = csv.IndexOf('\n');
            if (lineEnd < 0) lineEnd = csv.Length;

            ReadOnlySpan<char> line = csv.Slice(0, lineEnd);
            rows.Add(ParseLine(line));

            // Avanzar el slice
            csv = lineEnd < csv.Length
                ? csv.Slice(lineEnd + 1)
                : ReadOnlySpan<char>.Empty;
        }
        return rows;
    }

    private static string[] ParseLine(ReadOnlySpan<char> line)
    {
        var fields = new List<string>();
        while (line.Length > 0)
        {
            int comma = line.IndexOf(',');
            if (comma < 0) comma = line.Length;

            ReadOnlySpan<char> field = line.Slice(0, comma);
            // Solo aquí se materializa la cadena, si es necesario
            fields.Add(field.ToString());

            line = comma < line.Length
                ? line.Slice(comma + 1)
                : ReadOnlySpan<char>.Empty;
        }
        return fields.ToArray();
    }
}

Versión clásica con Substring:

// Versión clásica: cada Substring crea una nueva cadena en el heap
public static class CsvParserClassic
{
    public static List<string[]> Parse(string csv)
    {
        var rows = new List<string[]>();
        foreach (var line in csv.Split('\n'))
        {
            rows.Add(line.Split(','));
        }
        return rows;
    }
}

Benchmark:

Resultado típico: la versión Span reduce drásticamente las allocations porque Split y Substring generan miles de cadenas y arrays intermedios.

4.1. ¿Cuándo usar Memory<T>?

Los métodos asíncronos no pueden recibir Span<T> porque el span vive en la pila y el método puede suspenderse. Para esos casos usamos Memory<T>.

// Método async que recibe Memory<byte> para leer de un stream
public static async Task<int> ReadChunkAsync(Stream stream, Memory<byte> buffer)
{
    // Memory<byte> es seguro en async porque puede vivir en el heap
    return await stream.ReadAsync(buffer);
}

// Uso
byte[] buffer = new byte[4096];
int read = await ReadChunkAsync(stream, buffer.AsMemory());

5 · Buenas prácticas

  • Usa Span<T> para procesamiento síncrono y corto.
  • Usa Memory<T> cuando necesites async, campos de clase o lambdas.
  • Usa ReadOnlySpan<T> para datos de solo lectura (cadenas, buffers de entrada).
  • Valida siempre los límites antes de llamar a Slice.
  • Limita stackalloc a tamaños pequeños y fijos. Generalmente menos de 1 KB.
  • Prefiere Span<byte> buffer = stackalloc byte[128] sobre arrays de tamaño fijo para evitar allocations.

6 · Errores habituales

6.1. Guardar un Span en un campo

// ❌ MAL: Span es ref struct y no puede ser campo de clase
public class Bad
{
    private Span<byte> _span; // Error de compilación
}

Correcto:

// ✅ BIEN: usa Memory<T> para campos de clase
public class Good
{
    private Memory<byte> _memory;
}

6.2. stackalloc con tamaño dinámico no controlado

// ❌ MAL: riesgo de StackOverflowException
Span<byte> buffer = stackalloc byte[userInput.Length];

Correcto:

// ✅ BIEN: tamaño constante en tiempo de compilación o validado
const int MaxStackSize = 256;
Span<byte> buffer = userInput.Length <= MaxStackSize
    ? stackalloc byte[userInput.Length]
    : new byte[userInput.Length];

6.3. Slicing fuera de rango

// ❌ MAL: puede lanzar ArgumentOutOfRangeException
ReadOnlySpan<char> span = text.AsSpan(100, 50);

Correcto:

// ✅ BIEN: validar o usar Slice con start válido
ReadOnlySpan<char> span = text.AsSpan(Math.Min(100, text.Length));

7 · Ejercicio guiado

Crea un método que reciba una cadena con formato clave=valor&clave=valor y devuelva un diccionario usando ReadOnlySpan<char>. El objetivo es minimizar allocations.

Pasos:

  1. Crea un proyecto de consola.
  2. Implementa ParseQueryString(ReadOnlySpan<char> query).
  3. Busca & para separar pares y = para separar clave/valor.
  4. Materializa solo las claves y valores finales con ToString().

Solución:

public static Dictionary<string, string> ParseQueryString(ReadOnlySpan<char> query)
{
    var result = new Dictionary<string, string>();
    while (query.Length > 0)
    {
        int ampersand = query.IndexOf('&');
        if (ampersand < 0) ampersand = query.Length;

        ReadOnlySpan<char> pair = query.Slice(0, ampersand);
        int equal = pair.IndexOf('=');
        if (equal >= 0)
        {
            string key = pair.Slice(0, equal).ToString();
            string value = pair.Slice(equal + 1).ToString();
            result[key] = value;
        }

        query = ampersand < query.Length
            ? query.Slice(ampersand + 1)
            : ReadOnlySpan<char>.Empty;
    }
    return result;
}

8 · Reto

Implementa un parser de números enteros sobre ReadOnlySpan<char> (sin usar int.Parse ni Convert.ToInt32). Debe soportar opcionalmente signo negativo. Mide con BenchmarkDotNet la diferencia frente a int.Parse(string) en 100.000 iteraciones.

9 · Resumen

  • Span<T> es una ventana de memoria segura que solo vive en la pila.
  • Memory<T> es la versión segura para heap, async y campos.
  • stackalloc reserva memoria en pila sin GC; úsalo con tamaños pequeños.
  • Slice permite crear subventanas sin copiar datos.
  • Estos tipos son fundamentales para código de alto rendimiento en .NET.

10 · Preguntas frecuentes

¿Puedo usar Span<T> en async/await?
No. Span<T> es un ref struct y no puede sobrevivir a una suspensión del método. Usa Memory<T> en su lugar.
¿Span crea copias?
No. Slice solo cambia el puntero y la longitud. Las copias ocurren solo si tú las fuerzas (por ejemplo, con ToArray() o ToString()).
¿Es stackalloc seguro?
Es seguro si usas tamaños pequeños y constantes. Si el tamaño es dinámico o grande, cae en StackOverflowException. Prefiere ArrayPool<T> para buffers grandes.
¿Cuándo no usar Span?
Cuando la claridad del código es más importante que el rendimiento, o cuando necesitas interoperabilidad con APIs que no lo soportan. No optimices prematuramente.
