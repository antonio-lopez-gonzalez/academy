Source Generators

Módulo 4 · C# Avanzado40 min

1. Introducción

En esta lección aprenderemos a crear Source Generators: analizadores que se ejecutan durante la compilación y generan código C# automáticamente. Veremos el generador incremental (IIncrementalGenerator), la API de Roslyn para inspeccionar sintaxis y símbolos, y generaremos DTOs a partir de entidades de dominio usando un atributo personalizado.

¿Por qué existen? Porque mucho código repetitivo (DTOs, serializadores, mapeadores, ORMs, INotifyPropertyChanged) puede deducirse del código fuente. En lugar de escribirlo a mano o usar reflection en runtime, lo generamos en tiempo de compilación. Eso mejora el rendimiento, reduce errores y permite que el compilador verifique el código generado.

¿Cuándo se utilizan? Cuando:

  • Necesitas evitar reflection en runtime.
  • Tienes mucho código boilerplate que sigue un patrón.
  • Quieres que el IDE muestre el código generado y los errores de compilación.
  • Quieres serializar, validar o mapear objetos de forma eficiente.

Errores típicos: confundir generadores con T4, no marcar los paquetes como analizadores, no entender la diferencia entre syntax y semantic models, generar código que no compila.

2. Teoría

2.1. ¿Qué es un Source Generator?

Un Source Generator es una clase que implementa IIncrementalGenerator y se ejecuta en el proceso de compilación. Recibe la sintaxis y los símbolos del código fuente y puede añadir nuevos archivos .cs al proyecto. A diferencia de T4, no genera archivos en disco que luego compiles; el código aparece directamente en la compilación.

2.2. IIncrementalGenerator

El generador incremental es la API recomendada desde .NET 6. En lugar de recibir todo el árbol de sintaxis en cada pulsación de tecla, define un pipeline de transformaciones. Solo se re-ejecuta cuando cambian los nodos relevantes. Esto hace que el IDE sea más rápido y consuma menos memoria.

2.3. Roslyn: Syntax Tree y Semantic Model

Roslyn es el compilador de C# expuesto como API. El syntax tree representa el código fuente tal cual está escrito (palabras clave, llaves, nombres). El semantic model añade información semántica: qué tipo tiene cada símbolo, qué métodos existen, qué atributos están aplicados. Un generador robusto usa ambos: syntax para detectar candidatos y semantic para entenderlos.

2.5. Comparación con alternativas

Reflection en runtime es flexible pero lenta y no segura ante refactorings. T4 genera archivos físicos pero requiere ejecutar manualmente una plantilla. Source Generators son automáticos, integrados en el IDE y producen código C# verificable. AIs like AutoMapper o ReflectionMapper generan código en runtime con expression trees; los source generators hacen lo mismo pero en tiempo de compilación, sin startup cost.

Código del generador:

using Microsoft.CodeAnalysis;

namespace HelloGenerator;

[Generator]
public class HelloWorldGenerator : IIncrementalGenerator
{
    public void Initialize(IncrementalGeneratorInitializationContext context)
    {
        // Genera un archivo fijo independientemente del código fuente
        context.RegisterPostInitializationOutput(ctx =>
        {
            ctx.AddSource("HelloWorld.g.cs", SourceText.From(@"
namespace HelloGenerator.Generated;

public static class HelloWorld
{
    public static string SayHello() => \"Hola desde el generador!\";
}
", Encoding.UTF8));
        });
    }
}

En el consumidor referenciamos el generador como analyzer:

<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <OutputType>Exe</OutputType>
    <TargetFramework>net8.0</TargetFramework>
    <ImplicitUsings>enable</ImplicitUsings>
    <Nullable>enable</Nullable>
  </PropertyGroup>

  <ItemGroup>
    <ProjectReference Include="..\HelloGenerator\HelloGenerator.csproj" OutputItemType="Analyzer" ReferenceOutputAssembly="false" />
  </ItemGroup>
</Project>

Program.cs del consumidor:

using HelloGenerator.Generated;

Console.WriteLine(HelloWorld.SayHello());

Compilamos y ejecutamos:

dotnet run --project src/HelloGenerator.Consumer

4. Ejemplo real

Creamos un generador que, a partir de clases marcadas con [GenerateDto], genere una clase DTO con las mismas propiedades públicas.

Atributo (lo generamos también para no depender de un ensamblado compartido):

// Generamos el atributo en tiempo de compilación
context.RegisterPostInitializationOutput(ctx =>
{
    ctx.AddSource("GenerateDtoAttribute.g.cs", SourceText.From(@"
namespace DtoGenerator;

[AttributeUsage(AttributeTargets.Class, Inherited = false, AllowMultiple = false)]
public sealed class GenerateDtoAttribute : Attribute
{
    public string Suffix { get; } = ""Dto"";

    public GenerateDtoAttribute(string suffix = ""Dto"") => Suffix = suffix;
}
", Encoding.UTF8));
});

Generador DTO:

using Microsoft.CodeAnalysis;
using Microsoft.CodeAnalysis.CSharp;
using Microsoft.CodeAnalysis.CSharp.Syntax;
using System.Text;

namespace DtoGenerator;

[Generator]
public class DtoGenerator : IIncrementalGenerator
{
    public void Initialize(IncrementalGeneratorInitializationContext context)
    {
        context.RegisterPostInitializationOutput(ctx =>
        {
            ctx.AddSource("GenerateDtoAttribute.g.cs", SourceText.From(AttributeSource, Encoding.UTF8));
        });

        IncrementalValuesProvider<ClassDeclarationSyntax> classes = context.SyntaxProvider
            .ForAttributeWithMetadataName(
                fullyQualifiedMetadataName: "DtoGenerator.GenerateDtoAttribute",
                predicate: (node, _) => node is ClassDeclarationSyntax,
                transform: (ctx, _) => (ClassDeclarationSyntax)ctx.TargetNode);

        context.RegisterSourceOutput(classes, (spc, source) =>
        {
            GenerateDto(spc, source);
        });
    }

    private static void GenerateDto(SourceProductionContext context, ClassDeclarationSyntax classSyntax)
    {
        var className = classSyntax.Identifier.Text;
        var dtoName = $"{className}Dto";

        var properties = classSyntax.Members
            .OfType<PropertyDeclarationSyntax>()
            .Where(p => p.Modifiers.Any(SyntaxKind.PublicKeyword))
            .Select(p => p.Identifier.Text);

        var builder = new StringBuilder();
        builder.AppendLine("namespace DtoGenerator.Generated;");
        builder.AppendLine($"public sealed class {dtoName}");
        builder.AppendLine("{");
        foreach (var prop in properties)
        {
            builder.AppendLine($"    public string {prop} {{ get; set; }} = string.Empty;");
        }
        builder.AppendLine("}");

        context.AddSource($"{dtoName}.g.cs", SourceText.From(builder.ToString(), Encoding.UTF8));
    }

    private const string AttributeSource = @"
namespace DtoGenerator;

[AttributeUsage(AttributeTargets.Class, Inherited = false, AllowMultiple = false)]
public sealed class GenerateDtoAttribute : Attribute { }
";
}

Entidad de ejemplo:

using DtoGenerator;

namespace DtoGenerator.Sample;

[GenerateDto]
public class Product
{
    public int Id { get; set; }
    public string Name { get; set; } = string.Empty;
    public decimal Price { get; set; }
}

Código generado:

namespace DtoGenerator.Generated;

public sealed class ProductDto
{
    public string Id { get; set; } = string.Empty;
    public string Name { get; set; } = string.Empty;
    public string Price { get; set; } = string.Empty;
}

Nota: este ejemplo usa sintaxis para simplificar. En producción deberías usar el modelo semántico para obtener los tipos reales de las propiedades y generar propiedades tipadas correctamente.

5. Buenas prácticas

  • Usa IIncrementalGenerator, no el generador antiguo ISourceGenerator.
  • Define un pipeline claro: filtrado sintáctico → transformación semántica → generación.
  • Usa ForAttributeWithMetadataName para detectar atributos de forma eficiente.
  • Genera el propio atributo para evitar dependencias de ensamblado.
  • Usa StringBuilder o interpolación de cadenas para generar código; evita concatenaciones masivas.
  • Marca el proyecto del generador con OutputItemType="Analyzer" en el consumidor.
  • Prueba el generador con Roslyn test utilities o compilando proyectos de ejemplo.

6. Errores habituales

6.1. No marcar el generador como Analyzer

// ❌ MAL: el generador se compila como referencia normal
<ProjectReference Include="..\Generator\Generator.csproj" />

Correcto:

// ✅ BIEN: el generador actúa como analizador
<ProjectReference Include="..\Generator\Generator.csproj" OutputItemType="Analyzer" ReferenceOutputAssembly="false" />

6.2. Usar reflection en el generador

El generador se ejecuta en el proceso de compilación, no en runtime. No puedes usar reflection sobre el ensamblado del usuario. Debes usar la API de Roslyn.

6.3. Generar código con nombres duplicados

Cada archivo añadido con AddSource debe tener un nombre único. Si dos clases generan el mismo nombre de archivo, la compilación falla.

// ✅ BIEN: incluir namespace o nombre de clase en el hint name
context.AddSource($"{namespaceName}.{className}.g.cs", sourceText);

7. Ejercicio guiado

Extiende el generador DTO para que respete el tipo original de cada propiedad usando el modelo semántico. Pasos:

  1. En la transformación, obtén el SemanticModel y el ITypeSymbol de cada propiedad.
  2. Usa p.Type.ToString() para obtener el nombre del tipo.
  3. Genera la propiedad con ese tipo y su inicialización por defecto.

Fragmento clave:

var model = context.SemanticModel;
var propertyType = model.GetTypeInfo(property.Type).Type;
string typeName = propertyType?.ToString() ?? "object";
string defaultValue = propertyType?.SpecialType switch
{
    SpecialType.System_Int32 => "0",
    SpecialType.System_String => "string.Empty",
    _ => "default!"
};
builder.AppendLine($"    public {typeName} {property.Identifier.Text} {{ get; set; }} = {defaultValue};");

8. Reto

Crea un generador que, a partir de clases marcadas con [ToString], genere un método override string ToString() que incluya todas las propiedades públicas con formato Propiedad=Valor. Usa el modelo semántico para tipos complejos y anida propiedades si detectas otra clase con [ToString].

9. Resumen

  • Los Source Generators producen código en tiempo de compilación.
  • IIncrementalGenerator permite pipelines eficientes que solo re-ejecutan lo necesario.
  • Roslyn ofrece syntax trees (estructura) y semantic models (significado).
  • Usa ForAttributeWithMetadataName para detectar clases con atributos.
  • El proyecto consumidor debe referenciar el generador como Analyzer.
  • Es ideal para DTOs, serializadores, mapeadores y cualquier boilerplate mecánico.

10. Preguntas frecuentes

¿Dónde veo el código generado?
En Visual Studio o Rider puedes expandir "Analizadores" → "Generador" → "Generated Files". En VS Code, busca en la carpeta obj/Debug/net8.0/generated.
¿Puedo depurar un Source Generator?
Sí, puedes lanzar una segunda instancia de Visual Studio con el proyecto del generador y atacar al proceso de compilación del consumidor.
¿Son los Source Generators lo mismo que T4?
No. T4 genera archivos físicos que luego compiles. Los source generators generan código en memoria durante la compilación, sin archivos intermedios.
¿Puedo usar LINQ en un generador?
Sí, pero el generador debe compilarse para netstandard2.0. Asegúrate de que las librerías que usas sean compatibles con ese target.
¿Qué pasa si el código generado no compila?
El error aparece como un error de compilación normal en el proyecto consumidor. Verifica que los namespaces, nombres y tipos sean correctos.
