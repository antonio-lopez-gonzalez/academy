FrozenSet, TimeProvider y Keyed Services

Módulo 4 · C# Avanzado30 min

1 · Introducción

En esta lección cubrimos tres novedades importantes de .NET 8: FrozenSet<T> y FrozenDictionary<TKey, TValue> para colecciones inmutables de alto rendimiento, TimeProvider para hacer testeable el tiempo, y Keyed Services para registrar múltiples implementaciones de la misma interfaz en el contenedor de DI.

¿Por qué existen? Porque en aplicaciones reales necesitas:

  • Colecciones de configuración que no cambian tras el startup y se consultan millones de veces.
  • Abstraer DateTime.UtcNow, Task.Delay y Timer para poder testear sin Thread.Sleep.
  • Registrar varias estrategias de la misma interfaz (por ejemplo, múltiples cálculos de impuestos) y elegir una por clave.

Errores típicos: pensar que FrozenSet es mutable, olvidar registrar TimeProvider en DI, confundir keyed services con named options.

2 · Teoría

2.1. FrozenSet y FrozenDictionary

Estas colecciones se encuentran en el namespace System.Collections.Frozen. Aceptan datos mutables, los copian internamente y luego los "congelan". El tiempo de construcción es mayor que el de un HashSet normal, pero las consultas posteriores son más rápidas porque pueden optimizar la estructura interna según el contenido.

Son ideales para configuración, whitelist de IPs, conjuntos de roles, diccionarios de lookups estáticos, etc. No deben usarse cuando se necesitan inserciones frecuentes.

2.2. TimeProvider

TimeProvider es una abstracción sobre el tiempo del sistema. Expone propiedades como GetLocalNow(), GetUtcNow(), métodos como CreateTimer y GetTimestamp(). En producción usas TimeProvider.System; en tests usas FakeTimeProvider (disponible en el paquete Microsoft.Extensions.TimeProvider.Testing) para avanzar el tiempo programáticamente.

2.3. Keyed Services

Antes de .NET 8, si registrabas dos implementaciones de ITaxCalculator, la segunda reemplazaba a la primera. Con keyed services puedes asociar cada implementación a una clave de cadena o enum y luego inyectar la que necesitas con [FromKeyedServices("key")] o GetRequiredKeyedService.

2.4. Comparación con versiones anteriores

Antes de .NET 8, para lookups estáticos usábamos HashSet<T> o ReadOnlyDictionary<TKey, TValue>. Para tiempo testeable, creábamos wrappers manuales como IDateTimeProvider. Para múltiples implementaciones, recurrimos a factory patterns o contenedores externos como Autofac. .NET 8 trae estas capacidades al BCL y al contenedor de DI nativo.

3 · Ejemplo mínimo

Creamos un proyecto de consola para probar las tres características.

dotnet new console -n FrozenTimeKeyedDemo -o ejemplos/m04-csharp-avanzado/frozen-time-keyed-demo/src/FrozenTimeKeyedDemo

Program.cs:

// Ejemplo mínimo: FrozenSet, TimeProvider y Keyed Services
using System.Collections.Frozen;
using Microsoft.Extensions.DependencyInjection;

// 1. FrozenSet
var allowedRoles = new[] { "Admin", "Editor", "Author" }.ToFrozenSet();
Console.WriteLine(allowedRoles.Contains("Admin")); // True
Console.WriteLine(allowedRoles.Contains("Visitor")); // False

// 2. FrozenDictionary
var countryCodes = new Dictionary<string, string>
{
    ["ES"] = "Spain",
    ["MX"] = "Mexico",
    ["AR"] = "Argentina"
}.ToFrozenDictionary();
Console.WriteLine(countryCodes["MX"]); // Mexico

// 3. TimeProvider básico
var time = TimeProvider.System;
Console.WriteLine(time.GetUtcNow());

// 4. Keyed Services
var services = new ServiceCollection();
services.AddKeyedSingleton<IGreetingService, SpanishGreetingService>("es");
services.AddKeyedSingleton<IGreetingService, EnglishGreetingService>("en");

var provider = services.BuildServiceProvider();
var spanish = provider.GetRequiredKeyedService<IGreetingService>("es");
var english = provider.GetRequiredKeyedService<IGreetingService>("en");

Console.WriteLine(spanish.Greet("Ana")); // ¡Hola, Ana!
Console.WriteLine(english.Greet("Ana")); // Hello, Ana!

public interface IGreetingService
{
    string Greet(string name);
}

public class SpanishGreetingService : IGreetingService
{
    public string Greet(string name) => $"¡Hola, {name}!";
}

public class EnglishGreetingService : IGreetingService
{
    public string Greet(string name) => $"Hello, {name}!";
}

Explicación:

  • ToFrozenSet(): convierte un enumerable en un conjunto inmutable optimizado.
  • ToFrozenDictionary(): lo mismo para diccionarios.
  • TimeProvider.System: implementación real que delega al reloj del sistema.
  • AddKeyedSingleton: registra una implementación bajo una clave.
  • GetRequiredKeyedService: resuelve la implementación por clave.

4 · Ejemplo real

Construimos un servicio de validación de tokens de API que usa las tres características.

public class ApiKeyValidator
{
    private readonly FrozenSet<string> _validKeys;
    private readonly TimeProvider _timeProvider;

    public ApiKeyValidator(IEnumerable<string> validKeys, TimeProvider timeProvider)
    {
        _validKeys = validKeys.ToFrozenSet();
        _timeProvider = timeProvider;
    }

    public bool IsValid(string key)
    {
        return _validKeys.Contains(key);
    }

    public bool IsExpired(DateTimeOffset issuedAt, TimeSpan maxAge)
    {
        return _timeProvider.GetUtcNow() - issuedAt > maxAge;
    }
}

Test con FakeTimeProvider:

using Microsoft.Extensions.Time.Testing;

var fakeTime = new FakeTimeProvider(DateTimeOffset.UtcNow);
var validator = new ApiKeyValidator(["abc123"], fakeTime);

var issuedAt = fakeTime.GetUtcNow();
fakeTime.Advance(TimeSpan.FromHours(2));

bool expired = validator.IsExpired(issuedAt, TimeSpan.FromHours(1));
Console.WriteLine(expired); // True

Registro en DI:

services.AddSingleton<ApiKeyValidator>();
services.AddSingleton(TimeProvider.System);
services.AddKeyedSingleton<IGreetingService, SpanishGreetingService>("es");
services.AddKeyedSingleton<IGreetingService, EnglishGreetingService>("en");

// Inyección en un controlador
public class HomeController : ControllerBase
{
    public HomeController([FromKeyedServices("es")] IGreetingService greeting) { }
}

5 · Buenas prácticas

  • Usa FrozenSet/FrozenDictionary para datos de solo lectura que se consultan muchas veces.
  • No uses colecciones frozen si necesitas modificaciones frecuentes; reconstruirlas es costoso.
  • Inyecta TimeProvider en lugar de llamar directamente a DateTime.UtcNow o Task.Delay.
  • Usa FakeTimeProvider en tests unitarios; evita Thread.Sleep en el código de producción solo para testear.
  • Usa keyed services cuando tengas múltiples implementaciones de la misma abstracción.
  • Prefiere claves tipadas (enum o constants) en lugar de cadenas mágicas.

6 · Errores habituales

6.1. Intentar modificar una colección frozen

// ❌ MAL: FrozenSet no expone métodos de modificación
var set = new[] { "A" }.ToFrozenSet();
set.Add("B"); // Error de compilación

Si necesitas añadir elementos, reconstruye la colección:

// ✅ BIEN: reconstruir cuando cambia la configuración
set = set.Concat(["B"]).ToFrozenSet();

6.2. No registrar TimeProvider en DI

// ❌ MAL: el servicio no puede resolverse si no registras TimeProvider
services.AddSingleton<ApiKeyValidator>();

Correcto:

// ✅ BIEN: registrar la abstracción del sistema
services.AddSingleton(TimeProvider.System);
services.AddSingleton<ApiKeyValidator>();

6.3. Mezclar keyed services con inyección sin clave

// ❌ MAL: sin clave no sabe qué implementación resolver
public HomeController(IGreetingService greeting) { }

Correcto:

// ✅ BIEN: indicar la clave explícitamente
public HomeController([FromKeyedServices("es")] IGreetingService greeting) { }

7 · Ejercicio guiado

Crea un servicio RateLimiter que use FrozenDictionary<string, int> para almacenar los límites de requests por endpoint. Usa TimeProvider para saber cuándo reiniciar la ventana. Inyecta distintas estrategias de limitación con keyed services.

Solución parcial:

public class RateLimiter
{
    private readonly FrozenDictionary<string, int> _limits;
    private readonly TimeProvider _time;
    private readonly Dictionary<string, (int Count, DateTimeOffset WindowStart)> _state = new();

    public RateLimiter(Dictionary<string, int> limits, TimeProvider time)
    {
        _limits = limits.ToFrozenDictionary();
        _time = time;
    }

    public bool AllowRequest(string endpoint)
    {
        if (!_limits.TryGetValue(endpoint, out var limit)) return true;

        var now = _time.GetUtcNow();
        if (!_state.TryGetValue(endpoint, out var window) || now - window.WindowStart > TimeSpan.FromMinutes(1))
        {
            window = (0, now);
        }

        if (window.Count >= limit) return false;

        window.Count++;
        _state[endpoint] = window;
        return true;
    }
}

8 · Reto

Implementa un FakeTimeProvider que avance automáticamente cada vez que se llama a GetUtcNow(), simulando un reloj que se adelanta. Usa esto para testear un TokenService que emite tokens con expiración y valida si han caducado sin esperar tiempo real.

9 · Resumen

  • FrozenSet y FrozenDictionary ofrecen lookups rápidos en colecciones inmutables.
  • TimeProvider abstrae el tiempo para hacer el código testeable y determinista.
  • FakeTimeProvider permite avanzar el tiempo en tests.
  • Keyed services permiten registrar múltiples implementaciones de la misma interfaz bajo una clave.
  • Estas tres APIs son clave para aplicaciones profesionales en .NET 8.

10 · Preguntas frecuentes

¿FrozenSet es más rápido que HashSet?
En consultas sí, especialmente con muchos elementos. La construcción es más lenta porque optimiza la estructura interna. Úsalo para datos estáticos.
¿Necesito instalar un paquete para TimeProvider?
TimeProvider está en el BCL. FakeTimeProvider requiere el paquete Microsoft.Extensions.TimeProvider.Testing.
¿Puedo usar keyed services en Minimal APIs?
Sí, usa [FromKeyedServices("key")] como parámetro del endpoint.
¿Las claves de keyed services deben ser cadenas?
El tipo es object, pero lo más común es usar string o enum. Evita claves mutables.
¿TimeProvider reemplaza a DateTime?
No lo reemplaza, pero en código nuevo deberías preferir inyectar TimeProvider para facilitar tests y permitir simulaciones.
