Consultas, rendimiento y N+1

Módulo 7 · Entity Framework Core40 min

1 · Introducción

EF Core hace que escribir consultas sea sencillo, pero eso no significa que todas las consultas sean eficientes. El rendimiento es responsabilidad del desarrollador. En esta lección aprenderemos a pensar en SQL mientras escribimos LINQ, a detectar el problema N+1 y a usar las herramientas que EF Core ofrece para optimizar.

Veremos:

  • IQueryable vs IEnumerable.
  • Ejecución diferida e inmediata.
  • Include, ThenInclude y proyecciones con Select.
  • AsNoTracking, AsSplitQuery y AsNoTrackingWithIdentityResolution.
  • ToQueryString y paginación.
  • Cómo detectar y evitar el problema N+1.

2 · Teoría

2.1 IQueryable vs IEnumerable

IQueryable<T> representa una consulta que aún no se ha ejecutado. Cada operación LINQ que añadimos se traduce a SQL. IEnumerable<T>, en cambio, opera en memoria una vez que los datos ya están materializados.

IQueryable<Post> query = context.Posts.Where(p => p.IsPublished);
query = query.OrderByDescending(p => p.PublishedAt);
query = query.Take(10);

// SQL se genera y ejecuta aquí:
List<Post> posts = await query.ToListAsync();
Regla de oro: filtra, ordena y pagina antes de llamar a ToListAsync u otro operador de ejecución inmediata.

2.2 Operadores de ejecución inmediata

Los métodos que materializan la consulta son: ToListAsync, FirstAsync, FirstOrDefaultAsync, SingleAsync, SingleOrDefaultAsync, CountAsync, AnyAsync, SumAsync, LoadAsync, ToArrayAsync, etc.

2.3 Eager Loading con Include

Include carga datos relacionados en una sola consulta mediante JOIN. ThenInclude desciende niveles adicionales.

var posts = await context.Posts
    .Include(p => p.Category)
    .Include(p => p.Author)
    .ThenInclude(a => a.Profile)
    .Where(p => p.IsPublished)
    .ToListAsync();

2.4 Proyecciones con Select

La mejor forma de mejorar el rendimiento es no traer columnas que no necesitas. Select permite proyectar a un DTO directamente en SQL.

var dtos = await context.Posts
    .Where(p => p.IsPublished)
    .Select(p => new PostSummaryDto
    {
        Id = p.Id,
        Title = p.Title,
        CategoryName = p.Category.Name
    })
    .ToListAsync();

SQL generado (simplificado):

SELECT p.id, p.title, c.name
FROM posts AS p
INNER JOIN categories AS c ON p.category_id = c.id
WHERE p.is_published = TRUE;

2.5 AsNoTracking

Para consultas de solo lectura, desactiva el change tracking. Mejora el rendimiento y reduce el uso de memoria.

var posts = await context.Posts
    .AsNoTracking()
    .Where(p => p.IsPublished)
    .ToListAsync();

Para proyecciones que reusan entidades seguimiento, usa AsNoTrackingWithIdentityResolution para evitar duplicados en memoria.

2.6 AsSplitQuery

Cuando Include genera muchos JOIN, el resultado cartesiano puede multiplicar filas. AsSplitQuery divide la consulta en varias SQL para reducir redundancia.

var posts = await context.Posts
    .AsSplitQuery()
    .Include(p => p.Category)
    .Include(p => p.Tags)
    .ToListAsync();
Trade-off: AsSplitQuery hace más consultas SQL pero cada una es más pequeña. Úsalo cuando hay muchas colecciones incluidas.

2.7 ToQueryString

Para depurar, obtén la consulta SQL sin ejecutarla. Es útil durante el desarrollo y en tests.

var query = context.Posts.Where(p => p.IsPublished);
Console.WriteLine(query.ToQueryString());

2.8 Paginación

Usa Skip y Take siempre combinados con un OrderBy para resultados deterministas.

var page = await context.Posts
    .AsNoTracking()
    .Where(p => p.IsPublished)
    .OrderByDescending(p => p.PublishedAt)
    .Skip((pageNumber - 1) * pageSize)
    .Take(pageSize)
    .ToListAsync();

var total = await context.Posts.CountAsync(p => p.IsPublished);

2.9 El problema N+1

Ocurre cuando cargamos una lista de entidades y luego, en un bucle, accedemos a una propiedad de navegación sin haberla incluido. Cada acceso dispara una nueva consulta SQL.

// ❌ N+1: una consulta para posts y N consultas para categorías.
var posts = await context.Posts.ToListAsync();
foreach (var post in posts)
{
    Console.WriteLine(post.Category.Name); // ¡Nueva consulta por cada post!
}
// ✅ Solución: Eager Loading.
var posts = await context.Posts
    .Include(p => p.Category)
    .ToListAsync();

Otra opción es proyectar el DTO directamente, que evita la necesidad de cargar la entidad completa.

3 · Ejemplo mínimo

Consulta paginada de posts publicados con su categoría.

int page = 1;
int size = 5;

var posts = await context.Posts
    .AsNoTracking()
    .Where(p => p.IsPublished)
    .Include(p => p.Category)
    .OrderByDescending(p => p.PublishedAt)
    .Skip((page - 1) * size)
    .Take(size)
    .ToListAsync();

Console.WriteLine(context.Posts.ToQueryString()); // Solo para depuración

4 · Ejemplo real

Endpoint de búsqueda del CMS con filtros, paginación, proyección y DTOs.

public record PostListItemDto(
    int Id,
    string Title,
    string Slug,
    string CategoryName,
    string AuthorName,
    DateTime? PublishedAt);

public class SearchPostsHandler : IRequestHandler<SearchPostsQuery, PagedResult<PostListItemDto>>
{
    private readonly CmsDbContext _context;
    public SearchPostsHandler(CmsDbContext context) => _context = context;

    public async Task<PagedResult<PostListItemDto>> Handle(SearchPostsQuery request, CancellationToken cancellationToken)
    {
        var query = _context.Posts
            .AsNoTracking()
            .Where(p => p.Status == PostStatus.Published);

        if (!string.IsNullOrWhiteSpace(request.Category))
            query = query.Where(p => p.Category.Name == request.Category);

        if (!string.IsNullOrWhiteSpace(request.SearchTerm))
            query = query.Where(p => p.Title.Contains(request.SearchTerm));

        var total = await query.CountAsync(cancellationToken);

        var items = await query
            .OrderByDescending(p => p.PublishedAt)
            .Skip((request.Page - 1) * request.PageSize)
            .Take(request.PageSize)
            .Select(p => new PostListItemDto(
                p.Id,
                p.Title,
                p.Slug,
                p.Category.Name,
                p.Author.DisplayName,
                p.PublishedAt))
            .ToListAsync(cancellationToken);

        return new PagedResult<PostListItemDto>(items, total, request.Page, request.PageSize);
    }
}
Observación: la proyección Select hace que SQL solo traiga las columnas necesarias. No hay change tracking, no hay N+1 y no hay carga de colecciones innecesarias.

5 · Buenas prácticas

  • Proyecta siempre que puedas: usa Select para traer solo los datos necesarios.
  • Usa AsNoTracking en lecturas: mejora el rendimiento y la memoria.
  • Ordena antes de Skip/Take: de lo contrario, la paginación es indeterminista.
  • Usa Include para relaciones obligatorias: evita el N+1.
  • Considera AsSplitQuery cuando incluyas múltiples colecciones: reduce la redundancia de datos.
  • Revisa el SQL con ToQueryString: es la forma más rápida de entender qué está haciendo EF Core.
  • Evita CountAsync si no necesitas el total: en listados infinitos, usa cursor o keyset pagination.

6 · Errores habituales

Error 1: Filtrar en memoria

// ❌ Mal: ToList trae todo, Where filtra en memoria.
var posts = context.Posts.ToList().Where(p => p.IsPublished);
// ✅ Bien: el filtro se traduce a SQL.
var posts = await context.Posts.Where(p => p.IsPublished).ToListAsync();

Error 2: Ordenar después de paginar

El orden debe ir antes de Skip y Take. De lo contrario, cada página puede devolver resultados distintos.

Error 3: Materializar dentro de un bucle

// ❌ Mal: cada iteración ejecuta una consulta.
foreach (var id in ids)
{
    var post = await context.Posts.FindAsync(id);
    Console.WriteLine(post?.Title);
}

// ✅ Bien: una sola consulta con Where(...).Contains(...).
var posts = await context.Posts
    .Where(p => ids.Contains(p.Id))
    .ToListAsync();

Error 4: AsNoTracking en actualizaciones

Si necesitas modificar una entidad, no uses AsNoTracking. El contexto no detectará los cambios y SaveChanges no hará nada.

7 · Ejercicio guiado

Implementa un listado de pedidos con sus clientes y productos:

  1. Crea las entidades Order, Customer y OrderLine (1:N entre Order y OrderLine).
  2. Escribe una consulta que devuelva los últimos 10 pedidos con cliente y líneas.
  3. Usa AsSplitQuery si incluyes varias colecciones.
  4. Proyecta a un DTO con totales calculados.
  5. Imprime el SQL con ToQueryString y analiza los JOIN.
var dtos = await context.Orders
    .AsNoTracking()
    .AsSplitQuery()
    .Include(o => o.Customer)
    .Include(o => o.Lines)
    .OrderByDescending(o => o.OrderDate)
    .Take(10)
    .Select(o => new OrderDto(
        o.Id,
        o.Customer.Name,
        o.Lines.Sum(l => l.Quantity * l.UnitPrice)))
    .ToListAsync();

8 · Reto

Implementa una consulta de búsqueda de posts por etiqueta. El endpoint debe:

  • Filtrar por nombre de etiqueta.
  • Proyectar a un DTO con título, autor y lista de etiquetas.
  • Usar paginación con Skip/Take.
  • Evitar el problema N+1 sin usar Include (solo con Select).

9 · Resumen

  • IQueryable permite componer consultas que se traducen a SQL.
  • Los operadores de ejecución inmediata materializan los resultados.
  • Include y ThenInclude resuelven relaciones en una sola consulta.
  • Las proyecciones con Select reducen el volumen de datos.
  • AsNoTracking acelera consultas de solo lectura.
  • La paginación requiere OrderBy antes de Skip/Take.
  • El problema N+1 se evita cargando relaciones explícitamente o proyectando.

10 · Preguntas frecuentes

¿Siempre debo usar Include?

No. Si solo necesitas algunos campos de la relación, una proyección con Select suele ser más eficiente.

¿AsSplitQuery es siempre mejor?

No. Hace más consultas a la base de datos. Úsalo cuando haya muchas colecciones incluidas y el JOIN cartesiano supere un umbral de redundancia.

¿Por qué mi consulta no se traduce a SQL?

Probablemente uses un método no soportado por el proveedor de LINQ. Revisa el error: indica la expresión que no pudo traducirse.

¿Puedo usar GroupBy con EF Core?

Sí, pero con limitaciones. Algunas agregaciones no se traducen y deben hacerse en memoria después de materializar. Revisa siempre el SQL.

¿Cómo depuro el rendimiento de una consulta?

Usa ToQueryString, logs de EF Core, EXPLAIN ANALYZE en PostgreSQL y herramientas como dotnet trace o pgAdmin.
