Identity vs custom JWT

Módulo 11 · Autenticación y autorización30 min

1 · Introducción

.NET 8 ofrece dos caminos principales para autenticar usuarios: ASP.NET Core Identity y JWT personalizado. Elegir el adecuado ahorra meses de trabajo y evita soluciones sobre-ingenieradas.

En esta lección compararemos ambos enfoques, veremos cuándo usar cada uno y aprenderemos a hashear contraseñas correctamente con PasswordHasher<TUser> y BCrypt.Net.

¿Qué problema resuelve?

Decidir si una aplicación necesita un sistema completo de usuarios, roles, confirmación de email, recuperación de contraseña y 2FA, o si solo necesita validar tokens de APIs y servicios.

Errores típicos

  • Usar Identity para una API simple que solo necesita tokens de servicio.
  • Implementar manualmente un sistema completo de usuarios sin aprovechar Identity.
  • Almacenar contraseñas en texto plano o con hashes débiles.
  • No considerar el costo de mantener un sistema de login propio.
  • Mezclar tablas de Identity con lógica de negocio sin una arquitectura clara.

2 · Teoría

ASP.NET Core Identity

Identity es un sistema completo de gestión de usuarios que incluye:

  • Registro, login y logout.
  • Confirmación de email y reset de contraseña.
  • Roles y claims.
  • Autenticación de dos factores (2FA).
  • Login externo (Google, Microsoft, Facebook).
  • Tokens de propósito general (email confirmation, password reset).
  • Lockout por intentos fallidos.
  • Integración con EF Core mediante UserStore y RoleStore.

Identity puede generar cookies de sesión (para MVC con vistas) o tokens (para APIs). En .NET 8, las Identity APIs permiten exponer endpoints de autenticación como una API REST sin scaffolding de UI.

Custom JWT

En este enfoque nosotros controlamos todo:

  • Tablas de usuarios y roles propias.
  • Hash de contraseñas.
  • Emisión y validación de JWT.
  • Refresh tokens.
  • Revocación y logout.

Es más flexible pero también más responsabilidad.

Regla de decisión

Usa Identity si gestionas usuarios finales con registro, perfiles, email y 2FA. Usa JWT custom si tu API es consumida por servicios, microservicios o una app con login externo propio.

Hashing de contraseñas

Almacenar contraseñas en texto plano es un crimen de seguridad. Nunca debes poder recuperar la contraseña original. Debes usar un algoritmo de hashing adaptativo que sea lento y resistente a fuerza bruta.

  • PBKDF2: usado por PasswordHasher<TUser> de ASP.NET Core Identity.
  • bcrypt: popular, con factor de costo configurable.
  • Argon2: ganador de la Password Hashing Competition.
  • scrypt: alternativa resistente a hardware especializado.
