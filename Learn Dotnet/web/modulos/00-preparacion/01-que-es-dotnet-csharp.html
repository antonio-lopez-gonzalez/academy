¿Qué es .NET y C#?

Módulo 0 · Preparación 35 minutos

1 · Introducción

Antes de escribir una sola línea de código necesitas entender qué es exactamente .NET. Mucha gente llega con una idea borrosa: "es el lenguaje de Microsoft", "es como Java", "solo funciona en Windows". Las tres son incorrectas o incompletas, y te perseguirán durante todo el curso si no las aclaras ahora.

En esta lección vamos a responder, en este orden:

  • ¿Qué es .NET? Una plataforma de ejecución y librerías, no un lenguaje.
  • ¿Qué es C#? El lenguaje principal con el que escribimos código para .NET.
  • ¿Qué son el CLR, el IL y el JIT? Las piezas que hacen funcionar tu código.
  • ¿Por qué importa distinguir .NET moderno de .NET Framework? Son productos distintos.
Objetivo

Al terminar sabrás explicar con tus propias palabras qué es .NET, qué papel juega C# y cómo viaja tu código hasta convertirse en instrucciones de máquina.

2 · Teoría

El mapa: lenguaje, plataforma y runtime

La confusión nace porque usamos tres palabras como si fueran lo mismo. No lo son:

C# (lenguaje: sintaxis que escribes tú) │ ▼ .NET (plataforma: SDK + compilador + librerías base + runtime) │ ▼ CLR (runtime: la máquina que ejecuta tu programa)
  • C# es un lenguaje de programación: reglas de sintaxis. Podrías usar otro lenguaje (F#, Visual Basic) y seguir dentro de .NET.
  • .NET es la plataforma: incluye el compilador, una biblioteca estándar enorme (la Base Class Library, BCL) y las herramientas de línea de comandos.
  • CLR (Common Language Runtime) es la máquina virtual que ejecuta el código ya compilado.

¿Qué es el CLR?

El CLR es el corazón del sistema. Es el equivalente a la JVM de Java o al motor V8 de Node.js: un programa que gestiona la ejecución de tu código en lugar de que tu código hable directamente con el sistema operativo.

El CLR se encarga de cosas que en otros lenguajes haces tú a mano:

  • Gestión de memoria: reserva y libera memoria automáticamente (el Garbage Collector).
  • Seguridad de tipos: garantiza que no leas memoria de un tipo como si fuera otro.
  • Manejo de excepciones: un sistema unificado de errores.
  • Compilación JIT: convierte el código intermedio en instrucciones de máquina justo antes de ejecutarlo.

El viaje del código: C# → IL → JIT → máquina

Cuando escribes C# no compilas directamente a código máquina (como C++). Ocurre un proceso en dos pasos:

C# (Program.cs) │ 1. Compilador de C# (dotnet build) ▼ IL (Intermediate Language) → se guarda en un archivo .dll │ 2. JIT (Just-In-Time, en tiempo de ejecución) ▼ Código máquina → lo que ejecuta tu CPU
  1. El compilador traduce tu C# a IL (Intermediate Language), un lenguaje de bajo nivel independiente del sistema operativo y del procesador.
  2. El JIT (Just-In-Time compiler) toma ese IL y, justo en el momento de ejecutarse, lo traduce a código máquina específico de tu CPU.
¿Por qué dos pasos?

Porque así el mismo archivo compilado (.dll) funciona en Windows, Linux y macOS sin recompilar. El JIT adapta el IL a cada máquina concreta. Además puede optimizar usando información real de ejecución (qué rutas de código se usan más).

Cuando instalas el SDK (que haremos en la próxima lección), obtienes también el runtime. Por eso un desarrollador solo necesita el SDK.

Versiones y el lío del nombre

La historia de .NET tiene un punto de confusión famoso que conviene resolver ya:

  • .NET Framework (2002–2019): el original, solo Windows, propiedad de Microsoft. Llegó hasta la versión 4.8 y no recibirá más versiones mayores.
  • .NET Core (2016–2019): reescritura multiplataforma (Windows, Linux, macOS) y de código abierto.
  • .NET 5/6/7/8 (2020–hoy): la continuación de .NET Core, pero sin el "Core" en el nombre. El curso usa .NET 8 (LTS).
Regla práctica

Si ves "Core" o un número 5 o mayor, es .NET moderno. Si ves ".NET Framework 4.x", es la tecnología antigua solo-Windows. En este curso usamos siempre .NET moderno.

3 · Ejemplo mínimo

No necesitas instalar nada para ver la relación entre C#, IL y el runtime: lo haremos al final. De momento, el ejemplo conceptual más pequeño:

// 1. Tú escribes C# (legible para humanos)
Console.WriteLine("Hola, .NET");

Al compilar, el compilador lo convierte en algo parecido a IL (más críptico, independiente de la máquina), y al ejecutar, el JIT lo convierte en código máquina. Tú nunca tocas ni el IL ni el código máquina: el toolchain lo hace por ti.

4 · Ejemplo real

Un caso real de por qué el modelo de .NET importa: imagina que publicas tu API en un servidor Linux, pero tu compañero desarrolla en Windows. Ambos escriben el mismo C#, ambos compilan el mismo IL, y cada uno ejecuta en su sistema operativo sin cambiar una línea. Esa es la promesa de la plataforma.

En la próxima lección instalarás el SDK y crearás tu primer proyecto; después verás el IL de verdad con una herramienta llamada ildasm o el paquete ilspy (no hace falta memorizarlo ahora).

9 · Resumen

  • .NET es una plataforma; C# es un lenguaje que se ejecuta sobre ella.
  • El CLR es la máquina virtual que ejecuta tu programa y gestiona memoria, tipos y errores.
  • El código viaja C# → IL → JIT → código máquina.
  • El SDK sirve para desarrollar; el Runtime, para ejecutar.
  • .NET moderno (Core / 5 / 6 / 7 / 8) es multiplataforma; .NET Framework es el viejo solo-Windows.

10 · Preguntas frecuentes

¿.NET es gratuito y de código abierto?

Sí. La implementación moderna (.NET) es de código abierto y gratuita, bajo la Fundación .NET. Solo el antiguo .NET Framework era cerrado.

¿C# es lo mismo que Java?

No, pero son parientes: C# se inspiró en Java (y en C++). La diferencia clave es que Java usa la JVM y C# usa el CLR. Si vienes de Java, aprenderás C# muy rápido.

¿Puedo escribir .NET en otro lenguaje que no sea C#?

Sí. F# es funcional y Visual Basic es más verboso. Pero C# es el estándar de la industria y el que usa este curso.

¿Qué significa que el JIT compila "justo a tiempo"?

Que el IL no se traduce a código máquina cuando compilas, sino en el momento exacto en que una parte del programa va a ejecutarse por primera vez. Así el mismo binario sirve para cualquier máquina.
