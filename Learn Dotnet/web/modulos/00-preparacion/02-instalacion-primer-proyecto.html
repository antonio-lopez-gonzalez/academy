Instalar el SDK y crear tu primer proyecto

Módulo 0 · Preparación 30 minutos

1 · Introducción

Ya sabes qué es .NET. Ahora lo ponemos en tu máquina y creamos un proyecto de verdad. Aquí aprenderás las herramientas que usarás todos los días como desarrollador .NET: la CLI dotnet y la estructura de un proyecto.

  • Instalar el SDK: descarga y verificación.
  • La CLI dotnet: new, build, run, restore.
  • El archivo .csproj: el "manifiesto" de tu proyecto.
  • El editor: VS Code o cualquier otro.
Objetivo

Al terminar podrás crear, compilar y ejecutar un proyecto de consola desde la terminal, sin depender de un IDE.

2 · Teoría

Instalar el SDK

Descarga el instalador oficial desde dotnet.microsoft.com/download (elige ".NET 8 SDK", no "Runtime", recuerda la diferencia de la lección anterior).

Para verificar que quedó bien instalado, abre una terminal y ejecuta:

dotnet --version

Deberías ver algo como 8.0.x. Si no reconoce el comando, reinicia la terminal o revisa que el PATH incluya la carpeta de instalación.

La CLI de .NET

dotnet es un único ejecutable con el que haces todo. Todos los comandos siguen el patrón:

dotnet [comando] [argumentos] [opciones]
ComandoQué hace
dotnet newCrea proyectos desde plantillas
dotnet restoreDescarga las dependencias (paquetes NuGet)
dotnet buildCompila (C# → IL)
dotnet runCompila + ejecuta
dotnet testEjecuta tests
dotnet publishGenera la versión para producción

build y run ejecutan restore automáticamente, así que rara vez lo llamarás a mano.

La estructura de un proyecto

Al crear un proyecto de consola obtienes una carpeta con, al menos, dos archivos importantes:

MiProyecto/
├── MiProyecto.csproj      ← manifiesto del proyecto
├── Program.cs             ← punto de entrada (tu código)
├── obj/                   ← archivos temporales de compilación
└── bin/                   ← resultado compilado (.dll con IL)

obj/ y bin/ se generan solos; no los edites ni los subas a Git (se ignoran con .gitignore).

El archivo .csproj

Es un archivo de texto (XML) que describe tu proyecto: qué tipo es, qué versión de .NET usa y qué dependencias tiene.

<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <OutputType>Exe</OutputType>
    <TargetFramework>net8.0</TargetFramework>
    <ImplicitUsings>enable</ImplicitUsings>
    <Nullable>enable</Nullable>
  </PropertyGroup>
</Project>
  • Sdk: tipo de proyecto (Microsoft.NET.Sdk = consola/librería; el de web es otro).
  • OutputType: Exe para programas ejecutables, Library para librerías.
  • TargetFramework: net8.0 es .NET 8 (multiplataforma).
  • ImplicitUsings: importa automáticamente los using más comunes.
  • Nullable: activa el análisis de nulos (lo veremos a fondo más adelante).

El editor

Puedes usar VS Code (con la extensión "C# Dev Kit"), Visual Studio (Windows) o JetBrains Rider. Para este curso basta VS Code o Rider. Lo importante: siempre podrás hacer todo con la CLI, independientemente del editor.

3 · Ejemplo mínimo

Crear, compilar y ejecutar en tres comandos:

# Crea un proyecto de consola llamado HolaMundo en la carpeta ./HolaMundo
dotnet new console -n HolaMundo -o ./HolaMundo

# Compila y ejecuta
dotnet run --project ./HolaMundo

Verás el mensaje Hello, World! en la terminal. Ese es el hola-mundo de .NET.

4 · Ejemplo real

Un flujo real de trabajo diario se ve así:

# 1. Ver plantillas disponibles
dotnet new list

# 2. Crear el proyecto
dotnet new console -n MiApiInterna -o ./MiApiInterna

# 3. Restaurar dependencias (implícito, pero se puede forzar)
dotnet restore

# 4. Compilar
dotnet build

# 5. Ejecutar
dotnet run

# 6. Publicar para producción
dotnet publish -c Release -o ./publicacion
Consejo

Fíjate en la salida de dotnet build: te dice si hay warnings o errors y dónde. Es tu primera herramienta de feedback.

6 · Errores habituales

Error 1: confundir net8.0 con net48

<!-- Incorrecto: .NET Framework 4.8 (viejo, solo Windows) -->
<TargetFramework>net48</TargetFramework>

<!-- Correcto: .NET 8 (moderno, multiplataforma) -->
<TargetFramework>net8.0</TargetFramework>

Error 2: "dotnet no se reconoce"

# Tras instalar, si el comando no existe:
# 1. Cierra y reabre la terminal (el PATH se actualiza).
# 2. Verifica con: dotnet --list-sdks

Error 3: editar archivos dentro de bin/ u obj/

// Incorrecto: modificar bin/.../app.dll a mano.
// Correcto: editar Program.cs y volver a compilar.

7 · Ejercicio guiado

  1. Instala el SDK de .NET 8 y verifica con dotnet --version.
  2. Crea un proyecto: dotnet new console -n MiPrimerProyecto -o ./MiPrimerProyecto.
  3. Ábrelo en tu editor y localiza MiPrimerProyecto.csproj y Program.cs.
  4. Ejecuta dotnet build y lee la salida.
  5. Ejecuta dotnet run y observa el mensaje.

8 · Reto

Reto

Crea un global.json que fije la versión 8.0 de tu SDK y comprueba con dotnet --version que ahora se usa esa versión dentro de la carpeta. Pista: el comando es dotnet new globaljson.

9 · Resumen

  • Instala el SDK (no solo el runtime) y verifica con dotnet --version.
  • dotnet new, build, run y restore son tu día a día.
  • El .csproj es el manifiesto del proyecto; Program.cs, el código.
  • bin/ y obj/ son generados; no se editan ni se versionan.

10 · Preguntas frecuentes

¿Necesito Visual Studio (el IDE grande)?

No. VS Code + la CLI cubren todo. Visual Studio es útil para WinForms/WPF o diseñadores visuales, que no usamos en este curso.

¿Qué es dotnet restore exactamente?

Lee las dependencias del .csproj, descarga los paquetes NuGet a una caché local y resuelve el grafo. build y run lo hacen implícitamente.

¿Puedo tener varias versiones del SDK instaladas?

Sí. dotnet --list-sdks las muestra. Con global.json eliges cuál usa cada proyecto.

¿Qué diferencia hay entre dotnet run y dotnet build?

build solo compila (genera el .dll). run compila y además lanza el programa. En el día a día usas run para probar.
