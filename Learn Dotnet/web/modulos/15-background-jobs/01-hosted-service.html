IHostedService y BackgroundService

Módulo 15 · Background Jobs30 min

1 · Introducción

En esta lección aprenderemos a ejecutar código en segundo plano dentro de una aplicación ASP.NET Core. Veremos dos abstracciones clave: IHostedService y BackgroundService.

Imagina que necesitas enviar un email cada vez que un usuario se registra, generar un informe nocturno o limpiar archivos temporales. Estas tareas no deben bloquear la respuesta HTTP. La solución son los hosted services: procesos que viven junto con la aplicación y se ejecutan en un hilo de fondo.

Al final de la lección sabrás cuándo usar cada abstracción, cómo gestionar el ciclo de vida, cómo reaccionar ante un cierre ordenado (graceful shutdown) y cómo evitar los errores más comunes.

Objetivo de aprendizaje: entender el ciclo de vida de un hosted service, implementar tareas periódicas con BackgroundService y garantizar que la aplicación cierra de forma limpia incluso si hay trabajo pendiente.

2 · Teoría

¿Qué es un hosted service?

Un hosted service es una pieza de código que el host de ASP.NET Core arranca cuando la aplicación inicia y detiene cuando la aplicación finaliza. Se integra en el contenedor de dependencias y participa en el ciclo de vida de la aplicación.

En Node.js existen librerías como node-cron o bull; en Java tenemos @Scheduled de Spring. En .NET, el mecanismo nativo es IHostedService.

IHostedService: el contrato mínimo

IHostedService define dos métodos:

  • StartAsync(CancellationToken): se invoca cuando el host arranca.
  • StopAsync(CancellationToken): se invoca cuando el host se detiene.

Si implementas esta interfaz directamente, eres responsable de crear y gestionar el hilo o tarea de fondo. Es la opción más flexible pero también la más verbosa.

BackgroundService: la base recomendada

BackgroundService es una clase abstracta que implementa IHostedService y oculta la gestión del hilo. Tú solo sobreescribes ExecuteAsync(CancellationToken stoppingToken), que es el método que contiene el bucle o la lógica de la tarea.

// Clase base que gestiona el ciclo de vida por nosotros
public abstract class BackgroundService : IHostedService, IDisposable
{
    protected abstract Task ExecuteAsync(CancellationToken stoppingToken);

    public virtual Task StartAsync(CancellationToken cancellationToken);
    public virtual Task StopAsync(CancellationToken cancellationToken);
    public virtual void Dispose();
}

Ciclo de vida y cancellation token

El parámetro stoppingToken se cancela cuando el host solicita el apagado. Comprobarlo periódicamente permite que el servicio termine limpiamente en lugar de ser abortado por el sistema operativo.

Cuidado: si ignoras stoppingToken, el servicio puede impedir que la aplicación se cierre en el tiempo previsto. En producción esto provoca que Docker o Kubernetes maten el contenedor de forma forzada.

Registro en el contenedor de DI

Los hosted services se registran con AddHostedService<T>. Normalmente se registran como singletons, aunque internamente el host crea una instancia por servicio. No intentes inyectar un servicio scoped directamente; debes crear un scope manual con IServiceScopeFactory.

3 · Ejemplo mínimo

Creamos un servicio de fondo que imprime un mensaje cada 5 segundos hasta que la aplicación se cierra.

// Program.cs de una aplicación de consola hospedada
var builder = Host.CreateApplicationBuilder(args);

// Registramos el servicio de fondo en el contenedor de DI
builder.Services.AddHostedService<HeartbeatService>();

var host = builder.Build();
await host.RunAsync();
// HeartbeatService.cs
public class HeartbeatService(ILogger<HeartbeatService> logger) : BackgroundService
{
    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        logger.LogInformation("Heartbeat iniciado");

        // El bucle se ejecuta hasta que el token se cancela
        while (!stoppingToken.IsCancellationRequested)
        {
            logger.LogInformation("Latido: {Time:HH:mm:ss}", DateTime.Now);

            try
            {
                // Delay que respeta la cancelación
                await Task.Delay(TimeSpan.FromSeconds(5), stoppingToken);
            }
            catch (OperationCanceledException)
            {
                // Se espera cuando el host solicita el cierre
                logger.LogInformation("Heartbeat cancelado");
                break;
            }
        }

        logger.LogInformation("Heartbeat finalizado");
    }
}

Para ejecutarlo:

# Creamos un worker service con la plantilla oficial
dotnet new worker -n HeartbeatDemo -o ejemplos/m15-background-jobs/HeartbeatDemo

# Ejecutamos el proyecto
dotnet run --project ejemplos/m15-background-jobs/HeartbeatDemo
Tip: la plantilla dotnet new worker crea exactamente este tipo de proyecto: un IHost sin servidor HTTP, pensado para procesos en segundo plano.

4 · Ejemplo real

Vamos a construir un servicio que limpia archivos temporales antiguos de una carpeta. Incluye inyección de configuración, creación manual de un scope para usar servicios scoped y manejo de excepciones.

// Opciones de configuración para el limpiador
public class CleanerOptions
{
    public string FolderPath { get; set; } = string.Empty;
    public int MaxAgeInHours { get; set; } = 24;
    public int IntervalInMinutes { get; set; } = 60;
}
// ICleanupRepository.cs
public interface ICleanupRepository
{
    Task MarkAsCleanedAsync(IEnumerable<string> fileNames, CancellationToken ct);
}
// TempFileCleanupService.cs
public class TempFileCleanupService(
    ILogger<TempFileCleanupService> logger,
    IOptions<CleanerOptions> options,
    IServiceScopeFactory scopeFactory) : BackgroundService
{
    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        var settings = options.Value;
        logger.LogInformation("Limpiador arrancado para {Folder}", settings.FolderPath);

        while (!stoppingToken.IsCancellationRequested)
        {
            try
            {
                await CleanOldFilesAsync(settings, stoppingToken);
            }
            catch (Exception ex) when (ex is not OperationCanceledException)
            {
                // Evitamos que un error rompa el bucle indefinidamente
                logger.LogError(ex, "Error durante la limpieza");
            }

            try
            {
                await Task.Delay(
                    TimeSpan.FromMinutes(settings.IntervalInMinutes),
                    stoppingToken);
            }
            catch (OperationCanceledException)
            {
                logger.LogInformation("Limpiador detenido");
                break;
            }
        }
    }

    private async Task CleanOldFilesAsync(CleanerOptions settings, CancellationToken ct)
    {
        if (!Directory.Exists(settings.FolderPath))
        {
            logger.LogWarning("La carpeta {Folder} no existe", settings.FolderPath);
            return;
        }

        var threshold = DateTime.UtcNow.AddHours(-settings.MaxAgeInHours);
        var files = Directory
            .EnumerateFiles(settings.FolderPath)
            .Where(f => File.GetLastWriteTimeUtc(f) < threshold)
            .ToList();

        foreach (var file in files)
        {
            File.Delete(file);
            logger.LogInformation("Archivo eliminado: {File}", file);
        }

        // Creamos un scope para usar un servicio scoped desde un singleton
        await using var scope = scopeFactory.CreateAsyncScope();
        var repository = scope.ServiceProvider.GetRequiredService<ICleanupRepository>();
        await repository.MarkAsCleanedAsync(files, ct);
    }
}
// Registro en Program.cs
builder.Services.Configure<CleanerOptions>(
    builder.Configuration.GetSection("Cleaner"));

builder.Services.AddScoped<ICleanupRepository, CleanupRepository>();
builder.Services.AddHostedService<TempFileCleanupService>();
Patrón importante: los BackgroundService son singletons. Si necesitas acceder a DbContext, repositorios o servicios scoped, crea un scope con IServiceScopeFactory.CreateAsyncScope() dentro del método que los usa.

5 · Buenas prácticas

  • Respeta siempre stoppingToken: comprueba IsCancellationRequested en cada iteración y en operaciones de espera.
  • Envuelve el trabajo en try/catch: una excepción no controlada en ExecuteAsync finalizará la tarea y el servicio dejará de ejecutarse.
  • No bloquees ExecuteAsync: el método debe devolver una Task que represente el trabajo de fondo. Si esperas de forma síncrona, el host no puede iniciar otros servicios.
  • Usa IOptions<T>: evita leer IConfiguration dentro del servicio. Las opciones tipadas son más fáciles de testear.
  • Usa IServiceScopeFactory para scopes: nunca inyectes un DbContext directamente en un BackgroundService.
  • Registra logs estructurados: usa ILogger<T> y Serilog para poder diagnosticar problemas en producción.

6 · Errores habituales

Error 1: inyectar un servicio scoped en un singleton

// ❌ MAL: provoca Captive Dependency
public class BadService(DbContext context) : BackgroundService { ... }

Por qué está mal: DbContext es scoped. El BackgroundService vive toda la vida de la aplicación, así que el contexto nunca se liberará y acabarás con datos obsoletos o fugas de memoria.

// ✅ BIEN: scope manual
await using var scope = scopeFactory.CreateAsyncScope();
var context = scope.ServiceProvider.GetRequiredService<DbContext>();

Error 2: bloquear ExecuteAsync

// ❌ MAL: el host no termina de arrancar
protected override Task ExecuteAsync(CancellationToken stoppingToken)
{
    while (!stoppingToken.IsCancellationRequested)
    {
        Thread.Sleep(1000); // bloquea el hilo
    }
    return Task.CompletedTask;
}
// ✅ BIEN: bucle asíncrono
protected override async Task ExecuteAsync(CancellationToken stoppingToken)
{
    while (!stoppingToken.IsCancellationRequested)
    {
        await Task.Delay(1000, stoppingToken);
    }
}

Error 3: ignorar la cancelación

Si usas await Task.Delay(TimeSpan.FromMinutes(10)) sin pasar el token, la aplicación tardará 10 minutos en cerrar. Siempre pasa stoppingToken a métodos que lo acepten.

7 · Ejercicio guiado

Crea un BackgroundService que cada 10 segundos escriba en un archivo de log local el número de veces que ha ejecutado el bucle.

  1. Crea un proyecto worker: dotnet new worker -n LoopLogger.
  2. Inyecta ILogger<LoopLoggerService>.
  3. En ExecuteAsync, inicializa un contador.
  4. En cada iteración escribe una línea en logs/loop.txt usando File.AppendAllTextAsync.
  5. Espera 10 segundos con stoppingToken.
  6. Captura OperationCanceledException para cerrar limpiamente.

Ejecuta el proyecto y comprueba que el archivo crece cada 10 segundos. Detén la aplicación con Ctrl+C y verifica que el mensaje de cierre aparece en la consola.

9 · Resumen

  • IHostedService es el contrato base para código que vive con la aplicación.
  • BackgroundService simplifica la implementación de bucles de fondo.
  • ExecuteAsync recibe un stoppingToken que debes respetar para un cierre limpio.
  • Los hosted services son singletones; usa IServiceScopeFactory para consumir servicios scoped.
  • Un try/catch dentro del bucle evita que un error detenga el servicio para siempre.

10 · Preguntas frecuentes

¿Puedo tener varios BackgroundService en la misma aplicación?

Sí. Puedes registrar varios con AddHostedService<T>. El host los inicia secuencialmente en el orden de registro.

¿Se ejecutan también en una Web API?

Sí. AddHostedService funciona tanto en aplicaciones web como en worker services. El host las ejecuta junto con el servidor HTTP.

¿Cómo puedo testear un BackgroundService?

Crea una instancia manualmente inyectando mocks de ILogger, IOptions o IServiceScopeFactory. Luego invoca StartAsync y cancela el token pasado para simular el apagado.

¿Qué ocurre si ExecuteAsync termina sin excepción?

El servicio se considera finalizado y no se reinicia automáticamente. Si necesitas un bucle infinito, asegúrate de que solo termine cuando el token se cancele.
