DDD táctico: Entities, Value Objects, Aggregates

Módulo 6 · Arquitectura y organización40 min

1. Introducción

Domain-Driven Design (DDD) no es solo un lenguaje común entre negocio y desarrollo. También nos da patrones tácticos para modelar el dominio: Entities, Value Objects, Aggregates, Domain Services y Domain Events.

En esta lección aprenderemos a reconocerlos, cuándo usarlos y cómo implementarlos en C# 12 para nuestro CMS.

¿Por qué importa?

El objetivo es que las reglas de negocio vivan en el código y sean fáciles de encontrar. Un aggregate encapsula invariantes que deben cumplirse siempre. Si no usamos estos patrones, la lógica se dispersa entre controllers y servicios.

Errores típicos

  • Usar clases POCO sin comportamiento para todo.
  • Permitir que cualquier parte del sistema modifique listas internas de una entidad.
  • Confundir entidades con value objects.
  • Almacenar eventos de dominio como logs en Application.

2. Teoría

Entities

Una entidad es un objeto que tiene identidad propia y continuidad a lo largo del tiempo. Dos entidades con los mismos datos pero distinto Id son distintas.

  • Tiene un identificador único (normalmente un GUID).
  • Su identidad no cambia aunque cambien sus atributos.
  • Encapsula comportamiento que modifica su estado.

Value Objects

Un value object no tiene identidad. Se define completamente por sus atributos. Dos value objects con los mismos valores son iguales.

  • Inmutables por convención.
  • Encapsulan conceptos pequeños: dinero, direcciones, slugs, emails.
  • En C# 12 se modelan fácilmente con record.

Ejemplo mental

Una persona es una entidad (tiene DNI). Su dirección es un value object: si cambia la calle, es otra dirección, no otra persona.

Aggregates

Un aggregate es un clúster de entidades y value objects que se trata como una única unidad de consistencia. Tiene una raíz del aggregate (aggregate root), que es la única entidad accesible desde fuera.

          ┌─────────────────────────────────────┐
          │         Post (Aggregate Root)       │
          │  ┌───────────────┐ ┌─────────────┐  │
          │  │   Comment     │ │    Tag      │  │
          │  │  (entity)     │ │ (value obj) │  │
          │  │               │ │             │  │
          │  │ ┌───────────┐ │ │             │  │
          │  │ │   Author  │ │ │             │  │
          │  │ │ (value)   │ │ │             │  │
          │  │ └───────────┘ │ │             │  │
          │  └───────────────┘ └─────────────┘  │
          └─────────────────────────────────────┘

Domain Services

Cuando una regla no pertenece a una sola entidad o value object, la colocamos en un domain service. No contiene lógica de infraestructura, solo coordinación de reglas de dominio.

Domain Events

Son eventos que ocurren dentro del dominio y que otras partes del sistema pueden reaccionar de forma desacoplada. Por ejemplo: PostPublishedDomainEvent puede ser manejado para actualizar un índice de búsqueda o enviar notificaciones.

Repositories

Hay un repositorio por aggregate root. El repositorio persiste y recupera el aggregate completo. No se crean repositorios para entidades internas de un aggregate.

3. Ejemplo mínimo

Modelaremos un Order como aggregate con líneas internas. La única forma de modificar las líneas es a través de la raíz.

dotnet new console -n DddTactical -o DddTactical
cd DddTactical

// Money.cs
namespace DddTactical;

// Value Object: inmutable, sin identidad, igualdad por valor
public sealed record Money(string Currency, decimal Amount);

// ProductId.cs
namespace DddTactical;

// Value Object que envuelve un GUID para tipado fuerte
public sealed record ProductId(Guid Value);

// OrderLine.cs
namespace DddTactical;

// Entity interna del aggregate. Solo Order debería crearla.
public sealed class OrderLine
{
    public ProductId ProductId { get; }
    public int Quantity { get; private set; }
    public Money UnitPrice { get; }

    public OrderLine(ProductId productId, int quantity, Money unitPrice)
    {
        if (quantity <= 0)
            throw new ArgumentException("La cantidad debe ser mayor a cero.");

        ProductId = productId;
        Quantity = quantity;
        UnitPrice = unitPrice;
    }

    public Money Total => UnitPrice with { Amount = UnitPrice.Amount * Quantity };
}

// Order.cs
namespace DddTactical;

// Aggregate Root: la única entidad a la que se accede desde fuera
public sealed class Order
{
    public Guid Id { get; private set; }
    private readonly List<OrderLine> _lines = new();
    public IReadOnlyCollection<OrderLine> Lines => _lines.AsReadOnly();

    public Order(Guid id) => Id = id;

    public void AddLine(ProductId productId, int quantity, Money unitPrice)
    {
        var existing = _lines.FirstOrDefault(l => l.ProductId == productId);
        if (existing is not null)
        {
            // Invariante: no duplicamos líneas del mismo producto
            existing.Quantity += quantity;
        }
        else
        {
            _lines.Add(new OrderLine(productId, quantity, unitPrice));
        }
    }

    public Money Total(string currency)
    {
        if (_lines.Any(l => l.UnitPrice.Currency != currency))
            throw new InvalidOperationException("Todas las líneas deben tener la misma moneda.");

        return new Money(currency, _lines.Sum(l => l.Total.Amount));
    }
}

// Program.cs
using DddTactical;

var order = new Order(Guid.NewGuid());
order.AddLine(new ProductId(Guid.NewGuid()), 2, new Money("EUR", 10m));
order.AddLine(new ProductId(Guid.NewGuid()), 1, new Money("EUR", 25m));

Console.WriteLine($"Total: {order.Total("EUR").Amount} {order.Total("EUR").Currency}");

Compilar y ejecutar

dotnet run

4. Ejemplo real

En nuestro CMS, Post es un aggregate root. Sus comentarios son entidades internas, y el slug o el estado de publicación pueden modelarse como value objects.

// Domain/ValueObjects/Slug.cs
namespace Cms.Domain.ValueObjects;

public sealed record Slug
{
    public string Value { get; }

    private Slug(string value) => Value = value;

    public static Slug Create(string title)
    {
        if (string.IsNullOrWhiteSpace(title))
            throw new ArgumentException("El título no puede estar vacío.", nameof(title));

        var slug = title.ToLowerInvariant()
                        .Replace(" ", "-")
                        .Replace("á", "a")
                        .Replace("é", "e")
                        .Replace("í", "i")
                        .Replace("ó", "o")
                        .Replace("ú", "u")
                        .Replace("ñ", "n");
        return new Slug(slug);
    }
}

// Domain/Entities/Comment.cs
namespace Cms.Domain.Entities;

public sealed class Comment
{
    public Guid Id { get; private set; }
    public string Author { get; private set; } = string.Empty;
    public string Content { get; private set; } = string.Empty;
    public DateTime CreatedAt { get; private set; }

    internal Comment(Guid id, string author, string content)
    {
        Id = id;
        Author = author;
        Content = content;
        CreatedAt = DateTime.UtcNow;
    }
}

// Domain/Entities/Post.cs
using Cms.Domain.Events;
using Cms.Domain.ValueObjects;

namespace Cms.Domain.Entities;

public sealed class Post
{
    public Guid Id { get; private set; }
    public string Title { get; private set; } = string.Empty;
    public Slug Slug { get; private set; } = null!;
    public string Content { get; private set; } = string.Empty;
    public bool IsPublished { get; private set; }
    private readonly List<Comment> _comments = new();
    public IReadOnlyCollection<Comment> Comments => _comments.AsReadOnly();

    private readonly List<DomainEvent> _domainEvents = new();
    public IReadOnlyCollection<DomainEvent> DomainEvents => _domainEvents.AsReadOnly();

    public static Post Create(string title, string content)
    {
        var post = new Post
        {
            Id = Guid.NewGuid(),
            Title = title,
            Slug = Slug.Create(title),
            Content = content
        };
        return post;
    }

    public void Publish()
    {
        if (IsPublished) return;
        IsPublished = true;
        _domainEvents.Add(new PostPublishedDomainEvent(Id, Title));
    }

    public void AddComment(string author, string content)
    {
        if (!IsPublished)
            throw new InvalidOperationException("No se puede comentar un borrador.");

        _comments.Add(new Comment(Guid.NewGuid(), author, content));
    }

    public void ClearDomainEvents() => _domainEvents.Clear();
}

// Domain/Events/PostPublishedDomainEvent.cs
namespace Cms.Domain.Events;

// Evento de dominio: representa algo que ocurrió y que otros pueden escuchar
public sealed record PostPublishedDomainEvent(Guid PostId, string Title) : DomainEvent;

public abstract record DomainEvent
{
    public Guid Id { get; } = Guid.NewGuid();
    public DateTime OccurredOn { get; } = DateTime.UtcNow;
}

¿Por qué internal en Comment?

Para evitar que código externo al aggregate cree comentarios directamente. La raíz (Post) controla su creación. Esto protege invariantes como "no comentar borradores".

5. Buenas prácticas

  • Inmutabilidad para value objects: Usa record o clases con setters privados.
  • Constructores privados: Obligan a usar factories estáticas que validen invariantes.
  • Colecciones de solo lectura: Expón IReadOnlyCollection<T> en lugar de List<T>.
  • Un repositorio por aggregate: No crees ICommentRepository; accede a comentarios a través de IPostRepository.
  • Domain events inmutables: Modela eventos como record y publícalos desde el aggregate.

6. Errores habituales

❌ Exponer listas mutables

public List<Comment> Comments { get; set; } = new();

Cualquiera puede agregar o quitar comentarios sin pasar por Post.AddComment, rompiendo invariantes.

✅ Correcto

private readonly List<Comment> _comments = new();
public IReadOnlyCollection<Comment> Comments => _comments.AsReadOnly();

❌ Entidad con solo datos

public class Post
{
    public Guid Id { get; set; }
    public string Title { get; set; } = string.Empty;
    public bool IsPublished { get; set; }
}

Sin comportamiento, la lógica de negocio acaba en servicios de aplicación gigantes.

✅ Correcto

Encapsula transiciones de estado como Publish(), UpdateTitle(), etc., y valida dentro de la entidad.

7. Ejercicio guiado

Modela el aggregate Category del CMS.

  1. Crea un value object CategoryName que valide longitud entre 3 y 50 caracteres.
  2. Crea la entidad Category como aggregate root con Id, Name y una lista de PostSummary (otro value object).
  3. Añade el método AddPost(PostSummary post) que impida duplicados por Id.
  4. Implementa un evento de dominio PostAddedToCategoryDomainEvent.

Pista

public sealed record CategoryName
{
    public string Value { get; }
    private CategoryName(string value) => Value = value;
    public static CategoryName Create(string value)
    {
        if (value.Length is < 3 or > 50)
            throw new ArgumentException("Nombre inválido.");
        return new CategoryName(value);
    }
}

9. Resumen

  • Las Entities tienen identidad y continuidad en el tiempo.
  • Los Value Objects se identifican por sus valores; úsalos para conceptos pequeños e inmutables.
  • Los Aggregates agrupan entidades y value objects bajo una raíz que garantiza invariantes.
  • Los Domain Services contienen lógica que no pertenece a una sola entidad.
  • Los Domain Events desacoplan reacciones a cambios en el dominio.

10. Preguntas frecuentes

¿Puedo usar records para entidades?

Desaconsejado. Los records están diseñados para igualdad por valor, y las entidades se identifican por Id. Puedes usarlos para value objects, pero para entidades usa clases con setters privados.

¿Dónde se publican los domain events?

Desde el aggregate root. Luego, la capa de persistencia o un middleware de MediatR los lee de DomainEvents y los despacha a los handlers.

¿Cómo persisto aggregates con EF Core?

Configura la raíz como entidad principal y las entidades internas como OwnsMany o HasMany según necesites. Veremos esto en el módulo de Entity Framework Core.

¿Un repositorio por aggregate o por entidad?

Uno por aggregate root. Las entidades internas solo se acceden a través de él. Esto mantiene los límites de consistencia claros.
