CQRS con MediatR

Módulo 6 · Arquitectura y organización40 min

1 · Introducción

CQRS (Command Query Responsibility Segregation) separa las operaciones que modifican estado (commands) de las que solo leen (queries). En .NET, MediatR es la librería más usada para implementar este patrón de forma limpia.

En esta lección veremos qué es CQRS, cuándo aporta valor y cómo MediatR nos ayuda a desacoplar los endpoints de los handlers con pipelines transversales.

¿Qué resolveremos?

Evitar controladores o Minimal APIs con lógica de negocio mezclada. Cada operación tendrá su propio mensaje y su propio handler, lo que facilita testear, versionar y escalar por separado lecturas y escrituras.

Errores típicos

  • Aplicar CQRS a un CRUD simple sin necesidad, aumentando la complejidad.
  • Mezclar commands y queries en el mismo handler.
  • Olvidar que un command debe devolver el mínimo de datos posible.
  • Registrar handlers como transient sin entender el lifetime del DbContext.

2 · Teoría

Commands

Un command representa una intención de cambiar el estado del sistema. Por convención:

  • Se nombran con verbo en imperativo: CreatePostCommand, PublishPostCommand.
  • Devuelven el identificador creado o un Result; nunca devuelven entidades completas.
  • Son procesados por un IRequestHandler<TCommand, TResponse>.

Queries

Una query representa una pregunta que no modifica estado. Por convención:

  • Se nombran con sustantivo: GetPostByIdQuery, ListPostsQuery.
  • Devuelven DTOs planos optimizados para lectura.
  • También usan IRequestHandler<TQuery, TResponse>.

MediatR

MediatR implementa el patrón Mediator: los componentes no se llaman directamente, envían mensajes a través de un mediador central. Esto reduce el acoplamiento y permite interceptar los mensajes con pipelines.

  Endpoint (API)
      │
      ▼
  ISender.Send(command/query)
      │
      ▼
  MediatR
      │
      ├──▶ PipelineBehavior 1 (logging)
      ├──▶ PipelineBehavior 2 (validación)
      ├──▶ PipelineBehavior 3 (transacción)
      │
      ▼
  IRequestHandler
      │
      ▼
  Application / Domain

IPipelineBehavior

IPipelineBehavior<TRequest, TResponse> envuelve la ejecución de todos los handlers. Es ideal para:

  • Logging transversal.
  • Validación con FluentValidation.
  • Transacciones de EF Core.
  • Métricas y trazas de OpenTelemetry.

3 · Ejemplo mínimo

Crearemos un proyecto console/web mínimo con dos handlers: uno para crear un post (command) y otro para obtenerlo (query).

dotnet new console -n CqrsMediatRMini -o CqrsMediatRMini
cd CqrsMediatRMini
dotnet add package MediatR --version 12.2.0

// Program.cs
using CqrsMediatRMini;
using MediatR;
using Microsoft.Extensions.DependencyInjection;

var services = new ServiceCollection();
services.AddMediatR(cfg => cfg.RegisterServicesFromAssembly(typeof(Program).Assembly));

var provider = services.BuildServiceProvider();
var sender = provider.GetRequiredService<ISender>();

var id = await sender.Send(new CreatePostCommand("Hola CQRS", "Contenido"));
Console.WriteLine($"Creado: {id}");

var post = await sender.Send(new GetPostByIdQuery(id));
Console.WriteLine($"Leído: {post?.Title}");

// CreatePostCommand.cs
using MediatR;

namespace CqrsMediatRMini;

public sealed record CreatePostCommand(string Title, string Content) : IRequest<Guid>;

public sealed class CreatePostHandler : IRequestHandler<CreatePostCommand, Guid>
{
    private static readonly Dictionary<Guid, Post> Store = new();

    public Task<Guid> Handle(CreatePostCommand request, CancellationToken cancellationToken)
    {
        var post = new Post(Guid.NewGuid(), request.Title, request.Content);
        Store[post.Id] = post;
        return Task.FromResult(post.Id);
    }
}

public sealed record Post(Guid Id, string Title, string Content);

// GetPostByIdQuery.cs
using MediatR;

namespace CqrsMediatRMini;

public sealed record GetPostByIdQuery(Guid Id) : IRequest<Post?>;

public sealed class GetPostByIdHandler : IRequestHandler<GetPostByIdQuery, Post?>
{
    public Task<Post?> Handle(GetPostByIdQuery request, CancellationToken cancellationToken)
    {
        CreatePostHandler.Store.TryGetValue(request.Id, out var post);
        return Task.FromResult(post);
    }
}

4 · Ejemplo real

Añadimos pipelines de logging y transacciones a los handlers del CMS. Esto se ejecuta automáticamente para todos los comandos y queries.

// Application/Behaviors/LoggingBehavior.cs
using MediatR;
using Microsoft.Extensions.Logging;

namespace Cms.Application.Behaviors;

public sealed class LoggingBehavior<TRequest, TResponse>(ILogger<LoggingBehavior<TRequest, TResponse>> logger)
    : IPipelineBehavior<TRequest, TResponse>
    where TRequest : notnull
{
    public async Task<TResponse> Handle(
        TRequest request,
        RequestHandlerDelegate<TResponse> next,
        CancellationToken cancellationToken)
    {
        logger.LogInformation("Ejecutando {RequestType}", typeof(TRequest).Name);
        var response = await next();
        logger.LogInformation("Completado {RequestType}", typeof(TRequest).Name);
        return response;
    }
}

// Application/Behaviors/TransactionBehavior.cs
using MediatR;
using Cms.Domain;

namespace Cms.Application.Behaviors;

// Ejecuta commands dentro de una transacción de EF Core
public sealed class TransactionBehavior<TRequest, TResponse>(IUnitOfWork unitOfWork)
    : IPipelineBehavior<TRequest, TResponse>
    where TRequest : notnull
{
    public async Task<TResponse> Handle(
        TRequest request,
        RequestHandlerDelegate<TResponse> next,
        CancellationToken cancellationToken)
    {
        if (request is not ICommand) return await next();

        await unitOfWork.BeginTransactionAsync(cancellationToken);
        try
        {
            var response = await next();
            await unitOfWork.CommitTransactionAsync(cancellationToken);
            return response;
        }
        catch
        {
            await unitOfWork.RollbackTransactionAsync(cancellationToken);
            throw;
        }
    }
}

public interface ICommand { }

// Application/DependencyInjection.cs
using Cms.Application.Behaviors;
using Microsoft.Extensions.DependencyInjection;

namespace Cms.Application;

public static class DependencyInjection
{
    public static IServiceCollection AddApplication(this IServiceCollection services)
    {
        services.AddMediatR(cfg =>
        {
            cfg.RegisterServicesFromAssembly(typeof(DependencyInjection).Assembly);
            cfg.AddBehavior(typeof(IPipelineBehavior<,>), typeof(LoggingBehavior<,>));
            cfg.AddBehavior(typeof(IPipelineBehavior<,>), typeof(TransactionBehavior<,>));
        });

        return services;
    }
}

// Application/Features/Posts/CreatePost/CreatePostCommand.cs
using MediatR;

namespace Cms.Application.Features.Posts.CreatePost;

// Marca el comando para que el pipeline de transacciones lo intercepte
public sealed record CreatePostCommand(string Title, string Content)
    : IRequest<Guid>, ICommand;

Orden de pipelines

MediatR ejecuta los behaviors en el orden en que se registran. Generalmente quieres logging primero, luego validación y finalmente transacciones, para que el try/catch de la transacción envuelva la lógica de negocio.

5 · Buenas prácticas

  • Commands: verbos en imperativo, modifican estado, devuelven poca información.
  • Queries: sustantivos, no modifican estado, devuelven DTOs planos.
  • Un handler por mensaje: No combines varias responsabilidades en un solo handler.
  • Pipelines ligeros: No pongas lógica de negocio en behaviors; solo concerns transversales.
  • Validación en pipeline: Usa FluentValidation con AddBehavior para validar antes de entrar al handler.

6 · Errores habituales

❌ Query que muta estado

public async Task<PostDto> Handle(GetPostByIdQuery request, ...)
{
    var post = await _repo.GetByIdAsync(request.Id);
    post.Views++; // ¡Esto es un command disfrazado de query!
    await _repo.SaveChangesAsync();
    return Map(post);
}

✅ Correcto

Crea un comando separado IncrementPostViewsCommand si necesitas contar visitas.

❌ Handler con muchas dependencias

public class CreatePostHandler(
    IPostRepository posts,
    ICategoryRepository categories,
    ITagRepository tags,
    IEmailService email,
    ILogger<CreatePostHandler> logger,
    ISearchClient search,
    ICacheService cache) : IRequestHandler<CreatePostCommand, Guid>

Si un handler tiene muchas dependencias, probablemente esté haciendo demasiado. Considera extraer domain events o un application service.

7 · Ejercicio guiado

Extiende el ejemplo mínimo con un pipeline de validación simple.

  1. Crea ValidationBehavior<TRequest, TResponse> que verifique si Title está vacío antes de ejecutar el handler.
  2. Registra el behavior en AddMediatR.
  3. Prueba enviar un comando con título vacío y observa que se lanza una excepción antes de llegar al handler.

Pista

public sealed class ValidationBehavior<TRequest, TResponse>
    : IPipelineBehavior<TRequest, TResponse> where TRequest : notnull
{
    public async Task<TResponse> Handle(
        TRequest request,
        RequestHandlerDelegate<TResponse> next,
        CancellationToken cancellationToken)
    {
        if (request is CreatePostCommand cmd && string.IsNullOrWhiteSpace(cmd.Title))
            throw new ArgumentException("El título es obligatorio.");

        return await next();
    }
}

8 · Reto

Implementa un pipeline genérico de validación con FluentValidation. Crea un IValidatable y un ValidationBehavior<TRequest, TResponse> que use IValidator<TRequest>. Aplica validadores a CreatePostCommand y PublishPostCommand.

No resuelvas el reto todavía. FluentValidation lo veremos en el módulo 9, pero puedes adelantar conceptos si te sientes cómodo.

9 · Resumen

  • CQRS separa commands (escrituras) de queries (lecturas).
  • MediatR implementa el patrón Mediator con IRequest y IRequestHandler.
  • IPipelineBehavior permite logging, validación y transacciones transversales.
  • Registra behaviors en el orden correcto: logging → validación → transacción.
  • No apliques CQRS a cualquier CRUD; evalúa si la separación aporta valor.

10 · Preguntas frecuentes

¿MediatR es obligatorio para CQRS?

No. Puedes implementar CQRS manualmente con interfaces propias. MediatR simplemente estandariza el patrón y añade pipelines.

¿Puedo usar ISender desde Minimal APIs?

Sí. Inyectas ISender en el delegate del endpoint y envías el comando o query.

¿Un command siempre debe devolver void?

No necesariamente. Es aceptable devolver el Id creado o un Result. Lo que se evita es devolver entidades completas o DTOs de lectura.

¿Cómo manejo errores en MediatR?

Puedes usar excepciones para casos excepcionales o un Result<T> para errores esperados. Veremos el Result pattern en la siguiente lección.
