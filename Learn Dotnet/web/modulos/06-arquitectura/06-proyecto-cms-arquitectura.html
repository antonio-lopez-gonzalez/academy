Proyecto CMS: Clean Architecture + CQRS

Módulo 6 · Arquitectura y organización55 min

1. Introducción

En este proyecto práctico vamos a darle forma real al CMS que construimos en los módulos anteriores. Aplicaremos Clean Architecture, Vertical Slices, CQRS con MediatR y el Result pattern en un solo proyecto estructurado.

Al finalizar tendrás una solución con cuatro proyectos (Cms.Domain, Cms.Application, Cms.Infrastructure, Cms.Api) y un primer endpoint funcional para crear y consultar posts.

Objetivos del proyecto

  • Separar físicamente Domain, Application, Infrastructure y Presentation.
  • Organizar Application por Vertical Slices.
  • Implementar un command y un query con MediatR.
  • Aplicar el Result pattern para manejar errores.
  • Configurar DI sin romper la regla de dependencia.

2. Teoría

El CMS sigue una arquitectura limpia con capas concéntricas. Dentro de la capa de aplicación organizamos por features (slices) para maximizar la cohesión.

Decisiones de diseño

  • Domain no depende de nada. Contiene Post, Slug y el evento de dominio.
  • Application define Result<T>, IPostRepository e IUnitOfWork. Implementa handlers de MediatR.
  • Infrastructure implementa CmsDbContext y EfPostRepository usando Entity Framework Core (configurado en memoria para esta primera iteración).
  • Api compone todo, mapea Result a HTTP y expone endpoints.

4. Ejemplo real

Implementamos paso a paso el primer flujo del CMS: crear y consultar un post.

// src/Cms.Domain/ValueObjects/Slug.cs
namespace Cms.Domain.ValueObjects;

public sealed record Slug
{
    public string Value { get; }
    private Slug(string value) => Value = value;

    public static Slug Create(string title)
    {
        if (string.IsNullOrWhiteSpace(title))
            throw new ArgumentException("El título no puede estar vacío.", nameof(title));

        var normalized = title.ToLowerInvariant()
            .Replace(" ", "-")
            .Replace("á", "a")
            .Replace("é", "e")
            .Replace("í", "i")
            .Replace("ó", "o")
            .Replace("ú", "u")
            .Replace("ñ", "n");

        return new Slug(normalized);
    }
}

// src/Cms.Domain/Entities/Post.cs
using Cms.Domain.Events;
using Cms.Domain.ValueObjects;

namespace Cms.Domain.Entities;

public sealed class Post
{
    public Guid Id { get; private set; }
    public string Title { get; private set; } = string.Empty;
    public Slug Slug { get; private set; } = null!;
    public string Content { get; private set; } = string.Empty;
    public bool IsPublished { get; private set; }
    public DateTime CreatedAt { get; private set; }

    private readonly List<DomainEvent> _domainEvents = new();
    public IReadOnlyCollection<DomainEvent> DomainEvents => _domainEvents.AsReadOnly();

    public static Post Create(string title, string content)
    {
        var post = new Post
        {
            Id = Guid.NewGuid(),
            Title = title,
            Slug = Slug.Create(title),
            Content = content,
            CreatedAt = DateTime.UtcNow
        };
        post._domainEvents.Add(new PostCreatedDomainEvent(post.Id, post.Title));
        return post;
    }

    public void Publish() => IsPublished = true;
    public void ClearDomainEvents() => _domainEvents.Clear();
}

// src/Cms.Application/Abstractions/Result.cs
namespace Cms.Application.Abstractions;

public sealed class Result<T>
{
    public bool IsSuccess { get; }
    public bool IsFailure => !IsSuccess;
    public T Value { get; }
    public Error Error { get; }

    private Result(T value) { IsSuccess = true; Value = value; Error = Error.None; }
    private Result(Error error) { IsSuccess = false; Error = error; Value = default!; }

    public static Result<T> Success(T value) => new(value);
    public static Result<T> Failure(Error error) => new(error);
}

public sealed record Error(string Code, string Message, ErrorType Type)
{
    public static readonly Error None = new(string.Empty, string.Empty, ErrorType.Failure);
    public static Error NotFound(string code, string message) => new(code, message, ErrorType.NotFound);
    public static Error Validation(string code, string message) => new(code, message, ErrorType.Validation);
}

public enum ErrorType { Failure, Validation, NotFound, Conflict, Unauthorized }

// src/Cms.Application/Abstractions/IUnitOfWork.cs
namespace Cms.Application.Abstractions;

public interface IUnitOfWork
{
    Task<int> SaveChangesAsync(CancellationToken cancellationToken = default);
}

// src/Cms.Application/Features/Posts/CreatePost/CreatePostCommand.cs
using Cms.Application.Abstractions;
using MediatR;

namespace Cms.Application.Features.Posts.CreatePost;

public sealed record CreatePostCommand(string Title, string Content)
    : IRequest<Result<Guid>>;

// src/Cms.Application/Features/Posts/CreatePost/CreatePostHandler.cs
using Cms.Application.Abstractions;
using Cms.Domain.Entities;
using Cms.Domain.Repositories;
using MediatR;

namespace Cms.Application.Features.Posts.CreatePost;

public sealed class CreatePostHandler(IPostRepository posts, IUnitOfWork unitOfWork)
    : IRequestHandler<CreatePostCommand, Result<Guid>>
{
    public async Task<Result<Guid>> Handle(CreatePostCommand request, CancellationToken cancellationToken)
    {
        if (string.IsNullOrWhiteSpace(request.Title))
            return Result<Guid>.Failure(Error.Validation("Post.TitleRequired", "El título es obligatorio."));

        var post = Post.Create(request.Title, request.Content);
        await posts.AddAsync(post);
        await unitOfWork.SaveChangesAsync(cancellationToken);

        return Result<Guid>.Success(post.Id);
    }
}

// src/Cms.Application/Features/Posts/GetPostById/GetPostByIdQuery.cs
using Cms.Application.Abstractions;
using MediatR;

namespace Cms.Application.Features.Posts.GetPostById;

public sealed record GetPostByIdQuery(Guid Id) : IRequest<Result<PostDto>>;

public sealed record PostDto(Guid Id, string Title, string Slug, string Content, bool IsPublished, DateTime CreatedAt);

// src/Cms.Application/Features/Posts/GetPostById/GetPostByIdHandler.cs
using Cms.Application.Abstractions;
using Cms.Domain.Repositories;
using MediatR;

namespace Cms.Application.Features.Posts.GetPostById;

public sealed class GetPostByIdHandler(IPostRepository posts)
    : IRequestHandler<GetPostByIdQuery, Result<PostDto>>
{
    public async Task<Result<PostDto>> Handle(GetPostByIdQuery request, CancellationToken cancellationToken)
    {
        var post = await posts.GetByIdAsync(request.Id);
        if (post is null)
            return Result<PostDto>.Failure(Error.NotFound("Post.NotFound", $"Post {request.Id} no encontrado."));

        return Result<PostDto>.Success(
            new PostDto(post.Id, post.Title, post.Slug.Value, post.Content, post.IsPublished, post.CreatedAt));
    }
}

// src/Cms.Application/Behaviors/LoggingBehavior.cs
using MediatR;
using Microsoft.Extensions.Logging;

namespace Cms.Application.Behaviors;

public sealed class LoggingBehavior<TRequest, TResponse>(ILogger<LoggingBehavior<TRequest, TResponse>> logger)
    : IPipelineBehavior<TRequest, TResponse> where TRequest : notnull
{
    public async Task<TResponse> Handle(
        TRequest request,
        RequestHandlerDelegate<TResponse> next,
        CancellationToken cancellationToken)
    {
        logger.LogInformation("Handling {RequestType}", typeof(TRequest).Name);
        var response = await next();
        logger.LogInformation("Handled {RequestType}", typeof(TRequest).Name);
        return response;
    }
}

public static class DependencyInjection
{
    public static IServiceCollection AddApplication(this IServiceCollection services)
    {

// src/Cms.Infrastructure/Persistence/CmsDbContext.cs
using Cms.Domain.Entities;
using Microsoft.EntityFrameworkCore;

namespace Cms.Infrastructure.Persistence;

public sealed class CmsDbContext : DbContext
{
    public CmsDbContext(DbContextOptions<CmsDbContext> options) : base(options) { }

    public DbSet<Post> Posts => Set<Post>();

    protected override void OnModelCreating(ModelBuilder modelBuilder)
    {
        modelBuilder.Entity<Post>(entity =>
        {
            entity.HasKey(e => e.Id);
            entity.Property(e => e.Title).HasMaxLength(200).IsRequired();
            entity.Property(e => e.Content).IsRequired();
            entity.OwnsOne(e => e.Slug, slug =>
            {
                slug.Property(s => s.Value).HasColumnName("Slug").HasMaxLength(200).IsRequired();
            });
        });
    }
}

// src/Cms.Infrastructure/Persistence/EfPostRepository.cs
using Cms.Domain.Entities;
using Cms.Domain.Repositories;
using Microsoft.EntityFrameworkCore;

namespace Cms.Infrastructure.Persistence;

public sealed class EfPostRepository(CmsDbContext context) : IPostRepository
{
    public Task<Post?> GetByIdAsync(Guid id) =>
        context.Posts.AsNoTracking().FirstOrDefaultAsync(p => p.Id == id);

    public async Task AddAsync(Post post)
    {
        await context.Posts.AddAsync(post);
    }
}

// src/Cms.Infrastructure/DependencyInjection.cs
using Cms.Domain.Repositories;
using Cms.Infrastructure.Persistence;
using Microsoft.EntityFrameworkCore;
using Microsoft.Extensions.Configuration;
using Microsoft.Extensions.DependencyInjection;

namespace Cms.Infrastructure;

public static class DependencyInjection
{
    public static IServiceCollection AddInfrastructure(
        this IServiceCollection services,
        IConfiguration configuration)
    {
        services.AddDbContext<CmsDbContext>(options =>
            options.UseInMemoryDatabase("CmsDb"));

        services.AddScoped<IPostRepository, EfPostRepository>();
        services.AddScoped<Cms.Application.Abstractions.IUnitOfWork, CmsDbContext>();

        return services;
    }
}

// src/Cms.Api/Features/Posts/PostsEndpoints.cs
using Cms.Application.Abstractions;
using Cms.Application.Features.Posts.CreatePost;
using Cms.Application.Features.Posts.GetPostById;
using MediatR;

namespace Cms.Api.Features.Posts;

public static class PostsEndpoints
{
    public static IEndpointRouteBuilder MapPostEndpoints(this IEndpointRouteBuilder app)
    {
        app.MapPost("/api/posts", async (CreatePostCommand command, ISender sender) =>
        {
            var result = await sender.Send(command);
            return result.IsSuccess
                ? Results.Created($"/api/posts/{result.Value}", result.Value)
                : MapError(result.Error);
        });

        app.MapGet("/api/posts/{id:guid}", async (Guid id, ISender sender) =>
        {
            var result = await sender.Send(new GetPostByIdQuery(id));
            return result.IsSuccess
                ? Results.Ok(result.Value)
                : MapError(result.Error);
        });

        return app;
    }

    private static IResult MapError(Error error) =>
        error.Type switch
        {
            ErrorType.NotFound => Results.NotFound(),
            ErrorType.Validation => Results.BadRequest(new { error.Code, error.Message }),
            _ => Results.Problem(error.Message)
        };
}

5. Buenas prácticas

  • Domain sin dependencias externas: No references a EF Core, JSON ni HTTP en Cms.Domain.
  • Application orquesta: Handlers, DTOs, abstracciones y behaviors. No conoce ASP.NET Core.
  • Infrastructure implementa: Repositorios, DbContext, servicios externos. Depende de Application.
  • Api es un adaptador: Solo endpoints, DI, middleware y configuración.
  • Vertical Slices en Application: Cada feature tiene su propio command/query, handler, validator y DTO.
  • Result pattern: Errores de negocio se propagan tipados y la API los convierte a status codes.

6. Errores habituales

❌ Referenciar Infrastructure desde Application

<!-- PROHIBIDO en Cms.Application.csproj -->
<ProjectReference Include="..\Cms.Infrastructure\Cms.Infrastructure.csproj" />

Application debe depender de abstracciones, no de implementaciones. La API es la que conoce Infrastructure.

❌ Devolver entidades de dominio desde handlers

public async Task<Post> Handle(GetPostByIdQuery request, ...)

Devuelve DTOs. Las entidades de dominio no deben exponerse directamente en la API.

❌ Repository con lógica de negocio

public async Task AddAsync(Post post)
{
    if (post.Title.Length < 5) throw new InvalidOperationException("Título corto");
    await _context.Posts.AddAsync(post);
}

La validación de negocio debe estar en el handler o en el dominio. El repositorio solo persiste.

7. Ejercicio guiado

Extiende el CMS con la funcionalidad de publicar un post.

  1. En Domain, añade el método Post.Publish() y el evento PostPublishedDomainEvent.
  2. En Application, crea PublishPostCommand y PublishPostHandler que devuelva Result<Unit> (o Result<bool>).
  3. En Api, añade el endpoint POST /api/posts/{id}/publish.
  4. Prueba el flujo: crear → consultar → publicar → consultar.

Pista

public sealed record PublishPostCommand(Guid Id) : IRequest<Result<bool>>;

public sealed class PublishPostHandler(IPostRepository posts, IUnitOfWork unitOfWork)
    : IRequestHandler<PublishPostCommand, Result<bool>>
{
    public async Task<Result<bool>> Handle(PublishPostCommand request, CancellationToken cancellationToken)
    {
        var post = await posts.GetByIdAsync(request.Id);
        if (post is null)
            return Result<bool>.Failure(Error.NotFound("Post.NotFound", ...));

        post.Publish();
        await unitOfWork.SaveChangesAsync(cancellationToken);
        return Result<bool>.Success(true);
    }
}

9. Resumen

  • El CMS se estructura en cuatro proyectos: Domain, Application, Infrastructure, Api.
  • Application organiza handlers por Vertical Slices (features).
  • MediatR desacopla endpoints de la lógica de negocio.
  • Result pattern permite manejar errores de negocio sin excepciones.
  • La regla de dependencia se protege mediante referencias de proyecto controladas.
  • El pipeline de logging se ejecuta automáticamente para todos los mensajes.

10. Preguntas frecuentes

¿Por qué usar InMemoryDatabase en esta primera iteración?

Para enfocarnos en la arquitectura sin depender de una base de datos real. En el módulo de EF Core reemplazaremos InMemory por PostgreSQL con migraciones.

¿Dónde van los validadores con FluentValidation?

En cada slice, junto al command. Luego se registra un pipeline de validación para ejecutarlos automáticamente antes del handler.

¿Puedo usar controllers en lugar de Minimal APIs?

Sí. Clean Architecture y CQRS son independientes del estilo de API. Los controllers inyectan ISender y delegan en handlers igual que los endpoints.

¿Cómo testeo los handlers?

Los tests unitarios de handlers usan repositorios en memoria. Los tests de integración usan WebApplicationFactory. Lo veremos en el módulo de testing.

¿Qué sigue después?

En el módulo de Entity Framework Core conectaremos PostgreSQL, configuraremos migraciones y añadiremos relaciones entre posts, categorías y tags.
