AutoMapper vs mapeo manual

Módulo 9 · Validación y mapeo30 min

1 · Introducción

En esta lección aprenderemos a transformar objetos entre capas de una aplicación: del dominio a la aplicación, de la aplicación a la API, de la API a la base de datos. Compararemos dos enfoques:

  • Mapeo manual con métodos de extensión o constructores.
  • AutoMapper, una librería que genera el mapeo por convención.

Veremos cuándo usar cada uno, los peligros de ocultar la lógica de mapeo y cómo asegurar que el mapeo es correcto en tiempo de arranque.

Objetivos de la lección

  • Implementar mapeo manual con métodos de extensión.
  • Configurar perfiles de AutoMapper.
  • Usar ProjectTo con Entity Framework Core.
  • Validar la configuración con AssertConfigurationIsValid.
  • Decidir cuándo usar cada estrategia.

2 · Teoría

2.1. ¿Por qué necesitamos mapear?

En una aplicación bien organizada, cada capa tiene sus propios modelos:

  • Dominio: entidades ricas, protegen invariantes de negocio.
  • Aplicación: comandos, queries, DTOs de entrada y salida.
  • Infraestructura: modelos de EF Core, eventos de persistencia.
  • API: contratos de entrada y salida, optimizados para JSON.

El mapeo es la conversión entre estos modelos. Es una tarea repetitiva pero delicada: un campo mal mapeado puede filtrar datos internos, romper la inmutabilidad o causar errores de serialización.

2.2. Mapeo manual

El mapeo manual es simplemente escribir código que convierte un objeto en otro. La ventaja es que es explícito, fácil de depurar y no añade dependencias externas.

La desventaja es que, en proyectos grandes, puede generar mucho código repetitivo. La solución es encapsularlo en métodos de extensión o constructores estáticos.

2.3. AutoMapper

AutoMapper es una librería que, mediante convención, intenta mapear propiedades con el mismo nombre y tipo. Si hay discrepancias, configuras perfiles con CreateMap.

Ventajas:

  • Reduce el código repetitivo en mapeos triviales.
  • Facilita refactorizar nombres de propiedades sin romper mapeos.
  • ProjectTo permite proyectar directamente en la base de datos, optimizando consultas.

Desventajas:

  • Esconde la lógica de conversión.
  • Errores de configuración a veces aparecen en tiempo de ejecución.
  • Facilita filtrar campos sensibles si no se configura explícitamente.

Comparación honesta

Para proyectos pequeños o con mapeos complejos, el mapeo manual suele ser más claro. Para proyectos grandes con muchos DTOs simétricos, AutoMapper ahorra tiempo siempre que se valide la configuración en arranque.

3 · Ejemplo mínimo

Compararemos el mapeo manual y AutoMapper para una entidad simple.

3.1. Modelos

// Entidad de dominio.
public sealed class Category
{
    public Guid Id { get; set; }
    public string Name { get; set; } = string.Empty;
    public string? Description { get; set; }
}

// DTO de respuesta para la API.
public sealed class CategoryResponse
{
    public Guid Id { get; set; }
    public string Name { get; set; } = string.Empty;
    public string? Description { get; set; }
}

3.2. Mapeo manual

public static class CategoryMappings
{
    // Método de extensión que convierte una entidad de dominio en respuesta de API.
    public static CategoryResponse ToResponse(this Category category)
    {
        return new CategoryResponse
        {
            Id = category.Id,
            Name = category.Name,
            Description = category.Description
        };
    }
}

// Uso:
var response = category.ToResponse();

3.3. AutoMapper

dotnet add package AutoMapper --version 13.0.1
using AutoMapper;

public sealed class CategoryProfile : Profile
{
    public CategoryProfile()
    {
        // Mapeo bidireccional por convención de nombres iguales.
        CreateMap<Category, CategoryResponse>();
    }
}

// Uso en un servicio o handler:
public sealed class CategoryQueryHandler : IRequestHandler<GetCategoryQuery, CategoryResponse>
{
    private readonly IMapper _mapper;

    public CategoryQueryHandler(IMapper mapper)
    {
        _mapper = mapper;
    }

    public async Task<CategoryResponse> Handle(GetCategoryQuery request, CancellationToken cancellationToken)
    {
        var category = await _repository.GetByIdAsync(request.Id, cancellationToken);
        return _mapper.Map<CategoryResponse>(category);
    }
}

// Valida la configuración al arrancar la aplicación.

4 · Ejemplo real

4.1. Mapeo manual con propiedades calculadas

public static class PostMappings
{
    public static PostResponse ToResponse(this Post post)
    {
        return new PostResponse
        {
            Id = post.Id,
            Title = post.Title,
            Slug = post.Slug,
            Excerpt = post.Content?.Length > 200
                ? post.Content[..200] + "..."
                : post.Content,
            PublishedAt = post.PublishedAt,
            AuthorName = post.Author?.DisplayName ?? "Autor desconocido",
            CategoryName = post.Category?.Name ?? "Sin categoría",
            Tags = post.Tags.Select(t => t.Name).ToList()
        };
    }
}

4.2. AutoMapper con ForMember

public sealed class PostProfile : Profile
{
    public PostProfile()
    {
        CreateMap<Post, PostResponse>()
            .ForMember(dest => dest.Excerpt,
                opt => opt.MapFrom(src => src.Content!.Length > 200
                    ? src.Content[..200] + "..."
                    : src.Content))
            .ForMember(dest => dest.AuthorName,
                opt => opt.MapFrom(src => src.Author!.DisplayName))
            .ForMember(dest => dest.CategoryName,
                opt => opt.MapFrom(src => src.Category!.Name))
            .ForMember(dest => dest.Tags,
                opt => opt.MapFrom(src => src.Tags.Select(t => t.Name).ToList()));
    }
}

4.3. ProjectTo para consultas eficientes

AutoMapper puede proyectar directamente en la base de datos, seleccionando solo las columnas necesarias. Esto evita cargar entidades completas en memoria.

public sealed class GetPostsQueryHandler : IRequestHandler<GetPostsQuery, List<PostSummaryResponse>>
{
    private readonly CmsDbContext _context;
    private readonly IMapper _mapper;

    public GetPostsQueryHandler(CmsDbContext context, IMapper mapper)
    {
        _context = context;
        _mapper = mapper;
    }

    public async Task<List<PostSummaryResponse>> Handle(GetPostsQuery request, CancellationToken cancellationToken)
    {
        return await _context.Posts
            .AsNoTracking()
            .Where(p => p.IsPublished)
            .ProjectTo<PostSummaryResponse>(_mapper.ConfigurationProvider)
            .ToListAsync(cancellationToken);
    }
}

En este ejemplo, la consulta SQL generada solo incluye las columnas que forman parte de PostSummaryResponse, no toda la entidad Post.

5 · Buenas prácticas

  • Valida la configuración en arranque. Usa AssertConfigurationIsValid para detectar campos no mapeados antes de que lleguen a producción.
  • Prefiere mapeo manual en DTOs críticos. Si un mapeo maneja datos sensibles, dinero o autorización, escríbelo explícitamente.
  • Usa ProjectTo para queries de solo lectura, especialmente en listados paginados.
  • No mapees hacia entidades de EF Core con AutoMapper a menos que sea trivial. Las entidades de dominio tienen invariantes y lógica que un mapeo automático puede saltarse.
  • Agrupa perfiles por dominio. No pongas todos los mapeos en un único perfil gigante. Crea un perfil por agregado o funcionalidad.
  • Mantén los mapeos unidireccionales si no necesitas bidireccionalidad. Evita ReverseMap si no lo usas.

Advertencia

AutoMapper no es magia. Si no validas la configuración, un cambio de nombre en una propiedad puede provocar que se devuelva un valor por defecto en lugar de lanzar un error. Eso es peligroso en producción.

6 · Errores habituales

6.1. No validar la configuración

// MAL: faltan propiedades sin mapear y no se detecta hasta ejecución.
builder.Services.AddAutoMapper(typeof(Program).Assembly);

// BIEN: valida al arrancar.
var app = builder.Build();
app.Services.GetRequiredService<MapperConfiguration>().AssertConfigurationIsValid();

6.2. Mapear desde la entidad directamente al contrato de API

// MAL: expone campos internos como AuditInfo, InternalNotes, etc.
CreateMap<Post, PostResponse>();

// BIEN: usa DTOs intermedios o configura explícitamente los campos.
CreateMap<Post, PostResponse>()
    .ForMember(dest => dest.AuditInfo, opt => opt.Ignore());

6.3. Mapear a entidades de EF Core para actualizarlas

// PELIGROSO: puede crear una entidad desconectada y perder datos.
var post = _mapper.Map<Post>(command);
_context.Posts.Update(post);

// MEJOR: carga la entidad, aplica cambios controlados.
var post = await _context.Posts.FindAsync(command.Id);
post.UpdateTitle(command.Title);
await _context.SaveChangesAsync();

6.4. Usar Mapper.Map dentro de un bucle

// MAL: asignaciones repetidas por cada elemento.
var responses = posts.Select(p => _mapper.Map<PostResponse>(p)).ToList();

// BIEN: usa ProjectTo en la query si es posible, o mapea la colección.
var responses = _mapper.Map<List<PostResponse>>(posts);

7 · Ejercicio guiado

Crea un perfil de AutoMapper para un usuario de dominio y un DTO de respuesta. Las reglas son:

  • Id, Email y DisplayName se mapean directamente.
  • Role se mapea al nombre legible del rol: Admin → "Administrador", Editor → "Editor", Author → "Autor".
  • CreatedAt se formatea como cadena ISO 8601.
public sealed class UserProfile : Profile
{
    public UserProfile()
    {
        CreateMap<User, UserResponse>()
            .ForMember(dest => dest.RoleName,
                opt => opt.MapFrom(src => src.Role switch
                {
                    UserRole.Admin => "Administrador",
                    UserRole.Editor => "Editor",
                    UserRole.Author => "Autor",
                    _ => "Desconocido"
                }))
            .ForMember(dest => dest.CreatedAt,
                opt => opt.MapFrom(src => src.CreatedAt.ToString("O")));
    }
}

Escribe un test unitario que verifique que la configuración es válida y que el mapeo produce los valores esperados.

9 · Resumen

  • El mapeo convierte objetos entre capas y debe ser explícito y seguro.
  • El mapeo manual es más verboso pero más controlado y no añade dependencias.
  • AutoMapper reduce código repetitivo en mapeos simétricos y permite ProjectTo para queries eficientes.
  • Siempre valida la configuración de AutoMapper con AssertConfigurationIsValid.
  • Para entidades de dominio, carga y modifica explícitamente en lugar de mapear directamente.

10 · Preguntas frecuentes

¿AutoMapper ralentiza la aplicación?

AutoMapper usa compilación de expresiones en tiempo de ejecución, por lo que la primera vez es más lenta. Una vez compilado, el mapeo es rápido. Usa ProjectTo para evitar cargar entidades completas en memoria.

¿Debo usar AutoMapper en proyectos pequeños?

En proyectos pequeños, el mapeo manual suele ser suficiente. Añadir AutoMapper solo para dos o tres DTOs puede ser exceso.

¿Cómo evito que AutoMapper mapee campos sensibles?

Usa .ForMember(dest => dest.Campo, opt => opt.Ignore()) o, mejor aún, crea DTOs de respuesta que no contengan esos campos. La seguridad empieza en el diseño del DTO.

¿Puedo usar AutoMapper con records de C#?

Sí, AutoMapper soporta records. Ten en cuenta que los records con init-only properties requieren configuración adicional si el mapeo no es por convención.

¿Qué alternativas existen a AutoMapper?

Mapperly es un source generator que genera mapeo en tiempo de compilación. Es más rápido y no requiere reflexión, pero tiene menos flexibilidad. Es una excelente opción para AOT y proyectos que priorizan el rendimiento.
