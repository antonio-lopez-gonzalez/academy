Caching distribuido con Redis

Módulo 13 · Caching y rendimiento35 min

1 · Introducción

En la lección anterior vimos IMemoryCache, un caché rápido pero limitado a un solo proceso. Cuando desplegamos una API en varias instancias, cada máquina tendría su propia caché y los usuarios podrían ver respuestas inconsistentes según a qué instancia lleguen.

En esta lección aprenderemos a usar IDistributedCache, la abstracción de caché distribuido de .NET, con Redis como backend. Veremos cómo instalar Redis, serializar objetos, invalidar entradas y comparar ventajas e inconvenientes respecto al caché en memoria.

¿Por qué Redis? Es un almacén de estructuras de datos en memoria extremadamente rápido, soportado por ASP.NET Core a través del paquete Microsoft.Extensions.Caching.StackExchangeRedis. Además de caché, lo usaremos para SignalR backplane y rate limiting en otros módulos.

Al terminar sabrás configurar Redis en Docker, registrar IDistributedCache, crear métodos de extensión para leer y escribir objetos JSON, y decidir cuándo usar caché en memoria vs caché distribuido.

2 · Teoría

2.1 IDistributedCache

IDistributedCache es la interfaz común de .NET para cualquier caché distribuido. Los métodos principales son:

  • GetStringAsync(string key) / SetStringAsync(string key, string value): para textos planos.
  • GetAsync(string key) / SetAsync(string key, byte[] value): para datos binarios.
  • RefreshAsync(string key): renueva la expiración deslizante si existe.
  • RemoveAsync(string key): elimina una entrada.

La interfaz es intencionalmente simple: almacena bytes o strings, nunca objetos .NET directos. Por eso debemos serializar.

2.2 Redis como backend

Redis guarda todo en memoria y ofrece estructuras como strings, hashes, listas, sets y sorted sets. Para IDistributedCache, ASP.NET Core almacena cada clave como un string Redis con metadatos de expiración. Redis puede ejecutarse en contenedor, en la nube (Azure Cache for Redis, AWS ElastiCache) o localmente.

Latencia de red: aunque Redis es muy rápido, añade una ida y vuelta de red. Datos muy pequeños y de alta frecuencia pueden beneficiarse de IMemoryCache local con Redis como invalidador, o de una combinación de ambos.

2.3 Serialización

IDistributedCache no conoce de JSON, protobuf ni XML. Es responsabilidad nuestra convertir el objeto a byte[] o string. Usaremos System.Text.Json por ser nativo, rápido y seguro.

Considera estas opciones de serialización:

  • System.Text.Json: nativo, rápido, buen soporte para UTF-8. Recomendado por defecto.
  • MessagePack: más compacto y rápido, pero requiere un paquete adicional.
  • Protobuf: útil si ya tienes contratos .proto.

2.4 Estrategias de expiración

Con IDistributedCache no hay prioridades de memoria, pero sí expiración absoluta y deslizante. Al crear DistributedCacheEntryOptions indicamos:

  • AbsoluteExpiration: fecha/hora exacta de caducidad.
  • AbsoluteExpirationRelativeToNow: tiempo relativo desde el almacenamiento.
  • SlidingExpiration: tiempo que se renueva al consultar.

3 · Ejemplo mínimo

Primero levantamos Redis con Docker:

docker run -d --name redis-cache -p 6379:6379 redis:7-alpine

Creamos una aplicación de consola:

dotnet new console -n RedisCacheDemo -o ejemplos/m13-caching/RedisCacheDemo/src/RedisCacheDemo
dotnet add ejemplos/m13-caching/RedisCacheDemo/src/RedisCacheDemo package Microsoft.Extensions.Caching.StackExchangeRedis
dotnet add ejemplos/m13-caching/RedisCacheDemo/src/RedisCacheDemo package Microsoft.Extensions.DependencyInjection
using Microsoft.Extensions.Caching.Distributed;
using Microsoft.Extensions.DependencyInjection;
using System.Text.Json;

namespace RedisCacheDemo;

class Program
{
    static async Task Main()
    {
        var services = new ServiceCollection();
        services.AddStackExchangeRedisCache(options =>
        {
            options.Configuration = "localhost:6379";
            options.InstanceName = "Demo_"; // prefijo para todas las claves
        });

        var provider = services.BuildServiceProvider();
        var cache = provider.GetRequiredService<IDistributedCache>();

        const string key = "weather: Madrid";

        // Guardamos un objeto serializado.
        var weather = new WeatherDto("Madrid", 28.5m, DateTime.UtcNow);
        var options = new DistributedCacheEntryOptions
        {
            AbsoluteExpirationRelativeToNow = TimeSpan.FromMinutes(5),
            SlidingExpiration = TimeSpan.FromSeconds(30)
        };

        await cache.SetStringAsync(
            key,
            JsonSerializer.Serialize(weather),
            options);

        Console.WriteLine("Guardado en Redis.");

        // Recuperamos.
        var json = await cache.GetStringAsync(key);
        var cached = json is null
            ? null
            : JsonSerializer.Deserialize<WeatherDto>(json);

        Console.WriteLine(cached);

        // Eliminamos.
        await cache.RemoveAsync(key);
        Console.WriteLine("Eliminado de Redis.");
    }
}

public sealed record WeatherDto(string City, decimal Temperature, DateTime Timestamp);

Ejecuta con:

dotnet run --project ejemplos/m13-caching/RedisCacheDemo/src/RedisCacheDemo
Tip: el InstanceName añade un prefijo a las claves en Redis. Es útil para compartir un mismo servidor Redis entre varias aplicaciones sin colisiones.

4 · Ejemplo real

Vamos a añadir métodos de extensión para guardar y recuperar objetos tipados de forma limpia, y un servicio de posts que use el caché distribuido.

4.1 Extensiones de IDistributedCache

using Microsoft.Extensions.Caching.Distributed;
using System.Text.Json;

namespace Cms.Infrastructure.Caching;

public static class DistributedCacheExtensions
{
    public static async Task<T?> GetAsync<T>(
        this IDistributedCache cache,
        string key,
        CancellationToken ct = default)
    {
        var data = await cache.GetAsync(key, ct);
        if (data is null) return default;

        return JsonSerializer.Deserialize<T>(data);
    }

    public static async Task SetAsync<T>(
        this IDistributedCache cache,
        string key,
        T value,
        DistributedCacheEntryOptions? options = null,
        CancellationToken ct = default)
    {
        var data = JsonSerializer.SerializeToUtf8Bytes(value);
        await cache.SetAsync(key, data, options ?? new DistributedCacheEntryOptions(), ct);
    }
}

4.2 Servicio de posts con caché distribuido

using Cms.Infrastructure.Caching;
using Microsoft.Extensions.Caching.Distributed;

namespace Cms.Application.Posts;

public sealed class CachedPostService
{
    private readonly IPostRepository _repository;
    private readonly IDistributedCache _cache;
    private readonly ILogger<CachedPostService> _logger;

    public CachedPostService(
        IPostRepository repository,
        IDistributedCache cache,
        ILogger<CachedPostService> logger)
    {
        _repository = repository;
        _cache = cache;
        _logger = logger;
    }

    public async Task<PostDto?> GetByIdAsync(Guid id, CancellationToken ct)
    {
        var key = $"post:{id}";
        var cached = await _cache.GetAsync<PostDto>(key, ct);
        if (cached is not null)
        {
            _logger.LogInformation("Cache hit para {PostId}", id);
            return cached;
        }

        _logger.LogInformation("Cache miss para {PostId}; consultando BD", id);
        var post = await _repository.GetByIdAsync(id, ct);
        if (post is null) return null;

        var dto = MapToDto(post);
        await _cache.SetAsync(
            key,
            dto,
            new DistributedCacheEntryOptions
            {
                AbsoluteExpirationRelativeToNow = TimeSpan.FromMinutes(10)
            },
            ct);

        return dto;
    }

    public async Task InvalidateAsync(Guid id)
    {
        await _cache.RemoveAsync($"post:{id}");
    }

    private static PostDto MapToDto(Post post) =>
        new(post.Id, post.Title, post.Slug, post.Status, post.PublishedAt);
}

public sealed record PostDto(
    Guid Id,
    string Title,
    string Slug,
    string Status,
    DateTime? PublishedAt);

public interface IPostRepository
{
    Task<Post?> GetByIdAsync(Guid id, CancellationToken ct);
}

public sealed class Post(Guid id, string title, string slug, string status, DateTime? publishedAt)
{
    public Guid Id { get; } = id;
    public string Title { get; } = title;
    public string Slug { get; } = slug;
    public string Status { get; } = status;
    public DateTime? PublishedAt { get; } = publishedAt;
}

5 · Buenas prácticas

  • Usa prefijos de instancia: InstanceName evita colisiones entre aplicaciones en un mismo servidor Redis.
  • Claves con prefijo de dominio: post:{id}, categories:all. Nunca confíes en GUIDs sueltos sin contexto.
  • Serializa DTOs, no entidades de dominio: las entidades pueden tener navegación, propiedades privadas o comportamiento que no se serializa bien.
  • Define TTL siempre: una entrada sin expiración puede vivir para siempre y consumir memoria. Usa absoluta como mínimo.
  • Invalida al mutar: igual que en memoria. Tras crear, actualizar o eliminar, borra las claves afectadas.
  • Combina local + distribuido para lecturas intensivas: IMemoryCache local + IDistributedCache como fuente de verdad. Primero consulta local, luego distribuido, luego BD.
  • Monitoriza Redis: usa INFO, MONITOR o dashboards de cloud para detectar claves sin TTL, memoria alta o latencia.
  • Considera compresión para payloads grandes: JSON de grandes listas puede ocupar mucho. Comprimir con Brotli o GZip antes de guardar puede compensar.

6 · Errores habituales

6.1 No serializar correctamente

// ❌ Mal: intentar guardar un objeto de dominio complejo
await _cache.SetAsync(key, post); // no compila: SetAsync pide byte[] o string

// ✅ Bien: guardar un DTO serializado
await _cache.SetAsync(key, new PostDto(post.Id, post.Title, ...));

6.2 Claves sin prefijo

// ❌ Mal: colisiones fáciles y difíciles de depurar
var key = id.ToString();

// ✅ Bien: prefijo de dominio + identificador
var key = $"post:{id}";

6.3 Depender de Redis sin connection retry

# ❌ Mal: Redis caído tumba la aplicación
# options.Configuration = "localhost:6379"

# ✅ Bien: configura abortOnConnectFail=false para permitir reintentos
# La app seguirá funcionando con cache miss caído a base de datos

builder.Services.AddStackExchangeRedisCache(options =>
{
    options.Configuration = "localhost:6379,abortConnect=false";
});

6.4 Usar Redis para todo

// ❌ Mal: caché distribuido para datos de sesión de usuario con alta frecuencia
// y TTL muy corto. Cada petición viaja a Redis.

// ✅ Bien: datos de sesión en memoria o en cookie, y caché distribuido
// para catálogos, configuraciones y resultados de consultas costosas.

7 · Ejercicio guiado

Ampliaremos el ejemplo de consola para cachear una lista de ciudades con TTL absoluto.

Paso 1: extensión genérica

public static class DistributedCacheExtensions
{
    public static async Task SetListAsync<T>(
        this IDistributedCache cache,
        string key,
        IReadOnlyList<T> list,
        TimeSpan absoluteExpiration,
        CancellationToken ct = default)
    {
        var data = JsonSerializer.SerializeToUtf8Bytes(list);
        await cache.SetAsync(key, data, new DistributedCacheEntryOptions
        {
            AbsoluteExpirationRelativeToNow = absoluteExpiration
        }, ct);
    }

    public static async Task<IReadOnlyList<T>?> GetListAsync<T>(
        this IDistributedCache cache,
        string key,
        CancellationToken ct = default)
    {
        var data = await cache.GetAsync(key, ct);
        return data is null
            ? null
            : JsonSerializer.Deserialize<List<T>>(data);
    }
}

Paso 2: programa

var services = new ServiceCollection();
services.AddStackExchangeRedisCache(options =>
{
    options.Configuration = "localhost:6379";
    options.InstanceName = "Cities_";
});

var provider = services.BuildServiceProvider();
var cache = provider.GetRequiredService<IDistributedCache>();

var cities = await cache.GetListAsync<City>("cities:all");
if (cities is null)
{
    cities = new List<City>
    {
        new("Madrid", "ES"),
        new("Lisboa", "PT"),
        new("París", "FR")
    };
    await cache.SetListAsync("cities:all", cities, TimeSpan.FromMinutes(2));
}

foreach (var city in cities)
    Console.WriteLine(city);

public sealed record City(string Name, string CountryCode);

Comprueba con redis-cli que la clave existe y expira:

docker exec -it redis-cache redis-cli KEYS '*cities:all*'
docker exec -it redis-cache redis-cli TTL "Cities_cities:all"

8 · Reto

Implementa una capa híbrida HybridCache (puedes usar el paquete Microsoft.Extensions.Caching.Hybrid de .NET 8 si está disponible, o simularla manualmente):

  • Primero consulta IMemoryCache local.
  • Si no está, consulta IDistributedCache (Redis).
  • Si tampoco está, consulta base de datos y guarda en ambos niveles.
  • Al invalidar, borra de ambos niveles.

No resuelvas el reto ahora. Piensa en la implementación, sus ventajas y sus riesgos, y lo revisaremos en la siguiente sesión.

9 · Resumen

  • IDistributedCache es la abstracción de .NET para caché compartido entre procesos.
  • Redis se registra con AddStackExchangeRedisCache y se configura con la cadena de conexión.
  • Los valores se almacenan como bytes o string; debemos serializar, normalmente con System.Text.Json.
  • Usa InstanceName y claves con prefijo para evitar colisiones.
  • Invalida entradas al modificar los datos subyacentes.
  • Redis es ideal para entornos multi-instancia; IMemoryCache es más rápido para una sola instancia.

10 · Preguntas frecuentes

¿Puedo usar Redis sin Docker?

Sí, puedes instalar Redis nativamente o usar un servicio gestionado en la nube. Para desarrollo, Docker es la opción más limpia y reproducible.

¿Qué ocurre si Redis no está disponible?

Depende de la configuración. Con abortConnect=false la librería intenta reconectar y las operaciones fallan con excepciones que puedes capturar. Es buena práctica rodear el caché de un try/catch y caer a la fuente de datos.

¿Es más lento que IMemoryCache?

Sí, añade latencia de red. Sin embargo, sigue siendo mucho más rápido que una base de datos. Para datos de alta frecuencia y muy pequeños, considera una combinación de caché local + distribuido.

¿Puedo guardar objetos complejos directamente?

No. IDistributedCache trabaja con bytes o strings. Debes serializar. Si el objeto tiene navegaciones circulares, usa ReferenceHandler.IgnoreCycles o un DTO plano.

¿Cómo invalido el caché de todas las instancias?

Usa una clave de versión o un ChangeToken compartido. Por ejemplo, almacena cache:version en Redis; al cambiarla, todos los servicios invalidan sus claves locales. También puedes usar Redis pub/sub para notificaciones.

¿InstanceName es obligatorio?

No, pero es muy recomendable si compartes el servidor Redis entre aplicaciones. Sin prefijo, dos apps distintas podrían sobrescribirse con la misma clave.
