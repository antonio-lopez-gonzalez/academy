LINQ: consultas integradas en el lenguaje

Módulo 1 · Fundamentos de C# 50 minutos

1 · Introducción

Piensa cuántas veces escribes bucles foreach para filtrar, transformar o buscar en una colección. LINQ (Language Integrated Query) te permite hacerlo con métodos encadenados, declarativos y legibles.

Si vienes de JavaScript, LINQ es como filter/map/reduce; si vienes de Python, como las list comprehensions.

Objetivo

Dominar los operadores principales de LINQ y entender la ejecución diferida.

2 · Teoría

Antes de LINQ: el bucle manual

var numeros = new List<int> { 5, 12, 3, 20, 8 };

// Filtrar pares y multiplicarlos por 2 (imperativo)
var resultado = new List<int>();
foreach (int n in numeros)
{
    if (n % 2 == 0)
        resultado.Add(n * 2);
}

Con LINQ: declarativo

var resultado = numeros
    .Where(n => n % 2 == 0)   // filtro
    .Select(n => n * 2)       // transformación
    .ToList();                 // materializar

// resultado = [24, 40, 16]

LINQ está formado por métodos de extensión que operan sobre IEnumerable<T> y usan lambdas. Encadenas operaciones y se lee como una frase: "donde par, selecciona el doble".

Ejecución diferida (deferred execution)

La mayoría de operadores (Where, Select, OrderBy...) no ejecutan nada hasta que materializas el resultado. Esto conecta con lo visto en la lección de IEnumerable:

var consulta = numeros.Where(n => n > 5);   // no se ejecuta

numeros.Add(100);                            // añadimos DESPUÉS

var lista = consulta.ToList();               // aquí sí se evalúa
// ¡incluye el 100!, porque la consulta se evalúa al materializar
Diferido vs inmediato

Los operadores como ToList(), ToArray(), First(), Count() fuerzan la ejecución inmediata. Where/Select/OrderBy son diferidos.

Filtrado y proyección

// Where: filtrar
var mayores = numeros.Where(n => n > 10);

// Select: transformar (proyectar) cada elemento
var dobles = numeros.Select(n => n * 2);

// SelectMany: aplanar colecciones anidadas
var listas = new List<List<int>> { new() { 1, 2 }, new() { 3, 4 } };
var planos = listas.SelectMany(lista => lista);   // [1, 2, 3, 4]

Ordenación

var ordenados = numeros.OrderBy(n => n);                 // ascendente
var descendente = numeros.OrderByDescending(n => n);     // descendente

// ThenBy para desempatar (ordenar por dos criterios)
var personas = ...;
var porEdadYNomb = personas.OrderBy(p => p.Edad).ThenBy(p => p.Nombre);

Elementos individuales

int primero = numeros.First();                  // lanza si está vacío
int primeroSeguro = numeros.FirstOrDefault();   // default (0) si vacío

int unico = numeros.Single(n => n == 20);       // lanza si hay más de uno
int unicoSeguro = numeros.SingleOrDefault(n => n == 99);  // 0 si no existe

Agregación y comprobación

bool hayPares = numeros.Any(n => n % 2 == 0);   // ¿alguno cumple?
bool todosPositivos = numeros.All(n => n > 0);  // ¿todos cumplen?

int total = numeros.Count();                     // cuántos hay
int suma = numeros.Sum();                        // suma
int min = numeros.Min();                         // mínimo
int max = numeros.Max();                         // máximo
double media = numeros.Average();                // media

GroupBy y Join

// GroupBy: agrupar por clave
var porParidad = numeros.GroupBy(n => n % 2 == 0 ? "Par" : "Impar");
foreach (var grupo in porParidad)
{
    Console.WriteLine($"{grupo.Key}: {string.Join(", ", grupo)}");
}
// Join: unir dos colecciones por una clave (como SQL)
var alumnos = new[] { new { Id = 1, Nombre = "Ana" } };
var notas = new[] { new { AlumnoId = 1, Nota = 8.5 } };

var conNota = alumnos.Join(notas,
    a => a.Id, n => n.AlumnoId,
    (a, n) => new { a.Nombre, n.Nota });

Materializar: ToList y ToArray

var comoLista = numeros.Where(n => n > 5).ToList();
var comoArray = numeros.Where(n => n > 5).ToArray();

3 · Ejemplo mínimo

var numeros = new List<int> { 5, 12, 3, 20, 8 };

var mayores = numeros
    .Where(n => n > 10)
    .Select(n => n * 2)
    .ToList();

Console.WriteLine(string.Join(", ", mayores));   // 24, 40, 16

4 · Ejemplo real

Procesar una lista de productos: filtrar los activos, ordenarlos por precio y calcular el total:

var productos = new List<Producto>
{
    new("Teclado", 29.99m, true),
    new("Ratón", 15.50m, true),
    new("Monitor", 199.99m, false),
    new("Auriculares", 45.00m, true),
};

var activosOrdenados = productos
    .Where(p => p.Activo)
    .OrderBy(p => p.Precio);

decimal total = activosOrdenados.Sum(p => p.Precio);
int cantidad = activosOrdenados.Count();

foreach (var p in activosOrdenados)
    Console.WriteLine($"{p.Nombre}: {p.Precio:C}");

Console.WriteLine($"Total: {total:C} ({cantidad} productos)");

record Producto(string Nombre, decimal Precio, bool Activo);

5 · Buenas prácticas

HacerPor qué
Encadenar operadores en líneas separadasLegibilidad de la consulta
Usar FirstOrDefault/SingleOrDefault cuando puede no haber resultadoEvita excepciones
Materializar (ToList) si recorres varias vecesNo reevaluar la consulta
Recordar la ejecución diferidaEvita sorpresas cuando la colección cambia

6 · Errores habituales

Error 1: creer que la consulta se ejecuta al definirla

var q = numeros.Where(n => n > 5);   // solo define la consulta
numeros.Add(999);
// q ahora incluirá 999 cuando se materialice

Error 2: First en colección vacía

// First() lanza InvalidOperationException si no hay elementos
// Usa FirstOrDefault() si la colección puede estar vacía

Error 3: olvidar ToList y recorrer varias veces

var costoso = datos.Where(d => Calcular(d));
int c1 = costoso.Count();   // evalúa
int c2 = costoso.Count();   // ¡vuelve a evaluar!
// Correcto: var lista = datos.Where(...).ToList();

9 · Resumen

  • LINQ = métodos de extensión sobre IEnumerable<T> con lambdas.
  • Ejecución diferida: Where/Select/OrderBy no ejecutan hasta materializar.
  • Operadores clave: Where, Select, SelectMany, OrderBy, First/Single, Any/All, Count/Sum/Min/Max/Average, GroupBy, Join, ToList/ToArray.

10 · Preguntas frecuentes

¿Cuándo usar LINQ y cuándo un foreach?

LINQ para transformar/filtrar/consultar colecciones de forma declarativa. Un foreach simple para efectos secundarios (imprimir, acumular en una variable externa) puede ser más claro.

¿Qué pasa si encadeno y no llamo a ToList?

Nada se ejecuta. La variable guarda una "consulta" que se evaluará cuando la recorras o materialices.

¿LINQ funciona con bases de datos?

Sí. Con Entity Framework, el mismo LINQ se traduce a SQL. Por eso dominar LINQ to Objects es tan importante: la sintaxis se reutiliza.
