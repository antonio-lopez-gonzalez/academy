Structs y tipos por valor

Módulo 1 · Fundamentos de C# 35 minutos

1 · Introducción

Hasta ahora usabas tipos ya hechos (int, string, List<T>). Un struct te permite agrupar varios valores en un solo tipo propio que, además, se comporta como un tipo de valor: se copia al asignarlo.

Es tu primer paso hacia crear tipos, antes de llegar a las clases (en el siguiente curso, POO).

Objetivo

Crear structs, entender la copia por valor, y conocer readonly struct y record struct.

2 · Teoría

Declarar un struct

struct Punto
{
    public int X;
    public int Y;
}

Un struct agrupa campos y métodos. public hace el campo accesible desde fuera. Ahora puedes crear "Puntos":

Punto p1 = new Punto { X = 10, Y = 20 };
Console.WriteLine($"({p1.X}, {p1.Y})");   // (10, 20)

La copia por valor

La característica clave del struct: al asignarlo, se copia entero. Cada variable es independiente:

Punto p1 = new Punto { X = 10, Y = 20 };
Punto p2 = p1;      // COPIA completa, no comparte

p2.X = 99;          // modifica p2...
Console.WriteLine(p1.X);   // 10  (p1 NO cambia)

struct vs class

La class (que verás en POO) es un tipo de referencia: al asignarla se comparte la misma referencia. El struct es un tipo de valor: se copia. Por ahora quédate con esta regla:

structclass
TipoValorReferencia
Al asignarSe copiaSe comparte
HerenciaNo soportaSí soporta
Uso típicoDatos pequeños y efímerosEntidades con identidad

readonly struct

Un struct inmutable (no puede modificarse tras crearse). Se recomienda para la mayoría de casos:

readonly struct PuntoInmutable
{
    public int X { get; }
    public int Y { get; }

    public PuntoInmutable(int x, int y)
    {
        X = x;
        Y = y;
    }
}

record struct (C# 10+)

Una forma compacta de crear un struct inmutable con comparación por valor automática:

public readonly record struct Punto(int X, int Y);

var p1 = new Punto(1, 2);
var p2 = new Punto(1, 2);

bool iguales = p1 == p2;   // true (comparación por valor)

Cuándo usar un struct

Regla general

Usa struct para tipos pequeños, inmutables y efímeros (como un punto, un color, una cantidad de dinero). Para entidades con identidad y comportamiento complejo, usa class (POO).

3 · Ejemplo mínimo

struct Punto { public int X; public int Y; }

Punto a = new Punto { X = 1, Y = 2 };
Punto b = a;       // copia
b.X = 50;

Console.WriteLine(a.X);   // 1
Console.WriteLine(b.X);   // 50

4 · Ejemplo real

Modelar dinero de forma segura e inmutable con un record struct:

public readonly record struct Dinero(decimal Cantidad, string Moneda)
{
    public Dinero Sumar(Dinero otro)
    {
        if (Moneda != otro.Moneda)
            throw new InvalidOperationException("Monedas distintas");
        return new Dinero(Cantidad + otro.Cantidad, Moneda);
    }
}

var precio = new Dinero(10.50m, "EUR");
var iva = new Dinero(2.20m, "EUR");
var total = precio.Sumar(iva);
Console.WriteLine(total);   // Dinero { Cantidad = 12.70, Moneda = EUR }

6 · Errores habituales

Error 1: struct con muchos campos grandes

// Incorrecto: copiar esto en cada asignación es caro
struct FacturaGrande { public int Id; public decimal Total; /* ... 50 campos más */ }

// Correcto: usa class para datos complejos

Error 2: esperar que un struct se comparta

Punto p1 = new Punto { X = 1 };
Punto p2 = p1;   // copia, no referencia
p2.X = 9;        // p1.X sigue siendo 1

Error 3: struct mutable sin readonly

// Prefiere readonly para evitar cambios accidentales

9 · Resumen

  • struct = tipo de valor: se copia al asignar.
  • class = tipo de referencia: se comparte (POO).
  • readonly struct: inmutable.
  • record struct: inmutable y con comparación por valor.
  • Usa struct para datos pequeños y efímeros.

10 · Preguntas frecuentes

¿Por qué un struct no puede heredar?

Porque al ser un valor, su tamaño debe conocerse en compilación. La herencia complicaría el diseño (un subtipo podría tener más campos). Sí puede implementar interfaces.

¿Cuándo elijo struct en vez de class?

Cuando el tipo representa un "valor" pequeño e inmutable (punto, color, dinero) y no necesita identidad propia ni herencia.

¿Qué pasa si guardo un struct en una List?

Se guarda por valor dentro de la lista. Al leerlo obtienes una copia; para modificar el original debes reasignarlo: lista[i] = lista[i] with { X = 9 }; (si es record struct).
