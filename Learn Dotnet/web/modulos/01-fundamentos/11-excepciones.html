Excepciones

Módulo 1 · Fundamentos de C# 40 minutos

1 · Introducción

A veces las cosas fallan: un archivo no existe, la división entre cero, una conexión caída. C# tiene un mecanismo unificado para esto: las excepciones. Son objetos que "se lanzan" cuando ocurre un error y que puedes capturar para reaccionar.

Objetivo

Capturar errores con try/catch/finally, lanzarlos con throw y saber cuándo usarlos (y cuándo no).

2 · Teoría

¿Qué es una excepción?

Es un objeto que hereda de System.Exception y describe un error. Cuando algo falla, el runtime lanza una excepción y detiene el flujo normal hasta que alguien la captura.

try / catch / finally

try
{
    // Código que puede fallar
    int resultado = Dividir(10, 0);
}
catch (DivideByZeroException ex)
{
    // Se ejecuta si hubo ese error concreto
    Console.WriteLine($"No se puede dividir entre cero: {ex.Message}");
}
catch (Exception ex)
{
    // Captura cualquier otro error
    Console.WriteLine($"Error inesperado: {ex.Message}");
}
finally
{
    // Se ejecuta SIEMPRE (haya o no error)
    Console.WriteLine("Fin de la operación");
}
  • try: delimita el código vigilado.
  • catch: captura y maneja un tipo de excepción (puede haber varios, del más específico al más general).
  • finally: se ejecuta siempre, ideal para liberar recursos.

throw: lanzar excepciones

static int Dividir(int a, int b)
{
    if (b == 0)
        throw new ArgumentException("El divisor no puede ser cero", nameof(b));
    return a / b;
}

Cuándo lanzar y cuándo no

Regla de oro

Usa excepciones para errores excepcionales (archivo no encontrado, conexión caída). No las uses para controlar el flujo normal (por ejemplo, validar entrada de usuario): para eso existen TryParse, if, etc.

3 · Ejemplo mínimo

try
{
    int[] n = { 1, 2, 3 };
    Console.WriteLine(n[10]);
}
catch (IndexOutOfRangeException)
{
    Console.WriteLine("Índice fuera de rango");
}

4 · Ejemplo real

Leer un archivo de configuración que puede no existir, con finally para liberar recursos:

StreamReader? lector = null;
try
{
    lector = new StreamReader("config.txt");
    string contenido = lector.ReadToEnd();
    Console.WriteLine(contenido);
}
catch (FileNotFoundException)
{
    Console.WriteLine("El archivo config.txt no existe");
}
finally
{
    lector?.Dispose();   // libera el recurso siempre
}

6 · Errores habituales

Error 1: capturar y no hacer nada

// Incorrecto: el error se oculta
try { HacerAlgo(); } catch (Exception) { }

// Correcto: al menos loguear
try { HacerAlgo(); } catch (Exception ex) { Console.WriteLine(ex.Message); }

Error 2: usar excepciones para control de flujo

// Incorrecto: caro y poco legible
try { int n = int.Parse(entrada); } catch { /* manejar */ }

// Correcto
if (int.TryParse(entrada, out int n)) { /* manejar */ }

Error 3: catch demasiado genérico al inicio

// Incorrecto: Exception captura todo antes que los específicos
catch (Exception ex) { }
catch (FileNotFoundException ex) { }   // inalcanzable

// Correcto: de lo específico a lo general

8 · Reto

Reto

Escribe un método que lea un número de un string y lo devuelva, lanzando una excepción propia (ArgumentException) con un mensaje claro si el texto no es un número. Luego captúrala y muestra el mensaje al usuario.

9 · Resumen

  • Las excepciones son objetos que heredan de Exception.
  • try vigila, catch captura, finally siempre se ejecuta.
  • throw lanza una excepción (nueva o capturada).
  • Usa excepciones para errores reales, no para flujo normal.

10 · Preguntas frecuentes

¿Qué diferencia hay entre throw; y throw ex;?

throw; (dentro de un catch) relanza la excepción original conservando el stack trace. throw ex; lo reinicia y pierde el origen. Prefiere throw;.

¿Puedo crear mis propias excepciones?

Sí, heredando de Exception: class MiErrorException : Exception { ... }. Se usa para errores de dominio específicos.

¿Qué pasa si nadie captura una excepción?

El programa termina con un error (crash) y muestra el stack trace. Por eso en aplicaciones reales hay un manejador global de excepciones.
