Genéricos

Módulo 1 · Fundamentos de C# 40 minutos

1 · Introducción

Imagina que necesitas una función que devuelva el primer elemento de un array. ¿Escribes una para int, otra para string, otra para double? Eso es repetir código. Los genéricos resuelven esto: escribes el código una vez, parametrizado por un tipo T.

Objetivo

Crear métodos y clases genéricas, y aplicar restricciones con where.

2 · Teoría

El problema

Sin genéricos, para guardar "cualquier cosa" tendrías que usar object, perdiendo seguridad de tipos:

// Sin genéricos: object (peligroso, requiere cast)
object valor = 42;
int numero = (int)valor;   // cast obligatorio, puede fallar

El tipo T

Con genéricos, T es un "comodín" que representa un tipo que se decide al usar el código:

// Método genérico: T es el tipo del elemento
static T Primero<T>(T[] elementos)
{
    return elementos[0];
}

int[] numeros = { 1, 2, 3 };
string[] nombres = { "Ana", "Luis" };

int n = Primero<int>(numeros);       // 1
string s = Primero<string>(nombres);  // "Ana"

El compilador deduce el tipo automáticamente, así que puedes omitir <int> cuando sea evidente.

Clases genéricas

class Caja<T>
{
    private T _contenido;

    public void Guardar(T elemento) => _contenido = elemento;
    public T Sacar() => _contenido;
}

var cajaNumeros = new Caja<int>();
cajaNumeros.Guardar(10);
int valor = cajaNumeros.Sacar();   // 10, sin cast

Las colecciones son genéricas

Todo lo que usaste en la lección de colecciones ya era genérico: List<T>, Dictionary<K,V>, HashSet<T>. El <T> es exactamente esto.

Restricciones con where

Puedes limitar qué tipos puede ser T:

// where T : class      → T debe ser un tipo de referencia
// where T : struct     → T debe ser un tipo de valor
// where T : new()      → T debe tener constructor sin parámetros
// where T : Interfaz   → T debe implementar cierta interfaz

static T Crear<T>() where T : new()
{
    return new T();   // válido porque T tiene new()
}
Ventajas de los genéricos

1) Seguridad de tipos en compilación. 2) Reutilización de código. 3) Mejor rendimiento (sin boxing/casting).

3 · Ejemplo mínimo

static T Primero<T>(T[] elementos)
{
    return elementos[0];
}

string[] nombres = { "Ana", "Luis", "María" };
Console.WriteLine(Primero(nombres));   // "Ana"

4 · Ejemplo real

Un método genérico que intercambia dos valores de cualquier tipo (útil para ordenar):

static void Intercambiar<T>(ref T a, ref T b)
{
    (a, b) = (b, a);   // intercambio con tupla
}

int x = 1, y = 2;
Intercambiar(ref x, ref y);
Console.WriteLine($"{x}, {y}");   // 2, 1

string s1 = "hola", s2 = "adiós";
Intercambiar(ref s1, ref s2);
Console.WriteLine($"{s1}, {s2}");  // adiós, hola

6 · Errores habituales

Error 1: olvidar el tipo entre ángulos

// Incorrecto: falta  en la declaración
// static T Primero(T[] elementos)

// Correcto
static T Primero<T>(T[] elementos)

Error 2: intentar comparar T sin restricción

// static bool Igual<T>(T a, T b) => a == b;   // error: no todos los T tienen ==
// Se necesita restricción o usar EqualityComparer<T>.Default

Error 3: usar object en vez de genéricos

// Incorrecto: object + cast es frágil
object[] datos = { 1, "dos", 3.0 };
int i = (int)datos[0];   // cast, puede fallar en runtime

// Correcto: genéricos dan seguridad en compilación

9 · Resumen

  • Los genéricos parametrizan el tipo con T.
  • Métodos y clases genéricas escriben el código una vez.
  • Las colecciones (List<T>...) son genéricas.
  • where T : ... restringe los tipos permitidos.

10 · Preguntas frecuentes

¿Qué significa where T : new()?

Que el tipo T debe tener un constructor público sin parámetros, lo que permite hacer new T() dentro del código genérico.

¿Puedo tener varios parámetros de tipo?

Sí: Dictionary<TKey, TValue> tiene dos. Se separan por comas dentro de los ángulos.

¿Los genéricos existen en runtime?

Sí, a diferencia de los "type erasure" de Java. En .NET, List<int> y List<string> son tipos distintos en runtime, lo que evita el boxing.
