2 · Teoría

Solution, Project y .csproj

En .NET, el código se organiza en niveles:

Solution (.sln) ├── Proyecto 1 (MiApp.csproj) ├── Proyecto 2 (MiApp.Tests.csproj) └── Proyecto 3 (MiApp.Core.csproj)
  • Project: la unidad básica. Un .csproj describe qué compila y qué usa.
  • Solution (.sln): agrupa varios proyectos relacionados.
  • Assembly: el resultado compilado (el .dll) de un proyecto.
# Crear una solution y añadir proyectos
dotnet new sln -n MiApp
dotnet new console -n MiApp -o src/MiApp
dotnet sln add src/MiApp

Namespaces y using

Los namespaces agrupan tipos relacionados y evitan choques de nombres (como los módulos de Python o los packages de Java):

namespace MiApp.Modelos
{
    class Cliente { /* ... */ }
}

// Para usarlos desde otro archivo:
using MiApp.Modelos;

var cliente = new Cliente();

Con ImplicitUsings activado, los namespaces más comunes (System, System.Linq, etc.) se importan solos.

NuGet: el gestor de paquetes

NuGet es el repositorio de librerías de .NET (como npm para Node o pip para Python). Añades un paquete con:

dotnet add package Newtonsoft.Json      # añade una librería
dotnet restore                          # descarga las dependencias

El paquete queda registrado en el .csproj con su versión:

<ItemGroup>
  <PackageReference Include="Newtonsoft.Json" Version="13.0.3" />
</ItemGroup>
Dependencias y versiones

Cada paquete puede depender de otros, y NuGet resuelve el grafo completo con restore. Las versiones se fijan para reproducibilidad; puedes actualizarlas con dotnet add package Nombre --version x.y.z.

Configuración: appsettings.json y variables de entorno

Las aplicaciones configuran valores (cadenas de conexión, URLs) en archivos JSON o variables de entorno:

{
  "ConnectionStrings": {
    "Default": "Host=localhost;Database=miapp"
  },
  "Logging": {
    "LogLevel": "Information"
  }
}

En producción, los secretos y configuraciones suelen venir de variables de entorno, que tienen prioridad sobre el archivo. Veremos esto a fondo en los módulos de ASP.NET Core.

Logging con ILogger

En vez de usar Console.WriteLine, las aplicaciones .NET usan logging estructurado con la interfaz ILogger<T>:

using Microsoft.Extensions.Logging;

using var factory = LoggerFactory.Create(b => b.AddConsole());
ILogger<Program> logger = factory.CreateLogger<Program>();

logger.LogInformation("Aplicación iniciada");
logger.LogWarning("Esto es un aviso");
logger.LogError("Esto es un error: {Detalle}", "algo falló");

Los niveles de log, de menor a mayor severidad:

NivelCuándo
TraceDetalle máximo, diagnóstico
DebugInformación de desarrollo
InformationEventos normales (default)
WarningAlgo inesperado pero no crítico
ErrorFallos que hay que atender
CriticalFallos graves
¿Por qué no Console.WriteLine?

ILogger permite filtrar por nivel, formatear de forma estructurada y enviar los logs a distintos destinos (consola, archivo, servicios externos) sin cambiar el código. Es el estándar en .NET.

4 · Ejemplo real

Un flujo completo: añadir un paquete y usarlo, con logging de cada paso:

using Microsoft.Extensions.Logging;

using var factory = LoggerFactory.Create(b => b.AddConsole());
var logger = factory.CreateLogger<Program>();

logger.LogInformation("Iniciando proceso de datos...");

var datos = new[] { 1, 2, 3, 4, 5 };
var total = datos.Sum();

logger.LogInformation("Proceso completado. Total: {Total}", total);

6 · Errores habituales

Error 1: hardcodear secretos

// Incorrecto: nunca pongas contraseñas en el código
// string conexion = "Server=x;Password=supersecreto";

// Correcto: leer de configuración o variables de entorno

Error 2: concatenar strings en logs

// Incorrecto: pierde estructura
logger.LogInformation("Usuario " + nombre + " conectado");

// Correcto: plantillas estructuradas
logger.LogInformation("Usuario {Nombre} conectado", nombre);

10 · Preguntas frecuentes

¿Qué es un assembly?

El archivo compilado (.dll o .exe) que contiene tu código en IL. Es la unidad de despliegue de .NET.

¿Dónde se guardan los paquetes NuGet?

En una caché local (~/.nuget/packages). dotnet restore los descarga desde nuget.org (o tu feed privado).
