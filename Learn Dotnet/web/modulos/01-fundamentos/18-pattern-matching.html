Pattern Matching

Módulo 1 · Fundamentos de C# 40 minutos

1 · Introducción

Muchas veces necesitas saber "qué es" un valor (su tipo) o "cómo es" (su forma, sus valores) para decidir qué hacer. El pattern matching expresa esas comprobaciones de forma declarativa y mucho más clara que cadenas de if/else.

Objetivo

Dominar los patrones de tipo, constante, propiedad, relacional y lógico, y combinarlos en switch expressions.

2 · Teoría

El patrón de tipo con is

Comprueba si un valor es de un tipo y, si lo es, lo asigna a una variable:

object valor = "hola";

if (valor is string texto)
{
    Console.WriteLine(texto.ToUpper());   // "HOLA"
}

Antes hacías una comprobación y un cast por separado; ahora es una sola operación.

Patrón de constante

int estado = 200;
if (estado is 200)
{
    Console.WriteLine("OK");
}

Patrones relacionales

Comprueban rangos con <, >, <=, >=:

int edad = 25;

string categoria = edad switch
{
    < 13 => "Niño",
    >= 13 and < 18 => "Adolescente",
    >= 18 and < 65 => "Adulto",
    >= 65 => "Senior",
    _ => "?"
};

Patrones lógicos: and, or, not

string tipo = edad switch
{
    >= 0 and < 18 => "Menor",
    >= 18 and <= 120 => "Adulto",
    not 0 => "Distinto de cero",
    _ => "Desconocido"
};

Patrones de propiedad

Comprueban las propiedades de un objeto:

record Punto(int X, int Y);

static string Describir(Punto p) => p switch
{
    { X: 0, Y: 0 } => "Origen",
    { X: 0 } => "Sobre el eje Y",
    { Y: 0 } => "Sobre el eje X",
    { X: > 0, Y: > 0 } => "Primer cuadrante",
    _ => "Otro"
};

Con records posicionales puedes usar la forma aún más compacta de "deconstrucción":

static string Describir(Punto p) => p switch
{
    (0, 0) => "Origen",
    (0, _) => "Sobre el eje Y",
    (_, 0) => "Sobre el eje X",
    (> 0, > 0) => "Primer cuadrante",
    _ => "Otro"
};

Combinar con guardas when

static string Clasificar(int n) => n switch
{
    < 0 => "Negativo",
    0 => "Cero",
    > 0 when n % 2 == 0 => "Positivo par",
    > 0 => "Positivo impar"
};

El patrón de negación y el operador and en is

if (valor is int numero && numero > 10)
{
    Console.WriteLine("Número entero mayor que 10");
}

3 · Ejemplo mínimo

object valor = 42;

if (valor is int numero && numero > 10)
{
    Console.WriteLine($"Número mayor que 10: {numero}");
}

4 · Ejemplo real

Calcular el área de distintas figuras usando tipos y switch expression:

abstract record Figura;
record Circulo(double Radio) : Figura;
record Rectangulo(double Ancho, double Alto) : Figura;

static double Area(Figura figura) => figura switch
{
    Circulo c => Math.PI * c.Radio * c.Radio,
    Rectangulo r => r.Ancho * r.Alto,
    _ => throw new ArgumentException("Figura desconocida")
};

Console.WriteLine(Area(new Circulo(2)));      // 12.57
Console.WriteLine(Area(new Rectangulo(2, 3))); // 6

6 · Errores habituales

Error 1: poner el descarte antes de los casos específicos

// Incorrecto: _ captura todo antes de llegar a 5
string r = valor switch
{
    _ => "Cualquiera",
    5 => "Cinco"
};

// Correcto: específico primero
string r2 = valor switch
{
    5 => "Cinco",
    _ => "Cualquiera"
};

Error 2: no cubrir todos los casos

// Un switch expression debe ser exhaustivo (tener caso por defecto o cubrir todo)
string r = valor switch
{
    1 => "uno",
    // falta _ o más casos → error de compilación
};

Error 3: usar pattern matching para una comprobación trivial

// Incorrecto: sobre-ingeniería
// bool valido = edad is > 0 and < 120;

// Correcto: simple y claro
bool valido = edad > 0 && edad < 120;

9 · Resumen

  • is comprueba tipo y asigna a variable.
  • Patrones: de tipo, constante, relacional, lógico (and/or/not), de propiedad y posicional.
  • Switch expressions con => y descarte _.
  • Guardas when para condiciones extra.

10 · Preguntas frecuentes

¿Qué es el descarte _?

Es un patrón que coincide con cualquier valor. En switch expression funciona como el caso por defecto; en tuplas/deconstrucción, como "este valor no me importa".

¿Los patrones posicionales funcionan con clases normales?

Solo si la clase define un método Deconstruct. Los records posicionales lo tienen automáticamente.

¿Pattern matching es más rápido que if/else?

En general, el compilador genera código equivalente. La ventaja es la legibilidad y la seguridad (exhaustividad), no el rendimiento.
