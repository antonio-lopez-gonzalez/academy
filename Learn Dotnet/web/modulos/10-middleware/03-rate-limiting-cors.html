Rate Limiting y CORS

Módulo 10 · Middleware y pipelines30 min

1 · Introducción

Una API expuesta a internet debe protegerse contra el abuso y respetar las reglas de los navegadores. El rate limiting limita cuántas peticiones puede hacer un cliente en un intervalo. El CORS (Cross-Origin Resource Sharing) controla qué orígenes web pueden consumir la API desde el navegador.

En .NET 8, el rate limiting es un middleware de primer nivel, no un paquete externo. En esta lección aprenderemos a configurar ambos y a colocarlos correctamente en el pipeline.

¿Qué problema resuelven?

El rate limiting evita la degradación del servicio por tráfico excesivo o ataques. El CORS evita que sitios web maliciosos hagan peticiones a tu API en nombre de un usuario autenticado sin permiso.

Errores típicos

  • Colocar CORS después de UseAuthentication, lo que hace que los preflight OPTIONS fallen.
  • Permitir AllowAnyOrigin() con credenciales en producción, rompiendo la seguridad.
  • Aplicar rate limiting sin definir un RejectionStatusCode, devolviendo 503 por defecto sin información.
  • Usar el limitador FixedWindow para tráfico que necesita suavidad (pico al inicio de cada ventana).

2 · Teoría

Rate limiting en .NET 8

El middleware de rate limiting incluye cuatro algoritmos principales:

  • FixedWindow: permite N peticiones en un intervalo fijo. Sencillo pero genera picos al reiniciar la ventana.
  • SlidingWindow: permite N peticiones en una ventana que se desliza. Suaviza los picos.
  • TokenBucket: permite peticiones mientras haya tokens disponibles; se rellenan a una tasa constante. Útil para tráfico irregular con picos.
  • Concurrency: limita el número de peticiones concurrentes, sin importar el tiempo transcurrido.

Clasificación de peticiones

Para limitar por cliente, debes decirle al middleware cómo identificar al cliente. Puedes usar la IP, el usuario autenticado, un header personalizado, o una combinación:

options.AddPolicy("per-ip", context =>
{
    var remoteIp = context.Connection.RemoteIpAddress?.ToString() ?? "unknown";
    return RateLimitPartition.GetFixedWindowLimiter(remoteIp, _ => new FixedWindowRateLimiterOptions
    {
        PermitLimit = 100,
        Window = TimeSpan.FromMinutes(1)
    });
});

CORS

CORS es un mecanismo de seguridad del navegador, no del servidor. El servidor indica qué orígenes, métodos y cabeceras están permitidos. Los navegadores envían preflight OPTIONS para verificar. Si CORS no está bien configurado, el navegador bloquea la petición aunque el servidor la acepte.

AlgoritmoVentajaDesventaja
FixedWindowSimple de entenderPicos al inicio de ventana
SlidingWindowSuaviza el tráficoLigeramente más complejo
TokenBucketPermite ráfagas controladasRequiere ajustar tasa y capacidad
ConcurrencyLimita carga simultáneaNo protege por tiempo

Consejo de orden

CORS debe ir antes de autenticación porque el preflight OPTIONS no incluye credenciales. Rate limiting puede ir antes del routing si quieres proteger incluso rutas desconocidas, o después si quieres que no afecte a endpoints de salud.

3 · Ejemplo mínimo

Crearemos una API con rate limiting FixedWindow y CORS restringido.

dotnet new webapi -n RateLimitingCors -o RateLimitingCors
cd RateLimitingCors
dotnet run --project .
// Program.cs
var builder = WebApplication.CreateBuilder(args);

builder.Services.AddControllers();

builder.Services.AddCors(options =>
{
    options.AddPolicy("frontend", policy =>
    {
        policy.WithOrigins("https://localhost:3000")
              .WithMethods("GET", "POST")
              .WithHeaders("Content-Type", "Authorization")
              .AllowCredentials();
    });
});

builder.Services.AddRateLimiter(options =>
{
    options.RejectionStatusCode = 429;

    options.AddFixedWindowLimiter("fixed", policy =>
    {
        policy.PermitLimit = 5;
        policy.Window = TimeSpan.FromSeconds(10);
        policy.QueueProcessingOrder = QueueProcessingOrder.OldestFirst;
        policy.QueueLimit = 0;
    });

    options.AddPolicy("per-ip", context =>
    {
        var ip = context.Connection.RemoteIpAddress?.ToString() ?? "unknown";
        return RateLimitPartition.GetFixedWindowLimiter(ip, _ => new FixedWindowRateLimiterOptions
        {
            PermitLimit = 20,
            Window = TimeSpan.FromMinutes(1)
        });
    });
});

var app = builder.Build();

app.UseHttpsRedirection();

// CORS antes de autenticación
app.UseCors("frontend");

app.UseRateLimiter();

app.UseAuthorization();
app.MapControllers();

app.Run();
// Controllers/ValuesController.cs
using Microsoft.AspNetCore.Mvc;
using Microsoft.AspNetCore.RateLimiting;

[ApiController]
[Route("api/[controller]")]
[EnableRateLimiting("fixed")]
public class ValuesController : ControllerBase
{
    [HttpGet]
    public IActionResult Get() => Ok(new[] { "a", "b", "c" });
}

¿Qué ocurre aquí?

El endpoint /api/values usa la política fixed de 5 peticiones cada 10 segundos. Si superas el límite, el middleware devuelve 429. CORS aplica la política frontend a todas las peticiones.

4 · Ejemplo real

En una API con usuarios autenticados, limitar por IP no es suficiente: varios usuarios pueden compartir una IP. Limitaremos por usuario usando claims.

builder.Services.AddRateLimiter(options =>
{
    options.RejectionStatusCode = 429;
    options.AddPolicy("per-user", context =>
    {
        var userId = context.User.Identity?.IsAuthenticated == true
            ? context.User.FindFirst(ClaimTypes.NameIdentifier)!.Value
            : "anonymous";

        return RateLimitPartition.GetSlidingWindowLimiter(userId, _ => new SlidingWindowRateLimiterOptions
        {
            PermitLimit = 60,
            Window = TimeSpan.FromMinutes(1),
            SegmentsPerWindow = 6,
            QueueProcessingOrder = QueueProcessingOrder.OldestFirst,
            QueueLimit = 0
        });
    });
});

// Para aplicar globalmente:
app.UseRateLimiter();

Para aplicar por endpoint, usa [EnableRateLimiting("per-user")] en el controlador o el método.

CORS con origen dinámico

builder.Services.AddCors(options =>
{
    options.AddPolicy("dynamic", policy =>
    {
        policy.SetIsOriginAllowed(origin =>
            origin.StartsWith("https://app", StringComparison.OrdinalIgnoreCase))
              .AllowAnyHeader()
              .AllowAnyMethod()
              .AllowCredentials();
    });
});

No combines AllowAnyOrigin con AllowCredentials

El navegador rechaza la respuesta CORS si el origen es * y se envían credenciales. En producción, lista los orígenes permitidos explícitamente.

5 · Buenas prácticas

  • Define límites realistas. Limites muy bajos rompen clientes legítimos; límites muy altos no protegen.
  • Devuelve 429 con una cabecera Retry-After cuando sea posible. El middleware de .NET 8 no lo hace automáticamente, pero puedes personalizarlo.
  • Excluye endpoints de salud del rate limiting para no confundir a los balanceadores de carga.
  • Registra intentos rechazados con ILogger para detectar ataques o clientes mal configurados.
  • En CORS, nunca uses AllowAnyOrigin + AllowCredentials en producción.

6 · Errores habituales

6.1. CORS después de autenticación

// ❌ MAL: preflight sin credenciales falla antes de CORS
app.UseAuthentication();
app.UseCors("frontend");

// ✅ CORRECTO
app.UseCors("frontend");
app.UseAuthentication();

6.2. Rate limit sin mensaje útil

// ❌ MAL: devuelve 503 sin explicación
options.RejectionStatusCode = StatusCodes.Status503ServiceUnavailable;
// ✅ CORRECTO
options.RejectionStatusCode = StatusCodes.Status429TooManyRequests;
options.OnRejected = (context, token) =>
{
    context.Response.WriteAsync("Demasiadas peticiones. Inténtalo más tarde.", token);
    return new ValueTask();
};

6.3. FixedWindow para tráfico suave

// ❌ MAL: pico al inicio de cada minuto
options.AddFixedWindowLimiter("api", policy =>
{
    policy.PermitLimit = 100;
    policy.Window = TimeSpan.FromMinutes(1);
});
// ✅ CORRECTO: SlidingWindow reparte mejor
options.AddSlidingWindowLimiter("api", policy =>
{
    policy.PermitLimit = 100;
    policy.Window = TimeSpan.FromMinutes(1);
    policy.SegmentsPerWindow = 6;
});

7 · Ejercicio guiado

Configura un TokenBucket que permita 10 peticiones de golpe y se recargue a 2 peticiones por segundo.

builder.Services.AddRateLimiter(options =>
{
    options.RejectionStatusCode = 429;
    options.AddTokenBucketLimiter("token", policy =>
    {
        policy.TokenLimit = 10;
        policy.QueueProcessingOrder = QueueProcessingOrder.OldestFirst;
        policy.QueueLimit = 2;
        policy.ReplenishmentPeriod = TimeSpan.FromSeconds(1);
        policy.TokensPerPeriod = 2;
        policy.AutoReplenishment = true;
    });
});

app.UseRateLimiter();
app.MapGet("/limited", [EnableRateLimiting("token")] () => "OK");

Prueba con un bucle for i in {1..15}; do curl -i http://localhost:5000/limited; done y observa cómo algunas peticiones devuelven 429 hasta que se recargan tokens.

8 · Reto

Crea una política de rate limiting que combine dos reglas: autenticados tienen 100 peticiones/minuto; anónimos tienen 20 peticiones/minuto. Además, excluye del rate limiting la ruta /health pero sí aplica CORS a ella. Usa [DisableRateLimiting] y un Map separado si es necesario.

9 · Resumen

  • .NET 8 incluye rate limiting con FixedWindow, SlidingWindow, TokenBucket y Concurrency.
  • Usa AddRateLimiter, UseRateLimiter, [EnableRateLimiting] y [DisableRateLimiting].
  • Configura RejectionStatusCode y, si quieres, OnRejected para mensajes útiles.
  • CORS debe ir antes de autenticación y nunca combinarse AllowAnyOrigin con AllowCredentials.
  • El rate limiting se debe ajustar a autenticados y anónimos, y excluir endpoints de salud.

10 · Preguntas frecuentes

¿El rate limiting de .NET 8 reemplaza a AspNetCoreRateLimit?

Para muchos casos sí. Si necesitas reglas configurables desde una base de datos, integración con Redis o métricas avanzadas, AspNetCoreRateLimit o una solución con Redis siguen siendo útiles.

¿El rate limit se aplica por instancia o por cluster?

Por instancia. Si tienes varias réplicas, el límite se multiplica por el número de instancias. Para cluster, usa Redis o una base de datos central como contador.

¿CORS protege al servidor?

No. CORS protege al cliente (navegador). Un atacante puede hacer peticiones desde otros orígenes con herramientas como curl o Postman. La protección del servidor viene de autenticación, rate limiting y validación de inputs.

¿Por qué OPTIONS falla aunque la petición real funciona?

El navegador envía un preflight OPTIONS sin credenciales. Si el middleware de autenticación lo intercepta antes de CORS, el preflight se rechaza. Coloca UseCors antes de UseAuthentication.

¿Puedo usar rate limiting en Minimal APIs?

Sí. Tanto [EnableRateLimiting] como [DisableRateLimiting] funcionan en endpoints de Minimal APIs porque son atributos de metadatos que lee el sistema de endpoints.
