System.Text.Json en profundidad

Módulo 8 · ASP.NET Core Web API40 min

1 · Introducción

ASP.NET Core 8 usa System.Text.Json como serializador JSON por defecto. Es más rápido y consume menos memoria que Newtonsoft.Json, y está profundamente integrado con el runtime.

En esta lección aprenderemos a serializar y deserializar objetos, personalizar nombres de propiedades, ignorar campos, manejar polimorfismo, evitar ciclos y usar source generators para mejorar el rendimiento.

¿Por qué System.Text.Json?

Es la opción moderna en .NET: alto rendimiento, bajo alloc, compatible con UTF-8, y diseñado para ser seguro por defecto. Newtonsoft.Json sigue disponible, pero no es necesario en proyectos nuevos.

Errores típicos

  • Usar Newtonsoft.Json sin necesidad y añadir una dependencia extra.
  • No entender que System.Text.Json es case-sensitive por defecto.
  • Olvidar configurar ReferenceHandler.IgnoreCycles y provocar excepciones por referencias circulares.
  • Serializar propiedades internas o de navegación de EF Core sin querer.

2 · Teoría

Serialización básica

JsonSerializer convierte objetos a JSON y viceversa. Acepta opciones globales o por llamada.

using System.Text.Json;

var persona = new Persona("Ana", 30);

// Serialización con opciones personalizadas
var json = JsonSerializer.Serialize(persona, new JsonSerializerOptions
{
    PropertyNamingPolicy = JsonNamingPolicy.CamelCase,
    WriteIndented = true
});

Console.WriteLine(json);

// Deserialización
var deserializada = JsonSerializer.Deserialize(json);

public record Persona(string Nombre, int Edad);

Configuración global en ASP.NET Core

En Program.cs puedes configurar las opciones que se aplican a todos los controllers y Minimal APIs.

builder.Services.AddControllers()
    .AddJsonOptions(options =>
    {
        options.JsonSerializerOptions.PropertyNamingPolicy = JsonNamingPolicy.CamelCase;
        options.JsonSerializerOptions.ReferenceHandler = ReferenceHandler.IgnoreCycles;
        options.JsonSerializerOptions.DefaultIgnoreCondition = JsonIgnoreCondition.WhenWritingNull;
    });

Atributos de serialización

AtributoEfecto
[JsonIgnore]No serializa/deserializa la propiedad.
[JsonPropertyName("nuevoNombre")]Cambia el nombre en JSON.
[JsonRequired]La propiedad debe estar presente al deserializar.
[JsonInclude]Incluye campos o propiedades privadas.
[JsonConverter(typeof(...))]Usa un conversor personalizado.
[JsonPolymorphic]Habilita serialización polimórfica.
[JsonDerivedType(typeof(Derived))]Registra un tipo derivado.

Polimorfismo

Por defecto, System.Text.Json serializa propiedades del tipo declarado, no del runtime. Para serializar tipos derivados necesitas [JsonPolymorphic] y [JsonDerivedType].

[JsonPolymorphic(TypeDiscriminatorPropertyName = "$type")]
[JsonDerivedType(typeof(Perro), "dog")]
[JsonDerivedType(typeof(Gato), "cat")]
public abstract class Animal
{
    public string Nombre { get; set; } = string.Empty;
}

public class Perro : Animal
{
    public string Raza { get; set; } = string.Empty;
}

public class Gato : Animal
{
    public bool EsIndoor { get; set; }
}

Referencia cíclica

Cuando dos entidades se referencian mutuamente (común en EF Core), la serialización puede entrar en bucle. La solución es ReferenceHandler.IgnoreCycles, que reemplaza referencias repetidas por null.

Evita exponer entidades de EF Core

La mejor forma de evitar ciclos y fugas de datos es no serializar entidades de dominio directamente. Usa DTOs planos y proyecta solo los campos necesarios.

3 · Ejemplo mínimo

# Crear proyecto de consola
dotnet new console -n JsonDemo -o JsonDemo
cd JsonDemo
dotnet run --project .

// Program.cs
using System.Text.Json;
using System.Text.Json.Serialization;

var options = new JsonSerializerOptions
{
    PropertyNamingPolicy = JsonNamingPolicy.CamelCase,
    WriteIndented = true,
    DefaultIgnoreCondition = JsonIgnoreCondition.WhenWritingNull
};

var post = new BlogPost
{
    Id = Guid.NewGuid(),
    Title = "Introducción a System.Text.Json",
    Content = "Contenido aquí",
    InternalNotes = null // Se ignorará gracias a WhenWritingNull
};

var json = JsonSerializer.Serialize(post, options);
Console.WriteLine(json);

var parsed = JsonSerializer.Deserialize(json, options);
Console.WriteLine(parsed?.Title);

public class BlogPost
{
    public Guid Id { get; set; }
    public string Title { get; set; } = string.Empty;
    public string? Content { get; set; }

    [JsonIgnore]
    public string? InternalNotes { get; set; }

    [JsonPropertyName("publishedAt")]
    public DateTime PublishedDate { get; set; }
}

Observa

JsonIgnoreCondition.WhenWritingNull evita que propiedades nulas aparezcan en el JSON, haciendo la respuesta más limpia.

4 · Ejemplo real

Configuramos ASP.NET Core para que serialice DTOs con camelCase, ignore nulos, evite ciclos y use un conversor personalizado para DateOnly.

// Program.cs
using System.Text.Json;
using System.Text.Json.Serialization;

var builder = WebApplication.CreateBuilder(args);

builder.Services.AddControllers()
    .AddJsonOptions(options =>
    {
        options.JsonSerializerOptions.PropertyNamingPolicy = JsonNamingPolicy.CamelCase;
        options.JsonSerializerOptions.DefaultIgnoreCondition = JsonIgnoreCondition.WhenWritingNull;
        options.JsonSerializerOptions.ReferenceHandler = ReferenceHandler.IgnoreCycles;
        options.JsonSerializerOptions.Converters.Add(new JsonStringEnumConverter());
        options.JsonSerializerOptions.Converters.Add(new DateOnlyJsonConverter());
    });

var app = builder.Build();
app.MapControllers();
app.Run();

// Conversor personalizado para DateOnly
public class DateOnlyJsonConverter : JsonConverter
{
    private const string Format = "yyyy-MM-dd";

    public override DateOnly Read(ref Utf8JsonReader reader, Type typeToConvert, JsonSerializerOptions options)
    {
        var value = reader.GetString();
        return DateOnly.ParseExact(value!, Format);
    }

    public override void Write(Utf8JsonWriter writer, DateOnly value, JsonSerializerOptions options)
    {
        writer.WriteStringValue(value.ToString(Format));
    }
}

// DTO de respuesta plano
public class PostResponse
{
    public Guid Id { get; set; }
    public string Title { get; set; } = string.Empty;
    public string? Summary { get; set; }
    public DateOnly PublishedDate { get; set; }
    public PostStatus Status { get; set; }
}

public enum PostStatus
{
    Draft,
    Published,
    Archived
}

Source generators

Para reducir el uso de reflection y mejorar el rendimiento en AOT, .NET permite generar el código de serialización en tiempo de compilación.

// Contexto de serialización con source generator
[JsonSerializable(typeof(PostResponse))]
[JsonSerializable(typeof(List))]
public partial class AppJsonContext : JsonSerializerContext
{
}

// Uso
var json = JsonSerializer.Serialize(post, AppJsonContext.Default.PostResponse);

Source generators en Minimal APIs

En .NET 8, los endpoints de Minimal API pueden usar contextos de serialización para evitar reflection. Pasa el JsonTypeInfo al escribir la respuesta o configura opciones globales con el contexto.

5 · Buenas prácticas

  • Usa System.Text.Json en proyectos nuevos. Es más rápido y está mejor integrado.
  • Configura opciones globales en AddJsonOptions para mantener consistencia.
  • Usa DTOs en lugar de serializar entidades de EF Core directamente.
  • Ignora propiedades nulas si el cliente no las necesita (WhenWritingNull).
  • Configura ReferenceHandler.IgnoreCycles si usas DTOs con referencias.
  • Usa JsonStringEnumConverter para serializar enums como cadenas legibles.
  • Considera source generators para aplicaciones con alto rendimiento o AOT.

6 · Errores habituales

Incorrecto: serializar entidades de EF Core

// ❌ Mal: exponemos navegaciones internas y riesgo de ciclos
[HttpGet("{id:guid}")]
public async Task GetById(Guid id)
{
    var post = await _db.Posts
        .Include(p => p.Category)
        .Include(p => p.Author)
        .FirstOrDefaultAsync(p => p.Id == id);

    return Ok(post);
}

Correcto: proyectar a DTO

// ✅ Bien: controlamos exactamente qué se devuelve
[HttpGet("{id:guid}")]
public async Task GetById(Guid id)
{
    var post = await _db.Posts
        .Where(p => p.Id == id)
        .Select(p => new PostResponse
        {
            Id = p.Id,
            Title = p.Title,
            Summary = p.Summary,
            PublishedDate = p.PublishedDate,
            Status = p.Status
        })
        .FirstOrDefaultAsync();

    return post is null ? NotFound() : Ok(post);
}

Incorrecto: depender del casing por defecto sin configurar

// ❌ Mal: el cliente espera camelCase y recibe PascalCase
var json = JsonSerializer.Serialize(new { UserName = "ana" });
// {"UserName":"ana"}

Correcto: configurar naming policy

// ✅ Bien: camelCase es el estándar en JSON moderno
var options = new JsonSerializerOptions { PropertyNamingPolicy = JsonNamingPolicy.CamelCase };
var json = JsonSerializer.Serialize(new { UserName = "ana" }, options);
// {"userName":"ana"}

9 · Resumen

  • System.Text.Json es el serializador por defecto en ASP.NET Core 8.
  • Configura opciones globales para naming, nulos, ciclos y enums.
  • Usa atributos como [JsonIgnore], [JsonPropertyName] y [JsonRequired] para controlar la serialización.
  • El polimorfismo requiere [JsonPolymorphic] y [JsonDerivedType].
  • Evita serializar entidades de EF Core; proyecta a DTOs.
  • Considera source generators para aplicaciones de alto rendimiento.

10 · Preguntas frecuentes

¿Cómo migro de Newtonsoft.Json a System.Text.Json?

Revisa cada JsonProperty, JsonConverter personalizado y configuración de referencias circulares. Muchas funciones tienen equivalentes, pero algunos casos avanzados requieren reescribir conversores.

¿System.Text.Json distingue mayúsculas/minúsculas?

Sí, por defecto es case-sensitive. Puedes cambiarlo con PropertyNameCaseInsensitive = true, aunque no es recomendable por rendimiento.

¿Cómo manejo referencias circulares?

Usa ReferenceHandler.IgnoreCycles o ReferenceHandler.Preserve. La mejor solución es proyectar a DTOs sin ciclos.

¿Qué es JsonIgnoreCondition?

Controla cuándo una propiedad se ignora: nunca, cuando es nula, cuando es el valor por defecto, o siempre.

¿Puedo usar source generators en controllers?

Sí, aunque ASP.NET Core los usa automáticamente en muchos casos. Para control total, configura JsonSerializerOptions con el contexto y úsalo explícitamente.
