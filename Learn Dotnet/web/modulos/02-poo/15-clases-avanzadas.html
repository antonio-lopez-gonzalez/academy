Características avanzadas de clases

Módulo 2 · POO en C# 35 minutos

1 · Introducción

C# ofrece herramientas adicionales para afinar el diseño de clases: clases anidadas, clases parciales, clases selladas y métodos de extensión. Son las que completan tu caja de herramientas de POO.

Objetivo

Conocer nested/partial/sealed y los extension methods.

2 · Teoría

Nested classes (clases anidadas)

Una clase puede declararse dentro de otra, normalmente como detalle de implementación:

class ListaEnlazada
{
    private class Nodo   // anidada: solo visible dentro de ListaEnlazada
    {
        public int Valor;
        public Nodo? Siguiente;
    }
}

Partial classes

Permiten dividir una clase en varios archivos. Útil en código generado o para organizar clases grandes:

// Archivo 1
public partial class Persona
{
    public string Nombre { get; set; } = "";
}

// Archivo 2
public partial class Persona
{
    public void Saludar() => Console.WriteLine($"Hola, soy {Nombre}");
}

El compilador fusiona ambas partes en una sola clase.

Partial methods

Un método declarado en una parte y, opcionalmente, implementado en otra:

public partial class Persona
{
    partial void OnCreada();   // declaración sin cuerpo
}

public partial class Persona
{
    partial void OnCreada() => Console.WriteLine("Persona creada");   // implementación opcional
}

sealed: clases y métodos sellados

sealed impide que una clase sea heredada, o que un método sobrescrito vuelva a sobrescribirse:

sealed class ClaseFinal
{
    // no puede heredarse
}

class Base
{
    public virtual void Metodo() { }
}

class Derivada : Base
{
    public sealed override void Metodo() { }   // ya no se puede sobrescribir más
}
¿Por qué sellar?

Sellar mejora el rendimiento (el compilador optimiza llamadas) y protege invariantes de diseño: garantiza que nadie cambie el comportamiento de tu clase.

Extension methods (métodos de extensión)

Añaden métodos a tipos existentes sin modificarlos. Se definen en una clase estática, con this en el primer parámetro:

public static class StringExtensions
{
    public static int ContarPalabras(this string texto)
    {
        return texto.Split(' ', StringSplitOptions.RemoveEmptyEntries).Length;
    }
}

// Ahora cualquier string tiene el método
int palabras = "Hola mundo .NET".ContarPalabras();   // 3

LINQ está construido enteramente con extension methods sobre IEnumerable<T>.

3 · Ejemplo mínimo

public static class Extensions
{
    public static bool EsPar(this int n) => n % 2 == 0;
}

Console.WriteLine(4.EsPar());   // True

4 · Ejemplo real

Métodos de extensión para validar datos de dominio, y una clase sellada:

public static class Validaciones
{
    public static bool EsEmailValido(this string email) =>
        email.Contains('@') && email.Contains('.');
}

public sealed class Usuario
{
    public string Email { get; init; } = "";

    public bool EsValido() => Email.EsEmailValido();   // usa el extension method
}

var u = new Usuario { Email = "ana@mail.com" };
Console.WriteLine(u.EsValido());   // True

6 · Errores habituales

Error 1: heredar de una clase sealed

sealed class A { }
// class B : A { }   // error: no se puede heredar de A

Error 2: extension method sin this

// El primer parámetro de un extension method debe llevar this
public static int ContarPalabras(this string texto) { /* ... */ }

Error 3: abusar de extension methods para lógica de dominio

// Si el método pertenece conceptualmente a tu clase, ponlo dentro de ella,
// no como extensión.

8 · Reto

Reto

Crea un extension method genérico EsVacia<T>(this IEnumerable<T>) que indique si una secuencia no tiene elementos, y úsalo con listas y arrays.

9 · Resumen

  • Clases anidadas: detalles internos de otra clase.
  • partial: divide una clase en varios archivos.
  • sealed: impide herencia o re-sobrescritura.
  • Extension methods: añaden métodos a tipos existentes.

10 · Preguntas frecuentes

¿Los extension methods se heredan?

Sí: si extiendes un tipo base, sus derivadas también tienen el método. Por eso extender object o IEnumerable<T> es tan potente.

¿Puedo hacer extension methods sobre cualquier tipo?

Sobre cualquier tipo accesible, incluyendo interfaces y tipos genéricos, siempre que el primer parámetro lleve this.

¿Cuándo sello una clase?

Cuando su diseño no está pensado para herencia. Microsoft recomienda sellar por defecto a menos que diseñes explícitamente para heredar.
