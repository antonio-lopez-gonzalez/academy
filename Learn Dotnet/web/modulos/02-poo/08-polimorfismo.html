Polimorfismo

Módulo 2 · POO en C# 45 minutos

1 · Introducción

Imagina una lista de Animal donde cada uno hace un sonido distinto. El polimorfismo permite escribir código que trata a todos por igual ("haz tu sonido") y que cada uno responda a su manera.

Objetivo

Usar virtual/override, referencias de tipo base y entender el dynamic dispatch.

2 · Teoría

¿Qué es el polimorfismo?

Es la capacidad de que un mismo código actúe de formas distintas según el tipo real del objeto en tiempo de ejecución. En .NET se logra con métodos virtual/override y referencias de tipo base.

Referencias de tipo base

class Animal
{
    public virtual void HacerSonido() => Console.WriteLine("...");
}

class Perro : Animal
{
    public override void HacerSonido() => Console.WriteLine("Guau");
}

class Gato : Animal
{
    public override void HacerSonido() => Console.WriteLine("Miau");
}

// Una referencia de tipo base puede apuntar a un objeto derivado
Animal animal = new Perro();
animal.HacerSonido();   // "Guau" (usa el tipo REAL, no el declarado)

virtual y override

  • virtual: marca un método de la base como sobrescribible.
  • override: sobrescribe ese método en la derivada.

Dynamic dispatch

Cuando llamas a un método virtual, la decisión de qué versión ejecutar se toma en tiempo de ejecución según el tipo real del objeto, no según el tipo de la variable:

var animales = new List<Animal> { new Perro(), new Gato(), new Perro() };

foreach (var a in animales)
{
    a.HacerSonido();   // Guau, Miau, Guau (cada uno según su tipo real)
}

abstract

Un método abstract no tiene implementación y obliga a las derivadas a implementarlo (próxima lección):

abstract class Animal
{
    public abstract void HacerSonido();   // sin cuerpo
}

class Perro : Animal
{
    public override void HacerSonido() => Console.WriteLine("Guau");
}

new (ocultar, no sobrescribir)

new oculta un miembro de la base en vez de sobrescribirlo, rompiendo el polimorfismo. Es una fuente clásica de errores:

class Animal
{
    public virtual void HacerSonido() => Console.WriteLine("...");
}

class Perro : Animal
{
    public new void HacerSonido() => Console.WriteLine("Guau");   // oculta, no sobrescribe
}

Animal a = new Perro();
a.HacerSonido();   // "..."  (¡sorpresa! no hay polimorfismo)
virtual/override vs new

override produce polimorfismo real; new solo oculta y rompe el dynamic dispatch. Usa new con mucha cautela.

3 · Ejemplo mínimo

Animal animal = new Perro();
animal.HacerSonido();   // "Guau"

4 · Ejemplo real

Un sistema de pagos donde cada método de pago se comporta distinto:

abstract class Pago
{
    public decimal Monto { get; set; }
    public abstract void Procesar();
}

class PagoTarjeta : Pago
{
    public override void Procesar() => Console.WriteLine($"Cobrando {Monto:C} con tarjeta");
}

class PagoPayPal : Pago
{
    public override void Procesar() => Console.WriteLine($"Cobrando {Monto:C} con PayPal");
}

var pagos = new List<Pago>
{
    new PagoTarjeta { Monto = 100 },
    new PagoPayPal { Monto = 50 },
};

foreach (var pago in pagos)
{
    pago.Procesar();   // cada uno procesa a su manera
}

9 · Resumen

  • Polimorfismo: un código, varios comportamientos según el tipo real.
  • virtual en la base, override en la derivada.
  • Dynamic dispatch: la versión se elige en tiempo de ejecución.
  • new oculta (rompe polimorfismo); abstract obliga a implementar.

10 · Preguntas frecuentes

¿Polimorfismo en tiempo de ejecución vs compilación?

El polimorfismo por herencia (virtual/override) se resuelve en tiempo de ejecución. La sobrecarga de métodos (misma firma distinta) se resuelve en compilación.

¿Qué es el dynamic dispatch?

El mecanismo por el que, al llamar a un método virtual, se busca la implementación más derivada del objeto real en tiempo de ejecución.

¿virtual o abstract?

virtual tiene implementación por defecto y puede sobrescribirse. abstract no tiene implementación y obliga a sobrescribir.
