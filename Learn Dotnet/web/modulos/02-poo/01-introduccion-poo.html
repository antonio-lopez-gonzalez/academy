Introducción a la POO

Módulo 2 · POO en C# 35 minutos

1 · Introducción

Hasta ahora escribiste código con variables, métodos y estructuras de control. Funciona, pero cuando el programa crece, el código procedural se vuelve difícil de mantener: funciones largas, datos sueltos y cambios que rompen cosas en cadena.

La Programación Orientada a Objetos (POO) es un paradigma: una forma de organizar el código agrupando datos y comportamiento en "objetos". Es la base sobre la que se construye casi todo el software moderno en .NET.

Objetivo

Entender qué es la POO, por qué existe y cuáles son sus 4 pilares.

2 · Teoría

POO vs programación procedural

En el enfoque procedural, piensas en funciones que operan sobre datos:

// Enfoque procedural: datos sueltos + funciones sueltas
string nombre = "Ana";
int edad = 30;

void Saludar(string n, int e) => Console.WriteLine($"{n}, {e} años");
void CumplirAnios(ref int e) => e++;

En POO, agrupas esos datos y funciones relacionadas en una misma unidad, la clase:

// Enfoque POO: datos + comportamiento juntos
class Persona
{
    public string Nombre { get; set; }
    public int Edad { get; set; }

    public void Saludar() => Console.WriteLine($"{Nombre}, {Edad} años");
    public void CumplirAnios() => Edad++;
}

¿Por qué surge la POO?

Los programas grandes tienen tres problemas recurrentes:

  • Complejidad: difícil entender qué hace cada parte.
  • Fragilidad: un cambio rompe código en sitios inesperados.
  • Rigidez: es difícil añadir nuevas funcionalidades.

La POO ataca estos problemas agrupando por conceptos (Persona, Cuenta, Pedido) en lugar de por operaciones sueltas.

Objetos y clases

  • Clase: es el molde o plantilla. Define qué datos y qué comportamiento tendrán los objetos.
  • Objeto: es una instancia concreta creada a partir de la clase.
Analogía

La clase es el plano de una casa; los objetos son las casas construidas. Del mismo plano salen muchas casas, cada una con sus propios datos (color, dirección).

Estado y comportamiento

  • Estado: los datos del objeto (sus propiedades/campos). Ej: Nombre, Edad.
  • Comportamiento: lo que el objeto puede hacer (sus métodos). Ej: Saludar(), CumplirAnios().

Instancias y referencias

var p1 = new Persona { Nombre = "Ana" };   // p1 es una instancia
var p2 = new Persona { Nombre = "Luis" };  // p2 es OTRA instancia

// p1 y p2 son referencias a objetos distintos en memoria
Console.WriteLine(p1.Nombre);   // Ana
Console.WriteLine(p2.Nombre);   // Luis

Identidad de un objeto

Cada objeto tiene una identidad propia: aunque dos objetos tengan los mismos datos, son objetos distintos:

var a = new Persona { Nombre = "Ana" };
var b = new Persona { Nombre = "Ana" };

Console.WriteLine(a == b);   // False: son referencias distintas

Más adelante verás que esto se relaciona con la igualdad por referencia vs por valor.

Los 4 pilares de la POO

PilarQué significa
EncapsulaciónOcultar el estado interno y exponer solo lo necesario.
AbstracciónMostrar solo lo esencial y ocultar los detalles.
HerenciaCrear clases a partir de otras (relación "es un").
PolimorfismoTratar objetos de distintos tipos de forma uniforme.

Los cuatro se cubrirán en las próximas lecciones con detalle.

3 · Ejemplo mínimo

class Persona
{
    public string Nombre { get; set; } = "";

    public void Saludar()
    {
        Console.WriteLine($"Hola, soy {Nombre}");
    }
}

var persona = new Persona { Nombre = "Ana" };
persona.Saludar();   // Hola, soy Ana

4 · Ejemplo real

Modelar una cuenta bancaria sencilla con estado (saldo) y comportamiento (depositar/retirar):

class CuentaBancaria
{
    public string Titular { get; set; } = "";
    public decimal Saldo { get; private set; }

    public void Depositar(decimal cantidad) => Saldo += cantidad;
    public void Retirar(decimal cantidad) => Saldo -= cantidad;
}

var cuenta = new CuentaBancaria { Titular = "Ana" };
cuenta.Depositar(1000);
cuenta.Retirar(250);
Console.WriteLine($"{cuenta.Titular}: {cuenta.Saldo:C}");   // Ana: 750,00 €

6 · Errores habituales

Error 1: confundir clase con objeto

// Persona es la clase (molde); "persona" (minúscula) es el objeto (instancia)
var persona = new Persona();

Error 2: crear "clases" que solo agrupan funciones sueltas

// Incorrecto: una clase sin estado que es solo un cajón de funciones
class Utilidades { public static void HacerA() {} public static void HacerB() {} }

// Mejor: clases que representan conceptos con estado y comportamiento propios

Error 3: creer que dos objetos con los mismos datos son "el mismo"

var a = new Persona { Nombre = "Ana" };
var b = new Persona { Nombre = "Ana" };
Console.WriteLine(a == b);   // False: identidades distintas

9 · Resumen

  • La POO agrupa datos (estado) y comportamiento en objetos.
  • Clase = molde; objeto = instancia concreta.
  • Cada objeto tiene identidad propia, aunque comparta datos.
  • Los 4 pilares: encapsulación, abstracción, herencia y polimorfismo.

10 · Preguntas frecuentes

¿POO es obligatoria en C#?

No es obligatoria, pero es el paradigma natural y dominante en .NET. Casi todas las APIs y frameworks (ASP.NET Core, EF Core) están diseñados con POO.

¿C# es puramente orientado a objetos?

C# es multiparadigma: soporta POO, programación funcional (LINQ, lambdas) y procedural. La POO es el paradigma principal, pero no el único.

¿Qué diferencia hay entre estado y comportamiento?

El estado es "lo que el objeto sabe" (sus datos); el comportamiento es "lo que el objeto hace" (sus métodos). Juntos definen una clase.
