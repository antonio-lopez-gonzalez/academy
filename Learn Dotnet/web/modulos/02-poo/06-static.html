Modificadores y miembros static

Módulo 2 · POO en C# 30 minutos

1 · Introducción

Hasta ahora todos los miembros pertenecían a cada objeto (cada persona tiene su propio nombre). Con static, un miembro pertenece a la clase, no a las instancias: es único y compartido.

Objetivo

Distinguir miembros de instancia y estáticos, y usar static con criterio.

2 · Teoría

Miembros de instancia vs static

class Persona
{
    public string Nombre { get; set; } = "";        // de instancia: cada objeto tiene el suyo
    public static int TotalPersonas { get; private set; }   // estático: compartido por todos

    public Persona()
    {
        TotalPersonas++;   // cada instancia incrementa el contador compartido
    }
}

var a = new Persona { Nombre = "Ana" };
var b = new Persona { Nombre = "Luis" };

Console.WriteLine(Persona.TotalPersonas);   // 2 (se accede desde la clase)
Console.WriteLine(a.Nombre);                // "Ana" (se accede desde la instancia)

Campos, métodos y propiedades estáticos

class Calculadora
{
    public static double Pi = 3.14159;                // campo estático

    public static double AreaCirculo(double radio)     // método estático
    {
        return Pi * radio * radio;
    }
}

// Se usan desde la clase, sin crear objetos
double area = Calculadora.AreaCirculo(2);
Console.WriteLine(Calculadora.Pi);

Clases estáticas

Una clase estática solo puede contener miembros estáticos. Es útil para utilidades:

static class Matematicas
{
    public static int Sumar(int a, int b) => a + b;
    public static int Restar(int a, int b) => a - b;
}

Console.WriteLine(Matematicas.Sumar(2, 3));   // 5
Ya lo has visto

Console.WriteLine, Math.PI, File.ReadAllText... todos son miembros estáticos de sus clases. Por eso los usas sin crear un Console.

Cuándo usar static

  • Funciones puras sin estado (ej. Math.Sqrt).
  • Contadores o datos compartidos.
  • Utilidades que no dependen de un objeto.

Problemas del abuso de static

Cuidado

El estado estático es global: se comparte en toda la aplicación y complica las pruebas unitarias y la programación concurrente. Un exceso de clases "Utility" estáticas suele ser señal de mal diseño. Usa static para funciones puras, no para guardar estado mutable global.

3 · Ejemplo mínimo

class Contador
{
    public static int Total { get; private set; }
    public void Incrementar() => Total++;
}

var c1 = new Contador();
var c2 = new Contador();
c1.Incrementar();
c2.Incrementar();
Console.WriteLine(Contador.Total);   // 2 (compartido)

4 · Ejemplo real

Una utilidad para validar datos que no necesita estado:

static class Validacion
{
    public static bool EsEmailValido(string email) =>
        email.Contains('@') && email.Contains('.');

    public static bool EsEdadValida(int edad) =>
        edad is >= 0 and <= 120;
}

Console.WriteLine(Validacion.EsEmailValido("ana@mail.com"));   // True
Console.WriteLine(Validacion.EsEdadValida(200));               // False

}

9 · Resumen

  • static hace que un miembro pertenezca a la clase, no a las instancias.
  • Campos, métodos y propiedades estáticos; clases estáticas.
  • Acceso: Clase.Miembro.

10 · Preguntas frecuentes

¿Puedo llamar a un método estático desde un objeto?

Técnicamente C# no lo permite de forma natural: los miembros estáticos se acceden desde la clase (Clase.Metodo()), no desde una instancia.

¿Cuándo una clase debería ser estática?

Cuando no tiene estado ni instancias y solo agrupa funciones utilitarias. Si necesita estado, usa una clase normal.

¿Por qué el estado estático es problemático?

Es global y compartido: cualquier parte del programa puede cambiarlo, dificulta el aislamiento de pruebas y es peligroso en ejecución concurrente.
