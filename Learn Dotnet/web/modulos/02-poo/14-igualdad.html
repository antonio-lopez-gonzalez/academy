Igualdad y objetos

Módulo 2 · POO en C# 40 minutos

1 · Introducción

¿Cuándo dos objetos son "iguales"? Para C#, la respuesta por defecto es "cuando son el mismo objeto". Pero a menudo quieres comparar por contenido, y eso cambia todo: desde el == hasta cómo funcionan los Dictionary.

Objetivo

Entender igualdad por referencia vs por valor, Equals, GetHashCode y IEquatable<T>.

2 · Teoría

Igualdad por referencia (por defecto)

Para clases normales, == y Equals comparan referencias: son iguales solo si son el mismo objeto:

class Persona
{
    public string Nombre { get; set; } = "";
}

var a = new Persona { Nombre = "Ana" };
var b = new Persona { Nombre = "Ana" };

Console.WriteLine(a == b);      // False (objetos distintos)
Console.WriteLine(a.Equals(b)); // False

Igualdad por valor (records)

Los records sobrescriben esta lógica para comparar por valor:

public record Persona(string Nombre);

var a = new Persona("Ana");
var b = new Persona("Ana");

Console.WriteLine(a == b);      // True (mismos datos)
Console.WriteLine(a.Equals(b)); // True

Equals, GetHashCode y IEquatable<T>

  • Equals: define la igualdad entre dos objetos.
  • GetHashCode: devuelve un hash que debe coincidir si dos objetos son iguales.
  • IEquatable<T>: versión fuertemente tipada de Equals.
class Persona : IEquatable<Persona>
{
    public string Nombre { get; init; } = "";

    public bool Equals(Persona? otra)
        => otra is not null && Nombre == otra.Nombre;

    public override bool Equals(object? obj) => Equals(obj as Persona);

    public override int GetHashCode() => Nombre.GetHashCode();
}

¿Por qué importa GetHashCode?

Las colecciones basadas en hash (Dictionary, HashSet) usan GetHashCode para encontrar rápido los elementos. Si dos objetos son "iguales" pero tienen hashes distintos, estas colecciones fallan silenciosamente.

Regla

Si sobrescribes Equals, siempre sobrescribe también GetHashCode de forma coherente: iguales ⇒ mismo hash.

Equality en Dictionary y HashSet

// Con records, la igualdad por valor funciona directamente
var personas = new HashSet<Persona>();
personas.Add(new Persona("Ana"));
personas.Add(new Persona("Ana"));   // no se añade (ya "existe")

Console.WriteLine(personas.Count);   // 1
var edades = new Dictionary<Persona, int>();
edades[new Persona("Ana")] = 30;
Console.WriteLine(edades[new Persona("Ana")]);   // 30 (misma clave "por valor")

var p1 = new Punto(1, 2);

4 · Ejemplo real

Usar un value object como clave de un diccionario gracias a la igualdad por valor:

public record Moneda(string Codigo);

var precios = new Dictionary<Moneda, decimal>();
precios[new Moneda("EUR")] = 1.10m;
precios[new Moneda("USD")] = 1.00m;

Console.WriteLine(precios[new Moneda("EUR")]);   // 1.10 (funciona por valor)

9 · Resumen

  • Por defecto, las clases comparan por referencia.
  • Los records comparan por valor automáticamente.
  • Equals + GetHashCode deben ir siempre coherentes.
  • IEquatable<T> para igualdad tipada y eficiente.

10 · Preguntas frecuentes

¿Por qué hay que sobrescribir GetHashCode?

Porque Dictionary y HashSet lo usan para localizar elementos. Dos objetos iguales deben tener el mismo hash para que funcionen.

¿Qué es IEquatable<T>?

Una interfaz que declara Equals(T) fuertemente tipado, evitando el boxing/casting del Equals(object).

¿== y Equals son lo mismo?

No siempre. Equals es virtual y se puede sobrescribir; == es un operador. En records y strings coinciden, pero en clases normales == compara referencias salvo que lo sobrescribas.
