Interfaces

Módulo 2 · POO en C# 40 minutos

1 · Introducción

Una interfaz define un contrato: qué métodos y propiedades debe tener una clase, sin decir cómo implementarlos. Es una de las herramientas más importantes del diseño en .NET, base de SOLID y de la inyección de dependencias.

Objetivo

Declarar e implementar interfaces, entender los contratos y la implementación múltiple.

2 · Teoría

¿Qué es una interfaz?

Es un tipo que declara miembros (métodos, propiedades) sin implementación. Las clases que la implementan se comprometen a proporcionar esa implementación.

// Convención: nombre con "I" al inicio
interface IVolador
{
    void Volar();          // método (sin cuerpo)
    int Velocidad { get; } // propiedad (sin cuerpo)
}

class Pajaro : IVolador
{
    public int Velocidad { get; set; } = 30;

    public void Volar()
    {
        Console.WriteLine($"Volando a {Velocidad} km/h");
    }
}

Implementación múltiple

A diferencia de la herencia de clases (una sola base), una clase puede implementar varias interfaces:

interface IVolador { void Volar(); }
interface INadador { void Nadar(); }

// Un pato vuela y nada: implementa ambas
class Pato : IVolador, INadador
{
    public void Volar() => Console.WriteLine("Volando");
    public void Nadar() => Console.WriteLine("Nadando");
}

Interfaces como contratos

La interfaz es una promesa: "quien me implemente, garantiza que puede hacer esto". Eso permite escribir código genérico:

void HacerVolar(IVolador volador)   // acepta CUALQUIER cosa que vuele
{
    volador.Volar();
}

HacerVolar(new Pajaro());
HacerVolar(new Avion());   // también implementa IVolador

Implementación explícita

Cuando dos interfaces chocan (mismo método), puedes implementarlas explícitamente:

interface IA { void Hacer(); }
interface IB { void Hacer(); }

class Clase : IA, IB
{
    void IA.Hacer() => Console.WriteLine("A");
    void IB.Hacer() => Console.WriteLine("B");
}

var c = new Clase();
((IA)c).Hacer();   // A
((IB)c).Hacer();   // B

Default interface methods (C# 8+)

Las interfaces pueden tener métodos con implementación por defecto:

interface IVolador
{
    void Volar();

    // Implementación por defecto (no obliga a implementarla)
    void Aterrizar() => Console.WriteLine("Aterrizando por defecto");
}

4 · Ejemplo real

Un contrato de repositorio que desacopla la lógica del almacenamiento:

interface IRepositorioProductos
{
    void Guardar(Producto producto);
    Producto? Buscar(int id);
}

class RepositorioEnMemoria : IRepositorioProductos
{
    private readonly Dictionary<int, Producto> _datos = new();

    public void Guardar(Producto p) => _datos[p.Id] = p;
    public Producto? Buscar(int id) => _datos.TryGetValue(id, out var p) ? p : null;
}

record Producto(int Id, string Nombre);

Esto es la semilla de la Inversión de Dependencias (DIP), que verás en SOLID.

6 · Errores habituales

Error 1: interfaz con implementación de estado

// Las interfaces no pueden tener campos ni estado
interface IAlgo
{
    // int _contador;   // error: no se permiten campos
    int Contador { get; }
}

Error 2: no implementar todos los miembros

interface IVolador { void Volar(); void Aterrizar(); }
class Pajaro : IVolador
{
    public void Volar() { }
    // falta Aterrizar() → error (salvo que sea default method)
}

Error 3: interfaz gigante (lo verás en ISP)

// Incorrecto: una interfaz con 20 métodos que nadie implementa del todo
// En SOLID verás cómo dividirla (Interface Segregation Principle)

9 · Resumen

  • Interfaz = contrato sin implementación.
  • Convención I...; implementación múltiple.
  • Programa contra la interfaz, no la implementación.
  • Implementación explícita y default methods (C# 8+).

10 · Preguntas frecuentes

¿Puede una interfaz heredar de otra?

Sí: interface IB : IA { }. Quien implemente IB debe implementar también los miembros de IA.

¿Cuándo interfaz y cuándo abstracta?

Interfaz: solo contrato. Abstracta: contrato + estado/lógica común que quieres compartir.

¿Las interfaces se pueden instanciar?

No directamente, pero puedes declarar una variable del tipo interfaz y asignarle una clase que la implemente.
