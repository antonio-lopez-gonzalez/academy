Composición

Módulo 2 · POO en C# 40 minutos

1 · Introducción

La herencia no es la única forma de reutilizar código, ni la mejor en todos los casos. La composición construye objetos combinando otros objetos. Es la alternativa preferida por los diseñadores experimentados.

Objetivo

Distinguir composición de herencia, usar delegación y entender por qué se recomienda "composición sobre herencia".

2 · Teoría

¿Qué es la composición?

Composición es cuando un objeto contiene a otros objetos para delegarles trabajo. Expresa una relación "tiene un" (has-a).

Coche ├── Motor ← el coche TIENE un motor └── Ruedas[4] ← el coche TIENE ruedas
class Motor
{
    public void Arrancar() => Console.WriteLine("Motor arrancado");
}

class Rueda
{
    public void Girar() => Console.WriteLine("Rueda girando");
}

// Composición: Coche está formado por un Motor y Ruedas
class Coche
{
    private readonly Motor _motor = new();
    private readonly List<Rueda> _ruedas = new() { new(), new(), new(), new() };

    public void Encender()
    {
        _motor.Arrancar();
        foreach (var rueda in _ruedas)
            rueda.Girar();
    }
}

Idea fundamental

La regla de oro

Herencia expresa "es un" (un Perro ES un Animal).
Composición expresa "tiene un" (un Coche TIENE un Motor).

Composición vs herencia

HerenciaComposición
Relación"es un""tiene un"
AcoplamientoAlto (deriva depende de la base)Bajo (colabora con interfaces)
FlexibilidadFija en compilaciónCambiable en tiempo de ejecución
ReutilizaciónVertical (jerarquías)Horizontal (piezas combinables)

Delegación

En composición, el objeto "dueño" delega en los objetos que contiene:

class Logger
{
    public void Log(string m) => Console.WriteLine($"[LOG] {m}");
}

class Servicio
{
    private readonly Logger _logger;

    public Servicio(Logger logger)   // recibe la dependencia
    {
        _logger = logger;
    }

    public void HacerAlgo()
    {
        _logger.Log("Haciendo algo");   // delega en Logger
    }
}

Dependencias entre objetos e inyección de dependencias

La composición introduce dependencias (el Servicio depende del Logger). Pasarlas por el constructor es la base de la Inyección de Dependencias (Dependency Injection), que verás en SOLID y en el desarrollo profesional.

Favorecer composición sobre herencia

Principio de diseño

La herencia es rígida y acopla fuerte. La composición permite combinar comportamientos de forma flexible. Ante la duda, compón en lugar de heredar.

3 · Ejemplo mínimo

class Motor
{
    public void Arrancar() => Console.WriteLine("Arrancando");
}

class Coche
{
    private readonly Motor _motor = new();
    public void Encender() => _motor.Arrancar();
}

4 · Ejemplo real

Un servicio de pedidos que compone varios colaboradores (repositorio, notificador, logger):

class PedidoService
{
    private readonly RepositorioPedidos _repositorio;
    private readonly Notificador _notificador;

    public PedidoService(RepositorioPedidos repositorio, Notificador notificador)
    {
        _repositorio = repositorio;
        _notificador = notificador;
    }

    public void CrearPedido(Pedido pedido)
    {
        _repositorio.Guardar(pedido);
        _notificador.Enviar($"Pedido {pedido.Id} creado");
    }
}

6 · Errores habituales

Error 1: usar herencia para "tiene un"

// Incorrecto: un Coche NO es un Motor
// class Coche : Motor { }

// Correcto: un Coche TIENE un Motor
class Coche { private readonly Motor _motor = new(); }

Error 2: composición con dependencias ocultas

// Incorrecto: crear dependencias dentro (ocultas y difíciles de testear)
class Servicio { private readonly Logger _l = new Logger(); }

// Correcto: inyectarlas por constructor
class Servicio { private readonly Logger _l; public Servicio(Logger l) => _l = l; }

Error 3: jerarquía de herencia demasiado profunda

// A > B > C > D > E: frágil y difícil de cambiar. Considera composición.

9 · Resumen

  • Composición = un objeto contiene a otros ("tiene un").
  • Herencia = "es un"; composición = "tiene un".
  • Delegación y dependencias por constructor.
  • Favorece composición sobre herencia.

10 · Preguntas frecuentes

¿Composición e inyección de dependencias son lo mismo?

No. La composición es la idea de combinar objetos. La inyección de dependencias es una técnica para suministrar esas piezas (normalmente por constructor) en lugar de crearlas dentro.

¿Cuándo sí conviene la herencia?

Cuando hay una relación "es un" estable y un comportamiento común claro. Pero incluso entonces, muchas veces una interfaz + composición es más flexible.

¿Qué es la delegación?

Cuando un objeto reenvía una llamada a otro objeto que contiene, en lugar de implementarla él mismo.
