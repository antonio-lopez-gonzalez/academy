Minimal APIs avanzadas

Módulo 17 · Temas avanzados30 min

1. Introducción

En esta lección profundizamos en las Minimal APIs de ASP.NET Core. Ya sabemos crear endpoints simples; ahora veremos cómo organizar rutas con MapGroup, reutilizar lógica con IEndpointFilter, enlazar parámetros personalizados con BindAsync y devolver respuestas tipadas con TypedResults.

El objetivo es escribir APIs compactas, expresivas y fáciles de mantener sin caer en la duplicación de código.

Objetivo de aprendizaje: dominar grupos de rutas, filtros de endpoints, binding personalizado y resultados tipados en Minimal APIs.

2. Teoría

¿Cuándo usar Minimal APIs?

Las Minimal APIs son ideales cuando el dominio es pequeño, cuando queremos rapidez de desarrollo y cuando no necesitamos la estructura completa de controladores. Para APIs grandes con mucha lógica, controladores con ControllerBase siguen siendo una opción válida.

MapGroup

MapGroup permite agrupar endpoints que comparten prefijo, filtros o convenciones. Reduce la repetición y mejora la legibilidad.

IEndpointFilter

Un filtro de endpoint es como un middleware, pero a nivel de endpoint. Se ejecuta antes y después del handler. Sirve para validación, logging, autorización específica o transformación de respuestas.

BindAsync

BindAsync permite crear tipos que se enlazan automáticamente desde la request. Es útil para encapsular reglas de parsing, validación o combinación de fuentes (query + header, por ejemplo).

TypedResults vs Results

Results es un helper que devuelve IResult con respuestas genéricas. TypedResults devuelve tipos concretos como Ok<T>, CreatedAtRoute<T> o ValidationProblem. Esto mejora la generación de documentación OpenAPI y el type safety.

// Con Results: el tipo de retorno es IResult
app.MapGet("/posts/{id}", (Guid id) => Results.Ok(post));

// Con TypedResults: el tipo de retorno es Results<Ok<Post>, NotFound>
app.MapGet("/posts/{id}", (Guid id) =>
    post is null ? TypedResults.NotFound() : TypedResults.Ok(post));

3. Ejemplo mínimo

Creamos un grupo de rutas con un filtro que valida un header de API key.

// Program.cs
var builder = WebApplication.CreateBuilder(args);
var app = builder.Build();

// Grupo de rutas con prefijo común
var api = app.MapGroup("/api/v1/posts")
    .AddEndpointFilter(async (context, next) =>
    {
        // Filtro que se aplica a todos los endpoints del grupo
        if (!context.HttpContext.Request.Headers.ContainsKey("X-Api-Key"))
        {
            return Results.Unauthorized();
        }

        return await next(context);
    });

api.MapGet("/", () => Results.Ok(new[] { "Post 1", "Post 2" }));
api.MapGet("/{id}", (Guid id) => Results.Ok(new { Id = id, Title = "Demo" }));
api.MapPost("/", (CreatePostRequest request) => Results.Created($"/api/v1/posts/{Guid.NewGuid()}", request));

app.Run();

public sealed record CreatePostRequest(string Title, string Content);

Para ejecutarlo:

dotnet run --project ejemplos/m17-avanzados/MinimalApisAdvancedDemo
Tip: los filtros de grupo se aplican a todos los endpoints del grupo, pero no afectan a endpoints fuera del grupo.

4. Ejemplo real

Construimos una API de posts con validación de request mediante BindAsync, respuestas tipadas y filtros reutilizables.

// Program.cs
using Microsoft.AspNetCore.Http.HttpResults;

var builder = WebApplication.CreateBuilder(args);
builder.Services.AddSingleton<IPostService, InMemoryPostService>();

var app = builder.Build();

// Grupo con prefijo y filtros
var posts = app.MapGroup("/api/v1/posts")
    .WithTags("Posts")
    .WithOpenApi()
    .AddEndpointFilter<ValidationFilter>();

posts.MapGet("/", Task<Ok<List<PostResponse>>> (IPostService service, CancellationToken ct)
    => service.ListAsync(ct))
    .WithName("ListPosts");

posts.MapGet("/{id:guid}", async Task<Results<Ok<PostResponse>, NotFound>> (
    Guid id,
    IPostService service,
    CancellationToken ct) =>
{
    var post = await service.GetByIdAsync(id, ct);
    return post is null ? TypedResults.NotFound() : TypedResults.Ok(post);
}).WithName("GetPostById");

posts.MapPost("/", async Task<Results<CreatedAtRoute<PostResponse>, ValidationProblem>> (
    CreatePostRequest request,
    IPostService service,
    CancellationToken ct) =>
{
    var created = await service.CreateAsync(request, ct);
    return TypedResults.CreatedAtRoute(created, "GetPostById", new { id = created.Id });
}).WithName("CreatePost");

app.Run();
// CreatePostRequest.cs con BindAsync
public sealed class CreatePostRequest
{
    public string Title { get; set; } = string.Empty;
    public string Content { get; set; } = string.Empty;
    public string? AuthorEmail { get; set; }

    public static async ValueTask<CreatePostRequest?> BindAsync(
        HttpContext context,
        ParameterInfo parameter)
    {
        // Podemos combinar body con headers u otros valores
        var request = await context.Request.ReadFromJsonAsync<CreatePostRequest>();

        if (request is null)
            return null;

        // Regla de negocio de binding: si no hay email, lo tomamos de un claim
        request.AuthorEmail ??= context.User.Identity?.Name;

        return request;
    }
}
// ValidationFilter.cs
public class ValidationFilter(ILogger<ValidationFilter> logger) : IEndpointFilter
{
    public async ValueTask<object?> InvokeAsync(
        EndpointFilterInvocationContext context,
        EndpointFilterDelegate next)
    {
        logger.LogInformation("Validando endpoint {Endpoint}", context.HttpContext.Request.Path);

        foreach (var argument in context.Arguments)
        {
            if (argument is IValidatableObject validatable)
            {
                var validationResults = validatable.Validate(new ValidationContext(validatable));
                if (validationResults.Any())
                {
                    var errors = validationResults.ToDictionary(
                        r => r.MemberNames.FirstOrDefault() ?? string.Empty,
                        r => new[] { r.ErrorMessage ?? "Error" });

                    return TypedResults.ValidationProblem(errors);
                }
            }
        }

        return await next(context);
    }
}
Observación: TypedResults permite que Swagger/OpenAPI infiera el tipo de respuesta correctamente. Con Results.Ok(...), OpenAPI no siempre detecta el esquema.

5. Buenas prácticas

  • Agrupa endpoints relacionados con MapGroup: evita repetir prefijos y filtros.
  • Prefiere TypedResults sobre Results: mejora la documentación y el type safety.
  • Extrae filtros a clases reutilizables: no escribas filtros inline complejos.
  • Usa BindAsync para lógica de binding no trivial: combinar fuentes, aplicar transformaciones o validaciones iniciales.
  • No pongas lógica de negocio en los filtros: los filtros son infraestructura, no dominio.
  • Limita los filtros por grupo: demasiados filtros encadenados oscurecen el flujo de la request.
  • Usa Minimal APIs para APIs pequeñas y medianas: para APIs grandes considera controladores o vertical slices.

6. Errores habituales

Devolver IResult sin tipar

// MAL: OpenAPI no puede inferir el tipo de respuesta
app.MapGet("/posts/{id}", async (Guid id, IPostService service) =>
{
    var post = await service.GetByIdAsync(id);
    return post is null ? Results.NotFound() : Results.Ok(post);
});

Solución: usa TypedResults para declarar explícitamente los posibles tipos de respuesta.

Filtros que no llaman a next

// MAL: short-circuit sin devolver respuesta válida
.AddEndpointFilter(async (context, next) =>
{
    if (!context.HttpContext.User.Identity?.IsAuthenticated ?? true)
    {
        return null; // ❌ null rompe la pipeline
    }

    return await next(context);
});

Solución: devuelve siempre un IResult válido cuando cortocircuitas.

BindAsync sin manejar null

// MAL: el body puede ser null y no se valida
public static ValueTask<CreatePostRequest> BindAsync(HttpContext context, ParameterInfo parameter)
{
    return context.Request.ReadFromJsonAsync<CreatePostRequest>()!;
}

Solución: devuelve CreatePostRequest?, maneja el caso null y devuelve Results.BadRequest si es necesario.

9. Resumen

  • MapGroup organiza endpoints que comparten prefijo y filtros.
  • IEndpointFilter permite reutilizar lógica de validación, logging o autorización.
  • BindAsync personaliza el model binding para tipos complejos.
  • TypedResults mejora el type safety y la documentación de OpenAPI.
  • Las Minimal APIs avanzadas permiten construir APIs compactas y mantenibles.

10. Preguntas frecuentes

¿Puedo mezclar Minimal APIs y controladores?

Sí. En el mismo proyecto puedes tener endpoints mínimos y controladores. Úsalo para migraciones graduales o para separar responsabilidades.

¿Cómo añado autenticación a un grupo?

Usa .RequireAuthorization() en el grupo o en endpoints individuales. También puedes crear un filtro personalizado.

¿TypedResults funciona con Swagger?

Sí, y funciona mejor que Results. Swagger puede inferir los tipos de respuesta y generar documentación más precisa.

¿Puedo inyectar servicios en un filtro?

Sí. Los filtros implementados como clases con constructor admiten inyección de dependencias. Los filtros inline solo capturan variables del scope.

¿Cuándo no usar Minimal APIs?

Cuando la API crece mucho, cuando necesitas filtros de acción de MVC complejos, o cuando tu equipo prefiere la estructura explícita de controladores y carpetas.
