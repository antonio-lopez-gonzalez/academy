Proyecto CMS: gRPC + telemetría + Polly

Módulo 17 · Temas avanzados55 min

1 · Introducción

En este proyecto integraremos en el CMS que venimos construyendo los tres temas avanzados del módulo: gRPC para consultas internas de alto rendimiento, OpenTelemetry para observabilidad y Polly para comunicaciones resilientes.

Además añadiremos un feature flag que protege un endpoint beta de la nueva API. Al final del proyecto, el CMS contará con:

  • Un servicio gRPC para consultar posts por ID.
  • Trazas y métricas de OpenTelemetry para ASP.NET Core, EF Core, gRPC y HttpClient.
  • Un HttpClient resiliente con Polly para comunicación con un servicio externo de análisis.
  • Un endpoint beta protegido por FeatureGate.
Escenario real: el CMS necesita consultar un servicio de análisis externo para enriquecer posts. Usamos gRPC para comunicación interna entre microservicios, Polly para no caer ante fallos transitorios y OpenTelemetry para entender qué ocurre en producción.

2 · Teoría

Arquitectura del proyecto

Decisiones de diseño

  • gRPC para consultas internas: entre microservicios del mismo backend, gRPC aporta contratos fuertes y menor latencia.
  • REST para la API pública: los clientes externos consumen JSON a través de controladores REST.
  • Polly para llamadas externas: la API de análisis es externa; los reintentos y el circuit breaker protegen al CMS.
  • OpenTelemetry end-to-end: una traza sigue desde la petición REST hasta el servicio gRPC, la base de datos y el servicio externo.
  • Feature flag para beta: permitimos activar el endpoint de análisis sin redeployar.

Estructura de proyectos

Añadimos al CMS un proyecto de librería Cms.Grpc con los archivos .proto y un servicio gRPC dentro de Cms.Api. Las trazas se configuran en el API y se propagan automáticamente por gRPC y HttpClient.

// Protos/cms_posts.proto
syntax = "proto3";

option csharp_namespace = "Cms.Grpc";

package cms;

service CmsPostService {
  rpc GetPostById (GetPostByIdRequest) returns (PostGrpcResponse);
  rpc ListPostsByAuthor (ListPostsByAuthorRequest) returns (stream PostGrpcResponse);
}

message GetPostByIdRequest {
  string post_id = 1;
}

message ListPostsByAuthorRequest {
  string author_email = 1;
}

message PostGrpcResponse {
  string post_id = 1;
  string title = 2;
  string slug = 3;
  string status = 4;
  string author_email = 5;
}

// CmsPostGrpcService.cs
public class CmsPostGrpcService(
    IPostRepository repository,
    ILogger<CmsPostGrpcService> logger) : CmsPostService.CmsPostServiceBase
{
    public override async Task<PostGrpcResponse> GetPostById(
        GetPostByIdRequest request,
        ServerCallContext context)
    {
        using var activity = CmsTelemetry.ActivitySource.StartActivity("GrpcGetPostById");
        activity?.SetTag("post.id", request.PostId);

        var post = await repository.GetByIdAsync(Guid.Parse(request.PostId), context.CancellationToken);

        if (post is null)
            throw new RpcException(new Status(StatusCode.NotFound, "Post no encontrado"));

        return new PostGrpcResponse
        {
            PostId = post.Id.ToString(),
            Title = post.Title,
            Slug = post.Slug,
            Status = post.Status.ToString(),
            AuthorEmail = post.AuthorEmail
        };
    }

    public override async Task ListPostsByAuthor(
        ListPostsByAuthorRequest request,
        IServerStreamWriter<PostGrpcResponse> responseStream,
        ServerCallContext context)
    {
        await foreach (var post in repository.GetByAuthorAsync(request.AuthorEmail, context.CancellationToken))
        {
            await responseStream.WriteAsync(new PostGrpcResponse
            {
                PostId = post.Id.ToString(),
                Title = post.Title,
                Slug = post.Slug,
                Status = post.Status.ToString(),
                AuthorEmail = post.AuthorEmail
            });
        }
    }
}

4 · Ejemplo real

Integramos gRPC, Polly, OpenTelemetry y Feature Management en el Program.cs del CMS.

// Program.cs (fragmentos relevantes)
using OpenTelemetry.Resources;
using OpenTelemetry.Trace;
using OpenTelemetry.Metrics;

var builder = WebApplication.CreateBuilder(args);

// 1. Feature Management
builder.Services.AddFeatureManagement();

// 2. OpenTelemetry
builder.Services.AddOpenTelemetry()
    .ConfigureResource(resource => resource
        .AddService("Cms.Api")
        .AddAttributes(new Dictionary<string, object>
        {
            ["deployment.environment"] = builder.Environment.EnvironmentName
        }))
    .WithTracing(tracing => tracing
        .AddSource("Cms.Api")
        .AddAspNetCoreInstrumentation()
        .AddHttpClientInstrumentation()
        .AddGrpcClientInstrumentation()
        .AddGrpcAspNetCoreInstrumentation()
        .AddEntityFrameworkCoreInstrumentation()
        .AddConsoleExporter()
        .AddOtlpExporter(options => options.Endpoint = new Uri("http://localhost:4317")))
    .WithMetrics(metrics => metrics
        .AddAspNetCoreInstrumentation()
        .AddHttpClientInstrumentation()
        .AddRuntimeInstrumentation()
        .AddPrometheusExporter());

// 3. HttpClient con Polly para el servicio de análisis
builder.Services.AddHttpClient<IAnalyticsClient, AnalyticsClient>(client =>
{
    client.BaseAddress = new Uri(builder.Configuration["Analytics:BaseUrl"]!);
    client.DefaultRequestHeaders.Add("Accept", "application/json");
})
.AddPolicyHandler(GetRetryPolicy())
.AddPolicyHandler(GetCircuitBreakerPolicy());

// 4. gRPC
builder.Services.AddGrpc();

// 5. Controladores y servicios habituales
builder.Services.AddControllers();
builder.Services.AddEndpointsApiExplorer();
builder.Services.AddSwaggerGen();

var app = builder.Build();

// Middleware y endpoints
app.UseOpenTelemetryPrometheusScrapingEndpoint();

app.MapGrpcService<CmsPostGrpcService>();

app.MapControllers();

// Endpoint beta protegido por feature flag
app.MapGet("/api/v1/analytics/posts/{postId:guid}",
    [FeatureGate("PostAnalytics")]
    async Task<Results<Ok<PostAnalyticsResponse>, NotFound>> (
        Guid postId,
        IAnalyticsClient analyticsClient,
        CancellationToken ct) =>
    {
        var result = await analyticsClient.GetPostAnalyticsAsync(postId, ct);
        return result is null ? TypedResults.NotFound() : TypedResults.Ok(result);
    });

app.Run();

static IAsyncPolicy<HttpResponseMessage> GetRetryPolicy()
{
    return HttpPolicyExtensions
        .HandleTransientHttpError()
        .WaitAndRetryAsync(
            retryCount: 3,
            sleepDurationProvider: retryAttempt =>
                TimeSpan.FromSeconds(Math.Pow(2, retryAttempt)) +
                TimeSpan.FromMilliseconds(Random.Shared.Next(0, 1000)),
            onRetry: (outcome, duration, attempt, context) =>
            {
                var logger = context.GetLogger();
                logger?.LogWarning("Analytics retry {Attempt} after {Seconds}s", attempt, duration.TotalSeconds);
            });
}

static IAsyncPolicy<HttpResponseMessage> GetCircuitBreakerPolicy()
{
    return HttpPolicyExtensions
        .HandleTransientHttpError()
        .CircuitBreakerAsync(
            handledEventsAllowedBeforeBreaking: 5,
            durationOfBreak: TimeSpan.FromSeconds(30));
}
// CmsTelemetry.cs
public static class CmsTelemetry
{
    public static readonly ActivitySource ActivitySource = new("Cms.Api");
    public static readonly Meter Meter = new("Cms.Api");

    public static readonly Counter<long> AnalyticsRequests =
        Meter.CreateCounter<long>("cms.analytics_requests", "requests", "Llamadas al servicio de análisis");

    public static readonly Histogram<double> AnalyticsResponseTimeMs =
        Meter.CreateHistogram<double>("cms.analytics_response_time_ms", "ms", "Tiempo de respuesta del servicio de análisis");

    public static ILogger? GetLogger(this Context context)
    {
        context.TryGetLogger(out var logger);
        return logger;
    }
}
// AnalyticsClient.cs
public interface IAnalyticsClient
{
    Task<PostAnalyticsResponse?> GetPostAnalyticsAsync(Guid postId, CancellationToken ct = default);
}

public class AnalyticsClient(
    HttpClient httpClient,
    ILogger<AnalyticsClient> logger) : IAnalyticsClient
{
    public async Task<PostAnalyticsResponse?> GetPostAnalyticsAsync(Guid postId, CancellationToken ct = default)
    {
        using var activity = CmsTelemetry.ActivitySource.StartActivity("AnalyticsClient.GetPostAnalytics");

        var stopwatch = Stopwatch.StartNew();
        try
        {
            var response = await httpClient.GetAsync($"posts/{postId}/analytics", ct);
            response.EnsureSuccessStatusCode();

            CmsTelemetry.AnalyticsRequests.Add(1,
                new KeyValuePair<string, object?>("status", "success"));

            return await response.Content.ReadFromJsonAsync<PostAnalyticsResponse>(ct);
        }
        catch (HttpRequestException ex)
        {
            logger.LogError(ex, "Error consultando analytics del post {PostId}", postId);
            CmsTelemetry.AnalyticsRequests.Add(1,
                new KeyValuePair<string, object?>("status", "error"));
            return null;
        }
        finally
        {
            CmsTelemetry.AnalyticsResponseTimeMs.Record(stopwatch.Elapsed.TotalMilliseconds);
        }
    }
}

public sealed record PostAnalyticsResponse(Guid PostId, int Views, int Likes, DateTime CalculatedAt);

5 · Buenas prácticas

  • Usa gRPC para comunicación interna entre servicios .NET: aprovecha contratos fuertes y menor serialización.
  • Expone REST al exterior: los clientes públicos y terceros entienden JSON y HTTP.
  • Configura Polly en todos los clientes externos: retry, circuit breaker y timeout deben ser la norma.
  • Instrumenta automáticamente y manualmente: las librerías de OpenTelemetry cubren el framework; tú añade spans y métricas de negocio.
  • Usa feature flags para capacidades nuevas: permite activar funcionalidades gradualmente y desactivarlas si fallan.
  • Guarda secretos en variables de entorno o key vault: nunca commitea la URL o claves de servicios externos.
  • Documenta las métricas y trazas personalizadas: tu equipo de operaciones necesita saber qué significan.

6 · Errores habituales

No exponer HTTP/2 sin TLS en producción

gRPC requiere HTTP/2. En producción configura TLS. En desarrollo, Kestrel puede aceptar HTTP/2 sin TLS, pero nunca en un entorno real.

Registrar HttpClient sin nombre o tipo

// MAL: HttpClient sin Polly, no gestiona sockets ni resiliencia
builder.Services.AddHttpClient();

Solución: usa AddHttpClient<IAnalyticsClient, AnalyticsClient> con AddPolicyHandler.

Mezclar feature flags con autorización

// MAL: un feature flag no es un permiso
[FeatureGate("AdminFeature")]

Solución: usa [Authorize(Roles = "Admin")] para permisos y FeatureGate para disponibilidad de funcionalidades.

Olvidar registrar ActivitySource

// MAL: se crea ActivitySource pero no se añade al provider
builder.Services.AddOpenTelemetry()
    .WithTracing(t => t.AddAspNetCoreInstrumentation());

Solución: añade .AddSource("Cms.Api") en el TracerProvider.

9 · Resumen

  • gRPC añade consultas internas de alto rendimiento al CMS.
  • OpenTelemetry proporciona observabilidad end-to-end sobre REST, gRPC, EF Core y HttpClient.
  • Polly protege las llamadas al servicio externo de análisis con retry y circuit breaker.
  • Los feature flags permiten activar funcionalidades beta sin redeployar.
  • La combinación de estas técnicas eleva el CMS a un nivel profesional y preparado para producción.

10 · Preguntas frecuentes

¿Necesito dos puertos para gRPC y REST?

No. ASP.NET Core puede servir gRPC y REST en el mismo puerto si el cliente soporta HTTP/2. Algunos clientes antiguos requieren puertos separados.

¿Cómo visualizo las trazas del CMS?

Configura el exportador OTLP apuntando a un collector local. Usa Jaeger en http://localhost:16686 para explorar las trazas.

¿El circuit breaker de Polly afecta a todos los endpoints?

No. La política está vinculada al HttpClient de AnalyticsClient. Solo afecta a las llamadas a ese servicio externo.

¿Puedo desactivar un feature flag en caliente?

Con appsettings.json el archivo se recarga automáticamente. Para cambios inmediatos sin reiniciar, usa Azure App Configuration.

¿Qué pasa si el gRPC devuelve NotFound?

El servidor lanza un RpcException con StatusCode.NotFound. El cliente lo recibe como una excepción que debe manejar o transformar a un NotFound de REST.

¿Es obligatorio usar Polly si uso HttpClientFactory?

No es obligatorio, pero es muy recomendable para cualquier llamada a servicios externos. La fábrica soluciona el agotamiento de sockets; Polly añade resiliencia ante fallos.
