gRPC en .NET

Módulo 17 · Temas avanzados35 min

1. Introducción

En esta lección aprenderemos a usar gRPC, un framework de RPC de alto rendimiento creado por Google. A diferencia de REST, donde enviamos JSON sobre HTTP, gRPC usa Protocol Buffers como serializador y HTTP/2 como transporte.

Veremos cómo definir servicios en archivos .proto, generar código C# automáticamente, implementar los cuatro tipos de llamadas (unary, server streaming, client streaming y bidi streaming) y usar gRPC-Web para clientes navegador.

Objetivo de aprendizaje: entender cuándo gRPC supera a REST, crear un servicio gRPC en .NET 8 y consumirlo desde un cliente, incluyendo streaming y gRPC-Web.

2. Teoría

¿Qué es gRPC?

gRPC es un protocolo de llamada a procedimiento remoto. El cliente invoca un método como si fuera local, pero la ejecución ocurre en otro proceso o máquina. La definición del contrato se escribe en un archivo .proto, y el compilador de protobuf genera el código C# tanto para cliente como para servidor.

Protocol Buffers

Protocol Buffers (protobuf) es un formato binario de serialización. Es más compacto y rápido que JSON, y tiene esquemas fuertes. Cada mensaje se define con campos tipados y números de campo. Los números son importantes: si cambian, el esquema deja de ser compatible.

syntax = "proto3";

option csharp_namespace = "Cms.Grpc";

message GetPostRequest {
  string post_id = 1; // 1 es el número de campo
}

message PostResponse {
  string post_id = 1;
  string title = 2;
  string content = 3;
  string author_email = 4;
}

Tipos de llamadas gRPC

  • Unary: una petición, una respuesta. Similar a REST.
  • Server streaming: una petición, múltiples respuestas. Útil para logs o notificaciones.
  • Client streaming: múltiples peticiones, una respuesta. Útil para subir archivos en chunks.
  • Bidi streaming: múltiples peticiones y respuestas simultáneas. Chat, juegos, sensores.

gRPC-Web

Los navegadores no pueden forzar HTTP/2 con el formato binario de gRPC de forma nativa. gRPC-Web adapta el protocolo para funcionar sobre HTTP/1.1 o HTTP/2 con un proxy intermedio. Es adecuado para SPAs y Blazor, aunque en este curso no usamos Blazor.

3. Ejemplo mínimo

Creamos un servicio gRPC con una única llamada unary: GetPost.

# Creamos un proyecto gRPC
dotnet new grpc -n GrpcDemo -o ejemplos/m17-avanzados/GrpcDemo

# El proyecto gRPC ya incluye el paquete Grpc.AspNetCore
// Protos/posts.proto
syntax = "proto3";

option csharp_namespace = "Cms.Grpc";

service PostsGrpc {
  rpc GetPost (GetPostRequest) returns (PostResponse);
}

message GetPostRequest {
  string post_id = 1;
}

message PostResponse {
  string post_id = 1;
  string title = 2;
  string content = 3;
}
// Services/PostsGrpcService.cs
using Grpc.Core;

namespace Cms.Grpc.Services;

public class PostsGrpcService(IPostRepository repository) : PostsGrpc.PostsGrpcBase
{
    public override async Task<PostResponse> GetPost(
        GetPostRequest request,
        ServerCallContext context)
    {
        var post = await repository.GetByIdAsync(Guid.Parse(request.PostId), context.CancellationToken);

        if (post is null)
            throw new RpcException(new Status(StatusCode.NotFound, "Post no encontrado"));

        return new PostResponse
        {
            PostId = post.Id.ToString(),
            Title = post.Title,
            Content = post.Content
        };
    }
}
// Program.cs
var builder = WebApplication.CreateBuilder(args);
builder.Services.AddGrpc();

var app = builder.Build();

app.MapGrpcService<PostsGrpcService>();

app.Run();

Para consumir el servicio desde un cliente:

# Creamos un cliente de consola
dotnet new console -n GrpcClientDemo -o ejemplos/m17-avanzados/GrpcClientDemo

# Añadimos los paquetes de gRPC para el cliente
dotnet add package Grpc.Net.Client
dotnet add package Google.Protobuf
dotnet add package Grpc.Tools
// Program.cs del cliente
using var channel = GrpcChannel.ForAddress("http://localhost:5000");
var client = new PostsGrpc.PostsGrpcClient(channel);

var response = await client.GetPostAsync(new GetPostRequest { PostId = "123e4567-e89b-12d3-a456-426614174000" });

Console.WriteLine($"Título: {response.Title}");
Cuidado: en desarrollo con HTTP sin TLS, debes permitir HTTP/2 sin TLS. En producción usa siempre HTTPS.

4. Ejemplo real

Implementamos un servicio de streaming de notificaciones de posts: el servidor envía posts nuevos a medida que se publican.

// Protos/post_stream.proto
syntax = "proto3";

option csharp_namespace = "Cms.Grpc";

service PostStreamGrpc {
  rpc SubscribeToNewPosts (SubscribeRequest) returns (stream PostPublishedMessage);
  rpc PublishPostStream (stream PublishPostRequest) returns (PublishSummary);
}

message SubscribeRequest {
  string category_id = 1;
}

message PostPublishedMessage {
  string post_id = 1;
  string title = 2;
  string published_at = 3;
}

message PublishPostRequest {
  string title = 1;
  string content = 2;
}

message PublishSummary {
  int32 total_published = 1;
}
// Services/PostStreamGrpcService.cs
public class PostStreamGrpcService(IPostNotifier notifier) : PostStreamGrpc.PostStreamGrpcBase
{
    public override async Task SubscribeToNewPosts(
        SubscribeRequest request,
        IServerStreamWriter<PostPublishedMessage> responseStream,
        ServerCallContext context)
    {
        await foreach (var post in notifier.GetNewPostsAsync(request.CategoryId, context.CancellationToken))
        {
            await responseStream.WriteAsync(new PostPublishedMessage
            {
                PostId = post.Id.ToString(),
                Title = post.Title,
                PublishedAt = post.PublishedAt.ToString("O")
            });
        }
    }

    public override async Task<PublishSummary> PublishPostStream(
        IAsyncStreamReader<PublishPostRequest> requestStream,
        ServerCallContext context)
    {
        var count = 0;
        await foreach (var request in requestStream.ReadAllAsync(context.CancellationToken))
        {
            await notifier.PublishAsync(request.Title, request.Content, context.CancellationToken);
            count++;
        }

        return new PublishSummary { TotalPublished = count };
    }
}
// Program.cs del servidor con gRPC-Web
var builder = WebApplication.CreateBuilder(args);
builder.Services.AddGrpc();
builder.Services.AddGrpcWeb();

var app = builder.Build();

// gRPC-Web requiere un middleware de conversión
app.UseGrpcWeb();

app.MapGrpcService<PostStreamGrpcService>().EnableGrpcWeb();

app.Run();
Tip: en el servidor, un stream termina cuando el cliente cierra la conexión o cuando se cancela el CancellationToken. Siempre maneja OperationCanceledException para no llenar logs de errores.

5. Buenas prácticas

  • Reserva gRPC para comunicación interna entre microservicios: en APIs públicas expuestas a navegadores, REST sigue siendo más sencillo.
  • Versiona tus archivos .proto: no cambies los números de campo existentes. Añade campos nuevos con números nuevos.
  • Usa el campo google.protobuf.Timestamp: en lugar de cadenas para fechas. Nosotros usamos cadenas ISO para simplificar, pero Timestamp es más correcto.
  • Limita el tamaño de los mensajes: mensajes gigantescos degradan la eficiencia de HTTP/2.
  • Configura deadlines: usa CallOptions.Deadline para evitar llamadas colgadas.
  • Maneja RpcException: los códigos de estado gRPC (NotFound, Unavailable, etc.) son la forma correcta de comunicar errores.
  • Combina con Polly: los servicios gRPC también pueden ser resilientes ante reintentos.

6. Errores habituales

Cambiar el número de un campo existente

// MAL: el campo title cambió de 2 a 5
message PostResponse {
  string post_id = 1;
  string title = 5; // ❌ rompe la compatibilidad
  string content = 3;
}

Solución: mantén los números de campo existentes. Si necesitas renombrar, deja el número igual.

Usar gRPC sin HTTP/2 en producción

gRPC requiere HTTP/2. Algunos proxies antiguos (nginx sin configuración, ALB sin HTTP/2) pueden romper la comunicación. Configura correctamente el proxy o usa gRPC-Web.

Ignorar la cancelación en streams

// MAL: no pasa el cancellation token al await foreach
await foreach (var item in stream.ReadAllAsync())

Solución: pasa siempre context.CancellationToken para liberar recursos al desconectar el cliente.

7. Ejercicio guiado

Crea un servicio gRPC de chat bidi entre clientes.

  1. Crea un proyecto gRPC con dotnet new grpc.
  2. Define un servicio ChatGrpc con un método rpc StreamMessages (stream ChatMessage) returns (stream ChatMessage);.
  3. Implementa el servidor reenviando cada mensaje recibido a todos los clientes conectados.
  4. Crea un cliente de consola que envíe mensajes desde teclado y los muestre al recibirlos.
// chat.proto
service ChatGrpc {
  rpc StreamMessages (stream ChatMessage) returns (stream ChatMessage);
}

message ChatMessage {
  string user = 1;
  string text = 2;
  string sent_at = 3;
}

Tip: usa un Channel<ChatMessage> compartido para recibir mensajes del cliente y reenviarlos.

9. Resumen

  • gRPC usa Protocol Buffers y HTTP/2 para comunicación de alto rendimiento.
  • Los cuatro tipos de llamadas son: unary, server streaming, client streaming y bidi streaming.
  • Los archivos .proto generan código C# automáticamente para cliente y servidor.
  • gRPC es ideal para microservicios internos; REST es más flexible para APIs públicas.
  • gRPC-Web permite usar gRPC desde navegadores.

10. Preguntas frecuentes

¿Necesito instalar protoc manualmente?

No. El paquete Grpc.Tools incluye el compilador y se ejecuta automáticamente durante la compilación.

¿Puedo combinar gRPC y REST en el mismo proyecto?

Sí. Un servidor ASP.NET Core puede exponer controladores REST junto con servicios gRPC en el mismo puerto.

¿Qué es un RpcException?

Es la excepción que lanza gRPC cuando ocurre un error. Incluye un StatusCode y un mensaje detallado.

¿gRPC requiere HTTPS?

En producción sí. En desarrollo puedes desactivar TLS para HTTP/2, pero no lo hagas en producción.

¿Cuándo uso gRPC en lugar de SignalR?

Usa gRPC cuando necesitas contratos fuertes, baja latencia y streaming estructurado entre servicios. Usa SignalR para notificaciones push, chat y juegos en tiempo real con clientes variados.
