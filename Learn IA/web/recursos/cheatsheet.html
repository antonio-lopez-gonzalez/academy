Tokens, contexto y coste

Todo lo que entra y sale se factura en tokens. Regla aproximada en español: ~4 caracteres por token (≈0,75 palabras). Cuenta siempre con el recuento real del proveedor, no con len(texto).

coste(€) = (input_tokens  / 1_000_000) * precio_input
         + (output_tokens / 1_000_000) * precio_output

# Contar tokens reales sin llamar al modelo (local, sin API key).
import tiktoken

enc = tiktoken.get_encoding("o200k_base")

Los precios cambian: no los incrustes en la lógica. Guárdalos en una tabla editable (input/output por millón) y consúltalos en la página oficial de tu proveedor antes de dimensionar.

ParámetroQué haceReceta
temperatureReescala las probabilidades antes de elegir el tokenExtraer/clasificar/citar: 0.0–0.3. Redactar/idear: 0.7–1.0

# Llamada a Ollama con sampling controlado y métricas leídas después.
from ollama import Client

client = Client(host="http://localhost:11434")
r = client.chat(
    model="llama3.2",
    messages=[{"role": "user", "content": "¿Qué es un token?"}],
    options={"temperature": 0.0, "seed": 42, "num_predict": 80},
)
print(r.message.content)
print(r.prompt_eval_count, r.eval_count, r.done_reason)   # in, out, stop|length

temperature=0 no garantiza determinismo perfecto (GPU, batching, versión del modelo). Para comparar prompts de forma justa fija también seed, modelo y versión; para tests serios, evalúa propiedades, no cadenas exactas.

Plantilla de prompt

Separa siempre system (rol y reglas) de user (la tarea), delimita las secciones y pon las instrucciones de formato al final. Esta es la plantilla base del Copiloto:

SYSTEM
Eres el Copiloto, un asistente que responde sobre los cursos de la Academy.
Responde UNICAMENTE con la informacion del CONTEXTO.
Cita cada afirmacion con el numero del fragmento, asi: [1].
Si el contexto no contiene la respuesta, di exactamente:
"No lo se con el contexto disponible."
No uses conocimiento externo ni supongas nada que no este en el contexto.

USER
CONTEXTO:
[1] (Learn IA > Modulo 4 > pipeline-rag)
RAG recupera fragmentos relevantes antes de que el modelo responda...
[2] (Learn IA > Modulo 3 > que-son-los-embeddings)
Un embedding es un vector que representa el significado de un texto...

PREGUNTA: {pregunta}
# La plantilla en codigo: variables explicitamente delimitadas.
SYSTEM_PROMPT = (
    "Responde UNICAMENTE con el CONTEXTO. Cita con [n]. "
    "Si no esta, di: 'No lo se con el contexto disponible.'"
)

def build_messages(question: str, context: str) -> list[dict[str, str]]:
    return [
        {"role": "system", "content": SYSTEM_PROMPT},
        {"role": "user", "content": f"CONTEXTO:\n{context}\n\nPREGUNTA: {question}"},
    ]

Pide la salida como JSON Schema (pydantic) cuando necesites datos, no prosa. Las descripciones del esquema son documentación para el modelo: escríbelas en imperativo.

Pipeline de RAG

Dos fases offline (una vez, o al cambiar el corpus) y cuatro online (en cada pregunta). Confundirlas es el error clásico: reindexar en cada consulta dispara la latencia.

OFFLINE (una vez, o al cambiar el corpus)
  [1 Ingesta]  →  [2 Indexado]  →  [ vector store ]
   lecciones       chunk + embed     vectores + metadatos

ONLINE (en cada pregunta)
  [3 Consulta] → [4 Recuperar] → [5 Contexto] → [6 Generacion]
   embedding      top-k coseno    fragmentos +   LLM que cita
                  + umbral        pregunta       con [n]
FaseQué hacesHerramienta
1. IngestaExtraer texto útil y metadatos (curso, módulo, lección, sección)BeautifulSoup
2. IndexadoTrocear, embeber y guardar (vector, texto, meta)fastembed + sqlite-vec/pgvector
3. ConsultaEmbeber la pregunta con el mismo modeloTextEmbedding
4. RecuperaciónTop-k por similitud coseno + umbral (opcional: reranking)numpy
5. ContextoNumerar y referenciar los fragmentos; recortar si no cabebuild_context()
6. GeneraciónLLM redacta anclado al contexto y cita la fuentechat(messages)
 
# Recuperar (fases 3-4) + construir contexto (fase 5), sin reranking.
import numpy as np
from fastembed import TextEmbedding

model = TextEmbedding("intfloat/multilingual-e5-small")

def search(docs, doc_vecs, query, k=4):
    q = np.asarray(next(iter(model.embed([query]))))
    q /= np.linalg.norm(q)                 # normaliza: el producto punto ES coseno
    sims = doc_vecs @ q
    order = np.argsort(-sims)[:k]
    return [(float(sims[i]), docs[i]) for i in order]

def build_context(hits):
    return "\n\n".join(f"[{n}] {text}" for n, (_, text) in enumerate(hits, 1))

RAG reduce la alucinación, no la elimina. Si el retrieval trae ruido o el prompt no exige grounding, el modelo inventa con tono seguro. Devuelve «no lo sé» cuando no haya contexto.

Esquema de una tool (JSON Schema)

El modelo propone la llamada; tu código la ejecuta. La descripción es la documentación que el modelo lee para elegir, así que escríbela con cuidado. El esquema guía, no obliga: valida igualmente los argumentos.

{
  "type": "function",
  "function": {
    "name": "search_lessons",
    "description": "Busca lecciones del curso por texto y devuelve las mas relevantes.",
    "parameters": {
      "type": "object",
      "properties": {
        "query": {
          "type": "string",
          "description": "Terminos de busqueda, en lenguaje natural."
        },
        "limit": {
          "type": "integer",
          "description": "Numero maximo de resultados (1-10).",
          "minimum": 1,
          "maximum": 10
        }
      },
      "required": ["query"]
    }
  }
}
# El modelo propone; tu dispatcher ejecuta y valida.
import json
from pydantic import BaseModel, Field

class SearchArgs(BaseModel):
    query: str = Field(min_length=1)
    limit: int = Field(default=5, ge=1, le=10)

HANDLERS = {"search_lessons": search_lessons}   # nombre -> funcion real

def run_tool(name: str, arguments) -> str:
    if name not in HANDLERS:
        return json.dumps({"error": f"tool desconocida: {name}"})
    args = json.loads(arguments) if isinstance(arguments, str) else arguments
    try:
        args = SearchArgs.model_validate(args).model_dump()   # ultima linea de defensa
        return json.dumps(HANDLERS[name](**args), ensure_ascii=False)
    except (TypeError, ValueError) as exc:
        return json.dumps({"error": str(exc)})   # devuelve el error al modelo

Nube como alternativa: OpenAI usa tools=[{"type": "function", "function": ...}] y los argumentos llegan como string; Anthropic usa input_schema y devuelve el resultado en un bloque tool_result con tool_use_id.

El bucle del agente

Un agente es el tool calling a escala: pensar → actuar → observar, repetido bajo un tope duro de iteraciones. Nunca while True.

pregunta
   │
   ▼
[ modelo ] ──► ¿tool_calls? ──no──► respuesta final (stop)
   ▲                │ si
   │                ▼
   │        TU CODIGO ejecuta la tool
   │        y anade { role: "tool", content: ... }
   └────────────────┘   (repite hasta MAX_STEPS)
MODEL = "llama3.2"
MAX_STEPS = 4            # limite de iteraciones: coste y cuelgue bajo control
tools = [SEARCH_LESSONS_SCHEMA]

def answer_with_tools(question: str) -> str:
    messages = [
        {"role": "system", "content": "Usa las tools cuando aporten datos."},
        {"role": "user", "content": question},
    ]
    for _ in range(MAX_STEPS):
        response = client.chat(model=MODEL, messages=messages, tools=tools)
        msg = response.message
        if not msg.tool_calls:                       # ya no pide tools: final
            return msg.content or ""
        messages.append({"role": "assistant", "content": msg.content or "",
                         "tool_calls": msg.tool_calls})
        for call in msg.tool_calls:                  # ejecuta TODAS las propuestas
            result = run_tool(call.function.name, call.function.arguments)
            messages.append({"role": "tool", "content": result,
                             "tool_name": call.function.name})
    return "No pude cerrar la respuesta dentro del limite de pasos."

Esquema assistant (con tool_calls) + uno o más mensajes role="tool" en cada vuelta. Si ejecutas una tool y no devuelves el resultado, el modelo no ha hablado todavía: content estará vacío.

Comandos de Ollama y uv

# Ollama: LLM y embeddings en local, sin API key
ollama pull llama3.2              # descarga un modelo con soporte de tools
ollama list                       # modelos instalados
ollama run llama3.2               # chat interactivo en la terminal
ollama serve                      # servidor en http://localhost:11434
ollama ps                         # modelos cargados en memoria

# uv: proyecto y entorno (Python 3.12+)
uv init copiloto                  # crea pyproject.toml
uv add ollama pydantic fastembed  # dependencias de runtime
uv add --dev pytest ruff mypy     # herramientas de calidad
uv run copiloto ask "..."         # ejecuta dentro del entorno
uv sync                           # sincroniza con el lockfile
uv lock                           # regenera uv.lock
# Arrancar el servidor web del curso (desde "Learn IA/")
npm run serve                     # sirve web/ en local

Local primero. El núcleo del curso corre con Ollama y no necesita tarjeta ni clave. La nube (OpenAI/Anthropic) es una alternativa explícita con el mismo patrón de código; solo cambia el nombre de los campos.
