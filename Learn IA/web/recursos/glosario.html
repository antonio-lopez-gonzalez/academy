Glosario de términos

Referencia 📖 Términos clave de IA

A

Agente (agent)
Sistema que envuelve un LLM en un bucle: el modelo decide qué hacer, tu código ejecuta la acción y le devuelve el resultado, repitiendo hasta responder. Requiere tools, memoria y un límite de iteraciones. Es el tool calling a escala (Módulo 5).
Alucinación (hallucination)
Respuesta que el modelo presenta con seguridad pero que es falsa o inventada. No es un «bug» raro: es el modo natural de un predictor cuando no tiene el dato. RAG y grounding la reducen, no la eliminan.
Atención (attention)
Mecanismo del Transformer que pondera cuánto se fija el modelo en cada token anterior al predecir el siguiente. Es lo que hace posible el contexto: el modelo «mira» la parte relevante de la ventana.

B

Base vectorial (vector store)
Almacén que guarda embeddings con sus metadatos y hace búsqueda por vecinos más cercanos. En el curso: pgvector (PostgreSQL) y sqlite-vec. No «piensa»: solo indexa vectores y responde a consultas de similitud.
Bucle agentic (agentic loop)
Ciclo pensar → actuar → observar: el modelo pide una tool (tool_calls), tu código la ejecuta y añade un mensaje role="tool", y se repite hasta que el modelo deja de pedir tools. Debe tener un tope de pasos.

C

Caché semántica
Caché que devuelve la respuesta guardada cuando la nueva pregunta es similar (no idéntica) a una anterior, comparando embeddings. Ahorra coste y latencia, pero exige invalidación cuidadosa para no servir información obsoleta.
Chain-of-thought (CoT)
Pedir al modelo que razone «paso a paso» antes de responder. Mejora tareas de razonamiento, pero no convierte el texto en un razonamiento real y puede aumentar coste y latencia. Úsalo con criterio, no por defecto.
Chunk
Fragmento de un documento más largo (una sección, un párrafo) que se indexa como unidad. Un chunk es la pieza que se embebe, se recupera y se cita. Tamaño típico: 300–800 tokens con 10–20 % de solape.
Chunking
El proceso de trocear el corpus en chunks. Decisiones clave: tamaño, solape y respetar la estructura (títulos, secciones). Un mal chunking no se arregla con un modelo mejor (Módulo 3).
Contexto (ventana de contexto)
El máximo de tokens que el modelo puede tener «delante» a la vez: prompt más respuesta. No es memoria de largo plazo, es la mesa de trabajo de una sola llamada. Llenarla «por si acaso» cuesta tokens y diluye la respuesta.

D

Determinismo
Propiedad de obtener la misma salida ante la misma entrada. Con temperature=0 y una seed fija se consigue una reproducibilidad práctica, no perfecta (GPU, batching, versión del modelo). Por eso se evalúan propiedades, no cadenas exactas.

E

Embedding
Vector de números que representa el significado de un texto. Textos con sentido parecido quedan cerca en ese espacio, aunque no compartan palabras. Debe usarse el mismo modelo para indexar y para consultar (Módulo 3).
Eval (evaluación)
Medir la calidad del sistema con un dataset de casos y criterios reproducibles: aserciones deterministas (¿contiene la cita?, ¿el JSON valida?) y juez automático. Sin evaluar no hay ingeniería, solo intuición (Módulo 7).

F

Few-shot
Incluir unos pocos ejemplos (entrada → salida) en el prompt para fijar el formato o el estilo. Zero-shot es sin ejemplos; one-shot, con uno. Es prompting, no entrenamiento: no cambias los pesos del modelo.
Fine-tuning
Reentrenar un modelo con ejemplos propios. Enseña forma (estilo, formato), no hechos fiables y actualizables. Para conocimiento que cambia se usa RAG; el fine-tuning es el último recurso.

G

Grounding
Anclar la respuesta a una fuente verificable: el modelo responde solo con el contexto recuperado y lo cita. Es lo que evita que ignore el retrieval y responda de memoria. Se refuerza con instrucciones explícitas en el system.
Guardrail
Barrera que limita lo que el sistema puede hacer o decir: moderación de contenido, filtrado de PII, límite de iteraciones y de coste, validación de salida estructurada, permisos de tools. No confíes en el prompt como único guardrail (Módulo 7).

I

Índice (index)
Estructura que permite buscar rápido: en RAG, el conjunto de vectores + metadatos construido offline para consultarse online. Se construye una vez y se reindexa solo cuando cambia el corpus.
Inferencia (inference)
El «runtime» del modelo: la ejecución probabilística que predice tokens. Conviene separarla siempre de la lógica determinista de tu código (buscar, validar, concatenar, ejecutar tools).
Ingesta (ingestion)
Primera fase de RAG: reunir el corpus y convertirlo en texto limpio con metadatos (curso, módulo, lección, sección). Debe ser idempotente: reingestar lo mismo produce los mismos chunks.
Inyección de prompt (prompt injection)
Ataque en el que una entrada del usuario (o un documento recuperado) contiene instrucciones que secuestran al modelo. Defensa: delimitar y desconfiar de la entrada, y no dar por buenas sus órdenes (Módulo 1).

L

LLM (Large Language Model)
Modelo que predice el siguiente token a partir de los anteriores. No «piensa» ni consulta hechos: estima probabilidades. Todo lo demás (RAG, tools, agentes) son capas alrededor de ese motor (Módulo 0).
LLM-as-judge
Usar un LLM para evaluar la salida de otro (o de sí mismo) según una rúbrica. Escala la evaluación, pero tiene sesgos (favorece respuestas largas, su propio estilo); se calibra contra juicios humanos.

M

MCP (Model Context Protocol)
Protocolo estándar para conectar un LLM con fuentes de datos y herramientas externas mediante servidores que exponen tools, resources y prompts (transporte stdio). Estandariza lo que antes era integración a medida (Módulo 6).
Memoria (memory)
Información que el agente conserva entre pasos o turnos: historial de conversación, resúmenes, estado de la tarea. Hay que gestionarla (podar o resumir) porque cada token viaja y se paga en cada llamada.

O

Observabilidad
Capacidad de ver qué hizo el sistema: trazas de llamadas con tokens, coste, latencia y fragmentos recuperados. Es lo que separa «falló el Copiloto» de «recibió el chunk equivocado» (Módulo 7).

P

PII (Personally Identifiable Information)
Datos que identifican a una persona (nombre, email, teléfono, documento). No deben ir en el repositorio ni, sin control, al prompt; se detectan y se filtran como parte de los guardrails.
Planificación (planning)
Descomponer una tarea compleja en pasos antes de ejecutarlos (o encadenar decisiones). Es una capacidad del agente del Módulo 5; sin límites puede disparar el coste del bucle.
Prompt
El texto de entrada: instrucciones de system (rol y reglas) y user (la tarea). Un buen prompt separa responsabilidades, delimita las secciones y define el formato de salida.
Prompt stuffing
Meter el documento entero en el prompt en vez de recuperar lo relevante. Solo tiene sentido con corpus mínimo y estable; no escala y diluye la respuesta.

R

RAG (Retrieval-Augmented Generation)
Dar al modelo los fragmentos relevantes de tus documentos antes de responder. Cambia «recita de memoria» por «lee este texto y responde». Seis fases: ingesta, indexado, consulta, recuperación, contexto y generación (Módulo 4).
Rate limit
Límite de peticiones o tokens por unidad de tiempo que impone un proveedor. Al alcanzarlo hay que reintentar con backoff exponencial, no en bucle apretado.
Reranking
Reordenar los candidatos recuperados con un modelo más preciso (cross-encoder) para dejar pasar solo los mejores. Mejora la precisión del retrieval a cambio de algo de latencia (Módulo 4).
Retrieval (recuperación)
Buscar en el índice los top-k fragmentos más similares a la consulta, normalmente por similitud coseno, aplicando un umbral. Es la fase que más determina la calidad del RAG.

S

Sampling
Conjunto de técnicas que deciden qué token elegir entre las probabilidades que calcula el modelo: temperature, top_p, top_k, seed. Controla el equilibrio entre precisión y creatividad.
Sandboxing
Ejecutar código generado o tools en un entorno aislado y con límites (tiempo, memoria, red) para que un error o una acción maliciosa no dañe el sistema.
Seed
Valor que fija el generador pseudoaleatorio del sampling. Misma seed + mismos parámetros ⇒ salida (casi) reproducible; imprescindible para comparar prompts de forma justa.
Similitud coseno
Medida de parecido entre dos vectores: el coseno del ángulo que forman (1 = idénticos en dirección). Si normalizas los vectores, el producto punto es la similitud coseno.
Skill
Instrucciones (SKILL.md) que enseñan al agente cómo hacer un tipo de trabajo (un flujo, unas reglas, unos comandos). Amplía lo que sabe hacer sin tocar el modelo (Módulo 6).
Streaming
Recibir la respuesta token a token según se genera, en vez de esperar a tenerla entera. Baja el tiempo percibido de espera (TTFT) y hace la app más fluida.
Structured output (salida estructurada)
Obligar al modelo a devolver datos con una forma fija (JSON Schema / pydantic) en lugar de prosa, y validarlos. El esquema guía; la validación en tu código garantiza (Módulo 1).

T

Temperatura (temperature)
Parámetro que reescala las probabilidades antes de elegir el token. Baja (0–0.3): casi determinista, para extraer datos o citar. Alta (0.7–1.0): más diverso y creativo, y más propenso a errores.
Token
Unidad mínima de texto que maneja el modelo: puede ser una palabra, media palabra o un signo. Se factura y se cuenta en tokens, no en palabras ni caracteres (en español, ~4 caracteres por token).
Tokenizador (tokenizer)
Algoritmo (casi siempre BPE) que parte el texto en tokens y los convierte en ids. Cada modelo usa el suyo, por eso el recuento exacto depende del proveedor.
Tool calling (function calling)
Dar al modelo una lista de herramientas; cuando necesita una, propone nombre y argumentos, y tu código la ejecuta y le devuelve el resultado. El modelo decide, tú haces (Módulo 2).
Top-p (nucleus sampling)
Recortar el sampling al conjunto de tokens cuya probabilidad acumulada suma p (p. ej. 0.9). Regula cuánta «cola» de opciones raras se acepta. Ajusta top-p o temperature, no ambos a la vez.
Traza (trace)
Registro estructurado de lo que ocurrió en una petición: prompts, parámetros, tokens, coste, latencia, tools llamadas y fragmentos recuperados. Es la base de la depuración y de la observabilidad.

V

Vector
Lista ordenada de números. En IA, un embedding es un vector que codifica el significado de un texto; comparar vectores permite medir parecido semántico. «Vector store» = base vectorial.
