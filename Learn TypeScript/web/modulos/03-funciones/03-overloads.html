Overloads y genericos en funciones

Modulo 3 · Funciones 🕐 30 minutos

1 · Introduccion

A veces una funcion se comporta distinto segun los argumentos: "si le paso un numero, devuelve X; si le paso una cadena, devuelve Y". JavaScript lo resuelve con condicionales; TypeScript ofrece dos herramientas para describirlo con tipos: las function overloads (declarar varias firmas) y los genericos (representar tipos que se conectan entre entrada y salida). Esta leccion da la primera vuelta seria a ambos.

2 · Teoria

Cuando la salida depende de la entrada

El problema clasico: una funcion que recoge un "selector" y devuelve dato o lista segun una opcion. Sin ayuda, el retorno es el tipo union o el generico perdido.

Function overloads

Consisten en declarar la funcion varias veces con firmas distintas, y al final una sola implementacion (que cubre todas las firmas):

// PARTE 1: signaturas (overloads) que se ven desde fuera.
function doble(valor: string): string;
function doble(valor: number): number;

// PARTE 2: la implementacion (NO es parte visible).
function doble(valor: string | number): string | number {
  if (typeof valor === "string") return valor + valor;
  return valor * 2;
}

const conString = doble("ab");   // tipo: string ✅
const conNumber = doble(4);      // tipo: number ✅
// const tipo = doble(true);     // ✖ boolean no encaja en ninguna firma

Fuera se ven SOLO las overloads; la implementacion queda oculta. El compilador elige la firma que mejor encaja con cada llamada.

Los genericos: conectar entrada y salida

Con genericos, el tipo de retorno puede depender del tipo de entrada:

//  indica: "hay un tipo T que se decidira en cada llamada".
function primera<T>(arr: readonly T[]): T | undefined {
  return arr[0];
}

const n = primera([1, 2, 3]);     // T = number → number | undefined
const s = primera(["a", "b"]);    // T = string → string | undefined
const r = primera([true, false]); // T = boolean → boolean | undefined

El generico es un "comodin" que se fija por llamada y que permite que el retorno REFERENCIA el mismo tipo que el argumento. Es la diferencia entre "devuelvo algo" y "devuelvo exactamente lo mismo tipo".

Dos parametros genericos y su ambiguedad

function encolar<T>(lista: readonly T[], x: T): T[] {
  return [...lista, x];
}

const lista = encolar([1, 2], 3);      // T = number → number[]
// encolar([1, 2], "a");               // ✖ "a" no es number

Fijaos: TS infiere T simultaneamente de ambos argumentos, y si no cuadra, falla.

Overloads vs genericos: como elegir

Los genericos conectan "tu entrada con tu salida": quieres devolver lo MISMO tipo que recibes. Las overloads sirven cuando quieres tipos de retorno distintos para entradas concretas, y el compilador elige. Si puedes evitar las overloads con genericos o unions, hazlo: son mas simples de mantener.

Preferir unions a overloads cuando sea posible

// Con union + generico por defecto:
type Entrada = string | number;
function forma(valor: Entrada): string {
  return typeof valor === "number" ? `#${valor}` : valor;
}
// retorno: siempre string: sin overloads necesarias

3 · Ejemplo minimo

overload-minimo.ts
// Overloads: segun el tipo de entrada, distinto retorno.
function valor_de(clave: string): string;
function valor_de(clave: number): number;

function valor_de(clave: string | number): string | number {
  return clave; // implementacion compartida
}

const conCadena: string = valor_de("a"); // string
const conNumero: number = valor_de(1);   // number

// Generico: retorno conectado al tipo de entrada.
function identidad<T>(x: T): T {
  return x;
}

const literal = identidad(5);      // 5 (number)
const cadenaT = identidad("hola"); // "hola" (string)

4 · Ejemplo real

Una funcion de "cache con metadatos" que devuelve el dato o el snapshot segun una opcion tipada:

cache-g.ts
// Overloads para elegir el retorno segun la opcion "conMeta".
function consultar<T>(clave: string, conMeta: true): { dato: T; guardado: number };
function consultar<T>(clave: string, conMeta: false): T;
function consultar<T>(clave: string, conMeta: boolean): T | { dato: T; guardado: number } {
  // Implementacion real (simulamos un acceso a una cache).
  const dato = { valor: 42 } as unknown as T;
  return conMeta ? { dato, guardado: Date.now() } : dato;
}

// Llamadas:
const sinMeta = consultar("precio", false); // tipo: number (T infiere 42)
const conMeta = consultar("precio", true);  // tipo: { dato: number; guardado: number }

// Generico util: una clase generica reutiliza T en metodos.
class Pila<T> {
  private items: T[] = [];
  push(x: T): void { this.items.push(x); }
  pop(): T | undefined { return this.items.pop(); }
}

const pilaNum = new Pila<number>();
pilaNum.push(3);
const ultimo: number | undefined = pilaNum.pop(); // ✅

Decisiones:

  • Las overloads permiten dos contratos distintos segun conMeta, ambos con generico T.
  • La implementacion final cubre las dos firmas con una union.
  • La clase Pila<T> es generica: su tipo se fija al instanciarla y sus metodos lo respetan.

5 · Buenas practicas

  • Usa genericos cuando la salida dependa de la entrada (mismo tipo).
  • Usa overloads SOLO cuando las firmas sean realmente incompatibles y no resolubles con genericos/unions.
  • Siempre declara la implementacion como la MAS amplia y compatible con todas las overloads.
  • Prefiere unions y genericos "como plano B" antes que multiplicar overloads.
  • Nombre los genericos con letras significativas (T, K, V) y documenta cuando haya varios.

Que evitar

  • Overloads con todos los cuerpos iguales: genericos harian el trabajo mas simple.
  • La implementacion con el retorno mas amplio que las firmas publicas: rompe las seguridades.
  • Un solo parametro conMeta: boolean con la misma firma "object | T" sin overloads: pierde la discriminacion del retorno.

6 · Errores habituales

Mal — implementacion no compatible con las overloads 
function f(x: string): string;
function f(x: number): number;
function f(x: any): any { return x; } // any: tolerable pero rompe T
Bien — implementacion usa union explicita 
function f(x: string): string;
function f(x: number): number;
function f(x: string | number): string | number { return x; } // ✅
Mal — llamar con un tipo que no esta en ninguna overload 
function doble(v: string): string;
function doble(v: number): number;
doble(true); // ✖ no admite boolean
Bien — overload que cubra el caso o union 
function doble(v: boolean): boolean; // o mejor: doble(v: string | number | boolean)
Mal — generico que no conecta entrada y salida "de mentira" 
function solo(x: T): number { return 1; } // el generico es ruido: retorno fijo
Bien — generico usado con sentido o sin generico 
function devuelve(x: unknown): number { return 1; } // sin T, honesto

9 · Resumen

  • Genericos: <T> conecta tipos de entrada y de salida por llamada.
  • Overloads: varias firmas publicas + una implementacion amplia que las cubre.
  • Generico para "mismo tipo a la salida"; unions o overloads para retornos condicionales.
  • Preferi unions y genericos a mall graves overloads innecesarias.
  • Las clases tambien son genericas: class Pila<T>.

10 · Preguntas frecuentes

¿Cuando los genericos sustituyen a las overloads?

Cuando el retorno es "lo mismo que entro" o se deriva del tipo de entrada. Las overloads quedan para retornos estructurados por casos concretos no derivables.

¿Puedo tener overloads con genericos?

Si: cada firma overload puede declarar sus propios <T>. Es muy comun en librerias que combinan ambas cosas (como redux-thunk o React).

¿Por que la implementacion con "any" es mala praxis en overloads?

Porque dentro del cuerpo pierdes el tipado y puedes retornar algo erroneo que la firma no garantiza. TypeScript no valida que la implementacion cumpla las firmas con fuerza total; una implementacion union lo permite.

¿Los genericos solo funcionan con funciones y clases?

Tambien con types, interfaces, alias y hasta con valores (as const). Los tipos genericos avanzados los ves en el modulo 5.

¿Puedo tener un parametro generico por defecto?

Si: function f<T = string>(x: T): T. Si la llamada no lo infiere, usa el default. Muy util en type generics del modulo 5.
