Arrays, tuples y readonly

Modulo 1 · Tipos basicos 🕐 30 minutos

1 · Introduccion

Los arrays son la estructura de datos mas usada en JavaScript. Aqui aprendes a tiparlos con precision, descubriras las tuplas (arrays de longitud y posiciones fijas, que en JavaScript no existen como tales) y el concepto readonly, que protege tus datos de mutaciones accidentales.

Entender cuando un array "de verdad" es una lista homogenea y cuando es una tupla con estructura fija te separa del codigo que compila pero miente sobre sus datos.

2 · Teoria

Arrays homogeneos: T[]

Un array de tipo number[] contiene solo numeros, pero no fija su longitud: puede tener 0, 3 o 1.000 elementos. Eso es correcto: un array es una lista.

let precios: number[] = [9.99, 19.99, 29.99];
let nombres: string[] = ["ada", "grace", "linus"];

// Notacion alternativa (identica semanticamente):
let otros: Array<number> = [1, 2, 3];

T[] y Array<T> significan exactamente lo mismo. En el curso usaremos T[] (mas legible). La segunda notacion es imprescindible cuando T es complejo (lo veremos con genericos en el modulo 5).

Por que un array es un tipo

Un array es "un conjunto de valores del mismo tipo, en orden". Al declarar number[] el compilador ya sabe que map, filter y reduce trabajaran con number, y que meter un string es un error. Autocompletado y comprobacion van de la mano.

Tuplas: posiciones fijas

Una tupla declara cuantos elementos hay y que tipo tiene cada posicion. Es ideal para "pares", coordenadas o resultados con varias partes. 

// [string, number]: posicion 0 = nombre, posicion 1 = precio.
const producto: [string, number] = ["Teclado", 89];

// Desestructurar con tipos correctos:
const [nombre, precio] = producto; // nombre: string, precio: number

JavaScript no distingue "tupla" de "array": en runtime ambas son Array. La tupla es solo un contrato en tiempo de compilacion. Por eso solo la usamos cuando la estructura es verdaderamente fija.

Analogia: la caja del pedido

Un array es una caja donde caben N copias de la misma cosa (N cajas de arandanos). Una tupla es una caja compartimentada: un hueco para el nombre, otro para el precio. No puedes meter el precio en el hueco del nombre.

Tuplas con etiquetas y opcionales

// Etiquetas: documentan que significa cada posicion.
type Coordenada = [latitud: number, longitud: number];

// Elementos opcionales con "?" (puede que no existan).
type ParCoordenadas = [number, number?];

readonly: un array que no se puede mutar

readonly number[] bloquea los metodos que mutan: push, pop, splice... Un array readonly representa datos que "se leen" pero no se cambian. 

const fijo: readonly number[] = [1, 2, 3];

// fijo.push(4);  // ✖ error TS2339: push no existe en readonly number[]
// fijo[0] = 9;   // ✖ error TS2540: no puedes asignar a un elemento readonly

// Para "crear uno nuevo" con cambios, copiamos:
const ampliado: readonly number[] = [...fijo, 4]; // ✅ nuevo array
readonly no es inmutable

readonly impide la mutacion del array en si. Si los elementos fueran objetos, sus propiedades internas segurian pudiendo cambiarse. La inmutabilidad total se consigue a otro nivel (objetos frozen o estructuras como immutables). Por ahora: readonly = "no reasignes ni modifiques esta lista".

Deteccion de arrays en runtime

function sumarTodo(valor: unknown): number {
  // Array.isArray es el guard que comprueba en runtime si es un array.
  if (Array.isArray(valor)) {
    return valor.reduce((acc, n) => acc + n, 0);
  }
  return 0;
}

3 · Ejemplo minimo

arrays-minimo.ts
// Array homogeneo: solo numeros.
let notas: number[] = [7, 8, 9];

// Tupla: nombre + nota (posiciones fijas).
const alumno: [string, number] = ["Ada", 9];

// Tupla readonly: no se puede reasignar ni modificar.
const rango: readonly [number, number] = [1, 10];

// Los metodos tipados devuelven tipos correctos.
const suma: number = notas.reduce((a, n) => a + n, 0);
const mayores: number[] = notas.filter((n) => n >= 8);

4 · Ejemplo real

Un gestor de estadisticas de ventas. Usamos arrays homogeneos para las listas y tuplas para pares clave-valor:

ventas.ts
// Lista de ventas diarias (€). Homogenea: solo numeros.
const ventas: number[] = [120, 85, 210, 95, 340];

// Funcion que recibe UN ARRAY READONLY: promete no mutarlo.
// readonly number[] admite recibir number[] sin problema (regla 1).
function promedio(ventas: readonly number[]): number {
  // reduce sin mutar nada; el "?" protege del array vacio.
  return ventas.length === 0 ? 0 : ventas.reduce((a, b) => a + b, 0) / ventas.length;
}

// Tupla: [nombre, importe]. Ideal para un ranking (nombre + valor).
type TopVenta = [producto: string, importe: number];

const ranking: readonly TopVenta[] = [
  ["Teclado", 340],
  ["Mouse", 210],
  ["Monitor", 120],
];

// Desestructuramos la tupla con tipos inferidos correctos.
for (const [producto, importe] of ranking) {
  console.log(`${producto}: ${importe} €`);
}

console.log(`Promedio diario: ${promedio(ventas)} €`);

Decisiones:

  • readonly number[] en el parametro de promedio: la funcion promete no mutar la lista que le pasan. Quien la llama sabe que su array no sufrira efectos secundarios.
  • TopVenta como tupla con etiquetas: nombre y posicion documentados.
  • El for...of desestructura con tipos exactos gracias a la tupla.
Regla de asignabilidad

Un number[] si se puede pasar a un parametro readonly number[] (leer un array mutable es seguro). Al reves NO: no puedes pasar un readonly a una funcion que promete mutar. TypeScript favorece el lado conservador.

5 · Buenas practicas

  • Tipa los arrays con su elemento: string[], no dejar que se infiera any[].
  • Usa readonly T[] en parametros de funciones que solo leen: documenta intencion y previene efectos secundarios.
  • Usa tuplas SOLO para estructura fija (pares, coordenadas). Para listas, T[].
  • Para arrays de objetos (modulo 2), define primero el tipo del elemento y luego TipoElemento[].
  • En funciones que devuelven arrays, deja que el compilador infiera el elemento; suele ser mas preciso que anotarlo mal.

Que evitar

  • Anotar arrays como Array (sin parametro): es any[] disfrazado.
  • Mutar arrays que podrian ser readonly solo "por comodidad".
  • Usar tuplas para datos con logica (un objeto con nombre y precio es mas claro que [string, number]).

6 · Errores habituales

Mal — array sin tipar elemento 
const datos = [];   // inferido: any[] (hasta que lo asignes a un valor concreto)
datos.push("x");    // silencioso
Bien — anotar el elemento (es un limite) 
const datos: number[] = [];
datos.push("x");    // ✖ TS2345: string no es asignable a number
Mal — tupla para datos que son una lista 
const nombres: [string] = ["ada"]; // "tupla de 1" rara: deberia ser string[]
Bien — lista con array, estructura fija con tupla 
const nombres: string[] = ["ada", "grace"]; // lista
const pareja: [string, number] = ["Ada", 9]; // estructura fija
Mal — mutar un readonly 
const base: readonly number[] = [1, 2, 3];
base.push(4);   // ✖ TS2339: push no existe en readonly number[]
Bien — copiar para ampliar 
const base: readonly number[] = [1, 2, 3];
const ampliada = [...base, 4]; // ✅ nuevo array

Por que estan mal: un any[] silencioso permite errores en runtime; una "tupla de 1" miente sobre la estructura; y mutar algo declarado readonly contradice el contrato que acabas de firmar.

9 · Resumen

  • Array homogeneo: number[], string[]… lista sin longitud fija.
  • Notaciones equivalentes: T[] y Array<T>.
  • Tupla: [string, number] — posiciones y longitudes fijas, con etiquetas y opcionales.
  • readonly number[] bloquea mutaciones (push, pop, asignaciones de indice).
  • Para "cambiar" un readonly: crea una copia ([...fijo, nuevo]).

10 · Preguntas frecuentes

¿Cuando usar tupla y cuando usar objeto?

Tupla para estructura fija y posicional (coordenadas, pares). Objeto cuando hay 3+ campos o cuando el orden no es la semantica. Un objeto con {nombre, precio} es mas legible que [string, number].

¿readonly es lo mismo que "inmutable"?

No. readonly impide modificar el array en si. Si contiene objetos, sus campos siguen mutables. Para inmutabilidad total necesitas congelar o usar librerias (o disciplina).

¿Puedo convertir un array mutable en readonly?

Si: const r: readonly number[] = lista copia la referencia con promesa de no mutacion. Y se puede invertir con as const (leccion 3) o copiando con [...lista].

¿Por que mi array vacio se infiere como any[]?

TypeScript usa "evolucion de tipos": el array vacio empieza como any[] y se afina con los primeros push. Para seguridad desde el primer momento, anota el elemento: number[].

¿Metodos como map/filter devuelven tipos correctos?

Si. number[].map(...) devuelve un array del tipo que devuelve tu callback. El tipado de los metodos nativos es de alta precision y lo aprovecharemos todo el curso.
