Hooks con genericos

Modulo 8 · TypeScript con React 🕐 30 minutos

1 · Introduccion

Los hooks de React son genericos por dentro: useState<T>, useRef<T>, useCallback, etc. Pero el poder real aparece cuando creas custom hooks que encapsulan logica (fetch, formularios, persistencia) y la tipan con genericos para reutilizarla en cualquier componente.

El problema que resuelve: sin genericos, cada hook reutilizable te diria "devuelvo any" o tedrias que duplicarlo por tipo. Con genericos, un useFetch<Usuario>()` te da datos tipados de un endpoint, y useLocalStorage<number[]> te da un array de numeros.

Cuando se utilizan
  • Hooks custom de datos (fetch, cache, suscripciones).
  • Hooks de formulario (useForm con su shape de valores).
  • Persistencia local con tipos.
  • Refs y forwardRef tipados.

2 · Teoria

La analogia: la maquina de estampado de moldes

Imagina una maquina que estampa piezas. Un mismo marco estampa una pieza de metal, de plastico o de madera, segun el molde que le pongas. useState<T> es esa maquina: pones el molde (<string>, <number[]>...) y el estado queda del tipo que elegiste. Los custom hooks con genericos son "maquinas que ademas devuelven la pieza ya moldeada".

useState tipado (explícito e implícito)

// Inferido: number
const [cuenta, setCuenta] = useState(0);

// Explicito con union: el estado puede ser null o string
const [seleccion, setSeleccion] = useState<string | null>(null);
// seleccion: string | null
// setSeleccion solo acepta string | null | (() => string | null)

// Estado que empieza vacio pero sera un objeto:
const [perfil, setPerfil] = useState<Perfil | null>(null);
perfil?.nombre; // ✅ con optional chaining; sin el ? falla
Por que useState<T> es generico

El estado "empieza como" y "se actualiza con" un mismo tipo T. El generico mantiene el vinculo: lo que guardas y lo que lees tienen el mismo tipo. Sin el, useState devolvería any.

useRef tipado

import { useRef } from "react";

// Un ref a un elemento del DOM (HTMLInputElement):
const inputRef = useRef<HTMLInputElement>(null);
// inputRef.current: HTMLInputElement | null

function Focus() {
  const inputRef = useRef<HTMLInputElement>(null);
  return (
    <input ref={inputRef} />
    <button onClick={() => inputRef.current?.focus()}>Enfocar</button>
  );
}

// Ref con un valor mutable:
const clicksTotales = useRef(0); // number
clicksTotales.current += 1;

useState con objetos de formulario

interface FormData {
  nombre: string;
  email: string;
}

const [datos, setDatos] = useState<FormData>({ nombre: "", email: "" });

// Actualizacion por campo de forma tipada:
function actualizarCampo(clave: K, valor: FormData[K]) {
  setDatos((prev) => ({ ...prev, [clave]: valor }));
}

actualizarCampo("nombre", "Ana"); // ✅ el valor es tipado por clave
// actualizarCampo("email", 42);  // ✖ email es string

Custom hooks con genericos

// hook: useToggle (sin generico, estado boolean)
export function useToggle(initial = false) {
  const [activo, setActivo] = useState(initial);
  const activar = () => setActivo((a) => !a);
  return { activo, activar };
}

// hook con generico: useLocalStorage
export function useLocalStorage<T>(clave: string, inicial: T) {
  const [valor, setValor] = useState<T>(() => {
    const crudo = localStorage.getItem(clave);
    return crudo ? (JSON.parse(crudo) as T) : inicial; // parse tipado
  });

  const guardar = (nuevo: T) => {
    setValor(nuevo);
    localStorage.setItem(clave, JSON.stringify(nuevo));
  };

  return [valor, guardar] as const; // tupla: [T, (v: T) => void]
}

Consumo:

const [favoritos, setFavoritos] = useLocalStorage<number[]>("favoritos", []);
// favoritos: number[] ; setFavoritos espera number[]
setFavoritos([1, 5, 9]); // ✅

useFetch con genericos (el hook estrella)

import { useState, useEffect } from "react";

interface FetchEstado<T> {
  datos: T | null;
  cargando: boolean;
  error: string | null;
}

export function useFetch<T>(url: string): FetchEstado<T> {
  const [datos, setDatos] = useState<T | null>(null);
  const [cargando, setCargando] = useState(true);
  const [error, setError] = useState<string | null>(null);

  useEffect(() => {
    let cancelado = false;
    async function cargar() {
      try {
        const res = await fetch(url);
        if (!res.ok) throw new Error(`HTTP ${res.status}`);
        const json = await res.json() as T;
        if (!cancelado) setDatos(json);
      } catch (e) {
        if (!cancelado && e instanceof Error) setError(e.message);
      } finally {
        if (!cancelado) setCargando(false);
      }
    }
    cargar();
    return () => { cancelado = true; };
  }, [url]);

  return { datos, cargando, error };
}

3 · Ejemplo minimo

hook-minimo.tsx
// Un hook generico muy pequeno para contador con tipo.
import { useState } from "react";

export function useContador<T extends number>(inicial: T) {
  const [valor, setValor] = useState(inicial);
  const sumar = (n: number) => setValor((v) => (v + n) as T);
  return { valor, sumar };
}

// Uso:
const { valor, sumar } = useContador(0); // valor: number

Linea a linea:

  • useContador<T extends number>: el hook acepta un tipo numerico.
  • useState(inicial) infera T.
  • El retorno es un objeto con valor y sumar, todo tipado.

4 · Ejemplo real

Un hook useForm<T> que gestiona un formulario tipado sin libreria:

src/useForm.ts
import { useState } from "react";
import type { ChangeEvent } from "react";

export function useForm<T extends Record<string, string>>(inicial: T) {
  const [valores, setValores] = useState(inicial);

  function manejarCampo<K extends keyof T>(campo: K, valor: T[K]) {
    setValores((prev) => ({ ...prev, [campo]: valor }));
  }

  // Handler con nombre de input que se reutiliza en el onChange:
  function manejarInput(campo: keyof T) {
    return (e: ChangeEvent<HTMLInputElement>) => {
      manejarCampo(campo, e.target.value as T[keyof T]);
    };
  }

  return { valores, manejarInput, setValores };
}
src/Login.tsx
import { useForm } from "./useForm";

// El type de los campos: claves del formulario.
type CamposLogin = { email: string; password: string };

export function Login() {
  const { valores, manejarInput } = useForm<CamposLogin>({ email: "", password: "" });

  return (
    <form onSubmit={(e) => { e.preventDefault(); console.log(valores); }}>
      <input name="email" value={valores.email} onChange={manejarInput("email")} />
      <input name="password" type="password" value={valores.password} onChange={manejarInput("password")} />
      <button type="submit">Entrar</button>
    </form>
  );
}

Decisiones:

  • useForm<T> vincula cada campo con su valor: el hook no sabe que formulario es, el generico lo trae.
  • K extends keyof T restringe los campos a las claves reales del form (leccion 3, modulo 5).
  • manejarInput(campo) devuelve un handler tipado, conectando el JSX con el formulario.
  • El mismo hook vale para cualquier shape: maximamente reutilizable.

5 · Buenas practicas

  • Usa useState<T> explicito cuando el estado no puede inferirse (union, null inicial).
  • Los custom hooks con genericos deben devolver el tipo que "trajeron" (no any).
  • Tipa useRef<T>(null) para elementos del DOM; el resultado es T | null.
  • Devuelve tuplas con as const o objetos tipados desde hooks.
  • No sobre-generalices: si el hook solo se usa con un tipo, deja que la inferencia y el generic lo hagan simple.

Que evitar

  • as any en el valor de un hook generico: rompe la promesa de tipado.
  • Vaciar el cache/localStorage sin tipar la lectura (JSON.parse es any).
  • Ceder useRef con null! sin necesidad (pierde la comprobacion en el check).
  • Meter genericos a un hook que no los usa (sin efecto real).

6 · Errores habituales

Mal — hook generico que devuelve any 
function useDatos<T>(url: string) {
  const [d, setD] = useState<any>(null); // ✖ pierde T
  return d;
}
Bien — el hook mantiene T 
function useDatos<T>(url: string) {
  const [d, setD] = useState<T | null>(null); // ✅
  return d as T | null;
}
Mal — JSON.parse sin tipar 
const valor = JSON.parse(localStorage.getItem("clave") || "null");
// valor: any (✖)
Bien — parse as T 
const crudo = localStorage.getItem("clave");
const valor = crudo ? (JSON.parse(crudo) as number[]) : [];
Mal — useRef sin tipo 
// Sin el generico, el ref de un elemento es any:
const ref = useRef(null);
// ref.current: any (✖ puedes chocar con el DOM)
Bien — con el elemento 
const ref = useRef<HTMLDivElement>(null);
// ref.current: HTMLDivElement | null ✅

7 · Ejercicio guiado

Vamos a reutilizar el hook useFetch con un endpoint concreto y tipos.

  1. Define interface Post { id: number; titulo: string }.
  2. Usa useFetch<Post[]>("/api/posts").
  3. Renderea la lista si datos no es null.
  4. Muestra error si ocurre.

Solucion paso a paso:

src/Posts.tsx
import { useFetch } from "./useFetch"; // (el hook de la leccion)

interface Post { id: number; titulo: string; }

export function Posts() {
  const { datos, cargando, error } = useFetch<Post[]>("/api/posts");

  if (cargando) return <p>Cargando...</p>;
  if (error) return <p>Error: {error}</p>;
  if (!datos) return null;

  return (
    <ul>
      {datos.map((post) => (
        <li key={post.id}>{post.titulo}</li>
      ))}
    </ul>
  );
}

8 · Reto

Reto

Crea un hook useDebounce<T>(valor: T, retraso: number) que devuelva el valor diferido (version atrasada en el tiempo). Usa useState, useEffect y genericos. No mires la solucion; verifica que devuelve exactamente el tipo de T.

9 · Resumen

  • useState<T>, useRef<T>: hooks genericos de React.
  • Custom hooks con genericos reutilizan logica con tipos.
  • Tipar lecturas de JSON/localStorage para no caer en any.
  • keyof T para hooks de formulario vinculados a sus campos.
  • Devuelve el tipo que inyectaron: el hook generico nunca debe devolver any.

10 · Preguntas frecuentes

¿Siempre debo anotar el tipo de useState?

No. Si el estado infiere (useState(0), useState("")), no hace falta. Anota cuando el tipo no pueda inferirse o quieras una union (string | null).

¿Por que un hook generico "falla" de repente con un tipo nuevo?

Porque el generico debe ser flexible: usa extends (restricciones) y siempre un default si es posible. Si forza T con as, el consumo interno queda atado.

¿Puedo usar useFetch con endpoints de retorno distinto?

Si: el hook es generico (useFetch<T>). Solo cambia el parámetro de tipo en cada llamada (useFetch<Usuario>, useFetch<Post[]>).

¿useRef con null y strict?

Es el patrón correcto para refs a elementos: useRef<HTMLInputElement>(null) da T | null. Usa optional chaining (ref.current?.focus()).

¿Es malo usar as T en una funcion de hook?

Es aceptable solo en el "borde" de los datos no tipados (JSON.parse, fetch.json) y siempre documentado. Evita as any.

¿Los custom hooks necesitan genericos si solo se usan dos veces?

No necesariamente: puedes tiparlos con tipos concretos. Los genericos brillan cuando hay varios tipos de consumo o es una libreria reutilizable.
