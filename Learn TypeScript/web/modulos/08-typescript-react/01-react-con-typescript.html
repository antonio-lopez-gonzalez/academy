Setup React + TypeScript + Vite

Modulo 8 · TypeScript con React 🕐 35 minutos

1 · Introduccion

Configurar React + TypeScript con Vite es hoy el punto de partida estandar de cualquier app web nueva. En esta leccion levantas el andamiaje completo: Vite (bundler), React 18/19 (UI), TypeScript 7 (tipos) y pnpm como gestor.

El problema que resuelve: montar todo a mano (Babel, React, TS, resoluciones, HMR) es complejo y propenso a errores. Vite lo hace reproducible con un comando, y TypeScript añade la red de seguridad que las apps que crecen necesitan.

Cuando se utiliza
  • Toda app web nueva con React.
  • Proyectos que necesiten HMR rapido y build optimizado.
  • Como base para los proyectos de este curso (modulos 8 y 9).

2 · Teoria

La analogia: el taller pre-equipado

En vez de comprar tuercas, tornillos y llaves por separado y averiguar donde va cada pieza, Vite te entrega un taller ya montado: el husillo fijo (bundler con esbuild), la bancada (HMR) y el plano (tsconfig en condiciones). Tu solo pones el motor: tu codigo React + tus tipos.

Crear el proyecto

pnpm create vite@latest mi-app --template react-ts
cd mi-app
pnpm install
pnpm dev
Por que el template react-ts

react-ts escoge el template de React con TypeScript: ya trae .tsx, tsconfig.json (app + node), Vite config y el strict activado. Evita configurar Babel a mano y te deja escribir codigo desde el minuto uno.

Que genera cada archivo

mi-app/
├── index.html            ← punto de entrada del HTML
├── package.json          ← deps y scripts
├── tsconfig.json         ← "super config" (app + node)
├── tsconfig.app.json     ← config del codigo de la app (.tsx/.ts)
├── tsconfig.node.json    ← config para vite.config.ts
├── vite.config.ts        ← config del bundler
└── src/
    ├── main.tsx          ← monta la app en el DOM (root)
    ├── App.tsx           ← componente raiz
    ├── index.css
    └── vite-env.d.ts     ← tipos de Vite (import.meta.env, HMR)

El tsconfig.app.json tipico

{
  "compilerOptions": {
    "target": "ES2022",
    "useDefineForClassFields": true,
    "lib": ["ES2022", "DOM", "DOM.Iterable"],
    "module": "ESNext",
    "skipLibCheck": true,
    "moduleResolution": "bundler",
    "allowImportingTsExtensions": true,
    "isolatedModules": true,
    "moduleDetection": "force",
    "noEmit": true,
    "jsx": "react-jsx",
    "strict": true,
    "noUnusedLocals": true,
    "noUnusedParameters": true,
    "noFallthroughCasesInSwitch": true
  },
  "include": ["src"]
}
  • "lib": [..., "DOM", "DOM.Iterable"]: tipos del navegador (document, fetch, Storage...).
  • "jsx": "react-jsx": el transform moderno (no hace falta importar React en cada archivo).
  • moduleResolution: bundler: resuelve imports como hace Vite.
  • strict: true: la base de calidad de React + TS.

Vite y React en runtime

Vite sirve index.html, que referencia src/main.tsx. React.mount lo coloca en <div id="root">. En desarrollo usa esbuild (transpile rapido) y en produccion Rollup (bundle optimizado). TypeScript solo hace de "checker": no genera JS (noEmit).

vite.config.ts (tipado, como toda la config)

// vite.config.ts — tambien es TypeScript, por eso el tsconfig.node.json.
import { defineConfig } from "vite";
import react from "@vitejs/plugin-react";

export default defineConfig({
  plugins: [react()],
});

3 · Ejemplo minimo

src/main.tsx
import { StrictMode } from "react";
import { createRoot } from "react-dom/client";
import App from "./App.tsx";

createRoot(document.getElementById("root")!).render(
  <StrictMode>
    <App />
  </StrictMode>
);

Linea a linea:

  • createRoot(...) inicializa React 18/19 en el DOM.
  • document.getElementById("root")!: el ! asegura que existe (esta en index.html).
  • StrictMode activa comprobaciones de desarrollo.
  • App es el componente raiz.

4 · Ejemplo real

Un mini-componente inicial con estado, un efecto y render condicional, todo tipado:

src/Contador.tsx
import { useState, useEffect } from "react";

// El estado se infiere: un useEstado(0) → number.
export function Contador() {
  const [cuenta, setCuenta] = useState(0);
  const [doble, setDoble] = useState(0);

  // Efecto que depende del estado "cuenta":
  useEffect(() => {
    setDoble(cuenta * 2);
  }, [cuenta]);

  return (
    <div>
      <p>Cuenta: {cuenta} — Doble: {doble}</p>
      <button onClick={() => setCuenta((c) => c + 1)}>
        Incrementar
      </button>
    </div>
  );
}

// src/App.tsx
import { Contador } from "./Contador";

function App() {
  return (
    <main>
      <h1>Mi app con TypeScript</h1>
      <Contador />
    </main>
  );
}

export default App;

Decisiones:

  • useState(0) infiere number: no hace falta anotarlo, y todos sus valores quedan tipados.
  • setCuenta((c) => c + 1): el callback recibe el valor actual tipado.
  • Los eventos (onClick) y JSX se chequean con los tipos de react-dom.
  • pnpm build && pnpm preview genera y sirve el bundle de produccion.
Scripts de package.json
{
  "scripts": {
    "dev": "vite",
    "build": "tsc -b && vite build",
    "preview": "vite preview"
  }
}

5 · Buenas practicas

  • Usa el template react-ts oficial y pnpm para instalar.
  • Mantén strict: true siempre; Vite ya te lo pone.
  • Deja que el tipado infiera: no anotes lo obvio con interfaces innecesarias.
  • Usa tsc -b en el build para verificar tipos antes de empaquetar.
  • Separa tsconfig (app vs node) como hace el template: cada contexto con su config.
  • Haz build en CI con pnpm build (tsc + vite) para fallar ante errores de tipos.

Que evitar

  • Apagar strict "porque molesta" al configurar.
  • Importar React solo por JSX con el transform moderno (jsx: react-jsx).
  • Usar any[] en estado/eventos (pierdes la seguridad React+TS).
  • Mezclar moduleResolution: node con Vite (bundler es lo correcto).
  • Dejar <any> en createRoot/render: el tipado ya lo resuelve.

6 · Errores habituales

Mal — apagar strict 
{
  "compilerOptions": { "strict": false } // ✖ React sin red de seguridad
}
Bien — strict activo 
{
  "compilerOptions": { "strict": true } // ✅
}
Mal — importar React sin necesidad 
// Con jsx: react-jsx moderno:
import React from "react"; // ✖ no hace falta
Bien — solo los hooks que usas 
import { useState } from "react"; // ✅
Mal — any implícito en rangos con strict 
// En un handler que recibe eventos:
function handle(e) {
  // ✖ parameter 'e' implicitly has an 'any' type
}
Bien — tipar el evento 
import type { ChangeEvent } from "react";
function handle(e: ChangeEvent<HTMLInputElement>) { /* ... */ }

7 · Ejercicio guiado

Vamos a montar el proyecto de este modulo y añadir un primer componente tipado.

  1. Genera el proyecto con pnpm create vite (template react-ts).
  2. Revisa tsconfig.app.json: confirma strict, jsx react-jsx y lib DOM.
  3. Modifica App.tsx para mostrar tu nombre en un <h1>.
  4. Añade un Boton.tsx con un onClick que imprima algo.
  5. Ejecuta pnpm build y confirma que pasa los tipos.

Solucion paso a paso:

src/Boton.tsx
export function Boton() {
  function alClic() {
    console.log("Hola desde el boton");
  }
  return <button onClick={alClic}>Clic</button>;
}

// src/App.tsx
import { Boton } from "./Boton";

function App() {
  return (
    <main>
      <h1>Mi nombre</h1>
      <Boton />
    </main>
  );
}

export default App;

9 · Resumen

  • pnpm create vite ... --template react-ts levanta todo.
  • tsconfig con jsx: react-jsx, moduleResolution: bundler, strict.
  • Vite transpila (esbuild) y TypeScript solo chequea: noEmit.
  • Tipos de eventos, estado y DOM disponibles de forma gratuita.
  • pnpm build = tsc -b (tipos) + vite build (bundle).

10 · Preguntas frecuentes

¿Por que hay dos tsconfig (app y node)?

Porque el codigo de la app (navegador, DOM) y el vite.config.ts (Node) tienen contextos distintos: types globals, lib y resoluciones distintas. La raiz tsconfig.json solo los referencia.

¿Necesito instalar @types/react y @types/react-dom?

El template ya las incluye como devDependencies. Son obligatorias para los tipos de JSX, hooks y eventos.

¿jsx react-jsx elimina la necesidad de import React?

Si: el transform automatiza la importacion de jsx solo cuando hace falta. Solo importa React explicitamente si usas hooks u otros valores.

¿Cual es la diferencia con "vite" template sin ts?

El template JS no trae tsconfig, ni extensiones .tsx, ni strict. Empezar con react-ts te ahorra convertir luego el proyecto.

¿Vite soporta TS7?

Vite no usa tsc para transpilar; usa esbuild (que soporta la sintaxis). TypeScript 7 (el compilador nativo en Go) y esbuild conviven: tu usas tsc para tipos. Es el setup estandar de este curso.

¿El build fallará si tengo errores de tipos?

Con el template, si: build ejecuta tsc -b antes de vite, así un error de tipos rompe el CI. Puedes quitarlo, pero no es recomendable.
