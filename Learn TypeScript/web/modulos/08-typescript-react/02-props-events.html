Props y eventos tipados

Modulo 8 · TypeScript con React 🕐 30 minutos

1 · Introduccion

Los componentes React reciben props (entrada) y emiten eventos (salida). Tiparlas correctamente es lo que hace que un componente sea reutilizable: el editor te dice exactamente que props acepta, que tipos tienen, y que espera el callback que se le pasa.

El problema que resuelve: en JS, pasar mal una prop o un callback se descubre en runtime (o nunca). Con TypeScript, el contrato del componente se expresa en su firma: si olvidas una prop obligatoria o pasas el tipo equivocado, el error aparece en la linea de uso.

Cuando se utilizan
  • Componentes que reciben datos (listas, formularios, tarjetas).
  • Callbacks de elevacion de estado ("cuando pase algo, avisa").
  • Eventos nativos (click, change, submit, drag...).
  • Componentes reutilizables en librerias o equipos.

2 · Teoria

La analogia: la ficha del componente

Un componente es como una maquina con una ficha tecnica: dice que material acepta (props) y que salida produce (eventos). Si le metes papel de una medida equivocada, la maquina se atasca: con tipos, esa "medida equivocada" se detecta antes de encenderla, en la puerta de la fabrica (el editor/compilador).

Definir el tipo de props

// La convencion: interface Props o type Props.
interface TarjetaProps {
  titulo: string;         // obligatoria
  subtitulo?: string;     // opcional
  onCerrar?: () => void; // callback opcional
}

export function Tarjeta({ titulo, subtitulo, onCerrar }: TarjetaProps) {
  return (
    <article>
      <h2>{titulo}</h2>
      {subtitulo ? <p>{subtitulo}</p> : null}
      {onCerrar ? <button onClick={onCerrar}>Cerrar</button> : null}
    </article>
  );
}
  • interface Props es el estandar. Con destructuring, tipas el argumento como TarjetaProps.
  • Opcionales con ?: o no estan, o undefined.
  • Un callback prop se tipa como () => void (leccion de funciones, modulo 3).

Callbacks de elevacion de estado

// El componente padre pasa un callback para que el hijo avise.
interface ItemProps {
  item: string;
  onSeleccionar: (nombre: string) => void;
}

function Item({ item, onSeleccionar }: ItemProps) {
  return <li onClick={() => onSeleccionar(item)}>{item}</li>;
}

function Lista() {
  const items = ["uno", "dos", "tres"];
  const manejar = (nombre: string) => console.log(nombre);
  return (
    <ul>
      {items.map((i) => <Item key={i} item={i} onSeleccionar={manejar} />)}
    </ul>
  );
}

El contrato (nombre: string) => void garantiza que el padre y el hijo coinciden en la "moneda" que se pasan.

Eventos nativos tipados

import type { ChangeEvent, FormEvent, MouseEvent } from "react";

function Formulario() {
  function manejarChange(e: ChangeEvent<HTMLInputElement>) {
    console.log(e.target.value); // ✅ string, tipado
  }
  function manejarSubmit(e: FormEvent<HTMLFormElement>) {
    e.preventDefault();
    console.log("enviado");
  }
  return (
    <form onSubmit={manejarSubmit}>
      <input type="text" onChange={manejarChange} />
      <button type="submit">Enviar</button>
    </form>
  );
}
  • Los eventos de React tienen su propio tipo (ChangeEvent<T>, FormEvent<T>, MouseEvent<T>) con el elemento HTML como generico.
  • HTMLInputElement, HTMLFormElement, HTMLSelectElement... tipan el target.

Eventos inline vs handlers externos

// Inline: TypeScript infiere el tipo del evento por el atributo JSX.
<input type="text" onChange={(e) => setValor(e.target.value)} />

// Handler externo: anota el tipo explicitamente.
function manejar(e: ChangeEvent<HTMLInputElement>) { /* ... */ }
<input type="text" onChange={manejar} />
Por que e.target.value compila en inline

En JSX, React conoce el tipo de onChange segun el elemento: en un <input>, infiere ChangeEvent<HTMLInputElement> para el callback. Asi el e inline ya esta tipado sin anotarlo. En handlers separados debes anotarlo tu (perdiste el contexto del JSX).

children y props especiales

import type { ReactNode } from "react";

interface ContenedorProps {
  children: ReactNode; // "lo que pongas entre etiquetas"
}

function Contenedor({ children }: ContenedorProps) {
  return <div className="caja">{children}</div>;
}

// Uso:
<Contenedor><p>Texto dentro</p></Contenedor> // ✅ ReactNode acepta casi todo

Props de estilo y className

import type { CSSProperties } from "react";

interface EstiloProps {
  estilo?: CSSProperties; // objeto de estilos inline tipado
}

function Caja({ estilo }: EstiloProps) {
  return <div style={estilo}>hola</div>;
}

<Caja estilo={{ color: "red", marginTop: 8 }} /> // ✅ marginTop, no margin-top

3 · Ejemplo minimo

props-minimo.tsx
interface SaludoProps {
  nombre: string;
  edad?: number;
}

export function Saludo({ nombre, edad }: SaludoProps) {
  return (
    <p>
      Hola {nombre}
      {edad !== undefined ? `, tienes ${edad}` : ""}
    </p>
  );
}

Linea a linea:

  • interface SaludoProps define el contrato del componente.
  • nombre: string obligatoria: usarla sin pasarla da error.
  • edad?: number opcional: puede faltar o ser undefined.
  • El render usa los props con tipos: {nombre} es string.

4 · Ejemplo real

Un campo de entrada reutilizable con label, valor y callback de cambio, ademas de un formulario que lo usa:

src/CampoTexto.tsx
import type { ChangeEvent } from "react";

interface CampoTextoProps {
  etiqueta: string;
  valor: string;
  onCambio: (nuevo: string) => void;
  required?: boolean;
}

export function CampoTexto({ etiqueta, valor, onCambio, required }: CampoTextoProps) {
  function manejar(e: ChangeEvent<HTMLInputElement>) {
    onCambio(e.target.value); // el valor tipado sube al padre
  }
  return (
    <label>
      {etiqueta}
      <input value={valor} onChange={manejar} required={required} />
    </label>
  );
}
src/Registro.tsx
import { useState } from "react";
import { CampoTexto } from "./CampoTexto";

export function Registro() {
  const [nombre, setNombre] = useState("");
  const [email, setEmail] = useState("");

  return (
    <form onSubmit={(e) => { e.preventDefault(); console.log(nombre, email); }}>
      <CampoTexto etiqueta="Nombre" valor={nombre} onCambio={setNombre} required />
      <CampoTexto etiqueta="Email" valor={email} onCambio={setEmail} required />
      <button type="submit">Registrarme</button>
    </form>
  );
}

Decisiones:

  • onCambio: (nuevo: string) => void define el contrato de subida de datos.
  • setNombre y setEmail encajan exactamente en ese contrato (leccion de callbacks, modulo 3).
  • El required opcional pasa directo al input.
  • El formulario es totalmente tipado: el estado y los eventos coinciden.

5 · Buenas practicas

  • Define una interface Props (o type Props) por componente.
  • Usa callbacks tipados para elevar estado; el contrato es (dato) => void.
  • Eventos inline: no anotes (infiere); handlers externos: anota con los tipos react.
  • Usa ReactNode para children y CSSProperties para estilos inline.
  • Props opcionales solo cuando de verdad pueden faltar.

Que evitar

  • props: any: el tipado de props es la raiz de la seguridad en React.
  • Tipos de eventos de navegador (React.SyntheticEvent) sin el elemento generico.
  • Dejar el evento inline sin e tipado cuando lo separas a un handler.
  • Duplicar interfaces de props por copia/pega.

6 · Errores habituales

Mal — any en props 
function MiComp({ nombre }: any) {
  return <p>{nombre.toUpperCase()}</p>; // ✖ sin garantias
}
Bien — props tipadas 
interface Props { nombre: string; }
function MiComp({ nombre }: Props) {
  return <p>{nombre.toUpperCase()}</p>; // ✅
}
Mal — evento mal tipado (sin generico) 
function f(e: ChangeEvent) {
  // ✖ ChangeEvent necesita el generico del elemento
}
Bien — con el elemento 
function f(e: ChangeEvent<HTMLInputElement>) {
  // ✅ e.target.value es string
}
Mal — contrato de callback distinto 
// El hijo promete (id: number) => void
// El padre pasa (id: string) => void
// ✖ error: los parametros no coinciden (contravariance)
Bien — mismo contrato 
// Ambos con (id: number) => void ✅

7 · Ejercicio guiado

Vamos a crear un componente de seleccion de un elemento de una lista.

  1. Define interface SelectorProps { items: string[]; onSelect: (item: string) => void; }.
  2. Renderiza un <select> con las opciones.
  3. En onChange, sube e.target.value al callback.
  4. En el padre, usa onSelect={(v) => console.log(v)}.

Solucion paso a paso:

src/Selector.tsx
import type { ChangeEvent } from "react";

interface SelectorProps {
  items: string[];
  onSelect: (item: string) => void;
}

export function Selector({ items, onSelect }: SelectorProps) {
  function manejar(e: ChangeEvent<HTMLSelectElement>) {
    onSelect(e.target.value);
  }
  return (
    <select onChange={manejar}>
      {items.map((opcion) => (
        <option key={opcion} value={opcion}>{opcion}</option>
      ))}
    </select>
  );
}

Reto

Extiende el componente anterior con una prop icono?: string y un callback de "clic en el icono" (onIconoClick?: () => void). Ademas, haz un componente Grid<T> generico que reciba data: T[] y una render: (item: T) => ReactNode. No mires la solucion.

9 · Resumen

  • Props con interface Props: obligatorias, opcionales y callbacks.
  • Eventos: tipos de React con el elemento HTML como generico.
  • Elevar estado con callbacks tipados (dato) => void.
  • ReactNode para children; CSSProperties para estilos.
  • El contrato de props hace el componente reutilizable y seguro.

10 · Preguntas frecuentes

¿Que diferencia hay entre SyntheticEvent y los tipos ChangeEvent/MouseEvent?

SyntheticEvent es el base. ChangeEvent<T> y MouseEvent<T> son especializaciones con propiedades concretas (target, value). Usa la mas especifica.

¿Puedo usar los mismos tipos de eventos que el navegador nativo?

No exactamente: React usa SyntheticEvent (con propiedades normalizadas). Importa los de react (ChangeEvent...) o usa globalThis para nativos segun el contexto.

¿Que es ReactNode?

El union de todo lo renderizable por React: string, number, elementos, fragments, arrays, null. Es el tipo de children por defecto.

¿Por que mis callbacks de props fallan si cambian el tipo del parametro?

Por contravarianza de funciones (modulo 3): un callback que acepta string NO es asignable a uno que promete aceptar number y viceversa. Deben coincidir.

¿Puedo exportar el tipo Props para reutilizarlo?

Si: export interface Props {...} permite a otros importarlo. Es comun en librerias de componentes.

¿Necesito tipar los handlers que paso a onClick?

En inline no; React infiere. En handlers externos si, con el tipo adecuado segun el elemento (MouseEvent<HTMLButtonElement>, etc.).
