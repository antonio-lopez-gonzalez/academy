keyof, indexed, mapped types

Modulo 5 · Genericos 🕐 30 minutos

1 · Introduccion

En la leccion anterior viste keyof como restriccion. Ahora vamos a convertirlo en protagonista: TypeScript permite reflexionar sobre los tipos, igual que JavaScript reflexiona sobre objetos en runtime. Con keyof obtienes las claves; con los indexed access types (notacion T[K]) obtienes el tipo de un valor por su clave; con los mapped types transformas un tipo claves a claves ({ [P in K]: ... }).

Estas tres herramientas son el combustible de las utility types del modulo 6: Partial, Pick, Omit, Readonly estan definidos exactamente con estos mecanismos. Entenderlas es entender TypeScript "de verdad", no solo memorizar utilidades.

Cuando se utilizan
  • Validar que una clave existe (keyof + restricciones).
  • Tipos que dependen de las claves de otros tipos.
  • Transformaciones: opcional, readonly, filtrado por valor.
  • Formularios, columnas de tablas, mapeos de configuracion.

2 · Teoria

Reflexion: JavaScript vs TypeScript

En JavaScript "reflexionas" sobre objetos con Object.keys y obj[clave]. TypeScript hace lo mismo a nivel de tipos:

JavaScript (runtime) TypeScript (compilacion) Object.keys(obj) => keyof Obj obj[clave] => Obj[Clave] Mismos gestos, distinto plano.

keyof: la union de claves

type Punto = { x: number; y: number };

type ClavesPunto = keyof Punto; // "x" | "y"

// keyof sobre arrays/strings: sus indices como claves
type ClavesDeArray = keyof string[]; // number | "length" | "push" | ...
type IndiceDeString = keyof string;  // number | "length" | "charAt" | ...

keyof T devuelve la union de las claves de T. Es la "lista de llaves" a nivel de tipos. Si T tiene 3 propiedades, keyof T son 3 cadenas literales unidas. Si T es un indice de firma ({ [k: string]: number }), keyof es string.

Indexed access types (T[K])

type Punto = { x: number; y: number };

// El tipo del valor en la clave x:
type TipeX = Punto["x"]; // number

// Con unions de claves:
type TipeYx = Punto["x" | "y"]; // number (ambas dan number)

// Con keyof completo:
type TodoValor = Punto[keyof Punto]; // number

// De array a elemento (indexed con indice "number"):
type Palabras = string[];
type Elemento = Palabras[number]; // string

type Mixto = (string | number)[];
type ElementoMixto = Mixto[number]; // string | number
Por que la notacion con corchetes

T[K] replica obj[clave]: "el tipo del valor que hay en la clave K de T". Esto permite extraer tipos parciales de un tipo mayor (leccion util para Pick en el modulo 6). Aplicarlo sobre una union de claves da la union de valores.

Mapped types: transformar claves a claves

type Punto = { x: number; y: number };

// Recorre cada clave P del tipo y produce un nuevo objeto con esa clave,
// mapeando el tipo del valor.
type TodosOpcionales = { [P in keyof Punto]?: Punto[P] };
// { x?: number; y?: number }

type SoloLectura = { readonly [P in keyof Punto]: Punto[P] };
// { readonly x: number; readonly y: number }

La sintaxis es { [P in K]: tipoValor }. Es un bucle a nivel de tipos: genera un objeto con una propiedad por cada clave del union K. Es la mecanica interna de Partial, Readonly, Pick y Record (modulo 6). 

// Ejemplo: filtrar las claves cuyo valor es number.
type PuntoEtiquetado = {
  x: number;
  nombre: string;
  y: number;
};

// { [P in keyof PuntoEtiquetado as ...]: ... } — renombrado/copiado de claves
type SoloNumericas = {
  [P in keyof PuntoEtiquetado as PuntoEtiquetado[P] extends number ? P : never]:
    PuntoEtiquetado[P];
};
// { x: number; y: number }  ("nombre" se descarto)
La clausula as: renombrar/filtrar claves

Desde TS 4.1 puedes redefinir la clave mapeada con as ..., permitiendo filtrar claves (como arriba), renombrarlas con template literals o aplicar transformaciones. Es el mecanismo de utilidades avanzadas de modulo 6.

Mapped types con modificadores + y -

type QuitarReadonly<T> = { -readonly [P in keyof T]: T[P] };
type QuitarOpcional<T> = { [P in keyof T]-?: T[P] };
// "-?" elimina el opcional.

interface Config { readonly api: string; timeout?: number; }
type ConfigMutable = QuitarReadonly<Config>;
// { api: string; timeout?: number }  (readonly quitado)
type ConfigObligatoria = QuitarOpcional<Config>;
// { readonly api: string; timeout: number } (?: quitado)

+ añade (readonly, ?); - quita. Es la "eliminacion"" de modificadores opuesta a la utilidad Required.

Record, la utilidad que usa mapped

// Record es un mapped type predefinido (modulo 6):
type RecordBuiltin<K extends keyof any, V> = { [P in K]: V };
type Estados = "ido" | "activo" | "expirado";
type Etiquetas = Record<Estados, string>;
// { ido: string; activo: string; expirado: string }

3 · Ejemplo minimo

reflexion-minimo.ts
type Usuario = { id: number; nombre: string };

// 1) keyof: las claves de Usuario
type Claves = keyof Usuario; // "id" | "nombre"

// 2) indexed: el tipo del valor de cada clave
type idTipe = Usuario["id"];     // number
type nomTipe = Usuario["nombre"]; // string

// 3) mapped: un Usuario donde TODO es opcional
type UsuarioParcial = { [K in keyof Usuario]?: Usuario[K] };
// { id?: number; nombre?: string }

Linea a linea:

  • keyof Usuario genera la union de claves "id" | "nombre".
  • Usuario["id"] extrae el tipo del valor en esa clave.
  • El mapped type recorre cada K de keyof Usuario y crea la propiedad, añadiendo ? (opcional).

4 · Ejemplo real

Un mapeo de formularios: cada campo tiene tipo, etiqueta, requerido y default, derivado de un tipo de datos:

formulario-tipado.ts
// Los datos del formulario.
interface DatosContacto {
  nombre: string;
  email: string;
  edad: number;
}

// Descripcion de cada campo: claves identicas a DatosContacto,
// con el tipo de valor de cada clave mas metadata.
type CampoContacto<K extends keyof DatosContacto> = {
  clave: K;
  tipo: DatosContacto[K];      // indexed: el tipo real del valor
  etiqueta: string;
  requerido: boolean;
};

// Mapped type: un objeto con el MISMO shape que DatosContacto, pero
// donde cada valor es un CampoContacto.
type MapaFormulario = {
  [K in keyof DatosContacto]: CampoContacto<K>;
};

// Construimos el formulario con seguridad total:
const formulario: MapaFormulario = {
  nombre: { clave: "nombre", tipo: "", etiqueta: "Nombre", requerido: true },
  email: { clave: "email", tipo: "", etiqueta: "Email", requerido: true },
  edad: { clave: "edad", tipo: 0, etiqueta: "Edad", requerido: false },
};

// Si añadimos una clave a DatosContacto, TS exige su campo en el formulario
// y en TiposContacto. Si quitamos una, sobra y da error de tipo real.
function valorDe<K extends keyof DatosContacto>(campo: CampoContacto<K>): DatosContacto[K] {
  return campo.tipo; // el tipo exacto del valor en esa clave
}

Decisiones:

  • [K in keyof DatosContacto] obliga a que el formulario tenga exactamente las claves del tipo de datos: la union se vuelve un contrato.
  • DatosContacto[K] mantiene cada campo con su tipo real (nombre: string, edad: number).
  • El formulario queda "atado" a DatosContacto: los errores aparecen en el punto donde el DOM -> TS se desincroniza.

5 · Buenas practicas

  • Usa keyof para restringir claves (K extends keyof T) en lugar de aceptar string generico.
  • Usa indexed access (T[K]) para extraer subtipos en vez de duplicarlos.
  • Usa mapped types para derivar tipos derivados de otros: "el formulario sigue al modelo".
  • Con as, filtra/renombra claves con precisión (antes de la clausula as era imposible).
  • Prefiere las utilidades del modulo 6 cuando existan (Partial, Pick) sobre inventar las tuyas.

Que evitar

  • keyof sobre tipos amplios innecesariamente (obtendras strings y metodos).
  • Escribir T[K] con claves que no existen: error en compilacion, beneficio enorme.
  • Mapped types gigantes cuando una utility type del modulo 6 lo resuelve.
  • Mezclar keyof con objetos anidados sin anclar previamente.

6 · Errores habituales

Mal — indexar con un string generico 
type Usuario = { id: number };
function getValor(o: Usuario, clave: string) {
  return o[clave]; // ✖ clave podria no existir: error "no index signature"
}
Bien — restringir K a keyof Usuario 
type Usuario = { id: number };
function getValor<K extends keyof Usuario>(o: Usuario, clave: K): Usuario[K] {
  return o[clave]; // ✅ solo claves reales, retorno tipado
}
Mal — olvidar el modificador - para quitar readonly/opcional 
type QuitarReadonly<T> = { [P in keyof T]: T[P] };
// ✖ NO quita readonly: el mapped type conserva los modificadores originales
Bien — usar -readonly (y -? para el opcional) 
type QuitarReadonly<T> = { -readonly [P in keyof T]: T[P] };
Mal — indexed access con indice inexistente 
type Persona = { nombre: string };
type E = Persona["apellidos"]; // ✖ error: "apellidos" no existe
Bien — comprobar con keyof o anadir la clave 
type Persona = { nombre: string };
type E = Persona["nombre"]; // ✅ string

7 · Ejercicio guiado

Queremos hacer que cada configuracion del sistema sea opcional en partes.

  1. Define Config = { host: string; port: number; debug: boolean }.
  2. Escribe type ConfigParcial = { [K in keyof Config]?: Config[K] }.
  3. Crea type SoloDebug = { [K in keyof Config as Config[K] extends boolean ? K : never]: Config[K] }.
  4. Comprueba keyof SoloDebug y ConfigParcial en el Playground/tsc.

Solucion paso a paso:

ejercicio-keyof-mapped.ts
type Config = { host: string; port: number; debug: boolean };

// Todos los campos opcionales:
type ConfigParcial = { [K in keyof Config]?: Config[K] };
// { host?: string; port?: number; debug?: boolean }

// Solo los campos cuyo valor es boolean:
type SoloDebug = {
  [K in keyof Config as Config[K] extends boolean ? K : never]: Config[K];
};
// { debug: boolean }

type claveSoloDebug = keyof SoloDebug; // "debug" ✅
const cfg: ConfigParcial = { host: "10.0.0.1" }; // ✅ campos opcionales

8 · Reto

Reto

Escribe un mapped type PrefijoClave<T, P extends string> que añada un prefijo a cada clave de T (pista: template literal `${P}${string & keyof T}` con la clausula as). Despues escribe la funcion que lo consuma. No mires la solucion.

9 · Resumen

  • keyof T: la union de claves de T.
  • T[K]: el tipo del valor en la clave K (indexed access).
  • Mapped types { [P in K]: ... } transforman un tipo claves a claves, sin reemplazar el shape.
  • Modificadores +/- para readonly y opcional; as para renombrar o filtrar claves.
  • Son los engranajes de las utility types del modulo 6.

10 · Preguntas frecuentes

¿Hay diferencia entre keyof de interfaz y de type alias?

No para este proposito: ambos producen la union de claves. La diferencia interface vs type afecta a extension y merge, no a keyof.

¿Puedo usar keyof con arrays?

Si. keyof string[] incluye number (indices) y metodos como "push", "length". Si solo quieres los indices, usa T[number].

¿Los indexed access types funcionan con índices de firma?

Si: type Rec = { [k: string]: number }; Rec["x"] es number. Con firma string, cualquier clave string devuelve el tipo de valor.

¿Que es más eficiente: escribo utilidades a mano o uso las del modulo 6?

Las utilidades del modulo 6 (Partial, Pick, Omit, etc.) estan probadas y son homogéneas. Escribe las tuyas solo cuando la utilidad no exista o necesites lógica de dominio.

¿Puedo recorrer un objeto real con for...in y un tipo mapped?

Si, pero recuerda que los tipos no existen en runtime. El tipado mapped es lo que el compilador verifica; el recorrido real lo haces con for (const k in obj) usando keyof como tipo.

¿La clausula as existe en todos los TypeScript?

Se añadio en TypeScript 4.1 para renombrado de claves y filtros. El codigo del curso es compatible con 5.9+, asi que la tendras disponible.
