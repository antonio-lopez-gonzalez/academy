Assertion y type predicates

Modulo 4 · Unions y narrowing 🕐 30 minutos

1 · Introduccion

Los guards automaticos (typeof, instanceof) llegan hasta donde llegan. Para validar tu dominio (un JSON con forma de Usuario, un string que cumple un formato) necesitas guards propios. TypeScript ofrece dos herramientas: los type predicates (x is Tipo) y las assertion functions (asserts x is Tipo).

2 · Teoria

El problema: un guard custom no "avisa" al compilador

interface Usuario { nombre: string; email: string }

function esUsuario(valor: unknown): boolean {
  // Devuelve true si tu logica de validacion cuadra.
  return typeof valor === "object" && valor !== null && "nombre" in valor && "email" in valor;
}

const crudo: unknown = JSON.parse('{"nombre":"Ada","email":"a@d.ts"}');

// Aunque esUsuario(crudo) es true, el compilador NO lo sabe:
if (esUsuario(crudo)) {
  console.log(crudo.nombre); // ✖ crudo sigue siendo unknown
}

Un boolean no basta: el compilador no conecta el true/false con un tipo.

Type predicate: x is Tipo

function esUsuario(valor: unknown): valor is Usuario {
  return (
    typeof valor === "object" &&
    valor !== null &&
    "nombre" in valor &&
    "email" in valor
  );
}

// AHORA el compilador entiende el guard:
if (esUsuario(crudo)) {
  console.log(crudo.nombre); // ✅ crudo: Usuario
  console.log(crudo.email);  // ✅
}

El tipo de retorno valor is Usuario le dice a TypeScript: "si esta funcion devuelve true, entonces valor es un Usuario". Es la firma del guard. Si devuelve false, la union se estrecha a lo restante.

El predicate es una PROMESA tuya

TypeScript NO verifica que tu logica sea correcta a nivel de tipos: valor is Usuario promete que tipo real estara cuando devuelvas true. Si tu chequeo esta mal (p.ej. no compruebas la forma completa), el guard MINTIERA y el codigo fallaria en runtime. Escribe validaciones rigurosas.

Discriminated unions con predicates

type Mensaje =
  | { tipo: "texto"; cuerpo: string }
  | { tipo: "archivo"; nombre: string; tamano: number };

// Guard por variante:
function esArchivo(m: Mensaje): m is { tipo: "archivo"; nombre: string; tamano: number } {
  return m.tipo === "archivo";
}

function ver(m: Mensaje): string {
  if (esArchivo(m)) {
    return `Archivo ${m.nombre} (${m.tamano} KB)`; // m estrechado
  }
  return `Texto: ${m.cuerpo}`;
}

Assertion functions: asserts x is T

A veces no quieres un if: quieres validar y lanzar si no cuadra. Las assertion functions hacen justo eso y además estrechan despues de llamarlas: 

function afirmarUsuario(valor: unknown): asserts valor is Usuario {
  if (!esUsuario(valor)) {
    throw new Error("El valor no es un Usuario valido");
  }
}

// Uso: despues de la llamada, valor ES Usuario (si no, lanza).
function tramitar(valor: unknown): string {
  afirmarUsuario(valor);        // valida y lanza si falla
  return valor.nombre;          // ✅ valor: Usuario
}

Dos variantes de firma para asserts:

FirmaEfecto
asserts x is TipoSi no lanza, x pasa a ser Tipo.
asserts condicionSi no lanza, la condicion es verdadera (y estrecha la union).

typeof vs predicates para primitivos

function esNumeroPuro(v: unknown): v is number {
  return typeof v === "number" && Number.isFinite(v);
}
// Evita NaN, controlando el "numero" real.

3 · Ejemplo minimo

predicado-minimo.ts
interface Punto2D { x: number; y: number }

// Predicado: si devuelve true, valor es Punto2D.
function esPunto2D(valor: unknown): valor is Punto2D {
  return (
    typeof valor === "object" &&
    valor !== null &&
    "x" in valor &&
    "y" in valor
  );
}

const crudo: unknown = { x: 1, y: 2 };
if (esPunto2D(crudo)) {
  // El tipo ya es Punto2D: autocompletado y metodos funcionan.
  console.log(crudo.x, crudo.y);
}

4 · Ejemplo real

Validar la respuesta de una API en el "borde" del sistema (el patron de aduana del modulo 1, ahora con guard propio):

api-guard.ts
// Formas esperadas de la API.
interface Tarea {
  id: number;
  titulo: string;
  completada: boolean;
}

// Predicado: valida la forma del dato con rigor.
function esTarea(valor: unknown): valor is Tarea {
  if (typeof valor !== "object" || valor === null) return false;
  const v = valor as Record<string, unknown>; // acceso seguro a props
  return (
    typeof v.id === "number" &&
    typeof v.titulo === "string" &&
    typeof v.completada === "boolean"
  );
}

// Predicado para arrays:
function esListaTareas(valor: unknown): valor is Tarea[] {
  return Array.isArray(valor) && valor.every(esTarea);
}

async function cargarTareas(): Promise<Tarea[] | null> {
  const respuesta = await fetch("/api/tareas");
  const crudo: unknown = await respuesta.json(); // any → lo declaramos unknown

  // Tras el guard, ya tenemos las tareas validas.
  if (!esListaTareas(crudo)) {
    return null; // forma invalida: el consumidor decide
  }
  return crudo; // ✅ Tarea[]
}

async function demo() {
  const tareas = await cargarTareas();
  if (tareas) {
    console.log(tareas.map((t) => t.titulo).join(", "));
  }
}

Decisiones:

  • esTarea con predicate: convierte datos unknown en Tarea segun tu logica.
  • esListaTareas compone guards con every: el array entero se valida tipo a tipo.
  • El borde del sistema convierte unknown en tipos propios de forma ordenada, sin as a ciegas.

5 · Buenas practicas

  • Escribe predicates rigurosos: comprueba TODA la forma, no solo una propiedad.
  • Actualiza los predicates al mismo tiempo que los tipos: si Tarea gana un campo, el guard debe exigirlo.
  • Componé guards (every, some, anidados) para validar estructuras.
  • Usa asserts x is T en limites donde quieras lanzar con mensajes claros.
  • Manten un modulo guards.ts reutilizable en la app.

Que evitar

  • Predicates que solo miran una clave: el dato pasa "de paseo" y luego rompe.
  • Usar as Tarea para ahorrarte el guard: es la misma trampa del any.
  • Llamar predicates "baratos" y validar poco: la promesa se hara real en runtime.

6 · Errores habituales

Mal — predicado que solo comprueba el objeto 
function esUsuario(v: unknown): v is { nombre: string } {
  return typeof v === "object" && v !== null; // ❌ no valida "nombre"
}
// Se promete Usuario sin comprobar su forma: guard que miente.
Bien — validar la estructura completa 
function esUsuario(v: unknown): v is { nombre: string } {
  return (
    typeof v === "object" &&
    v !== null &&
    "nombre" in v &&
    typeof (v as Record<string, unknown>).nombre === "string"
  );
}
Mal — predicado sobre valor que ya ES el tipo (amiguisimo inutil) 
function yaEsEs(v: Usuario): v is Usuario { return true; } // no aporta nada
Bien — predicates solo para estrechar unknown/union 
function esNumeroFinito(v: unknown): v is number {
  return typeof v === "number" && Number.isFinite(v);
}
Mal — asercion que no lanza cuando deberia 
function chequear(v: unknown): asserts v is Usuario {
  if (!v) {} // ❌ sin throw: la funcion "asegura" sin comprobar
}
Bien — lanzar si no cuadra 
function chequear(v: unknown): asserts v is Usuario {
  if (!esUsuario(v)) throw new Error("Se esperaba un Usuario");
}

Reto

9 · Resumen

  • Type predicate valor is T: convierte tu funcion booleana en un guard que el compilador entiende.
  • Assertion function asserts valor is T: valida y estrecha tras lanzar (o lanzar).
  • Escribe predicates rigurosos: son una promesa para el compilador cuya verdad se cumple en runtime.
  • Componé guards para estructuras (arrays, objetos anidados).
  • Alternativa superior a as en el borde del sistema.

10 · Preguntas frecuentes

¿Por que my guard con boolean no estrecha el tipo?

Porque un boolean solo dice "true/false": el compilador no asocia el true con un tipo. El predicate x is T es la forma de hacer esa asociacion.

¿Puedo tener un predicate que devuelva false y estrecha al resto?

Si. Con un union A | B, un predicate x is A en el if deja en el else estrictamente B (si la forma lo permite).

¿Es lo mismo asserts x is T que throw de mi parte?

No exactamente: asserts valor is Usuario ademas de "puede lanzar", le dice al compilador "si retorna, valor ES Usuario". Si solo lanzas con If (!esUser) throw, el compilador corre con mas cautela.

¿Puedo combinar varios predicates?

Si, anidando o encadenando: if (esA(v)) { ... } else if (esB(v)) { ... }. Tambien componiendo sobre arrays con .every.

¿TypeScript verifica la logica del predicate?

No. El predicate es una promesa: el tipo real que prometes debe ser cierto cuando devuelves true y posible cuando devuelves false. Verifica a mano con tests o con firma conservadora (restringe de mas, nunca de menos).
