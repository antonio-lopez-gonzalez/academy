Union types y type guards

Modulo 4 · Unions y narrowing 🕐 30 minutos

1 · Introduccion

Los union types te dicen "puede ser esto O aquello". Lo realmente poderoso llega con el narrowing (estrechamiento): cuando TypeScript observa una comprobacion en tu codigo y reduce el tipo a una de sus parte. Aqui dominamos los type guards tacitas: typeof, instanceof, in y la igualdad de literales.

Esta es de las lecciones que mas cambian tu forma de leer codigo: empezaras a "ver" el tipo que se estrecha en cada if.

2 · Teoria

Union type: el "o" de los tipos

let valor: string | number;
valor = "texto";  // ✅
valor = 42;       // ✅
// valor = true;  // ✖ boolean no esta en la union

Mientras no estrechas, solo puedes usar lo comun a ambas parte:

function largo(x: string | number): number {
  // String(x) es seguro para ambos.
  return String(x).length;
}

Acceder a valor.toFixed() (solo number) da error: en este punto el compilador no sabe que "valor" es un numero. Ahí entra el narrowing.

Narrowing: el compilador elimina posibilidades

valor: string | number │ │ if (typeof valor === "string") ▼ rama true: valor: string ← aqui SOLO string rama false: valor: number ← queda la otra parte 
function procesar(valor: string | number): string {
  if (typeof valor === "string") {
    return valor.toUpperCase(); // ✅ valor es string aqui
  }
  return valor.toFixed(2);       // ✅ aqui valor es number
}

TypeScript "ejecuta tu logica" a nivel de tipos: cada condicion que comprueba el tipo real estrecha la union en las ramas. Eso es el narrowing, y los guards son las herramientas que lo disparan.

Type guards automaticos

GuardCompruebaEstrecha a
typeofPrimitivosstring, number, boolean, symbol, bigint, undefined, function, object
instanceofInstancias de claseDate, Error, clases propias
inPropiedadVariante de objeto que tienen la clave
=== IgualdadLiterales (discriminante)
Array.isArraySi es arrayT[] en una union con arrays

Truthiness y boolean

// La comprobacion "si existe" también estrecha null/undefined.
function saludar(nombre: string | null): string {
  if (nombre) {
    return `Hola ${nombre}`;  // nombre: string ✅
  }
  return "Hola anonimo";
}

typeof: solo primitivos

// typeof no estrecha objetos (typeof {} === "object" para arrays y null).
if (typeof x === "object") {
  // x: object | null — cuidado, no te dice el tipo concreto.
}

in: propiedad presente

type AnimalP = { tipo: "perro"; ladra: boolean };
type AnimalG = { tipo: "gato"; arana: boolean };

function detalle(a: AnimalP | AnimalG): string {
  if ("ladra" in a) {
    return a.ladra ? "Ladra" : "No ladra"; // a: AnimalP
  }
  return a.arana ? "Araña" : "No araña";   // a: AnimalG
}

Nota: in y typeof son guards de runtime validos (no "ticks" del compilador), asi que tambien funcionan en JavaScript puro.

3 · Ejemplo minimo

guards-minimo.ts
type Entrada = string | number | boolean;

function clasificar(valor: Entrada): string {
  if (typeof valor === "string") return "cadena";
  if (typeof valor === "number") return "numero";
  return "booleano"; // aqui ya sabemos: boolean
}

console.log(clasificar("hola"));   // cadena
console.log(clasificar(42));       // numero
console.log(clasificar(true));     // booleano

4 · Ejemplo real

Un formateador de "identificadores" que puede llegar como numero, string o instancia de Date:

formatear.ts
type Identificador = string | number | Date;

function etiqueta(id: Identificador): string {
  // typeof para primitivos...
  if (typeof id === "string") {
    return id.trim();
  }
  if (typeof id === "number") {
    return Number.isInteger(id) ? id.toFixed(0) : id.toString();
  }
  // ...y instanceof para instancias de clase.
  if (id instanceof Date) {
    return id.toISOString().slice(0, 10); // solo la fecha
  }
  return "desconocido"; // el exhaustivo del modulo 2: rama imposible
}

console.log(etiqueta("   ABC  ")); // "ABC"
console.log(etiqueta(42));          // "42"
console.log(etiqueta(new Date("2026-01-01"))); // "2026-01-01"

Decisiones:

  • El typeof responde por los primitivos; instanceof Date por la instancia.
  • Cada rama simplifica el tipo: string, number, Date.
  • La ultima posicion queda never en la practica: si alguien añade un miembro a la union, este codigo cambia (mas adelante lo protegemos con exhaustive check).

5 · Buenas practicas

  • Diseña unions "lo mas cerradas posible": pocas variante y bien diferenciables entre si.
  • USA la comprobacion mas directa: typeof para primitivos, instanceof para clases, in o discriminante para objetos.
  • Combina guards: primero el caso mas comun/barato, luego los raros.
  • Aprovecha el narrowing para crear variable auxiliares tipadas (refactor de ayuda).
  • Recuerda que la rama "else" o la final de los guards queda con lo restante: usa never o retornos por defecto para no dejar casos sin cerrar.

Que evitar

  • Usar typeof para objetos (no da el tipo concreto).
  • Comprobar dos veces lo mismo; el narrowing ya elimino la posibilidad.
  • Creer que el orden de guard no importa: se evalua secuencialmente.

6 · Errores habituales

Mal — typeof sobre un objeto esperando el tipo concreto 
function f(x: Date | string) {
  if (typeof x === "object") {
    // x: Date | null (no "Date"): typeof object no discrimina clases
  }
}
Bien — instanceof para instancias 
function f(x: Date | string) {
  if (x instanceof Date) {
    return x.getTime(); // ✅ x: Date
  }
  return x.length;      // x: string
}
Mal — ignorar que la rama final puede ser vacia 
type X = "a" | "b";
function f(x: X): number {
  if (x === "a") return 1;
  // ojo: falta el caso "b" → retorno indefinido en runtime
}
Bien — cerrar todas las ramas 
function f(x: X): number {
  if (x === "a") return 1;
  return 0; // el resto (solo "b")
}

8 · Reto

Reto

Crea un tipo Configuracion = { tipo: "basica"; nombre: string } | { tipo: "avanzada"; nombre: string; nivel: number } | { tipo: "oculta" } y una funcion sumario que use SOLO guards automaticos (typeof no vale; usa el discriminante tipo y in/===) para devolver un string descriptivo. Implementa el guard "nivel" in cfg explicitamente.

9 · Resumen

  • Union type = "puede ser cualquiera de estas parte".
  • Narrowing = TypeScript elimina posibilidades segun tus condiciones.
  • Guards: typeof (primitivos), instanceof (clases), in (propiedad), === (literales), truthiness.
  • El orden de los guards importa: se evalua secuencialmente.
  • Cierre siempre todas las ramas y usa never en las imposibles.

10 · Preguntas frecuente

¿Puedo estrechar con una variable auxiliar?

Si: const esNumero = typeof x === "number". TypeScript puede inferir guard en constante (control flow analysis) y estrechar con if (esNumero).

¿Por que typeof null es "object"?

Es una rareza historica de JavaScript. Por eso al comprobar objetos hay que añadir && x !== null.

¿Array.isArray estrecha correctamente?

Si: x: number[] | string + if (Array.isArray(x)) da number[] en la rama y string en la otra.

¿Puedo hacer mis propios guards?

Si, con type predicate x is Tipo: las vemos en detalle en la leccion 3 de este modulo.

¿El narrowing funciona con unions de 5+ variante?

Si, cuantas mas variante, mas precisa la maquina: cada guard elimina las que no cumplen. Por eso las discriminated unions (modulo 2) y el exhaustivo (proxima leccion) brillan con unions grandes.
