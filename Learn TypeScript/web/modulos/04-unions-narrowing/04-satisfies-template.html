satisfies, as const, template literals

Modulo 4 · Unions y narrowing 🕐 30 minutos

1 · Introduccion

Tres herramientas avanzadas que se usan en codigo moderno de librerias y configuraciones: satisfies (comprobar sin cambiar el tipo inferido), el verdadero poder de as const, y los template literal types que te permiten crear tipos a partir de plantillas de strings. Parecen detalle, y resuelven problemas reales de precision.

2 · Teoria

El problema que resuelve satisfies

A veces quieres comprobar que tu valor cumple un tipo, pero SIN que el tipo ancho reemplace al tipo estrecho que inferiste: 

type Temperaturas = Record<string, number>;

// Sin satisfies: anotamos el tipo ancho y perdemos precision.
const temp1: Temperaturas = { lunes: 21, martes: 22 };
temp1.lunes;     // tipo: number (ok)
temp1["miercoles"]; // tambien compila... (Record lo permite)

// Con satisfies: comprueba y conserva el tipo inferido.
const temp2 = { lunes: 21, martes: 22 } satisfies Temperaturas;
temp2.lunes;             // tipo: 21 (literal exacto)
// temp2.miercoles;      // ✖ NO existe: el tipo es el objeto real
satisfies vs anotacion

Anotar (: Temperaturas) reemplaza el tipo: pierdes lo concreto. satisfies solo verifica: el tipo sigue siendo el inferido (estrecho), pero TypeScript confirma que cumple el contrato. Es "comprueba, no cambies".

as const: el profundo "no cambies nada"

Ya lo vimos en el modulo 1. Repasemos su equipamiento completo:

const config = {
  entorno: "prod",
  puertos: [80, 443],
  niveles: { alto: 3, bajo: 1 },
} as const;
// entorno: "prod"   (literal)
// puertos: readonly [80, 443]  (tupla readonly)
// niveles: { readonly alto: 3; readonly bajo: 1 }

as const es un "profundo" sobre la estructura: niega mutacion y convierte todo en literal. No es un Object.freeze: a nivel de tipos impide que asignes algo más estrecho.

Template literal types

Como los template strings de JS, pero a nivel de tipos. Puedes crear apartir de literales y de otros tipos de strings: 

// Un tipo que describe rutas de API.
type Ruta = `/api/${string}`;
const r: Ruta = "/api/usuarios"; // ✅
// const mal: Ruta = "api/users"; // ✖ falta "/api/"

// Union de rutas:
type Recurso = "usuarios" | "pedidos";
type RutaUnion = `/api/${Recurso}`;
// "/api/usuarios" | "/api/pedidos"

Combinado con genericos se vuelve potente (tuplas de rutas tipadas, endpoints con parametros).

template literal type `/api/${Recurso}` ▲ ▲ ▲ literal │ literal └─ union interpolada resultado: "/api/usuarios" | "/api/pedidos"

Narrowing con template literals

function argv(tipo: "cli" | `cli:${string}`): string {
  return tipo; // acepta "cli" o "cli:cualquier cosa"
}

Combinando satisfies + as const + template literals

// Estilos de tema validos por su prefijo.
type Tema = `tema-${"claro" | "oscuro" | "auto"}`;

const temáticas = {
  actual: "tema-oscuro",
  lista: ["tema-claro", "tema-auto"],
} satisfies Record<string, string | string[]>;
// temáticas.actual es (literal) "tema-oscuro" y cumple Record

3 · Ejemplo minimo

satisfies-minimo.ts
// 1. Template literal type para endpoints.
type Endpoint = `/api/${string}`;

function llamar(ruta: Endpoint): void {
  console.log("GET", ruta);
}
llamar("/api/usuarios"); // ✅
// llamar("api/usuarios"); // ✖ falta el prefijo "/api/"

// 2. satisfies conservando el tipo estrecho.
type Opciones = { silencioso: boolean };
const opts = { silencioso: true } satisfies Opciones;
opts.silencioso; // tipo: true (literal)

4 · Ejemplo real

Un cliente de API tipado con rutas template y una configuracion validada con satisfies:

cliente.ts
// Rutas validas para nuestros endpoints.
type Recurso = "usuarios" | "pedidos" | "informes";
type Ruta = `/v2/${Recurso}${"/" | ""}${string | ""}`;

// Configuracion con satisfies: garantiza la forma sin perder precision.
const config = {
  baseUrl: "https://api.ejemplo.dev",
  timeout: 5000,
  opciones: {
    reintentos: 3,
    agresivo: false,
  },
} satisfies {
  baseUrl: string;
  timeout: number;
  opciones: { reintentos: number; agresivo: boolean };
};

// Acceso tipado estrecho: config.opciones.reintentos es literal 3.
function cliente(ruta: Ruta): string {
  return `${config.baseUrl}${ruta}`;
}

console.log(cliente("/v2/usuarios"));       // https://api.ejemplo.dev/v2/usuarios
// console.log(cliente("/v1/pedidos"));     // ✖ no es /v2/...
// console.log(cliente("/v2/otros"));       // ✖ "otros" no es recurso valido

Decisiones:

  • /v2/${Recurso}${"/" | ""}${string | ""} modela rutas con recurso valido y segmentos libres.
  • satisfies verifica la config contra su plantilla pero mantiene el tipo concreto (opciones.reintentos = 3).
  • Si cambias la version de la API (/v2/ → /v3/), el tipo te atrapa todos los usos.

5 · Buenas practicas

  • Usa satisfies cuando quieras verificar contra un contrato sin perder el tipo inferido.
  • Usa as const para literales de configuracion, listas cerradas y "valores que no cambiaran".
  • Template literal types para rutas, prefijos y parlantes con formato (=> patrones de dominio).
  • Combina los tres: configuraciones tipadas y auto-documentadas.
  • "La union con template literals sustituye a strings sueltos en rutas y claves de i18n."

Que evitar

  • Anotar tipos anchos donde satisfies conservaria precision (pierdes autocompletado).
  • Template literals desmitificados: `${string}` es equivalente a string.
  • as const sobre datos que SI cambiaran: buscaria inmutabilidad falsa.

6 · Errores habituales

Mal — anotar y perder precision 
type C = { modo: string };
const c: C = { modo: "estricto" };
c.modo;      // tipo: string (perdimos el literal "estricto")
Bien — satisfies mantiene el literal 
type C = { modo: string };
const c = { modo: "estricto" } satisfies C;
c.modo; // tipo: "estricto" ✅
Mal — template literal que no exige prefijo 
type Ruta = `${string}`; // = string: sin estructura
Bien — prefijo fijo + segmentos 
type Ruta = `/api/${string}`; // obliga a empezar por /api/
Mal — as const sobre algo mutable 
const estadistica = { clicks: 0 } as const;
estadistica.clicks = 1; // ✖ readonly: no puedes incrementar
Bien — as const para fijos; let para contadores 
let clicks = 0;            // mutable
const nomenclatura = { clicks: 0 } as const; // solo si no va a cambiar

Reto

Despues construye un objeto ENDPOINTS con as const y comprueba que ENDPOINTS.usuarios es el literal exacto. Pista: usa el template literal type y el generico con satisfies si lo necesitas.

9 · Resumen

  • satisfies: verifica el contrato SIN reemplazar el tipo inferido.
  • as const: literales, tuplas readonly, inmutabilidad a nivel de tipos.
  • Template literal types: crea tipos de strings con plantillas (`/api/${...}`).
  • Combinados: configuraciones validadas y auto-documentadas.

10 · Preguntas frecuentes

¿Cuando uso satisfies en vez de : Tipo?

Cuando quieres validar contra una forma amplia pero mantener la precision del valor real. Si el tipo inferido te da igual, la anotacion simple basta.

¿as const congela el objeto en runtime?

No. as const es solo a nivel de tipos: no llama a Object.freeze. Si necesitas congelacion real de runtime, usa Object.freeze ademas.

¿Los template literals pueden usar genericos?

Si, son especialmente potentes: type SinPrefijo<T extends string> = `/api/${T}` genera tipos a partir del parametro. Empieza a brillar con el modulo 5.

¿Puedo hacer inferencia con template literals?

Si, con infer (modulo 5). TypeScript puede extraer partes de un string template, por ejemplo capturar la clave dinamica de una ruta.

¿Por que a veces el literal no se mantiene con anotaciones?

Porque el tipo anotado es el que cuenta: si anotas : string, el valor "estricto" se amplia a string. satisfies evita ese ensanchamiento conservando el tipo inferido.
