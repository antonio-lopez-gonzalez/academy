CRUD completo tipado

Modulo 9 · Proyecto final 🕐 40 minutos Proyecto

1 · Introduccion

El corazón de cualquier app de datos: el CRUD (Create, Read, Update, Delete). Aqui implementamos las cuatro operaciones sobre las tareas, todas tipadas, inmutables y con la UI real de formularios y listas.

El problema que resuelve: el CRUD es donde se cometen los errores mas caros (borrar lo equivocado, editar con campos rotos, estados inconsistentes). TypeScript lo hace evidente: cada operacion tiene tipos claros de entrada y salida, y la UI no puede invocarlas mal.

Cuando se utilizan
  • Toda app que gestione datos (tareas, pedidos, usuarios...).
  • Formularios de creacion/edicion con campos tipados.
  • Acciones de borrado con confirmacion.
  • Sincronizacion del estado con el almacen (localStorage/API).

2 · Teoria

La analogia: la ficha del archivo

Piensa en una ficha de cliente en una oficina. Tienes cuatro movimientos posibles: dar de alta (create), consultar (read), modificar datos (update) y retirar (delete). Cada movimiento debe pedir los datos correctos: no puedes "modificar" sin decir que ficha, ni "dar de alta" sin el nombre. Nuestras funciones tipadas definen exactamente esos requisitos.

CREATE: crear una tarea

import type { Tarea } from "../domain/modelo";

export interface NuevaTarea {
  titulo: string;
  descripcion?: string;
  etiquetas?: string[];
}

export function crearTarea(nueva: NuevaTarea): Tarea {
  // El sistema decide los campos inmutables y los estructura:
  return {
    id: crypto.randomUUID(),          // id unico
    titulo: nueva.titulo,
    descripcion: nueva.descripcion ?? "",
    estado: "pendiente",              // siempre arranca pendiente
    creadaEn: new Date().toISOString(),
    ...(nueva.etiquetas ? { etiquetas: nueva.etiquetas } : {}),
  };
}

NuevaTarea es el DTO de entrada (modulo 6): el formulario solo entrega lo que el usuario mete; la funcion decide el resto.

READ: leer y filtrar

import type { EstadoTarea, Tarea } from "../domain/modelo";

export function porEstado(tareas: Tarea[], estado: EstadoTarea): Tarea[] {
  return tareas.filter((t) => t.estado === estado);
}

export function findById(tareas: Tarea[], id: string): Tarea | undefined {
  return tareas.find((t) => t.id === id);
}

UPDATE: actualizar (inmutable)

// Update parcial tipado: solo los campos editables.
export interface CambioTarea {
  titulo?: string;
  descripcion?: string;
  estado?: EstadoTarea;
  etiquetas?: string[];
}

export function actualizarTarea(
  tareas: Tarea[],
  id: string,
  cambios: CambioTarea
): Tarea[] {
  return tareas.map((t) => (t.id === id ? { ...t, ...cambios } : t));
}

No mutamos la tarea: creamos una copia con ...cambios aplicados solo en la que coincida.

DELETE: eliminar

export function eliminarTarea(tareas: Tarea[], id: string): Tarea[] {
  return tareas.filter((t) => t.id !== id);
}

Integrando con el hook (estado global)

import { useState } from "react";
import type { Tarea, EstadoTarea } from "../domain/modelo";
import type { NuevaTarea, CambioTarea } from "../domain/operaciones";
import { crearTarea, actualizarTarea, eliminarTarea } from "../domain/operaciones";
import { leerTareas, guardarTareas } from "../data/tareasStore";

export function useTareas() {
  const [tareas, setTareas] = useState<Tarea[]>(leerTareas);

  function crear(nueva: NuevaTarea): void {
    const siguiente = [...tareas, crearTarea(nueva)];
    setTareas(siguiente);
    guardarTareas(siguiente);
  }

  function actualizar(id: string, cambios: CambioTarea): void {
    const siguiente = actualizarTarea(tareas, id, cambios);
    setTareas(siguiente);
    guardarTareas(siguiente);
  }

  function eliminar(id: string): void {
    const siguiente = eliminarTarea(tareas, id);
    setTareas(siguiente);
    guardarTareas(siguiente);
  }

  return { tareas, crear, actualizar, eliminar };
}

Todas las operaciones del dominio son funciones puras (reciben Tarea[] y devuelven Tarea[]), y el hook solo las orquesta y sincroniza el almacen.

3 · Ejemplo minimo

crud-minimo.ts
interface Tarea { id: string; titulo: string; done: boolean; }

// CREATE
function crear(tareas: Tarea[], titulo: string): Tarea[] {
  return [...tareas, { id: crypto.randomUUID(), titulo, done: false }];
}

// READ
function pendientes(tareas: Tarea[]): Tarea[] {
  return tareas.filter((t) => !t.done);
}

// UPDATE
function toggle(tareas: Tarea[], id: string): Tarea[] {
  return tareas.map((t) => (t.id === id ? { ...t, done: !t.done } : t));
}

// DELETE
function borrar(tareas: Tarea[], id: string): Tarea[] {
  return tareas.filter((t) => t.id !== id);
}

Linea a linea:

  • Las cuatro funciones reciben y devuelven Tarea[]: puras y tipadas.
  • spread para crear/actualizar: nunca muta.
  • filter para lecturas y borrado: devuelve copia.
  • El type Tarea gobierna todas las firmas.

4 · Ejemplo real

La UI completa del CRUD: formulario tipado, lista con estados y borrado con confirmacion.

src/components/TareaForm.tsx
import { useState } from "react";
import type { NuevaTarea } from "../domain/operaciones";

interface TareaFormProps {
  onCrear: (nueva: NuevaTarea) => void;
}

export function TareaForm({ onCrear }: TareaFormProps) {
  const [titulo, setTitulo] = useState("");
  const [descripcion, setDescripcion] = useState("");

  return (
    <form
      onSubmit={(e) => {
        e.preventDefault();
        if (titulo.trim() === "") return; // validacion minima
        onCrear({ titulo: titulo.trim(), descripcion: descripcion.trim() });
        setTitulo("");
        setDescripcion("");
      }}
    >
      <input value={titulo} onChange={(e) => setTitulo(e.target.value)} placeholder="Titulo" />
      <input value={descripcion} onChange={(e) => setDescripcion(e.target.value)} placeholder="Descripcion" />
      <button type="submit">Crear</button>
    </form>
  );
}
src/components/TareaItem.tsx
import type { Tarea, EstadoTarea } from "../domain/modelo";

interface TareaItemProps {
  tarea: Tarea;
  onCambiarEstado: (id: string, estado: EstadoTarea) => void;
  onEliminar: (id: string) => void;
}

export function TareaItem({ tarea, onCambiarEstado, onEliminar }: TareaItemProps) {
  return (
    <li className={tarea.estado}>
      <strong>{tarea.titulo}</strong>
      {tarea.descripcion ? <p>{tarea.descripcion}</p> : null}
      <select
        value={tarea.estado}
        onChange={(e) => onCambiarEstado(tarea.id, e.target.value as EstadoTarea)}
      >
        <option value="pendiente">Pendiente</option>
        <option value="en-progreso">En progreso</option>
        <option value="completada">Completada</option>
      </select>
      <button
        onClick={() => {
          if (confirm(`Eliminar "${tarea.titulo}"?`)) onEliminar(tarea.id);
        }}
      >
        Borrar
      </button>
    </li>
  );
}
src/App.tsx (resumen)
import { useTareas } from "./hooks/useTareas";
import { TareaForm } from "./components/TareaForm";
import { TareaItem } from "./components/TareaItem";

function App() {
  const { tareas, crear, actualizar, eliminar } = useTareas();

  return (
    <main>
      <h1>Mis tareas</h1>
      <TareaForm onCrear={crear} />
      <ul>
        {tareas.map((t) => (
          <TareaItem
            key={t.id}
            tarea={t}
            onCambiarEstado={actualizar}
            onEliminar={eliminar}
          />
        ))}
      </ul>
    </main>
  );
}

Decisiones:

  • El formulario solo emite NuevaTarea: no puede enviar ids ni estados inventados.
  • El select castea e.target.value as EstadoTarea en el borde del evento.
  • El borrado pide confirmacion (UX segura) y luego la funcion pura lo aplica.
  • Cada mutacion pasa por el hook que sincroniza localStorage: los datos nunca se desincronizan.

5 · Buenas practicas

  • Separar DTOs de entrada (NuevaTarea, CambioTarea) del modelo completo.
  • Funciones CRUD puras en el dominio; el hook solo orquesta y persiste.
  • Inmutabilidad en toda mutacion (spread, map, filter).
  • Validacion minima en el borde (formulario / evento) antes de crear.
  • Confirmar borrados; tipar las confirmaciones con tipos explicitos.

Que evitar

  • Mutar el estado (splice/push) y luego romper el render.
  • Leer localStorage en cada render; usa el hook que centraliza.
  • Permitir NuevaTarea con campos obligatorios vacios.
  • Desincronizar almacen y estado (guardar SIEMPRE tras mutar).

6 · Errores habituales

Mal — mutar el array del estado 
tareas.push(tarea); // ✖ muta el array; React no lo detecta
setTareas(tareas);
Bien — array nuevo 
const siguiente = [...tareas, tarea]; // ✅ nuevo array
setTareas(siguiente);
Mal — estado suelto como string 
function actualizar(t: Tarea, estado: string) {
  // ✖ puede pasar "cualquier" estado invalido
}
Bien — union del dominio 
function actualizar(t: Tarea, estado: EstadoTarea) {
  // ✅ solo pendiente | en-progreso | completada
}
Mal — olvidar persistir 
function crear(nueva: NuevaTarea) {
  setTareas((prev) => [...prev, crearTarea(nueva)]); // si no guardas...
  // ...al recargar la pagina, las tareas desaparecen ✖
}
Bien — persistir cada mutacion 
function crear(nueva: NuevaTarea) {
  const siguientes = [...tareas, crearTarea(nueva)];
  setTareas(siguientes);
  guardarTareas(siguientes); // ✅
}

7 · Ejercicio guiado

Vamos a añadir edicion de titulo a una tarea existente.

  1. Anade un input en Linea en TareaItem que permita editar titulo.
  2. Llama a onCambiarEstado con un nuevo CambioTarea parcial (solo titulo).
  3. Asegurate de que la propagacion a actualizar del hook sea correcta.
  4. Comprueba que el texto cambia y que el almacen se actualiza.

Solucion paso a paso:

src/components/TareaItem.tsx (con edicion)
// Nuevo prop:
interface TareaItemProps {
  tarea: Tarea;
  onGuardarCambios: (id: string, cambios: CambioTarea) => void;
  // onEliminar: ...  (igual que antes)
}

// Estado local de edicion:
const [editando, setEditando] = useState(false);
const [tituloTemp, setTituloTemp] = useState(tarea.titulo);

function guardar() {
  if (tituloTemp.trim() !== "") {
    onGuardarCambios(tarea.id, { titulo: tituloTemp.trim() });
  }
  setEditando(false);
}

// Render:
{editando ? (
  <input value={tituloTemp} onChange={(e) => setTituloTemp(e.target.value)} />
) : (
  <strong onDoubleClick={() => setEditando(true)}>{tarea.titulo}</strong>
)}
<button onClick={guardar} disabled={!editando}>Guardar</button>

9 · Resumen

  • CRUD = Create (crear), Read (leer), Update (actualizar), Delete (borrar).
  • DTOs de entrada vs modelo completo; funciones puras de dominio.
  • Inmutabilidad en todas las mutaciones.
  • El hook orquesta y persiste; la UI solo emite acciones tipadas.
  • Validacion en el borde (formulario/evento) y confirmacion en borrado.

10 · Preguntas frecuentes

¿Por que usar CRUD con funciones puras en vez de metodos?

Porque son deterministicas y testables (la leccion 03 las testea). Los metodos de clase mutarian o necesitarian mas contexto. La funcion pura recibe un Tarea[] y devuelve otro: nada mas facil de verificar.

¿Debo usar el id como string o como number?

String con crypto.randomUUID() es lo estandar: unico, no secuencial y sin colisiones entre dispositivos. Los numeros autoincrementales complican el sync con APIs.

¿Que pasa si tengo duplicados en el estado?

El CRUD no los evita por si solo. Puedes des-duplicar por id al leer (un Map) y validar en crear que el titulo no exista si la regla lo exige.

¿El pedido save en cada mutacion es ineficiente?

Para una demo, no. Si tuvieras miles de mutaciones por segundo, usarias batching o persistencia debounce. La claridad supera la micro-optimizacion aqui.

¿Como hago CRUD contra una API real?

Reemplaza guardarTareas/leerTareas por fetch con POST/GET/PUT/DELETE manteniendo las mismas firmas. La UI no se entera del cambio.

¿Necesito optimistic UI para el borrado?

Es opcional para esta escala. Lo correcto aqui: confirmar, mutar, persistir de forma sincrona y sencilla. Para APIs remotas, la leccion 04 comenta el patron optimistic vs pessimistic.
