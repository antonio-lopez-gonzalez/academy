Record, Exclude, Extract

Modulo 6 · Utility Types 🕐 30 minutos

1 · Introduccion

Tres utilidades que resuelven dos problemas frecuentes: mapear un conjunto cerrado de claves a un tipo (Record) y filtrar miembros de unions (Exclude y Extract). En JavaScript hariamos "un objeto con estas claves" o "filtrar un array"; aqui lo hacemos a nivel de tipos.

Cuando se utilizan
  • Record<K, V>: locales/i18n, estados de maquinas, opciones de configuracion, mapas de datos por clave.
  • Exclude<T, U>: quitar casos de una union (eventos que no quieres).
  • Extract<T, U>: quedarse solo con los casos que si quieres.

2 · Teoria

Record<K, V>: el mapa tipado

Record construye un objeto con las claves del union K, donde todas las claves apuntan al tipo V: 

type Estado = "pendiente" | "enviado" | "expirado";

// Un objeto donde CADA estado mape a una descripcion string.
type EstadoColores = Record<Estado, string>;

const colores: EstadoColores = {
  pendiente: "#f5a623",
  enviado: "#2ecc71",
  expirado: "#e74c3c",
};
// ✅ si falta una clave de Estado, falla en compilacion
Por que Record sobre una index signature

La firma { [k: string]: string } acepta cualquier string, incluso claves que no existen. Record<Estado, string> restringe a las claves exactas del union: te obliga a definirlas todas y, si la union cambia, te avisa de las que faltan o sobran. Perfeccion para dominios con conjuntos cerrados.

Record con todos los matices

// Valores de tipo distinto por clave (con readonly):
type Config = Record<"host" | "port", string | number>;

// Se usa mucho para mapear "una clave ⇒ dato":
type Columna = "nombre" | "edad" | "email";
type Tabla = Record<Columna, string>;

Exclude<T, U>: quitar miembros de una union

Exclude<T, U> devuelve los miembros de T que NO son asignables a U. Internamente es un conditional distributivo: 

type Evento = "crear" | "editar" | "borrar" | "consultar";

// Quita "borrar" de la union:
type SinBorrar = Exclude<Evento, "borrar">;
// "crear" | "editar" | "consultar"

// Quita varios a la vez:
type SoloLectura = Exclude<Evento, "crear" | "editar" | "borrar">;
// "consultar"

// Implementacion interna:
// type Exclude<T, U> = T extends U ? never : T;

Extract<T, U>: quedarse con la interseccion

type Evento = "crear" | "editar" | "borrar" | "consultar";

// Conserva solo los miembros de T que SI son asignables a U:
type Mutables = Extract<Evento, "crear" | "editar" | "borrar">;
// "crear" | "editar" | "borrar"

// Internamente:
// type Extract<T, U> = T extends U ? T : never;
Union T = A | B | C | D │ Exclude<T, C> → A | B | D (quita C) Extract<T, B | C> → B | C (conserva B y C) Son operaciones inversas complementarias.

Combinaciones con keyof y Record

interface Usuario { id: number; nombre: string; email?: string; }

// Todas las claves menos las opcionales, a string:
type ClavesSinOpcional = Exclude<keyof Usuario, keyof Required<Usuario>>;
// "email" (la unica opcional)

// Mapea SOLO las claves numericas a null:
type SoloNumeros = {
  [K in keyof Usuario as Usuario[K] extends number ? K : never]: null;
};
// { id: null }

3 · Ejemplo minimo

record-minimo.ts
// Mapa cerrado: cada mes a su numero de dias.
type Mes = Record<"ene" | "feb" | "mar", number>;

const dias: Mes = { ene: 31, feb: 28, mar: 31 }; // ✅

// Quitamos "feb" de la union de meses:
type Trimestre = Exclude<"ene" | "feb" | "mar" | "abr" | "may" | "jun", "feb">;
// "ene" | "mar" | "abr" | "may" | "jun"

// Extraemos solo los meses de verano:
type Verano = Extract<"jun" | "jul" | "ago" | "sep", "jul" | "ago">;
// "jul" | "ago"

4 · Ejemplo real

Una aplicacion con estados de pedido y etiquetas traducibles, usando las tres utilidades:

estados.ts
// Estados posibles de un pedido.
type EstadoPedido = "creado" | "pagado" | "enviado" | "entregado" | "cancelado";

// Etiquetas por estado: un Record con las claves del estado.
type Etiquetas = Record<EstadoPedido, string>;

const etiquetas: Etiquetas = {
  creado: "Pendiente",
  pagado: "Pagado",
  enviado: "Enviado",
  entregado: "Entregado",
  cancelado: "Cancelado",
};

// Estado final (ya no puede cambiar):
type EstadoFinal = Extract<EstadoPedido, "entregado" | "cancelado">;
// "entregado" | "cancelado"

// Definimos un "estado no cancelable":
type EstadoActivo = Exclude<EstadoPedido, "cancelado">;
// "creado" | "pagado" | "enviado" | "entregado"

function cambiarEstado(actual: EstadoActivo, nuevo: EstadoFinal): void {
  console.log(`De ${etiquetas[actual]} a ${etiquetas[nuevo]}`);
}

cambiarEstado("enviado", "entregado"); // ✅
// cambiarEstado("cancelado", "pagado"); // ✖ cancelado no es "Activo"

Decisiones:

  • Record<EstadoPedido, string> obliga a definir las 5 etiquetas; si anades un estado, el compilador exige su etiqueta.
  • Extract y Exclude derivan subconjuntos de estados sin duplicar las cadenas.
  • Las firmas de funciones usan estos subconjuntos, por lo que el flujo de estados queda validado en compilacion.

5 · Buenas practicas

  • Usa Record como "mapa tipado", no una index signature abierta.
  • Combina keyof + Extract/Exclude para derivar subconjuntos de claves.
  • Define los tipos base como unions de literales y deriva de ellos con estas utilidades.
  • Para condiciones sobre values, extrae con mapped type + as (leccion 3): "solo las claves cuyo valor es number".

Que evitar

  • Escribir a mano un objeto de "colores por estado" con strings sueltos (te dejas uno).
  • Usar string como clave de Record cuando conoces el union (muy abierto).
  • Confundir Exclude (elimina) con Extract (conserva): piensa en "excluir" vs "extraer".
  • Record anidado cuando un objeto plano con tipo basta.

6 · Errores habituales

Mal — confundir Exclude y Extract 
type U = "a" | "b" | "c";
type X = Exclude<U, "a">;   // "b" | "c"   (elimina a)
type Y = Extract<U, "a">;   // "a"          (conserva a)
Bien — recuerda la direccion 
// Exclude = "todo menos"
// Extract = "solo lo compartido"
type Resultado = Extract<U, "a" | "b">; // "a" | "b"
Mal — Record con valor distinto por clave 
// Quieres "valor por union" pero distintos tipos:
type M = Record<"a" | "b", string | number>; // ambos aceptan cualquiera
// Pierdes que "a" sea solo string
Bien — objeto tipado mano a mano para valores heterogeneos 
type M = { a: string; b: number }; // cada clave con su tipo exacto
Mal — index signature sin restriccion 
const colores: { [k: string]: string } = {};
colores["cualquiercosa"] = "x"; // acepta claves no definidas
Bien — Record con union cerrada 
type Estado = "ok" | "error";
const colores2: Record<Estado, string> = { ok: "#0f0", error: "#f00" };

7 · Ejercicio guiado

Vamos a construir las etiquetas de una notificacion con Record y luego a filtrar por tipo.

  1. Define type Tipo = "info" | "success" | "warning" | "error".
  2. Define type Etiquetas = Record<Tipo, string> y rellena los 4 valores.
  3. Deriva type Cierre = Extract<Tipo, "success" | "error">.
  4. Deriva type SinWarning = Exclude<Tipo, "warning">.

Solucion paso a paso:

ejercicio-record.ts
type Tipo = "info" | "success" | "warning" | "error";

type Etiquetas = Record<Tipo, string>;

const etiquetas: Etiquetas = {
  info: "Informacion",
  success: "Correcto",
  warning: "Atencion",
  error: "Error",
};

type Cierre = Extract<Tipo, "success" | "error">; // "success" | "error"
type SinWarning = Exclude<Tipo, "warning">;       // "info" | "success" | "error"

function mostrar(t: Tipo): void {
  console.log(etiquetas[t]);
}
mostrar("info"); // ✅ todos los tipos tienen etiqueta

8 · Reto

Reto

Escribe un tipo SoloClavesString<T> que, dado un objeto con valores de distintos tipos, devuelva keyof T restringido a las claves cuyo valor es string (pista: mapped type con as y una condicion). Luego define un Record con esas claves y el tipo string. No mires la solucion.

9 · Resumen

  • Record<K, V>: objeto con claves K y valores V, obligando a definirlas todas.
  • Exclude<T, U>: union T sin los miembros asignables a U.
  • Extract<T, U>: union T conservando solo los miembros asignables a U.
  • Combina con keyof, mapped types y unions de literales para derivar tipos sin duplicar.

10 · Preguntas frecuentes

¿Record requiere que TODAS las claves del union esten presentes?

Si. Record<K, V> define un objeto con exactamente esas claves obligatorias. Es una garantia fuerte, ideal para configuraciones cerradas.

¿Puedo poner 0 claves en Record?

Si usas Record<never, V> obtienes un objeto vacio (de hecho {}). Rara vez util, pero existe.

¿Exclude funciona con tipos que no son unions?

Si. Si T es un solo tipo, devuelve T o never segun la asignabilidad. Pero su uso tipico es sobre unions de literales y de claves.

¿Como quito un campo opcional de keyof?

Exclude<keyof T, keyof Required<T>> da las claves opcionales (las que Required vuelve obligatorias no). Es un patron util combinando utilidades.

¿Puedo usar Record anidado para configuraciones en arbol?

Si: Record<Clave, Record<SubClave,V>> o mejor un tipo de objeto tipado para arboles reales. Record brilla cuando el conjunto de claves es plano y cerrado.

¿Que es mejor, Record o un type de objeto normal?

Para un shape conocido con claves fijas, un objeto tipado normal da tipos mas precisos por clave. Record es superior cuando quieres garantizar un conjunta de claves, especialmente derivadas de una union.
