ReturnType, Parameters, Awaited

Modulo 6 · Utility Types 🕐 30 minutos

1 · Introduccion

Estas utilidades trabajan sobre funciones: extraen el tipo de retorno (ReturnType), el tipo de los argumentos (Parameters) y "desempaquetan" promesas (Awaited). Son utiles en librerias, eventos, APIs y cuando quieres reutilizar el tipo de resultado de una funcion sin escribirlo de nuevo.

Cuando se utilizan
  • ReturnType: tipar el resultado de un callback, una API, un event handler.
  • Parameters: derivar un DTO desde los argumentos de una funcion de creacion.
  • Awaited: "esperar" promesas para conocer el tipo final (async, fetch).

2 · Teoria

La analogia: leer la etiqueta del embalaje

Una funcion es como un paquete que dice en su caja: "acepta estos argumentos, devuelve esto". ReturnType lee "lo que devuelve"; Parameters lee "lo que recibe"; Awaited abre la caja hasta el contenido final, incluso si hay una Promesa dentro.

funcion: (id: number, nombre: string) => Promise<Usuario> │ │ │ Parameters │ ReturnType ▼ ▼ [number, string] Promise<Usuario> │ Awaited ▼ Usuario

ReturnType<F>

function construirEtiqueta(color: string, texto: string): string {
  return `${color}:${texto}`;
}

// El tipo de retorno de esa funcion:
type Resultado = ReturnType<typeof construirEtiqueta>;
// string

// Implementacion interna:
// F extends (...args: any[]) => infer R ? R : any

Importante: necesita typeof de la funcion (o el tipo de la funcion directamente).

Parameters<F>

function guardar(id: number, etiqueta: string): void {
  /* ... */
}

// Tupla con los tipos de los argumentos:
type Args = Parameters<typeof guardar>;
// [id: number, etiqueta: string]

// Podemos convertir la tupla en un Objeto:
type Opciones = Parameters<typeof guardar>[0]; // number

Awaited<T>

// Desempaqueta promesas, con soporte de anidamiento y PromiseLike.
async function buscarUsuario(): Promise<{ id: number }> {
  return { id: 1 };
}

type Respuesta = ReturnType<typeof buscarUsuario>;      // Promise<{id:number}>
type Contenido = Awaited<ReturnType<typeof buscarUsuario>>; // { id: number }

// Awaited tambien atraviesa varias capas:
type Profundo = Awaited<Promise<Promise<number>>>; // number

// Awaited con typeof del valor async:
async function fetchData(): Promise<number[]> { return [1,2]; }
type Datos = Awaited<ReturnType<typeof fetchData>>; // number[]
Por que Awaited en vez de quitar Promise a mano

Awaited es recursiva y conoce PromiseLike, luego trabaja con librerias que no son la Promise nativa. Ademas es semantico: "lo que se obtiene cuando esperas". Forzar T[0] o anidar genericos a mano es fragil. La builtin esta desde TS 4.5.

Compuestos y variaciones

// Parameter tokens también con this:
function saludar(this: { nombre: string }, msg: string): void {}
type ThisTipo = ThisParameterType<typeof saludar>; // { nombre: string }
type ParamsSinThis = OmitThisParameter<Parameters<typeof saludar>>;
// [msg: string]

// En funciones sobrecargadas, se usa la ultima firma:
function dual(x: string): string;
function dual(x: number): number;
function dual(x: unknown): unknown { return x; }
type Ret = ReturnType<typeof dual>; // number (la ultima firma)

3 · Ejemplo minimo

funciones-minimo.ts
function suma(a: number, b: number): number {
  return a + b;
}

type ArgsSuma = Parameters<typeof suma>;      // [a: number, b: number]
type RetSuma = ReturnType<typeof suma>;        // number

async function obtener(): Promise<string> {
  return "ok";
}
type Esperado = Awaited<ReturnType<typeof obtener>>; // string

Linea a linea:

  • Parameters<typeof suma> extrae la tupla de argumentos.
  • ReturnType<typeof suma> extrae el tipo del retorno.
  • Awaited<ReturnType<typeof obtener>> quita la capa de Promise y da el tipo real.
  • Siempre con typeof de la funcion, no de la llamada.

4 · Ejemplo real

Un repositorio de datos + un selector tipado que deriva la forma de las funciones de la API:

api-repo.ts
// Nuestro "contrato" de la API (normalmente en otra capa).
interface API {
  getUsuario(id: number): Promise<{ id: number; nombre: string }>;
  listUsers(): Promise<Array<{ id: number }>>;
}

// Extraemos el tipo de datos a partir de los metodos:
type MetodoAPI = keyof API; // "getUsuario" | "listUsers"

// ReturnType de cada metodo -> la Promise
type PromiseDe<K extends MetodoAPI> = ReturnType<API[K]>;
// Promise<{id,nombre}> | Promise<{id}[]>

// Awaited del mismo -> el objeto real:
type DatosDe<K extends MetodoAPI> = Awaited<ReturnType<API[K]>>;

// Podemos tipar el estado de una cache:
type Cache = Partial<Record<MetodoAPI, Awaited<ReturnType<API[MetodoAPI]>>>>;
// { getUsuario?: {id,nombre}; listUsers?: {id}[] }

const cache: Cache = {
  getUsuario: { id: 1, nombre: "Ana" },
};

// Si la API cambia su retorno, la cache se actualiza sola.

Decisiones:

  • ReturnType<API[K]> saca la Promise de cada metodo; Awaited la abre.
  • Partial<Record<MetodoAPI, ...>> define una cache con cada endpoint disponible pero vacia hasta que se llene.
  • Todo deriva del tipo API: un cambio en el contrato toca la cache en compilacion.

5 · Buenas practicas

  • Usa typeof para funciones/con valores al extraer ReturnType/Parameters.
  • Combina ReturnType + Awaited para async: el orden importa (primero ReturnType, después Awaited).
  • Deriva tipos de la "fuente" (la firma de la API) y no dupliques manualmente el shape.
  • Para sobrecargas, documenta que se usa la ultima firma real.
  • Usa Parameters para reutilizar los argumentos de funciones de creacion como DTOs.

Que evitar

  • Escribir Promise<...> a mano cuando conoces la funcion base.
  • Llamar ReturnType a una llamada (con parentesis) en vez de a la funcion.
  • Anidar Awaited<Awaited<...>> sin necesidad: Awaited ya recorre varias promesas.
  • Depender de any para estos resultados: pierdes la derivacion.

6 · Errores habituales

Mal — olvidar typeof 
function f(): number { return 1; }
// type R = ReturnType<f>;       // ✖ f aqui es un valor, no un tipo
type R = ReturnType<typeof f>;    // ✅
Bien — typeof de la funcion 
function f(): number { return 1; }
type R = ReturnType<typeof f>;   // number
Mal — Awaited en el orden equivocado 
async function x(): Promise<number> { return 5; }
type A = Awaited<ReturnType<typeof x>>; // ✅ number
// (Si pusieras Awaited despues de ReturnType sin envolver:
// type B = ReturnType<typeof x>; // Promise<number> — aun es Promise)
Bien — aplica Awaited fuera 
type Resultado2 = Awaited<ReturnType<typeof x>>; // number ✅
Mal — Parameters sobre una funcion con this/named optional 
// La tupla DEBE coincidir en orden:
function duplica(a: number, b?: string): void {}
type P = Parameters<typeof duplica>; // [a: number, b?: string]
// No inviertas el orden al consumir
Bien — consume la tupla tal cual 
function aplicar<F extends (...args: any[]) => unknown>(
  fn: F, ...args: Parameters<F>
): ReturnType<F> {
  return fn(...args) as ReturnType<F>;
}

7 · Ejercicio guiado

Vamos a construir un wrapper que ejecute una funcion row sin perder el tipado de sus argumentos y retorno.

  1. Define function conLog<A extends unknown[], R>(fn: (...args: A) => R): (...args: A) => R.
  2. Implementa loggear y llamar a fn.
  3. Prueba con const f = (a: number, b: string) => a + b.length.
  4. Comprueba que f(1, "x") es number, y que f("1", "x") da error.

Solucion paso a paso:

ejercicio-funciones.ts
function conLog<A extends unknown[], R>(
  fn: (...args: A) => R
): (...args: A) => R {
  return (...args: A): R => {
    console.log("llamada con", args.length, "argumentos");
    return fn(...args);
  };
}

const f = (a: number, b: string) => a + b.length;
const g = conLog(f);

const res: number = g(1, "x"); // ✅ 2 (1 + 1)
// g("1", "x"); // ✖ el primer argumento debe ser number

8 · Reto

Reto

Escribe un tipo UltimoArg<F extends (...args: any[]) => unknown> que devuelva el tipo del ULTIMO argumento de F (pista: usa Parameters<F> y luego indexa con la longitud, o mejor con [...rest, last] en un conditional + infer). Aplica el mismo patron para PrimerArg. No mires la solucion.

9 · Resumen

  • ReturnType<F>: tipo de retorno de una funcion.
  • Parameters<F>: tupla de los argumentos.
  • Awaited<T>: desempaqueta promesas (recursivo, con PromiseLike).
  • Usa typeof para pasar funciones (no llamadas) a estas utilidades.
  • Compone: Awaited<ReturnType<typeof fn>> para async.

10 · Preguntas frecuentes

¿Por que ReturnType no acepta una funcion directamente con parentesis?

Porque ReturnType espera un tipo. Pasar typeof fn da el tipo de la funcion; pasar fn() seria el valor resultante de llamarla, que es un valor, no un tipo.

¿Awaited funciona con async/await o solo con Promise?

Con Promise<T> y con PromiseLike<T>. async devuelve Promise, asi que se integra con los dos: Awaited sobre Promise<T> da T.

¿Puedo extraer el tipo de una propiedad con ReturnType?

Si: ReturnType<typeof obj.metodo>. Tambien sobre clases: ReturnType<InstanceType<typeof C>["m"]>.

¿Parameters devuelve el tipo del this?

No; Parameters excluye this. Para el this usa ThisParameterType. Si quieres incluir, dependera de la firma.

¿Que ocurre con parametros opcionales en Parameters?

Se conservan como opcionales en la tupla resultante ([...es: string[]] con rest inclusive). Esto respeta la verdad de la firma.

¿Hay riesgo de break si la API cambia?

No; al contrario. Como derivas de la fuente, si la funcion cambia su retorno o sus argumentos, ReturnType/Parameters lo reflejan y los usos se actualizan, forzando errores donde haga falta.
