infer en funciones: ReturnType y Parameters a mano

Modulo 10 · Tipos avanzados 🕐 30 minutos

1 · Introduccion

En el Modulo 6 usaste ReturnType, Parameters y Awaited. Esta leccion abre la caja negra: vamos a rellenar las utilidades a mano con conditional types y infer. Cuando entiendes que ReturnType es un conditional type con un pattern de funcion, dejas de depender de la magia y puedes construir tus propias variantes.

El mismo mecanismo te da tres habilidades nuevas: inferir el retorno (infer R), inferir la tupla de parametros completa (infer P), y desnudar promesas de forma recursiva (Awaited). De paso veremos que significa la distributividad de los conditional types sobre las unions.

2 · Teoria

La analogia: un formulario con campos vacios

Un conditional type con infer funciona como un formulario: escribes la estructura de una funcion con huecos ((...args) => retorno) y el compilador rellena los huecos con lo que encuentre en el tipo real. Donde pones infer R, TypeScript deduce el retorno; donde pones infer P, deduce la lista de parametros completa.

ReturnType a mano

returntype-mano.ts
// ReturnType a mano: infiere el tipo de retorno de una funcion.
type MyReturnType<T extends (...args: any) => any> =
  T extends (...args: any) => infer R ? R : never;

type Retorno = MyReturnType<(n: number) => string>; // string
type Numeros = MyReturnType<() => number[]>;       // number[]
  • La restriccion T extends (...args: any) => any filtra: solo functions types llegan al conditional.
  • Dentro, el pattern (...args: any) => infer R deja un hueco en el retorno; si la firma coincide, R es el retorno concreto.
  • La rama falsa devuelve never: nunca deberia dispararse si la restriccion es correcta.
Diferencia con el built-in

La version real de la libreria usa any en la rama falsa por compatibilidad historica; nosotros usamos never, que es mas honesto: si algo no es una funcion, el tipo no deberia "inventar" un retorno.

Parameters a mano: la tupla de parametros

parameters-mano.ts
// Parameters a mano: devuelve la tupla completa de parametros.
type MyParameters<T extends (...args: any) => any> =
  T extends (...args: infer P) => any ? P : never;

type Args = MyParameters<(id: number, nombre: string) => void>;
// → [id: number, nombre: string]

type DelPrimero = Args[0]; // number — la tupla se indexa como un array

Aqui el hueco esta en los parametros: infer P no captura un tipo cualquiera, sino la tupla completa. Por eso Parameters devuelve una tupla y no un solo tipo: la lista de argumentos se modela internamente como tupla, con toda su informacion (nombres, opcionales, rest).

infer en parametros concretos: primero y ultimo

first-last.ts
// Primer parametro: fija el primer hueco y deja el resto en un rest tuple.
type FirstParam<T extends (...args: any) => any> =
  T extends (first: infer F, ...rest: any[]) => any ? F : never;

type P = FirstParam<(id: number, nombre: string) => void>; // number

// Ultimo parametro: infiere la tupla y busca su final.
type LastParam<T extends (...args: any) => any> =
  T extends (...args: infer P) => any
    ? P extends [...any[], infer U] ? U : never
    : never;

type L = LastParam<(a: string, b: number, c: boolean) => void>; // boolean
type SinArgs = LastParam<() => void>;                           // never

El pattern (first: infer F, ...rest: any[]) => any es un rest tuple dentro de la firma: exige al menos un parametro y mete el resto en rest. Para el ultimo, invertimos el truco: inferimos toda la tupla y usamos otro pattern de tupla ([...any[], infer U]) para capturar su final.

Awaited a mano: recursion sobre promesas

awaited-mano.ts
// Awaited a mano: quita niveles de Promise de forma recursiva.
type MyAwaited<T> = T extends Promise<infer U> ? MyAwaited<U> : T;

type Resultado = MyAwaited<Promise<Promise<string>>>; // string
type Plano = MyAwaited<number>;                          // number — no cambia

Cada llamada consume un Promise: si el valor es una promesa, se extrae su contenido y se vuelve a preguntar (por si hay otra promesa dentro). Cuando ya no hay promesa, se devuelve el valor tal cual. Sin la recursion, solo quitarian un nivel y Promise<string> se quedaria a medias.

Distributividad: la union se reparte

distributividad.ts
type MyReturnType<T extends (...args: any) => any> =
  T extends (...args: any) => infer R ? R : never;

// Un conditional con el parametro "desnudo" (T suelto) reparte por cada union.
type Fin = (() => string) | ((n: number) => boolean);
type Res = MyReturnType<Fin>; // string | boolean

// Si "envuelves" T, la distribucion se apaga: se evalua la union entera.
type Envuelto<T> = [T] extends [(...args: any) => any] ? "funcion" : "otro";
type E = Envuelto<(() => void) | (() => number)>; // "funcion"
Por que importa la distributividad

Cuando escribes T extends X ? A : B, TypeScript aplica la condicion a cada miembro de la union por separado y despues une los resultados. Es la razon por la que MyReturnType sobre una union de funciones devuelve la union de los retornos. Envolver el parametro ([T]) desactiva ese comportamiento, util cuando quieres juzgar la union como un bloque.

3 · Ejemplo minimo

infer-mano.ts
type MyReturnType<T extends (...args: any) => any> =
  T extends (...args: any) => infer R ? R : never;

type MyParameters<T extends (...args: any) => any> =
  T extends (...args: infer P) => any ? P : never;

const combinar = (a: string, b: number) => `${a}#${b}`;

type R = MyReturnType<typeof combinar>; // string
type P = MyParameters<typeof combinar>; // [a: string, b: number]
type DelPrimero = P[0];                 // string

Linea a linea:

  • Dos conditional types identicos en forma: cambia solo donde pones infer (retorno vs parametros).
  • typeof combinar convierte la funcion en su function type, que es lo que los tipos consumen.
  • P[0] usa la tupla como un array: el primer elemento es el tipo del primer parametro.

4 · Ejemplo real

Un bus de eventos que deriva el tipo del payload a partir del handler suscrito, y un cliente de API que calcula el tipo de la respuesta con ReturnType + Awaited a mano.

eventos-y-api.ts
type MyParameters<T extends (...args: any) => any> =
  T extends (...args: infer P) => any ? P : never;

type MyReturnType<T extends (...args: any) => any> =
  T extends (...args: any) => infer R ? R : never;

type MyAwaited<T> = T extends Promise<infer U> ? MyAwaited<U> : T;

// 1) El bus conoce el tipo del "primer argumento" de cada handler.
type Handler = (payload: unknown) => void;

function suscribir(nombre: string, handler: Handler): void {
  // registro del handler en el bus (omitido)
}

const onNuevoUsuario = (usuario: { id: number; email: string }) => {
  console.log(`Nuevo usuario ${usuario.id}`);
};

// MyParameters[0] extrae el tipo del payload del handler concreto.
type PayloadUsuario = MyParameters<typeof onNuevoUsuario>[0];
// → { id: number; email: string }

// 2) Cliente de API: el tipo de la respuesta se deduce de la funcion fetch.
async function obtenerPerfil(id: number): Promise<{ nombre: string }> {
  const res = await fetch(`/api/perfil/${id}`);
  return res.json();
}

type Perfil = MyAwaited<MyReturnType<typeof obtenerPerfil>>;
// → { nombre: string }

declare function pintarPerfil(perfil: Perfil): void;

async function principal() {
  const perfil = await obtenerPerfil(1);
  pintarPerfil(perfil); // ✅ el tipo "viajo" por ReturnType + Awaited a mano
}

Decisiones:

  • El bus no tiene que conocer los tipos de cada payload: los deriva del propio handler con MyParameters. Si el handler cambia, el payload derivado cambia con el, sin tocar el bus.
  • MyAwaited<MyReturnType<...>> compone dos utilidades: primero el retorno de la promesa y despues se desnuda. Publicar el Perfil solo requiere una linea de tipo.
  • declare function declara dependencias externas sin implementarlas: el foco queda en los tipos.

5 · Buenas practicas

  • En produccion usa los utility types nativos; replica a mano solo para aprender o para variantes propias (FirstParam, LastParam, PayloadDeEvento...).
  • Manten el parametro del conditional "desnudo" (T extends ...) si quieres distributividad; envuelvelo ([T]) cuando quieras evaluar la union como bloque.
  • Usa never en la rama falsa en tus versiones: los fallos se ven como errores, no como any silencioso.
  • Para varios valores, infiere tuplas: (...args: infer P) o P extends [...any[], infer U].
  • Restringe el generico a function types (T extends (...args: any) => any) para recibir errores tempranos al usar el tipo.
  • En recursion (Awaited), asegura que cada nivel consume una promesa; si no, la recursion no termina.

Que evitar

  • Escribir infer fuera de un conditional type: es un error de sintaxis.
  • Devolver any en la rama falsa "para que compile": esconde el error del usuario del tipo.
  • Esperar que un conditional envuelto distribuya: [T] apaga la distribucion.
  • Pensar que Awaited quita un solo nivel: es recursion hasta el valor final.

6 · Errores habituales

Mal — infer fuera de un conditional 
// El compilador lo rechaza: infer solo vive dentro de un conditional type.
type Mal = infer R; // ✖ "'infer' declarations are only permitted..."
Bien — infer dentro del pattern 
type Bien<T> = T extends (...args: any) => infer R ? R : never;
Mal — rama falsa con any 
type MalReturn<T> = T extends (...args: any) => infer R ? R : any;
// Con T equivocado, obtienes any y el error desaparece en silencio.
Bien — never para delatar el error 
type BienReturn<T extends (...args: any) => any> =
  T extends (...args: any) => infer R ? R : never;
Mal — Awaited de un solo nivel 
type UnNivel<T> = T extends Promise<infer U> ? U : T;
type R = UnNivel<Promise<Promise<string>>>; // Promise<string> — se queda a medias
Bien — recursion hasta el final 
type MyAwaited<T> = T extends Promise<infer U> ? MyAwaited<U> : T;
type R = MyAwaited<Promise<Promise<string>>>; // string
Mal — preguntarle a UNA firma generica 
type SoloUnaFirma<T> = ((...args: any) => any) extends (...args: any) => infer R ? R : never;
// R siempre es any: juzgas una firma generica, no el T del que quieres inferir.
Bien — juzgar al propio T (y distribuir) 
type SobreT<T> = T extends (...args: any) => infer R ? R : never;
type R = SobreT<(() => string) | (() => number)>; // string | number (distribuye)

7 · Ejercicio guiado

Construye FirstParam y LastParam, las utilidades que extraen el primer y el ultimo parametro de una funcion.

  1. Define type FirstParam<T extends (...args: any) => any>.
  2. Pattern (first: infer F, ...rest: any[]) => any: el primer hueco captura el primer parametro, el rest recoge el resto.
  3. Define type LastParam<T extends (...args: any) => any>.
  4. Infiere la tupla con (...args: infer P) => any y luego busca su final: P extends [...any[], infer U] ? U : never.
  5. Comprueba con una funcion de tres parametros y con una sin parametros (never).

Solucion paso a paso:

ejercicio-first-last.ts
// 1 y 2) Primer parametro con rest tuple.
type FirstParam<T extends (...args: any) => any> =
  T extends (first: infer F, ...rest: any[]) => any ? F : never;

// 3 y 4) Ultimo parametro: tupla completa y despues su final.
type LastParam<T extends (...args: any) => any> =
  T extends (...args: infer P) => any
    ? P extends [...any[], infer U] ? U : never
    : never;

// 5) Pruebas:
const compute = (id: number, label: string, flag: boolean) => 0;
type Primero = FirstParam<typeof compute>; // number
type Ultimo = LastParam<typeof compute>;    // boolean
type SinArgs = LastParam<() => void>;       // never — no hay ultimo parametro

8 · Reto

Reto

Dado el mapa de eventos type Eventos = { abrir: { ventana: string }; cerrar: () => void }, escribe PayloadDe<K extends keyof Eventos> que devuelva el tipo del payload de cada evento: para los que son funciones, el primer parametro (usa tu FirstParam); para los que son objetos, el propio objeto. No mires la solucion: piensa en un conditional con K extends keyof Eventos y en Eventos[K] como parametro desnudo.

9 · Resumen

  • infer solo vive dentro de un conditional type y crea "huecos" que el compilador rellena con el tipo real.
  • ReturnType a mano: T extends (...args: any) => infer R ? R : never.
  • Parameters a mano: T extends (...args: infer P) => any ? P : never — devuelve la tupla completa.
  • Con rest tuples capturas parametros concretos: (first: infer F, ...rest: any[]) y P extends [...any[], infer U].
  • Awaited es recursion: consume un Promise por llamada hasta llegar al valor.
  • Los conditional types distribuyen sobre unions cuando el parametro va desnudo; envuelvelo con [T] para apagarlo.

10 · Preguntas frecuentes

¿El built-in ReturnType usa never?

No: usa any en la rama falsa por compatibilidad historica. En tus versiones a mano prefiere never para que los usos invalidos se vean como errores.

¿Que es exactamente la distributividad?

Cuando el parametro de un conditional va desnudo, TypeScript aplica la condicion a cada miembro de la union por separado y une los resultados. Por eso ReturnType sobre una union de funciones devuelve la union de los retornos.

¿Por que Parameters devuelve una tupla y no varios tipos?

Porque internamente una firma se modela como una tupla de parametros. Eso permite conservar nombres, opcionales y rest, y te deja indexarla (P[0]) o volver a componerla.

¿Awaited quita todos los niveles de Promise?

Si, recursivamente, hasta que ya no hay promesa. El built-in ademas contempla PromiseLike; la version a mano cubre la idea central sin ese matiz.

¿Como se comportan con overloads?

El built-in considera la firma de implementacion (la ultima). Una version a mano depende del pattern que hagas coincidir: si la overload no encaja con tu pattern, caeras en la rama falsa.

¿Cuando usare esto de verdad?

Para derivar tipos de handlers, eventos, HOCs y wrappers, y para leer librerias de tipado avanzado. El patron conditional + infer es la pieza que desbloquea el resto del tipado avanzado.
