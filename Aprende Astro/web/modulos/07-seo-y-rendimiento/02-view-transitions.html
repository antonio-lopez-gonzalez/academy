View Transitions API

Módulo 7 · SEO y Rendimiento 🕐 35 minutos

1 · Introducción

Cuando navegas entre páginas de un sitio Astro, el navegador hace lo de siempre: se pone la pantalla en blanco y carga la siguiente página. Es rápido, pero se siente brusco. La View Transitions API permite animar ese cambio: la página vieja se desvanece o se desliza, y la nueva aparece con continuidad visual.

Astro trae un componente, <ClientRouter />, que activa esta API y añade navegación de cliente ligera. Lo interesante es que sigues teniendo un MPA: cada página es un HTML real. Solo ganas la sensación de fluidez de una SPA, sin convertir tu sitio en una SPA.

¿Por qué existe esta lección? Porque la percepción cuenta. Dos sitios con los mismos milisegundos de carga se sienten distintos si uno salta en blanco y el otro fluye. Pero también hay una trampa: activar transiciones cambia el comportamiento de tus scripts y añade JavaScript. Entender el intercambio entre «sentirse fluido» y «seguir siendo sencillo» es la lección real.

Errores típicos que veremos: activar <ClientRouter /> y descubrir que un script de menú deja de funcionar (porque el script ya no se re-ejecuta); animar sin respetar prefers-reduced-motion; o abusar de transiciones y convertir una web de contenido en una aplicación lenta.

2 · Teoría

Qué hace exactamente la View Transitions API

La API nativa del navegador funciona así: antes de cambiar de vista, hace una captura del estado actual; luego cambia el DOM; y finalmente anima la transición entre la captura vieja y el estado nuevo. Para animar elementos concretos (una imagen que se mueve de una página a otra), se les asigna un view-transition-name que coincide entre ambas páginas.

  1) Página A visible
     +-----------------+        el navegador CAPTURA A
     |   [ imagen ]    |  --->  como una "foto" para animar
     +-----------------+
  2) Ocurre la navegacion (se cambia el DOM a la pagina B)
  3) El navegador anima de la foto de A a la realidad de B
     +-----------------+
     |   [ imagen ]    |   la misma imagen, con el mismo
     +-----------------+   view-transition-name, "viaja"

Dos formas de usarla: nativa y con <ClientRouter />

Un punto que confunde mucho:

  • Transiciones nativas entre documentos (cross-document): solo animan. No añaden JavaScript de routing, no cambian tus scripts. Es la versión más «inocente».
  • <ClientRouter /> de Astro: además de animar, intercepta la navegación y la hace del lado del cliente (SPA mode). Ganas estado compartido y elementos persistentes, pero debes revisar tus scripts.

En este curso usaremos <ClientRouter /> porque es el mecanismo estándar de Astro para esto, pero sabiendo qué añade. La tendencia del ecosistema es que, conforme avancen los estándares, cada vez haga falta menos router de cliente y más transición nativa.

En Astro 5 el componente se llama <ClientRouter /> (el nombre anterior era <ViewTransitions />). Se importa de astro:transitions y se coloca en el <head>.

Las directivas transition:*

DirectivaQué haceCuándo usarla
transition:nameEmpareja un elemento entre dos páginas para que «viaje»Una imagen o título que aparece en ambas páginas
transition:animateElige el tipo de animación del elementofade, slide o none en elementos concretos
transition:persistMantiene el elemento (con su estado) entre navegacionesUn reproductor que no debe reiniciarse, o una isla con estado

Variantes de transition:animate:

  • fade (por defecto): fundido cruzado.
  • slide: la vieja sale a la izquierda y la nueva entra por la derecha; al retroceder, al revés.
  • none: desactiva la animación de ese elemento (útil en <html> para apagarlas todas).
  • initial: usa el estilo por defecto del navegador.

Animaciones a medida: puedes importar fade de astro:transitions y personalizarlo, por ejemplo transition:animate={fade({ duration: '0.4s' })}. Para algo totalmente propio, defines @keyframes en CSS y un objeto de animación con las partes old y new.

El coste: los scripts ya no se re-ejecutan

Este es el detalle que rompe proyectos. Con navegación de cliente, la página no se recarga entera, así que los scripts que antes corrían en cada carga ahora corren una sola vez. Un menú desplegable que se inicializaba al cargar deja de funcionar al navegar a otra página.

La solución es engancharse al ciclo de vida. El evento clave es astro:page-load, que se dispara tanto en la carga inicial como tras cada navegación:

src/scripts/menu.js
// Sin esto, el menu solo funcionaria en la primera pagina.
// astro:page-load se dispara en la carga inicial Y tras cada navegacion.
document.addEventListener('astro:page-load', () => {
  const toggle = document.querySelector('.menu-toggle');
  const links = document.querySelector('.nav-links');
  toggle?.addEventListener('click', () => links?.classList.toggle('open'));
});

Otros eventos útiles del ciclo de vida, en orden: astro:before-preparation, astro:after-preparation, astro:before-swap, astro:after-swap y astro:page-load.

Accesibilidad: prefers-reduced-motion y anuncio de ruta

Hay dos salvaguardas de accesibilidad que conviene conocer:

  • prefers-reduced-motion: si el usuario ha pedido «reducir movimiento» en su sistema, <ClientRouter /> desactiva todas las animaciones automáticamente e intercambia el DOM sin transición. No hay que hacer nada: Astro lo respeta por defecto.
  • Anuncio de ruta: al navegar del lado del cliente, el usuario de lector de pantalla no «ve» la recarga. <ClientRouter /> añade un elemento aria-live que anuncia el nuevo <title> (o el primer <h1>). Por eso cada página debe tener un <title>.

No abuses. Una web de contenido con transiciones en cada rincón se siente más lenta, no más rápida. La animación debe servir a la orientación del usuario, no ser un espectáculo. Si dudas, menos es más.

3 · Ejemplo mínimo

Activar las transiciones por defecto es una línea en el <head> del layout:

src/layouts/Layout.astro
---
// El router de cliente de Astro. Se importa de astro:transitions.
import { ClientRouter } from 'astro:transitions';
---
<html lang="es">
  <head>
    <meta charset="utf-8" />
    <title>Mi sitio</title>
    <!-- Activa las transiciones y la navegacion de cliente. -->
    <ClientRouter />
  </head>
  <body>
    <!-- Tus enlaces internos ya navegan con transicion. -->
    <nav>
      <a href="/">Inicio</a>
      <a href="/acerca">Acerca</a>
    </nav>
    <slot />
  </body>
</html>

Explicado línea a línea:

  1. import { ClientRouter } from 'astro:transitions': el módulo integrado de Astro para transiciones.
  2. <ClientRouter />: en el <head>. Activa tanto la animación como la navegación de cliente.
  3. Nada más: los enlaces internos (los del mismo sitio) ya se benefician. Los enlaces externos y los que tengan data-astro-reload se cargan de forma normal.
  4. Automático: la animación por defecto es un fade entre páginas, y prefers-reduced-motion se respeta sin configuración.

Si solo quieres una página con transiciones y no todo el sitio, coloca <ClientRouter /> únicamente en el layout que usa esa página. Recuerda: para que funcione la navegación de cliente, ambas páginas implicadas deben usarlo.

4 · Ejemplo real

Un blog con elementos que «viajan» entre la lista y el artículo, un reproductor persistente, y scripts que sobreviven a la navegación.

Portada: la tarjeta lleva un nombre de transición

src/pages/blog/index.astro
---
const posts = [
  { slug: 'islands', title: 'Que son las islands', cover: '/img/islands.png' },
  { slug: 'seo', title: 'SEO en Astro', cover: '/img/seo.png' },
];
---
<ul>
  {posts.map((post) => (
    <li>
      <a href={`/blog/${post.slug}`}>
        <!-- El name debe coincidir con el del articulo para que
             la imagen "vuele" de la tarjeta al encabezado. -->
        <img src={post.cover} alt="" transition:name={`cover-${post.slug}`} />
        <h2>{post.title}</h2>
      </a>
    </li>
  ))}
</ul>

Artículo: el mismo nombre en el destino

src/pages/blog/[slug].astro
---
export async function getStaticPaths() {
  return [{ params: { slug: 'islands' }, props: { title: 'Que son las islands', cover: '/img/islands.png' } }];
}
const { title, cover } = Astro.props;
---
<article>
  <!-- El mismo transition:name: el navegador empareja y anima. -->
  <img src={cover} alt="" transition:name="cover-islands" />
  <h1 transition:animate="slide">{title}</h1>
  <p transition:animate="fade">Contenido del articulo...</p>
</article>

Layout: reproductor persistente y script que sobrevive

src/layouts/Layout.astro
---
import { ClientRouter } from 'astro:transitions';
---
<html lang="es">
  <head>
    <meta charset="utf-8" />
    <title>{Astro.props.title}</title>
    <ClientRouter />
  </head>
  <body>
    <nav><a href="/">Inicio</a></nav>
    <slot />

    <!-- Persist: el audio sigue sonando al navegar entre paginas. -->
    <audio controls autoplay transition:persist>
      <source src="/podcast.mp3" type="audio/mpeg" />
    </audio>

    <script>
      // Estos listeners deben reiniciarse tras cada navegacion.
      document.addEventListener('astro:page-load', () => {
        document.querySelectorAll('[data-collapse]').forEach((el) => {
          el.addEventListener('click', () => el.classList.toggle('open'));
        });
      });

      // Cambiar el estado del tema ANTES de pintar la nueva pagina,
      // para evitar un parpadeo de tema claro.
      document.addEventListener('astro:after-swap', () => {
        const theme = localStorage.getItem('astro-theme') || 'dark';
        document.documentElement.dataset.theme = theme;
      });
    </script>
  </body>
</html>

Decisiones profesionales detrás de este ejemplo:

  • transition:name emparejado: la imagen de la tarjeta y la del artículo comparten nombre, así el navegador las conecta y la imagen «vuela» de una a otra. Es el efecto más vistoso y el más útil para orientar al usuario.
  • transition:animate por elemento: el <h1> usa slide y el párrafo fade. Puedes mezclar animaciones para guiar la mirada.
  • transition:persist: el reproductor de audio no se reinicia al navegar. Para contenido multimedia es imprescindible.
  • Scripts con astro:page-load: el fallo número uno al adoptar transiciones es este. Los listeners se re-inicializan tras cada navegación.
  • Estado del tema con astro:after-swap: se aplica antes de pintar, evitando un destello del tema por defecto.

Verifica en DevTools: en la pestaña Animations puedes ralentizar las animaciones al 10 % y observar cada transición. Además, activa «Emulate CSS prefers-reduced-motion: reduce» en el panel Rendering y comprueba que las animaciones desaparecen: es la prueba de que respetas la preferencia del usuario.

6 · Errores habituales

Scripts que dejan de ejecutarse tras navegar

✗ Incorrecto

// Corre UNA vez. Al navegar a otra pagina, el listener ya no se añade.
const toggle = document.querySelector('.menu-toggle');
toggle?.addEventListener('click', () => document.querySelector('.nav-links')?.classList.toggle('open'));

✓ Correcto

// Se re-inicializa en la carga inicial y tras CADA navegacion.
document.addEventListener('astro:page-load', () => {
  const toggle = document.querySelector('.menu-toggle');
  toggle?.addEventListener('click', () => document.querySelector('.nav-links')?.classList.toggle('open'));
});

El error más común al activar transiciones. Si un botón «funciona al principio y luego no», casi siempre es esto: falta envolver el código en astro:page-load.

Reutilizar transition:name en la misma página

✗ Incorrecto

<!-- Dos elementos con el mismo name en una pagina: conflicto. -->
<img src="/a.png" transition:name="cover" />
<img src="/b.png" transition:name="cover" />

✓ Correcto

<!-- Un name unico por pagina; en el destino, el que corresponda. -->
<img src="/a.png" transition:name="cover-a" />
<img src="/b.png" transition:name="cover-b" />

Cada view-transition-name debe ser único en la página. Si se repite, el navegador no sabe qué animar y la transición se rompe o se ignora.

Fuente de verdad del tema sin manejar el swap

✗ Incorrecto

<!-- El tema se aplica solo en la carga inicial:
     al navegar, la pagina nueva parpadea en claro. -->
<script>document.documentElement.dataset.theme = localStorage.getItem('theme') || 'dark';</script>

✓ Correcto

<script>
  // Reaplica el tema ANTES de que se pinte la nueva pagina.
  document.addEventListener('astro:after-swap', () => {
    document.documentElement.dataset.theme = localStorage.getItem('theme') || 'dark';
  });
</script>

Con navegación de cliente, el <html> se reemplaza. Si no reaplicas el tema en astro:after-swap, cada navegación provoca un destello del tema por defecto.

Animarlo todo sin criterio

✗ Incorrecto

<!-- Animaciones distintas en cada elemento: caos visual. -->
<header transition:animate="slide">
  <h1 transition:animate="fade">...</h1>
  <p transition:animate="slide">...</p>
  <ul><li transition:animate="fade">...</li></ul>
</header>

✓ Correcto

<!-- Deja el fade por defecto y anima solo lo que guia al usuario. -->
<html transition:name="root" transition:animate="none">
<!-- ... y una sola transicion destacada, por ejemplo la portada: -->
<img src={cover} transition:name="cover" />

Las transiciones son una herramienta de orientación, no una galería de efectos. Menos animaciones, mejor percibidas.

7 · Ejercicio guiado

Objetivo: activar transiciones en un blog y crear el efecto «imagen que vuela» de la lista al artículo.

  1. Activa el router en tu layout común: 
    ---
import { ClientRouter } from 'astro:transitions';
---
<head>
  <meta charset="utf-8" />
  <title>{title}</title>
  <ClientRouter />
</head>
  2. Nombra la portada en la lista (/blog): 
    <a href={`/blog/${post.slug}`}>
  <img src={post.cover} alt="" transition:name={`cover-${post.slug}`} />
</a>
  3. Repite el nombre en el artículo (/blog/[slug]) para que la imagen viaje: 
    <img src={cover} alt="" transition:name={`cover-${slug}`} />
  4. Añade una animación a medida al título, más suave que el fade por defecto: 
    ---
import { fade } from 'astro:transitions';
---
<h1 transition:animate={fade({ duration: '0.4s' })}>{title}</h1>
  5. Comprueba todo: navega entre la lista y varios artículos y observa la imagen viajar. Luego activa «prefers-reduced-motion: reduce» en DevTools → Rendering y confirma que las animaciones desaparecen.

8 · Reto

🎯 Navegación de cliente robusta y accesible

Lleva las transiciones a nivel de producción en un blog:

  • Menú móvil que sobreviva: implementa un menú desplegable cuyos listeners se re-inicialicen en astro:page-load. Verifica que funciona tras navegar varias veces.
  • Tema sin parpadeo: gestiona el modo claro/oscuro con astro:after-swap para que no haya destello al cambiar de página.
  • Barra de progreso: muestra un indicador de carga entre astro:before-preparation y astro:after-preparation.
  • Estado persistente: usa transition:persist en una isla interactiva (por ejemplo, un contador) y comprueba que su estado se conserva al navegar entre páginas que la contienen.
  • Accesibilidad: confirma que cada página tiene <title> (para el anuncio de ruta) y que todo respeta prefers-reduced-motion.

Documenta en el README qué eventos del ciclo de vida usaste y para qué.

Pista: para la barra de progreso, añade una clase en astro:before-preparation y quítala en astro:after-preparation. Para el estado persistente de una isla, transition:persist mantiene el estado pero re-renderiza con nuevos props; si quieres conservar también los props, existe transition:persist-props.

9 · Resumen

  • <ClientRouter /> (de astro:transitions) activa transiciones y navegación de cliente; se pone en el <head> del layout.
  • Sigues teniendo un MPA: cada página es HTML real; solo ganas fluidez.
  • transition:name empareja elementos entre páginas (efecto «vuela»); es único por página.
  • transition:animate elige la animación (fade, slide, none); transition:persist mantiene elementos con estado.
  • Los scripts no se re-ejecutan: re-inicialízalos con astro:page-load; usa astro:after-swap para el tema.
  • prefers-reduced-motion y el anuncio de ruta funcionan automáticamente.
ElementoQué hace
<ClientRouter />Activa transiciones + navegación de cliente
transition:nameEmpareja un elemento entre dos páginas
transition:animateElige la animación del elemento
transition:persistMantiene el elemento con su estado
astro:page-loadEvento para re-inicializar scripts
astro:after-swapEvento para reaplicar el tema

10 · Preguntas frecuentes

¿Las transiciones convierten mi sitio en una SPA?

No. Sigue siendo un MPA: cada página es un HTML estático completo y funciona sin JavaScript. <ClientRouter /> añade una capa de navegación de cliente por encima, que mejora la percepción y permite estados persistentes, pero no cambia la naturaleza del sitio. Puedes quitarlo y todo seguirá funcionando con navegación normal.

¿Por qué mi botón funciona solo la primera vez?

Porque con navegación de cliente los scripts se ejecutan una sola vez. Envuelve la inicialización (los addEventListener) dentro de document.addEventListener('astro:page-load', ...). Así se re-ejecuta en la carga inicial y después de cada navegación.

¿Cómo hago que una imagen viaje entre dos páginas?

Dale el mismo transition:name en ambas páginas. El navegador empareja los elementos con el mismo nombre y anima el viaje. Recuerda que el nombre debe ser único en cada página, por eso lo habitual es generar algo como cover-{slug}.

¿Funciona en todos los navegadores?

<ClientRouter /> funciona también en navegadores sin soporte nativo de View Transitions, usando un mecanismo de respaldo (por defecto animate, que simula la transición). Puedes cambiar ese comportamiento con el prop fallback (swap o none). En el peor caso, degrada a navegación normal sin animación.

¿Tengo que desactivar las animaciones a mano por accesibilidad?

No. <ClientRouter /> incluye un media query que desactiva todas las transiciones (incluidas las de respaldo) cuando el sistema indica prefers-reduced-motion. Lo que sí debes hacer es no sobreescribir esa lógica con CSS propio que reanime las cosas.
