Tailwind CSS en Astro

Módulo 6 · Tailwind e Integraciones 🕐 30 minutos

1 · Introducción

Ya sabes escribir HTML con componentes en Astro, pero hasta ahora el estilo era CSS suelto dentro de <style>. En esta lección conectamos Tailwind CSS v4 —la última generación del framework de utilidades— con Astro, usando su motor de build, Vite.

La buena noticia: en Astro 5 la integración de Tailwind moderno es una sola declaración. Se instala a través de un plugin de Vite y se activa con un @import en un único CSS global. Nada de tailwind.config.js, nada de content con globs que se desincronizan, nada de un plugin de PostCSS que adivine qué archivos escanear.

¿Por qué existe esta lección? Porque dominar Tailwind es hoy casi un requisito de mercado y, además, encaja como un guante con la filosofía de Astro. Entender cómo se conectan (Vite, no PostCSS) y por qué Tailwind v4 es un cambio de modelo (configuración en CSS, no en JavaScript) te evita el 90 % de los problemas que la gente arrastra desde la época de Tailwind v3.

Errores típicos que verás (y evitaremos) en esta lección: copiar una guía de Tailwind v3 e instalar @astrojs/tailwind, crear un tailwind.config.js obsoleto, olvidar importar el CSS global, o pelear con la precedencia entre utilidades de Tailwind y estilos con scope de Astro.

2 · Teoría

Qué es Tailwind y por qué encaja con Astro

Tailwind no es «Bootstrap con otro nombre». Bootstrap te da componentes ya hechos (btn, card) con una apariencia decidida por otros. Tailwind te da átomos de estilo (flex, px-4, text-slate-200) que compones en el propio HTML. Frente a CSS clásico, la diferencia es esta:

AspectoCSS tradicionalTailwind (utilidades)
Dónde vive el estiloEn un .css aparte, lejos del markupJunto al elemento, en la clase
Al cambiar el markupRiesgo de dejar CSS muertoEl estilo se borra con el elemento
NombradoHay que inventar nombres (.card, .hero, .btn--primary)No hay que inventar nada
ConvenciónCambia según el equipoVocabulario único y predecible

¿Por qué encaja tan bien con Astro? Porque en Astro escribes mucho HTML a mano dentro de componentes .astro. Tailwind te ahorra mantener dos archivos sincronizados (markup y CSS) y evita el problema clásico de borrar CSS que ya no usa nadie. Es el complemento natural de un framework centrado en contenido.

Analogía: el CSS tradicional es como un manual de instrucciones guardado en otro cajón: para cambiar cómo se ve algo tienes que ir a buscarlo. Tailwind es como un Lego: cada pieza va pegada al sitio donde la usas, y cuando quitas la construcción no queda nada suelto.

El cambio clave: Tailwind v4 es un plugin de Vite

En Astro moderno (5.2+), Tailwind se integra como plugin de Vite (@tailwindcss/vite), no como integración de Astro (@astrojs/tailwind). ¿Por qué importa? Porque Vite es el motor de build de Astro, así que Tailwind se ejecuta dentro del mismo proceso que compila tu proyecto. Esto trae ventajas directas:

  • Detección automática de contenido: Tailwind v4 escanea tus archivos por sí solo. Ya no hay que mantener la lista content: [...].
  • Configuración en CSS: el tema se define con @theme dentro de tu CSS, no en un archivo JavaScript.
  • Más rápido: el motor Oxide está escrito en Rust y aprovecha el grafo de módulos de Vite.

«Sin configuración» no significa «sin personalización». Puedes seguir definiendo colores, fuentes y breakpoints propios. La diferencia es que ahora lo haces con CSS nativo (@theme, variables --color-*) en lugar de con JavaScript. Es configuración CSS-first.

Cómo se conecta: el flujo completo

  astro.config.mjs                    src/styles/global.css
  +---------------------+             +--------------------------+
  | vite: {             |             | @import "tailwindcss";   |
  |   plugins: [        |             | @theme { ... }           |
  |     tailwindcss()   |             +------------+-------------+
  |   ]                 |                          |
  | }                   |                          | (lo importa)
  +----------+----------+                          v
             |                        src/layouts/Layout.astro
             |  registra el plugin    +--------------------------+
             +----------------------->| import '../styles/       |
                 en Vite              |   global.css';           |
                                      +------------+-------------+
                                                   |
                                                   v
                     En build, Vite pasa tu HTML/CSS por Tailwind:
                     escanea las clases usadas y genera SOLO el CSS
                     de esas clases -> CSS final minimo.

En resumen: un plugin en el config, un @import en un CSS global, y ese CSS importado en tu layout. Con esos tres puntos, cualquier clase de Tailwind funciona en tus componentes .astro.

Vite vs PostCSS: por qué el cambio de arquitectura

Tailwind v3 se enchufaba a Astro a través de PostCSS, un procesador de CSS más genérico. Vite ya usa PostCSS internamente, así que funcionaba… pero había que mantener el content, y el escaneo era menos inteligente. El plugin de Vite de Tailwind v4 se integra más arriba en el pipeline, conoce el grafo de módulos real del proyecto y puede ser más preciso y rápido.

ComparaciónTailwind v3 (legacy)Tailwind v4 (actual)
Instalación en Astro@astrojs/tailwind + tailwindcss@3@tailwindcss/vite
Dónde se enganchaIntegración de Astro / PostCSSPlugin de Vite
Configuracióntailwind.config.js (JavaScript)@theme en CSS (CSS-first)
Detección de contenidoManual (content: [...])Automática
Activar el framework@tailwind base/components/utilities@import "tailwindcss";

El error nº 1 en 2025: seguir una guía antigua e instalar @astrojs/tailwind. Esa integración da soporte a Tailwind v3, que este curso prohíbe. Si en tu astro.config.mjs ves integrations: [tailwind()], estás en la versión antigua: hay que migrar a @tailwindcss/vite.

Comparación con otros frameworks

FrameworkCómo integra Tailwind
Astro 5pnpm astro add tailwind → plugin @tailwindcss/vite + @import "tailwindcss"
Next.jsDepende de PostCSS (postcss.config.mjs) y de la detección de contenido
Vite puro (React SPA)Mismo plugin @tailwindcss/vite: Astro y Vite comparten el enfoque moderno
Gatsbygatsby-plugin-postcss + configuración JavaScript de Tailwind

Fíjate en que Astro y Vite puro comparten el enfoque moderno (plugin de Vite, CSS-first). Next.js y Gatsby siguen más anclados al modelo PostCSS + config en JavaScript. Si ya sabes Tailwind por Next.js, lo que aprendas aquí te valdrá, pero con menos configuración.

3 · Ejemplo mínimo

Tres pasos y Tailwind funciona. Empezamos instalando con el comando de Astro (que ya usa pnpm):

Terminal
# Astro >=5.2: instala tailwindcss y @tailwindcss/vite,
# y actualiza astro.config.mjs por ti.
pnpm astro add tailwind

# Arranca el servidor de desarrollo para ver el resultado.
pnpm dev

El comando deja el plugin configurado así:

astro.config.mjs
// @ts-check
import { defineConfig } from 'astro/config';
// Plugin oficial de Tailwind para Vite (el motor de build de Astro).
import tailwindcss from '@tailwindcss/vite';

export default defineConfig({
  vite: {
    plugins: [tailwindcss()],
  },
});

El CSS global que activa Tailwind. Vive en src/styles/:

src/styles/global.css
/* Una sola linea trae todo Tailwind v4: base, componentes,
   utilidades y variantes. Ya no se separa en @tailwind base,
   components y utilities como en v3. */
@import "tailwindcss";

Y el componente donde usas las clases. Importamos el CSS una vez, en el layout:

src/layouts/Layout.astro
---
// Importamos el CSS global en el layout: TODAS las paginas que
// usen este layout tendran Tailwind disponible.
import '../styles/global.css';

const { title = 'Mi sitio' } = Astro.props;
---
<html lang="es">
  <head>
    <meta charset="utf-8" />
    <title>{title}</title>
  </head>
  <body class="bg-slate-950 text-slate-100 antialiased">
    <slot />
  </body>
</html>

Y una página que lo usa:

src/pages/index.astro
---
import Layout from '../layouts/Layout.astro';
---
<Layout title="Tailwind en Astro">
  <main class="mx-auto max-w-2xl px-6 py-16">
    <h1 class="text-4xl font-bold tracking-tight text-white">
      Hola, Tailwind
    </h1>
    <p class="mt-4 text-lg text-slate-400">
      Este parrafo ya esta estilado con utilidades.
    </p>
  </main>
</Layout>

Explicado paso a paso:

  1. pnpm astro add tailwind: instala dependencias y edita el config. En Astro 5.2+ este comando ya usa el plugin de Vite, no la integración antigua.
  2. plugins: [tailwindcss()]: registra el plugin en Vite. A partir de aquí, Vite pasa tu CSS por Tailwind y genera solo las clases usadas.
  3. @import "tailwindcss";: activa Tailwind. Es el único punto de entrada; sin esta línea no hay utilidades.
  4. import '../styles/global.css';: hace que el CSS forme parte del build. Ponlo en el layout para cubrir todas las páginas.
  5. class="mx-auto max-w-2xl ...": las utilidades se aplican directamente en el HTML. No hace falta escribir CSS propio.

4 · Ejemplo real

Una tarjeta de precios reutilizable. Aquí vemos lo importante en un proyecto real: componer utilidades en un componente con props y personalizar el tema con @theme.

Primero, el tema. Definimos una fuente y un color de marca sin tocar JavaScript:

src/styles/global.css
@import "tailwindcss";

/* @theme define tokens que generan utilidades.
   --color-brand-500 crea clases como bg-brand-500,
   text-brand-500, border-brand-500, etc. */
@theme {
  --color-brand-50:  oklch(0.97 0.02 265);
  --color-brand-500: oklch(0.62 0.19 265);
  --color-brand-600: oklch(0.55 0.20 265);

  /* --font-display crea la utilidad font-display. */
  --font-display: "Inter", ui-sans-serif, system-ui, sans-serif;
}

Ahora el componente de tarjeta, con props tipadas:

src/components/PricingCard.astro
---
// Props tipadas: plan, precio y si es la opcion destacada.
interface Props {
  plan: string;
  price: number;
  featured?: boolean;
  features: string[];
}

const { plan, price, featured = false, features } = Astro.props;

// Elegimos clases segun el estado. class:list combina strings
// y objetos condicionales: {'border-brand-500': featured}.
const cardClass = [
  'flex flex-col rounded-2xl border p-8 shadow-sm transition',
  featured
    ? 'border-brand-500 bg-brand-50/5 ring-1 ring-brand-500'
    : 'border-slate-800 bg-slate-900/50',
];
---
<div class:list={cardClass}>
  <div class="flex items-center justify-between">
    <h2 class="font-display text-xl font-semibold text-white">{plan}</h2>
    {featured && <span class="rounded-full bg-brand-500 px-3 py-1 text-xs font-medium text-white">Popular</span>}
  </div>

  <p class="mt-4 text-4xl font-bold text-white">
    {price}<span class="text-base font-normal text-slate-400">€/mes</span>
  </p>

  <ul class="mt-6 space-y-3 text-sm text-slate-300">
    {features.map((feature) => (
      <li class="flex items-start gap-2">
        <span class="text-brand-500">✓</span>
        <span>{feature}</span>
      </li>
    ))}
  </ul>

  <a
    href="/signup"
    class:list={[
      'mt-8 inline-flex items-center justify-center rounded-lg px-4 py-2 font-medium',
      featured
        ? 'bg-brand-500 text-white hover:bg-brand-600'
        : 'bg-slate-800 text-slate-100 hover:bg-slate-700',
    ]}
  >
    Empezar
  </a>
</div>

Y su uso en una página:

src/pages/precios.astro
---
import Layout from '../layouts/Layout.astro';
import PricingCard from '../components/PricingCard.astro';
---
<Layout title="Precios">
  <section class="mx-auto grid max-w-5xl gap-6 px-6 py-16 md:grid-cols-3">
    <PricingCard plan="Free" price={0} features={['1 proyecto', 'Soporte comunidad']} />
    <PricingCard
      plan="Pro"
      price={19}
      featured
      features={['Proyectos ilimitados', 'Soporte prioritario', 'Dominio propio']}
    />
    <PricingCard plan="Team" price={49} features={['Todo lo de Pro', '5 asientos', 'SSO']} />
  </section>
</Layout>

Decisiones profesionales detrás de este ejemplo:

  • Tema en @theme: el color de marca se define una vez. Si mañana cambia, cambia en un sitio y todas las utilidades brand-* se actualizan.
  • class:list: la forma idiomática de Astro de componer clases condicionales sin concatenar strings a mano ni meter ${} frágiles.
  • Responsive con prefijos: md:grid-cols-3 aplica tres columnas solo desde el breakpoint md. Sin media queries escritas a mano.
  • Componente, no copia-pega: las tres tarjetas comparten markup y solo cambian datos. Tailwind no impide componentizar; al contrario, lo hace fácil.

Depurar con DevTools: abre el inspector, selecciona un elemento y mira la pestaña Styles. Verás muchísimas declaraciones (una por utilidad), pero todas con la misma especificidad (una clase). Eso es clave: Tailwind no «gana» por especificidad, gana por orden de aparición. Si una utilidad no se aplica, casi siempre es porque otra clase posterior la sobrescribe.

Truco profesional: cuando un conjunto de utilidades se repite mucho, extrae un componente .astro antes que crear una clase CSS nueva. Si de verdad necesitas una clase reutilizable, Tailwind v4 permite @utility dentro de tu CSS para definir utilidades propias que conviven con las nativas.

6 · Errores habituales

Instalar la integración antigua de Tailwind v3

✗ Incorrecto

// astro.config.mjs (modelo ANTIGUO, Tailwind v3)
import { defineConfig } from 'astro/config';
import tailwind from '@astrojs/tailwind'; // <-- integracion legacy

export default defineConfig({
  integrations: [tailwind()],
});

✓ Correcto

// astro.config.mjs (modelo ACTUAL, Tailwind v4)
import { defineConfig } from 'astro/config';
import tailwindcss from '@tailwindcss/vite'; // <-- plugin de Vite

export default defineConfig({
  vite: {
    plugins: [tailwindcss()],
  },
});

Si sigues tutoriales antiguos acabarás con Tailwind v3 y un tailwind.config.js que ya no es el camino recomendado. En Astro 5.2+, deja que pnpm astro add tailwind haga el trabajo.

No importar el CSS global

✗ Incorrecto

---
// No se importa global.css en ningun sitio: ninguna clase funciona.
---
<div class="p-8 bg-slate-900">Sin estilos</div>

✓ Correcto

---
// Importa el CSS global donde corresponda (layout o pagina).
import '../styles/global.css';
---
<div class="p-8 bg-slate-900">Con estilos</div>

El plugin está registrado, pero hasta que el CSS global no forma parte del build, Tailwind no emite ninguna regla. Parece obvio, pero es el fallo más frecuente al crear la primera página.

Configurar el tema en el lugar equivocado

✗ Incorrecto

// tailwind.config.js (modelo v3) conviviendo con Tailwind v4:
// el tema de aqui se IGNORA, generando horas de confusion.
export default {
  content: ['./src/**/*.{astro,js,ts}'],
  theme: { extend: { colors: { brand: '#6d28d9' } } },
};

✓ Correcto

/* src/styles/global.css: el tema se define en CSS. */
@import "tailwindcss";

@theme {
  --color-brand-500: oklch(0.62 0.19 265);
}

Con Tailwind v4 el tema vive en CSS. Un tailwind.config.js heredado no produce error, simplemente no hace lo que esperas: la peor clase de bug.

Forzar estilos con !important por especificidad

✗ Incorrecto

/* Pelearse con Tailwind subiendo especificidad a mano. */
.hero .title {
  color: white !important;
}

✓ Correcto

<!-- Ordena las clases: la ultima gana. No hace falta !important. -->
<h1 class="text-slate-900 text-white">Titulo</h1>

Tailwind usa especificidad de una sola clase; el orden decide. Si no se aplica una utilidad, revisa si otra posterior la pisa, en lugar de recurrir a !important.

7 · Ejercicio guiado

Objetivo: añadir Tailwind a un proyecto Astro y construir un banner de aviso reutilizable con un color de marca propio.

  1. Instala Tailwind y arranca el servidor: 
    pnpm astro add tailwind
pnpm dev
  2. Comprueba el config generado. Debe contener el plugin de Vite: 
    // astro.config.mjs
import tailwindcss from '@tailwindcss/vite';
export default defineConfig({ vite: { plugins: [tailwindcss()] } });
  3. Define un color de marca en el CSS global: 
    /* src/styles/global.css */
@import "tailwindcss";

@theme {
  --color-menta-500: oklch(0.75 0.15 165);
  --color-menta-700: oklch(0.55 0.15 165);
}
  4. Crea el banner en src/components/Banner.astro, con un prop para alternar el tono: 
    ---
interface Props {
  tone?: 'info' | 'warning';
}

const { tone = 'info' } = Astro.props;

const tones = {
  info: 'bg-menta-500/15 text-menta-700 border-menta-500/40',
  warning: 'bg-amber-500/15 text-amber-700 border-amber-500/40',
};
---
<aside class:list={['rounded-lg border px-4 py-3 text-sm', tones[tone]]}>
  <slot />
</aside>
  5. Úsalo en la portada importando el CSS donde corresponda y comprueba en DevTools que las clases bg-menta-500/15 existen (significa que tu token de marca se generó bien).

Verificación: si escribes una clase inválida (bg-menta-999), Tailwind simplemente no la genera. En DevTools no aparecerá ninguna regla para ella: eso te confirma que el token no existe.

8 · Reto

🎯 Sistema de diseño mínimo con tema propio

Amplía el proyecto con un mini design system basado en tokens de Tailwind v4:

  • Define en @theme una paleta de marca completa (al menos 50, 500 y 700) y una fuente de display.
  • Crea un componente Button.astro con variantes primary / secondary / ghost y tamaños sm / md, eligiendo las clases con class:list.
  • Crea un componente Badge.astro que reutilice tu paleta.
  • Demuéstralo en una página /design-system donde se vean todas las combinaciones de botón y badge.

Requisitos: nada de CSS propio salvo el @theme; todos los estilos deben salir de utilidades. Ejecuta pnpm build y observa el tamaño del CSS resultante.

Pista: para variantes, usa un objeto de mapas como en el ejercicio (variants[variant]). ¿Qué pasaría si en vez de utilidades eligieras clases CSS propias dentro de <style> con scope? ¿Cuándo compensaría cada enfoque?

9 · Resumen

  • Tailwind v4 en Astro se integra como plugin de Vite (@tailwindcss/vite), no como integración de Astro.
  • El comando pnpm astro add tailwind (Astro 5.2+) instala y configura todo.
  • Se activa con @import "tailwindcss"; en un único CSS global, importado a su vez en el layout.
  • La personalización es CSS-first: tokens en @theme, no en tailwind.config.js.
  • Tailwind no se pelea con los componentes: se combinan. class:list es la forma idiomática de condicionar clases.
  • La especificidad de Tailwind es plana (una clase): decide el orden, no el !important.

10 · Preguntas frecuentes

¿Necesito un tailwind.config.js?

No. Con Tailwind v4 la configuración es CSS-first: defines tu tema dentro del CSS con @theme. Un tailwind.config.js es propio de la era v3 (con @astrojs/tailwind) y se ignora en el modelo actual. Si vienes de v3, elimínalo al migrar.

¿Cómo migro de Tailwind v3 a v4 en un proyecto Astro?

Dos pasos: (1) añade el soporte de v4 con pnpm astro add tailwind (o el plugin @tailwindcss/vite a mano); (2) desinstala @astrojs/tailwind y quita tailwind() de integrations en el config. Después, sigue la guía de actualización de Tailwind v4 para adaptar tu tailwind.config.js a @theme.

¿Dónde importo el global.css?

Lo habitual es importarlo una sola vez en tu layout principal (src/layouts/Layout.astro). Así todas las páginas que lo usan disponen de Tailwind. Si tienes varios layouts raíz (por ejemplo, uno público y otro de admin), impórtalo en cada uno.

¿Las utilidades funcionan dentro de un componente React (isla)?

Sí. Tailwind escanea también los archivos .jsx/.tsx. Importa el CSS global en el layout (o directamente en el componente) y las clases de las islas se generarán igual que en los .astro. Recuerda que las islas solo aportan CSS en build; en runtime no hay diferencias.

¿Qué pasa con el CSS definido en <style> de un componente?

Conviven. Los estilos con scope de Astro tienen mayor precedencia en el orden de aparición que el CSS importado, así que suelen ganar a las utilidades de Tailwind del mismo nivel de especificidad. Esa es una razón más para preferir utilidades: evitas dos sistemas compitiendo.
