Páginas y sistema de ficheros

Módulo 2 · Routing y Layouts 🕐 30 minutos

1 · Introducción

Hasta ahora has construido componentes: piezas de interfaz que se combinan como ladrillos. Pero una web no es un montón de ladrillos sueltos: es un edificio con direcciones. En esta lección aprendes cómo Astro convierte tu sistema de ficheros en las URLs reales del sitio.

La idea es tan simple que parece magia: creas un archivo y ya tienes una página. No hay un fichero de rutas, no hay un router que configurar, no hay que registrar nada. La carpeta src/pages/ es la tabla de rutas. A esta filosofía se la llama file-based routing (enrutado basado en ficheros) y es una de las razones por las que Astro se siente tan directo.

¿Por qué existe el routing por ficheros? Porque los ficheros ya forman una jerarquía: carpetas dentro de carpetas. Esa jerarquía es exactamente la forma de una URL. En lugar de duplicar esa información en un archivo de configuración aparte, dejamos que el árbol de directorios sea la ruta. Menos código, menos divergencia, menos bugs: si existe el fichero, existe la página.

Cuándo lo usarás: siempre. Cada página de cada proyecto Astro (portada, listado, detalle, contacto, 404…) nace aquí. En las siguientes lecciones verás cómo añadir rutas dinámicas ([param].astro) y cómo envolver todo con un layout compartido.

Errores típicos: crear la página fuera de src/pages/ (nunca aparece), nombrar el fichero index.html en lugar de index.astro, olvidar que las carpetas anidan la URL, y chocar dos ficheros que generan la misma ruta (por ejemplo about.astro y about/index.astro).

2 · Teoría

Una carpeta, una tabla de rutas

Astro mira el contenido de src/pages/ y traduce cada fichero a una URL. Las reglas caben en cinco líneas:

  • Cada fichero .astro (o .md, o .mdx, o .html) dentro de src/pages/ genera una página.
  • El nombre del fichero, salvo la extensión, es el último segmento de la URL.
  • Cada subcarpeta añade un segmento a la URL.
  • Un fichero llamado index.astro se convierte en la raíz de su carpeta (no aparece en la URL).
  • Los ficheros que empiezan por _ se ignoran: son un buen sitio para dejar piezas auxiliares que no quieres publicar como ruta.

Veámoslo dibujado. A la izquierda el árbol real de tu proyecto; a la derecha las URLs que Astro produce al compilar:

src/pages/                    URL resultante
├── index.astro          ──▶  /
├── about.astro          ──▶  /about
├── contact.astro        ──▶  /contact
├── 404.astro            ──▶  (página de error 404)
└── blog/
    ├── index.astro      ──▶  /blog
    ├── about.astro      ──▶  /blog/about
    └── archive/
        └── index.astro  ──▶  /blog/archive

Analogía: piensa en src/pages/ como un archivador con cajones y carpetas. La ruta de una carpeta dentro de otra es la dirección postal de un documento: blog/archive/index.astro se lee como «la portada (índice) de la carpeta archive, que está dentro de blog». El index es el «recibidor» de esa carpeta.

¿Dónde vive una página en el navegador y en el build?

Durante el desarrollo ejecutas pnpm dev y Astro levanta un servidor de Vite. Este sirve http://localhost:4321/ y recalcula las rutas al vuelo: creas un fichero nuevo y la URL ya existe sin reiniciar. Al compilar con pnpm build, Astro ejecuta el mismo enrutado pero de forma estática y escribe el HTML resultante en dist/:

src/pages/about.astro      ──(astro build)──▶   dist/about/index.html
src/pages/index.astro      ──(astro build)──▶   dist/index.html
src/pages/blog/index.astro ──(astro build)──▶   dist/blog/index.html

Fíjate en el detalle: por defecto Astro genera un directorio con un index.html dentro por cada ruta. Es lo que se llama build.format: 'directory'. Gracias a eso, un servidor estático cualquiera (nginx, Netlify, GitHub Pages) resuelve /about/ buscando el index.html de la carpeta. Si prefieres dist/about.html en lugar de dist/about/index.html, cambia el formato:

astro.config.mjs
import { defineConfig } from 'astro/config';

export default defineConfig({
  // 'directory' (por defecto) → /about/ resuelto por about/index.html
  // 'file'                     → genera about.html y la URL es /about.html
  build: {
    format: 'directory',
  },
  // Normaliza si las URLs llevan barra final. Con 'ignore' el build saca ambas.
  trailingSlash: 'ignore',
});

Salida estática por defecto: en Astro 5 el modo por defecto es output: 'static': todo se genera en tiempo de build y se sirve como HTML puro. Eso es exactamente el modelo MPA (Multi-Page App): varias páginas reales, cada una con su HTML. En el Módulo 5 verás output: 'server' para SSR cuando necesites datos en cada petición.

Comparación con otros frameworks

No estás aprendiendo una rareza: el enrutado por ficheros es el estándar moderno. Lo que cambia es dónde se renderiza el HTML:

FrameworkCómo se define la rutaQué se envía al navegador
Astrosrc/pages/blog/index.astroHTML estático + islands opcionales
Next.js (App Router)app/blog/page.tsxHTML + runtime React (hidratación)
Gatsbysrc/pages/blog.jsxHTML + runtime React
Hugo / 11tycontent/blog/_index.mdHTML estático (sin componentes)
SPA (React puro)Router en JavaScriptUn solo HTML vacío; el router corre en el cliente

La diferencia clave con una SPA: en Astro, /about ya existe como documento antes de que se ejecute una sola línea de JavaScript. Por eso es más rápido, mejor para SEO y funciona incluso sin JS. Es la herencia de Hugo y 11ty, pero con la potencia de componentes de React o Vue cuando los necesitas.

La página 404

Crea src/pages/404.astro y Astro la usa como página de "no encontrado". En modo estático se genera dist/404.html; los hostings (Netlify, Vercel, GitHub Pages, nginx) están configurados para servirla cuando la ruta pedida no existe. El nombre es fijo: tiene que llamarse 404.astro, no not-found.astro.

3 · Ejemplo mínimo

El Astro más pequeño posible: dos ficheros dentro de src/pages/ producen la portada y una página secundaria. Crea el proyecto y añade los archivos.

Terminal
# Crea un proyecto nuevo con la plantilla mínima de Astro
pnpm create astro@latest mini-site --template minimal --no-install
cd mini-site
# Instala dependencias con pnpm (nunca npm)
pnpm install
src/pages/index.astro
---
// --- es el "frontmatter": código que se ejecuta en el servidor (build),
// nunca en el navegador. Aquí no necesitamos nada, pero el bloque es obligatorio.
---

<!-- Todo lo que sigue es la plantilla que se convierte en HTML. -->
<html lang="es">
  <head>
    <meta charset="UTF-8" />
    <title>Inicio</title>
  </head>
  <body>
    <h1>¡Hola desde la portada!</h1>
    <!-- Un enlace normal: no hay router en el cliente, es una navegación real. -->
    <a href="/about">Ir a la página About</a>
  </body>
</html>
src/pages/about.astro
---
// No hace falta registrar la ruta en ningún sitio: el nombre del fichero ya es /about.
---

<html lang="es">
  <head>
    <meta charset="UTF-8" />
    <title>About</title>
  </head>
  <body>
    <h1>Sobre este sitio</h1>
    <a href="/">Volver a la portada</a>
  </body>
</html>

Línea por línea: el bloque entre --- es el frontmatter (component code). Todo lo que va debajo es el template: HTML con superpoderes. El archivo index.astro es especial porque index significa «la raíz de esta carpeta», y aquí esa carpeta es src/pages, o sea, la URL /. El archivo about.astro se traduce mecánicamente a /about. Los enlaces son <a> normales: en un MPA, navegar es pedir otro documento al servidor.

Compruébalo: ejecuta pnpm dev, abre http://localhost:4321/ y luego http://localhost:4321/about. Sin configurar nada, las dos rutas funcionan. Escribe una que no exista (por ejemplo /nope) y verás la página de desarrollo de Astro avisando de un 404.

4 · Ejemplo real

Ahora un esqueleto de blog con la jerarquía de rutas que usarás durante todo el módulo: portada, listado de blog, una sección anidada, contacto y un 404 propio. Este es el proyecto blog/ que iremos ampliando lección a lección.

src/pages/
├── index.astro          ──▶  /
├── contact.astro        ──▶  /contact
├── 404.astro            ──▶  (error 404)
└── blog/
    ├── index.astro      ──▶  /blog        (listado)
    └── tag/
        └── index.astro  ──▶  /blog/tag    (archivo por etiquetas)
src/pages/index.astro
---
// Portada del blog. De momento datos de ejemplo hardcodeados;
// en la lección 2 del Módulo 3 vendrán de una content collection.
const siteName = 'Bitácora Astro';
---

<html lang="es">
  <head>
    <meta charset="UTF-8" />
    <title>{siteName}</title>
  </head>
  <body>
    <h1>{siteName}</h1>
    <p>Un blog construido paso a paso con Astro.</p>

    <nav>
      <!-- Rutas absolutas: siempre empiezan por /. Nunca uses rutas relativas
           para navegar entre páginas, se rompen al anidar carpetas. -->
      <a href="/blog">Ver el blog</a>
      <a href="/contact">Contacto</a>
    </nav>
  </body>
</html>
src/pages/blog/index.astro
---
// El "índice" del blog: la lista de posts.
// Observa que el nombre de la CARPETA (blog) es lo que crea el segmento /blog.
const posts = [
  { slug: 'hola-astro', title: 'Hola, Astro' },
  { slug: 'por-que-mpa', title: 'Por qué MPA' },
];
---

<html lang="es">
  <head>
    <meta charset="UTF-8" />
    <title>Blog</title>
  </head>
  <body>
    <h1>Blog</h1>
    <ul>
      {posts.map((post) => (
        <li>
          <!-- En la lección 2 esta ruta será dinámica: /blog/hola-astro... -->
          <a href={`/blog/${post.slug}`}>{post.title}</a>
        </li>
      ))}
    </ul>
    <a href="/">← Portada</a>
  </body>
</html>
src/pages/blog/tag/index.astro
---
// Página DENTRO de una subcarpeta dentro de otra: la ruta es /blog/tag.
// Cada nivel de carpeta añade un segmento a la URL.
const tags = ['astro', 'routing', 'mpa'];
---

<html lang="es">
  <head>
    <meta charset="UTF-8" />
    <title>Etiquetas</title>
  </head>
  <body>
    <h1>Todas las etiquetas</h1>
    <ul>{tags.map((tag) => <li>{tag}</li>)}</ul>
    <a href="/blog">← Volver al blog</a>
  </body>
</html>
src/pages/404.astro
---
// Nombre reservado: Astro lo usa como página de error "no encontrado".
---

<html lang="es">
  <head>
    <meta charset="UTF-8" />
    <title>404 · No encontrado</title>
  </head>
  <body>
    <h1>404 — Esta página no existe</h1>
    <p>Puede que el enlace esté roto o que la URL sea incorrecta.</p>
    <a href="/">Volver a la portada</a>
  </body>
</html>

Decisiones: (1) todas las navegaciones usan rutas absolutas (/blog), porque una relativa como ../blog se rompería al visitar una ruta más profunda. (2) El listado vive en blog/index.astro, no en blog.astro, para dejar la carpeta blog/ libre a las rutas de detalle. (3) El 404 vive en la raíz de pages para aplicar a todo el sitio. Este mismo esqueleto, envuelto después en un layout, es el 90 % de cualquier blog real.

Regla de oro de nombres: usa kebab-case en ficheros y carpetas (blog-post.astro). Las mayúsculas crean URLs frágiles: según el sistema de ficheros, About.astro y about.astro pueden o no ser el mismo archivo, y eso es una fuente clásica de «funciona en mi máquina».

6 · Errores habituales

Error 1 — La página está fuera de src/pages/

Mal — el fichero nunca se convierte en ruta 
src/components/contact.astro     ← es un componente, NO una página
src/data/about.astro             ← tampoco
Bien — dentro de pages 
src/pages/contact.astro          ← genera /contact

Error 2 — Extensión que Astro no procesa como página

Mal 
src/pages/index.html    ← HTML crudo: no ejecuta frontmatter ni componentes
Bien 
src/pages/index.astro   ← la plantilla .astro por defecto

Matiz: los .html sí se sirven como páginas, pero no admiten frontmatter ni componentes; para cualquier página con lógica usa .astro.

Error 3 — Dos ficheros que generan la misma URL

Mal — colisión de rutas 
src/pages/about.astro          → /about
src/pages/about/index.astro    → /about   ← ¡misma ruta!

Astro avisará de la colisión o una página pisará a la otra de forma impredecible. Elige una sola representación. Si about tendrá subpáginas, usa about/index.astro; si es una página suelta, about.astro.

Error 4 — Enlaces relativos que se rompen al profundizar

Mal — depende de la profundidad 
<!-- Desde /blog/tag esto apunta a /blog/blog, no a /blog -->
<a href="blog">Volver al blog</a>
Bien — ruta absoluta 
<a href="/blog">Volver al blog</a>

8 · Reto

🧭 Diseña una jerarquía de URLs para una tienda

Diseña solo sobre el papel (lista de ficheros en src/pages/) el árbol completo de una tienda online que tenga: portada, listado de productos, página de cada producto, categorías, una página de cada categoría, sobre nosotros y contacto. Justifica cuántos niveles de anidamiento usas y por qué.

9 · Resumen

  • src/pages/ es la tabla de rutas: un fichero, una URL.
  • index.astro es la raíz de su carpeta; las subcarpetas anidan la URL.
  • Los ficheros que empiezan por _ se ignoran como ruta.
  • 404.astro es un nombre reservado para la página de error.
  • Con pnpm dev las rutas se recalculan al vuelo; con pnpm build se escriben en dist/ como HTML estático.
  • Navega siempre con rutas absolutas y usa kebab-case.

10 · Preguntas frecuentes

¿Y si quiero que /about no exista como carpeta sino como HTML suelto?

Con build.format: 'file' Astro genera dist/about.html en lugar de dist/about/index.html. Aun así, el fichero de origen sigue siendo src/pages/about.astro: el formato solo cambia cómo se escribe la salida, no cómo declaras la ruta.

¿Puedo usar un fichero .md como página directamente en src/pages/?

Sí. Astro trata los Markdown dentro de src/pages/ como páginas: src/pages/about.md genera /about. Es ideal para páginas de contenido puro. Lo verás a fondo en el Módulo 3, donde además usaremos content collections para tener esquemas tipados.

¿Necesito un servidor Node para servir el resultado?

No. En modo static (el de por defecto) el resultado es HTML, CSS y JS estáticos que valen para cualquier hosting estático. El servidor Node solo hace falta cuando activas SSR con output: 'server' y necesitas renderizar en cada petición (Módulo 5).

¿Por qué mi carpeta src/pages/ con un componente dentro me genera una URL rara?

Porque todo lo que pongas en src/pages/ se publica como ruta. Los componentes compartidos deben vivir en src/components/. Si por alguna razón necesitas dejar un auxiliar junto a las páginas, prefíjalo con _ para que Astro lo ignore.

¿El enrutado por ficheros funciona también en modo SSR?

Exactamente igual. El enrutado por ficheros es independiente del modo de renderizado: lo único que cambia es cuándo se genera el HTML (en build o por petición). El mapa de rutas sigue naciendo del mismo árbol src/pages/.
