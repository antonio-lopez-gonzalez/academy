Rutas dinámicas y getStaticPaths

Módulo 2 · Routing y Layouts 🕐 35 minutos

1 · Introducción

En la lección anterior viste que un fichero = una página. Perfecto… hasta que tienes 500 artículos de blog. No vas a crear 500 ficheros mi-articulo.astro copiados y pegados. Necesitas lo contrario: una plantilla y 500 URLs. Esa es la misión de las rutas dinámicas.

La pieza central es un fichero con corchetes en el nombre, como [slug].astro. Los corchetes significan «aquí va un valor variable». Y como Astro es estático por defecto, necesita saber de antemano qué valores existen para poder generar los HTML. Para eso está getStaticPaths(): una función que devuelve la lista de rutas a generar durante el build.

¿Por qué existe getStaticPaths? Porque en un sitio estático el HTML debe existir antes de que llegue el visitante. Una SPA puede resolver /blog/lo-que-sea en el navegador con JavaScript; Astro (MPA) necesita fabricar cada documento por adelantado. getStaticPaths es la respuesta honesta a la pregunta «¿y qué páginas exactamente genero?». El resultado es un sitio rápido y completo, sin depender de un servidor vivo.

Cuándo lo usarás: cada vez que muchos elementos compartan plantilla y cambien solo los datos: artículos, productos, categorías, perfiles de usuario, documentación… Es, con diferencia, el patrón más rentable de Astro.

Errores típicos: olvidar exportar getStaticPaths en una ruta dinámica (la página no se genera), devolver slug en lugar de anidarlo en params, que el nombre del array en params no coincida con el nombre entre corchetes del fichero, y tratar de leer Astro.params dentro de getStaticPaths (ahí todavía no existe).

2 · Teoría

El nombre del fichero declara el parámetro

Un fichero llamado [slug].astro dentro de src/pages/blog/ declara la ruta /blog/:slug. Es decir: captura cualquier valor en esa posición y lo deja disponible como Astro.params.slug. Hay tres variantes de corchetes:

NombreCapturaEjemplo de URL
[slug].astroUn segmento obligatorio/blog/hola-astro
[[slug]].astroUn segmento opcional/blog y /blog/hola
[...path].astroUno o varios segmentos (rest)/blog/a/b/c

Analogía: una ruta dinámica es un molde de galletas. El fichero [slug].astro es el molde con forma de artículo; getStaticPaths es el horno que lo usa una vez por cada «sabor» (post) y saca una galleta distinta por cada uno. El molde es uno; las galletas, tantas como datos tengas.

Cómo funciona el build, paso a paso

Cuando ejecutas pnpm build, Astro recorre src/pages/. Al llegar a una ruta dinámica, ejecuta su getStaticPaths() en Node y para cada elemento del array generado produce un HTML:

getStaticPaths()  ─▶  [
                        { params: { slug: 'hola-astro' }, props: { post } },
                        { params: { slug: 'por-que-mpa' }, props: { post } },
                        { params: { slug: 'islands' },     props: { post } },
                      ]
        │
        ▼  Astro ejecuta la plantilla UNA vez por elemento
   dist/blog/hola-astro/index.html
   dist/blog/por-que-mpa/index.html
   dist/blog/islands/index.html

Fíjate en dos cosas importantes. Primera: el params determina la URL. Segunda: el props determina los datos que recibirá esa página concreta. Puedes pasar datos por props (lo normal) o volver a buscarlos por la clave de params dentro de la plantilla; pasar props suele ser más limpio y eficiente.

El tipo de retorno, formalmente

getStaticPaths puede ser síncrona o async (útil para leer ficheros o llamar a una API en build time). Debe devolver un array de objetos con esta forma:

// Cada elemento describe UNA ruta a generar.
type StaticPath = {
  params: Record<string, string | undefined>;  // clave = nombre entre corchetes
  props?: Record<string, unknown>;            // datos extra para la página
};

La regla de oro: la clave de params debe coincidir exactamente con el nombre entre corchetes del fichero. Si el fichero es [slug].astro, el objeto debe ser { params: { slug: '...' } }. Si escribes { params: { id: '...' } }, Astro no sabrá rellenar el hueco y fallará.

SSG vs SSR: cuándo NO hace falta getStaticPaths

En modo static (por defecto), una ruta dinámica necesita siempre getStaticPaths: no hay forma de servir una URL imprevista. En cambio, en modo server (SSR, Módulo 5) la ruta se renderiza por petición y puede leer directamente Astro.params.slug sin generar rutas por adelantado. Puedes mezclar ambos por página con la constante prerender:

src/pages/blog/[slug].astro
// Fuerza que ESTA página se genere en build aunque el sitio sea SSR.
export const prerender = true;

// Lo contrario: en un sitio estático, marca una página como bajo demanda.
// (Solo tiene efecto si el proyecto usa output: 'server').
// export const prerender = false;

Decisión de diseño: Astro separa qué rutas existen (params) de qué contienen (props). Es la misma separación que hace Next.js con generateStaticParams / getStaticProps, pero en una sola función. Gatsby, en cambio, usa su API createPages en gatsby-node.js, más lejos del fichero de la ruta. Astro gana en cercanía y sencillez.

3 · Ejemplo mínimo

Una ruta con un solo parámetro y dos páginas generadas. Crea src/pages/blog/[slug].astro:

src/pages/blog/[slug].astro
---
// getStaticPaths se ejecuta en BUILD, no en el navegador.
// Devuelve la lista exacta de URLs que habrá que generar.
export function getStaticPaths() {
  return [
    { params: { slug: 'hola-astro' } },   // genera /blog/hola-astro
    { params: { slug: 'por-que-mpa' } },  // genera /blog/por-que-mpa
  ];
}

// Astro.params contiene los valores capturados por los corchetes del fichero.
// Aquí: { slug: 'hola-astro' } o { slug: 'por-que-mpa' }, según la página.
const { slug } = Astro.params;
---

<html lang="es">
  <head>
    <meta charset="UTF-8" />
    <title>Post: {slug}</title>
  </head>
  <body>
    <h1>Artículo: {slug}</h1>
    <p>Estás en la URL <code>{Astro.url.pathname}</code>.</p>
    <a href="/blog">← Volver al listado</a>
  </body>
</html>

Línea por línea: export function getStaticPaths() es obligatoria en modo estático; sin ella Astro no sabe qué URLs crear. Cada objeto del array tiene una clave slug que coincide con el [slug] del nombre del fichero. Dentro de la plantilla, Astro.params.slug es el valor de esa página. Astro.url.pathname es la URL completa que se está generando, útil para depurar. Si borras getStaticPaths y ejecutas el build, Astro te avisará de que falta; si lo dejas sin el array correcto, verás un error pidiendo que coincidan los params.

4 · Ejemplo real

Un blog que separa los datos de la plantilla: los posts viven en un módulo TypeScript reutilizable y la ruta dinámica los recorre con props tipadas. Así el mismo modelo servirá para el listado y el detalle sin duplicar información.

src/data/posts.ts
// Modelo de un post. Una sola fuente de verdad para toda la app.
export interface Post {
  slug: string;        // identificador que aparece en la URL
  title: string;
  description: string;
  pubDate: Date;
  body: string;        // de momento texto plano; en el Módulo 3 será Markdown
}

// Lista de ejemplo. Cuando lleguemos a content collections,
// esto lo sustituirá getCollection('blog').
export const posts: Post[] = [
  {
    slug: 'hola-astro',
    title: 'Hola, Astro',
    description: 'Primer contacto con el framework.',
    pubDate: new Date('2026-01-10'),
    body: 'Astro genera HTML estático por defecto.',
  },
  {
    slug: 'por-que-mpa',
    title: 'Por qué MPA',
    description: 'La arquitectura multi-página frente a la SPA.',
    pubDate: new Date('2026-02-02'),
    body: 'Cada página es un documento real y completo.',
  },
  {
    slug: 'islands',
    title: 'Islands e hidratación',
    description: 'Interactividad solo donde hace falta.',
    pubDate: new Date('2026-03-15'),
    body: 'El JavaScript se carga únicamente para las islas.',
  },
];
src/pages/blog/[slug].astro
---
import type { Post } from '../../data/posts';
import { posts } from '../../data/posts';

// Una ruta por cada post: params decide la URL, props lleva los datos.
export function getStaticPaths() {
  return posts.map((post) => ({
    params: { slug: post.slug },
    props: { post },
  }));
}

// Tipamos las props que la página recibe. TypeScript sabrá que `post` existe.
interface Props {
  post: Post;
}
const { post } = Astro.props;

// Enlaces anterior/siguiente: ordenamos por fecha y buscamos vecinos.
const ordered = [...posts].sort(
  (a, b) => a.pubDate.getTime() - b.pubDate.getTime()
);
const index = ordered.findIndex((p) => p.slug === post.slug);
const prev = ordered[index - 1];
const next = ordered[index + 1];
---

<html lang="es">
  <head>
    <meta charset="UTF-8" />
    <title>{post.title}</title>
    <meta name="description" content={post.description} />
  </head>
  <body>
    <article>
      <h1>{post.title}</h1>
      <time datetime={post.pubDate.toISOString()}>
        {post.pubDate.toLocaleDateString('es-ES')}
      </time>
      <p>{post.body}</p>
    </article>

    <nav>
      {prev && <a href={`/blog/${prev.slug}`}>← {prev.title}</a>}
      {next && <a href={`/blog/${next.slug}`}>{next.title} →</a>}
    </nav>
    <a href="/blog">Todos los artículos</a>
  </body>
</html>

Decisiones: separar los datos en src/data/ evita duplicar la lista entre el listado y el detalle. Pasar el post entero por props es más cómodo que volver a buscarlo por slug, y el tipado interface Props da autocompletado. Los enlaces prev/next se calculan en build time: cero JavaScript en el navegador. Como ejercicio mental, imagina cambiar posts por cien entradas: la plantilla no cambia ni una coma.

Depuración con DevTools: abre pnpm dev y navega a /blog/hola-astro. En la pestaña Network verás un documento HTML completo (no un JSON). Ese es el síntoma de que el routing dinámico funcionó: cada URL tiene su propio index.html generado.

6 · Errores habituales

Error 1 — Ruta dinámica sin getStaticPaths

Mal — en estático no se genera nada 
---
// Fichero: src/pages/blog/[slug].astro
const { slug } = Astro.params;   // ¿de dónde sale slug? Nadie dijo que URLs existen
---
Bien — declara las rutas 
export function getStaticPaths() {
  return posts.map((post) => ({ params: { slug: post.slug } }));
}

Error 2 — La clave de params no coincide con el fichero

Mal — fichero [slug].astro, params id 
export function getStaticPaths() {
  // La clave debería ser "slug", no "id"
  return [{ params: { id: 'hola-astro' } }];
}
Bien 
export function getStaticPaths() {
  return [{ params: { slug: 'hola-astro' } }];
}

Error 3 — Leer Astro.params dentro de getStaticPaths

Mal — ahí todavía no hay página concreta 
export function getStaticPaths() {
  // Astro.params no existe en este contexto: se ejecuta una vez para TODAS las rutas
  return [{ params: { slug: Astro.params.slug } }];
}
Bien — los valores vienen de tus datos 
export function getStaticPaths() {
  return posts.map((post) => ({ params: { slug: post.slug } }));
}
// Astro.params solo se usa DENTRO de la plantilla, una vez por ruta generada.

Regla mental: getStaticPaths se ejecuta una vez para decidir el conjunto de rutas; la plantilla se ejecuta una vez por ruta. Son dos momentos distintos y por eso no comparten Astro.params.

8 · Reto

🗂️ Categoría + slug en un solo nivel de URL

Amplía el blog para que cada post pertenezca a una categoría, y la URL sea /blog/<categoria>/<slug>/. Crea src/pages/blog/[category]/[slug].astro que reciba dos parámetros a la vez y genera todas las combinaciones a partir de los datos. Enlaza cada post desde su listado con la ruta nueva.

Pista: dentro de getStaticPaths devuelve { params: { category, slug }, props: { post } } en un solo objeto por post; ambos huecos se rellenan a la vez. Dentro de la plantilla, Astro.params.category y Astro.params.slug existen. Comprueba en dist/ que se crean dos niveles de carpetas.

9 · Resumen

  • Los corchetes en el nombre del fichero declaran parámetros de ruta: [param], [[opcional]], [...rest].
  • En modo estático, una ruta dinámica necesita getStaticPaths().
  • params decide la URL; props lleva los datos a esa página.
  • La clave de params debe coincidir con el nombre entre corchetes.
  • getStaticPaths corre una vez en build; la plantilla, una vez por ruta.
  • En SSR (output: 'server') no hace falta prerenderizar rutas; puedes mezclar con export const prerender.
ElementoQué hace
[slug].astroCaptura un segmento obligatorio de la URL
getStaticPaths()Devuelve el array de rutas { params, props } a generar
Astro.paramsValores capturados de la URL, dentro de la plantilla
Astro.propsDatos pasados por getStaticPaths, tipados con interface Props
export const prerenderFuerza o desactiva la generación estática por página

10 · Preguntas frecuentes

¿getStaticPaths puede ser async?

Sí. Al ejecutarse en build time puedes hacer await: leer ficheros, consultar una API o una base de datos. Devuelve el mismo array { params, props }. Es la base del «fetch en build time» que verás en el Módulo 5.

¿Puedo generar rutas que no salen de datos locales?

Por supuesto. getStaticPaths solo devuelve un array; su origen puede ser una lista estática, un fichero JSON, una llamada a una CMS o combinaciones. Lo único importante es la forma del array: { params, props }.

¿Qué pasa si dos entradas generan el mismo params?

Astro intentará generar la misma URL dos veces; la última ruta gana o recibes un aviso de colisión. Asegúrate de que tus identificadores (slugs, ids) son únicos. Es la misma regla que en bases de datos: la clave de la URL debe ser única.

¿Y si el visitante teclea una URL de blog que no existe?

Como esa ruta no está en getStaticPaths, no se generó ningún HTML. En un hosting estático acabará sirviendo tu 404.astro. Por eso es tan importante tener una buena página 404 que reconduzca al listado.

¿Conviene pasar objetos grandes por props?

Para el contenido visible, sin problema: los props no se serializan al HTML (se calculan en servidor y producen HTML). Lo que no debes pasar por props a una isla interactiva son objetos enormes, porque ahí sí cruzarían al cliente. En Módulo 4 verás exactamente esa diferencia.
