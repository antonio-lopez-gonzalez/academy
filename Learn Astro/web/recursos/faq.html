💡 General

¿Astro reemplaza a Next.js?

Depende del proyecto. Astro y Next.js resuelven problemas distintos:

Astro es ideal para: sitios de contenido (blogs, documentación, marketing, ecommerce), donde la mayor parte del contenido es estático y solo pequeñas partes necesitan interactividad.

Next.js es ideal para: aplicaciones web complejas con mucha interactividad (dashboards, SaaS, redes sociales), donde casi todo necesita ser interactivo.

La gran diferencia es la cantidad de JavaScript que envías al cliente. Astro envía 0 KB por defecto. Next.js envía ~70-100 KB de React solo para que funcione el framework, más tu código.

¿Necesito saber React para usar Astro?

No. Astro es un framework independiente. Su lenguaje de componentes nativo es .astro, que es HTML con JavaScript/TypeScript en el frontmatter. Puedes construir sitios completos sin tocar React, Vue o Svelte.

Si necesitas interactividad (un formulario, un carrusel, un chat), ahí sí necesitas un framework UI como React. Pero solo para esas "islas" concretas, no para toda la página. Y puedes elegir el que prefieras: Astro soporta React, Vue, Svelte, Solid, Preact... incluso combinarlos en un mismo proyecto.

¿Astro es solo para blogs?

No, aunque brilla especialmente en sitios de contenido. Astro es excelente para:

  • Landing pages y marketing: 100/100 en Lighthouse sin esfuerzo. Tailwind integrado de fábrica.
  • Documentación: Starlight, el tema oficial de docs para Astro, es probablemente la mejor herramienta actual para documentación técnica.
  • Ecommerce: Páginas de producto estáticas con carrito como isla interactiva.
  • Sitios institucionales: Rápido, seguro (sin JS en cliente), SEO perfecto.
  • Aplicaciones con zonas privadas: Con SSR puedes tener auth, sesiones y páginas protegidas.

🏝️ Islands

¿Qué es exactamente una "island"?

Una island (isla) es un componente de framework UI (React, Vue, Svelte...) que se hidrata de forma independiente del resto de la página. Imagina una página web como un océano de HTML estático con pequeñas islas de interactividad.

Cada isla se carga de forma aislada: su JavaScript, su estado y su hidratación no afectan a otras islas ni al HTML estático que las rodea. Esto es radicalmente distinto a un SPA, donde todo el árbol de componentes se hidrata de una vez.

Beneficio clave: si tienes un carrusel abajo del todo, su JavaScript no se descarga hasta que el usuario hace scroll y la isla se vuelve visible (client:visible). En un SPA, ese JS se descargaría al entrar aunque el usuario nunca haga scroll.

¿Puedo usar varios frameworks en un mismo proyecto Astro?

Sí, y es uno de los superpoderes de Astro. Puedes tener un componente React como carrusel, un componente Vue como selector de fechas y un componente Svelte como gráfico animado, todos en la misma página. Cada uno se hidrata de forma independiente.

En la práctica, los equipos suelen elegir un solo framework para mantener la consistencia. Pero poder mezclar es increíblemente útil durante migraciones o cuando necesitas una librería que solo existe para un framework concreto.

🧭 Routing

¿Cómo funciona el enrutamiento en Astro?

Astro usa file-based routing: la estructura de archivos dentro de src/pages/ define las URLs de tu sitio. Es idéntico al sistema de Next.js o Nuxt.

src/pages/index.astro        → /
src/pages/about.astro        → /about
src/pages/blog/index.astro   → /blog
src/pages/blog/[slug].astro  → /blog/:slug (dinámica)

Para rutas dinámicas, exportas getStaticPaths() y devuelves los parámetros. En modo SSG, Astro genera un HTML por cada ruta. En modo SSR, se renderiza bajo demanda.

📝 Content

¿Content Collections o archivos sueltos?

Siempre Content Collections para contenido estructurado. Las colecciones te dan:

  • Validación de esquemas con Zod: si un artículo no tiene title o la fecha tiene formato incorrecto, Astro te avisa en el build. Sin colecciones, un error de frontmatter se descubre en producción.
  • TypeScript automático: entry.data.title sabe que es string sin que declares nada.
  • Consultas tipadas: getCollection("blog") devuelve un array con tipos completos.

Usa archivos sueltos solo para páginas únicas (about, contact) que no forman parte de una colección repetible.

🚀 Producción

¿Dónde despliego un sitio Astro?

En prácticamente cualquier plataforma. El build de Astro genera una carpeta dist/ con HTML, CSS y JS estático que se puede servir desde cualquier hosting:

  • Vercel, Netlify: Soporte nativo con adaptadores oficiales. Despliegue con un git push. SSR incluido.
  • Cloudflare Pages: Excelente rendimiento global con CDN. Adaptador oficial.
  • GitHub Pages, GitLab Pages: Ideal para sitios estáticos. Build en CI/CD y despliegue automático.
  • Nginx, Apache, S3 + CloudFront: Cualquier hosting que sirva archivos estáticos.

Para SSR, necesitas un adaptador (Node, Vercel, Netlify, Cloudflare, Deno). El adaptador traduce las funciones de Astro a la plataforma de destino.
