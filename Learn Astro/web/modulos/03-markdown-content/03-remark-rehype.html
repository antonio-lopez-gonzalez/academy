Plugins remark y rehype

Módulo 3 · Markdown y Content 🕐 30 minutos

1 · Introducción

Cuando escribes Markdown, Astro no lo convierte a HTML «de golpe». Lo hace pasando el texto por una cadena de montaje de tres etapas: primero lo parsea a un árbol de Markdown (mdast), luego lo transforma en un árbol de HTML (hast) y por último lo serializa a HTML. Esa cadena es unified, y sus estaciones de trabajo son los plugins.

En la lección anterior conseguimos un índice manualmente filtrando headings. En esta aprendes a extender el procesador para generar un TOC automático, añadir anclas a los títulos, marcar enlaces externos, añadir tiempo de lectura y más. No es un detalle cosmético: es lo que separa un blog de juguete de uno profesional.

¿Por qué una arquitectura de plugins? Porque el Markdown estándar es pequeño a propósito. En lugar de meter todas las funciones imaginables en el lenguaje, unified ofrece un núcleo mínimo y un ecosistema enorme de plugins (remark para el árbol de Markdown, rehype para el de HTML). Tú decides qué añadir. Es el mismo diseño que Babel, PostCSS o ESLint: un motor y extensiones.

Cuándo lo usarás: cuando quieras una función de autoría que el Markdown base no trae: índice automático, anclas en títulos, tablas de contenidos, enlaces externos con target="_blank", tiempo de lectura, embeds, notas al pie con estilo… Aplica a Markdown y a MDX.

Errores típicos: añadir un plugin que hace lo que Astro ya hace por defecto (IDs de cabecera o GFM), confundir remark (antes de convertir a HTML) con rehype (después), olvidar instalar el paquete del plugin, y configurar los plugins en mdx() cuando querías que afectaran también a los .md.

2 · Teoría

La cadena de montaje de unified

Todo el proceso se llama pipeline y tiene dos tipos de estaciones según en qué momento actúan:

   Markdown (.md / .mdx)
        │
        ▼  remark  (plugins en el árbol de Markdown, mdast)
   mdast ── remark-gfm, remark-toc, remark de tu cosecha…
        │
        ▼  remark-rehype  (mdast → hast, lo hace Astro por dentro)
   hast  ── rehype-slug, rehype-autolink-headings, rehype-external-links…
        │
        ▼  rehype  (plugins en el árbol de HTML, hast)
   HTML final  ──▶  inyectado en el <slot /> del layout
TipoCuándo actúaQué manipulaEjemplos
remark (mdast)Antes de convertir a HTMLNodos de Markdownremark-toc, remark-gfm
rehype (hast)Después de convertir a HTMLNodos de HTMLrehype-slug, rehype-autolink-headings, rehype-external-links

Analogía: es una línea de embotellado. Los plugins remark trabajan con la fruta entera (el texto Markdown: puede reordenar secciones, insertar un índice). Los plugins rehype trabajan con el líquido ya envasado (el HTML: pueden añadir atributos a etiquetas, envolver enlaces). Según lo que quieras tocar, eliges una estación u otra.

Qué hace Astro ya por defecto

Antes de añadir plugins, conviene saber qué viene «de fábrica». Astro 5 usa unified como procesador por defecto y activa:

  • GitHub-flavored Markdown (tablas, tachado, listas de tareas, autolinks).
  • Smart punctuation (comillas tipográficas, guiones largos).
  • IDs en las cabeceras, generados con github-slugger, disponibles en headings.
  • Resaltado de sintaxis con Shiki en build time.

Nota de versiones: Astro 5 usa el procesador unified (el ecosistema remark/rehype que se explica aquí). Versiones posteriores están introduciendo markdown.processor con un procesador alternativo; si sigues una versión más nueva, consulta la documentación oficial de tu versión. Lo que aprendes aquí —remark antes de HTML, rehype después— es el modelo mental correcto.

Dónde se configuran

La configuración global vive en astro.config.mjs, dentro de la clave markdown. También se pueden configurar por colección, en defineCollection, para que solo cierta colección use ciertos plugins.

astro.config.mjs
import { defineConfig } from 'astro/config';
import remarkToc from 'remark-toc';                 // remark: índice automático
import rehypeSlug from 'rehype-slug';               // rehype: ids en cabeceras
import rehypeAutolinkHeadings from 'rehype-autolink-headings'; // anclas
import rehypeExternalLinks from 'rehype-external-links';       // enlaces externos

export default defineConfig({
  markdown: {
    // Se aplican ANTES de convertir a HTML (árbol de Markdown).
    remarkPlugins: [
      // Genera un índice a partir del heading "## Contenido"
      [remarkToc, { heading: 'contenido', tight: true }],
    ],
    // Se aplican DESPUÉS de convertir a HTML (árbol de HTML).
    rehypePlugins: [
      rehypeSlug, // añade id="…" a cada título (Astro ya lo hace: ejemplo didáctico)
      [rehypeAutolinkHeadings, { behavior: 'wrap' }], // envuelve el título en un <a>
      [rehypeExternalLinks, { target: '_blank', rel: ['noopener'] }],
    ],
    // Configuración del resaltador de código
    shikiConfig: {
      theme: 'github-dark', // o 'github-light', 'dracula', etc.
      wrap: true,           // ajusta líneas largas
    },
  },
});

Orden importa: los plugins se ejecutan en el orden del array. Si un plugin rehype necesita que los títulos ya tengan id, coloca antes el que los genera. Astro inyecta sus propios IDs después de tus plugins, por lo que un ID puesto por un plugin se respeta.

Plugins por colección

A veces solo una colección necesita un plugin (por ejemplo, la de documentación quiere TOC, el blog no). Se declara en el propio defineCollection:

const docs = defineCollection({
  loader: glob({ pattern: '**/*.md', base: './src/content/docs' }),
  schema: z.object({ title: z.string() }),
  // Solo esta colección usa estos plugins
  remarkPlugins: [[remarkToc, { heading: 'contenido' }]],
  rehypePlugins: [rehypeAutolinkHeadings],
});

Escribir tu propio plugin remark

No todo está en npm. Un caso clásico es calcular el tiempo de lectura y añadirlo al frontmatter. Un plugin remark es una función que devuelve un transformer con acceso al árbol (tree) y al fichero (file). Astro expone el frontmatter en file.data.astro.frontmatter:

src/utils/remark-reading-time.mjs
// mdast-util-to-string convierte cualquier nodo del árbol a texto plano.
import { toString } from 'mdast-util-to-string';

// Un plugin remark es una función que devuelve otra función (el transformer).
export function remarkReadingTime() {
  return function (tree, file) {
    // Todo el texto del documento, sin marcado.
    const text = toString(tree);
    // Estimación estándar: 200 palabras por minuto.
    const words = text.split(/\s+/).filter(Boolean).length;
    const minutes = Math.ceil(words / 200);
    // Escribimos el resultado en el frontmatter: quedará accesible después.
    file.data.astro.frontmatter.readingTime = `${minutes} min de lectura`;
  };
}

Después, al usar render(entry) en una colección, el valor calculado aparece en remarkPluginFrontmatter:

const { Content, remarkPluginFrontmatter } = await render(entry);
// remarkPluginFrontmatter.readingTime → '3 min de lectura'

Este patrón (plugin que enriquece el frontmatter) es uno de los más rentables: calculas una vez en build y lo muestras en las plantillas sin tocar el Markdown de cada post.

3 · Ejemplo mínimo

El plugin más pequeño y útil: añadir anclas a los títulos para poder enlazarlos. Necesitas el paquete y la config.

Terminal
# Instala los plugins con pnpm
pnpm add remark-toc rehype-slug rehype-autolink-headings
astro.config.mjs
import { defineConfig } from 'astro/config';
import rehypeAutolinkHeadings from 'rehype-autolink-headings';

export default defineConfig({
  markdown: {
    // Solo un plugin rehype: envuelve cada título en un enlace a sí mismo.
    rehypePlugins: [
      [rehypeAutolinkHeadings, { behavior: 'wrap' }],
    ],
  },
});
src/content/blog/ejemplo.md
---
title: Post con anclas
---

## Sección enlazable

Ahora este título genera un enlace permanente (`#seccion-enlazable`)
al que puedes apuntar desde cualquier parte.

Línea por línea: importamos el plugin y lo colocamos en markdown.rehypePlugins. La opción behavior: 'wrap' hace que el propio texto del título quede dentro del <a>. Como es un plugin rehype, actúa sobre el HTML ya generado: por eso puede envolver la etiqueta <h2> en un <a>. Abre la página y pasa el ratón por el título: es un enlace a #su-id. Sin escribir un ancla a mano en cada post.

4 · Ejemplo real

Combinamos varios plugins para dejar el blog del módulo «con acabado profesional»: índice automático, anclas en títulos, enlaces externos seguros y tiempo de lectura calculado por un plugin propio.

Instalación

Terminal
pnpm add remark-toc rehype-slug rehype-autolink-headings rehype-external-links mdast-util-to-string

El plugin propio: tiempo de lectura

src/utils/remark-reading-time.mjs
import { toString } from 'mdast-util-to-string';

// Añade `readingTime` al frontmatter de cada Markdown/MDX procesado.
export function remarkReadingTime() {
  return (tree, file) => {
    const words = toString(tree).split(/\s+/).filter(Boolean).length;
    // 200 palabras por minuto es la convención habitual.
    file.data.astro.frontmatter.readingTime = `${Math.ceil(words / 200)} min`;
  };
}

La configuración completa

astro.config.mjs
import { defineConfig } from 'astro/config';
import mdx from '@astrojs/mdx';
import remarkToc from 'remark-toc';
import rehypeSlug from 'rehype-slug';
import rehypeAutolinkHeadings from 'rehype-autolink-headings';
import rehypeExternalLinks from 'rehype-external-links';
import { remarkReadingTime } from './src/utils/remark-reading-time.mjs';

export default defineConfig({
  integrations: [mdx()], // MDX hereda esta configuración de Markdown
  markdown: {
    remarkPlugins: [
      remarkReadingTime, // 1) cálculo del tiempo de lectura
      // 2) índice automático: busca el heading "## Contenido" y lo rellena
      [remarkToc, { heading: 'contenido', tight: true }],
    ],
    rehypePlugins: [
      rehypeSlug, // IDs en los títulos
      [rehypeAutolinkHeadings, { behavior: 'wrap' }],
      // Los enlaces externos abren en pestaña nueva, de forma segura
      [rehypeExternalLinks, { target: '_blank', rel: ['noopener', 'noreferrer'] }],
    ],
    shikiConfig: {
      theme: 'github-dark',
      wrap: true,
    },
  },
});

Decisiones: remark-reading-time es nuestro y va primero porque solo enriquece el frontmatter. remark-toc genera el índice antes de la conversión a HTML (por eso es remark: reordena/inserta nodos de Markdown). rehype-slug y rehype-autolink-headings actúan ya sobre el HTML para poner y envolver los id. rehype-external-links añade target y rel a los enlaces externos, una práctica de seguridad y UX. Y Shiki colorea el código sin JavaScript. Todo el trabajo ocurre en build: al navegador solo llega HTML.

Depuración: si el TOC no aparece, revisa que exista un heading ## Contenido con esa palabra exacta (o cambia la opción heading). Si un plugin no hace nada, comprueba el orden en el array y que el paquete esté realmente instalado (pnpm ls remark-toc). Recuerda reiniciar pnpm dev cuando cambies astro.config.mjs.

6 · Errores habituales

Error 1 — Confundir remark y rehype

Mal — rehype en la lista de remark 
import rehypeAutolinkHeadings from 'rehype-autolink-headings';

export default defineConfig({
  markdown: {
    // Un plugin de HTML no debe ir aquí: opera sobre nodos de Markdown
    remarkPlugins: [rehypeAutolinkHeadings],
  },
});
Bien 
export default defineConfig({
  markdown: {
    rehypePlugins: [[rehypeAutolinkHeadings, { behavior: 'wrap' }]],
  },
});

Error 2 — Olvidar instalar el paquete

Mal — importar algo que no existe 
import remarkToc from 'remark-toc'; // Error: Cannot find package 'remark-toc'
Bien 
pnpm add remark-toc

Error 3 — Configurar en mdx() cuando querías todo el Markdown

Los plugins dentro de mdx() solo afectan a los ficheros .mdx. Si quieres que apliquen también a los .md, configúralos en markdown (los MDX los heredan). Si solo quieres afectar a MDX y no a Markdown, entonces sí van en mdx().

Error 4 — Duplicar lo que Astro ya hace

// Astro ya genera los ids de las cabeceras con github-slugger.
// Añadir rehype-slug «por si acaso» puede chocar en el orden de ejecución.
markdown: { rehypePlugins: [rehypeSlug] }

Conocer los defaults evita plugins redundantes. rehype-slug solo tiene sentido si necesitas que tus IDs se generen antes que otros plugins, o si quieres personalizar el slug.

8 · Reto

⏱️ Tiempo de lectura propio (sin librería)

Escribe tu propio plugin remark remarkReadingTime que cuente las palabras del documento y escriba readingTime (en minutos) en el frontmatter. Después muéstralo en el BlogLayout junto a la fecha. Ajusta la velocidad a 220 palabras/minuto y comprueba con un post largo que el valor es razonable.

Pista: un plugin remark es () => (tree, file) => { ... }. Para obtener el texto plano del árbol usa toString de mdast-util-to-string (pnpm add mdast-util-to-string). El frontmatter se escribe en file.data.astro.frontmatter, y lo recuperas con const { remarkPluginFrontmatter } = await render(post);. Recuerda que los plugins propios deben registrarse en markdown.remarkPlugins y que el servidor hay que reiniciarlo al cambiar la config.

9 · Resumen

  • Astro procesa Markdown con unified: Markdown → mdast → hast → HTML.
  • remark = plugins del árbol de Markdown; rehype = plugins del árbol de HTML.
  • Se configuran en astro.config.mjs (markdown.remarkPlugins / rehypePlugins) o por colección en defineCollection.
  • Astro ya trae GFM, smart punctuation, IDs de cabecera y Shiki; no los dupliques.
  • El orden del array importa: un plugin que usa los id va después del que los crea.
  • Puedes escribir plugins propios para enriquecer el frontmatter (tiempo de lectura, etc.).
  • Todo ocurre en build time: el HTML sale listo y sin JavaScript extra.

10 · Preguntas frecuentes

¿Los plugins afectan a MDX?

Sí: los MDX heredan la configuración markdown. Si quieres reglas distintas para MDX, configúralas dentro de mdx(). Ten presente que solo los plugins compatibles con el árbol de Markdown/HTML funcionan en MDX; los «recma» (que operan sobre el árbol JSX) van aparte.

¿Puedo escribir un plugin en TypeScript?

Sí. Un plugin es una función normal; puedes escribirla en .ts y tiparla con las utilidades de unified (Plugin, Root…). Recuerda que astro.config.mjs importa el plugin; si usas TS para el plugin, importa el fichero compilado o usa .mjs para evitar sorpresas.

¿Los plugins se ejecutan en el navegador?

No. Se ejecutan en build time (o por petición en SSR), dentro de Node. El navegador solo recibe el HTML resultante. Por eso estos plugins son un ejemplo perfecto de «trabajo que se hace una vez y no cuesta nada al visitante».

¿Cómo sé si un plugin es remark o rehype?

Por su nombre y por lo que manipula: los que empiezan por remark- trabajan con Markdown; los que empiezan por rehype-, con HTML. Si necesitas reordenar o insertar contenido en el Markdown, remark; si necesitas añadir atributos a etiquetas del HTML resultante, rehype.

¿Y si dos plugins entran en conflicto?

Casi siempre el problema es el orden de ejecución. Reordena el array y vuelve a probar: el plugin que necesita datos de otro debe ir después. Si aún así chocan, aísla cada uno en un proyecto mínimo para identificar cuál falla. La documentación de unified recomienda probar los plugins por separado.
