Crear una transacción por mensaje JSON

Módulo 4 · Instrumentar WebSocket ⏱ 40 minutos

1 · Introducción

La columna vertebral de tu WebSocket observable: cada mensaje entrante genera una transacción nombrada correctamente como OtherTransaction. Sobre ella colgarás atributos, errores, spans y propagación W3C.

Esta lección te da el patrón completo y ejecutable: handler async con WebSocket, parseo con System.Text.Json y la transacción colocada en el sitio exacto para que no mida «tiempo muerto» del socket.

La trampa que evitamos: si abarcas la espera del ReceiveAsync dentro de la transacción, medirás el tiempo de espera del siguiente mensaje (ruido), no el trabajo. El truco es marcar la transacción después de recibir, o usar la transacción solo alrededor del procesado.

2 · Teoría

La forma correcta

ReceiveAsync (espera bloqueante — fuera de la transacción)
   │
   ▼
ParseJson   (recogida y validación mínima)
   │
   ▼
OnMessage()  [Transaction] — aquí se mide el "trabajo útil" del mensaje
   │   ├── AcceptDistributedTraceHeaders  (línea M3-04)
   │   ├── atributos (type, messageId, userId…)
   │   ├── dispatch por tipo → [Trace] de negocio
   │   └── errores con NoticeError
   ▼
respuesta opcional (SendAsync) con spans propios

Si envías respuesta al cliente, el SendAsync debe estar dentro de la transacción para que se mida (o con su propio [Trace]), pero nunca bloqueando la transacción con la espera del siguiente frame.

Async y transacciones

Los atributos y la API del agente funcionan con async/await; el agente mantiene el contexto de transacción del mensaje. La única advertencia: en procesado muy paralelo (Task.Run, hilos del TP) el «CurrentTransaction» puede no coincidir con tu mensaje — mantenlo predecible o propaga explícitamente.

3 · Ejemplo mínimo

using NewRelic.Api.Agent;

public sealed class MessageDispatcher
{
    // Solo el "trabajo" del mensaje se mide como transacción
    [Transaction]
    public void OnMessage(MessageEnvelope msg)
    {
        IAgent agent = NewRelic.Api.Agent.NewRelic.GetAgent();
        var txn = agent.CurrentTransaction;

        txn.AddCustomAttribute("messageType", msg.Type);
        txn.AddCustomAttribute("messageId", msg.MessageId);

        // Acepto el contexto W3C si el cliente lo incluyó
        txn.AcceptDistributedTraceHeaders(
            msg.TraceContext,
            static (env, key) =>
                env.TraceContext.TryGetValue(key, out var v) ? [v] : [],
            TransportType.Other);   // no hay valor WebSocket; usamos Other

        // dispatch
        _handlers[msg.Type](msg);
    }
}

4 · Ejemplo real

Handler WebSocket completo con System.Net.WebSockets:

public class WsServer
{
    private readonly MessageDispatcher _dispatcher;

    public async Task Handle(WebSocket socket)
    {
        var buffer = new byte[4 * 1024];
        while (socket.State == WebSocketState.Open)
        {
            // 1) Esperar (FUERA de la transacción)
            var result = await socket.ReceiveAsync(buffer, CancellationToken.None);
            if (result.MessageType == WebSocketMessageType.Close) break;

            // 2) Convierte los bytes que llegan a texto
            var json = Encoding.UTF8.GetString(buffer, 0, result.Count);
            var msg = Parse(json);   // MessageEnvelope

            // 3) Trabajo por mensaje (la transacción)
            _dispatcher.OnMessage(msg);
        }
    }

    private static MessageEnvelope Parse(string json) =>
        JsonSerializer.Deserialize<MessageEnvelope>(json)
        ?? throw new InvalidDataException("JSON nulo");
}

Con esto: cada trade, ping o disconnect es una transacción con sus atributos, y la duración media mide solo el procesado.

6 · Errores habituales

Transacción alrededor del ReceiveAsync

// ❌ Recibe… y mientras espera, la transacción está "abierta"
[Transaction]
public async Task Handle(WebSocket socket)
{
    while (socket.State == WebSocketState.Open)
    {
        var result = await socket.ReceiveAsync(...);  // ⏳ duración = espera
        OnMessage(Parse(result));                       // trabajo escondido
    }
}

// ✅ El [Transaction] va en OnMessage (procesado), ReceiveAsync fuera

Resincronizar en hilos del pool sin contexto

// ❌ CurrentTransaction puede apuntar a otra cosa en Task.Run
await Task.Run(() => ProcessHeavy(msg));   // timer ajeno

// ✅ O procesa sin Task.Run para conservar el contexto de transacción,
//    o instrumenta explícitamente dentro (y acepta el contexto ahí)

No aceptar el contexto del mensaje en el primer procesado

Si no llamas a AcceptDistributedTraceHeaders, tu nuevo traceId ignora el que llevaba el mensaje.

9 · Resumen

  • [Transaction] en el «procesado» del mensaje, no en la espera del socket.
  • Atributos estables + AcceptDistributedTraceHeaders por mensaje.
  • La respuesta (SendAsync) dentro de la transacción.
  • Ojo con Task.Run: preserva el contexto de transacción.

10 · Preguntas frecuentes

¿Es caro tener transacción por mensaje con miles de mensajes/minuto?

Los eventos Transaction se generan en cliente con sampling de trazas; el volumen controlado y los facets y métricas lo mantienen en la green band. Si es enorme, sustituye la transacción por métricas y conserva trazas muestreadas.

¿Tengo que usar [Transaction] o puedo crear transacciones desde la API?

Para .NET lo idiomático son los atributos. La API te da IAgent.CurrentTransaction pero necesitas que exista una transacción; crearla la hacen los atributos o el XML.

¿El agente mide el tamaño del payload?

No por defecto. Añade tú sizeBytes con AddCustomAttribute si quieres.
