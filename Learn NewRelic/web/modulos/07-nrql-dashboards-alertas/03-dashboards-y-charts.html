Dashboards y charts

Módulo 7 · NRQL, Dashboards y Alertas ⏱ 35 minutos

1 · Introducción

Una consulta se usa una vez; un dashboard se mira todos los días. New Relic One dashboards agrupan charts construidos sobre NRQL, con variables para filtrar (por app, por entorno), versiones para comparar y permisos para compartir.

Esta lección: cómo construir el «panel de mando» de tu WebSocket con criterio, en vez de amontonar widgets.

2 · Teoría

Estructura del dashboard

  • Dashboard: contenedor de widgets (charts y tablas), con un período global.
  • Widget: una consulta NRQL + tipo de visualización (line, area, bar, table, billboard, …).
  • Variable: parámetro configurable (appName, environment) que reutilizas en todas las consultas del dashboard.
  • Versiones: snapshot del dashboard en el tiempo (para comparar cuando cambias widgets).

Cómo se usa una variable en la query

-- {@appName} se sustituye con el valor de la variable antes de ejecutar
SELECT count(*) FROM Transaction
WHERE appName = '{appName}'
SINCE 1 hour ago FACET messageType

Si definas la variable appName con valores (dev/prod), cambias de app con un menú sin tocar cada widget.

Tipos de chart según la pregunta

PreguntaChart
Evolución de volumen/latenciaLine/area con TIMESERIES
Ranking por tipoBar con FACET
Un único dato clave (Apdex, clientes conectados)Billboard
Lista de errores/spansTable con ORDER BY

Menos es más: un dashboard operativo enciende alarmas cuando algo cambia, no cuando esconde el dato entre 40 gráficos. Empieza por 6-8 widgets que respondan a las preguntas que definiste en M0-01.

3 · Ejemplo mínimo

Crear un widget de línea desde Query Builder («Save as chart»):

SELECT rate(count(*), 1 minute) FROM Transaction
WHERE appName = '{appName}'
FACET messageType SINCE 1 hour ago TIMESERIES 1 minute

Así tienes la evolución de mensajes por minuto y por tipo, filtrable por app.

4 · Ejemplo real

«Dashboard de operaciones WebSocket» en 8 widgets:

WidgetQuery
Mensajes/minSELECT rate(count(*), 1 minute) FROM Transaction WHERE name LIKE 'OtherTransaction/%' ...
p95 por tipoSELECT percentile(duration, 95) FROM Transaction FACET messageType ...
Errores/esperadosSELECT count(*) FROM TransactionError FACET error.expected, error.class ...
Latencia de colaSELECT percentile(metricTimeslice.value, 95) FROM Metric WHERE metricName='Custom/QueueLatencyMs' ...
Tiempo de broadcastSELECT average(metricTimeslice.value) FROM Metric WHERE metricName='Custom/BroadcastMs' ...
ApdexSELECT apdex(duration, t: 0.5) FROM Transaction
Top spans lentosSELECT name, max(duration.ms) FROM Span FACET name ORDER BY max(duration.ms) DESC LIMIT 10
Órdenes por monedaSELECT count(*) FROM OrderPlaced FACET currency ...

Con una variable appName, un menú cambia todo el tablero entre entornos.

6 · Errores habituales

Variables con nombre de atributo equivocado

-- ❌ WHERE appName = '{application}'   (variable no definida)
-- ✅ Define la variable "application" (o usa {appName})

FACET con muchos valores sin LIMIT

-- ❌ FACET messageType LIMIT 10     (valor alto que desordena)
-- ✅ Añade ORDER BY count(*) DESC LIMIT 10

7 · Ejercicio guiado

  1. Paso 1: Crea un dashboard «Operaciones WebSocket».
  2. Paso 2: Añade la variable appName con tus valores.
  3. Paso 3: Añade 4 widgets: mensajes/min, p95, errores, latencia de cola (usa {appName} en todos).
  4. Paso 4: Cambia la variable en la cabecera y verifica que todo el tablero se actualiza.

8 · Reto

🎯 Tu tablero de mando

Define el dashboard definitivo de tu WebSocket (máx. 10 widgets) y ordénalos por «¿qué observa un humano que entró a las 3 AM?». Justifica el orden y qué alerta le pedirías en cada uno. Lo construiremos juntos en M8.

9 · Resumen

  • Dashboard = contenedor de widgets NRQL con variables globales.
  • Variable {var} se sustituye en las queries; facilita filtro por app/entorno.
  • Chart según pregunta: línea/evolución, bar/ranking, billboard/dato, table/crudo.

10 · Preguntas frecuentes

¿Puedo importar/exportar dashboards?

Sí (JSON) y hay plantillas listas para instrumentar. Exportar facilita mover entre cuentas o versionar en Git.

¿Puedo hacer clic de un widget a otro?

Los widgets con FACET permiten drilling; los dashboards encadenan con variables y entidades (entity explorer).
