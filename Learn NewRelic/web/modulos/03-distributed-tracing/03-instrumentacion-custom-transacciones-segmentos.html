Instrumentación custom: atributos [Transaction] y [Trace]

Módulo 3 · Distributed Tracing y traceId ⏱ 40 minutos

1 · Introducción

Aquí empieza de verdad la «tuya»: la instrumentación que el agente no hace sola. El agente .NET ofrece dos mecanismos: atributos en tu código ([Transaction], [Trace]) e instrumentación XML sin tocar código. Empezamos por los atributos, que son la vía natural en un WebSocket en C#.

Verás cuándo crear una transacción y cuándo añadir detalle a una existente, cómo clasificarla web/no-web y las reglas de oro (métodos concretos, no Main, no interfaces).

2 · Teoría

Dos preguntas antes de instrumentar

¿Tu método NO aparece en la UI?Acción
Sí, aparece pero tiene huecos sin detalleCrear detalle → [Trace]
No aparece en absoluto (tu WebSocket)Crear transacción → [Transaction]

Un método con [Transaction] crea transacción solo si no hay ninguna en curso; si se llama dentro de otra transacción, se comporta como [Trace] (detalle). Este comportamiento es perfecto para tu handler: si lo llamas desde el middleware del mensaje (sin transacción HTTP), crea su propia transacción «non-web».

Cómo se ve

using NewRelic.Api.Agent;   // atributos viven aquí (en NewRelic.Agent.Api)

// Crea UNA TRANSACCIÓN non-web cuando no haya ninguna en curso
[Transaction]
public void ProcessOrderMessage(MessageEnvelope msg) { ... }

// Crea transacción web (por ejemplo un endpoint que quieras medir como web)
[Transaction(Web = true)]
public void RunHealthCheck() { ... }

// Añade DETALLE (segmento) dentro de una transacción ya existente
[Trace]
private void ParsePayload(JsonElement payload) { ... }

Reglas y requisitos

  • Requiere el paquete NewRelic.Agent.Api y using NewRelic.Api.Agent;.
  • Los atributos van en implementaciones concretas, no en interfaces ni definiciones de clase base.
  • Evita instrumentar Main()/métodos de vida larga: como no terminan, podrían retrasar el envío de datos.
  • Si un [Trace] no aparece, prueba [MethodImpl(MethodImplOptions.NoInlining)] (evita que el JIT inline lo haga invisible al profiler).
  • Ejecuta en Release, no Debug: el modo debug puede ocultar métodos al profiler.

¿Y los nombres?

El nombre de transacción sale del método. Si quieres agruparlo por dominio, usa SetTransactionName dentro (M2-01) o XML de instrumentación para renombrados potentes.

Alternativa XML: si no quieres tocar código, el agente acepta un archivo XML en newrelic.config que marca métodos. Los XML-created transactions son siempre non-web. Para este curso usaremos atributos (más legibles y testables).

3 · Ejemplo mínimo

using NewRelic.Api.Agent;

public class TradeProcessor
{
    // Cada llamada crea una OtherTransaction/.../ProcessTrade
    [Transaction]
    public void ProcessTrade(TradeMessage trade)
    {
        Parse(trade);          // [Trace] → segmento ProcessDetail?
        Apply(trade);
    }

    // Detalle dentro de la transacción
    [Trace]
    private void Apply(TradeMessage trade)
    {
        // ... lógica de negocio ...
    }
}

Al mirar APM verás una transacción OtherTransaction/.../ProcessTrade con su segmento Apply. Ese es el «corazón del mensaje» que antes era invisible.

4 · Ejemplo real

Modelo típico para un WebSocket: transacción por mensaje, detalle en las fases:

public class MessageDispatcher
{
    [Transaction]                       // 1 mensaje = 1 transacción
    public void Dispatch(MessageEnvelope msg)
    {
        _agent.CurrentTransaction
            .AddCustomAttribute("messageType", msg.Type)
            .AddCustomAttribute("messageId", msg.MessageId);

        switch (msg.Type)
        {
            case "trade": _tradeProcessor.ProcessTrade(msg);   break;
            case "ping":  _pingProcessor.Respond(msg);         break;
            default:      _logger.LogWarning("unknown {Type}", msg.Type); break;
        }
    }
}

public class TradeProcessor
{
    [Trace]
    public void ProcessTrade(MessageEnvelope msg) { /* ... */ }
}

Ahora la pregunta «p95 de procesar un trade» es una consulta NRQL que agrupa por name o por messageType.

6 · Errores habituales

Atributo en una interfaz

// ❌ No funciona: el agente instrumenta implementaciones concretas
public interface ITradeProcessor
{
    [Transaction]
    void ProcessTrade(TradeMessage t);
}

// ✅ En la clase concreta
public sealed class TradeProcessor : ITradeProcessor
{
    [Transaction]
    public void ProcessTrade(TradeMessage t) { ... }
}

Instrumentar Main()

// ❌ Main() vive hasta terminar el proceso: retrasa el envío
[Transaction]
public static void Main(string[] args) { ... }

// ✅ Transacción en los métodos de trabajo (loop de mensajes)

Esperar que aparezca «ya» en la UI

Los atributos solo funcionan si el profiler está adjunto (NewRelic.Agent + env vars). Sin agente, no se reporta nada — la API es no-op.

8 · Reto

🎯 [Transaction] vs [Trace]

Explica con tus palabras cuándo crearías una transacción y cuándo solo detalle, y pon dos ejemplos reales de tu app. Además, investiga el SetTransactionUri() de la API y para qué se usa con [Transaction(Web = true)].

9 · Resumen

  • [Transaction] crea transacción si no existe (web con Web = true); en una existente actúa como [Trace].
  • [Trace] añade detalle (segmento) a la transacción en curso.
  • Solo en métodos concretos; no Main(); Release build.
  • Atributos + AddCustomAttribute = transacción de negocio con contexto.

10 · Preguntas frecuentes

¿Por qué no aparece mi [Trace] en los traces?

Comprueba: Release, NoInlining si hace falta, método concreto, agente adjunto, y que la transacción que lo contiene sea muestreada (sampleada).

¿Puedo aplicar atributos a métodos async?

El agente sigue a los methodoes marcados con los atributos; para async/await el timing se mide sobre el método. Para trabajo muy concurrente (Task.Run) revisa que la transacción «actual» siga siendo la del hilo correcto; en esos casos se usa la API de headers (M3-04) o con cuidado el contexto.

¿Qué diferencia hay con el XML?

El XML no exige tocar código ni recompilar, pero es frágil (nombres exactos) y sus transacciones siempre son non-web. Los atributos son la vía recomendada en el curso.
