Instalación y compatibilidad (NuGet)

Módulo 1 · El agente APM de New Relic para .NET ⏱ 35 minutos

1 · Introducción

Instalar el agente de New Relic en un proyecto .NET moderno es tan simple como añadir un paquete NuGet… y conocer bien cuatro variables de entorno. Esa es la diferencia con las instalaciones MSI del pasado: hoy el agente viaja en la carpeta de salida de tu app.

Verás la instalación recomendada (NuGet), cuáles son los target frameworks y plataformas soportados, y cómo se adjunta el profiler en Windows y Linux.

2 · Teoría

El paquete NewRelic.Agent (recomendado)

El método oficial para .NET (Core/5+) es el paquete NewRelic.Agent: al publicar tu app, coloca dentro de bin\newrelic\ el profiler (NewRelic.Profiler.dll) y la configuración, sin necesidad de instalación de sistema. Incluye profilers para Windows (x86/x64) y Linux (x64/arm64).

Si además vas a usar la API de instrumentación custom (lo harás en este curso), referencía también NewRelic.Agent.Api.

Qué variables necesita el profiler (Windows, .NET Core)

CORECLR_ENABLE_PROFILING=1
CORECLR_PROFILER={36032161-FFC0-4B61-B559-F6C5D41BAE5A}
CORECLR_PROFILER_PATH=C:\ruta\a\bin\newrelic\NewRelic.Profiler.dll
CORECLR_NEWRELIC_HOME=C:\ruta\a\bin\newrelic

En Linux, en lugar de NewRelic.Profiler.dll apuntas a libNewRelicProfiler.so (o linux-arm64/libNewRelicProfiler.so). El propio paquete NuGet genera estas variables en el entorno de ejecución de tu app; tú solo necesitas NEW_RELIC_LICENSE_KEY y NEW_RELIC_APP_NAME.

Alternativa MSI (Windows / IIS)

Para hosts clásicos (IIS, NT Service), el instalador MSI escribe el profiler en C:\Program Files\New Relic\.NET Agent\, la configuración en C:\ProgramData\New Relic\.NET Agent\ y registra las variables de IIS automáticamente. Para procesos .NET Core no-IIS sigue haciendo falta fijar CORECLR_ENABLE_PROFILING.

Recomendación del curso: usa NuGet en tus proyectos .NET 8 modernos y aporta versionado, reproducibilidad y despliegue en contenedores. Reserva el MSI para servidores Windows con IIS heredado.

3 · Ejemplo mínimo

Desde la carpeta de tu proyecto:

dotnet add package NewRelic.Agent
dotnet add package NewRelic.Agent.Api

# Variables de entorno para adjuntar el profiler al ejecutar
export NEW_RELIC_LICENSE_KEY=YOUR_LICENSE_KEY
export NEW_RELIC_APP_NAME=NotificadorWebSocket

dotnet run

Verás en la consola mensajes del agente (p. ej. referencias a que «the agent has started»). En ~1 minuto, la entidad aparece en APM & services.

4 · Ejemplo real

Contenedor Docker (multistage) con el agente por NuGet:

# stage de build
FROM mcr.microsoft.com/dotnet/sdk:8.0 AS build
WORKDIR /src
COPY ["NewRelicWsDemo.csproj", "."]
RUN dotnet restore .

# stage de runtime
FROM mcr.microsoft.com/dotnet/aspnet:8.0 AS runtime
WORKDIR /app
COPY --from=build /src/publish .
# El agente ya viaja en ./newrelic por el paquete NewRelic.Agent
ENV NEW_RELIC_LICENSE_KEY=YOUR_LICENSE_KEY
ENV NEW_RELIC_APP_NAME=NotificadorWebSocket
# El paquete define CORECLR_* al arrancar; si no, defínelas aquí
ENTRYPOINT ["dotnet", "NewRelicWsDemo.dll"]

En Kubernetes, mejor inyectar la clave desde un Secret (visto en M0-03) y activar el agente vía env vars del deployment.

6 · Errores habituales

Añadir solo la API y esperar datos

# ❌ dotnet add package NewRelic.Agent.Api   → solo API (sin profiler)
# ✅ Añade también NewRelic.Agent           → profiler + config en bin/newrelic

Confundir COR_ vs CORECLR_

# ❌ COR_PROFILER={...}   (solo para .NET Framework)
# ✅ CORECLR_PROFILER={36032161-FFC0-4B61-B559-F6C5D41BAE5A}  (.NET 8)

Publicar con trim/AOT y esperar el agente

# ❌ dotnet publish -p:PublishTrimmed=true  + agente
# ✅ Usa publish normal; si necesitas AOT, plantéate OTel/OTLP (Módulo 6)

7 · Ejercicio guiado

  1. Paso 1: En una copia del proyecto newrelic-ws-demo, añade NewRelic.Agent y NewRelic.Agent.Api.
  2. Paso 2: Publica con dotnet publish -c Release -o ./publish y comprueba que existe publish/newrelic/NewRelic.Profiler.dll.
  3. Paso 3: Fija NEW_RELIC_LICENSE_KEY y NEW_RELIC_APP_NAME, ejecuta y confirma en la consola que el agente arranca.
  4. Paso 4: Si tu cuenta no está en US, añade NEW_RELIC_HOST=collector.eu.newrelic.com (o el de tu región).

8 · Reto

🎯 Agente en contenedor

Sin instalar nada local, escribe el Dockerfile multistage completo que ejecute la app con el agente adjunto e inyecte la clave desde una variable de entorno SECRET_NEWRELIC. Pruébalo con docker build si tienes Docker; si no, explica qué haría en tu CI/CD.

9 · Resumen

  • Instalación recomendada: NewRelic.Agent (profiler) + NewRelic.Agent.Api (API).
  • Soporte: .NET 5–10 y .NET Framework 4.6.2+; Windows y Linux; no AOT/trimmed.
  • El profiler se adjunta con variables CORECLR_* (Windows) o apuntando a .so en Linux; el paquete lo gestiona.
  • Siempre: NEW_RELIC_LICENSE_KEY + NEW_RELIC_APP_NAME (+ NEW_RELIC_HOST fuera de US).

10 · Preguntas frecuentes

¿El paquete NuGet vale para producción o solo dev?

Vale para todo. Es el método recomendado para .NET moderno; el MSI es para hosts/IIS heredados. En contenedores, NuGet es la vía natural.

¿Necesito reiniciar algo al cambiar config?

Con variable de entorno, reinicicias el proceso. Con newrelic.config en IIS, a veces hace falta iisreset o reiniciar el pool.

¿Cuál es la última versión estable?

El paquete NewRelic.Agent/NewRelic.Agent.Api publica versiones 10.x (a la fecha de este curso, 10.54.0). Compruébalo en nuget.org al instalar.
