Atributos y AddCustomAttribute

Módulo 2 · Transacciones, Métricas y Errores ⏱ 30 minutos

1 · Introducción

El agente añade atributos estándar a cada evento (appName, duration, traceId…). Pero la información tuya (tipo de mensaje, usuario, versión, región) solo llega si la añades tú. Esa es una de las decisiones de diseño más rentables de la observabilidad: los custom attributes.

Verás cómo añadirlos a transacciones y a spans, qué tipos acepta la API y cómo usarlos con WHERE/FACET casi al instante.

2 · Teoría

Atributos de transacción vs. de span

NivelAPIDónde aparece
Transacciónagent.CurrentTransaction.AddCustomAttribute(key, value)En el evento Transaction
Spanagent.CurrentSpan.AddCustomAttribute(key, value)En el span concreto del trace

Tipos soportados y reglas

  • string (truncada a 255 bytes), bool, números (enteros/decimal), DateTime (ISO-8601), TimeSpan (segundos), arrays/List (como JSON, desde agente 10.50+).
  • null no se registra; los keys vacíos no se registran y van limitados a 255 bytes.
  • Otras cosas: se aplica ToString() (asegúrate de tenerlo implementado).

Las dos reglas de oro de DI

Regla 1: Regístrate IAgent de forma lazy (lambda), porque GetAgent() debe ejecutarse cuando el profiler ya está adjunto. Regla 2: CurrentTransaction y CurrentSpan no se cachean en campos: hay que leerlos en cada uso, porque representan la petición actual.

// ❌ Eager: puede capturar el placeholder no-op si el profiler aún no
//   está: servicio muerto en silencio
builder.Services.AddSingleton<IAgent>(NewRelic.Api.Agent.NewRelic.GetAgent());

// ✅ Lazy: se resuelve a la primera inyección, con el profiler listo
builder.Services.AddSingleton<IAgent>(_ => NewRelic.Api.Agent.NewRelic.GetAgent());
// ❌ Cachear ITransaction en un campo: te quedas fijada a OTRA petición
private readonly ITransaction _txn;
public Worker(IAgent agent) => _txn = agent.CurrentTransaction;

// ✅ Leer por llamada
public void Process(Message msg)
{
    _agent.CurrentTransaction.AddCustomAttribute("messageType", msg.Type);
}

3 · Ejemplo mínimo

using NewRelic.Api.Agent;

IAgent agent = NewRelic.Api.Agent.NewRelic.GetAgent();

// Atributo a la transacción actual
agent.CurrentTransaction
     .AddCustomAttribute("messageType", msg.Type)
     .AddCustomAttribute("userId", msg.UserId)
     .AddCustomAttribute("sizeBytes", msg.SizeBytes)
     .AddCustomAttribute("sentAt", msg.Timestamp);

// Atributo al span actual (los spans de trazas distribuidas)
agent.CurrentSpan.AddCustomAttribute("symbol", symbol);

Nota: AddCustomAttribute devuelve la transacción/span para encadenar.

4 · Ejemplo real

Piensa en atributos por dimensión de negocio, no por instancia:

AtributoCardinalidadPregunta que habilita
messageTypeBaja (5–20 tipos)¿qué tipo es más lento/falla?
userIdMedia/alta — usar con cuidado¿qué usuarios sufren más latencia?
env/regionMuy baja (prod/staging)comparar rendimiento por entorno
versionBajadetectar regresiones al desplegar
traceIdAltísima — NO lo pongas túya lo añade el agente (M3)

Cardinalidad importa para el coste. Un atributo de alta cardinalidad multiplica los datos indexados. Úsalo en transacciones que ya pagas, no lo difundas a logs masivos.

6 · Errores habituales

Atributo con valor alto en cardinalidad en logs forwardeados

// ❌ Cada log de cada mensaje lleva un identificador único:
_logger.LogInformation("Procesado {uniqueId}", msg.UniqueId);

// ✅ El traceId ya correlaciona; añade atributos de bajo volumen al mensaje
//    y deja los logs de parsing con su contexto de nivel bajo-medio

Esperar que el atributo aparezca «al instante» en la query

Los nuevos atributos requieren un momento para ser facetables en NRQL y deben existir con datos. Verifícalos empíricamente con una query, no con intuición.

9 · Resumen

  • Custom attributes = contexto de negocio en transacciones y spans.
  • Tipos: string, bool, numérico, DateTime, TimeSpan, arrays; no se registran null/empty.
  • DI: IAgent lazy; CurrentTransaction/CurrentSpan por cada llamada.
  • Cardinalidad baja-media; nombres estables; centraliza constantes.

10 · Preguntas frecuentes

¿Los atributos van a eventos y a logs?

Los que añades a la transacción van al evento Transaction y (según config) a logs. Los de span van al span. Hay separación por decisión de diseño.

¿Puedo añadir atributos a un custom event?

Sí: es la tercera forma, vía RecordCustomEvent("Tipo", attrs), con atributos solo para ese evento (máx. 64).

¿Los atributos con PII son un problema?

Sí: los datos van a tu cuenta y quedan indexados. Excluye lo sensible con <attributes> en config o no los envíes.
