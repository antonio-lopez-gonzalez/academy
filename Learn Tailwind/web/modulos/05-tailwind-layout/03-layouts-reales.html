Layouts reales compuestos

Módulo 5 · Tailwind: Layout ⏱ 35 minutos

1 · Introducción

Ya dominas Flex y Grid por separado. Ahora viene lo importante: combinarlos para construir layouts reales. En el mundo profesional, ningún layout se resuelve con una sola herramienta. Usas Grid para la estructura principal de la página y Flex para los detalles internos de cada componente.

En esta lección vas a construir —pieza a pieza— los 6 patrones de layout más comunes en la web: navbar sticky, sidebar layout, centrado absoluto, hero section, holy grail y sticky footer. Al terminar, tendrás un catálogo mental de soluciones que podrás aplicar directamente en cualquier proyecto.

¿Por qué aprender patrones compuestos?

Porque en el mundo real nunca tienes «un problema de flex» o «un problema de grid». Tienes una página que necesita header, sidebar, contenido, hero y footer. La habilidad está en saber qué herramienta usar para cada parte y cómo hacer que encajen sin conflictos.

2 · Teoría

La pirámide de decisión: ¿Flex o Grid?

Antes de escribir una sola clase, hazte estas preguntas en orden:

  1. ¿El layout tiene filas y columnas simultáneas? → Grid. Ejemplo: dashboard con sidebar + stats en grid.
  2. ¿Solo necesito una dirección (fila o columna)? → Flex. Ejemplo: navbar horizontal, stack de tarjetas.
  3. ¿Necesito alinear en el eje cruzado? → Flex con items-center. Ejemplo: centrar icono y texto en un botón.
  4. ¿Necesito que elementos salten de línea? → Flex con flex-wrap. Ejemplo: chips, tags, badges.
Pirámide de decisión Flex vs Grid: ┌─────────────────┐ │ ¿Filas Y │ │ columnas? │──SÍ──▶ GRID └────────┬────────┘ │NO ┌────────▼────────┐ │ ¿Una sola │ │ dirección? │──SÍ──▶ FLEX └────────┬────────┘ │ ┌────────▼────────┐ │ ¿Wrap │ │ necesario? │──SÍ──▶ FLEX + flex-wrap └─────────────────┘

🧠 Analogía: arquitectura de una casa

Grid es la estructura del edificio: define dónde van las paredes maestras (sidebar, contenido principal, footer). Flex es la decoración interior: cómo colocas los muebles dentro de cada habitación. No usas vigas de acero para colgar un cuadro, ni usas alcayatas para sostener el tejado.

3 · Ejemplo mínimo

El patrón más simple que combina ambas herramientas: un layout de página con Grid para la estructura y Flex para el navbar interno.

<!-- Grid: estructura principal (sidebar + contenido) -->
<div class="grid grid-cols-[260px_1fr] min-h-screen">
  <aside class="bg-slate-900 p-6">Sidebar</aside>

  <!-- Flex: todo dentro del contenido usa flex -->
  <main class="flex flex-col">
    <!-- Flex: navbar horizontal -->
    <nav class="flex items-center justify-between p-4 bg-slate-800">
      <span>Logo</span>
      <span>Usuario</span>
    </nav>
    <!-- Flex: contenido centrado -->
    <div class="flex-1 flex items-center justify-center">
      <p>Contenido centrado</p>
    </div>
  </main>
</div>

Observa cómo Grid y Flex no compiten: Grid define las columnas de la página, Flex maneja el interior de cada zona. Esta separación de responsabilidades es la clave de los layouts profesionales.

4 · Ejemplo real

4.1 Navbar sticky con Tailwind

El navbar más usado en producción: sticky en el top, con logo, enlaces centrales y botones de acción. Totalmente responsive: en móvil los enlaces se ocultan y aparece un menú hamburguesa.

<nav class="sticky top-0 z-50 bg-slate-900/95 backdrop-blur border-b border-slate-800">
  <div class="max-w-7xl mx-auto px-4">
    <div class="flex items-center justify-between h-16">
      <!-- Logo -->
      <a href="#" class="flex items-center gap-2 shrink-0">
        <span class="text-2xl">⚡</span>
        <span class="text-xl font-bold text-white">MiApp</span>
      </a>

      <!-- Enlaces (ocultos en móvil) -->
      <div class="hidden md:flex items-center gap-8">
        <a href="#" class="text-slate-400 hover:text-white text-sm transition-colors">Producto</a>
        <a href="#" class="text-slate-400 hover:text-white text-sm transition-colors">Precios</a>
        <a href="#" class="text-slate-400 hover:text-white text-sm transition-colors">Docs</a>
        <a href="#" class="text-slate-400 hover:text-white text-sm transition-colors">Blog</a>
      </div>

      <!-- Acciones -->
      <div class="flex items-center gap-3">
        <button class="hidden sm:block text-slate-400 hover:text-white text-sm transition-colors">Iniciar sesión</button>
        <button class="bg-sky-500 hover:bg-sky-400 text-white px-4 py-1.5 rounded-lg text-sm font-semibold transition-colors">Registrarse</button>
        <button class="md:hidden text-slate-400 p-1">☰</button>
      </div>
    </div>
  </div>
</nav>
🔑 Las 4 clases mágicas del navbar

sticky top-0 z-50 — pegado al techo, por encima de todo. bg-slate-900/95 backdrop-blur — fondo semitransparente con desenfoque (efecto vidrio esmerilado). h-16 — altura fija de 4rem para que el contenido debajo no salte. hidden md:flex — oculto en móvil, visible en tablet+.

🧠 ¿Por qué Flex y no Grid para este sidebar?

Con Flex, el sidebar tiene ancho fijo (w-64) y el contenido usa flex-1 para ocupar el resto. En móvil, el sidebar desaparece con hidden lg:flex y el contenido ocupa todo el ancho automáticamente. Grid también funcionaría con grid-cols-[256px_1fr] lg:grid-cols-1, pero Flex es más simple para este caso porque solo hay 2 zonas y el comportamiento responsive es trivial.

4.5 Sticky footer con Flex

El footer pegado al fondo es uno de los problemas clásicos del CSS. Con Tailwind se resuelve en 2 clases en el contenedor y 1 en el footer:

<div class="flex flex-col min-h-screen">
  <header class="bg-slate-900 p-6 text-white">Header</header>

  <main class="flex-1 p-6 text-slate-400">
    <h2 class="text-white text-xl mb-4">Contenido principal</h2>
    <p>Si esta página tiene poco contenido, el footer igual se pega al fondo.
       Si tiene mucho, el footer queda al final del scroll.</p>
  </main>

  <footer class="bg-slate-900 border-t border-slate-800 p-6 text-slate-500 text-sm text-center">
    © 2026 MiApp · Footer pegado al fondo
  </footer>
</div>
💡 La magia de flex-1 en el main

flex-1 le dice al main: «ocupa todo el espacio vertical sobrante entre el header y el footer». Si hay poco contenido, el main se estira y empuja el footer al fondo. Si hay mucho contenido, el main crece y el footer baja naturalmente. Funciona en todos los casos sin media queries.

4.6 Centrado absoluto (la combinación que salva vidas)

Centrar un elemento en el centro exacto de la pantalla —vertical y horizontal— es una de las operaciones más comunes y más frustrantes en CSS. Con Tailwind son 3 clases:

<div class="flex items-center justify-center min-h-screen bg-slate-950 px-4">
  <div class="w-full max-w-md bg-slate-900 border border-slate-800 rounded-2xl p-8 text-center">
    <div class="text-6xl mb-4">✅</div>
    <h2 class="text-2xl font-bold text-white mb-2">¡Todo listo!</h2>
    <p class="text-slate-400">Tu cuenta ha sido creada correctamente. Revisa tu email para verificarla.</p>
    <button class="mt-6 bg-sky-500 hover:bg-sky-400 text-white px-6 py-2.5 rounded-xl font-semibold transition-colors w-full">
      Ir al dashboard
    </button>
  </div>
</div>

La misma técnica sirve para pantallas de login, mensajes de error 404, pantallas de carga, modales a pantalla completa y cualquier contenido que deba ocupar el centro visual del viewport.

5 · Buenas prácticas

HazEvitaPor qué
Grid para la estructura de página, Flex para los componentes internos Todo con Flex (anidando flex-col en flex-row en flex-col) La anidación excesiva de Flex crea markup difícil de mantener. Grid expresa la intención del layout de página directamente.
sticky top-0 z-50 para navbars fijos fixed top-0 w-full y añadir padding al body sticky no saca el elemento del flujo. El contenido debajo no necesita padding compensatorio.
min-h-screen en el contenedor raíz para sticky footer height: 100vh con overflow-y auto min-h-screen permite que la página crezca si hay más contenido. h-screen trunca el contenido que excede el viewport.
Sidebar con hidden lg:flex y contenido con flex-1 Sidebar con absolute o fixed que se superpone al contenido El sidebar en el flujo normal evita solapamientos y simplifica el layout responsive.
Hero con min-h-[80vh] en lugar de h-screen Hero que ocupa el 100% exacto del viewport Dejar un 20% visible del contenido siguiente invita al scroll y mejora la experiencia de usuario.
Agrupa las decisiones de layout en el contenedor más externo posible Esparcir clases de layout en elementos profundamente anidados Centralizar el layout facilita los cambios. Si el layout está en 10 sitios, cambiarlo requiere tocar 10 sitios.

6 · Errores habituales

Error 1 — Usar fixed en lugar de sticky para el navbar

<!-- ❌ MAL: fixed saca el navbar del flujo, necesitas padding compensatorio -->
<nav class="fixed top-0 w-full z-50">...</nav>
<main class="pt-16">...</main> <!-- padding mágico que se desincroniza -->

<!-- ✅ BIEN: sticky no saca del flujo, no necesita compensación -->
<nav class="sticky top-0 z-50">...</nav>
<main>...</main>

Error 2 — Usar h-screen en lugar de min-h-screen para sticky footer

<!-- ❌ MAL: el contenido que excede el viewport se corta -->
<div class="flex flex-col h-screen">
  <main class="flex-1 overflow-y-auto">...</main>
</div>

<!-- ✅ BIEN: la página crece con el contenido -->
<div class="flex flex-col min-h-screen">
  <main class="flex-1">...</main>
</div>

Error 3 — No ocultar el sidebar en móvil

Un sidebar de 260px ocupa casi el 70% de un móvil de 375px. Siempre debe ocultarse o convertirse en un drawer en pantallas pequeñas. hidden lg:flex es el patrón estándar.

Error 4 — Anidar scrolls innecesarios

<!-- ❌ MAL: scroll anidado — el body scrollea y el main también -->
<div class="h-screen flex flex-col">
  <main class="flex-1 overflow-y-auto">...</main>
</div>

<!-- ✅ BIEN: un solo scroll en el body, layout natural -->
<div class="min-h-screen flex flex-col">
  <main class="flex-1">...</main>
</div>

Error 5 — Hero sin padding lateral en móvil

Un hero con text-6xl sin px-4 tocará los bordes en pantallas de 375px. Siempre añade padding horizontal (px-4 o px-6) en contenedores a ancho completo.

7 · Ejercicio guiado

Objetivo: Construir una landing page completa combinando todos los patrones aprendidos: navbar sticky, hero section, features grid y sticky footer.

  1. Contenedor raíz: flex flex-col min-h-screen bg-slate-950. Esto habilita el sticky footer con flex-1 en el main.
  2. Navbar sticky: sticky top-0 z-50 bg-slate-900/95 backdrop-blur border-b border-slate-800. Contiene logo a la izquierda y enlaces + botones a la derecha con flex items-center justify-between.
  3. Main con flex-1: flex-1 para que ocupe el espacio entre el navbar y el footer.
  4. Hero section: flex flex-col items-center justify-center min-h-[70vh] text-center px-4. Título con text-4xl sm:text-6xl font-extrabold, subtítulo, botones CTA con flex flex-col sm:flex-row gap-4.

  6. Footer: bg-slate-900 border-t border-slate-800 py-8. Contiene 3 columnas de enlaces con flex flex-wrap gap-8 justify-between y una barra de copyright debajo.

8 · Reto

🎯 Layout de aplicación de chat

Construye la estructura de una aplicación de chat como WhatsApp Web o Slack usando Grid + Flex con Tailwind. Requisitos:

  1. Estructura Grid de 3 columnas: Lista de chats (320px) | Área de mensajes (1fr) | Panel de detalles (280px, solo visible al seleccionar un chat).
  2. Columna izquierda (chats): Header con buscador (flex), lista de chats con scroll (flex flex-col overflow-y-auto), cada chat es un flex items-center gap-3 con avatar y última línea de texto.
  3. Columna central (mensajes): Header del chat (flex items-center justify-between), área de mensajes con scroll (flex-1 flex flex-col gap-2 overflow-y-auto), input bar al fondo (flex items-center gap-2 p-4 border-t).
  4. Columna derecha (detalles): hidden xl:flex flex-col. Solo visible en pantallas grandes. Muestra info del contacto seleccionado.
  5. Responsive: En móvil solo se ve una columna a la vez. La lista de chats o el área de mensajes ocupan el 100%.

Pista: La columna derecha usa hidden xl:block. La columna de mensajes usa flex-1 para ocupar el espacio sobrante entre la lista de chats y los detalles.

9 · Resumen

  • Grid + Flex no compiten, se complementan. Grid para la macroestructura (zonas de la página). Flex para la microestructura (componentes internos).
  • Navbar sticky: sticky top-0 z-50 bg-slate-900/95 backdrop-blur. No uses fixed si no es necesario.
  • Sidebar layout: Flex con w-64 + flex-1, o Grid con grid-cols-[256px_1fr]. En móvil: hidden lg:flex.
  • Hero section: flex flex-col items-center justify-center min-h-[70vh] text-center. Botones en flex-col sm:flex-row para responsive.
  • Holy Grail: grid grid-cols-[240px_1fr_240px] grid-rows-[auto_1fr_auto] min-h-screen.
  • Sticky footer: Contenedor con flex flex-col min-h-screen + main con flex-1.
  • Centrado absoluto: flex items-center justify-center min-h-screen. 3 clases, cero complicaciones.
  • Regla de oro: La decisión más importante es qué herramienta usar para cada capa del layout. Resuelve de fuera hacia dentro: primero la estructura de página (Grid), luego los componentes (Flex).

10 · Preguntas frecuentes

¿Puedo hacer toda una landing page solo con Flex?

Sí, pero acabarás con markup profundamente anidado. Un grid de features con Flex requiere flex flex-wrap y cálculos de ancho. Con Grid usas grid-cols-3 gap-8 y listo. Para la landing page global, Grid para el layout principal y Flex para navbar, hero y footer es la combinación óptima.

¿Cuándo usar sticky vs fixed para un navbar?

sticky cuando el navbar es parte del flujo natural de la página (la mayoría de los casos). fixed cuando necesitas que el navbar esté SIEMPRE visible incluso al hacer scroll, y no te importa que se superponga al contenido (menos común). sticky es casi siempre la mejor opción porque no requiere padding compensatorio.

¿Cómo manejo un sidebar que se colapsa con animación?

Usa una combinación de clases condicionales. El sidebar empieza con w-64 transition-all duration-300. Al colapsarse, cambia a w-16 (solo iconos). Los textos del sidebar usan overflow-hidden whitespace-nowrap para no desbordar. La lógica de colapso la manejas con un estado en JavaScript que togglea las clases.

¿Por qué no usar position: absolute para centrar elementos?

El patrón clásico position: absolute; top: 50%; left: 50%; transform: translate(-50%, -50%) requiere 4 propiedades, saca el elemento del flujo (puede solaparse con otros), y falla si el contenedor no tiene posición relativa. flex items-center justify-center en el padre es más simple, más robusto y mantiene el elemento en el flujo normal.

¿Es mejor un layout con scroll en el body o en un contenedor interno?

Para la mayoría de sitios web, el scroll natural del body es la mejor opción: es lo que los usuarios esperan, funciona con la barra de scroll del navegador, y no crea problemas de accesibilidad. El scroll en contenedores internos es necesario en layouts de aplicación (dashboard con sidebar fijo, chat con lista de mensajes), pero debe ser la excepción, no la regla.
