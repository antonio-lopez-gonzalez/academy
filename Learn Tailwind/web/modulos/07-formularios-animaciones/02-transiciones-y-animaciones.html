Transiciones y Animaciones

Módulo 7 · Formularios, Animaciones y Patrones ⏱ 35 minutos

1 · Introducción

Una interfaz sin movimiento se siente rota. No es un capricho estético: las transiciones y animaciones cumplen funciones cognitivas esenciales. Le dicen al usuario qué pasó (un botón se hundió al click), dónde está (un modal apareció desde arriba), y qué está pasando (un spinner indica carga).

Analogía: CSS sin animaciones es como un libro sin ilustraciones

Puedes leer el contenido perfectamente, pero las ilustraciones te ayudan a entender la historia, a ubicarte y a mantener el interés. Las animaciones en una interfaz hacen lo mismo: guían al usuario, confirman acciones y hacen la experiencia memorable sin que el usuario sea consciente de ello.

Tailwind ofrece tres niveles de movimiento: transiciones (suavizar cambios de estado entre A y B), animaciones predefinidas (spin, ping, pulse, bounce — loops o one-shot), y animaciones personalizadas (definir tus propios @keyframes). En esta lección dominarás los tres niveles.

Al final sabrás crear desde un micro-efecto de hover en un botón hasta una notificación toast que entra deslizándose desde arriba, todo sin una sola línea de JavaScript para las animaciones.

2 · Teoría

Transiciones vs Animaciones: ¿cuál usar?

CaracterísticaTransición (transition-*)Animación (animate-*)
DisparadorCambio de estado (hover, focus, clase añadida)Automática al cargar, o con clase aplicada
DirecciónIda y vuelta (hover in → hover out)Control total con @keyframes
RepeticiónNo (un solo ciclo por disparo)Sí (infinite, repeat)
ComplejidadSimple: propiedad A → propiedad BCompleja: múltiples pasos intermedios
Uso típicohover de botón, color de enlace, opacidad de tooltipspinners, loaders, notificaciones, entrada de modales
Regla práctica

Si el movimiento tiene dos estados (normal → hover) usa transición. Si tiene más de dos pasos o necesita ejecutarse automáticamente al cargar, usa animación.

Animaciones personalizadas en Tailwind v4

En Tailwind v4, defines animaciones personalizadas directamente en tu CSS con @theme. No necesitas tocar tailwind.config.js (que ya no existe en v4):

/* En tu archivo CSS principal (site.css o app.css) */
@import "tailwindcss";

@theme {
  --animate-slide-down: slide-down 300ms ease-out;
  --animate-slide-up: slide-up 300ms ease-out;
  --animate-fade-in: fade-in 200ms ease-out;
  --animate-scale-in: scale-in 200ms ease-out;
}

@keyframes slide-down {
  from {
    opacity: 0;
    transform: translateY(-12px);
  }
  to {
    opacity: 1;
    transform: translateY(0);
  }
}

@keyframes slide-up {
  from {
    opacity: 1;
    transform: translateY(0);
  }
  to {
    opacity: 0;
    transform: translateY(-12px);
  }
}

@keyframes fade-in {
  from { opacity: 0; }
  to   { opacity: 1; }
}

@keyframes scale-in {
  from {
    opacity: 0;
    transform: scale(0.95);
  }
  to {
    opacity: 1;
    transform: scale(1);
  }
}

Una vez definidas, las usas como cualquier clase de Tailwind: animate-slide-down, animate-fade-in, etc.

Prefiere GPU-accelerated properties

Para animaciones fluidas a 60fps, usa solo transform y opacity. Estas propiedades se ejecutan en la GPU y no disparan reflow ni repaint. Evita animar width, height, top, left, margin o padding — disparan reflow y causan jank (tirones).

3 · Ejemplo mínimo

El ejemplo más pequeño: un botón que cambia de color suavemente al hacer hover y se hunde al hacer clic:

<button class="px-6 py-2.5 bg-blue-600 text-white font-semibold
               rounded-lg
               hover:bg-blue-700
               active:scale-[0.97]
               transition-all duration-200 ease-in-out">
  Haz clic
</button>

Desglose: transition-all activa la transición en todas las propiedades. duration-200 establece 200ms de duración (ni muy rápido ni muy lento). ease-in-out da una curva de aceleración natural. hover:bg-blue-700 define el estado destino del color de fondo. active:scale-[0.97] reduce ligeramente el tamaño al hacer clic, creando la sensación de "hundimiento". Sin transition-all, el cambio sería instantáneo y brusco.

Un spinner de carga con la animación predefinida animate-spin:

</div>

4 · Ejemplo real

1. Botón con múltiples transiciones

Un botón que combina transición de color, sombra y transformación. Cada aspecto del botón se anima de forma cohesiva:

<button class="px-5 py-2.5 rounded-xl font-semibold text-sm
               bg-gradient-to-r from-indigo-600 to-purple-600
               text-white shadow-lg shadow-indigo-600/25
               hover:shadow-xl hover:shadow-indigo-600/40
               hover:from-indigo-700 hover:to-purple-700
               hover:-translate-y-0.5
               active:translate-y-0 active:shadow-md
               transition-all duration-200 ease-out">
  <span class="flex items-center gap-2">
    🚀 Lanzar proyecto
    <svg class="w-4 h-4 transition-transform duration-300
                group-hover:translate-x-0.5" ...>
    </svg>
  </span>
</button>
La magia de -translate-y-0.5

Cuando haces hover, el botón sube ligeramente (hover:-translate-y-0.5 = 2px hacia arriba). La sombra crece (hover:shadow-xl). El resultado: el botón "flota" hacia el cursor. Al hacer clic, active:translate-y-0 lo devuelve a su sitio. Micro-interacción de calidad profesional con 4 clases.

¿Por qué skeleton y no un spinner?

Los skeleton loaders reducen la percepción de tiempo de espera porque el usuario ya ve la "forma" del contenido que va a aparecer. Un spinner dice "espera"; un skeleton dice "esto está a punto de cargarse". Estudios de UX muestran que los skeletons reducen la tasa de abandono en un 10-15% frente a spinners genéricos.

6 · Errores habituales

Error #1 — «La animación funciona al entrar pero no al salir»

Causa: La clase animate-* está en el elemento base, no en un estado condicional. Si pones animate-fade-in directamente en el elemento, la animación se ejecuta al cargar, pero al quitar el elemento con hidden no hay animación de salida. Solución: Usa dos animaciones: una de entrada aplicada al mostrar y otra de salida con animation-fill-mode: forwards antes de ocultar. O mejor, usa la API de View Transitions o un enfoque con JavaScript que añada/quite clases.

Error #2 — «La animación parpadea o se reinicia al hacer hover»

Causa: Usaste animate-pulse o animate-bounce en un elemento que también tiene hover: con otra animación. Al hacer hover, la animación se reinicia porque el navegador recalcula los keyframes. Solución: No mezcles animaciones CSS en el mismo elemento. Si necesitas un cambio en hover, usa transiciones para ese cambio, no otra animación.

Error #3 — «La animación custom no funciona en Tailwind v4»

Causa: Definiste @keyframes pero no los registraste en @theme. En Tailwind v4, los keyframes deben mapearse explícitamente a nombres de animación. Solución: Asegúrate de tener @theme { --animate-nombre: nombre keyframes duración timing; } en tu CSS global y de que estás importando ese archivo. No puedes definir @keyframes en un <style> inline y esperar que Tailwind lo reconozca como clase utilitaria.

Error #4 — «La transición no ocurre al cambiar entre dark/light mode»

Causa: El cambio de modo modifica variables CSS (custom properties), y las transiciones CSS no interpolan variables — interpolan valores concretos. Si el color de fondo está definido con var(--bg), la transición de background-color no funcionará. Solución: Usa valores de color directos de Tailwind (bg-slate-900 dark:bg-white) en lugar de variables, o aplica la transición sobre * con @media (prefers-color-scheme) en vez de clases dark:.

Error #5 — «Animar height de 0 a auto no funciona»

Causa: CSS no puede transicionar de una altura fija (0) a auto. La transición necesita valores numéricos en ambos extremos. Solución: (1) Usa max-height con un valor suficientemente grande (ej: max-h-0 → max-h-96). (2) Usa grid-rows-[0fr] → grid-rows-[1fr] (más moderno y limpio). (3) Calcula la altura real con JS y usa style.height. La opción 2 con grid es la más limpia y no requiere JS.

Construye un sistema de toast notifications paso a paso. Vamos a implementar el toast que viste en el ejemplo real, pero esta vez tú lo escribirás desde cero entendiendo cada parte:

// JavaScript mínimo para mostrar el toast
function showToast(message, type = 'success') {
  const container = document.getElementById('toast-container');
  const template = document.getElementById('toast-template');
  const clone = template.content.cloneNode(true);

  // Personalizar mensaje
  clone.querySelector('p:last-of-type').textContent = message;

  container.appendChild(clone);

  // Auto-eliminar después de 4 segundos (coincide con la animación)

  setTimeout(() => {
    toast.style.opacity = '0';
    toast.style.transform = 'translateY(-12px)';
    setTimeout(() => toast.remove(), 300);
  }, 4000);
}

8 · Reto

🎯 Modal animado con backdrop

Construye un modal que aparece con las siguientes animaciones:

  • Backdrop: Fondo oscuro semitransparente que aparece con fade-in (opacity 0 → 1).
  • Modal: El contenedor blanco/oscuro entra con scale-in (scale 0.95 + opacity 0 → scale 1 + opacity 1).
  • Salida: Al cerrar, ambas animaciones se reproducen en reversa antes de ocultar el elemento.
  • Contenido: Header con título y botón de cerrar, cuerpo con texto, footer con botones de acción.
  • Transiciones en botones: Los botones del footer tienen hover y active con transición.
  • Accesibilidad: Al abrirse, el foco se mueve al modal. Escape cierra el modal. Foco atrapado dentro del modal mientras está abierto.

Pistas: Define --animate-fade-in y --animate-scale-in en @theme. Usa fixed inset-0 z-50 para backdrop y modal. El backdrop usa bg-black/50 backdrop-blur-sm. El modal usa animate-scale-in. Para la salida, alterna entre clases con JS: aplica una clase de salida, espera a que termine la animación (animationend), y luego oculta con hidden.

9 · Resumen

  • Transiciones: suavizan cambios entre dos estados (A → B). Se disparan con hover, focus, o clases añadidas. Usa transition (propiedades comunes), transition-all (todas) o transition-colors/transition-opacity/transition-transform (específicas).
  • Duración: duration-150 o duration-200 para la mayoría de interacciones. duration-300 para elementos que entran. duration-500 o más para énfasis deliberado.
  • Curvas: ease-out para entradas (empieza rápido, frena). ease-in para salidas. ease-in-out para cambios simétricos. Evita ease-linear en UI (antinatural).
  • Animaciones predefinidas: animate-spin (carga), animate-ping (notificación), animate-pulse (skeleton), animate-bounce (atención). Úsalas con moderación.
  • Animaciones personalizadas: Define @keyframes en tu CSS y regístralas en @theme con --animate-nombre:. Luego úsalas como animate-nombre.
  • Rendimiento: Anima solo transform y opacity (GPU). Evita width, height, top, left (disparan reflow).
  • Accesibilidad: Respeta prefers-reduced-motion con motion-reduce:. No uses animaciones infinitas en elementos críticos para la lectura.

10 · Preguntas frecuentes

¿Por qué mis animaciones van a tirones (jank)?

Causa más probable: estás animando propiedades que disparan reflow (layout). Solo transform y opacity se ejecutan en la GPU sin recalcular el layout. Abre las DevTools → Rendering → Paint Flashing. Si ves parpadeos verdes constantes, estás causando repaints innecesarios. Cambia a animar solo transform y opacity.

¿Cómo desactivo todas las animaciones para usuarios con prefers-reduced-motion?

Tailwind v4 incluye el modificador motion-reduce:. Puedes usarlo así: motion-reduce:animate-none motion-reduce:transition-none. Para una solución global, añade en tu CSS: @media (prefers-reduced-motion: reduce) { *, *::before, *::after { animation-duration: 0.01ms !important; animation-iteration-count: 1 !important; transition-duration: 0.01ms !important; } }.

¿Puedo usar animaciones CSS para animar la entrada/salida de elementos con display:none?

No directamente. display: none elimina el elemento del flujo instantáneamente sin posibilidad de transición. Alternativas: (1) Usa opacity-0 + pointer-events-none en vez de hidden. (2) Usa @starting-style (CSS moderno). (3) Usa la API View Transitions. (4) El truco clásico: añade la clase de animación de salida, espera animationend con JS, y entonces aplica hidden.

¿Vale la pena usar librerías como Framer Motion o GSAP en vez de animaciones Tailwind?

Depende de la complejidad. Tailwind + animaciones CSS es perfecto para el 90% de las interacciones UI: hovers, transiciones de estado, loaders, toasts, skeletons. Si necesitas animaciones complejas orquestadas (secuencias, stagger, scroll-triggered, morphing SVG), GSAP o Framer Motion son herramientas superiores. La regla: empieza con Tailwind, y si necesitas más, añade una librería especializada. No sobrediseñes antes de tiempo.

¿Puedo animar un gradiente en Tailwind?

CSS no permite transicionar gradientes directamente (no son valores interpolables). Trucos: (1) Superpón dos elementos con diferentes gradientes y transiciona la opacidad de uno de ellos. (2) Usa background-size ampliado y anima background-position: bg-[length:200%_200%] + animate-gradient con @keyframes { 0% { background-position: 0% 50%; } 50% { background-position: 100% 50%; } 100% { background-position: 0% 50%; } }. Esto crea la ilusión de un gradiente animado.
