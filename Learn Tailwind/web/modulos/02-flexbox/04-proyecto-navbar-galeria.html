Proyecto Guiado: Navbar y Galería con Flexbox

Módulo 2 · Flexbox ⏱ 50 minutos

1 · Introducción

Esta lección es diferente: no hay conceptos nuevos. En su lugar, vas a construir un proyecto completo usando exclusivamente lo aprendido en las tres lecciones anteriores. El objetivo es que termines con un componente de página real, funcional y responsive, escrito con CSS puro y Flexbox.

El proyecto consta de tres partes:

  1. Navbar responsive: Logo, enlaces centrados y botón de acción.
  2. Galería de cards: Grid flexible con flex-wrap + gap.
  3. Footer de tres columnas: Distribución equitativa con Flexbox.

Reglas del proyecto: CSS puro, sin frameworks, sin JavaScript para el layout. Solo HTML semántico y Flexbox. La galería y el footer serán 100% responsive sin media queries.

2 · Teoría aplicada

Antes de escribir código, vamos a planificar la arquitectura Flexbox del proyecto. Cada decisión de diseño debe tener una justificación técnica.

Navbar: ¿por qué no space-between?

Con solo space-between empujamos elementos a los extremos, pero no podemos centrar el del medio. La estrategia correcta para tres zonas es:

  • Contenedor navbar con display: flex; align-items: center.
  • El logo mantiene su tamaño natural con flex: 0 0 auto.
  • El grupo de enlaces usa flex: 1 para ocupar el espacio central, y dentro de él justify-content: center para centrar los enlaces.
  • El botón CTA también usa flex: 0 0 auto.
ANATOMÍA DEL NAVBAR:

┌──────────────────────────────────────────────────┐
│ 🌊 Logo  │  flex:1 + justify-content:center  │ CTA│
│ (flex:0) │  [Link1] [Link2] [Link3]         │flex:0│
└──────────────────────────────────────────────────┘
          ↑                                    ↑
    flex-shrink:0                   flex-shrink:0
    (no se encoge)                  (no se encoge)

Galería: ¿por qué flex-wrap + flex basis en vez de Grid?

Para este caso de uso, Flexbox funciona mejor que Grid porque:

  • No necesitamos que las columnas estén perfectamente alineadas entre filas (contenido tipo blog/masonry).
  • Queremos que las cards se adapten fluidamente al ancho disponible sin definir breakpoints.
  • El número de cards puede ser variable (cargado desde un CMS, por ejemplo).

Footer: ¿por qué flex: 1 en cada columna?

Tres columnas que se reparten el espacio equitativamente. Con flex: 1 en cada una, siempre ocupan 1/3 del ancho disponible, independientemente del contenido. Cuando la pantalla es pequeña, cambiamos a flex-direction: column y se apilan.

El body del proyecto usa display: flex; flex-direction: column; min-height: 100vh. Esto permite que el footer se pegue al fondo con margin-top: auto cuando el contenido es más corto que la ventana. Un truco clásico de Flexbox que sigue siendo la mejor solución para sticky footers.

3 · Ejemplo mínimo

Verificamos que cada pieza del proyecto funciona por separado antes de integrar todo:

Navbar mínimo

nav {
  display: flex;
  align-items: center;
  padding: 1rem 2rem;
}

.logo        { flex: 0 0 auto; }
.nav-links   { flex: 1; display: flex; justify-content: center; gap: 1.5rem; }
.nav-cta     { flex: 0 0 auto; }

Galería mínima

.galeria {
  display: flex;
  flex-wrap: wrap;
  gap: 1.5rem;
}

.card {
  flex: 1 1 250px;         /* La magia: base 250px, crece si sobra, se encoge si falta */
  min-width: 0;
}

Footer mínimo

footer {
  display: flex;
  gap: 2rem;
}

footer > div {
  flex: 1;                  /* Cada columna = 1/3 */
  min-width: 0;
}

Estos tres bloques son la esencia del proyecto. El resto es HTML semántico, estilos visuales y contenido. Si entiendes estas 12 líneas de CSS, entiendes el 90% del layout web moderno.

Explicación de cada decisión

Navbar

  • flex: 0 0 auto en logo y CTA: tamaño definido por contenido, no crecen ni se encogen. Si el logo se encoge, se vuelve ilegible. Si el botón se estira, se ve extraño.
  • flex: 1 en .navbar__links: absorbe todo el espacio sobrante entre logo y CTA. Dentro, justify-content: center centra los enlaces.
  • white-space: nowrap en logo y CTA: evita que el texto se parta en palabras cuando el espacio es reducido.
  • position: sticky; top: 0: el navbar se queda fijo al hacer scroll.
  • Una sola media query cambia a flex-direction: column en pantallas < 640px.

Galería

  • flex: 1 1 280px: cada card quiere al menos 280px. Si sobra espacio, crece. Si falta, se encoge. Si no caben 2, wrap a siguiente línea.
  • max-width: 1200px + margin: 0 auto: centra y limita el ancho máximo.
  • min-width: 0: evita el bug de overflow con contenido largo.
  • Cero media queries en la galería. Flexbox con wrap maneja todo el responsive.

Footer

  • flex: 1 en cada columna: garantiza que las tres columnas tengan el mismo ancho.
  • Cada columna es un contenedor flex con flex-direction: column para apilar su contenido.
  • margin-top: auto: sticky footer gracias al body flex column.

5 · Buenas prácticas

Usar variables CSS para colores, radios y gaps Repetir valores mágicos por todo el CSS Si cambian, cambian en un solo lugar. Esencial en proyectos que crecen

6 · Errores habituales

Error 1: No poner flex: 1 en el contenedor de enlaces del navbar

/* ❌ MAL: Sin flex: 1, los enlaces se pegan al logo */
.navbar__links {
  display: flex;
  justify-content: center;
  gap: 2rem;
}

/* ✅ BIEN: Con flex: 1, los enlaces ocupan el centro */
.navbar__links {
  flex: 1;
  display: flex;
  justify-content: center;
  gap: 2rem;
}

Error 2: Olvidar min-width: 0 en las cards

Si una card tiene un título muy largo (ej: "Guía definitiva para dominar Flexbox en desarrollo web moderno"), sin min-width: 0 la card fuerza un overflow horizontal en lugar de hacer wrap o truncarse.

Error 3: Usar flex: 1 en el footer sin gap

Sin gap, el texto de columnas adyacentes se tocará. Siempre combina flex: 1 con gap cuando distribuyes columnas.

Error 4: No probar con contenido extremo

Prueba siempre con: una card con título muy largo, una card con título muy corto, una card sin imagen, y un número impar de cards (ej: 5) para ver cómo se comporta la última fila.

7 · Ejercicio guiado

Objetivo: Partiendo del código base de la sección 4, realiza estas modificaciones guiadas para entender cómo cada cambio afecta al layout.

  1. Cambia el flex-basis de las cards: Modifica .card { flex: 1 1 280px; } a 400px y luego a 200px. Observa cómo cambia el número de cards por fila y cómo se comportan en pantallas pequeñas.
  2. Añade una cuarta columna al footer: Agrega un nuevo <div class="footer__col">. Con flex: 1, automáticamente las 4 columnas se reparten el 25% cada una. No necesitas tocar el CSS.
  3. Haz que una card destaque: Añade .card--featured { flex: 2 1 280px; border-color: var(--color-accent); } a la primera card. Ahora ocupa el doble que las demás.
  4. Añade align-self al botón CTA: Con .navbar__cta { align-self: flex-start; }, en móvil el botón mantiene su ancho natural en lugar de estirarse al 100% cuando el navbar cambia a columna.
  5. Cambia el hero a row en desktop: Con .hero { flex-direction: row; gap: 3rem; text-align: left; } y .hero > * { flex: 1; }, el texto va a la izquierda y dejas espacio para una imagen a la derecha.

Si este proyecto creciera y necesitaras más secciones (testimonios, pricing, features), el patrón sería siempre el mismo: una sección es un contenedor flex en columna para título + contenido, y dentro, otro contenedor flex con wrap para los items. La arquitectura se escala de forma predecible.

8 · Reto

🎯 Extiende el proyecto

Nivel: Avanzado. Tiempo estimado: 45-60 minutos. Partiendo del proyecto base de la sección 4, añade:

  1. Barra de búsqueda en el navbar: Entre los enlaces y el botón CTA, añade un <input type="search"> con flex: 0 1 250px. En móvil debe ocupar todo el ancho.
  2. Sidebar de filtros en la galería: Añade un <aside> a la izquierda con flex: 0 0 200px. La galería existente toma flex: 1. En móvil, el sidebar va arriba.
  3. Sticky sidebar: Haz que el sidebar use position: sticky; top: 80px; align-self: flex-start. align-self: flex-start es necesario porque align-items: stretch (por defecto) impide que sticky funcione correctamente.
  4. Footer con copyright: Añade una línea de copyright debajo de las columnas que ocupe el 100%. El footer debe usar flex-wrap: wrap para contener columnas + copyright.
  5. Modo oscuro/claro: Implementa un toggle de tema con localStorage. El botón va en el navbar, a la derecha del CTA.

9 · Resumen

Has construido un proyecto web completo usando exclusivamente Flexbox para el layout. Recapitulemos lo aprendido en las 4 lecciones del módulo:

  • Lección 1: Flexbox es unidimensional. Eje principal vs eje cruzado. flex-direction define la dirección. Solo los hijos directos son flex items.
  • Lección 2: justify-content distribuye en el eje principal. align-items alinea en el eje cruzado. gap reemplaza márgenes. align-self da control por item.
  • Lección 3: flex-grow, flex-shrink, flex-basis controlan el tamaño. El shorthand flex es preferible. flex-wrap + flex: 1 1 <medida> = responsive sin media queries.
  • Lección 4 (este proyecto): La arquitectura real combina contenedores flex anidados. Navbar con flex: 1 en zona central. Galería con wrap. Footer con columnas equitativas.

Flexbox no es un truco ni un hack. Es un sistema de layout maduro, con 15 años de evolución, soportado universalmente y diseñado para resolver los problemas reales del desarrollo web moderno.

10 · Preguntas frecuentes

¿Este proyecto funcionaría igual con CSS Grid?

Partes sí, partes no. La galería sería más fácil con Grid (grid-template-columns: repeat(auto-fill, minmax(280px, 1fr))) porque las columnas se alinearían perfectamente. El navbar también se puede hacer con Grid (grid-template-columns: auto 1fr auto). Pero el objetivo es demostrar que Flexbox puede hacerlo todo por sí solo.

¿Cuándo debería usar Flexbox y cuándo Grid en un proyecto real?

Flexbox cuando el layout fluye en una dirección: navbar, lista de tags, grupo de botones, cards que hacen wrap. Grid cuando necesitas control bidimensional: página completa con áreas, galería con celdas alineadas, dashboards. En la práctica los usas juntos: Grid para la estructura de página y Flexbox para los componentes internos.

¿Por qué el proyecto usa una media query si dijimos "sin media queries"?

La galería y el footer no usan media queries: son 100% responsive gracias a Flexbox. La única media query es para el navbar, porque cambiar de row a column requiere intervención explícita. No hay forma de que Flexbox cambie automáticamente de row a column basado en el ancho del viewport sin media query (o container queries).

¿Cómo evito que el texto del navbar se solape en pantallas intermedias?

El navbar usa flex-wrap: wrap en los enlaces para que salten de línea si no caben. Si aun así hay solapamiento, puedes: reducir el gap, usar font-size más pequeño, ocultar enlaces tras un menú hamburguesa (requiere JS), o aumentar el breakpoint de 640px a 768px.

¿Puedo usar este proyecto como base para un sitio en producción?

Sí. Los patrones usados (navbar con flex, galería con wrap, footer con columnas flex) son exactamente los que usan sitios como Smashing Magazine, CSS-Tricks y miles de proyectos corporativos. En producción querrás añadir un reset CSS más completo y posiblemente prefijos de navegador.
