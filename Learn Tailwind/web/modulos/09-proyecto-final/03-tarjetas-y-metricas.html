Tarjetas y métricas

Módulo 9 · Proyecto Final: Dashboard ⏱ 35 minutos

1 · Introducción

Tienes el esqueleto del dashboard y la navegación funcionando. Ahora necesitas que el panel diga algo útil. La función principal de un dashboard es comunicar datos de un vistazo: ¿cuántos usuarios tenemos? ¿Van bien las ventas? ¿Hay algo que requiera atención inmediata?

Las tarjetas de métricas (stats cards) son el componente más importante de cualquier dashboard. Son lo primero que mira un usuario al abrir la aplicación. Deben responder las preguntas clave en menos de 2 segundos.

En esta lección construirás:

  • 4 tarjetas de estadísticas con icono, valor numérico, etiqueta y tendencia (↑ sube, ↓ baja) codificada por colores.
  • Barras de progreso con porcentaje y barra coloreada animada.
  • Gráfico de barras con CSS puro (sin librerías, sin canvas, sin SVG — solo divs y Tailwind).
  • Lista de actividad reciente con avatares, timestamps y descripciones.
  • Skeleton loaders para simular estados de carga mientras los datos llegan del backend.

2 · Teoría

Anatomía de una stats card

Toda tarjeta de métrica tiene 4 elementos. Conocerlos te permite diseñar cualquier variante:

┌─────────────────────────────────┐
│  👤 Usuarios totales      📈 ↑  │  ← icono + indicador de tendencia
│                                 │
│  24,892                         │  ← valor principal (grande, bold)
│                                 │
│  +12.5% desde el mes pasado     │  ← etiqueta secundaria
└─────────────────────────────────┘
  1. Icono + tendencia: Identifica la métrica visualmente y muestra si va bien (verde ↑) o mal (rojo ↓). Ocupan la misma fila, extremos opuestos (flex justify-between).
  2. Valor principal: El número grande. Usa text-2xl o text-3xl font-bold. Debe ser lo primero que lea el ojo.
  3. Etiqueta: Qué significa ese número. text-sm text-slate-500. Secundaria visualmente.
  4. Indicador de tendencia: Flecha + porcentaje + texto descriptivo. Verde si es positivo, rojo si es negativo. Pequeño pero con color llamativo.

Psicología del color en métricas

Color Significado Clase Tailwind Cuándo usarlo
Verde Positivo, crecimiento, éxito text-emerald-500 ↑ ingresos, ↑ usuarios, ↑ conversión
Rojo Negativo, decrecimiento, alerta text-red-500 ↓ ingresos, ↑ tasa de rebote, ↑ errores
Ámbar Advertencia, estancamiento text-amber-500 → métrica plana, sin cambios significativos
Azul/Cian Informativo, neutral text-cyan-500 Métrica que no es ni buena ni mala, solo informativa

Regla de oro: Nunca uses rojo para una métrica positiva ni verde para una negativa. Parece obvio, pero verás dashboards reales donde "tasa de rebote baja" se muestra en rojo porque el número es alto. La métrica "tasa de rebote" es negativa cuando es alta — si baja, ponla en verde aunque el número absoluto sea pequeño.

Gráfico de barras con CSS puro

No necesitas Chart.js, D3 ni SVG para un gráfico de barras simple. Con CSS puedes crear barras horizontales o verticales usando:

  • height (barras verticales) o width (barras horizontales) en porcentaje.
  • inline style para establecer la altura/anchura dinámicamente (los datos vendrían de JS/backend).
  • transition para animar el cambio de altura cuando los datos se actualizan.
  • bg-gradient-to-t para dar profundidad a las barras.
Gráfico de barras verticales (CSS puro):

  100% ┤
       │
   75% ┤  ██
       │  ██     ██
   50% ┤  ██     ██     ██
       │  ██     ██     ██
   25% ┤  ██  ██ ██  ██ ██
       │  ██  ██ ██  ██ ██  ██
    0% ┤  ██  ██ ██  ██ ██  ██
       └──┬───┬───┬───┬───┬───┬──
         E   F   M   A   M   J

Cada barra es un <div> con style="height: X%" dentro de un contenedor flex con items-end (para que las barras crezcan desde abajo). El valor de altura viene de los datos — no está hardcodeado en Tailwind.

Skeleton loaders: el arte de mostrar "nada"

Un skeleton loader es un placeholder animado que ocupa el espacio del contenido mientras carga. Mejora la percepción de velocidad: el usuario ve que "algo está pasando" en lugar de una pantalla en blanco. Se implementa con:

  • Forma: Divs con bg-slate-200 rounded que imitan la silueta del contenido real.
  • Animación: animate-pulse de Tailwind — un fade in/out que simula actividad.
  • Layout: El mismo grid/flex que el contenido real, para que cuando los datos lleguen y reemplacen el skeleton, no haya reflow.

3 · Ejemplo mínimo

Una stats card en su expresión más pura — icono, valor, etiqueta y tendencia. Sin grid responsive, sin decoración extra:

<div class="bg-white rounded-xl border border-slate-200 p-5 shadow-sm">
  <div class="flex items-center justify-between mb-3">
    <div class="w-10 h-10 bg-blue-50 rounded-lg flex items-center justify-center text-lg">
      👤
    </div>
    <span class="flex items-center gap-1 text-xs font-medium text-emerald-600 bg-emerald-50 px-2 py-0.5 rounded-full">
      ↑ 12.5%
    </span>
  </div>
  <div class="text-2xl font-bold text-slate-900 mb-1">24,892</div>
  <div class="text-sm text-slate-500">Usuarios totales</div>
</div>

Analicemos las decisiones:

  • Icono con fondo de color: w-10 h-10 bg-blue-50 rounded-lg — un cuadrado de 40px con fondo azul muy claro. El icono (emoji o SVG) va centrado con flex. El fondo de color identifica la métrica más rápido que el icono solo.
  • Badge de tendencia: bg-emerald-50 text-emerald-600 — fondo verde muy claro con texto verde oscuro. El rounded-full lo convierte en una píldora. text-xs para que no compita con el valor principal.
  • Valor en text-2xl font-bold: Es el elemento tipográficamente más pesado. El ojo va directo a él.
  • Etiqueta en text-sm text-slate-500: Contraste bajo para no competir con el valor. El usuario ya sabe qué significa la tarjeta por el icono.

5 · Buenas prácticas

Haz Evita Por qué
Usa style="width: X%" para barras de progreso y alturas de gráficos Intentar generar clases de Tailwind para cada valor posible (w-1/2, w-2/3...) — no hay suficientes Tailwind es para estilos estáticos. Los datos son dinámicos. Inline styles para valores de datos es el patrón correcto
Codifica la tendencia con color semántico: verde ↑ positivo, rojo ↓ negativo Usar siempre verde "porque queda bonito" aunque la métrica esté empeorando El color es información. Si mientes con el color, el usuario tomará decisiones equivocadas basadas en tu dashboard
Usa flex items-end para que las barras del gráfico crezcan desde abajo Dejar las barras con altura fija desde el centro — no se parecen a ningún gráfico real items-end alinea los hijos al fondo del contenedor flex. Las barras "descansan" sobre la línea base, como en cualquier gráfico
Los skeletons deben tener la misma estructura de layout que el contenido real Crear skeletons genéricos que no coinciden con el layout final — la página "salta" al cargar El propósito del skeleton es reservar el espacio exacto. Si cambia el layout al cargar, el skeleton es contraproducente
Agrupa visualmente la actividad reciente con divide-y divide-slate-100 Poner bordes manualmente en cada fila o usar márgenes inconsistentes divide-y aplica border-top a todos los hijos excepto el primero. Es declarativo y se adapta automáticamente si añades/quitas filas

6 · Errores habituales

Las barras del gráfico no arrancan desde abajo

Olvidaste items-end en el contenedor flex de las barras. Sin él, las barras se alinean al centro (stretch por defecto) y el gráfico parece flotar. Solución: <div class="flex items-end justify-between gap-2 h-48">. Con items-end, todas las barras se anclan a la base del contenedor.

Las tarjetas de métricas se ven amontonadas sin espacio entre ellas

Usaste grid grid-cols-4 pero olvidaste el gap-4. En CSS Grid, sin gap explícito las celdas están pegadas. En Tailwind, gap-4 (1rem / 16px) es el espaciado estándar entre tarjetas de dashboard.

Los valores de tendencia no se entienden sin contexto

Pusiste "+12.5%" sin decir respecto a qué periodo. ¿Respecto al mes pasado? ¿Al año pasado? ¿Al trimestre? Solución: añade una etiqueta contextual: "vs. mes pasado", "desde enero", "interanual". Si no hay espacio en la tarjeta, usa un tooltip con title.

El skeleton loader hace que la página parpadee al cargar los datos

El skeleton y el contenido real tienen estructuras de grid diferentes. Cuando los datos llegan y reemplazas el HTML, el layout cambia (reflow) y todo "salta". Solución: el skeleton debe ser una copia exacta de la estructura del contenido final, solo que con divs grises en lugar de datos reales. Mismo grid, mismos gaps, mismos paddings.

7 · Ejercicio guiado

Vamos a añadir interactividad simple al gráfico de barras: al hacer hover sobre una barra, se muestra un tooltip con el valor exacto y la barra se oscurece ligeramente.

Paso 1: Añadir grupo hover a cada columna

<div class="flex-1 flex flex-col items-center gap-2 group cursor-pointer">
  <div class="w-full flex flex-col items-center gap-0.5 relative">
    <!-- Tooltip flotante -->
    <span class="absolute -top-8 left-1/2 -translate-x-1/2 bg-slate-800 text-white text-xs px-2 py-1 rounded
                 opacity-0 group-hover:opacity-100 transition-opacity pointer-events-none whitespace-nowrap z-10">
      $2,450
    </span>
    <div class="w-full bg-cyan-500 rounded-t-md transition-all duration-300 group-hover:bg-cyan-600 group-hover:shadow-lg"
         style="height: 120px"></div>
    <div class="w-full bg-slate-200 rounded-t-sm transition-all duration-300"
         style="height: 90px"></div>
  </div>
  <span class="text-xs text-slate-500 group-hover:text-slate-700 transition-colors">Lun</span>
</div>

Paso 2: Aplicar a todas las columnas del gráfico

Replica el patrón anterior en las 7 columnas del gráfico de ingresos semanales. Cada columna recibe:

  • group en el contenedor de la columna.
  • group-hover:bg-cyan-600 group-hover:shadow-lg en la barra de cian.
  • Un <span> con tooltip posicionado absolutamente, invisible por defecto (opacity-0), visible al hover (group-hover:opacity-100).

El patrón group de Tailwind: group en el padre + group-hover: en los hijos. Es como :hover pero propagado: cuando haces hover en cualquier parte del padre, TODOS los hijos con group-hover: reaccionan. Perfecto para tooltips, cambios de color en barras de gráfico, o resaltar toda una fila de tabla (lo veremos en la lección 4).

8 · Reto

🎯 Convierte el gráfico de barras en un gráfico de líneas con CSS puro

Sin usar SVG, canvas ni librerías, crea un gráfico de líneas usando solo divs y CSS:

  1. Cada punto de datos es un <div> circular (rounded-full) posicionado absolutamente dentro de un contenedor relative.
  2. Los puntos se conectan con líneas usando pseudo-elementos ::before que dibujan segmentos entre puntos consecutivos.
  3. Las líneas usan border-top o height: 2px con transform: rotate() para conectar puntos a diferentes alturas.
  4. Añade un gradiente de área bajo la línea (bg-gradient-to-t from-cyan-500/20 to-transparent).

    <div class="border-t border-slate-100"></div>

    <div class="border-t border-slate-100"></div>
    <div class="border-t border-slate-100"></div>

9 · Resumen

  • Stats cards: Icono con fondo coloreado + valor grande + etiqueta secundaria + badge de tendencia codificado por colores. Grid responsive: grid-cols-1 sm:grid-cols-2 lg:grid-cols-4.
  • Tendencias con color semántico: Verde para crecimiento, rojo para decrecimiento, ámbar para estancamiento. El color comunica más rápido que el número.
  • Barras de progreso: style="width: X%" en un div interno. El contenedor tiene bg-slate-100 rounded-full h-2.5. La barra tiene bg-{color} rounded-full transition-all.
  • Gráfico de barras con CSS puro: Contenedor flex con items-end. Cada barra es un div con style="height: Xpx". Dos barras por columna (año actual + anterior) para comparación.
  • Actividad reciente: Avatar circular + texto + timestamp. Separadores con divide-y. Hover con hover:bg-slate-50 transition-colors.
  • Skeleton loaders: Misma estructura de grid que el contenido real. Placeholders grises con animate-pulse. Sin reflow al cargar datos.
  • Group hover: group en el contenedor + group-hover: en hijos. Permite tooltips, cambios de color y resaltados al hacer hover en cualquier parte de un componente.

10 · Preguntas frecuentes

¿Por qué no usar Chart.js o una librería de gráficos?

Para dashboards de producción con gráficos complejos (líneas, áreas, dispersión, radar), una librería como Chart.js, Recharts o Tremor es la decisión correcta. Pero para este curso, construir gráficos con CSS puro te enseña DOS cosas: (1) entiendes cómo funcionan los gráficos por dentro, (2) para gráficos simples (barras, progreso, donut básico), CSS puro es más ligero, más rápido y no añade dependencias. La decisión depende del contexto: si solo necesitas 4 barras de progreso, no cargues Chart.js.

¿Cómo hago que las barras se animen al cargar la página?

Añade transition-all duration-1000 a las barras y establece la altura inicial en 0. Luego, en un setTimeout o IntersectionObserver, aplica la altura real con JS: bar.style.height = finalHeight + 'px'. La transición CSS se encarga de la animación. También puedes usar animation con @keyframes desde height: 0 hasta la altura final, pero necesitarías una animación por cada barra (o usar CSS custom properties).

¿Los skeletons son accesibles?

Los skeletons básicos (animate-pulse) no son ideales para lectores de pantalla porque no comunican "cargando". Para accesibilidad, añade aria-busy="true" al contenedor y aria-label="Cargando datos..." a los placeholders. También puedes usar un elemento <span class="sr-only">Cargando...</span> que solo los lectores de pantalla perciben. Tailwind incluye sr-only (screen-reader-only) para este propósito exacto.

¿Cómo formateo números grandes (24,892 en lugar de 24892)?

JavaScript: new Intl.NumberFormat('es-ES').format(24892) → "24.892" (nota: en español usa punto, en inglés usa coma). Si quieres formato abreviado: Intl.NumberFormat('en', { notation: 'compact' }).format(24892) → "25K". Esto lo harías en el JS que rellena los datos, no en Tailwind. Tailwind solo recibe el string ya formateado.

¿Cómo hago que los datos del dashboard se actualicen en tiempo real?

Necesitas JavaScript para polling o WebSockets. Cada X segundos, haces fetch a tu API y actualizas los valores con element.textContent = nuevoValor. Las transiciones CSS (transition-all duration-500) harán que los cambios sean suaves. Para las barras de progreso, actualiza bar.style.width = nuevoPorcentaje + '%' y la transición CSS animará el cambio automáticamente.
