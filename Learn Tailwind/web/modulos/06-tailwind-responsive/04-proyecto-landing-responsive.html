Proyecto: Landing Page Responsive Completa

Módulo 6 · Tailwind: Responsive y Temas ⏱ 55 minutos

1 · Introducción

Este es el proyecto final del Módulo 6. Vamos a construir una landing page profesional completa usando todo lo aprendido: mobile-first con breakpoints, dark mode con toggle, y un diseño moderno que funciona en cualquier dispositivo.

Lo que construirás:

  • Navbar con logo, enlaces de navegación y toggle de tema oscuro/claro con iconos SVG.
  • Hero con título, subtítulo, botones CTA y una imagen decorativa.
  • Features en grid responsive: 1 columna en móvil, 2 en tablet, 3 en desktop.
  • Testimonios con scroll horizontal (snap-x) y tarjetas con foto, nombre y cargo.
  • Pricing con 3 columnas, la central destacada con borde y sombra especial.
  • CTA con fondo de acento y botón de acción.
  • Footer con columnas de enlaces y copyright.

💡 ¿Por qué este proyecto es importante?

Una landing page es la carta de presentación de cualquier producto o servicio en internet. Combina TODOS los conceptos del módulo: mobile-first, breakpoints, dark mode, contenedores responsive, grid, flex y diseño visual. Al terminar, tendrás una plantilla que puedes reutilizar para cualquier proyecto personal o profesional. Es el tipo de trabajo que marca la diferencia en un portfolio.

2 · Teoría

Arquitectura de la landing page

Organizamos el CSS (o las clases de Tailwind) en secciones independientes. Cada sección es autónoma: tiene su propio espaciado, su propio responsive y sus propias variantes de dark mode. La página se construye apilando estas secciones verticalmente.

ARQUITECTURA POR SECCIONES: <body> <nav> ← Sección 1: Navbar (sticky, con toggle de tema) <header> ← Sección 2: Hero (fondo con gradiente, texto centrado) <section> ← Sección 3: Features (grid responsive) <section> ← Sección 4: Testimonios (snap-x horizontal) <section> ← Sección 5: Pricing (3 cards, centro destacada) <section> ← Sección 6: CTA (fondo acento, texto centrado) <footer> ← Sección 7: Footer (grid de enlaces) </body> Cada <section> es independiente: se puede quitar, reordenar o añadir sin afectar a las demás.

Estrategia mobile-first aplicada

Cada sección empieza con el diseño móvil (1 columna, padding mínimo) y añade complejidad con prefijos md: y lg:. La regla: nunca uses un prefijo sin tener el estilo base sin prefijo primero.

<!-- Mobile-first aplicado a cada sección -->

<!-- Features: 1 col → 2 cols (md) → 3 cols (lg) -->
<div class="grid grid-cols-1 md:grid-cols-2 lg:grid-cols-3 gap-6">

<!-- Contenedor: padding crece con el ancho -->
<div class="max-w-7xl mx-auto px-4 sm:px-6 lg:px-8">

<!-- Hero: texto centrado siempre, más grande en desktop -->
<h1 class="text-3xl sm:text-4xl lg:text-5xl font-bold text-center">

<!-- Pricing: 1 col → 3 cols en lg, centro destacado -->
<div class="grid grid-cols-1 lg:grid-cols-3 gap-8">

Estrategia de dark mode: clase .dark en el html

Usamos la estrategia selector (la que aprendiste en la lección 2): un script en el <head> aplica la clase .dark al <html> antes de pintar, y todas las variantes visuales usan el prefijo dark:. El toggle es un botón en la navbar que alterna la clase y persiste en localStorage.

<head>
  <script>
    if (localStorage.getItem('theme') === 'dark' ||
        (!localStorage.getItem('theme') &&
         window.matchMedia('(prefers-color-scheme: dark)').matches)) {
      document.documentElement.classList.add('dark');
    }
  </script>
</head>

Testimonios con scroll snap

El scroll snapping es una técnica CSS que hace que el scroll horizontal se "enganche" a cada tarjeta, como un carrusel nativo sin JavaScript. Las propiedades clave:

.testimonials-container {
  display: flex;
  overflow-x: auto;
  scroll-snap-type: x mandatory;  /* El scroll se engancha en el eje X */
  -webkit-overflow-scrolling: touch;
  scrollbar-width: none;  /* Oculta la barra de scroll en Firefox */
}

.testimonial-card {
  flex: 0 0 auto;
  width: 320px;  /* Ancho fijo en móvil */
  scroll-snap-align: start;  /* Punto de enganche al inicio de cada card */
}

/* En Tailwind: snap-x snap-mandatory overflow-x-auto */
/* Cada card: snap-start shrink-0 w-[320px] */

Pricing con columna destacada

Un patrón clásico de SaaS: 3 columnas de precio, la del centro ligeramente más grande y con un borde o sombra que la hace destacar. En diseño responsive, en móvil van apiladas (la destacada se ve igual que las otras, pero sigue teniendo el badge "Más popular").

3 · Ejemplo mínimo

El esqueleto mínimo de la landing page con todas las secciones vacías, el script de dark mode y el toggle. Esto es lo que usaremos como punto de partida.

<!DOCTYPE html>
<html lang="es">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">

  <script>
    if (localStorage.getItem('theme') === 'dark' ||
        (!localStorage.getItem('theme') &&
         window.matchMedia('(prefers-color-scheme: dark)').matches)) {
      document.documentElement.classList.add('dark');
    }
  </script>

  <script src="https://cdn.jsdelivr.net/npm/@tailwindcss/browser@4"></script>
  <style type="text/tailwindcss">
    /* v4 CSS-first: cambiamos la estrategia de dark mode a selector (clase .dark) */
    @custom-variant dark (&:where(.dark, .dark *));
  </style>

  <style>
    *, *::before, *::after {
      transition: background-color 0.3s ease, color 0.3s ease, border-color 0.3s ease;
    }
  </style>
</head>
<body class="bg-white dark:bg-gray-950 text-gray-900 dark:text-gray-100">

  <!-- Navbar -->
  <nav>...</nav>

  <!-- Hero -->
  <header>...</header>

  <!-- Features -->
  <section id="features">...</section>

  <!-- Testimonios -->
  <section id="testimonios">...</section>

  <!-- Pricing -->
  <section id="pricing">...</section>

  <!-- CTA -->
  <section id="cta">...</section>

  <!-- Footer -->
  <footer>...</footer>

  <script>
    document.getElementById('theme-toggle').addEventListener('click', () => {
      const isDark = document.documentElement.classList.toggle('dark');
      localStorage.setItem('theme', isDark ? 'dark' : 'light');
    });
  </script>
</body>
</html>

Decisiones de diseño explicadas:

  • Navbar sticky con backdrop-blur: el fondo semitransparente (bg-white/80) con backdrop-blur crea ese efecto de "vidrio esmerilado" tan popular. La navbar permanece fija al hacer scroll sin tapar el contenido.
  • Hero con gradiente: from-blue-50 via-white to-indigo-50 crea un fondo suave que se oscurece elegantemente en dark mode (dark:from-gray-900 dark:via-gray-950 dark:to-blue-950).
  • Features con efecto hover: group-hover:scale-110 en el icono y hover:border-blue-200 en la tarjeta crean una micro-interacción agradable sin ser intrusiva.
  • Testimonios con scroll snap: snap-x snap-mandatory en el contenedor y snap-start en cada tarjeta. El scroll horizontal se "engancha" a cada testimonio. Sin JavaScript.
  • Pricing con columna destacada: la tarjeta central usa border-blue-600 (borde azul), shadow-xl shadow-blue-600/10 y lg:scale-105 (ligeramente más grande en desktop). El badge "Más popular" está posicionado con absolute -top-3.
  • CTA con formulario: fondo azul sólido con texto blanco. El formulario tiene un input y un botón en línea (flex row en sm+, columna en móvil).

5 · Buenas prácticas

HazEvitaPor qué
Diseña cada sección de forma independiente Depender de márgenes entre secciones para el espaciado Cada <section> debe tener su propio py-20 lg:py-28. Así puedes reordenarlas o eliminarlas sin romper el layout.
Usa max-w-7xl mx-auto px-4 sm:px-6 lg:px-8 en cada contenedor Usar la clase container de Tailwind El container de Tailwind tiene max-widths fijos por breakpoint que a veces son incómodos. Controlar el ancho manualmente con max-w-7xl es más predecible.
Prueba dark mode en cada sección Asumir que los colores funcionan igual en ambos modos Abre el toggle de tema y revisa cada sección. Los gradientes, sombras y colores de texto necesitan ajustes específicos en dark mode.
Usa snap-x snap-mandatory para carruseles Implementar un carrusel con JavaScript solo para 4 tarjetas El scroll snap nativo es más rápido, no requiere JS y funciona con gestos táctiles. Solo usa JS cuando necesites botones de navegación o autoplay.
Mantén el HTML semántico Usar <div> para todo <nav> para navegación, <header> para hero, <section> para cada sección, <footer> para el pie. Los lectores de pantalla y el SEO lo agradecen.

6 · Errores habituales

Error 1: Olvidar los anchos de línea en testimonios

Sin shrink-0 y un ancho fijo, las tarjetas de testimonio se encogen hasta volverse ilegibles en el scroll horizontal.

❌ Incorrecto

<div class="snap-start">  <!-- Sin shrink-0 ni ancho fijo -->
  <p>Texto del testimonio...</p>
</div>

✅ Correcto

<div class="snap-start shrink-0 w-[320px] sm:w-[380px]">
  <p>Texto del testimonio...</p>
</div>

Error 2: La columna de pricing destacada se desborda en móvil

Si usas scale-105 sin el prefijo lg:, la tarjeta destacada se escala también en móvil, donde no hay espacio suficiente.

❌ Incorrecto

<div class="scale-105">  <!-- Escalado en TODOS los tamaños -->

✅ Correcto

<div class="lg:scale-105">  <!-- Solo escalado en desktop -->

Error 3: No probar la landing con el teclado

Los enlaces de navegación, el toggle de tema y los botones CTA deben ser accesibles con Tab. Si usas <div onclick> en lugar de <button> o <a>, rompes la navegación por teclado.

❌ Incorrecto

<div onclick="..." class="cursor-pointer">Comenzar</div>

✅ Correcto

<a href="#cta" class="...">Comenzar</a>
<button id="theme-toggle" class="...">Toggle</button>

9 · Resumen

📌 Conceptos clave del proyecto
  • Mobile-first: cada sección empieza con el estilo base (móvil) y añade md: y lg: para pantallas más grandes. Nunca un prefijo sin su estilo base.
  • Dark mode completo: script anti-flash en <head>, prefijo dark: en cada elemento, toggle con persistencia en localStorage, transiciones suaves.
  • Navbar sticky: sticky top-0 z-50 con backdrop-blur para el efecto vidrio esmerilado. Enlaces ocultos en móvil (hidden md:flex).
  • Features grid: grid-cols-1 md:grid-cols-2 lg:grid-cols-3 con tarjetas que tienen efecto hover (group-hover:scale-110).
  • Testimonios con scroll snap: snap-x snap-mandatory + snap-start shrink-0 w-[320px]. Carrusel nativo sin JavaScript.
  • Pricing con destacado: 3 columnas, la central con border-blue-600, shadow-xl y lg:scale-105. Badge "Más popular" posicionado con absolute.
  • CTA con formulario: fondo sólido, input + botón en flex row, centrado.
  • Footer con grid: grid-cols-2 md:grid-cols-4 para las columnas de enlaces.

10 · Preguntas frecuentes

¿Puedo usar esta landing page en un proyecto real?

Absolutamente. Las secciones son modulares: puedes copiar solo la navbar, solo el pricing o la landing entera. Cambia los colores (azul por tu color de marca), el contenido (textos e iconos) y las imágenes, y tienes una landing page lista para producción. La estructura responsive y el dark mode están probados en todos los breakpoints.

¿Cómo añado imágenes reales a las tarjetas de features?

Sustituye los emojis (📦) por SVG inline o por <img>. Si usas <img>, añade w-14 h-14 object-cover rounded-xl para mantener el formato. Para iconos, los SVG inline con w-8 h-8 text-blue-600 son la mejor opción porque heredan colores y no necesitan peticiones HTTP adicionales.

¿El scroll snap funciona en todos los navegadores?

Sí. Safari (iOS y macOS) fue el primero en soportarlo, Chrome y Firefox lo añadieron después. Tiene soporte universal desde 2020. En navegadores muy antiguos, las tarjetas simplemente hacen scroll horizontal sin "engancharse" — no se rompe nada, solo pierdes el efecto snap. Para producción, añade los prefijos -webkit- si tu audiencia incluye dispositivos iOS antiguos.

¿Cómo evito que la landing se vea "genérica"?

El esqueleto (navbar, hero, features, testimonios, pricing, CTA, footer) es un patrón probado. Lo que la hace única es: (1) tu paleta de colores personalizada con @theme. (2) tu contenido real, no Lorem Ipsum. (3) imágenes, ilustraciones o capturas de pantalla de tu producto. (4) micro-interacciones: animaciones sutiles, efectos hover con personalidad. La estructura es genérica; el contenido y los detalles visuales son lo que la diferencian.

¿Cómo integro esta landing con un framework como React o Vue?

Cada sección (<nav>, <header>, <section>, <footer>) se convierte en un componente. Las clases de Tailwind se mantienen exactamente igual. El script del toggle de tema va en un useEffect (React) o onMounted (Vue). El script anti-flash del <head> puede ir en el index.html (Vite) o en el _document.js (Next.js). En el Módulo 8 verás la integración con frameworks en detalle.

¿Es necesario el CDN de Tailwind para este proyecto?

Para prototipado, el CDN es perfecto: copias, pegas y ves el resultado instantáneamente. Para producción, deberías usar una instalación local con Vite (como aprendiste en el Módulo 0). La instalación local te da: árbol de clases sacudido (solo se incluyen las clases que usas), compilación JIT, plugins, y un bundle CSS de ~10KB en lugar de cargar el CDN completo. El código HTML es idéntico; solo cambia cómo cargas Tailwind.
