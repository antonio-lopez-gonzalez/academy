El modelo de caja

Módulo 1 · CSS: Fundamentos ⏱ 30 minutos

1 · Introducción

Imagina que compras un móvil nuevo por internet. La caja que recibes no es solo el móvil: viene dentro de un embalaje de plástico, rodeado de espuma protectora, metido en una caja de cartón con el logo de la marca. Si midieras la caja exterior, no mide lo mismo que el móvil — es más grande, porque incluye todo el embalaje.

En CSS, cada elemento HTML es exactamente igual: una caja con capas.

El modelo de caja (box model) es el concepto más fundamental de CSS. Absolutamente todo lo que ves en una página web — un botón, un párrafo, una imagen, un div — es una caja rectangular compuesta por cuatro capas. Dominar este modelo es la diferencia entre entender por qué las cosas se posicionan como lo hacen y pasar horas peleándote con anchos que "no cuadran".

Al terminar esta lección sabrás:

  • Las cuatro capas del modelo de caja y cómo se apilan.
  • La diferencia entre content-box y border-box, y por qué TODO el mundo usa border-box.
  • Cómo usar las DevTools del navegador para visualizar y depurar el modelo de caja.
  • Controlar desbordamientos con overflow y dimensiones mínimas/máximas.

2 · Teoría

Las cuatro capas del modelo de caja

Cada elemento HTML es un rectángulo. Cuando el navegador renderiza la página, calcula el tamaño y la posición de ese rectángulo en función de cuatro capas concéntricas, de dentro hacia fuera:

           ┌──────────────────────────────┐
           │           margin             │  ← espacio EXTERIOR (no visible)
           │  ┌────────────────────────┐  │
           │  │        border          │  │  ← borde de la caja (visible)
           │  │  ┌──────────────────┐  │  │
           │  │  │     padding      │  │  │  ← relleno interior (fondo visible)
           │  │  │  ┌────────────┐  │  │  │
           │  │  │  │  content   │  │  │  │  ← el contenido (texto, imagen)
           │  │  │  └────────────┘  │  │  │
           │  │  └──────────────────┘  │  │
           │  └────────────────────────┘  │
           └──────────────────────────────┘
Capa Propiedad ¿Es visible? ¿Afecta al tamaño total? Analogía
content width / height Sí — el propio contenido Sí El móvil en sí
padding padding Sí — se pinta del color de fondo Sí (dependiendo de box-sizing) La espuma protectora pegada al móvil
border border Sí — línea alrededor Sí (dependiendo de box-sizing) El plástico duro que envuelve la espuma
margin margin No — es espacio transparente Sí — separa de otros elementos El aire entre la caja y otras cajas

El tamaño de cada lado es independiente

Puedes controlar cada capa de forma individual por cada lado (arriba, derecha, abajo, izquierda):

.caja {
  padding-top: 16px;
  padding-right: 32px;
  padding-bottom: 16px;
  padding-left: 32px;

  margin: 10px 20px;  /* arriba/abajo=10px, izquierda/derecha=20px */

  border-width: 2px 4px; /* arriba/abajo=2px, izquierda/derecha=4px */
}

box-sizing: la propiedad que lo cambió TODO

Aquí está el meollo de la cuestión. CSS tiene dos modos de calcular el ancho/alto de un elemento, controlados por box-sizing:

content-box (el valor por defecto original de CSS)

Con box-sizing: content-box, width y height definen SOLO el área de contenido. El padding y el border se suman al ancho total. Esto es contraintuitivo:

.caja {
  box-sizing: content-box;
  width: 200px;
  padding: 20px;    /* 20px a cada lado → +40px total */
  border: 5px solid blue; /* 5px a cada lado → +10px total */
  /* ANCHO REAL = 200 + 40 + 10 = 250px  ← ¡SORPRESA! */
}

Si diseñas pensando en una caja de 200px y el navegador te la pinta de 250px, es frustrante. Bienvenido al CSS de los años 2000.

border-box (el valor que cambió el juego)

Con box-sizing: border-box, width y height definen el tamaño TOTAL de la caja (incluyendo padding y border). El contenido se encoge para hacer sitio:

.caja {
  box-sizing: border-box;
  width: 200px;
  padding: 20px;    /* 20+20=40px van DENTRO de los 200px */
  border: 5px solid blue; /* 5+5=10px van DENTRO de los 200px */
  /* ANCHO REAL = 200px  ← ¡LO QUE ESPERABAS! */
  /* CONTENIDO = 200 - 40 - 10 = 150px */
}

¿Por qué TODO el mundo usa border-box? Porque coincide con la intuición humana: "quiero que esta caja mida 200px de ancho". Punto. No "quiero que el contenido mida 200px y luego a ver cuánto ocupa en total". Esta fue una decisión tan universalmente aplaudida que prácticamente todos los frameworks CSS (incluido Tailwind) resetean el box-sizing a border-box desde el principio:

/* El reset universal más importante de la web moderna */
*, *::before, *::after {
  box-sizing: border-box;
}

Este fragmento está en el corazón de Tailwind y de prácticamente cualquier proyecto web serio. Apréndetelo de memoria.

margin: el espacio que no se ve pero se nota

El margin es la capa más externa. Es transparente: no se pinta del color de fondo de la caja ni de ningún color. Su único propósito es separar la caja de otros elementos.

Un detalle crucial: los márgenes verticales de elementos adyacentes colapsan. Si tienes un <p> con margin-bottom: 20px y el siguiente <p> tiene margin-top: 30px, el espacio entre ellos no es 50px — es 30px (el mayor gana). Esto es el margin collapsing y es una de las peculiaridades más confusas de CSS al principio. Tailwind evita este problema usando espaciado consistente y predecible.

width, height y sus variantes

Propiedad Qué hace Ejemplo de uso
width / height Tamaño fijo width: 300px — siempre 300px
min-width / min-height No deja que sea más pequeño que este valor min-height: 100vh — al menos toda la pantalla
max-width / max-height No deja que sea más grande que este valor max-width: 600px — ideal para texto legible

Las combinaciones son muy potentes: width: 100%; max-width: 800px hace que la caja ocupe todo el ancho disponible, pero nunca más de 800px. Es el patrón más usado para contenedores de contenido.

overflow: cuando el contenido no cabe en la caja

¿Qué pasa si el contenido es más grande que la caja? Depende de overflow:

  • visible (default): el contenido sobresale de la caja. Útil casi nunca.
  • hidden: el contenido sobrante se recorta y no se ve. Útil para imágenes decorativas.
  • scroll: aparecen barras de scroll siempre, aunque no hagan falta.
  • auto: aparecen barras de scroll solo si el contenido desborda. La opción más práctica.

3 · Ejemplo mínimo

Dos cajas: una con content-box y otra con border-box. Ambas tienen width: 300px, mismo padding y mismo borde. Una mide 300px de ancho total. La otra, 370px.

<!-- Con content-box: el ancho real es 300 + 60(padding) + 10(border) = 370px -->
<div class="caja content-box">Soy content-box: mi ancho real es 370px</div>

<!-- Con border-box: el ancho real son los 300px que pedí -->
<div class="caja border-box">Soy border-box: mi ancho real es 300px</div>
.caja {
  width: 300px;
  padding: 30px;
  border: 5px solid #333;
  background: #e2e8f0;
  margin-bottom: 16px;
  font-family: sans-serif;
}
.content-box {
  box-sizing: content-box; /* el defecto histórico */
}
.border-box {
  box-sizing: border-box;  /* el que deberías usar siempre */
}

La diferencia visual es inmediata: la primera caja es notablemente más ancha. Si estuvieras maquetando una fila de tres cajas de 300px dentro de un contenedor de 900px, con content-box la tercera caja se saldría. Con border-box encajan perfectamente.

4 · Ejemplo real

Construyamos una tarjeta de producto típica, aprovechando todo lo aprendido sobre el modelo de caja:

<div class="product-card">
  <img src="https://placehold.co/600x400/e2e8f0/475569?text=Zapatillas" alt="Producto">
  <div class="product-card__body">
    <span class="product-card__badge">Nuevo</span>
    <h3>Zapatillas UltraBoost Pro</h3>
    <p>Máxima amortiguación para running y trail. Suela Vibram.</p>
    <div class="product-card__price">129.99 €</div>
  </div>
</div>
/* Reset obligatorio */
*, *::before, *::after { box-sizing: border-box; margin: 0; padding: 0; }

body {
  font-family: system-ui, sans-serif;
  background: #f1f5f9;
  padding: 40px;
}

.product-card {
  max-width: 360px;    /* nunca más ancho de 360px */
  background: white;
  border-radius: 12px;
  overflow: hidden;     /* la imagen redondeada no sobresale */
  box-shadow: 0 4px 24px rgba(0,0,0,0.08);
}

.product-card img {
  width: 100%;          /* ocupa todo el ancho de la tarjeta */
  height: 220px;
  object-fit: cover;    /* recorta sin deformar */
}

.product-card__body {
  padding: 24px;        /* espacio interior generoso */
}

.product-card__badge {
  display: inline-block;
  padding: 4px 12px;
  background: #10b981;
  color: white;
  border-radius: 100px;
  font-size: 12px;
  font-weight: 700;
  text-transform: uppercase;
  margin-bottom: 12px;
}

.product-card h3 {
  font-size: 20px;
  margin-bottom: 8px;
}

.product-card p {
  color: #64748b;
  line-height: 1.5;
  margin-bottom: 16px;
  max-width: 50ch;      /* ~50 caracteres de ancho para legibilidad */
}

.product-card__price {
  font-size: 24px;
  font-weight: 700;
  color: #0f172a;
}

Varias decisiones importantes en este ejemplo:

  • max-width + no width fijo: La tarjeta se adapta a contenedores más pequeños. Con width: 360px fijo se desbordaría en móvil.
  • overflow: hidden en la tarjeta: Sin esto, la imagen sobresaldría del border-radius de la tarjeta y las esquinas no se verían redondeadas.
  • object-fit: cover en la imagen: La imagen se recorta proporcionalmente para llenar el espacio. Sin esto, se deformaría o dejaría huecos.
  • padding en lugar de margin para espacio interior: El padding es parte de la caja (el fondo blanco lo cubre). El margin sería un espacio transparente fuera de la tarjeta, que no es lo que queremos.

6 · Errores habituales

🚫 "Mi caja mide 200px en CSS pero en el navegador es más grande"

No has puesto box-sizing: border-box. Sin él, width: 200px solo define el área de contenido, y el padding + border se suman por fuera. Solución: añade el reset universal al inicio de tu CSS. Es lo primero que deberías escribir en cualquier proyecto.

🚫 "Mis márgenes no se suman como esperaba entre dos elementos"

Estás experimentando margin collapsing: los márgenes verticales de bloques adyacentes colapsan al mayor de los dos, no se suman. Si el primer elemento tiene margin-bottom: 20px y el segundo margin-top: 30px, el espacio total es 30px, no 50px. Esto solo afecta a márgenes verticales, no horizontales. Solución: usa padding para espaciado interior o gap con flexbox/grid.

🚫 "Puse height: 100% pero no funciona"

El porcentaje en height necesita una referencia: el elemento padre debe tener una altura definida. Si el padre no tiene height explícito, height: 100% se calcula como auto. Solución: usa min-height: 100vh en el ancestro raíz (html, body) o usa flexbox/grid que no dependen de alturas explícitas.

🚫 "Mi imagen se sale del borde redondeado de la tarjeta"

Tienes border-radius en el contenedor pero la imagen es cuadrada y sobresale. border-radius no recorta el contenido por sí mismo. Necesitas overflow: hidden en el contenedor para que el contenido que desborda se recorte respetando el radio del borde.

7 · Ejercicio guiado

Vamos a construir paso a paso un "sistema de notificaciones" con tres tipos de alerta (éxito, aviso, error). Cada alerta será una caja con icono, texto y botón de cierre. Aplicaremos todo lo del modelo de caja.

Paso 1: El HTML base

<div class="alert alert--success">
  <span class="alert__icon">✅</span>
  <p class="alert__text">Tu pedido se ha enviado correctamente.</p>
  <button class="alert__close">×</button>
</div>

<div class="alert alert--warning">
  <span class="alert__icon">⚠️</span>
  <p class="alert__text">Tu suscripción caduca en 3 días.</p>
  <button class="alert__close">×</button>
</div>

<div class="alert alert--error">
  <span class="alert__icon">❌</span>
  <p class="alert__text">El pago ha sido rechazado. Intenta de nuevo.</p>
  <button class="alert__close">×</button>
</div>

Paso 2: El CSS — modelo de caja en acción

*, *::before, *::after { box-sizing: border-box; margin: 0; padding: 0; }

body {
  font-family: system-ui, sans-serif;
  padding: 32px;
  background: #f8fafc;
}

.alert {
  max-width: 520px;
  padding: 16px 20px;      /* vertical | horizontal */
  border-radius: 10px;
  border: 1px solid;
  margin-bottom: 12px;     /* separación entre alertas (fuera de la caja) */
  display: flex;
  align-items: flex-start;
  gap: 12px;
}

.alert--success {
  background: #f0fdf4;     /* verde muy claro */
  border-color: #86efac;   /* verde suave */
  color: #166534;          /* texto verde oscuro */
}

.alert--warning {
  background: #fffbeb;
  border-color: #fcd34d;
  color: #92400e;
}

.alert--error {
  background: #fef2f2;
  border-color: #fca5a5;
  color: #991b1b;
}

.alert__icon { font-size: 20px; flex-shrink: 0; }
.alert__text { flex: 1; line-height: 1.5; }
.alert__close {
  background: none;
  border: none;
  font-size: 22px;
  cursor: pointer;
  color: inherit;
  opacity: 0.5;
  padding: 0 4px;
  flex-shrink: 0;
}

Decisiones de modelo de caja en este código:

  • max-width + no width: Las alertas se adaptan a cualquier pantalla sin desbordar.
  • padding en la alerta: El color de fondo (verde, amarillo, rojo) cubre TODO el interior incluyendo el padding — el icono, texto y botón tienen "aire" alrededor.
  • margin-bottom entre alertas: Espacio transparente fuera de cada caja para separarlas entre sí.
  • border: Un borde sutil del mismo tono que el fondo para dar definición. Sin border-radius las alertas serían cuadradas y toscas.
  • flex-shrink: 0 en icono y botón: Evita que se encojan si el texto es muy largo.

8 · Reto

🎯 Construye una card de perfil de usuario

Crea desde cero una tarjeta de perfil con las siguientes características:

  • Un avatar circular de 96x96px en la parte superior, centrado, que sobresalga ligeramente hacia arriba de la tarjeta (usa margin negativo).
  • Nombre del usuario, cargo y un texto corto de bio.
  • Padding interior de 32px arriba y 24px en los demás lados (para compensar el avatar que sobresale).
  • La tarjeta debe tener un ancho máximo de 340px y centrarse en la página.
  • Borde sutil, sombra suave y bordes redondeados.
  • Un borde de 3px blanco alrededor del avatar para separarlo del fondo.

Restricciones:

  • Usa box-sizing: border-box como reset global.
  • No uses flexbox ni grid para centrar (aún no hemos llegado). Usa margin: 0 auto para centrar horizontalmente y text-align: center para el contenido.
  • Escribe el CSS a mano. No uses Tailwind (todavía).

9 · Resumen

  • Todo elemento HTML es una caja rectangular con 4 capas concéntricas: content → padding → border → margin (de dentro hacia fuera).
  • content-box (el valor por defecto histórico): width define solo el contenido. Padding y border se suman. Es confuso e inesperado.
  • border-box: width define el tamaño total de la caja. Padding y border se restan del espacio del contenido. Es lo que intuitivamente esperas. Úsalo siempre.
  • El reset universal *, *::before, *::after { box-sizing: border-box; } es la primera línea de CSS que deberías escribir en cualquier proyecto. Tailwind ya lo hace por ti.
  • margin es transparente (no se colorea con el fondo), padding sí se colorea. Usa padding para "aire" dentro de la caja y margin para separar cajas entre sí.
  • margin collapsing: los márgenes verticales de bloques adyacentes no se suman, colapsan al valor más grande. Es un comportamiento esperado de CSS, no un bug.
  • max-width y min-height son más flexibles y seguros que width/height fijos. Prefiere max-width para texto y contenedores, y min-height: 100vh para secciones a pantalla completa.
  • overflow: hidden + border-radius es la combinación mágica para tarjetas con imágenes redondeadas que no sobresalen.
  • Las DevTools del navegador muestran el modelo de caja completo en la pestaña Styles/Computed. Es tu mejor herramienta de depuración: úsala siempre.

10 · Preguntas frecuentes

¿Por qué el W3C eligió content-box como valor por defecto original?

El modelo de caja se diseñó a mediados de los 90, cuando la web era fundamentalmente documentos de texto. En un documento, lo lógico era que width definiera el ancho del texto (el contenido) y el padding fuera un extra. Con la llegada del diseño web moderno (layouts, interfaces, aplicaciones), esta decisión resultó ser un error monumental. Pero por compatibilidad hacia atrás, no se pudo cambiar el defecto. Por eso existe border-box como "parche" que todo el mundo usa.

¿Tailwind usa border-box? ¿Tengo que preocuparme?

Sí, Tailwind incluye el reset box-sizing: border-box por defecto en su preflight (su versión de normalize.css). No tienes que preocuparte. Todo el sistema de espaciado de Tailwind (p-, m-, w-, h-, etc.) asume border-box. Es una de las razones por las que Tailwind "simplemente funciona" sin cálculos extraños.

¿Los márgenes negativos son mala práctica?

No son mala práctica en absoluto. Son una herramienta perfectamente válida para solapamientos controlados (como el avatar que sobresale de una tarjeta). Tailwind incluye clases para márgenes negativos (-mt-4, -ml-2, etc.). Lo que sí es mala práctica es usar márgenes negativos para "arreglar" un layout mal diseñado — si estás poniendo márgenes negativos por todas partes para que las cosas encajen, probablemente tu estructura de layout es incorrecta.

¿Cuándo debo usar width fijo vs max-width?

Usa width fijo cuando el elemento deba tener un tamaño exacto: un icono, un avatar, una miniatura. Usa max-width cuando el elemento deba ser flexible pero no superar un límite: una columna de texto, una tarjeta, un contenedor de contenido. La regla general: si dudas, usa max-width. Es más seguro en responsive.

¿El modelo de caja afecta a los elementos inline como <span>?

Sí, pero con diferencias importantes. Los elementos inline (como <span>, <a>) ignoran width y height — su tamaño lo determina el contenido. El padding y el border sí se aplican visualmente, pero el margin solo funciona en horizontal (izquierda/derecha), no en vertical. El margin y padding vertical en inline no empujan a otros elementos; simplemente se solapan. Esto cambia completamente cuando el elemento inline se convierte en inline-block, como veremos en la siguiente lección.
