Display y posicionamiento

Módulo 1 · CSS: Fundamentos ⏱ 35 minutos

1 · Introducción

Imagina que estás organizando una mudanza. Tienes cajas pequeñas (libros), muebles grandes (sofá, armario), lámparas de pie y una alfombra. Cada objeto ocupa el espacio de forma distinta: el sofá no puede apilarse como las cajas, la lámpara ocupa poco suelo pero mucho aire, la alfombra va en el suelo y los muebles van encima.

En CSS, display define cómo se comporta una caja en el flujo del documento. Es la propiedad que decide si un elemento se apila en vertical como un bloque, fluye en horizontal como un texto o se sale completamente del flujo normal. Y la propiedad position te da el poder de mover elementos con precisión quirúrgica respecto a puntos de referencia.

Al terminar esta lección sabrás:

  • Los valores fundamentales de display: block, inline, inline-block, none.
  • Los cinco tipos de posicionamiento y cuándo usar cada uno.
  • Cómo funciona z-index y el contexto de apilamiento.
  • Construir dos patrones reales: un modal con overlay y un badge posicionado sobre una card.

2 · Teoría

Display: el ADN de cada elemento HTML

Cada elemento HTML nace con un display por defecto. No es aleatorio — forma parte del diseño de HTML desde sus orígenes como lenguaje de documentos:

Valor de display Comportamiento Elementos por defecto ¿Respeta width/height?
block Ocupa TODO el ancho disponible. Empieza en nueva línea. Apila verticalmente. <div>, <p>, <h1>-<h6>, <section>, <header> Sí
inline Ocupa solo el ancho de su contenido. Fluye en horizontal como texto. No fuerza salto de línea. <span>, <a>, <strong>, <em> No — ignora width/height, y margin/padding vertical no empujan
inline-block Híbrido: fluye en horizontal como inline, pero acepta width, height, margin y padding verticales. Ninguno por defecto. Lo aplicas tú cuando lo necesitas. Sí
none El elemento desaparece completamente del flujo. No ocupa espacio. Como si no existiera. Ninguno por defecto. Se usa para esconder cosas. N/A

none vs visibility:hidden vs opacity:0 — parecen iguales, no lo son

Propiedad ¿Ocupa espacio? ¿Recibe eventos (click)? ¿Transicionable?
display: none No No No — desaparece instantáneamente
visibility: hidden Sí — deja un hueco invisible No Sí, si lo combinas con opacity
opacity: 0 Sí Sí — ¡cuidado! Un botón invisible pero clickable Sí — se puede animar con transition

Para animar la desaparición de un elemento necesitas una estrategia combinada: transicionas opacity a 0, y cuando la transición termina aplicas visibility: hidden (o eliminas el elemento del DOM).

Posicionamiento: los cinco modos

static (el valor por defecto)

El elemento se coloca según el flujo normal del documento. Ignora top, right, bottom, left y z-index. Es como un alumno sentado en su pupitre asignado: no se mueve de ahí.

relative

El elemento se coloca en el flujo normal, pero puedes desplazarlo respecto a su posición original usando top, right, bottom, left. El espacio original se respeta — los demás elementos no se recolocan. Es como si te levantas del pupitre y das un paso a la derecha: tu silla sigue ahí, ocupando tu sitio.

.caja {
  position: relative;
  top: 10px;     /* 10px hacia ABAJO desde su posición original */
  left: -5px;    /* 5px hacia la IZQUIERDA desde su posición original */
}

El uso más importante de relative en la práctica no es mover el elemento, sino crear un contexto de posicionamiento para hijos con position: absolute.

absolute

El elemento sale completamente del flujo. Los demás elementos se recolocan como si no existiera. Se posiciona respecto al ancestro posicionado más cercano (un ancestro con position: relative, absolute, fixed o sticky). Si no encuentra ninguno, se posiciona respecto al <html>.

.contenedor {
  position: relative;  /* crea el contexto de posicionamiento */
}
.badge {
  position: absolute;
  top: -8px;
  right: -8px;         /* se coloca en la esquina superior derecha del contenedor */
}

Regla de oro: el hijo absolute necesita un padre relative. Sin esta combinación, los posicionamientos absolutos se vuelven impredecibles porque se anclan al viewport o al html.

fixed

Similar a absolute, pero se posiciona respecto al viewport (la ventana del navegador). No se mueve al hacer scroll. Ideal para navbars fijas, modales, botones de "volver arriba" y cookies banners.

sticky

Un híbrido entre relative y fixed. Se comporta como relative hasta que el scroll llega a un umbral (definido con top), momento en el que "se pega" y se comporta como fixed. Perfecto para headers de tabla o sidebars que acompañan al hacer scroll.

.sticky-header {
  position: sticky;
  top: 0;  /* se pega al llegar al borde superior del viewport */
}

Cuidado: sticky solo funciona si el ancestro contenedor tiene altura suficiente para "desplazarse". Si el contenedor padre mide lo mismo que el elemento sticky, nunca se activará.

z-index y el contexto de apilamiento

Cuando varios elementos se solapan (por posicionamiento), z-index decide quién va delante. Solo funciona en elementos posicionados (relative, absolute, fixed, sticky).

Un contexto de apilamiento es como una "burbuja" que contiene sus propios z-index, aislados del exterior. Un contexto nuevo se crea con:

  • position: relative/absolute/fixed/sticky + z-index (cualquier valor que no sea auto).
  • opacity menor que 1.
  • transform, filter, perspective.

Dentro de cada contexto de apilamiento, los z-index son un micro-universo. Un elemento con z-index: 9999 dentro de un contexto de apilamiento NUNCA se pondrá por encima de un elemento con z-index: 1 de otro contexto de apilamiento "superior". Este es uno de los bugs más frustrantes y difíciles de depurar en CSS.

3 · Ejemplo mínimo

Tres cajas: una block (por defecto), una inline-block y una absolute dentro de un contenedor relative.

<div class="box box--block">Soy block — ocupo todo el ancho</div>
<span class="box box--inline-block">Soy inline-block</span>
<span class="box box--inline-block">Yo también — fluimos juntos</span>
<div class="relative-parent">
  Soy el padre relative
  <div class="absolute-child">Soy absolute — colocado en la esquina</div>
</div>
.box { padding: 16px; margin: 8px; border-radius: 8px; }
.box--block { background: #dbeafe; display: block; }
.box--inline-block { background: #d1fae5; display: inline-block; width: 200px; }
.relative-parent {
  position: relative;
  width: 400px;
  height: 120px;
  background: #fef3c7;
  margin: 16px 8px;
  padding: 16px;
  border-radius: 8px;
}
.absolute-child {
  position: absolute;
  top: 8px;
  right: 8px;
  background: #fca5a5;
  padding: 8px 16px;
  border-radius: 6px;
  font-size: 14px;
}

Observa cómo el absolute-child se coloca en la esquina superior derecha del relative-parent (su ancestro posicionado), no del body. Sin position: relative en el padre, el hijo absolute se iría a la esquina del viewport.

2. Modal con overlay

<!-- El overlay cubre toda la pantalla -->
<div class="modal-overlay">
  <div class="modal">
    <h2>Confirmar eliminación</h2>
    <p>¿Estás seguro? Esta acción no se puede deshacer.</p>

  position: fixed;

  display: flex;
  align-items: center;
  justify-content: center;
  z-index: 1000;
}
.modal {
  background: white;
  border-radius: 16px;
  padding: 32px;
  max-width: 440px;
  width: 90%;
  box-shadow: 0 20px 60px rgba(0,0,0,0.3);

.modal p { color: #64748b; margin-bottom: 24px; }

El overlay usa position: fixed; inset: 0 para cubrir TODO el viewport. El modal en sí es un hijo flexbox centrado. La magia está en la combinación fixed + flex + z-index.

5 · Buenas prácticas

✅ Haz esto ❌ Evita esto 🤔 Por qué
Siempre pon position: relative al ancestro de un elemento con position: absolute Dejar un elemento absolute sin ancestro posicionado — se ancla al viewport y se descontrola al redimensionar Sin contexto de posicionamiento definido, absolute se comporta de forma impredecible en layouts responsive
Usa position: sticky para cabeceras de tabla o sidebars que deben seguir al hacer scroll Usar JavaScript con scroll events para simular sticky — es más lento y propenso a bugs sticky es nativo del navegador, no requiere JS, y funciona con GPU acceleration
Define una escala de z-index en tu proyecto (ej: 10=dropdown, 100=sticky nav, 1000=modal overlay, 10000=toast) Usar valores aleatorios como z-index: 9999 sin criterio — acabas en una guerra de z-index sin fin Una escala predefinida evita conflictos y hace que cualquier developer del equipo sepa qué esperar
Usa display: none cuando el elemento no deba existir en el flujo; usa opacity/visibility cuando necesites animar la transición Animar display — no es animable. El elemento aparece/desaparece a saltos display es una propiedad discreta (on/off). Para transiciones suaves usa opacity + visibility + transition
Usa el shorthand inset para definir los cuatro lados en posicionamiento Escribir top: 0; right: 0; bottom: 0; left: 0; manualmente inset es más conciso y semánticamente más claro: estás definiendo los bordes de posicionamiento

6 · Errores habituales

🚫 "Mi elemento absolute se va al body en vez de quedarse en su padre"

Has olvidado poner position: relative al padre. Sin él, el elemento absolute busca el ancestro posicionado más cercano subiendo por el DOM. Si no encuentra ninguno, se ancla al viewport (<html>). Solución: position: relative en el ancestro directo.

🚫 "Mi elemento sticky no se pega al hacer scroll"

Verifica tres cosas: (1) el padre del sticky debe ser más alto que el propio sticky — si miden lo mismo no hay espacio para "desplazar", (2) necesitas al menos un valor top, right, bottom o left, (3) ningún ancestro entre el sticky y el viewport puede tener overflow: hidden, overflow: auto o overflow: scroll — rompen el sticky.

🚫 "Puse z-index: 999999 y sigue sin verse por encima"

Estás atrapado en un contexto de apilamiento inferior. Recuerda: los z-index compiten SOLO dentro del mismo contexto de apilamiento. Si un ancestro crea un contexto de apilamiento (con opacity, transform, o position + z-index), todos sus hijos quedan confinados a ese contexto. Revisa los ancestros buscando opacity < 1, transform, filter, o position + z-index.

🚫 "Oculté un elemento con opacity: 0 pero sigue siendo clickable"

opacity: 0 solo oculta visualmente el elemento — sigue ahí, ocupando espacio y recibiendo eventos. Para que deje de ser interactivo sin sacarlo del flujo, usa pointer-events: none como complemento. Si además no debe ocupar espacio, usa visibility: hidden. Si nada de eso aplica, display: none.

7 · Ejercicio guiado

Construyamos un tooltip que aparece al hacer hover sobre un botón. El tooltip será un elemento con position: absolute dentro de un contenedor relative.

HTML

<div class="tooltip-wrapper">
  <button class="icon-button" aria-describedby="tooltip-msg">?</button>
  <span class="tooltip" id="tooltip-msg" role="tooltip">Haz clic aquí para más información sobre este producto</span>
</div>

CSS

.tooltip-wrapper {
  position: relative;            /* contexto para el tooltip */
  display: inline-block;         /* no ocupa todo el ancho */
}

.icon-button {
  width: 32px;
  height: 32px;
  border-radius: 50%;
  border: 2px solid #94a3b8;
  background: white;
  font-weight: 700;
  cursor: help;
  font-size: 16px;
  color: #475569;
}

.tooltip {
  position: absolute;
  bottom: calc(100% + 8px);     /* justo encima del botón + 8px */
  left: 50%;
  transform: translateX(-50%);  /* centrado horizontal */
  background: #1e293b;
  color: white;
  padding: 8px 14px;
  border-radius: 8px;
  font-size: 13px;
  line-height: 1.4;
  white-space: nowrap;          /* evita que el texto se parta */
  pointer-events: none;         /* el tooltip no bloquea clics */
  opacity: 0;
  visibility: hidden;
  transition: opacity 0.2s, visibility 0.2s;
}

.tooltip::after {               /* flechita triangular debajo */
  content: '';
  position: absolute;
  top: 100%;
  left: 50%;
  transform: translateX(-50%);
  border: 6px solid transparent;
  border-top-color: #1e293b;
}

.tooltip-wrapper:hover .tooltip {
  opacity: 1;
  visibility: visible;
}

Puntos clave: bottom: calc(100% + 8px) coloca el tooltip justo encima del botón. left: 50%; transform: translateX(-50%) es el patrón clásico para centrar un elemento absolute horizontalmente. El pseudo-elemento ::after crea la flechita triangular con el truco de los bordes transparentes.

9 · Resumen

  • display define cómo fluye un elemento: block apila verticalmente ocupando todo el ancho, inline fluye horizontal como texto, inline-block es el híbrido que acepta dimensiones, none desaparece del flujo.
  • Ocultar no es todo igual: display: none elimina el elemento del flujo (no ocupa espacio, no es animable), visibility: hidden ocupa espacio pero no se ve ni interactúa, opacity: 0 ocupa espacio y sigue siendo interactivo salvo que añadas pointer-events: none.
  • position: static es el valor por defecto. El elemento va donde le toca en el flujo normal.
  • position: relative desplaza el elemento respecto a su posición original. Su uso principal es crear contexto para hijos absolute.
  • position: absolute saca el elemento del flujo y lo posiciona respecto al ancestro posicionado más cercano. REGLA DE ORO: el ancestro necesita position: relative.
  • position: fixed posiciona respecto al viewport. No se mueve con el scroll. Ideal para modales, navbars fijas, botones flotantes.
  • position: sticky es el híbrido relative + fixed. Solo funciona si el contenedor es más alto y ningún ancestro tiene overflow diferente a visible.
  • z-index controla el orden de apilamiento solo entre elementos dentro del mismo contexto de apilamiento. Los contextos se crean con position + z-index, opacity < 1, transform, filter, etc.
  • Define una escala de z-index en tu proyecto para evitar la guerra del 9999.

10 · Preguntas frecuentes

¿Cuándo uso inline-block en lugar de block?

Usa inline-block cuando necesites que varios elementos fluyan en horizontal (como texto) pero cada uno acepte width, height y padding vertical. Casos típicos: botones en una toolbar, tags o etiquetas, iconos con texto al lado. Si necesitas más control sobre la distribución (espacio entre elementos, alineación), es mejor usar flexbox — flexbox reemplaza la mayoría de usos de inline-block en el diseño moderno.

¿Cómo centro un elemento absolute horizontal y verticalmente?

El patrón clásico es: top: 50%; left: 50%; transform: translate(-50%, -50%);. El top y left al 50% colocan la esquina superior izquierda en el centro. El transform: translate mueve el elemento hacia atrás la mitad de su propio ancho y alto, logrando el centrado perfecto. Con flexbox/grid en el padre también puedes centrar sin absolute, pero este patrón es imprescindible cuando el elemento DEBE ser absolute (como un badge, un tooltip o un spinner de carga).

¿Qué diferencia hay entre fixed y sticky?

fixed siempre está fijo al viewport, desde el primer momento. sticky empieza como relative (en su posición normal en el flujo) y SOLO se vuelve fixed cuando el scroll alcanza un umbral. Son para cosas distintas: fixed para elementos que siempre deben estar visibles (navbar superior), sticky para elementos que queremos que acompañen al scroll solo cuando sea necesario (cabecera de una sección larga).

¿Tailwind tiene clases para position y z-index?

Sí. Tailwind incluye .relative, .absolute, .fixed, .sticky, y el shorthand .inset-0 (equivale a top/right/bottom/left:0). Para z-index: .z-0 (0), .z-10, .z-20, .z-30, .z-40, .z-50, .z-auto. Es una escala predefinida que cubre el 99% de los casos. Cuando estudiemos Tailwind en el Módulo 4, todo esto te resultará inmediatamente familiar.

¿Por qué no puedo animar la propiedad display?

display es una propiedad discreta: solo tiene valores concretos (none, block, flex...) sin valores intermedios. No puedes tener "un 50% de block". Para animar la aparición/desaparición de un elemento, usa opacity (que sí es animable) combinado con visibility: hidden al final de la animación. Un truco moderno: @starting-style y transition-behavior: allow-discrete permiten transicionar display en navegadores modernos, pero el método opacity + visibility es universalmente compatible.
