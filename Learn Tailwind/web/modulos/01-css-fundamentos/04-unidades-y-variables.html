Unidades CSS y custom properties

Módulo 1 · CSS: Fundamentos ⏱ 30 minutos

1 · Introducción

Imagina que estás diseñando una habitación. Puedes medir todo en centímetros fijos — "la mesa mide 120 cm, la estantería 80 cm". Eso funciona en un piso concreto. Pero, ¿y si la habitación cambia de tamaño? ¿Y si quieres que la mesa ocupe siempre el 60% de la pared, sin importar lo ancha que sea?

En CSS pasa exactamente lo mismo. Hay unidades absolutas (px, cm) que no cambian nunca, y unidades relativas (%, em, rem, vw, vh) que se adaptan al contexto. Saber elegir entre ellas es lo que separa un diseño rígido que se rompe al mínimo cambio de un diseño flexible que funciona en cualquier pantalla.

Al terminar esta lección sabrás:

  • Cuándo usar px y cuándo usar unidades relativas como rem, em o %.
  • La diferencia crucial entre rem y em (herencia).
  • Cómo funcionan las unidades de viewport: vw, vh, dvh y por qué dvh es un game-changer en móviles.
  • Usar clamp(), min() y max() para responsive sin media queries.
  • Custom properties (variables CSS): scope, herencia, fallback y por qué Tailwind v4 se basa en ellas.

2 · Teoría

Unidades absolutas: el mundo del px

Un píxel CSS (px) es una unidad fija. En la mayoría de pantallas modernas, 1px CSS equivale a 1/96 de pulgada (aunque en pantallas retina puede mapearse a varios píxeles de dispositivo).

¿Cuándo usar px? Para cosas que NO deben escalar: bordes (border: 1px solid), sombras sutiles, espaciados mínimos. Para casi todo lo demás, considera unidades relativas.

¿Cuándo NO usar px? Para tamaños de fuente. Un font-size: 16px ignora la preferencia de zoom del usuario. Si alguien tiene configurado el navegador con un tamaño de fuente base más grande por accesibilidad, tus px se lo saltan. Usa rem para fuentes.

rem: la unidad reina del CSS moderno

rem = root em. Es relativo al tamaño de fuente del elemento raíz (<html>). Por defecto, los navegadores establecen font-size: 16px en el <html>. Así que:

html { font-size: 16px; }  /* el estándar del navegador */

1rem  = 16px
0.5rem = 8px
1.5rem = 24px
2rem  = 32px

Si cambias el font-size del html (por ejemplo, a 20px), TODOS los rem se recalculan automáticamente. Esto permite escalar la interfaz completa cambiando una sola línea. Tailwind usa rem para TODO su sistema de espaciado.

La escala de Tailwind usa múltiplos de 0.25rem (4px):

p-1  = 0.25rem = 4px
p-2  = 0.5rem  = 8px
p-3  = 0.75rem = 12px
p-4  = 1rem    = 16px
p-6  = 1.5rem  = 24px
p-8  = 2rem    = 32px

em: relativo al padre (y se acumula)

em es relativo al font-size del elemento padre (o del propio elemento, para font-size). Esto puede causar efectos de acumulación:

.parent { font-size: 20px; }
.parent .child { font-size: 1.5em; }  /* 1.5 × 20px = 30px */
.parent .child .grandchild { font-size: 0.8em; } /* 0.8 × 30px = 24px */

El problema con em: cada nivel de anidación multiplica. Si tienes una lista anidada con font-size: 0.9em en cada nivel, el tercer nivel es 16 × 0.9 × 0.9 × 0.9 = 11.66px. Con rem, siempre es relativo al root — no hay acumulación.

¿Cuándo usar em? Para media queries (@media (min-width: 40em)), porque em en media queries siempre es relativo al font-size del navegador, no al del documento. También para componentes autocontenidos donde quieres que el espaciado escale con el tamaño de fuente local.

% (porcentajes): relativo al padre

El porcentaje es relativo a la misma propiedad del elemento padre:

  • width: 50% → 50% del ancho del padre.
  • font-size: 120% → 120% del font-size del padre.
  • line-height: 150% → 150% del font-size del propio elemento.

Cuidado con height: 100% — solo funciona si el padre tiene una altura definida.

Unidades de viewport: vw, vh, dvh, svh, lvh

Estas unidades son relativas al tamaño del viewport (la ventana del navegador):

100vw = ancho total del viewport
100vh = alto total del viewport
50vw  = mitad del ancho
10vh  = 10% del alto

El problema con 100vh en móviles: los navegadores móviles tienen barras de navegación que aparecen/desaparecen al hacer scroll. 100vh NO tiene en cuenta estas barras, lo que hace que secciones "a pantalla completa" queden cortadas o generen scroll innecesario.

La solución moderna: dvh (dynamic viewport height), que se ajusta dinámicamente cuando las barras del navegador aparecen o desaparecen:

.hero {
  min-height: 100dvh;  /* se adapta a barras del navegador en móvil */
}

También existen svh (small viewport height — asume barras visibles) y lvh (large viewport height — asume barras ocultas). Tailwind v4 incluye min-h-dvh y min-h-svh.

Otras unidades útiles

  • ch: ancho del carácter "0" en la fuente actual. Ideal para limitar ancho de texto: max-width: 65ch (legibilidad óptima).
  • ex: altura de la letra "x" minúscula.
  • vmin: el menor entre vw y vh. Útil para elementos que deben caber en la dimensión más restrictiva.
  • vmax: el mayor entre vw y vh.

Funciones matemáticas CSS: clamp(), min(), max()

Son la navaja suiza del diseño responsive moderno. Permiten calcular valores dinámicamente sin media queries.

clamp(MÍNIMO, IDEAL, MÁXIMO): la más potente. El valor fluctúa entre un mínimo y un máximo:

/* Tamaño de fuente responsive: 16px mínimo, 2.5vw ideal, 32px máximo */
h1 { font-size: clamp(1rem, 2.5vw, 2rem); }

/* Ancho entre 280px y 600px, idealmente 50% del padre */
.card { width: clamp(280px, 50%, 600px); }

/* Padding que escala con viewport pero no baja de 16px ni sube de 64px */
section { padding: clamp(1rem, 5vw, 4rem); }

min() — elige el valor más pequeño: width: min(600px, 100%) hace que la caja sea de 600px, pero si la pantalla es más pequeña, se adapta al 100%.

max() — elige el valor más grande: padding: max(1rem, 3vw) asegura al menos 1rem de padding, pero si el viewport es grande, crece con 3vw.

Custom Properties (variables CSS)

Las custom properties son variables nativas de CSS. Se definen con --nombre: valor y se usan con var(--nombre):

:root {
  --color-primary: #6366f1;
  --color-surface: #ffffff;
  --spacing-unit: 1rem;
  --radius-card: 12px;
  --font-sans: system-ui, sans-serif;
}

.card {
  background: var(--color-surface);
  border-radius: var(--radius-card);
  padding: var(--spacing-unit);
  font-family: var(--font-sans);
}

.button {
  background: var(--color-primary);
  padding: var(--spacing-unit) calc(var(--spacing-unit) * 2);
}

Scope (ámbito) de las variables

Las variables CSS se heredan en cascada. Definir una variable en :root la hace global. Definirla en un selector más específico la limita a ese ámbito:

.card--danger {
  --color-primary: #ef4444;  /* solo afecta a .card--danger y sus hijos */
}
.card--danger .button {
  background: var(--color-primary);  /* usa el rojo redefinido */
}

Fallback

var() acepta un segundo parámetro como fallback si la variable no está definida:

.element {
  color: var(--text-color, #333);  /* si --text-color no existe, usa #333 */
}

Por qué Tailwind v4 se basa en custom properties

Tailwind v4 usa custom properties como su mecanismo interno de diseño. Cuando configuras @theme { --color-primary: blue; }, Tailwind genera variables CSS que luego usa en sus utilidades. Esto significa que:

  • Puedes sobrescribir cualquier valor de Tailwind redefiniendo su variable CSS.
  • Las variables se respetan en tiempo de ejecución (cambias la variable en JS y toda la UI responde).
  • El sistema de dark mode (dark:) se basa en cambiar variables CSS desde un selector .dark.

3 · Ejemplo mínimo

Veamos la diferencia entre rem, em, vw y % aplicados a un mismo diseño:

<div class="demo">
  <p class="rem-demo">Tamaño con rem (relativo al html)</p>
  <p class="em-demo">Tamaño con em (relativo al padre)</p>
  <div class="percent-demo">50% del ancho del padre</div>
  <div class="vw-demo">50vw (mitad del viewport)</div>
</div>
html { font-size: 16px; }
.demo { font-size: 20px; padding: 1rem; }  /* padding = 16px (root) */

.rem-demo { font-size: 1.5rem; }            /* 1.5 x 16px = 24px */
.em-demo { font-size: 1.5em; }              /* 1.5 x 20px = 30px (padre) */
.percent-demo { width: 50%; background: #dbeafe; } /* 50% del padre */
.vw-demo { width: 50vw; background: #fef3c7; }     /* 50% del viewport */

rem y em dan resultados distintos aunque ambos son 1.5. La diferencia está en QUÉ toman como referencia: rem mira al html (16px), em mira al padre (.demo = 20px).

Ejemplo con clamp()

/* Un título que nunca será más pequeño que 24px ni más grande que 48px */
h1 {
  font-size: clamp(1.5rem, 4vw, 3rem);
}

4 · Ejemplo real

Construyamos un sistema de diseño con custom properties que alimenta componentes reales. Este patrón es exactamente cómo Tailwind v4 organiza su sistema de tokens:

/* ===== TOKENS DE DISEÑO (el "theme" de tu app) ===== */
:root {
  /* Colores */
  --color-bg: #ffffff;
  --color-surface: #f8fafc;
  --color-text: #0f172a;
  --color-text-muted: #64748b;
  --color-primary: #6366f1;
  --color-primary-hover: #4f46e5;
  --color-border: #e2e8f0;

  /* Espaciado (escala basada en 0.25rem como Tailwind) */
  --space-1: 0.25rem;
  --space-2: 0.5rem;
  --space-4: 1rem;
  --space-6: 1.5rem;
  --space-8: 2rem;

  /* Tipografía */
  --font-sans: system-ui, -apple-system, sans-serif;
  --font-mono: 'Fira Code', monospace;
  --text-sm: 0.875rem;
  --text-base: 1rem;
  --text-lg: 1.125rem;
  --text-2xl: 1.5rem;

  /* Radios */
  --radius-sm: 6px;
  --radius-md: 10px;
  --radius-lg: 16px;
}

/* ===== COMPONENTES QUE CONSUMEN LOS TOKENS ===== */
.article {
  max-width: 68ch;               /* ancho óptimo de lectura */
  margin: 0 auto;
  padding: var(--space-8) var(--space-4);
  font-family: var(--font-sans);
  color: var(--color-text);
  line-height: 1.7;
}

.article h2 {
  font-size: clamp(1.5rem, 3vw, 2rem);
  margin-top: var(--space-8);
  margin-bottom: var(--space-4);
}

.article code {
  font-family: var(--font-mono);
  background: var(--color-surface);
  padding: var(--space-1) var(--space-2);
  border-radius: var(--radius-sm);
  border: 1px solid var(--color-border);
  font-size: var(--text-sm);
}

.btn {
  display: inline-block;
  padding: var(--space-2) var(--space-6);
  background: var(--color-primary);
  color: white;
  border-radius: var(--radius-md);
  font-family: var(--font-sans);
  font-size: var(--text-base);
  text-decoration: none;
}

.btn:hover {
  background: var(--color-primary-hover);
}

Mira lo poderoso que es este sistema: si mañana quieres cambiar el color primario de toda tu aplicación, solo tocas --color-primary en :root. Todos los botones, enlaces, badges y cualquier componente que use var(--color-primary) se actualizan automáticamente. Esto es un single source of truth — el santo grial del diseño a escala.

6 · Errores habituales

🚫 "Mis textos son inconsistentes porque usé px en lugar de rem"

Usar font-size: 16px en vez de font-size: 1rem parece inocente, pero rompe la accesibilidad. Si un usuario configura su navegador con un tamaño de fuente base más grande, tu texto en px no cambia. Con rem, todo escala. Es una línea de código que marca la diferencia entre una web accesible y una que no lo es.

🚫 "Usé em en componentes anidados y los tamaños se descontrolaron"

El efecto compuesto de em es traicionero. Si un componente hijo usa font-size: 1.2em y se anida dentro de otro que también lo usa, el tamaño se multiplica. Solución: usa rem para fuentes base y em solo cuando quieras que algo sea deliberadamente proporcional al tamaño de fuente local (ej: padding: 0.5em 1em en un botón).

🚫 "100vh no cubre toda la pantalla en mi iPhone"

Es el problema más famoso del CSS móvil. Safari en iOS incluye la barra de navegación inferior en el cálculo de 100vh, lo que significa que tu hero section queda parcialmente tapada. Solución: min-height: 100dvh (con fallback: min-height: 100vh; min-height: 100dvh; para navegadores antiguos).

🚫 "Definí una variable CSS en :root pero no se aplica"

Las custom properties distinguen mayúsculas y minúsculas. --colorPrimary no es lo mismo que --colorprimary. También verifica que no estés intentando usar una variable definida en un scope más interno desde fuera — las variables solo se heredan hacia ABAJO en el DOM, nunca hacia arriba.

7 · Ejercicio guiado

Construyamos un sistema de tipografía responsive usando custom properties y clamp(). Definiremos una escala tipográfica completa con tokens:

:root {
  /* Escala tipográfica base */
  --text-step--2: clamp(0.69rem, 0.65rem + 0.21vw, 0.80rem);
  --text-step--1: clamp(0.83rem, 0.77rem + 0.33vw, 1.00rem);
  --text-step-0:  clamp(1.00rem, 0.90rem + 0.49vw, 1.25rem);
  --text-step-1:  clamp(1.20rem, 1.06rem + 0.71vw, 1.56rem);
  --text-step-2:  clamp(1.44rem, 1.24rem + 1.00vw, 1.95rem);
  --text-step-3:  clamp(1.73rem, 1.45rem + 1.39vw, 2.44rem);
  --text-step-4:  clamp(2.07rem, 1.69rem + 1.91vw, 3.05rem);
  --text-step-5:  clamp(2.49rem, 1.97rem + 2.59vw, 3.82rem);
}

h1 { font-size: var(--text-step-5); }
h2 { font-size: var(--text-step-4); }
h3 { font-size: var(--text-step-3); }
h4 { font-size: var(--text-step-2); }
body { font-size: var(--text-step-0); }
small, .text-sm { font-size: var(--text-step--1); }
.text-xs { font-size: var(--text-step--2); }

Esta escala usa clamp() para que cada nivel de la jerarquía tipográfica fluya suavemente entre un tamaño mínimo (móvil) y uno máximo (desktop), sin saltos bruscos. Los valores están calculados con una fórmula de escala tipográfica (ratio 1.2). Todo esto en 10 líneas de CSS, sin una sola media query.

Tailwind v4 genera internamente una escala similar para sus clases text-sm, text-base, text-lg, text-xl, etc.

8 · Reto

🎯 Crea un sistema de theming con custom properties

Construye un tema claro y uno oscuro usando SOLO custom properties:

  • Define todas las variables de color en :root (tema claro por defecto).
  • Crea una clase .dark-mode que sobrescriba las variables para el tema oscuro.
  • Construye dos componentes que consuman estas variables: una card (.card) y un badge (.badge).
  • Añade un botón que alterne la clase .dark-mode en el <body> con JavaScript.
  • Usa clamp() para que el padding de la card sea responsive.
🔍 Ver solución propuesta 
<button id="themeToggle">Alternar tema</button>

<div class="card">
  <span class="badge">Nuevo</span>
  <h2>Título de la card</h2>
  <p>Este texto cambia de color según el tema activo. Las variables CSS hacen toda la magia.</p>
</div>
:root {
  --bg: #ffffff;
  --bg-card: #f8fafc;
  --text: #0f172a;
  --text-muted: #64748b;
  --primary: #6366f1;
  --border: #e2e8f0;
}

.dark-mode {
  --bg: #0f172a;
  --bg-card: #1e293b;
  --text: #f1f5f9;
  --text-muted: #94a3b8;
  --primary: #818cf8;
  --border: #334155;
}

body {
  background: var(--bg);
  color: var(--text);
  font-family: system-ui, sans-serif;
  padding: clamp(1rem, 5vw, 3rem);
  transition: background 0.3s, color 0.3s;
}

.card {
  background: var(--bg-card);
  border: 1px solid var(--border);
  border-radius: 12px;
  padding: clamp(1rem, 4vw, 2rem);
  max-width: 400px;
  transition: background 0.3s;
}

.badge {
  background: var(--primary);
  color: white;
  padding: 4px 12px;
  border-radius: 100px;
  font-size: 0.75rem;
  font-weight: 600;
}

.card h2 { margin: 12px 0 8px; }
.card p { color: var(--text-muted); line-height: 1.6; }
document.getElementById('themeToggle').addEventListener('click', () => {
  document.body.classList.toggle('dark-mode');
});

Cuando haces clic en el botón, el body gana o pierde la clase .dark-mode. Como esa clase redefine las variables, TODOS los componentes que consumen esas variables cambian de color automáticamente. Esto es exactamente cómo funciona el dark mode en Tailwind v4.

9 · Resumen

  • px es absoluto y no escala. Úsalo solo para bordes finos, sombras y detalles que no deben cambiar. NUNCA para fuentes.
  • rem (root em) es la unidad estándar del CSS moderno. Relativo al font-size del html (16px por defecto). Tailwind basa todo su espaciado en rem.
  • em es relativo al font-size del padre. Es útil para media queries y para componentes autocontenidos, pero peligroso en anidación por su efecto compuesto.
  • % es relativo a la misma propiedad del padre. height: 100% solo funciona si el padre tiene altura definida.
  • vw y vh son relativos al viewport. dvh (dynamic viewport height) resuelve el problema de las barras del navegador en móvil. Úsalo en lugar de vh para alturas a pantalla completa.
  • clamp(), min(), max() permiten diseño responsive fluido sin media queries. clamp(min, ideal, max) es la más potente.
  • Custom properties (--nombre) son variables CSS nativas con cascada y herencia. Tailwind v4 las usa como base de todo su sistema de diseño.
  • var() acepta fallback: var(--color, #333).
  • Las variables se heredan hacia abajo en el DOM. Redefinir una variable en un selector más específico crea un "scope" limitado a ese subárbol.

10 · Preguntas frecuentes

¿Por qué Tailwind usa rem en lugar de px?

Tailwind usa rem por dos razones: (1) accesibilidad — si un usuario cambia el tamaño de fuente base en su navegador, toda la UI de Tailwind escala proporcionalmente; (2) consistencia — al estar todo basado en el mismo root font-size, los tamaños son coherentes entre sí. La escala de Tailwind (0.25rem = 4px, 0.5rem = 8px, etc.) está diseñada para que la conversión mental sea fácil tras unos días de práctica.

¿Qué diferencia hay entre dvh, svh y lvh?

dvh = dynamic viewport height: se ajusta en tiempo real cuando las barras del navegador aparecen/desaparecen. svh = small viewport height: asume que las barras de navegación SIEMPRE están visibles (el viewport más pequeño posible). lvh = large viewport height: asume que las barras NUNCA están visibles (viewport más grande). dvh es el que debes usar en el 95% de los casos porque se adapta al estado real del navegador.

¿Las custom properties funcionan en todos los navegadores?

Sí, las custom properties tienen soporte universal desde 2017 (IE11 fue el último navegador que no las soportaba, y ya no recibe soporte). Puedes usarlas sin miedo en cualquier proyecto moderno. De hecho, Tailwind v4 las requiere — no funciona en navegadores sin soporte para custom properties.

¿Cuándo debería usar clamp() vs media queries?

clamp() es ideal para valores que deben fluir suavemente entre un mínimo y un máximo: tamaños de fuente, paddings, anchos de contenedor. Las media queries son necesarias cuando necesitas cambiar el comportamiento (no solo el tamaño): pasar de una columna a dos, cambiar la dirección de flex, mostrar/ocultar elementos. No son excluyentes — se complementan. clamp() para fluidez, media queries para cambios estructurales.
