Selectores, especificidad y cascada

Módulo 1 · CSS: Fundamentos ⏱ 30 minutos

1 · Introducción

Imagina que tienes 1000 hojas de papel apiladas, cada una con una instrucción sobre cómo pintar una pared. Algunas dicen "pinta la pared de azul", otras dicen "pinta SOLO la pared del salón de verde", otras dicen "IGNORA TODO LO ANTERIOR, ¡PINTA DE ROJO!". ¿Qué color acaba teniendo cada pared?

Esto es exactamente lo que hace CSS. No es un lenguaje caprichoso: tiene reglas matemáticas precisas para decidir qué estilo "gana" cuando varias reglas apuntan al mismo elemento. Esas reglas son la especificidad y la cascada. Si no las entiendes, CSS te parecerá un oráculo impredecible. Si las dominas, entenderás exactamente por qué cada elemento se ve como se ve.

Al terminar esta lección sabrás:

  • Todos los tipos de selectores CSS y cómo combinarlos.
  • Cómo calcular la especificidad usando el sistema (0,0,0,0).
  • Qué es la cascada y el orden de precedencia de los estilos.
  • Por qué !important es el último recurso — y por qué Tailwind elimina todo este problema.

2 · Teoría

Selectores: cómo apuntas a los elementos

Selectores básicos

Selector Sintaxis Ejemplo ¿Qué selecciona?
Tipo (etiqueta) elemento p { } Todos los <p>
Clase .nombre .card { } Todos los elementos con class="card"
ID #nombre #header { } El ÚNICO elemento con id="header"
Universal * * { } Todos los elementos
Atributo [atributo] [disabled] { } Elementos con ese atributo

Combinadores: cómo relacionas selectores

Combinador Sintaxis Ejemplo Qué selecciona
Descendiente A B (espacio) nav a Todos los <a> DENTRO de <nav>, a cualquier profundidad
Hijo directo A > B ul > li Solo los <li> que son hijos DIRECTOS de <ul>
Hermano adyacente A + B h2 + p El <p> que va INMEDIATAMENTE después de un <h2>
Hermano general A ~ B h2 ~ p TODOS los <p> que van después de un <h2>, al mismo nivel

Pseudo-clases: seleccionas por estado

Las pseudo-clases se escriben con : y seleccionan elementos según su estado, no según su posición en el DOM:

a:hover { }              /* el ratón está encima */
input:focus { }          /* el input tiene el foco */
li:first-child { }       /* el primer hijo de su padre */
li:last-child { }        /* el último hijo */
li:nth-child(2) { }      /* el segundo hijo (empieza en 1) */
li:nth-child(odd) { }    /* hijos impares: 1, 3, 5... */
li:nth-child(even) { }   /* hijos pares: 2, 4, 6... */
li:nth-child(3n) { }     /* cada tercer hijo: 3, 6, 9... */
button:not(.primary) { } /* todos los buttons que NO tengan class="primary" */
input:checked { }        /* checkbox/radio marcados */

Pseudo-elementos: seleccionas partes de un elemento

::before { }    /* contenido insertado ANTES del elemento */
::after { }     /* contenido insertado DESPUÉS del elemento */
::first-line { }/* la primera línea de texto */
::placeholder {}/* el texto placeholder de un input */

Especificidad: la guerra de los números

Cuando dos o más reglas CSS apuntan al mismo elemento, el navegador decide cuál gana calculando la especificidad. Se representa como una tupla de cuatro números: (a, b, c, d).

Especificidad = (estilos-inline, ids, clases/atributos/pseudo-clases, elementos/pseudo-elementos)
Selector Cálculo Especificidad
* 0,0,0,0 La más baja — cualquier otro selector lo sobrescribe
p 0,0,0,1 1 elemento tipo
div p 0,0,0,2 2 elementos tipo
.card 0,0,1,0 1 clase — GANA a cualquier selector solo por tipo
div.card 0,0,1,1 1 clase + 1 tipo
#header 0,1,0,0 1 id — GANA a cualquier número de clases o tipos
#header .nav a:hover 0,1,2,1 1 id + 2 clases + 1 tipo
style="color:red" 1,0,0,0 Estilo inline — GANA a TODO excepto !important
!important ∞ La bomba nuclear del CSS

Comparación: se compara columna por columna, de izquierda a derecha. En cuanto una columna es mayor, ese selector gana. La columna "a" (inline) es como las centenas, "b" (ids) las decenas, "c" (clases) las unidades, "d" (tipos) los decimales. 0,1,0,0 (100 en base decimal) SIEMPRE le gana a 0,0,99,99 (99 en base decimal).

!important: la opción nuclear

!important sobrescribe TODO — incluso los estilos inline. Pero crea una escalada: si pones !important en un sitio, luego necesitas otro !important para sobrescribirlo, y otro, y otro. Acabas en una guerra nuclear donde todo es !important y nada es mantenible. Solo debe usarse en dos casos:

  • Para sobrescribir estilos de terceros que no controlas (ej: un widget embebido).
  • Para clases de utilidad que DEBEN aplicarse sí o sí (ej: .hidden { display: none !important; }).

La cascada: cuando la especificidad empata

Si dos reglas tienen LA MISMA especificidad, gana el que aparece DESPUÉS en el orden de cascada:

  1. Origen: estilos del navegador (user-agent) → estilos del usuario → estilos del autor (tú).
  2. Orden de aparición: el último declarado gana (el CSS se lee de arriba a abajo).
  3. Herencia: algunas propiedades se heredan de padres a hijos (color, font-family, font-size...). Otras no (margin, padding, border, background...).
/* Ambas reglas tienen especificidad 0,0,1,0 */
.card { color: blue; }   /* ← esta se aplica primero... */
.card { color: red; }    /* ← ...pero esta gana porque va después */

Por qué Tailwind elimina el problema de la especificidad

Tailwind usa exclusivamente clases de utilidad. Todas las clases tienen una especificidad de (0,0,1,0). No hay ids, no hay selectores anidados, no hay combinadores. Esto significa que:

  • La especificidad SIEMPRE es la misma para todas las utilidades.
  • Si dos clases entran en conflicto (ej: text-red-500 text-blue-500), gana la que aparece DESPUÉS en el HTML — predecible, visible, sin calculadora.
  • No hay "guerras de especificidad". No hay que sobrescribir .header .nav .link .active con monstruosidades de 5 selectores anidados.

Esta es una de las razones filosóficas más profundas de Tailwind: la especificidad plana es mantenibilidad.

3 · Ejemplo mínimo

Un mismo párrafo recibe color de cuatro reglas distintas. ¿Cuál gana?

<div class="contenedor" id="principal">
  <p class="texto">¿De qué color soy?</p>
</div>
p                    { color: gray; }    /* 0,0,0,1 — PIERDE */
.contenedor p        { color: blue; }    /* 0,0,1,1 — PIERDE (pero iba bien) */
#principal .texto    { color: green; }   /* 0,1,1,0 — PIERDE contra !important */
.texto               { color: red !important; } /* ∞ — GANA */

El párrafo será rojo. El !important barre todo lo demás. Sin él, ganaría el verde (0,1,1,0) porque tiene un id, y los ids pesan más que cualquier cantidad de clases o tipos.

Un componente de "tabla de precios" donde usamos selectores y pseudo-clases para estilizar filas alternas y la fila destacada:

/* Selectores en acción */
.plan { border: 1px solid #e2e8f0; border-radius: 12px; padding: 32px 24px; }
.plan--popular { border-color: #6366f1; box-shadow: 0 8px 30px rgba(99,102,241,0.15); transform: scale(1.03); }

/* Resaltar la primera característica de cada plan: es el beneficio principal */
.plan ul li:first-child { font-weight: 600; color: #1e293b; }

/* Las características pares tienen fondo sutil para las rayas tipo tabla */
.plan ul li:nth-child(even) { background: #f8fafc; border-radius: 4px; }

/* Combinador de hijo directo: solo los li directamente dentro de ul */
.plan > ul { list-style: none; padding: 0; margin: 24px 0; }
.plan > ul > li { padding: 8px 12px; color: #475569; }

/* Pseudo-clase :not para estilizar todos los botones excepto el del plan popular */
.plan__cta:not(.plan--popular .plan__cta) { background: #e2e8f0; }

/* Hermano adyacente: el párrafo de precio que va justo después del h3 */
.plan h3 + .plan__price { margin-top: 12px; font-size: 32px; font-weight: 800; }

Observa la variedad de selectores usados: cada uno tiene un propósito específico. :first-child para destacar el primer elemento, :nth-child(even) para las rayas alternas, > para ser preciso y no afectar a listas anidadas, :not para excluir un caso concreto. La clave está en elegir el selector más específico para cada necesidad sin caer en la sobrespecificación.

5 · Buenas prácticas

✅ Haz esto ❌ Evita esto 🤔 Por qué
Usa selectores de clase para estilizar componentes. Es el punto dulce: específico, reutilizable, mantenible Usar IDs para estilizar. No son reutilizables y tienen una especificidad altísima que hace difícil sobrescribirlos Las clases son reutilizables (puedes tener varios .card), los IDs no (solo un #header). Además (0,0,1,0) es más manejable que (0,1,0,0)
Usa > (hijo directo) cuando solo quieras afectar al primer nivel de anidación Usar el selector descendiente (espacio) sin control — puede afectar a elementos profundamente anidados que no esperabas El selector descendiente es un "comodín peligroso": .card a afecta a cualquier <a> dentro de .card, incluso dentro de otros componentes anidados
Prefiere selectores con especificidad baja y constante (0,0,1,0 — una sola clase) Crear cadenas de selectores anidados: .header .nav .menu .item a.active span (especificidad 0,0,5,2) Cada vez que anidas, la especificidad sube y luego necesitas selectores aún más largos para sobrescribir. Es una espiral sin fin
Mantén el CSS ordenado según la cascada: resets → elementos base → componentes → utilidades Escribir CSS en orden aleatorio y depender de especificidad para que funcione El orden predecible reduce la necesidad de especificidad alta. Si sabes que las utilidades van al final, no necesitas !important
Usa convenciones de nomenclatura (BEM) para evitar colisiones: .bloque__elemento--modificador Nombres genéricos como .card, .title, .button en proyectos grandes con varios desarrolladores Las colisiones de nombres son el principal generador de bugs CSS en equipos. BEM o CSS Modules eliminan este riesgo

6 · Errores habituales

🚫 "Mi regla CSS no se aplica y no sé por qué"

El 90% de las veces es un problema de especificidad. Abre las DevTools, inspecciona el elemento y mira la pestaña "Styles". Si tu regla aparece tachada, es que otra regla con mayor especificidad la está sobrescribiendo. Las DevTools te muestran la especificidad de cada regla y cuál está ganando. Es la herramienta de depuración más infrautilizada de la web.

🚫 "Puse !important en un sitio y ahora todo mi CSS está roto"

Has entrado en la espiral de !important. La única solución es refactorizar: elimina todos los !important y reescribe los selectores con la especificidad correcta. Duele, pero es la única forma de recuperar el control. En proyectos grandes, puedes usar una herramienta como Stylelint con la regla declaration-no-important para prohibir !important a nivel de linting.

🚫 "Usé IDs para todo y ahora mi CSS es imposible de sobrescribir"

Los IDs son anclas de especificidad. Un solo #mi-id (0,1,0,0) requiere 11 clases (0,0,11,0) para ser sobrescrito. No uses IDs para estilizar — usa IDs solo para JavaScript (document.getElementById) y anclas de navegación (<section id="faq">).

🚫 "El selector :nth-child no funciona como espero"

:nth-child cuenta TODOS los hijos, no solo los del mismo tipo. Si tienes div :nth-child(2) pero en tu div hay un <h2>, un <p> y otro <p>, el :nth-child(2) selecciona el primer <p> (porque el <h2> es el hijo 1). Si quieres contar solo elementos de un tipo específico, usa :nth-of-type.

7 · Ejercicio guiado

Vamos a estilizar una lista de notificaciones usando selectores avanzados. Aprenderemos a usar :first-child, :nth-child, :not y el combinador +.

<ul class="notifications">
  <li class="notification notification--unread">
    <strong>Nuevo mensaje</strong> de Laura <time>hace 2 min</time>
  </li>
  <li class="notification notification--unread">
    <strong>Factura disponible</strong> <time>hace 1 h</time>
  </li>
  <li class="notification">
    <strong>Actualización completada</strong> <time>ayer</time>
  </li>
  <li class="notification">
    <strong>Bienvenido al equipo</strong> <time>hace 3 días</time>
  </li>
</ul>
.notifications {
  list-style: none;
  padding: 0;
  max-width: 480px;
}

.notification {
  padding: 14px 18px;
  border-bottom: 1px solid #e2e8f0;
  font-size: 14px;
  color: #334155;
}

/* Borde superior solo al primer elemento, no en todos */
.notification:first-child {
  border-top: 1px solid #e2e8f0;
}

/* Fondo alterno tipo zebra con pseudo-clase */
.notification:nth-child(even) {
  background: #f8fafc;
}

/* Resalta las no leídas */
.notification--unread {
  background: #eff6ff !important; /* el !important aquí es por el zebra */
}

/* El time siempre a la derecha y más pequeño */
.notification time {
  float: right;
  font-size: 12px;
  color: #94a3b8;
}

/* Hermanos adyacentes: espacio extra cuando hay dos no leídas seguidas */
.notification--unread + .notification--unread {
  border-top: 2px solid #bfdbfe;
}

/* Highlight al hacer hover en cualquier notification */
.notification:hover {
  background: #f1f5f9;
}

El uso de !important en .notification--unread es uno de los pocos casos justificados: necesitamos que gane sobre el zebra (:nth-child(even)) que tiene especificidad (0,0,2,0) vs (0,0,1,0). Sin !important, el zebra sobrescribiría el fondo azul de las no leídas pares.

8 · Reto

🎯 Sistema de comentarios con hilos

Construye el CSS para una sección de comentarios con las siguientes reglas:

  • Lista de comentarios con anidación (respuestas dentro de comentarios).
  • Los comentarios de nivel 1 (respuestas directas al post) tienen borde izquierdo azul de 3px.
  • Los comentarios de nivel 2 (respuestas a respuestas) tienen borde izquierdo gris de 2px y un margen izquierdo de 24px para crear indentación visual.
  • Las respuestas alternan color de fondo (blanco / gris muy clarito) para distinguirlas — pero SOLO entre hermanos del mismo nivel, no entre niveles distintos.
  • El último comentario de cada hilo no tiene borde inferior.
  • Al hacer hover en una respuesta, su fondo cambia a un azul muy clarito.

El truco clave aquí es usar > (hijo directo) para diferenciar los comentarios del nivel 1 de los anidados. El zebra con :nth-child(even) dentro de .comments__replies solo afecta a hermanos de ese contenedor, no cruza niveles. Y el :hover con más especificidad que el zebra (porque se declara después) asegura que el hover funcione incluso en filas pares.

9 · Resumen

  • Selectores básicos: tipo (p), clase (.card), id (#header), universal (*), atributo ([disabled]). Las clases son el punto dulce para estilizar.
  • Combinadores: descendiente (espacio), hijo directo (>), hermano adyacente (+), hermano general (~). Usa > cuando necesites precisión, espacio cuando quieras afectar a todo un subárbol.
  • Pseudo-clases seleccionan por estado (:hover, :focus, :first-child, :nth-child, :not). Pseudo-elementos seleccionan partes de un elemento (::before, ::after).
  • Especificidad (a,b,c,d): inline (1,0,0,0) → id (0,1,0,0) → clase/atributo/pseudo-clase (0,0,1,0) → tipo/pseudo-elemento (0,0,0,1). Se compara de izquierda a derecha.
  • !important gana a todo. Es el último recurso. Úsalo solo para utilidades que DEBEN aplicarse o para sobrescribir CSS de terceros.
  • La cascada resuelve empates de especificidad: gana lo que aparece después en el código (mismo nivel de origen).
  • Tailwind evita el problema de raíz: todas las clases son (0,0,1,0). Especificidad plana = sin guerras = código predecible y mantenible.

10 · Preguntas frecuentes

¿Especificidad 0,0,1,0 vs 0,0,0,99: ¿quién gana?

Gana 0,0,1,0. La comparación es columna por columna de izquierda a derecha. La tercera columna (clases) tiene un 1, mientras que la cuarta columna solo acumula elementos tipo. En cuanto una columna de la izquierda es mayor, se acabó la comparación. No importa cuántos elementos tipo acumules (99, 999, 9999) — una sola clase siempre los supera.

¿Cuál es la diferencia entre :nth-child y :nth-of-type?

:nth-child(n) cuenta TODOS los hijos de un padre, sin importar su tipo. :nth-of-type(n) cuenta SOLO los hijos del mismo tipo (misma etiqueta). Si tienes <h2>, <p>, <p>: p:nth-child(2) selecciona el primer p (porque el hijo 2 es un p), mientras que p:nth-of-type(2) selecciona el segundo p (el hijo 3). En la práctica, :nth-of-type suele ser más intuitivo para listas de elementos iguales.

¿Por qué Tailwind no usa selectores anidados ni IDs?

Tailwind sigue la filosofía utility-first: cada clase CSS es una unidad atómica que aplica una propiedad CSS. No necesita selectores anidados porque no crea "componentes CSS" — los componentes se crean en el HTML combinando utilidades. Los IDs no se usan porque tienen especificidad muy alta y no son reutilizables. Al mantener todas las clases al mismo nivel de especificidad (0,0,1,0), el sistema es totalmente predecible: el orden de las clases en el HTML determina qué gana en caso de conflicto.

¿Existe un límite práctico de anidación de selectores?

Técnicamente no hay límite en CSS. Pero como regla práctica: si tu selector tiene más de 3 niveles de profundidad, hay un problema de arquitectura. Un selector como .page .section .card .header .title strong es una bandera roja. Significa que tu HTML está excesivamente anidado o que estás usando selectores para compensar un mal diseño de componentes. Herramientas como Stylelint pueden configurarse para limitar la profundidad máxima de anidación.

¿Cómo lidio con la especificidad cuando uso bibliotecas de terceros que no controlo?

Tienes tres estrategias, de mejor a peor: (1) Envuelve el componente de terceros en un contenedor y usa selectores descendientes con una clase en el wrapper — ganas especificidad sin ids. (2) Si la biblioteca usa custom properties (--css-variables), sobrescribe las variables en lugar de las propiedades. (3) Como último recurso, !important en una hoja de estilos separada y claramente documentada como "overrides de terceros". Nunca mezcles !important de terceros con tu CSS normal — mantenlos en archivos separados.
