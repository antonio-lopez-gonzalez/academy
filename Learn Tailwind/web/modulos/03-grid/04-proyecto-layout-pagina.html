4. Proyecto: layout de pagina completa con Grid

50 minutos Proyecto CSS Grid Avanzado

1 · Introduccion

Este es el proyecto final del Modulo 3. Vamos a construir un layout de pagina profesional completo usando exclusivamente CSS Grid. Nada de Flexbox para la estructura principal (solo para componentes internos pequenos). Nada de floats. Nada de hacks.

Lo que construiras:

  • Header con logo, titulo y navegacion horizontal.
  • Sidebar izquierda con menu de navegacion vertical.
  • Contenido principal con cards en sub-grid usando auto-fit.
  • Aside derecha con widgets.
  • Footer con enlaces organizados en columnas.

Responsive en 3 breakpoints:

  • Movil: 1 columna, areas reordenadas.
  • Tablet: 2 columnas (sidebar + contenido).
  • Desktop: 3 columnas completas.
LAYOUT DESKTOP (3 columnas): +------------------------------------------+ | HEADER | +--------+---------------------+----------+ | | | | | NAV | MAIN | ASIDE | |(menu | (cards sub-grid) |(widgets) | | 200px) | | (200px) | | | | | +--------+---------------------+----------+ | FOOTER | +------------------------------------------+ LAYOUT TABLET (2 columnas): +---------------------------------+ | HEADER | +--------+------------------------+ | | | | NAV | MAIN | | | | | | ASIDE | | | | +--------+------------------------+ | FOOTER | +---------------------------------+ LAYOUT MOVIL (1 columna): +-------------------+ | HEADER | +-------------------+ | NAV | +-------------------+ | MAIN | +-------------------+ | ASIDE | +-------------------+ | FOOTER | +-------------------+
Por que este proyecto es importante

Al terminar, tendras una plantilla de layout profesional que podras reutilizar en cualquier proyecto web. Es el equivalente a comprar un traje a medida: lo ajustas a tus necesidades, pero la estructura base es solida y probada. Ademas, entenderas como combinar grid-template-areas, auto-fit y minmax en un proyecto real.

2 · Teoria

Arquitectura del layout

Vamos a estructurar el CSS en capas, de fuera hacia dentro, como una muneca rusa:

  1. Capa 1 — Layout externo: el grid principal que define header, nav, main, aside, footer usando grid-template-areas.
  2. Capa 2 — Componentes de area: cada area (header, nav, main, aside, footer) puede ser a su vez un grid container para su contenido interno.
  3. Capa 3 — Sub-grid de cards: dentro de main, un sub-grid con repeat(auto-fit, minmax(280px, 1fr)) para las tarjetas de contenido.
ARQUITECTURA EN CAPAS: CAPA 1: Grid externo (grid-template-areas) +------------------------------------------+ | header | +--------+---------------------+----------+ | nav | main | aside | +--------+---------------------+----------+ | footer | +------------------------------------------+ CAPA 2: Cada area es un grid/item independiente header: +-------------------------------------+ | logo | titulo | nav horizontal | +-------------------------------------+ nav (flex o grid de 1 columna): +-----------+ | enlace 1 | | enlace 2 | | enlace 3 | +-----------+ main: +-------------------------------------+ | card 1 | card 2 | card 3 | <- sub-grid con auto-fit +-------------------------------------+ CAPA 3: Sub-grid de cards (auto-fit + minmax) main { display: grid; grid-template-columns: repeat(auto-fit, minmax(280px, 1fr)); }

La estrategia responsive

En vez de luchar contra el layout en cada breakpoint, redefinimos grid-template-areas en cada media query. El HTML nunca cambia de orden; solo cambia como se dibuja en pantalla.

/* DESKTOP (por defecto, mobile-first al reves en este caso) */
.layout {
  grid-template-areas:
    "header header header"
    "nav    main   aside"
    "footer footer footer";
  grid-template-columns: 200px 1fr 200px;
}

/* TABLET: aside baja debajo de main, formando 2 columnas */
@media (max-width: 1023px) {
  .layout {
    grid-template-areas:
      "header header"
      "nav    main"
      "nav    aside"
      "footer footer";
    grid-template-columns: 180px 1fr;
  }
}

/* MOVIL: todo apilado en 1 columna */
@media (max-width: 767px) {
  .layout {
    grid-template-areas:
      "header"
      "nav"
      "main"
      "aside"
      "footer";
    grid-template-columns: 1fr;
  }
}

minmax para el contenido principal

El main debe crecer pero no infinitamente. Usamos minmax() para limitar el ancho maximo del contenido mientras permitimos que ocupe todo el espacio disponible en pantallas intermedias.

/* La columna central crece con el viewport hasta un maximo de 900px */
grid-template-columns: 200px minmax(0, 900px) 200px;

/* O usando fr con un wrapper interno con max-width:
   La columna central ocupa 1fr (todo el espacio sobrante),
   y el contenido dentro de main tiene max-width: 900px */
Mobile-first o desktop-first?

En este proyecto usamos desktop-first (el layout de 3 columnas es el default y vamos simplificando con max-width). En produccion real, el enfoque mobile-first (empezar por movil y anadir complejidad con min-width) es mas mantenible. Usamos desktop-first aqui porque es mas facil de entender el layout completo y luego simplificarlo.

5 · Buenas practicas

Que hacer

  • Manten el grid de layout externo simple. Solo define areas y tamanos de columna. No mezcles alineacion, gaps complejos ni estilos visuales en el grid principal. Cada area se encarga de su propio contenido.
  • Usa variables CSS para breakpoints y colores. Si mananas quieres cambiar el ancho de la sidebar de 230px a 260px, deberias cambiarlo en un solo sitio. Las custom properties lo hacen trivial.
  • Anida grids. El main es un grid container con auto-fit para sus cards. El footer es otro grid container para sus columnas de enlaces. Cada zona gestiona su propio layout interno.
  • Prueba los 3 breakpoints con contenido real. Las areas se reordenan visualmente, pero el orden del DOM no cambia. Asegurate de que el orden de tabulacion (Tab) sigue siendo logico en movil.
  • Usa gap en los sub-grids, no en el grid principal. El grid externo usa las areas de borde a borde. El espaciado interno de cada area lo gestiona su propio padding.

Que evitar

  • No mezcles Flexbox y Grid para el mismo problema de layout. Si estas definiendo la estructura de pagina con Grid, no uses Flexbox en el mismo nivel anidado para "arreglar" algo. Refactoriza el grid.
  • No definas grid-template-rows con alturas fijas en el layout principal. El contenido define la altura. Usa auto y 1fr para que las areas se adapten.
  • No olvides el gap en el sub-grid de cards. Sin gap, las tarjetas aparecen pegadas entre si. gap: 20px en el grid de cards es esencial.
  • No uses numeros magicos para columnas. grid-template-columns: 230px minmax(0, 900px) 220px es mejor que 230px 1fr 220px porque minmax(0, ...) evita que el contenido fuerce un ancho minimo excesivo.

6 · Errores habituales

Error 1: El contenido principal desborda la columna central

Cuando tienes una imagen grande o una palabra muy larga (como una URL sin guiones), el grid puede romperse porque 1fr tiene un minimo implicito de min-content.

Incorrecto

/* 1fr permite que la columna crezca hasta el tamano del contenido */
grid-template-columns: 200px 1fr 200px;
/* Una URL de 500 caracteres rompe el layout */

Correcto

/* minmax(0, 1fr) fuerza que la columna pueda encojerse a 0 */
grid-template-columns: 200px minmax(0, 1fr) 200px;

/* Ademas, asegura que el contenido largo se rompa */
.main {
  overflow-wrap: break-word;
  min-width: 0;  /* Refuerzo extra para navegadores antiguos */
}

Error 2: Las areas no coinciden en numero de columnas entre breakpoints

Al cambiar grid-template-areas en una media query, el numero de columnas en cada fila debe coincidir con grid-template-columns.

Incorrecto

@media (max-width: 767px) {
  .layout {
    grid-template-columns: 1fr;
    /* ERROR: solo 1 columna, pero las areas definen 2 columnas */
    grid-template-areas:
      "header nav"
      "main aside"
      "footer .";
  }
  /* El navegador ignora la declaracion entera */
}

Correcto

@media (max-width: 767px) {
  .layout {
    grid-template-columns: 1fr;
    /* Cada fila tiene EXACTAMENTE 1 columna */
    grid-template-areas:
      "header"
      "nav"
      "main"
      "aside"
      "footer";
  }
}

Error 3: Olvidar que el footer es parte del grid de pagina

Si el footer no se asigna a un area del grid, se coloca como un grid item normal, probablemente en una posicion inesperada.

<div class="layout">
  <header class="header">...</header>
  <nav class="nav">...</nav>
  <main class="main">...</main>
  <aside class="aside">...</aside>
  <footer class="footer">...</footer> <!-- SIN grid-area asignado -->
</div>

El footer se coloca en la siguiente celda disponible del grid, no al final de la pagina. Siempre asigna grid-area: footer al elemento.

Vamos a construir el layout paso a paso. Sigue las instrucciones en orden. Cada paso anade una capa nueva.

  1. Crea la estructura HTML base. Un div.layout con 5 hijos: header, nav, main, aside, footer.

9 · Resumen

Conceptos clave del proyecto
  • Grid externo con areas: grid-template-areas define la estructura de pagina de forma legible y mantenible.
  • Columnas con minmax: minmax(0, 1fr) en la columna central evita desbordamientos de contenido.
  • Sub-grids anidados: las cards dentro de main y las columnas del footer son sus propios grid containers con auto-fit + minmax.
  • Responsive redefiniendo areas: cada media query redefine grid-template-columns y grid-template-areas. El HTML no se toca.
  • Flexbox para componentes internos: el header usa Flexbox para alinear logo y navegacion. Grid y Flexbox se complementan, no compiten.
  • Desktop-first en este proyecto: empezamos por el layout mas complejo (3 columnas) y simplificamos con max-width. En produccion, considera mobile-first.

10 · FAQ — Preguntas frecuentes

Por que usar grid-template-areas y no solo lineas numeradas?

Las areas comunican intencion. Cuando otro desarrollador (o tu mismo en 6 meses) lea "header header header" "nav main aside" "footer footer footer", entendera el layout al instante. Con lineas numeradas (grid-column: 1 / 4), necesitas contar columnas y hacer aritmetica mental. Las areas son auto-documentadas.

Este layout funciona sin Flexbox en los componentes internos?

Si, puedes usar solo Grid para absolutamente todo. Pero no es recomendable. El header con logo + navegacion es un caso perfecto para Flexbox (distribucion en una dimension). Usa la herramienta adecuada para cada problema: Grid para la estructura bidimensional, Flexbox para componentes unidimensionales.

Como hago que la sidebar sea colapsable?

Hay varias tecnicas: (a) CSS-only con un checkbox hack que cambie grid-template-columns via :has(). (b) Una clase .sidebar-collapsed que reduzca la primera columna a 60px y oculte el texto. (c) JavaScript para toggle de clase. La opcion (b) es la mas simple y mantenible: .layout.sidebar-collapsed { grid-template-columns: 60px 1fr 220px; }.

Por que el contenido de main se desborda horizontalmente en movil?

Causa mas comun: 1fr sin minmax(0, ...). Como 1fr tiene un minimo implicito de min-content, contenido ancho (tablas, pre, URLs largas) fuerza la columna a ser mas ancha que el viewport. Solucion: minmax(0, 1fr) y min-width: 0 en el contenedor de contenido.

Puedo usar este layout con Tailwind CSS?

Absolutamente. Tailwind tiene utilidades para Grid: grid, grid-cols-[230px_minmax(0,1fr)_220px], grid-areas-[...] (con plugin o valores arbitrarios). En el Modulo 5 aprenderas exactamente como traducir todo esto a clases de Tailwind. La teoria de Grid que has aprendido aqui se aplica directamente.

El orden del DOM es correcto para accesibilidad en movil?

Cuando redefines grid-template-areas en movil, cambias el orden visual pero no el orden del DOM. Si en desktop el orden es header-nav-main-aside-footer, y en movil pones header-main-nav-aside-footer, un lector de pantalla seguira leyendo header-nav-main... (el orden del DOM). Para accesibilidad, asegurate de que el orden visual coincida con un orden logico de lectura, o usa tabindex con cuidado.
