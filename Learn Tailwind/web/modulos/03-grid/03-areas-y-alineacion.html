3. Áreas de grid y alineación

⏱ 30 minutos 📐 CSS Grid 🎓 Intermedio

1 · Introducción

Hasta ahora hemos definido grids usando números de líneas y tamaños de tracks. Funciona, pero cuando el layout es complejo, leer grid-column: 2 / 4; grid-row: 1 / 3; no es intuitivo. Aquí entra grid-template-areas: nombras regiones del layout con palabras y dibujas el diseño como si fuera arte ASCII.

💡 ¿Por qué existen las grid areas?

Porque el código debe comunicar intención. Cuando lees grid-template-areas: "header header" "sidebar content" "footer footer", ves el layout inmediatamente. Cuando lees grid-column: 2 / 4; grid-row: 1 / 3;, tienes que hacer aritmética mental. Las áreas hacen que el CSS sea auto-documentado.

Además de las áreas, en esta lección dominarás la alineación en Grid: cómo centrar, distribuir y posicionar items dentro de sus celdas y el grid completo dentro de su contenedor.

2 · Teoría

grid-template-areas: el layout como diagrama ASCII

Con grid-template-areas, defines el layout escribiendo nombres de área en una cuadrícula de texto. Cada fila es un string entre comillas. Cada palabra dentro de la fila es el nombre de una celda. Es literalmente dibujar el layout con palabras.

CSS: grid-template-areas: "header header header" ← Fila 1: 3 celdas, todas "header" "sidebar content aside" ← Fila 2: 3 celdas distintas "footer footer footer"; ← Fila 3: 3 celdas, todas "footer" RESULTADO VISUAL: ┌──────────────────────────────┐ │ HEADER │ ├────────┬──────────┬───────────┤ │SIDEBAR │ CONTENT │ ASIDE │ ├────────┴──────────┴───────────┤ │ FOOTER │ └──────────────────────────────┘
.layout {
  display: grid;
  grid-template-columns: 200px 1fr 200px;
  grid-template-rows: auto 1fr auto;
  grid-template-areas:
    "header  header  header"
    "sidebar content aside"
    "footer  footer  footer";
  min-height: 100vh;
}

/* Asignar cada elemento a su área NOMBRADA */
.header  { grid-area: header; }
.sidebar { grid-area: sidebar; }
.content { grid-area: content; }
.aside   { grid-area: aside; }
.footer  { grid-area: footer; }
🧩 Analogía: grid-template-areas es un mapa del metro

El mapa del metro no muestra distancias exactas, muestra relaciones espaciales: qué línea va arriba, cuál abajo, dónde se cruzan. grid-template-areas hace lo mismo para tu layout: muestra qué elemento va arriba, cuál al lado, cuál abajo. El navegador se encarga de los tamaños exactos usando grid-template-columns y grid-template-rows.

Reglas de grid-template-areas

  • Cada nombre debe ser un identificador CSS válido (sin espacios, sin empezar por número).
  • Un área debe formar un rectángulo (no puede tener forma de L o T).
  • Usa . (punto) para celdas vacías (sin contenido asignado).
  • Todas las filas deben tener el mismo número de celdas.
/* Ejemplo con celdas vacías (representadas con . ) */
grid-template-areas:
  "logo   .      nav"
  "main   main   aside"
  "footer footer footer";

/* INCORRECTO: las áreas deben ser rectangulares ❌ */
grid-template-areas:
  "a a a"
  "a b a"     /* El área "a" forma una U, no un rectángulo */
  "a a a";    /* Esto no funciona */

Posicionamiento explícito: grid-column y grid-row

Cuando las áreas no son suficientes (o prefieres un enfoque más numérico), puedes posicionar items usando las líneas del grid.

/* Sintaxis con inicio / fin */
grid-column: 1 / 3;       /* Desde línea 1 hasta línea 3 (ocupa 2 columnas) */
grid-row: 2 / 4;          /* Desde línea 2 hasta línea 4 (ocupa 2 filas) */

/* Sintaxis con span (más legible a veces) */
grid-column: span 2;      /* Ocupa 2 columnas desde donde esté */
grid-row: span 3;         /* Ocupa 3 filas desde donde esté */

/* Combinado: empieza en línea 2 y ocupa 2 columnas */
grid-column: 2 / span 2;

/* Atajos: grid-area con 4 valores (row-start / col-start / row-end / col-end) */
grid-area: 1 / 1 / 3 / 4; /* Fila 1 a 3, Columna 1 a 4 */
grid-column y grid-row con números de línea: Líneas col: 1 2 3 4 ┌───────┬───────┬───────┐ Línea fila 1│ │ │ │ ├───────┼───────┼───────┤ 2│ │ item │ │ ← item: grid-column: 2 / 4 ├───────┤ │ │ grid-row: 2 / 4 3│ │ │ │ ├───────┼───────┼───────┤ 4│ │ │ │ └───────┴───────┴───────┘

Alineación en Grid: place-items, place-content, place-self

Grid tiene dos niveles de alineación, y esta es la parte que más confunde al principio:

NivelPropiedad¿Qué alinea?Se aplica en
Items dentro de su celda place-items Cada grid item dentro del área que ocupa El grid container
Todo el grid dentro de su contenedor place-content El conjunto de tracks respecto al contenedor El grid container
Un item específico place-self Un grid item concreto dentro de su celda El grid item
place-items vs place-content en un grid 2x2 de 100px cada celda dentro de un contenedor de 500px × 500px: CONTENEDOR (500×500) ┌─────────────────────────────────────────┐ │ │ │ ┌──────┬──────┐ │ │ │ A │ B │ ← place-content │ │ ├──────┼──────┤ centra el grid │ │ │ C │ D │ dentro del padre │ │ └──────┴──────┘ │ │ │ └─────────────────────────────────────────┘ DENTRO DE CADA CELDA (100×100): ┌──────┐ │ │ │ X │ ← place-items centra el contenido │ │ dentro de cada celda └──────┘
/* place-items: alineación de items DENTRO de sus celdas */
/* Sintaxis: place-items: <align> <justify>; */
/* Si solo pones un valor, se aplica a ambos ejes */

place-items: center;          /* Centrado perfecto en ambos ejes */
place-items: start center;    /* Arriba (start) y centrado horizontal */
place-items: center stretch;  /* Centrado vertical, estirado horizontal */

/* place-content: alineación del GRID dentro del contenedor */
/* Solo tiene efecto si el grid es más pequeño que su contenedor */
place-content: center;        /* Grid centrado en el contenedor */
place-content: space-between; /* Espacio entre filas, columnas pegadas a bordes */
place-content: end start;     /* Abajo a la derecha */

/* place-self: alineación de UN item específico */
/* Sobrescribe place-items para ese item */
.item-especial {
  place-self: end center;     /* Abajo, centrado horizontal */
}

Los valores de alineación

ValorSignificado
startAl inicio del eje (arriba o izquierda)
endAl final del eje (abajo o derecha)
centerCentrado en el eje
stretchEstirado para ocupar todo el espacio (por defecto)
space-betweenPrimer y último track pegados a bordes, espacio distribuido entre ellos (solo place-content)
space-aroundEspacio igual alrededor de cada track (solo place-content)
space-evenlyEspacio exactamente igual entre tracks y bordes (solo place-content)

📱 El responsive con grid-template-areas es trivial

Fíjate en cómo cambiamos el layout para móvil: simplemente redefinimos grid-template-columns a 1 columna y reescribimos grid-template-areas para apilar todo verticalmente. Incluso podemos cambiar el orden (nav arriba o abajo del main) reordenando las filas del área. Sin tocar el HTML.

5 · Buenas prácticas

✅ Qué hacer

  • Usa grid-template-areas para layouts de página. Es la forma más legible y mantenible. Cualquier desarrollador que lea tu CSS entenderá la estructura al instante.
  • Nombra las áreas con guiones y prefijo del componente. "page-header" en lugar de "a" o "top". El código se lee más veces de las que se escribe.
  • Usa place-items: center para centrar contenido en una celda. Es la forma más corta y expresiva de centrar algo en ambos ejes. Reemplaza al viejo combo display: flex; align-items: center; justify-content: center cuando el padre ya es grid.
  • Cambia grid-template-areas en media queries para layouts responsive. Es trivial reorganizar la página solo cambiando las áreas, sin tocar el HTML.
  • Usa span en lugar de números de línea cuando sea posible. grid-column: span 2 es más legible que grid-column: 1 / 3 porque expresa la intención ("ocupar 2 columnas") en vez de la implementación ("línea 1 a línea 3").

❌ Qué evitar

  • No uses grid-template-areas para grids de contenido dinámico. Si tienes una galería con número variable de items, auto-fit con minmax es mucho mejor. Las áreas son para layouts estructurales conocidos de antemano.
  • No crees áreas no rectangulares. Cada nombre de área debe formar un rectángulo contiguo. Formas en L o T no son válidas y el navegador ignorará la declaración entera.
  • No abuses de place-self cuando place-items en el contenedor es suficiente. Si todos los items necesitan la misma alineación, defínela una vez en el contenedor.

6 · Errores habituales

Error 1: Área no rectangular

❌ Incorrecto — El área "main" tiene forma de L

grid-template-areas:
  "header header header"
  "main   sidebar aside"
  "main   footer  footer";  /* "main" está en columna 1 fila 2 y 3...
                                "sidebar" solo en fila 2, columna 2...
                                "footer" en fila 3 columnas 2-3...
                                ESTO NO FORMA RECTÁNGULOS VÁLIDOS */

✅ Correcto — Cada área es un rectángulo

grid-template-areas:
  "header  header  header"
  "main    main    aside"
  "footer  footer  footer";

Error 2: Confundir place-items con place-content

Este es uno de los errores más frecuentes incluso entre desarrolladores con experiencia.

❌ Incorrecto — Intentar centrar el grid usando place-items

.grid {
  display: grid;
  grid-template-columns: 200px 200px;
  place-items: center;  /* Centra el CONTENIDO de cada celda, no el grid */
  /* El grid sigue pegado a la esquina superior izquierda si es más
     pequeño que su contenedor */
}

✅ Correcto — place-content centra el grid en el contenedor

.grid {
  display: grid;
  grid-template-columns: 200px 200px;
  place-content: center; /* Centra el GRID entero en el contenedor */
  height: 100vh;         /* Necesita altura para que se note el centrado */
}

Error 3: Olvidar que grid-area también es un atajo de 4 valores

grid-area tiene dos usos completamente distintos, y esto confunde a principiantes:

/* USO 1: Asignar nombre de área (para grid-template-areas) */
.header { grid-area: header; }  /* Nombre que usas en grid-template-areas */

/* USO 2: Atajo de 4 valores (row-start / col-start / row-end / col-end) */
.item {
  grid-area: 2 / 1 / 4 / 3;     /* Equivale a:
                                   grid-row-start: 2;
                                   grid-column-start: 1;
                                   grid-row-end: 4;
                                   grid-column-end: 3; */
}

7 · Ejercicio guiado

Vamos a construir un layout de dashboard usando grid-template-areas. El diseño tendrá: header superior, sidebar izquierda, área de estadísticas (4 tarjetas en grid), contenido principal y footer.

  1. Define la estructura base con áreas. 
    .dashboard {
  display: grid;
  grid-template-columns: 240px 1fr;
  grid-template-rows: auto 1fr auto;
  grid-template-areas:
    "header  header"
    "sidebar stats"
    "sidebar main"
    "footer  footer";
  min-height: 100vh;
  gap: 0; /* Las áreas no llevan gap entre sí, los elementos internos sí */
}
  2. Asigna cada elemento a su área y aplica estilos base. 
    .header  { grid-area: header;  background: #1a1a2e; padding: 20px; }
.sidebar { grid-area: sidebar; background: #16213e; padding: 20px; }
.stats   { grid-area: stats;   padding: 24px; }
.main    { grid-area: main;    padding: 24px; }
.footer  { grid-area: footer;  background: #1a1a2e; padding: 16px; }
  3. Dentro de .stats, crea un sub-grid para las 4 tarjetas. 
    .stats {
  grid-area: stats;
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(200px, 1fr));
  gap: 20px;
  padding: 24px;
}

.stat-card {
  background: white;
  border-radius: 12px;
  padding: 24px;
  box-shadow: 0 2px 8px rgba(0,0,0,0.08);
}
  4. Añade centrado al contenido del main. 
    .main {
  grid-area: main;
  display: grid;
  place-items: center;
  padding: 32px;
  min-height: 300px;
}
  5. Hazlo responsive: en móvil, todo en una columna. 
    @media (max-width: 768px) {
  .dashboard {
    grid-template-columns: 1fr;
    grid-template-areas:
      "header"
      "stats"
      "sidebar"
      "main"
      "footer";
  }
}

8 · Reto

🎯 Tu reto: Layout de portfolio personal

Diseña un layout de portfolio para un desarrollador con estas especificaciones:

  • Desktop (≥1024px): header a todo ancho con nombre y menú horizontal. Debajo, una grid de 3 columnas: foto de perfil (izquierda, ocupa 2 filas), bio (centro), skills (derecha). Debajo, proyectos destacados (2 columnas). Footer a todo ancho.

  • Móvil (<768px): 1 columna. Todo apilado.
  • Obligatorio: usa grid-template-areas en LAS TRES versiones. Nada de números de línea para el layout principal.
  • Usa place-items o place-self para centrar la foto de perfil dentro de su área.
  • Los proyectos en desktop deben usar la combinación mágica repeat(auto-fit, minmax(300px, 1fr)).

Este reto combina todo lo aprendido en las tres lecciones de Grid. Tómate 45 minutos. La solución debe ser exclusivamente CSS Grid, sin Flexbox salvo para componentes pequeños internos.

9 · Resumen

📌 Conceptos clave de esta lección
  • grid-template-areas: define el layout nombrando regiones con palabras. La forma más legible de crear layouts complejos.
  • Cada área debe formar un rectángulo contiguo. Usa . para celdas vacías.
  • grid-area: nombre que vincula un elemento con su región en grid-template-areas.
  • grid-column / grid-row: posicionamiento por números de línea o span. Alternativa a las áreas.
  • place-items: alinea el contenido de cada celda (eje vertical + horizontal). Se aplica en el contenedor.
  • place-content: alinea todo el grid dentro de su contenedor. Solo visible si el grid es más pequeño que el padre.
  • place-self: alinea un item específico dentro de su celda. Sobrescribe place-items.
  • El Holy Grail Layout se resuelve con 10 líneas de CSS Grid + áreas.
  • Cambiar grid-template-areas en media queries permite reorganizar completamente la página sin tocar el HTML.

10 · FAQ — Preguntas frecuentes

¿Cuándo usar grid-template-areas vs números de línea?

Usa áreas para layouts de página estructurales donde la disposición es conocida y fija (header, sidebar, contenido, footer). Usa números de línea / span para layouts dinámicos donde los items pueden colocarse en posiciones arbitrarias (galería masonry, dashboard con widgets reposicionables). Las áreas comunican mejor la intención del diseño; los números son más flexibles para posicionamiento algorítmico.

¿Puedo anidar grid-template-areas?

Sí. Un grid item con un área asignada puede ser a su vez un grid container con sus propias grid-template-areas. Es perfectamente válido y muy útil para layouts complejos. Por ejemplo, el área main puede contener su propio sub-grid con áreas como "article sidebar". Con subgrid, puedes incluso heredar las tracks del padre.

¿place-items: center reemplaza al viejo display: flex + align + justify?

Sí, si el contenedor ya es grid. place-items: center en un grid container centra todos los items en ambas direcciones. Es equivalente a align-items: center; justify-items: center;. Si necesitas centrar un solo elemento en un contenedor que no es grid, Flexbox con display: flex; align-items: center; justify-content: center sigue siendo la opción correcta.

¿Puedo tener áreas con el mismo nombre en posiciones no contiguas?

No. Si repites un nombre de área en celdas no contiguas, CSS Grid las trata como celdas independientes y la declaración se vuelve inválida. Para que múltiples celdas formen una sola área, deben ser contiguas y rectangulares. Si necesitas el mismo contenido en dos lugares distintos del grid, deberías plantearte si realmente quieres duplicar contenido o si tu layout necesita rediseñarse.

¿La alineación con place-content funciona si el grid ocupa todo el ancho?

No. place-content solo tiene efecto visible cuando el grid es más pequeño que su contenedor. Si tu grid ocupa todo el ancho y alto disponible (lo más común con 1fr), place-content no produce ningún cambio visual porque no hay espacio sobrante que distribuir. En ese caso, lo que buscas es place-items para alinear el contenido dentro de cada celda.

¿Cómo cambio el orden visual de las áreas en móvil sin cambiar el HTML?

Simplemente redefine grid-template-areas en una media query. Por ejemplo, si en desktop tienes "nav main aside" y en móvil quieres que nav aparezca debajo de main, escribe "main" "nav" "aside". El HTML no cambia en absoluto; solo cambia la definición de áreas. Esto es imposible de lograr sin Grid (con Flexbox necesitarías order, que tiene problemas de accesibilidad).
