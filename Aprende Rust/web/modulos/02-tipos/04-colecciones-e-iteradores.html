Vec, HashMap, closures e iteradores

Módulo 2 · Tipos y abstracciones ⏱ 40 minutos

1 · Introducción

Un programa real no vive de valores sueltos: guarda muchos. Vec<T> es la lista dinámica, HashMap<K, V> el diccionario, y los iteradores son la forma idiomática de recorrerlos. En Rust no hay un for mágico sobre índices: hay un trait Iterator que produce valores uno a uno, y una batería de adaptadores que transforman esa secuencia. La diferencia con Python o JavaScript está en el coste: cada adaptador es un tipo que se compone en compilación, sin listas intermedias ni bucles escondidos. links.iter().filter(...).map(...).sum() se compila a un solo recorrido, tan rápido como el bucle escrito a mano.

¿Por qué existe esta lección?

Porque el módulo 7 pide «los 10 códigos más usados», «hits por dominio» y «cuántos enlaces hay». Todo eso son colecciones e iteradores. Y porque elegir get en vez de links[99], o entry en vez de dos búsquedas, es la diferencia entre código robusto y un panic en producción.

Errores típicos al empezar: indexar sin comprobar, usar iter() cuando hace falta into_iter() (o al revés), mutar una colección mientras se recorre, y creer que map ejecuta algo antes de que un consumidor lo pida.

2 · Teoría

Vec<T>: el array que crece

Un Vec es un puntero a un bloque del heap con longitud y capacidad. push añade y, si no cabe, reserva el doble y copia: por eso el coste es amortizado constante. with_capacity evita esas reservas cuando sabes cuántos elementos vienen.

let mut hits = vec![0u64; 3];      // [0, 0, 0]
hits.push(5);                     // longitud 4
let last = hits.pop();            // Option<u64> = Some(5)
let second = hits.get(1);         // Option<&u64>: no puede fallar el programa
let first = hits[0];              // u64; si el índice no existe: panic

let mut codes = Vec::with_capacity(10_000);
codes.push(String::from("abc234"));

get devuelve Option y te obliga a decidir; el índice [] es cómodo cuando el índice es demostrablemente válido. En código que depende de entrada del usuario, get.

HashMap<K, V> y la entry API

HashMap guarda pares y busca por clave en tiempo (amortizado) constante. No tiene orden: si necesitas recorrer ordenado, usa BTreeMap. El patrón «si existe, modifica; si no, inserta» se escribe con entry, que hace una sola búsqueda:

use std::collections::HashMap;

let mut by_domain: HashMap<String, u64> = HashMap::new();
let domain = String::from("rust-lang.org");

*by_domain.entry(domain).or_insert(0) += 1;            // inserta o devuelve &mut V
*by_domain.entry("a.dev".to_string()).or_insert_with(|| 0) += 2;
by_domain.entry("b.dev".to_string())
    .and_modify(|n| *n += 10)
    .or_insert(1);                                     // si existe: +10; si no: 1

or_insert_with recibe una closure porque el valor por defecto puede ser caro (un Vec, una conexión); or_insert lo evalúa siempre. Para búsquedas simples, get devuelve Option<&V> y get_mut Option<&mut V>.

ColecciónOrdenUso típico
HashMap<K, V>NingunoConteos, índices, cachés
BTreeMap<K, V>Por claveInformes ordenados, rangos
HashSet<T>NingunoPertenencia y deduplicación

Closures: funciones que capturan

Una closure captura variables del entorno. Cómo las captura determina qué trait implementa y, por tanto, dónde puedes usarla:

TraitCapturaPuede llamarse
FnPor referencia (&T)Muchas veces, en paralelo
FnMutPor referencia mutable (&mut T)Muchas veces, en serie
FnOncePor valor (mueve o consume)Una sola vez
 
let factor = 2;
let double = |n: u64| n * factor;          // Fn: presta factor
let mut total = 0;
let mut add = |n: u64| total += n;         // FnMut: presta total mut
add(double(3));
add(1);
let consume = move || total;               // FnOnce: se lleva total
println!("{}", consume());

move es imprescindible cuando la closure sobrevive al ámbito (hilos, 'static) o cuando el tipo no es Copy. Los adaptadores de iterador aceptan closures FnMut, así que pueden modificar un acumulador externo sin problema.

Iteradores: perezosos por diseño

Iterator tiene un método obligatorio, next(), y decenas de adaptadores (map, filter, take, zip, chain, enumerate) que devuelven otro iterador sin ejecutar nada. El recorrido ocurre cuando llega un consumidor (collect, sum, fold, count, for).

let evens = (1..).filter(|n| n % 2 == 0);   // infinito y perezoso: no calcula nada
let first: Vec<i32> = evens.take(3).collect();   // [2, 4, 6]

let total: u64 = links.iter().map(|l| l.hits).sum();
let last_hit = links.iter().fold(0, |acc, l| acc.max(l.hits));

Un iterador encadenado no crea Vecs intermedios: cada elemento atraviesa la cadena. collect sí reserva el resultado (y a menudo acierta el tamaño con size_hint). Si el resultado es grande, esa es la única asignación relevante.

ExpresiónProduceConsume la colección
&v / v.iter()&TNo: préstamo inmutable
&mut v / v.iter_mut()&mut TNo: préstamo exclusivo
v / v.into_iter()TSí: mueve la colección

Regla: iter() para leer, iter_mut() para modificar en sitio, into_iter() cuando ya no necesitas la colección. Confundirlos es el origen de la mitad de los E0382 y E0502 de este módulo.

3 · Ejemplo mínimo

Contar visitas por código con HashMap y ordenar el resultado con un iterador. Compila tal cual:

use std::collections::HashMap;

fn main() {
    let mut visits: HashMap<&str, u32> = HashMap::new();

    for code in ["abc234", "abc234", "zzz999"] {
        *visits.entry(code).or_insert(0) += 1;   // una sola búsqueda
    }

    let mut pairs: Vec<(&str, u32)> = visits.into_iter().collect();
    pairs.sort_by(|a, b| b.1.cmp(&a.1).then_with(|| a.0.cmp(&b.0)));

    for (code, n) in pairs.iter().take(2) {
        println!("{code}: {n}");
    }
}

La clave: entry(code) evita el clásico «buscar, si no existe insertar, volver a buscar», y sort_by con then_with desempata por código para que el orden no sea arbitrario entre visitas iguales.

4 · Ejemplo real

Las estadísticas del panel de urlshort: totales, top de códigos y hits agrupados por dominio. Todo con iteradores y una sola pasada por colección:

use std::collections::HashMap;

#[derive(Debug, Clone)]
pub struct Link {
    pub code: String,
    pub url: String,
    pub hits: u64,
}

#[derive(Debug, Default)]
pub struct Stats {
    pub total_links: usize,
    pub total_hits: u64,
    pub top_codes: Vec<(String, u64)>,
    pub hits_by_domain: HashMap<String, u64>,
}

/// "https://a.dev/x" -> "a.dev"; si no hay esquema, corta en la primera barra.
pub fn domain_of(url: &str) -> &str {
    let rest = url.split_once("://").map(|(_, r)| r).unwrap_or(url);
    rest.split('/').next().unwrap_or(rest)
}

pub fn top_codes(links: &[Link], n: usize) -> Vec<(String, u64)> {
    let mut ranked: Vec<&Link> = links.iter().filter(|l| l.hits > 0).collect();
    ranked.sort_by(|a, b| b.hits.cmp(&a.hits).then_with(|| a.code.cmp(&b.code)));
    ranked.into_iter()
        .take(n)
        .map(|l| (l.code.clone(), l.hits))
        .collect()
}

pub fn hits_by_domain(links: &[Link]) -> HashMap<String, u64> {
    let mut acc: HashMap<String, u64> = HashMap::new();
    for link in links {
        *acc.entry(domain_of(&link.url).to_owned()).or_insert(0) += link.hits;
    }
    acc
}

pub fn stats(links: &[Link], n: usize) -> Stats {
    Stats {
        total_links: links.len(),
        total_hits: links.iter().map(|l| l.hits).sum(),
        top_codes: top_codes(links, n),
        hits_by_domain: hits_by_domain(links),
    }
}

fn main() {
    let links = vec![
        Link { code: "abc234".into(), url: "https://rust-lang.org/learn".into(), hits: 12 },
        Link { code: "zzz999".into(), url: "https://example.com/a".into(), hits: 5 },
        Link { code: "qqq111".into(), url: "https://rust-lang.org/tools".into(), hits: 3 },
        Link { code: "old000".into(), url: "https://example.com/b".into(), hits: 0 },
    ];

    let s = stats(&links, 2);
    println!("enlaces: {} · hits: {}", s.total_links, s.total_hits);
    for (code, hits) in &s.top_codes {
        println!("top /{code}: {hits}");
    }

    // HashMap no tiene orden: se ordena solo para imprimir.
    let mut domains: Vec<_> = s.hits_by_domain.iter().collect();
    domains.sort();
    for (domain, hits) in domains {
        println!("{domain}: {hits}");
    }
}

Salida:

enlaces: 4 · hits: 20
top /abc234: 12
top /zzz999: 5
example.com: 5
rust-lang.org: 15
DecisiónPor qué
or_insert(0) += link.hitsUna búsqueda por enlace y acumulación directa; el dominio nulo se crea en el acto.
map(...).sum() y ordenar una vista de referenciasSin Vec intermedio; y HashMap no garantiza orden, así que se ordenan las claves sin copiarlas.

Regla de oro

Si escribes un bucle que solo transforma o filtra, probablemente es un iterador. Si escribes tres búsquedas seguidas en un mapa, probablemente es una entry. Y si indexas con un número que viene de fuera, probablemente es un get.

6 · Errores habituales

1. Llamar a un adaptador sobre un Vec

let activos = links.filter(|l| l.hits > 0);
error[E0599]: no method named `filter` found for struct `Vec<Link>` in the current scope
 --> src/main.rs:5:23
  |
5 |     let activos = links.filter(|l| l.hits > 0);
  |                       ^^^^^^ method not found in `Vec<Link>`
  |
  = note: the method `filter` exists on the iterator returned by `.iter()`

Por qué: filter vive en Iterator, no en Vec. Bien: links.iter().filter(...).

2. Mutar mientras se recorre

let mut links = vec![];
for link in &links {
    links.push(link.clone());
}
error[E0502]: cannot borrow `links` as mutable because it is also borrowed as immutable
 --> src/main.rs:3:9
  |
2 |     for link in &links {
  |                 ------ immutable borrow occurs here
3 |         links.push(link.clone());
  |         ^^^^^^^^^^^^^^^^^^^^^^^ mutable borrow occurs here
4 |     }
  |     - immutable borrow later used here

Por qué: el for mantiene un préstamo inmutable vivo; push puede reasignar y dejar el iterador apuntando a memoria liberada. Bien: recorre una copia de los índices, usa retain o construye un Vec nuevo y asígnalo al final.

3. Usar la colección después de into_iter

let codes: Vec<String> = links.into_iter().map(|l| l.code).collect();
println!("{}", links.len());
error[E0382]: borrow of moved value: `links`
 --> src/main.rs:7:20
  |
5 |     let codes: Vec<String> = links.into_iter().map(|l| l.code).collect();
  |                              ----- value moved here
7 |     println!("{}", links.len());
  |                    ^^^^^ value borrowed here after move
  |
  = note: move occurs because `links` has type `Vec<Link>`,
          which does not implement the `Copy` trait

Por qué: into_iter() consume la colección. Bien: links.iter().map(|l| l.code.clone()) si necesitas conservarla, o calcula len() antes.

4. Meter en un HashSet un tipo sin Hash

error[E0277]: the trait bound `Link: Hash` is not satisfied
 --> src/main.rs:6:16
  |
6 |     set.insert(link);
  |         ------ ^^^^ the trait `Hash` is not implemented for `Link`
  |
  = note: `HashSet<Link>` requires `Link: Hash` for its `insert` method
  = help: the trait `Hash` is implemented for `String`, `&str`, `u64`, ...

Por qué: el conjunto usa el hash para decidir pertenencia. Bien: #[derive(Hash, PartialEq, Eq)] en Link, o guarda String (el código) en lugar del struct entero.

Y recuerda que indexar fuera de rango no es un error de compilación sino un panic en ejecución: index out of bounds: the len is 3 but the index is 5. v.get(5) devuelve None y te obliga a manejar el caso; en un servidor, ese panic mata la tarea que atendía la petición.

8 · Reto

🎯 El informe de 2 GB sin cargarlo en memoria

Tienes un log de accesos de 2 GB, una línea por resolución: 2026-11-17T10:03:12Z /abc234. El equipo quiere el top 10 de códigos y un histograma por hora, y la máquina no puede permitirse cargar el fichero entero.

Escribe un binario que lea el fichero en streaming y produzca ambos informes con memoria acotada:

  • BufReader y lines(): nunca read_to_string del fichero completo.
  • HashMap<&str, u64> o HashMap<String, u64> para los códigos; razona cuál puedes permitirte.
  • Para el top 10, no ordenes un millón de claves: usa un BinaryHeap de tamaño 10 o un select_nth_unstable.
  • El histograma por hora puede ser un [u64; 24] si normalizas la marca temporal; evita un mapa por minuto, y cuenta las líneas malformadas en lugar de romper el proceso.

Pista: lines() asigna un String por línea; si el rendimiento importa, lee con read_line sobre un buffer reutilizado y haz clear() en cada vuelta. Y ojo con los préstamos: un HashMap<&str, _> que apunte al buffer dejará de ser válido al reutilizarlo, así que ahí sí necesitas String.

9 · Resumen

  • Vec<T> es la lista dinámica y HashMap el diccionario sin orden; la entry API inserta y actualiza en una sola búsqueda, y BTreeMap/BTreeSet pagan un logaritmo por mantener el orden.
  • Las closures capturan por referencia (Fn), mutable (FnMut) o valor (FnOnce); move fuerza la captura por valor.
  • Los iteradores son perezosos: los adaptadores no ejecutan nada hasta que un consumidor los recorre.
  • iter() presta, iter_mut() presta en exclusiva, into_iter() consume; encadenar adaptadores no crea colecciones intermedias.

Comandos y conceptos de esta lección

ComandoQué hace
vec![0; n] / Vec::with_capacity(n)Crea un vector con valores repetidos o con capacidad reservada.

10 · Preguntas frecuentes

¿Vec<T> es lo mismo que un array o un slice?

No. [T; N] es un array de tamaño fijo, normalmente en el stack. &[T] es un slice: una vista prestada de una secuencia contigua, sin dueño. Vec<T> posee su bloque en el heap y puede crecer. Una función que solo lee debe pedir &[T]: acepta arrays, slices y Vec por igual.

¿Por qué el orden de un HashMap cambia entre ejecuciones?

Porque usa una semilla aleatoria para el hash (protección contra ataques de colisiones) y el recorrido depende de la capacidad y de los hashes. Si necesitas un orden estable, usa BTreeMap o recoge las claves y ordénalas. No escribas tests que dependan del orden de iteración de un HashMap.

¿iter(), iter_mut() o into_iter()?

iter() produce &T y deja la colección intacta; úsalo para leer y calcular. iter_mut() produce &mut T y permite modificar en sitio, con préstamo exclusivo. into_iter() produce T y consume la colección: úsalo cuando el resultado sustituye a los datos originales o cuando quieres mover los String sin clonar.

¿Por qué mi map no hace nada?

Porque es perezoso. links.iter().map(|l| println!("{}", l.code)); no imprime nada: el iterador se crea y se descarta sin consumirse. Necesitas un consumidor: for_each, collect, count o un for. En Rust, un #[must_use] sobre Map hace que el compilador te avise, pero el hábito de preguntar «¿quién consume esto?» es más fiable.
