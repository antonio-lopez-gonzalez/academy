Structs, métodos y funciones asociadas

Módulo 2 · Tipos y abstracciones ⏱ 40 minutos

1 · Introducción

Un struct agrupa datos relacionados bajo un nombre y les da un tipo propio. Hasta ahora has manejado valores sueltos: un String para el código, otro para la URL, un u64 para las visitas. Eso funciona durante veinte líneas y se convierte en un infierno cuando nada impide pasar los argumentos en el orden equivocado.

Rust no tiene clases ni herencia. Tiene structs (los datos) y bloques impl (el comportamiento), separados a propósito. Un struct no «sabe» nada: es un diseño de memoria. El comportamiento se añade después, y el compilador comprueba que cada método respeta el contrato de propiedad que ya conoces del módulo 1.

¿Por qué existe esta lección?

Porque el dominio de urlshort empieza aquí. Link { code, url, created_at, hits } es la primera pieza real del proyecto y la vas a usar en todas las lecciones siguientes: enums, traits, persistencia, CLI y servidor. Si los structs te quedan flojos, el resto del curso se construye sobre arena.

Al terminar sabrás distinguir las tres formas de struct, elegir el receptor correcto (&self, &mut self o self), escribir constructores idiomáticos y proteger invariantes con campos privados.

Errores típicos al empezar:

  • Creer que new es un constructor mágico del lenguaje. Es solo una convención.
  • Pedir &mut self en todos los métodos «por si acaso» y bloquear el resto del programa.
  • Dejar todos los campos pub y descubrir que cualquiera puede romper un invariante.
  • Usar ..otro y luego seguir usando otro como si estuviera intacto.

2 · Teoría

Datos y comportamiento, separados

En Java o C# una clase mezcla estado y métodos y hereda de otra clase. En Rust la separación es explícita: el tipo es un diseño de memoria y el comportamiento se añade en un bloque aparte. Eso permite implementar rasgos sobre tipos que no controlas (con reglas, lo verás en traits) y evita arrastrar jerarquías enteras.

FormaSintaxisCuándo usarla
Campos nombradosstruct Link { code: String, url: String }El caso normal: el nombre documenta el dato y el orden no importa.
Tuplastruct Code(String);Newtype: dar identidad y validación a un valor sin coste en ejecución.
Unitariostruct Marked;Marcar un tipo en el sistema de tipos, sin datos.

Instanciar: sin constructor implícito

Crear un valor exige rellenar todos los campos. No hay constructores por defecto ni campos sin inicializar; el compilador no deja crear un valor a medias. Si la variable se llama igual que el campo, el field init shorthand evita la repetición:

let code = String::from("abc234");
let url = String::from("https://www.rust-lang.org");
let link = Link { code, url, created_at: 0, hits: 0 };

Con ..base rellenas el resto desde otro valor. Ojo: los campos que no son Copy se mueven, no se copian; el original queda parcialmente movido.

let base = Link::new("https://a.dev");
let bumped = Link { hits: 1, ..base };   // code y url se MUEVEN
// println!("{base:?}");                 // error[E0382]

El bloque impl: tres receptores, tres contratos

El primer parámetro de un método decide qué puede hacer con el valor. link.register_hit() es azúcar sintáctico de Link::register_hit(&mut link): por eso los errores de métodos son, en realidad, errores de préstamo.

ReceptorQué puede hacerSe llama sobre
&selfLeer. Puede haber varios a la vez.Un valor prestado.
&mut selfLeer y escribir. Exclusivo mientras dure.Solo si la variable es mut.
selfConsumir; puede devolver partes sin clonar.El dueño; el valor deja de existir.
 
impl Link {
    fn hits(&self) -> u64 { self.hits }
    fn register_hit(&mut self) { self.hits += 1; }
    fn into_url(self) -> String { self.url }   // sin clone
}

Funciones asociadas, new y Default

Una función asociada vive en el impl pero no recibe self: se invoca como Link::new(url). new es la convención de la std para el constructor habitual, no una palabra reservada. Su ventaja real: si los campos son privados, es la única puerta de entrada, y ahí validas, normalizas y calculas derivados.

impl Link {
    fn new(url: &str) -> Self {
        Self { code: derive_code(url), url: url.to_owned(), created_at: 0, hits: 0 }
    }
}
// let link = Link::new("https://rust-lang.org");   // no link.new(...)

Default es el trait del «valor neutro razonable». Se deriva si todos los campos lo implementan, o se escribe a mano cuando el neutro no es trivial. La std lo usa en unwrap_or_default, Vec::default() y muchos constructores.

Derivar y proteger

#[derive(Debug, Clone, PartialEq)] cubre lo mecánico: Debug da {:?} para diagnosticar, Clone hace copia profunda explícita y PartialEq habilita ==. Display no se deriva: el formato de usuario es una decisión de producto. Y la visibilidad importa: un campo pub promete que cualquier valor es válido; si hay invariantes (hits nunca baja, code mide 6), los campos van privados y el acceso pasa por métodos.

  Link en el stack                         Datos en el heap
  ┌───────────────────────────┐
  │ code: String              │──────►  "abc234"           (len 6, cap 6)
  │   ptr · len · cap  (24 B) │
  ├───────────────────────────┤
  │ url: String               │──────►  "https://..."     (len 41, cap 41)
  │   ptr · len · cap  (24 B) │
  ├───────────────────────────┤
  │ created_at: u64    (8 B)  │
  │ hits: u64          (8 B)  │
  └───────────────────────────┘

Un struct así ocupa 64 bytes en un target de 64 bits: por eso moverlo es barato y pasar &Link también; clone(), en cambio, sí reserva memoria para el texto. El struct es una ficha con dos punteros; las cadenas viven aparte.

3 · Ejemplo mínimo

Un struct con dos campos, una función asociada y los tres receptores. Compila tal cual:

#[derive(Debug, Clone, PartialEq)]
struct Link {
    code: String,
    url: String,
}
impl Link {
    // Función asociada: se llama sobre el TIPO, no sobre un valor.
    fn new(code: &str, url: &str) -> Self {
        Self { code: code.to_owned(), url: url.to_owned() }
    }
    // Préstamo inmutable: solo lee.
    fn is_short(&self) -> bool {
        self.code.len() == 6
    }
    // Préstamo mutable: modifica, el dueño sigue siendo el mismo.
    fn rewrite(&mut self, url: &str) {
        self.url = url.to_owned();
    }
    // Consume: devuelve el String sin clonarlo.
    fn into_url(self) -> String {
        self.url
    }
}
fn main() {
    let mut link = Link::new("abc234", "https://rust-lang.org");
    assert!(link.is_short());
    link.rewrite("https://www.rust-lang.org/learn");
    println!("{link:?}");
    let url = link.into_url();   // a partir de aquí `link` ya no existe
    println!("{url}");
}

Línea a línea:

  • #[derive(Debug, Clone, PartialEq)] genera tres implementaciones. Debug hace posible {link:?}; sin él, el compilador rechaza el println!.
  • Self dentro del impl es alias del tipo: menos repetición y menos errores al renombrar.
  • code.to_owned() convierte &str en String; String::from(code) y code.to_string() son equivalentes.
  • link.rewrite(...) exige let mut. Sin mut, el error es E0596.
  • Tras into_url, usar link sería un E0382: el valor se movió.

Lo que no hay: Display. println!("{link}") no compilaría y el compilador pediría error[E0277]: `Link` doesn't implement `std::fmt::Display`. Se implementa a mano en el ejemplo real, cuando el formato sea una decisión y no un detalle de depuración.

4 · Ejemplo real

Así queda Link en urlshort. El código se deriva de la URL (no lo elige el usuario) y el contador solo sube por una puerta:

// src/domain.rs — el corazón de urlshort
use std::fmt;
use std::time::{SystemTime, UNIX_EPOCH};
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct Link {
    code: String,
    url: String,
    created_at: u64,
    hits: u64,
}
impl Link {
    /// Crea un enlace nuevo: código derivado de la URL y hits a 0.
    pub fn new(url: &str) -> Self {
        let created_at = SystemTime::now()
            .duration_since(UNIX_EPOCH)
            .map(|d| d.as_secs())
            .unwrap_or(0);
        Self { code: derive_code(url), url: url.to_owned(), created_at, hits: 0 }
    }
    pub fn code(&self) -> &str { &self.code }
    pub fn url(&self) -> &str { &self.url }
    pub fn hits(&self) -> u64 { self.hits }
    /// Registra una resolución: la única forma de subir el contador.
    pub fn register_hit(&mut self) {
        self.hits += 1;
    }
    pub fn age_secs(&self, now: u64) -> u64 {
        now.saturating_sub(self.created_at)
    }
}
impl fmt::Display for Link {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        write!(f, "/{} -> {} ({} hits)", self.code, self.url, self.hits)
    }
}
/// FNV-1a de 64 bits: corto, estable y sin dependencias.
fn derive_code(url: &str) -> String {
    let mut hash: u64 = 0xcbf2_9ce4_8422_2325;
    for byte in url.bytes() {
        hash = (hash ^ u64::from(byte)).wrapping_mul(0x0000_0100_0000_01b3);
    }
    const ALPHABET: &[u8] = b"23456789abcdefghjkmnpqrstuvwxyz";
    (0..6)
        .map(|i| ALPHABET[(hash >> (i * 6)) as usize % ALPHABET.len()] as char)
        .collect()
}
fn main() {
    let mut link = Link::new("https://www.rust-lang.org/learn");
    link.register_hit();
    link.register_hit();
    println!("{link}");
    println!("antigüedad: {} s", link.age_secs(link.created_at + 120));
    let bumped = Link { hits: 10, ..link.clone() };
    println!("{bumped}");
}

Salida (tu código de 6 caracteres dependerá del hash):

/k7m2qd -> https://www.rust-lang.org/learn (2 hits)
antigüedad: 120 s
/k7m2qd -> https://www.rust-lang.org/learn (10 hits)
DecisiónPor qué
Campos privados + gettersNadie fabrica un Link fuera de new ni cambia el código por la espalda.
register_hit(&mut self)hits solo sube, y solo por esta puerta. Un campo público permitiría link.hits -= 5.
created_at en segundos (u64)Suficiente para el dominio, comparable y trivial de serializar.
age_secs(now) recibe nowSin reloj escondido: determinista y testeable con cualquier instante.
Display a mano y Eq junto a PartialEqEl formato de usuario es una decisión; Eq permite usar el tipo como clave de colecciones.

Analogía: la ficha del archivador

El struct es una ficha con casillas. new es la ventanilla donde la rellenan; los getters son la fotocopiadora (leer sin llevarte el original); register_hit es el sello que solo pone el funcionario; un método con self es romper la ficha para quedarte una casilla. Y ..otro es fotocopiar una ficha vieja cambiando un dato: si la fotocopiadora se lleva los datos, la vieja queda incompleta.

Regla de oro

Antes de añadir un método, pregúntate qué receptor necesita de verdad. Si dudas entre &self y &mut self, empieza por &self: el compilador te avisará en el primer sitio donde haga falta mutar. Relajar es más fácil que endurecer.

6 · Errores habituales

1. Llamar a una función asociada como si fuera método

Mal:

let link = Link::new("https://rust-lang.org");
let otro = link.new("https://example.com");
error[E0599]: no method named `new` found for struct `Link` in the current scope
  --> src/main.rs:12:18
   |
3  |     fn new(url: &str) -> Self {
   |        --- associated function `new` defined here
...
12 |     let otro = link.new("https://example.com");
   |                   ^^^ this is an associated function, not a method
   |
   = note: associated functions are called with `Link::new(...)`

Por qué: new no recibe self, así que no existe sobre un valor. Bien: Link::new("https://example.com").

2. Confundir &str con String al rellenar un campo

Mal:

struct Link { code: String, url: String }
let link = Link { code: "abc234", url: "https://a.dev" };
error[E0308]: mismatched types
 --> src/main.rs:2:23
  |
2 | let link = Link { code: "abc234", url: "https://a.dev" };
  |                       ^^^^^^^^ expected `String`, found `&str`
  |
help: try using a conversion method
  |
2 | let link = Link { code: "abc234".to_string(), url: "https://a.dev".to_string() };

Por qué: un literal es &'static str, una vista prestada; el campo posee su memoria y necesita String. Bien: "abc234".to_owned().

3. Usar el original después de ..base

let base = Link::new("https://a.dev");
let bumped = Link { hits: 1, ..base };
println!("{base:?}");
error[E0382]: borrow of partially moved value: `base`
 --> src/main.rs:8:16
  |
6 |     let bumped = Link { hits: 1, ..base };
  |                                     ---- value partially moved here
8 |     println!("{base:?}");
  |               ^^^^ value borrowed here after partial move
  |
  = note: partial move occurs because `base.code` has type `String`,
          which does not implement the `Copy` trait

Por qué: ..base no copia: mueve cada campo no Copy, y Rust no permite usar valores parcialmente movidos. Bien: ..base.clone() si de verdad necesitas ambos, o construir el nuevo valor campo a campo sin tocar el original.

4. Mutar sin declarar mut

error[E0596]: cannot borrow `link` as mutable, as it is not declared as mutable
 --> src/main.rs:5:5
  |
4 |     let link = Link::new("https://a.dev");
  |         ---- help: consider changing this to be mutable: `mut link`
5 |     link.register_hit();
  |     ^^^^^^^^^^^^^^^^^^^ cannot borrow as mutable

Por qué: la mutabilidad es una propiedad del binding, no del tipo. Bien: let mut link = ..., y solo donde haga falta.

7 · Ejercicio guiado

Objetivo: construir el módulo de dominio con un struct encapsulado, sus métodos y tests. Criterio: dos tests en verde y clippy sin avisos.

  1. Crea la librería. 
    cargo new urlshort-domain --lib
cd urlshort-domain

    Una --lib no tiene main: el dominio se prueba y se reutiliza desde el binario y, más adelante, desde el servidor.

  2. Define el struct con campos privados. En src/lib.rs: 
    use std::fmt;
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct Link {
    code: String,
    url: String,
    hits: u64,
}
impl Link {
    pub fn new(code: &str, url: &str) -> Self {
        Self { code: code.to_owned(), url: url.to_owned(), hits: 0 }
    }
    pub fn code(&self) -> &str { &self.code }
    pub fn url(&self) -> &str { &self.url }
    pub fn hits(&self) -> u64 { self.hits }
    pub fn register_hit(&mut self) { self.hits += 1; }
    pub fn is_never_used(&self) -> bool { self.hits == 0 }
}
impl fmt::Display for Link {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        write!(f, "/{} -> {} ({} hits)", self.code, self.url, self.hits)
    }
}
  3. Añade los tests. Al final del mismo fichero: 
    #[cfg(test)]
mod tests {
    use super::*;
    #[test]
    fn nuevo_link_empieza_sin_hits() {
        let link = Link::new("abc234", "https://rust-lang.org");
        assert_eq!(link.hits(), 0);
        assert!(link.is_never_used());
    }
    #[test]
    fn register_hit_incrementa_el_contador() {
        let mut link = Link::new("abc234", "https://rust-lang.org");
        link.register_hit();
        link.register_hit();
        assert_eq!(link.hits(), 2);
        assert_eq!(link.to_string(), "/abc234 -> https://rust-lang.org (2 hits)");
    }
}
  4. Ejecuta los tests. 
    cargo test
    running 2 tests
test result: ok. 2 passed; 0 failed; 0 ignored
  5. Rompe el invariante y pasa clippy. Añade link.code = String::from("x"); en un test: error[E0616]: field `code` of struct `Link` is private. Después: 
    cargo clippy --all-targets -- -D warnings

    Si sugiere Self { .. } o to_owned() en vez de to_string(), acéptalo: es la forma idiomática.

Criterio de éxito

Puedes explicar por qué code es privado y por qué hits solo cambia por register_hit. Y has visto el E0616 con tus ojos: la encapsulación ya no es teoría.

8 · Reto

🎯 El newtype Code

Ahora mismo Link::new acepta cualquier &str como código: vacío, de 200 caracteres o con emojis. El resto del sistema asume 6 caracteres del alfabeto 23456789abcdefghjkmnpqrstuvwxyz.

Crea un struct de tupla pub struct Code(String) con el campo privado e impide que exista un Code inválido:

  • Implementa TryFrom<&str> con un error InvalidCode que distinga «longitud incorrecta» de «carácter no permitido».
  • Implementa Display y AsRef<str> para leerlo sin exponer el String.
  • Cambia Link para que su campo code sea un Code y su new devuelva Result<Link, InvalidCode>.
  • Añade rename(&mut self, code: Code) y razona por qué recibe el tipo ya validado y no un &str.

Pista: el newtype no cuesta nada en ejecución (mismo layout que String) y convierte «validar en todos los sitios» en «validar una vez, en la puerta». Para el error, un enum con BadLength { got: usize } y BadChar { ch: char } te dará mensajes útiles sin strings mágicos.

9 · Resumen

  • Un struct agrupa datos y un bloque impl añade comportamiento: no hay clases ni herencia. Tres formas: campos nombrados, tupla (newtypes) y unitario (marcadores de tipo).
  • El receptor decide el contrato: &self lee, &mut self escribe, self consume.
  • new es una convención, no un constructor del lenguaje: tú decides qué valores son válidos.
  • #[derive(Debug, Clone, PartialEq)] cubre lo mecánico; Display se escribe a mano.
  • ..otro mueve los campos no Copy del original: no es una copia; y los campos privados con constructor son invariantes protegidos por el compilador.

10 · Preguntas frecuentes

¿Por qué no hay constructores como en C++ o Java?

Porque un constructor implícito permite estados a medio construir y obliga al lenguaje a decidir cuándo un objeto está «completo». En Rust cualquier valor de un tipo es válido por definición: si hay un invariante, se pone detrás de una función asociada que valida y devuelve Result. Menos magia, más garantías.

¿Puedo repartir los métodos en varios bloques impl?

Sí. Puedes tener varios impl Link en distintos módulos o ficheros, e incluso uno por trait. El compilador los une. Es lo que permite que un trait añada métodos a un tipo sin tocar el impl original.

¿Cuándo uso un struct de tupla en lugar de uno con nombres?

Cuando envuelve un solo valor y lo importante es la identidad del tipo, no los nombres: struct Code(String), struct Meters(f64), struct UserId(u64). Evita mezclar unidades y hace imposible pasar un u64 cualquiera donde se espera un identificador. Con dos o más campos con significado distinto, usa nombres.

¿#[derive(Clone)] es una copia superficial?

Es una copia profunda de lo que el tipo posee: clonar un Link duplica las dos cadenas. Lo que no clona son recursos externos (ficheros, sockets), que no implementan Clone por buenas razones. Copy es otra cosa: solo para tipos de tamaño fijo sin dueño, y se copia de forma implícita.
