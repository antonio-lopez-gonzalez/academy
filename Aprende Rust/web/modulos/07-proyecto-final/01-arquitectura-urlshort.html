Arquitectura de urlshort

Módulo 7 · Proyecto final ⏱ 40 minutos

1 · Introducción

Treinta y una lecciones después, cada pieza de Rust funciona por separado: propiedad, traits, errores, async, clap, axum, SQLite. El proyecto final consiste en algo distinto y más difícil: ponerlas juntas sin que se contaminen. urlshort tiene que acortar una URL desde la terminal, guardarla en disco, resolverla por HTTP, contar visitas y sobrevivir a un test que lo arranca en un puerto efímero.

¿Por qué existe esta lección?

Porque la diferencia entre un ejercicio y un crate publicable no es la sintaxis: es el dibujo de las dependencias. Si el dominio depende de axum, cada test arrastra un runtime. Si el CLI conoce el fichero, no puedes probar los mensajes de error con un store en memoria. La arquitectura decide qué se puede cambiar sin romper lo demás.

Errores típicos al diseñar esto:

  • Poner #[derive(Serialize)] y las rutas HTTP en el mismo fichero que las reglas del negocio.
  • Creer que «arquitectura» significa más carpetas: aquí son ocho ficheros y una regla.

2 · Teoría

Cuatro capas y una flecha que nunca se invierte

urlshort se organiza en cuatro capas. La regla es una sola: las dependencias apuntan hacia dentro. El dominio no sabe que existe HTTP; los adaptadores sí saben que existe el dominio.

┌──────────────────────────────────────────────────────────────┐
│  ADAPTADORES DE ENTRADA    main.rs · cli.rs · server.rs      │
└──────────────────────────────┬───────────────────────────────┘
                               │ short() · resolve() · list() · delete()
┌──────────────────────────────▼───────────────────────────────┐
│  CASO DE USO             service.rs · Service (Clone)        │
│  validar → generar código → comprobar → guardar              │
└──────────────────────────────┬───────────────────────────────┘
                               │ trait Store  (puerto)
┌──────────────────────────────▼───────────────────────────────┐
│  ADAPTADORES DE SALIDA  MemoryStore · JsonStore · SqliteStore│
└──────────────────────────────────────────────────────────────┘
  DOMINIO (domain.rs) no depende de nadie: está a la izquierda de todo.

Fíjate en dónde se declara el trait. En Java o C# el puerto viviría en infraestructura y el dominio lo importaría. Aquí se declara junto al caso de uso que lo necesita y el adaptador —que sí conoce el sistema de ficheros— es quien se adapta. Eso es inversión de dependencias con traits, sin contenedores de inyección.

Qué es dominio y qué no lo es

El dominio son las reglas que seguirían siendo verdaderas si mañana urlshort se usara desde gRPC: una URL solo es válida con esquema http/https, host y longitud razonable; un enlace tiene código, URL, fecha y contador; dos enlaces no comparten código. No es dominio que se guarde en JSON, que el CLI imprima una tabla, que el servidor responda 302 o que la fecha se muestre en tu zona horaria: son decisiones de borde.

El flujo de una petición, de punta a punta

3 · Ejemplo mínimo

El corazón del dominio en un fichero: un enlace, la validación de URL y el generador de códigos. Va en domain.rs, con error.rs creado y cargo add chrono ya ejecutado.

use std::collections::hash_map::DefaultHasher;
use std::hash::{Hash, Hasher};
use chrono::{SecondsFormat, Utc};
use serde::{Deserialize, Serialize};
use crate::error::Error;

pub const CODE_LEN: usize = 6;
pub const MAX_URL_LEN: usize = 2048;
#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
pub struct Link {
    code: String,
    url: String,
    created_at: String,
    hits: u64,
}

impl Link {
    pub fn new(code: impl Into<String>, url: impl Into<String>) -> Self {
        Self {
            code: code.into(),
            url: url.into(),
            created_at: Utc::now().to_rfc3339_opts(SecondsFormat::Secs, true),
            hits: 0,
        }
    }

    pub fn code(&self) -> &str { &self.code }
    pub fn url(&self) -> &str { &self.url }
    pub fn created_at(&self) -> &str { &self.created_at }
    pub fn hits(&self) -> u64 { self.hits }
    pub fn register_hit(&mut self) { self.hits += 1; }

    pub fn short_url(&self, base_url: &str) -> String {
        format!("{}/{}", base_url.trim_end_matches('/'), self.code)
    }
}

/// Devuelve la URL recortada o un error de dominio.
pub fn validate_url(raw: &str) -> Result<String, Error> {
    let url = raw.trim();
    if url.is_empty() { return Err(Error::InvalidUrl("la URL está vacía".into())); }
    if url.len() > MAX_URL_LEN { return Err(Error::InvalidUrl("la URL es demasiado larga".into())); }
    if url.chars().any(char::is_whitespace) { return Err(Error::InvalidUrl("la URL tiene espacios".into())); }
    let rest = url
        .strip_prefix("https://")
        .or_else(|| url.strip_prefix("http://"))
        .ok_or_else(|| Error::InvalidUrl("se esperaba http:// o https://".into()))?;
    // corta en el primer separador de ruta: "https:///x" deja host vacío
    let host = rest.split(|c| matches!(c, '/' | '?' | '#')).next().unwrap_or("");
    if host.is_empty() { return Err(Error::InvalidUrl("la URL no tiene host".into())); }
    Ok(url.to_string())
}

/// Base62 de 6 caracteres; el `salt` resuelve colisiones.
pub fn generate_code(seed: &str, salt: u64) -> String {
    const ALPHABET: &[u8; 62] = b"0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz";
    let mut hasher = DefaultHasher::new();
    seed.hash(&mut hasher);
    salt.hash(&mut hasher);
    let mut n = hasher.finish();
    let mut code = String::with_capacity(CODE_LEN);
    for _ in 0..CODE_LEN {
        code.push(ALPHABET[(n % 62) as usize] as char);
        n /= 62;
    }
    code
}
  • validate_url devuelve un String ya recortado: el resto del programa no vuelve a limpiar la entrada. Es la frontera donde el texto del usuario se convierte en dato del dominio.
  • strip_prefix + or_else acepta dos esquemas sin expresiones regulares; ok_or convierte el «no hay prefijo» en error con ?.

4 · Ejemplo real

Así queda el crate: ocho ficheros con una responsabilidad cada uno y un único tipo de error.

proyectos/urlshort/
├── Cargo.toml
├── src/
│   ├── main.rs        ← arranca: parsea y delega
│   ├── lib.rs         ← la biblioteca: pub mod …
│   ├── domain.rs      ← Link, validate_url, generate_code
│   ├── error.rs       ← enum Error: la única moneda de fallo
│   ├── store.rs       ← trait Store + MemoryStore + JsonStore
│   ├── service.rs     ← Service: short, resolve, list, delete
│   ├── cli.rs         ← clap y salida (lección 02)
│   └── server.rs      ← router, handlers, ApiError (lección 03)
└── tests/cli.rs       ← flujo completo contra un fichero temporal

El error único. Cada capa puede producir estos seis casos; el adaptador decide qué significa cada uno (400, 404, 409 o 500).

// src/error.rs
use thiserror::Error;

#[derive(Debug, Error)]
pub enum Error {
    #[error("URL inválida: {0}")]
    InvalidUrl(String),
    #[error("no existe el código {0}")]
    NotFound(String),
    #[error("conflicto con el código {0}")]
    Conflict(String),
    #[error("el almacén está bloqueado por otro hilo")]
    Lock,
    #[error("fallo de entrada/salida: {0}")]
    Io(#[from] std::io::Error),
    #[error("JSON inválido: {0}")]
    Json(#[from] serde_json::Error),
}

El puerto. Cinco operaciones y una implementación por defecto; recibe &self porque el estado mutable vive dentro del adaptador, no en quien lo llama.

// src/store.rs
pub trait Store: Send + Sync {
    fn insert(&self, link: Link) -> Result<(), Error>;
    fn get(&self, code: &str) -> Result<Option<Link>, Error>;
    fn list(&self) -> Result<Vec<Link>, Error>;
    fn delete(&self, code: &str) -> Result<bool, Error>;
    fn update(&self, link: Link) -> Result<(), Error>;

    /// Por defecto, existir es poder leerse. Los adaptadores pueden optimizarlo.
    fn exists(&self, code: &str) -> Result<bool, Error> {
        Ok(self.get(code)?.is_some())
    }
}

El caso de uso. `Service` guarda el trait como objeto y se clona para cada handler; el Mutex está en el adaptador, no aquí.

// src/service.rs
pub const MAX_ATTEMPTS: u64 = 16;

#[derive(Clone)]
pub struct Service {
    store: Arc<dyn Store>,
    base_url: String,
}

impl Service {
    pub fn new(store: Arc<dyn Store>, base_url: impl Into<String>) -> Self {
        Self { store, base_url: base_url.into() }
    }
    pub fn base_url(&self) -> &str { &self.base_url }

    pub fn short(&self, raw_url: &str) -> Result<Link, Error> {
        let url = validate_url(raw_url)?;
        for salt in 0..MAX_ATTEMPTS {
            let link = Link::new(generate_code(&url, salt), url.clone());
            match self.store.insert(link.clone()) {
                Ok(()) => return Ok(link),
                Err(Error::Conflict(_)) => continue,   // colisión: otro salt
                Err(err) => return Err(err),
            }
        }
        Err(Error::Conflict(format!("sin códigos libres para {url}")))
    }

    pub fn resolve(&self, code: &str) -> Result<Link, Error> {
        let mut link = self.store.get(code)?.ok_or_else(|| Error::NotFound(code.into()))?;
        link.register_hit();
        self.store.update(link.clone())?;
        Ok(link)
    }
    pub fn list(&self) -> Result<Vec<Link>, Error> { self.store.list() }

    pub fn delete(&self, code: &str) -> Result<(), Error> {
        if self.store.delete(code)? { Ok(()) }
        else { Err(Error::NotFound(code.into())) }
    }
}

El adaptador JSON cumple el puerto sin que el caso de uso lo sepa. El Mutex va dentro; el volcado escribe en un temporal y renombra, atómico en el mismo sistema de ficheros.

// src/store.rs (adaptador)
pub struct JsonStore {
    path: PathBuf,
    links: Mutex<BTreeMap<String, Link>>,
}

impl JsonStore {
    /// Lee el JSON si existe; si no, arranca vacío.
    pub fn open(path: impl Into<PathBuf>) -> Result<Self, Error> { /* … */ }

    fn flush(&self, links: &BTreeMap<String, Link>) -> Result<(), Error> {
        let json = serde_json::to_string_pretty(links)?;
        let tmp = self.path.with_extension("json.tmp");
        fs::write(&tmp, json)?;
        fs::rename(&tmp, &self.path)?;       // o queda el JSON nuevo, o el viejo
        Ok(())
    }
}

impl Store for JsonStore {
    fn insert(&self, link: Link) -> Result<(), Error> {
        let mut links = self.links.lock().map_err(|_| Error::Lock)?;
        if links.contains_key(link.code()) {
            return Err(Error::Conflict(link.code().to_string()));
        }
        links.insert(link.code().to_string(), link);
        self.flush(&links)                   // si falla, el mapa ya cambió
    }
    // get, list, delete y update: candado + operación sobre el mapa
}

5 · Buenas prácticas

Haz estoEvita estoPor qué
Declarar el puerto con lo que el dominio necesitaCopiar la API del ORM en el traitUn puerto con begin_transaction obliga a todos los adaptadores a fingir transacciones.
Validar en validate_url y devolver el dato limpioRepetir starts_with("http") en tres capasLas comprobaciones duplicadas divergen y el mensaje cambia según la puerta.
Candado dentro del adaptadorArc<Mutex<Service>> en el servidorEl que conoce el recurso compartido es el store, no el router.

No conviertas esto en una catedral

Cuatro capas para un acortador es suficiente, no un dogma. Regla práctica: añade una capa cuando puedas nombrar el test que se vuelve posible gracias a ella. Si no puedes, es ceremonia.

6 · Errores habituales

1. Un método genérico en el trait que vas a usar como dyn

pub trait Store: Send + Sync {
    fn all(&self) -> Result<Vec<Link>, Error>;
    fn find<F>(&self, predicate: F) -> Result<Option<Link>, Error>
    where
        F: Fn(&Link) -> bool;
}

fn main() {
    let store: Arc<dyn Store> = Arc::new(MemoryStore::new());
}

El error real:

error[E0038]: the trait `Store` cannot be made into an object
 --> src/main.rs:9:36
  |
9 |     let store: Arc<dyn Store> = Arc::new(MemoryStore::new());
  |                        ^^^^^ `Store` cannot be made into an object
  |
note: for a trait to be "dyn-compatible" it needs to allow building a vtable
note: method `find` has generic type parameters

Por qué está mal: un método genérico genera una versión por cada F; la vtable tendría tamaño infinito. Bien: el puerto no necesita find genérico (filtra en el caso de uso) o se pasa el predicado como &dyn Fn:

fn find(&self, predicate: &dyn Fn(&Link) -> bool) -> Result<Option<Link>, Error>

2. Olvidar Send + Sync en el trait

Mal: pub trait Store { … } y luego Arc<dyn Store> dentro de un handler. Compila la creación, pero el router no compila: error[E0277]: `dyn Store` cannot be shared between threads safely. Por qué: axum exige que el estado sea Send + Sync + 'static. Bien: declararlo en el trait, como hace store.rs, para que el adaptador que no lo cumpla falle al implementarlo y no al montar el servidor.

3. Importar axum dentro del dominio

Mal: src/domain.rs empieza con use axum::http::StatusCode; para mapear errores. Ahora cada test del dominio compila axum, tokio y hyper, el binario sin red arrastra el servidor y el mapeo a HTTP queda enterrado. Bien: el dominio produce Error::InvalidUrl; server.rs lo traduce en impl From<Error> for ApiError.

Objetivo: crear el crate con la estructura de capas y dejar dominio y puerto en verde antes de escribir una línea de CLI o de HTTP.

  2. Escribe el puerto y los dos adaptadores. MemoryStore sobre Mutex<BTreeMap<…>> y JsonStore con temporal + rename. Ambos devuelven Error::Lock si el candado está envenenado, nunca unwrap.
  3. Prueba el contrato una vez, con dos adaptadores. 
    fn contrato(store: &dyn Store) {
    let link = Link::new("abc123", "https://example.com");
    store.insert(link.clone()).unwrap();
    assert!(store.exists("abc123").unwrap());
    assert!(matches!(store.insert(link), Err(Error::Conflict(_))));

    let mut hit = store.get("abc123").unwrap().unwrap();
    hit.register_hit();
    store.update(hit).unwrap();
    assert_eq!(store.get("abc123").unwrap().unwrap().hits(), 1);

    assert!(store.delete("abc123").unwrap());
    assert!(!store.delete("abc123").unwrap());
}

#[test]
fn memory_cumple_el_contrato() { contrato(&MemoryStore::new()); }

#[test]
fn json_cumple_el_contrato() {
    let path = std::env::temp_dir().join(format!("urlshort-{}.json", std::process::id()));
    let _ = std::fs::remove_file(&path);
    contrato(&JsonStore::open(&path).unwrap());
    let _ = std::fs::remove_file(&path);
}
  4. Pasa tests y linter. cargo test y cargo clippy --all-targets -- -D warnings. Salida esperada: test result: ok con las pruebas del dominio y las dos del contrato en verde, sin haber arrancado ningún servidor.

Criterio de éxito

cargo test pasa sin haber escrito ni un argumento de CLI ni una ruta. Eso demuestra que el dominio está aislado. Si has necesitado arrancar un servidor para probar la validación de URL, la flecha de dependencias apunta al revés.

8 · Reto

🎯 Enlaces con caducidad, sin romper el puerto

Producto quiere que un enlace pueda nacer con fecha de caducidad. Pasado ese tiempo, resolverlo debe devolver NotFound y list no debe mostrarlo.

Pista: la hora no debería venir de Utc::now() dentro de la lógica. Si el «reloj» es un parámetro del caso de uso (o del enlace), un test puede simular el futuro. Y ojo con el JSON: un enlace antiguo sin campo de caducidad debe seguir cargando; #[serde(default)] existe para eso.

9 · Resumen

  • urlshort se divide en dominio, caso de uso, puerto y adaptadores; las dependencias solo apuntan hacia dentro.
  • validate_url devuelve el dato limpio y generate_code produce 6 caracteres base62 con salt para colisiones.
  • Error es único: seis variantes que cada adaptador traduce a HTTP, a código de salida o a mensaje.
  • trait Store usa &self y Send + Sync; el Mutex vive dentro de MemoryStore y JsonStore.
  • Service es Clone, guarda Arc<dyn Store> y se comparte entre peticiones sin envolverlo en otro candado.
  • Separar lib.rs de main.rs permite tests de integración, doctests y documentación en docs.rs.

10 · Preguntas frecuentes

¿No es excesiva esta estructura para un proyecto pequeño?

Son ocho ficheros y una prohibición (el dominio no importa axum ni clap). El coste real es de veinte minutos; el beneficio aparece el primer día que quieres probar la generación de códigos sin arrancar un servidor. Lo que sí sería excesivo es añadir repository, factory y un contenedor de inyección: eso no lo pide nada de este proyecto.

¿Por qué Service es Clone y los métodos toman &self?

Porque cada petición de axum recibe una copia del estado: Clone de un Arc y un String son un incremento de contador y una copia corta. Si los métodos pidieran &mut self, necesitarías un Mutex externo alrededor de todo el servicio y serializarías peticiones que solo leen. El candado vive donde está el recurso: en el store.

¿Por qué no uso la crate url?

Porque la validación de URLs es un campo minado (IDN, esquemas, puertos, credenciales) y para urlshort solo necesitamos un subconjunto explícito: http/https, host no vacío y un límite de longitud. Al escribir validate_url aprendes dónde está la frontera y, si mañana necesitas la crate real, el cambio queda dentro de un fichero. En un proyecto serio, usa url.

¿DefaultHasher es estable entre versiones de Rust?

No está garantizado por el contrato del lenguaje. En la práctica es estable, pero no lo necesitas: los códigos ya generados viven en el store y no se recalculan. Si te preocupara la reproducibilidad entre compiladores, implementa un hash propio (FNV-1a son diez líneas) o acepta que el código es un dato persistido, que es lo que hace el diseño actual.
