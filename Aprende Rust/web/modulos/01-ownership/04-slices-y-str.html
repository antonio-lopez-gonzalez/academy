Slices, str y String

Módulo 1 · Ownership y borrowing ⏱ 40 minutos

1 · Introducción

Rust tiene dos tipos de texto y ninguno es «el de verdad»: String es una cadena con dueño, modificable y en el heap; &str es una vista prestada de texto UTF-8 que ya existe en otro sitio. La separación es la misma que entre un Vec<T> y un &[T]: dueño frente a vista.

Los slices son la generalización: una referencia a un trozo contiguo de elementos. &[T] para cualquier T, &str para bytes UTF-8 validados. Sirven para pasar «una parte de» sin copiar, y son la razón por la que la biblioteca estándar pide &str y &[T] en lugar de &String y &Vec<T>.

¿Por qué existe esta lección?

Porque el E0308 «expected &str, found String» es el error más frecuente de las primeras semanas, y porque cortar una cadena por bytes sin mirar UTF-8 produce panics en producción. Entender qué es un puntero gordo, qué mide len() y dónde están las fronteras de carácter resuelve los dos problemas de golpe.

Errores típicos al empezar:

  • Intentar declarar una variable de tipo str (no tiene tamaño conocido).
  • Cortar por índices calculados con chars().count() y provocar un panic de frontera UTF-8, o usar &String en firmas y obligar al llamante a tener un String.
  • Creer que s.len() devuelve caracteres y clonar una cadena para «pasar una parte».

2 · Teoría

str es un tipo sin tamaño

str representa una secuencia de bytes UTF-8 válidos, pero su longitud solo se conoce en ejecución. Por eso es un DST (dynamically sized type): no puedes tenerlo por valor, solo detrás de un puntero.

fn main() {
    // let s: str = "hola";        // no compila: tamaño desconocido
    let s: &str = "hola";         // sí: referencia a un str
    println!("{s}");
}

Una referencia a un DST es un puntero gordo (fat pointer): dos palabras, una dirección y una longitud. Eso permite recorrer un &str sin saber de antemano cuánto mide.

   String (dueño, 24 bytes en stack)             heap (6 bytes)
   ┌───────────────────────────┐
   │ ptr  ─────────────────────┼──────► ┌───┬───┬───┬───┬───┬───┐
   │ len  = 6                  │        │ k │ 7 │ m │ 2 │ q │ d │
   │ cap  = 6                  │        └───┴───┴───┴───┴───┴───┘
   └───────────────────────────┘

   &str (vista, 16 bytes en stack)         puede apuntar a cualquier
   ┌───────────────────────────┐           buffer UTF-8: un String,
   │ ptr  ─────────────────────┼──────►    un literal en el binario,
   │ len  = 6                  │           un trozo de otro &str
   └───────────────────────────┘

De ahí las tres ideas que ordenan lo demás: el String posee y puede crecer; el &str observa y no puede crecer; y un &str puede apuntar dentro de un String, así que no puedes modificar el String mientras la vista exista.

Los cuatro tipos de texto y cuándo usar cada uno

TipoDueñoTamañoCuándo

Un literal como "https://sho.rt" es &'static str: está incrustado en el binario y vive lo que el programa, así que cumple cualquier vida y puede devolverse desde cualquier función.

Slices: la misma idea para cualquier colección

fn main() {
    let numbers = [10, 20, 30, 40, 50];
    let all: &[i32] = &numbers[..];
    let head: &[i32] = &numbers[..2];
    let tail: &[i32] = &numbers[3..];
    let middle: &[i32] = &numbers[1..4];
    let inclusive: &[i32] = &numbers[1..=3];
    println!("{all:?} {head:?} {tail:?} {middle:?} {inclusive:?}");
    println!("suma del medio: {}", middle.iter().sum::<i32>());
}
[10, 20, 30, 40, 50] [10, 20] [40, 50] [20, 30, 40] [20, 30, 40]
suma del medio: 90

Los rangos son mitad abiertos por defecto: 1..4 incluye 1, 2 y 3; 1..=3 incluye también el 3. Un rango fuera de límites no devuelve error: hace panic, porque es un fallo de programación, no una condición esperada.

Deref coercion: &String sirve donde se pide &str

String implementa Deref<Target = str> y Vec<T> implementa Deref<Target = [T]>. El compilador convierte automáticamente &String en &str y &Vec<T> en &[T] cuando el tipo esperado lo pide:

fn count_words(text: &str) -> usize { text.split_whitespace().count() }
fn sum(values: &[i32]) -> i32 { values.iter().sum() }

fn main() {
    let owned = String::from("urlshort acorta urls");
    println!("{}", count_words(&owned));   // &String -> &str
    let vec = vec![1, 2, 3];
    println!("{}", sum(&vec));                // &Vec<i32> -> &[i32]
    println!("{}", sum(&[10, 20]));           // &[i32; 2] -> &[i32]
}

Esta es la razón práctica para escribir &str y &[T] en las firmas: aceptas más sin coste. Si pides &String, quien tenga un literal tendrá que crear un String; si pides &str, todo el mundo pasa lo que tiene.

Cortar por bytes: UTF-8 no perdona

Los índices de un &str son offsets de byte, no posiciones de carácter. En UTF-8 un carácter ocupa entre 1 y 4 bytes: a ocupa 1, ó 2, € 3 y 😀 4. Cortar en medio de un carácter no produce un texto raro: produce un panic, porque Rust no puede devolver un &str que no sea UTF-8 válido.

fn main() {
    let text = String::from("óxido");
    println!("bytes={} chars={}", text.len(), text.chars().count());   // 6 y 5
    let good = &text[..2];          // "ó" completo: 2 bytes
    println!("{good}");
    // let bad = &text[..1];       // panic: byte index 1 is not a char boundary
}

Para cortar con seguridad hay tres herramientas: char_indices() (posiciones válidas), is_char_boundary(i) (comprueba un índice) y los métodos de str que ya piensan en caracteres (split, find, strip_prefix). Volveremos a ellas en el ejemplo real.

char no es un byte

Un char de Rust es un valor escalar Unicode y ocupa 4 bytes en memoria, aunque en la cadena se codifique con 1 a 4. No es lo mismo que u8:

fn main() {
    let text = "café";
    println!("len() = {} / chars() = {}", text.len(), text.chars().count());
    println!("bytes = {:?}", text.as_bytes());
    for c in text.chars() { print!("[{c}]"); }
    println!();
}
len() = 5 / chars() = 4
bytes = [99, 97, 102, 195, 169]
[c][a][f][é]

Consecuencia práctica: nunca uses len() para límites de interfaz de usuario (campos de texto, contadores de caracteres). Usa chars().count() si necesitas el número de caracteres. Y nunca indexes por posición de carácter con s[i]: no compila, porque un String no implementa Index<usize>.

3 · Ejemplo mínimo

Tres slices, tres orígenes distintos, cero copias del contenido:

fn main() {
    // 1. Slice de un literal: el texto vive en el binario
    let url = "https://sho.rt/k7m2qd";
    let code = &url[15..];
    println!("{code}");

    // 2. Slice de un array
    let numbers = [10, 20, 30, 40];
    let half = &numbers[1..3];
    println!("{half:?} suma={}", half.iter().sum::<i32>());

    // 3. Slice de un String, con la frontera comprobada
    let text = String::from("óxido");
    let cut = text.char_indices().nth(1).map(|(i, _)| i).unwrap_or(0);
    println!("{:?} de {text:?}", &text[..cut]);
}
cargo run --quiet
k7m2qd
[20, 30] sum=50
"ó" de "óxido"

Línea a línea: &url[15..] apunta al byte 15 del literal y no copia nada; &numbers[1..3] es un &[i32] de dos elementos que iter() recorre; char_indices().nth(1) da la posición del segundo carácter (índice 0 es el primero), que en "óxido" es el byte 2, frontera válida; y &text[..cut] presta el String, así que mientras first viva, text no se puede modificar.

Cambia let code = &url[15..]; por &url[..15]; y verás la base de la URL sin el código. Cambia nth(1) por nth(0) y obtendrás una cadena vacía: la primera frontera está en el byte 0.

4 · Ejemplo real

El CLI de urlshort recibe una URL y necesita su código. La operación natural es prestar: validar el texto y devolver un trozo de la URL original. Solo se copia cuando el enlace se guarda, porque ahí el dato debe sobrevivir al argumento del usuario.

pub const BASE: &str = "https://sho.rt/";

// Devuelve el código si `url` empieza por la base y es alfanumérico.
// El resultado es un préstamo de `url`: no se copia ni un byte.
pub fn extract_code(url: &str) -> Option<&str> {
    let path = url.strip_prefix(BASE)?;                      // &str dentro de url
    let code = path.split(|c| c == '/' || c == '?').next()?; // corta en / o ?
    if code.is_empty() || !code.bytes().all(|b| b.is_ascii_alphanumeric()) {
        return None;
    }
    Some(code)
}

#[derive(Debug)]
pub struct Link { pub code: String, pub hits: u32 }

// Acepta &[Link] y no &Vec<Link>: vale para vectores, arrays y sub-slices.
pub fn top_hits(links: &[Link], min: u32) -> Vec<&str> {
    links.iter().filter(|l| l.hits >= min).map(|l| l.code.as_str()).collect()
}

fn main() {
    let raw = String::from("https://sho.rt/k7m2qd?ref=news");
    match extract_code(&raw) {
        Some(code) => {
            println!("código: {code} ({} bytes)", code.len());
            let owned: String = code.to_string();   // aquí SÍ se copia: se guarda
            println!("guardado: {owned}");
            let links = vec![Link { code: owned, hits: 5 }];
            println!("con 1+ hits: {:?}", top_hits(&links, 1));
        }
        None => eprintln!("URL no reconocida: {raw}"),
    }
}
cargo run --quiet
código: k7m2qd (6 bytes)
guardado: k7m2qd
con 1+ hits: ["k7m2qd"]

Qué está pasando, pieza a pieza:

PiezaQué devuelveCoste
strip_prefix(BASE)?&str con el resto de la URLO(1): compara y avanza
split(|c| ...)Iterador de trozosO(n) al recorrer, sin reservar
code.to_string()String propioUna reserva de 6 bytes: la única copia
top_hits(&links, 1)Vec<&str> con vistas a los códigosReserva el vector de punteros, no el texto

La firma pub fn extract_code(url: &str) -> Option<&str> no lleva anotación de vida porque la elisión la resuelve: una sola referencia de entrada, así que la salida vive lo que url (lección anterior). Es la firma que quieres en cualquier parser de zero-copy.

Analogía: el billete y la ventana

Un String es un billete que llevas en el bolsillo: puedes gastarlo, romperlo o guardarlo. Un &str es una ventana para mirar ese billete, o cualquier otro que esté en la mesa. Mirar no cuesta nada, pero si alguien se lleva el billete, la ventana deja de mostrar nada. Y cortar la ventana justo por la mitad de un número es lo que Rust no te deja hacer: el corte tiene que caer en una frontera real.

5 · Buenas prácticas

La pregunta que decide el tipo

«¿Este texto tiene que seguir existiendo cuando la función termine?» Si la respuesta es sí, String. Si es no, &str. Y si el texto es un trozo de otro, &str sin dudarlo: devolver un trozo no debería costar una copia.

6 · Errores habituales

1. Cortar en mitad de un carácter

fn main() {
    let text = String::from("óxido");
    let bad = &text[..1];
    println!("{bad}");
}
thread 'main' panicked at src/main.rs:3:15:
byte index 1 is not a char boundary; it is inside 'ó' (bytes 0..2) of `óxido`
note: run with `RUST_BACKTRACE=1` environment variable to display a backtrace

El byte 1 es la mitad de una secuencia UTF-8 de dos bytes; devolver &str ahí sería devolver texto inválido. En un servidor, ese panic puede tumbar la tarea que atiende la petición. Bien: cortar por fronteras reales con char_indices, split_at o get(a..b), que devuelve Option en lugar de hacer panic.

2. Intentar usar str por valor

fn normalize(s: str) -> usize {
    s.len()
}
error[E0277]: the size for values of type `str` cannot be known at compilation time
 --> src/main.rs:1:15
  |

  |                 ^^^ doesn't have a size known at compile-time

  = help: the trait `Sized` is not implemented for `str`

help: consider borrowing here
  |

  |                 +

El compilador necesita saber cuántos bytes reservar en el stack, y un str puede medir cualquier cosa. Es el mismo motivo por el que no existe Vec<str>. Bien: &str (vista) o String (dueño), según quién deba poseer el texto.

3. Pasar un String donde se espera &str

fn normalize(s: &str) -> String { s.to_ascii_lowercase() }

fn main() {
    let code = String::from("ABC123");
    let out = normalize(code);
    println!("{out}");
}
error[E0308]: mismatched types
 --> src/main.rs:5:26
  |
2 | fn normalize(s: &str) -> String {
  |                 ---- expected `&str` due to this parameter type
5 |     let out = normalize(code);
  |                          ^^^^ expected `&str`, found `String`
  |
help: consider borrowing here
  |
5 |     let out = normalize(&code);
  |                          +

&str y String son tipos distintos. La coerción de &String a &str existe, pero se activa con el &; sin él estás ofreciendo el dueño entero. Bien: normalize(&code): prestar nunca te obliga a regalar.

4. Mover un elemento fuera de un slice

fn first(items: &[String]) -> String {
    items[0]
}
error[E0507]: cannot move out of index of `[String]`
 --> src/main.rs:2:5
  |
2 |     items[0]
  |     ^^^^^^^^ move occurs because value has type `String`,
  |              which does not implement the `Copy` trait

Un &[String] es una vista: no posee los elementos, así que no puede regalarlos. Bien: devolver &str (items.first().map(String::as_str).unwrap_or("")) o clonar explícitamente si el llamante necesita uno propio.

7 · Ejercicio guiado

Objetivo: cortar texto sin copiar, provocar y arreglar un panic de frontera UTF-8 y comprobar que una función con &[T] acepta más de lo que parece.

  1. Crea el proyecto. 
    cargo new slices-lab --bin
cd slices-lab
  2. Extrae un trozo con find. Sin índices mágicos: 
    fn main() {
    let url = String::from("https://sho.rt/k7m2qd");
    let (scheme, rest) = match url.find("://") {
        Some(i) => (&url[..i], &url[i + 3..]),

}

    Salida esperada: scheme=https rest=sho.rt/k7m2qd. Comprueba que url sigue siendo dueño y que no has clonado nada.

  3. Rompe UTF-8 a propósito. Prueba &url[..1] con un texto que empiece por "ó" y observa el panic. Después arréglalo con char_indices: 
    fn main() {
    let text = String::from("órbita");
    let end = text.char_indices().nth(1).map(|(i, _)| i).unwrap_or(0);
    println!("{:?} / {} bytes en total", &text[..end], text.len());
}

    Salida esperada: "ó" / 7 bytes en total.

  4. Acepta más tipos con &[T]. 
    fn max_of(values: &[i32]) -> Option<i32> {
    values.iter().copied().max()
}

fn main() {
    let vec = vec![3, 9, 2];
    let array = [7, 1];

    Salida esperada: Some(9), Some(7), Some(9).

  5. Convierte en dueño solo al final. Escribe una función que devuelva un &str recortado de la entrada y otra que devuelva String; llama a las dos con el mismo valor y compara firmas: 
    fn trim_borrowed(url: &str) -> &str { url.trim() }          // O(1), presta

    Decide cuál necesitas según si el resultado sobrevive a la variable original. Después cierra con cargo clippy -- -D warnings: si avisa de un &String en una firma, cámbialo a &str.

Criterio de éxito

Puedes mirar un tipo de texto y decir en un segundo quién es el dueño, cuántos bytes ocupa en el stack y qué pasa si se corta. Y sabes por qué &url[..1] con «ó» no es un texto raro sino un panic.

8 · Reto

🎯 El validador de códigos sin copias

El CLI de urlshort acepta códigos escritos a mano: a veces con espacios, a veces en mayúsculas, a veces con un prefijo sho.rt/ delante, y a veces con basura detrás. Escribe una función fn normalize(raw: &str) -> Option<&str> que devuelva el código canónico como vista del texto original, sin asignar memoria, o None si no es válido.

Reglas: recorta espacios por ambos lados; descarta un prefijo "https://sho.rt/" o "sho.rt/" si está presente; corta en el primer /, ? o #; exige entre 4 y 12 caracteres alfanuméricos ASCII; y no aceptes caracteres no ASCII. Añade una segunda función que reciba &[&str] de candidatos y devuelva solo los válidos, también sin copiarlos.

Pista: trim, strip_prefix, split_once y find devuelven préstamos del original y respetan UTF-8, así que puedes encadenarlos sin miedo. Para el rango de longitud, (4..=12).contains(&code.len()); para la validación, bytes().all(|b| b.is_ascii_alphanumeric()). Y ojo con las mayúsculas: convertir a minúsculas exige un String nuevo; si de verdad necesitas el código canónico en minúsculas, decide si el contrato devuelve &str (y entonces solo valida) o Cow<'_, str> (que copia solo cuando hace falta).

9 · Resumen

  • str es un DST (tamaño dinámico); solo se usa detrás de un puntero: &str.
  • &str es un puntero gordo (dirección + longitud) de 16 bytes; String es un dueño de 24 bytes con ptr/len/cap, y un literal es &'static str incrustado en el binario.
  • &[T] es la misma idea para cualquier colección; acepta arrays, Vec y sub-slices por deref coercion.
  • Los índices son bytes; cortar fuera de una frontera UTF-8 hace panic.
  • len() cuenta bytes, chars().count() cuenta caracteres; un char ocupa 4 bytes en memoria.
  • Las APIs idiomáticas piden &str y &[T]: aceptan más tipos y no obligan a copiar.

Comandos y conceptos de esta lección

10 · Preguntas frecuentes

¿Por qué no hay un solo tipo de cadena, como en Python?

Porque Rust separa propiedad de vista en todo el lenguaje: Vec<T>/&[T], PathBuf/&Path, String/&str. Un solo tipo obligaría a elegir entre copiar siempre (caro) o tener un tipo que a veces posee y a veces no (ambiguo). Con dos tipos, la firma te dice si la función se queda el texto o solo lo mira.

¿&str siempre apunta a un String?

No. Puede apuntar a un literal en el binario, a un trozo de otro &str, a un buffer estático o a una zona de un String. Lo único que garantiza es que los bytes son UTF-8 válidos y que alguien los mantiene vivos mientras la referencia exista.

¿Cómo corto los primeros N caracteres sin arriesgarme a un panic?

Con char_indices().nth(n), que te da un byte de frontera. Si solo necesitas mostrar un extracto, también sirve chars().take(n).collect::<String>(), que copia pero es imposible que falle. Para quitar un prefijo concreto, strip_prefix es O(1) y seguro.

¿len() o chars().count() para validar un campo de formulario?

Depende del límite. Si es de bytes (un buffer, un protocolo, una columna de base de datos), len(). Si es de caracteres visibles, chars().count(), y aun así recuerda que un emoji con modificadores puede ser varios char: para interfaces serias se cuentan graphemes con un crate como unicode-segmentation.

¿Puedo modificar un String a través de un &str?

No: &str es una vista inmutable. Para modificar necesitas &mut String (o &mut str si solo reescribes bytes ASCII existentes, como make_ascii_uppercase). Y mientras exista la vista, el String no puede cambiar de tamaño: si crece, reasigna el buffer y la vista quedaría colgando.
