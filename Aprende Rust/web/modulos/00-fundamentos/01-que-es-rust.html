Qué es Rust y por qué existe

Módulo 0 · Fundamentos ⏱ 30 minutos

1 · Introducción

Rust es un lenguaje compilado, con tipado estático y sin recolector de basura, que garantiza la seguridad de la memoria en tiempo de compilación. Ese es el resumen de una frase. El resto del curso explica por qué esa frase cambia la forma en que escribes programas.

Si vienes de Python, JavaScript o C#, estás acostumbrado a que alguien gestione la memoria por ti: el recolector de basura (GC) decide cuándo se libera algo. Si vienes de C o C++, la gestionas tú a mano, y con ella los errores más caros de la industria. Rust propone una tercera vía: un conjunto de reglas que el compilador verifica y que, si las cumples, hacen imposible liberar dos veces, usar memoria liberada o tener dos escritores a la vez.

¿Por qué existe esta lección?

Porque Rust no se aprende «igual que los demás lenguajes». La primera semana no peleas con la sintaxis: peleas con el préstamo de datos. Entender de dónde viene el lenguaje y qué problema está resolviendo evita que el compilador te parezca un adversario. Aquí no hay magia: hay un modelo que se puede explicar.

Vas a aprender qué es Rust, qué problema resuelve, en qué se diferencia de C++, Go o Java y por qué el compilador a veces dice «no» cuando tu código parece perfectamente razonable.

Errores típicos al empezar:

  • Tratar a Rust como C++ y llenar el código de clone() para callar al compilador.
  • Usar unwrap() en todas partes porque es lo primero que compila.
  • Creer que el borrow checker está roto cuando lo que está roto es el diseño del programa.
  • Escribir clases como en Java y pelear luego con traits y ownership.

2 · Teoría

El problema que nadie quería mirar

Durante treinta años, la seguridad de la memoria se resolvió con dos pactos incómodos:

EstrategiaQuién paga el costeQué falla
Gestión manual (C, C++)El programador: malloc, free, deleteLiberaciones dobles, fugas, referencias colgantes, desbordamientos. Muy rápido y muy frágil.
Recolector de basura (Java, Go, C#, JS)El programa: pausas, memoria extra, un runtimeSeguro, pero el consumo y la latencia son menos predecibles; hay un runtime que arrancar y mantener.
Propiedad en compilación (Rust)El compilador: analiza y rechaza lo inseguroCurva de aprendizaje al principio. A cambio: seguridad sin GC y sin coste en ejecución.

Rust elige la tercera. No hay recolector: el dueño de cada valor libera la memoria cuando deja de existir, y el compilador comprueba que nadie más la está usando. Lo que en C++ es una convención («nadie debería usar este puntero después de delete») en Rust es una regla que no compila si la rompes.

Qué significa «seguro» aquí

Rust distingue dos mundos:

  • Rust seguro (todo el código normal): el compilador garantiza que no hay punteros nulos, ni datos corruptos por carreras de hilos, ni accesos tras liberar.
  • unsafe (bloques explícitos): aquí el programador asume la responsabilidad de las cuatro garantías de memoria. Es un opt-in visible en una búsqueda de texto, no el estado por defecto.

Esto es lo que hace que Rust sea a la vez un lenguaje de sistemas y un lenguaje de servicios: puedes escribir un servidor web con la confianza de Java y el consumo de recursos de C.

Cada flecha cuenta. El compilador no solo traduce: demuestra propiedades sobre tu programa. Cuando termina, el binario no lleva ninguna comprobación extra de propiedad: esas comprobaciones se han «gastado» en compilar. Esa es la promesa de las zero-cost abstractions.

Dónde se usa de verdad

Rust no es un lenguaje de juguete académico. Está en el kernel de Linux (drivers), en Windows, en Android, en infraestructura de red (Cloudflare, Discord), en bases de datos (TiKV, SurrealDB), en herramientas de terminal (ripgrep, fd, bat), en cripto (Solana, Polkadot), en WebAssembly y en servicios de alto rendimiento de AWS, Shopify o Dropbox.

Dónde NO brilla

En prototipos desechables de una tarde, en scripts de 30 líneas o donde el equipo no puede asumir la curva inicial. Rust prioriza corrección y rendimiento predecible; si tu problema es «quiero algo funcionando ya», Python o Go llegarán antes. No es un defecto: es una elección.

Ediciones: el lenguaje evoluciona sin romperte

Rust usa ediciones (2015, 2018, 2021, 2024) para introducir cambios incompatibles sin dividir el ecosistema: un crate de 2018 y otro de 2024 conviven en el mismo binario. La edición se declara en Cargo.toml y este curso usa edition = "2021" por compatibilidad con el ecosistema actual; la 2024 aparece documentada en la lección de Cargo avanzado.

3 · Ejemplo mínimo

El programa más pequeño que se puede compilar. Sin Cargo, sin dependencias, solo el compilador.

// hola.rs — todo programa ejecutable empieza en main()
fn main() {
    // println! es una macro (lo dice la exclamación), no una función
    println!("Hola desde Rust");
}

Compilar y ejecutar:

# Compila y genera un binario nativo llamado hola
rustc hola.rs

# Ejecutarlo: no hay máquina virtual ni intérprete de por medio
./hola        # Linux / macOS / WSL
.\hola.exe    # Windows (PowerShell)

Salida:

Hola desde Rust

Línea a línea:

  • fn main() es el punto de entrada. Obligatorio en un binario; sin él, el enlazador no sabe por dónde empezar.
  • println! con ! es una macro: se expande en tiempo de compilación y admite un número variable de argumentos con formato.
  • El punto y coma cierra la sentencia. Rust es de llaves, no de indentación significativa.
  • rustc produce un ejecutable de tu plataforma. Ese fichero funciona en otra máquina del mismo sistema operativo sin instalar nada más.

Ahora rompamos el contrato de propiedad a propósito para ver cómo responde el compilador:

fn main() {
    let nombre = String::from("urlshort"); // el String es dueño de su memoria
    let otro = nombre;                     // se MUEVE: ahora el dueño es otro
    println!("{nombre}");                  // error: nombre ya no es válido
}
error[E0382]: borrow of moved value: `nombre`
  |
3 |     let nombre = String::from("urlshort");
  |         ------ move occurs because `nombre` has type `String`,
  |                which does not implement the `Copy` trait
4 |     let otro = nombre;
  |                ------ value moved here
5 |     println!("{nombre}");
  |               ^^^^^^^^ value borrowed here after move
  |
  = note: this error originates in the macro `$crate::format_args_nl`

Este error no existe en C++ (compila y puede petar en ejecución), en Java (compila y funciona porque el GC mantiene vivo el objeto) ni en Python. En Rust es un error de compilación con sugerencia de arreglo: el compilador te está ahorrando un use-after-free. Lo estudiaremos a fondo en el módulo de ownership.

4 · Ejemplo real

El hilo conductor del curso es urlshort: una herramienta de terminal que acorta URLs, las guarda y las resuelve, y que al final del curso también sirve por HTTP. Empieza como algo que cabe en una pantalla:

// src/main.rs — primera versión de urlshort
// Lee la URL de los argumentos y muestra un código corto derivado de ella.
use std::collections::hash_map::DefaultHasher;
use std::hash::{Hash, Hasher};

fn main() {
    // args() incluye el nombre del programa en la posición 0
    let args: Vec<String> = std::env::args().collect();

    // Sin argumentos: mensaje de uso y salida con código de error
    if args.len() < 2 {
        eprintln!("uso: urlshort <url>");
        std::process::exit(2);
    }

    let url = &args[1];              // préstamo: no copiamos la URL
    let code = short_code(url);      // calcula un código de 6 caracteres
    println!("{url} -> /{code}");
}

// Deriva un código estable a partir del contenido de la URL
fn short_code(url: &str) -> String {
    let mut hasher = DefaultHasher::new();
    url.hash(&mut hasher);
    let n = hasher.finish();         // u64

    const ALPHABET: &[u8] = b"23456789abcdefghjkmnpqrstuvwxyz";
    let mut code = String::with_capacity(6);
    for i in 0..6 {
        // Desplaza 6 bits por posición y elige un carácter del alfabeto
        let idx = ((n >> (i * 6)) % ALPHABET.len() as u64) as usize;
        code.push(ALPHABET[idx] as char);
    }
    code
}

Ejecución:

cargo run -- "https://www.rust-lang.org/learn"

# Salida
https://www.rust-lang.org/learn -> /k7m2qd

Decisiones que ya están tomadas aquí y que el curso desarrollará:

DecisiónPor qué
&args[1] en vez de args[1].clone()La URL no se copia: se presta. Copiar por comodidad es el vicio número uno de quien viene de otros lenguajes.
eprintln! y exit(2)Los errores van a stderr y el código de salida importa: un script que llama a urlshort debe poder detectar el fallo.
&str como parámetroAcepta tanto literales como String prestados. Es la firma idiomática que verás en todo el ecosistema.
Alfabeto sin 0, 1, l, oLos códigos se leen en voz alta y se copian a mano: se eliminan caracteres ambiguos.
Sin dependencias externasLa biblioteca estándar basta para la primera lección. clap llegará en el módulo 6, cuando el CLI crezca.

Analogía: el préstamo de un libro

Un String es un libro que alguien posee. let otro = nombre no fotocopia el libro: transfiere la propiedad y el anterior deja de poder leerlo. &nombre es prestarlo para que lo lean sin llevárselo; &mut nombre es dejar que alguien escriba en él, pero solo uno a la vez y sin que nadie más lo esté leyendo. Todo el modelo de Rust es ese contrato de biblioteca.

Regla de oro del principiante

Si el compilador se queja de préstamos y no entiendes por qué, no añadas clone(): dibuja quién posee qué y quién lo usa después. El 90 % de los errores de borrow checker desaparecen al reordenar el código, no al copiar datos.

6 · Errores habituales

1. Creer que Rust tiene un GC que «ya lo arreglará»

Mal:

fn main() {
    let datos = cargar();          // datos posee un Vec<String>
    procesar(datos);               // se mueve a procesar
    imprimir(datos);               // error[E0382]: use of moved value
}

Por qué está mal: en Java o C# el objeto seguiría vivo porque el GC ve una referencia. En Rust la propiedad se transfirió: nadie más puede usarlo.

Bien: prestar en lugar de mover, o devolver la propiedad.

fn main() {
    let datos = cargar();
    procesar(&datos);              // prestamos una referencia de solo lectura
    imprimir(&datos);             // sigue siendo el dueño y puede usarlo
}

2. Usar String donde se pide &str

Mal:

fn saludar(nombre: &str) {
    println!("Hola, {nombre}");
}

fn main() {
    let nombre = String::from("Ana");
    saludar(nombre);                // error[E0308]: mismatched types
}

Bien: prestar el String como &str.

saludar(&nombre);                   // deref coercion: &String -> &str

3. Silenciar todo con unwrap()

Mal:

let puerto: u16 = std::env::var("PORT").unwrap().parse().unwrap();

Por qué está mal: si la variable no existe o no es un número, el proceso muere sin decir qué pasó.

Bien: propagar el error con ? y un mensaje útil.

fn leer_puerto() -> Result<u16, String> {
    let raw = std::env::var("PORT").map_err(|_| "falta PORT".to_string())?;
    raw.parse::<u16>().map_err(|_| format!("PORT no es un número: {raw}"))
}

4. Pelear con el compilador en lugar de escucharlo

Cuando un préstamo mutable y otro inmutable chocan, casi siempre el problema es de diseño: estás modificando una colección mientras la recorres. El compilador no es un obstáculo; es un revisor que ha leído tu código entero y conoce todas las ramas.

7 · Ejercicio guiado

Objetivo: compilar, romper y arreglar tres programas para reconocer los errores E0382, E0502 y E0308. Necesitas el toolchain; si aún no lo tienes, instálalo siguiendo la lección Instalación: rustup, cargo y rust-analyzer.

  1. Crea el espacio de trabajo. 
    cargo new ejercicios-01 --bin
cd ejercicios-01

    Cargo genera Cargo.toml, src/main.rs y un .gitignore con target/.

  2. Provoca un error de propiedad. Pega esto en src/main.rs y ejecuta cargo build. 
    fn main() {
    let lista = vec![1, 2, 3];
    let copia = lista;
    println!("{:?}", lista);
}

    Salida esperada: error[E0382]: borrow of moved value: `lista`. Anota en qué línea ocurre el movimiento y en cuál el uso.

  3. Arréglalo sin clonar. Sustituye el movimiento por un préstamo y comprueba que compila: 
    fn main() {
    let lista = vec![1, 2, 3];
    let copia = &lista;              // prestamos, no movemos
    println!("{copia:?} / {lista:?}");
}
  4. Provoca un conflicto de préstamos. 
    fn main() {
    let mut numeros = vec![1, 2, 3];
    let primero = &numeros[0];
    numeros.push(4);               // error[E0502]: cannot borrow as mutable
    println!("{primero}");
}

    Léelo despacio: hay un préstamo inmutable vivo (primero) cuando se pide el mutable (push). El arreglo es acortar la vida del préstamo.

    fn main() {
    let mut numeros = vec![1, 2, 3];
    let primero = numeros[0];      // copia el valor i32, no presta el vector
    numeros.push(4);
    println!("{primero} / {numeros:?}");
}
  5. Provoca un desajuste de tipos. Llama a una función que pide &str con un String sin prestarlo, observa el error[E0308] y arréglalo con &.
  6. Pasa clippy. 
    cargo clippy -- -D warnings

    Debe terminar sin warnings. Si aparece alguno, sigue la explicación que imprime: casi siempre es la versión idiomática de lo que ya has escrito.

Criterio de éxito

Sabes reconocer E0382 (valor movido), E0502 (préstamo mutable con uno inmutable vivo) y E0308 (tipos incompatibles) por el mensaje, sin buscarlos en internet. Ese reflejo te ahorrará cien horas.

8 · Reto

🎯 El informe diario sin copias

Tienes un programa que descarga un CSV de 40 MB, lo parsea en un Vec<Fila>, calcula tres totales, escribe un informe y guarda el CSV en un fichero histórico. La primera versión funciona pero hace tres clone() del vector completo.

Reescribe el flujo para que el vector se cree una sola vez y ningún dato se copie: usa préstamos entre funciones, y decide quién es el dueño del vector al final. Escribe las firmas de las tres funciones antes del cuerpo (es lo que hará el compilador por ti: te obligará a pensarlo).

Pista: la propiedad no tiene por qué volver al main. Si al final nadie usa el vector, la función que lo consuma puede recibirlo por valor. Y cuando varias funciones solo leen, todas pueden pedir &[Fila] a la vez: los préstamos de solo lectura son compatibles entre sí.

9 · Resumen

  • Rust es un lenguaje compilado y de tipado estático que garantiza seguridad de memoria sin recolector de basura.
  • La pieza que lo hace posible es la propiedad: cada valor tiene un único dueño que lo libera al salir de ámbito.
  • unsafe existe, pero es una excepción explícita y auditable, no el estado por defecto.
  • Las comprobaciones de propiedad se pagan al compilar: en ejecución no queda ninguna verificación extra.
  • Rust es excelente en sistemas, infraestructura, CLI, redes y WebAssembly; no es la mejor opción para prototipos desechables.
  • Las ediciones permiten que el lenguaje evolucione sin romper crates antiguos.

10 · Preguntas frecuentes

¿Rust es tan difícil como dicen?

La sintaxis se aprende en días. Lo que cuesta es el modelo de propiedad y préstamos: unas dos o tres semanas de práctica constante para dejar de pelearse con el compilador. Después, la mayoría de la gente reporta que escribe menos bugs y que el código le dura más tiempo sin romperse.

¿Puedo usar Rust para una API web en producción?

Sí. Axum, Actix Web y Rocket son maduros, y hay servicios grandes en producción. En este curso construirás el servidor de urlshort con Axum en el módulo 6 y lo probarás con tests de integración. La advertencia realista: el ecosistema async tiene su propia curva y el tiempo de compilación crece con las dependencias.

¿Y si vengo de C++? ¿Es un reemplazo directo?

Comparte rendimiento y control, pero no es un reemplazo mecánico: no hay herencia de clases, no hay constructores por defecto implícitos y el modelo de propiedad sustituye a los punteros inteligentes manuales. Lo que ganas es que el compilador demuestra lo que en C++ era convención.

¿Por qué println! lleva una exclamación?

Porque es una macro, no una función. Las macros se expanden antes de compilar y pueden aceptar un número variable de argumentos con formato ("{nombre} tiene {n} años"), algo que una función normal no puede hacer con tipos heterogéneos. Cuando veas un ! detrás de un nombre, es una macro.

¿Necesito saber C para aprender Rust?

No, pero ayuda entender qué es el stack, el heap y un puntero. Este curso los explica cuando aparecen: en la lección de ownership verás qué vive en el stack y qué en el heap, y por qué mover un Vec es barato aunque tenga un millón de elementos.
