Variables, tipos y mutabilidad

Módulo 0 · Fundamentos ⏱ 35 minutos

1 · Introducción

En Rust, una variable no es una caja que abres y cierras cuando quieres: es un compromiso. let x = 5; significa «x vale 5 y nadie lo va a cambiar en este ámbito». Si necesitas cambiarlo, lo dices con mut. Esa palabra de más es el precio de que el compilador pueda razonar sobre tu programa sin miedo.

El sistema de tipos es estático y no hace conversiones implícitas peligrosas: un u32 no se convierte en u64 porque sí, ni un entero en f64 porque lo necesites. Cada conversión es visible, y las que pueden perder datos se escriben con as (explícita y sin comprobación) o con try_into (explícita y comprobada). Los ejemplos se ejecutan con cargo, como en la lección anterior.

¿Por qué existe esta lección?

Porque la mitad de los errores de un principiante vienen de dos malentendidos: creer que mut es como el var de JavaScript (no: la mutabilidad es del binding, no del valor) y creer que as es una conversión segura (no: trunca en silencio). Entender ambos ahorra horas de depuración.

Errores típicos al empezar:

  • Poner mut en todo «por si acaso», que es lo mismo que no tener inmutabilidad.
  • Confundir shadowing (let otra vez) con mutación (x = ...).
  • Usar as para convertir anchos de entero sin comprobar el rango.

2 · Teoría

Inmutabilidad por defecto

Rust toma la decisión contraria a casi todos los lenguajes: el estado que cambia es la excepción y debe declararse. No es purismo; tiene tres consecuencias medibles: lectura (al ver let x sabes que x no cambia en todo el ámbito), concurrencia (un dato que nadie escribe se comparte entre hilos sin sincronización) y optimización (el compilador evita recargas).

fn main() {
    let max = 100;      // inmutable: no se puede reasignar
    let mut hits = 0;   // mutable: se puede modificar

    hits += 1;
    // max = 200;       // error[E0384]: cannot assign twice to immutable variable
    println!("{hits} de {max}");
}

mut no es shadowing

Son dos mecanismos distintos que a veces se confunden porque ambos permiten «cambiar» lo que vale un nombre:

let mut xlet x = ... otra vez
Qué ocurreSe modifica el mismo bindingSe crea un binding nuevo que oculta al anterior
TipoNo puede cambiarPuede cambiar
ÁmbitoEl mismoDesde ese let hasta el final del bloque
Uso típicoContadores, acumuladores, buffersTransformar un valor por etapas: String → u32
 
fn main() {
    let entrada = "  42 ";
    let entrada = entrada.trim();                     // shadowing: &str más corto
    let entrada: u32 = entrada.parse().unwrap_or(0);  // shadowing: ahora es u32
    let mut total = entrada;
    total += 8;                                       // mutación del mismo binding
    println!("{total}");                              // 50
}

El shadowing es especialmente útil con parse: conviertes texto en número sin inventar nombres como entrada_str y entrada_num. El binding original no se destruye: deja de ser accesible y se libera al final del bloque. Ojo, no es una asignación: si otro binding prestó el valor anterior, el préstamo sigue vivo.

Constantes y estáticas

const MAX_HITS: u32 = 10_000;                        // siempre con tipo
static ALPHABET: &[u8] = b"23456789abcdefghjkmnpqrstuvwxyz";

fn main() {
    println!("{MAX_HITS} / {}", ALPHABET.len());
}

const se evalúa al compilar y se inlinea en cada uso; static también se evalúa al compilar, pero tiene dirección fija y vive todo el programa. Un const nunca es mutable; un static mut existe pero exige unsafe. Ambos requieren tipo explícito y un valor computable en compilación. La convención de nombres lo dice todo: SCREAMING_SNAKE_CASE para constantes y estáticas, snake_case para variables y funciones, CamelCase para tipos y traits.

Los literales admiten separadores y bases: 1_000_000, 0xFF, 0o755, 0b1010_1010, y sufijos cuando el contexto no basta: 42u8, 3.14f32. Un literal de byte es b'a' (u8) y una cadena de bytes es b"abc" (&[u8; 3]).

Inferencia: cuándo decide el compilador y cuándo decides tú

La inferencia es local a la función y fluye en las dos direcciones: deduce por el uso posterior o por el tipo esperado. Los valores por defecto son i32 para enteros y f64 para flotantes, así que let a = 5; es i32 y let c = 2.0; es f64. Cuando el contexto no basta se anota (let b: u8 = 5;) o se usa el turbofish: "42".parse::<u32>(). Si el compilador no puede deducir un tipo, lo dice: type annotations needed.

Tuplas y arrays: dos formas de agrupar

  ("k7m2qd", 12u32, true)       tupla: tipos distintos, longitud fija
   └── &str    └── u32  └── bool   acceso por posición: .0 .1 .2

  [0u32; 3]                     array: un solo tipo, longitud fija
   └── u32 └── u32 └── u32        acceso por índice: a[0]

  vec![0u32; 3]                 Vec: un solo tipo, longitud dinámica (módulo 2)
fn main() {
    let link = ("k7m2qd", 12u32, true);   // (&str, u32, bool)
    let (code, hits, activo) = link;      // desestructuración
    println!("{code} {hits} {activo}");
    let mut buffer = [0u8; 6];            // [u8; 6], inicializado a cero
    buffer[0] = b'k';
    println!("{:?} · {} elementos", buffer, buffer.len());
}

El array vive en el stack si su tamaño es conocido y no crece: [T; N] es parte del tipo, así que [u8; 6] y [u8; 8] son tipos distintos. Indexar fuera de rango no es undefined behavior: es un panic con un mensaje claro. Los índices son usize, no i32.

Desbordamiento: el comportamiento depende del perfil

Los enteros tienen ancho fijo. Sumar 1 a un u8 que vale 255 no cabe en 8 bits: en dev y test Rust hace panic (attempt to add with overflow), porque los bugs se detectan cuando son baratos; en release el valor se envuelve (255 + 1 = 0), porque el rendimiento manda. Cuando el desbordamiento es parte del algoritmo, se escribe explícito:

fn main() {
    let max: u8 = 255;
    println!("{:?}", max.checked_add(1));    // None: no cabe
    println!("{}", max.saturating_add(1));   // 255: se queda en el máximo
    println!("{}", max.wrapping_add(1));     // 0: da la vuelta
}

Conversiones: as frente a try_into

Forma¿Puede perder datos?FirmaUso

fn main() {
    let grande: u32 = 300;
    println!("{}", grande as u8);            // 44: truncado, silencioso
    println!("{:?}", u8::try_from(grande));  // Err(TryFromIntError(()))
    let texto = "no soy un número";
    println!("{:?}", texto.parse::<u32>());  // Err(ParseIntError { kind: InvalidDigit })
}

300u32 as u8 es 44 y -1i32 as u32 es 4294967295: no hay panic ni error de compilación, el compilador asume que sabes lo que haces. En código que procesa entrada externa, as es una fuente clásica de bugs de seguridad.

Valor o préstamo: una decisión que se ve en la firma

Los escalares son Copy: pasarlos por valor copia el dato, no lo mueve. Por eso let b = a; con enteros no da error, y con String sí. Una firma fn f(hits: &mut u32) presta el valor para que la función lo modifique con *hits = ...; fn f(link: String) transfiere la propiedad y el llamador deja de poder usarlo. El módulo 1 entra de lleno en esta distinción; aquí basta con reconocerla.

3 · Ejemplo mínimo

Un programa que usa las cuatro piezas de la lección: mutabilidad, shadowing, tupla y array.

fn main() {
    const MAX_HITS: u32 = 10_000;        // constante, siempre tipada
    let nombre = "urlshort";             // &str inmutable

    let mut hits = 0u32;                 // contador mutable
    hits += 1;
    hits += 1;

    let digitos = hits.to_string();      // String
    let digitos: usize = digitos.len();  // shadowing: String → usize

    let link = ("k7m2qd", hits, hits < MAX_HITS); // tupla heterogénea
    let code = ['k', '7', 'm', '2'];               // array homogéneo

    println!("{nombre}: {} visitas · dígitos: {digitos}", link.1);
    println!("código: {} · bajo el máximo: {}", code[0], link.2);
}
urlshort: 2 visitas · dígitos: 1
código: k · bajo el máximo: true

Línea a línea:

  • const MAX_HITS: u32 se evalúa al compilar y no ocupa un binding en el stack. Las constantes siempre llevan tipo: no hay inferencia para ellas.
  • let mut hits = 0u32 declara un binding mutable con sufijo de tipo. Sin mut, hits += 1 sería E0384.
  • Los dos let digitos son dos bindings: el segundo oculta al primero y cambia de tipo. No hay error aunque los tipos difieran.
  • link.1 accede al segundo campo de la tupla; code[0] indexa el array. hits < MAX_HITS compara dos u32 y produce un bool.

4 · Ejemplo real

En urlshort, las visitas de un enlace se acumulan y se resumen. El código elige los tipos con intención: u32 para el contador de un enlace, u64 para el total agregado, f64 para la media y u8 para la longitud del código.

const MAX_CODE_LEN: usize = 6;

// El total puede superar los 4 000 millones: suma en u64, no en u32.
fn total_hits(links: &[(String, u32)]) -> u64 {
    let mut total: u64 = 0;
    for (_, hits) in links {
        total += u64::from(*hits);
    }
    total
}

// Recibe un préstamo mutable: modifica el contador del llamador.
fn registrar_visita(hits: &mut u32) {
    *hits = hits.saturating_add(1);
}

fn media(total: u64, enlaces: usize) -> f64 {
    if enlaces == 0 {
        return 0.0;
    }
    total as f64 / enlaces as f64
}

fn main() {
    let mut links = vec![
        (String::from("k7m2qd"), 12u32),
        (String::from("a9x4bc"), 0u32),
        (String::from("zz3f8p"), 301u32),
    ];

    registrar_visita(&mut links[0].1);

    let total = total_hits(&links);
    println!("{} enlaces · {total} visitas · media {:.1}", links.len(), media(total, links.len()));

    // Entrada externa: parsear y convertir sin `as` a ciegas.
    let entrada = "  42 ";
    let hits: u32 = entrada.trim().parse().unwrap_or(0);
    let code_len: u8 = u8::try_from(MAX_CODE_LEN).unwrap_or(0);
    println!("hits parseados: {hits} · longitud máxima: {code_len}");
}
3 enlaces · 314 visitas · media 104.7
hits parseados: 42 · longitud máxima: 6
Decisión de tiposMotivo
Contador por enlace en u324 000 millones de visitas por enlace es un techo razonable; ocupa la mitad que u64.
Total en u64La suma de muchos u32 puede desbordar. Se convierte al sumar con u64::from (sin pérdida).
Media en f64La división entera truncaría. El as f64 es aceptable aquí y se justifica: se documenta como cast.
&mut u32 en registrar_visitaEl llamador conserva la propiedad y ve el cambio; el préstamo deja clara la intención de mutar.
saturating_addUn contador de visitas no debe hacer panic en producción si llega al máximo: se queda ahí.
try_from para usize → u8El tipo garantiza con una comprobación real que el valor cabe, no con una promesa.

La pregunta que evita la mitad de los bugs numéricos

Antes de operar, pregúntate: ¿qué rango puede tener este valor y qué debe pasar si se sale? Si la respuesta es «no se sale», demuéstralo con el tipo; si puede salirse, elige checked, saturating o un tipo más ancho. Si no lo sabes, ese es el bug.

6 · Errores habituales

1. Mezclar anchos de entero sin convertir: E0308

fn acumular(total: u64, hits: i32) -> u64 {
    total + hits
}
error[E0308]: mismatched types
 --> src/main.rs:2:13
  |
1 | fn acumular(total: u64, hits: i32) -> u64 {
  |                     --- expected due to this
2 |     total + hits
  |             ^^^^ expected `u64`, found `i32`

Por qué ocurre: Rust no promociona enteros automáticamente, ni siquiera cuando el valor cabe. La suma exige el mismo tipo a los dos lados. Bien: convierte en la frontera, una sola vez, y elige según el rango:

fn acumular(total: u64, hits: i32) -> u64 {
    total + u64::try_from(hits).unwrap_or(0)
}

Cambiar la firma a hits: u32 y usar u64::from(hits) sería aún mejor: un contador negativo no tiene sentido.

2. Mover un String y seguir usándolo: E0382

fn main() {
    let nombre = String::from("urlshort");
    let alias = nombre;
    println!("{nombre}");
}
error[E0382]: borrow of moved value: `nombre`
 --> src/main.rs:4:15
  |
2 |     let nombre = String::from("urlshort");
  |         ------ move occurs because `nombre` has type `String`,
  |                which does not implement the `Copy` trait
3 |     let alias = nombre;
  |                 ------ value moved here
4 |     println!("{nombre}");
  |               ^^^^^^^^ value borrowed here after move

Por qué ocurre: String posee memoria en el heap y no implementa Copy: asignarlo transfiere la propiedad. Con i32, bool o char esto no pasa, porque copiar el valor es trivial y seguro. Bien: prestar en lugar de mover:

let nombre = String::from("urlshort");
let alias = nombre.as_str();        // &str prestado
println!("{nombre} / {alias}");     // los dos válidos

3. Desbordar y usar as a ciegas

fn main() {
    let mut visits: u8 = 255;
    visits += 1;                    // panic en debug, 0 en release
    println!("{visits} / {}", 300u32 as u8);
}
thread 'main' panicked at src/main.rs:3:5:
attempt to add with overflow
note: run with `RUST_BACKTRACE=1` environment variable to display a backtrace

Por qué es peligroso: el panic solo existe en dev y test. Compilado con --release, el mismo programa imprime 0 / 44 sin avisar: el contador se reinicia y el cast trunca, todo en silencio. Es el bug que aparece meses después, en producción.

Bien: decidir el comportamiento en el código, no en el perfil, y convertir con comprobación:

let mut visits: u8 = 255;
visits = visits.saturating_add(1);              // 255
let byte = u8::try_from(300u32).unwrap_or(255); // 255, no 44

Un literal imposible ni siquiera compila: let x: u8 = 300; produce error: literal out of range for `u8`. El compilador protege los literales, no las variables.

7 · Ejercicio guiado

Objetivo: usar tipos elegidos con criterio, shadowing para parsear, un array como ventana de datos y conversiones comprobadas para no truncar nada.

  1. Crea el proyecto y declara las piezas. 
    cargo new tipos-urlshort --bin
cd tipos-urlshort
    const MAX_CODE_LEN: usize = 6;
const ALPHABET: &[u8] = b"23456789abcdefghjkmnpqrstuvwxyz";

fn main() {
    let mut total: u64 = 0;              // acumulado: puede crecer mucho
    let mut ultimas: [u32; 5] = [0; 5];  // ventana de 5 visitas
    let mut pos = 0usize;                // índice: usize, no i32
    for hits in [12u32, 0, 301, 7, 45, 1_000] {
        total += u64::from(hits);
        let slot = pos % ultimas.len();
        ultimas[slot] = hits;
        pos += 1;
    }

    println!("total: {total}");
    println!("ventana: {ultimas:?}");
    println!("alfabeto: {} caracteres · código de {MAX_CODE_LEN}", ALPHABET.len());
}

    Salida esperada: total: 1365, ventana: [1000, 0, 301, 7, 45] y alfabeto: 32 caracteres · código de 6. Comprueba a mano por qué la ventana queda así: el sexto valor sustituye a la posición 0.

  2. Parsea argumentos con shadowing. Añade al principio de main: 
        let raw = std::env::args().nth(1).unwrap_or_else(|| "100".to_string());
    let raw = raw.trim();
    let limite: u32 = raw.parse().unwrap_or(100);
    println!("límite: {limite}");

    Ejecuta cargo run -- 250 y cargo run -- no-es-un-numero. El segundo debe imprimir límite: 100: el valor por defecto es explícito.

  3. Convierte sin truncar. Añade: 
        let largo: u32 = 300;
    match u8::try_from(largo) {
        Ok(v) => println!("cabe: {v}"),
        Err(e) => println!("no cabe: {e}"),
    }
    println!("con as sería: {}", largo as u8);

    Salida esperada: no cabe: out of range integral type conversion attempted y con as sería: 44. Esa línea es la prueba de por qué as no se usa sobre datos externos.

  4. Cierra con la tríada de calidad. 
    cargo fmt
cargo clippy --all-targets -- -D warnings
cargo test

    Sin tests, el arnés dirá running 0 tests y terminará con éxito. Lo importante es que clippy no objete nada a tus tipos. Criterio de éxito: puedes justificar cada tipo (por qué u64 en el total, usize en el índice, try_from en lugar de as); si un tipo no tiene justificación, cámbialo.

8 · Reto

🎯 El informe de visitas a prueba de balas

Escribe un programa que reciba una lista de contadores de visitas (por ejemplo [0, 3, 12, 999, 4_294_967_295, 7]) y produzca un informe con total agregado, media, máximo, mínimo, porcentaje de enlaces sin visitas y una barra de texto proporcional al máximo.

  • Ninguna operación puede desbordar, ni en debug ni en release, con ningún valor de entrada que quepa en el tipo elegido.
  • El único as permitido es el de los porcentajes y la barra; cada uno debe llevar un comentario que explique por qué no pierde información relevante.
  • La longitud de la barra se calcula con usize y debe funcionar con listas vacías sin dividir entre cero.
  • Los valores llegan como texto: hay que parsearlos con parse y decidir qué hacer con los que no son números, sin unwrap en el camino de la entrada.

Pista: el máximo de la lista sirve de denominador y siempre es mayor que cero si la lista no está vacía; el total, en cambio, puede superar el rango del tipo de entrada y necesita un tipo más ancho. Para la barra, calcula primero cuántos caracteres corresponden al máximo y escala el resto; multiplica antes de dividir, pero elige un tipo que no desborde al multiplicar.

9 · Resumen

  • Los bindings son inmutables por defecto; mut declara la intención de cambiarlos.
  • El shadowing crea un binding nuevo (puede cambiar de tipo); mut modifica el mismo.
  • const se inlinea y siempre lleva tipo; static tiene dirección fija y static mut exige unsafe.
  • Enteros con y sin signo de 8 a 128 bits; isize/usize siguen la arquitectura y son los índices canónicos.
  • La inferencia usa i32 y f64 por defecto; en fronteras de API, anota el tipo.
  • Tuplas: tipos distintos, longitud fija. Arrays: un tipo, longitud fija en el propio tipo. Vec llega en el módulo 2.
  • El desbordamiento hace panic en debug y envuelve en release: si importa, usa checked_* o saturating_*.
  • as trunca en silencio; try_into y parse devuelven Result y obligan a decidir.
  • Los escalares son Copy: pasarlos por valor copia; String se mueve (E0382).

10 · Preguntas frecuentes

¿Por qué inmutable por defecto y no al revés?

Porque el estado que cambia es la fuente de la mayoría de los bugs difíciles: carreras, valores que alguien modificó por detrás, invariantes rotos. Al hacer explícito cada cambio, el compilador puede asumir que lo inmutable lo es de verdad, y el lector no tiene que reconstruir la historia de una variable. En la práctica no escribes más mut del que necesitas: suele ser una minoría de los bindings.

¿Shadowing es lo mismo que reasignar?

No. Reasignar (x = 6) exige mut y mantiene el mismo tipo y el mismo binding. El shadowing (let x = 6;) declara un binding nuevo, puede cambiar el tipo y el anterior deja de ser accesible pero sigue vivo hasta el final del bloque. Es ideal para transformaciones por etapas, sobre todo tras un parse o un trim.

¿i32, i64 o isize? ¿Cuál uso por defecto?

i32 es el valor por defecto razonable para números generales: rápido, cabe bien en caché y es lo que espera la mayoría de las APIs. Usa u32/u64 para cantidades que no pueden ser negativas (visitas, tamaños, identificadores). Usa usize para índices y longitudes porque es lo que exige el indexing. Y usa i64/u64 si el dominio lo pide: timestamps, dinero en céntimos, acumulados.

¿Por qué let x: u8 = 300; no compila?

Porque el literal se comprueba contra el rango del tipo en tiempo de compilación: 300 no cabe en u8 (0 a 255) y el lint overflowing_literals, activo por defecto, lo convierte en error. Es una protección que no existe para variables: let v = 300u32; let x = v as u8; sí compila y trunca. Los literales son analizables; los valores en ejecución no siempre.
