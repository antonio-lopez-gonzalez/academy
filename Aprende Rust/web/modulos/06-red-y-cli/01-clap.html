CLI con clap: subcomandos y validación

Módulo 6 · Red y CLI real ⏱ 40 minutos

1 · Introducción

En el módulo 0, urlshort leía la URL de args[1]. Funcionaba porque había un solo argumento. Ahora tiene que acortar, resolver, listar, borrar y configurarse: cinco órdenes con sus opciones, sus valores por defecto y sus errores. Parsear eso a mano es escribir un parser mediocre, sin tests y sin ayuda.

clap es el crate de facto para interfaces de línea de comandos en Rust. Describes la interfaz con tipos —un struct para el programa, un enum para los subcomandos— y el crate lee argv, convierte cada valor a su tipo, genera --help y --version, sugiere correcciones y sale con el código correcto.

¿Por qué existe esta lección?

Porque un CLI no se juzga por su happy path, sino por lo que hace cuando el usuario escribe mal. clap convierte «¿y si falta el argumento?» en algo que el runtime resuelve por ti. A cambio, te obliga a diseñar la interfaz antes que la lógica.

Errores típicos al empezar: recorrer args() con índices; validar a mano lo que value_parser ya valida; usar String para todo y convertir con parse().unwrap(); definir -c dos veces y descubrirlo con un panic al arrancar; llamar a Cli::parse() en un test y matar al runner.

2 · Teoría

Qué hace un parser de argumentos

El shell entrega una lista de cadenas: el nombre del programa y todo lo demás, ya separado por espacios. Nada más. No hay tipos, ni nombres de opción, ni ayuda. Todo eso lo construye el programa:

  argv: ["urlshort", "short", "https://x.dev", "--code", "demo"]

  ┌──────────────┐   ┌──────────────────┐   ┌────────────────────┐
  │ tokenizar    │──►│ asignar a campos │──►│ convertir tipos    │
  │ (clap)       │   │ (derive)         │   │ (value_parser)     │
  └──────────────┘   └──────────────────┘   └────────────────────┘
        │                     │                        │
        ▼                     ▼                        ▼
   ¿es una opción?      Cli { data, output,      u32, usize, PathBuf
   ¿es un valor?        command: Cmd::Short {…} } en vez de String
        │
        └──► error de uso ──► stderr + código de salida 2

Un parser decente reconoce la gramática (--code valor, --code=valor, -c valor), valida antes de ejecutar, explica cómo se usa y falla con un código distinto al de un error de negocio. clap hace las cuatro; tu trabajo es declarar la gramática.

Derive o builder, y las piezas del derive

clap tiene dos APIs para lo mismo: derive, que describe la interfaz con un struct y un enum, y builder, que la construye con Command::new(…).arg(…) en tiempo de ejecución. El curso usa derive: la interfaz queda como un tipo del dominio y se puede testear. Los dos producen el mismo Command; puedes derivar y retocar después con Cli::command().

DeriveQué representaDónde se pone
ParserEl programa. Aporta parse() y try_parse_from().Un único struct Cli.
SubcommandUna orden: short, resolve…Un enum; sus variantes y campos son subcomandos y argumentos.
ArgsBloque de opciones reutilizable.Un struct incrustado con #[command(flatten)].
ValueEnumConjunto cerrado de valores.Un enum; genera [possible values: …].

La regla mental: el tipo describe la interfaz. Opcional es Option<T>; repetible es Vec<T>; tres valores posibles son un ValueEnum; un número es u32, no String. Y la obligatoriedad se deduce: String es obligatorio, Option<String> no.

Dónde va cada validación

  • Al parsear (value_parser): la cadena no es un número, el código tiene caracteres prohibidos. clap imprime invalid value … for '--code <CODE>': <tu mensaje> y sale con 2. Es el sitio de las reglas locales del argumento.
  • Al ejecutar: la URL no responde, el código ya existe. No es un error de uso sino de negocio: stderr y salida 1.

value_parser acepta fn(&str) -> Result<T, E> con E: Into<Box<dyn Error + Send + Sync>>. Devolver Result<String, String> basta: ese texto es el que ve el usuario. Para reglas entre argumentos (por ejemplo, «o URL o stdin») está ArgGroup: un struct con #[derive(Args)], #[group(required = true, multiple = false)] y los campos que compiten entre sí, incrustado con #[command(flatten)].

#[derive(Args)]
#[group(required = true, multiple = false)]
pub struct Input {
    #[arg(value_name = "URL")]
    pub url: Option<String>,
    /// Lee las URLs de stdin, una por línea
    #[arg(long)]
    pub from_stdin: bool,
}

Ayuda, versión, códigos de salida y subcomandos

#[command(version)] toma la versión de Cargo.toml y añade -V/--version. Los comentarios /// rellenan la descripción del programa, de cada subcomando y de cada argumento: documentación y ayuda son lo mismo.

CódigoCuándoQuién lo decide
0Éxito, --help o --versionclap o tu main
1Error de ejecución: no se pudo guardar, el destino no respondeTu aplicación
2Error de uso: falta un argumento, valor inválido, opción desconocidaclap

La distinción no es cosmética: un script en CI necesita saber si falló por los datos (1) o porque está mal invocado (2). Los subcomandos pueden anidarse con otro #[command(subcommand)] dentro de una variante (urlshort config path), y las opciones global = true se aceptan antes o después de la orden.

Cli::parse() lee el argv real y, si algo falla, llama a process::exit: en un test eso mata al runner. La variante testeable es try_parse_from(iterable), que devuelve Result<Cli, clap::Error>.

let cli = Cli::try_parse_from(["urlshort", "short", "https://x.dev"])?;
let err = Cli::try_parse_from(["urlshort", "short", "--code", "a!"]).unwrap_err();
assert_eq!(err.kind(), clap::error::ErrorKind::ValueValidation);

3 · Ejemplo mínimo

El CLI más pequeño con un subcomando. Cargo.toml y src/main.rs:

[package]
name = "urlshort"
version = "0.1.0"
edition = "2021"

[dependencies]
clap = { version = "4.6", features = ["derive"] }
use clap::{Parser, Subcommand};

/// Acorta URLs desde la terminal.
#[derive(Parser, Debug)]
#[command(name = "urlshort", version, about, long_about = None)]
struct Cli {
    /// Subcomando que se va a ejecutar.
    #[command(subcommand)]
    command: Cmd,
}

#[derive(Subcommand, Debug)]
enum Cmd {
    /// Acorta una URL y muestra el código generado.
    Short {
        /// URL que se quiere acortar.
        #[arg(value_name = "URL")]
        url: String,
    },
}

fn main() {
    let cli = Cli::parse();

    match cli.command {
        Cmd::Short { url } => println!("{url} -> /a1b2c3"),
    }
}

La ayuda sale del propio tipo, sin escribir una línea de texto extra:

$ urlshort --help
Acorta URLs desde la terminal

Usage: urlshort <COMMAND>

Commands:
  short  Acorta una URL y muestra el código generado
  help   Print this message or the help of the given subcommand(s)

Options:
  -h, --help     Print help
  -V, --version  Print version

$ urlshort short --help
Usage: urlshort short <URL>

Arguments:
  <URL>  URL que se quiere acortar

Línea a línea:

  • #[derive(Parser)] genera Cli::parse(). El nombre del binario sale de #[command(name = …)] o de Cargo.toml.
  • version sin valor usa CARGO_PKG_VERSION: no escribes la versión dos veces.
  • /// sobre el struct es el about del programa; sobre una variante, el del subcomando; sobre un campo, el del argumento.
  • #[command(subcommand)] marca el campo con la orden. Si no es Option, el subcomando es obligatorio.
  • value_name = "URL" cambia cómo se llama el argumento en la ayuda y en los errores.
  • El match es exhaustivo y normal: el parseo ya terminó y el tipo dice qué datos hay.

El nombre Cmd, no Command

clap también exporta un tipo Command (el builder interno). Llamar Command a tu enum funciona hasta que necesites clap::Command y tengas un choque de nombres. Cmd lo evita.

4 · Ejemplo real

El CLI de urlshort con lo necesario para crecer: opciones globales, un grupo, validación al parsear, un subcomando anidado y un App testeable. Todo en src/lib.rs:

use std::path::PathBuf;

use clap::{Args, Parser, Subcommand, ValueEnum};

#[derive(Debug, Parser)]
#[command(name = "urlshort", version, about = "Acorta, resuelve y lista URLs",
          subcommand_required = true, arg_required_else_help = true)]
pub struct Cli {
    /// Fichero de datos
    #[arg(short, long, global = true, value_name = "PATH")]
    pub data: Option<PathBuf>,

    /// Repite para más detalle: -v, -vv
    #[arg(short, long, action = clap::ArgAction::Count, global = true)]
    pub verbose: u8,

    #[command(flatten)]
    pub output: OutputOpts,

    #[command(subcommand)]
    pub command: Cmd,
}

#[derive(Debug, Clone, Args)]
pub struct OutputOpts {
    /// Formato de salida
    #[arg(long, value_enum, default_value = "text", global = true)]
    pub format: OutputFormat,
}

#[derive(Debug, Clone, Copy, ValueEnum)]
pub enum OutputFormat {
    Text,
    Json,
}

/// De dónde sale la URL: argumento posicional o stdin, pero no las dos.
#[derive(Debug, Args)]
#[group(required = true, multiple = false)]
pub struct Input {
    #[arg(value_name = "URL")]
    pub url: Option<String>,

    /// Lee las URLs de stdin, una por línea
    #[arg(long)]
    pub from_stdin: bool,
}

#[derive(Debug, Subcommand)]
pub enum Cmd {
    /// Acorta una URL
    Short {
        #[command(flatten)]
        input: Input,

        /// Código personalizado (3-16 caracteres)
        #[arg(short, long, value_name = "CODE", value_parser = parse_code)]
        code: Option<String>,

        /// Caduca en N días (0 = nunca)
        #[arg(short = 'e', long, value_name = "DAYS", default_value_t = 0)]
        expires_in: u32,
    },

    /// Resuelve un código e imprime su URL
    Resolve {
        #[arg(value_name = "CODE")]
        code: String,
    },

    /// Lista los enlaces guardados
    List {
        #[arg(short, long, default_value_t = 20, value_name = "N")]
        limit: usize,
    },

    /// Borra un enlace
    Delete {
        #[arg(value_name = "CODE")]
        code: String,
    },

    /// Inspecciona la configuración efectiva
    Config {
        #[command(subcommand)]
        action: ConfigCmd,
    },
}

#[derive(Debug, Subcommand)]
pub enum ConfigCmd {
    /// Imprime la ruta del fichero de datos
    Path,
    /// Imprime la configuración resuelta
    Show,
}

// Se ejecuta DURANTE el parseo: si devuelve Err, clap imprime y sale con 2.
fn parse_code(raw: &str) -> Result<String, String> {
    let valido = (3..=16).contains(&raw.len())
        && raw
            .chars()
            .all(|c| c.is_ascii_alphanumeric() || c == '-' || c == '_');

    if valido {
        Ok(raw.to_string())
    } else {
        Err("el código debe tener entre 3 y 16 caracteres: letras, dígitos, '-' o '_'".into())
    }
}

pub struct App {
    cli: Cli,
}

impl App {
    pub fn new(cli: Cli) -> Self {
        Self { cli }
    }

    pub fn run(self) -> Result<(), Box<dyn std::error::Error>> {
        match self.cli.command {
            Cmd::Short { input, code, .. } => match input.url {
                Some(url) => {
                    println!("{} <- {url}", code.unwrap_or_else(|| "a1b2c3".to_string()));
                }
                None => eprintln!("leyendo URLs de stdin…"),
            },
            Cmd::Resolve { code } => println!("{code} -> https://www.rust-lang.org/"),
            Cmd::List { limit } => println!("{limit} enlaces"),
            Cmd::Delete { code } => println!("borrado {code}"),
            Cmd::Config { action } => println!("config: {action:?}"),
        }
        Ok(())
    }
}

El binario solo arranca y traduce errores a códigos de salida:

// src/main.rs
use std::process::ExitCode;

use clap::Parser;
use urlshort::{App, Cli};

fn main() -> ExitCode {
    // --help y --version salen con 0; un uso incorrecto, con 2.
    let cli = Cli::parse();

    match App::new(cli).run() {
        Ok(()) => ExitCode::SUCCESS,
        Err(err) => {
            eprintln!("error: {err}");
            ExitCode::FAILURE
        }
    }
}

DecisiónPor qué
Input con #[group]La URL viene como argumento o por stdin; el tipo solo no lo expresa y el grupo exige exactamente una fuente.
--code con value_parserEl formato del código es una regla local: si es inválido, no se ejecuta nada.
default_value_t = 0 en u32El defecto se escribe con el tipo del campo y se documenta en la ayuda.
global = true--data, --format y --verbose son del programa, no de un subcomando.
App::new(cli) en lib.rsmain no tiene lógica: los tests construyen un Cli y ejecutan sin tocar el proceso.

Analogía: la gramática frente a la lectura a ojo

Parsear args() a mano es buscar palabras sueltas en la frase que tenías en la cabeza: falla con cualquier variante. Declarar el CLI con tipos es escribir la gramática: el parser acepta todas las formas válidas, rechaza el resto con el motivo y de paso genera el manual.

6 · Errores habituales

1. Parsear args() a mano

Mal:

fn main() {
    let args: Vec<String> = std::env::args().collect();
    let url = &args[1];              // pánico si no hay argumento
    let code = &args[2];             // pánico si falta --code
    println!("{url} -> {code}");
}

Por qué está mal: asume posiciones fijas. urlshort short --code demo https://x.dev hace algo absurdo, no hay --help ni validación, y el índice 2 no existe si el usuario omite la opción. Bien: declarar los argumentos y dejar que clap los asigne por nombre.

2. Convertir con parse().unwrap() dentro del handler

Mal:

#[derive(Parser)]
struct Cli {
    #[arg(long)]
    limit: String,                  // el tipo miente: es un número
}

fn main() {
    let cli = Cli::parse();
    let limit: usize = cli.limit.parse().unwrap(); // pánico con "abc"
    println!("{limit}");
}
thread 'main' panicked at src/main.rs:9:41:
called `Result::unwrap()` on an `Err` value: ParseIntError { kind: InvalidDigit }

Por qué está mal: el usuario ve un panic y un código 101, no un error de uso. Bien: declarar #[arg(long, default_value_t = 20)] limit: usize y dejar que clap convierta; el error pasa a ser invalid value 'abc' for '--limit <LIMIT>': invalid digit found in string, con salida 2.

3. Dos opciones con el mismo nombre corto

Mal: #[arg(short, long)] code: Option<String> y #[arg(short, long)] count: Option<usize> en el mismo struct.

thread 'main' panicked at ...:
Command urlshort: Short option names must be unique for each argument,
but '-c' is in use by both 'code' and 'count'

Por qué está mal: clap detecta la ambigüedad al construir el comando y aborta. Es mejor que aceptar dos significados para -c, pero el fallo aparece en ejecución. Bien: elegir otro corto (-n) o dejar solo --count.

4. Llamar a Cli::parse() en un test

Mal:

#[test]
fn parsea_short() {
    let cli = Cli::parse(); // lee el argv del test runner y puede llamar a exit(2)
    assert!(matches!(cli.command, Cmd::Short { .. }));
}
error: unexpected argument '--nocapture' found
test tests::parsea_short ... FAILED

Por qué está mal: parse() usa los argumentos de cargo test y, ante un error, termina el proceso. Bien: Cli::try_parse_from(["urlshort", "short", "https://x.dev"]), que devuelve Result y no sale.

5. Validar el grupo en el handler

Mal: aceptar short sin URL y sin --from-stdin, y descubrirlo con un if que imprime «falta la URL» y sale con 1. El usuario recibe un error de negocio por un problema de uso, y --help nunca menciona la regla.

Bien: declarar el grupo con #[group(required = true, multiple = false)] en un struct con Args. La ayuda muestra la alternativa y el código es 2.

7 · Ejercicio guiado

Objetivo: construir el CLI con subcomandos, validación y tests del parseo, y comprobar los códigos de salida.

  1. Crea el crate con librería y binario. 
    cargo new urlshort --lib
cd urlshort
cargo add clap --features derive

    Añade src/main.rs a mano. Cargo compila la librería para los tests y el binario para el usuario.

  2. Pega el Cli del ejemplo real en src/lib.rs —sin App— y compila. Si aparece error[E0433]: failed to resolve: use of undeclared crate or module …, revisa el use clap::{…}: faltan Args, Parser, Subcommand o ValueEnum según lo que uses.
  3. Comprueba la ayuda y la versión. cargo run -- --help, cargo run -- short --help y cargo run -- --version. Verifica que --data y --format salen también en la ayuda del subcomando (son globales) y que la versión coincide con Cargo.toml.
  4. Comprueba los códigos de salida. 
    cargo run -- short https://x.dev --code a!

cargo run -- --help
echo $?        # 0: la ayuda no es un error

    En PowerShell, $LASTEXITCODE en lugar de $?.

  5. Escribe los tests del parseo. 
    #[cfg(test)]
mod tests {
    use super::*;
    use clap::error::ErrorKind;

    #[test]
    fn short_acepta_url_y_codigo() {
        let cli = Cli::try_parse_from([
            "urlshort", "short", "https://www.rust-lang.org/", "--code", "rust",
        ])
        .expect("el parseo debería funcionar");

        match cli.command {
            Cmd::Short { input, code, expires_in, .. } => {
                assert_eq!(input.url.as_deref(), Some("https://www.rust-lang.org/"));
                assert_eq!(code.as_deref(), Some("rust"));
                assert_eq!(expires_in, 0);
            }
            other => panic!("se esperaba short, llegó {other:?}"),
        }
    }

    #[test]
    fn rechaza_codigos_invalidos() {
        let err = Cli::try_parse_from(["urlshort", "short", "https://x.dev", "--code", "a!"])
            .expect_err("'a!' no es un código válido");
        assert_eq!(err.kind(), ErrorKind::ValueValidation);
    }

    #[test]
    fn exige_url_o_stdin() {
        let err = Cli::try_parse_from(["urlshort", "short"]).expect_err("falta la entrada");
        assert_eq!(err.kind(), ErrorKind::MissingRequiredArgument);
    }
}

    Los tres deben pasar. Añade un cuarto que compruebe que ["urlshort", "--help"] devuelve ErrorKind::DisplayHelp: clap representa la ayuda como un Err para que el handler no se ejecute.

  6. Rompe la interfaz a propósito. Cambia url: Option<String> por url: String dentro de Input y ejecuta los tests: el grupo deja de tener sentido y exige_url_o_stdin falla. Vuelve atrás. El tipo y la regla deben contar la misma historia.

    cargo fmt

    clippy avisa si el match repite ramas o si un unwrap_or_else puede ser unwrap_or_default.

Criterio de éxito

Añades un subcomando tocando un solo enum, la ayuda se actualiza sola, los argumentos inválidos no llegan a tu código y un test comprueba el parseo sin lanzar el binario.

8 · Reto

🎯 Precedencia de configuración y autocompletado

urlshort debe resolver su configuración desde tres fuentes: ~/.urlshort/config.toml, variables de entorno (URLSHORT_DATA, URLSHORT_FORMAT) y argumentos de línea de comandos. La regla es la habitual: CLI > entorno > fichero > valor por defecto.

Implementa la resolución sin que clap y el fichero se pisen: los argumentos deben seguir siendo Option<T> para distinguir «no lo ha dicho el usuario» de «ha aceptado el defecto». Añade un config show que imprima la configuración resuelta y de dónde viene cada valor; después genera el autocompletado de bash y zsh con clap_complete.

Pista: ValueSource en ArgMatches te dice si un valor vino del CLI, del entorno o del defecto. Y Cli::command() te da el Command para pasárselo a clap_complete::generate sin duplicar la definición.

9 · Resumen

  • clap convierte la interfaz en tipos: un struct con Parser y un enum con Subcommand.
  • derive es el estilo recomendado; el builder queda para interfaces dinámicas.
  • El tipo decide obligatoriedad (String vs Option<String>) y conversión (u32, PathBuf, ValueEnum).
  • value_parser valida al parsear; las reglas de negocio se validan al ejecutar, con otro código de salida.
  • #[group] / ArgGroup expresa «exactamente uno»; #[command(flatten)] reutiliza bloques de argumentos.
  • --help y --version salen con 0; los errores de uso, con 2; los fallos de ejecución, con 1.
  • Separa lib.rs (Cli + App) de main.rs y prueba con try_parse_from.

10 · Preguntas frecuentes

¿derive o builder? ¿Puedo cambiar después?

Empieza con derive: la interfaz queda en un tipo, se documenta con /// y se testea. Si luego necesitas opciones dinámicas, obtén el Command con Cli::command() y retócalo antes de get_matches(). Los dos caminos convergen en el mismo Command.

¿Cómo defino un argumento que puede repetirse?

Con Vec<T>: #[arg(short, long)] tag: Vec<String> acumula cada aparición. Añade value_delimiter = ',' si quieres separarlas por comas, o usa ArgAction::Count con un u8 para contar -vvv.

¿Por qué un error de uso sale con código 2 y no con 1?

Convención de Unix: 1 es «se ejecutó y falló», 2 es «no se pudo ni empezar porque la invocación es incorrecta». clap usa 2 para que un script distinga un fallo de datos de uno de sintaxis. Tu main devuelve ExitCode::FAILURE para los errores de negocio.

¿Puedo usar el mismo Cli desde los tests de integración?

Sí, y es la razón de tenerlo en lib.rs. Los tests de tests/ importan el crate como dependencia externa y llaman a Cli::try_parse_from o a App::new(…).run(). Solo main.rs conoce argv y ExitCode; el resto trabaja con el Cli ya validado.
