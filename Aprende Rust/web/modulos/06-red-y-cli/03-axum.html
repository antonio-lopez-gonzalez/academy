Servidor HTTP con Axum

Módulo 6 · Red y CLI real ⏱ 45 minutos

1 · Introducción

El CLI ya acorta URLs, pero un acortador vive de que alguien pinte el enlace en un navegador. Eso exige un servidor: recibir GET /rust, buscar el código y devolver un 302 con la URL original. Y exige una API: crear enlaces con POST /links, consultarlos, listarlos y borrarlos.

Axum es el framework HTTP del ecosistema Tokio. No inventa un modelo nuevo: compone hyper (protocolo), tower (middleware) y tokio (runtime), y añade lo justo para que escribir un handler sea escribir una función async con parámetros tipados. El router empareja rutas, los extractores convierten la petición en argumentos y el valor devuelto se convierte en respuesta.

¿Por qué existe esta lección?

Porque un servidor no es «una función que devuelve JSON». Es estado compartido entre tareas, errores que deben llegar al cliente con el código correcto, rutas que no pueden entrar en pánico y un handler que se pueda probar sin abrir un puerto. Axum obliga a pensar en esas cuatro cosas; aquí verás el patrón completo.

Errores típicos: usar la sintaxis de rutas de 0.7 (/links/:code) en Axum 0.8; guardar el estado en un Mutex global en vez de pasarlo con State; devolver 200 con un error dentro; poner el extractor del cuerpo antes que los demás; olvidar .with_state(); bloquear el runtime dentro de un handler.

2 · Teoría

La arquitectura de una petición

Axum es una cadena de transformaciones. Cada eslabón es un tipo que implementa un trait de tower, lo que permite componer middleware sin tocar los handlers:

  TCP ──► hyper ──► tower ──────────► Router (matchit) ──► handler
                     (Trace, CORS,       │                    │
                      timeout…)           │ /links/{code}      │
                                          ▼                    ▼
                                     extractores        async fn(State, Path, Json)
                                     State / Path /            │
                                     Query / Json              ▼
                                                        IntoResponse
                                                        (status, headers, body)
PiezaResponsabilidad
RouterEmpareja método + ruta y decide qué handler se ejecuta. En 0.8 los parámetros se escriben con llaves: /links/{code}.
ExtractorConvierte partes de la petición en argumentos: State<T>, Path<T>, Query<T>, Json<T>, HeaderMap…
HandlerUna async fn cuyos argumentos implementan FromRequestParts (o FromRequest para el cuerpo) y cuyo retorno implementa IntoResponse.
IntoResponseTraduce el valor devuelto a una respuesta HTTP: &str, Json<T>, (StatusCode, T), Result<T, E>…
LayerMiddleware de tower: trazas, CORS, compresión, timeouts. Se aplica con .layer().

Estado: Arc y clon barato

Un handler es una función pura: no hay self ni variables globales. Todo lo que necesita se pasa con State<T>, y T debe ser Clone + Send + Sync + 'static porque Axum lo clona por petición. Por eso el estado se envuelve en Arc: clonar el Arc copia un puntero, no el mapa.

#[derive(Clone)]
pub struct AppState {
    links: Arc<RwLock<HashMap<String, Link>>>,
}

El RwLock es de tokio, no de std: el guard se puede mantener a través de un .await sin romper Send. Las lecturas concurrentes son compatibles; la escritura es exclusiva.

Analogía: la pizarra de la oficina

AppState es la pizarra común. Cada petición recibe una llave (Arc) a la misma pizarra, no una copia. RwLock es la norma de uso: varios pueden leer a la vez, pero para escribir hay que quedarse solo. Copiar la pizarra entera en cada petición sería copiar la base de datos.

Extractores: el orden importa

Los extractores que solo leen partes de la petición (State, Path, Query, cabeceras) implementan FromRequestParts y pueden ir en cualquier orden. El que consume el cuerpo (Json, String, Bytes) implementa FromRequest y debe ser el último argumento. Solo se puede consumir el cuerpo una vez.

ExtractorDe dónde saleFallo típico
Path<String>/links/{code}Ruta sin el parámetro declarado: no compila o no empareja.
Path<(String, u32)>Varios segmentos, en ordenOrden distinto al de la ruta.
Query<T>?limit=10&q=rustCampos obligatorios que no vienen: 400 automático.
Json<T>Cuerpo JSONContent-Type ausente o cuerpo inválido: 415/422 automático.
State<T>El estado del routerOlvidar .with_state(): error de compilación.

Errores: IntoResponse y thiserror

Un handler puede devolver Result<T, E> si E: IntoResponse. El patrón es un enum de error de dominio con thiserror y una implementación de IntoResponse que mapea cada variante a un StatusCode y a un cuerpo JSON. Así el cliente recibe 404, 409 o 422 de verdad, no un 200 con {"error": …}.

Los rechazos de los extractores (JSON mal formado, query inválida) ya devuelven 4xx por su cuenta. Si quieres un cuerpo de error homogéneo, envuelve el extractor con WithRejection o define un tipo propio que implemente FromRequest.

Routers anidados y middleware

Router::merge combina dos routers al mismo nivel; Router::nest monta uno bajo un prefijo (/api/v1). El estado se aplica al final con .with_state(state), que devuelve un Router<()> listo para servir.

Los layers se apilan: el último añadido es el más externo y ve la petición primero. TraceLayer registra método, ruta, estado y latencia; CorsLayer añade las cabeceras que un navegador necesita para llamar a tu API desde otro origen. En producción, CORS se restringe a los orígenes reales: permissive() es para desarrollo.

Servir y probar

axum::serve(listener, app).await toma un TcpListener de Tokio: tú decides la dirección y puedes añadir with_graceful_shutdown. Y como Router implementa tower::Service<Request<Body>>, se puede probar sin red con oneshot: se le pasa una Request construida a mano y se inspecciona la Response. Es la forma canónica de testear handlers.

let response = app
    .oneshot(Request::get("/health").body(Body::empty())?)
    .await?;
assert_eq!(response.status(), StatusCode::OK);

3 · Ejemplo mínimo

Un servidor que responde en /health. Cargo.toml:

[dependencies]
axum = "0.8"
tokio = { version = "1", features = ["macros", "rt-multi-thread", "net"] }
use axum::{routing::get, Router};

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    let app = Router::new().route("/health", get(|| async { "ok" }));

    let listener = tokio::net::TcpListener::bind("127.0.0.1:3000").await?;
    println!("escuchando en http://{}", listener.local_addr()?);

    axum::serve(listener, app).await?;
    Ok(())
}
cargo run
# en otra terminal
curl -i http://127.0.0.1:3000/health
HTTP/1.1 200 OK
content-type: text/plain; charset=utf-8
content-length: 2

ok

Línea a línea:

  • Router::new() crea una tabla de rutas vacía. .route(ruta, método(handler)) añade una entrada.
  • get(...) recibe cualquier Handler: aquí una closure async sin argumentos. El valor devuelto, &str, implementa IntoResponse.
  • TcpListener::bind es de Tokio y es async. local_addr() sirve para imprimir el puerto real (útil con el puerto 0 en tests).
  • axum::serve acepta el listener y el router; se queda esperando conexiones hasta que el proceso termina.
  • No hay unwrap: los dos ? convierten errores de bind y de serve en la salida de main.

La sintaxis de rutas cambió en 0.8

En Axum 0.7 se escribía /links/:code. En 0.8 los parámetros van entre llaves: /links/{code}, y los comodines son /{*resto}. Si copias un ejemplo antiguo, el servidor entra en pánico al arrancar con un mensaje que te lo recuerda.

4 · Ejemplo real

La API de urlshort: crear, consultar, listar, borrar y redirigir. El estado es un mapa en memoria; en la lección de persistencia se sustituye por un Store sin tocar los handlers.

// src/server.rs
use std::{
    collections::HashMap,
    sync::Arc,
    time::{SystemTime, UNIX_EPOCH},
};

use axum::{
    extract::{Path, Query, State},
    http::{header, StatusCode},
    response::{IntoResponse, Response},
    routing::{get, post},
    Json, Router,
};
use serde::{Deserialize, Serialize};
use tokio::sync::RwLock;
use tower_http::{cors::CorsLayer, trace::TraceLayer};

#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct Link {
    pub code: String,
    pub url: String,
    pub created_at: u64,
    pub hits: u64,
}

#[derive(Clone)]
pub struct AppState {
    links: Arc<RwLock<HashMap<String, Link>>>,
}

impl AppState {
    pub fn new() -> Self {
        Self { links: Arc::new(RwLock::new(HashMap::new())) }
    }
}

#[derive(Debug, Deserialize)]
pub struct CreateLink {
    pub url: String,
    pub code: Option<String>,
}

#[derive(Debug, Deserialize)]
pub struct ListParams {
    pub limit: Option<usize>,
}

// ----- errores de la API ------------------------------------------------

#[derive(Debug, thiserror::Error)]
pub enum ApiError {
    #[error("código no encontrado")]
    NotFound,
    #[error("la URL debe empezar por http:// o https://")]
    InvalidUrl,
    #[error("el código debe tener entre 3 y 16 caracteres alfanuméricos")]
    InvalidCode,
    #[error("el código ya existe")]
    Conflict,
    #[error("error interno")]
    Internal(#[from] std::io::Error),
}

impl IntoResponse for ApiError {
    fn into_response(self) -> Response {
        let status = match &self {
            ApiError::NotFound => StatusCode::NOT_FOUND,
            ApiError::InvalidUrl | ApiError::InvalidCode => StatusCode::UNPROCESSABLE_ENTITY,
            ApiError::Conflict => StatusCode::CONFLICT,
            ApiError::Internal(_) => StatusCode::INTERNAL_SERVER_ERROR,
        };

        // No filtramos detalles internos al cliente; sí los registramos.
        let message = match &self {
            ApiError::Internal(err) => {
                tracing::error!(%err, "error interno");
                "error interno".to_string()
            }
            other => other.to_string(),
        };

        (status, Json(serde_json::json!({ "error": message }))).into_response()
    }
}

// ----- handlers ---------------------------------------------------------

async fn health() -> &'static str {
    "ok"
}

async fn create_link(
    State(state): State<AppState>,
    Json(payload): Json<CreateLink>,
) -> Result<(StatusCode, Json<Link>), ApiError> {
    if !(payload.url.starts_with("http://") || payload.url.starts_with("https://")) {
        return Err(ApiError::InvalidUrl);
    }

    let code = match payload.code {
        Some(code) if !valid_code(&code) => return Err(ApiError::InvalidCode),
        Some(code) => code,
        None => short_code(&payload.url),
    };

    let link = Link {
        code: code.clone(),
        url: payload.url,
        created_at: now(),
        hits: 0,
    };

    let mut links = state.links.write().await;
    if links.contains_key(&code) {
        return Err(ApiError::Conflict);
    }
    links.insert(code, link.clone());

    Ok((StatusCode::CREATED, Json(link)))
}

async fn get_link(
    State(state): State<AppState>,
    Path(code): Path<String>,
) -> Result<Json<Link>, ApiError> {
    let links = state.links.read().await;
    let link = links.get(&code).ok_or(ApiError::NotFound)?;
    Ok(Json(link.clone()))
}

async fn list_links(
    State(state): State<AppState>,
    Query(params): Query<ListParams>,
) -> Json<Vec<Link>> {
    let limit = params.limit.unwrap_or(50).min(200);

    let mut out: Vec<Link> = state.links.read().await.values().cloned().collect();
    out.sort_by(|a, b| b.created_at.cmp(&a.created_at));
    out.truncate(limit);
    Json(out)
}

async fn delete_link(
    State(state): State<AppState>,
    Path(code): Path<String>,
) -> Result<StatusCode, ApiError> {
    let mut links = state.links.write().await;
    links.remove(&code).ok_or(ApiError::NotFound)?;
    Ok(StatusCode::NO_CONTENT)
}

// 302 Found: el navegador repetirá el GET en la nueva URL.
async fn redirect(
    State(state): State<AppState>,
    Path(code): Path<String>,
) -> Result<Response, ApiError> {
    let mut links = state.links.write().await;
    let link = links.get_mut(&code).ok_or(ApiError::NotFound)?;
    link.hits += 1;
    let url = link.url.clone();
    drop(links);

    Ok((StatusCode::FOUND, [(header::LOCATION, url)]).into_response())
}

async fn not_found() -> ApiError {
    ApiError::NotFound
}

// ----- router -----------------------------------------------------------

pub fn router(state: AppState) -> Router {
    let api = Router::new()
        .route("/links", post(create_link).get(list_links))
        .route("/links/{code}", get(get_link).delete(delete_link));

    Router::new()
        .route("/health", get(health))
        .merge(api)
        .route("/{code}", get(redirect))
        .fallback(not_found)
        .layer(TraceLayer::new_for_http())
        .layer(CorsLayer::permissive())   // en producción: CorsLayer::new().allow_origin(...)
        .with_state(state)
}

// ----- utilidades -------------------------------------------------------

fn valid_code(code: &str) -> bool {
    (3..=16).contains(&code.len())
        && code
            .chars()
            .all(|c| c.is_ascii_alphanumeric() || c == '-' || c == '_')
}

fn short_code(url: &str) -> String {
    use std::hash::{Hash, Hasher};

    let mut hasher = std::collections::hash_map::DefaultHasher::new();
    url.hash(&mut hasher);
    let mut n = hasher.finish();

    const ALPHABET: &[u8] = b"23456789abcdefghjkmnpqrstuvwxyz";
    let mut code = String::with_capacity(6);
    for _ in 0..6 {
        code.push(ALPHABET[(n % ALPHABET.len() as u64) as usize] as char);
        n /= ALPHABET.len() as u64;
    }
    code
}

fn now() -> u64 {
    SystemTime::now()
        .duration_since(UNIX_EPOCH)
        .map(|d| d.as_secs())
        .unwrap_or(0)
}

Decisiones que importan:

DecisiónPor qué
Arc<RwLock<HashMap>>Clone barato para el estado; lecturas concurrentes y escritura exclusiva. Mutex bastaría, pero las lecturas son mayoría.
Json como último argumentoConsume el cuerpo; debe ir después de State. Es una regla del trait, no un estilo.
Result<T, ApiError>El estado HTTP lo decide el error, no el handler. Un 404 llega como 404.
302 con LOCATIONRedirección temporal: el enlace puede cambiar. Redirect::temporary daría 307 y conservaría el método.
drop(links) antes de responderSe libera el guard en cuanto se copia la URL; no se retiene durante la respuesta.
fallback con el mismo errorUna ruta desconocida devuelve el mismo JSON de error que un código inexistente.

El estado en memoria se pierde al reiniciar

Este servidor es correcto y efímero. En la lección de persistencia, AppState pasará a contener un Store detrás de un Arc; los handlers cambiarán dos líneas y el resto del diseño se mantiene. Esa es la prueba de que el estado estaba bien aislado.

6 · Errores habituales

1. La sintaxis de rutas de 0.7

Mal:

let app = Router::new().route("/links/:code", get(get_link));
thread 'main' panicked at ...:
Path segments must not start with `:`. For capture groups, use `{capture}`.
If you need to literally match `:`, call `Router::without_v07_checks`

Por qué está mal: Axum 0.8 cambió la sintaxis para alinearse con matchit. Bien: /links/{code} y /{*resto} para el resto de la ruta.

2. Estado que no implementa Clone

Mal:

pub struct AppState {
    links: RwLock<HashMap<String, Link>>,   // sin Arc y sin derive Clone
}
error[E0277]: the trait bound `AppState: Clone` is not satisfied
  |
  = note: required by a bound in `axum::extract::State`

Por qué está mal: Axum clona el estado por petición. Bien: #[derive(Clone)] con Arc alrededor de lo compartido. Clonar el Arc no clona el mapa.

3. Json antes que State

Mal: async fn create(Json(p): Json<CreateLink>, State(s): State<AppState>).

error[E0277]: the trait bound `Json<CreateLink>: FromRequestParts<AppState>` is not satisfied
  |
  = note: Function argument #1 is not a valid extractor

Por qué está mal: el extractor del cuerpo implementa FromRequest, no FromRequestParts, y solo puede ser el último. Bien: ponerlo al final.

4. Olvidar .with_state()

Mal: construir las rutas con handlers que piden State y servir el router sin aplicarlo.

error[E0277]: the trait bound `fn(State<AppState>, ...) -> ...: Handler<_, _>`
is not satisfied
  = note: consider using `Router::with_state`

Por qué está mal: el tipo del router conserva el parámetro de estado y axum::serve exige Router<()>. Bien: .with_state(state) al final de la construcción.

5. Bloquear dentro del handler

Mal:

async fn list(State(state): State<AppState>) -> String {
    let texto = std::fs::read_to_string("links.json").unwrap();  // bloquea el worker
    texto
}

Por qué está mal: Tokio multiplexa muchas tareas en pocos hilos; una lectura de disco lenta detiene a todas. Además, unwrap convierte un fallo de disco en un 500 opaco. Bien: tokio::task::spawn_blocking(move || std::fs::read_to_string(…)) o una API async (tokio::fs), y propagar el error.

8 · Reto

🎯 Caducidad, cuota y apagado ordenado

Amplía la API con tres piezas que un acortador real necesita:

  • Caducidad: cada enlace puede llevar expires_at; al resolverlo después de la fecha, responde 410 Gone en vez de redirigir. Un enlace caducado no debe contar como hit.
  • Cuota por IP: máximo 10 creaciones por minuto y por IP. Devuelve 429 con Retry-After. La IP se obtiene de ConnectInfo<SocketAddr> o de X-Forwarded-For si confías en el proxy.
  • Apagado ordenado: al recibir Ctrl+C, deja de aceptar conexiones, termina las peticiones en vuelo y sale con 0. Usa axum::serve(...).with_graceful_shutdown(...).

Pista: la cuota encaja en un layer propio con tower::Service, o en un crate como tower_governor. Para la IP, Router::into_make_service_with_connect_info::<SocketAddr>() es lo que espera axum::serve cuando usas ConnectInfo. Para el apagado, tokio::signal::ctrl_c().await dentro de una async fn que se pasa a with_graceful_shutdown.

9 · Resumen

  • Axum compone Router → extractores → handler → IntoResponse sobre hyper, tower y Tokio.
  • En 0.8 los parámetros de ruta usan llaves: /links/{code}; los comodines, /{*resto}.
  • El estado se pasa con State<T>, se deriva Clone y se comparte con Arc; el RwLock de Tokio permite esperar con el guard tomado.
  • Path, Query, Json y State convierten la petición en argumentos; el extractor del cuerpo va al final.
  • Los errores se modelan con thiserror + IntoResponse: cada variante tiene su estado HTTP y su cuerpo JSON.
  • merge/nest componen routers; layer añade middleware de tower (TraceLayer, CorsLayer).
  • Se sirve con TcpListener + axum::serve y se prueba con tower::ServiceExt::oneshot, sin abrir puertos.

10 · Preguntas frecuentes

¿Axum, Actix Web o Rocket?

Los tres son maduros. Axum se integra con el resto del stack Tokio/tower, tiene extractores tipados y una curva pequeña; Actix Web es muy rápido y con más «baterías incluidas»; Rocket prioriza ergonomía. En este curso Axum encaja porque reutiliza lo aprendido de async y porque sus handlers son funciones normales, fáciles de testear con oneshot.

¿Mutex o RwLock para el estado?

Si las lecturas dominan, RwLock permite varias simultáneas. Si todas las operaciones escriben o las secciones críticas son diminutas, Mutex es más simple y a veces más rápido. Lo importante: usa el de tokio si vas a esperar con el guard tomado; el de std no es Send a través de un .await.

¿Cómo devuelvo un 404 con una página HTML en vez de JSON?

Con otra implementación de IntoResponse o con Html(...): (StatusCode::NOT_FOUND, Html("<h1>No existe</h1>")).into_response(). Si tu API y tu web conviven, separa routers (/api con JSON, resto con HTML) y aplica fallback distintos a cada uno.

¿Cómo limito el tamaño del cuerpo que acepta la API?

Con DefaultBodyLimit: .layer(DefaultBodyLimit::max(64 * 1024)). Por defecto Axum ya impone un límite de 2 MB en Json; si lo subes, hazlo por ruta y no globalmente. Para subidas grandes, usa Multipart y escribe a disco por trozos.

¿Cómo añado autenticación sin repetirla en cada handler?

Con un extractor propio que implemente FromRequestParts y devuelva un Usuario o un rechazo 401, o con un middleware de tower que valide el token y meta los datos en Extension. El extractor se compone mejor con el tipado; el middleware es mejor si la lógica es común a muchas rutas y quieres aplicarla por prefijo.
