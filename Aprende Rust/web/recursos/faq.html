Preguntas frecuentes del curso

FAQ general ❓ 14 preguntas

Antes de empezar

¿Cuánto se tarda en ser productivo con Rust?

La sintaxis, en días. El modelo de propiedad, en unas dos o tres semanas de práctica diaria. La curva tiene un escalón: durante la primera semana el compilador rechaza casi todo, y a partir de ahí empieza a ser una ayuda. Este curso está diseñado para que ese escalón llegue pronto y con explicaciones, no con frustración.

¿Necesito saber C o C++ para seguir el curso?

No. Ayuda haber oído hablar de stack y heap, y el curso los explica cuando aparecen (lección de ownership). Si vienes de Python o JavaScript, la parte que más te costará es aceptar que un dato tenga un único dueño; si vienes de C#, echarás de menos la herencia de clases.

¿Windows, WSL2 o Linux?

Las tres funcionan. En Windows se recomienda WSL2 + VS Code Remote: compilas en Linux sin cruzar /mnt/c, que es lento. Si compilas nativo en Windows, necesitas el linker MSVC (Visual Studio Build Tools con «Desktop development with C++»). La lección de instalación cubre ambos caminos.

¿Qué edición de Rust usa el curso?

Edición 2021, con Rust 1.85 o superior. La edición 2024 se explica en el módulo de Cargo avanzado como migración (cargo fix --edition), porque es la que encontrarás en crates nuevos pero aún no es mayoritaria en todo el ecosistema.

¿Hace falta instalar algo más que Rust?

Para el curso web, nada. Para el proyecto, solo Rust. Opcionales: VS Code con rust-analyzer y CodeLLDB, cargo-audit y cargo-deny para el módulo de calidad, y Docker si quieres probar la imagen del binario en el proyecto final.

Durante el curso

El compilador no me deja compilar y no entiendo el error. ¿Qué hago?

Lee el error entero, incluida la nota final: Rust suele decir la causa, la línea y el arreglo. Los tres errores que verás el 90 % de las veces son E0382 (valor movido), E0502 (préstamo mutable con uno inmutable vivo) y E0308 (tipos incompatibles). La respuesta correcta casi nunca es clone(): es prestar (&), reordenar el código o devolver la propiedad.

¿Por qué el código tarda tanto en compilar?

Porque el compilador hace mucho más que traducir: monomorfiza genéricos, verifica préstamos, comprueba traits y optimiza con LLVM. Ayuda usar cargo check mientras escribes, cargo build --release solo al final, y configurar lld o mold como linker. Las dependencias pesadas (tokio, axum) son la mayor parte del tiempo en la primera compilación; luego queda en caché.

¿Cuándo uso String y cuándo &str?

String cuando el dato se posee y puede cambiar (lo que guardas en una estructura). &str cuando solo lo lees o lo recibes como parámetro: acepta literales y String prestados. La regla práctica: en las firmas de funciones, pide &str; en los structs, guarda String.

¿Por qué no hay clases ni herencia?

Rust usa composición y traits: compartes comportamiento sin compartir implementación. Eso evita la jungla de jerarquías y el problema del diamante, y permite despacho estático sin coste. Cuando de verdad necesitas polimorfismo en ejecución, usas dyn Trait.

¿Async es obligatorio?

No. Muchos servicios de Rust son síncronos con hilos y funcionan perfectamente. Async brilla con muchas conexiones concurrentes y poco trabajo por conexión (servidores HTTP, clientes de red). Si tu programa es un CLI que hace una cosa y termina, no lo necesita: el proyecto del curso solo usa Tokio en el servidor y en la validación HTTP.

¿Puedo usar Rust en un equipo donde el resto escribe Python?

Sí, como módulo nativo o servicio aparte, pero asume un coste: compilación, toolchain y un lenguaje más que mantener. La pregunta honesta es si el rendimiento o la corrección justifican ese coste. Muchas veces la respuesta es sí para el núcleo y no para toda la aplicación.

Sobre el proyecto y el final

¿El proyecto urlshort es solo didáctico o sirve de verdad?

Sirve: guarda en JSON con escritura atómica, expone CLI y HTTP con el mismo dominio y tiene tests. Lo que no tiene es autenticación ni verificación del destino, y su almacén no está pensado para millones de enlaces. El propio README dice qué falta y por qué, que es más útil que fingir que es producción.

¿Voy a poder publicar mi propio crate al terminar?

Sí. El módulo 7 recorre metadatos, documentación, cargo package, --dry-run, versionado semántico y CI. Ten en cuenta que publicar es irreversible: una versión publicada no se puede borrar (solo yank), así que el --dry-run no es opcional.

¿Qué hago cuando termine el curso?

Tres caminos que funcionan: (1) reescribir una herramienta que ya uses en otro lenguaje; (2) contribuir a un crate pequeño del ecosistema leyendo sus issues; (3) profundizar en un dominio (embebido, WebAssembly, cripto, bases de datos). El Rust Book y el Rustonomicon quedan como siguientes lecturas.
