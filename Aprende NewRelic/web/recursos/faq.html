FAQ general del curso

Referencia ❓ Dudas frecuentes
¿Necesito una cuenta de New Relic para seguir el curso?

Sí, para ver tus datos en la UI. New Relic ofrece una cuenta gratuita (free tier) con límite de datos; con ella puedes seguir todo el curso. El proyecto de ejemplo funciona sin licencia: el agente se ejecuta en modo no-op y tú solo activas el envío cuando tengas tu NEW_RELIC_LICENSE_KEY.

¿Tengo que pagar algo?

No necesariamente. La cuenta «Free» permite enviar una cantidad determinada de datos (GB) sin coste. Más allá de eso, New Relic cobra por consumo de datos y usuarios. El curso te enseña a ser consciente de qué datos envías para no malgastar unidades de reporting.

¿Este curso reemplaza a OpenTelemetry? ¿Y al curso Aprende Dotnet?

No. El curso OpenTelemetry vs. agente APM te explica cuándo usar cada camino. Y «Aprende Dotnet» te enseña .NET de cero; este curso asume que ya sabes .NET y se centra en observabilidad.

Mi app no usa WebSocket. ¿Me sirve?

El curso está construido alrededor de un servidor WebSocket + API, pero casi todo es aplicable a cualquier app .NET: agente, APM, trazas HTTP automáticas, logs en contexto, NRQL y alertas. La parte de WebSocket se convierte en «cualquier canal no instrumentado» (colas, workers, gRPC…).

¿Qué versión de .NET usamos?

.NET 8 (LTS), alineado con el curso Aprende Dotnet. El agente de New Relic soporta .NET 5+ hasta .NET 10, así que los ejemplos funcionan igual en versiones más nuevas.

He cambiado newrelic.config y no veo cambios. ¿Por qué?

Hay varias causas típicas: el daemon cachéa la config (reinicias la app o, en IIS, iisreset); hay una variable de entorno que sobreescribe (las variables tienen prioridad sobre el archivo); o el archivo no está en la ruta esperada. Se cubre en el módulo de configuración.

¿NRQL es como SQL?

Se parece (SELECT, FROM, WHERE), pero está pensado para series temporales: tiene SINCE/UNTIL, TIMESERIES, FACET y agregadores de time series. El cheatsheet de NRQL te da el resumen rápido.

¿Manda muchos datos mi WebSocket si lo instrumento por mensaje?

Depende del caudal. Veremos técnicas para no disparar el consumo: muestreo (distributed tracing), eventos solo para caras de negocio relevantes, métricas agregadas para el volumen y límites del forwarding de logs. El módulo de buenas prácticas lo aborda con detalle.
