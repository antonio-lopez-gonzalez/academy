Logs en contexto en .NET

Módulo 5 · Logs en Contexto y Datos JSON ⏱ 30 minutos

1 · Introducción

Ver una traza y poder abrir los logs del mismo traceId desde la misma pantalla es el «logs in context». Con el agente .NET no necesitas librerías extra: si usas Microsoft.Extensions.Logging, Serilog, NLog o log4net, el agente puede forwardear tus logs a New Relic y enriquecerlos con trace.id y span.id.

Verás las dos vías (forwarding y local decorating), su configuración y cuándo conviene cada una.

2 · Teoría

Quién hace qué

OpciónCómo funcionaQué obtienes
Agent forwarding (recomendada)El agente intercepta los logs de los frameworks y los envía al producto Logs, enriqueciéndolosLogs con trace.id, span.id, hostname, entity.guid, entity.name → visibles en la UI de Logs y en el trace
Local decoratingEl agente añade un token «NR-LINKING» al mensaje para que tu propio pipeline de logs lo useCorrelación en tu sistema centralizado de logs (si ya mandas logs a otro lado)

Configuración XML

<applicationLogging enabled="true">
  <metrics enabled="true" />                       <!-- Logging/lines, Logging/lines/ERROR ... -->
  <forwarding enabled="true" maxSamplesStored="10000" />  <!-- envía logs a New Relic -->
  <localDecorating enabled="false" />                   <!-- token NR-LINKING (si no usas forwarding) -->
</applicationLogging>

y su equivalente por variables de entorno (que ganan):

export NEW_RELIC_APPLICATION_LOGGING_ENABLED=true
export NEW_RELIC_APPLICATION_LOGGING_FORWARDING_ENABLED=true
export NEW_RELIC_APPLICATION_LOGGING_METRICS_ENABLED=true
# límite por minuto:
export NEW_RELIC_APPLICATION_LOGGING_FORWARDING_MAX_SAMPLES_STORED=10000

Frameworks soportados (auto-instrumentados)

Serilog (Core 2.0+), NLog, log4net/log4net.Core y Microsoft.Extensions.Logging con .NET Core (agente 10+). El enganche del agente los intercepta sin cambiar tu pipeline.

Nota de límites: por defecto se forwardean hasta ~10.000 logs/min por agente. Es un control de coste: los logs demasiado verbosos se descartan. Diseña niveles de logging con criterio (M5-03).

3 · Ejemplo mínimo

Con ILogger al estilo .NET 8 no hay más que activarlo:

public class TradeProcessor(ILogger<TradeProcessor> logger)
{
    public void ProcessTrade(MessageEnvelope msg)
    {
        logger.LogInformation("Procesando trade {MessageId} en {Utc}", msg.MessageId, DateTimeOffset.UtcNow);
        // ... el agente (con forwarding) enviará este log con trace.id y span.id
    }
}

En la UI: abre la traza del trade y pulsa la pestaña Logs — aparece este log correlacionado.

4 · Ejemplo real

Con Serilog (montando el logging de la app), el forwarding lo hace el agente igualmente:

// appsettings.json (o Program)
builder.Host.UseSerilog((ctx, cfg) => cfg
    .MinimumLevel.Information()
    .WriteTo.Console(new JsonFormatter()));   // logs JSON legibles

// El agente .NET detecta Serilog y forwardea con trace.id/span.id.
// No necesitas el paquete "NewRelic.LogEnrichers.Serilog": es para
// OTROS destinos (local decorating / pipelines propios).

Con Serilog, la propiedad {TraceId} {SpanId} de ASP.NET Core se puede etiquetar para que el agente la use, pero con forwarding el agente las pone él.

6 · Errores habituales

Activar forwarding pero no ver logs

# Comprueba:
# 1. NEW_RELIC_APPLICATION_LOGGING_ENABLED=true
# 2. NEW_RELIC_APPLICATION_LOGGING_FORWARDING_ENABLED=true
# 3. El framework de logging es soportado (Serilog/NLog/log4net/M.E.Logging)
# 4. Hay logs a nivel que llegan (Information/Error) y no has rebasado el límite

Enviar PII en el mensaje

Los logs van a tu cuenta e indexados. No vuelques emails, tokens o datos de tarjeta en el mensaje; usa etiquetas/IDs y omite el dato sensible.

9 · Resumen

  • Forwarding del agente: logs de Serilog/NLog/log4net/M.E.Logging → New Relic con trace.id/span.id.
  • Configuración XML applicationLogging o env NEW_RELIC_APPLICATION_LOGGING_*.
  • LocalDecorating = token NR-LINKING para pipelines propios.
  • Límite ~10k logs/min: diseña niveles con cabeza.

10 · Preguntas frecuentes

¿Necesito algún paquete de enriquecimiento?

No para forwarding con los frameworks soportados. Los paquetes NewRelic.LogEnrichers.* son solo para localDecorating/pipelines propios.

¿Qué pasa si mando logs a New Relic y además a otro SIEM?

Forwarding a NR + tu exportación habitual es válido y común (aunque duplica la salida). Puedes controlar qué se envía a cada sitio con niveles.

¿Los logs cuentan para el consumo?

Sí: cada log forwardeado consume del plan de datos (y del límite de 10k/min). Por eso los niveles y el denylist importan.
