Estructura JSON de los mensajes y forwarding

Módulo 5 · Logs en Contexto y Datos JSON ⏱ 30 minutos

1 · Introducción

Tu WebSocket habla JSON. Si diseñas bien la estructura de los mensajes y de los logs, New Relic podrá consultarlos como datos, no como texto. Esta lección une dos cosas: el esquema de tu envoltorio JSON y cómo el forwarding del agente convierte atributos en «campos de búsqueda y facet».

2 · Teoría

Dos JSON distintos, dos propósitos

JSONDóndeQué guarda New Relic
MessageEnvelopeTráfico de tu WebSocketSus campos como atributos si los copias a Transaction/Span/Log
Log recordSalida de Serilog/NLog/ILoggerCada parámetro como atributo del log (además de trace.id/span.id)

El esquema del MessageEnvelope (recapitulación + clase)

// Campos del envoltorio y su uso en observabilidad:
//  type       → FACET (baja cardinalidad)
//  timestamp  → latencia de cola (Custom/QueueLatencyMs)
//  traceId    → contexto W3C (M3-04)
//  messageId  → identidad para correlación
//  payload    → datos de negocio
public sealed record MessageEnvelope(
    string Type,
    DateTimeOffset Timestamp,
    string MessageId,
    Dictionary<string, string> TraceContext,
    JsonElement Payload);

Context data en el forwarding

Desde el agente 10.x puedes pedir que los logs forwardeados incluyan context data: atributos que la app registra con tu logger pasan al log en New Relic como context.*.

<forwarding enabled="true">
  <contextData enabled="true" include="" exclude="" />
</forwarding>
export NEW_RELIC_APPLICATION_LOGGING_FORWARDING_CONTEXT_DATA_ENABLED=true

Ej.: con Serilog y enriquecedor AppName, verás context.AppName en el log. En el Módulo 8 lo usaremos para etiquetar el entorno.

Logs con atributos consultables

logger.LogInformation("Trade procesado {Type} por {UserId} en {LatencyMs} ms",
    msg.Type, msg.UserId, latencyMs);

→ en Logs: columnas Type, UserId, LatencyMs facetables.

3 · Ejemplo mínimo

// Un log estructurado que se vuelve "tabla" en New Relic
logger.LogInformation("trade {MessageId} {Symbol} {Amount}", msg.MessageId, symbol, amount);

Consulta: los parámetros del log ya son atributos facetables.

SELECT count(*) FROM Log FACET Symbol, Amount SINCE 1 hour ago

4 · Ejemplo real

En el proyecto final, cada fase escribe «en el idioma de quien investiga»:

// WsServer: recibido
logger.LogInformation("recibido {Type} {MessageId} bytes={Bytes}",
    msg.Type, msg.MessageId, msg.Bytes.Length);

// TradeProcessor: fase
logger.LogDebug("apply trade {MessageId} symbol={Symbol}", msg.MessageId, symbol);

// Fallo
logger.LogError("trade falló {MessageId} reason={Reason}", msg.MessageId, reason);

Con forwarding: puedes filtrar FROM Log WHERE MessageId='887' y obtener la biografía del mensaje de punta a punta.

6 · Errores habituales

Loguear el payload JSON entero por mensaje

// ❌ El payload completo de cada trade infla los logs y la factura
logger.LogInformation("trade {Payload}", msg.Payload.ToString());

// ✅ Solo lo que facilites: campos, no documentos
logger.LogInformation("trade {Symbol} {Amount}", symbol, amount);

Ignorar el límite de 10k/min

En picos, se descartan logs. Prioriza los niveles: ERROR siempre, INFO solo en caras relevantes.

8 · Reto

🎯 Convierte tu envelope en dato

Diseña el mapa «campo del envelope → atributo de NR» (type→messageType, timestamp→latencia, messageId→MessageId, payload.symbol→Symbol…). Indica qué atributos van a la transacción, cuáles al span y cuáles al log. Es la plantilla de instrumentación del Módulo 8.

9 · Resumen

  • Envelope JSON con campos estables → atributos de NR.
  • Logs estructurados (parámetros) → columnas facetables.
  • Context data del agente para marcas globales (context.*).
  • Control de niveles y límites para el coste.

10 · Preguntas frecuentes

¿Cómo limito el nivel máximo en prod?

Con el logging framework: en Serilog, MinimumLevel.Override("Microsoft", Warning); o denylist de niveles con logLevelDenyList del forwarding del agente.

¿Debo mandar los logs del WebSocket como Custom events en vez de Log?

No. Los logs son para depurar; los eventos para negocio. Mezclarlos confunde a quien investiga.

¿Qué pasa con los mensajes que se descartan por el límite?

Se contabilizan en las métricas Logging/lines (si métricas activas) pero no se guardan: «ves que se emitió, no su contenido». Diseña niveles para no llegar ahí.
