Configuración: newrelic.config y variables de entorno

Módulo 1 · El agente APM de New Relic para .NET ⏱ 35 minutos

1 · Introducción

El agente se configura con un archivo newrelic.config (XML) y/o con variables de entorno. Saber cuál gana y qué opciones importan (distributed tracing, logs, errores) te ahorrará el clásico «no veo mis datos».

Verás la estructura del archivo, la precedencia de configuración y las variables más útiles para nuestra app.

2 · Teoría

Precedencia (de más a menos prioridad)

  1. Configuración de la app: appsettings.json, web.config/app.config
  2. Variables de entorno (NEW_RELIC_*)
  3. Server-side config (lo que Configure el UI, en Managed Accounts)
  4. newrelic.config local de la app (el del paquete, en bin/newrelic)
  5. newrelic.config global (MSI: C:\ProgramData\New Relic\.NET Agent\)

Conclusión práctica: lo más fiable para un despliegue es variables de entorno en docker/K8s, y newrelic.config para opciones estructurales estables.

Anatomía del newrelic.config

<?xml version="1.0" encoding="utf-8"?>
<configuration xmlns="urn:newrelic-config" agentEnabled="true">
  <service licenseKey="YOUR_LICENSE_KEY" sendDataOnExit="false" />

  <application>
    <name>NotificadorWebSocket</name>
  </application>

  <!-- Trazas distribuidas (W3C + header newrelic). Por defecto en agentes ≥ 9.0 -->
  <distributedTracing enabled="true" excludeNewrelicHeader="false" />

  <!-- Errores: capturas y eventos de error -->
  <errorCollector enabled="true" captureEvents="true" maxEventSamplesStored="100" />

  <!-- Transacciones: límites de almacenamiento y umbrales -->
  <transactionTracer enabled="true" transactionThreshold="apdex_f" />

  <!-- Logs: forwarding del agente (logs in context) -->
  <applicationLogging enabled="true">
    <metrics enabled="true" />
    <forwarding enabled="true" maxSamplesStored="10000" />
    <localDecorating enabled="false" />
  </applicationLogging>
</configuration>

Atributos/hijos clave

SecciónQué controla
<service licenseKey>Clave de ingest y opciones de envío
<application>Hasta 3 nombres de app (rollup)
<distributedTracing>Habilita W3C Trace Context y el header newrelic
<transactionTracer>Umbral del tracer (apdex_f), número de segmentos
<errorCollector>Captura errores y si genera eventos de error
<applicationLogging>Metrics, forwarding y decoración local de logs
<attributes enabled>Incluir/excluir atributos (p. ej. <exclude>request.headers.*</exclude>)

3 · Ejemplo mínimo

# La configuración EXPRESA mínima para que funcione:
export NEW_RELIC_LICENSE_KEY=YOUR_LICENSE_KEY
export NEW_RELIC_APP_NAME=NotificadorWebSocket

# Activar trazas (por defecto) y logs en contexto:
export NEW_RELIC_DISTRIBUTED_TRACING_ENABLED=true
export NEW_RELIC_APPLICATION_LOGGING_ENABLED=true
export NEW_RELIC_APPLICATION_LOGGING_FORWARDING_ENABLED=true

4 · Ejemplo real

En appsettings.Development.json de tu app podrías llevar la config de logs y dejar las claves en variables. Recuerda: la config vía appsettings.json NO configura el agente; el agente se configura con NEW_RELIC_* o newrelic.config:

{
  "NewRelic": {
    "LicenceKey": "",                      // ← mejor dejarlo vacío y usar env
    "AppName": "NotificadorWebSocket",
    "DistributedTracingEnabled": true,
    "ApplicationLogging": {
      "Enabled": true,
      "ForwardingEnabled": true
    }
  }
}

El agente de New Relic lee las variables de entorno por encima de cualquier archivo de tu app. Por eso en producción sueles configurarlo todo por env en el despliegue.

6 · Errores habituales

Cambiar la config y esperar efecto sin reiniciar

# ❌ Cambiaste NEW_RELIC_APP_NAME y no reiniciaste el proceso
# ✅ El agente lee la config al arrancar (y a veces al cambiar archivo);
#    con IIS además: iisreset

Usar appsettings.json para configurar el agente

# ❌ El agente NO lee appsettings.json del framework de config.
# ✅ Usa NEW_RELIC_* o newrelic.config.

Ignorar el log del agente cuando «no hay datos»

# Al arrancar, el agente escribe en NEW_RELIC_LOG (o stdout).
# Si ves "Connection refused" / "No collector" revisa host/región.
export NEW_RELIC_LOG=stdout

7 · Ejercicio guiado

  1. Paso 1: Copia el newrelic.config del proyecto de ejemplo y edítalo: pon tu license key y app name.
  2. Paso 2: Define las variables equivalenciales en el entorno y borra la license del archivo (para ver que las env ganan).
  3. Paso 3: Ejecuta la app; comprueba en APM que la app aparece bajo NEW_RELIC_APP_NAME (y no la del config).
  4. Paso 4: Cambia NEW_RELIC_APPLICATION_LOGGING_FORWARDING_ENABLED=false, reinicia y observa que dejan de aparecer logs en Logs.

8 · Reto

🎯 Precedencia en acción

Diseña el esquema de configuración para 3 entornos (dev-prod-drill) con NEW_RELIC_APP_NAME distinta por entorno, manteniendo un solo newrelic.config con la license en blanco. Explica qué ganarías al separar entornos en entidades distintas.

9 · Resumen

  • newrelic.config (XML) define estructura; las env vars ganan a las config de la app y al archivo.
  • Secciones clave: service, application, distributedTracing, transactionTracer, errorCollector, applicationLogging.
  • Nombres de variables: NEW_RELIC_LICENSE_KEY, NEW_RELIC_APP_NAME, NEW_RELIC_HOST, NEW_RELIC_DISTRIBUTED_TRACING_ENABLED, NEW_RELIC_APPLICATION_LOGGING_*…
  • El agente no lee appsettings.json: usa NEW_RELIC_* o newrelic.config.

10 · Preguntas frecuentes

¿Puedo tener varias apps (nombres) enviando a la misma cuenta?

Sí. Con <name>App1</name><name>App2</name> o NEW_RELIC_APP_NAME="App1, App2" (hasta 3). Sirve para rollups en dashboards e IA.

¿Por qué New Relic no usa mi appsettings.json?

Porque el agente se configura a nivel de CLR (antes de que tu app cargue su configuración de .NET). Por eso la config nativa son env vars/archivo propio.

¿Dónde está el log del agente?

Por defecto en un archivo junto al agente; con NEW_RELIC_LOG=stdout lo ves en tu consola/container. Es tu primera herramienta de debugging.
