Cómo funciona el agente .NET (CLR profiling)

Módulo 1 · El agente APM de New Relic para .NET ⏱ 35 minutos

1 · Introducción

Antes de instalar nada, conviene entender qué es el agente. No es una librería que «loguees» desde tu código: es un profiler del CLR que se engancha a la máquina virtual de .NET y observa el código en ejecución sin que tu código cambie. Por eso «funciona solo» con ASP.NET Core, HttpClient, EF Core, etc.

Verás qué es el CLR profiling, qué parte es automática y qué parte (la instrumentación custom) depende de ti, y por qué la API del agente está separada del propio agente.

2 · Teoría

El CLR y los profilers

El Common Language Runtime (CLR) es la máquina virtual de .NET: compila el IL a código nativo (JIT), gestiona memoria (GC) y ejecuta tu aplicación. .NET expone una API de profiling (ICorProfilerCallback) pensada para diagnosticar y observarlo: cuándo se carga un ensamblado, cuándo se compila un método, cuándo entra/sale de un método, asignaciones de objetos, etc.

El agente de New Relic es un profiler CLR: se inyecta vía variables de entorno (CORECLR_ENABLE_PROFILING=1, CORECLR_PROFILER=<GUID>) y, con callbacks + recompilación de IL (técnica llamada instrumentation injection), envuelve los métodos de los frameworks soportados para medirlos sin tocar tu código.

Tu código C# ──► IL ──► JIT ──► código nativo
                  │           ▲
                  │           │ el profiler recompila (reJIT) métodos
                  ▼           │
              [ NewRelic.Profiler ]  ──► recolecta perfil (tiempos, llamadas)
                  │
                  ▼
              El agente (.NET) ──► agrupa datos ──► envía al collector (HTTPS)

Qué se espera de la instrumentación automática

  • ASP.NET Core (Minimal APIs y controllers): transacciones web por petición.
  • HttpClient: llamadas de salida como external services.
  • Bases de datos soportadas (SQL Server, PostgreSQL, MySQL, …): queries como datastore.
  • Sistemas de mensajería que el agente reconoce (p. ej. RabbitMQ.Client): propagación automática de trazas.
  • Y con distributed tracing activo, los headers HTTP/W3C se propagan solo.

Lo que NO hace solo: los mensajes que recorren canales que el agente no conoce (tu WebSocket con JSON) y la lógica de negocio en métodos arbitrarios. Ahí entra la instrumentación custom vía la API NewRelic.Agent.Api.

Dos piezas: el agente y la API

Paquete NuGetRol
NewRelic.AgentEl agente completo: profiler + configuración. Se despliega en la carpeta de salida de tu app (bin).
NewRelic.Agent.ApiSolo la API de instrumentación (IAgent, ITransaction, ISpan, RecordCustomEvent…). Es no-op si el agente no está adjunto.

Esto significa que puedes escribir código de instrumentación siempre, y decidir en cada entorno si el agente se adjunta o no (por ejemplo, sin adjuntarlo en tu máquina durante el desarrollo).

3 · Ejemplo mínimo

Endpoints de diagnóstico útiles (disponibles en GET /agent del proyecto de ejemplo):

app.MapGet("/agent", () => Results.Ok(new
{
    licenseKey = !string.IsNullOrWhiteSpace(
        Environment.GetEnvironmentVariable("NEW_RELIC_LICENSE_KEY")),
    appName = !string.IsNullOrWhiteSpace(
        Environment.GetEnvironmentVariable("NEW_RELIC_APP_NAME")),
}));

// OJO: NO compruebes la carga con "GetAgent() is not null": la API
// devuelve un handle no-op (no nulo) aunque el profiler no esté adjunto.
// La señal fiable es el log del agente al arrancar ("Connected"/"agentEnabled").

Con el profiler adjunto verás en la consola mensajes del agente y datos en APM; sin él, la URL responde igual porque la API es no-op.

4 · Ejemplo real

En tu app podrías distinguir «auto-instrumentable» de «custom» en cada pieza:

PiezaAutomáticaCustom (vía API)
GET /api/statusSí → transacción webAñadir atributos (ej. versión) con AddCustomAttribute
POST /api/broadcastSí → transacción webAtributo audience, métrica de tamaño del broadcast
Handshake WSSí → transacción del upgrade HTTPAtributo clientId para saber quién se conecta
Procesar memoria del mensajeNoMódulo 4: transacción/spans por mensaje

Al final tendrás «el borde» automático y «el corazón» custom; los dos conectados por el mismo traceId.

6 · Errores habituales

Creer que «tengo la API» = «tengo agente»

// ❌ Referenciar NewRelic.Agent.Api no adjunta el profiler:
// la API es no-op si no instales/desplegues NewRelic.Agent.

// ✅ Añade también NewRelic.Agent (despliega el profiler + newrelic.config)

Usar COR_PROFILER en lugar de CORECLR_PROFILER

# ❌ Las variables "COR_*" son para .NET Framework (4.x)
# ✅ Para .NET (Core/5+/8) el profiler usa CORECLR_*:
CORECLR_ENABLE_PROFILING=1
CORECLR_PROFILER={36032161-FFC0-4B61-B559-F6C5D41BAE5A}

Comprobar el agente con un null-check

GetAgent() is not null es falso positivo: la API devuelve un handle no-op sin agente. Comprueba la carga mirando el log del agente (o el entorno con el paquete NewRelic.Agent), no con un null-check.

7 · Ejercicio guiado

  1. Paso 1: Crea un proyecto mínimo dotnet new web -n Probe (o usa el de proyectos/newrelic-ws-demo).
  2. Paso 2: Añade el paquete API y crea el endpoint /agent del ejemplo mínimo.
  3. Paso 3: Ejecuta sin agente: la app arranca y responde (no-op). Anota la salida.
  4. Paso 4: Añade NewRelic.Agent, define NEW_RELIC_LICENSE_KEY/NEW_RELIC_APP_NAME y vuelve a correr. Comprueba que ahora los logs del agente indican «Connected» / «agentEnabled».

9 · Resumen

  • El agente es un profiler del CLR que instrumenta frameworks conocidos sin tocar tu código.
  • ASP.NET Core, HttpClient y bases de datos soportadas son automáticos; tu WebSocket no.
  • NewRelic.Agent (profiler) y NewRelic.Agent.Api (API) son piezas distintas; la API es no-op sin agente.
  • La instrumentación custom resuelve lo que el automático no cubre.

10 · Preguntas frecuentes

¿Puedo usar el agente en .NET Framework?

Sí, el agente soporta .NET Framework 4.6.2+ (con variables COR_*) y .NET (Core/5–10). Este curso se centra en .NET 8 con CORECLR_*.

¿Native AOT?

No. La instrumentación por profiling no es compatible con apps AOT/trimmed: es un límite del acoplamiento al CLR.

¿Cuánto overhead añade?

Bajo y regulable (muestreo de trazas, límites de spans). La instrumentación automática está optimizada y el agente agrupa datos antes de enviarlos.
