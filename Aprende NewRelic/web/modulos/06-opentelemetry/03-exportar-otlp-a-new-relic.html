Exportar OTLP a New Relic

Módulo 6 · OpenTelemetry (OTLP a New Relic) ⏱ 35 minutos

1 · Introducción

El momento de la verdad: que los datos OTel de tu app .NET lleguen a New Relic. Todo pasa por apuntar el exporter OTLP al endpoint correcto y autenticarte con la license key como header api-key.

Verás los endpoints por región, las variables a configurar y cómo verificar que los datos aparecen en la UI.

2 · Teoría

Endpoints OTLP de New Relic

RegiónEndpointPuertos
UShttps://otlp.nr-data.netgRPC :4317 · HTTP :4318
EUhttps://otlp.eu01.nr-data.netgRPC :4317 · HTTP :4318

Variables de entorno (casi todo va por aquí)

export OTEL_EXPORTER_OTLP_ENDPOINT=https://otlp.nr-data.net:4318   # HTTP/protobuf
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
export OTEL_EXPORTER_OTLP_HEADERS="api-key=YOUR_NEW_RELIC_LICENSE_KEY"
export OTEL_EXPORTER_OTLP_COMPRESSION=gzip

# recomendado para métricas:
export OTEL_EXPORTER_OTLP_METRICS_TEMPORALITY_PREFERENCE=delta
export OTEL_EXPORTER_OTLP_METRICS_DEFAULT_HISTOGRAM_AGGREGATION=base2_exponential_bucket_histogram

Detalle que suele fallar: si usas variables específicas por signal (OTEL_EXPORTER_OTLP_TRACES_ENDPOINT, ..._METRICS_ENDPOINT…) deben incluir el path completo (.../v1/traces). La genérica OTEL_EXPORTER_OTLP_ENDPOINT + protocolo maneja los paths solo.

El header de autenticación

New Relic espera api-key con tu ingest license key (la misma de NEW_RELIC_LICENSE_KEY). Es una de las diferencias con otros backends (que usan Authorization).

3 · Ejemplo mínimo

Con las variables anteriores y el SDK de M6-02, ejecuta y genera tráfico. Luego, la primera verificación cómoda:

SELECT count(*) FROM Span SINCE 15 minutes ago
SELECT count(*) FROM Metric SINCE 15 minutes ago

Si aparecen datos, el OTLP está funcionando.

4 · Ejemplo real

Con Docker/K8s inyectas las variables, y en el código solo configuras el AddOtlpExporter():

# deployment.yaml (fragmento)
env:
  - name: OTEL_EXPORTER_OTLP_ENDPOINT
    value: "https://otlp.nr-data.net:4318"
  - name: OTEL_EXPORTER_OTLP_PROTOCOL
    value: "http/protobuf"
  - name: OTEL_EXPORTER_OTLP_HEADERS
    value: "api-key=YOUR_LICENSE_KEY"      # ← vía Secret en producción
  - name: OTEL_SERVICE_NAME
    value: "NotificadorWebSocket-otel"

OTEL_SERVICE_NAME define el service.name con el que agruparás la entidad OTLP en New Relic.

6 · Errores habituales

Auth 401/403 por header equivocado

# ❌ OTEL_EXPORTER_OTLP_HEADERS="Authorization=Bearer ..."
# ✅ api-key con la license key de ingest
export OTEL_EXPORTER_OTLP_HEADERS="api-key=YOUR_LICENSE_KEY"

Signal-specific endpoint sin el path correcto

# ❌ OTEL_EXPORTER_OTLP_TRACES_ENDPOINT=https://otlp.nr-data.net:4318
#    → 404: falta el path /v1/traces
# ✅ OTEL_EXPORTER_OTLP_TRACES_ENDPOINT=https://otlp.nr-data.net:4318/v1/traces
# (o usa la variable genérica y deja que el protocolo ponga el path)

9 · Resumen

  • Endpoint otlp.nr-data.net (+ región y puerto) y header api-key = license key.
  • Configura todo por OTEL_EXPORTER_OTLP_*; OTEL_SERVICE_NAME da el nombre de entidad.
  • Verifica con FROM Span / FROM Metric en NRQL.

10 · Preguntas frecuentes

¿gRPC o HTTP?

Cualquiera con el path correcto. http/protobuf es la opción más portable (sin depender de certificados gRPC). Usa puerto :4318.

¿Los datos OTLP cuentan para consumo igual?

Sí: spans, métricas y logs enviados consumen del plan. El muestreo OTel (OTEL_TRACES_SAMPLER) lo controlas tú.

¿Necesito el collector de OTel para esto?

No. Directo endpoint→New Relic vale. El collector es para pipelines más complejos (agregación, scraping, filtros).
