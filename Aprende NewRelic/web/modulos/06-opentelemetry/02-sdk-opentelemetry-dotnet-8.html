SDK de OpenTelemetry en .NET 8

Módulo 6 · OpenTelemetry (OTLP a New Relic) ⏱ 40 minutos

1 · Introducción

Instalamos y configuramos el SDK de OpenTelemetry en una app .NET 8: traces (ActivitySource + instrumentaciones automáticas), métricas (Meter, counter/histogram y métricas de ASP.NET Core) y logs (bridge desde el logging).

Al final tendrás el equivalente OTel de la instrumentación del WebSocket para poder comparar las dos vías.

2 · Teoría

Conceptos de OTel que usaremos

  • ActivitySource: tu «fábrica» de spans (Activities). Equivale a [Transaction]/[Trace].
  • Activity: un span. StartActivity lo crea; SetTag añade atributos; RecordException graba errores.
  • Meter + Instrument: contadores e histogramas para métricas custom.
  • Exporter: a quién mandas los datos (nosotros: un OtlpExporter en el M6-03).

Paquetes

dotnet add package OpenTelemetry
dotnet add package OpenTelemetry.Exporter.OpenTelemetryProtocol
dotnet add package OpenTelemetry.Instrumentation.AspNetCore   # traces/métricas ASP.NET Core automat.

Versiones 1.x (a la fecha, 1.18.x). Ojo: los paquetes de instrumentation traen dependencias transitivas (HTTP Client, etc.).

Añadir el SDK en Program.cs

using OpenTelemetry;
using OpenTelemetry.Metrics;
using OpenTelemetry.Trace;

var builder = WebApplication.CreateBuilder(args);

builder.Services.AddOpenTelemetry()
    .WithTracing(t => t
        .AddAspNetCoreInstrumentation()                // transacciones HTTP
        .AddSource("NotificadorWs")                     // nuestro ActivitySource
        .AddOtlpExporter())                             // exporta OTLP (config por env)
    .WithMetrics(m => m
        .AddAspNetCoreInstrumentation()
        .AddMeter("NotificadorWs.Meters")
        .AddOtlpExporter());

3 · Ejemplo mínimo

// Una ActivitySource estática: la «firma» de tu instrumentación
public static class Telemetry
{
    public static readonly System.Diagnostics.ActivitySource Source = new("NotificadorWs");
}

// En el handler del mensaje:
using var activity = Telemetry.Source.StartActivity("ProcessTrade");
activity?.SetTag("messageType", "trade");
activity?.SetTag("messageId", msg.MessageId);

Thread.Sleep(100);   // "trabajo"

activity?.SetStatus(System.Diagnostics.ActivityStatusCode.Ok);
// Si falla:
// activity?.SetStatus(System.Diagnostics.ActivityStatusCode.Error);
// activity?.RecordException(ex);

Con AddSource("NotificadorWs") en la config, estos Activities se exportan.

4 · Ejemplo real

El mismo procesado del WebSocket con métricas OTel:

public sealed class TradeMetrics
{
    private readonly Counter<long> _processed;
    private readonly Histogram<double> _latency;

    public TradeMetrics()
    {
        var meter = new Meter("NotificadorWs.Meters", "1.0.0");
        _processed = meter.CreateCounter<long>("ws.messages.processed");
        _latency   = meter.CreateHistogram<double>("ws.trade.latency.ms");
    }

    public void Record(string type, double latencyMs)
    {
        _processed.Add(1, new KeyValuePair<string, object?>("type", type));
        _latency.Record(latencyMs);
    }
}

// Uso dentro del handler:
public void OnMessage(MessageEnvelope msg)
{
    using var act = Telemetry.Source.StartActivity("ProcessTrade");
    act?.SetTag("messageType", msg.Type).SetTag("messageId", msg.MessageId);
    var sw = System.Diagnostics.Stopwatch.StartNew();
    Process(msg);
    sw.Stop();
    _metrics.Record(msg.Type, sw.Elapsed.TotalMilliseconds);
}

Traces automáticas de ASP.NET Core (AspNetCore Instrumentation), custom (Source) y métricas del Meter están listas para exportarse.

9 · Resumen

  • SDK OTel en .NET 8: ActivitySource para traces, Meter para métricas; instrumentaciones automáticas en paquetes.
  • El exportador y el endpoint se configuran por variables OTEL_EXPORTER_OTLP_*.
  • Reglas: sources estables, tags low-cardinality, using en Activities.

10 · Preguntas frecuentes

¿Por qué no veo mis activities si no hago AddSource?

El SDK solo procesa lo que se suscribe. Instrumentaciones automáticas: las configuras con AddAspNetCoreInstrumentation() etc. Sources propios: con AddSource("nombre").

¿Necesito un collector separado?

No para hacer el curso: el exporter OTLP directo a New Relic basta. Un collector se justifica cuando quieras procesar/agregar/filtrar antes de enviar.

¿OTel puede exportar logs también?

Sí (OTLP Logs). En New Relic encajan en el producto Logs. Aquí nos centramos en traces+métricas; los logs ya los resolvemos bien con el forwarding del agente (M5).
