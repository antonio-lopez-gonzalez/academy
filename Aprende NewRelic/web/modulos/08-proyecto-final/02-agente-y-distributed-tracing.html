Agente, distributed tracing y traceId

Módulo 8 · Proyecto Final ⏱ 45 minutos 🟢 proyecto

1 · Introducción

Ahora encendemos la observabilidad de verdad: adjuntamos el agente APM, activamos distributed tracing y vemos cómo el traceId que viaja en el JSON del WebSocket se convierte en una traza pulsable en New Relic.

Es la verificación del corazón del curso: agente + transacciones custom + W3C = un solo trace por mensaje.

2 · Teoría

1. Adjuntar el profiler

cd proyectos/newrelic-ws-demo
dotnet add src/NewRelicWsDemo package NewRelic.Agent -v 10.54.0

# variables (o newrelic.config)
export NEW_RELIC_LICENSE_KEY=YOUR_LICENSE_KEY
export NEW_RELIC_APP_NAME=NotificadorWebSocket
# export NEW_RELIC_HOST=collector.eu.newrelic.com   # si no eres US

Con el profiler vivo, en la consola verás mensajes del agente; en ~1-2 min aparece la entidad en APM.

2. Distributed tracing (por defecto en agentes 10.x)

No hay que hacer nada: <distributedTracing enabled="true"/> es el default (agentes ≥9.0). Solo verifica con env: NEW_RELIC_DISTRIBUTED_TRACING_ENABLED=true.

3. La pieza custom: aceptar el W3C del mensaje

En MessageDispatcher, dentro de la transacción del mensaje:

txn.AcceptDistributedTraceHeaders(
    msg.TraceContext,                       // carrier: el JSON del mensaje
    static (carrier, key) =>                // getter tolerante
        carrier.TryGetValue(key, out var v) ? [v] : [],
    TransportType.Other);                   // no existe WebSocket; Other

Si el cliente incluyó traceparent en el JSON, este mensaje queda enlazado a la traza del origen; si no, tu servidor comienza una traza nueva.

4. Qué verás al final

En New Relic → Distributed tracing:
  Trace (traceId 4bf92f35…)
   ├─ Span (agente): WebTransaction/.../WS /ws        ← upgrade HTTP
   └─ Span (custom, OtherTransaction): ProcessTrade   ← tu mensaje
       ├─ Span (custom): Validate  (symbol, isValid)
       ├─ Span (custom): Apply     (priceValue, applyMs)
       └─ Span (agente): http externo (si hicieses HttpClient real)

3 · Ejemplo mínimo

Verifica el flujo de datos con estas dos consultas tras generar tráfico:

SELECT count(*) FROM Transaction WHERE appName = 'NotificadorWebSocket'
SELECT count(*) FROM Span     WHERE appName = 'NotificadorWebSocket'

Si ambas devuelven filas, el pipeline agente → NRDB funciona y las trazas se están registrando (con muestreo).

4 · Ejemplo real

Flujo de verificación end-to-end:

  1. Ejecuta la app con agente + env.
  2. Envía un trade con un traceparent (o sin él).
  3. Abre All capabilities → Distributed tracing, filtra por tu app.
  4. Busca la traza cuyo primer/solo span se llame ProcessTrade: ábrela.
  5. Anota traceId, los spans (Validate/Apply) y sus atributos.

Consulta para validar que la cadena del mensaje es un árbol:

SELECT timestamp, name, guid, parentId, duration.ms
FROM Span
WHERE appName = 'NotificadorWebSocket' AND name LIKE '%ProcessTrade%'
ORDER BY timestamp
LIMIT 20

6 · Errores habituales

Aceptar el contexto sin transacción creada

// ❌ Accept antes de que exista la transacción del mensaje
AcceptTrace(msg.TraceContext);   // no enlaza nada

// ✅ Primero [Transaction] sobre OnMessage; dentro, Accept (así está en el proyecto)

El traceId «no aparece» en el trace buscado

El traceId del mensaje se propaga si el cliente manda traceparent válido; si manda solo traceId (sin tracestate) el agente puede empezar otra traza. Lleva el contexto completo (traceparent/tracestate) en el carrier (y saneido 00-<32 hex>-<16 hex>-<flags>).

7 · Ejercicio guiado

  1. Paso 1: Adjunta el agente (paquete + env) y ejecuta la app.
  2. Paso 2: Envía 20 mensajes mixtos (ping/trade), con y sin traceparent.

8 · Reto

🎯 End-to-end con un cliente real

Añade a un cliente WebSocket propio la generación de un traceparent aleatorio por mensaje. Envía 10 mensajes y demuestra (por NRQL) que los 10 generaron traces con ese traceId único y bien formado. Bonus: envía uno con formato inválido y observa cómo lo trata el servidor.

9 · Resumen

  • Profiler vía paquete + env; DT por defecto en agentes 10.x.
  • AcceptDistributedTraceHeaders en cada mensaje enlaza el W3C del JSON.
  • El trace del WebSocket: upgrade (agente) + ProcessTrade (custom) + fases (spans).

10 · Preguntas frecuentes

¿Puedo ver «todos» mis traces o solo una muestra?

Con standard distributed tracing el agente muestrea (por defecto ~10/min). Si necesitas el 100%, evalúa Infinite Tracing (tail-based). Para el curso, la muestra basta.

¿El traceparent del cliente es fiable?

Es input del cliente: sánalo (formato/longitud). El agente descarta traceparent inválido e inicia traza nueva; documenta el caso.
