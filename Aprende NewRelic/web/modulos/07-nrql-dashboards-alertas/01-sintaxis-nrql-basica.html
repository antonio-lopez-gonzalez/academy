Sintaxis NRQL: SELECT, FROM, WHERE, SINCE, TIMESERIES

Módulo 7 · NRQL, Dashboards y Alertas ⏱ 40 minutos

1 · Introducción

NRQL (New Relic Query Language) es como SQL pero para series temporales: le pides agregaciones sobre un tipo de evento (transacción, span, log, métrica, custom) en una ventana de tiempo. Es el idioma con el que construirás dashboards y alertas.

Esta lección fija el tronco: SELECT, FROM, WHERE, FACET, SINCE/UNTIL, TIMESERIES, LIMIT/AS y las reglas de comillas.

2 · Teoría

La estructura mínima

SELECT (agregadores)
FROM   (tipo de evento: Transaction, Span, Log, Metric, customEvent, ...)
[WHERE filtro]
[FACET grupo]
[SINCE ventana] [UNTIL fin] [TIMESERIES paso] [LIMIT n] [AS etiqueta]

Ejemplo con todo «compacto»:

SELECT count(*), average(duration) AS 'duración media'
FROM Transaction
WHERE appName = 'NotificadorWebSocket' AND name LIKE '%ProcessTrade%'
FACET messageType
SINCE 1 day ago UNTIL 30 minutes ago
TIMESERIES 1 hour

Agregadores clave

FunciónUso
count(*)nº de eventos
average(attr)media
sum(attr), min(attr), max(attr)agregados clásicos
percentile(attr, 50, 90, 99)percentiles (clave en WebSocket)
rate(fn, 1 minute)ratio por unidad de tiempo
percentage(fn, WHERE cond)% que cumple una condición
uniqueCount(attr) / uniques(attr)cardinalidad / valores únicos
latest(attr) / earliest(attr)último / primero
apdex(attr, t: 0.5)Apdex con umbral
filter(fn, WHERE cond)agregación condicional inline

Cláusulas de tiempo

  • SINCE: ventana (por defecto «1 hour ago»).
  • UNTIL: fin (exclusivo; por defecto NOW).
  • TIMESERIES: divide en buckets (1 minute, AUTO, MAX).
  • COMPARE WITH: compara períodos (p. ej. semana pasada).

Comillas y nombres raros

  • Strings de valor y etiquetas AS: comillas simples (AS 'mi etiqueta', WHERE state = 'WA').
  • Atributos que son palabras reservadas o con espacios: acentos graves `attribute name`.
  • No uses comillas dobles en NRQL.

3 · Ejemplo mínimo

-- Mi primera query serie temporal: mensajes por minuto
SELECT rate(count(*), 1 minute)
FROM Transaction
WHERE name LIKE 'OtherTransaction/%'
TIMESERIES 1 minute
SINCE 15 minutes ago

Verás la evolución minuto a minuto de tu WebSocket.

4 · Ejemplo real

Un «panel de operaciones» del WebSocket en 4 consultas:

-- 1) Por tipo de mensaje (última hora)
SELECT count(*) FROM Transaction FACET messageType SINCE 1 hour ago

-- 2) Percentiles de duración por tipo
SELECT percentile(duration, 50, 95, 99) FROM Transaction
FACET messageType SINCE 1 hour ago

-- 3) Latencia de cola (métrica custom)
SELECT average(metricTimeslice.value), max(metricTimeslice.value)
FROM Metric WHERE metricName = 'Custom/QueueLatencyMs' SINCE 1 hour ago

-- 4) Comparativa con la semana pasada
SELECT percentile(duration, 95) FROM Transaction
SINCE 1 day ago COMPARE WITH 1 week ago TIMESERIES 1 hour

Con esto ya sabes «si hoy es peor que la semana pasada» sin mirar nada más.

6 · Errores habituales

Comillas dobles / acentos mal

-- ❌ WHERE appName = "api"  → error de parseo
-- ✅ WHERE appName = 'api'
-- ❌ FACET `message type` en vez de atributo real

-- Etiquetas:
-- ❌ AS "mi tabla"
-- ✅ AS 'mi tabla'

Agregador que no va con el tipo

-- ❌ average(metricTimeslice.value) FROM Transaction  (no es una métrica de ese tipo)
-- ✅ FROM Metric ... WHERE metricName = '...'

7 · Ejercicio guiado

  1. Paso 1: Abre el Query Builder de tu cuenta.
  2. Paso 2: Ejecuta SHOW EVENT TYPES SINCE 1 day ago.
  3. Paso 3: Con Transaction, escribe: count + avg + p95 por messageType, con TIMESERIES 5 minutes.
  4. Paso 4: Cambia UNTIL y COMPARE WITH y observa el resultado.

8 · Reto

🎯 Tu query «firma»

Define la consulta que querrías tener SIEMPRE en el dashboard principal de tu WebSocket: debe combinar volumen + p95 + errores, facet por tipo, y una comparativa. Justifica cada cláusula en 2 líneas.

9 · Resumen

  • NRQL = agregaciones sobre eventos en una ventana temporal.
  • Percentiles > media para latencias; TIMESERIES para evolución.
  • Comillas simples para strings/etiquetas; acentos graves para atributos raros.

10 · Preguntas frecuentes

¿Puedo usar JOIN entre tipos?

NRQL admite JOIN de tipos en algunos planes (y subqueries). Para empezar, usa dos queries con el traceId común (M5-02).

¿Por qué me da «0» una query que «seguro» tiene datos?

Revisa: el tipo del evento, el nombre exacto del atributo (mayúsculas/espacios), la ventana SINCE, el appName, y el atributo (¿está en TODOS los eventos?).
