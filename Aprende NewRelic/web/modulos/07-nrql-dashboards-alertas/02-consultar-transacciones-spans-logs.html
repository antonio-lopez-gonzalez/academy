Consultar Transactions, Spans, Logs y custom events

Módulo 7 · NRQL, Dashboards y Alertas ⏱ 30 minutos

1 · Introducción

Sabes la sintaxis; ahora afina el «sobre qué» consultas. Cada tipo de evento tiene sus atributos: Transaction, Span, Log, Metric y tus custom events. Elegir bien el FROM es 80% de una buena query.

Aquí tienes el «menú» con las consultas típicas de un WebSocket instrumentado.

2 · Teoría

Descubrir en vez de adivinar: SHOW EVENT TYPES y SELECT keyset() FROM Log te enseñan los atributos reales que tienes.

3 · Ejemplo mínimo

Las 4 consultas «de bolsillo» del WebSocket:

-- Transacciones por tipo (volumen)
SELECT count(*) FROM Transaction FACET messageType SINCE 1 hour ago

-- Errores por clase, separando esperados
SELECT count(*) FROM TransactionError
FACET error.class, error.expected SINCE 1 hour ago

-- Spans más lentos de hoy (top 10)
SELECT name, max(duration.ms) AS 'max ms'
FROM Span FACET name SINCE 1 hour ago ORDER BY max(duration.ms) DESC LIMIT 10

-- Logs de error por nivel
SELECT count(*) FROM Log WHERE level = 'ERROR' FACET appName SINCE 6 hours ago

4 · Ejemplo real

Con un custom event OrderPlaced (emitido en M8 con RecordCustomEvent):

-- Órdenes por moneda (facet de negocio)
SELECT count(*) FROM OrderPlaced FACET currency SINCE 24 hours ago

-- Importe medio por moneda
SELECT average(amount), sum(amount) FROM OrderPlaced FACET currency

-- Comparativa órdenes hoy vs ayer
SELECT count(*) FROM OrderPlaced SINCE 1 day ago COMPARE WITH 1 day ago

Y la consulta estrella para «correlacionar todo» de un mensaje concreto:

SELECT message, level, timestamp FROM Log WHERE MessageId = '887'

6 · Errores habituales

Consultar un atributo de transacción en Log

-- ❌ FROM Log WHERE messageType = 'trade'
-- ✅ FROM Transaction WHERE messageType = 'trade'
-- ✅ FROM Log WHERE Type = 'trade'   (si lo pusiste en tus logs)

Esperar que el custom event exista sin haberlo generado

Los eventos OrderPlaced solo existen si tu código hizo RecordCustomEvent (M8). Comprueba primero SHOW EVENT TYPES.

7 · Ejercicio guiado

  1. Paso 1: Ejecuta SHOW EVENT TYPES y anota los tipos que tiene tu cuenta.
  2. Paso 2: Escribe la consulta de transactions por messageType y la de errores por error.class.
  3. Paso 3: Elige una de tus métricas Custom/ y dibuja su serie temporal.
  4. Paso 4: Si tienes un log de un mensaje concreto, obtén la fila con su MessageId.

8 · Reto

🎯 El dashboard «soporte»

Diseña 5 consultas que un soporte usaría para contestar «el trade X tardó y falló»: localízalo en Transaction, Span, Log, TransactionError y Metric (si aplica). Escríbelas y marca cuál le pedirías a un cliente «que te pegue el traceId».

9 · Resumen

  • Elige bien el FROM: Transaction (petición), Span (árbol), Log (detalle), Metric (serie), custom event (negocio).
  • Descubre atributos con SHOW EVENT TYPES/keyset().
  • Un traceId enlaza los 5 tipos para el postmortem.

10 · Preguntas frecuentes

¿TransactionError es un tipo aparte?

Sí: es el evento de error asociado a una transacción. Tiene sus propios atributos (error.class, …).

¿Puedo consultar la duración en Log?

Solo si la pusiste como atributo de tu log. La duración «sintética» vive en Transaction/Span, no en Log.
