Transacciones web en ASP.NET Core

Módulo 2 · Transacciones, Métricas y Errores ⏱ 30 minutos

1 · Introducción

La transacción es la unidad que la UI de APM usa para hablar de tu app: «una petición atendida». Que las entiendas bien importa porque de ellas derivan Apdex, dashboards y alertas — y porque nombrarlas mal fragmenta todos tus datos.

Verás qué es una transacción web, cómo la captura el agente en ASP.NET Core, cómo renombrarlas y cómo ignorarlas cuando no aportan.

2 · Teoría

Qué es una transacción

Un evento Transaction representa una unidad de trabajo con duración y resultado. El agente distingue dos familias que determinan su nombre de métrica:

FamíliaCómo se creaPrefijo de nombre
WebTransactionPeticiones HTTP entrantes (ASP.NET Core, MVC, Minimal API). Se mide con Apdex.WebTransaction/...
OtherTransactionTrabajo no HTTP: workers, consolas, colas… y todo lo que instrumentes custom (tu WebSocket). No afecta a Apdex web por defecto.OtherTransaction/...

En tu app, el upgrade del WebSocket y los endpoints /api/* generan WebTransactions. El procesamiento de mensajes, cuando lo instrumentes, serán OtherTransactions (verás el patrón exacto en el Módulo 4).

Cómo se captura en ASP.NET Core

HTTP request
   │
   ▼
ASP.NET Core pipeline  ←─ el profiler captura aquí el start/end
   │
   ▼
evento Transaction { name: 'WebTransaction/ASP/MINIMAL/GET/api/status', duration, http.statusCode, appName, traceId }
   │
   ▼ (con distributed tracing) spans: httpx 1 llamada, datastore, segmentos

El nombre por defecto incluye ruta del endpoint. ¡Cuidado! Con rutas dinámicas tipo /api/orders/{id} el agente normaliza el parámetro para no fragmentar, pero cualquier enfoque artesanal puede romperlo.

Nombrar transacciones

A veces quieres un nombre más legible o agrupar varias rutas. Usa SetTransactionName(category, name) dentro de la transacción:

app.MapGet("/api/status", () =>
{
    NewRelic.Api.Agent.NewRelic.SetTransactionName("WebAPI", "Status");
    return Results.Ok(new { status = "ok", utc = DateTimeOffset.UtcNow });
});

El nombre final será WebTransaction/WebAPI/Status. Cambiar nombres fragmenta los datos históricos; por eso: establécelo bien desde el principio.

Ignorar transacciones ruidosas

// Health checks y poling interno no aportan a dashboards:
app.MapGet("/healthz", () =>
{
    NewRelic.Api.Agent.NewRelic.IgnoreTransaction();
    return Results.Ok();
});

3 · Ejemplo mínimo

var builder = WebApplication.CreateBuilder(args);
var app = builder.Build();

app.MapGet("/api/status", () =>
{
    // Deja huella de la "versión" en la transacción (M2-04 amplía)
    NewRelic.Api.Agent.NewRelic.GetAgent().CurrentTransaction
        .AddCustomAttribute("version", builder.Configuration["App:Version"] ?? "dev");

    return Results.Ok(new { status = "ok" });
});

app.Run();

Tras llamarlo, la transacción aparece en APM con nombre WebTransaction/ASP/.../GET/api/status y atributo version.

4 · Ejemplo real

En una app con varios endpoints y un WebSocket, define la política de nombre:

// Endpoints: agrupados por dominio, con nombre estable
app.MapPost("/api/broadcast", (BroadcastRequest req) =>
{
    NewRelic.Api.Agent.NewRelic.SetTransactionName("API", "Broadcast");
    NewRelic.Api.Agent.NewRelic.GetAgent().CurrentTransaction
        .AddCustomAttribute("audience", req.Audience);
    // ...
});

// Health checks: invisibles para APM
app.MapGet("/healthz", () =>
{
    NewRelic.Api.Agent.NewRelic.IgnoreTransaction();
    return Results.Ok();
});

Las transacciones quedan estables (WebAPI/Broadcast) aunque cambies el path interno, y el ruido de health checks no contamina tus Agregadores.

6 · Errores habituales

Transacciones fragmentadas por IDs en el path

// ❌ Dos registros por cada orderId distinto
app.MapGet("/api/orders/{orderId}", (Guid orderId) => ...);

// ✅ Nombra con dominio estable para agrupar
app.MapGet("/api/orders/{orderId}", (Guid orderId) =>
{
    NewRelic.Api.Agent.NewRelic.SetTransactionName("API", "GetOrder");
    ...
});

Usar el nombre default que codifica el método HTTP y el path largo

El default es útil para debugging, no para dashboards. Define nombres de dominio cuando sepas que el público del dashboard es operaciones.

9 · Resumen

  • Una transacción = unidad de trabajo con duración; WebTransaction (HTTP) vs OtherTransaction (custom/WS).
  • El agente captura automáticamente los endpoints de ASP.NET Core.
  • Nombres estables y de dominio: SetTransactionName; ruido fuera: IgnoreTransaction.

10 · Preguntas frecuentes

¿Qué pasa si llamo SetTransactionName dos veces?

La última llamada gana para ese transaction. Usa uno por transacción, en un punto claro.

¿Los WebSockets generan transacciones por mensaje?

No, solo el upgrade HTTP inicial. El procesamiento de cada mensaje lo deberás instrumentar tú como OtherTransaction (Módulo 4).

¿Health checks ignorados siguen gastando datos?

No se reportan como transacción si llamas a IgnoreTransaction() antes de terminar; es la práctica recomendada para sondas.
