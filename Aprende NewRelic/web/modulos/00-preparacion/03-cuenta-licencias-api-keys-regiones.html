Cuenta, licencias, API keys y regiones

Módulo 0 · Observabilidad y New Relic ⏱ 30 minutos

1 · Introducción

Antes de instalar el agente necesitas tres cosas de tu región de New Relic: una cuenta, un ingest license key (para que los agentes puedan enviar datos) y un user key (para leer: consultas, API REST, NerdGraph). Confundir cuál es cuál, o mezclar claves de regiones, es el primer error típico de instalaciones.

Verás también por qué la región importa (UE vs. EE.UU.) y cómo se mide el consumo (la «green band» de tu cuenta).

¿Por qué importa? Porque tu agente solo habla con el collector de su región. Manda una clave de la región EU a un collector US y recibirás «401 Unauthorized» o el famoso «no data for app» con el agente perfectamente instalado.

2 · Teoría

Tipos de claves

ClavePara quéDónde se usa
License key (ingest)Autenticar el envío de datos: agente .NET, OTLP, API de eventosNEW_RELIC_LICENSE_KEY, newrelic.config, header OTLP api-key
User API keyAutenticar lectura y gestión: REST API, NerdGraph, exportar consultasHeader Api-Key en llamadas a api.newrelic.com / api.eu.newrelic.com

Regiones y endpoints

RegiónCollector del agenteOTLPAPI (NerdGraph/REST)
UScollector.newrelic.comotlp.nr-data.netapi.newrelic.com
EUcollector.eu.newrelic.comotlp.eu01.nr-data.netapi.eu.newrelic.com

El agente .NET utiliza NEW_RELIC_HOST cuando tu cuenta no está en US. Si omites esto, intentará US y fallará la autenticación o el envío.

Consumo y límites

New Relic factura por consumo de datos (GB que envías) y por usuarios. La cuenta gratuita («Free») incluye una cantidad de datos por mes. Los conceptos que más inflan el consumo: eventos de alta cardinalidad, trazas sin muestrear, logs a tope de volumen y métricas infinitas. A lo largo del curso verás técnicas de muestreo y de elección métrica vs. evento para mantenerte en la green band.

Dónde se crea y gestiona

  • Cuenta: newrelic.com/signup.
  • API keys: one.newrelic.com → Admin → API keys (botón «Ingest — license» o «User»).
  • Alertas de consumo y Green band: en Admin → Usage/Cost.

3 · Ejemplo mínimo

En Linux/macOS (igual en Windows con el panel de variables):

export NEW_RELIC_LICENSE_KEY=YOUR_LICENSE_KEY
export NEW_RELIC_APP_NAME=NotificadorWebSocket
# Si tu cuenta es de la región EU:
export NEW_RELIC_HOST=collector.eu.newrelic.com

dotnet run

Si usas la región US y solo cambias las dos primeras, el agente envía datos. Los tres primeros datos aparecen en APM en ~1-2 minutos.

4 · Ejemplo real

Una app de producción con Kubernetes y secretos:

# deployment.yaml (fragmento)
env:
  - name: NEW_RELIC_LICENSE_KEY
    valueFrom:
      secretKeyRef:
        name: newrelic
        key: ingest-key     # ← nunca en texto plano
  - name: NEW_RELIC_APP_NAME
    value: "NotificadorWebSocket"
  - name: NEW_RELIC_HOST
    value: "collector.eu.newrelic.com"

Nunca comites el license key. En desarrollo usa user-secrets o un archivo local ignorado por git.

6 · Errores habituales

Usar la user key donde va la license key

# ❌ El agente espera el INGEST license key, no la user key
export NEW_RELIC_LICENSE_KEY=NRRA-xxxxxxxxxxxxxxxx # (user key)

# ✅ Nuestra user key NRR... seguirá sirviendo para API/NerdGraph,
# pero el agente necesita la que pone "Ingest - license"
export NEW_RELIC_LICENSE_KEY=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxNRAL

Olvidar la región en el agente

# ¿Cuenta en EU? El agente mira el collector US por defecto
NEW_RELIC_HOST=collector.eu.newrelic.com   # ← necesario

Confiar en el número de datos «a pelo»

Ver «datos» no significa «barato». Vigila la green band y configura muestreo antes de que el volumen crezca con tu WebSocket.

7 · Ejercicio guiado

  1. Paso 1: Crea tu cuenta en newrelic.com/signup y anota tu región.
  2. Paso 2: En one.newrelic.com → Admin → API keys, localiza tu ingest license key y tu user key.
  3. Paso 3: Guarda la license key en una variable de entorno temporal y ejecuta echo $env:NEW_RELIC_LICENSE_KEY (o el equivalente de tu shell) para confirmar que está disponible.
  4. Paso 4: Guarda NEW_RELIC_APP_NAME=NotificadorWebSocket.

8 · Reto

🎯 Consumo consciente

Con tu cuenta en blanco, escribe en un comentario de código (o un archivo README) el plan de consumo para tu WebSocket: qué enviarás como métricas, qué como eventos, qué como trazas (con muestreo) y qué como logs. Justifícalo mirando la green band. Lo verás una vez instrumentes la app.

9 · Resumen

  • License key (ingest) = enviar datos; user key = leer/consultar.
  • Región importa: agente, OTLP y API tienen cada uno su endpoint.
  • El consumo se mide en GB/usuarios y se controla con muestreo y diseño de datos.
  • Las claves se gestionan en → Admin → API keys y nunca se commitean.

10 · Preguntas frecuentes

¿Qué hago si veo «401 Unauthorized» en el agente?

Revisa: es el license key y no la user key; la región coincide con tu cuenta; no hay espacios o saltos de línea al copiar la clave.

¿El free tier es suficiente para el curso?

Sí. Con la green band gratuita puedes instrumentar la app de ejemplo, enviar trazas y logs, y hacer dashboards. El curso cuida el volumen.

¿Necesito más de un license key?

Uno por cuenta suele bastar; algunas organizaciones usan uno por entorno (dev/prod) para auditar y facturar por separado.
