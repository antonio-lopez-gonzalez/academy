Glosario de TypeScript

Recurso Terminos de los modulos 0-9

Tipos y valores

anotacion de tipo
Escritura explicita del tipo de una variable, parametro o retorno, por ejemplo : number. Es la forma de decirle al compilador tu intencion cuando la inferencia no es suficiente.
inferencia
Capacidad de TypeScript de deducir el tipo de una expresion sin anotarla. let n = 42 infiere number. Es la base del "JavaScript con tipos donde quieras".
tipo primitivo
Los tipos base del lenguaje: string, number, boolean, bigint, symbol, null, undefined. En el runtime son valores; en el tipado son el atomo mas pequeno.
literal type
Un tipo que es un unico valor concreto: "pendiente" o 42. Combinar literales con unions crea conjuntos de valores permitidos.
union type
Tipo formado por dos o mas alternativas: string | null. El valor debe pertenecer a al menos una de las alternativas.
intersection type
Tipo formado por la suma de dos o mas tipos: Base & Extra. El valor debe cumplir todos a la vez (tiene todas las propiedades).
discriminated union
Union en la que cada variante comparte una propiedad literal (el discriminante) y se distingue por ella. Es el patron central para modelar estados y dominios en TypeScript.
narrowing
Proceso por el que el compilador reduce el tipo de un valor dentro de una rama, por ejemplo tras typeof, in, comparaciones o throw con never.
type guard
Funcion o expresion que limita el tipo de un valor dentro de una rama (typeof, instanceof, Array.isArray o un predicate propio).
type predicate
Anotacion de retorno v is Tipo en una funcion que actua como guardia: si devuelve true, el compilador asume el tipo en la rama del if.
assertion
Uso de as (o as const, satisfies) para afirmar un tipo que el compilador no deduce. Solo se debe usar en el borde (datos externos) o cuando se sabe mas que el compilador.
as const
Afirmacion que hace un valor lo mas literal posible: objectos readonly, strings y numeros como literales. Es la alternativa moderna a los enums.
satisfies
Operador que valida que un valor cumple un tipo SIN cambiar el tipo inferido. Mantiene los literales inferidos y comprueba el contrato a la vez.

Estructuras

tuple
Array con un numero y tipos fijos por posicion: [string, number]. Ideal para pares de datos conocidos. Con readonly evitas mutacion.
interface
Declaracion de la forma de un objeto: nombres y tipos de propiedades. Es extensible (declaration merging) y se usa para contratos de objetos y clases.
type alias
Nombre para un tipo: type Id = string. Puede representar unions, tuples, primitivos; las interfaces no pueden (solo objetos y funciones).
index signature
Declaracion que permite acceso dinamico por clave: [clave: string]: number. Define que claves y valores acepta un objeto.
opcional
Propiedad o parametro que puede faltar, marcado con ?. Su tipo incluye implicitamente undefined.
readonly
Modificador que impide reasignar la propiedad (o el array/tuple). Es a nivel de tipos: no existe en el runtime, por eso hay que respetarlo en el codigo.
enum
Estructura de valores nombrados numericos o string. Genera codigo en el runtime; hoy se prefiere as const + unions por ser mas predecible.
branded type
Tipo con una marca simbolica que lo distingue del primitivo base (string & { _marca: "id" }). Evita mezclar valores que comparten forma.

Funciones

function type
Tipo que describe la firma de una funcion: (a: number) => string. Se usa para tipar callbacks y props de componentes.
overload
Varias firmas de llamada para la misma funcion (con un unico cuerpo). El compilador elige la firma segun los argumentos.
parametros rest
Agrupar el resto de argumentos en un array tipado: (...nombres: string[]) => void.
parametros opcionales y por defecto
Los opcionales (?) pueden faltar; los de defecto (= valor) tienen un valor cuando no se pasan. El orden importa: opcionales y rest al final.
generico
Parametro de tipo en funciones, clases o interfaces que se concreta en el uso: function primero<T>(arr: T[]): T. Mantiene la relacion entre entrada y salida.
restriccion extends
Limitar un generico a un subtipo: <T extends string>. Garantiza que T tiene al menos las propiedades base.
declaracion this
Anotar el this de una funcion en el primer parametro falso: function f(this: Config) { ... }.

Tipos especiales y utilidades

any
Escapatoria total: cualquier valor, sin comprobaciones. Solo debe usarse en casos limite; en strict, anotarlo es una senal de alarma.
unknown
El tipo seguro de "algo que aun no se": exige narrowing antes de usarlo. Es el reemplazo correcto de any para datos externos.
never
El tipo del "nunca ocurre": una funcion que siempre lanza, un array vacio, o una rama exhaustiva. Se usa para comprobar exhaustividad de unions.
void
Tipo de retorno de funciones que no devuelven valor (o cuyo valor se ignora). Distinto de undefined: void indica "no me importa el retorno".
null / undefined
Valores de ausencia. Con strictNullChecks hay que tratarlos explicitamente, lo que elimina toda una clase de bugs.
utility types
Tipos predefinidos que transforman otros tipos: Partial, Required, Pick, Omit, Record, Exclude, Extract, ReturnType, Parameters, Awaited, Readonly, NonNullable.
keyof
Operador que extrae las claves de un objeto como union de literales: keyof Tarea es "id" | "titulo" | ....
indexed access
Acceso a un tipo por clave: T["titulo"] devuelve el tipo de esa propiedad. Base de los mapped types.
mapped type
Tipo construido recorriendo las claves de otro: { [K in keyof T]: T[K] }. Permite transformar cada propiedad (opcional, readonly, valor).
conditional type
Tipo que elige entre dos ramas segun una condicion: T extends U ? A : B. Es el "if" del sistema de tipos.
infer
Palabra clave que extrae un tipo dentro de un conditional type: T extends infer U ? U : never. Se usa en ReturnType, Parameters, Promise, etc.
template literal type
Tipo literal con interpolacion: `/tarea/${string}`. Genera unions de strings y se usa para rutas, eventos y patrones.

Modulos, configuracion y herramientas

module
Archivo con imports/exports. TypeScript sigue los modulos ES; el alcance por archivo evita colisiones globales.
import type / export type
Importar solo el tipo, sin codigo de runtime. Permite borrar las importaciones de tipos en el bundle (verbatimModuleSyntax).
declaration file
Archivo .d.ts con solo tipos: describe una API o un global sin codigo de runtime. Es la interfaz publica de una libreria.
tsconfig.json
Archivo de configuracion del compilador: target, module, strict, paths, etc. Es el contrato de tu proyecto.
strict
Grupo de opciones que activa las comprobaciones mas estrictas (strictNullChecks, noImplicitAny...). El curso lo usa siempre.
noImplicitAny
Prohibe que un tipo quede en any implicito (por ejemplo parametros sin anotar). Te obliga a decidir el tipo explicitamente.
strictNullChecks
Trata null y undefined como valores reales que hay que manejar. Elimina errores de "null" en runtime.
compilador nativo (tsgo)
El port de TypeScript a Go (desde TS 6/7): ~10x mas rapido, compatible con el mismo tsconfig y comportamiento.
tsc
El compilador de TypeScript (tsc -b en modo build). Comprueba tipos y (si se configura) emite JavaScript.
esbuild
Bundler/transpilador en Go que usa Vite para transformar TS a JS en desarrollo y build. Borra tipos pero NO los comprueba.
vite
Servidor de desarrollo y empaquetador de aplicaciones web. Con TypeScript via esbuild + tsc -b para el chequeo de tipos.
vitest
Corredor de tests nativo de Vite. Ejecuta tests escritos en TypeScript en Node con describe/it/expect.
monorepo
Varios paquetes en un solo repositorio. TypeScript los coordina con project references y tsc -b.
project references
Declarar dependencias entre tsconfigs (references) para compilar proyectos en orden y cachearlos por pieza.
strict mode (React)
En React, utilidad de desarrollo que monta dos veces los componentes para detectar efectos impuros. No confundir con strict de TypeScript.
props / hooks
En React con TS: las props se tipan con interfaces y los hooks (useState, useEffect) se tipan con genericos. Todo el flujo queda tipado.
