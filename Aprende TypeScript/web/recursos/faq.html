Preguntas frecuentes

Recurso Dudas habituales del curso

Empezando con TypeScript

¿TypeScript es un reemplazo de JavaScript?

No. Es un superset: todo JavaScript valido es TypeScript valido. Anade un sistema de tipos que se borra al compilar. Al final, el navegador ejecuta JavaScript normal.

¿Debo aprender TS si ya se JavaScript?

Si. TypeScript no cambia como se programa JavaScript: anade una capa que detecta errores antes de ejecutar. La mayoria de ofertas profesionales piden TypeScript, y dominarlo te hace mas preciso en proyectos grandes.

¿TypeScript va mas lento que JavaScript en el navegador?

No: en runtime es el mismo JavaScript (los tipos se borran en la compilacion). La "velocidad" se percibe solo en el tiempo de compilacion/desarrollo, y con el compilador nativo en Go (TS 7) es similar a un transpilador rapido.

¿Que version de TypeScript debo usar?

La ultima estable. Este curso usa TypeScript 7 (compilador nativo en Go), y todo el codigo es compatible con 5.9+. Manten la que uses en tu trabajo; la sintaxis de este curso compila en ambas.

¿Por que el curso pide modo strict?

Porque strict es donde TypeScript te protege de verdad: obliga a manejar null, a tipar todo y a eliminar descendentes silenciosos. Si activas strict desde el dia uno, el tipado es consistente y sin trampas.

Conceptos que confunden

¿Cual es la diferencia entre interface y type alias?

Las interfaces describen objetos y se pueden extender por declaracion (merging); con extends en objetos y clases. Los type aliases pueden representar unions, tuplas y primitivos. Regla practica: usa interface para objetos publicos y type para el resto.

¿any y unknown no son lo mismo?

No. any desactiva el chequeo: puedes hacer cualquier cosa sin errores. unknown es la version segura: debes reducir con narrowing antes de usarlo. Para datos externos (JSON, APIs) usa unknown y luego valida.

¿Los enums estan obsoletos?

No son "obsoletos", pero la comunidad tiende a preferir as const + union: mas predecible, sin codigo extra en runtime y con los mismos literales. Este curso ensena ambos y recomienda cuando usar cada uno.

¿Que es el "narrowing" de una vez?

Es reducir el tipo de un valor dentro de una rama: despues de un if (typeof x === "string"), TypeScript sabe que x es string en esa rama. Con ello el mismo codigo JavaScript gana autocompletado y comprobaciones.

¿Necesito usar genericos en mi dia a dia?

Los usas mas de lo que crees: Map<string>, Promise<T>, useState<T>... Escribir genericos propios te permite mantener la relacion entre entrada y salida de funciones y componentes.

¿Que diferencia tsc, esbuild y Vite?

tsc comprueba tipos y (si se pide) emite JS. esbuild transpila rapido borrando tipos pero no los valida. Vite empaqueta con esbuild y delega el chequeo de tipos a tsc -b. Por eso el build de este curso es tsc -b && vite build.

En el trabajo

¿Cuanto TypeScript "de verdad" necesito en mi primer proyecto?

Empieza con strict, tipos para props/funciones y evita any. Con eso ya tienes el 80% de la seguridad. Anade genericos, narrowings avanzados y utility types cuando el codigo te lo pida. No hace falta conocer todo el sistema de tipos para producir.

¿Como migro un proyecto JavaScript a TypeScript?

Paso a paso: 1) anade tsconfig con allowJs y compile en modo check, 2) renombra ficheros a .ts eliminando errores, 3) activa strict poco a poco, y 4) elimina los any restantes. La migracion puede convivir con JS en la misma fase.

¿Debo tipar cada funcion hasta el ultimo detalle?

No: TypeScript es "fuertemente tipado con inferencia". Deja inferir lo obvio (let n = 42) y anota cuando el contexto no alcanza (retornos, props, APIs) o cuando la intencion debe ser explicita. El equilibrio es parte de la seniority.

¿TypeScript evita todos los bugs?

No. Atrapa una familia enorme (valores equivocados, null, typos en nombres) en tiempo de compilacion, pero la logica de negocio sigue siendo tuya: los tests (Vitest) cubren el comportamiento runtime y el tipado cubre los contratos.

¿Cuanto rinde en rendimiento y como controla el bundle?

En runtime no anade coste (los tipos se borran). En el bundle, importa con import type para que los tipos no generen codigo, y usa verbatimModuleSyntax. El resto lo gestiona el bundler (Vite).

Herramientas y configuracion

¿Que es una .d.ts y cuando la creo?

Es un archivo de solo tipos: describe la API de un modulo o un global sin codigo de runtime. La creas cuando escribes librerias (declaraciones publicas) o cuando describes librerias JS de terceros sin tipos.

¿tsconfig serve o la compila Vite?

Vite no usa tsconfig para compilar (via esbuild), pero si lo lee para configuraciones como paths y jsx. El chequeo de tipos lo hace tsc aparte. Por eso en este curso pnpm build ejecuta primero tsc -b.

¿Debo commitear node_modules y dist?

No. node_modules se regenera con pnpm install (usa el lockfile) y dist/ es una salida de build. Nunca se suben al repo. El lockfile (pnpm-lock.yaml) SI se commitea para reproducibilidad.

¿Progreso y tema se sincronizan entre dispositivos?

No: viven en localStorage de tu navegador. Es una web estatica sin backend, pensada para tu uso local. Para sincronizar, usa el mismo navegador o una cuenta de sincronizacion del navegador.
