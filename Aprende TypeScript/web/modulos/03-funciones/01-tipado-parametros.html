Tipado de parametros y retorno

Modulo 3 · Funciones 🕐 30 minutos

1 · Introduccion

Las funciones son los limites del sistema: lo que entra (parametros) y lo que sale (retorno). Aqui aprendes a tiparlas con precision: tipos de parametros, de retorno, parametros opcionales, valores por defecto y rest params. Es la base para callbacks, overloads y genericos de las siguientes lecciones.

2 · Teoria

La firma de una funcion

La firma es lo que describimos con tipos: parametros y retorno.

function sumar(a: number, b: number): number {
  return a + b;
}
//                ▲        ▲       ▲
//               tipo de a, tipo de b, tipo de retorno

Tipos de retorno: explicito vs inferido

TypeScript infiere el retorno casi siempre; anotalo cuando la funcion es publica o compleja:

function doble(x: number) {
  return x * 2;            // inferido: number (no hace falta anotarlo)
}

function config(): Config { // anotado: es publica y queremos explicitar
  return { puerto: 3000 };
}

Parametros opcionales y valores por defecto

// Opcional con "?": puede venir o no (undefined).
function saludar(nombre: string, apellido?: string): string {
  return apellido ? `${nombre} ${apellido}` : nombre;
}

// Valor por defecto: como JS, aplica si llega undefined.
function saludar2(nombre: string, apellido = "Lopez"): string {
  return `${nombre} ${apellido}`;
}

Diferencia sutil: con ? el tipo es string | undefined y decides en runtime. Con valor por defecto, el parametro se comporta siempre como string (si omiten el valor, entra el default). Los opcionales deben ir al final de la lista.

Rest params

// ...numeros recoge TODOS los argumentos extra en un array de number.
function total(...numeros: number[]): number {
  return numeros.reduce((acc, n) => acc + n, 0);
}

console.log(total(1, 2, 3, 4)); // 10

El rest params siempre es un array (...x: T[]) y debe ir al final. Es el tipado natural de "recibe n argumentos del mismo tipo".

Retorno void: la funcion no devuelve nada util

function logear(mensaje: string): void {
  console.log(mensaje);
  // sin return: el tipo es void
}

void tambien aparece cuando una funcion devuelve undefined explicitamente (como return sin valor).

Comprobacion estricta de argumentos

En TypeScript no puedes llamar a una funcion con el numero de argumentos equivocado (salvo que uses parametros opcionales). Con strict activo, la funcion te exige los argumentos que declaraste. Es otra diferencia con JavaScript puro.

3 · Ejemplo minimo

firma-minima.ts
// Retorno inferido: number.
function cuadrado(n: number) {
  return n * n;
}

// Parametro opcional + retorno explicito.
function etiqueta(nombre: string, precio?: number): string {
  return precio !== undefined ? `${nombre}: ${precio} €` : nombre;
}

// Rest params.
function unir(sep: string, ...partes: string[]): string {
  return partes.join(sep);
}

console.log(cuadrado(4));        // 16
console.log(etiqueta("Teclado")); // "Teclado"
console.log(unir("-", "a", "b", "c")); // "a-b-c"

4 · Ejemplo real

Un servicio de descuentos con varias firmas tipadas:

descuentos.ts
// Opcional: cupon con valor por defecto (0 = sin descuento).
function precioFinal(precio: number, cupon = 0): number {
  const aplicar = cupon > 0 ? cupon : 0;
  return Math.max(0, precio - aplicar);
}

// Rest params para precios multiples.
function totalCarrito(...precios: number[]): number {
  return precios.reduce((acc, p) => acc + precioFinal(p), 0);
}

// Objeto como parametro (desestructurado y tipado).
interface Opciones {
  descuento?: number;   // opcional
  esVip?: boolean;      // opcional
}

function conOpciones(precio: number, { descuento = 0, esVip = false }: Opciones = {}): number {
  const dto = descuento + (esVip ? 5 : 0);
  return Math.max(0, precio - dto);
}

console.log(totalCarrito(10, 20, 30));          // 60
console.log(precioFinal(50, 10));                // 40
console.log(conOpciones(50, { esVip: true }));   // 45

Decisiones:

  • cupon = 0: la API de la funcion dice "puedes pasar un cupon; si no, 0".
  • ...precios: number[]: acepta cualquier numero de argumentos numericos.
  • El parametro objeto desestructurado con defaults: patron clasico de opciones; el tipo Opciones = {} permite llamar sin argumentos.

5 · Buenas practicas

  • Tipa SIEMPRE los parametros; deja que el retorno se infiera salvo en funciones publicas.
  • Usa ? para opcionales que si faltan quieres tratar como "ausencia" y default para valores con respaldo sencillo.
  • Opcionales y rest al final de la firma.
  • Para muchas opciones, usa un objeto tipado como parametro en vez de 6 parametros: mas legible y extensible.
  • Retorna void explicitamente en funciones con efectos secundarios.

Que evitar

  • Parametros de tipo any: el error se propaga a todo lo que toque la funcion.
  • Muchos parametros posicionales booleanos (orden facil de equivocar): usa un objeto de opciones.
  • Anotar el retorno cuando la inferencia ya es exacta y la funcion es privada.

6 · Errores habituales

Mal — numero de argumentos equivocado 
function suma(a: number, b: number): number { return a + b; }
suma(1);   // ✖ Se esperaban 2 argumentos, pero se recibio 1
Bien — opcional o default 
function suma(a: number, b = 0): number { return a + b; }
suma(1); // ✅ b = 0
Mal — retornar otro tipo al declarado 
function precio(importe: number): number {
  return importe.toFixed(2); // string no es asignable a number
}
Bien — retorno coherente 
function precio(importe: number): number {
  return Number(importe.toFixed(2)); // number
}
Mal — opcional con valor por defecto a la vez (redundante) 
function f(a?: number = 5) {} // ✖ sintaxis invalida
Bien — elegir una 
function f(a = 5) {} // ✅ default basta

9 · Resumen

  • Firma: tipos de parametros + tipo de retorno.
  • Retorno inferido normalmente; anotalo en funciones publicas.
  • Opcional ?, default =, rest ...: T[].
  • void para funciones de solo efectos.
  • Objeto tipado como parametro para muchas opciones.

10 · Preguntas frecuentes

¿Puedo mezclar opcionales con obligatorios?

Si, pero los opcionales van despues de los obligatorios. function f(a: string, b?: number) es correcto; a la inversa no tiene sentido.

¿Por que mi funcion con return condicional da "number | undefined"?

Porque en alguna rama no hay return. TypeScript deduce el retorno union de todas las salidas. O cubre todas las ramas con return o retorna un default explicito.

¿Rest params es lo mismo que un array normal?

En runtime si (el compilador lo trata como array). La diferencia es la firma: ...numeros: number[] permite llamar con 0..n argumentos sueltos, no con un array.

¿Por que debo tipar los parametros y no el retorno?

Los parametros son el limite de entrada: sin tipo, TypeScript asume any (con strict, error). El retorno se infiere del cuerpo casi siempre. Tipa lo que el compilador no puede saber por si solo.

¿Que pasa si llamo a una funcion y me faltan argumentos?

Error de compilacion (TS2554). TypeScript comprueba el numero y los tipos de argumentos en cada llamada. Es mas estricto que JS.
