this en TypeScript y declare

Modulo 3 · Funciones 🕐 30 minutos

1 · Introduccion

this es una de las zonas mas confusas de JavaScript. TypeScript puede tiparlo si se lo declaras como primer parametro de la firma, y con noImplicitThis te obliga a hacerlo bien. En esta leccion tambien vemos declare: la palabra que dice "esto existe, pero no lo implementes aqui", clave para los .d.ts del modulo 7.

2 · Teoria

El misterio de this en JavaScript

En JS, this NO se fija por donde se declara la funcion, sino por como se llama. Un método llamada como obj.metodo() usa this = obj; llamada suelta (const f = obj.metodo; f()) usa this = undefined (strict) o window (no strict). 

const usuario = {
  nombre: "Ada",
  saludar() { return `Hola ${this.nombre}`; }
};
usuario.saludar();          // "Hola Ada"
const suelto = usuario.saludar;
suelto();                   // 💥 this es undefined/global → rompe

Tipando this como primer parametro

TypeScript permite declarar this como primer parametro (no cuenta como argumento real):

// Declaramos el tipo de this que espera la funcion.
function imprimir(this: { nombre: string }): string {
  return `Hola ${this.nombre}`;
}

const p = { nombre: "Ada", imprimir };
p.imprimir();          // ✅ this = p, que tiene nombre
// const f = p.imprimir;
// f();                // ✖ this está mal ligado (sin el objeto)

Este primer parametro es puramente de tipos: se borra en el build. Pero le da al compilador la informacion que necesita para avisarte cuando this esta "descolgado".

noImplicitThis

Dentro de strict, si usas this sin declararlo, TypeScript asume any o da error. Es la red que atrapa el "this perdido" tan tipico en JavaScript.

this en callbacks y arrow functions

const contador = {
  n: 0,
  // Arrow function: hereda el this del ambito exterior (el objeto).
  aumentar: () => {
    // este this es el contador (heredado), no se re-liga.
    this.n++;
  },
};

Las arrow functions NO tienen su propio this: capturan el del ambito donde se crearon. Eso las hace ideales para callbacks dentro de metodos.

declare: "existe, pero no lo escribas aqui"

declare le dice al compilador que una variable, funcion, clase o modulo existe en runtime (lo aporta otra cosa: un script, un archivo externo, el navegador), pero que tu no das la implementacion. Es la base de los declaration files .d.ts (modulo 7). 

// Declaramos que "miLibreria" existira en runtime (la inyecta un script).
declare const miLibreria: { version: string; init(): void };

miLibreria.init(); // ✅ compila; el runtime lo provee

Casos tipicos de declare:

  • Variables globales puestas por otro script (window.ga, window.__CONFIG__).
  • Modulos sin tipos (declare module "img/*").
  • Ficheros .d.ts de librerias (allí declare es omnipresente).
Por que declare existe

TypeScript quiere que todo dato tenga un tipo conocido. Cuando el dato lo trae el mundo exterior (un script, una lib sin tipos, el navegador), declare te permite "firmar el cheque" sin implementarlo. Es el puente entre tu codigo y el mundo no tipado.

this tipado en metodos de objeto y clases

interface Boton {
  etiqueta: string;
  onPulsa(this: Boton): void;   // this es el boton
}

const b: Boton = {
  etiqueta: "OK",
  onPulsa() {
    console.log(this.etiqueta); // this: Boton → etiqueta accesible
  },
};

3 · Ejemplo minimo

this-minimo.ts
// Tipamos this como primer parametro (solo tipos).
function mostrarSaldo(this: { saldo: number }): string {
  return `Saldo: ${this.saldo} €`;
}

const cuenta = { saldo: 100, mostrarSaldo };
cuenta.mostrarSaldo(); // ✅ "Saldo: 100 €"

// declare: una variable global que inyecta otro script.
declare const VERSION_APP: string;
console.log(VERSION_APP); // solo compilacion: el runtime la provee

4 · Ejemplo real

Un componente de UI con estado interno (patron clasico de "objeto con metodos"):

caja.ts
// La forma de "this" que esperan los metodos.
interface EstadoCaja {
  valor: number;                 // valor actual
  incrementar(): void;           // +1
  mostrar(): string;             // cadena con el valor
}

// Creamos el objeto que cumple la interface.
const caja: EstadoCaja = {
  valor: 0,

  // this es EstadoCaja: podemos usar this.valor.
  incrementar() {
    this.valor += 1;
  },

  mostrar() {
    return `Valor: ${this.valor}`;
  },
};

// Demostracion: el callback "descolgado" con arrow que usa this NO re-liga.
// Si lo sacamos, this se pierde:
const incrementoSuelto = caja.incrementar;
// incrementoSuelto();  // 💥 this no es EstadoCaja (con noImplicitThis lo sabes)

// Uso correcto: llamamos como metodo del objeto.
caja.incrementar();
caja.incrementar();
console.log(caja.mostrar()); // "Valor: 2"

Decisiones:

  • La interface declara this en los metodos: documenta el contexto y permite que this.valor se autocompleten.
  • El comentario sobre incrementoSuelto demuestra por que noImplicitThis es tu amigo.
  • declare cubre los globales que no controlamos, como configs inyectadas.

5 · Buenas practicas

  • Declara this como primer parametro cuando escribas funciones que dependan del contexto.
  • Usa arrow functions para callbacks que deben conservar el this del ambito.
  • Confia en noImplicitThis: es el vigia de los "this perdidos".
  • En clases, TypeScript ya conoce this; el parametro explicito se usa en funciones sueltas.
  • Para datos que provee el exterior, declara con declare y su tipo, nunca con any.

Que evitar

  • Usar this en arrow functions del nivel top-level: no hay ambito que heredar.
  • Extraer metodos a variables sueltas sin pensar en la ligadura de this.
  • Declarar globales con declare sin tipo: pierde el sentido.

6 · Errores habituales

Mal — usar this en una funcion sin declararlo 
function f() {
  return this.algo; // ✖ con noImplicitThis: 'this' implicitly has type any
}
Bien — declarar this o usar el parametro 
function f(this: { algo: string }): string {
  return this.algo; // ✅
}
Mal — arrow function con this propio 
// No puedes declarar this en una arrow (no tienen contexto propio).
const f = (this: { x: number }) => this.x; // ✖
Bien — arrow hereda el this exterior 
function g() { return () => this.x; } // el this de g se hereda
Mal — declarar variable que ya existe en runtime sin declare 
// Esto intenta CREAR una variable en runtime que YA inyecta un script
// y pisa la global: const VERSION_APP = VERSION_APP;  (confuso)
Bien — declare: solo tipos, sin codigo 
declare const VERSION_APP: string; // el script la provee en runtime

9 · Resumen

  • En JS, this depende de como se llama, no de donde se declara.
  • TypeScript tipa this como primer parametro de la firma (solo tipos).
  • noImplicitThis (parte de strict) atrapa los "this descolgados".
  • Arrow functions heredan el this exterior; no tienen uno propio.
  • declare declara algo que existe en runtime sin implementarlo: base de los .d.ts.

10 · Preguntas frecuentes

¿El primer parametro this cuenta como argumento?

No. Es un "falso parametro" que solo existe a nivel de tipos; en runtime no se pasa ni se borra. Solo se usa para tipar el contexto.

¿Puedo declarar this en arrow functions?

No. Las arrow no tienen this propio: usan el del ambito. Intenta declararlo y TypeScript te lo rechaza.

¿Que es un .d.ts?

Un fichero de declaraciones (no de implementacion) donde se describen los tipos de un modulo o de variables globales. Es el fichero que las librerias distribuyen para que sus usuarios tengan tipos. Lo ampliamos en el modulo 7.

¿declare añade codigo en runtime?

No. declare solo informa al compilador: la declaracion no genera ningun JavaScript. La implementacion la aporta el mundo exterior.

¿Por que en clases no hago falta tipar this?

Porque las clases tienen this "auto": el compilador ya sabe que this es la instancia de la clase. El parametro explicito se reserva para funciones sueltas y callbacks.
