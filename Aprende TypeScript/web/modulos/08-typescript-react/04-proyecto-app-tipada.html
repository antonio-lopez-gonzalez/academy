Proyecto: app tipada con API

Modulo 8 · TypeScript con React 🕐 50 minutos Proyecto

1 · Introduccion

Llega la hora de unir todo lo del curso: una aplicacion React + TypeScript que consume una API real (JSONPlaceholder) con fetch tipado, muestra listas, gestiona estado y navega entre vistas. Todo el codigo corre bajo strict y compila con tsc -b.

El proyecto completo y ejecutable esta en proyectos/08-typescript-react. Aqui construimos los archivos paso a paso, explicando cada decision.

Que vas a construir
  • Una app de posts de blog que trae datos de una API.
  • Vista de lista con estado de carga/error.
  • Detalle de un post con sus comentarios.
  • Persistencia local tipada (favoritos).
  • Un custom hook useFetch generico (leccion 3).

2 · Teoria

La arquitectura en capas

src/ ├── types.ts ← contratos (Post, Comment, User) ├── api.ts ← funciones fetch tipadas ├── hooks/useFetch.ts ← hook generico reutilizable ├── hooks/useLocalStorage.ts ├── components/ ← UI: PostCard, PostDetail, Favoritos └── App.tsx ← composicion y estado global

Separamos tipos (que forma tienen los datos), API (de donde vienen), hooks (logica reutilizable) y componentes (UI). Cada capa con su responsabilidad y todos tipados.

Por que JSONPlaceholder

Una API publica de pruebas con /posts, /posts/:id/comments y /users. No requiere autentificacion y devuelve JSON estable. Ideal para practicar el fetch tipado sin montar un backend.

El flujo de datos tipado

API (JSON) ──► api.ts (fetch) ──► useFetch<T> ──► Componente │ │ │ contrato de as T (borde) datos: T | null tipos (types.ts) cargando, error

El JSON "sin tipar" se valida en el borde (res.json() as T) y a partir de ahi todo el flujo es seguro.

src/api.ts
import type { Post, Comment, User } from "./types";

// Funcion fetch tipada: cada endpoint devuelve su forma exacta.
export async function getPosts(): Promise<Post[]> {
  const res = await fetch("https://jsonplaceholder.typicode.com/posts");
  if (!res.ok) throw new Error(`HTTP ${res.status}`);
  return res.json() as Post[]; // borde: afirmamos la forma
}

export async function getComments(postId: number): Promise<Comment[]> {
  const res = await fetch(
    `https://jsonplaceholder.typicode.com/posts/${postId}/comments`
  );
  if (!res.ok) throw new Error(`HTTP ${res.status}`);
  return res.json() as Comment[];
}

export async function getUser(id: number): Promise<User> {
  const res = await fetch(`https://jsonplaceholder.typicode.com/users/${id}`);
  if (!res.ok) throw new Error(`HTTP ${res.status}`);
  return res.json() as User;
}

4 · Ejemplo real

La aplicacion completa con componentes, hooks y estado:

src/hooks/useFetch.ts
import { useState, useEffect } from "react";

interface FetchEstado<T> {
  datos: T | null;
  cargando: boolean;
  error: string | null;
}

// Hook generico: se reutiliza para posts, comentarios y usuarios.
export function useFetch<T>(url: string): FetchEstado<T> {
  const [datos, setDatos] = useState<T | null>(null);
  const [cargando, setCargando] = useState(true);
  const [error, setError] = useState<string | null>(null);

  useEffect(() => {
    let cancelado = false;
    async function cargar() {
      try {
        const res = await fetch(url);
        if (!res.ok) throw new Error(`HTTP ${res.status}`);
        const json = await res.json() as T;
        if (!cancelado) setDatos(json);
      } catch (e) {
        if (!cancelado && e instanceof Error) setError(e.message);
      } finally {
        if (!cancelado) setCargando(false);
      }
    }
    cargar();
    return () => { cancelado = true; };
  }, [url]);

  return { datos, cargando, error };
}
src/hooks/useLocalStorage.ts
import { useState } from "react";

// Persistencia local tipada con generico.
export function useLocalStorage<T>(clave: string, inicial: T) {
  const [valor, setValor] = useState<T>(() => {
    const crudo = localStorage.getItem(clave);
    return crudo ? (JSON.parse(crudo) as T) : inicial;
  });

  const guardar = (nuevo: T) => {
    setValor(nuevo);
    localStorage.setItem(clave, JSON.stringify(nuevo));
  };

  return [valor, guardar] as const;
}
src/components/PostCard.tsx
import type { Post } from "../types";

interface PostCardProps {
  post: Post;
  favorito: boolean;
  onToggleFavorito: (id: number) => void;
  onAbrir: (id: number) => void;
}

export function PostCard({ post, favorito, onToggleFavorito, onAbrir }: PostCardProps) {
  return (
    <article className="post-card">
      <h2>{post.title}</h2>
      <p>{post.body.slice(0, 120)}...</p>
      <div className="acciones">
        <button onClick={() => onAbrir(post.id)}>Ver detalle</button>
        <button onClick={() => onToggleFavorito(post.id)}>
          {favorito ? "★ Quitar" : "☆ Favorito"}
        </button>
      </div>
    </article>
  );
}
src/App.tsx
import { useState } from "react";
import { useFetch } from "./hooks/useFetch";
import { useLocalStorage } from "./hooks/useLocalStorage";
import { PostCard } from "./components/PostCard";
import { PostDetail } from "./components/PostDetail";
import type { Post } from "./types";

export default function App() {
  const { datos: posts, cargando, error } = useFetch<Post[]>(
    "https://jsonplaceholder.typicode.com/posts"
  );
  const [seleccion, setSeleccion] = useState<number | null>(null);
  const [favoritos, setFavoritos] = useLocalStorage<number[]>("favoritos", []);

  function toggleFavorito(id: number) {
    setFavoritos(
      favoritos.includes(id)
        ? favoritos.filter((f) => f !== id)
        : [...favoritos, id]
    );
  }

  if (seleccion !== null) {
    return (
      <PostDetail
        postId={seleccion}
        onVolver={() => setSeleccion(null)}
      />
    );
  }

  return (
    <main>
      <h1>Posts del blog</h1>
      {cargando && <p>Cargando...</p>}
      {error && <p>Error: {error}</p>}
      {posts?.map((post) => (
        <PostCard
          key={post.id}
          post={post}
          favorito={favoritos.includes(post.id)}
          onToggleFavorito={toggleFavorito}
          onAbrir={setSeleccion}
        />
      ))}
    </main>
  );
}

Decisiones:

  • useFetch<Post[]>: el hook trae los posts tipados; posts?.map navega con seguridad.
  • useLocalStorage<number[]>: los favoritos son numeros, no any.
  • El estado de seleccion es number | null: o no hay post abierto, o hay un id.
  • Los callbacks (onToggleFavorito, onAbrir) están tipados (leccion 2).
  • Todo el flujo (JSON → borde → estado → UI) sin any.

5 · Buenas practicas

  • Define los contratos (types.ts) antes de los componentes: es tu "mapa de datos".
  • Aisla el fetch en api.ts: los componentes no saben de fetch.
  • Tipa el borde (as T) solo en el punto de entrada de datos.
  • Reutiliza hooks genericos en vez de copiar logica por vista.
  • Compila con pnpm build (tsc -b + vite) en cada hito.

Que evitar

  • any en datos de la API: pierdes todo el tipado del flujo.
  • Llamar fetch dentro del componente (acopla UI con transporte).
  • Ignorar el estado de error (una app que no falla "bien" es fragil).
  • Persistir en localStorage sin tipar la lectura.

6 · Errores habituales

Mal — tipar el fetch como any 
const res = await fetch(url);
const data: any = await res.json(); // ✖ se pierde todo
Bien — borde tipado 
const json = await res.json() as Post[]; // ✅ solo aqui se afirma
Mal — callback prop sin tipar 
// Componente que recibe onAbrir sin tipos:
function PostCard({ onAbrir }: any) { /* ... */ }
Bien — contrato de props 
interface PostCardProps {
  onAbrir: (id: number) => void;
  // ...
}
Mal — acceder a post.title sin null-check 
// datos puede ser null mientras carga:
const { datos } = useFetch<Post[]>(url);
datos.map(...) // ✖ datos: Post[] | null
Bien — guardas o optional chaining 
datos?.map((post) => ...) // ✅ con optional chaining

7 · Ejercicio guiado

Vamos a construir la vista de detalle que falta: un post con sus comentarios.

  1. Crea PostDetail.tsx que reciba postId y onVolver.
  2. Usa useFetch<Post>(`.../posts/${postId}`) para el post.
  3. Usa useFetch<Comment[]>(`.../posts/${postId}/comments`) para los comentarios.
  4. Renderea el post y la lista de comentarios (nombre, email, body).
  5. Anade un boton "Volver" que llame a onVolver.

Solucion paso a paso:

src/components/PostDetail.tsx
import { useFetch } from "../hooks/useFetch";
import type { Post, Comment } from "../types";

interface PostDetailProps {
  postId: number;
  onVolver: () => void;
}

export function PostDetail({ postId, onVolver }: PostDetailProps) {
  const { datos: post } = useFetch<Post>(
    `https://jsonplaceholder.typicode.com/posts/${postId}`
  );
  const { datos: comentarios } = useFetch<Comment[]>(
    `https://jsonplaceholder.typicode.com/posts/${postId}/comments`
  );

  return (
    <article>
      <button onClick={onVolver}>← Volver</button>
      {post ? <>
        <h1>{post.title}</h1>
        <p>{post.body}</p>
      </> : <p>Cargando post...</p>}

      <h2>Comentarios ({comentarios?.length ?? 0})</h2>
      {comentarios?.map((c) => (
        <div key={c.id} className="comentario">
          <strong>{c.name}</strong> ({c.email})
          <p>{c.body}</p>
        </div>
      ))}
    </article>
  );
}

9 · Resumen

  • Capas: types.ts (contratos), api.ts (transporte), hooks (logica), components (UI).
  • El borde as T es el unico punto de afirmacion de tipos de datos externos.
  • Hooks genericos (useFetch, useLocalStorage) reutilizan con tipos.
  • Estado: number | null para seleccion; arrays tipados para favoritos.
  • Sin any en todo el flujo; comprobado con tsc -b.

10 · Preguntas frecuentes

¿JSONPlaceholder me funciona en produccion?

Es para desarrollo/demos. En produccion tu app deberia consumir tu propia API. Aqui es el "backend de juguete" perfecto para practicar el fetch tipado.

¿El as T en el borde es seguro?

Es una afirmacion de confianza: le dices al compilador "se que esta forma". Si la API cambia, el error aparece donde se usa el dato. Para validacion real, en el modulo 9 veras schemas con zod.

¿Por que el hook devuelve datos: T | null?

Porque al empezar no hay datos (cargando). Con strict, es mejor ser honesto: T | null te obliga a manejar el caso "aun no hay nada".

¿Necesito redux/zustand para el estado global?

No para este tamano. El estado sube a App y baja por props tipados. Solo añade un state manager cuando el arbol lo pida de verdad.

¿Por que se separan hooks y componentes?

Los hooks contienen logica reutilizable con tipos; los componentes son presentacion. Separarlos hace el codigo testable y evita duplicacion entre vistas.

¿Este proyecto se puede desplegar?

Si: pnpm build genera dist/, que puedes servir en cualquier hosting estatico (Netlify, Vercel, GitHub Pages). En el modulo 9 lo hacemos paso a paso.
