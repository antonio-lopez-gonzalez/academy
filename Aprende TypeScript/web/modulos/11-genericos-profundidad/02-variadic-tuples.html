Variadic tuple types

Modulo 11 · Genericos en profundidad 🕐 30 minutos

1 · Introduccion

Las tuplas de TypeScript ([string, number]) tienen longitud fija, pero el mundo real no: un argumento puede recibir 2 o 20 parametros, una fila de CSV tiene 1 columna fija y N variables, y push/unshift/concat cambian el largo de un array en runtime. Los variadic tuple types (TypeScript 4.0+) llevan esa dinamica al sistema de tipos: un tipo de tupla puede declarar la parte fija y un resto variable con el spread ....

  • Spread tipado de tuplas: [number, ...string[]] tipa cabeza fija y cola variable.
  • Manipuladores de tipos: Push, Unshift, Concat y Zip construyen tuplas nuevas a partir de otras.
  • Funciones reales tipadas: funciones que hacen push/unshift/concat y cuyo retorno cambia con la entrada.
  • infer sobre spreads: extraer el primer o ultimo elemento, o el interior, con condicionales.
  • Acceso tipado: funciones at/rebanado que devuelven pedazos exactos de la tupla.
Cuando se utilizan
  • APIs de eventos donde cada evento trae un payload distinto.
  • Parsers de filas ([id, ...resto]), argumentos de CLI, combinaciones de opciones.
  • Librerias de funciones que prefijan o sufijan parametros (como bind/partial).
  • Cualquier cola donde el "largo exacto" importe en el tipo.

2 · Teoria

Tuplas con cola variadica

Un spread dentro de un tipo de tupla declara "el resto": el tipo repite el patron N veces. La cabecera fija puede estar al principio, al final, o en medio de dos restos. Es como un tren: la locomotora (number) siempre delante, y detras los vagones pueden ser 1 o 100 (...string[]). 

// Cabeza fija + cola variable: 1 numero y cuantos strings haga falta.
type FilaCsv = [id: number, ...valores: string[]];

const fila1: FilaCsv = [7, "Ana", "admin", "granada"]; // ✅ 1 + 3
const fila2: FilaCsv = [3];                            // ✅ 1 + 0
// const fila3: FilaCsv = ["Ana"];                     // ✖ falta el numero

// Cola variable al principio:
type Registro = [...marcas: string[], total: number];
const r: Registro = ["a", "b", 99]; // ✅ 2 strings + 1 numero
Limites del spread de tipos

Un tipo de tupla admite como mucho un rest elemental en cada posicion, y el rest elemental debe ser un array o una tupla: ...string (sin corchetes) es un error. Ademas, el spread no puede ir al final de tipos opcionales/rest ya usados en ciertas posiciones de firma de funcion. Si el compilador se queja, revisa que el rest sea ...T[] o ...T con T tupla.

Manipular tuplas con tipos: Push, Unshift, Concat

Como las tuplas son valores, podemos devolver tuplas nuevas que resulten de operaciones sobre el tipo original. El spread es la herramienta: [...T, U] es "todo T y luego U".

type Push<T extends readonly unknown[], U> = [...T, U];
type Unshift<T extends readonly unknown[], U> = [U, ...T];
type Concat<A extends readonly unknown[], B extends readonly unknown[]> = [...A, ...B];

type Con3 = Push<[1, 2], 3>;          // [1, 2, 3]
type Con0 = Unshift<[2, 3], 1>;       // [1, 2, 3]
type Cinco = Concat<[1, 2], [3, 4]>;  // [1, 2, 3, 4]

Funciones reales con spreads tipados

El salto de calidad llega cuando la funcion usa el patron en sus parametros: TypeScript infiere la tupla T desde el argumento (gracias al patron [...T]) y el retorno queda tipado exacto. Asi se implementan push, unshift y concat tipados en puras funciones. 

// "push" puro: devuelve una tupla nueva con un elemento mas.
function agregar<T extends readonly unknown[], U>(tupla: [...T], valor: U): [...T, U] {
  return [...tupla, valor];
}
const tres = agregar([1, 2], 3); // [1, 2, 3] → numero exacto

// "unshift" puro: elemento al principio.
function prepender<T extends readonly unknown[], U>(valor: U, tupla: [...T]): [U, ...T] {
  return [valor, ...tupla];
}
const invertida = prepender("x", [1, true]); // ["x", 1, true]

// "concat" puro: dos tuplas unidas.
function concatenar<A extends readonly unknown[], B extends readonly unknown[]>(
  a: [...A],
  b: [...B],
): [...A, ...B] {
  return [...a, ...b];
}
const unida = concatenar([1, 2], ["a", "b"]); // [1, 2, "a", "b"]
Por que el patron [...T] en los parametros

Si el parametro fuese simplemente tupla: T con T extends unknown[], TypeScript inferiria T = unknown[]: pierde la tupla exacta. Al escribir [...T] le dices "estoy dispuesto a desarmar y rearmar la forma de entrada", y el compilador infiere la tupla literal ([1, 2] en vez de number[]). Es una senal para la inferencia: quiero la forma, no el array.

Extraer partes con infer

Los spreads tambien se combinan con infer en condicionales para deconstruir la tupla: el ultimo elemento, el primero, el cuerpo.

type Ultimo<T extends readonly unknown[]> = T extends [...infer _Resto, infer U] ? U : never;
type Primero<T extends readonly unknown[]> = T extends [infer F, ...infer _Resto] ? F : never;
type Cuerpo<T extends readonly unknown[]> = T extends [infer _Cabeza, ...infer M] ? M : [];

type U = Ultimo<[1, 2, 3]>;      // 3
type P = Primero<[1, 2, 3]>;     // 1
type M = Cuerpo<[1, 2, 3]>;      // [2, 3]
type V = Ultimo<[string, ...number[]]>; // number (la cola variadica)

El nombre _Resto es una convencion: subraya que no nos importa ese trozo. El compilador lo descarta igual. Esta tecnica es la base de utilidades como extraer el retorno de funciones variadicas o normalizar argumentos de CLI.

Acceso y rebanado tipado: at, cola, toma

El metodo at de los arrays reales devuelve T | undefined. Con tuplas podemos hacerlo mas preciso: indexar por la clave literal de la tupla y obtener exactamente ese tipo.

// Indices de una tupla: las claves "0" | "1" | ... (sin las de Array).
type IndiceDe<T extends readonly unknown[]> = Exclude<keyof T, keyof unknown[]>;

declare function en<T extends readonly [unknown, ...unknown[]], I extends IndiceDe<T>>(
  tupla: T,
  indice: I,
): T[I];

const mix: [string, number, boolean] = ["a", 1, true];
const letra = en(mix, "0");   // string
const numero = en(mix, "1");  // number
// const mal = en(mix, "length"); // ✖ length es de Array, no de la tupla

// Rebanado: quitar la cabeza con la "cola" tipada.
type Cola<T extends readonly unknown[]> = T extends [unknown, ...infer R] ? R : [];

function cola<T extends readonly [unknown, ...unknown[]]>(tupla: T): Cola<T> {
  const [, ...resto] = tupla;
  return resto as Cola<T>;
}
const sinCabeza = cola([1, 2, 3]); // [2, 3]

Para "tomar los primeros N" recurrimos a un contador de tipos: acumulamos con length del resultado parcial.

type Toma<T extends readonly unknown[], N extends number, Acc extends unknown[] = []> =
  Acc["length"] extends N
    ? Acc
    : T extends [infer H, ...infer R]
      ? Toma<R, N, [...Acc, H]>
      : Acc;

type PrimerosDos = Toma<[1, 2, 3, 4], 2>; // [1, 2]

3 · Ejemplo minimo

variadico-minimo.ts
// 1) Cola variadica: un numero y N strings.
type Linea = [id: number, ...tags: string[]];
const l1: Linea = [1, "ts", "tipos"]; // ✅
const l2: Linea = [2];               // ✅

// 2) Push tipado.
type Push<T extends readonly unknown[], U> = [...T, U];
type P = Push<[1, 2], 3>; // [1, 2, 3]

// 3) La funcion real devuelve la tupla exacta.
function agregar<T extends readonly unknown[], U>(tupla: [...T], valor: U): [...T, U] {
  return [...tupla, valor];
}
const resultado = agregar([true, "a"], 9); // [true, "a", 9]

// 4) Ultimo elemento con infer.
type Ultimo<T extends readonly unknown[]> = T extends [...infer _, infer U] ? U : never;
type U = Ultimo<["a", "b", "c"]>; // "c"

Linea a linea:

  • [id: number, ...tags: string[]]: la parte fija queda tipada y el resto se repite a gusto.
  • Push<[1, 2], 3>: puro calculo de tipos, sin runtime.
  • agregar([true, "a"], 9): el patron [...T] fuerza la inferencia de la tupla literal.
  • [...infer _, infer U]: el guion bajo descarta el resto y saca el ultimo tipo.

4 · Ejemplo real

Un emisor de eventos donde cada tema tiene su propio payload (una tupla distinta), mas un parser de filas para un fichero CSV estadistico. Ambos casos son imposibles de tipar bien sin variadic tuples.

eventos-y-csv.ts
// 1) Mapa de eventos: cada tema declara su payload como tupla.
interface MapaEventos {
  click: [x: number, y: number];
  tecla: [codigo: string, presionado: boolean];
  carrito: [producto: string, cantidad: number];
}

type Tema = keyof MapaEventos;

class Emisor {
  private escuchadores = new Map<Tema, Array<(...args: unknown[]) => void>>();

  // El spread de una tupla en la firma: ...args: MapaEventos[E]
  on<E extends Tema>(tema: E, cb: (...args: MapaEventos[E]) => void): void {
    this.escuchadores.set(tema, [...(this.escuchadores.get(tema) ?? []), cb]);
  }

  emitir<E extends Tema>(tema: E, ...args: MapaEventos[E]): void {
    for (const cb of this.escuchadores.get(tema) ?? []) {
      cb(...args); // el spread en runtime casa con el spread del tipo
    }
  }
}

const bus = new Emisor();
bus.on("click", (x, y) => console.log(x, y));           // ambos numeros
bus.on("tecla", (codigo, presionado) => { /* ... */ }); // string y boolean
// bus.emitir("click", "izquierda"); // ✖ "izquierda" no es number

// 2) Fila de CSV: la cabecera es siempre un numero y luego N valores.
type FilaEstadistica = [anio: number, ...valores: number[]];

function promedio(fila: FilaEstadistica): number {
  const [, ...valores] = fila; // rebanado con spread de runtime
  return valores.reduce((acc, v) => acc + v, 0) / Math.max(valores.length, 1);
}

const datos: FilaEstadistica[] = [
  [2020, 10, 12, 9], // anio + 3 valores
  [2021, 11, 8],     // anio + 2 valores
];
console.log(promedio(datos[0])); // el spread de runtime devuelve la parte variable

Decisiones:

  • MapaEventos[E] es una tupla; al hacer ...args: MapaEventos[E] el callback recibe la forma exacta del payload de cada tema.
  • El spread de runtime (cb(...args)) queda sincronizado con el de tipos por construccion: si cambia el mapa, cambia la firma del handler.
  • [anio: number, ...valores: number[]] es "headers tipados": el anio no se mezcla con la serie de datos.
  • const [, ...valores] = fila demuestra el patron en datos reales: la primera posicion se ignora y el resto es un number[].
  • Errores claros: bus.emitir("click", "izquierda") falla porque el payload de click exige numeros.

5 · Buenas practicas

  • Usa readonly en las restricciones (T extends readonly unknown[]): aceptas tuplas inmutables y mutables sin perder precision.
  • Nombra con _ los trozos que descartas en infer: el codigo se lee solo.
  • Pon la cabecera fija de la tupla donde semanticamente este: id primero, cola variable despues.
  • Prefiere funciones puras (agregar, concatenar) sobre mutar arrays: el tipo de retorno siempre representa el estado final.
  • Combina con as const en llamadas para que los literales no se ensanchen a string/number.

Que evitar

  • Restricciones any[] en spreads: pierdes todo el beneficio de la precision.
  • Tuplas gigantes (decenas de elementos): el compilador pagara caro la recursion en infer/Toma.
  • Mas de un rest elemental en posiciones dudosas de firmas: comprueba que el compilador acepta el orden.
  • Usar spread tipado donde un Array<T> basta: si la longitud no importa, no declares una tupla.

6 · Errores habituales

Mal — rest elemental sin forma de array o tupla 
type Rota = [numero: number, ...resto: string]; // ✖ el rest debe ser array o tupla
Bien — rest como array o como tupla 
type Ok1 = [numero: number, ...resto: string[]]; // array
type Ok2 = [...resto: ["a", "b", "c"]];            // tupla fija
Mal — restriccion que tumba la inferencia de la forma 
function agregar<T extends unknown[]>(tupla: T, valor: unknown): T {
  return [...tupla, valor]; // ✖ T no sabe que crecio; pierde la forma
}
Bien — patron [...T] que conserva la tupla en el retorno 
function agregar<T extends readonly unknown[], U>(tupla: [...T], valor: U): [...T, U] {
  return [...tupla, valor]; // ✅ retorno [1, 2, 3] si entra [1, 2]
}
Mal — indexar una tupla con indice generico sin cuidar las claves 
declare function en<T extends readonly unknown[]>(t: T, i: number): T[i]; // ✖ i debe ser clave
Bien — el indice se restringe a las claves de la tupla 
type IndiceDe<T extends readonly unknown[]> = Exclude<keyof T, keyof unknown[]>;
declare function en<T extends readonly [unknown, ...unknown[]], I extends IndiceDe<T>>(
  t: T,
  i: I,
): T[I]; // ✅ Solo claves reales como "0" | "1"

7 · Ejercicio guiado

Construye una utilidad que "normalice" argumentos tipados: queremos Concat, un ultimo y una funcion encolar (push) que devuelva la tupla exacta.

  1. Define type Concat<A extends readonly unknown[], B extends readonly unknown[]> = [...].
  2. Define type Ultimo<T extends readonly unknown[]> con un infer sobre el spread.
  3. Escribe function encolar<T, U>(cola: [...T], valor: U): [...T, U].
  4. Prueba: encolar(["a", 1], true) debe dar ["a", 1, true].
  5. Comprueba que Ultimo<["x", 9]> es 9.

Solucion paso a paso:

ejercicio-variadico.ts
type Concat<A extends readonly unknown[], B extends readonly unknown[]> = [...A, ...B];
type Unido = Concat<[1], [2, 3]>; // [1, 2, 3]

type Ultimo<T extends readonly unknown[]> = T extends [...infer _, infer U] ? U : never;
type Diez = Ultimo<["x", 9]>; // 9

function encolar<T extends readonly unknown[], U>(cola: [...T], valor: U): [...T, U] {
  return [...cola, valor];
}

const colaFinal = encolar(["a", 1], true); // ["a", 1, true]

// Uso combinado: sacamos el ultimo de la tupla resultante.
type DeColaFinal = Ultimo<typeof colaFinal>; // true

9 · Resumen

  • Los variadic tuple types ([number, ...string[]]) tipan cabeceras fijas con colas variables.
  • Push, Unshift, Concat y Zip son calculos puros de tipos con spreads.
  • El patron [...T] en parametros fuerza la inferencia de la tupla literal en funciones reales.
  • infer sobre spreads extrae primero, ultimo, cuerpo o posiciones concretas.
  • Funciones at/rebanado con IndiceDe y Cola devuelven pedazos exactos de la tupla.

10 · Preguntas frecuentes

¿Que diferencia hay entre [...T] y T como parametro?

[...T] le dice al compilador que estas dispuesto a descomponer la forma de entrada; asi infiere la tupla literal ([1, 2]) en lugar de number[]. Con T plano, la inferencia se queda en el array amplio y pierdes precision.

¿Por que un array real entra en restricciones readonly unknown[]?

Porque unknown[] y readonly unknown[] son supertipos de cualquier tupla; el readonly solo dice "no voy a mutarlo", no "el dato es inmutable". Acepta lo que le des y conserva la forma.

¿Los spreads de tipos funcionan en posiciones medias?

Si: [number, ...string[], boolean] es valido (cabeza, resto, cola). El compilador calcula cuantos elementos van a cada lado segun el resto. Con dos restos en posiciones distintas es posible, aunque la inferencia se vuelve mas lenta y fragile.

¿Cuando elijo tuple en vez de Array<T>?

Cuando la posicion importa (coordenadas, parametros, fila con cabecera) o cuando quieres precision de longitud. Si solo necesitas "una lista de T", un Array<T> es mas simple y el compilador lo maneja mejor.

¿Puedo usar variadic tuples en overloads?

Si, y es un combo potente: overloads que difieren en la cola variadica (por ejemplo, una funcion bind que prefiere argumentos) mantienen cada rama tipada. Aun asi, antes de anadir overloads mira si un solo generico variadico lo resuelve: menos codigo, menos superficie de error.

¿Por que el reto de Zip con recursion "cuenta" en el compilador?

Porque cada llamada recursiva instancia tipos hasta la condicion de corte. TypeScript limita la profundidad (normalmente 50 niveles por defecto, configurable con tsc --extendedDiagnostics o de manera interna). Para tuplas cortas (menos de ~30 elementos) es perfecto; no lo uses para arrays de miles.
