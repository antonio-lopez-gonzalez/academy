Restricciones extends

Modulo 5 · Genericos 🕐 30 minutos

1 · Introduccion

Un generico sin limite acepta cualquier tipo. Pero casi siempre necesitas saber algo concreto de T para operar: que tiene una propiedad length, que es un objeto con id, que es un numero. La restriccion extendido (sintaxis T extends Restriccion) establece un "requisito minimo" que el tipo real debe cumplir.

Resuelve el problema del "necesito una garantia": antes de extends tendrias que comprobar en runtime con typeof, o usar any y perder seguridad. Con restricciones, TypeScript verifica en compilacion que quien llama a una funcion generica trae un tipo compatible, y te permite acceder a las propiedades que sabes que existiran.

Cuando se utilizan
  • Funciones que operan sobre "cosas con length" (strings, arrays, listas).
  • Utilidades que requieren que T tenga cierta forma (id, nombre).
  • Claves de objetos (keyof, modulo 5, leccion 3).
  • Estructuras que solo aceptan subtipos de un tipo base.

2 · Teoria

La analogia: el requisito del trabajo

Cuando contratas a alguien no aceptas "a cualquiera": exiges al menos saber JavaScript. No sabes si sabra React, o testing, o arquitectura, pero garantizas el minimo. La restriccion generica es eso mismo: <T extends { sabeJS: true }> dice "cualquier T, pero que tenga como minimo esta forma". TypeScript garantiza que el T real cumple el minimo, y por tanto puedes tocar sus propiedades en la implementacion.

T extends { length: number } ▲───────┤───────┐ │ │ │ string Array Set ⟵ tiposs que cumplen (estructuralmente) │ │ length: number (requisito minimo)

Sintaxis y que significa "compatible"

Escribes <T extends Limite, ...>. "Compatible" significa asignabilidad estructural: que T sea un subtipo de Limite. No es herencia de clases: es "cabe dentro del tipo limite". 

// La restriccion mas clasica: algo con .length.
function longitud<T extends { length: number }>(valor: T): number {
  return valor.length; // TypeScript SABE que T tiene length: numero
}

longitud("hola");      // ✅ string tiene length
longitud([1, 2, 3]);   // ✅ arrays tienen length
// longitud(42);       // ✖ number no tiene length — falla en compilacion

El resultado del tipo restringido

La restriccion no convierte a T en el limite: sigue siendo T (el tipo especifico). Solo añade el requisito de que existan las propiedades del limite: 

function longitud<T extends { length: number }>(valor: T): number {
  return valor.length;
}
const n = longitud("hola");  // n: number (no "string")
// Puedes seguir sabiendo que es string FUERA, porque la restriccion no borra T
const s: string = "hola";
longitud(s); // ok

Restricciones a primitivos y tipos base

// Restriccion a string: solo strings (y sus subtipos literales).
function formatea<S extends string>(s: S): string {
  return s.toUpperCase();
}
formatea("hola");   // ✅
// formatea(42);    // ✖ number no es string

// Restriccion a objetos con id numerico.
type ConIdentidad = { id: number };
function buscar<T extends ConIdentidad>(item: T, id: number): T | undefined {
  return item.id === id ? item : undefined;
}
const libro = { id: 1, titulo: "Dune" };
buscar(libro, 1); // ✅ compatible (libro tiene id: number y mas)

Restricciones entre multiples parametros

Un parametro puede restringir a otro, expresando dependencia: 

// K es "una clave de T": el segundo parametro depende del primero.
function obtenerValor<T, K extends keyof T>(objeto: T, clave: K): T[K] {
  return objeto[clave];
}

const user = { nombre: "Ana", edad: 30 };
obtenerValor(user, "nombre"); // string ✅
obtenerValor(user, "edad");   // number ✅
// obtenerValor(user, "email"); // ✖ "email" no es clave de user
Por que la notacion de dependencia

K extends keyof T dice: "K puede ser cualquier clave de T". El retorno T[K] es el tipo del valor de esa clave. TypeScript infiere T del primer argumento y valida K contra las claves reales: autocompletado y errores en compilacion. Si usaras string en vez de K, perderias el vinculo entre la clave y su valor.

Restricciones a clases base y shape objects

class Animal { constructor(public nombre: string) {} }
class Perro extends Animal { ladrar() { console.log("guau"); } }

function presentar<T extends Animal>(a: T): string {
  return `Hola, soy ${a.nombre}`;
}

presentar(new Animal("Bicho")); // ✅
presentar(new Perro("Rex"));    // ✅ Perro es un Animal

El valor por defecto con extends

// Tipo por defecto: si no se infiere, T = { length: number }.
type ConLongitud<T extends { length: number } = string> = T;

const a: ConLongitud = "x";   // usa el default: string
const b: ConLongitud<number[]> = [1]; // ✅
// const c: ConLongitud<number> = 5; // ✖ number no tiene length

3 · Ejemplo minimo

extends-minimo.ts
// Requisito: "todo lo que tenga .length, como minimo".
function longitud<T extends { length: number }>(valor: T): number {
  return valor.length;
}

const a = longitud("abc");      // 3 (string)
const b = longitud([1, 2, 3]);  // 3 (number[])
// const c = longitud(5);       // ✖ number no cumple el requisito

Linea a linea:

  • T extends { length: number }: T debe tener la propiedad length de tipo number.
  • En el cuerpo, valor.length compila porque TypeScript conoce la garantia.
  • longitud(5) falla: el requisito minimo no se cumple, y el error aparece en la llamada (no en la implementacion).

4 · Ejemplo real

Un sistema de alertas que muestra cualquier entidad con nombre e id, con seguridad de tipos:

alertas.ts
// Base de datos minima que nuestros registros deben cumplir.
interface Registro {
  id: number;
  nombre: string;
}

// La funcion generica muestra la alerta sin perder el tipo real.
function alertar<T extends Registro>(registro: T, motivo: string): string {
  return `[${registro.id}] ${registro.nombre}: ${motivo}`;
}

// Entidades concretas que cumplen el requisito (estructuralmente).
const usuario = { id: 7, nombre: "Ana", rol: "admin" };
const pedido = { id: 900, nombre: "P-900", total: 45 };

console.log(alertar(usuario, "acceso denegado"));
// "[7] Ana: acceso denegado"

console.log(alertar(pedido, "reembolso"));
// "[900] P-900: reembolso"

// La funcion no necesita saber los campos extra (rol, total):
// solo exige id y nombre. T sigue siendo el tipo completo.
const nombreUsuario: string = usuario.nombre; // ok, sigue tipado

Decisiones:

  • La restriccion extends Registro exige el minimo, pero la funcion es reutilizable para cualquier entidad con id + nombre.
  • Los objetos extra (rol, total) son permitidos: la asignabilidad estructural los acepta (duck typing).
  • Si una nueva entidad no tuviera id, un error de compilacion apareceria en la llamada, no en la funcion. El contrato se avisa en el punto de uso.

5 · Buenas practicas

  • Piensa en la restriccion como el contrato minimo, no como el tipo "verdadero". Menos exigencia = mas reutilizable.
  • Usa keyof T con extends para dependencias entre parametros (leccion 3).
  • Da un default (= ...) cuando el generico sea comunmente omitido.
  • Preferelo a any: la restriccion da acceso a propiedades con seguridad, any no.
  • Coloca la restriccion en el parametro mas "segun" el cual dependa el resto (orden logico, de T hacia K).

Que evitar

  • Restricciones demasiado anchas que acepten lo que no deberian.
  • Restricciones demasiado estrechas que hagan la funcion casi inutil.
  • Usar extends cuando solo quieres el tipo base (<T extends Animal> puede reducirse a tipar el parametro Animal si no usas T).
  • Olvidar que extends no vive en runtime: solo compilacion.

6 · Errores habituales

Mal — usar T sin restriccion y acceder a propiedades 
function idioma<T>(objeto: T): string {
  return objeto.lang; // ✖ Error: T no garantiza .lang
}
Bien — restringe al minimo con .lang 
function idioma<T extends { lang: string }>(objeto: T): string {
  return objeto.lang; // ✅ compila: la restriccion lo garantiza
}
Mal — tratar la restriccion como si "volviera" el tipo limite 
function getID<T extends { id: number }>(objeto: T): string {
  // T no es un objeto nuevo: sigue siendo el tipo de entrada
  return String(objeto.id);
}
Bien — el retorno refleja la transformacion real 
function getID<T extends { id: number }>(objeto: T): number {
  return objeto.id; // devuelve number, no una cadena
}
Mal — restriccion a clase en vez de shape 
// Depende de la herencia de clases:
function pepita<T extends Perro>(x: T): string { return "ok"; }
// ✖ Un objeto con nombre y ladrar() pero sin clase Perro no pasa
Bien — restriccion estructural (shape) 
function pepita<T extends { ladrar(): void }>(x: T): string { return "ok"; }

7 · Ejercicio guiado

Crea una funcion etiquetar que añada una fecha a cualquier objeto con id.

  1. Define conId = { id: number }.
  2. Escribe function etiquetar<T extends conId>(x: T): T & { creadoEn: Date }.
  3. Devuelve { ...x, creadoEn: new Date() }.
  4. Comprueba que el resultado tiene id, las props originales y creadoEn.

Solucion paso a paso:

ejercicio-restricciones.ts
type conId = { id: number };

function etiquetar<T extends conId>(x: T): T & { creadoEn: Date } {
  return { ...x, creadoEn: new Date() };
}

// Probamos con un objeto que tiene id + campos extra:
const libro = { id: 1, titulo: "El Quijote" };
const etiquetado = etiquetar(libro);

// etiquetado: { id: number; titulo: string } & { creadoEn: Date }
const t: Date = etiquetado.creadoEn; // ✅
const ti: string = etiquetado.titulo; // ✅ se preserva el tipo original

9 · Resumen

  • T extends Limite exige un requisito minimo al parametro de tipo.
  • La restriccion ofrece acceso a las propiedades del limite dentro de la funcion, con seguridad.
  • Es asignabilidad estructural: objeto compatible "cabe" aunque tenga mas propiedades.
  • Los parametros pueden depender entre si (K extends keyof T).
  • El tipo real se conserva: extends no convierte T en el limite.

10 · Preguntas frecuentes

¿Por que recibo "Type 'number' does not satisfy the constraint" si paso un numero a algo con length?

Porque number no tiene .length. La restriccion extends { length: number } exige una propiedad, y los numeros primitivos no la tienen. Solo strings, arrays, Set, Map, etc.

¿extends significa herencia de clases?

No necesariamente. En genericos, extends significa "es asignable estructuralmente a": cualquier subtipo del limite. La herencia de clases es solo un caso particular donde la clase base cumple el contrato.

¿Puedo llamar a una funcion restringida con un tipo que cumpla mas de lo exigido?

Si. En TypeScript, un objeto con propiedades extra es asignable a un tipo que solo requiere un subconjunto (extra props si el origen es un literal pueden avisar, pero en variables normales se permiten).

¿Que diferencia hay entre T extends Animal y parametro tipado Animal?

Si necesitas devolver el tipo concreto (T) o usarlo en otro generico, T extends Animal conserva el valor especifico. Si solo consumes el parametro como Animal, tiparlo directamente es mas simple.

¿Las restricciones se comprueban en runtime?

No. Solo en compilacion. En runtime los genericos desaparecen. Si necesitas validar la forma de datos de entrada, usalo en el borde (parsing de JSON) o con una libreria de schemas.

¿Puedo restringir al valor por defecto en una interfaz generica?

Si: interface Almacen<T, U = string> { ... }. El default es opcional para quien contrate el tipo.
