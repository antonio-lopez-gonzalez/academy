Tipos primitivos, inferencia y anotaciones

Modulo 1 · Tipos basicos 🕐 30 minutos

1 · Introduccion

Empieza el verdadero lenguaje. En esta leccion conoces los tipos primitivos de TypeScript y las dos formas de asignarlos: dejar que el compilador los infiera o escribirlos explícitamente. Tambien entenderas que "string", "number" y "boolean" son mas que etiquetas: son conjuntos de valores posibles, una idea que usaras todo el curso.

Ya sabes JavaScript, asi que la sintaxis de los valores no es nueva. Lo nuevo es el vocabulario que les asigna tsc y como aprovecharlo para que el editor te ayude en vez de estorbar.

2 · Teoria

Un tipo es un conjunto de valores

La forma correcta de pensar: string no es "una cadena", es el conjunto infinito de todas las cadenas posibles. number es el conjunto de todos los numeros. Escribir let x: number significa "x solo puede tomar valores de ESE conjunto". Esta lectura como conjuntos explica casi todo lo que veras: union, interseccion, literales, narrowing.

Analogia: el embudo

Un tipo es un embudo por el que solo caben ciertos valores. boolean deja pasar solo true y false. number deja pasar cualquier numero. TypeScript te avisa cuando intentas meter por el embudo un valor que no cabe.

Inferencia vs anotacion

const nombre = "ana"; ▲ └── el compilador OBSERVA el valor y deduce el tipo (INFERENCIA) const edad: number = 30; ▲ └── nosotros DECLARAMOS el tipo (ANOTACION)

Inferencia: TypeScript mira tu valor inicial y deduce el tipo. Es su superpoder.

let ciudad = "Madrid";      // inferido: string
let total = 9.99;           // inferido: number
let activo = true;          // inferido: boolean

Anotacion: escribimos el tipo con : cuando queremos imponerlo o cuando el valor inicial no deja claro el conjunto.

let ciudad: string = "Madrid"; // lo mismo, pero escrito explicitamente

¿Cual usar? La regla de oro:

Regla de oro

Deja que TypeScript infiera las variables locales inicializadas. Anota los limites: parametros de funciones, valores que llegan de fuera, y cuando el tipo inferido no es el que quieres.

const vs let cambia la inferencia

Aqui esta la primera sorpresa: el tipo de una constante es mas estrecho (un literal):

const puerto = 3000;   // tipo: 3000 (el LITERAL, no number)
let puerto2 = 3000;    // tipo: number (porque puede cambiar)

const no puede reasignarse, asi que TypeScript sabe que siempre sera 3000. let puede cambiar, por eso el tipo se amplia a number. A este proceso de "estrechar el tipo de los literales" lo veras a fondo en la leccion de const assertions.

null, undefined y el "strictNullChecks"

Con strict activo, null y undefined son valores que NO se asignan automaticamente a string ni number. La famosa pregunta "¿que pasa si no viene?" se vuelve explicita: 

let email: string = null;   // ✖ error TS2322: null no es asignable a string
let email2: string | null = null; // ✅ optamos explicitamente por "puede ser null"

Ese | es un union type: el valor puede ser de uno u otro conjunto (lo dominaras en el modulo 4). Por ahora interioriza que en TypeScript estricto, "puede faltar" hay que decirlo.

3 · Ejemplo minimo

primitivos.ts
// 1. Inferencia: el compilador deduce el tipo del valor inicial.
let nombre = "Ada";          // nombre: string
let anios = 36;              // anios: number
let cursa = true;            // cursa: boolean

// 2. Anotacion explicita: nosotros declaramos el tipo.
let ciudad: string = "Londres";
let salario: number = 0;
let activo: boolean = false;

// 3. TypeError evitado antes de ejecutar:
// anios = "treinta y seis"; // ✖ error TS2322: string no es asignable a number

// 4. bigint y symbol, primitivos menos comunes.
const cuentasEstrella: bigint = 9223372036854775807n;
const idUnico: symbol = Symbol("sesion");

Linea por linea:

  1. Con let nombre = "Ada" tsc infiere string. No hace falta anotarlo.
  2. Las anotaciones sirven para imponer el conjunto deseado.
  3. La linea comentada demuestra que la reasignacion con el tipo equivocado falla en compilacion.
  4. bigint con n al final y symbol para identificadores unicos.

4 · Ejemplo real

Una tarjeta de perfil de usuario de una red social. Los primitivos aparecen por todas partes:

perfil.ts
// Datos que pueden venir de una API. Los anotamos explicitamente
// porque "no hay valor inicial" que el compilador pueda mirar.
let nombre: string;        // nombre mostrado
let seguidores: number;    // cuantos te siguen
let verificado: boolean;   // si tiene el check azul
let bio: string | null;    // puede faltar: o hay texto o hay null

// Asignacion con el tipo correcto.
nombre = "Ada";
seguidores = 1_024_000;    // los guiones bajos solo separan digitos: 1024000
verificado = true;
bio = "Matematica y primera programadora.";

// Funcion tipada que recibe primitivos y devuelve una cadena.
function resumenPerfil(nombre: string, seguidores: number): string {
  // typeof comprueba en runtime si bio es string (narrowing básico).
  const resumen = typeof bio === "string" ? bio : "Sin bio";
  return `${nombre}: ${seguidores} seguidores — ${resumen}`;
}

console.log(resumenPerfil(nombre, seguidores));

Decisiones:

  • bio: string | null documenta una decision de dominio: "la bio puede no estar". El compilador te fuerza a gestionar el caso null en todo uso.
  • 1_024_000 es la misma cifra que 1024000 pero legible. TypeScript soporta separadores de digitos.
  • Los primitivos tipados en los limites de la funcion hacen el contrato explicito.
El peligro silencioso

En JavaScript, seguidores podria ser "1M" y el resumen seguiria funcionando (con concatenacion). TypeScript detecta que "1M" no es number y lo rechaza. Ese rechazo es la diferencia entre un bug visible y uno invisible.

5 · Buenas practicas

  • Usa inferencia para variables locales con valor inicial; no escribas : string redundante.
  • Anota parametros de funciones siempre: es el limite del sistema.
  • Primitivos en minuscula: string, number, boolean, nunca String.
  • Representa la ausencia de forma explicita: string | null en vez de dejar que undefined aparezca solo.
  • Mantén strict activo: el strictNullChecks es lo que hace segura esta leccion.

Que evitar

  • Anotar todo ("over-annotation"): es ruido y dificulta el mantenimiento.
  • Usar el tipo Number (mayuscula) o String creyendo que son equivalentes.
  • Confiar en == o typeof para "descubrir" el tipo sin declararlo.

6 · Errores habituales

Mal — anotar el obvio 
const nombre: string = "Ana"; // redundante: la inferencia ya da string
Bien — dejar inferir 
const nombre = "Ana"; // string inferido por el compilador
Mal — confundir String con string 
let saludo: String = "hola"; // el tipo es la CLASE String (con S mayuscula)
Bien — primitivo en minuscula 
let saludo: string = "hola"; // el primitivo de toda la vida
Mal — olvidar que null no entra sin avisar 
let apodo: string;
apodo = null;  // ✖ error TS2322: null no es asignable a string
Bien — decir explicitamente que puede faltar 
let apodo: string | null;
apodo = null; // ✅ decidido de forma consciente

Por que estan mal: el ruido anota lo evidente; String abre la puerta a confundir primitivo con objeto; y omitir | null deja el error para mas tarde, que es justo lo que evitamos con tipos.

7 · Ejercicio guiado

Crea un pequeño "formulario de pedido" tipado:

  1. Declara producto, unidades y envioGratis usando inferencia (los valores que veas).
  2. Añade descuento: number | null y asigna null (una decision explicita).
  3. Escribe function total(unidades: number, precio: number): number.
  4. Comprueba que pasar una cadena a total da error TS2345.
Solucion resumida
const producto = "Teclado";     // inferido string
let unidades = 2;               // inferido number
const envioGratis = true;       // inferido boolean
let descuento: number | null = null; // puede faltar

function total(unidades: number, precio: number): number {
  return unidades * precio;
}
// total(2, "99")  // ✖ TS2345: string no es asignable a number

9 · Resumen

  • Un tipo es un conjunto de valores: boolean = {true, false}, number = todos los numeros.
  • Primitivos en minuscula: string, number, boolean, bigint, symbol, null, undefined, void.
  • Inferencia: el compilador deduce el tipo del valor inicial. Anotacion: lo declaras con :.
  • const estrecha a literal; let amplia al tipo general.
  • Con strict, "puede faltar" se declara con | null o | undefined.

10 · Preguntas frecuentes

¿Debo escribir el tipo de TODAS las variables?

No. Inferencia para lo local, anotacion para limites y para cuando quieres imponer un tipo concreto (como number | null).

¿Que diferencia hay entre number y Number?

number es el tipo primitivo (valores como 1, 2.5). Number es la funcion/objeto envoltorio. Anota siempre con minuscula.

¿Por que const puerto = 3000 da el tipo literal "3000"?

Una constante no cambia nunca, asi que el compilador puede fijar el conjunto a un unico valor. Eso permite que 3000 sea utilizable donde se espere exactamente ese literal.

¿Es obligatorio manejar null y undefined?

Con strict si: si declaras string | null, cada uso debe comprobar el caso null. Es molesto al principio y te ahorra la categoria completa de bugs "Cannot read property of undefined".

¿Que pasa si uso var?

Funciona igual, pero usa let/const: evita los problemas de ambito historicos de JS y el tipo inferido es mas preciso.
