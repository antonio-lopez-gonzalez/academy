Recursion de tipos con template literals

Modulo 10 · Tipos avanzados 🕐 35 minutos

1 · Introduccion

Los template literal types no solo construyen cadenas tipadas: combinados con infer pueden recorrer una cadena pieza a pieza, como si el compilador tuviera un bucle. Esa es la base de utilidades reales como Split, Join o KebabCase.

El problema que resuelve: a nivel de tipos no existen bucles for ni while. TypeScript es declarativo, asi que la unica forma de "iterar" sobre un string, una tupla o una union es la recursion: un tipo que se llama a si mismo consumiendo una parte de la entrada en cada llamada.

Por que importa hoy

Estas tecnicas aparecen en librerias de enrutado (/users/:id convertida en objetos tipados), en sistemas i18n, en generadores de nombres de eventos y en la validacion de formatos en tiempo de compilacion. Entender la recursion de tipos es el salto que separa "usar tipos" de construir tipos.

2 · Teoria

La analogia: partir un cable hasta el tramo que interesa

Imagina un cable marcado con separadores ("a,b,c"). Para obtener sus tramos, lo cortas por el primer separador, guardas el primer tramo y repites con el resto. La recursion de tipos es exactamente eso: cada llamada consume un tramo y delega el resto en si misma, hasta que la cadena queda vacia (el caso base) y se detiene.

El patron basico: consumir con infer en plantilla

split.ts
// Split: separa la cadena por un separador y devuelve una tupla.
type Split<S extends string, Sep extends string> =
  S extends `${infer Head}${Sep}${infer Tail}`
    ? [Head, ...Split<Tail, Sep>]
    : S extends ""
      ? []
      : [S];

type Segs = Split<"a,b,c", ",">;  // ["a", "b", "c"]
type Vacia = Split<"", ",">;       // []
type SinSep = Split<"solo", ",">;  // ["solo"]

Linea a linea:

  • S extends `${infer Head}${Sep}${infer Tail}`: la plantilla actua como un patron; si coincide, Head captura el trozo hasta el separador y Tail el resto.
  • [Head, ...Split<Tail, Sep>]: acumula el tramo en una tupla y sigue con el resto.
  • Segunda rama: cadena vacia devuelve []. Tercera rama: un tramo sin separador devuelve [S]. Esas dos ramas son el caso base.
La recursion es un bucle declarativo

En JS escribirias "a,b,c".split(",") y el runtime itera. En tipos no hay runtime: la "iteracion" es la recursion, y el compilador la expande en tiempo de compilacion. Por eso la cadena debe acortarse en cada llamada: si nunca se acorta, el compilador aborta con un error de profundidad.

Join: el camino inverso

join.ts
// Join: une una tupla de strings con un separador (recursion sobre tuplas).
type Join<T extends string[], Sep extends string> =
  T extends [infer Head, ...infer Rest]
    ? Head extends string
      ? Rest extends [string, ...string[]]
        ? `${Head}${Sep}${Join<Rest, Sep>}`
        : Head
      : never
    : "";

type Unida = Join<["a", "b", "c"], "-">; // "a-b-c"
type Una = Join<["solo"], "-">;          // "solo"
type Vacio = Join<[], "-">;              // ""

Aqui la recursion consume la tupla en lugar del string: [infer Head, ...infer Rest] separa el primer elemento del resto. Cuando Rest vuelve a ser una tupla no vacia interpolamos el separador; si es el ultimo elemento, lo devolvemos tal cual (sin separador final).

KebabCase: transformar caracter a caracter

kebab.ts
// KebabCase: convierte camelCase en kebab-case letra a letra.
type KebabCase<S extends string> =
  S extends `${infer Head}${infer Tail}`
    ? Head extends Uppercase<Head>
      ? Tail extends ""
        ? Lowercase<Head>
        : `${Lowercase<Head>}-${KebabCase<Tail>}`
      : `${Head}${KebabCase<Tail>}`
    : S;

type Clave = KebabCase<"totalPrecioNeto">; // "total-precio-neto"
type Ruta = KebabCase<"miVariableLarga">;  // "mi-variable-larga"
type Vacio = KebabCase<"">;                // ""

Tres decisiones importantes aqui:

  • S extends `${infer Head}${infer Tail}` consume una letra por llamada; sin un literal entre los dos infer, el primero toma un caracter y el segundo el resto.
  • Head extends Uppercase<Head> detecta una mayuscula: si lo es, ponemos la letra en minuscula y anteponemos un guion (salvo que sea la primera letra, rama Tail extends "").
  • Caso base: : S devuelve la cadena vacia tal cual y termina la recursion.

Limites y rendimiento del compilador

// PELIGRO: recursion sin caso base. El compilador aborta la expansion.
type Loop<S extends string> = `${Loop<S>}${S}`;
// ✖ error TS2589: "Type instantiation is excessively deep and possibly infinite."

// La profundidad de instanciacion esta limitada (del orden de ~50 niveles por defecto).
// Cada caracter o segmento consume un nivel: cadenas muy largas rozan el limite
// aunque la recursion este bien planteada.
type MuyLarga = KebabCase<"abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ012345">;

// Estrategias:
// 1) El caso base va SIEMPRE primero y la entrada decrece en cada llamada.
// 2) Prefiere recursar por segmentos (Split) antes que por caracter cuando puedas.
// 3) Acota el domino: restringe la entrada con extends y evita strings gigantes.
// 4) TS 4.5+ optimiza la recursion de cola de algunos conditional types.
La explosion combinatoria

Los template literals multiplican las unions: `/x/${"a" | "b"}/${"1" | "2"}` genera 4 rutas. Si anidas plantillas dentro de plantillas recursivas con unions grandes, el numero de instanciaciones crece de forma exponencial y el compilador se vuelve lento. Usa unions acotadas y dominios pequenos.

3 · Ejemplo minimo

recursiva-minimo.ts
// Split: separar una ruta en segmentos.
type Split<S extends string, Sep extends string> =
  S extends `${infer Head}${Sep}${infer Tail}`
    ? [Head, ...Split<Tail, Sep>]
    : S extends "" ? [] : [S];

type RouteParts = Split<"/api/users/7", "/">; // ["", "api", "users", "7"]

// KebabCase: camelCase -> kebab-case.
type Kebab<S extends string> =
  S extends `${infer Head}${infer Tail}`
    ? Head extends Uppercase<Head>
      ? Tail extends "" ? Lowercase<Head> : `${Lowercase<Head>}-${Kebab<Tail>}`
      : `${Head}${Kebab<Tail>}`
    : S;

type Key = Kebab<"totalPrice">; // "total-price"

Linea a linea:

  • Split<"/api/users/7", "/"> devuelve una tupla con cada tramo, incluido el primer elemento vacio (porque la ruta empieza con /).
  • Kebab<"totalPrice"> recorre la cadena: las minusculas se copian tal cual y la mayuscula P se convierte en -p.
  • Ambos tipos terminan porque en cada llamada la entrada se acorta: un tramo en el primer caso, un caracter en el segundo.

4 · Ejemplo real

Sistema de rutas de una API y bus de eventos: las rutas se convierten en objetos de parametros tipados, y los nombres de acciones camelCase se pasan a kebab-case para emitir eventos.

rutas-tipadas.ts
// 1) Parsea los parametros de una ruta: /users/:id/orders/:orderId
type RouteParams<Ruta extends string> =
  Ruta extends `${infer Head}/${infer Tail}`
    ? RouteSegment<Head> & RouteParams<Tail>
    : RouteSegment<Ruta>;

// Una segmento ":id" se convierte en una clave { id: string }.
type RouteSegment<Seg extends string> =
  Seg extends `:${infer Name}` ? { [K in Name]: string } : {};

type Params = RouteParams<"/users/:id/orders/:orderId">;
// → { id: string } & { orderId: string }

const params: Params = { id: "7", orderId: "91" }; // ✅ ambas claves

declare function pedirPedido(params: Params, ruta: string): void;
pedirPedido(params, "/users/7/orders/91");

// 2) Nombres de acciones camelCase → eventos kebab para el bus.
type ToKebab<S extends string> =
  S extends `${infer Head}${infer Tail}`
    ? Head extends Uppercase<Head>
      ? Tail extends "" ? Lowercase<Head> : `${Lowercase<Head>}-${ToKebab<Tail>}`
      : `${Head}${ToKebab<Tail>}`
    : S;

type EventName = ToKebab<"usuarioRegistrado">; // "usuario-registrado"

declare function emitir(nombre: EventName): void;
emitir("usuario-registrado");

Decisiones:

  • RouteParams parte la ruta por /, no por caracter: cada nivel consume un segmento entero, lo que mantiene la profundidad baja aunque la ruta sea larga.
  • La interseccion & permite combinar los parametros de cada segmento sin reescribir el tipo. Si alguna ruta deja de encajar, el tipo resultante deja de tener una clave, y el fallo aparece donde se usa.
  • ToKebab consume una letra por llamada: es el patron correcto para transformaciones, pero recuerda que cada letra cuesta un nivel de recursion.

5 · Buenas practicas

  • Escribe el caso base antes que la recursion: garantiza que la expansion termina.
  • Reduce la entrada en cada llamada: un tramo, un caracter o un elemento de tupla. Si la entrada no decrece, la recursion es infinita.
  • Recursa por segmentos (Split por separador) siempre que puedas: menos niveles de profundidad y menos trabajo para el compilador que ir caracter a caracter.
  • Acota la entrada: restringe con extends string o extends string[] y documenta el dominio que soporta el tipo.
  • Evita anidar plantillas sobre unions grandes: la expansion de combinaciones es multiplicativa y degrada el rendimiento de tsc.
  • Prueba los tipos recursivos con ejemplos cortos antes de usarlos en codigo real, y mide el coste si los aplicas a cadenas largas.

Que evitar

  • Recursion sin caso base (provoca TS2589).
  • Olvidar el caso de string vacio en Split-like types (la tupla queda con un hueco).
  • Aplicar recursion por caracter a cadenas de cientos de caracteres.
  • Usar recursion cuando un mapped type o una union simple resuelve el caso (menos es mas).

6 · Errores habituales

Mal — recursion sin caso base 
// Nunca se acorta la entrada: el compilador aborta.
type Infinito<S extends string> = `${Infinito<S>}extra`;
type R = Infinito<"x">; // ✖ TS2589: "excessively deep and possibly infinite"
Bien — cada nivel consume un caracter 
type Pop<S extends string> =
  S extends `${infer Head}${infer Tail}` ? Tail : S;

type Quitado = Pop<"abc">; // "bc" — la entrada decrece en cada llamada
Mal — Split que pierde el ultimo tramo 
type SplitMal<S extends string, Sep extends string> =
  S extends `${infer Head}${Sep}${infer Tail}`
    ? [Head, ...SplitMal<Tail, Sep>]
    : [S]; // ✖ la cadena vacia devuelve [""] en lugar de []
Bien — caso base para el string vacio 
type SplitBien<S extends string, Sep extends string> =
  S extends `${infer Head}${Sep}${infer Tail}`
    ? [Head, ...SplitBien<Tail, Sep>]
    : S extends "" ? [] : [S];
Mal — explosion combinatoria descontrolada 
type Duplicar<U extends string> = `${U}-${U}`;
type R = Duplicar<"a" | "b" | "c" | "d">; // 16 combinaciones
// Con 20 valores habria 400; anidando plantillas, el coste crece sin fin.
Bien — dominios acotados 
type Ruta = `/${"usuarios" | "pedidos"}/${"listado" | "detalle"}`;
// 4 rutas totales: controlado y documentado por el propio tipo

7 · Ejercicio guiado

Vamos a invertir una cadena a nivel de tipos: Reverse<"abc"> debe ser "cba".

  1. Define type Reverse<S extends string>.
  2. Extrae el primer caracter y la cola: S extends `${infer Head}${infer Tail}`.
  3. Recurre sobre la cola y coloca el caracter al final: `${Reverse<Tail>}${Head}`.
  4. Escribe el caso base: si no hay pattern, devuelve S (la cadena vacia devuelve "").
  5. Comprueba con "abc" (→ "cba") y con "" (→ "").

Solucion paso a paso:

ejercicio-reverse.ts
// 1) Definicion y restriccion a string.
type Reverse<S extends string> =
  // 2) Patron: primer caracter y cola.
  S extends `${infer Head}${infer Tail}`
    // 3) Recurre con la cola y pega el caracter al final.
    ? `${Reverse<Tail>}${Head}`
    // 4) Caso base: cadena vacia.
    : S;

// 5) Pruebas:
type Inverso = Reverse<"abc">;  // "cba"
type Vacio = Reverse<"">;       // ""

8 · Reto

Reto

Implementa Join<T, Sep> que convierta una tupla de strings en una cadena con separador, manejando los tres casos: tupla vacia, tupla de un solo elemento y tuplas largas. Despues combinalo con tu Split para escribir toKebab<"NombreAccion"> que splittee por mayusculas y vuelva a unir con -. No mires la solucion: piensa en el patron [infer Head, ...infer Rest] y en cual de las tres ramas evita el guion final.

9 · Resumen

  • A nivel de tipos no hay bucles: la iteracion es recursion, y cada llamada debe consumir parte de la entrada.
  • ${infer Head}${Sep}${infer Tail} convierte un template literal en un patron que captura trozos de la cadena.
  • Split, Join y KebabCase son los tres buques insignia: separar, unir y transformar cadenas de forma tipada.
  • El caso base va primero; sin el, TS2589 corta la expansion (excessively deep).
  • Cada caracter o segmento cuesta un nivel de profundidad (~50 por defecto): recursa por segmentos y acota el domino.
  • Las unions anidadas en plantillas explotan de forma combinatoria: usa dominios pequenos.

10 · Preguntas frecuentes

¿Por que no hay bucles a nivel de tipos?

Los tipos son declarativos: describen estructura, no secuencias de pasos. La recursion es la unica forma de "repetir" un patron, igual que en lenguajes funcionales puros.

¿Cual es el limite real de profundidad?

El compilador corta la expansion cuando la profundidad de instanciacion supera un limite (del orden de ~50 niveles por defecto). Desde TS 4.5, la recursion de cola en conditional types se optimiza y permite casos mas profundos sin disparar el corte.

¿Por que me da "excessively deep" si mi caso base existe?

Porque cada caracter o elemento de la entrada consume un nivel de recursion. Si aplicas el tipo a una cadena larga, alcanzas el limite aunque el caso base este bien planteado. Reduce la entrada o recursa por segmentos.

¿Estas tecnicas se usan en proyectos reales?

Si: tipado de rutas, claves i18n, nombres de eventos, formatos validados en tiempo de compilacion. Librerias como type-fest o ts-toolbelt las usan todo el tiempo.

¿Puedo recursar sobre objetos o tuples igual que sobre strings?

Si: el patron es el mismo, cambiando el pattern. Para tuples usas T extends [infer Head, ...infer Rest]; para objetos, mapped types con recursion sobre keyof.

¿La recursion funciona con genericos abiertos como S extends string?

Si, pero la expansion queda diferida: el compilador solo materializa el resultado cuando el generico se concreta con literales. Evita recursar sobre tipos abiertos gigantes, porque el coste se pospone y puede golpear donde menos lo esperas.
