Preguntas frecuentes

FAQ ❓ Dudas comunes del curso

Antes de empezar

¿MinIO es gratis? ¿Qué licencia tiene?

La Community Edition de MinIO es software libre bajo AGPLv3. Puedes usarla y modificarla, pero si ofreces un servicio modificado por red, la licencia tiene obligaciones que conviene revisar. MinIO también ofrece ediciones comerciales (AIStor). El curso se centra en la Community y menciona la diferencia cuando importa.

¿Necesito una cuenta de AWS?

No. Todo el curso funciona contra un MinIO local en Docker. La API es compatible con S3, así que el mismo código puede apuntar a AWS cambiando endpoint y credenciales; la lección de compatibilidad lo demuestra con AWS SDK v3, pero no hace falta cuenta para seguir el curso.

¿Necesito saber Node.js para seguir el curso?

Los ejemplos de SDK usan Node.js 22 con minio-js, pero el modelo (bucket, objeto, clave, prefijo, política, lifecycle) es de S3 y se traslada a cualquier lenguaje. Si vienes de Python, .NET o Java, cambia el cliente, no los conceptos.

Modelo y operación

¿Puedo usar MinIO con Docker Compose en producción?

Para un solo nodo, sí es una opción razonable en entornos pequeños. Para un clúster distribuido, no: MinIO no soporta ni documenta Docker Compose multi-nodo. La vía soportada es Kubernetes con el Operator, o baremetal. El curso lo dice explícitamente para que no diseñes sobre una base frágil.

¿Un bucket es una carpeta?

No. Un bucket contiene objetos identificados por una clave plana. Lo que parece una carpeta (2026/facturas/) es un prefijo de la clave. Renombrar un «directorio» implica copiar y borrar cada objeto; no hay una operación atómica de rename de carpeta.

¿Cómo evito perder datos si borro un objeto?

Activa versionado en el bucket: un borrado crea un delete marker y las versiones anteriores siguen recuperables. Para retención legal o WORM, añade object locking. Y no confundas versionado con backup: un borrado del bucket o del servidor sigue siendo un riesgo; necesitas réplica o copia externa.

Seguridad y acceso

¿Puedo usar las credenciales root en mi aplicación?

No. Root tiene control total y, si se filtra, compromete todos los buckets y usuarios. Crea un usuario con una política de mínimo privilegio y úsalo desde la aplicación. Root queda para el arranque y la administración puntual.

¿Son seguras las presigned URLs?

Son seguras si se tratan como credenciales temporales: expiración corta, acción mínima, HTTPS y nunca en logs o repositorios. Una URL filtrada permite la acción firmada hasta que caduque. No las generes con root ni las reutilices para todo el bucket.

¿Cómo hago que un bucket sea público?

Se puede con una política anónima (mc anonymous set download), pero el curso lo desaconseja por defecto. Si necesitas servir contenido público, limita el prefijo, usa solo lectura y considera una CDN delante. Para todo lo demás, presigned URLs o usuarios autenticados.

El proyecto final

¿Qué construye exactamente el proyecto?

Un document store con API HTTP: crea buckets y prefijos, valida metadatos, genera presigned uploads, lista documentos, aplica versionado y lifecycle, y emite eventos a un webhook cuando llega un PDF. Se levanta con Docker Compose y se prueba con node --test.

¿Se conecta con el curso de RabbitMQ?

La lección de notificaciones explica cómo enviar eventos a una cola y enlaza con Aprende RabbitMQ, pero el proyecto de MinIO funciona sin RabbitMQ. La integración es opcional: un webhook local permite probar el flujo completo sin dependencias externas.
