Glosario de términos

Referencia 📖 El vocabulario del almacenamiento de objetos

A

access key / secret key
Par de credenciales que identifica a un usuario ante la API S3. La access key es pública; la secret key nunca se comparte ni se registra. Root también las tiene, pero solo debe usarse para el arranque (Credenciales root).
ARN (Amazon Resource Name)
Identificador de un recurso usado en políticas y notificaciones. En MinIO aparece en recursos de políticas (arn:aws:s3:::bucket/*) y en destinos de eventos (arn:minio:sqs::1:webhook) (Usuarios y políticas).

B

bucket
Contenedor lógico de objetos con nombre único global en un servidor S3. Tiene políticas, versionado, lifecycle y notificaciones propias. No es una carpeta del sistema de ficheros (Buckets y prefijos).
bucket policy
Documento JSON que concede o deniega acciones sobre un bucket y sus objetos. Se evalúa junto con la política del usuario; el resultado efectivo es la intersección de lo permitido (Usuarios y políticas).

C

clave (key)
Nombre completo del objeto dentro del bucket, por ejemplo 2026/facturas/1042.pdf. Es una cadena plana: las barras son convención, no jerarquía real. Cambiar la clave es crear un objeto nuevo (Buckets y prefijos).
consola
Interfaz web de MinIO (puerto 9001) para explorar buckets, usuarios, políticas y configuración. Útil para observar y aprender; la infraestructura debe poder reproducirse con mc o código (Instalación y consola web).
content-type
Metadato que declara el tipo de contenido del objeto (application/pdf, image/png). MinIO no lo adivina al descargar: si no lo envías, el navegador puede tratarlo como binario (PUT, GET y metadatos).

E

erasure coding
Técnica de durabilidad que divide cada objeto en fragmentos de datos y paridad, distribuidos entre discos. Permite reconstruir datos si fallan algunos discos, con menos sobrecoste que la réplica completa (Erasure coding).
ETag
Identificador devuelto por S3 para una versión de un objeto, normalmente el hash del contenido (o del multipart). Sirve para verificar integridad y para condiciones If-Match, no como identificador de negocio (PUT, GET y metadatos).
evento / notificación
Aviso que MinIO envía cuando ocurre una acción sobre un objeto (put, delete…). Se configura con mc event add y se entrega a un webhook o cola (Notificaciones de eventos).

I

IAM
Modelo de identidades y permisos. En MinIO se gestiona con usuarios, grupos y políticas mediante mc admin. No hay un servicio IAM externo como en AWS: el servidor evalúa las políticas (Usuarios y políticas).
ILM (information lifecycle management)
Conjunto de reglas de ciclo de vida: expirar objetos, transicionar a almacenamiento frío o conservar versiones. Se aplica por prefijo y se versiona como configuración (Lifecycle e ILM).

M

mc
Cliente oficial de línea de comandos de MinIO. Gestiona alias, buckets, objetos, usuarios, políticas, lifecycle, réplica y eventos. Es la herramienta canónica del curso (mc y el primer bucket).
metadatos
Pares clave-valor asociados a un objeto: Content-Type, Cache-Control, x-amz-meta-*. Se envían al subir y no se indexan para búsquedas complejas; para eso necesitas un catálogo externo (PUT, GET y metadatos).
multipart upload
Subida de un objeto grande en partes, con un identificador de subida y un cierre que ensambla el resultado. Permite reintentar partes sin empezar de cero (Multipart y streaming).

O

objeto
Unidad de datos de S3: bytes + metadatos + clave. No se modifica parcialmente; se reemplaza por una versión nueva. Su tamaño máximo y el multipart condicionan el diseño (Qué es el almacenamiento de objetos).
object locking
Modo WORM que impide borrar o sobrescribir una versión durante un periodo de retención. Se activa al crear el bucket y se combina con versionado (Versionado y object locking).
operator
Controlador de Kubernetes que gestiona tenants de MinIO de forma declarativa. Es la vía soportada para despliegues distribuidos en Kubernetes (Kubernetes Operator).

P

prefijo
Parte inicial de una clave que se usa para agrupar y listar objetos, por ejemplo 2026/facturas/. La consola lo muestra como carpeta, pero no existe como entidad (Buckets y prefijos).
presigned URL
URL firmada temporalmente que permite ejecutar una acción concreta (GET o PUT) sobre un objeto sin entregar credenciales. Tiene expiración y alcance; se genera con el SDK o mc share (Presigned URLs).

R

réplica (replication)
Copia continua de objetos y versiones de un bucket a otro destino, local o remoto. No sustituye a un backup: una réplica de un borrado también puede replicar el borrado si no se configura con cuidado (Réplica entre sitios).
root user
Credencial de administración total del servidor. Solo debe usarse para el arranque y operaciones administrativas puntuales; la aplicación usa usuarios acotados (Credenciales root).

S

S3
API de almacenamiento de objetos de Amazon, convertida en estándar de facto. MinIO la implementa, y por eso el mismo SDK puede apuntar a MinIO o a la nube cambiando el endpoint (La API S3 y MinIO).
SSE (server-side encryption)
Cifrado de objetos en reposo por parte del servidor. Puede usar claves gestionadas por el servidor (SSE-S3) o un KMS (SSE-KMS). No sustituye a TLS en tránsito (TLS y cifrado).

T

tenant
Instancia de MinIO gestionada por el Operator en Kubernetes, con su propio namespace, pools y configuración. No confundir con un «inquilino» lógico dentro de un bucket (Kubernetes Operator).

V

versionado
Capacidad de conservar varias versiones de un objeto. Un borrado crea un delete marker en lugar de eliminar los datos, lo que permite recuperar. Se activa por bucket (Versionado y object locking).
