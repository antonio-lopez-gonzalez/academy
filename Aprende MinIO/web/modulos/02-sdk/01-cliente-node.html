El cliente de Node.js

Módulo 2 · SDK y aplicación 🕐 35 minutos

1 · Introducción

Hasta ahora has hablado con MinIO desde mc y desde la consola web. Las dos herramientas son cómodas para explorar, pero ninguna es una aplicación: no validan un formulario, no registran quién sube qué y no reaccionan a un evento. Cuando el almacenamiento pasa a formar parte de un producto, quien escribe y lee objetos es tu código.

La API S3 es HTTP con firma SigV4. Podrías construir cada petición a mano, pero estarías reimplementando canonicalización de cabeceras, codificación de claves, subidas multipart y reintentos. minio-js existe para eso: es un cliente oficial, pequeño y sin dependencias pesadas, que convierte las operaciones S3 en métodos asíncronos de JavaScript.

En esta lección montamos el cliente que usaremos durante todo el módulo: configuración desde variables de entorno, creación idempotente del bucket, subida, lectura, listado, metadatos y borrado. El objetivo no es memorizar la lista de métodos, sino entender qué petición hay detrás de cada uno y qué errores aparecen cuando la configuración no coincide con el servidor.

Por qué esta lección es la base del módulo

Las tres lecciones siguientes —subidas directas, reintentos y descargas— asumen que ya sabes construir un cliente y que distingues un fallo de configuración de un fallo de permisos. Si el cliente está mal montado, cada error posterior parece un misterio del servidor.

2 · Teoría

Qué es y qué no es minio-js

Es un SDK para el lado servidor: se ejecuta en Node.js, no en el navegador, porque necesita tu secretKey para firmar cada petición. El navegador nunca debe ver esa clave; por eso las subidas desde el cliente se hacen con presigned URLs, como veremos en la siguiente lección.

El SDK no guarda estado remoto ni crea una sesión: cada método compone una petición HTTP, la firma con las credenciales y la envía al endpoint configurado. Esa frase explica casi todo su comportamiento:

  • No hay «conexión abierta» que mantener: hay un pool de sockets HTTP reutilizados.
  • Los permisos se evalúan en el servidor en cada petición, no al construir el cliente.
  • Cambiar una variable de entorno después de arrancar no cambia el cliente: hay que reiniciar el proceso.

El viaje de una petición

app.mjs                    minio-js                         MinIO :9000
   |                          |                                 |
   | putObject(bucket, key)   |                                 |
   |------------------------->| 1. calcula el hash del cuerpo    |
   |                          | 2. firma SigV4 con secretKey     |
   |                          | 3. PUT /documentos/acme/2026/...      |
   |                          |-------------------------------->|
   |                          |<--------------------------------|
   |<-------------------------| 200 OK + ETag + x-amz-request-id |
   |                          |                                 |
   |  (si el cuerpo es grande, el SDK lo parte en multipart)     |

Los tres datos que debes saber leer de la respuesta son el ETag, el tamaño y el request id. El primero identifica la versión del contenido en la mayoría de los casos; el segundo confirma cuántos bytes se guardaron; el tercero es lo único que el soporte del servidor puede buscar en sus logs.

Endpoint no es URL

endPoint es solo el nombre del host o la IP. El esquema lo decide useSSL y el puerto se pasa aparte. Esta es la causa número uno de clientes que «no conectan» en el primer intento.

Streams: el contrato que hay que respetar

getObject devuelve un Readable. Mientras no lo consumas, el socket queda ocupado y el objeto no se libera. Y si el stream emite un error y nadie lo escucha, Node termina el proceso. Las dos formas correctas son:

  • pipeline(stream, destino) de node:stream/promises: propaga errores y cierra ambos extremos.
  • for await (const chunk of stream): consume por partes con backpressure automática.

Para subir, putObject acepta un Buffer o un Readable. Con un stream debes pasar el tamaño en bytes; el SDK lo necesita para decidir entre una subida simple y una multipart. Si no lo sabes de antemano, escribe primero a un fichero temporal o calcula el tamaño con fs.stat.

La edición Community y su licencia

El servidor que estás usando es MinIO Community, distribuido bajo AGPLv3. Es software libre, pero la licencia tiene obligaciones si ofreces el servicio modificado a terceros. El SDK, en cambio, es Apache-2.0. No confundas las licencias del cliente y del servidor al elegir qué puedes redistribuir.

3 · Ejemplo mínimo

El programa más pequeño que crea un bucket, escribe un objeto y lo verifica. Necesitas un MinIO escuchando en localhost:9000; si no lo tienes, los pasos del ejercicio lo levantan.

mkdir laboratorio-sdk
cd laboratorio-sdk
npm init -y
npm pkg set type=module
npm install minio@^8.0.7
// cliente.mjs
import * as Minio from 'minio'

const client = new Minio.Client({
  endPoint: process.env.MINIO_ENDPOINT ?? 'localhost',
  port: Number(process.env.MINIO_PORT ?? 9000),
  useSSL: process.env.MINIO_USE_SSL === 'true',
  accessKey: process.env.MINIO_ACCESS_KEY,
  secretKey: process.env.MINIO_SECRET_KEY,
})

const bucket = 'documentos'
const key = 'acme/2026/11/hola.txt'

if (!(await client.bucketExists(bucket))) {
  await client.makeBucket(bucket, 'us-east-1')
  console.log(`bucket ${bucket} creado`)
}

await client.putObject(bucket, key, Buffer.from('hola\n'), 5, {
  'Content-Type': 'text/plain; charset=utf-8',
  'X-Amz-Meta-Tenant': 'acme',
})

const stat = await client.statObject(bucket, key)
console.log(stat.size, stat.etag, stat.metaData['content-type'])
console.log(stat.metaData.tenant)
node --env-file=.env cliente.mjs
bucket documentos creado
5 9c1e0b2a4d5f60718293a4b5c6d7e8f9 text/plain; charset=utf-8
acme

Línea a línea:

  • import * as Minio trae el espacio de nombres completo; el cliente se instancia con new Minio.Client.
  • Number(...) convierte el puerto, que siempre llega como cadena desde el entorno.
  • useSSL === 'true' evita el error clásico de 'false' como cadena, que es truthy.
  • bucketExists hace un HEAD al bucket; makeBucket solo se llama si no existe.
  • putObject recibe el tamaño 5 porque el cuerpo es un buffer pequeño; con streams es obligatorio.
  • statObject devuelve size, etag, lastModified y metaData; las claves x-amz-meta-* vuelven sin el prefijo.

4 · Ejemplo real

El almacén de documentos necesita un módulo de almacenamiento que la API pueda importar sin saber nada de S3. Estas son las operaciones que usaremos durante el resto del curso, con configuración validada al arrancar.

// src/storage.mjs
import * as Minio from 'minio'
import { createReadStream, statSync } from 'node:fs'
import { basename } from 'node:path'
import { randomUUID } from 'node:crypto'

const BUCKET = process.env.MINIO_BUCKET ?? 'documentos'

function required(name) {
  const value = process.env[name]
  if (!value) throw new Error(`falta la variable ${name}`)
  return value
}

export const client = new Minio.Client({
  endPoint: required('MINIO_ENDPOINT'),
  port: Number(process.env.MINIO_PORT ?? 9000),
  useSSL: process.env.MINIO_USE_SSL === 'true',
  accessKey: required('MINIO_ACCESS_KEY'),
  secretKey: required('MINIO_SECRET_KEY'),
})

export async function ensureBucket() {
  if (!(await client.bucketExists(BUCKET))) {
    await client.makeBucket(BUCKET, 'us-east-1')
  }
}

export function buildKey({ tenant, kind, filename }) {
  const year = new Date().getUTCFullYear()
  const safe = basename(filename).replace(/[^\w.-]+/g, '-').toLowerCase()
  return `${tenant}/${year}/${kind}/${randomUUID()}-${safe}`
}

La clave la genera el servidor, no el cliente. Así se evita que dos personas suban a la misma ruta, que un nombre con ../ escape del prefijo y que el tenant se pueda falsificar. El tenant va primero para poder listar y aplicar políticas por cliente; el año dentro del tenant ordena y permite lifecycle por prefijo.

// src/storage.mjs (continuación)
export async function uploadDocument({ tenant, kind, filePath, contentType }) {
  const key = buildKey({ tenant, kind, filename: filePath })
  const size = statSync(filePath).size
  const metaData = {
    'Content-Type': contentType,
    'X-Amz-Meta-Tenant': tenant,
    'X-Amz-Meta-Kind': kind,
    'X-Amz-Meta-Original-Name': basename(filePath),
  }
  const etag = await client.putObject(
    BUCKET, key, createReadStream(filePath), size, metaData,
  )
  return { key, etag, size }
}

export async function listDocuments(prefix = '') {
  const items = []
  const stream = client.listObjectsV2(BUCKET, prefix, true)
  for await (const obj of stream) {
    items.push({
      key: obj.name,
      size: obj.size,
      etag: obj.etag,
      lastModified: obj.lastModified,
    })
  }
  return items
}

export async function openDocument(key) {
  const stat = await client.statObject(BUCKET, key)
  const stream = await client.getObject(BUCKET, key)
  return { stream, stat }
}

export async function deleteDocument(key) {
  await client.removeObject(BUCKET, key)
}

Con esas funciones, la API sube un PDF, lista el prefijo del tenant y descarga el objeto a disco con pipeline. El listado y la descarga se detallan en la última lección del módulo.

Un cliente por proceso

Minio.Client reutiliza el pool de sockets. Crear uno por petición funciona, pero multiplica conexiones y handshakes TLS. Exporta una instancia y reúsala; si necesitas otro endpoint, crea otro cliente explícitamente.

6 · Errores habituales

1. Poner la URL completa en endPoint

Mal — mezclar esquema, host y puerto 
const client = new Minio.Client({
  endPoint: 'http://localhost:9000', // ❌ ENOTFOUND http
  accessKey: 'app',
  secretKey: 'secreto',
})
Bien — host, puerto y TLS por separado 
const client = new Minio.Client({
  endPoint: 'localhost',
  port: 9000,
  useSSL: false,
  accessKey: 'app',
  secretKey: 'secreto',
})

El SDK construye la URL con https:// o http:// según useSSL. Si le pasas un esquema, lo trata como parte del nombre del host.

2. Olvidar que useSSL es true por defecto

Mal — dejar el valor por defecto en local 
new Minio.Client({ endPoint: 'localhost', port: 9000, accessKey, secretKey })
// ❌ write EPROTO ... wrong version number
Bien — decidirlo con una variable explícita 
useSSL: process.env.MINIO_USE_SSL === 'true'

El error de «wrong version number» significa que el cliente habló TLS contra un puerto que habla HTTP. No es un problema de credenciales.

3. Usar localhost dentro de un contenedor

Mal — la API corre en otro contenedor 
MINIO_ENDPOINT=localhost   # ❌ dentro del contenedor es él mismo
Bien — el nombre del servicio en la red de Compose 
MINIO_ENDPOINT=minio       # nombre del servicio en docker-compose.yml

En tu máquina, localhost:9000 funciona porque el puerto está publicado. Dentro de la red de Compose, cada servicio tiene su propio localhost y debe usar el nombre del servicio.

4. Pasar un stream sin tamaño

Mal — el SDK no puede planificar la subida 
await client.putObject(bucket, key, createReadStream(path))
// ❌ size must be provided for stream
Bien — tamaño conocido antes de subir 
const { size } = statSync(path)
await client.putObject(bucket, key, createReadStream(path), size, meta)

Con un Buffer el tamaño se deduce del contenido. Con un stream no hay forma de saberlo sin consumirlo, y el SDK se niega en lugar de buffearlo entero en memoria.

7 · Ejercicio guiado

Objetivo: levantar MinIO, conectar el cliente, subir un objeto con metadatos y comprobar desde mc que lo que ves en la API coincide con lo que hay en el servidor.

  1. Arranca MinIO con credenciales de desarrollo: 
    docker run -d --name minio-sdk \
  -p 9000:9000 -p 9001:9001 \
  -e MINIO_ROOT_USER=minioadmin \
  -e MINIO_ROOT_PASSWORD=minioadmin123 \
  -v minio-sdk-data:/data \
  quay.io/minio/minio server /data --console-address ":9001"

    Salida esperada: el id del contenedor. La consola queda en http://localhost:9001.

  2. Crea el proyecto y el fichero de entorno: 
    mkdir laboratorio-sdk && cd laboratorio-sdk

npm install minio@^8.0.7

    .env.example contiene los nombres, nunca los secretos reales:

    mc alias set local http://localhost:9000 minioadmin minioadmin123
mc ls -r local/documentos

  5. Comprueba la idempotencia del bucket y la sobrescritura: vuelve a ejecutar el programa. No debe aparecer «bucket creado», y el ETag será el mismo porque el contenido es idéntico. Cambia el texto a hola otra vez, vuelve a ejecutar y observa que el ETag y el tamaño cambian.

Comprobación final

mc ls debe mostrar exactamente la misma clave que devolvió el SDK. Si la clave tiene caracteres raros, revisa que no estés construyéndola con rutas absolutas de Windows: la clave S3 siempre usa /.

8 · Reto

🎯 Un inspector de objetos

Escribe inspect.mjs <key> que imprima tamaño, ETag, fecha, content-type y todos los metadatos de usuario de un objeto. Debe detectar si el ETag corresponde a una subida multipart (contiene un guion y un número de partes) y, en ese caso, avisar de que no es el MD5 del contenido.

Después, haz que acepte un prefijo en lugar de una clave: si termina en /, lista los objetos y muestra un resumen por kind (el metadato que pusimos al subir). Debe funcionar con más de 1000 objetos, sin cargar todo en memoria de golpe.

Pista: statObject para la clave exacta y listObjectsV2 para el prefijo. Para el resumen, agrupa mientras recorres el stream; no necesitas un array intermedio.

9 · Resumen

  • minio-js es un cliente de servidor: firma cada petición con SigV4 y no debe usarse en el navegador.
  • endPoint es un host, no una URL; el esquema lo decide useSSL y el puerto va aparte.
  • useSSL vale true por defecto: en local hay que desactivarlo explícitamente.
  • El cliente se crea una vez y se reutiliza; los permisos se evalúan en el servidor en cada operación.
  • getObject devuelve un stream: consúmelo con pipeline o for await.
  • Con streams, putObject exige el tamaño; con buffers, no.

10 · Preguntas frecuentes

¿Puedo usar minio-js en el navegador?

No para operaciones autenticadas. El cliente necesita la secretKey para firmar, y cualquier secreto que llegue al navegador deja de ser secreto. Para subidas y descargas desde el navegador se usan presigned URLs, que veremos en la lección 2.

¿Por qué el ETag no coincide con el MD5 que calculo?

En una subida simple, el ETag suele ser el MD5 del contenido. En una subida multipart es el MD5 de los MD5 de cada parte, con el sufijo -N. Y con cifrado SSE-KMS el ETag deja de ser un hash del contenido. No uses el ETag como verificación de integridad sin entender el caso; lo detallamos en la lección 3.

¿Tengo que crear el bucket desde la aplicación?

Puedes, pero en producción suele ser una tarea de aprovisionamiento: el bucket se crea con mc mb o con infraestructura declarativa, y la aplicación solo comprueba que existe. Si la aplicación lo crea, dale permiso s3:CreateBucket solo al usuario de arranque, no al de cada petición.

¿Qué región pongo si MinIO no es AWS?

MinIO acepta us-east-1 por defecto y no requiere una región real. Si tu despliegue tiene una región configurada, usa la misma. Lo importante es que la firma y el servidor coincidan; un valor inventado puede producir AuthorizationHeaderMalformed.

¿Cómo distingo un problema de red de uno de permisos?

Los errores de red no son S3Error: llegan como ECONNREFUSED, ENOTFOUND, ETIMEDOUT o errores de TLS. Los de permisos sí son S3Error con code: 'AccessDenied' y un statusCode 403. Captura ambos por separado; en la lección 3 montamos la taxonomía completa.
