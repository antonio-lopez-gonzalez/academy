mc y el primer bucket

Módulo 0 · Fundamentos 🕐 35 minutos

1 · Introducción

mc es el cliente de línea de comandos de MinIO. Su diseño imita a los comandos UNIX que ya conoces —ls, cp, cat, rm, stat— pero habla S3 en lugar de un sistema de ficheros. Esa familiaridad es útil y también peligrosa: mc rm no tiene papelera y mc cp no copia «carpetas» sin --recursive.

La consola web sirve para mirar y para una operación puntual. mc sirve para todo lo demás: crear buckets en un script de arranque, subir artefactos desde CI, generar una URL temporal, comprobar metadatos, automatizar un backup. Es la interfaz que puedes versionar, revisar y repetir.

En esta lección instalamos mc, configuramos un alias, creamos el bucket documentos, subimos el primer objeto con metadatos, lo inspeccionamos y generamos una URL firmada. Al terminar tendrás el esqueleto del almacén de documentos funcionando desde la terminal.

Alias: la pieza que lo conecta todo

mc no tiene un «servidor configurado» global. Cada alias es un nombre corto que apunta a un endpoint con unas credenciales. local, staging y prod pueden convivir en el mismo fichero de configuración, y un script puede seleccionar el destino con una variable de entorno. Ese es el mecanismo que hace que mc sea automatizable.

Comprueba la versión antes de seguir:

mc version RELEASE.2025-... (commit:...)

Si usas el contenedor, cada invocación necesita montar la configuración para que el alias persista:

docker run --rm -it \
  -v "$HOME/.mc:/root/.mc" \
  minio/mc alias list

En Windows la ruta equivalente es %USERPROFILE%\.mc. Sin ese volumen, el alias se crea dentro de un contenedor efímero y desaparece al terminar.

El alias y su fichero

Un alias guarda: nombre, URL, access key, secret key, si usa path-style y la versión de firma. Vive en ~/.mc/config.json (Linux/macOS) o %USERPROFILE%\.mc\config.json (Windows).

~/.mc/config.json
{
  "version": "10",
  "aliases": {
    "local": {
      "url": "http://localhost:9000",
      "accessKey": "app-documentos",
      "secretKey": "...",
      "api": "S3v4",
      "path": "on"
    }
  }
}

Las credenciales están en claro en ese fichero; el sistema operativo lo protege con permisos de usuario, no con cifrado. No lo copies a un repositorio, no lo metas en una imagen Docker y no lo compartas por chat. Para CI existen variables MC_HOST_<alias>, que veremos en el ejemplo real.

La anatomía de un comando

mc <comando> [flags] <origen> [destino]
mc cp --attr "tenant=acme" ./informe.pdf local/documentos/2026/
   │       │                  │           │
   │       │                  │           └── destino: alias/bucket/prefijo
   │       │                  └── origen local
   │       └── flag del comando
   └── comando

Los destinos siempre empiezan por alias/bucket. No hay rutas absolutas del sistema operativo que funcionen por accidente: si escribes /documentos, mc lo interpreta como una ruta local.

Sin --recursive, mc ls muestra solo el nivel actual: los prefijos aparecen como directorios y los objetos como ficheros. Con --recursive recorre todo y muestra claves completas. Con --json cambia a un objeto por línea, ideal para jq o para un script.

La regla del curso

Si una operación importa, debe existir como comando. La consola puede ejecutarla una vez; el comando permite repetirla, revisarla y deshacerla con el mismo nivel de detalle.

3 · Ejemplo mínimo

Seis comandos que resumen el 80 % del uso diario:

# 1. Registrar el servidor
mc alias set local http://localhost:9000 \
  "$MINIO_ROOT_USER" "$MINIO_ROOT_PASSWORD" --path on
# 2. Crear el bucket (idempotente)
mc mb --ignore-existing local/documentos
# 3. Subir un objeto
mc cp ./informe.pdf local/documentos/2026/informes/acme/
# 4. Listar
mc ls local/documentos/2026/informes/acme/
# 5. Ver metadatos sin descargar
mc stat local/documentos/2026/informes/acme/informe.pdf
# 6. Generar una URL temporal
mc share download --expire 24h \
  local/documentos/2026/informes/acme/informe.pdf

Qué hace cada uno:

  • alias set escribe la configuración; no valida que el servidor exista hasta que lanzas una operación. --path on fuerza path-style, como en la lección anterior.
  • mb crea el bucket. Sin --ignore-existing, un segundo intento devuelve error; con el flag, el script es reejecutable.
  • cp sube el fichero y deduce Content-Type por la extensión. Como el destino acaba en /, conserva el nombre.
  • ls lista el prefijo. No descarga nada.
  • stat hace un HEAD: tamaño, ETag, fecha y metadatos.
  • share download firma una URL de descarga válida 24 horas. Es una capacidad portadora: quien la tenga puede descargar el objeto sin credenciales.

Salida de mc share download:

Share: http://localhost:9000/documentos/2026/informes/acme/informe.pdf?X-Amz-Algorithm=...
Expire: 23 hours 59 minutes 59 seconds

Compruébala con curl:

curl -o descarga.pdf "<URL_DEL_COMANDO_ANTERIOR>"
cmp ./informe.pdf ./descarga.pdf && echo "idénticos"

4 · Ejemplo real

Vamos a sembrar el almacén de documentos con tres ficheros y metadatos de negocio. El script debe poder ejecutarse en local y en staging sin cambios, y debe negarse a correr si falta una variable:

#!/usr/bin/env bash
set -euo pipefail
: "${MINIO_ALIAS:=local}"
: "${MINIO_BUCKET:=documentos}"
mc alias set "$MINIO_ALIAS" "$S3_ENDPOINT" \
  "$MINIO_ROOT_USER" "$MINIO_ROOT_PASSWORD" --path on
mc mb --ignore-existing "$MINIO_ALIAS/$MINIO_BUCKET"
mc cp --attr "tenant=acme;doc-id=CTR-2026-0142" \
  ./fixtures/contrato.pdf \
  "$MINIO_ALIAS/$MINIO_BUCKET/2026/contratos/acme/CTR-2026-0142.pdf"
mc cp --attr "tenant=acme;doc-id=INF-2026-0007" \
  ./fixtures/informe.pdf \
  "$MINIO_ALIAS/$MINIO_BUCKET/2026/informes/acme/INF-2026-0007.pdf"
mc cp ./fixtures/notas.txt \
  "$MINIO_ALIAS/$MINIO_BUCKET/2026/informes/acme/notas.txt"
mc ls --recursive "$MINIO_ALIAS/$MINIO_BUCKET/2026/"

Salida esperada:

[2026-02-11 09:14:22 CET]   1.8MiB STANDARD 2026/contratos/acme/CTR-2026-0142.pdf
[2026-02-11 09:14:23 CET]   2.4MiB STANDARD 2026/informes/acme/INF-2026-0007.pdf
[2026-02-11 09:14:23 CET]     412B STANDARD 2026/informes/acme/notas.txt

Para CI no escribas el alias con un comando: mc entiende la variable MC_HOST_<alias> con la URL completa.

export MC_HOST_ci="http://$CI_ACCESS_KEY:$CI_SECRET_KEY@minio.internal:9000"
mc ls ci/documentos/2026/

La URL lleva las credenciales, así que trátala como un secreto: no la imprimas en los logs ni la pases como argumento visible. Si la clave contiene caracteres especiales (@, :, /), codifícalos en porcentaje o usa mc alias set con un fichero temporal.

La barra final cambia el resultado

mc cp informe.pdf local/documentos/2026/ crea 2026/informe.pdf. mc cp informe.pdf local/documentos/2026 crea un objeto llamado 2026, sin extensión y sin relación con el prefijo. La barra final no es decorativa: expresa «dentro de».

Automatización con --json

Los comandos de mc aceptan --json. Es la forma de consumir la salida desde un script sin parsear columnas de ancho variable:

mc ls --recursive --json local/documentos/2026/ \
  | jq -r 'select(.type == "file") | [.key, .size] | @tsv'
2026/contratos/acme/CTR-2026-0142.pdf	1887436
2026/informes/acme/INF-2026-0007.pdf	2516582
2026/informes/acme/notas.txt	412

Con eso puedes construir un informe de capacidad, detectar objetos huérfanos o comparar dos entornos. La regla es siempre la misma: primero un comando que funcione a mano, después el script que lo repite.

6 · Errores habituales

1. Copiar una carpeta sin --recursive

Mal — mc no adivina que quieres el árbol 
# ❌ "is a folder, please use --recursive"
mc cp ./fixtures/ local/documentos/2026/
Bien — explícito 
mc cp --recursive ./fixtures/ local/documentos/2026/

El error es intencionado: copiar miles de ficheros por accidente es peor que escribir un flag. Lo mismo aplica a mc rm: sin --recursive solo borra un objeto.

2. Olvidar la barra final del destino

Mal — el objeto se llama como el prefijo 
# ❌ Crea la clave "2026" con el contenido del PDF
mc cp ./informe.pdf local/documentos/2026
Bien — «dentro de 2026/» 
mc cp ./informe.pdf local/documentos/2026/

Compruébalo con mc ls local/documentos/. Si ves un objeto sin extensión llamado 2026, ya sabes qué pasó; bórralo con mc rm antes de que alguien lo confunda con un prefijo.

3. Borrar en producción sin ensayo

Mal — confiar en la memoria y en la suerte 
# ❌ Sin versionado, esto no se deshace.
mc rm --recursive --force local/documentos/2026/
Bien — simular, acotar y comprobar 
mc rm --recursive --force --dry-run local/documentos/2026/
mc rm --recursive --force --older-than 90d local/documentos/tmp/

--dry-run imprime lo que borraría. --older-than acota por fecha. Y si el bucket tiene versionado, el borrado deja delete markers, no elimina los datos: eso cambia el significado de «borrado».

4. Compartir un enlace sin caducidad razonable

Mal — una URL de siete días pegada en un ticket 
mc share download local/documentos/2026/contratos/acme/CTR-2026-0142.pdf
Bien — expiración corta y alcance mínimo 
mc share download --expire 1h \
  local/documentos/2026/contratos/acme/CTR-2026-0142.pdf

Sin --expire, el enlace dura 7 días. Cualquiera que lo encuentre en un log, un correo o el historial del navegador puede descargar el objeto. Genera enlaces con la vida mínima que necesite el caso de uso.

7 · Ejercicio guiado

Objetivo: dejar el bucket documentos creado con tres objetos, metadatos y una descarga verificada por URL firmada.

  1. Instala y comprueba mc. 
    mc --version
mc alias list

    Si ya tienes un alias local apuntando a otro sitio, usa otro nombre para no pisarlo.

  2. Configura el alias con path-style. 
    mc alias set local http://localhost:9000 \
  "$MINIO_ROOT_USER" "$MINIO_ROOT_PASSWORD" --path on
mc admin info local

    Salida esperada: un nodo online y 1/1 drives OK. Si falla, revisa el contenedor antes de seguir.

  3. Crea el bucket. 
    mc mb --ignore-existing local/documentos
mc ls local
    [2026-02-11 09:10:00 CET]     0B documentos/
  4. Sube los tres objetos con metadatos. 
    mc cp --attr "tenant=acme;doc-id=CTR-2026-0142" \
  ./fixtures/contrato.pdf \
  local/documentos/2026/contratos/acme/CTR-2026-0142.pdf
mc cp --attr "tenant=acme;doc-id=INF-2026-0007" \
  ./fixtures/informe.pdf \
  local/documentos/2026/informes/acme/INF-2026-0007.pdf
mc cp ./fixtures/notas.txt \
  local/documentos/2026/informes/acme/notas.txt
  5. Inspecciona y compara. 
    mc ls --recursive local/documentos/2026/
mc stat local/documentos/2026/contratos/acme/CTR-2026-0142.pdf
mc cat local/documentos/2026/informes/acme/notas.txt
mc du local/documentos/2026/

    Comprueba que Metadata incluye X-Amz-Meta-Tenant y X-Amz-Meta-Doc-Id. Si no aparecen, revisa las comillas de --attr.

  6. Genera una URL y descarga con curl. 
    mc share download --expire 1h \
  local/documentos/2026/contratos/acme/CTR-2026-0142.pdf
curl -o /tmp/contrato-descargado.pdf "<URL>"
cmp ./fixtures/contrato.pdf /tmp/contrato-descargado.pdf

    Sin salida, cmp confirma que los bytes son idénticos. Repite la descarga después de la expiración y comprueba que devuelve un error de firma caducada.

8 · Reto

🎯 Un sincronizador idempotente

Escribe un script sync-docs.sh que reciba una carpeta local y un prefijo remoto, y que suba solo lo que haya cambiado. Debe imprimir un resumen con objetos nuevos, modificados y eliminados, y debe poder ejecutarse dos veces seguidas sin volver a subir nada en la segunda. Si el destino tiene objetos que no están en el origen, no debe borrarlos salvo que se pase --prune.

Añade un modo --check que no escriba nada y devuelva código de salida distinto de cero si hay diferencias, para poder usarlo en CI. Documenta cómo distingue un objeto modificado de uno idéntico.

Pista: mc mirror ya resuelve la sincronización y tiene --dry-run; mc ls --json te da tamaño y ETag para comparar. La parte interesante del reto es el resumen y el código de salida, no reimplementar la copia.

9 · Resumen

  • mc es el cliente S3 de MinIO: comandos familiares, semántica de objetos.
  • Un alias une nombre corto, endpoint y credenciales; vive en ~/.mc/config.json.
  • mc mb --ignore-existing hace los scripts idempotentes.
  • La barra final del destino significa «dentro de»; sin ella, el objeto toma el nombre del prefijo.
  • --recursive es obligatorio para árboles, tanto en cp como en rm.
  • --json es la salida para automatización; --dry-run es el ensayo de un borrado.
  • mc share download crea una URL portadora con expiración; sin --expire, dura 7 días.

10 · Preguntas frecuentes

¿Dónde guarda mc las credenciales y están cifradas?

En ~/.mc/config.json (o %USERPROFILE%\.mc\config.json), en claro dentro de un fichero con permisos del usuario. No hay cifrado con contraseña maestra. Protégelo como protegerías un .ssh o un .aws/credentials: no lo versiones, no lo copies a imágenes y rota las claves si sospechas que se ha filtrado.

¿Puedo tener varios alias a la vez?

Sí, es lo normal: local, staging, prod, aws. Cada uno tiene su endpoint y sus credenciales. En los scripts conviene recibir el alias por variable (MINIO_ALIAS) para no hardcodear el destino y evitar ejecutar un borrado contra producción por copiar un comando.

¿mc rm borra también las versiones anteriores?

No. En un bucket versionado, mc rm sin --version-id crea un delete marker: el objeto deja de verse, pero las versiones siguen ocupando espacio. Para eliminar una versión concreta usa --version-id; para eliminar todas, mc rm --versions. Son operaciones destructivas y no se pueden deshacer.

¿Puedo usar la AWS CLI en lugar de mc?

Sí, con --endpoint-url http://localhost:9000. La AWS CLI es útil para comprobar que el comportamiento es estándar y para equipos que ya la tienen integrada. mc añade administración del servidor, mirror, share y una salida más cómoda para operaciones de bucket. En el curso usamos mc y el SDK; la CLI de AWS aparece como contraste.

¿Cómo veo el contenido de un prefijo que tiene miles de objetos?

Con mc ls --recursive, que pagina internamente y puede tardar. Para contar o sumar usa mc du; para filtrar por nombre, mc find --name. Recuerda que el listado devuelve como máximo 1 000 claves por página en la API: las herramientas lo ocultan, pero el coste de recorrer un prefijo enorme existe y conviene medirlo antes de meterlo en un bucle de aplicación.
