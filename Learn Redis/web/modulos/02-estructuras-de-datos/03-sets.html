Sets: usuarios por canal

Módulo 2 · Estructuras de Datos ⏱ 30 minutos

1 · Introducción

Un set es una colección de miembros únicos y sin orden y con operaciones de conjunto. Es la forma natural de responder «¿quiénes están conectados a este canal?» o «¿este usuario está suscrito?».

Verás los comandos, la membrecía instantánea y las operaciones de conjuntos (unión/intersec/diferencia) que hacen del set algo más que «una lista sin duplicados».

2 · Teoría

Comandos

SADD chan:gaming user:1 user:42      # añadir (ignora duplicados)
SREM chan:gaming user:1              # quitar
SMEMBERS chan:gaming                 # todos
SISMEMBER chan:gaming user:42        # 1/0 (¿pertenece?)
SCARD chan:gaming                    # tamaño
SRANDMEMBER chan:gaming 1            # muestrear al azar
SMOVE chan:gaming chan:news user:1   # mover entre sets

Operaciones de conjuntos

SUNION chan:gaming chan:news        # unión
SINTER chan:gaming chan:news        # intersección (en ambos)
SDIFF chan:gaming chan:news         # solo en el primero
SINTERSTORE res chan:gaming chan:news  # guardar resultado en otra key

Por qué es O(1) la membrecía

Internamente un set es un hash-table (o intset si todos son enteros): SISMEMBER contesta en tiempo constante, igual que HashSet en .NET pero compartido entre procesos. Los sets son la respuesta a «presencia por grupo» de forma distribuida.

3 · Ejemplo mínimo

SADD hub:users user:1 user:2 user:3
SISMEMBER hub:users user:2     # 1
SADD hub:users user:2          # no-op (ya estaba)
SCARD hub:users                # 3
SMEMBERS hub:users             # todos
SREM hub:users user:3
SCARD hub:users                # 2

4 · Ejemplo real

En el hub: membrecía por canal, para responder «¿a quién le mando este mensaje?» sin re-correr todas las conexiones:

// Suscribir al canal
await db.SetAddAsync($"chan:{channel}", userId);
await db.KeyExpireAsync($"chan:{channel}", lease);   // presencia de pertenencia

// ¿Está suscrito?
bool in = await db.SetContainsAsync($"chan:{channel}", userId);

// Listar suscriptores del canal (para broadcast directo si es acotado)
RedisValue[] members = await db.SetMembersAsync($"chan:{channel}");

// Usuarios en TODOS los canales (personas que reciben el mensaje crítico)
var users = await db.SetCombineAsync(SetOperation.Intersect,
    [new RedisKey("chan:general"), new RedisKey("chan:alerts")]);

Cuando necesitas «miembros + su score o tiempo», el sorted set del próximo módulo lo sustituye.

6 · Errores habituales

Usar set para algo que necesita orden

# ❌ Un set con timestamps NO te da orden
SADD chan:logs user:1 user:2      # (¿quién llegó antes?)

# ✅ Si el orden importa: list (FIFO) o sorted set (score=ts)

Depender de SMEMBERS para decidir en caliente

SMEMBERS devuelve todos los miembros; si el set es grande, el coste de red sube. Para «¿está fulano?» usa SISMEMBER, no SMEMBERS.

7 · Ejercicio guiado

  1. Paso 1: Crea dos sets chan:general y chan:alerts con intersección de usuarios.
  2. Paso 2: Obtén SINTER, SUNION, SDIFF.
  3. Paso 3: Comprueba SISMEMBER y SCARD.
  4. Paso 4: Decide en tu hub: ¿qué pregunta responde SINTER y para qué serviría (p. ej. «quiénes están en todos los canales críticos»)?

8 · Reto

🎯 Set con TTL y expiración selectiva

Los sets no tienen TTL por miembro, solo por key. Diseña una forma de «presencia en canal» que expire por usuario (pista: una key por miembro, o sorted set con timestamp que se limpia). Es el límite que el sorted set del próximo módulo resuelve de forma nativa.

9 · Resumen

  • Sets: miembros únicos sin orden, con SADD/SREM/SISMEMBER/SMEMBERS/SCARD.
  • Operaciones algebraicas: SUNION/SINTER/SDIFF (+STOREs).
  • Membrecía O(1) y compartida entre procesos → «quiénes leen este canal».
  • Para orden/tiempo → sorted set (siguiente lección).

10 · Preguntas frecuentes

¿Y los sets «de expiración por miembro»?

No existen nativamente. Para eso: o TTL por key (todos), o sorted set con timestamps, o una key-a-key por miembro con TTL. M2-04 te da la solución limpia.

¿Cuándo NO usar un set?

Cuando necesitas orden (list), cuando necesitas score por miembro (zset), o cuando guardas valores con campos (hash).
