Hashes: el registro de una conexión

Módulo 2 · Estructuras de Datos ⏱ 35 minutos

1 · Introducción

Un hash es un mapa campo→valor bajo una key. Es la forma natural de representar un «objeto»: todos los campos de una conexión (node, userId, state, since) en una sola key, con acceso a campos individuales.

Es LA estructura del registro de conexiones del hub. Verás los comandos principales y por qué es mejor que un string con JSON para campos que tocas por separado.

2 · Teoría

El comando core

HSET hub:conn:8632 node node-1 userId 42 state open
HGET hub:conn:8632 node          # "node-1"
HGETALL hub:conn:8632            # pares campo,valor
HMGET hub:conn:8632 node state   # varios campos
HEXISTS hub:conn:8632 state      # 1/0
HDEL hub:conn:8632 state         # borra un campo
HLEN hub:conn:8632               # nº de campos
HINCRBY hub:conn:8632 msgs 1     # incrementa un campo numérico

Por qué hash en lugar de «string con JSON»

CriterioString+JSONHash
Leer UN campoHay que deserializar todoHGET solo lo pedido
Actualizar UN campoReleer-modificar-escribir (raza)HSET/HINCRBY atómico por campo
MemoriaOK (compacto)Muy eficiente con <128 campos cortos (listpack)
Modelo de «objeto»Todo el JSONCampos tipados e independientes

Regla: si necesitas acceder/actualizar campos por separado o incrementar contadores dentro del objeto → hash. Si solo lees/escribes el objeto completo de una pieza → string (JSON) o incluso un documento.

Bajo el capó

Para hashes pequeños (menos de ~128 campos y valores cortos) Redis guarda un listpack (una fila continua, muy barata); al crecer pasa a un dict clásico. Eso hace los HGETALL de tus conexiones eficientes.

3 · Ejemplo mínimo

HSET user:42 name ana role operator
HGET user:42 name              # "ana"
HSET user:42 role supervisor   # actualiza solo role
HGETALL user:42                # name, role
HINCRBY user:42 msgCount 3     # contador dentro del objeto
HLEN user:42                   # 4 (añadió msgCount)
DEL user:42

4 · Ejemplo real

Registro de una conexión del hub como hash:

// Registrar (o refrescar) la conexión en el nodo local
var key = $"hub:conn:{connectionId}";
var entries = new HashEntry[]
{
    new("node", _nodeId),
    new("userId", userId),
    new("state", "open"),
    new("since", DateTimeOffset.UtcNow.ToUnixTimeSeconds()),
};

await db.HashSetAsync(key, entries);
await db.KeyExpireAsync(key, TimeSpan.FromSeconds(30));   // presencia

// Otro nodo pregunta: ¿dónde está la conexión 8632?
var node = await db.HashGetAsync($"hub:conn:{8632}", "node");
if (!node.IsNull && node == "node-2") { /* reenvío al nodo dueño */ }

// Bajada de estado sin perder el resto
await db.HashSetAsync(key, "state", "closing");

Lees y actualizas campos sin re-serializar el objeto cada vez.

6 · Errores habituales

Guardar un set de campos como lista de strings (N keys)

# ❌ Una key por campo es peor y fragmenta
SET hub:conn:8632:node node-1
SET hub:conn:8632:userId 42

# ✅ Un hash agrupa el objeto
HSET hub:conn:8632 node node-1 userId 42

HGETALL de hashes gigantes

En el hub están acotados, pero entra cuidando el tamaño: un HGETALL de 100k campos lastima la red y la RAM.

  2. Paso 2: Actualiza solo state a closing y lee los demás con HMGET.

9 · Resumen

  • Hash = objeto bajo una key: HSET/HGET/HGETALL/HMGET/HDEL/HINCRBY.
  • Acceso e incremento por campo sin re-serializar.
  • Campos cortos + TTL = registro de conexión ideal.

10 · Preguntas frecuentes

¿Cuántos campos puede tener un hash?

Prácticamente ilimitados (RAM mediante), pero la eficiencia (listpack) se mantiene con valores cortos. No lo uses como «una tabla SQL grande».

¿El hash soporta JSON dentro de un campo?

Sí: un campo puede guardar un string (y dentro, JSON). Pero si lo necesitas consultable, mejor otro tipo o campo plano.
