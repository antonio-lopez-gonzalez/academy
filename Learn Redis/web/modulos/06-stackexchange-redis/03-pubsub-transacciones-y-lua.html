ISubscriber, transacciones y scripting Lua

Módulo 6 · StackExchange.Redis en .NET ⏱ 40 minutos

1 · Introducción

Cuando un comando no basta y necesitas varios pasos atómicos, StackExchange.Redis te da tres herramientas: ISubscriber (pub/sub en .NET), transacciones (IBatch/MULTI) y scripting Lua (lógica atómica en el servidor).

Estas tres son el «arma avanzada» del hub: locks seguros, contadores compuestos y publicaciones coordinadas.

2 · Teoría

ISubscriber (pub/sub en .NET)

ISubscriber sub = mux.GetSubscriber();

// Suscribir (vuelve a inscribir al reconectar)
await sub.SubscribeAsync("hub:events", (channel, value) =>
    Handle(value!));

// Publicar
long n = await sub.PublishAsync("hub:events", JsonSerializer.Serialize(evt));
  • El callback llega en la conexión del suscriptor; no hagas trabajo pesado dentro: despáchalo a otro hilo/cola.
  • PublishAsync devuelve el nº de suscriptores que recibieron.
  • Patrones: SubscribeAsync(RedisChannel.Pattern("hub:*"), ...).

Transacciones: MULTI/EXEC → IBatch (pipeline)

StackExchange.Redis no expone MULTI/EXEC clásico; usa CreateTransaction (MULTI+EXEC) o CreateBatch (pipeline sin garantía atómica). Para atomicidad de varios comandos, la API recomendada es CreateTransaction con condiciones:

var txn = db.CreateTransaction();
txn.AddCondition(Condition.StringNotEqual("cfg:ver", "v2"));   // WATCH-like
var set = txn.StringSetAsync("cfg:ver", "v2");
var save = txn.StringSetAsync("cached:profile:1", "...", TimeSpan.FromHours(1));
bool committed = await txn.ExecuteAsync();   // MULTI+EXEC real

Lua: el «stored procedure» atómico

const string LuaLock =
    "if redis.call('GET', KEYS[1]) == ARGV[1] then " +
    "  return redis.call('DEL', KEYS[1]) " +
    "else " +
    "  return 0 " +
    "end";

// Liberar el lock SOLO si soy el dueño (token)  — atómico y seguro
long freed = (long)await db.ScriptEvaluateAsync(
    LuaLock,
    [Key: key], [Arguments: token]);

// El dueño: SET nx + dt + un TTL definido
bool got = await db.StringSetAsync(key, token, TimeSpan.FromSeconds(5), When.NotExists);

Lua corre dentro del same single-thread: es la forma de hacer operaciones multi-key con lógica condicional de forma segura.

3 · Ejemplo mínimo

// Un contador compuesto: guardar «último + total» en una sola operación
const string script = """
    local incr = redis.call('INCR', KEYS[1])
    redis.call('SET', KEYS[2], incr)
    return incr
    """;
long val = (long)await db.ScriptEvaluateAsync(script, ["stats:total", "stats:last"], []);

4 · Ejemplo real

En el hub: el «lock de migración de nodo» (SÓLO el dueño des-registra), con Lua:

public async Task<bool> TryLockAsync(IDatabase db, RedisKey key, string token, TimeSpan ttl)
    => await db.StringSetAsync(key, token, ttl, When.NotExists);

public async Task<bool> UnlockAsync(IDatabase db, RedisKey key, string token)
{
    const string script =
        "if redis.call('GET', KEYS[1]) == ARGV[1] then " +
        "  redis.call('DEL', KEYS[1]); return 1 " +
        "end " +
        "return 0";
    return (long)await db.ScriptEvaluateAsync(script, [key], [token]) == 1;
}

// Uso: al migrar un cliente de nodo
if (await TryLockAsync(db, "lock:migrate:887", myToken, TimeSpan.FromSeconds(5)))
{
    await MigrateAsync(887);                       // mover conexión
    await UnlockAsync(db, "lock:migrate:887", myToken);
}

El Unlock con Lua es garantía de que solo el dueño cierra el lock (M5-02 prometido).

6 · Errores habituales

Liberar lock ajeno

// ❌ El lock de otro se elimina (problema en migraciones)
await db.KeyDeleteAsync(lockKey);

// ✅ Verifica el token en el servidor (Lua) antes de DEL
//   → script del ejemplo real

Usar MULTI para ahorrar latency sin WATCH de condiciones

MULTI te da «atomicidad» pero no «optimistic concurrency»; si necesitas «solo si el valor no cambió», usa condiciones (Condition.*) sobre la transacción.

7 · Ejercicio guiado

  2. Paso 2: Suscríbete a hub:events y publica desde otro endpoint: comprueba el callback.
  3. Paso 3: Crea una transacción con una Condition (p. ej. version) y muéstrala fallar si no cumple.
  4. Paso 4: Verifica con redis-cli que el unlock solo funciona con el token correcto.

8 · Reto

🎯 Contador compuesto atómico

9 · Resumen

  • ISubscriber: suscripción/publicación en .NET (para el hub).
  • IBatch (pipeline) / CreateTransaction (MULTI+condiciones).
  • Lua: lógica atómica en el servidor (locks seguros).
  • Trabajo pesado fuera del callback de suscripción.

10 · Preguntas frecuentes

¿Cuándo transacción (IBatch/CreateTransaction) y cuándo Lua?

Si solo necesitas «varios comandos y ya» → IBatch. Si necesitas «O todo o nada con condiciones» → CreateTransaction. Si necesitas lógica (if/leer+decidir+escribir) dentro → Lua.

¿Lua bloquea Redis?

Como cualquier comando: durante su ejecución, el event-loop espera. Mantenlos cortos (evita bucles largos y scripts con N grande).
