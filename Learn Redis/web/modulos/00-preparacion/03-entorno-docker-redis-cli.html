Entorno: Docker, redis-cli y RedisInsight

Módulo 0 · Qué es Redis y el caso de uso ⏱ 35 minutos

1 · Introducción

Para aprender y ejecutar el proyecto no necesitas instalaciones raras: con Docker levantas Redis en 10 segundos, con redis-cli lo usas desde la terminal y con RedisInsight ves las keys y la memoria de forma visual.

Esta lección monta el entorno completo que usarás en todo el curso — y te enseña los comandos de cliente con los que experimentarás.

2 · Teoría

Componentes

Docker para Redis

# Redis puro
docker run -d --name redis -p 6379:6379 --restart unless-stopped redis:7.4-alpine

# RedisInsight (GUI) — conecta a localhost:6379
docker run -d --name redis-insight -p 8001:8001 -p 5540:5540 redis/redisinsight:latest

# Comprobación
docker exec -it redis redis-cli ping   # PONG

redis-cli: lo que necesitas cada día

redis-cli                    # modo interactivo
redis-cli GET saludo         # un comando suelto
redis-cli -h 127.0.0.1 -p 6379
redis-cli --scan --pattern 'hub:*'   # explorar con SCAN
redis-cli -3                 # protocolo RESP3 (más tipos de respuesta)
AUTH <password>              # si el server exige contraseña
SELECT 0                     # cambiar DB lógica
DBSIZE                       # nº de keys

Contexto importante: en Windows el binario redis-cli no viene instalado por defecto. Usar Docker (docker exec -it redis redis-cli) te da el binario sin instalar nada, y StackExchange.Redis será tu «cli» preferido al programar en .NET.

Ya tienes lectura/escritura con expiración funcionando. El respaldo es: Redis corre (Docker), lo controlas por redis-cli.

4 · Ejemplo real

Levanta el ping-pong del hub entre dos terminales con redis-cli:

# Terminal 1 (suscriptor)
docker exec -it redis redis-cli
SUBSCRIBE hub:events
# (queda esperando)

# Terminal 2 (publica)
docker exec -it redis redis-cli
PUBLISH hub:events '{"type":"connect","userId":42}'
# → Terminal 1 recibe el mensaje

Es exactamente el mecanismo del backplane entre tus nodos WebSocket, ya funcionando en tu máquina.

6 · Errores habituales

«Connection refused» al conectar desde .NET

# ❌ app apunta a localhost pero Redis está en un contenedor sin -p
# ✅ docker run -p 6379:6379  (o red de Docker para usar el nombre del servicio)
docker ps | grep redis        # ¿está corriendo?
nc -vz 127.0.0.1 6379         # ¿puerto abierto?

KEYS en Redis grande que deja todo en pausa

En producción usa SCAN iterativo y nunca KEYS *.

10 · Preguntas frecuentes

¿Redis funciona en Windows nativo?

Redis oficial va en Linux/macOS/BSD. En Windows se usa WSL, binarios de terceros o Docker. El camino recomendado en este curso es Docker.

¿RedisInsight es obligatorio?

No, pero facilita entender keys/memoria. Si prefieres solo terminal, con redis-cli te basta.

¿Qué significa el puerto 6379?

Es el puerto por defecto de Redis. Los despliegues gestionados usan otros; siempre se conecta por esa «dirección» (host:puerto).
