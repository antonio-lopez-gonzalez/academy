El modelo de datos de Redis

Módulo 0 · Qué es Redis y el caso de uso ⏱ 35 minutos

1 · Introducción

Todo en Redis gira alrededor de la key: un nombre y un tipo de estructura que guarda el valor. Saber qué tipo usar para cada problema es el 80% de modelar bien en Redis.

Esta lección te da el mapa de los tipos, cómo se almacenan físicamente (por qué importa), y qué significa realmente «una key». Con eso, luego elegirás estructuras para tu hub con criterio.

2 · Teoría

Keyspace: el diccionario

Redis es un diccionario gigante: key → valor. El valor puede ser un string, un hash, una lista, un set, un sorted set, un stream… La key es un string binario (hasta 512 MB, pero sé razonable). Para identificar el tipo: TYPE key.

Los tipos y a qué problema responden

Por qué el tipo importa (memoria y operación)

Redis guarda cada valor con estructuras internas optimizadas según el tamaño (listpack/skiplist, intset…). Eso quiere decir: la estructura no es solo una «API»; define la eficiencia. Un hash con menos de ~128 campos y valores cortos se comprime a una sola fila; un sorted set usa skip lists. Elegir el tipo correcto ahorra RAM y mejora la latencia de cada comando.

No hay consultas «tipo SQL»

En Redis accedes por key. Si necesitas «todos los usuarios conectados que cumplen X», modelas para esa pregunta (índice auxiliar: un set o zset). Esto se llama denormalización planificada: ya sabes las consultas y creas las keys para responderlas.

Las DB lógicas (0-15) son separadores manuales dentro del mismo proceso. Úsalas con cuidado; el patrón moderno prefiere namespaces en la key (hub:conn:<id>) a cambiar de DB.

3 · Ejemplo mínimo

TYPE mi_key
SET  contar 10
INCR contar              # string usado como número
HSET user:42 nombre ana  role operadora
HGETALL user:42          # hash
RPUSH cola:jobs a b c
LRANGE cola:jobs 0 -1    # lista
SADD online user:42 user:7
SCARD online             # set
ZADD presencia 1750000000 user:42   # sorted set (score = ts)

Antes de cada comando, la key puede cambiar de tipo (¡error si mezclas tipos en la misma key!). Verifica con TYPE.

6 · Errores habituales

Mezclar tipos en la misma key

SET user:42 "operadora"
HSET user:42 role operadora    # ❌ WRONGTYPE Operation against a...
DEL user:42                    # borrar para empezar limpio

Keys infinitas que llenan la RAM

Si guardas conn:<guid> por conexión sin TTL y nunca borras, la memoria crece. Toda «presencia» debería expirar (M1-03).

9 · Resumen

  • Redis = diccionario de key → valor tipado.
  • Tipos: string, hash, list, set, sorted set, stream, bitmap/HLL.
  • El tipo define eficiencia y las operaciones atómicas disponibles.
  • Modelas «por consulta» (denormalización), no como SQL.

10 · Preguntas frecuentes

¿Puedo cambiar de tipo una key?

No directamente: lo que cambias es eliminar y crear (DEL + nuevo). Por eso conviene fijar el tipo al modelar.

¿KEYS es bueno para buscar?

No en producción: recorre todo el keyspace (O(N)). Usa SCAN o, mejor, índices propios (sets por dimensión).
