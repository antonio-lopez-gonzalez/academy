Registro de conexiones y presencia

Módulo 7 · El Hub de Conexiones WebSocket con Redis ⏱ 40 minutos

1 · Introducción

El corazón del hub: «¿dónde está la conexión X?» (registro) y «¿quién está conectado ahora?» (presencia). Ambas son responsabilidad de Redis, con hashes y zsets + TTL.

Aquí está el código concreto (redis-cli y .NET) que usará el proyecto final.

2 · Teoría

Registro por conexión (hash)

HSET hub:conn:8632 node node-1 userId 42 since 1750000000
EXPIRE hub:conn:8632 30
# ¿dónde está 8632? → HGET hub:conn:8632 node
# Detalle → HGETALL hub:conn:8632

Cada conexión es una key con su hash; el TTL se renueva con el heartbeat (lease).

Presencia global (zset)

ZADD hub:presence 1750000000 user:42
ZRANGEBYSCORE hub:presence 1749913600 +inf    # online desde hace 60 s
ZREMRANGEBYSCORE hub:presence -inf 1748913600 # limpiar viejos
ZCARD hub:presence

Cardinalidad de «presencia» (por nodo)

ZADD hub:presence:node:node-1 1750000000 user:42   # por nodo (opcional)
ZADD hub:presence:node:node-2 1750000000 user:7

Decisión: un zset global para «¿quién online?» + hashes por conexión para «¿dónde está cada uno?». Si además quieres «¿quién en qué nodo?», separa por nodo (o sácaselo del hash).

3 · Ejemplo mínimo

HSET hub:conn:100 node node-1 userId 42
EXPIRE hub:conn:100 30
ZADD hub:presence 1750000000 user:42
# simula clientes verde: consultas
HGET hub:conn:100 node
ZRANGEBYSCORE hub:presence -inf +inf

4 · Ejemplo real

Los métodos con que el redis-ws-hub gestiona registro + presencia:

public sealed class ConnectionRegistry
{
    private const long PresenceWindowSecs = 60;
    private readonly IDatabase _db;
    private readonly string _nodeId;

    public ConnectionRegistry(IConnectionMultiplexer mux, string nodeId)
        { _db = mux.GetDatabase(); _nodeId = nodeId; }

    public async Task RegisterAsync(string connectionId, string userId)
    {
        RedisKey key = $"hub:conn:{connectionId}";
        await _db.HashSetAsync(key,
            [new HashEntry("node", _nodeId),
             new HashEntry("userId", userId),
             new HashEntry("since", DateTimeOffset.UtcNow.ToUnixTimeSeconds())]);
        await _db.KeyExpireAsync(key, Lease);         // presencia por conexión

        long now = DateTimeOffset.UtcNow.ToUnixTimeSeconds();
        await _db.SortedSetAddAsync("hub:presence", userId, now);        // global
    }

    public async Task HeartbeatAsync(string connectionId, string userId)
    {
        // refresca el lease del registro y el score de presencia
        await _db.KeyExpireAsync($"hub:conn:{connectionId}", Lease);
        long now = DateTimeOffset.UtcNow.ToUnixTimeSeconds();
        await _db.SortedSetAddAsync("hub:presence", userId, now);
    }

    public async Task UnregisterAsync(string connectionId, string userId)
    {
        await _db.KeyDeleteAsync($"hub:conn:{connectionId}");
        await _db.SortedSetRemoveAsync("hub:presence", userId);
    }

    public async Task<RedisValue> FindNodeAsync(string connectionId)
        => await _db.HashGetAsync($"hub:conn:{connectionId}", "node");

    public async Task<RedisValue[]> OnlineAsync()
    {
        long cutoff = DateTimeOffset.UtcNow.ToUnixTimeSeconds() - PresenceWindowSecs;
        return await _db.SortedSetRangeByScoreAsync("hub:presence", cutoff, double.PositiveInfinity);
    }

    private static readonly TimeSpan Lease = TimeSpan.FromSeconds(30);
}

Un solo servicio centraliza registro/presencia y es el que reutilizan los handlers del socket.

5 · Buenas prácticas

HazEvitaPor qué
TTL en registro + zset de presenciaGuardar presencia solo en el hashEl hash ayuda «dónde», no «quién ahora»; el zset responde presencia
Heartbeat refrescando ambos (lease y score)Refrescar solo uno de los dosUn registro vivo con presencia muerta es inconsistente
Unregister explícito al desconectar (además del TTL)Dejarlo todo a la expiraciónLa expiración es el safety net; el unregister limpia al instante
Consulta de presencia con score cutoffZRANGE por rango pensando que es «online»«Online» = score reciente, no posición

6 · Errores habituales

Esperar «cero» presencia tras purgar con TTL

# ❌ Crear el registro sin EXPIRE → fantasma eterno
HSET hub:conn:8632 node node-1

# ✅ Siempre TTL (lease) + unregister
HSET hub:conn:8632 node node-1 EXPIRE hub:conn:8632 30

Contar «online» con SMEMBERS de un set en vez de zset

Un set no tiene tiempo; te dice «se añadió una vez». La presencia necesita score/ts → zset.

8 · Reto

🎯 Presencia multi-usuario

Tu presencia guarda «userId», pero un usuario puede tener varias conexiones (pestañas). Diseña cómo contarlas: pista — usa el zset con un miembro por (userId:connectionId) o un contador por usuario. Escribe la estructura elegida y 2 consultas que responderían «quantos sockets tiene user:42».

9 · Resumen

  • Registro = hash/TTL por conexión («¿dónde está?»).
  • Presencia = zset con score-timestamp («¿quién y desde cuándo?»).
  • Heartbeat refresca ambos; unregister explícito + expiración safety.
  • Un servicio ConnectionRegistry para reutilizar.

10 · Preguntas frecuentes

¿Por qué no usar solo el hash para «quién está online»?

El hash no es enumerable por tiempo; el zset responde «los de la última ventana» al instante. Son dos estructuras para dos preguntas, ambas baratas.

¿El TTL del registro y el del zset deben coincidir?

No necesariamente. El registro (dónde) puede vivir 30 s; la ventana de presencia 60 s. Define cada lease por su propósito.
