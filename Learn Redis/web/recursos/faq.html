FAQ general del curso

Referencia ❓ Dudas frecuentes
¿Necesito instalar Redis para seguir el curso?

Sí, y la vía más cómoda es Docker: docker run -d -p 6379:6379 redis:7.4-alpine. En proyectos/redis-ws-hub hay un docker-compose.yml con Redis y RedisInsight. Si no puedes usar Docker, Redis tiene instaladores nativos (Windows: usar WSL o la imagen Docker; la vía recomendada es Linux/container).

¿Redis es solo una caché?

No. Aunque destaca como caché (TTL, eviction), es un servidor de datos en memoria con estructuras ricas: listas (colas), sets, hashes, sorted sets, streams y pub/sub. En este curso lo usamos además como backplane y registro distribuido del hub.

Mi hub ahora funciona con un solo servidor. ¿Merece la pena Redis?

Si tienes una sola instancia, un diccionario en memoria sirve. Redis renta desde que quieres escalar horizontalmente (2+ nodos, failover), reiniciar sin perder presencia, o compartir estado entre procesos. El curso te da el patrón, y lo aplicas cuando llegue el momento.

¿StackExchange.Redis o IDistributedCache?

StackExchange.Redis es el cliente de bajo nivel (comandos reales, pub/sub, Lua, transacciones): es el que usamos para el hub. IDistributedCache (paquete AddStackExchangeRedisCache) es una abstracción simple de caché clave/valor sin pub/sub: la vemos como complemento en la lección de StackExchange.Redis.

¿Qué pasa si Redis se cae?

Depende de tu uso: con caché, tu app debe degradar con gracia (leer de la fuente y seguir). Con el hub, pierdes la presencia compartida temporalmente; hay que diseñar reconexión y re-registro (Módulo 7). Nunca hagas a Redis un punto único de fallo sin plan de caída.

¿Redis es "gratis"?

Redis es open source (BSD-3 / licencia RSAL/SSPL desde 8 según el componente). Puedes ejecutarlo tú mismo con Docker; proveedores gestionados (Upstash, Redis Cloud, AWS ElastiCache) cobran por el servicio. Este curso usa el servidor libre local.

¿Qué versión de Redis uso?

El curso se escribe contra las APIs estables (comandos compatibles 6→7→8). Las imágenes del proyecto usan redis:7.4-alpine (muy estable); Redis 8.x mantiene los mismos comandos y añade nuevos tipos de datos y mejoras. El código .NET funciona igual en ambas.

¿No es mejor una base de datos SQL para guardar conexiones?

Para estado efímero de alta frecuencia (presencia, sesiones, heartbeat), Redis es mejor: latencias de microsegundos y expiración nativa. SQL es la fuente de verdad si necesitas historial/consultas complejas. Se complementan: SQL persiste, Redis da velocidad (M5: cache-aside).
