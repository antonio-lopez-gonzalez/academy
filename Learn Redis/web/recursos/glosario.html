Glosario de Redis

Referencia 📖 De la A a la Z
AOF (Append Only File)
Persistencia que registra cada operación de escritura en un log; al reiniciar, Redis reproduce el log. Más duradero (ms a 1 s) y pesado que RDB.
Backplane
Capas de mensajería compartida que conectan varias instancias de una app (por ejemplo, varios nodos WebSocket). Con Redis, suele ser un canal de pub/sub.
Cache-aside (look-aside)
Patrón de caché: primero miras Redis; si hay acierto lo devuelves y si hay fallo lees la fuente de verdad (base de datos), guardas el resultado en Redis con TTL y lo devuelves.
Cache stampede (thundering herd)
Cuando una key expira justo en un pico de tráfico y N procesos consultan a la vez la fuente de verdad. Se mitiga con TTL/jitter, locks o soft-expiry.
ConnectionMultiplexer
Cliente de StackExchange.Redis que gestiona la conexión(es) a Redis. Se crea una sola vez por proceso y es thread-safe.
DB lógica (0–15)
Espacios de keys separados dentro de un mismo servidor Redis (máx. 16 por defecto). No es particionado: todas comparten el mismo proceso y memoria.
Eviction (LRU/LFU/…) y maxmemory
Política que decide qué keys borrar cuando se alcanza maxmemory (por ejemplo allkeys-lru). Importante cuando la caché supera la RAM.
Expiración / TTL
Cada key puede tener una vida útil (EXPIRE). Al agotarse, Redis la borra (lazy + active). Es la base de la "presencia" con heartbeats (TTL que se refresca).
Hash
Estructura de mapa campo→valor bajo una key. Ideal para representar un objeto (p. ej. una conexión del hub).
Hash slot
En Redis Cluster, cada key se asigna a uno de los 16384 slots (CRC16(key) % 16384); cada nodo dueño de un rango de slots.
INCR / atomicidad
Operaciones atómicas: Redis ejecuta cada comando en un solo paso (single-thread), sin condiciones de carrera entre clientes para un mismo comando.
Key
El identificador (string binario) de cada valor almacenado. Con nombres espaciados (domain:type:id) para no chocar entre equipos.
List
Lista ordenada con operaciones en cabeza y cola (LPUSH/RPOP). Sirve como pila (LIFO) o cola (FIFO), y con BRPOP/BLPOP como cola bloqueante.
maxmemory-policy
Ver Eviction.
MULTI/EXEC (transacciones)
Grupo de comandos que se ejecutan en bloque (sin intercalar otros). No son rollback — se valida al encolar y se ejecutan todos o el pipeline se marca de error.
Pipeline
Enviar varios comandos a la vez sin esperar la respuesta de cada uno, para reducir el round-trip. StackExchange.Redis tiene IBatch.
Pub/Sub
Modelo publicador-suscriptor: PUBLISH a un canal entrega el mensaje a todos los SUBSCRIBE activos. El mensaje no queda guardado (fire-and-forget).
RDB (Redis Database File)
Snapshot binario periódico del keyspace (SAVE/BGSAVE). Compacto y rápido de restaurar, pero puede perder lo escrito desde el último snapshot.
Redis Cluster
Modo de sharding con múltiples nodos y réplicas, reparto por hash slots y tolerancia a fallos a nivel de nodo (sin Sentinel por nodo).
RedisInsight
GUI oficial de Redis para explorar keys, ver estructuras, ejecutar comandos y monitorizar (imagen redis/redisinsight).
Replica / replicaof
Réplica de solo lectura que sigue al primary (REPLICAOF host port). Base de la alta disponibilidad y de las lecturas escaladas.
Sentinel
Proceso que monitoriza primary/replicas y promueve una réplica cuando el primary cae; la app descubre el primary actual preguntando al Sentinel.
Set
Colección de miembros únicos sin orden (SADD/SMEMBERS). Ideal para "usuarios conectados a X", tags o permisos.
Single-threaded
Redis ejecuta los comandos en un solo hilo (event loop). Eso simplifica la atomicidad; la latencia por comando es microsegundos y no debe bloquearse (comandos O(N) elevados, KEYS, etc.).
Sorted set (zset)
Como un set pero con un score por miembro; ordenado por score. Sirve para rankings, ventanas temporales (score = timestamp) y rate limiting.
Stream
Log de eventos append-only con ID progresivo (XADD) y consumo por grupos (XREADGROUP/XACK). Mensajes persistidos hasta que se recortan/borran.
String
El tipo básico (hasta 512 MB). Sirve para caché, contadores binarios y hasta bitsets. Soporta INCR, GETSET, MGET, etc.
TTL / jitter
TTL es la vida de la key; aplicar un pequeño jitter aleatorio a los TTL evita que muchas keys expiren a la vez (estampada generalizada).
