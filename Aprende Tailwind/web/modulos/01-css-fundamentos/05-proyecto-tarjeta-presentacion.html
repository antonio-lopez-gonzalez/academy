🛠 Proyecto: tarjeta de presentación

Módulo 1 · CSS: Fundamentos ⏱ 45 minutos

1 · Introducción

Imagina que estás en un evento de networking. Alguien te pide tu tarjeta de presentación. No tienes una física, pero sacas tu móvil, abres un enlace y le muestras una tarjeta digital impecable. Con tu foto, tu nombre, a qué te dedicas, tus redes sociales y un diseño que habla bien de ti antes de que digas una palabra.

Eso es lo que vamos a construir hoy.

Este proyecto aplica TODO lo aprendido en el Módulo 1: el modelo de caja (padding, border, margin), display y posicionamiento (badge "online" con absolute), selectores con especificidad controlada (metodología BEM), unidades relativas (rem, %, ch) y custom properties para los colores. No usaremos Tailwind — lo haremos con CSS puro para asentar las bases. Cuando llegues a Tailwind en el Módulo 4, entenderás exactamente qué hay debajo de cada clase de utilidad.

Al terminar este proyecto tendrás:

  • Una tarjeta de presentación digital completa con HTML y CSS puro.
  • Un avatar circular con badge de estado "online" posicionado absolutamente.
  • Botones de contacto estilizados.
  • Un diseño responsive que se ve bien en móvil y desktop.
  • Comprensión práctica de cómo se integran todos los conceptos de CSS fundamental.

2 · Teoría

¿Por qué construir algo con CSS puro antes de aprender Tailwind?

Tailwind no es magia. Cada clase de Tailwind compila a una propiedad CSS real. Cuando escribes class="flex items-center gap-4 p-6 rounded-xl", Tailwind genera:

.flex { display: flex; }
.items-center { align-items: center; }
.gap-4 { gap: 1rem; }
.p-6 { padding: 1.5rem; }
.rounded-xl { border-radius: 0.75rem; }

Si no entiendes qué hace display: flex o por qué gap es mejor que margin para separar elementos, usar Tailwind se convierte en copiar y pegar clases sin criterio. El objetivo de este módulo es que entiendas el CSS que hay DEBAJO de Tailwind. Cuando termines, cada clase de Tailwind te será transparente: sabrás exactamente qué propiedad CSS representa.

La tarjeta de presentación como laboratorio de CSS

Una tarjeta de presentación es el proyecto perfecto para practicar fundamentos porque concentra todos los conceptos clave en un espacio reducido:

  • Modelo de caja: padding interior de la tarjeta, margin entre elementos, border sutil.
  • Display: block para la tarjeta, inline-block/inline para badges y etiquetas.
  • Posicionamiento: relative en el contenedor del avatar, absolute en el badge "online".
  • Unidades: rem para espaciado, % para anchos, ch para limitar texto.
  • Custom properties: paleta de colores centralizada en :root.
  • Selectores: BEM para nombrar componentes sin colisiones.

Metodología BEM aplicada al proyecto

BEM (Block, Element, Modifier) es una convención de nomenclatura que evita colisiones de nombres en CSS. La sintaxis es:

.bloque { }                  /* El componente */
.bloque__elemento { }        /* Una parte del componente */
.bloque--modificador { }     /* Una variante del componente */

En nuestra tarjeta usaremos:

.profile-card { }                   /* El bloque */
.profile-card__avatar-wrapper { }    /* El contenedor de la foto */
.profile-card__avatar { }            /* La foto en sí */
.profile-card__status { }            /* El badge "online" */
.profile-card__name { }              /* El nombre */
.profile-card__role { }              /* El cargo */
.profile-card__bio { }               /* La biografía */
.profile-card__actions { }           /* El contenedor de botones */
.profile-card__button { }            /* Botones individuales */
.profile-card__button--primary { }   /* Variante: botón principal */

BEM nos da nombres únicos y autoexplicativos. Nadie más en el proyecto tendrá una clase llamada .profile-card__status. Sin colisiones, sin sobrescrituras accidentales.

5 · Buenas prácticas

✅ Haz esto ❌ Evita esto 🤔 Por qué
Usa BEM para nombrar clases: .profile-card__avatar en vez de .avatar Nombres genéricos como .card, .title, .button — colisionan en proyectos con más de un desarrollador BEM crea un namespace por componente. .profile-card__title y .pricing-card__title nunca colisionan
Centraliza colores y tamaños en custom properties dentro de :root Repetir el mismo valor hexadecimal en 10 selectores distintos Cambiar un color en 1 sitio vs 10 sitios. Además, habilita theming (claro/oscuro) con solo redefinir variables
Usa max-width + width: 100% para componentes que deben ser flexibles Usar width: 400px fijo que desborda en pantallas de 375px max-width establece un techo; width: 100% permite que el elemento se encoja. Juntos son responsive sin media queries
Pon position: relative en el ancestro directo de cualquier elemento con position: absolute Dejar absolute sin contexto — se va al viewport o a un ancestro inesperado El posicionamiento predecible requiere un contexto de posicionamiento explícito
Organiza el CSS en este orden: reset → custom properties → elementos base (body) → layout → componentes → variantes Escribir CSS desordenado y depender de la especificidad para que funcione El orden predecible aprovecha la cascada en vez de luchar contra ella

6 · Errores habituales

🚫 "Mi badge online no se ve en la esquina del avatar"

Causa más común: olvidaste poner position: relative en .profile-card__avatar-wrapper. Sin él, el badge con position: absolute se posiciona respecto al ancestro posicionado más cercano, que probablemente sea la tarjeta o el body. Solución: siempre crea el contexto de posicionamiento con position: relative en el wrapper.

🚫 "Los botones de acción no tienen el mismo ancho"

Causa: usaste display: inline-block en los botones sin width: 100%. Los inline-block toman el ancho de su contenido. Solución: display: block; width: 100% en cada botón para que ocupen todo el ancho de la tarjeta.

🚫 "El borde blanco del badge no contrasta con el avatar"

Si el avatar tiene un borde de otro color o el fondo de la tarjeta no es blanco, el borde del badge se confunde. Solución: asegúrate de que border: 3px solid var(--color-surface) coincida con el color de fondo de la tarjeta. La propiedad box-shadow en el avatar no afecta al badge porque el badge está por encima en el contexto de apilamiento.

🚫 "Mi tarjeta se ve bien en desktop pero fatal en móvil"

Probablemente usaste width: 400px en lugar de max-width: 400px; width: 100%. O usaste padding fijo enorme que no deja espacio para el contenido en pantallas pequeñas. Solución: max-width + width: 100% para la tarjeta y padding responsive con clamp(): padding: clamp(20px, 5vw, 40px) clamp(16px, 4vw, 32px);.

7 · Ejercicio guiado

Vamos a añadir una funcionalidad extra a la tarjeta: un botón para expandir/colapsar la bio. Esto nos permite practicar cómo CSS y un poco de JavaScript pueden trabajar juntos.

HTML adicional (dentro de .profile-card, después de .profile-card__bio)

<button class="profile-card__expand-btn" aria-expanded="false">
  Leer más
  <span class="profile-card__expand-icon">▼</span>
</button>

CSS para la bio colapsable

.profile-card__bio {
  max-height: 4.8em;              /* ~3 líneas de texto */
  overflow: hidden;
  transition: max-height 0.4s ease;
  position: relative;
}

/* Estado expandido */
.profile-card__bio--expanded {
  max-height: 20em;              /* suficiente para todo el texto */
}

.profile-card__expand-btn {
  display: inline-flex;
  align-items: center;
  gap: 6px;
  background: none;
  border: none;
  color: var(--color-primary);
  font-size: 0.85rem;
  font-weight: 600;
  cursor: pointer;
  padding: 4px 8px;
  margin-top: -12px;
  margin-bottom: 20px;
  transition: color 0.2s;
}

.profile-card__expand-btn:hover {
  color: var(--color-primary-hover);
}

.profile-card__expand-icon {
  font-size: 0.65rem;
  transition: transform 0.3s;
}

.profile-card__bio--expanded ~ .profile-card__expand-btn .profile-card__expand-icon {
  transform: rotate(180deg);
}

JavaScript

document.querySelector('.profile-card__expand-btn').addEventListener('click', function() {
  const bio = document.querySelector('.profile-card__bio');
  const isExpanded = bio.classList.toggle('profile-card__bio--expanded');
  this.setAttribute('aria-expanded', isExpanded);
  this.childNodes[0].textContent = isExpanded ? 'Leer menos ' : 'Leer más ';
});

El truco aquí es max-height en lugar de height para la animación: pasar de max-height: 4.8em a max-height: 20em es transicionable. overflow: hidden recorta el texto sobrante. La flecha rota 180 grados gracias a transform: rotate(180deg) en el icono — nota el uso del combinador ~ (hermano general).

8 · Reto

🎯 Personaliza y extiende la tarjeta

Toma el código completo de la tarjeta de presentación y haz las siguientes mejoras por tu cuenta:

  1. Tema oscuro: Añade una clase .dark al body que redefina las custom properties para un tema oscuro. Crea un botón de toggle (sol/luna) en la esquina de la tarjeta usando position absolute.
  2. Avatar con iniciales: En lugar de usar una imagen externa, crea el avatar con las iniciales del nombre usando CSS puro (background + ::after con content: attr(data-initials)).
  3. Tooltip en el badge online: Al hacer hover sobre el badge verde, muestra un tooltip que diga "En línea ahora" usando el pseudo-elemento ::after.
  4. Animación de carga: Cuando la página carga, la tarjeta debe aparecer con una animación de fade-in + slide-up (opacity + transform: translateY).
  5. Enlaces de redes sociales con iconos reales: Sustituye los textos "GH", "LI" por iconos SVG inline o emojis.

9 · Resumen

  • La tarjeta de presentación integra los 4 temas del Módulo 1: modelo de caja (padding/border/margin en la tarjeta y elementos), display y posicionamiento (badge absolute dentro de relative, flex en stats y botones), selectores BEM (sin colisiones, nombres autoexplicativos), unidades y custom properties (colores y tamaños centralizados).
  • BEM (.bloque__elemento--modificador) es una convención que previene colisiones de nombres. Cada componente tiene su namespace.
  • Custom properties en :root actúan como single source of truth para colores, tipografía y espaciado. Cambiar un valor en :root lo propaga a toda la UI.
  • position: relative + absolute es el patrón fundamental para posicionar elementos "flotantes" (badges, tooltips, dropdowns) dentro de un contenedor.
  • max-width + width: 100% es la combinación responsive más simple: el elemento se adapta a pantallas pequeñas sin desbordar.
  • El orden del CSS importa: reset → variables → base → layout → componentes → variantes. La cascada es tu aliada si la organizas bien.
  • Tailwind automatiza todo esto. En el Módulo 4 verás cómo cada clase de Tailwind equivale a una o varias líneas del CSS que acabas de escribir a mano. La diferencia: con Tailwind escribes 10 clases en el HTML en lugar de 100 líneas de CSS. Pero ahora entiendes qué hay debajo.

10 · Preguntas frecuentes

¿Por qué usamos BEM si luego Tailwind no lo necesita?

BEM resuelve el problema de nombres en CSS tradicional. Tailwind lo resuelve de otra forma: eliminando los nombres por completo. Con Tailwind no creas clases con nombres semánticos — usas clases de utilidad directamente en el HTML. Pero entender BEM te ayuda a comprender POR QUÉ Tailwind tomó esa decisión radical. Además, en proyectos donde uses CSS tradicional (legacy, o componentes muy complejos), BEM sigue siendo una herramienta valiosa.

¿Este código es accesible?

Hemos incluido buenas prácticas de accesibilidad: alt descriptivo en la imagen, aria-label en los enlaces de redes sociales, title en el badge, aria-expanded en el botón de expandir. Pero una tarjeta de presentación real necesitaría más: roles ARIA adecuados, contraste de color verificado (WCAG AA), y navegación por teclado completa. La accesibilidad es un tema profundo que abordaremos en detalle en el Módulo 7.

¿Cómo haría esto mismo con Tailwind?

La tarjeta completa se reduciría a unas 15-20 clases de Tailwind en el HTML, sin ningún archivo CSS aparte. Algo como class="bg-white rounded-3xl p-10 max-w-sm w-full text-center shadow-xl" para la tarjeta, class="relative w-30 h-30 mx-auto mb-5" para el wrapper del avatar, y class="absolute bottom-2 right-2 w-5.5 h-5.5 bg-green-500 border-3 border-white rounded-full" para el badge. Lo construiremos con Tailwind en el proyecto del Módulo 4.

¿Puedo usar este código en un proyecto real?

Absolutamente. Este es CSS estándar, compatible con todos los navegadores modernos. En producción probablemente querrías: (1) usar una imagen real en lugar de placehold.co, (2) añadir lazy loading a la imagen, (3) minificar el CSS, (4) añadir tests de accesibilidad, (5) asegurar que los enlaces de redes sociales van a URLs reales. Pero la arquitectura CSS es perfectamente válida para producción.
