Proyecto: Formulario de Registro Animado

Módulo 7 · Formularios, Animaciones y Patrones ⏱ 50 minutos

1 · Introducción

Esta lección es la culminación de todo el módulo. Vas a construir un formulario de registro completo que integra todo lo aprendido en las lecciones anteriores: estilización de inputs, estados de validación, checkboxes personalizados, transiciones, animaciones, floating labels con peer, indicador de fortaleza de contraseña, estado de carga en el botón y un toast de éxito animado.

¿Por qué un proyecto integrador?

Las lecciones individuales enseñan herramientas. Pero en el mundo real, esas herramientas se usan juntas. Un formulario de registro real tiene inputs, validación, checkbox legal, indicador de fortaleza de contraseña, estado de loading y feedback visual de éxito. Todo junto, funcionando en armonía. Este proyecto te enseña a orquestar todas las piezas.

No es un ejemplo por partes: es un solo archivo HTML funcional que puedes abrir en tu navegador. Todo el CSS usa clases de Tailwind (vía CDN para que funcione sin build). El JavaScript es mínimo y solo maneja lo que CSS no puede: validación al submit, toggle de visibilidad de contraseña, cálculo de fortaleza, estado de carga y el toast.

Al terminar tendrás un componente de registro de calidad profesional que puedes adaptar a cualquier proyecto real.

2 · Teoría

Arquitectura del proyecto

El formulario se compone de 5 módulos interconectados. Vamos a desglosarlos antes de escribir código:

MóduloTecnologíaResponsabilidad
1. Layout gridTailwind GridDistribuir campos en 1 o 2 columnas según viewport
2. Inputs con validaciónpeer + invalid:Campos de texto, email, password con borde rojo y mensaje de error condicional
3. Toggle contraseña + fortalezaJS toggle + CSS barsIcono de ojo para mostrar/ocultar + 4 barras de colores que indican fortaleza
4. Checkbox personalizadosr-only + peer + SVGCheckbox de términos con estilo personalizado y focus visible
5. Botón con spinner + toastJS loading + animación CSSSpinner durante el submit, toast de éxito/error que entra deslizándose

El indicador de fortaleza de contraseña

La fortaleza se calcula con un algoritmo simple basado en 4 criterios. Cada criterio cumplido ilumina una barra:

BarraCriterioColor
1ªLongitud ≥ 6 caracteresRojo (débil)
2ªContiene mayúsculas Y minúsculasNaranja (regular)
3ªContiene al menos 1 númeroAmarillo (buena)
4ªContiene al menos 1 carácter especialVerde (fuerte)

Las barras se implementan con 4 <div> que tienen h-1.5 rounded-full flex-1 y colores condicionales aplicados con JavaScript al detectar cambios en el input. No usamos peer- aquí porque la lógica requiere evaluar el contenido del input, algo que CSS no puede hacer.

El spinner de carga en el botón

Cuando el usuario hace clic en "Crear cuenta", ocurre lo siguiente:

  1. Se previene el envío real con e.preventDefault().
  2. Se valida el formulario (checkValidity()).
  3. El botón cambia a estado "cargando": el texto se reemplaza por un spinner SVG con animate-spin y el botón se deshabilita.
  4. Después de 2 segundos simulados, el formulario se resetea y aparece el toast de éxito.

El toast de éxito

El toast usa la técnica aprendida en la lección 02: una animación slide-down que mueve el toast desde translateY(-16px) hasta su posición natural. El toast se posiciona con fixed top-4 right-4 z-50, tiene una barra de progreso que se consume en 4 segundos, y se auto-elimina después de 4 segundos con una animación de salida.

3 · Ejemplo mínimo

Antes de construir el formulario completo, veamos cómo funciona el indicador de fortaleza de contraseña. Es el componente más novedoso del proyecto:

<!-- Input de contraseña -->
<input id="password" type="password"
       oninput="updateStrength(this.value)"
       class="w-full px-4 py-2.5 bg-slate-900 border border-slate-600
              rounded-lg text-sm text-slate-200
              focus:outline-none focus:border-blue-500
              focus:ring-2 focus:ring-blue-500/30
              transition-all duration-200"
       placeholder="Mínimo 6 caracteres">

<!-- Indicador de fortaleza: 4 barras -->
<div class="flex gap-1.5 mt-2">
  <div id="bar-1" class="h-1.5 rounded-full flex-1
                         bg-slate-700 transition-colors
                         duration-300"></div>
  <div id="bar-2" class="h-1.5 rounded-full flex-1
                         bg-slate-700 transition-colors
                         duration-300"></div>
  <div id="bar-3" class="h-1.5 rounded-full flex-1
                         bg-slate-700 transition-colors
                         duration-300"></div>
  <div id="bar-4" class="h-1.5 rounded-full flex-1
                         bg-slate-700 transition-colors
                         duration-300"></div>
</div>
<p id="strength-text"
   class="text-xs text-slate-500 mt-1">
  Escribe una contraseña...
</p>
function updateStrength(password) {
  const bars = [
    document.getElementById('bar-1'),
    document.getElementById('bar-2'),
    document.getElementById('bar-3'),
    document.getElementById('bar-4')
  ];
  const text = document.getElementById('strength-text');

  const checks = [
    password.length >= 6,
    /[A-Z]/.test(password) && /[a-z]/.test(password),
    /[0-9]/.test(password),
    /[^A-Za-z0-9]/.test(password)
  ];

  const colors = ['bg-red-500', 'bg-orange-500',
                  'bg-yellow-500', 'bg-emerald-500'];
  const labels = ['Débil', 'Regular', 'Buena', 'Fuerte'];
  const inactive = 'bg-slate-700';

  let score = 0;
  bars.forEach((bar, i) => {
    if (checks[i]) {
      bar.className = bar.className.replace(inactive, colors[i]);
      score++;
    } else {
      bar.className = bar.className.replace(
        new RegExp(colors.join('|')), inactive
      ).replace(inactive, inactive); // reset
      bar.classList.add(inactive);
    }
  });

  if (password.length === 0) {
    text.textContent = 'Escribe una contraseña...';
    text.className = 'text-xs text-slate-500 mt-1';
  } else {
    text.textContent = labels[score - 1] ||
      'Escribe una contraseña...';
    text.className = `text-xs mt-1 text-${score > 2
      ? 'emerald' : score > 1
      ? 'yellow' : 'red'}-400`;
  }
}

¿Por qué JS y no CSS puro? La fortaleza de una contraseña requiere evaluar el contenido carácter por carácter (longitud, tipos de caracteres). CSS puede detectar :valid o :invalid basado en el atributo pattern, pero no puede contar caracteres ni clasificar tipos. Para una evaluación semántica de la contraseña, necesitas JavaScript.

<script>
  /* ====== TOGGLE CONTRASEÑA ====== */
  function togglePassword() {
    const input = document.getElementById('reg-password');
    const type = input.type === 'password'
      ? 'text' : 'password';
    input.type = type;
  }

  /* ====== FORTALEZA DE CONTRASEÑA ====== */

    'bg-red-500', 'bg-orange-500',
    'bg-yellow-500', 'bg-emerald-500'
  ];
  const strengthLabels = [
    'Débil — añade más caracteres',
    'Regular — incluye números',
    'Buena — añade caracteres especiales',
    'Fuerte — ¡contraseña segura!'
  ];

  document.getElementById('reg-password')
    .addEventListener('input', function(e) {
      const pass = e.target.value;
      const checks = [
        pass.length >= 6,
        /[A-Z]/.test(pass) && /[a-z]/.test(pass),
        /[0-9]/.test(pass),
        /[^A-Za-z0-9]/.test(pass)
      ];

      let score = 0;
      for (let i = 1; i <= 4; i++) {
        const bar = document.getElementById(
          'strength-bar-' + i);

            'bg-slate-700 transition-colors duration-300';
        }
      }

      const label = document.getElementById('strength-label');
      if (pass.length === 0) {
        label.textContent = 'Escribe una contraseña...';
        label.className = 'text-xs text-slate-500 mt-1';
      } else {
        label.textContent = strengthLabels[score - 1] ||
          'Escribe una contraseña...';
        const colors = ['text-red-400', 'text-orange-400',
          'text-yellow-400', 'text-emerald-400'];
        label.className = 'text-xs mt-1 ' +
          (colors[score - 1] || 'text-slate-500');
      }
    });

  /* ====== VALIDACIÓN DE CONFIRMACIÓN ====== */
  document.getElementById('confirm-password')
    .addEventListener('input', function(e) {
      const pass = document.getElementById('reg-password')
        .value;
      const error = document.getElementById(
        'password-match-error');
      if (e.target.value && e.target.value !== pass) {
        error.classList.remove('hidden');
      } else {
        error.classList.add('hidden');
      }
    });

  /* ====== SUBMIT CON SPINNER Y TOAST ====== */
  document.getElementById('register-form')
    .addEventListener('submit', async function(e) {
      e.preventDefault();

      // Validar HTML5
      if (!this.checkValidity()) {
        this.reportValidity();
        return;
      }

      // Validar que las contraseñas coincidan
      const pass = document.getElementById(
        'reg-password').value;
      const confirm = document.getElementById(
        'confirm-password').value;
      if (pass !== confirm) {
        document.getElementById('password-match-error')
          .classList.remove('hidden');
        return;
      }

      // Estado de carga
      const btn = document.getElementById('submit-btn');
      const btnText = document.getElementById('btn-text');
      const spinner = document.getElementById('btn-spinner');
      btn.disabled = true;
      btnText.textContent = 'Creando cuenta...';
      spinner.classList.remove('hidden');

      // Simular envío (2 segundos)
      await new Promise(r => setTimeout(r, 2000));

      // Resetear formulario
      this.reset();
      document.querySelectorAll('[id^="strength-bar-"]')
        .forEach(b => {
          b.className = 'h-1.5 rounded-full flex-1 ' +
            'bg-slate-700 transition-colors duration-300';
        });
      document.getElementById('strength-label')
        .textContent = 'Escribe una contraseña...';
      document.getElementById('strength-label')
        .className = 'text-xs text-slate-500 mt-1';

      // Restaurar botón
      btn.disabled = false;
      btnText.textContent = 'Crear cuenta';
      spinner.classList.add('hidden');

      // Mostrar toast
      showToast('Revisa tu correo para verificar tu cuenta.');
    });

  /* ====== TOAST ====== */
  function showToast(message) {
    const toast = document.getElementById('toast');
    document.getElementById('toast-msg')
      .textContent = message;

    // Resetear animación
    toast.classList.remove('hidden');
    toast.classList.remove('animate-slide-down');
    void toast.offsetWidth; // Forzar reflow
    toast.classList.add('animate-slide-down');

    // Resetear barra de progreso
    const progress = document.getElementById(
      'toast-progress');
    progress.classList.remove('animate-shrink');
    void progress.offsetWidth;
    progress.classList.add('animate-shrink');

    // Auto-ocultar tras 4 segundos
    clearTimeout(toast._timeout);
    toast._timeout = setTimeout(() => hideToast(), 4000);
  }

  function hideToast() {
    const toast = document.getElementById('toast');
    toast.style.opacity = '0';
    toast.style.transform = 'translateY(-12px)';
    setTimeout(() => {
      toast.classList.add('hidden');
      toast.style.opacity = '';
      toast.style.transform = '';
    }, 300);
  }

El truco del reflow forzado

¿Por qué void toast.offsetWidth? Cuando quitas y vuelves a poner la misma clase de animación, el navegador no la re-ejecuta porque técnicamente no ha cambiado nada. offsetWidth fuerza un reflow (recalculo de layout), lo que hace que el navegador "olvide" que la animación ya se ejecutó y la reinicie desde el principio. Es un truco común para reiniciar animaciones CSS.

6 · Errores habituales

Error #1 — «El indicador de fortaleza no se actualiza al borrar caracteres»

Causa: Solo estás comprobando si se cumple el criterio, no reiniciando la barra cuando deja de cumplirse. Si el usuario escribe y luego borra, las barras que ya se iluminaron no vuelven a su estado inactivo. Solución: En cada iteración del bucle, siempre reinicia la barra a bg-slate-700 antes de comprobar si cumple el criterio. Solo aplica el color si el check es verdadero.

Error #2 — «El formulario se envía aunque las contraseñas no coincidan»

Causa: La validación de coincidencia de contraseñas no es nativa de HTML. El navegador no sabe que dos campos deben ser iguales. Solo required, type="email", pattern y minlength son validaciones nativas. Solución: Añade validación manual en el handler de submit: compara los valores de ambos campos y si no coinciden, muestra el error y haz return antes de proceder.

Error #3 — «El toast aparece solo la primera vez»

Causa: La animación CSS ya se ejecutó. Al volver a mostrar el toast con la misma clase animate-slide-down, el navegador no la re-ejecuta porque la propiedad animation-name no cambió. Solución: Quita la clase de animación, fuerza un reflow con void element.offsetWidth, y vuelve a añadir la clase. Esto reinicia la animación desde el principio.

Error #4 — «El botón de toggle contraseña envía el formulario»

Causa: El botón está dentro de un <form> y por defecto los <button> tienen type="submit". Al hacer clic en el ojo para mostrar/ocultar la contraseña, el formulario se envía. Solución: Siempre añade type="button" explícitamente a cualquier botón dentro de un formulario que no sea el de submit.

Error #5 — «El toast se superpone a otros elementos interactivos»

Causa: El toast no tiene z-50 o un valor suficientemente alto. Otros elementos con z-index (modales, dropdowns) pueden taparlo. Solución: Usa z-50 como mínimo para toasts. Si tu aplicación tiene modales (z-40), tooltips (z-30), dropdowns (z-20), diseña una escala de z-index: toasts en lo más alto porque son información urgente que el usuario debe ver.

7 · Ejercicio guiado

Vamos a reconstruir el formulario paso a paso, añadiendo cada capa de funcionalidad gradualmente. Empieza con un archivo HTML vacío y añade cada bloque en orden:

  1. Setup: Crea el HTML base con CDN de Tailwind. Añade <body class="bg-slate-900 min-h-screen flex items-center justify-center p-4">.
  2. Contenedor: Crea el <div> contenedor con max-w-2xl bg-slate-800 rounded-2xl border border-slate-700 shadow-2xl p-8.
  3. Cabecera: Añade el título "Crear cuenta" y subtítulo centrados.
  4. Form: Crea el <form id="register-form" novalidate class="space-y-5">.
  5. Fieldset datos personales: Grid de 2 columnas con nombre, apellidos, email (col-span-2), teléfono y país (select). Añade required y peer a los inputs. Añade mensajes de error con peer-invalid:.
  6. Fieldset seguridad: Input password con botón toggle (ojo), 4 barras de fortaleza, label de texto descriptivo. Input confirmar password con validación de coincidencia.
  7. Checkbox términos: Personalizado con sr-only + peer + div visual. Enlaces a términos y privacidad.
  8. Botón submit: Con texto normal + spinner SVG oculto. Estados hover, focus-visible, active, disabled.
  9. Toast HTML: Contenedor fixed con icono, texto, botón cerrar y barra de progreso. Oculto por defecto (hidden).

Estructura HTML primero (todo el markup sin JS). Estilos Tailwind después (clases en cada elemento). Validación visual con peer-invalid: a continuación. JavaScript al final para la interactividad. 9 · Resumen

  • Formularios completos: Combinan múltiples técnicas: grid para layout, peer para estados condicionales, sr-only para custom inputs, transiciones para feedback visual.
  • Grid en formularios: grid-cols-1 md:grid-cols-2 con md:col-span-2 para campos de ancho completo. Mobile-first: una columna en móvil, dos en desktop.
  • Toggle contraseña: Botón con type="button" (¡importante!) que cambia input.type entre password y text. Icono SVG con transición de color en hover.
  • Indicador de fortaleza: 4 barras que se iluminan secuencialmente según criterios de complejidad. Requiere JavaScript porque CSS no puede evaluar contenido semántico.
  • Botón con spinner: Alterna entre texto y spinner SVG con animate-spin. Deshabilita el botón durante la carga. Restaura al terminar.
  • Toast animado: fixed top-4 right-4 con animación slide-down. Barra de progreso con animate-shrink. Auto-ocultación con timeout y animación de salida. Truco del reflow para reiniciar animaciones.
  • Validación: HTML5 nativa (required, type, minlength) + validación manual en JS (coincidencia de contraseñas). novalidate en el form para controlar la UX. checkValidity() + reportValidity() para disparar la validación nativa bajo demanda.

10 · Preguntas frecuentes

¿Por qué usamos novalidate en el form si también usamos required?

novalidate desactiva los tooltips de validación nativos del navegador, que no puedes estilizar. Pero los atributos como required y type="email" siguen funcionando a nivel de CSS (activan :invalid y :valid) y a nivel de JavaScript (afectan a checkValidity()). La combinación te da: estilos visuales personalizados con Tailwind (invalid:border-red-500) + validación programática con JS (form.checkValidity()) + sin tooltips feos del navegador.

¿Cómo hago que el formulario funcione de verdad (enviar datos a un backend)?

Reemplaza el setTimeout simulado por una llamada fetch real:

const formData = new FormData(this);
const response = await fetch('/api/register', {
  method: 'POST',
  body: formData
});

if (response.ok) {
  showToast('¡Registro exitoso!');
} else {
  const error = await response.json();
  showErrorToast(error.message);
}

El resto del código (spinner, validación, toast) se mantiene igual.

¿Cómo evito envíos duplicados si el usuario hace doble clic?

Ya lo estás haciendo: al inicio del handler de submit, deshabilitas el botón (btn.disabled = true) y el CSS con disabled:cursor-not-allowed evita interacción adicional. Pero necesitas una protección extra: guarda un flag let isSubmitting = false; al inicio del script. En el handler, si isSubmitting es true, haz return inmediato. Ponlo a true al empezar y a false al terminar (en el finally de un try/catch). Esto protege contra clics rápidos incluso si el botón no se deshabilita a tiempo.

¿Por qué la barra de fortaleza no funciona con el foco del teclado?

Sí funciona. El listener está en el evento input, que se dispara con cualquier cambio de valor, ya sea escribiendo con teclado, pegando con Ctrl+V, o incluso usando el autocompletado del navegador. Si no funciona, comprueba que el id del input coincide con el getElementById en JavaScript y que el script se ejecuta después de que el DOM esté listo (el <script> al final del body garantiza esto).

¿Puedo usar este formulario en producción?

Sí, con algunos ajustes: (1) Reemplaza el CDN de Tailwind por el build de producción que solo incluye las clases usadas. (2) Conecta el formulario a tu backend real. (3) Añade protección CSRF (token en un campo oculto). (4) Considera rate limiting en el backend para evitar abusos. (5) Añade aria-* attributes para accesibilidad (aria-describedby para mensajes de error, aria-live para el toast). El diseño visual y las interacciones son perfectamente válidos para producción.
