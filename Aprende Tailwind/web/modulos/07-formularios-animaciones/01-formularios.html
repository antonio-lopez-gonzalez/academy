Formularios con Tailwind

Módulo 7 · Formularios, Animaciones y Patrones ⏱ 35 minutos

1 · Introducción

Los formularios son el punto de contacto más crítico entre el usuario y tu aplicación. Un formulario mal diseñado genera frustración, abandono y pérdida de conversiones. Un formulario bien diseñado es invisible: el usuario lo completa sin pensar.

Tailwind te da control absoluto sobre cada elemento de un formulario sin tener que luchar contra los estilos por defecto del navegador. Vas a aprender a estilizar todos los tipos de input, a crear layouts de formulario flexibles, a gestionar estados de validación y a construir componentes como checkboxes y radios personalizados usando únicamente CSS (con peer como protagonista).

¿Por qué es tan difícil estilizar formularios?

Cada navegador —Chrome, Firefox, Safari, Edge— renderiza los elementos de formulario de manera distinta. Un <select> en Chrome no se parece en nada a uno en Safari. Un checkbox tiene tamaño, color y forma diferentes según el sistema operativo. Tailwind no puede eliminar estas diferencias por sí solo, pero te da las herramientas para resetear y reconstruir cada elemento desde cero con consistencia cross-browser.

Al final de esta lección serás capaz de construir cualquier formulario — desde un simple login hasta un complejo formulario de registro multipaso — con Tailwind, sin dependencias externas.

2 · Teoría

El reseteo base: por qué lo necesitas

Antes de estilizar, necesitas una capa de reseteo para eliminar las diferencias entre navegadores. Tailwind v4 incluye Preflight (su reset moderno) que normaliza inputs, pero para formularios avanzados necesitas clases adicionales:

<!-- Reset imprescindible para inputs en Tailwind -->
<input class="
  appearance-none          /* Elimina estilos nativos del SO */
  bg-transparent           /* Fondo transparente (tú pones el bg) */
  outline-none             /* Quita el outline azul por defecto */
  w-full                   /* Ocupa todo el ancho disponible */
">
Regla de oro del foco

Siempre combina outline-none con un indicador de foco visible como focus:ring-2 focus:ring-blue-500. Si quitas el outline sin reemplazo, rompes la accesibilidad (WCAG 2.4.7: Focus Visible).

Tipos de input y su estilización

ElementoCómo se estilizaParticularidad

<input type="email">Idéntico a text. Usa invalid: para validación nativa.El navegador valida el formato automáticamente.
<input type="password">Idéntico a text. Los dots los pone el navegador.No puedes estilizar los caracteres de ocultación.
<input type="number">Igual que text. Oculta spinners con [appearance:textfield]Los spinners (flechas) rompen diseños.

El patrón label + input (accesibilidad)

Cada input debe tener un <label> asociado. Hay dos formas válidas:

<!-- Forma explícita (recomendada): for apunta al id del input -->
<label for="email" class="block text-sm font-medium text-slate-300 mb-1">
  Correo electrónico
</label>
<input id="email" type="email" class="...">

<!-- Forma implícita: el input está dentro del label -->
<label class="block text-sm font-medium text-slate-300 mb-1">
  Correo electrónico
  <input type="email" class="...">
</label>

La forma explícita (for + id) es preferible porque permite separar visualmente el label del input y es más fácil de interpretar para lectores de pantalla.

Peer: el arma secreta de los formularios

peer es una de las funcionalidades más potentes de Tailwind. Colocas peer en un elemento y puedes estilizar cualquier hermano posterior basándote en su estado. Es la base de floating labels, mensajes de error condicionales y validación visual sin JavaScript:

<div class="relative">
  <input id="name"
         class="peer w-full border rounded-lg px-4 py-3
                focus:border-blue-500 outline-none">

  <!-- Este label flota hacia arriba cuando el input tiene foco -->
  <label for="name"
         class="absolute left-4 top-3 text-slate-400
                peer-focus:text-blue-500
                peer-focus:-top-2.5 peer-focus:text-xs
                peer-focus:bg-slate-800 peer-focus:px-1
                transition-all duration-200">
    Nombre
  </label>

  <!-- Mensaje de error que aparece solo cuando el input es inválido -->
  <p class="text-red-400 text-xs mt-1 hidden
            peer-invalid:block">
    Este campo es obligatorio
  </p>
</div>
Limitación importante de peer

peer usa el combinador CSS ~ (subsequent-sibling), así que solo funciona con hermanos posteriores en el DOM. El mensaje de error debe ir después del input, no antes.

Layouts de formulario: los tres patrones clásicos

<!-- 1. Stack vertical (el más común y accesible) -->
<form class="flex flex-col gap-5 max-w-md">
  <div><label>...</label><input></div>
  <div><label>...</label><input></div>
  <button>Enviar</button>
</form>

<!-- 2. Grid de 2 columnas (formularios densos) -->
<form class="grid grid-cols-1 md:grid-cols-2 gap-4 max-w-2xl">
  <div><label>Nombre</label><input></div>
  <div><label>Apellidos</label><input></div>
  <div class="md:col-span-2"><label>Email</label><input></div>
</form>

<!-- 3. Inline (buscadores, suscripciones, filtros) -->
<form class="flex gap-2">
  <input class="flex-1" placeholder="Buscar...">
  <button>Buscar</button>
</form>

3 · Ejemplo mínimo

El formulario más pequeño posible con Tailwind: un input de email con label y botón de suscripción. Cada clase tiene un propósito concreto:

<form class="flex flex-col gap-4 max-w-sm mx-auto p-6
             bg-slate-800 rounded-xl border border-slate-700">
  <div>
    <label for="email"
           class="block text-sm font-medium text-slate-300 mb-1.5">
      Email
    </label>
    <input
      id="email"
      type="email"
      placeholder="tu@correo.com"
      class="w-full px-4 py-2.5 bg-slate-900
             border border-slate-600 rounded-lg
             text-sm text-slate-200
             placeholder:text-slate-500
             focus:outline-none focus:border-blue-500
             focus:ring-2 focus:ring-blue-500/20
             transition-all duration-200"
    >
  </div>

  <button
    type="submit"
    class="w-full py-2.5 bg-blue-600 text-white

El truco de has-[:checked]

El selector has-[:checked] (v4) estiliza el contenedor cuando contiene un hijo checked. Esto permite que toda la tarjeta cambie de color al seleccionar el radio button, algo imposible con CSS puro tradicional sin JS.

6 · Errores habituales

Error #1 — «El checkbox personalizado no se puede marcar con teclado»

Causa: Usaste hidden en el input nativo en vez de sr-only. Con hidden, el input desaparece completamente del flujo del documento y no recibe foco nunca. Solución: Siempre usa sr-only para ocultar el input nativo manteniéndolo accesible.

Error #2 — «peer-invalid no funciona en mi input»

Causas comunes: (1) El elemento con peer-invalid: no es hermano posterior del input en el DOM. Recuerda que peer usa el selector ~ que solo mira hacia adelante. (2) El navegador no considera el campo inválido hasta que el usuario interactúa con él. Usa required y haz submit para disparar la validación.

Error #3 — «El select personalizado no se abre al hacer clic en la flecha»

Causa: El SVG de la flecha no tiene pointer-events-none. Sin esta clase, el clic cae sobre el SVG y no sobre el <select> que está debajo. Solución: Añade pointer-events-none al contenedor del icono.

Error #4 — «Los inputs tienen diferente altura en Safari vs Chrome»

Causa: Safari aplica un padding interno distinto a los inputs. Solución: Usa appearance-none en todos los inputs y define explícitamente el padding (py-2.5). Tailwind aplica box-border por defecto via Preflight, lo que evita que el padding expanda el elemento.

Error #5 — «El autofill de Chrome pone fondo amarillo»

Solución: Usa [-webkit-autofill]:!bg-slate-900 [-webkit-autofill]:[transition-delay:9999s]. El truco del transition-delay:9999s evita que Chrome re-aplique el color amarillo tras su propia transición interna porque la transición nunca termina.

7 · Ejercicio guiado

Construye un formulario de contacto paso a paso. Cada paso añade una capa nueva:

Construye un formulario con los siguientes requisitos:

  • Campos: País (select personalizado), Dirección (text), Ciudad (text), Código Postal (text), Teléfono (tel).
  • Layout en grid de 2 columnas en pantallas medianas+, stack vertical en móviles.

  • Checkbox "Usar como dirección de facturación" personalizado.
  • Todos los campos con indicador de error (invalid:) y mensaje de error condicional.
  • Botón submit con ancho completo y estados interactivos.

9 · Resumen

  • Reset base: appearance-none bg-transparent outline-none en todos los inputs para eliminar estilos nativos del SO. Siempre reemplaza outline-none con focus:ring-* para accesibilidad.
  • Estados esenciales: focus: (ring + borde), invalid: (borde rojo), disabled: (opacidad + cursor), placeholder: (color secundario), required: y read-only:.
  • Label + input: Usa for + id (forma explícita). El label debe ser visible SIEMPRE, no solo el placeholder.
  • Checks y radios: Input nativo con sr-only + peer. Estilos visuales en un <div> hermano con peer-checked:. Nunca uses hidden.
  • Select: appearance-none + SVG de flecha posicionado con absolute right-0 + pointer-events-none.
  • Peer: peer-invalid:block hidden muestra mensajes de error condicionales sin JavaScript. Solo funciona con hermanos posteriores en el DOM.
  • Layouts: Stack vertical con flex flex-col gap-4, grid con grid grid-cols-1 md:grid-cols-2 gap-4, inline con flex gap-2.
  • Accesibilidad: sr-only no hidden. focus-visible:ring-* siempre. Tamaño mínimo de toque 44px (WCAG 2.5.5). Labels asociados siempre.

10 · Preguntas frecuentes

¿Cómo oculto las flechas de incremento en un input type="number"?

Añade estas clases: [appearance:textfield] [&::-webkit-inner-spin-button]:appearance-none [&::-webkit-outer-spin-button]:appearance-none. La primera es para Firefox, las otras dos para Chrome/Safari/Edge. Esto elimina los spinners manteniendo el teclado numérico en móviles.

¿Cómo hago un toggle de mostrar/ocultar contraseña?

Necesitas una mínima cantidad de JavaScript para cambiar el type del input entre password y text. Tailwind no puede cambiar atributos HTML. El botón de toggle (icono de ojo) se posiciona con absolute right-3 top-1/2 -translate-y-1/2 y un onclick que alterna el type. Lo verás implementado en la lección 04 del proyecto final.

¿peer-invalid funciona con validación personalizada (pattern)?

Sí. El atributo pattern acepta una expresión regular. Ej: pattern="[0-9]{5}" para un código postal de 5 dígitos. El modificador invalid: (y por tanto peer-invalid:) se activará cuando el valor no coincida con el patrón. También puedes usar setCustomValidity() en JavaScript para mensajes de error personalizados.

¿Cómo evito que el formulario se envíe si hay errores?

Tienes dos opciones: (1) Sin novalidate, el navegador muestra sus tooltips nativos y bloquea el envío automáticamente con required y type="email". (2) Con novalidate en el <form>, manejas la validación tú mismo con JavaScript para una UX más avanzada. La combinación ideal: validación nativa + estilos visuales con Tailwind + un poco de JS para el estado de loading y el toast de éxito.

¿Por qué mis floating labels no funcionan en Safari?

Safari tiene un bug histórico con peer-focus: en elementos con position: absolute dentro de un relative. Si el label flotante no responde, asegúrate de que el input tiene placeholder=" " (un espacio, no vacío). Algunas implementaciones de floating label usan peer-placeholder-shown: para detectar si el input está vacío, y Safari requiere que el placeholder no sea una cadena vacía.
