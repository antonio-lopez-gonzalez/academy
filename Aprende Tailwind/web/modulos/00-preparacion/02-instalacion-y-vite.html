Instalación y Vite

Módulo 0 · Preparación ⏱ 35 minutos

1 · Introducción

En la lección anterior entendiste qué es Tailwind CSS. Ahora vamos a tenerlo funcionando en tu ordenador. Esta es la parte más práctica del módulo: instalar herramientas, crear un proyecto y ver Tailwind en acción.

Al terminar esta lección tendrás:

  • Node.js instalado en tu sistema.
  • pnpm como gestor de paquetes rápido y eficiente.
  • Un proyecto Vite vanilla funcionando.
  • Tailwind CSS v4 integrado y generando estilos.
  • Un servidor de desarrollo ejecutándose en http://localhost:5173.

Importante: Vamos paso a paso. Cada comando está explicado. Si algo falla, no te preocupes — la sección de FAQ y errores habituales cubre los problemas más comunes. Y recuerda: todos pasamos por esto la primera vez.

2 · Teoría

¿Por qué necesitamos Node.js?

Tailwind CSS no es simplemente un archivo .css que descargas y enlazas. Tailwind es un generador de CSS: analiza tu HTML, detecta qué clases estás usando, y genera solo el CSS necesario. Para hacer esto, necesita ejecutarse en un entorno que entienda JavaScript fuera del navegador. Ese entorno es Node.js.

Piensa en Node.js como "el motor que permite ejecutar JavaScript en tu ordenador, no solo en el navegador". Es como tener un pequeño chef (Node) en tu cocina que prepara solo los platos (CSS) que tú pides (las clases que usas).

¿Por qué pnpm y no npm?

Tradicionalmente, Node.js incluye npm (Node Package Manager) para instalar paquetes. Funciona. Pero pnpm es una alternativa moderna que ofrece:

  • Velocidad: Hasta 2-3 veces más rápido que npm al instalar dependencias.
  • Eficiencia en disco: Si tienes 10 proyectos que usan la misma versión de Tailwind, pnpm la almacena una sola vez en tu disco y la enlaza a cada proyecto. npm la copia 10 veces.
  • Estricto: Por defecto, un paquete no puede usar dependencias que no ha declarado. Esto evita bugs misteriosos donde algo funciona "de casualidad".

No necesitas desinstalar npm. pnpm se instala como una herramienta adicional y puedes elegir cuál usar. En este curso, usaremos pnpm porque es el estándar moderno.

¿Qué es Vite y por qué lo usamos?

Vite (pronunciado "vit", francés para "rápido") es un bundler y servidor de desarrollo creado por Evan You (el creador de Vue.js). Pero no necesitas usar Vue — Vite funciona perfectamente con HTML vanilla, React, Svelte o cualquier cosa.

Las ventajas de Vite frente a opciones antiguas como webpack:

  • Arranque instantáneo: El servidor de desarrollo arranca en milisegundos, no en segundos o minutos. No hace bundling completo al iniciar.
  • Hot Module Replacement (HMR): Cuando editas un archivo, solo se actualiza ese módulo en el navegador. Sin recargar la página completa. Los cambios de CSS se ven al instante.
  • Configuración mínima: Vite funciona sin configuración para la mayoría de casos. Solo necesitas un plugin para Tailwind.
  • Usa ESM nativo: Aprovecha los módulos ES del navegador durante el desarrollo, lo que lo hace increíblemente rápido.

La combinación Vite + Tailwind CSS v4 es la recomendación oficial del equipo de Tailwind para nuevos proyectos. Es lo que usaremos en todo el curso.

Tailwind v4: la gran diferencia con v3

Si has oído hablar de tailwind.config.js, olvídalo. Tailwind v4 introdujo un cambio fundamental: configuración CSS-first.

En Tailwind v3 necesitabas un archivo JavaScript de configuración:

// tailwind.config.js — ESTILO ANTIGUO (v3), NO USAR
module.exports = {
  content: ['./src/**/*.{html,js}'],
  theme: {
    extend: {
      colors: {
        primary: '#3b82f6',
      }
    }
  }
}

En Tailwind v4, todo se configura directamente en tu CSS usando @theme:

@import "tailwindcss";

@theme {
  --color-primary: #3b82f6;
}

Esto es más limpio, más lógico (el CSS se configura en CSS) y permite que las herramientas de CSS existentes entiendan tu configuración. En su momento practicaremos con @theme en detalle.

El ecosistema de herramientas

Visualiza así el stack que vas a montar:

┌─────────────────────────────────────┐
│          TU CÓDIGO                  │
│  index.html  +  style.css           │
│  (escribes clases de Tailwind)      │
└──────────────┬──────────────────────┘
               │
               ▼
┌─────────────────────────────────────┐
│            VITE                     │
│  - Sirve los archivos              │
│  - Procesa Tailwind con el plugin  │
│  - Recarga el navegador (HMR)      │
│  - Optimiza para producción        │
└──────────────┬──────────────────────┘
               │
               ▼
┌─────────────────────────────────────┐
│     @tailwindcss/vite (plugin)     │
│  - Escanea tu HTML                 │
│  - Detecta clases usadas           │
│  - Genera solo el CSS necesario    │
│  - Aplica @theme y personalización │
└─────────────────────────────────────┘

Cada capa tiene una responsabilidad clara. Tú escribes HTML con clases de Tailwind. Vite orquesta el proceso. El plugin de Tailwind escanea y genera el CSS mínimo necesario.

3 · Ejemplo mínimo

Veamos la secuencia completa de comandos que ejecutarás. Léela primero para tener una visión general, luego desglosaremos cada paso en la sección del ejemplo real.

Secuencia de instalación (visión general)

# 1. Instalar pnpm (Windows PowerShell como Administrador)
iwr https://get.pnpm.io/install.ps1 -useb | iex

# 2. Crear carpeta del proyecto
mkdir mi-primer-tailwind
cd mi-primer-tailwind

# 3. Crear proyecto Vite vanilla
pnpm create vite@latest . -- --template vanilla

# 4. Instalar dependencias base
pnpm install

# 5. Instalar Tailwind CSS v4 y su plugin para Vite
pnpm add tailwindcss @tailwindcss/vite

# 6. Arrancar el servidor de desarrollo
pnpm dev

Eso es todo. En menos de 3 minutos (dependiendo de tu conexión a internet) tendrás Tailwind funcionando. Ahora vamos a entender cada paso en detalle.

4 · Ejemplo real

Paso 1: Verificar Node.js

Abre PowerShell (o Terminal) y ejecuta:

node --version

Deberías ver algo como v20.x.x o v22.x.x. Si ves un número de versión, Node.js ya está instalado. Si ves un error, descarga el instalador desde nodejs.org. Elige la versión LTS (Long Term Support), que es la más estable.

Durante la instalación en Windows, asegúrate de marcar la casilla "Automatically install the necessary tools". Esto instalará Chocolatey y herramientas de compilación que algunos paquetes necesitan.

Paso 2: Instalar pnpm

Abre PowerShell como Administrador (clic derecho en el icono de PowerShell → Ejecutar como administrador) y ejecuta:

iwr https://get.pnpm.io/install.ps1 -useb | iex

Este comando descarga e instala pnpm. Al terminar, cierra PowerShell y ábrelo de nuevo (esta vez no hace falta como administrador). Verifica la instalación:

pnpm --version

Deberías ver un número de versión (ej: 9.x.x).

🪟 Usuarios de Windows: Si el comando iwr da error de políticas de ejecución, ejecuta primero: Set-ExecutionPolicy RemoteSigned -Scope CurrentUser y luego vuelve a intentar.

Paso 3: Instalar VSCode

Si aún no tienes Visual Studio Code, descárgalo desde code.visualstudio.com. Es gratuito y es el editor más usado para desarrollo web.

Una vez instalado, abre VSCode, ve a la pestaña de extensiones (Ctrl+Shift+X) e instala:

  • Tailwind CSS IntelliSense (por Tailwind Labs) — imprescindible.

Este plugin te dará autocompletado de clases, previsualización de colores y tooltips con el CSS equivalente. En la Lección 3 lo exploraremos a fondo.

Paso 4: Crear el proyecto

Abre PowerShell y navega hasta donde quieras crear el proyecto:

cd C:\Desarrollo
mkdir mi-primer-tailwind
cd mi-primer-tailwind

Ahora crea el proyecto Vite usando la plantilla vanilla (HTML + CSS + JS puro):

pnpm create vite@latest . -- --template vanilla

El punto . le dice a Vite que cree el proyecto en la carpeta actual (no dentro de una subcarpeta nueva). El doble guión -- separa los argumentos de pnpm de los de Vite. Vite te preguntará si quieres continuar — dile que sí.

Instala las dependencias base del proyecto:

pnpm install

Paso 5: Instalar Tailwind CSS v4

pnpm add tailwindcss @tailwindcss/vite

Esto instala dos paquetes:

  • tailwindcss — el framework en sí.
  • @tailwindcss/vite — el plugin que conecta Tailwind con Vite para que procese tu CSS automáticamente.

Paso 6: Configurar vite.config.js

Abre el archivo vite.config.js que Vite creó en la raíz del proyecto. Tendrá este aspecto inicial:

import { defineConfig } from 'vite'

export default defineConfig({
  // plugins: []
})

Modifícalo para añadir el plugin de Tailwind. Debe quedar así:

import { defineConfig } from 'vite'
import tailwindcss from '@tailwindcss/vite'

export default defineConfig({
  plugins: [tailwindcss()]
})

Eso es todo lo que necesita Vite para saber que debe procesar Tailwind. No hay tailwind.config.js, no hay postcss.config.js, no hay más archivos de configuración. Así de simple es Tailwind v4.

Paso 7: Añadir Tailwind a tu CSS

Abre src/style.css (o style.css en la raíz, depende de la plantilla de Vite). Borra TODO el contenido existente y escribe únicamente:

@import "tailwindcss";

Esa sola línea le dice a Tailwind: "genera todo tu CSS por defecto y escanea mis archivos HTML para ver qué clases estoy usando". No necesitas @tailwind base, @tailwind components ni @tailwind utilities. En v4, @import "tailwindcss" lo reemplaza todo.

Paso 8: Verificar que el HTML enlaza el CSS

Abre index.html y asegúrate de que tiene un <link> a tu CSS. Con la plantilla vanilla de Vite, deberías ver algo como:

<link rel="stylesheet" href="/style.css">

o

<link rel="stylesheet" href="/src/style.css">

Depende de dónde esté tu CSS. Si usas src/style.css, el enlace debe apuntar a /src/style.css. Vite resuelve las rutas desde la raíz del proyecto.

Paso 9: Escribir HTML con Tailwind

Reemplaza el contenido del <body> en index.html con algo sencillo para probar:

<body class="bg-slate-900 min-h-screen flex items-center justify-center">
  <div class="text-center">
    <h1 class="text-5xl font-extrabold text-white mb-4">
      🎉 ¡Tailwind funciona!
    </h1>
    <p class="text-xl text-slate-400">
      Tu primer proyecto con Vite + Tailwind CSS v4
    </p>
  </div>
</body>

Paso 10: Arrancar el servidor

pnpm dev

Verás algo como:

VITE v6.x.x  ready in 350 ms

➜  Local:   http://localhost:5173/
➜  Network: use --host to expose

Abre http://localhost:5173 en tu navegador. Deberías ver un fondo oscuro con el texto blanco centrado. ¡Enhorabuena! Tailwind CSS v4 está funcionando en tu proyecto.

Estructura de archivos resultante

Tu proyecto debería tener esta estructura:

mi-primer-tailwind/
├── index.html
├── node_modules/          ← las dependencias (nunca se toca a mano)
├── package.json           ← metadatos del proyecto y scripts
├── pnpm-lock.yaml         ← bloqueo de versiones exactas
├── public/                ← archivos estáticos (imágenes, fuentes...)
├── src/
│   └── style.css          ← tu CSS con @import "tailwindcss"
└── vite.config.js         ← configuración de Vite + plugin Tailwind

Para detener el servidor de desarrollo, pulsa Ctrl+C en la terminal.

Para reanudarlo más tarde, simplemente navega a la carpeta del proyecto y ejecuta pnpm dev de nuevo.

5 · Buenas prácticas

✅ Haz esto ❌ Evita esto
Usa siempre la versión LTS de Node.js. Es la más estable y la que usan los servidores de producción Instalar la versión "Current" de Node.js si estás empezando. Puede tener bugs o cambios aún no adoptados por paquetes
Abre el proyecto en VSCode desde la raíz (code .) para que las extensiones funcionen correctamente Abrir solo un archivo suelto en VSCode. El plugin de Tailwind necesita ver el package.json para activarse
Confirma que Tailwind funciona escribiendo una clase obvia (bg-red-500) y viendo si surte efecto en el navegador Asumir que "está instalado" solo porque no hubo errores en la terminal. Siempre verifica visualmente
Mantén node_modules/ en .gitignore. Vite lo añade automáticamente, pero compruébalo Commitear node_modules a git. Son cientos de megabytes que se regeneran con pnpm install
Guarda el proyecto y haz commits tras cada paso importante para poder volver atrás si algo se rompe Hacer 20 cambios sin probar y luego no saber cuál rompió todo. Pequeños pasos, verificaciones constantes
Aprende los atajos de VSCode: Ctrl+Ñ abre la terminal integrada, Ctrl+B alterna la barra lateral Saltar entre ventanas de PowerShell y VSCode constantemente. La terminal integrada es mucho más rápida

6 · Errores habituales

🚫 "pnpm no se reconoce como un comando"

Causa: Después de instalar pnpm, no cerraste y reabriste la terminal. La variable de entorno PATH se actualiza al iniciar una nueva sesión de terminal.

Solución: Cierra PowerShell, ábrelo de nuevo y ejecuta pnpm --version. Si sigue fallando, reinicia el ordenador. En Windows, a veces es necesario.

🚫 "El CSS no se aplica aunque escribí clases de Tailwind"

Causa: Varias posibles: (1) No has añadido @import "tailwindcss" en tu CSS. (2) El vite.config.js no tiene el plugin tailwindcss(). (3) El HTML no está enlazando correctamente el CSS.

Solución: Revisa los tres puntos en orden. Abre las DevTools del navegador (F12) y mira la pestaña Network: ¿se está cargando el archivo CSS? ¿Su contenido incluye reglas de Tailwind? Si el CSS está vacío o solo tiene tu @import, el plugin no está procesándolo.

🚫 "Error: Cannot find module '@tailwindcss/vite'"

Causa: No has ejecutado pnpm add tailwindcss @tailwindcss/vite o lo ejecutaste en la carpeta equivocada.

Solución: Asegúrate de estar en la raíz del proyecto (donde está package.json) y ejecuta el comando de instalación. Verifica que package.json tenga "@tailwindcss/vite" y "tailwindcss" en dependencies.

🚫 "El puerto 5173 ya está en uso"

Causa: Otro proyecto Vite o alguna otra aplicación está usando ese puerto.

Solución: Vite detecta esto automáticamente y prueba con el siguiente puerto (5174, 5175...). Mira la salida de la terminal para ver en qué puerto se levantó. Si quieres forzar un puerto específico: pnpm dev --port 3000.

🚫 "Instalé Tailwind pero veo v3 en algún tutorial y me confundo"

Causa: Tailwind v4 es relativamente nuevo. Mucho contenido online está escrito para v3.

Solución: Diferencias clave para detectar tutoriales de v3: mencionan tailwind.config.js, usan @tailwind base/components/utilities en lugar de @import "tailwindcss", o instalan postcss y autoprefixer aparte. Si ves eso, el tutorial es de v3. La documentación oficial en tailwindcss.com siempre está actualizada a la última versión.

9 · Resumen

  • Node.js es el motor que permite ejecutar Tailwind (y otras herramientas de desarrollo) fuera del navegador. Necesitas la versión LTS instalada.
  • pnpm es un gestor de paquetes más rápido y eficiente que npm. Se instala una vez y lo usas en todos tus proyectos con pnpm add.
  • Vite es el servidor de desarrollo y bundler. Arranca instantáneamente y recarga los cambios automáticamente (HMR). Se configura con vite.config.js.
  • @tailwindcss/vite es el plugin oficial que conecta Tailwind con Vite. Se añade en el array plugins de vite.config.js.
  • Tailwind v4 no usa tailwind.config.js. Toda la configuración se hace con @theme dentro del CSS. La línea @import "tailwindcss" en tu archivo CSS es suficiente para empezar.
  • El comando pnpm dev arranca el servidor de desarrollo en http://localhost:5173. Los cambios en HTML o CSS se reflejan instantáneamente.
  • La estructura del proyecto es mínima: un HTML, un CSS con @import "tailwindcss", un vite.config.js con el plugin, y las dependencias en package.json.
  • En la próxima lección aprenderás el flujo de trabajo diario con Tailwind: cómo usar el plugin de VSCode, cómo inspeccionar estilos en DevTools y cómo consultar la documentación eficientemente.

10 · Preguntas frecuentes

¿Puedo usar npm en lugar de pnpm?

Sí. Todos los comandos son equivalentes: npm create vite@latest, npm install, npm add tailwindcss @tailwindcss/vite, npm run dev. pnpm es más rápido y eficiente, pero npm funciona perfectamente. Si prefieres npm, úsalo. Lo importante es que tengas Tailwind funcionando.

¿Necesito instalar PostCSS o Autoprefixer?

No. En Tailwind v3 era necesario instalar postcss y autoprefixer y crear un postcss.config.js. En Tailwind v4, el plugin @tailwindcss/vite gestiona todo eso internamente. No necesitas PostCSS ni Autoprefixer por separado.

¿Qué hago si Vite no detecta cambios en mis archivos?

Raro, pero puede pasar en Windows con sistemas de archivos antiguos o en WSL. Prueba: (1) Parar y reiniciar pnpm dev. (2) En vite.config.js, añadir server: { watch: { usePolling: true } } dentro del objeto de configuración. Esto hace que Vite compruebe cambios periódicamente en lugar de depender de eventos del sistema de archivos.

¿Puedo usar Tailwind con React, Vue o Svelte?

Absolutamente. Tailwind es agnóstico al framework. Funciona con HTML vanilla, React, Vue, Svelte, Angular, Astro, lo que sea. El setup sería idéntico al que has hecho aquí: añades el plugin @tailwindcss/vite a tu configuración de Vite, importas Tailwind en tu CSS y empiezas a usar clases en tu JSX/HTML. En módulos posteriores del curso trabajaremos con React + Tailwind.

¿Cómo actualizo Tailwind a futuras versiones?

Simplemente ejecuta pnpm update tailwindcss @tailwindcss/vite. Como Tailwind v4 es CSS-first, las actualizaciones suelen ser compatibles hacia atrás. Aun así, siempre revisa el changelog en el blog oficial antes de actualizar en proyectos importantes.

¿Puedo usar Tailwind sin Vite, solo con un CDN?

Tailwind tiene un Play CDN para prototipos rápidos: <script src="https://cdn.jsdelivr.net/npm/@tailwindcss/browser@4"></script>. Pero el CDN no es para producción: es más lento, no hace tree-shaking (incluye TODO el CSS de Tailwind, ≈300KB), y no soporta personalización con @theme. Para cualquier proyecto real, siempre usa el setup con Vite que has aprendido aquí.
