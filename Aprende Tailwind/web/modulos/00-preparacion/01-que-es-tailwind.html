Qué es Tailwind CSS

Módulo 0 · Preparación ⏱ 25 minutos

1 · Introducción

Imagina que quieres decorar tu casa. Tienes dos opciones:

  • Opción A: Comprar muebles prefabricados de una tienda — un sofá que viene en tres colores, una mesa de centro estándar, una estantería que encaja o no en tu pared. Es rápido, pero todo el mundo tiene la misma decoración.
  • Opción B: Comprar piezas de LEGO — bloques individuales de todos los colores y formas, y construir exactamente los muebles que imaginas. Tardas un poco más al principio, pero el resultado es 100% tuyo.

Bootstrap es la opción A. Tailwind CSS es la opción B.

En esta primera lección vas a entender qué es Tailwind CSS, por qué existe y por qué se ha convertido en la herramienta más popular para escribir estilos en la web moderna. No necesitas saber nada previo — empezamos desde cero.

Al terminar esta lección sabrás:

  • Qué problema resuelve Tailwind CSS.
  • En qué se diferencia de frameworks como Bootstrap.
  • Qué significa realmente "utility-first".
  • Por qué empresas como GitHub, Netflix, Shopify y OpenAI lo usan.

2 · Teoría

El problema del CSS a gran escala

Cuando empiezas un proyecto web pequeño, escribir CSS es fácil. Creas un archivo styles.css, escribes unas reglas y funciona. Pero el proyecto crece. El equipo crece. Y de repente:

  • Dead code: Tienes 3000 líneas de CSS y no sabes cuáles se usan y cuáles no. Borrar algo da miedo porque "¿y si se rompe algo en una página que no recuerdo?".
  • Colisiones de nombres: Dos developers crean una clase .card sin saberlo. Una sobrescribe a la otra. Bugs misteriosos. Pesadillas.
  • Especificidad fuera de control: Para sobrescribir .header .nav .link acabas escribiendo .header .nav .link.active#main. Cada vez más selectores anidados, cada vez más difícil de mantener.
  • Context switching constante: Editas HTML en un archivo y CSS en otro. Saltas de uno a otro todo el día. Tu cerebro se fríe.

El nacimiento de Tailwind CSS

Adam Wathan, un desarrollador canadiense, se enfrentó a estos problemas una y otra vez. En 2017, mientras trabajaba en un proyecto, empezó a experimentar con una idea radical: ¿y si en vez de crear clases con nombres como .login-form__submit-button, usáramos clases que describieran directamente el estilo que aplican?

Así nacieron clases como:

<button class="bg-blue-500 text-white font-bold py-2 px-4 rounded">
  Enviar
</button>

En lugar de:

<button class="submit-button">Enviar</button>

Y en otro archivo:

.submit-button {
  background-color: #3b82f6;
  color: white;
  font-weight: bold;
  padding: 0.5rem 1rem;
  border-radius: 0.25rem;
}

Adam publicó la primera versión de Tailwind CSS en noviembre de 2017. La comunidad lo adoptó masivamente. Hoy, con la versión 4, es el framework CSS con mayor crecimiento del ecosistema.

Utility-first vs Component-first

Esta es la diferencia fundamental que necesitas entender:

Component-first (Bootstrap) Utility-first (Tailwind)
Filosofía Te doy componentes ya diseñados Te doy piezas para que diseñes tú
Clases típicas .btn, .card, .navbar .flex, .p-4, .text-lg
Personalización Sobrescribir CSS existente Combinar clases libremente
Resultado visual Todos los sitios se parecen Cada sitio es único
Curva de aprendizaje Rápida al inicio Requiere aprender clases, pero luego eres imparable

Piensa en Bootstrap como comprar un coche ya fabricado. Es cómodo, te subes y conduces. Pero no puedes cambiar el motor, ni el color del salpicadero, ni la forma de los asientos sin un taller especializado.

Tailwind es como tener acceso a la fábrica de piezas del coche. Puedes construir el coche exactamente como quieres: eliges el motor, los asientos, el volante, los colores. Cada coche que sale es diferente porque cada conductor lo construye a su gusto.

Analogía LEGO: el poder de las piezas pequeñas

Coge una caja de LEGO clásica. Tienes cientos de piezas: ladrillos 2x4, 1x2, planchas, ruedas, ventanas. Con esas mismas piezas puedes construir:

  • Un castillo medieval.
  • Una nave espacial.
  • Un coche de carreras.
  • Un dragón.

Cada clase de Tailwind es un bloque de LEGO. flex es un ladrillo. p-4 es una plancha. text-red-500 es una pieza roja. Combinándolos construyes cualquier diseño, sin limitaciones.

Bootstrap sería como comprar un set de LEGO con instrucciones para construir solo el castillo. Puedes modificar algo, pero el resultado siempre se parece mucho al castillo original.

¿Por qué empresas gigantes usan Tailwind?

No es una moda pasajera. Tailwind resuelve problemas reales a escala empresarial:

  • Dead code eliminado automáticamente: Tailwind genera solo el CSS de las clases que realmente usas en tu HTML. Si no usas text-9xl, esa clase no se incluye en el CSS final. Tu hoja de estilos es mínima siempre.
  • Consistencia sin esfuerzo: Las clases como p-4 siempre son 1rem. No hay "cada developer usa el padding que le parece". Todo sigue la escala definida por el sistema de diseño de Tailwind.
  • Refactorización sin miedo: ¿Quieres cambiar el color de un botón? Cambias sus clases en el HTML y ya. No hay CSS que buscar, no hay cascada que romper, no hay miedo.
  • Colaboración real: Cuando todo el equipo usa las mismas utilidades, cualquiera puede leer el HTML de otro y entender exactamente qué estilos tiene cada elemento.

3 · Ejemplo mínimo

Veamos la diferencia entre Bootstrap y Tailwind con un ejemplo concreto: una tarjeta de producto sencilla.

Con Bootstrap (component-first):

<div class="card" style="width: 18rem;">
  <img src="camiseta.jpg" class="card-img-top" alt="Camiseta">
  <div class="card-body">
    <h5 class="card-title">Camiseta básica</h5>
    <p class="card-text">Algodón 100%, disponible en 5 colores.</p>
    <a href="#" class="btn btn-primary">Comprar</a>
  </div>
</div>

Funciona, sí. Pero si quieres que esta tarjeta tenga sombra diferente, bordes redondeados distintos o el botón de otro color, tienes que sobrescribir el CSS de Bootstrap. Y cada pequeña personalización es una batalla contra estilos que no has escrito tú.

Con Tailwind CSS (utility-first):

<div class="w-72 bg-white rounded-xl shadow-lg overflow-hidden">
  <img src="camiseta.jpg" alt="Camiseta" class="w-full h-48 object-cover">
  <div class="p-6">
    <h3 class="text-lg font-semibold text-gray-900">Camiseta básica</h3>
    <p class="mt-2 text-sm text-gray-600">Algodón 100%, disponible en 5 colores.</p>
    <button class="mt-4 w-full bg-indigo-600 text-white font-medium py-2 px-4 rounded-lg hover:bg-indigo-700">
      Comprar
    </button>
  </div>
</div>

Observa la diferencia: cada clase tiene un propósito concreto y explícito. No hay magia. w-72 es width: 18rem. bg-white es background-color: white. rounded-xl es border-radius: 0.75rem. Puedes leer el HTML y visualizar el diseño en tu cabeza.

¿Quieres cambiar la sombra? Cambias shadow-lg por shadow-2xl. ¿Quieres otro color de botón? Cambias bg-indigo-600 por bg-emerald-600. No buscas nada en ningún otro archivo. Todo está delante de tus ojos.

4 · Ejemplo real

Veamos un ejemplo más completo: el hero section de una landing page. Así se vería el HTML con Tailwind (este código es 100% real y ejecutable):

<header class="bg-gradient-to-br from-slate-900 to-slate-800 min-h-screen flex items-center">
  <div class="max-w-5xl mx-auto px-6 py-24 text-center">
    <span class="inline-block px-4 py-1.5 rounded-full text-sm font-medium bg-indigo-500/10 text-indigo-400 border border-indigo-500/20">
      🚀 Nuevo curso disponible
    </span>

    <h1 class="mt-8 text-5xl md:text-7xl font-extrabold text-white leading-tight">
      Aprende Tailwind CSS
      <span class="block text-transparent bg-clip-text bg-gradient-to-r from-indigo-400 to-purple-400">
        desde cero hasta profesional
      </span>
    </h1>

    <p class="mt-6 max-w-2xl mx-auto text-lg text-slate-400 leading-relaxed">
      Domina el framework CSS más popular del mundo. Construye interfaces modernas,
      rápidas y mantenibles sin pelearte con el CSS tradicional.
    </p>

    <div class="mt-10 flex flex-col sm:flex-row gap-4 justify-center">
      <a href="#" class="px-8 py-3.5 rounded-xl bg-indigo-600 text-white font-semibold hover:bg-indigo-500 transition-colors">
        Empieza gratis
      </a>
      <a href="#" class="px-8 py-3.5 rounded-xl bg-white/10 text-white font-semibold hover:bg-white/20 transition-colors border border-white/10">
        Ver temario
      </a>
    </div>
  </div>
</header>

Fíjate en varios detalles importantes:

  • Cada clase hace una cosa: flex activa flexbox. justify-center centra horizontalmente. gap-4 añade espacio entre hijos. Todo explícito.
  • Responsive sin media queries: Los prefijos como md: y sm: aplican la clase solo a partir de ciertos anchos de pantalla. text-5xl md:text-7xl significa: "texto tamaño 5xl en móvil, tamaño 7xl a partir de pantalla md".
  • Estados con prefijos: hover:bg-indigo-500 aplica ese color de fondo solo al pasar el ratón. transition-colors anima el cambio suavemente.
  • Gradientes como clases: bg-gradient-to-br from-slate-900 to-slate-800 crea un gradiente diagonal. Sin escribir linear-gradient() a mano.
  • Texto con gradiente: text-transparent bg-clip-text bg-gradient-to-r from-indigo-400 to-purple-400 aplica un gradiente al texto. Esto en CSS tradicional son 4 propiedades que tienes que recordar.

Este es el tipo de código que escribirás en este curso. Al principio puede parecer mucho texto en el HTML, pero en la Lección 3 verás que tras unos días de práctica, tu cerebro aprende a "parsear" estas clases automáticamente, como cuando aprendes a leer un nuevo idioma.

6 · Errores habituales

🚫 "Tailwind es como escribir estilos inline"

Es la crítica más común de quien no lo ha usado. No es inline. El estilo inline (style="color: red") no tiene media queries, no tiene estados (:hover, :focus), no tiene diseño responsive, no se puede optimizar ni cachear. Tailwind tiene todo eso y más. md:text-lg hover:bg-blue-500 no tiene equivalente en inline styles.

🚫 "Con Bootstrap ya sé hacer webs, no necesito Tailwind"

Bootstrap es estupendo para prototipos y proyectos donde el diseño visual no es prioritario. Pero en cuanto necesitas un diseño personalizado (el 95% de los proyectos profesionales), Bootstrap se convierte en un obstáculo. Tailwind no compite con Bootstrap en "componentes listos para usar" — compite en libertad de diseño.

🚫 "No quiero aprender otro framework de CSS"

Tailwind no es otro lenguaje que aprender. Cada clase es literalmente una propiedad CSS abreviada. Si sabes CSS (o lo vas aprendiendo), sabes Tailwind. flex = display: flex. m-4 = margin: 1rem. No hay curva de aprendizaje de un nuevo lenguaje — hay curva de memorización de nombres de clase, que se resuelve con el plugin de VSCode y la práctica.

🚫 "Mi HTML va a ser un desastre ilegible"

Es la reacción inicial de todo el mundo. Yo también la tuve. A las dos semanas de usar Tailwind, tu cerebro se adapta. Lees flex items-center gap-4 p-6 igual de rápido que lees "esto es flexbox, centrado vertical, con espacio y padding". La legibilidad mejora porque no tienes que ir a otro archivo a buscar qué hace .card__wrapper. Todo está delante de ti.

7 · Ejercicio guiado

No necesitas tener nada instalado todavía. Este es un ejercicio puramente conceptual para entrenar tu ojo.

Traduce mentalmente de CSS a Tailwind

Aquí tienes un bloque de CSS tradicional. Intenta imaginar qué clases de Tailwind usarías para lograr el mismo resultado. Luego mira la solución.

.profile-card {
  background-color: white;
  border-radius: 8px;
  padding: 24px;
  display: flex;
  align-items: center;
  gap: 16px;
  box-shadow: 0 4px 6px rgba(0, 0, 0, 0.1);
  max-width: 400px;
}

.profile-card img {
  width: 64px;
  height: 64px;
  border-radius: 50%;
}

.profile-card h2 {
  font-size: 18px;
  font-weight: 600;
  color: #1a1a1a;
}

.profile-card p {
  font-size: 14px;
  color: #666;
}

Solución con Tailwind:

<div class="bg-white rounded-lg p-6 flex items-center gap-4 shadow-md max-w-sm">
  <img class="w-16 h-16 rounded-full" src="avatar.jpg" alt="Avatar">
  <div>
    <h2 class="text-lg font-semibold text-gray-900">María García</h2>
    <p class="text-sm text-gray-500">Frontend Developer</p>
  </div>
</div>

¿Notas el patrón? Cada propiedad CSS se convierte en una o varias clases. La traducción es casi directa:

  • padding: 24px → p-6 (la escala de Tailwind: 6 × 4px = 24px)
  • display: flex → flex (literalmente igual)
  • border-radius: 50% → rounded-full
  • font-weight: 600 → font-semibold

9 · Resumen

  • Tailwind CSS es un framework CSS utility-first creado por Adam Wathan en 2017. En lugar de darte componentes prefabricados, te da cientos de clases de utilidad que representan propiedades CSS individuales.
  • Resuelve los problemas del CSS a gran escala: dead code (solo se genera el CSS que usas), colisiones de nombres (no hay nombres de clase inventados), especificidad descontrolada (todas las utilidades tienen la misma especificidad).
  • Bootstrap = muebles prefabricados. Rápido para empezar, doloroso para personalizar.
  • Tailwind = piezas de LEGO. Inviertes un poco más al principio, pero construyes cualquier diseño sin limitaciones.
  • El HTML tiene más clases, pero ganas claridad: cada estilo está explícito en el HTML. No tienes que buscar en archivos CSS qué hace una clase con un nombre abstracto.
  • Tailwind NO es inline styles. Soporta responsive (md:, lg:), estados (hover:, focus:, dark:), y genera CSS optimizado y cacheable.
  • En la próxima lección instalaremos las herramientas necesarias para crear tu primer proyecto con Tailwind CSS v4 usando Vite.

10 · Preguntas frecuentes

¿Necesito saber CSS antes de aprender Tailwind?

No es obligatorio, pero sí muy recomendable. Tailwind es básicamente CSS con nombres de clase. Si entiendes qué es display: flex, padding, margin o border-radius, aprender Tailwind es simplemente aprender los nombres que Tailwind les da a esas propiedades. En este curso partiremos asumiendo que conoces los fundamentos de HTML y CSS. Si no los tienes claros, te recomiendo repasar los conceptos básicos de CSS (el modelo de caja, flexbox, posicionamiento) antes de continuar.

¿Tailwind reemplaza completamente el CSS tradicional?

En el 95% de los casos, sí. Para estilos muy complejos (animaciones personalizadas con keyframes, sombras muy específicas, gradientes cónicos) puede que necesites escribir algo de CSS personalizado. Tailwind v4 lo hace muy fácil: puedes definir valores personalizados con @theme en tu CSS y luego usarlos como clases. Pero para el día a día, Tailwind cubre prácticamente todo lo que necesitas.

¿Es Tailwind más rápido que escribir CSS a mano?

Al principio no. Los primeros días estarás consultando la documentación constantemente. Pero tras una o dos semanas de práctica, sí: eres mucho más rápido con Tailwind. La razón es que eliminas el context switching entre HTML y CSS, no tienes que inventar nombres de clase, y el autocompletado de VSCode te sugiere las clases mientras escribes. La mayoría de developers que usan Tailwind reportan ser significativamente más productivos tras el período inicial de adaptación.

¿Tailwind sirve para proyectos pequeños o solo para grandes?

Sirve para ambos. En un proyecto pequeño te ahorra crear y mantener un archivo CSS. En un proyecto grande te ahorra pesadillas de mantenimiento. La única situación donde quizás Tailwind es excesivo es en una página de una sola etiqueta HTML (y aún así, mucha gente lo usa hasta para eso porque ya tiene el setup).

¿Qué cambió en Tailwind v4 respecto a v3?

Tailwind v4 es una reescritura importante del motor interno. Las novedades clave: configuración CSS-first (adiós a tailwind.config.js, ahora configuras con @theme en tu CSS), rendimiento muchísimo más rápido, mejor integración con Vite, y soporte nativo para capas CSS (@layer). En este curso usamos v4 desde el principio para que aprendas la forma moderna de trabajar.
