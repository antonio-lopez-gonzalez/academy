Proyecto: Hero + Features de Landing Page

Módulo 5 · Proyecto práctico ⏱ 50 minutos

1 · Introducción

Ha llegado el momento de integrar todo lo aprendido en el Módulo 5. Vas a construir —de principio a fin— la sección superior de una landing page profesional: navbar sticky + hero section + features grid + footer. Este es el patrón más demandado en el mercado: toda startup, SaaS o producto digital necesita una landing page, y este proyecto te da la base para construirlas con confianza.

No vamos a usar CSS personalizado. Solo clases de Tailwind. Todo el diseño, la responsividad, los efectos hover y las transiciones se expresan directamente en el HTML. Al terminar, tendrás una página completa que puedes adaptar a cualquier proyecto real.

¿Por qué este proyecto?

Porque una landing page es el 90% de los trabajos freelance y el primer entregable en cualquier startup. Si puedes construir esta página en 50 minutos con Tailwind, puedes construir cualquier landing page. No es un ejercicio académico: es una habilidad profesional directa.

2 · Teoría

Arquitectura del proyecto

Vamos a dividir la landing page en 4 zonas independientes. Cada zona se construye con la herramienta de layout adecuada:

Arquitectura de la landing page: ┌─────────────────────────────────────────┐ │ NAVBAR (Flex) │ │ logo ······ enlaces ······ botones │ │ sticky top-0 │ ├─────────────────────────────────────────┤ │ │ │ HERO SECTION (Flex col + center) │ │ ┌─────────────────────────────────┐ │ │ │ Badge "Nuevo" │ │ │ │ Título principal (gradiente) │ │ │ │ Subtítulo descriptivo │ │ │ │ [Botón CTA] [Botón secundario]│ │ │ │ Social proof / logos │ │ │ └─────────────────────────────────┘ │ │ │ ├─────────────────────────────────────────┤ │ FEATURES GRID (Grid 3 cols) │ │ ┌──────────┬──────────┬──────────┐ │ │ │ Feature 1│ Feature 2│ Feature 3│ │ │ ├──────────┼──────────┼──────────┤ │ │ │ Feature 4│ Feature 5│ Feature 6│ │ │ └──────────┴──────────┴──────────┘ │ ├─────────────────────────────────────────┤ │ FOOTER (Flex wrap) │ │ Logo · Enlaces · Enlaces · Newsletter │ │ ───────────────────────────────────── │ │ Copyright · Privacidad │ └─────────────────────────────────────────┘

Herramientas por zona

ZonaLayoutClases clave

Estrategia responsive

Todo se construye mobile-first: las clases sin prefijo definen el diseño para móvil, y los prefijos md: y lg: añaden complejidad para pantallas más grandes.

  • Navbar: En móvil, los enlaces se ocultan (hidden md:flex) y se muestra un botón hamburguesa.
  • Hero: Título text-4xl en móvil, sm:text-5xl en tablet, lg:text-7xl en desktop. Botones apilados en móvil (flex-col sm:flex-row).
  • Features: 1 columna en móvil, 2 en tablet, 3 en desktop.
  • Footer: Columnas en flex-wrap: se apilan naturalmente cuando no caben.
📐 Contenedor max-w-7xl

Todas las secciones usan max-w-7xl mx-auto px-4 para limitar el ancho máximo y centrar el contenido. Esto evita que el texto se estire en monitores ultrawide y mantiene la legibilidad. Es el patrón estándar de la industria.

5 · Buenas prácticas

HazEvitaPor qué
Navbar con sticky y backdrop-blur fixed con padding compensatorio en el body sticky mantiene el navbar en el flujo. El contenido debajo no necesita ajustes manuales.
Hero con gradiente de fondo sutil y blur decorativo Imagen de fondo pesada que ralentiza la carga Los gradientes CSS son nativos, pesan 0 KB y se renderizan al instante. Las imágenes de fondo requieren carga de red.
Tamaños de fuente responsive: text-4xl sm:text-5xl lg:text-7xl Tamaño fijo que se ve bien en desktop pero rompe en móvil Un título enorme en desktop es ilegible en móvil si no se escala hacia abajo. Mobile-first previene esto.
Botones CTA con flex-col sm:flex-row para responsive Dos botones en fila que se solapan en móvil En pantallas de 375px, dos botones lado a lado con texto largo se desbordan. Apilarlos verticalmente es la solución correcta.
Features con hover effects sutiles: hover:-translate-y-1 Animaciones bruscas o excesivas que distraen Un desplazamiento de 0.25rem en hover indica interactividad sin ser molesto. Transiciones de 300ms son el sweet spot.
Footer con grid para alineación precisa de columnas Footer con flex flex-wrap que descuadra en ciertos anchos Grid garantiza que las 4 columnas estén perfectamente alineadas. Flex-wrap puede dejar columnas huérfanas en anchos intermedios.
max-w-7xl mx-auto px-4 en cada sección Contenido a ancho completo en monitores ultrawide El texto a 2560px de ancho es ilegible. Limitar el ancho máximo mantiene la legibilidad y el diseño controlado.

6 · Errores habituales

Error 1 — No probar el hero en móvil real

Un título con text-7xl se ve espectacular en un monitor de 27", pero en un iPhone SE (375px) ocupa 3 líneas con palabras cortadas. La regla: siempre empieza con text-4xl como base y escala hacia arriba.

Error 2 — Navbar que tapa el contenido al hacer scroll

<!-- ❌ MAL: navbar fixed con height variable -->
<nav class="fixed top-0 w-full z-50 py-4">...</nav>

Error 3 — Features grid sin gap suficiente

Un gap-4 en un grid de features con bordes y sombras hace que las tarjetas se sientan apretadas. Para tarjetas con contenido, usa gap-6 como mínimo y gap-8 para diseños más espaciosos.

Error 4 — Olvidar el contraste en los textos del hero

Un subtítulo text-slate-500 sobre un fondo degradado oscuro puede ser ilegible. Usa text-slate-400 como mínimo para textos secundarios, y text-slate-300 si el fondo tiene mucho gradiente.

Error 5 — Footer con solo 2 columnas que dejan la mitad vacía en desktop

Un footer con 2 columnas en un grid de 4 deja espacios vacíos antiestéticos. O usa 4 columnas (producto, compañía, recursos, legal/contacto) o usa flex flex-wrap justify-between con min-w-[160px] para que las columnas se distribuyan naturalmente.

Error 6 — Botones sin estado active

El estado active: es crucial en botones. Sin él, el botón no da feedback al hacer click. Añade active:scale-95 o active:translate-y-0 para completar la experiencia táctil.

10 · Preguntas frecuentes

¿Necesito JavaScript para que la landing page funcione?

No. Todo el layout, la responsividad y los efectos hover funcionan solo con Tailwind (CSS puro). El único JavaScript que podrías necesitar es para el menú hamburguesa en móvil (toggle de clases) y para el scroll suave a secciones (aunque scroll-smooth en el <html> ya lo resuelve para enlaces internos).

¿Cómo hago que el navbar cambie de estilo al hacer scroll?

Necesitas un pequeño script que escuche el evento scroll y añada/quite clases. Por ejemplo: cuando window.scrollY > 0, añade shadow-lg al navbar. Tailwind no tiene una pseudo-clase :scroll, así que este comportamiento requiere JS. Pero es opcional: muchos sitios modernos mantienen el mismo estilo siempre.

¿Puedo reutilizar este código en un proyecto real con React o Vue?

Absolutamente. Esta landing page está diseñada como HTML plano para que funcione sin build, pero el 100% de las clases de Tailwind son compatibles con React (className) y Vue (:class). Puedes copiar cada sección y convertirla en un componente de tu framework en minutos. De hecho, en el Módulo 8 aprenderás exactamente cómo hacer esta migración.

¿Cómo añado animaciones de entrada al hacer scroll?

Tailwind no incluye animaciones de entrada por defecto (aunque v4 está añadiendo soporte). La forma más común es usar la API IntersectionObserver para añadir clases cuando un elemento entra en el viewport. También puedes usar bibliotecas como AOS (Animate on Scroll) que funcionan añadiendo atributos data-aos a los elementos.

¿Por qué usar backdrop-blur en el navbar en lugar de un fondo sólido?

El efecto backdrop-blur crea un desenfoque del contenido que hay detrás del navbar, dando una sensación de profundidad y modernidad (efecto "vidrio esmerilado"). Es una tendencia de diseño que usan Apple, Stripe, Vercel y la mayoría de sitios modernos. Requiere bg-slate-950/90 (fondo semitransparente) para funcionar.
