Catálogo de componentes UI

Módulo 8 · Tailwind en Frameworks ⏱ 35 minutos

1 · Introducción

Tailwind te da los átomos (clases utilitarias). Tú construyes las moléculas (componentes). Pero no tienes que construir todas las moléculas desde cero. Existe un ecosistema enorme de librerías de componentes UI diseñadas específicamente para integrarse con Tailwind. Saber cuál elegir —y por qué— es una habilidad que te ahorrará semanas de desarrollo.

En esta lección aprenderás:

  • El panorama completo de librerías de componentes para Tailwind: desde las "headless" hasta las "opinionadas".
  • Qué es shadcn/ui y por qué se ha convertido en el estándar de facto en 2024-2026.
  • La diferencia fundamental entre componentes headless (Radix, Headless UI) y componentes estilizados (DaisyUI, Flowbite).
  • Cuándo usar cada librería según el tipo de proyecto, equipo y requisitos.
  • La combinación ganadora: componentes headless + Tailwind.

2 · Teoría

El espectro de librerías de componentes

No todas las librerías de componentes son iguales. Se sitúan en un espectro que va desde "solo lógica, sin estilos" hasta "estilos completos, sin flexibilidad":

ESPECTRO DE LIBRERÍAS DE COMPONENTES UI: HEADLESS │ OPINIONADAS (solo lógica, sin estilos) │ (estilos completos, cerrados) │ Radix UI ── Headless UI ── Ark UI │ shadcn/ui ── Catalyst ── Tailwind UI ── Flowbite ── Preline ── DaisyUI └─ Máxima flexibilidad │ └─ Máxima velocidad inicial Tú controlas TODO el CSS │ Menos control sobre el diseño

Componentes headless: lógica sin estilos

Un componente headless (sin cabeza = sin estilos) proporciona toda la funcionalidad y accesibilidad pero ningún estilo visual. Tú le pasas las clases de Tailwind. El componente se encarga de la lógica compleja (teclado, focus, ARIA, estado) y tú te encargas de que se vea bien.

Radix UI (React) y Headless UI (React + Vue) son los dos grandes exponentes de esta filosofía. Un ejemplo con Headless UI:

import { Switch } from "@headlessui/react";

function MiToggle({ enabled, onChange }) {
  return (
    <Switch
      checked={enabled}
      onChange={onChange}
      className={`relative inline-flex h-6 w-11 items-center rounded-full
        transition-colors focus:outline-none focus:ring-2 focus:ring-blue-500
        ${enabled ? "bg-blue-600" : "bg-gray-300"}`}
    >
      <span
        className={`inline-block h-4 w-4 transform rounded-full bg-white
          transition-transform ${enabled ? "translate-x-6" : "translate-x-1"}`}
      />
    </Switch>
  );
}

Headless UI gestiona el role="switch", aria-checked, el foco del teclado, el clic, la pulsación de Enter/Space... y tú solo te preocupas del diseño visual con Tailwind. Esto es la división perfecta del trabajo.

💡 ¿Por qué "headless" + Tailwind es la combinación ganadora?

Porque separa dos problemas que históricamente han estado acoplados: comportamiento y apariencia. Una librería headless te da accesibilidad y lógica probada en miles de proyectos (sin bugs de teclado ni lectores de pantalla rotos). Tailwind te da control total sobre el diseño sin pelearte con la especificidad de una hoja de estilos ajena. El resultado: componentes robustos que se ven exactamente como tu diseño, no como el diseño genérico de la librería.

shadcn/ui: el punto dulce del espectro

shadcn/ui no es una librería de componentes en el sentido tradicional. No instalas un paquete npm. En su lugar, ejecutas un comando CLI que copia el código fuente del componente a tu proyecto. Una vez copiado, es tu código: lo modificas, lo extiendes, lo adaptas. No hay dependencia externa más allá de Radix UI (para la lógica) y Tailwind (para los estilos).

Esto resuelve el mayor problema de las librerías de componentes tradicionales: la personalización forzada a través de props. Con shadcn/ui, si necesitas que el diálogo tenga una animación diferente, editas el código fuente del diálogo. Punto. Sin workarounds, sin CSS hacks, sin !important.

Componentes que incluye shadcn/ui (todos basados en Radix + Tailwind):

  • Formularios: Input, Select, Checkbox, Radio, Switch, Textarea, Combobox, DatePicker.
  • Layout: Card, Separator, Sheet (panel lateral), Tabs, Accordion.
  • Overlays: Dialog (modal), AlertDialog, Popover, Tooltip, HoverCard, DropdownMenu, ContextMenu.
  • Datos: Table, DataTable, Pagination.
  • Navegación: Breadcrumb, NavigationMenu, Sidebar.
  • Feedback: Toast (Sonner), Skeleton, Progress, Badge, Alert.
🧩 Analogía: shadcn/ui es como IKEA pero con los planos

Una librería tradicional es comprar un mueble ya montado: si no te gusta el color de una pieza, tienes que pintarla por encima y rezar. shadcn/ui es como IKEA pero con el código fuente de la fábrica: recibes las piezas, los planos y las herramientas. Puedes montarlo igual o modificar una pieza antes de encajarla. El resultado es tuyo, no de la tienda.

Tailwind UI: componentes premium oficiales

Tailwind UI es la librería oficial del equipo de Tailwind CSS. A diferencia de shadcn/ui, es de pago (licencia única) y proporciona HTML ya escrito, no componentes de framework. Cada componente es HTML + Tailwind puro, listo para copiar y pegar en React, Vue, Laravel Blade o lo que uses.

Incluye cientos de ejemplos en categorías como Application UI (layouts, navbars, forms), Marketing (hero sections, pricing, testimonios) y E-commerce (productos, carritos, checkouts). Es ideal si necesitas inspiración o un punto de partida rápido, pero no proporciona comportamiento (animaciones, accesibilidad, estado) — eso lo pones tú sobre el HTML base.

DaisyUI: componentes opinionados con clases semánticas

DaisyUI es un plugin de Tailwind que añade clases semánticas como btn, card, alert, modal. En lugar de combinar 15 clases utilitarias para un botón, escribes class="btn btn-primary btn-lg". DaisyUI genera los estilos internamente usando Tailwind.

Es la opción más rápida para prototipar y la más familiar para quienes vienen de Bootstrap. El inconveniente: la personalización visual es limitada. Si el diseño de tu proyecto no coincide con el tema de DaisyUI, vas a pelear contra él constantemente.

Flowbite y Preline: componentes para múltiples frameworks

Flowbite y Preline son librerías de componentes que soportan React, Vue, Svelte y vanilla JS. Incluyen JavaScript para interactividad (modales, dropdowns, tooltips funcionan sin escribir JS). Son ideales para proyectos con múltiples tecnologías donde quieres una experiencia de componentes consistente.

Flowbite tiene versión gratuita (open source) y versión pro (de pago, con componentes avanzados y templates). Preline es completamente gratuito y destaca por su integración con Figma (plugin de diseño que exporta a componentes Preline).

Catalyst: componentes React de Tailwind UI

Catalyst es la librería de componentes React del equipo de Tailwind. A diferencia de Tailwind UI (HTML plano), Catalyst proporciona componentes React completos con lógica, accesibilidad y animaciones. Está incluido en Tailwind UI (sin coste adicional) y sigue patrones similares a shadcn/ui (código copiado a tu proyecto, usa Headless UI para la lógica). Si ya tienes Tailwind UI, Catalyst es tu opción natural para React.

Árbol de decisión: ¿cuál elijo?

No hay una respuesta única. Depende de tu contexto. Aquí tienes una guía práctica:

¿QUÉ LIBRERÍA DE COMPONENTES ELEGIR? 1. ¿Necesitas control total del diseño? ├─ SÍ → Headless UI / Radix UI / Ark UI └─ NO → ¿Quieres código copiable y modificable? ├─ SÍ → shadcn/ui (gratis, React/Vue) o Catalyst (pago, React) └─ NO → ¿Necesitas componentes listos con JS? ├─ SÍ → Flowbite o Preline └─ NO → ¿Vienes de Bootstrap y quieres velocidad? └─ SÍ → DaisyUI

3 · Ejemplo mínimo

La diferencia entre un componente estilizado (DaisyUI) y uno headless (Radix UI + Tailwind) para el mismo botón:

<!-- DaisyUI: una sola clase semántica, personalización limitada -->
<button class="btn btn-primary">
  Enviar
</button>

<!-- Radix + Tailwind: control total sobre cada aspecto visual -->
<button class="inline-flex items-center justify-center rounded-lg
  bg-blue-600 px-5 py-2.5 text-sm font-semibold text-white
  hover:bg-blue-700 focus:outline-none focus:ring-2 focus:ring-blue-500
  focus:ring-offset-2 disabled:opacity-50 disabled:cursor-not-allowed
  transition-colors duration-200">
  Enviar
</button>

Con DaisyUI, tienes que aceptar el diseño del tema. Con Radix + Tailwind, el diseño es exactamente el que quieres. La contrapartida: más código que escribir. La decisión depende de si valoras más la velocidad inicial o el control a largo plazo.

4 · Ejemplo real

Construyamos un DropdownMenu con Headless UI + Tailwind. Sin esta librería, un menú desplegable accesible (teclado, ARIA, foco, click outside) requiere ~200 líneas de JS. Con Headless UI, 30 líneas.

import { Menu, MenuButton, MenuItem, MenuItems } from "@headlessui/react";

function UserDropdown() {
  return (
    <Menu as="div" className="relative inline-block text-left">
      <MenuButton className="inline-flex items-center gap-2 rounded-lg
          bg-gray-100 px-4 py-2 text-sm font-semibold text-gray-700
          hover:bg-gray-200 focus:outline-none focus:ring-2 focus:ring-blue-500
          dark:bg-gray-800 dark:text-gray-200 dark:hover:bg-gray-700">
        👤 Marina Gómez
        <svg className="h-4 w-4" /* icono chevron */ />
      </MenuButton>

      <MenuItems
        anchor="bottom end"
        className="z-50 mt-2 w-56 origin-top-right rounded-xl border
          border-gray-200 bg-white p-1.5 shadow-lg ring-1 ring-black/5
          focus:outline-none dark:border-gray-700 dark:bg-gray-800">
        <MenuItem>
          {({ active }) => (
            <button className={`flex w-full items-center gap-2 rounded-lg px-3 py-2
              text-sm ${active ? "bg-gray-100 dark:bg-gray-700" : ""}`}>
              👤 Ver perfil
            </button>
          )}
        </MenuItem>
        <MenuItem>
          {({ active }) => (
            <button className={`flex w-full items-center gap-2 rounded-lg px-3 py-2
              text-sm ${active ? "bg-gray-100 dark:bg-gray-700" : ""}`}>
              ⚙️ Configuración
            </button>
          )}
        </MenuItem>
        <hr className="my-1 border-gray-200 dark:border-gray-700" />
        <MenuItem>
          {({ active }) => (
            <button className={`flex w-full items-center gap-2 rounded-lg px-3 py-2
              text-sm text-red-600 ${active ? "bg-red-50 dark:bg-red-950" : ""}`}>
              🚪 Cerrar sesión
            </button>
          )}
        </MenuItem>
      </MenuItems>
    </Menu>
  );
}

Headless UI se encarga de: abrir/cerrar con clic, cerrar al hacer clic fuera, cerrar con Escape, mover foco con flechas, roles ARIA (role="menu", role="menuitem"), aria-expanded en el botón. Tú solo te preocupas de las clases de Tailwind. El render prop {({ active }) => ...} te da el estado del item (focus del teclado) para estilizarlo.

📱 El anchor positioning nativo de Headless UI v2

La prop anchor="bottom end" usa el nuevo CSS Anchor Positioning del navegador para posicionar el menú sin JavaScript de posicionamiento. Antes necesitabas Popper.js o Floating UI. Hoy Headless UI lo resuelve con CSS nativo y un pequeño polyfill para navegadores antiguos. Menos JS, más rendimiento.

6 · Errores habituales

🚫 Usar shadcn/ui y DaisyUI en el mismo proyecto

shadcn/ui y DaisyUI tienen filosofías opuestas: shadcn/ui te da control total con clases utilitarias; DaisyUI abstrae las clases con nombres semánticos. Mezclarlos produce una guerra de especificidad y un diseño visual inconsistente. El resultado es un frankestein inmantenible donde nadie sabe si un botón usa btn o Button.

Solución: elige UNA filosofía y sé consistente. Si necesitas algo de DaisyUI, no uses shadcn/ui. Y viceversa.

🚫 Elegir DaisyUI sin probar antes su tema en el diseño real del proyecto

DaisyUI viene con un tema por defecto (colores, tamaños, bordes redondeados). Si tu diseño no coincide, tendrás que sobrescribir variables CSS una a una. Para cuando termines, habrías tardado menos construyendo los componentes desde cero con Tailwind puro.

Solución: antes de decidir, crea una página de prueba con los 5-6 componentes principales de tu app usando DaisyUI. Si necesitas más de 20 overrides de tema, DaisyUI no es para ese proyecto.

🚫 Asumir que Flowbite/Preline no necesitan JavaScript propio

Flowbite y Preline incluyen JS para interactividad, pero ese JS asume que los componentes se montan en el DOM de una manera específica. En aplicaciones React/Vue con renderizado condicional, el JS puede no detectar componentes montados dinámicamente y la interactividad se rompe.

Solución: si usas Flowbite/Preline en React/Vue, usa sus versiones específicas para framework (flowbite-react, flowbite-vue), no la versión vanilla JS. O mejor aún: usa Headless UI + Tailwind, que es nativo de React/Vue.

🚫 Instalar shadcn/ui como paquete npm

shadcn/ui no se instala con npm install shadcn-ui. Es un CLI que copia código a tu proyecto. Si ves un paquete npm llamado shadcn-ui, es un fork no oficial o un wrapper que probablemente no se mantiene actualizado. La forma correcta es npx shadcn-ui@latest init (que configura Tailwind, paths y CSS variables) y luego npx shadcn-ui@latest add button para añadir componentes.

7 · Ejercicio guiado

Vamos a construir un Dialog (modal) accesible con Headless UI + Tailwind, paso a paso.

  1. Instala Headless UI en tu proyecto. 
    pnpm add @headlessui/react
  2. Crea el componente Dialog. 
    import { Dialog, DialogPanel, DialogTitle, Transition } from "@headlessui/react";
import { Fragment, useState } from "react";

export function ConfirmDialog({ isOpen, onClose, onConfirm, title, message }) {
  return (
    <Transition show={isOpen} as={Fragment}>
      <Dialog onClose={onClose} className="relative z-50">
        {/* Overlay: fondo oscuro con transición */}
        <Transition.Child
          as={Fragment}
          enter="ease-out duration-300"
          enterFrom="opacity-0"
          enterTo="opacity-100"
          leave="ease-in duration-200"
          leaveFrom="opacity-100"
          leaveTo="opacity-0">
          <div className="fixed inset-0 bg-black/50" />
        </Transition.Child>

        {/* Panel: el modal en sí */}
        <div className="fixed inset-0 flex items-center justify-center p-4">
          <Transition.Child
            as={Fragment}
            enter="ease-out duration-300"
            enterFrom="opacity-0 scale-95"
            enterTo="opacity-100 scale-100"
            leave="ease-in duration-200"
            leaveFrom="opacity-100 scale-100"
            leaveTo="opacity-0 scale-95">
            <DialogPanel className="w-full max-w-md rounded-2xl bg-white p-6
              shadow-xl dark:bg-gray-900 dark:ring-1 dark:ring-gray-800">
              <DialogTitle className="text-lg font-semibold text-gray-900
                dark:text-gray-100">
                {title}
              </DialogTitle>
              <p className="mt-2 text-sm text-gray-600 dark:text-gray-400">
                {message}
              </p>
              <div className="mt-6 flex gap-3 justify-end">
                <button onClick={onClose} className="rounded-lg px-4 py-2 text-sm
                  font-semibold text-gray-700 hover:bg-gray-100
                  dark:text-gray-300 dark:hover:bg-gray-800">
                  Cancelar
                </button>
                <button onClick={onConfirm} className="rounded-lg bg-blue-600 px-4
                  py-2 text-sm font-semibold text-white hover:bg-blue-700
                  focus:ring-2 focus:ring-blue-500">
                  Confirmar
                </button>
              </div>
            </DialogPanel>
          </Transition.Child>
        </div>
      </Dialog>
    </Transition>
  );
}
  3. Úsalo en tu aplicación. 
    export default function App() {
  const [isOpen, setIsOpen] = useState(false);
  return (
    <div className="p-8">
      <button onClick={() => setIsOpen(true)}
        className="rounded-lg bg-blue-600 px-5 py-2.5 text-white">
        Eliminar cuenta
      </button>
      <ConfirmDialog
        isOpen={isOpen}
        onClose={() => setIsOpen(false)}
        onConfirm={() => { /* lógica de eliminación */; setIsOpen(false); }}
        title="¿Eliminar cuenta?"
        message="Esta acción es irreversible. Todos tus datos se eliminarán permanentemente."
      />
    </div>
  );
}

Lo que Headless UI te regala aquí: cierre con Escape, cierre con click fuera (si onClose lo permite), foco atrapado dentro del modal (Tab no se escapa), restauración del foco al cerrar, role="dialog", aria-modal="true", y las animaciones de entrada/salida con Transition. Sin Headless UI, escribirías 150+ líneas de JS solo para la accesibilidad.

8 · Reto

🎯 Evalúa qué stack de componentes elegirías para cada escenario

Para cada uno de los siguientes proyectos, justifica qué librería(s) de componentes usarías y por qué:

  1. Startup SaaS B2B: producto en React, equipo de 4 devs, diseñadora full-time con un design system propio en Figma. Estarán iterando el producto durante años.
  2. Agencia web: hacéis landing pages y sitios corporativos para clientes. Stack variado: a veces React, a veces Vue, a veces WordPress con HTML plano. Necesitáis velocidad de entrega.
  3. Proyecto interno de empresa: dashboard administrativo en Vue. Lo usarán 20 empleados. No hay diseñador. El objetivo es funcionalidad, no diseño.
  4. Prototipo para demo de inversores: necesitas una app funcional en 3 días para enseñar en una reunión. React, da igual el diseño mientras se vea profesional.
  5. E-commerce grande: React, equipo de 15 devs, identidad visual muy definida, requisitos de accesibilidad WCAG AA estrictos.

No hay una única respuesta correcta. Lo importante es el razonamiento: ¿por qué esa librería para ese contexto?

9 · Resumen

  • Componentes headless (Radix, Headless UI, Ark UI) proporcionan lógica, accesibilidad y comportamiento sin imponer diseño visual. Tú añades Tailwind. Es la arquitectura más flexible y escalable.
  • shadcn/ui copia el código fuente a tu proyecto. Es tu código, no una dependencia. Combina Radix (lógica headless) con Tailwind (estilos) en componentes listos para usar y modificar. Es el estándar recomendado para React/Vue.
  • Tailwind UI (pago) y Catalyst (incluido) son las opciones oficiales del equipo de Tailwind. Ideales si ya tienes la licencia o trabajas con HTML plano.
  • DaisyUI es la opción más rápida para prototipar pero la menos flexible. Ideal para MVPs y proyectos internos; mala elección para productos con diseño propio.
  • Flowbite y Preline brillan en equipos multi-framework (React + Vue + Svelte) y cuando necesitas componentes con JS incluido.
  • No mezcles librerías de filosofías opuestas (shadcn/ui + DaisyUI). Elige una y sé consistente.
  • La combinación headless + Tailwind es la respuesta definitiva a "¿cómo construyo componentes accesibles sin perder control del diseño?".

10 · Preguntas frecuentes

¿shadcn/ui es gratis? ¿Cómo ganan dinero?

Sí, shadcn/ui es completamente open source y gratuito. El autor (shadcn) no monetiza directamente la librería. Su modelo es similar al de Tailwind CSS: la herramienta es gratis y construye reputación/autoridad que luego monetiza con otros productos (consultoría, cursos, templates premium). Además, shadcn/ui depende de Radix UI y Tailwind CSS, que son sus propios proyectos con sus propios modelos.

¿Puedo usar Headless UI con Vue sin React?

Sí. Headless UI tiene paquetes separados: @headlessui/react y @headlessui/vue. Ambos son oficiales y mantenidos por el equipo de Tailwind. La API es prácticamente idéntica, adaptada a las convenciones de cada framework (props en React, slots y v-model en Vue).

¿Qué diferencia hay entre Radix UI y Headless UI?

Ambos son headless, pero Radix UI tiene un catálogo más amplio (30+ componentes vs ~15 de Headless UI) y una API más orientada a composición. Headless UI es más minimalista y está más integrado con Tailwind (mismo equipo). En la práctica, shadcn/ui usa Radix como base para la mayoría de componentes, y Headless UI para algunos (Dialog, Listbox, Combobox). No son excluyentes; puedes usar ambos en el mismo proyecto.

¿Necesito saber React avanzado para usar shadcn/ui?

No. shadcn/ui usa patrones de React básicos (props, children, useState, forwardRef). Si sabes crear un componente con props y pasar className, puedes usar shadcn/ui. La complejidad de accesibilidad y lógica está encapsulada en Radix UI, que shadcn/ui envuelve. Tú ves componentes React normales con clases de Tailwind.

¿Merece la pena pagar por Tailwind UI si ya uso shadcn/ui?

Depende. shadcn/ui cubre componentes de interfaz (botones, inputs, modales, tablas). Tailwind UI añade secciones de página completas (hero sections, pricing tables, feature grids, footers) que shadcn/ui no incluye. Si necesitas inspiración para páginas de marketing o landing, Tailwind UI lo vale. Si solo construyes la aplicación en sí (dashboard, formularios, tablas), shadcn/ui es suficiente.
