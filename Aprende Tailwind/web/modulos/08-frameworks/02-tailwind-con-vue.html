Tailwind con Vue

Módulo 8 · Tailwind en Frameworks ⏱ 30 minutos

1 · Introducción

Vue tiene una relación especialmente natural con Tailwind. Mientras que en React necesitas librerías extra (clsx, tailwind-merge) para manejar clases condicionales, Vue incluye mecanismos nativos en su sistema de templates que resuelven muchos de esos casos sin dependencias adicionales. Esto hace que la integración Vue + Tailwind sea sorprendentemente ligera.

En esta lección aprenderás:

  • El binding de clases en Vue: sintaxis de objeto y de array, y cuándo usar cada una.
  • Fallthrough attributes: la magia de Vue que hace que className fluya automáticamente al elemento raíz.
  • Crear un BaseButton con props de variantes usando las herramientas nativas de Vue (sin cva).
  • Composables para lógica de clases reutilizable.
  • Comparativa React vs Vue para clases condicionales: ventajas y desventajas de cada enfoque.

2 · Teoría

:class binding en Vue: el superpoder nativo

Vue tiene una directiva :class (abreviatura de v-bind:class) que acepta objetos y arrays para construir clases dinámicas. Esto es mucho más expresivo que los template literals de React y cubre el 80% de los casos de uso de clsx sin instalar nada.

Sintaxis de objeto

Pasas un objeto donde las claves son nombres de clase y los valores son booleanos. La clase se aplica si el valor es true:

<!-- Clases estáticas + dinámicas por objeto -->
<div
  class="rounded-lg p-4 shadow"
  :class="{
    'bg-blue-500 text-white': isActive,
    'bg-gray-200 text-gray-500': !isActive,
    'cursor-not-allowed opacity-50': disabled,
    'border-2 border-blue-700': isActive && highlighted
  }"
>
  Contenido
</div>

Vue fusiona class (estática) y :class (dinámica) automáticamente. No necesitas template literals ni concatenación.

Sintaxis de array

Pasas un array de expresiones. Cada elemento puede ser un string, un objeto o una expresión condicional:

<div
  :class="[
    'rounded-lg p-4 shadow',           // clases base siempre presentes
    isActive ? 'bg-blue-500' : 'bg-gray-200',  // ternario
    { 'border-2 border-blue-700': highlighted }, // objeto condicional
    sizeClass                            // variable computada
  ]"
>
  Contenido
</div>
💡 Objeto vs Array: ¿cuál usar?

Usa objeto cuando tienes varias clases que dependen de condiciones booleanas independientes (más legible). Usa array cuando necesitas mezclar strings fijos, ternarios y expresiones complejas (más flexible). En la práctica, muchos componentes usan el array con un objeto dentro para las condiciones booleanas: :class="['base', { active: isActive, disabled: isDisabled }]".

Fallthrough attributes: className fluye solo

Esta es una de las características más elegantes de Vue y una ventaja enorme sobre React para la integración con Tailwind. Cuando pasas un atributo (incluyendo class) a un componente Vue, y ese atributo no está declarado como prop, Vue lo transmite automáticamente al elemento raíz del template del componente:

<!-- BaseCard.vue — sin declarar className como prop -->
<template>
  <div class="rounded-xl bg-white p-6 shadow-lg dark:bg-gray-900">
    <slot />
  </div>
</template>

<!-- App.vue — uso del componente -->
<BaseCard class="mt-8 border-2 border-blue-500">
  <p>Esta tarjeta tendrá mt-8 y borde azul</p>
</BaseCard>

<!-- HTML resultante (automático, sin código extra) -->
<div class="rounded-xl bg-white p-6 shadow-lg dark:bg-gray-900 mt-8 border-2 border-blue-500">
  <p>Esta tarjeta tendrá mt-8 y borde azul</p>
</div>
💡 ¿Por qué es tan potente esto?

En React, cada componente tiene que aceptar manualmente className como prop y fusionarlo con sus clases base. En Vue, los fallthrough attributes lo hacen automáticamente. Esto significa que puedes tomar cualquier componente Vue que envuelva un solo elemento raíz y pasarle class sin que el autor del componente haya escrito una sola línea para soportarlo. Es componibilidad "gratis".

Atención: los fallthrough attributes solo van al elemento raíz. Si tu componente tiene múltiples elementos raíz (fragmentos), necesitas usar v-bind="$attrs" explícitamente en el elemento que quieras que los reciba:

<!-- Componente con múltiples raíces: hay que ser explícito -->
<template>
  <label class="block text-sm font-medium">{{ label }}</label>
  <input v-bind="$attrs" class="mt-1 w-full rounded-lg border p-2" />
</template>

Herencia de clases: el comportamiento inteligente de Vue

Cuando el elemento raíz ya tiene una class definida en el componente y el padre también pasa class, Vue fusiona ambas en lugar de sobrescribir:

<!-- Componente hijo (BaseButton.vue) -->
<template>
  <button class="rounded-lg px-4 py-2 font-semibold">
    <slot />
  </button>
</template>

<!-- Componente padre -->
<BaseButton class="bg-blue-600 text-white hover:bg-blue-700">
  Enviar
</BaseButton>

<!-- Resultado: AMBAS clases, fusionadas -->
<button class="rounded-lg px-4 py-2 font-semibold bg-blue-600 text-white hover:bg-blue-700">
  Enviar
</button>
📝 Diferencia clave con React

En React, si quieres fusionar clases necesitas hacerlo manualmente con cn(). En Vue, la fusión es automática gracias a los fallthrough attributes. Sin embargo, esto no resuelve conflictos de Tailwind: si el componente tiene p-4 y el padre pasa p-6, ambas clases coexisten en el HTML. Para resolver conflictos, sigue necesitando una herramienta como tailwind-merge — lo veremos más adelante.

BaseButton con props: el patrón Vue nativo

En lugar de usar cva como en React, en Vue puedes aprovechar las props y computed properties para definir variantes:

<!-- components/BaseButton.vue -->
<script setup>
import { computed } from "vue";

const props = defineProps({
  variant: {
    type: String,
    default: "primary",
    validator: (v) => ["primary", "secondary", "outline", "ghost", "danger"].includes(v),
  },
  size: {
    type: String,
    default: "md",
    validator: (v) => ["sm", "md", "lg"].includes(v),
  },
});

const variantClasses = computed(() => ({
  primary: "bg-blue-600 text-white hover:bg-blue-700 focus:ring-blue-500",
  secondary: "bg-gray-200 text-gray-900 hover:bg-gray-300 focus:ring-gray-400",
  outline: "border-2 border-gray-300 text-gray-700 hover:bg-gray-50 focus:ring-gray-400",
  ghost: "text-gray-700 hover:bg-gray-100 focus:ring-gray-400",
  danger: "bg-red-600 text-white hover:bg-red-700 focus:ring-red-500",
}[props.variant]));

const sizeClasses = computed(() => ({
  sm: "px-3 py-1.5 text-xs",
  md: "px-5 py-2.5 text-sm",
  lg: "px-7 py-3.5 text-base",
}[props.size]));
</script>

<template>
  <button
    class="inline-flex items-center justify-center rounded-lg font-semibold transition-all focus:outline-none focus:ring-2 focus:ring-offset-2 disabled:opacity-50 disabled:cursor-not-allowed"
    :class="[variantClasses, sizeClasses]"
  >
    <slot />
  </button>
</template>

El consumidor puede pasar clases adicionales que se fusionan automáticamente:

<BaseButton variant="outline" size="lg" class="w-full mt-4">
  Cancelar suscripción
</BaseButton>

Composables: lógica de clases reutilizable

Para lógica de clases más compleja que se repite entre componentes, Vue permite extraerla a composables:

// composables/useButtonClasses.js
import { computed } from "vue";

export function useButtonClasses(props) {
  const classes = computed(() => {
    const variants = {
      primary: "bg-blue-600 text-white hover:bg-blue-700",
      secondary: "bg-gray-200 text-gray-900 hover:bg-gray-300",
    };
    const sizes = {
      sm: "px-3 py-1.5 text-xs",
      md: "px-5 py-2.5 text-sm",
      lg: "px-7 py-3.5 text-base",
    };
    return [
      "inline-flex items-center justify-center rounded-lg font-semibold",
      variants[props.variant] || variants.primary,
      sizes[props.size] || sizes.md,
    ];
  });

  return { classes };
}

Comparativa React vs Vue para clases condicionales

Aspecto React Vue
Clases condicionales Necesita clsx o template literals Nativo con :class="{}" y :class="[]"
Herencia de className Manual: aceptar prop y fusionar con cn() Automática: fallthrough attributes al elemento raíz
Resolución de conflictos tailwind-merge (via cn) También necesita tailwind-merge para conflictos
Variantes tipadas class-variance-authority (cva) Computed properties + objetos (sin dependencia extra)
Lógica reutilizable Custom hooks Composables
Dependencias externas recomendadas clsx, tailwind-merge, cva Solo tailwind-merge (opcional)
🧩 Analogía: React y Vue ante las clases

React trata las clases como JavaScript puro: tú controlas todo manualmente. Es como un coche con cambio manual: más control, pero más trabajo. Vue trata las clases como parte del lenguaje de templates: te da directivas y comportamientos inteligentes (:class, fallthrough). Es como un coche automático: menos código para el mismo resultado. Ambos llegan al mismo destino, pero el camino de Vue es más corto para este caso concreto.

3 · Ejemplo mínimo

El componente más pequeño posible que demuestra la fusión automática de clases en Vue: un Badge.

<!-- Badge.vue -->
<script setup>
defineProps({
  variant: { type: String, default: "default" },
});
</script>

<template>
  <span
    class="inline-flex items-center rounded-full px-2.5 py-0.5 text-xs font-semibold"
    :class="{
      'bg-blue-100 text-blue-800': variant === 'default',
      'bg-green-100 text-green-800': variant === 'success',
      'bg-red-100 text-red-800': variant === 'danger',
    }"
  >
    <slot />
  </span>
</template>
<!-- App.vue — consumo con fusión automática -->
<script setup>
import Badge from "./components/Badge.vue";
</script>

<template>
  <div class="flex gap-2 p-8">
    <Badge>Normal</Badge>
    <Badge variant="success">OK</Badge>
    <Badge variant="danger">Error</Badge>
    <!-- className extra se fusiona automáticamente al <span> raíz -->
    <Badge variant="success" class="px-4 py-1 text-sm">Grande</Badge>
  </div>
</template>

Fíjate: no hay ninguna prop class declarada en Badge.vue. Vue la transmite automáticamente al <span> raíz y la fusiona con las clases existentes. Cero código extra.

4 · Ejemplo real

Construyamos un sistema de Alert con variantes, icono, título, descripción y botón de cierre, usando composables y fallthrough attributes:

// composables/useAlertClasses.js
import { computed } from "vue";

export function useAlertClasses(variant) {
  const containerClasses = computed(() => {
    const map = {
      info: "border-blue-300 bg-blue-50 text-blue-900 dark:border-blue-800 dark:bg-blue-950 dark:text-blue-200",
      success: "border-green-300 bg-green-50 text-green-900 dark:border-green-800 dark:bg-green-950 dark:text-green-200",
      warning: "border-amber-300 bg-amber-50 text-amber-900 dark:border-amber-800 dark:bg-amber-950 dark:text-amber-200",
      error: "border-red-300 bg-red-50 text-red-900 dark:border-red-800 dark:bg-red-950 dark:text-red-200",
    };
    return map[variant] || map.info;
  });

  const iconMap = { info: "ℹ️", success: "✅", warning: "⚠️", error: "🚫" };

  return { containerClasses, iconMap };
}
<!-- components/AppAlert.vue -->
<script setup>
import { useAlertClasses } from "../composables/useAlertClasses";

const props = defineProps({
  variant: { type: String, default: "info" },
  title: { type: String, default: "" },
  dismissible: { type: Boolean, default: false },
});

const emit = defineEmits(["dismiss"]);
const { containerClasses, iconMap } = useAlertClasses(props.variant);
</script>

<template>
  <div
    class="flex items-start gap-3 rounded-lg border p-4 text-sm"
    :class="containerClasses"
    role="alert"
  >
    <span class="shrink-0 text-lg" aria-hidden="true">{{ iconMap[variant] }}</span>
    <div class="flex-1">
      <strong v-if="title" class="block font-semibold">{{ title }}</strong>
      <div class="mt-1">
        <slot />
      </div>
    </div>
    <button
      v-if="dismissible"
      class="shrink-0 rounded p-1 opacity-50 hover:opacity-100 transition-opacity"
      @click="emit('dismiss')"
      aria-label="Cerrar alerta"
    >
      ×
    </button>
  </div>
</template>
<!-- App.vue — uso del sistema de alertas -->
<script setup>
import { ref } from "vue";
import AppAlert from "./components/AppAlert.vue";

const showAlert = ref(true);
</script>

<template>
  <div class="mx-auto max-w-xl space-y-3 p-8">
    <AppAlert variant="success" title="Operación completada">
      Tu perfil se ha actualizado correctamente. Los cambios se reflejarán en unos minutos.
    </AppAlert>

    <AppAlert variant="warning" title="Atención">
      Tu suscripción caduca en 3 días. Renueva para mantener el acceso.
    </AppAlert>

    <AppAlert variant="error" title="Error de conexión" dismissible @dismiss="showAlert = false">
      No se ha podido conectar con el servidor. Revisa tu conexión a internet.
    </AppAlert>

    <!-- Fusión automática de clases: el padre añade estilos extra sin modificar el componente -->
    <AppAlert variant="info" class="shadow-lg ring-1 ring-blue-200">
      Esta alerta tiene sombra y anillo extra gracias a fallthrough attributes.
    </AppAlert>
  </div>
</template>

Puntos clave de este ejemplo:

  • Composable useAlertClasses: la lógica de estilos está aislada y es reutilizable. Si otro componente necesita los mismos mapas de colores, solo importa el composable.
  • Fallthrough attributes en acción: la última alerta recibe class="shadow-lg ring-1 ring-blue-200" y Vue lo fusiona con las clases del <div> raíz sin que AppAlert.vue declare ninguna prop class.
  • :class con array + computed: class="..." (estático) + :class="containerClasses" (dinámico vía computed).
  • Eventos con defineEmits: el botón de cierre emite dismiss y el padre decide qué hacer (ocultar el alerta).

6 · Errores habituales

🚫 Asumir que los fallthrough attributes funcionan con componentes multi-raíz

Si tu componente tiene 2+ elementos raíz (fragmentos), Vue no sabe a cuál pasar los atributos heredados. Simplemente no los aplica a ninguno. Esto produce el clásico "pasé class al componente y no se aplica".

Solución: Vincula v-bind="$attrs" explícitamente al elemento que deba recibir los atributos. O mejor aún, envuelve todo en un único elemento raíz (un <div> o <template> no es un elemento real) para que los fallthrough sigan funcionando automáticamente.

🚫 Usar :class de objeto con valores no booleanos

En :class="{ active: isActive }", la clase active se aplica si isActive es truthy (no solo true, sino también 1, "string", etc.). Esto puede causar clases aplicadas cuando no deberían si pasas accidentalmente un string no vacío o un número distinto de 0.

Solución: Asegúrate de que las condiciones sean estrictamente booleanas. Usa !!valor o Boolean(valor) si hay riesgo de truthy/falsy inesperado.

🚫 Olvidar que class y :class se fusionan, no se sobrescriben

Si tu componente tiene class="p-4" y el padre pasa class="p-6", el HTML tendrá class="p-4 p-6" (ambas). Esto no es un error de Vue — es el comportamiento esperado. Pero si esperabas que p-6 sobrescribiera a p-4, te llevarás una sorpresa.

Solución: Para componentes donde la personalización externa debe poder sobrescribir estilos base, usa tailwind-merge dentro de una computed:

import { twMerge } from "tailwind-merge";
const mergedClass = computed(() => twMerge("p-4", attrs.class));

🚫 Declarar class como prop y luego no usarla, confiando en fallthrough

Si declaras class en defineProps, Vue la trata como una prop normal y no la transmite como fallthrough attribute. El resultado: la clase que pasaste desaparece. Esto es confuso porque el comportamiento cambia silenciosamente.

Solución: No declares class ni style como props a menos que necesites manipularlas explícitamente. Deja que Vue las maneje con fallthrough attributes.

7 · Ejercicio guiado

Vamos a construir un InputGroup con label, input y mensaje de error, usando computed classes y fallthrough attributes.

  1. Crea el componente InputField.vue con props para label, error y estado. 
    <script setup>
import { computed } from "vue";

const props = defineProps({
  label: { type: String, required: true },
  error: { type: String, default: "" },
  id: { type: String, required: true },
});

const hasError = computed(() => !!props.error);
</script>

<template>
  <div class="space-y-1.5">
    <label :for="id" class="block text-sm font-medium text-gray-700 dark:text-gray-300">
      {{ label }}
    </label>
    <input
      :id="id"
      v-bind="$attrs"
      class="w-full rounded-lg border px-3 py-2 text-sm transition-colors focus:outline-none focus:ring-2"
      :class="{
        'border-gray-300 focus:ring-blue-500 focus:border-blue-500 dark:border-gray-600 dark:bg-gray-800 dark:text-gray-100': !hasError,
        'border-red-400 focus:ring-red-500 focus:border-red-500 bg-red-50 dark:border-red-500 dark:bg-red-950': hasError,
      }"
    />
    <p v-if="hasError" class="text-xs text-red-600 dark:text-red-400">{{ error }}</p>
  </div>
</template>
  2. Úsalo con diferentes props y atributos heredados. 
    <script setup>
import InputField from "./components/InputField.vue";
</script>

<template>
  <form class="mx-auto max-w-md space-y-4 p-8" @submit.prevent>
    <InputField
      id="name"
      label="Nombre completo"
      type="text"
      placeholder="Marina Gómez"
      autocomplete="name"
    />
    <InputField
      id="email"
      label="Correo electrónico"
      type="email"
      placeholder="marina@ejemplo.com"
      error="El formato del correo no es válido"
    />
    <InputField
      id="password"
      label="Contraseña"
      type="password"
      placeholder="Mínimo 8 caracteres"
    />
  </form>
</template>

Fíjate en que type, placeholder y autocomplete no son props declaradas — son fallthrough attributes que v-bind="$attrs" transmite al <input> nativo. El componente es genérico y acepta cualquier atributo HTML válido en inputs.

8 · Reto

🎯 Crea un componente Tabs con navegación por teclado

Diseña un sistema de pestañas con:

  • Tabs: componente contenedor que acepta modelValue (pestaña activa) y emite update:modelValue al cambiar de pestaña.
  • TabList: lista de botones de pestaña. Cada botón muestra si está activo (subrayado azul, texto azul) o inactivo (texto gris).
  • TabPanel: contenido de una pestaña. Solo se renderiza si está activo (usa v-if o v-show).
  • Navegación por teclado: flechas izquierda/derecha mueven el foco entre pestañas. Enter/Space activa la pestaña enfocada.
  • Estilos completamente con Tailwind, incluyendo dark mode.
  • Usa fallthrough attributes para que el consumidor pueda añadir clases al contenedor.

Pistas: Usa provide/inject para compartir el estado entre Tabs y sus hijos. Para el teclado, usa @keydown con las teclas ArrowLeft, ArrowRight, Home, End.

9 · Resumen

  • :class es nativo en Vue: acepta objetos ({'clase': condicion}) y arrays (['base', cond ? 'x' : 'y']). Se fusiona automáticamente con class estática.
  • Fallthrough attributes transmiten automáticamente class, style y cualquier atributo no declarado como prop al elemento raíz del componente. En componentes multi-raíz, usa v-bind="$attrs" explícitamente.
  • Composables son la forma canónica de reutilizar lógica de clases en Vue. Extrae mapas de variantes a composables cuando se usen en más de un componente.
  • Para resolver conflictos de clases Tailwind (p-4 + p-6), instala tailwind-merge. Vue no resuelve conflictos por sí mismo.
  • Vue requiere menos dependencias que React para clases condicionales (:class reemplaza a clsx en el 80% de los casos, fallthrough attributes reemplazan la prop className manual).
  • No declares class ni style como props a menos que necesites manipularlas: eso bloquea los fallthrough attributes y la clase desaparece silenciosamente.

10 · Preguntas frecuentes

¿Vue necesita clsx y tailwind-merge como React?

clsx: no es necesario. La directiva :class nativa de Vue cubre la mayoría de sus casos de uso (condicionales con objeto, composición con array). tailwind-merge: sí es recomendable si tienes componentes con clases base que el consumidor puede sobrescribir. Vue fusiona clases pero no resuelve conflictos entre clases Tailwind que compiten por la misma propiedad CSS (p-4 + p-6). Puedes crear una pequeña función cn() con twMerge para usarla en computed properties cuando sea necesario.

¿Qué pasa si mi componente tiene múltiples elementos raíz (fragmentos)?

Los fallthrough attributes no se aplican automáticamente. Debes usar v-bind="$attrs" en el elemento que quieres que los reciba. Si ningún elemento tiene v-bind="$attrs", los atributos se pierden silenciosamente. Vue emite un warning en desarrollo si hay atributos no vinculados en un componente multi-raíz, pero no en producción.

¿Puedo usar class-variance-authority (cva) en Vue?

Sí, cva es agnóstico de framework. Funciona igual que en React. Pero en Vue suele ser innecesario porque las computed properties + objetos ya proporcionan un patrón muy similar de forma nativa. Si vienes de React y te sientes cómodo con cva, puedes seguir usándolo en Vue sin problema.

¿Los fallthrough attributes funcionan con eventos (@click, @focus)?

Los listeners de eventos se incluyen en $attrs con el prefijo on (ej: onClick). Con v-bind="$attrs" se vinculan automáticamente al elemento. Sin embargo, si el componente ya tiene su propio @click en el elemento raíz, los fallthrough listeners se ejecutan además del listener interno (ambos se disparan), no lo sobrescriben.

¿Cómo manejo dark mode en componentes Vue con Tailwind?

Exactamente igual que en HTML plano: usa el prefijo dark: en las clases. Asegúrate de que la clase dark esté en el <html> (Vue no la gestiona automáticamente). Lo habitual es usar un pequeño script en index.html que lea localStorage y añada la clase dark al <html> antes de que Vue monte la aplicación. Tailwind genera los estilos de dark mode a partir de esas clases con prefijo.
