Dark Mode

Módulo 6 · Tailwind: Responsive y Temas ⏱ 30 minutos

1 · Introducción

Hace unos años, el modo oscuro era una rareza que solo unos pocos desarrolladores activaban en su editor de código. Hoy, el 70% de los usuarios prefiere el modo oscuro en sus aplicaciones. Sistemas operativos, navegadores, redes sociales — todos ofrecen tema claro y oscuro. Tu web también debería.

💡 ¿Por qué es importante el dark mode?

Va mucho más allá de la estética. El modo oscuro reduce la fatiga visual en entornos con poca luz, ahorra batería en pantallas OLED (los píxeles negros están apagados), y es una expectativa básica de accesibilidad. Un usuario con sensibilidad a la luz no debería sentirse agredido por tu web. Implementarlo bien es síntoma de profesionalidad.

Qué problema resuelve: ofrecer dos esquemas de color (claro y oscuro) que el usuario pueda elegir, con una transición suave entre ambos y sin duplicar el CSS.

Cuándo se utiliza: en prácticamente cualquier proyecto web moderno. Si tu web tiene texto sobre fondo (todas lo tienen), necesitas dark mode. Las excepciones son webs puramente informativas que heredan el tema del sistema operativo sin toggle manual.

Errores típicos de principiantes:

  • Invertir colores sin más. Negro sobre blanco no se traduce a blanco sobre negro sin ajustes. Los contrastes no son simétricos.
  • Olvidar las imágenes y los iconos. Un logo oscuro sobre fondo oscuro desaparece. Un PNG con fondo blanco en modo oscuro parece un parche.
  • No respetar la preferencia del sistema. Si el usuario tiene macOS en dark mode y tu web carga en blanco nuclear, algo falla.
  • Persistir el tema solo en una variable de JavaScript. Si recargas la página, vuelves al tema por defecto. El flash de tema incorrecto es la peor experiencia.

2 · Teoría

Las dos estrategias de dark mode en Tailwind

Tailwind soporta dos formas de activar el modo oscuro. La elección depende de quién controla el tema y cómo quieres que se comporte:

EstrategiaQuién decideCSS generadoCuándo usarla
media (preferencia del sistema) El sistema operativo @media (prefers-color-scheme: dark) Webs simples donde no necesitas toggle manual
selector (clase manual) El usuario (con toggle) .dark .clase { ... } La gran mayoría de proyectos profesionales
📝 Nota: Tailwind v4 vs v3 en dark mode

En Tailwind v3, la estrategia se elegía con darkMode: 'class' o darkMode: 'media' en el archivo de configuración. En Tailwind v4 (CSS-first), se configura directamente en tu CSS con @custom-variant. Por defecto, v4 usa la preferencia del sistema (@media (prefers-color-scheme: dark)). Para usar la estrategia por clase, sobrescribes la variante dark así:

/* En tu archivo CSS principal, tras @import "tailwindcss" */
@custom-variant dark (&:where(.dark, .dark *));

Ojo con la sintaxis: la directiva es @custom-variant (define una variante). @variant es otra directiva distinta que solo sirve para aplicar una variante dentro de CSS propio, no para definirla. Confundirlas es un error muy común. El prefijo dark: funciona igual en ambas versiones.

Estrategia selector (recomendada): dark:

Es la estrategia que usaremos y la que recomienda Tailwind para el 95% de los proyectos. El prefijo dark: se activa cuando un elemento ancestro tiene la clase .dark. Normalmente se aplica al <html> o al <body>.

<!-- Modo claro (sin la clase .dark) -->
<html>
  <body class="bg-white text-gray-900">
    <h1 class="text-2xl font-bold">Hola</h1>
  </body>
</html>

<!-- Modo oscuro (con la clase .dark en html) -->
<html class="dark">
  <body class="bg-white dark:bg-gray-900 text-gray-900 dark:text-gray-100">
    <h1 class="text-2xl font-bold dark:text-white">Hola</h1>
  </body>
</html>

La clave está en el patrón de doble clase: el estilo base es para modo claro, dark: sobrescribe para modo oscuro. Tailwind genera el CSS automáticamente:

/* Tailwind genera esto por ti */
.bg-white { background-color: white; }
.dark .dark\:bg-gray-900 { background-color: #111827; }

.text-gray-900 { color: #111827; }
.dark .dark\:text-gray-100 { color: #f3f4f6; }

Persistencia: el patrón anti-flash

El mayor problema de dark mode es el flash de tema incorrecto (FOUC — Flash of Unstyled Content). Cuando el usuario recarga la página, hay un instante en que se ve el tema por defecto (claro) antes de que JavaScript aplique la clase .dark. Es horrible.

La solución es un script bloqueante en el <head> que lee localStorage y aplica la clase ANTES de que se renderice nada:

<head>
  <!-- Este script se ejecuta ANTES de pintar la página.
       No hay flash porque la clase .dark ya está puesta cuando el HTML se renderiza. -->
  <script>
    // Lee el tema guardado en localStorage.
    // Si no hay nada guardado, respeta la preferencia del sistema operativo.
    // IMPORTANTE: va en el <head>, SIN defer ni async, para que sea bloqueante.
    if (
      localStorage.getItem('theme') === 'dark' ||
      (!localStorage.getItem('theme') &&
       window.matchMedia('(prefers-color-scheme: dark)').matches)
    ) {
      document.documentElement.classList.add('dark');
    }
  </script>
</head>
💡 ¿Por qué el script va en el head y sin defer?

Los scripts con defer o async esperan a que el HTML esté parseado. Para entonces, el navegador ya ha pintado el fondo blanco. Un script bloqueante en el <head> pausa el parseo del HTML hasta que se ejecuta — son microsegundos, pero suficientes para poner .dark antes del primer píxel. Es el mismo patrón que usa Tailwind en su propia documentación.

El toggle: JavaScript mínimo

Un botón que alterna la clase .dark en el <html> y guarda la preferencia. Este es el código completo que necesitas:

// Obtén el botón que alterna el tema
const themeToggle = document.getElementById('theme-toggle');

themeToggle.addEventListener('click', () => {
  // Alterna la clase .dark en el elemento html
  document.documentElement.classList.toggle('dark');

  // Guarda la preferencia en localStorage
  const isDark = document.documentElement.classList.contains('dark');
  localStorage.setItem('theme', isDark ? 'dark' : 'light');

  // Opcional: cambia el icono del botón (sol ↔ luna)
  themeToggle.textContent = isDark ? '☀️' : '🌙';
});

// Al cargar la página, asegura que el icono del botón coincide con el tema
const savedTheme = localStorage.getItem('theme');
const prefersDark = window.matchMedia('(prefers-color-scheme: dark)').matches;
const isDark = savedTheme === 'dark' || (!savedTheme && prefersDark);
themeToggle.textContent = isDark ? '☀️' : '🌙';

Transiciones suaves entre temas

Por defecto, cambiar entre modo claro y oscuro es instantáneo y brusco. Para suavizar la transición, añade una transición CSS a los elementos raíz:

/* Transición suave al cambiar de tema.
   Se aplica a todos los elementos (*) pero solo en propiedades de color. */
*,
*::before,
*::after {
  transition: background-color 0.3s ease,
              color 0.3s ease,
              border-color 0.3s ease,
              box-shadow 0.3s ease;
}

/* Reduce la transición para el usuario que prefiere movimiento reducido */
@media (prefers-reduced-motion: reduce) {
  *,
  *::before,
  *::after {
    transition: none !important;
  }
}
💡 ¿Por qué limitar la transición a color, background-color y border-color?

Si pones transition: all, cada cambio de layout (como un breakpoint responsive) también se anima, creando efectos extraños al redimensionar la ventana. Limitando la transición a propiedades de color, solo se anima el cambio de tema, no todo lo demás.

Problemas comunes y sus soluciones

1. Contraste insuficiente en modo oscuro

El error más común: usar text-gray-500 (gris medio) sobre bg-gray-900 (fondo oscuro). En modo claro se lee bien, en modo oscuro el contraste es bajísimo.

<!-- MAL: text-gray-500 sobre fondo oscuro = ilegible -->
<p class="text-gray-500 dark:text-gray-500">
  Este texto apenas se ve en modo oscuro.
</p>

<!-- BIEN: texto más claro sobre fondo oscuro -->
<p class="text-gray-500 dark:text-gray-400">
  Contraste adecuado en ambos modos.
</p>

2. Imágenes y logos

Un logo oscuro sobre fondo oscuro desaparece. Tienes dos opciones:

<!-- Opción A: Mostrar diferente imagen según el tema -->
<img src="logo-light.svg" class="block dark:hidden" alt="Logo">
<img src="logo-dark.svg" class="hidden dark:block" alt="Logo">

<!-- Opción B (recomendada): SVG inline con currentColor -->
<svg class="w-32 h-8 text-gray-900 dark:text-white">
  <!-- SVG que usa fill="currentColor", hereda el color del texto -->
</svg>

3. Sombras en modo oscuro

Las sombras (shadow-md, shadow-lg) apenas se ven sobre fondo oscuro porque son negras semitransparentes. Solución: sombras más claras en modo oscuro.

<!-- MAL: sombra negra sobre fondo oscuro = invisible -->
<div class="bg-white dark:bg-gray-800 shadow-lg">

<!-- BIEN: sombra con color ajustado para modo oscuro -->
<div class="bg-white dark:bg-gray-800 shadow-lg
            dark:shadow-gray-900/50">

4. Bordes

Los bordes claros (border-gray-200) son casi invisibles sobre fondo oscuro. Usa bordes más oscuros en modo claro y más claros en modo oscuro:

<!-- BIEN: bordes adaptados a cada tema -->
<div class="border border-gray-200 dark:border-gray-700">

3 · Ejemplo mínimo

El ejemplo más pequeño de dark mode funcional: una tarjeta que cambia de aspecto con el toggle del tema. HTML, CSS y JS mínimos.

<!DOCTYPE html>
<html lang="es">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Dark Mode — Ejemplo mínimo</title>

  <!-- 1. Script anti-flash: lee el tema ANTES de pintar -->
  <script>
    if (
      localStorage.getItem('theme') === 'dark' ||
      (!localStorage.getItem('theme') &&
       window.matchMedia('(prefers-color-scheme: dark)').matches)
    ) {
      document.documentElement.classList.add('dark');
    }
  </script>

  <!-- 2. Tailwind CDN v4 (solo para este ejemplo) -->
  <script src="https://cdn.jsdelivr.net/npm/@tailwindcss/browser@4"></script>

  <!-- 2b. Configuramos la estrategia de dark mode por clase .dark -->
  <style type="text/tailwindcss">
    @custom-variant dark (&:where(.dark, .dark *));
  </style>

  <style>
    /* 3. Transición suave solo en propiedades de color */
    *, *::before, *::after {
      transition: background-color 0.3s ease, color 0.3s ease,
                  border-color 0.3s ease;
    }
    @media (prefers-reduced-motion: reduce) {
      *, *::before, *::after { transition: none !important; }
    }
  </style>
</head>
<body class="bg-gray-100 dark:bg-gray-950 text-gray-900
             dark:text-gray-100 min-h-screen flex items-center
             justify-center p-8 transition-colors">

  <!-- 4. Tarjeta con variantes dark: -->
  <div class="max-w-sm bg-white dark:bg-gray-900 rounded-2xl
              shadow-lg dark:shadow-gray-950/50 p-8">
    <h2 class="text-xl font-bold mb-4">
      Título de la tarjeta
    </h2>
    <p class="text-gray-600 dark:text-gray-400 mb-6">
      Este texto cambia de color automáticamente con el tema.
      El contraste se mantiene legible en ambos modos.
    </p>

    <!-- 5. Botón toggle de tema -->
    <button id="theme-toggle"
            class="bg-gray-900 dark:bg-yellow-400
                   text-white dark:text-gray-900
                   px-4 py-2 rounded-lg font-medium
                   hover:opacity-90 transition-opacity">
      🌙 Modo oscuro
    </button>
  </div>

  <!-- 6. JavaScript del toggle -->
  <script>
    const btn = document.getElementById('theme-toggle');
    const updateButton = () => {
      const isDark = document.documentElement.classList.contains('dark');
      btn.textContent = isDark ? '☀️ Modo claro' : '🌙 Modo oscuro';
    };

    updateButton(); // Texto inicial correcto

    btn.addEventListener('click', () => {
      document.documentElement.classList.toggle('dark');
      const isDark = document.documentElement.classList.contains('dark');
      localStorage.setItem('theme', isDark ? 'dark' : 'light');
      updateButton();
    });
  </script>
</body>
</html>

Explicación línea por línea:

  1. Script anti-flash: bloqueante en el <head>. Comprueba localStorage y la preferencia del sistema. Si alguna dice "oscuro", añade .dark al <html> antes del primer renderizado.
  2. Transición CSS: limitada a background-color, color y border-color. No anima layout ni dimensiones. Respeta prefers-reduced-motion.
  3. Estilos base (modo claro): bg-white, text-gray-900 — se aplican siempre que no haya .dark en un ancestro.
  4. Estilos dark: dark:bg-gray-900, dark:text-gray-400 — solo cuando html.dark está presente.
  5. Toggle: alterna .dark en document.documentElement, guarda en localStorage, actualiza el texto del botón.

Decisiones de diseño explicadas:

  • Header con backdrop-blur: el bg-white/80 con backdrop-blur crea un efecto de desenfoque del contenido al hacer scroll. En dark mode: dark:bg-gray-950/80.
  • Toggle con iconos SVG: en lugar de texto, usamos iconos de sol y luna que se alternan con hidden dark:block y block dark:hidden. Más profesional que un texto.
  • Código: fondo claro en light mode (bg-gray-100), fondo oscuro en dark mode (dark:bg-gray-900). El texto del código hereda el color general.
  • Badges: azul sobre fondo azul claro en light mode, azul claro sobre fondo azul oscuro en dark mode. El contraste se mantiene legible.
  • Tabla: cada elemento de la tabla tiene su variante dark: cabecera, filas, bordes divisores. Es tedioso pero necesario para que la tabla sea legible.

6 · Errores habituales

Error 1: Flash de tema incorrecto (FOUC)

El error más visible. El usuario recarga y durante una fracción de segundo ve el tema claro antes de que JavaScript ponga el oscuro.

❌ Incorrecto

<!-- MAL: el script va al final del body con defer. Llega tarde. -->
<script defer>
  if (localStorage.getItem('theme') === 'dark') {
    document.documentElement.classList.add('dark');
  }
</script>

✅ Correcto

<!-- BIEN: script bloqueante en <head>, antes de cualquier renderizado -->
<head>
  <script>
    if (localStorage.getItem('theme') === 'dark') {
      document.documentElement.classList.add('dark');
    }
  </script>
</head>

Error 2: Olvidar dark: en elementos anidados

Poner dark:bg-gray-900 en el body no tiñe mágicamente todos los hijos. Cada elemento que tenga un fondo o color definido necesita su variante dark:.

❌ Incorrecto

<body class="bg-white dark:bg-gray-950">
  <div class="bg-white">  <!-- Queda blanco en dark mode -->
    <h2 class="text-gray-900">Título</h2>  <!-- Ilegible -->
  </div>
</body>

✅ Correcto

<body class="bg-white dark:bg-gray-950">
  <div class="bg-white dark:bg-gray-900">
    <h2 class="text-gray-900 dark:text-white">Título</h2>
  </div>
</body>

Error 3: Sombras invisibles en dark mode

Las sombras de Tailwind son negras semitransparentes. Sobre fondo oscuro, la sombra se funde con el fondo y no se ve.

❌ Incorrecto

<div class="bg-white dark:bg-gray-800 shadow-xl rounded-xl p-6">
  <!-- shadow-xl = sombra negra. Sobre gray-800: invisible. -->
</div>

✅ Correcto

<div class="bg-white dark:bg-gray-800 rounded-xl p-6
            shadow-xl dark:shadow-none
            ring-1 ring-gray-200 dark:ring-gray-700">
  <!-- En dark mode: sin sombra, con un anillo sutil (ring) en su lugar -->
</div>

  localStorage.setItem('theme', isDark ? 'dark' : 'light');
});

// Escucha cambios en la preferencia del sistema (si el usuario
// cambia el tema del SO mientras la página está abierta)
window.matchMedia('(prefers-color-scheme: dark)')
  .addEventListener('change', (e) => {
    // Solo reacciona si el usuario no ha elegido manualmente
    if (!localStorage.getItem('theme')) {
      if (e.matches) {
        document.documentElement.classList.add('dark');
      } else {
        document.documentElement.classList.remove('dark');
      }
    }
  });

8 · Reto

🎯 Tu reto: Toggle de tema con 3 opciones

Crea un selector de tema con tres opciones en lugar de dos:

  • 🌙 Oscuro: fuerza modo oscuro siempre.
  • ☀️ Claro: fuerza modo claro siempre.
  • 💻 Sistema: sigue la preferencia del sistema operativo, y reacciona en tiempo real si el usuario la cambia.

Especificaciones:

  • El selector debe ser un grupo de 3 botones o un desplegable. El que uses, debe mostrar cuál está activo.
  • Guarda la elección en localStorage como "dark", "light" o null (sistema).
  • Cuando el usuario elige "Sistema", escucha cambios en prefers-color-scheme y actualiza el tema automáticamente sin recargar.
  • El script anti-flash del <head> debe manejar los tres casos correctamente.
  • Bonus: anima la transición entre los 3 estados. Cuando pulses "Sistema" y el SO esté en dark mode, el cambio debe ser inmediato pero suave.

Este patrón de 3 estados es el que usan aplicaciones como GitHub, VSCode y macOS. Implementarlo bien demuestra que entiendes dark mode a nivel profesional.

9 · Resumen

📌 Conceptos clave de esta lección
  • Estrategia selector: dark: se activa cuando un ancestro tiene la clase .dark. Es el enfoque recomendado porque da al usuario control total con un toggle.
  • Script anti-flash: un script bloqueante en el <head> que lee localStorage y aplica .dark antes del primer renderizado. Sin él, cada recarga muestra un destello del tema incorrecto.
  • Transiciones suaves: anima solo propiedades de color (background-color, color, border-color). Respeta prefers-reduced-motion para accesibilidad.
  • Contraste: en dark mode necesitas colores de texto más claros y fondos más oscuros. text-gray-500 es ilegible sobre bg-gray-900.
  • Imágenes y logos: usa SVG inline con currentColor para que hereden el color del tema, o muestra/oculta versiones específicas con dark:hidden y hidden dark:block.
  • Sombras y bordes: las sombras negras no se ven en dark mode. Usa ring-* o sombras más claras. Los bordes claros necesitan su variante dark:border-gray-700.
  • Persistencia: guarda la elección del usuario en localStorage. Respeta la preferencia explícita por encima de prefers-color-scheme.

10 · Preguntas frecuentes

¿Por qué no usar solo prefers-color-scheme sin toggle?

prefers-color-scheme es una preferencia del sistema, no una elección por sitio web. Muchos usuarios tienen su SO en dark mode pero prefieren leer documentación en modo claro, o viceversa. Un toggle da al usuario control granular. Además, hay entornos (como presentaciones en proyector) donde el modo claro es necesario independientemente de la configuración del SO. La mejor práctica es: respeta la preferencia del SO como valor inicial, pero permite que el usuario la sobrescriba.

¿Cómo evito que las imágenes se vean mal en dark mode?

Tres estrategias, de mejor a peor: (1) SVG inline con fill="currentColor" — se adapta automáticamente al color del texto. (2) Mostrar diferentes imágenes con block dark:hidden / hidden dark:block — efectivo pero duplica recursos. (3) Aplicar dark:brightness-90 o dark:invert a la imagen — reduce el brillo o invierte colores, funciona para fotos pero no para logos. Para fotos, dark:brightness-75 suele ser suficiente para que no deslumbren.

¿Qué hago con los colores de marca que no cambian en dark mode?

Los colores de marca (brand colors) NO deberían cambiar drásticamente en dark mode. Un botón azul corporativo puede oscurecerse ligeramente (bg-blue-600 dark:bg-blue-500) para no deslumbrar, pero mantener su esencia. Lo que SÍ cambia son los fondos y textos que rodean esos elementos. Un botón azul sobre fondo blanco funciona; sobre fondo negro puede necesitar un ajuste sutil de saturación o luminosidad para mantener el mismo "peso visual".

¿Vale la pena el esfuerzo del dark mode para proyectos pequeños?

Sí, por tres razones: (1) Tailwind hace que sea trivial — solo añades dark: a las clases que ya tienes. (2) Los usuarios lo esperan. Un portfolio o una landing sin dark mode en 2026 parece descuidado. (3) Implementarlo desde el principio es fácil; añadirlo después requiere revisar cada componente. El coste marginal de añadir dark:bg-gray-900 junto a bg-white es casi cero si lo haces mientras escribes el componente.

¿Puedo usar el prefijo dark: con cualquier utilidad de Tailwind?

Sí. Absolutamente todas las utilidades aceptan dark:: colores, tipografía, espaciado, bordes, sombras, filtros, transformaciones... La sintaxis es dark:[utilidad]. Esto incluye valores arbitrarios como dark:bg-[#1a1a2e] o dark:shadow-[0_0_15px_rgba(56,189,248,0.3)].

¿Cómo pruebo el dark mode en desarrollo?

Además del toggle que construyas, puedes: (1) En Chrome DevTools (F12), pulsar los tres puntos > More tools > Rendering > Emulate CSS media feature prefers-color-scheme y elegir dark o light. (2) En el panel Elements, añadir/eliminar manualmente la clase dark del <html>. (3) Usar la extensión "Dark Mode" de Chrome para forzar el tema en cualquier web. Lo ideal es probar las 4 combinaciones: localStorage + toggle, localStorage + recarga, sin localStorage + SO en dark, sin localStorage + SO en light.
