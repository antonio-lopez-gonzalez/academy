Personalización con @theme

Módulo 6 · Tailwind: Responsive y Temas ⏱ 35 minutos

1 · Introducción

Tailwind CSS viene con un sistema de diseño excelente: paletas de colores profesionales, escalas tipográficas equilibradas, espaciados consistentes. Pero cada proyecto tiene su propia identidad visual. Si todos usáramos los colores por defecto de Tailwind, internet sería azul índigo con grises slate.

🧩 Analogía: Tailwind por defecto es un esqueleto; @theme es la piel

Imagina que Tailwind es una casa prefabricada. Viene con paredes, ventanas y puertas estándar. Funciona. Pero con @theme puedes cambiar el color de las paredes, elegir suelos de madera, poner ventanas más grandes y añadir una chimenea. La estructura es la misma, pero la casa ahora es TUYA. Y lo mejor: si mañana cambias una pieza, toda la casa se actualiza automáticamente.

Qué problema resuelve: adaptar Tailwind a la identidad visual de tu marca o proyecto sin perder las ventajas del utility-first. Colores corporativos, fuentes personalizadas, breakpoints específicos — todo definido en un solo lugar.

Cuándo se utiliza: en absolutamente todo proyecto real. Nadie usa Tailwind con los valores por defecto en producción. Siempre personalizas colores (tu paleta de marca), fuentes (tu tipografía corporativa) y a veces breakpoints o espaciados.

Errores típicos de principiantes:

  • Sobrescribir TODO el tema por defecto. Si borras la paleta de colores de Tailwind con --color-*: initial, pierdes clases como bg-red-500 que quizá necesites para alertas.
  • Crear nombres de color poco semánticos. brand dice qué es; color-1 no dice nada. Los nombres cuentan una historia.
  • Olvidar la escala completa de colores. Si defines --color-primary: #3b82f6 pero no defines primary-100, primary-200, etc., no podrás usar fondos claros ni bordes sutiles con ese color.
  • Añadir demasiadas fuentes. Cada fuente personalizada añade peso de descarga y puede ralentizar el renderizado. Una o dos fuentes bien elegidas > cinco fuentes decorativas.

2 · Teoría

El nuevo modelo de configuración de Tailwind v4

Tailwind v4 abandonó el archivo tailwind.config.js en favor de una configuración CSS-first. Todo — colores, fuentes, breakpoints, animaciones — se define con propiedades CSS personalizadas dentro de la directiva @theme. Esto significa que la configuración de Tailwind ahora es CSS estándar, no JavaScript.

/* Antes (Tailwind v3): tailwind.config.js */
export default {
  theme: {
    extend: {
      colors: { brand: '#ff6b6b' },
      fontFamily: { display: ['Inter', 'sans-serif'] }
    }
  }
}
/* Ahora (Tailwind v4): tu archivo CSS principal */
@import "tailwindcss";

@theme {
  --color-brand: #ff6b6b;
  --font-family-display: "Inter", sans-serif;
}
💡 ¿Por qué el cambio a CSS-first?

Varias razones: (1) No necesitas un paso de build para procesar JavaScript de configuración — el CSS se procesa directamente. (2) Las variables CSS son nativas del navegador — puedes leer --color-brand desde cualquier otro CSS o JavaScript. (3) Un solo archivo CSS contiene TODO: imports, configuración, estilos personalizados. Menos archivos, menos contexto mental. (4) Los editores de código ya entienden CSS; no necesitan un plugin especial para autocompletar un tailwind.config.js.

Extender colores con @theme

Los colores son lo primero que personalizas en cualquier proyecto. Tailwind usa una paleta numérica (50-950) para cada color, y puedes añadir tus propios colores de marca usando variables CSS:

@import "tailwindcss";

@theme {
  /* Añades un color de marca con su escala completa */
  --color-primary-50: #eff6ff;
  --color-primary-100: #dbeafe;
  --color-primary-200: #bfdbfe;
  --color-primary-300: #93c5fd;
  --color-primary-400: #60a5fa;
  --color-primary-500: #3b82f6;  /* El color base de tu marca */
  --color-primary-600: #2563eb;
  --color-primary-700: #1d4ed8;
  --color-primary-800: #1e40af;
  --color-primary-900: #1e3a8a;
  --color-primary-950: #172554;

  /* Para colores que no necesitan escala, solo el base */
  --color-accent: #f59e0b;  /* Se usa como bg-accent, text-accent, etc. */
}

/* Ahora puedes usar estas clases en tu HTML: */
/* bg-primary-500, text-primary-200, border-primary-700, etc. */
📝 Nota: colores con y sin escala

Si defines un color simple (--color-accent: #f59e0b), solo tienes la clase text-accent. Si defines la escala --color-primary-50 a --color-primary-950, tienes text-primary-50 hasta text-primary-950. Para colores de marca que necesitas en múltiples intensidades (fondos claros, bordes, hover), la escala completa es indispensable.

Personalizar fuentes

Tailwind incluye tres familias por defecto: font-sans (system-ui), font-serif (Georgia) y font-mono (monospace). Puedes extenderlas o reemplazarlas:

@import "tailwindcss";

@theme {
  /* Reemplaza la fuente sans-serif por defecto */
  --font-family-sans: "Inter", ui-sans-serif, system-ui, sans-serif;

  /* Añade una fuente display para títulos */
  --font-family-display: "Cabinet Grotesk", "Inter", sans-serif;

  /* Personaliza la fuente mono para código */
  --font-family-mono: "JetBrains Mono", "Fira Code", monospace;
}

/* Uso en HTML: */
/* <body class="font-sans">    Inter */
/* <h1 class="font-display">   Cabinet Grotesk */
📌 Carga las fuentes correctamente

Al definir fuentes personalizadas en @theme, también debes cargarlas. Las opciones: (1) Google Fonts con @import en tu CSS. (2) Archivos locales con @font-face. (3) Servicio propio con next/font en Next.js. Tailwind solo genera las clases; la carga de la fuente es responsabilidad tuya.

Personalizar breakpoints

Los breakpoints por defecto (sm: 640px, md: 768px, lg: 1024px, xl: 1280px, 2xl: 1536px) cubren la mayoría de casos, pero a veces necesitas ajustarlos o añadir nuevos:

@import "tailwindcss";

@theme {
  /* Modifica breakpoints existentes */
  --breakpoint-sm: 480px;   /* Más pequeño que el default (640px) */
  --breakpoint-md: 800px;   /* Personalizado para tablets grandes */

  /* Añade breakpoints nuevos */
  --breakpoint-3xl: 1920px; /* Monitores 1080p+ */
  --breakpoint-4xl: 2560px; /* Monitores 2K/4K */

  /* Ahora existen clases como 3xl:grid-cols-4, 4xl:text-2xl, etc. */
}
💡 ¿Por qué querrías breakpoints personalizados?

Si trabajas en un dashboard que siempre tiene una sidebar de 280px, el breakpoint md: a 768px quizá no sea ideal — querrías que el layout cambie a 800px o 900px para acomodar la sidebar. O si tu audiencia usa mayoritariamente portátiles pequeños (1366px), podrías ajustar lg: para que active el layout de desktop antes. Personalizar breakpoints es raro, pero cuando lo necesitas, @theme lo hace trivial.

Personalizar espaciados, tamaños y más

Puedes personalizar prácticamente cualquier aspecto del sistema de diseño de Tailwind:

@import "tailwindcss";

@theme {
  /* Espaciado: añade un valor extra-grande */
  --spacing-18: 4.5rem;    /* Tailwind no tiene spacing-18 por defecto */
  --spacing-88: 22rem;
  --spacing-128: 32rem;

  /* Bordes redondeados personalizados */
  --radius-xl: 1rem;       /* Sobrescribe el xl por defecto (0.75rem) */
  --radius-2xl: 1.5rem;
  --radius-4xl: 3rem;

  /* Sombras personalizadas */
  --shadow-brand: 0 4px 14px 0 rgba(59, 130, 246, 0.3);
  --shadow-elevated: 0 10px 40px -10px rgba(0, 0, 0, 0.15);

  /* Tamaños de fuente personalizados */
  --font-size-2xs: 0.625rem;
  --font-size-huge: 4rem;

  /* Animaciones personalizadas */
  --animate-fade-in: fade-in 0.5s ease-out;
  --animate-slide-up: slide-up 0.4s ease-out;
}

/* Define los keyframes en tu CSS también */
@keyframes fade-in {
  from { opacity: 0; }
  to { opacity: 1; }
}

@keyframes slide-up {
  from { opacity: 0; transform: translateY(20px); }
  to { opacity: 1; transform: translateY(0); }
}

/* Uso en HTML: animate-fade-in, animate-slide-up */

La directiva @import en Tailwind v4

@import "tailwindcss" es el punto de entrada. Sustituye a las tres directivas de Tailwind v3 (@tailwind base; @tailwind components; @tailwind utilities;). Internamente, carga todo el framework.

/* Archivo CSS principal de tu proyecto (ej. src/index.css) */
@import "tailwindcss";

/* Tu configuración de tema */
@theme {
  --color-brand: #ff6b6b;
  --font-family-sans: "Inter", sans-serif;
}

/* Estilos globales personalizados */
@layer base {
  body {
    @apply bg-white text-gray-900 dark:bg-gray-950 dark:text-gray-100;
  }
}

/* Componentes reutilizables */
@layer components {
  .btn-primary {
    @apply bg-brand text-white px-4 py-2 rounded-lg
           hover:opacity-90 transition-opacity;
  }
}
📝 Nota: @import vs @tailwind

En Tailwind v4, @import "tailwindcss" reemplaza a @tailwind base, @tailwind components y @tailwind utilities. Solo necesitas una línea. Si migras de v3 a v4, este es uno de los cambios principales. Las capas (@layer base, @layer components, @layer utilities) siguen funcionando igual.

Plugins oficiales de Tailwind CSS

Tailwind mantiene varios plugins oficiales que extienden el framework con funcionalidad adicional. En v4 se cargan con @plugin en tu CSS:

@tailwindcss/typography

El plugin más popular de Tailwind. Añade la clase prose que estiliza automáticamente contenido HTML generado desde Markdown o CMS: encabezados, párrafos, listas, citas, tablas, código... Todo con espaciado y tipografía profesional. Perfecto para blogs, documentación y artículos.

@import "tailwindcss";
@plugin "@tailwindcss/typography";
<article class="prose dark:prose-invert max-w-none">
  <h1>Título del artículo</h1>
  <p>Este párrafo tiene interlineado, margen y tamaño de fuente óptimos
     para lectura. No he escrito ni una línea de CSS.</p>
  <blockquote>Las citas se estilizan automáticamente</blockquote>
  <ul>
    <li>Listas con espaciado perfecto</li>
    <li>Y viñetas estilizadas</li>
  </ul>
  <pre><code>const code = 'bloques de código con sintaxis';</code></pre>
</article>

Variantes de prose:

  • prose-sm, prose-lg, prose-xl, prose-2xl — tamaños de fuente.
  • prose-gray, prose-slate, prose-zinc — esquemas de color.
  • dark:prose-invert — invierte colores para modo oscuro.

@tailwindcss/forms

Restablece y estiliza formularios HTML de forma sensata. Por defecto, los inputs, selects, textareas y checkboxes se ven diferentes en cada navegador. Este plugin los normaliza con un diseño limpio y accesible.

@import "tailwindcss";
@plugin "@tailwindcss/forms";
<form class="space-y-4 max-w-md">
  <div>
    <label class="block text-sm font-medium mb-1">Email</label>
    <input type="email" class="w-full rounded-lg border-gray-300
           dark:border-gray-600 dark:bg-gray-800
           focus:ring-2 focus:ring-brand focus:border-brand">
  </div>
  <div>
    <label class="block text-sm font-medium mb-1">Mensaje</label>
    <textarea rows="4" class="w-full rounded-lg border-gray-300
              dark:border-gray-600 dark:bg-gray-800"></textarea>
  </div>
  <div class="flex items-center gap-2">
    <input type="checkbox"
           class="rounded border-gray-300 text-brand focus:ring-brand">
    <label class="text-sm">Acepto los términos</label>
  </div>
  <button type="submit"
          class="bg-brand text-white px-6 py-2 rounded-lg
                 hover:opacity-90 transition-opacity">Enviar</button>
</form>

3 · Ejemplo mínimo

El ejemplo más pequeño de personalización: un proyecto Tailwind v4 que define un color de marca y una fuente personalizada. Solo necesitas dos archivos.

/* src/index.css — Tu archivo CSS principal */
@import "tailwindcss";

/* Carga la fuente desde Google Fonts */
@import url('https://fonts.googleapis.com/css2?family=Inter:wght@400;500;600;700&display=swap');

@theme {
  /* Color de marca corporativo en OKLCH */
  --color-brand: oklch(0.65 0.25 20);

  /* Fuente personalizada */
  --font-family-sans: "Inter", ui-sans-serif, system-ui, sans-serif;
}
<!DOCTYPE html>
<html lang="es">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <link rel="stylesheet" href="/src/index.css">
</head>
<body class="font-sans bg-white text-gray-900 p-8">
  <h1 class="text-3xl font-bold text-brand">
    Mi proyecto con Tailwind personalizado
  </h1>
  <p class="mt-4 text-gray-600">
    La fuente es Inter y el color de marca es coral, definidos en @theme.
  </p>
  <button class="mt-6 bg-brand text-white px-6 py-2 rounded-lg
                 hover:opacity-90 transition-opacity">
    Botón de marca
  </button>
</body>
</html>

Explicación línea por línea:

  1. @import "tailwindcss" — carga el framework completo. Sin esto, Tailwind no genera ninguna clase.
  2. @import url('https://fonts.googleapis.com/...') — carga la fuente Inter desde Google Fonts. La fuente debe estar disponible antes de usarse.
  3. --color-brand: oklch(...) — define un nuevo color llamado brand. Usamos OKLCH (el espacio de color moderno) en lugar de HEX para mejor control perceptual. Ahora existen clases como bg-brand, text-brand, border-brand, ring-brand, etc.
  4. --font-family-sans — reemplaza la fuente sans-serif por defecto. Ahora font-sans usa Inter en lugar de la fuente del sistema.
  5. En el HTML, text-brand y bg-brand usan el color definido. font-sans usa Inter. Todo funciona como si fueran utilidades nativas de Tailwind.

4 · Ejemplo real

Vamos a configurar un tema corporativo completo para una startup ficticia llamada "NeonPulse". Incluye paleta de colores, dos fuentes, breakpoints personalizados, animaciones y el plugin de tipografía. Este es un archivo de configuración realista que podrías encontrar en producción.

/* src/index.css — Configuración completa de NeonPulse */
@import "tailwindcss";
@plugin "@tailwindcss/typography";

/* Fuentes corporativas */
@import url('https://fonts.googleapis.com/css2?family=Space+Grotesk:wght@400;500;600;700&family=JetBrains+Mono:wght@400;500&display=swap');

@theme {

  --color-neon-200: #bbf7d0;
  --color-neon-300: #86efac;
  --color-neon-400: #4ade80;
  --color-neon-500: #22c55e;
  --color-neon-600: #16a34a;
  --color-neon-700: #15803d;
  --color-neon-800: #166534;
  --color-neon-900: #14532d;
  --color-neon-950: #052e16;

  /* Color de acento: púrpura eléctrico */
  --color-electric-50: #faf5ff;
  --color-electric-100: #f3e8ff;
  --color-electric-200: #e9d5ff;
  --color-electric-300: #d8b4fe;

  }

Decisiones de diseño explicadas:

  • Dos colores de marca con escala completa: verde neón (primario) y púrpura eléctrico (acento). Cada uno con escala 50-950 para cubrir fondos claros, bordes, hover states y texto.
  • Colores simples para superficies: surface y surface-dark no necesitan escala; solo se usan como fondos base.
  • Breakpoints ajustados: xs a 480px para móviles grandes, md a 800px para tablets grandes.
  • Sombras de marca: en lugar de usar shadow-lg genérico, definimos sombras con el color de la marca. Esto crea cohesión visual.
  • Componentes con @layer: .btn-neon, .btn-electric y .card usan @apply para combinar utilidades. Esto es opcional (puedes poner las clases en el HTML), pero útil para componentes muy repetidos.

5 · Buenas prácticas

HazEvitaPor qué
Extiende el tema por defecto, no lo reemplaces Hacer --color-*: initial para borrar todo Los colores de Tailwind (red-500, green-600...) son útiles para alertas, validación y estados. Borrarlos te obliga a redefinir colores que no son de marca pero sí necesarios.
Usa nombres semánticos para tus colores Nombres como --color-1, --color-a text-brand comunica intención. text-color-1 obliga a mirar la definición cada vez.
Define escalas completas (50-950) para colores de marca Definir solo --color-brand sin variantes Necesitarás bg-brand-50 para fondos sutiles, border-brand-200 para bordes, text-brand-700 para texto.
Agrupa la configuración en un solo archivo Esparcir variables @theme en múltiples archivos Un solo archivo de tema es la única fuente de verdad para colores, fuentes y breakpoints. Si un color cambia, lo cambias en un sitio.
Carga solo las fuentes que usas Importar una fuente con 10 pesos si solo usas 2 Cada peso de fuente añade ~20KB. wght@400;700 pesa la mitad que wght@100;200;300;400;500;600;700;800;900.

6 · Errores habituales

Error 1: Sobrescribir en lugar de extender

El error más destructivo: borrar toda la paleta de colores de Tailwind para poner solo los tuyos. Luego necesitas un color rojo para un mensaje de error y no existe bg-red-500.

❌ Incorrecto

/* MAL: esto borra TODOS los colores de Tailwind */
@theme {
  --color-*: initial;
  --color-brand: #ff6b6b;
}
/* Ahora bg-red-500 no existe. bg-blue-500 tampoco. Solo bg-brand. */

✅ Correcto

/* BIEN: solo añades tus colores. Los de Tailwind permanecen. */
@theme {
  --color-brand-50: #fff5f5;
  --color-brand-100: #ffe0e0;
  --color-brand-200: #ffc2c2;
  --color-brand-300: #ff9e9e;
  --color-brand-400: #ff7a7a;
  --color-brand-500: #ff6b6b;
  --color-brand-600: #e05555;
  --color-brand-700: #c04040;
  --color-brand-800: #a03030;
  --color-brand-900: #802020;
  --color-brand-950: #601010;
}

Error 2: Definir colores sin pensar en dark mode

Si defines --color-surface: #ffffff, necesitas también su contraparte oscura o usar las variantes dark: de Tailwind.

❌ Incorrecto

@theme {
  --color-surface: #ffffff;
  --color-content: #111827;
}
/* En dark mode, texto negro sobre fondo oscuro del navegador = ilegible */

✅ Correcto

@theme {
  --color-surface: #ffffff;
  --color-content: #111827;
}

@layer base {
  body {
    @apply bg-surface text-content
           dark:bg-gray-950 dark:text-gray-100;
  }
}

Error 3: Mala elección de pesos de fuente

Cargar una fuente con 9 pesos cuando solo usas regular (400) y bold (700) es desperdiciar ancho de banda.

❌ Incorrecto

<!-- MAL: 200KB extra para pesos que nunca se usan -->
<link href="https://fonts.googleapis.com/css2?family=Inter:
      wght@100;200;300;400;500;600;700;800;900&display=swap"
      rel="stylesheet">

✅ Correcto

<!-- BIEN: solo los pesos necesarios (400, 500, 700) = ~60KB -->
<link href="https://fonts.googleapis.com/css2?family=Inter:
      wght@400;500;700&display=swap" rel="stylesheet">

7 · Ejercicio guiado

Vamos a crear un tema de marca completo para una cafetería ficticia llamada "Café Oscuro". Definiremos colores, fuentes y un componente reutilizable. Paso a paso.

  1. Crea el archivo CSS principal. Empieza con @import "tailwindcss" y un @theme vacío. 
    @import "tailwindcss";

@theme {
  /* Aquí irá nuestra configuración */
}
  2. Define la paleta de colores de la cafetería. Marrón cálido como color principal, crema como acento. Escala completa para el marrón. 
    @theme {
  /* Marrón café (escala completa) */
  --color-cafe-50: #fdf8f0;
  --color-cafe-100: #f9edd5;
  --color-cafe-200: #f2d9aa;
  --color-cafe-300: #e8bf75;
  --color-cafe-400: #dba550;
  --color-cafe-500: #c4883a;
  --color-cafe-600: #a36b2e;
  --color-cafe-700: #825328;
  --color-cafe-800: #6a4325;

📌 Resultado

Has creado un tema de marca completo para una cafetería. Si mañana quieres cambiar el color principal de marrón a verde, solo tienes que modificar las variables --color-cafe-* en @theme. Todos los componentes (.btn-cafe, .btn-cafe-outline) y todas las clases (bg-cafe-600, text-cafe-700) se actualizan automáticamente. Esto es el poder de un design system centralizado.

8 · Reto

🎯 Tu reto: Crea tu propio tema de marca

Elige una marca real o inventa una y crea su tema completo en Tailwind v4. Especificaciones:

  • Paleta de colores: un color primario con escala completa (50-950), un color de acento (puede ser simple o con escala), y al menos un color semántico (success, warning o error) con escala completa.
  • Tipografía: dos fuentes — una para títulos y otra para texto. Cárgalas desde Google Fonts.
  • Componentes reutilizables: mínimo 3 componentes con @layer components y @apply (botón primario, botón secundario, tarjeta, badge... los que tengan sentido para tu marca).
  • Breakpoints: si tu marca tiene requisitos específicos de responsive, personaliza al menos un breakpoint.
  • Animación personalizada: define al menos un @keyframes y su correspondiente --animate-*.
  • Demo: crea una página HTML sencilla que use todos los elementos de tu tema (colores, fuentes, componentes, animaciones).

El objetivo es que sientas que el tema es "tuyo". No copies la paleta de Tailwind con otros nombres — crea algo con personalidad. Un buen tema de marca es reconocible incluso sin logos.

9 · Resumen

📌 Conceptos clave de esta lección
  • Tailwind v4 CSS-first: la configuración se hace con @theme en CSS, no con tailwind.config.js. @import "tailwindcss" reemplaza a las directivas @tailwind de v3.
  • Colores personalizados: define --color-nombre-50 a --color-nombre-950 para la escala completa. Usa nombres semánticos (brand, accent).
  • Fuentes: --font-family-sans, --font-family-serif, --font-family-mono para reemplazar las fuentes por defecto. Añade nombres nuevos como --font-family-display para crear la clase font-display.
  • Breakpoints: --breakpoint-sm, --breakpoint-md, etc. Añade nuevos con --breakpoint-3xl y se generan prefijos como 3xl:.
  • Espaciados, sombras, animaciones: todo se configura con variables CSS en @theme. Las animaciones necesitan también los @keyframes correspondientes.
  • Plugins: @plugin "@tailwindcss/typography" para contenido editorial. @plugin "@tailwindcss/forms" para formularios normalizados.
  • Capas: @layer base para estilos globales, @layer components para componentes reutilizables con @apply.

10 · Preguntas frecuentes

¿Puedo usar @theme sin @import "tailwindcss"?

No. @theme es una directiva de Tailwind que solo funciona si has cargado el framework con @import "tailwindcss" primero. Sin ese import, el compilador de Tailwind no procesa el archivo y las variables CSS no se traducen a clases utilitarias.

¿Qué pasa si defino un color que ya existe en Tailwind?

Lo sobrescribes. Si defines --color-red-500: #ff0000, todas las clases bg-red-500, text-red-500, etc. usarán tu nuevo valor en lugar del rojo por defecto de Tailwind. Esto es muy potente: puedes "recolorear" toda la paleta de Tailwind manteniendo los mismos nombres de clase. Útil si quieres que blue-* use los colores corporativos de tu empresa.

¿Cuándo usar @apply en @layer components y cuándo no?

@apply es útil cuando un mismo conjunto de clases se repite mucho (botones, cards, badges). Pero tiene un coste: añade abstracción. La regla práctica: si usas exactamente las mismas clases en 3 o más sitios, considera @apply. Si es 1 o 2 veces, deja las clases en el HTML. El equilibrio está en no crear componentes para todo (volverías a Bootstrap) pero tampoco repetir 15 clases de botón en cada página.

¿Funciona @theme en Tailwind CDN?

El CDN de Tailwind (https://cdn.jsdelivr.net/npm/@tailwindcss/browser@4) tiene soporte limitado para @theme. Puedes definir algunas variables CSS, pero no todas las funcionalidades (como @plugin) están disponibles. Para desarrollo real, usa siempre una instalación local con Vite o PostCSS. El CDN es solo para prototipado rápido y ejemplos.

¿Cómo organizo los archivos de tema en un proyecto grande?

Patrón recomendado: un archivo index.css que importa Tailwind y luego importa archivos parciales. Ejemplo: @import "tailwindcss"; @import "./theme/colors.css"; @import "./theme/fonts.css"; @import "./theme/components.css";. Tailwind v4 procesa los imports de CSS nativo, así que puedes modularizar tu tema sin problemas. Cada archivo parcial contiene su bloque @theme { ... }. Tailwind los fusiona internamente.

¿Puedo usar OKLCH en lugar de HEX en @theme?

Sí, y es recomendable. --color-brand: oklch(0.65 0.25 20) es perfectamente válido. OKLCH es el espacio de color moderno con mejor soporte en navegadores, gama más amplia y control perceptual más intuitivo que HEX o RGB. Tailwind v4 está migrando internamente a OKLCH. Si empiezas un proyecto nuevo en 2026, usa OKLCH.
