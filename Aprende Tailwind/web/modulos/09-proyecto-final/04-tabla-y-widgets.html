Tabla de datos y widgets

Módulo 9 · Proyecto Final: Dashboard ⏱ 40 minutos

1 · Introducción

Las métricas de la lección anterior te dan la foto general. Pero un dashboard de verdad necesita que el usuario pueda inspeccionar los datos en detalle. ¿Quiénes son esos 24,892 usuarios? ¿Cuál es su estado? ¿Cuándo se registró el último?

La tabla de datos es el componente más complejo y más usado en dashboards profesionales. Es donde los usuarios pasan más tiempo: filtrando, ordenando, paginando, evaluando. Una buena tabla de datos debe ser:

  • Escaneable: Columnas bien definidas, cabeceras claras, alineación consistente.
  • Informativa a primera vista: Badges de estado, avatares, indicadores visuales.
  • Interactiva: Hover de fila, ordenación por columna, paginación.
  • Responsive: En móvil, la tabla se transforma en tarjetas apiladas (table→cards pattern).

Además de la tabla, añadiremos widgets complementarios: un calendario en grid, una lista de próximos eventos y una barra de almacenamiento con indicador visual. Estos widgets ocupan la columna lateral y dan contexto adicional a los datos de la tabla.

2 · Teoría

Anatomía de una tabla de datos profesional

Una tabla de datos tiene 5 zonas distintas. Cada una merece atención de diseño:

┌──────────────────────────────────────────────────────────┐
│  CABECERA DE TABLA (toolbar)                             │
│  👥 Usuarios    [🔍 Buscar...]  [+ Nuevo]  [Exportar]    │
├──────────┬──────────────┬──────────┬──────────┬──────────┤
│ Nombre ▲ │ Email        │ Rol      │ Estado   │ Fecha    │ ← Encabezados
├──────────┼──────────────┼──────────┼──────────┼──────────┤
│ Marina   │ m@gomez.com  │ Admin    │ 🟢 Activo│ 12 Ene   │ ← Filas de datos
│ Carlos   │ c@ruiz.com   │ Editor   │ 🟢 Activo│ 03 Feb   │   (hover resalta)
│ Laura    │ l@martin.com │ Viewer   │ 🔴 Inact │ 28 Dic   │
├──────────┼──────────────┼──────────┼──────────┼──────────┤
│ Mostrando 1-3 de 48    │ ◀ 1  2  3 ... 16 ▶ │          │ ← Paginación
└──────────────────────────────────────────────────────────┘

El patrón table→cards para responsive

En móvil, una tabla HTML tradicional es un desastre: requiere scroll horizontal y oculta columnas. El patrón moderno es transformar cada fila en una "card" vertical apilada:

Desktop (tabla):                 Móvil (cards):

┌──────┬──────┬──────┐          ┌────────────────────┐
│ Nom  │ Rol  │ Est  │          │ Marina Gómez       │
├──────┼──────┼──────┤          │ m@gomez.com        │
│ M.G. │ Adm  │ 🟢   │    →    │ Admin │ 🟢 Activo  │
│ C.R. │ Edt  │ 🟢   │          │ 12 Ene 2025        │
│ L.M. │ View │ 🔴   │          └────────────────────┘
└──────┴──────┴──────┘          ┌────────────────────┐
                                │ Carlos Ruiz        │
                                │ c@ruiz.com         │
                                │ Editor │ 🟢 Activo │
                                │ 03 Feb 2025        │
                                └────────────────────┘

Implementamos esto con CSS puro: en desktop mostramos la tabla con <table> y ocultamos las cards. En móvil (max-width: 640px o el breakpoint sm: de Tailwind), ocultamos la tabla y mostramos las cards. El HTML contiene AMBAS versiones, controladas por visibilidad condicional.

¿Por qué no usar solo CSS para adaptar la tabla? Puedes usar display: block en filas y celdas para convertirlas en bloques verticales. Pero pierdes el control sobre el orden y la presentación de cada campo. Con el patrón de dos versiones (tabla + cards), tienes control total sobre cómo se ve cada fila en móvil: puedes agrupar campos, cambiar el orden, añadir iconos, y mostrar/ocultar columnas selectivamente.

Paginación: el componente olvidado

La paginación parece trivial pero tiene muchas decisiones de diseño:

  • Botones Previous/Next: Siempre visibles, incluso si están deshabilitados (para mantener el layout estable).
  • Página activa: Fondo coloreado, texto blanco — imposible de confundir con las inactivas.
  • Elipsis (…): Cuando hay muchas páginas, muestra primera, última, y las adyacentes a la actual.
  • Indicador de rango: "Mostrando 1-10 de 48 resultados" — le da al usuario contexto de cuántos datos hay.

Widget de calendario con CSS Grid

Un calendario mensual es un grid de 7 columnas (Lu-Sa-Do) con celdas cuadradas. CSS Grid es la herramienta perfecta:

/* 7 columnas iguales para los días de la semana */
grid-template-columns: repeat(7, 1fr);

Cada celda es un día. Los días del mes actual tienen texto normal, los días de meses adyacentes tienen opacidad reducida. El día actual tiene un círculo de color. Los días con eventos tienen un punto indicador debajo del número.

overflow-x-auto en el contenedor de tabla: En pantallas muy estrechas (antes de que las cards tomen el control), el scroll horizontal en la tabla es un mal menor. Pero es una red de seguridad, no la solución principal. La solución real es el patrón table→cards que veremos a continuación. El overflow-x-auto está ahí para el caso extremo: alguien que rota el móvil a landscape con un tamaño intermedio donde ni la tabla ni las cards funcionan perfectamente.

6 · Errores habituales

La tabla en móvil se ve con scroll horizontal y columnas cortadas

Usaste overflow-x-auto como solución definitiva en lugar de implementar el patrón table→cards. El scroll horizontal en móvil es una mala experiencia de usuario — el usuario tiene que deslizar horizontalmente para ver datos que deberían ser visibles de un vistazo. Solución: añade la versión cards con block sm:hidden y oculta la tabla con hidden sm:block.

Los badges de estado tienen el mismo color para "Activo" e "Inactivo"

Usaste el mismo estilo para todos los badges o solo cambiaste el texto. El estado es la columna más importante para escanear rápidamente — debe tener un contraste de color inmediato. Solución: usa bg-emerald-50 text-emerald-700 para activo y bg-red-50 text-red-700 para inactivo. El cerebro procesa el color antes que el texto.

La paginación desaparece al filtrar y solo queda 1 página de resultados

Escondiste la paginación con un v-if o display: none cuando solo hay 1 página. El layout de la tabla cambia de altura, y todo el contenido debajo "salta". Solución: mantén la barra de paginación siempre visible, aunque esté deshabilitada. El texto "Mostrando 1-3 de 3 resultados" ya comunica que no hay más páginas.

Los días del calendario no se alinean correctamente con los días de la semana

El primer día del mes no cae en la columna correcta. Agosto 2025 empieza en viernes, así que necesitas 4 celdas vacías (o de julio) antes del día 1. Si no añades esas celdas, el día 1 aparece en la columna del lunes y todo el mes está desplazado. Solución: calcula el día de la semana del día 1 y añade celdas vacías o del mes anterior con opacidad reducida.

7 · Ejercicio guiado

Vamos a añadir ordenación por columna a la tabla de usuarios. Al hacer clic en el encabezado de una columna, las filas se ordenan por ese campo (ascendente/descendente alternando).

Paso 1: Convertir los encabezados en botones clickeables

<th class="text-left px-6 py-3 font-semibold text-slate-600">
  <button class="flex items-center gap-1 hover:text-slate-900 transition-colors group"
          onclick="sortTable('nombre')">
    Usuario
    <span class="text-slate-300 group-hover:text-slate-400 text-xs sort-icon">⇅</span>
  </button>
</th>

Paso 2: JavaScript de ordenación

<script>
  let sortDirection = {}; /* guarda la dirección por columna */

  function sortTable(column) {
    const tbody = document.querySelector('tbody');
    const rows = Array.from(tbody.querySelectorAll('tr'));

    /* Alternar dirección */
    sortDirection[column] = sortDirection[column] === 'asc' ? 'desc' : 'asc';
    const dir = sortDirection[column];

    rows.sort((a, b) => {
      let aVal, bVal;

      switch(column) {
        case 'nombre':
          aVal = a.querySelector('.font-medium').textContent.trim();
          bVal = b.querySelector('.font-medium').textContent.trim();
          break;
        case 'email':
          aVal = a.querySelector('td:nth-child(2)')?.textContent.trim() || '';
          bVal = b.querySelector('td:nth-child(2)')?.textContent.trim() || '';
          break;
        case 'rol':
          aVal = a.querySelector('[class*="bg-"][class*="text-"]')?.textContent.trim() || '';
          bVal = b.querySelector('[class*="bg-"][class*="text-"]')?.textContent.trim() || '';
          break;
        default:
          return 0;
      }

      const cmp = aVal.localeCompare(bVal, 'es');
      return dir === 'asc' ? cmp : -cmp;
    });

    /* Reordenar las filas en el DOM */
    rows.forEach(row => tbody.appendChild(row));

    /* Actualizar iconos de ordenación */
    document.querySelectorAll('.sort-icon').forEach(icon => {
      icon.textContent = '⇅';
    });
    /* Mostrar dirección en la columna ordenada */
    const activeIcon = document.querySelector(`[onclick="sortTable('${column}')"] .sort-icon`);
    if (activeIcon) {
      activeIcon.textContent = dir === 'asc' ? '↑' : '↓';
      activeIcon.classList.add('text-cyan-500');
    }
  }
</script>

Reordenar nodos del DOM: appendChild en un nodo que ya existe en el DOM lo MUEVE al final. Al recorrer el array ordenado y hacer appendChild de cada fila, las filas se reordenan en el orden correcto. Es más eficiente que eliminar y recrear nodos.

🎯 Tabla con selección de filas y acciones en lote

Añade checkboxes a la tabla de usuarios para seleccionar múltiples filas y ejecutar acciones en lote:

  1. Añade una columna de checkbox al principio de cada fila y un checkbox "Seleccionar todo" en el encabezado.
  2. Al seleccionar filas, aparece una barra de acciones flotante en la parte inferior: "X filas seleccionadas · [Eliminar] [Exportar] [Cambiar rol]".
  3. La barra de acciones debe tener sticky bottom-0 y un fondo blanco con sombra hacia arriba.
  4. El checkbox "Seleccionar todo" debe tener un estado intermedio (indeterminate) cuando solo algunas filas están seleccionadas.

9 · Resumen

  • Tabla de datos profesional: Encabezados con bg-slate-50, filas con hover:bg-slate-50 transition-colors, divisores con divide-y. Badges de estado con punto de color + texto.
  • Patrón table→cards: hidden sm:block para la tabla desktop, block sm:hidden para las cards móviles. Dos versiones completas en HTML con control total sobre el diseño de cada breakpoint.
  • Columnas progresivas: hidden md:table-cell oculta columnas secundarias en tablet, hidden lg:table-cell las muestra en desktop. El usuario de móvil ve solo lo esencial.
  • Paginación: Botones Previous/Next, página activa con bg-cyan-500 text-white, elipsis para saltos, indicador de rango. Siempre visible para estabilidad de layout.
  • Calendario CSS Grid: grid grid-cols-7 para los días. Día actual con círculo coloreado. Días con eventos: punto indicador debajo del número. Días de otros meses: opacidad reducida.
  • Donut chart SVG: Círculo con stroke-dasharray para el porcentaje. Texto centrado con posicionamiento absoluto. Infinitamente escalable y animable.
  • Ordenación con JS vanilla: Array.from(rows).sort() + appendChild para reordenar nodos en el DOM. Sin dependencias, sin frameworks.

10 · Preguntas frecuentes

¿No es malo duplicar el HTML para las cards móviles?

Es un trade-off. Duplicas HTML (que el navegador parsea una vez) a cambio de control total sobre el diseño responsive. En aplicaciones reales, este HTML lo genera un framework (React, Vue) o un template engine, así que no hay duplicación en el código fuente — solo en el HTML renderizado. Si el rendimiento te preocupa, el coste de unos pocos KB extra de HTML es insignificante comparado con el JavaScript necesario para transformar la tabla dinámicamente.

¿Cómo hago que la tabla cargue datos de una API real?

Sustituye el HTML estático del <tbody> por una plantilla que se rellena con JavaScript: haz fetch a tu API, itera sobre los resultados, y para cada fila creas un <tr> con insertAdjacentHTML o clonas un <template>. Las clases de Tailwind en las filas generadas son idénticas a las del ejemplo estático. Si usas React/Vue, el patrón es aún más simple: mapeas el array de datos a componentes de fila.

¿Puedo hacer el calendario interactivo (click en día, navegación entre meses)?

Sí. Necesitas JavaScript para: (1) mantener el estado del mes/año actual, (2) calcular el primer día de la semana de ese mes, (3) generar el grid de 42 celdas (6 semanas × 7 días) dinámicamente, (4) manejar clics en días para mostrar/crear eventos. El CSS (el grid de 7 columnas) no cambia — solo cambia el contenido de las celdas. Es un proyecto perfecto para practicar manipulación del DOM.

¿Cómo manejo tablas con miles de filas sin que la página se congele?

Para miles de filas necesitas virtualización (virtual scrolling): solo renderizas las filas visibles en el viewport + un pequeño buffer. Librerías como TanStack Table (React/Vue/Solid) o AG Grid manejan esto. Pero para la mayoría de dashboards, la paginación con 10-50 filas por página es suficiente y mucho más simple. Si tienes 10,000 usuarios, nadie va a hacer scroll por todos — van a buscar, filtrar o paginar.

¿El SVG del donut chart es accesible?

El SVG básico no es accesible por sí mismo. Para accesibilidad, añade: (1) role="img" al SVG, (2) un <title> dentro del SVG con la descripción, (3) aria-labelledby apuntando al title, (4) el texto del porcentaje fuera del SVG (ya lo tenemos en el centro) debe ser un elemento HTML real, no un <text> del SVG. Así los lectores de pantalla pueden leer "68.4% usado" como texto semántico.
