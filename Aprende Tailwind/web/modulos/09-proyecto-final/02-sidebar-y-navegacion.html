Sidebar y navegación

Módulo 9 · Proyecto Final: Dashboard ⏱ 40 minutos

1 · Introducción

En la lección anterior construiste el esqueleto del dashboard: grid lateral, topbar sticky y área de contenido. Pero la sidebar era estática — enlaces fijos, sin interactividad, sin adaptación a móvil. Es como tener el chasis de un coche sin volante ni pedales.

Hoy vamos a darle vida a la navegación. La sidebar es el centro de mando del dashboard: por aquí el usuario se mueve entre secciones, ve notificaciones pendientes y accede a su perfil. Una buena sidebar debe ser:

  • Colapsable: En desktop, el usuario puede encogerla para ganar espacio de contenido.
  • Informativa: Badges de notificación que indican elementos pendientes sin abrir cada sección.
  • Clara: El enlace activo se resalta para que el usuario siempre sepa dónde está.
  • Organizada: Secciones con separadores visuales que agrupan enlaces relacionados.
  • Adaptable a móvil: En pantallas pequeñas se convierte en un overlay que se desliza desde la izquierda.

Al terminar esta lección tendrás una sidebar profesional con todas estas características, implementada con Tailwind + un puñado de líneas de JavaScript.

2 · Teoría

Los tres estados de una sidebar

Toda sidebar de dashboard tiene tres estados posibles. Conocerlos antes de programar evita tener que reescribir código después:

Estado Cuándo se usa Ancho Comportamiento
Expandida Desktop, por defecto w-64 (256px) Muestra icono + texto. Navegación completa visible.
Colapsada Desktop, cuando el usuario quiere más espacio w-16 (64px) o w-20 (80px) Solo iconos. Texto oculto. Tooltip al hacer hover.
Overlay (móvil) Pantallas < 1024px (lg:) w-64 con fondo semi-transparente detrás Se desliza desde la izquierda. Clic fuera = cierra. Ocupa toda la altura.

Transiciones CSS para el colapso

Cuando la sidebar cambia de ancho, los elementos internos deben adaptarse con suavidad. Tailwind proporciona transition-all para transicionar todas las propiedades animables:

/* Lo que Tailwind genera con transition-all duration-300 */
.sidebar {
  transition-property: all;
  transition-timing-function: cubic-bezier(0.4, 0, 0.2, 1);
  transition-duration: 300ms;
}

Pero hay una trampa: transition-all anima TODAS las propiedades, incluyendo las que no deberían animarse (como display o visibility). En producción, es mejor animar solo width, padding y opacity:

/* Más óptimo que transition-all */
.sidebar {
  transition: width 300ms ease, padding 300ms ease, opacity 200ms ease;
}

Para este proyecto usaremos transition-all duration-300 por simplicidad, pero ten presente la optimización para producción.

El patrón overlay para móvil

En móvil no hay espacio para una sidebar fija. El patrón estándar es:

  1. La sidebar se oculta con -translate-x-full (desplazada fuera de la pantalla hacia la izquierda).
  2. Un botón hamburguesa en la topbar la muestra aplicando translate-x-0.
  3. Un fondo oscuro semitransparente (bg-black/50) detrás de la sidebar indica que es un overlay.
  4. Al hacer clic en el fondo oscuro o en un enlace, la sidebar se cierra (-translate-x-full de nuevo).

Jerarquía visual con secciones y separadores

Los enlaces de navegación no deberían ser una lista plana. Agruparlos en secciones con títulos mejora drásticamente la escaneabilidad:

PRINCIPAL              ← título de sección (text-xs, uppercase, slate-500)
  📊 Dashboard         ← enlace con icono
  📋 Proyectos
  👥 Equipo

GESTIÓN                ← otro título de sección
  📁 Archivos
  ⚙️ Configuración
  📈 Reportes

Los títulos de sección usan text-xs font-semibold text-slate-500 uppercase tracking-wider. El tracking-wider (letter-spacing: 0.05em) hace que el texto respire y se lea como una etiqueta, no como un enlace.

Badges de notificación: el patrón absolute dentro de relative

Un badge de notificación (ej. "3" en rojo junto a "Mensajes") se implementa con posicionamiento absoluto dentro de un contenedor relative. Es el mismo patrón que el badge "online" de la tarjeta del Módulo 1:

<a href="#" class="relative flex items-center gap-3 px-3 py-2 rounded-lg">
  📨 Mensajes
  <span class="absolute right-2 top-1/2 -translate-y-1/2 bg-red-500 text-white text-xs font-bold px-1.5 py-0.5 rounded-full min-w-[20px] text-center">
    3
  </span>
</a>

El badge usa absolute right-2 top-1/2 -translate-y-1/2: se ancla a la derecha del enlace, centrado verticalmente con el truco de translate. min-w-[20px] garantiza que números de un dígito y dos dígitos tengan un ancho mínimo consistente.

<script>
  const sidebar = document.getElementById('sidebar');
  const toggleBtn = document.getElementById('toggle-sidebar');
  const logoText = document.getElementById('sidebar-logo');
  const sidebarTexts = document.querySelectorAll('.sidebar-text');
  const toggleIcon = document.getElementById('toggle-icon');

  toggleBtn.addEventListener('click', () => {
    sidebar.classList.toggle('w-64');   /* ↔ alterna entre w-64 y w-16 */
    sidebar.classList.toggle('w-16');

    /* Oculta/muestra textos */
    sidebarTexts.forEach(el => el.classList.toggle('hidden'));

    /* Oculta/muestra logo */
    logoText.classList.toggle('hidden');

    /* Gira el icono */
    toggleIcon.classList.toggle('rotate-180');
  });
</script>

El código anterior demuestra el mecanismo básico:

  • Alternancia de clases: classList.toggle('w-64') y classList.toggle('w-16') cambian el ancho. La sidebar tiene ambas inicialmente (w-64) y al hacer toggle se intercambian.
  • transition-all duration-300: El cambio de ancho se anima en 300ms con una curva ease-in-out.
  • flex-shrink-0: Evita que la sidebar se encoja por presión del contenido — el ancho lo controlamos nosotros con JS.
  • Ocultar textos: Al colapsar, los textos se ocultan con classList.toggle('hidden'). Los iconos (flex-shrink-0) permanecen visibles y centrados.

¿Por qué toggle de w-64 y w-16 en lugar de una sola clase condicional? Tailwind es mobile-first: las clases se aplican de menor a mayor breakpoint. Si usáramos w-64 lg:w-16, en pantallas grandes siempre sería w-16. Con toggle de JS controlamos manualmente ambos estados. En producción usarías un data attribute (data-collapsed="true") y CSS condicional, pero para este curso el toggle de clases es más didáctico.

JavaScript completo: toggle desktop + overlay móvil

<script>
  const sidebar = document.getElementById('sidebar');
  const overlay = document.getElementById('sidebar-overlay');
  const toggleBtn = document.getElementById('toggle-sidebar');
  const toggleIcon = document.getElementById('toggle-icon');
  const sidebarBrand = document.getElementById('sidebar-brand');
  const sidebarTexts = document.querySelectorAll('.sidebar-text');
  const sidebarLabels = document.querySelectorAll('.sidebar-label');
  const sidebarBadges = document.querySelectorAll('.sidebar-badge');
  const navLinks = document.querySelectorAll('.nav-link');
  const hamburgerBtn = document.getElementById('hamburger-btn');

  let sidebarCollapsed = false;

  /* ===== TOGGLE DESKTOP (colapsar/expandir) ===== */
  toggleBtn.addEventListener('click', () => {
    sidebarCollapsed = !sidebarCollapsed;

    if (sidebarCollapsed) {
      sidebar.classList.remove('w-64');
      sidebar.classList.add('w-16');
      toggleIcon.style.transform = 'rotate(180deg)';
      sidebarTexts.forEach(el => el.classList.add('hidden'));
      sidebarLabels.forEach(el => el.classList.add('hidden'));
      sidebarBadges.forEach(el => el.classList.add('hidden'));
    } else {
      sidebar.classList.remove('w-16');
      sidebar.classList.add('w-64');
      toggleIcon.style.transform = 'rotate(0deg)';
      sidebarTexts.forEach(el => el.classList.remove('hidden'));
      sidebarLabels.forEach(el => el.classList.remove('hidden'));
      sidebarBadges.forEach(el => el.classList.remove('hidden'));
    }
  });

  /* ===== OVERLAY MÓVIL ===== */
  function openMobileSidebar() {
    sidebar.classList.remove('-translate-x-full');
    overlay.classList.remove('hidden');
    document.body.style.overflow = 'hidden'; /* previene scroll del body */
  }

  function closeMobileSidebar() {
    sidebar.classList.add('-translate-x-full');
    overlay.classList.add('hidden');
    document.body.style.overflow = '';
  }

  if (hamburgerBtn) {
    hamburgerBtn.addEventListener('click', openMobileSidebar);
  }

  overlay.addEventListener('click', closeMobileSidebar);

  /* Cierra la sidebar móvil al hacer clic en cualquier enlace */
  navLinks.forEach(link => {
    link.addEventListener('click', () => {
      if (window.innerWidth < 1024) {
        closeMobileSidebar();
      }

      /* Actualizar enlace activo */
      navLinks.forEach(l => {
        l.classList.remove('bg-slate-800', 'text-white');
        l.classList.add('text-slate-400');
      });
      link.classList.remove('text-slate-400');
      link.classList.add('bg-slate-800', 'text-white');
    });
  });

  /* Cierra con tecla Escape */
  document.addEventListener('keydown', (e) => {
    if (e.key === 'Escape' && window.innerWidth < 1024) {
      closeMobileSidebar();
    }
  });
</script>

¿Por qué fixed en móvil pero static en desktop? En móvil, la sidebar usa fixed para flotar sobre el contenido como overlay. En desktop (lg:static), vuelve a su posición normal en el flujo del flex. La clase -translate-x-full lg:translate-x-0 la oculta fuera de pantalla en móvil pero la muestra normalmente en desktop. Es el mismo elemento HTML con comportamientos radicalmente diferentes según el breakpoint — Tailwind en estado puro.

6 · Errores habituales

La sidebar colapsada muestra los textos cortados, no ocultos

Te falta overflow-hidden en el contenedor de los textos o en el enlace. Cuando la sidebar se reduce a w-16 (64px), los textos que miden más de 64px - padding - icono deberían ocultarse. Pero si no pones overflow-hidden, el texto desborda visualmente aunque la sidebar sea estrecha. Solución: asegúrate de ocultar los textos con JS (classList.add('hidden')) al colapsar, no solo confiar en que el ancho los recorte.

El overlay móvil cubre la sidebar en lugar de estar detrás

El z-index del overlay es mayor o igual que el de la sidebar. La sidebar debe tener z-50 y el overlay z-40. Si el overlay está por encima, el usuario no puede interactuar con los enlaces de navegación. Solución: sidebar con z-50, overlay con z-40.

La sidebar no se cierra al hacer clic en un enlace en móvil

Olvidaste añadir el event listener que cierra la sidebar al hacer clic en los enlaces de navegación. El comportamiento esperado en móvil es: el usuario toca un enlace → la navegación ocurre → la sidebar se cierra automáticamente. Sin esto, el overlay se queda abierto y el usuario tiene que cerrarlo manualmente. Solución: añade link.addEventListener('click', closeMobileSidebar) a cada enlace.

La transición de colapso es brusca, no animada

Falta transition-all duration-300 en la sidebar. Sin transition, el cambio de w-64 a w-16 es instantáneo y parece un bug. Con transition, el ancho se interpola suavemente en 300ms. Asegúrate de que la clase transition está en el elemento que cambia de tamaño (el aside), no en un hijo.

7 · Ejercicio guiado

Vamos a añadir tooltips a los iconos de navegación cuando la sidebar está colapsada. Así el usuario puede ver el nombre de cada sección haciendo hover sobre el icono, sin necesidad de expandir la sidebar.

Paso 1: Añadir el atributo data-tooltip a cada enlace

<!-- Ejemplo para el enlace de Dashboard -->
<a href="#" class="nav-link group flex items-center gap-3 px-3 py-2 rounded-lg bg-slate-800 text-white relative">
  <span class="text-lg flex-shrink-0">📊</span>
  <span class="sidebar-text whitespace-nowrap">Dashboard</span>
  <!-- Tooltip (visible solo cuando la sidebar está colapsada) -->
  <span class="sidebar-tooltip absolute left-full ml-3 px-2 py-1 bg-slate-800 text-white text-xs rounded-md whitespace-nowrap
               opacity-0 invisible group-hover:opacity-100 group-hover:visible transition-all duration-200 pointer-events-none z-50">
    Dashboard
  </span>
</a>

Paso 2: Mostrar tooltips solo en estado colapsado

/* Dentro del toggle de la sidebar, añadir: */
const tooltips = document.querySelectorAll('.sidebar-tooltip');

/* Al colapsar: mostrar tooltips */
tooltips.forEach(el => el.classList.remove('hidden'));

/* Al expandir: ocultar tooltips (el texto ya es visible) */
tooltips.forEach(el => el.classList.add('hidden'));

Paso 3: Estilizar el tooltip con una flecha triangular

<!-- Tooltip mejorado con flecha -->
<span class="sidebar-tooltip absolute left-full ml-3 px-2.5 py-1.5 bg-slate-700 text-white text-xs font-medium rounded-md whitespace-nowrap
             opacity-0 invisible group-hover:opacity-100 group-hover:visible transition-all duration-200 pointer-events-none z-50
             shadow-lg">
  Dashboard
  <!-- Flecha izquierda -->
  <span class="absolute right-full top-1/2 -translate-y-1/2 border-4 border-transparent border-r-slate-700"></span>
</span>

El truco de la flecha CSS: un elemento con border-4 border-transparent es invisible. Al añadir border-r-slate-700, solo el borde derecho tiene color, creando un triángulo que apunta a la izquierda. Posicionado con right-full (a la izquierda del tooltip) y centrado verticalmente con top-1/2 -translate-y-1/2.

8 · Reto

🎯 Sidebar con submenús expandibles (acordeón)

Transforma una de las secciones de la navegación (por ejemplo, "Gestión") en un acordeón:

  1. El título de sección "Gestión" se convierte en un botón clickeable con una flecha ▼ que rota al expandir.
  2. Los enlaces de esa sección se ocultan/muestran con una transición de altura (max-height + overflow-hidden).
  3. El estado (expandido/colapsado) debe persistir al colapsar y expandir la sidebar.
  4. Añade un indicador visual (línea vertical sutil a la izquierda) en los subenlaces para marcar la jerarquía.

Restricciones:

  • No uses librerías de acordeón. Implementa la lógica con JS vanilla (máximo 15 líneas).
  • La animación debe ser suave: usa max-height con transition-all duration-300.
  • Respeta el estado de la sidebar: si la sidebar está colapsada, el submenú no debería ser visible aunque esté "expandido".

9 · Resumen

  • La sidebar tiene tres estados: expandida (w-64 con icono + texto), colapsada (w-16 solo iconos + tooltips) y overlay móvil (fixed, se desliza desde la izquierda con fondo oscuro).
  • JavaScript controla el colapso: classList.toggle alterna w-64/w-16, oculta textos con hidden, gira el icono de toggle y muestra/oculta tooltips. Todo animado con transition-all duration-300.
  • El overlay móvil usa el mismo elemento: fixed lg:static y -translate-x-full lg:translate-x-0. Un solo aside con breakpoints de Tailwind maneja ambos comportamientos.
  • Secciones con separadores: text-xs uppercase tracking-wider para etiquetas de sección. space-y-6 entre secciones, space-y-1 entre enlaces. La jerarquía visual es inmediata.
  • Badges de notificación: absolute right-2 top-1/2 -translate-y-1/2 dentro de un enlace relative. Colores semánticos: rojo para urgente, ámbar para pendiente. min-w-[20px] para ancho consistente.
  • Enlace activo: bg-slate-800 text-white. El JS actualiza la clase al hacer clic, eliminando el estilo activo de todos los enlaces y aplicándolo solo al clickeado.
  • Buenas prácticas de UX: Cerrar con Escape, bloquear scroll del body durante overlay, tooltips en sidebar colapsada, transiciones suaves en todos los cambios de estado.

10 · Preguntas frecuentes

¿Por qué usar classList.toggle y no un data attribute con CSS?

En producción, un data attribute (data-collapsed="true") con CSS condicional es más mantenible. Pero para este curso, classList.toggle es más didáctico: ves exactamente qué clases cambian y entiendes el mecanismo. Cuando domines esto, migrar a data attributes es trivial. El patrón sería: aside[data-collapsed="true"] .sidebar-text { display: none; }.

¿Cómo añado iconos SVG en lugar de emojis?

Los emojis en los ejemplos son para simplificar — no requieren dependencias. En producción usarías una librería de iconos como Heroicons (gratis, misma estética que Tailwind) o Lucide. El HTML sería idéntico, solo cambiarías el <span>📊</span> por un <svg>...</svg>. Las mismas clases de Tailwind (w-5 h-5, flex-shrink-0) aplican.

¿Cómo persisto el estado colapsado entre recargas de página?

Guarda el estado en localStorage: localStorage.setItem('sidebar-collapsed', sidebarCollapsed) al hacer toggle. Al cargar la página, lee el valor y aplica las clases correspondientes antes de que el usuario vea la interfaz. Es exactamente el mismo patrón que usamos para el tema claro/oscuro en el Módulo 6. Unas 5 líneas extra de JS.

¿Puedo usar este sistema de navegación con React o Vue?

Absolutamente. La lógica de clases de Tailwind es idéntica en cualquier framework. La diferencia es cómo manejas el estado: en React usarías useState para sidebarCollapsed y renderizarías condicionalmente las clases. En Vue usarías :class bindings reactivos. El HTML y las clases de Tailwind no cambian — solo cambia el mecanismo que las aplica. Exploramos esto en detalle en el Módulo 8.

¿Qué pasa si tengo 50 enlaces de navegación?

Con 50 enlaces, la sidebar necesita scroll interno. Ya lo tenemos: overflow-y-auto en el <nav>. Pero considera alternativas: (1) añadir un buscador dentro de la sidebar que filtre enlaces, (2) usar solo la primera sección expandida por defecto y colapsar el resto (acordeón), (3) mover enlaces poco usados a una página de "Configuración". Si necesitas 50 enlaces siempre visibles, replantéate la arquitectura de información.
