Responsive y pulido final

Módulo 9 · Proyecto Final: Dashboard ⏱ 45 minutos

1 · Introducción

Has construido un dashboard completo: estructura grid, sidebar con navegación, tarjetas de métricas, gráficos, tabla de datos, widgets. Pero hasta ahora solo funciona en tema claro y en desktop. Un dashboard profesional funciona en cualquier dispositivo y respeta las preferencias del usuario.

Esta lección es el pulido final. No añadimos funcionalidades nuevas — refinamos las existentes para que el dashboard sea:

  • Dark mode completo: El usuario puede alternar entre tema claro y oscuro. La preferencia se guarda en localStorage y se respeta al recargar.
  • Responsive mobile-first: La sidebar se convierte en bottom nav o overlay, la tabla pasa a cards, el grid se reduce a 1 columna. Todo fluye naturalmente.
  • Accesible: Navegación por teclado con focus-visible, roles ARIA en componentes interactivos, contraste suficiente en ambos temas.
  • Pulido visual: Dropdown de perfil con animación, sistema de toasts para notificaciones, transiciones consistentes de 300ms en toda la interfaz.

Al terminar, tendrás un dashboard que podrías entregar a un cliente. Solo faltarían los datos reales del backend.

2 · Teoría

Dark mode: no es solo invertir colores

Implementar dark mode correctamente va mucho más allá de poner dark:bg-gray-900 en todo. Requiere decisiones de diseño deliberadas:

Elemento Tema claro Tema oscuro Razón del cambio
Fondo principal bg-slate-50 bg-slate-950 El fondo más oscuro reduce la emisión de luz en pantallas OLED. Slate-950 es casi negro pero mantiene un matiz azulado para no ser "negro puro"
Sidebar bg-slate-900 bg-slate-950 + borde La sidebar ya es oscura en tema claro. En dark mode necesita ser aún más oscura que el fondo para mantener la jerarquía. Un borde sutil la separa del contenido
Tarjetas bg-white bg-slate-900 Las tarjetas "flotan" sobre el fondo. En dark mode, slate-900 sobre slate-950 crea una diferencia sutil pero perceptible
Texto text-slate-900 text-slate-100 Texto claro sobre fondo oscuro. No uses blanco puro (text-white) — cansa la vista. Slate-100 es más suave
Bordes border-slate-200 border-slate-800 En dark mode, los bordes deben ser más sutiles. Slate-800 sobre slate-900 es apenas visible pero define las tarjetas
Sombras shadow-sm shadow-none o ring-1 ring-slate-800 Las sombras no funcionan en dark mode (no se ven sobre fondo oscuro). Se sustituyen por ring (borde sutil) o se eliminan

El sistema de dark mode en Tailwind v4

Tailwind v4 ofrece dos estrategias para dark mode: media query (@media (prefers-color-scheme: dark)) y selector (.dark en un ancestro). Para un dashboard, el método selector es superior porque el usuario puede elegir independientemente de su preferencia del sistema:

/* Tailwind procesa esto automáticamente con el prefijo dark: */
/* En tema claro (por defecto) */
.card { background: white; color: #0f172a; }

/* En tema oscuro (cuando un ancestro tiene class="dark") */
.dark .card { background: #1e293b; color: #f1f5f9; }
<!-- Implementación con JS + localStorage -->
<script>
  /* Al cargar: aplicar tema guardado o preferencia del sistema */
  if (localStorage.getItem('theme') === 'dark' ||
      (!localStorage.getItem('theme') && window.matchMedia('(prefers-color-scheme: dark)').matches)) {
    document.documentElement.classList.add('dark');
  }

  /* Toggle: el botón alterna la clase dark + guarda en localStorage */
  document.getElementById('theme-toggle').addEventListener('click', () => {
    document.documentElement.classList.toggle('dark');
    localStorage.setItem('theme',
      document.documentElement.classList.contains('dark') ? 'dark' : 'light'
    );
  });
</script>

¿Por qué class="dark" en <html> y no en <body>? El <html> es el ancestro más alto. Poner la clase ahí garantiza que ABSOLUTAMENTE TODO en la página (incluyendo elementos fixed, overlays, modales renderizados con portales) herede el tema oscuro. Si la pones en <body>, los elementos fixed que se renderizan fuera del flujo del body pueden no heredarla.

Mobile-first responsive: la estrategia de breakpoints

Tailwind es mobile-first por defecto: las clases sin prefijo aplican a todos los tamaños. Los prefijos (sm:, md:, lg:) añaden estilos para pantallas MÁS GRANDES. Esta es la estrategia de nuestro dashboard:

Breakpoint Ancho Cambios en el dashboard
Base (móvil) < 640px Sidebar full-screen overlay. Tabla → cards. Grid métricas: 1 columna. Topbar simplificada. Buscador oculto.
sm: ≥ 640px Grid métricas: 2 columnas. Buscador visible. Breadcrumb visible. Tabla ya usa versión tabla (no cards).
md: ≥ 768px Tabla muestra columna Email. Selector de fechas visible. Sidebar aún overlay.
lg: ≥ 1024px Sidebar fija (no overlay). Grid métricas: 4 columnas. Tabla muestra todas las columnas. Layout de 2 columnas (sidebar + contenido).

focus-visible: accesibilidad sin estropear el diseño

El problema: focus:ring-2 muestra un anillo azul CADA VEZ que haces clic en un botón. Es feo y molesto para usuarios de ratón. La solución: focus-visible: solo muestra el anillo cuando el usuario navega con teclado (Tab), no con ratón:

<!-- ❌ Mal: anillo en cada clic -->
<button class="focus:ring-2 focus:ring-cyan-500">...</button>

<!-- ✅ Bien: anillo solo con teclado -->
<button class="focus:outline-none focus-visible:ring-2 focus-visible:ring-cyan-500 focus-visible:ring-offset-2">
  ...
</button>

Toasts: notificaciones efímeras

Un toast es una notificación que aparece en una esquina de la pantalla, muestra un mensaje, y desaparece automáticamente. Se implementa con:

  • Posicionamiento: fixed bottom-4 right-4 z-50 — esquina inferior derecha.
  • Animación de entrada: translate-y-4 opacity-0 → translate-y-0 opacity-100 con transición.
  • Timer de salida: setTimeout(() => toast.remove(), 4000) después de mostrarlo.
  • Variantes: Success (verde), Error (rojo), Warning (ámbar), Info (azul).

3 · Ejemplo mínimo

Toggle de dark mode mínimo funcional

<!-- HTML mínimo para dark mode -->
<html lang="es">
<head>
  <script src="https://cdn.jsdelivr.net/npm/@tailwindcss/browser@4"></script>
  <style type="text/tailwindcss">
    /* v4 CSS-first: usamos la clase .dark como estrategia de dark mode */
    @custom-variant dark (&:where(.dark, .dark *));
  </style>
  <script>
    /* Aplicar tema guardado antes de que se renderice la página */
    if (localStorage.getItem('theme') === 'dark' ||
        (!localStorage.getItem('theme') && matchMedia('(prefers-color-scheme: dark)').matches)) {
      document.documentElement.classList.add('dark');
    }
  </script>
</head>
<body class="bg-slate-50 dark:bg-slate-950 text-slate-900 dark:text-slate-100 min-h-screen p-8">

  <button id="theme-toggle"
    class="px-4 py-2 bg-white dark:bg-slate-800 border border-slate-200 dark:border-slate-700
           rounded-lg text-sm font-medium shadow-sm
           hover:bg-slate-50 dark:hover:bg-slate-700 transition-colors
           focus:outline-none focus-visible:ring-2 focus-visible:ring-cyan-500">
    <span class="dark:hidden">🌙 Oscuro</span>
    <span class="hidden dark:inline">☀️ Claro</span>
  </button>

  <div class="mt-6 p-6 bg-white dark:bg-slate-900 border border-slate-200 dark:border-slate-800 rounded-xl shadow-sm">
    <h2 class="text-lg font-semibold text-slate-800 dark:text-slate-100">Título de ejemplo</h2>
    <p class="mt-2 text-sm text-slate-600 dark:text-slate-400">
      Este texto cambia de color automáticamente con el tema.
    </p>
  </div>

  <script>
    document.getElementById('theme-toggle').addEventListener('click', () => {
      document.documentElement.classList.toggle('dark');
      localStorage.setItem('theme',
        document.documentElement.classList.contains('dark') ? 'dark' : 'light'
      );
    });
  </script>
</body>
</html>

Analicemos las partes clave:

  • @custom-variant dark en el bloque text/tailwindcss: Le dice a Tailwind v4 que active el prefijo dark: basado en la presencia de class="dark" en un ancestro. Sin esta línea, v4 usa la preferencia del sistema (prefers-color-scheme) por defecto.
  • Script inline en <head>: Lee localStorage y aplica la clase dark ANTES de que el navegador pinte nada. Si lo pones al final del body, hay un flash de tema claro antes de cambiar a oscuro (FOUC — Flash Of Unstyled Content, pero de tema).
  • dark:hidden y hidden dark:inline: El botón muestra "🌙 Oscuro" en tema claro y "☀️ Claro" en tema oscuro. Usando display condicional en lugar de cambiar texto con JS.
  • Doble clase en cada elemento: bg-white dark:bg-slate-900. La primera aplica en tema claro, la segunda sobreescribe en tema oscuro. Es verboso pero explícito y fácil de leer.

<script>
  const profileBtn = document.getElementById('profile-btn');
  const dropdown = document.getElementById('profile-dropdown');
  const chevron = document.getElementById('profile-chevron');

  function toggleDropdown() {
    const isOpen = dropdown.classList.contains('opacity-100');
    if (isOpen) {
      dropdown.classList.remove('opacity-100', 'visible', 'translate-y-0', 'scale-100');
      dropdown.classList.add('opacity-0', 'invisible', 'translate-y-1', 'scale-95');
      chevron.style.transform = 'rotate(0deg)';
      profileBtn.setAttribute('aria-expanded', 'false');
    } else {
      dropdown.classList.remove('opacity-0', 'invisible', 'translate-y-1', 'scale-95');
      dropdown.classList.add('opacity-100', 'visible', 'translate-y-0', 'scale-100');
      chevron.style.transform = 'rotate(180deg)';
      profileBtn.setAttribute('aria-expanded', 'true');
    }
  }

  profileBtn.addEventListener('click', (e) => {
    e.stopPropagation();
    toggleDropdown();
  });

  /* Cerrar al hacer clic fuera */
  document.addEventListener('click', () => {
    if (dropdown.classList.contains('opacity-100')) {
      toggleDropdown();
    }
  });

  /* Cerrar con Escape */
  document.addEventListener('keydown', (e) => {
    if (e.key === 'Escape' && dropdown.classList.contains('opacity-100')) {
      toggleDropdown();
      profileBtn.focus();
    }
  });
</script>

Transiciones compuestas: El dropdown anima opacity, visibility, transform (translate + scale) simultáneamente. invisible + opacity-0 lo oculta visualmente y lo hace no-interactuable. visible + opacity-100 lo revela con fade + slide-down. e.stopPropagation() evita que el clic en el botón cierre inmediatamente el dropdown.

<script>
  function showToast(message, type = 'info') {
    const container = document.getElementById('toast-container');

    const colors = {
      success: 'bg-emerald-50 dark:bg-emerald-950 border-emerald-200 dark:border-emerald-800 text-emerald-800 dark:text-emerald-300',
      error: 'bg-red-50 dark:bg-red-950 border-red-200 dark:border-red-800 text-red-800 dark:text-red-300',

      info: 'bg-blue-50 dark:bg-blue-950 border-blue-200 dark:border-blue-800 text-blue-800 dark:text-blue-300'
    };

    const icons = { success: '✅', error: '❌', warning: '⚠️', info: 'ℹ️' };

    const toast = document.createElement('div');
    toast.className = `pointer-events-auto flex items-center gap-3 px-4 py-3 rounded-xl border shadow-lg
      translate-y-4 opacity-0 transition-all duration-300 ${colors[type]}`;
    toast.innerHTML = `
      <span class="flex-shrink-0">${icons[type]}</span>
      <span class="text-sm font-medium flex-1">${message}</span>
      <button class="flex-shrink-0 text-current opacity-50 hover:opacity-100 transition-opacity ml-2">×</button>
    `;

    container.appendChild(toast);

    /* Animación de entrada */
    requestAnimationFrame(() => {
      toast.classList.remove('translate-y-4', 'opacity-0');
    });

    /* Botón de cierre */
    toast.querySelector('button').addEventListener('click', () => dismissToast(toast));

    /* Auto-dismiss después de 4 segundos */
    setTimeout(() => dismissToast(toast), 4000);
  }

  function dismissToast(toast) {
    toast.classList.add('translate-y-4', 'opacity-0');
    setTimeout(() => toast.remove(), 300);
  }

5 · Buenas prácticas

Haz Evita Por qué
Aplica class="dark" en <html>, no en <body> Poner la clase dark en un contenedor interno — los elementos fixed/portales no la heredan html es el ancestro raíz. Cualquier elemento en el DOM, incluso los añadidos dinámicamente con portales, hereda el tema
Ejecuta el script de tema en <head> (bloqueante) para evitar flash de tema incorrecto Poner el script al final del body — el usuario ve un destello blanco antes de cambiar a oscuro El FOUC (flash of unstyled content) de tema es la peor primera impresión. El script en head se ejecuta antes de pintar
Usa focus-visible:ring en lugar de focus:ring en botones y enlaces focus:ring que deja un anillo azul cada vez que haces clic con el ratón — parece un bug focus-visible solo aplica estilos cuando el navegador detecta navegación por teclado. Ratón = sin anillo
Usa transiciones consistentes de 200-300ms en toda la interfaz (transition-all duration-300) Transiciones de 500ms+ (se sienten lentas) o sin transición (cambios bruscos) 200-300ms es el rango óptimo: lo bastante rápido para sentirse instantáneo, lo bastante lento para percibir el cambio
Proporciona aria-label, role y aria-expanded en componentes interactivos Confiar solo en el texto visual — los lectores de pantalla no entienden íconos ni estados implícitos Los atributos ARIA traducen la interfaz visual a una experiencia navegable para tecnologías asistivas
Elimina sombras en dark mode y sustitúyelas por ring-1 ring-slate-800 Dejar shadow-sm o shadow-md en dark mode — no se ven sobre fondo oscuro Las sombras dependen de contraste con el fondo. Sobre slate-950, una sombra es invisible. Un borde sutil (ring) cumple la misma función

6 · Errores habituales

Al recargar la página en dark mode, hay un flash blanco

El script que aplica el tema está en el <body> o al final del HTML, después de que el navegador ya ha pintado la página con el tema claro (por defecto). El usuario ve blanco durante ~100ms y luego oscuro. Solución: mueve el script de tema al <head>, antes de cualquier elemento visible. Usa document.documentElement.classList.add('dark') — sin esperar a DOMContentLoaded.

El dropdown de perfil se abre pero no se cierra al hacer clic fuera

El click listener en document no existe o el stopPropagation en el botón está mal colocado. El patrón correcto: (1) botón tiene e.stopPropagation() para que el clic en él no llegue al document, (2) document tiene un listener que cierra el dropdown si está abierto. Si olvidas stopPropagation, el clic en el botón abre el dropdown e inmediatamente el listener del document lo cierra.

Los toasts se acumulan y nunca desaparecen

Olvidaste el setTimeout que llama a dismissToast después de X segundos. O el setTimeout se cancela porque el toast se eliminó antes (error de referencia). Solución: guarda el ID del timer en una propiedad del elemento toast (toast._timer = setTimeout(...)) y limpia con clearTimeout si el usuario cierra manualmente el toast antes de que expire.

Los textos en dark mode tienen poco contraste y cuesta leerlos

Usaste dark:text-slate-400 para texto principal. Slate-400 (#94a3b8) sobre slate-900 (#0f172a) tiene un ratio de contraste de ~4.5:1 — justo en el límite WCAG AA. Para texto principal, usa dark:text-slate-100 o dark:text-slate-200. Slate-400 es aceptable para texto secundario o etiquetas. Verifica siempre el contraste con las DevTools (pestaña Accessibility).

Paso 2: JavaScript con animación de rotación

const themeToggle = document.getElementById('theme-toggle');
const sunIcon = document.getElementById('sun-icon');
const moonIcon = document.getElementById('moon-icon');

themeToggle.addEventListener('click', () => {
  /* Rotar ambos iconos durante la transición */
  sunIcon.style.transform = 'rotate(360deg)';
  moonIcon.style.transform = 'rotate(-360deg)';

  /* Cambiar tema */
  const isDark = document.documentElement.classList.toggle('dark');
  localStorage.setItem('theme', isDark ? 'dark' : 'light');
  themeToggle.setAttribute('aria-label', isDark ? 'Cambiar a tema claro' : 'Cambiar a tema oscuro');

  /* Resetear la rotación después de la animación */
  setTimeout(() => {
    sunIcon.style.transform = '';
    moonIcon.style.transform = '';
  }, 500);
});

La combinación de transition-transform duration-500 en CSS y style.transform en JS produce una animación fluida: el icono rota 360 grados mientras Tailwind intercambia los SVGs visibles (dark:block / dark:hidden). El resultado es un toggle que gira elegantemente al cambiar de tema.

9 · Resumen

  • Dark mode con selector: en v4 se define con @custom-variant dark (&:where(.dark, .dark *)) en el CSS y class="dark" en <html>. Script en <head> para evitar flash. Preferencia guardada en localStorage. Cada elemento tiene bg-white dark:bg-slate-900.
  • Mobile-first responsive: Sidebar overlay en móvil → fixed en lg. Tabla → cards en sm. Grid métricas: 1 → 2 → 4 columnas. Buscador y breadcrumb ocultos hasta sm.
  • Dropdown de perfil: absolute right-0 top-full mt-2. Animación con opacity + translate-y + scale. Cierre con clic fuera (document listener) y tecla Escape. aria-expanded y role="menu".
  • Sistema de toasts: Contenedor fixed bottom-4 right-4. Tipos: success, error, warning, info. Entrada con translate-y-4 opacity-0 → animado. Auto-dismiss a los 4s. Botón de cierre manual.
  • Accesibilidad: focus-visible: en lugar de focus:. Roles ARIA (navigation, menu, menuitem). aria-label, aria-expanded, aria-current. sr-only para textos solo de screen reader.
  • Transiciones consistentes: transition-all duration-300 en sidebar, dropdown, toasts, hover de filas. La interfaz se siente viva y responsiva, no estática.
  • Dashboard completo: 5 lecciones, ~1000 líneas de código. Layout grid + sidebar colapsable + métricas con gráficos + tabla responsive con paginación + widgets + dark mode + accesibilidad. Solo faltan los datos reales del backend.

10 · Preguntas frecuentes

¿Cómo integro este dashboard con React o Vue?

El 90% del trabajo es idéntico: las clases de Tailwind no cambian entre vanilla JS y frameworks. La diferencia está en cómo manejas el estado. El colapso de sidebar pasa de classList.toggle a useState en React o ref en Vue. El dark mode pasa de classList.toggle('dark') a un provider de tema. Los datos de la tabla pasan de HTML estático a un .map() sobre un array. El CSS y las clases de Tailwind son las mismas. El Módulo 8 cubre esta integración en detalle.

¿Cómo despliego este dashboard en producción?

Si es HTML + Tailwind CDN: simplemente sube los archivos a cualquier servidor estático (Vercel, Netlify, GitHub Pages). Si usas Vite + Tailwind (recomendado para producción): pnpm build genera una carpeta dist/ con HTML, CSS y JS optimizados (purged, minificados, con hashes para cache-busting). El CDN de Tailwind no es adecuado para producción (pesa ~3MB sin purgar). Usa siempre el build de Vite para producción.

¿Cómo añado animaciones de entrada a las tarjetas (fade-in al hacer scroll)?

Usa Intersection Observer: cuando una tarjeta entra en el viewport, le añades una clase que activa la animación. Ejemplo: opacity-0 translate-y-4 transition-all duration-500 por defecto, y al intersectar cambias a opacity-100 translate-y-0. Puedes escalonar las animaciones con un delay incremental (style="transition-delay: ${i * 100}ms") para un efecto cascade. Tailwind no incluye esto nativo — necesitas JS o una librería como AOS.

¿El rendimiento se resiente con tantas clases de Tailwind?

En desarrollo con CDN: sí, hay un pequeño coste de parseo. En producción con build: no. Tailwind genera una hoja de CSS estática con solo las clases usadas (purging). El HTML tiene más bytes por las clases, pero con compresión gzip/brotli la diferencia es mínima (~5-10KB extra). El navegador aplica clases CSS de forma nativa y extremadamente rápida. El verdadero cuello de botella en dashboards rara vez es el CSS — suele ser JavaScript mal optimizado o demasiadas llamadas a API.

¿Qué sigue después de este módulo?

Este es el módulo final del curso. Has construido un dashboard profesional completo desde cero usando Tailwind CSS. El siguiente paso natural es: (1) Conectar este dashboard a un backend real (REST API o GraphQL) para que los datos sean dinámicos, (2) Migrarlo a React/Vue si tu stack lo requiere, (3) Añadir autenticación real, (4) Escribir tests end-to-end con Playwright o Cypress, (5) Iterar sobre el diseño basándote en feedback de usuarios reales. El curso te ha dado las bases de CSS y Tailwind — el resto es práctica deliberada.
