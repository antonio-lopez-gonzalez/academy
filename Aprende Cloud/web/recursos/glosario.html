Glosario de términos

Referencia 📖 Términos clave de cloud (Azure / AWS)

A

ACR / ECR
Azure Container Registry y Elastic Container Registry: los registros de imágenes de contenedor gestionados de cada proveedor. Guardan la imagen por etiqueta y por digest; el digest es lo que permite desplegar de forma verificable. Se autentican con identidad, no con usuario y contraseña en el repo (Módulo 1).
Alta disponibilidad (HA)
Diseño que mantiene el servicio en pie aunque falle una pieza: varias réplicas repartidas por zonas, balanceador y health checks. No elimina los fallos, los hace transparentes para el usuario. Se mide como «nueves» (99,9 % ≈ 8,7 h de parada al año).
Autoescalado (autoscaling)
Ajustar el número de instancias a la carga según una regla (CPU, peticiones por segundo, longitud de la cola). Escalar horizontalmente (más instancias) es lo natural en cloud; se apaga cuando baja la demanda, y ahí está el ahorro (Módulo 4).
Availability zone → zona de disponibilidad
Sinónimo inglés de zona de disponibilidad.

B

Backend remoto (Terraform state)
Dónde vive el archivo de estado de Terraform. Debe estar fuera del equipo y del repositorio, con bloqueo, para que todo el equipo y el pipeline partan de la misma memoria. En Azure suele ser un Storage Account; en AWS, un bucket S3.
Blob / S3
El almacenamiento de objetos de cada proveedor: Azure Blob Storage y Amazon S3. Ideal para archivos, copias, imágenes y estáticos. Tiene «clases» de acceso (caliente/FRÍO/archivo) cuyo precio y latencia cambian (Módulo 3).

C

Capa gratuita (free tier)
Cuota mensual de recursos gratis o con descuento que ofrecen Azure y AWS a cuentas nuevas (y algunas siempre). Perfecta para practicar; trampa clásica: consumirla sin darte cuenta y seguir facturando el exceso (Módulo 0).
Cold start
La primera invocación de una función serverless tras un rato inactiva: el proveedor tiene que arrancar un entorno y ese arranque añade latencia (decenas o cientos de milisegundos). No es un error; es una característica que se mitiga con provisioned concurrency o manteniendo el servicio caliente (Módulo 1).
Contenedor gestionado
Servicio que ejecuta tu imagen sin que tú operes el clúster: Azure Container Apps o AWS App Runner. Es el punto medio entre «una VM» y «un Kubernetes a tu cargo» (Módulo 4).
Cómputo (espectro de)
El abanico de formas de ejecutar código en cloud, de más control a menos: VM → contenedor → contenedor gestionado → serverless. Cuanto menos gestionas tú, menos operas y más pagas por unidad de uso. Elegir es decidir qué quieres operar (Módulo 1).
Cumplimiento (compliance)
Conjunto de normas (RGPD, SOC 2, HIPAA…) que condicionan dónde pueden estar los datos y quién puede verlos. Es uno de los criterios para elegir región, por delante incluso del precio (Módulo 0).

D

Digest (de imagen)
Hash sha256:… que identifica el contenido de una imagen de forma inequívoca e inmutable. A diferencia de una etiqueta (latest), no se mueve: desplegar por digest garantiza que lo que corre es exactamente lo que se probó (Módulo 1).
DR (recuperación ante desastres)
Disaster Recovery: plan para volver a funcionar tras la caída de una región entera. Se define con dos números (RTO y RPO), se ensaya y casi siempre implica replicar datos a otra región. Tener backups no es tener DR.
Drift (deriva)
Diferencia entre lo que declara tu infraestructura como código y lo que de verdad existe (alguien cambió algo a mano en el portal). terraform plan es lo que la saca a la luz; corregirla es volver a aplicar el estado declarado.

E

Egress (tráfico de salida)
Los datos que salen de la nube hacia internet u otra región. Entrar suele ser gratis; salir, no: se cobra por GB y es el coste que más sorprende. Mantener juntas las piezas que se hablan mucho es la mejor defensa (Módulo 0).
Entra ID
El servicio de identidad de Azure (antes Azure Active Directory). Guarda usuarios, grupos y aplicaciones, y es contra quien se autentican los recursos. Su equivalente conceptual en AWS es IAM / IAM Identity Center (Módulo 2).
Etiqueta (tag)
Par clave/valor (env=dev, owner=antonio) pegado a un recurso. No cambia su funcionamiento; cambia tu capacidad de entenderlo: qué gasta cada entorno, qué no tiene dueño, qué se puede apagar. Es la base del control de coste (Módulo 0).

G

Grupo de recursos (resource group)
Contenedor lógico de Azure que agrupa recursos con el mismo ciclo de vida, permisos y etiquetas. Borrar el grupo borra todo lo que contiene. AWS no tiene un equivalente exacto: la organización se hace por cuenta y etiquetas (Módulo 0).

I

IaaS / PaaS / SaaS
Tres formas de consumir cloud según cuánto gestionas tú. IaaS: te dan la máquina (VMs) y tú pones todo lo de arriba. PaaS: te dan la plataforma (base de datos, app service) y tú solo el código. SaaS: consumes la aplicación ya hecha (Módulo 0).
IAM
Identity and Access Management: quién (identidad) puede hacer qué (permisos) sobre qué (recurso). La regla que rige todo el curso es el mínimo privilegio: cada identidad, solo lo que necesita (Módulo 2).
Identidad gestionada (managed identity)
Identidad que el proveedor crea y rota por ti, asociada a un recurso (una Container App, una VM, una función). Permite que el recurso acceda a Key Vault o a una base sin contraseñas en el código. En AWS el patrón equivalente es un IAM Role adjunto al recurso (Módulo 2).
Imagen (de contenedor)
Empaquetado inmutable de una aplicación con sus dependencias. Se construye una vez y se despliega igual en todos los entornos: lo que se prueba es lo que se despliega (Módulo 1).
Infraestructura como código (IaC)
Declarar la infraestructura en archivos versionados (HCL con Terraform) en vez de crearla a clics. Aporta revisión por PR, reproducibilidad, detección de deriva y la posibilidad de reconstruir un entorno idéntico.

K

Key Vault / Secrets Manager
La bóveda de secretos de cada proveedor: contraseñas, cadenas de conexión, claves de API. Se consultan en tiempo de ejecución con una identidad gestionada; nunca se copian al repositorio ni a la imagen (Módulo 2).

L

Latencia
El tiempo que tarda un dato en ir y volver. La impone la física (unos 5 ms por 1.000 km en fibra) y la región que elijas. Un dato que cruza el océano añade milisegundos y euros (Módulo 0).

M

Mínimo privilegio
Principio de dar a cada identidad únicamente los permisos que necesita, y nada más. Un permiso de más es una llave de más en manos de un atacante o de un bug (Módulo 2).
Multi-región
Desplegar en más de una región para servir usuarios de varios continentes o sobrevivir a la caída de una región. Sube la disponibilidad y el coste: úsalo cuando el requisito lo justifique (Módulo 0).

N

NAT Gateway
Salida a internet para recursos en una subred privada: les da conectividad de salida sin exponerlos a conexiones entrantes. Es el patrón por defecto del curso: red privada, salida controlada (Módulo 1).
NSG (Network Security Group)
Cortafuegos por subred o interfaz en Azure: reglas que permiten o deniegan tráfico por puerto y origen. En AWS el rol lo cumplen los Security Groups (por instancia) y las NACL (por subred) (Módulo 1).

O

Observabilidad
Capacidad de responder «¿qué está pasando?» con evidencia: métricas, logs y trazas. Sin ella, un despliegue es a ciegas y un rollback, adivinar. Azure Monitor y CloudWatch son las plataformas base.
OIDC (OpenID Connect)
Mecanismo por el que tu CI/CD demuestra su identidad al proveedor y recibe credenciales temporales, sin guardar ninguna clave de larga vida. Es la forma correcta de desplegar desde GitHub Actions (Módulo 2).

P

PaaS (Platform as a Service)
Modelo en el que el proveedor gestiona el sistema operativo, el escalado y el parcheo, y tú aportas la aplicación. Una base de datos gestionada o un App Service son PaaS: ganas velocidad y pierdes algo de control (Módulo 0).
Private Endpoint / Private Link
Acceso a un servicio PaaS (una base de datos, un Key Vault) por la red privada, sin pasar por internet. Elimina la exposición pública del servicio. En AWS el equivalente es un VPC Endpoint (Módulo 2).
Presupuesto (budget)
Límite de gasto con alertas asociadas. No corta el servicio por sí solo (salvo que lo configures), pero avisa antes de la factura: es el cinturón de seguridad del coste (Módulo 0).
Provider (Terraform)
El plugin que sabe hablar con la API de un proveedor: azurerm, aws, kubernetes. Se declara en required_providers con su versión y se descarga en terraform init.
Punto de servicio (service endpoint)
Ruta más sencilla que Private Link para llegar a un PaaS desde una VNet: se habilita el servicio en la subred y el tráfico sigue por la red troncal de Azure, aunque el servicio conserva su dirección pública (Módulo 2).

R

Región
Una zona geográfica con uno o varios centros de datos (westeurope, eu-west-1). Elegir región es elegir latencia, cumplimiento, disponibilidad de servicios y precio. Los recursos que se hablan mucho entre sí deben vivir en la misma región (Módulo 0).
Región emparejada (region pair)
Par de regiones que Azure (y AWS, con las regions correspondientes) empareja para replicación y recuperación: la distancia y los planes de actualización están coordinados, así que un desastre no afecta a ambas a la vez (Módulo 0).
Registro (registry)
Almacén de imágenes de contenedor. ACR en Azure, ECR en AWS, GHCR en GitHub. Guarda por etiqueta y por digest.
RTO / RPO
Las dos cifras que definen un plan de DR. RTO (Recovery Time Objective): cuánto tiempo puedes estar caído. RPO (Recovery Point Objective): cuántos datos puedes permitirte perder (es decir, cada cuánto haces backup). Se deciden antes, no durante el incidente.

S

SaaS (Software as a Service)
Software ya operado que consumes tal cual (correo, CRM, tu propio Copiloto si lo ofreces así). Tú no gestionas ni el código ni la infraestructura: solo el uso (Módulo 0).
Secretos
Valores sensibles (contraseñas, cadenas de conexión, claves). Viven en una bóveda (Key Vault / Secrets Manager), se leen con identidad gestionada y nunca aparecen en el repositorio, en la imagen ni en un log (Módulo 2).
Serverless
Modelo en el que el proveedor gestiona toda la infraestructura y pagas por uso (por invocación y por tiempo de ejecución), escalando a cero cuando no hay tráfico. Ideal para cargas intermitentes; a cambio, hay cold start y límites de tiempo (Módulo 1).
SKU
La «talla» o nivel de un recurso (Basic, Standard, Premium). Cambia prestaciones, límites de SLA y precio. Elegir la SKU correcta es parte del control de coste (Módulo 1).
SLA
Service Level Agreement: el compromiso de disponibilidad que el proveedor firma (99,9 %, 99,95 %…). Si no lo cumple, hay compensación; si tu arquitectura depende de un servicio sin SLA, el problema es tuyo.
Subred (subnet)
Segmento de una VNet/VPC con su propio rango de direcciones y sus reglas de firewall. Segmentar (pública, privada, datos) es la primera medida de seguridad de red (Módulo 1).

T

Tenant
La instancia de directorio de una organización en Azure (o el espacio de identidad en AWS). Bajo un tenant cuelgan suscripciones, y bajo las suscripciones, los grupos de recursos (Módulo 0).
Terraform / OpenTofu
Herramientas de IaC declarativa: describes el estado deseado en HCL y calculan el diff (plan) y lo aplican (apply). Su memoria es el estado. OpenTofu es el fork abierto, compatible con la misma sintaxis y providers.
Tráfico de salida → egress
Los datos que salen de la nube, y el coste que más sorprende.

V

VNet / VPC
La red virtual privada donde viven tus recursos: Virtual Network en Azure, Virtual Private Cloud en AWS. Dentro se definen subredes, rutas y cortafuegos; fuera, internet. Es el plano sobre el que se apoya todo lo demás (Módulo 1).

Z

Zona de disponibilidad (availability zone)
Uno o varios centros de datos independientes dentro de una región: comparten ubicación geográfica pero tienen energía, refrigeración y red separadas. Repartir réplicas entre zonas es lo que protege de la caída de un edificio (Módulo 0).
