CLI de Azure (az)

La CLI de Azure es la vía como código para explorar y automatizar. Antes de nada, identifícate y fija el contexto: suscripción, grupo por defecto y región. Todo lo que crees pasa por un resource group, la unidad de organización, permisos y coste.

# --- sesión y contexto ---
az login                              # login interactivo (navegador o device code)
az account show                       # suscripción activa y tenant
az account list --output table        # todas las suscripciones a las que tienes acceso
az account set --subscription "Produccion"
az configure --defaults location=westeurope group=copiloto-rg   # menos flags repetidos

# --- resource groups: la unidad de coste y ciclo de vida ---
az group create --name copiloto-rg --location westeurope \
  --tags env=dev owner=antonio project=copiloto
az group list --output table

# --- registro de imágenes (ACR) ---
az acr create --name copilotoregistry --resource-group copiloto-rg --sku Basic
az acr login --name copilotoregistry
az acr build --registry copilotoregistry --image copiloto-api:v1 .   # build dentro de Azure

# --- contenedores gestionados (Container Apps) ---
az containerapp env create --name copiloto-env --resource-group copiloto-rg --location westeurope
az containerapp up --name copiloto-api --resource-group copiloto-rg \
  --environment copiloto-env \
  --image copilotoregistry.azurecr.io/copiloto-api:v1 --target-port 8000
az containerapp show --name copiloto-api --resource-group copiloto-rg \
  --query properties.configuration.ingress.fqdn

# --- secretos (Key Vault) ---
az keyvault create --name copiloto-kv --resource-group copiloto-rg --location westeurope
az keyvault secret set --vault-name copiloto-kv --name database-url --value "postgres://..."
az keyvault secret show --vault-name copiloto-kv --name database-url --query value

# --- Kubernetes gestionado (AKS) ---
az aks create --resource-group copiloto-rg --name copiloto-aks \
  --node-count 1 --enable-managed-identity
az aks get-credentials --resource-group copiloto-rg --name copiloto-aks

# --- coste y diagnóstico ---
az consumption usage list --top 10 --output table
az monitor activity-log list --max-events 20
az resource list --resource-group copiloto-rg --output table

Usa --output table y --query. Sin --output, az devuelve JSON enorme; para leer en la terminal, table. Y --query (sintaxis JMESPath) extrae un solo campo sin tuberías: --query properties.configuration.ingress.fqdn -o tsv.

CLI de AWS (aws)

La CLI de AWS se configura con credenciales y una región. La primera comprobación siempre es la misma: ¿quién soy y con qué permisos? Es la versión de línea de comandos de az account show.

# --- sesión y contexto ---
aws configure                         # access key, secret y región por defecto
aws sts get-caller-identity           # ¿qué cuenta y qué rol estoy usando?
aws configure set region eu-west-1    # fija la región activa
aws ec2 describe-regions --output table
aws s3 ls                             # prueba rápida de credenciales y permisos

# --- registro de imágenes (ECR) ---
aws ecr create-repository --repository-name copiloto-api
aws ecr get-login-password --region eu-west-1 \
  | docker login --username AWS --password-stdin <cuenta>.dkr.ecr.eu-west-1.amazonaws.com
docker push <cuenta>.dkr.ecr.eu-west-1.amazonaws.com/copiloto-api:v1

# --- contenedores gestionados (App Runner / ECS) ---
aws apprunner create-service --service-name copiloto-api --source-configuration file://apprunner.json
aws ecs list-clusters
aws ecs describe-services --cluster copiloto --services copiloto-api

# --- secretos (Secrets Manager) ---
aws secretsmanager create-secret --name copiloto/database-url --secret-string "postgres://..."
aws secretsmanager get-secret-value --secret-id copiloto/database-url \
  --query SecretString --output text

# --- Kubernetes gestionado (EKS) ---
aws eks update-kubeconfig --name copiloto-eks --region eu-west-1

# --- coste y diagnóstico ---
aws ce get-cost-and-usage \
  --time-period Start=2026-10-01,End=2026-11-01 --granularity MONTHLY \
  --metrics UnblendedCost --group-by Type=DIMENSION,Key=SERVICE
aws logs tail /aws/containerinsights/copiloto/application --follow
aws cloudwatch describe-alarms --output table

Nunca escribas las access keys en un archivo del repositorio. aws configure las guarda en ~/.aws/credentials. En CI/CD no se usan claves de larga vida: se configura OIDC y se asume un rol temporal (Módulo 2).

Terraform / OpenTofu

La infraestructura se declara en HCL y se aplica en ciclos plan → revisar → apply. El estado es la memoria de Terraform: guárdalo en un backend remoto, nunca en el portátil ni en el repositorio.

ComandoQué hace
terraform initDescarga providers y prepara el backend remoto
terraform fmt -checkComprueba el formato (falla si hay que reformatear)
terraform validateValida sintaxis y referencias sin tocar la infraestructura
terraform plan -out=tfplanCalcula el diff y lo guarda en un archivo revisable
terraform apply tfplanAplica exactamente el plan aprobado
terraform state listLista los recursos que gestiona el estado
terraform output -jsonExporta salidas (URLs, IDs) para el pipeline
terraform import <dir>.<nombre> <id>Adopta un recurso creado a mano
terraform destroyElimina lo gestionado (con pinzas: mira el plan primero)
infra/main.tf — esqueleto mínimo (Azure)
terraform {
  required_version = ">= 1.6"

  required_providers {
    azurerm = {
      source  = "hashicorp/azurerm"
      version = "~> 4.0"
    }
  }

  # Estado remoto: nunca local. En Azure, un Storage Account.
  backend "azurerm" {
    resource_group_name  = "tfstate-rg"
    storage_account_name = "copilototfstate"
    container_name       = "tfstate"
    key                  = "prod/terraform.tfstate"
  }
}

provider "azurerm" {
  features {}
}

variable "environment" {
  type        = string
  description = "dev, staging o prod"
}

variable "location" {
  type    = string
  default = "westeurope"
}

# El recurso más pequeño: un grupo de recursos etiquetado.
resource "azurerm_resource_group" "main" {
  name     = "copiloto-${var.environment}-rg"
  location = var.location

  tags = {
    env     = var.environment
    project = "copiloto"
    owner   = "acme"
  }
}

output "resource_group_name" {
  value = azurerm_resource_group.main.name
}

Plan y apply, el mismo artefacto. Genera tfplan en el job de plan, guárdalo como artifact y ejecútalo tal cual tras la aprobación. Un apply que recalcula el plan puede aplicar algo distinto de lo revisado (Módulo 7).

De concepto a comando, de un vistazo

Cuatro tareas que se repiten todo el curso, y cómo se hacen en cada herramienta.

Quieres…AzureAWS
Comprobar quién soyaz account showaws sts get-caller-identity
Autenticar el registryaz acr login --name Xaws ecr get-login-password | docker login …
Leer un secretoaz keyvault secret showaws secretsmanager get-secret-value
Ver el gastoaz consumption usage listaws ce get-cost-and-usage
Identificarse con Terraformaz login + provider azurermaws configure + provider aws

Las CLI az, aws y terraform son multiplataforma (Linux, macOS y Windows). La sintaxis de los comandos no cambia; en PowerShell, sustituye la tubería | de bash por su equivalente o ejecuta los ejemplos en bash (WSL, Git Bash).

¿Por qué una chuleta y no la consola web? Porque el curso hace todo como código: reproducible, revisable en un PR y automatizable. El portal sirve para explorar, no para construir. Si te descubres haciendo clics para crear algo, párate y escríbelo en Terraform (Módulo 7).
