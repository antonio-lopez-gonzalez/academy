Expresiones en JSX

Módulo 1 · Fundamentos ⏱ 25 minutos

1 · Introducción

Las llaves { } de JSX son el «portal» entre el mundo declarativo del marcado y todo el poder de JavaScript. Parecen triviales, pero tienen reglas precisas: qué puedes meter dentro, qué no, y qué se pinta exactamente de cada tipo de valor.

Dominar esta lección es dominar la mitad de los errores de principiante: el temido «Objects are not valid as a React child», los undefined que no se ven, los false que no se pintan… Todo tiene explicación y la vamos a ver.

2 · Teoría

Regla fundamental: dentro de {} solo caben EXPRESIONES

Una expresión es cualquier fragmento de código que produce un valor. Un statement (declaración) es una instrucción que hace algo pero no produce un valor directamente usable.

Expresiones (✔ valen en JSX)Statements (✘ NO valen en JSX)
nombre (variable)if (x) { … }
2 + 2for (…), while (…)
user.nameconst x = 5
edad >= 18 ? "adulto" : "menor" (ternario: SÍ produce valor)switch (…)
items.map(i => …) (llamada a función)function f() {…} (declaración)
isAdmin && <Boton /> (cortocircuito)import … / export …
formatPrice(total) (llamada)try { } catch { }
💡 ¿Por qué esta limitación?

Porque JSX compila a argumentos de una función: <p>{ AQUÍ }</p> se convierte en jsx("p", { children: AQUÍ }). Y en la posición de un argumento solo caben expresiones — igual que no puedes escribir console.log(if (x) …). No es una restricción arbitraria de React: es cómo funciona JavaScript. Por eso existen el ternario (el «if» que produce valor) y map (el «for» que produce un array).

Qué se pinta de cada tipo de valor

La segunda regla: no todo lo que evalúas se renderiza. La tabla exacta:

Valor en las llaves¿Se pinta?Ejemplo
string✔ tal cual (¡escapado contra XSS!){"Hola"} → Hola
number✔ (incluido el 0){0} → 0
elemento JSX✔{<strong>Hola</strong>}
array de los anteriores✔ (los pinta en orden){["a", "b"]} → ab
null, undefined, true, false✘ se ignoran (pinta NADA){false} → (vacío)
objeto plano { }💥 ERROR{{a:1}} → «Objects are not valid as a React child»
función sin ejecutar💥 ERROR (React 19 lo avisa){miFuncion} en vez de {miFuncion()}
BigInt💥 ERROR{10n}
🛡 Seguridad gratuita: JSX escapa el HTML

Si un string contiene HTML ({"<script>alert('xss')</script>"}), React lo pinta como texto, no lo ejecuta. Es protección anti-XSS incorporada por diseño. (Existe una escotilla, dangerouslySetInnerHTML, que no debes usar con contenido de usuarios; la nombramos para que la reconozcas.)

Las expresiones que usarás el 95 % del tiempo

  1. Variables y acceso a propiedades: {user.name}
  2. Ternario para condicionales: {isVip ? "⭐ VIP" : "Estándar"}
  3. Cortocircuito && para «mostrar u ocultar»: {error && <p>{error}</p>}
  4. map para listas: {tasks.map(t => <li>{t.title}</li>)} (Módulo 2)
  5. Operador ?? para valores por defecto: {user.bio ?? "Sin biografía"}
  6. Llamadas a funciones de formato: {formatDate(post.date)}

?? vs ||: ?? solo usa el valor por defecto con null/undefined; || también con 0, "" y false. Para números que pueden ser 0, usa SIEMPRE ??.

3 · Ejemplo mínimo

src/App.jsx
export default function App() {
  const name = "Ada";
  const age = 36;
  const hobbies = ["matemáticas", "programación"];
  const mentor = null; // sin mentor asignado

  return (
    <div>
      <p>Nombre: {name}</p>
      <p>El año que viene: {age + 1} años</p>
      <p>Mayoría de edad: {age >= 18 ? "sí" : "no"}</p>
      <p>Hobbies: {hobbies.join(", ")}</p>
      <p>Mentor: {mentor ?? "aún sin asignar"}</p>
    </div>
  );
}

Línea por línea:

  1. {name} — la expresión más simple: una variable. Pinta «Ada».
  2. {age + 1} — cualquier cálculo vale: se evalúa y pinta 37.
  3. {age >= 18 ? "sí" : "no"} — el ternario es el «if» de las expresiones.
  4. {hobbies.join(", ")} — llamada a método: devuelve un string. (Renderizar el array directo también funciona, pero sin separador bonito.)
  5. {mentor ?? "aún sin asignar"} — null no se pinta; con ?? mostramos un fallback elegante.

4 · Ejemplo real

Una ficha de producto con precio formateado, descuento y stock condicional:

src/components/ProductCard.jsx
export default function ProductCard() {
  const product = {
    name: "Teclado mecánico K87",
    price: 89.9,
    discount: 0.15,        // 15 % de descuento
    stock: 3,
    currency: "EUR",
  };

  // Lógica de negocio FUERA del JSX (buena práctica de la lección 1)
  const finalPrice = product.price * (1 - product.discount);

  // Función de formato: reutilizable y testeable
  const formatPrice = (value) =>
    value.toLocaleString("es-ES", { style: "currency", currency: product.currency });

  return (
    <article className="product-card">
      <h2>{product.name}</h2>

      <p>
        {/* Ternario: con descuento muestra precio original tachado */}
        {product.discount > 0 ? (
          <>
            <del>{formatPrice(product.price)}</del>{" "}
            <strong>{formatPrice(finalPrice)}</strong>
          </>
        ) : (
          <strong>{formatPrice(product.price)}</strong>
        )}
      </p>

      {/* Cortocircuito: el aviso solo existe si hay poco stock */}
      {product.stock < 5 && (
        <p className="warning">¡Solo quedan {product.stock} unidades!</p>
      )}
    </article>
  );
}

Decisiones explicadas:

  • toLocaleString("es-ES", …) — formateo de moneda profesional: nunca concatenes price + " €" (¿y los decimales? ¿y el formato americano vs europeo?).
  • El ternario devuelve un Fragment con dos elementos cuando hay descuento — las expresiones pueden ser tan grandes como necesites, pero si crecen, mejor extraerlas a una variable antes del return.
  • {" "} — truco: JSX colapsa los espacios entre líneas; esta expresión fuerza un espacio visible entre <del> y <strong>.
  • El cortocircuito && es seguro aquí porque la condición es un booleano puro (stock < 5). Cuidado: {product.stock && …} pintaría un «0» si stock fuera 0 — el error clásico que veremos en la sección 6.

6 · Errores habituales

Error 1: «Objects are not valid as a React child»

✘ Incorrecto 
const user = { name: "Ana", age: 28 };
return <p>{user}</p>;   // 💥 React no sabe cómo pintar un objeto
✔ Correcto 
return <p>{user.name}</p>;              // pinta una propiedad
// o para depurar:
return <pre>{JSON.stringify(user, null, 2)}</pre>;

Error 2: el 0 fantasma

✘ Incorrecto 
{messages.length && <Badge>{messages.length}</Badge>}
// Si no hay mensajes: length = 0 → JavaScript evalúa 0 && … = 0
// …y React PINTA el 0 en pantalla 👻
✔ Correcto 
{messages.length > 0 && <Badge>{messages.length}</Badge>}
// La condición es booleana: false no se pinta. Problema resuelto.

Regla de oro: a la izquierda de && en JSX, siempre un booleano.

Error 3: if dentro de las llaves

✘ Incorrecto 
<p>{if (isAdmin) { return "Admin" }}</p>  // 💥 if es un statement
✔ Correcto 
<p>{isAdmin ? "Admin" : "Usuario"}</p>    // ternario = if que devuelve valor

// o mejor, antes del return:
const roleLabel = isAdmin ? "Admin" : "Usuario";
// y en el JSX: <p>{roleLabel}</p>

7 · Ejercicio guiado

Ficha de película con todas las expresiones aprendidas:

  1. Datos: const movie = { title: "Dune", year: 2021, rating: 8.0, genres: ["Sci-Fi", "Aventura"], director: null }

  2. Muestra el título en <h2> y el año calculado: «hace X años» usando {new Date().getFullYear() - movie.year}.

  3. Clasifica con ternario: rating ≥ 8 → «⭐ Imprescindible», ≥ 6 → «Recomendable», si no → «Prescindible». (Un ternario anidado corto, o mejor: calcula verdict antes del return.)

  4. Géneros con {movie.genres.join(" · ")}.

  5. Director: {movie.director ?? "Director desconocido"}.

  6. Sello de estreno reciente: {new Date().getFullYear() - movie.year <= 2 && <span>🆕 Estreno</span>} — comprueba que con year: 2021 no aparece y con el año actual sí.

8 · Reto

🎯 El resumen del pedido

Construye un componente OrderSummary con estos datos:

const order = {
  items: [
    { name: "Ratón", price: 25.99, qty: 1 },
    { name: "Teclado", price: 89.9, qty: 2 },
  ],
  coupon: "REACT19", // o null
};
  1. Calcula el subtotal sumando price * qty de cada item (pista: reduce).
  2. Si hay cupón, aplica 10 % de descuento y muestra «Cupón aplicado: REACT19» con cortocircuito.
  3. Muestra el total formateado en euros con toLocaleString.
  4. Si el total supera 100 €, muestra «🚚 Envío gratis»; si no, muestra cuánto falta para conseguirlo.

Toda la lógica de cálculo, fuera del JSX. Solo expresiones finales dentro.

9 · Resumen

  • En { } solo caben expresiones (producen valor): variables, ternarios, llamadas, map, &&, ??.
  • Los statements (if, for, const) van FUERA, antes del return.
  • Se pintan: strings, números, elementos y arrays de ellos. No se pintan: null, undefined, booleanos. Error: objetos planos, funciones sin llamar, BigInt.
  • El ternario es tu if; && tu «mostrar si»; map tu bucle.
  • A la izquierda de &&, siempre booleanos (cuidado con el 0 fantasma).
  • JSX escapa el HTML de los strings: protección anti-XSS por diseño.

10 · Preguntas frecuentes

¿Puedo anidar llaves dentro de llaves?

No directamente, pero no lo necesitas: dentro de una expresión puedes usar otra expresión JSX: {items.map(i => <li>{i.name}</li>)}. Las llaves «se reinician» en cada frontera JSX↔JS.

¿Cómo pinto un salto de línea de un string ("Hola\nMundo")?

HTML colapsa los saltos de línea. Opciones: dividir en elementos, usar <br /> construyendo un array, o CSS white-space: pre-line sobre el contenedor (la más limpia para textos largos de usuario).

¿Y si necesito un switch de verdad con muchos casos?

Fuera del JSX: una función renderStatus(status) con el switch y returns de JSX, y en el marcado {renderStatus(order.status)}. Es el patrón estándar cuando el ternario se queda corto.

¿Por qué {JSON.stringify(obj)} a veces es mala idea?

Para depurar está bien, pero en producción expone datos internos, puede ser enorme y falla con referencias circulares. Úsalo solo en desarrollo y quítalo antes de desplegar.

¿Los emojis en JSX son seguros?

Sí: son texto Unicode normal. Mejor en strings ({"⭐"} o directamente en el marcado) y con role="img" aria-label si transmiten significado (accesibilidad).
