🛠 Proyecto: página de perfil

Proyecto del Módulo 1 ⏱ 45 minutos

1 · Introducción

Primer proyecto del curso. Vamos a construir una página de perfil de desarrollador completa usando únicamente lo aprendido en el Módulo 1: JSX, componentes, props, children y composición. Nada de estado ni eventos todavía (llegan en los Módulos 3 y 4): una página estática pero bien arquitecturada.

Objetivo didáctico: que compruebes que con solo 7 conceptos ya puedes construir algo real y con estructura profesional.

El código completo y ejecutable está en proyectos/m01-pagina-perfil. Esta página explica el por qué de cada decisión.

2 · Diseño: el árbol antes que el código

Recordando la lección 3 del Módulo 0: primero el árbol, luego el código. Miramos la página objetivo y la descomponemos:

PÁGINA DE PERFIL (objetivo) ÁRBOL DE COMPONENTES ────────────────────────────── ───────────────────── ┌───────────────────────────────┐ App │ ┌───────────────────────────┐ │ └── ProfilePage │ │ [Avatar] Ana García │ │ ├── Card (contenedor agnóstico) │ │ Frontend Developer │ │ │ ├── ProfileHeader │ │ 📍 Madrid · 🟢 Online │ │ │ │ ├── Avatar │ └───────────────────────────┘ │ │ │ │ └── Badge (online) │ ┌───────────────────────────┐ │ │ ├── StatsBar │ │ 24 repos 1.2k seguidores│ │ │ │ └── StatItem × 3 │ └───────────────────────────┘ │ │ └── SkillList │ ┌───────────────────────────┐ │ │ └── SkillTag × N │ │ [JS ●●●] [React ●●○] … │ │ │ └───────────────────────────┘ │ └───────────────────────────────┘

Decisiones de diseño:

  • Card es el contenedor agnóstico de la lección de children: da borde, sombra y padding; no sabe qué contiene.
  • StatItem y SkillTag son piezas repetitivas con props: número+etiqueta, nombre+nivel.
  • Los datos del usuario viven en un objeto en ProfilePage y fluyen hacia abajo por props. Un solo punto de verdad.
  • Badge demuestra el renderizado condicional más simple (ternario en JSX).

3 · El código, pieza a pieza

Card.jsx — el contenedor (children en acción)

src/components/Card.jsx
// Contenedor visual agnóstico: no sabe qué contiene
export default function Card({ title, children }) {
  return (
    <section className="card">
      {/* title es opcional: solo pinta cabecera si existe */}
      {title && <h3 className="card__title">{title}</h3>}
      {children}
    </section>
  );
}

ProfileHeader.jsx — composición de piezas pequeñas

src/components/ProfileHeader.jsx
import Avatar from "./Avatar.jsx";
import Badge from "./Badge.jsx";

// Cabecera del perfil: avatar + datos + estado de conexión
export default function ProfileHeader({ user }) {
  return (
    <header className="profile-header">
      <Avatar src={user.avatarUrl} alt={user.name} size={96} />
      <div>
        <h1 className="profile-header__name">{user.name}</h1>
        <p className="profile-header__role">{user.role}</p>
        <p className="profile-header__location">📍 {user.location}</p>
        <Badge online={user.isOnline} />
      </div>
    </header>
  );
}

Badge.jsx — renderizado condicional con ternario

src/components/Badge.jsx
// Insignia de estado: verde si online, gris si no.
// La CLASE se calcula con un ternario (expresión en JSX).
export default function Badge({ online }) {
  return (
    <span className={online ? "badge badge--online" : "badge badge--offline"}>
      {online ? "🟢 Disponible" : "⚪ Ocupado"}
    </span>
  );
}

StatsBar.jsx + StatItem.jsx — lista renderizada a mano

src/components/StatsBar.jsx
import StatItem from "./StatItem.jsx";

// Fila de estadísticas. Nota: recibe el ARRAY y delega cada item.
// (Usamos map() como avance del Módulo 2: un StatItem por dato.)
export default function StatsBar({ stats }) {
  return (
    <div className="stats-bar">
      {stats.map((stat) => (
        <StatItem key={stat.label} value={stat.value} label={stat.label} />
      ))}
    </div>
  );
}
src/components/StatItem.jsx
// Una estadística: número grande + etiqueta pequeña
export default function StatItem({ value, label }) {
  return (
    <div className="stat-item">
      <strong className="stat-item__value">{value}</strong>
      <span className="stat-item__label">{label}</span>
    </div>
  );
}

ProfilePage.jsx — la página compone todo

src/components/ProfilePage.jsx
import Card from "./Card.jsx";
import ProfileHeader from "./ProfileHeader.jsx";
import StatsBar from "./StatsBar.jsx";
import SkillList from "./SkillList.jsx";

// Datos de ejemplo: UN solo objeto, fuente de verdad de la página.
// En el Módulo 9 vendrá de una API; la estructura ya está preparada.
const user = {
  name: "Ana García",
  role: "Frontend Developer",
  location: "Madrid, España",
  avatarUrl: "https://i.pravatar.cc/150?img=47",
  isOnline: true,
  stats: [
    { value: 24, label: "repos" },
    { value: "1.2k", label: "seguidores" },
    { value: 312, label: "contribuciones" },
  ],
  skills: [
    { name: "JavaScript", level: 3 },
    { name: "React", level: 3 },
    { name: "CSS", level: 2 },
    { name: "Node", level: 1 },
  ],
};

export default function ProfilePage() {
  return (
    <main className="profile-page">
      <Card>
        <ProfileHeader user={user} />
      </Card>

      <Card title="Estadísticas">
        <StatsBar stats={user.stats} />
      </Card>

      <Card title="Habilidades">
        <SkillList skills={user.skills} />
      </Card>
    </main>
  );
}

Fíjate en la belleza del resultado: ProfilePage se lee como un índice de la página. Cada detalle vive en su componente. Eso es pensar en React.

4 · Decisiones profesionales aplicadas

  • Un objeto user como fuente única: cambiar la foto o el nombre es tocar UNA línea; toda la página se actualiza. Si estuviera hardcodeado en 5 componentes, se desincronizaría.
  • Card agnóstica con título opcional: el cortocircuito {title && …} evita renderizar un h3 vacío cuando no hay título.
  • Clases BEM en CSS (.card__title, .stats-bar): nombrado predecible sin herramientas extra (Módulo 7 profundiza).
  • Sin estado, sin eventos: forzado a propósito. La arquitectura por componentes y props ya sostiene una página completa.

5 · Buenas prácticas demostradas en este proyecto

  • Diseña el árbol en papel ANTES de programar (lo hicimos en la sección 2).
  • Contenedores agnósticos (Card) + contenido especializado (ProfileHeader).
  • Datos en el nivel más alto que los necesite (ProfilePage), fluyendo hacia abajo.
  • Componentes pequeños con una responsabilidad: ninguno supera las 25 líneas.
  • Valores por defecto y condicionales defensivos (title &&).

6 · Errores que este proyecto evita

  • Un único archivo gigante: habría «funcionado» igual, pero sería imposible de mantener. La estructura ES el objetivo del proyecto.
  • Datos duplicados en varios componentes: violaría la fuente única de verdad.
  • Props excesivamente granulares: pasamos user={user} al header en lugar de 6 props sueltas; pero value+label a StatItem porque SON su identidad. Criterio, no dogma.

7 · Ejercicio guiado (extiende el proyecto)

  1. Arranca el proyecto y cambia los datos del usuario por los tuyos (nombre, rol, skills…). Verifica que TODO se actualiza: la fuente única funciona.
  2. Añade una cuarta Card: «Proyectos destacados», con un componente nuevo ProjectItem (nombre + descripción + tecnología). Reutiliza el patrón de StatsBar.
  3. Añade a Badge una prop opcional text que, si existe, sobreescriba el texto por defecto.

8 · Reto

🎯 Modo «tarjeta compacta»

Añade a ProfilePage una prop compact (booleana, default false). Cuando sea true: el avatar se reduce a 48px, la Card de estadísticas no se muestra y las skills se pintan en una sola línea. Toda la lógica en JSX con ternarios y cortocircuitos — sin tocar los estilos de los componentes hijos salvo clases condicionales.

9 · Resumen

  • Con JSX + componentes + props + children ya construyes páginas reales bien estructuradas.
  • El flujo: datos arriba → props hacia abajo → UI fuera. Siempre.
  • Contenedores agnósticos (Card) multiplican la reutilización sin herencia.
  • El código ejecutable está en proyectos/m01-pagina-perfil.
  • Próximo módulo: renderizar LISTAS de verdad con map() y keys, y condicionales avanzados.

10 · Preguntas frecuentes

¿Por qué usamos map() si es del Módulo 2?

Es un avance controlado: renderizar 3 stats a mano sería ridículo. En el Módulo 2 entenderás las keys a fondo y por qué key={stat.label} es importante.

¿Dónde están los estilos del proyecto?

En src/index.css del proyecto, con metodología BEM. El Módulo 7 enseña la arquitectura CSS completa; aquí basta con ver que cada componente tiene su bloque de estilos.

¿Puedo ver el proyecto funcionando sin instalar nada?

Necesitas instalar una vez (pnpm install), pero desde la raíz del curso un solo comando instala TODOS los proyectos (es un workspace).
