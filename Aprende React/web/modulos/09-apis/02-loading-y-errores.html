Estados de carga y error

Módulo 9 · Consumo de APIs ⏱ 35 minutos

1 · Introducción

Las peticiones a APIs son asíncronas: tardan un tiempo en completarse. Durante ese tiempo, la UI debe mostrar feedback al usuario: un spinner, un skeleton, o un mensaje de "Cargando...". Si la petición falla, debemos mostrar un mensaje de error claro y permitir reintentar.

En esta lección veremos patrones para manejar correctamente los estados de carga, error y éxito en componentes que consumen APIs.

2 · Teoría

Los tres estados

  • Loading: la petición está en curso.
  • Error: la petición falló.
  • Success: la petición completó con datos.

Patrón con estados separados

const [data, setData] = useState(null);
const [loading, setLoading] = useState(true);
const [error, setError] = useState(null);

// Renderizado condicional
if (loading) return <Spinner />;
if (error) return <ErrorMessage message={error} />;
return <DataView data={data} />;

Patrón con estado unificado

const [state, setState] = useState({
  status: "loading",   // "loading" | "error" | "success"
  data: null,
  error: null,
});

// Renderizado condicional
if (state.status === "loading") return <Spinner />;
if (state.status === "error") return <ErrorMessage message={state.error} />;
return <DataView data={state.data} />;

Componentes reutilizables

function Spinner() {
  return <div className="spinner">Cargando...</div>;
}

function ErrorMessage({ message, onRetry }) {
  return (
    <div className="error">
      <p>Error: {message}</p>
      {onRetry && <button onClick={onRetry}>Reintentar</button>}
    </div>
  );
}

Skeleton screens

function SkeletonCard() {
  return (
    <div className="skeleton-card">
      <div className="skeleton-image" />
      <div className="skeleton-text" />
      <div className="skeleton-text short" />
    </div>
  );
}

3 · Ejemplo mínimo

src/components/UserProfile.jsx
import { useState, useEffect } from "react";

export default function UserProfile({ userId }) {
  const [user, setUser] = useState(null);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);

  async function loadUser() {
    setLoading(true);
    setError(null);
    try {
      const response = await fetch(
        `https://jsonplaceholder.typicode.com/users/${userId}`
      );
      if (!response.ok) throw new Error("Usuario no encontrado");
      const data = await response.json();
      setUser(data);
    } catch (err) {
      setError(err.message);
    } finally {
      setLoading(false);
    }
  }

  useEffect(() => {
    loadUser();
  }, [userId]);

  if (loading) return <p>Cargando usuario...</p>;
  if (error) return (
    <div>
      <p style={{ color: "red" }}>{error}</p>
      <button onClick={loadUser}>Reintentar</button>
    </div>
  );

  return (
    <div>
      <h2>{user.name}</h2>
      <p>{user.email}</p>
      <p>{user.company.name}</p>
    </div>
  );
}

4 · Ejemplo real

Lista de productos con skeleton loading:

src/components/ProductList.jsx
import { useState, useEffect } from "react";

function SkeletonCard() {
  return (
    <div style={{
      background: "#f0f0f0",
      padding: "1rem",
      borderRadius: "8px",
      animation: "pulse 1.5s infinite"
    }}>
      <div style={{ height: "150px", background: "#ddd", marginBottom: "1rem" }} />
      <div style={{ height: "20px", background: "#ddd", marginBottom: "0.5rem" }} />
      <div style={{ height: "16px", background: "#ddd", width: "60%" }} />
    </div>
  );
}

export default function ProductList() {
  const [products, setProducts] = useState([]);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);

  async function loadProducts() {
    setLoading(true);
    setError(null);
    try {
      const response = await fetch("https://fakestoreapi.com/products");
      if (!response.ok) throw new Error("Error al cargar productos");
      const data = await response.json();
      setProducts(data);
    } catch (err) {
      setError(err.message);
    } finally {
      setLoading(false);
    }
  }

  useEffect(() => {
    loadProducts();
  }, []);

  if (error) {
    return (
      <div style={{ textAlign: "center", padding: "2rem" }}>
        <p style={{ color: "red" }}>{error}</p>
        <button onClick={loadProducts}>Reintentar</button>
      </div>
    );
  }

  return (
    <div style={{
      display: "grid",
      gridTemplateColumns: "repeat(auto-fill, minmax(250px, 1fr))",
      gap: "1rem"
    }}>
      {loading
        ? Array(8).fill(0).map((_, i) => <SkeletonCard key={i} />)
        : products.map((product) => (
            <div key={product.id} style={{
              border: "1px solid #ddd",
              padding: "1rem",
              borderRadius: "8px"
            }}>
              <img src={product.image} alt={product.title} style={{
                width: "100%",
                height: "150px",
                objectFit: "contain"
              }} />
              <h3>{product.title}</h3>
              <p style={{ fontWeight: "bold", color: "#0066cc" }}>
                ${product.price}
              </p>
            </div>
          ))
      }
    </div>
  );
}

6 · Errores habituales

Error 1: no resetear el error al reintentar

async function loadData() {
  // ✘ no se resetea el error anterior
  const response = await fetch("/api/data");
  // ...
}

async function loadData() {
  setError(null);   // ✔ resetear antes de reintentar
  const response = await fetch("/api/data");
  // ...
}

Error 2: mostrar el contenido anterior durante la recarga

async function refreshData() {
  setLoading(true);
  // ✘ data todavía tiene el valor anterior
  const newData = await fetch("/api/data");
  setData(newData);
  setLoading(false);
}

// Mejor: mostrar skeleton o spinner, no datos antiguos

Error 3: errores técnicos para el usuario

<p>Error: fetch failed: ECONNREFUSED 127.0.0.1:3000</p>   // ✘ técnico
<p>No pudimos conectar con el servidor. Inténtalo de nuevo.</p>   // ✔ claro

7 · Ejercicio guiado

  1. Crea un componente que cargue datos de una API.
  2. Muestra un skeleton screen mientras carga (3 tarjetas placeholder).
  3. Si hay error, muestra un mensaje claro y un botón "Reintentar".
  4. Al reintentar, resetea el error y vuelve a mostrar el skeleton.
  5. Cuando los datos cargan, muestra el contenido real.

8 · Reto

🎯 Componente DataFetcher reutilizable

Crea un componente DataFetcher que acepte una URL y un render function. Maneja internamente los estados de carga, error y éxito. Úsalo para cargar diferentes tipos de datos (usuarios, productos, posts).

9 · Resumen

  • Tres estados: loading, error, success.
  • Muestra feedback visual durante la carga (spinner o skeleton).
  • Permite reintentar después de un error.
  • Resetea el estado de error al reintentar.
  • Mensajes de error claros y útiles para el usuario.
  • Skeleton screens para mejor UX que spinners genéricos.

10 · Preguntas frecuentes

¿Spinner o skeleton?
Skeleton es mejor para contenido estructurado (listas, tarjetas). Spinner es mejor para acciones puntuales (botones, formularios).
¿Cómo manejo múltiples peticiones simultáneas?
Usa estados separados para cada petición, o un objeto con el estado de cada una.
¿Puedo mostrar datos antiguos mientras recargo?
Sí, es el patrón "stale-while-revalidate". Muestra datos antiguos y actualiza en background.
¿Cómo hago un timeout para peticiones lentas?
Usa AbortController con setTimeout para cancelar peticiones que tardan demasiado.
