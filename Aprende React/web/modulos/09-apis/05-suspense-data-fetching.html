Suspense para data fetching

Módulo 9 · Consumo de APIs ⏱ 45 minutos

1 · Introducción

Hasta ahora hemos gestionado la carga de datos manualmente con useState + useEffect: creamos tres estados (loading, error, data) y renderizamos condicionalmente según el estado. Este patrón funciona, pero tiene problemas: cada componente repite la misma estructura, es fácil olvidar un estado, y no hay una forma declarativa de decir "muestra esto mientras cargan los hijos".

Suspense es un componente de React que resuelve esto de forma declarativa. Envuelves un componente que necesita datos con <Suspense>, le pasas un fallback (lo que se muestra mientras carga), y React se encarga del resto. No necesitas if (loading) en cada componente.

En React 19, la llegada de use() permite leer promesas directamente en el render, activando Suspense de forma nativa. Esto cambia completamente la forma de consumir APIs.

2 · Teoría

¿Qué es Suspense?

Suspense no es un gestor de datos. Es un mecanismo de orquestación que le dice a React: "este componente aún no está listo; mientras tanto, muestra esto otro". Es similar a los loading states pero declarativo y manejado por React internamente. 

import { Suspense } from "react";

<Suspense fallback={<p>Cargando...</p>}>
  <Profile />
</Suspense>

Cuando Profile suspende (porque está cargando datos), React automáticamente muestra el fallback. Cuando los datos llegan, React reemplaza el fallback con Profile ya renderizado.

El hook use() en React 19

use() es un nuevo hook de React 19 que permite leer el valor de una promesa directamente en el render. Si la promesa no se ha resuelto, el componente suspende (pausa su render) y React busca el Suspense más cercano para mostrar su fallback. 

import { use } from "react";

function Profile({ userId }) {
  // fetchProfile(userId) devuelve una Promise
  const user = use(fetchProfile(userId));

  return (
    <div>
      <h2>{user.name}</h2>
      <p>{user.email}</p>
    </div>
  );
}

Cuando use() recibe una promesa, React se "suscribe" a ella. Mientras la promesa esté pendiente, el componente no se renderiza (suspende). Cuando se resuelve, React lo renderiza con el valor.

Diagrama de flujo

Componente
    │
    ▼
use(promise)  ──►  ¿promesa resuelta?
    │                      │
    │                      │
    ▼                      ▼
  Sí: renderiza       No: SUSPENDE
                          │
                          ▼
                   <Suspense fallback />
                          │
                   (promesa se resuelve)
                          │
                          ▼
                   React renderiza el componente

Librerías que usan Suspense

Suspense no es solo para use(). Varias librerías de fetching lo soportan:

  • SWR: useSWR("key", fetcher, { suspense: true }).
  • TanStack Query: useSuspenseQuery() desde v5.
  • Relay: usa Suspense de forma nativa con GraphQL.
  • Next.js: los Server Components usan Suspense para streaming.
// Ejemplo con TanStack Query
import { useSuspenseQuery } from "@tanstack/react-query";

function Profile({ userId }) {
  const { data: user } = useSuspenseQuery({
    queryKey: ["user", userId],
    queryFn: () => fetchUser(userId),
  });

  return <h2>{user.name}</h2>;
}

3 · Ejemplo mínimo

El ejemplo más pequeño posible: un perfil que carga con Suspense.

src/services/api.js
const API_BASE = "https://jsonplaceholder.typicode.com";

export function fetchUser(id) {
  return fetch(`${API_BASE}/users/${id}`).then((res) => {
    if (!res.ok) throw new Error("Error al cargar usuario");
    return res.json();
  });
}
src/components/UserProfile.jsx
import { use } from "react";
import { fetchUser } from "../services/api";

// Este componente suspende si la promesa no está resuelta
export default function UserProfile({ userId }) {
  const user = use(fetchUser(userId));

  return (
    <div>
      <h2>{user.name}</h2>
      <p>Email: {user.email}</p>
      <p>Teléfono: {user.phone}</p>
    </div>
  );
}
src/App.jsx
import { Suspense } from "react";
import UserProfile from "./components/UserProfile";

export default function App() {
  return (
    <div>
      <h1>Directorio de usuarios</h1>

      <Suspense fallback={<p>🔄 Cargando perfil...</p>}>
        <UserProfile userId={1} />
      </Suspense>
    </div>
  );
}

Cuando App se monta, llama a UserProfile. Este ejecuta use(fetchUser(1)), que lanza la petición y suspende. React muestra "🔄 Cargando perfil..." hasta que la promesa se resuelve. Entonces renderiza el perfil completo.

El componente UserProfile no tiene ni un solo useState. No gestiona loading, no gestiona error. Solo recibe datos y renderiza. Todo el manejo de estados lo delega a Suspense y al ErrorBoundary.

4 · Ejemplo real

Aplicación con carga progresiva: perfil de usuario con sus posts. Usamos Suspense anidado para que cada sección cargue independientemente.

src/services/api.js
const API_BASE = "https://jsonplaceholder.typicode.com";

export function fetchUser(id) {
  return fetch(`${API_BASE}/users/${id}`).then((r) => {
    if (!r.ok) throw new Error("Error al cargar usuario");
    return r.json();
  });
}

export function fetchPosts(userId) {
  return fetch(`${API_BASE}/posts?userId=${userId}`).then((r) => {
    if (!r.ok) throw new Error("Error al cargar posts");
    return r.json();
  });
}

export function fetchComments(postId) {
  return fetch(`${API_BASE}/comments?postId=${postId}`).then((r) => {
    if (!r.ok) throw new Error("Error al cargar comentarios");
    return r.json();
  });
}
src/components/UserProfile.jsx
import { use } from "react";
import { fetchUser } from "../services/api";

export default function UserProfile({ userIdPromise }) {
  const user = use(userIdPromise);

  return (
    <div className="profile-card">
      <h2>{user.name}</h2>
      <p>@{user.username}</p>
      <p>{user.email} · {user.phone}</p>
      <p>{user.company.name}</p>
    </div>
  );
}
src/components/UserPosts.jsx
import { use } from "react";
import { fetchPosts } from "../services/api";
import PostCard from "./PostCard";

export default function UserPosts({ postsPromise }) {
  const posts = use(postsPromise);

  return (
    <div className="posts-list">
      <h3>Posts ({posts.length})</h3>
      {posts.map((post) => (
        <PostCard key={post.id} post={post} />
      ))}
    </div>
  );
}
src/components/PostCard.jsx
import { Suspense, use } from "react";
import { fetchComments } from "../services/api";

function Comments({ commentsPromise }) {
  const comments = use(commentsPromise);
  return (
    <ul>
      {comments.map((c) => (
        <li key={c.id}><strong>{c.name}:</strong> {c.body}</li>
      ))}
    </ul>
  );
}

export default function PostCard({ post }) {
  const commentsPromise = fetchComments(post.id);

  return (
    <article className="post-card">
      <h4>{post.title}</h4>
      <p>{post.body}</p>
      <Suspense fallback={<p className="loading-comments">Cargando comentarios...</p>}>
        <Comments commentsPromise={commentsPromise} />
      </Suspense>
    </article>
  );
}
src/components/Dashboard.jsx (componente contenedor)
import { Suspense } from "react";
import { fetchUser, fetchPosts } from "../services/api";
import UserProfile from "./UserProfile";
import UserPosts from "./UserPosts";

// Render as you fetch: empezamos a cargar ANTES de renderizar
const userPromise = fetchUser(1);
const postsPromise = fetchPosts(1);

export default function Dashboard() {
  return (
    <div className="dashboard">
      <h1>Dashboard</h1>

      {/*
        Suspense anidado para carga progresiva:
        Primero se muestra el perfil, luego los posts,
        y dentro de cada post los comentarios.
      */}
      <Suspense fallback={<div className="skeleton skeleton--large" />}>
        <UserProfile userIdPromise={userPromise} />

        <Suspense fallback={<div className="skeleton skeleton--medium" />}>
          <UserPosts postsPromise={postsPromise} />
        </Suspense>
      </Suspense>
    </div>
  );
}
src/components/Layout.jsx (con ErrorBoundary)
import { Suspense } from "react";
import { ErrorBoundary } from "react-error-boundary";
import Dashboard from "./Dashboard";

function GlobalErrorFallback({ error, resetErrorBoundary }) {
  return (
    <div className="error-screen">
      <h2>Algo salió mal</h2>
      <p>{error.message}</p>
      <button onClick={resetErrorBoundary}>Reintentar</button>
    </div>
  );
}

export default function Layout() {
  return (
    <ErrorBoundary FallbackComponent={GlobalErrorFallback}>
      <Suspense fallback={<div className="full-page-loader" />}>
        <Dashboard />
      </Suspense>
    </ErrorBoundary>
  );
}

/*
 * ErrorBoundary + Suspense = manejo completo:
 *   - Mientras carga → fallback de Suspense
 *   - Si hay error → fallback de ErrorBoundary
 *   - Al reintentar → se monta todo de nuevo
 */

Observa el patrón "Render as you fetch": las promesas userPromise y postsPromise se crean fuera del componente, en el módulo. Esto significa que la petición empieza antes de que React renderice el componente, ganando tiempo valioso.

6 · Errores habituales

Error 1: crear la promesa dentro del render (carga secuencial)

// ✘ MAL: la promesa se crea al renderizar
function Dashboard() {
  const userPromise = fetchUser(1);

  return (
    <Suspense fallback={<Loader />}>
      <Profile userIdPromise={userPromise} />
    </Suspense>
  );
}

// ✔ BIEN: la promesa se crea fuera, carga inmediata
const userPromise = fetchUser(1);

function Dashboard() {
  return (
    <Suspense fallback={<Loader />}>
      <Profile userIdPromise={userPromise} />
    </Suspense>
  );
}

Error 2: olvidar el ErrorBoundary

// ✘ MAL: si la promesa se rechaza, no hay quien capture el error
<Suspense fallback={<Loader />}>
  <Profile />
</Suspense>

// ✔ BIEN: ErrorBoundary captura el error de la promesa rechazada
<ErrorBoundary FallbackComponent={ErrorFallback}>
  <Suspense fallback={<Loader />}>
    <Profile />
  </Suspense>
</ErrorBoundary>

Error 3: usar Suspense dentro de useEffect

// ✘ MAL: Suspense y useEffect mezclados no tienen sentido
function Profile({ userId }) {
  const [user, setUser] = useState(null);

  useEffect(() => {
    fetchUser(userId).then(setUser);
  }, [userId]);

  if (!user) return null;  // ¿y el suspense?
  return <h2>{user.name}</h2>;
}

// ✔ BIEN: Suspense + use() o librería que lo soporte
function Profile({ userId }) {
  const user = use(fetchUser(userId));
  return <h2>{user.name}</h2>;
}

Error 4: Suspense en cada componente atómico

// ✘ MAL: demasiados Suspense, micro-gestión
function Page() {
  return (
    <Suspense fallback={...}>
      <Header />
      <Suspense fallback={...}>
        <Sidebar />
        <Suspense fallback={...}>
          <Main />
        </Suspense>
      </Suspense>
    </Suspense>
  );
}

// ✔ BIEN: Suspense en los bordes lógicos
function Page() {
  return (
    <ErrorBoundary FallbackComponent={ErrorScreen}>
      <Suspense fallback={<PageSkeleton />}>
        <Header />
        <div className="layout">
          <Sidebar />
          <Suspense fallback={<MainSkeleton />}>
            <Main />
          </Suspense>
        </div>
      </Suspense>
    </ErrorBoundary>
  );
}

8 · Reto

🎯 Refactorizar con Suspense

Toma un componente existente del proyecto que use useState + useEffect para cargar datos y refactorízalo para usar Suspense + use(). Debes eliminar todos los estados de loading y error del componente, mover las promesas fuera del render, y añadir Suspense + ErrorBoundary en el padre. Compara la versión original con la nueva: ¿cuál es más legible?

9 · Resumen

  • Suspense es un componente declarativo para mostrar fallbacks mientras los hijos cargan.
  • use() (React 19) lee promesas directamente en el render y activa Suspense.
  • Suspense elimina la necesidad de useState + if (loading) en cada componente.
  • Patrón "Render as you fetch": crea las promesas fuera del render para empezar antes.
  • Suspense anidado permite carga progresiva (skeleton loading por secciones).
  • Siempre combina Suspense con ErrorBoundary para manejar también los errores.
  • Librerías como SWR, TanStack Query y Relay integran Suspense de forma nativa.
  • Coloca Suspense en los bordes del componente, no en cada componente atómico.

10 · Preguntas frecuentes

¿Suspense reemplaza a useEffect para data fetching?
Sí, para carga inicial de datos. useEffect sigue siendo útil para efectos secundarios (suscripciones, analytics, sincronización con APIs no soportadas).
¿Puedo usar Suspense con fetch tradicional?
Sí, combinando use() con la promesa de fetch. Pero librerías como TanStack Query o SWR ofrecen caché, revalidación y más.
¿Cómo evito peticiones duplicadas con Suspense?
Usa una librería con caché (TanStack Query, SWR) o implementa un cache simple con Promises en un mapa.
¿Qué pasa si el usuario cambia de página mientras carga?
React descarta el render anterior. Si usas AbortController, cancela la petición. Si no, la promesa se resuelve pero el resultado se ignora.
¿ErrorBoundary captura errores de Suspense?
Sí, si una promesa se rechaza, el error se propaga al ErrorBoundary más cercano por encima del Suspense.
¿Puedo tener múltiples Suspense en paralelo?
Sí, cada Suspense es independiente. Si dos hermanos están en Suspenses separados, cargan en paralelo y cada uno muestra su propio fallback.
