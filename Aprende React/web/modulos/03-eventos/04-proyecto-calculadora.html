🛠 Proyecto: calculadora

Proyecto del Módulo 3 ⏱ 55 minutos

1 · Introducción

Tercer proyecto: una calculadora funcional con teclado de dígitos, operaciones básicas, pantalla de resultado y botón de limpiar. Es el proyecto perfecto para este módulo porque TODO son eventos con parámetros: 10 dígitos, 4 operaciones, igual, limpiar…

📌 Nota honesta sobre useState

Una calculadora necesita recordar lo que escribes (la pantalla), y eso es estado — el tema del Módulo 4. Usaremos useState aquí con una introducción mínima anticipada (solo lo imprescindible), porque la alternativa sería construirla mal a propósito. Cuando llegues al Módulo 4, todo lo que aquí «funciona por ahora» se entenderá por completo.

2 · Diseño

LA CALCULADORA ÁRBOL ─────────────── ────── ┌─────────────────┐ Calculator │ 12 + 34 = │ ← display ├── Display (props: value) │ 46 │ ├── Keypad ├─────────────────┤ │ └── CalcButton × 19 │ 7 8 9 ÷ │ │ (props: label, onPress) │ 4 5 6 × │ │ 1 2 3 − │ Lógica: funciones puras │ 0 . = + │ (calculate, formatNumber) │ C │ └─────────────────┘

Decisiones:

  • CalcButton genérico: 19 botones, UN componente. Recibe label y onPress (el callback): la esencia de la lección de parámetros.
  • La lógica de cálculo en funciones puras fuera del componente: testeables y sin mezclar con la UI.
  • El estado mínimo posible: lo que se ve en pantalla (display) y la operación pendiente. Lo justo para que funcione; la teoría completa llega en el Módulo 4.

useState en 60 segundos (la dosis mínima anticipada)

import { useState } from "react";

// const [valor, setValor] = useState(valorInicial);
const [display, setDisplay] = useState("0");

// display        → el valor ACTUAL (se lee como una constante)
// setDisplay(n)  → lo CAMBIA y React repinta la pantalla
// useState("0")  → valor inicial: empieza en "0"

Eso es todo lo que necesitas saber hoy: un dato que, al cambiar, actualiza la pantalla solo. El Módulo 4 lo desmontará por completo.

3 · El código clave

src/components/CalcButton.jsx — UN botón para gobernarlos a todos
// Botón genérico de la calculadora.
// Recibe: label (qué muestra) y onPress (qué AVISA al pulsarse).
// La variante visual se configura con la prop opcional "variant".
export default function CalcButton({ label, onPress, variant = "default" }) {
  return (
    <button
      className={`calc-btn calc-btn--${variant}`}
      onClick={() => onPress(label)}   // ← la arrow envuelve: avisa CON su etiqueta
    >
      {label}
    </button>
  );
}
src/logic/calculate.js — la lógica, PURA y separada
// Función pura: mismos inputs → mismo output. Sin React. Testeable.
export function calculate(a, operator, b) {
  const x = Number(a);
  const y = Number(b);

  switch (operator) {
    case "+": return x + y;
    case "−": return x - y;      // (signo menos tipográfico del botón)
    case "×": return x * y;
    case "÷": return y === 0 ? "Error" : x / y;   // división entre cero
    default: return y;
  }
}
src/components/Calculator.jsx — el cerebro (versión comentada en el proyecto)
const [display, setDisplay] = useState("0");       // lo que se ve
const [previous, setPrevious] = useState(null);     // primer operando
const [operator, setOperator] = useState(null);     // operación pendiente

// Dígito pulsado: lo añade a la pantalla (o sustituye el "0" inicial)
function handleDigit(digit) {
  setDisplay(display === "0" ? digit : display + digit);
}

// Operación pulsada: guarda el primer número y el operador
function handleOperator(op) {
  setPrevious(display);
  setOperator(op);
  setDisplay("0");
}

// Igual pulsado: calcula con la función pura y muestra el resultado
function handleEquals() {
  if (previous === null || operator === null) return;  // nada que calcular
  setDisplay(String(calculate(previous, operator, display)));
  setPrevious(null);
  setOperator(null);
}

4 · Decisiones profesionales aplicadas

  • Los manejadores viven en el padre (Calculator): el estado está ahí, así que la lógica que lo modifica también. Los botones solo avisan (onPress(label)). Flujo unidireccional del Módulo 0, aplicado.
  • onPress(label) en vez de 19 callbacks: el botón se identifica con su etiqueta; el padre decide qué hacer según sea dígito, operador, «=» o «C». Es el patrón de la lección de parámetros llevado a producción.
  • División entre cero controlada: la lógica pura devuelve «Error» en lugar de Infinity. Las decisiones de negocio van en la capa de lógica, no en la UI.
  • Teclado con layout CSS Grid: el orden visual (7-8-9 arriba) se controla desde el array de definición de botones, no desde CSS enrevesado.

5 · Buenas prácticas demostradas

  • Un solo componente botón configurado por props (label, variant, onPress).
  • Lógica de cálculo pura en logic/, separada de la UI: se podría testear sin React (Módulo 12 lo hará).
  • Los manejadores con nombre claro (handleDigit, handleOperator) y los callbacks-prop con on* (onPress).
  • Guard clauses (if (… ) return;) para casos inválidos: pulsar «=» sin operación no hace nada.

6 · Errores que este proyecto evita

  • 19 manejadores distintos: con onPress(label), uno solo para dígitos y otro para operadores.
  • Calcular con eval(): eval("12+34") es un agujero de seguridad y de mantenimiento. La función calculate es explícita y segura.
  • Leer la pantalla del DOM: la pantalla vive en el estado; nunca se lee con querySelector.

7 · Ejercicio guiado

  1. Arranca el proyecto y haz 12 + 34 =: sigue mentalmente el flujo (dígito → handleDigit → setDisplay → repinta; operador → guarda; igual → calculate → muestra).
  2. Añade el botón «±» que invierta el signo del número en pantalla (setDisplay(String(-Number(display))), cuidando el «0» y el «Error»).
  3. Añade el botón «%» que divida entre 100 el valor actual.
  4. Haz que al pulsar un dígito justo después de un «=», empiece un cálculo nuevo en lugar de concatenar al resultado (pista: necesitas saber que acabas de mostrar un resultado — una bandera más de estado, o compara con previous/operator).

10 · Preguntas frecuentes

¿Por qué la pantalla guarda strings y no números?

Porque estás construyendo el número tecla a tecla: concatenar «1» + «2» da «12» (string), sumar 1 + 2 da 3. Se convierte a número solo al calcular (Number(a) en la función pura).

¿No debería usar una máquina de estados para la calculadora?

Las calculadoras reales son un ejemplo clásico de máquina de estados (operand1 → operator → operand2 → result). Nuestra versión simplificada cubre lo esencial; si te pica la curiosidad, useReducer (Módulo 10) es la herramienta para modelarlo formalmente.
