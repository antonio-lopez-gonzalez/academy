Document Metadata y preloading de recursos

Módulo 11 · Optimización ⏱ 35 minutos

1 · Introducción

En las lecciones anteriores has optimizado renders, memoizaciones y el tamaño del bundle. Pero hay una optimización que ocurre antes de que el JavaScript siquiera se cargue: los recursos de la página. Fuentes, imágenes, CSS y hojas de estilo que tarda el navegador en descubrir y descargar.

Hasta ahora, el título de la pestaña (<title>), los meta tags y los <link rel="stylesheet"> se ponían en el <head> de una sola página. Pero en una SPA con rutas, cada vista necesita sus propios meta tags (SEO, compartir en redes) y sus propios recursos. Mantener eso a mano, o con librerías externas como react-helmet, era frágil.

React 19 resuelve esto de forma nativa con dos capacidades que verás en esta lección:

  • Document Metadata: renderiza <title>, <meta>, <link> y <script> desde cualquier componente. React los "sube" (hoist) al <head> automáticamente.
  • Preloading de recursos: las APIs preload, preinit, prefetchDNS y preconnect para descargar recursos críticos antes de que se necesiten.

¿Qué problema resuelve? Antes usabas react-helmet, efectos que manipulaban document.title (lo viste en useEffect) y `` globales. React 19 te da una API declarativa, con deduplicación, orden correcto y sin librerías de terceros.

2 · Teoría

Document Metadata: cómo funciona

React 19 reconoce ciertas etiquetas — <title>, <meta>, <link>, <script>, <base> y <noscript> — como "hoistable". Si las renderizas en cualquier punto de tu árbol de componentes, React las mueve automáticamente al <head> del documento en el cliente y las coloca correctamente durante el renderizado en servidor.

CÓMO SE "SUBEN" LOS METADATOS ───────────────────────────── Componente (cualquier profundidad) │ ▼ Mi página │ ▼ React los detecta como hoistable │ ▼ del documento (cliente) o del HTML (SSR) - deduplicación: si ya existe, no se duplica - orden estable: meta antes que title, etc.

La prop precedence

Para hojas de estilo (<link rel="stylesheet">) puedes indicar un orden de carga con la prop precedence. React agrupa los estilos con la misma precedencia y los inserta antes de mostrar contenido de un Suspense que los necesita: 

import "./reset.css";
import { css } from "some-css-lib";

function Dashboard() {
  return (
    <div className="dashboard">
      <link rel="stylesheet" href="/styles/base.css" precedence="default" />
      {css`color: red`}
    </div>
  );
}

En el renderizado en servidor, React inserta los estilos en el orden de precedencia. En el cliente, los hoistea al <head>. Esto sustituye a librerías que gestionaban estilos en tiempo de ejecución.

Preloading: las cuatro APIs

Cuando sabes que una ruta futura o un componente perezoso necesitará un recurso, puedes descargarlo antes de que se renderice. React 19 expone estas funciones desde react-dom:

FunciónQué haceUso típico
preconnect Abre una conexión TCP/TLS temprana con un dominio. APIs de terceros: preconnect("https://api.ejemplo.com").
prefetchDNS Resuelve el DNS de un dominio sin conexión. Dominios que se usarán pronto, sin coste de conexión.
preload Descarga un recurso (estilo, imagen, script) antes de que se necesite. Fuentes, imágenes de héroe de la siguiente ruta.
preinit Descarga y ejecuta un recurso crítico (script, estilo) de inmediato. Analytics, estilos críticos de la vista siguiente. 
import { preload, preinit, preconnect, prefetchDNS } from "react-dom";

// Conecta temprano con la API que usarás
preconnect("https://api.ejemplo.com");

// Resuelve el DNS del CDN de imágenes
prefetchDNS("https://cdn.ejemplo.com");

// Descarga la fuente antes de que la vista la pida
preload("/fonts/Inter.woff2", { as: "font" });

// Descarga y ejecuta el script de analytics de inmediato
preinit("https://cdn.ejemplo.com/analytics.js", { as: "script" });

Todas estas funciones son idempotentes: puedes llamarlas desde varios componentes sin duplicar la descarga. React gestiona la deduplicación por ti.

3 · Ejemplo mínimo

src/components/ProductPage.jsx
export default function ProductPage({ product }) {
  return (
    <>
      <title>{product.name} · Mi Tienda</title>
      <meta
        name="description"
        content={`Compra ${product.name} al mejor precio`}
      />
      <h1>{product.name}</h1>
      <p>{product.description}</p>
    </>
  );
}

Línea por línea:

  1. <title>{product.name} · Mi Tienda</title>: React sube este título al <head>. El usuario ve el nombre del producto en la pestaña.
  2. <meta name="description" ...>: meta description para SEO y redes sociales. También se hoistea.
  3. Sin useEffect ni react-helmet: declarativo y automático. Si otro componente renderiza un <title>, gana el que se renderice más tarde (el último).

4 · Ejemplo real

Un layout con preloading de la siguiente ruta: cuando el usuario está en el dashboard, pre-cargamos los recursos de la vista de "informes" para que la navegación sea instantánea:

src/App.jsx
import { preload, preinit } from "react-dom";
import { lazy, Suspense, useEffect } from "react";

// Carga diferida de la vista de informes (code splitting, visto en lección 03)
const ReportsView = lazy(() => import("./views/ReportsView"));

export default function App({ route }) {
  // Al montar en el dashboard, pre-cargamos recursos para la ruta de informes
  useEffect(() => {
    if (route === "dashboard") {
      preinit("/styles/reports.css", { as: "style" });
      preload("/img/report-cover.webp", { as: "image" });
    }
  }, [route]);

  return (
    <>
      <title>{route === "dashboard" ? "Dashboard" : "Informes"} · Mi App</title>
      <meta name="description" content="Panel de métricas en tiempo real" />
      <Suspense fallback={<div>Cargando informes…</div>}>
        <ReportsView />
      </Suspense>
    </>
  );
}

Decisiones explicadas:

  • preinit para el CSS: el estilo de informes es crítico para la siguiente vista; se descarga e instala de inmediato en background.
  • preload para la imagen: la portada del informe se descarga antes de navegar, así la vista aparece completa.
  • Metadata condicional: el <title> y el meta cambian según la ruta, sin librerías externas.
  • Dentro de useEffect: solo se pre-carga cuando hace falta (en dashboard), no al cargar la app entera.

5 · Buenas prácticas

HazEvitaPor qué
Renderizar metadata declarativamente en cada vista Manipular document.title en useEffect Declarativo es predecible, funciona en SSR y evita parpadeos de título.
Pre-cargar solo recursos que se usarán pronto Pre-cargar todo "por si acaso" Cada recurso pre-cargado compite por el ancho de banda de la página actual.
Usar preconnect para dominios de terceros críticos Usar preconnect para dominios secundarios Preconnect abre conexiones que ocupan recursos; úsalo solo con dominios importantes.
Poner precedence a las hojas de estilo dinámicas Insertar <link> en el cuerpo a mano React ordena los estilos y evita destellos de contenido sin estilo (FOUC).
Combinar con lazy() + Suspense Pre-cargar el JS de rutas que el usuario no visitará El preloading de datos/rutas debe basarse en patrones de navegación reales.

6 · Errores habituales

Error 1: poner el title en useEffect en vez de declarativo

✘ Incorrecto 
useEffect(() => {
  document.title = "Mi página";   // 💥 parpadeo, no funciona en SSR
}, []);
✔ Correcto 
// ✅ React 19: declara el título y React lo sube al head
return (
  <>
    <title>Mi página</title>
    <div>Contenido</div>
  </>
);

Error 2: olvidar la prop as en preload

✘ Incorrecto 
preload("/fonts/Inter.woff2");   // 💥 falta as: el navegador no sabe cómo priorizarla
✔ Correcto 
preload("/fonts/Inter.woff2", { as: "font" });   // ✅ tipo de recurso explícito

Error 3: pre-cargar recursos de más

✘ Incorrecto 
// Al montar la app, pre-cargamos TODO:
preload("/images/a.png", { as: "image" });
preload("/images/b.png", { as: "image" });
// ... 50 más   💥 satura la conexión y ralentiza la página actual
✔ Correcto 
// Solo los recursos de la siguiente acción probable del usuario:
preload("/images/hero.png", { as: "image" });   // ✅

7 · Ejercicio guiado

Crea una mini SPA de dos vistas con metadata y preloading:

  1. Crea un componente HomePage que renderice un <title>, una meta description y una imagen de héroe.

  2. Crea un componente AboutPage con su propio <title> y meta tags.

  3. Añade un estado simple para alternar entre las dos vistas (o usa React Router si lo tienes a mano).

  4. En HomePage, usa preconnect hacia el dominio de la API que usarás y preload de la imagen de la siguiente vista.

  5. Comprueba en DevTools (pestaña Network / Performance) que la imagen se descarga antes de navegar.

  6. Añade una hoja de estilo con precedence y verifica el orden en el <head>.

8 · Reto

🎯 Pre-carga predictiva por comportamiento

Implementa pre-carga basada en el comportamiento del usuario:

  1. Hover: cuando el cursor esté sobre un enlace, pre-carga la vista de destino (usa preload del JS y de sus recursos).
  2. Metadatos por ruta: una función getMetadata(route) que devuelva <title>, meta y preconnect para cada ruta.
  3. Timer: si el usuario permanece en una vista más de 3 segundos, pre-carga la siguiente ruta probable.
  4. Métricas: usa la pestaña Performance para medir la diferencia de tiempo hasta "First Contentful Paint" entre precargar y no precargar.

9 · Resumen

  • React 19 "hoistea" <title>, <meta>, <link> y <script> al <head> desde cualquier componente.
  • Metadata declarativa reemplaza a react-helmet y a los document.title en useEffect.
  • La prop precedence ordena las hojas de estilo dinámicas y evita FOUC.
  • Las APIs preconnect, prefetchDNS, preload y preinit optimizan la carga de recursos futuros.
  • Todo es idempotente: React deduplica los recursos y las conexiones.

10 · Preguntas frecuentes

¿Necesito react-helmet todavía?

No. React 19 gestiona la metadata de forma nativa. react-helmet era una solución para React 16-18. En proyectos nuevos con React 19 usa las capacidades integradas.

¿Y si dos componentes renderizan un título distinto?

Gana el <title> que se renderice más tarde en el árbol (el render más reciente). Para rutas, renderiza el título en la vista activa y se actualizará al navegar.

¿preload y preinit funcionan en el cliente y en el servidor?

Sí. Durante el renderizado en servidor (SSR), React genera los <link rel="preload"> correspondientes en el HTML. En el cliente, preload añade el recurso a la caché del navegador sin esperar a ser renderizado.

¿Qué diferencia hay entre preload y preinit?

preload descarga el recurso pero no lo ejecuta; está listo cuando se necesite. preinit descarga y ejecuta de inmediato (por ejemplo, un script de analytics o un CSS crítico). Para scripts y estilos críticos, usa preinit; para recursos diferibles (fuentes, imágenes), preload.

¿Los estilos con precedence son compatibles con CSS Modules?

Sí. CSS Modules se compilan a clases locales, pero puedes usarlos junto con la metadata. La prop precedence aplica a <link rel="stylesheet"> que insertes dinámicamente o a estilos de librerías CSS-in-JS.
