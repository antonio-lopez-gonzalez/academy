Proyecto: carrito de compra

Módulo 10 · Estado global 🕐 70 minutos

1 · Introducción

Es el momento de juntar todo lo aprendido en el módulo. Vamos a construir, paso a paso, un carrito de compra completo con React 19 + Redux Toolkit + Vite + pnpm. Un carrito es el ejemplo perfecto de estado global de verdad: lo leen y lo modifican varios componentes que no son familia, cambia con mucha frecuencia y queremos que sobreviva a un refresco de página.

El proyecto es una pequeña tienda: un listado de productos, botones para añadirlos, un contador en la cabecera y un panel lateral (drawer) con el carrito, donde se puede cambiar la cantidad, quitar productos, vaciarlo y ver el total.

¿Qué vas a practicar?

  • Store y slice: configureStore y createSlice.
  • Acciones y dispatch: addItem, removeItem, updateQuantity, clearCart, toggleCart.
  • Selectores: datos derivados como el número de artículos y el total.
  • Composición de componentes: cabecera, lista, tarjeta y panel del carrito.
  • Inmutabilidad aunque RTK nos deje "mutar" (Immer) de forma segura.
  • Persistencia opcional en localStorage.
📍 Requisitos previos

Este proyecto asume que ya has leído las lecciones de Redux Toolkit (createSlice, configureStore, useSelector, useDispatch) y de renderizado de listas (map y keys). Si algo de eso te suena raro, repásalo antes: aquí lo usamos todo junto.

2 · Teoría

¿Por qué Redux Toolkit para este carrito?

Podríamos hacerlo con Context o con Zustand. Elegimos Redux Toolkit por tres motivos didácticos que ya conoces:

  • El carrito es estado global que comparten muchos componentes no relacionados (cabecera, lista, panel).
  • Cambia con mucha frecuencia: añadir, quitar, cambiar cantidades. Es justo el escenario donde Context re-renderiza de más y los selectores de Redux ayudan.
  • Tiene lógica de actualización compleja (si el producto ya existe, incrementar; si no, añadirlo), que se expresa muy bien en un reducer.

El modelo de datos

Antes de escribir una línea de código, define tus datos. Este es el contrato del proyecto:

Modelo de datos
{
  "product": { "id": 1, "name": "Camiseta", "price": 20 },
  "cartItem": { "id": 1, "name": "Camiseta", "price": 20, "quantity": 3 },
  "cart": { "items": ["cartItem"], "isOpen": false }
}

Fíjate en que el cartItem es un producto más una cantidad. Guardamos una copia de name y price dentro del item: así el carrito no depende de que el catálogo siga cargado. El total no se guarda; se deriva.

El flujo de datos

Todo proyecto con Redux sigue el mismo ciclo unidireccional. Memorízalo, porque es la base de por qué Redux es predecible:

Usuario pulsa "Añadir al carrito" │ ▼ ProductCard ──dispatch(addItem(product))──► cartSlice.reducer │ (Immer crea un estado nuevo) │ ▼ store (actualizada) │ ┌──────────────────────────────┤ ▼ ▼ Header (selectCartCount) CartDrawer (selectCartItems) se re-renderiza se re-renderiza
💡 Por qué el total NO vive en el estado

El total es suma(price × quantity): puede calcularse a partir de items. Guardarlo sería duplicar información y crear dos fuentes de verdad que podrían desincronizarse (un bug clásico: cambiar la cantidad y que el total quede viejo). Lo calculamos en un selector.

3 · Ejemplo mínimo

Antes del proyecto completo, montamos el núcleo mínimo que ya funciona: un slice con una sola acción, un store y un componente. Si esto se entiende, el resto es repetir el patrón.

Paso 1 — El slice

src/store/cartSlice.js
import { createSlice } from "@reduxjs/toolkit";

const cartSlice = createSlice({
  name: "cart",
  initialState: { items: [] },
  reducers: {
    // Añade un producto: si ya existe, suma 1 a su cantidad.
    addItem: (state, action) => {
      const existing = state.items.find((item) => item.id === action.payload.id);
      if (existing) {
        existing.quantity += 1; // Immer nos deja "mutar" con seguridad
      } else {
        state.items.push({ ...action.payload, quantity: 1 });
      }
    },
  },
});

export const { addItem } = cartSlice.actions;
export default cartSlice.reducer;

Paso 2 — El store

src/store/index.js
import { configureStore } from "@reduxjs/toolkit";
import cartReducer from "./cartSlice";

export const store = configureStore({
  reducer: {
    cart: cartReducer, // el slice vive bajo state.cart
  },
});

Paso 3 — El slice del carrito completo

Aquí está el corazón del proyecto. Cinco acciones y un flag de UI (isOpen, para el panel).

src/store/cartSlice.js
import { createSlice } from "@reduxjs/toolkit";

const initialState = {
  items: [], // [{ id, name, price, quantity }]
  isOpen: false, // si el panel del carrito está visible
};

const cartSlice = createSlice({
  name: "cart",
  initialState,
  reducers: {
    // Añadir un producto: si ya está, sube la cantidad.
    addItem: (state, action) => {
      const existing = state.items.find((item) => item.id === action.payload.id);
      if (existing) {
        existing.quantity += 1;
      } else {
        state.items.push({ ...action.payload, quantity: 1 });
      }
    },

    // Quitar un producto por completo.
    removeItem: (state, action) => {
      state.items = state.items.filter((item) => item.id !== action.payload);
    },

    // Cambiar la cantidad. Nunca bajamos de 1.
    updateQuantity: (state, action) => {
      const { id, quantity } = action.payload;
      const item = state.items.find((item) => item.id === id);
      if (item) {
        item.quantity = Math.max(1, quantity);
      }
    },

    // Vaciar el carrito por completo.
    clearCart: (state) => {
      state.items = [];
    },

    // Abrir / cerrar el panel.
    toggleCart: (state) => {
      state.isOpen = !state.isOpen;
    },

    // Abrir o cerrar con un valor explícito.
    setCartOpen: (state, action) => {
      state.isOpen = action.payload;
    },
  },
});

export const {
  addItem,
  removeItem,
  updateQuantity,
  clearCart,
  toggleCart,
  setCartOpen,
} = cartSlice.actions;

export default cartSlice.reducer;
💡 Nota sobre la "mutación" segura

Ver existing.quantity += 1 o state.items.push(...) asusta si vienes de la lección de inmutabilidad. Es correcto: RTK usa Immer, que registra esas "mutaciones" y produce internamente un estado nuevo e inmutable. Eso sí: solo funciona dentro de un reducer de Redux Toolkit, nunca fuera.

Paso 5 — Los selectores (datos derivados)

Los selectores encapsulan cómo se lee el estado. Así, si mañana cambia la forma del estado, solo tocas este archivo.

src/store/selectors.js
// Cada selector recibe el estado completo y devuelve una porción.
export const selectCartItems = (state) => state.cart.items;
export const selectCartIsOpen = (state) => state.cart.isOpen;

// Número total de unidades (suma de cantidades).
export const selectCartCount = (state) =>
  state.cart.items.reduce((count, item) => count + item.quantity, 0);

// Importe total en euros.
export const selectCartTotal = (state) =>
  state.cart.items.reduce(
    (total, item) => total + item.price * item.quantity,
    0
  );

// ¿Hay algo en el carrito?
export const selectIsEmpty = (state) => state.cart.items.length === 0;

Paso 6 — Persistencia en localStorage

Queremos que el carrito sobreviva al refresco. Guardamos solo items (el panel abierto no merece la pena) cada vez que el store cambia, y lo restauramos al arrancar.

src/store/persistence.js
const STORAGE_KEY = "react19-cart";

// Leer el carrito guardado (o [] si no hay nada / está corrupto).
export function loadCart() {
  try {
    const raw = localStorage.getItem(STORAGE_KEY);
    return raw ? JSON.parse(raw) : [];
  } catch {
    // Si el JSON está corrupto, empezamos limpios.
    return [];
  }
}

// Guardar el carrito actual.
export function saveCart(items) {
  try {
    localStorage.setItem(STORAGE_KEY, JSON.stringify(items));
  } catch {
    // En modo privado o sin cuota, ignoramos silenciosamente.
  }
}

Conectamos la persistencia fuera de React: el store expone subscribe() y getState(), así que no necesitamos ningún hook.

src/store/index.js (actualizado)
import { configureStore } from "@reduxjs/toolkit";
import cartReducer from "./cartSlice";
import { loadCart, saveCart } from "./persistence";

export const store = configureStore({
  reducer: {
    cart: cartReducer,
  },
  // Estado inicial del slice "cart" tomado de localStorage.
  preloadedState: {
    cart: { items: loadCart(), isOpen: false },
  },
});

// Cada vez que el store cambia, guardamos los items.
// subscribe se llama en cada dispatch; getState lee el estado actual.
store.subscribe(() => {
  saveCart(store.getState().cart.items);
});

Paso 7 — La cabecera

La cabecera demuestra el poder de los selectores: solo depende de selectCartCount, así que se re-renderiza únicamente cuando cambia el número de artículos (no cuando cambia, por ejemplo, el precio del total).

src/components/Header.jsx
import { useDispatch, useSelector } from "react-redux";
import { toggleCart } from "../store/cartSlice";
import { selectCartCount } from "../store/selectors";

export default function Header() {
  // Solo nos suscribimos al contador.
  const count = useSelector(selectCartCount);
  const dispatch = useDispatch();

  return (
    <header className="header">
      <h1>🛍️ Tienda React</h1>
      <button className="header__cart" onClick={() => dispatch(toggleCart())}>
        🛒 Carrito
        {count > 0 && <span className="header__badge">{count}</span>}
      </button>
    </header>
  );
}

Paso 9 — El panel del carrito

Primero una fila (para no repetir markup) y luego el panel. La fila encapsula las acciones de cambiar cantidad y eliminar.

src/components/CartItemRow.jsx
import { useDispatch } from "react-redux";
import { removeItem, updateQuantity } from "../store/cartSlice";

export default function CartItemRow({ item }) {
  const dispatch = useDispatch();

  return (
    <li className="row">
      <span className="row__name">{item.name}</span>
      <span className="row__price">
        {(item.price * item.quantity).toFixed(2)} €
      </span>
      <input
        type="number"
        min="1"
        value={item.quantity}
        aria-label={`Cantidad de ${item.name}`}
        onChange={(e) =>
          dispatch(
            updateQuantity({ id: item.id, quantity: Number(e.target.value) })
          )
        }
      />
      <button onClick={() => dispatch(removeItem(item.id))}>Eliminar</button>
    </li>
  );
}
src/components/CartDrawer.jsx
import { useDispatch, useSelector } from "react-redux";
import { clearCart, setCartOpen } from "../store/cartSlice";
import {
  selectCartItems,
  selectCartIsOpen,
  selectCartTotal,
  selectIsEmpty,
} from "../store/selectors";
import CartItemRow from "./CartItemRow";

export default function CartDrawer() {
  const items = useSelector(selectCartItems);
  const isOpen = useSelector(selectCartIsOpen);
  const total = useSelector(selectCartTotal);
  const isEmpty = useSelector(selectIsEmpty);
  const dispatch = useDispatch();

  // Sin panel abierto no dibujamos nada.
  if (!isOpen) return null;

  return (
    <aside className="drawer">
      <div className="drawer__head">
        <h2>Tu carrito</h2>
        <button onClick={() => dispatch(setCartOpen(false))}>Cerrar</button>
      </div>

      {isEmpty ? (
        <p>El carrito está vacío.</p>
      ) : (
        <>
          <ul className="drawer__list">
            {items.map((item) => (
              <CartItemRow key={item.id} item={item} />
            ))}
          </ul>
          <footer className="drawer__foot">
            <strong>Total: {total.toFixed(2)} €</strong>
            <button onClick={() => dispatch(clearCart())}>Vaciar</button>
          </footer>
        </>
      )}
    </aside>
  );
}

Resultado final

Con todo esto tienes un carrito completo y funcional: catálogo, añadir, contador en la cabecera, panel lateral, cambio de cantidades, eliminación, vaciado, total y persistencia. Y todas las piezas se comunican sin pasar props entre ellas, gracias a la store global.

5 · Buenas prácticas

HazEvita
Un selector por dato que el componente necesita useSelector((state) => state.cart) (todo el slice)
Definir selectores en selectors.js y reutilizarlos Escribir la lógica de lectura repetida en cada componente
Derivar totales y contadores en selectores Guardar el total dentro del estado
Acciones con nombres de dominio (addItem, clearCart) Una acción genérica setCart(state) que lo cambia todo
Usar key={item.id} en las listas key={index} (rompe el estado al reordenar)
Persistir solo lo necesario y protegido con try/catch Serializar el store entero con funciones dentro
⚡ Un extra de rendimiento: componentes que solo actúan

ProductCard y CartItemRow solo necesitan acciones (dispatch), no estado. Como no llaman a useSelector, Redux no los marca para re-renderizar nunca por cambios en el store. Si además los envolvemos con React.memo (Módulo 11), obtenemos listas que apenas se recalculan.

6 · Errores habituales

Error 1: seleccionar todo el slice

Mal — re-renderiza por cualquier cambio del slice 
function Header() {
  // ✘ El componente depende del objeto cart ENTERO.
  const cart = useSelector((state) => state.cart);
  return <span>{cart.items.length}</span>;
}
Bien — solo lo que se usa, y derivado 
import { selectCartCount } from "../store/selectors";

function Header() {
  // ✔ Solo depende de un número.
  const count = useSelector(selectCartCount);
  return <span>{count}</span>;
}

Error 2: mutar el estado fuera del reducer

Mal — el estado no cambia 
function CartItemRow({ item }) {
  const items = useSelector(selectCartItems);
  const handleClick = () => {
    // ✘ Mutar el estado leído no dispara ningún cambio en Redux.
    item.quantity += 1;
  };
  return <button onClick={handleClick}>+</button>;
}
Bien — dispatch y que el reducer lo haga 
function CartItemRow({ item }) {
  const dispatch = useDispatch();
  return (
    <button
      onClick={() =>
        dispatch(updateQuantity({ id: item.id, quantity: item.quantity + 1 }))
      }
    >
      +
    </button>
  );
}

Error 3: usar el índice como key

Mal — el estado de las filas se descoloca 
// ✘ Al eliminar un producto, React reutiliza mal las filas.
{items.map((item, index) => (
  <CartItemRow key={index} item={item} />
))}
Bien — key estable con el id 
// ✔ El id identifica la fila de forma unívoca.
{items.map((item) => (
  <CartItemRow key={item.id} item={item} />
))}

Error 4: mutar el objeto del catálogo al añadirlo

Mal — contaminamos el producto original 
addItem: (state, action) => {
  // ✘ Añadimos "quantity" al propio objeto del catálogo.
  action.payload.quantity = 1;
  state.items.push(action.payload);
}
Bien — copiar el producto 
addItem: (state, action) => {
  // ✔ Creamos un item nuevo: el catálogo queda intacto.
  state.items.push({ ...action.payload, quantity: 1 });
}

7 · Ejercicio guiado

Vamos a añadir al carrito una funcionalidad muy común en tiendas reales: cupones de descuento. El carrito tendrá un cupón activo y un descuento aplicado sobre el total.

  1. Añade al initialState del slice un campo coupon (por defecto null) y un campo discount (por defecto 0).
  2. Crea la acción applyCoupon con payload { code, percent }: guarda el código y el porcentaje de descuento (por ejemplo 10 = 10%).
  3. Crea la acción removeCoupon que deje coupon en null y discount en 0.
  4. En selectors.js, crea selectDiscountAmount que devuelva el dinero descontado (total × porcentaje / 100) y selectFinalTotal (total − descuento).
  5. En CartDrawer, muestra el subtotal, la línea de descuento (si hay cupón) y el total final. Añade un botón para quitar el cupón.
  6. Prueba: aplica un 10% a un carrito de 100 € y comprueba que el total final son 90 €.
Ver solución
src/store/cartSlice.js (fragmentos)
const initialState = {
  items: [],
  isOpen: false,
  coupon: null,   // por ejemplo { code: "REACT10", percent: 10 }
  discount: 0,    // porcentaje aplicado
};

// dentro de reducers:
applyCoupon: (state, action) => {
  const { code, percent } = action.payload;
  state.coupon = { code, percent };
  state.discount = percent;
},

removeCoupon: (state) => {
  state.coupon = null;
  state.discount = 0;
},

// recuerda exportarlos:
// export const { ..., applyCoupon, removeCoupon } = cartSlice.actions;
src/store/selectors.js (añadido)
// Dinero descontado según el porcentaje activo.
export const selectDiscountAmount = (state) =>
  (selectCartTotal(state) * state.cart.discount) / 100;

8 · Reto

🎯 Historial de compras con "repetir pedido"

Amplía el carrito para que el usuario pueda finalizar la compra y después repetir un pedido anterior. Debe incluir:

  • Una acción checkout que guarde los items actuales en un array orders dentro del estado (cada pedido con su id, date, items y total), y vacíe el carrito.
  • Acciones reorder(orderId) que vuelquen los items de un pedido anterior al carrito actual, y clearHistory.
  • Selectores selectOrders y un contador selectOrderCount.
  • Un componente OrderHistory que liste los pedidos con su fecha, número de artículos y total, y un botón "Repetir".
  • Persistencia de los pedidos: además del carrito, guarda orders en localStorage.

Pista: no guardes objetos Date en el estado ni en localStorage: serializa con new Date().toISOString() y formatea al mostrar. Y ojo con la persistencia: ahora toca guardar dos cosas (items y orders), así que tu saveCart debería pasar a ser algo como saveState que reciba ambos. Piensa qué forma tiene el objeto que escribes en localStorage antes de tocarlo: si cambias el formato, loadState debe entender el nuevo y tolerar el antiguo.

9 · Resumen

  • El carrito es el ejemplo canónico de estado global: lo comparten muchos componentes no relacionados y cambia con frecuencia.
  • Redux Toolkit lo modela con un slice (estado + acciones + reducer) y un store de una sola línea.
  • Las acciones del carrito son de dominio: addItem, removeItem, updateQuantity, clearCart, toggleCart, setCartOpen.
  • El estado guarda solo datos mínimos (items y el flag isOpen); totales y contadores se derivan en selectores.
  • Cada componente se suscribe a lo mínimo con useSelector; los que solo despachan no se re-renderizan nunca por el store.
  • La inmutabilidad la produce Immer dentro de los reducers; fuera de ellos, siempre copias.
  • La persistencia se conecta fuera de React con store.subscribe + getState y localStorage protegido con try/catch.
  • El resultado: una app donde los componentes se comunican sin pasar props, gracias a la store global.

10 · Preguntas frecuentes

¿Por qué no guardo el total directamente en el estado?
Porque el total es estado derivado: se calcula a partir de items. Si lo guardaras, tendrías dos fuentes de verdad y podrían desincronizarse (cambias la cantidad, olvidas recalcular, y el total miente). Guárdalo solo como función en un selector.
¿Cómo persisto el carrito sin romper nada?
Guarda únicamente lo serializable (items, cantidades) y nunca funciones ni objetos no serializables, como instancias de Date. Usa store.subscribe(() => ...) con store.getState() para escribir, y preloadedState para restaurar al arrancar. Envuelve el acceso a localStorage en try/catch: puede fallar en modo privado o al superar la cuota.
¿Por qué mi componente no se actualiza al pulsar "Añadir"?
Dos causas típicas. Una: olvidaste el <Provider store={store}> en main.jsx. Otra: estás leyendo el estado mutándolo directamente en lugar de leerlo con useSelector. Redux no sabe nada de las mutaciones fuera de un reducer. Repasa que toda escritura pasa por dispatch.
¿Por qué existing.quantity += 1 y state.items.push(...) funcionan si la inmutabilidad es "sagrada"?
Porque estás dentro de un reducer de Redux Toolkit, que usa Immer por debajo. Immer registra esas "mutaciones" y genera un estado nuevo e inmutable. Es azúcar sintáctico seguro. Pero solo funciona ahí: fuera de un reducer (en un componente) mutar el estado no provoca ninguna actualización.
¿Y si en vez de Redux hubiera usado Zustand?
Perfectamente válido: el carrito encaja bien en Zustand y tendrías menos piezas (sin slice, sin Provider, sin dispatch; con set/get y persist). Elegimos Redux aquí para consolidar el patrón que has aprendido en el módulo. La lógica (items, total derivado, selectores) sería prácticamente idéntica.
