Arquitectura CSS en React

Módulo 7 · Estilos ⏱ 30 minutos

1 · Introducción

React no impone ninguna forma de escribir CSS. Puedes usar CSS puro, CSS Modules, styled-components, Tailwind, o cualquier otra solución. Pero esa libertad es también una trampa: sin una arquitectura clara, los estilos se convierten en una bola de nieve de selectores globales, colisiones de nombres y reglas que se pisan entre sí.

En esta lección sentaremos las bases: entenderemos los problemas del CSS global, las estrategias para organizar los estilos en una app React, y cuándo usar cada enfoque. En las próximas lecciones profundizaremos en CSS Modules y variables CSS.

2 · Teoría

El problema del CSS global

CSS fue diseñado para documentos, no para aplicaciones. Cuando tienes un archivo styles.css con cientos de selectores, todos son globales:

  • Colisiones de nombres: dos componentes que usen .button se pisan entre sí.
  • Especificidad impredecible: un selector más específico en otro archivo puede anular tus estilos.
  • Efectos secundarios: cambiar un estilo "inofensivo" puede romper algo en otra parte de la app.
  • Difícil de eliminar: ¿puedes borrar una clase? No sabes si se usa en otro componente.

Estrategias de estilos en React

EstrategiaVentajasInconvenientes
CSS global (un archivo .css) Simple, familiar, sin build Colisiones, sin aislamiento
CSS Modules (.module.css) Aislamiento automático, sin runtime Requiere build, nombres generados
CSS-in-JS (styled-components, Emotion) Colocación co-locada, dinámico Runtime, bundle mayor
Utility-first (Tailwind) Rápido, sin nombrar clases HTML verboso, curva de aprendizaje
Inline styles (style={{}}) Dinámico, sin archivos Sin pseudo-clases, sin caché

La recomendación del curso

Usaremos CSS puro + CSS Modules como enfoque principal. Es la solución más equilibrada:

  • CSS global para estilos base (reset, tipografía, layout general).
  • CSS Modules para estilos de componentes (aislados y predecibles).
  • Variables CSS para temas y valores reutilizables.

Importar CSS en React

// CSS global: se aplica a toda la app
import "./index.css";

// CSS Module: se aplica solo a este componente
import styles from "./Button.module.css";

function Button() {
  return <button className={styles.button}>Haz clic</button>;
  // styles.button → "Button_button_x7k2m" (nombre único generado)

La regla de colocación

En React, la convención moderna es co-locar: los estilos de un componente viven junto al componente. Si tienes Button.jsx, su CSS va en Button.module.css en la misma carpeta. 

src/
├── components/
│   ├── Button/
│   │   ├── Button.jsx
│   │   ├── Button.module.css
│   │   └── index.js
│   ├── Card/
│   │   ├── Card.jsx
│   │   └── Card.module.css
│   └── …
├── index.css          ← estilos globales (reset, tipografía)
└── App.jsx

.button {

  font-size: 1rem;
  background: #0066cc;
  color: white;

.button:hover {
  background: #0052a3;
}

.primary {
  background: #0066cc;
}

.danger {
  background: #cc0000;
}
src/components/Button.jsx
import styles from "./Button.module.css";

export default function Button({ variant = "primary", children, ...props }) {
  // Combinamos la clase base con la variante
  const className = `${styles.button} ${styles[variant]}`;

  return <button className={className} {...props}>{children}</button>;
}

/* Reset y base */

6 · Errores habituales

Error 1: usar !important para sobreescribir

.button { color: red !important; }   // ✘ síntoma de un problema de arquitectura

Si necesitas !important, hay un problema de especificidad. Usa CSS Modules y el problema desaparece.

Error 2: estilos inline para todo

<div style={{ padding: "1rem", background: "white" }}>
// ✘ no soporta pseudo-clases (:hover), media queries, ni se cachea

Error 3: mezclar estrategias sin criterio

// ✘ Algunos componentes con CSS Modules, otros con inline, otros con clases globales…
// Elige UNA estrategia principal y sé consistente.

9 · Resumen

  • CSS global tiene problemas de colisiones y especificidad en apps grandes.
  • Estrategias: CSS global, CSS Modules, CSS-in-JS, utility-first, inline.
  • Recomendación: CSS global para reset + CSS Modules para componentes.
  • Co-locar estilos con componentes: Button.jsx + Button.module.css.
  • Variables CSS para valores compartidos y temas.

10 · Preguntas frecuentes

¿Puedo usar Tailwind con React?
Sí, pero el curso usa CSS puro para que entiendas los fundamentos. Tailwind es una capa encima de CSS utility-first.
¿CSS Modules funciona sin Vite?
Necesita un build tool que lo soporte. Vite, Webpack, Next.js lo soportan nativamente.
¿Puedo combinar CSS Modules con clases globales?
Sí: className={`${styles.local} global-class`}. Útil para utilidades globales.
¿Cómo paso estilos a un componente hijo?
Con la prop className o style. El hijo decide cómo combinarlos con sus propios estilos.
