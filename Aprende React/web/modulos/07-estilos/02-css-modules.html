CSS Modules

Módulo 7 · Estilos ⏱ 30 minutos

1 · Introducción

CSS Modules son la solución más equilibrada para aislar estilos en React. No requieren librerías externas, no añaden runtime al bundle, y resuelven el problema de las colisiones de nombres de forma automática.

La idea es simple: cada archivo CSS se trata como un "módulo" donde las clases son locales por defecto. Al importar el CSS, obtienes un objeto con nombres únicos generados automáticamente. Tus estilos nunca se pisan con los de otro componente.

2 · Teoría

Cómo funcionan

// Button.module.css
.button { padding: 0.5rem 1rem; }
.primary { background: blue; }

// Button.jsx
import styles from "./Button.module.css";
// styles = { button: "Button_button_x7k2m", primary: "Button_primary_a3b9c" }

<button className={styles.button}>   // clase única, sin colisiones

Vite (y otros build tools) transforman los nombres de clase a identificadores únicos basados en el nombre del archivo y la clase. El CSS generado sigue siendo CSS normal; los navegadores no saben nada de "modules".

Convención de nombres

  • El archivo debe terminar en .module.css (no solo .css).
  • Se importa como default: import styles from "./Foo.module.css".
  • El objeto tiene una propiedad por cada clase del CSS.

Componer clases

/* Card.module.css */
.card {
  background: white;
  border-radius: 8px;
  padding: 1rem;
}

.cardHighlighted {
  composes: card;   /* hereda todos los estilos de .card */
  border: 2px solid gold;
}

composes permite heredar estilos entre clases del mismo módulo. Es como la herencia de OOP, pero para CSS.

Clases dinámicas

// Condicionales
<div className={`${styles.card} ${isActive ? styles.active : ""}`}>

// Con template literals
<div className={`${styles.card} ${styles[variant]}`}>

// Múltiples clases
<div className={[styles.card, styles.large, styles.shadowed].join(" ")}>

Variables globales dentro de CSS Modules

/* styles.module.css */
:global(.container) {
  max-width: 1200px;
  margin: 0 auto;
}
/* .container NO se transforma: sigue siendo global */

3 · Ejemplo mínimo

src/components/Badge.module.css
.badge {
  display: inline-block;
  padding: 0.25rem 0.75rem;
  border-radius: 999px;
  font-size: 0.75rem;
  font-weight: 600;
}

.success { background: #d4edda; color: #155724; }
.warning { background: #fff3cd; color: #856404; }
.error   { background: #f8d7da; color: #721c24; }
.info    { background: #d1ecf1; color: #0c5460; }
src/components/Badge.jsx
import styles from "./Badge.module.css";

export default function Badge({ variant = "info", children }) {
  return (
    <span className={`${styles.badge} ${styles[variant]}`}>
      {children}
    </span>
  );
}

4 · Ejemplo real

Componente Card con variantes y estados:

src/components/Card/Card.module.css
.card {
  background: white;
  border-radius: 12px;
  padding: 1.5rem;
  box-shadow: 0 2px 8px rgba(0, 0, 0, 0.08);
  transition: transform 0.2s, box-shadow 0.2s;
}

.clickable {
  composes: card;
  cursor: pointer;
}

.clickable:hover {
  transform: translateY(-2px);
  box-shadow: 0 4px 16px rgba(0, 0, 0, 0.12);
}

.header {
  display: flex;
  justify-content: space-between;
  align-items: center;
  margin-bottom: 1rem;
}

.title {
  font-size: 1.25rem;
  font-weight: 600;
}

.body {
  color: #666;
  line-height: 1.6;
}

.footer {
  margin-top: 1rem;
  padding-top: 1rem;
  border-top: 1px solid #eee;
  display: flex;
  gap: 0.5rem;
}
src/components/Card/Card.jsx
import styles from "./Card.module.css";

export default function Card({ title, children, footer, onClick }) {
  const className = onClick ? styles.clickable : styles.card;

  return (
    <div className={className} onClick={onClick}>
      {title && (
        <div className={styles.header}>
          <h3 className={styles.title}>{title}</h3>
        </div>
      )}
      <div className={styles.body}>{children}</div>
      {footer && <div className={styles.footer}>{footer}</div>}
    </div>
  );
}

6 · Errores habituales

Error 1: olvidar .module en el nombre

import styles from "./Button.css";   // ✘ no es un module, las clases son globales
import styles from "./Button.module.css";   // ✔

Error 2: acceder a una clase que no existe

styles.nonExistent;   // → undefined
// No da error, pero className será "undefined". Usa optional chaining o verifica.

Error 3: estilos inline para valores dinámicos simples

// Para valores que cambian (ancho dinámico), inline está bien:
<div style={{ width: `${percent}%` }}>
// Pero para todo lo demás, usa CSS Modules.

9 · Resumen

  • CSS Modules aísla estilos automáticamente: las clases son locales por defecto.
  • Convención: .module.css + import default.
  • composes para heredar estilos entre clases.
  • Clases dinámicas con template literals o arrays.
  • :global() para escapar del aislamiento cuando sea necesario.

10 · Preguntas frecuentes

¿Puedo usar Sass/Less con CSS Modules?
Sí: .module.scss o .module.less. Vite los soporta con los plugins adecuados.
¿Los CSS Modules afectan al rendimiento?
No: en build, se transforman a CSS normal con nombres únicos. El navegador no nota la diferencia.
¿Puedo usar selectores anidados en CSS Modules?
Sí, CSS Modules soporta toda la sintaxis CSS. Los nombres de clase se transforman, los selectores de elemento no.
¿Cómo depuro los nombres generados?
En DevTools, inspecciona el elemento: verás el nombre generado (ej: Button_button_x7k2m). Busca ese nombre en el CSS generado.
