Tu primer proyecto con Vite

Módulo 0 · Preparación ⏱ 30 minutos

1 · Introducción

Ha llegado el momento: vas a crear, ejecutar y modificar tu primera aplicación React. Y no lo harás «a mano» ni con herramientas obsoletas, sino con Vite, la herramienta estándar actual para desarrollar con React.

Qué aprenderás:

  • Qué es Vite y por qué desbancó a Create React App.
  • Crear un proyecto React 19 en 30 segundos.
  • Entender CADA archivo de la estructura generada (sin magia).
  • Qué es el Hot Module Replacement y por qué cambia tu vida como desarrollador.
  • Cómo se construye la versión de producción.

Errores típicos: usar Create React App (muerto), no entender qué es el div#root, y creer que Vite «es un framework».

2 · Teoría

El problema: el navegador no entiende React «en crudo»

Cuando escribes React usas tres cosas que el navegador NO entiende directamente:

  1. JSX (<h1>Hola</h1> dentro de JS): hay que compilarlo a llamadas JavaScript.
  2. Módulos modernos con import entre decenas de archivos: hay que resolverlos y servirlos eficientemente.
  3. Paquetes de npm (import React from "react"): el navegador no sabe dónde está node_modules.

Necesitas una herramienta de build que traduzca tu código de desarrollo a JavaScript que el navegador entienda. Durante años esa herramienta fue Create React App (CRA), basada en webpack. CRA está oficialmente abandonado (el equipo de React lo retiró de la documentación en 2023 y el proyecto quedó deprecado en 2025): era lento, con dependencias obsoletas y caja negra.

Vite: rápido por diseño, no por casualidad

Vite (del francés «rápido», se pronuncia /vit/) es la herramienta creada por Evan You (el autor de Vue) que hoy es el estándar para React, Vue, Svelte y más. Su velocidad viene de una idea brillante:

DESARROLLO CON WEBPACK (CRA) DESARROLLO CON VITE ────────────────────────────── ──────────────────── Al arrancar: Al arrancar: empaqueta TODA la app NO empaqueta NADA (miles de módulos) sirve cada archivo como antes de responder módulo ES nativo │ │ 10-60 segundos ~100-300 milisegundos Al cambiar un archivo: Al cambiar un archivo: re-empaqueta gran parte re-sirve SOLO ese archivo del bundle (HMR quirúrgico)
  • En desarrollo: Vite aprovecha los módulos ES nativos del navegador (import funciona ya en browsers modernos). Solo transforma el archivo que pides, cuando lo pides, usando esbuild (escrito en Go, ~30 veces más rápido que las herramientas JS clásicas).
  • En producción (pnpm build): usa Rollup para generar un bundle optimizado, minificado y con code splitting.

HMR (Hot Module Replacement): cuando guardas un archivo, Vite inyecta el módulo nuevo en la página sin recargarla entera. Si tenías un formulario a medio rellenar o un modal abierto, sigue ahí. Cambiar código y ver el resultado al instante es el flujo de trabajo que hace adictivo desarrollar con React.

La anatomía del proyecto (sin magia)

Esto es lo que genera la plantilla react de Vite y qué hace cada cosa:

mi-app/ ├── index.html ← LA ÚNICA página HTML de la SPA. │ Contiene <div id="root"> y carga /src/main.jsx │ ├── package.json ← DNI del proyecto: nombre, scripts y dependencias ├── pnpm-lock.yaml ← Versiones EXACTAS instaladas (va a Git) ├── vite.config.js ← Configuración de Vite (plugins…) ├── node_modules/ ← Dependencias instaladas (NUNCA va a Git) │ ├── public/ ← Archivos estáticos que se copian TAL CUAL │ └── vite.svg (favicon, imágenes, robots.txt…) │ └── src/ ← TU CÓDIGO. Aquí vivirá el 99% de tu trabajo ├── main.jsx ← PUNTO DE ENTRADA: monta React en #root ├── App.jsx ← El componente raíz de tu aplicación ├── App.css ← Estilos del componente App ├── index.css ← Estilos globales └── assets/ ← Imágenes/fuentes que pasan por el build

Las dos piezas que conectan todo:

  1. index.html tiene un <div id="root"></div> vacío y una etiqueta <script type="module" src="/src/main.jsx">. Ese div vacío es el «hueco» donde vivirá tu aplicación.
  2. main.jsx busca ese div y le dice a React: «renderiza aquí dentro el componente <App />». A partir de ahí, todo es React.

Los scripts de package.json

ComandoQué haceCuándo lo usas

dependencies vs devDependencies

react y react-dom van en dependencies: forman parte del producto final. vite y el plugin van en devDependencies: son herramientas de construcción que el usuario final nunca descarga. Se instalan con pnpm add paquete y pnpm add -D paquete respectivamente.

3 · Ejemplo mínimo: tu primera app en 4 comandos

# 1. Crea el proyecto (la plantilla "react" trae React 19 + Vite)
pnpm create vite@latest mi-primera-app -- --template react

# 2. Entra en la carpeta
cd mi-primera-app

# 3. Instala las dependencias (lee package.json y descarga node_modules)
pnpm install

# 4. Arranca el servidor de desarrollo
pnpm dev

Verás algo así:

  VITE v7.x.x  ready in 218 ms

  ➜  Local:   http://localhost:5173/
  ➜  Network: use --host to expose
  ➜  press h + enter to show help

Línea por línea de lo que acabas de hacer:

  1. pnpm create vite@latest … — descarga y ejecuta el generador oficial. El --template react elige la plantilla React (JavaScript; react-ts sería TypeScript).
  2. cd mi-primera-app — entras en la carpeta creada.
  3. pnpm install — lee package.json y crea node_modules con React, Vite y todo lo necesario. Solo hace falta al crear el proyecto o cuando cambian las dependencias.
  4. pnpm dev — arranca Vite. El puerto por defecto es 5173. Abre esa URL: ¡tu primera app React está viva!
Prueba el HMR ahora mismo

Abre src/App.jsx, cambia cualquier texto (por ejemplo el contenido de un <p>) y guarda. El navegador se actualiza al instante, sin recargar y sin perder el estado de la página. Eso es el Hot Module Replacement.

4 · Ejemplo real: entender el punto de entrada

Vamos a leer main.jsx como un profesional, porque es el archivo que conecta tu HTML con React. Aparecerá en TODOS los proyectos del curso:

src/main.jsx
// 1. StrictMode: componente de DESARROLLO que detecta problemas
//    (doble-ejecuta efectos y renders para destapar impurezas; en
//    producción no hace nada). Lo entenderemos en el Módulo 6.
import { StrictMode } from "react";

// 2. createRoot: la API de React 19 para montar la app en el navegador
//    (react-dom = el "traductor" de React al DOM del navegador)
import { createRoot } from "react-dom/client";

// 3. Estilos globales: Vite permite importar CSS desde JS
import "./index.css";

// 4. El componente raíz de tu aplicación
import App from "./App.jsx";

// 5. Buscamos el <div id="root"> de index.html y montamos React ahí.
//    A partir de esta línea, React controla todo lo que ocurre
//    dentro de ese div.
createRoot(document.getElementById("root")).render(
  <StrictMode>
    <App />
  </StrictMode>
);
LA CADENA COMPLETA DE ARRANQUE ────────────────────────────── index.html (div#root vacío) │ carga ▼ main.jsx ──createRoot(#root).render()──► React toma el control │ importa ▼ App.jsx ──► renderiza tu árbol de componentes dentro de #root

Detalles que un senior nota:

  • react y react-dom son paquetes separados: react define componentes y hooks (es agnóstico de plataforma); react-dom es el «renderer» que materializa esos componentes en el DOM del navegador. React Native usa el mismo react con otro renderer. Es la prueba de que React no es «para la web»: es para construir UIs, donde sea.
  • El .render() se llama una sola vez en toda la vida de la app. Después, React se re-renderiza a sí mismo cuando cambia el estado (esa es la gracia).
  • Importar CSS desde JS (import "./index.css") funciona gracias a Vite: lo inyecta en desarrollo y lo extrae/minifica en producción.

Y para producción:

pnpm build     # genera dist/ (HTML + JS + CSS minificados y hasheados)
pnpm preview   # sirve dist/ localmente para probarla

La carpeta dist/ es lo único que se sube a un servidor estático en producción: tu Node y Vite ya no participan. Es lo que veremos en la lección de despliegue del Módulo 13.

6 · Errores habituales

Error 1: abrir index.html con doble clic (file://)

Por qué falla: la app necesita un servidor HTTP (los módulos ES no funcionan desde file:// por seguridad del navegador). Además, el JSX aún no está compilado.

Versión correcta: SIEMPRE a través de pnpm dev y la URL http://localhost:5173.

Error 2: editar archivos de otra carpeta mientras el servidor corre

Síntoma: «cambio el código y no pasa nada». Causa típica: tienes DOS proyectos abiertos y editas el que no está siendo servido, o VSCode abierto en la carpeta padre y guardas en el lugar equivocado.

Versión correcta: File → Open Folder sobre la carpeta del proyecto (mi-primera-app), no sobre su padre.

Error 3: «El puerto 5173 está ocupado»

Causa: ya tienes un pnpm dev corriendo en otra terminal.

Versión correcta: Vite te ofrece automáticamente el 5174. O cierra el anterior (Ctrl+C en su terminal). O elige puerto: pnpm dev -- --port 3000.

Error 4: commitear node_modules a Git

✘ Incorrecto 
git add .   # …y suben 200 MB de node_modules 😱
✔ Correcto 
# La plantilla de Vite ya trae un .gitignore que excluye
# node_modules y dist. Respétalo: cualquiera podrá regenerarlos
# con `pnpm install` a partir de package.json + pnpm-lock.yaml

7 · Ejercicio guiado

Vamos a personalizar la plantilla para entender que controlas cada pieza:

  1. Crea y arranca el proyecto (comandos del ejemplo mínimo) y abre http://localhost:5173.

  2. Limpia App.jsx dejándolo así (no entendemos aún la sintaxis en detalle; eso es el Módulo 1, aquí solo comprobamos que tú mandas):

    src/App.jsx
    function App() {
  return (
    <main>
      <h1>Mi primera app con React 19 + Vite</h1>
      <p>Edito, guardo y el navegador se actualiza solo.</p>
    </main>
  );
}

export default App;

  3. Cambia el título de la pestaña editando index.html: <title>Mi primera app</title>. Observa que index.html NO se recarga con HMR (Vite lo avisa): refresca el navegador manualmente esa vez.

  4. Comprueba el montaje: en el navegador, F12 → Elements → busca <div id="root">. Verás que YA NO está vacío: dentro está tu <main>. Ese es React materializando el Virtual DOM.

  5. Rompe algo a propósito: borra el </main> de cierre y guarda. Vite muestra un overlay rojo con el error EXACTO y la línea. Corrígelo. Conocer el overlay de errores te ahorrará horas de pánico futuro.

9 · Resumen

  • El navegador no entiende JSX ni node_modules: necesitas una herramienta de build. Vite es el estándar actual (CRA está muerto).
  • Vite es rápido porque en desarrollo sirve módulos ES nativos con esbuild, sin empaquetar la app entera.
  • Crear proyecto: pnpm create vite@latest nombre -- --template react → pnpm install → pnpm dev (puerto 5173).
  • index.html tiene el div#root; main.jsx monta ahí <App /> con createRoot. Esa llamada ocurre UNA vez.
  • react (componentes/hooks) y react-dom (renderer del navegador) son paquetes separados.
  • HMR: guardas → el cambio aparece sin recargar ni perder estado. Es tu nuevo flujo de trabajo.
  • pnpm build genera dist/: archivos estáticos listos para cualquier servidor.

10 · Preguntas frecuentes

¿Vite es un framework?

No: es una herramienta de build (dev server + bundler). No aparece en tu código de producción; solo transforma y sirve. Por eso el mismo conocimiento de React te sirve con cualquier herramienta (Vite, Next.js, Astro…).

¿Por qué el div se llama "root"? ¿Puedo cambiarlo?

Es solo una convención: un id cualquiera. Puedes llamarlo app si coinciden el index.html y el getElementById de main.jsx. Todo el mundo usa root; mejor mantenerlo.

¿Qué es exactamente StrictMode y por qué «duplica» cosas?

En desarrollo, React con StrictMode ejecuta dos veces los renders y los efectos para destapar impurezas (código que depende de ejecutarse una única vez). No es un bug: es un detector de bugs. En producción se desactiva solo. Lo dominaremos en el Módulo 6 con useEffect.

¿Puedo tener varias apps React en la misma página?

Sí: cada createRoot(div) crea una raíz independiente. Es la técnica de las «islas» (un widget React dentro de una web tradicional). Para este curso, una raíz por app.

¿Dónde está TypeScript en todo esto?

La plantilla react es JavaScript puro; existe react-ts para TypeScript. Este curso usa JavaScript a propósito: primero React en profundidad; TypeScript se añade después sin cambiar nada de lo aprendido.
