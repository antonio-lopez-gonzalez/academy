useEffect: sincronizar con el exterior

Módulo 6 · Hooks en profundidad ⏱ 45 minutos

1 · Introducción

Hasta ahora, todo lo que hemos hecho en React ocurre dentro del mundo de React: el estado cambia, la UI se actualiza, el usuario interactúa, el estado cambia… Es un círculo perfecto y cerrado.

Pero a veces necesitas sincronizar tu componente con algo exterior a React: una API, el DOM directamente, un temporizador, una suscripción a WebSockets, el título de la pestaña del navegador… Estos sistemas no son React; viven fuera y tienen su propio ciclo de vida. useEffect es el puente entre ambos mundos.

useEffect te dice: «después de que React pinte la UI, haz esta cosa exterior». Y cuando el componente desaparezca, puedes limpiar lo que hiciste (cerrar la suscripción, cancelar el temporizador…). Es el hook más poderoso y también el más malentendido del curso. Dedícale tiempo.

2 · Teoría

Qué es un "efecto" en React

Un efecto es código que necesita ejecutarse después de que React haya terminado de renderizar, para sincronizar tu componente con un sistema exterior. No es parte del render; es una consecuencia del render.

Ejemplos típicos:

  • Conectarse a una API cuando el componente aparece.
  • Suscribirse a un WebSocket y desuscribirse al salir.
  • Poner el foco en un input automáticamente.
  • Cambiar el título de la pestaña del navegador.
  • Iniciar un temporizador (setInterval).

NO son efectos: cálculos derivados (eso va en el render), manejar eventos (eso va en onClick, onChange…), actualizar estado basado en props (eso también va en el render).

Anatomía de useEffect

useEffect(() => {
  // código del efecto: se ejecuta DESPUÉS del render
  // …conectarse a API, suscribirse, etc.

  return () => {
    // función de limpieza (opcional): se ejecuta al desmontar
    // …desuscribirse, cancelar temporizador, etc.
  };
}, [dependencias]);   // array de dependencias
  • Primer argumento: la función que contiene tu efecto. React la ejecuta después de pintar.
  • Segundo argumento: el array de dependencias. Le dice a React «solo vuelve a ejecutar este efecto si alguna de estas variables cambia».
  • Return (opcional): la función de limpieza. Se ejecuta antes de volver a ejecutar el efecto y al desmontar el componente.

El array de dependencias: el concepto clave

El array de dependencias controla cuándo se vuelve a ejecutar el efecto:

DependenciasComportamientoCuándo usarlo
Sin array (omito el segundo argumento) Se ejecuta en cada render Casi nunca. Peligroso.
[] (array vacío) Solo se ejecuta una vez, al montarse Conectar con APIs, suscripciones que no dependen de nada.
[a, b] Se ejecuta al montarse y cuando a o b cambian Efectos que dependen de valores específicos.
⚠ La regla de oro de las dependencias

Toda variable externa al efecto que se use dentro DEBE estar en el array de dependencias. Si tu efecto lee userId, userId debe estar en las dependencias. Si no, el efecto usará un valor obsoleto (el del primer render) y tendrás bugs rarísimos.

La función de limpieza (cleanup)

Cuando tu efecto crea algo que sobrevive entre renders (una suscripción, un temporizador, una conexión), necesitas limpiarlo antes de que el componente desaparezca o antes de que el efecto se vuelva a ejecutar. 

useEffect(() => {
  const id = setInterval(() => {
    console.log("tick");
  }, 1000);

  return () => clearInterval(id);   // limpieza: cancela el temporizador
}, []);

Sin la limpieza, el temporizador seguiría ejecutándose aunque el componente ya no exista, causando memory leaks y errores.

El ciclo de vida de un efecto

CICLO DE useEffect CON DEPENDENCIAS [a, b] ────────────────────────────────────────── 1. Primer render: - React pinta la UI - Se ejecuta el efecto (mount) 2. Cambia "a": - React pinta la nueva UI - Se ejecuta la limpieza del efecto anterior - Se ejecuta el efecto nuevo 3. Cambia "b": - React pinta la nueva UI - Se ejecuta la limpieza del efecto anterior - Se ejecuta el efecto nuevo 4. El componente se desmonta: - Se ejecuta la limpieza del efecto (definitiva)

3 · Ejemplo mínimo

Cambiar el título de la pestaña del navegador cuando cambia un contador:

src/components/DocumentTitle.jsx
import { useState, useEffect } from "react";

export default function DocumentTitle() {
  const [count, setCount] = useState(0);

  // Efecto: sincroniza el título del documento con el contador
  useEffect(() => {
    document.title = `Contador: ${count}`;   // efecto secundario: modificar el DOM global
  }, [count]);   // solo se re-ejecuta cuando "count" cambia

  return (
    <div>
      <p>Contador: {count}</p>
      <button onClick={() => setCount(count + 1)}>+1</button>
      <p>Mira la pestaña del navegador ↑</p>
    </div>
  );
}

Línea por línea:

  1. useState(0) — el estado del contador.
  2. useEffect(() => { … }, [count]) — después de cada render donde count haya cambiado, ejecuta el efecto.
  3. document.title = … — modifica algo fuera de React (el título de la pestaña).
  4. [count] — solo re-ejecutar si count cambia. Al montar también se ejecuta (primera vez).

4 · Ejemplo real

Cargar datos de una API cuando el componente se monta, con limpieza para evitar actualizar estado si el componente ya se desmontó:

src/components/UserProfile.jsx
import { useState, useEffect } from "react";

export default function UserProfile({ userId }) {
  const [user, setUser] = useState(null);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    let cancelled = false;   // bandera para saber si el componente se desmontó

    async function fetchUser() {
      try {
        setLoading(true);
        const res = await fetch(`https://jsonplaceholder.typicode.com/users/${userId}`);
        if (!res.ok) throw new Error("Error al cargar usuario");
        const data = await res.json();
        if (!cancelled) {   // solo actualizamos si el componente sigue vivo
          setUser(data);
          setError(null);
        }
      } catch (err) {
        if (!cancelled) setError(err.message);
      } finally {
        if (!cancelled) setLoading(false);
      }
    }

    fetchUser();

    return () => {
      cancelled = true;   // limpieza: marcamos como cancelado al desmontar
    };
  }, [userId]);   // se re-ejecuta cuando cambia userId

  if (loading) return <p>Cargando…</p>;
  if (error) return <p>Error: {error}</p>;
  if (!user) return null;

  return (
    <div>
      <h2>{user.name}</h2>
      <p>{user.email}</p>
      <p>{user.company.name}</p>
    </div>
  );
}

Decisiones explicadas:

  • useEffect con [userId]: el efecto se re-ejecuta cada vez que cambia el userId (por ejemplo, si el usuario navega a otro perfil).
  • Banderas cancelled: evitan actualizar el estado si el componente ya se desmontó. Sin esto, React muestra una warning en consola.
  • Tres estados: loading, error, user. Patrón estándar para APIs (Módulo 9 lo profundiza).
  • Renderizado condicional: mostramos diferentes UIs según el estado (cargando, error, datos).

5 · Buenas prácticas

HazEvitaPor qué
Siempre declarar todas las dependencias externas Omitir dependencias para "evitar re-ejecuciones" Dependencias faltantes = valores obsoletos y bugs rarísimos. El linter de React te avisa.
Limpiar suscripciones y temporizadores Dejar efectos sin cleanup Memory leaks: el efecto sigue ejecutándose aunque el componente ya no exista.
Usar useEffect solo para sincronizar con sistemas externos Usar useEffect para calcular valores derivados Los valores derivados van en el render, no en efectos. Es más simple y reactivo.
Manejar el caso "componente desmontado" en efectos asíncronos Actualizar estado sin comprobar si el componente sigue vivo React muestra warnings y puedes tener comportamiento inesperado.
Extraer lógica compleja a custom hooks (lección 5) Tener efectos gigantes dentro del componente Componentes más limpios y lógica reutilizable.

6 · Errores habituales

Error 1: bucle infinito de renders

✘ Incorrecto 
const [count, setCount] = useState(0);

useEffect(() => {
  setCount(count + 1);   // 💥 actualiza el estado → re-render → efecto → actualiza estado → …
});   // sin array de dependencias: se ejecuta en CADA render
✔ Correcto 
useEffect(() => {
  setCount(count + 1);
}, []);   // solo al montar: un único incremento

Error 2: dependencia faltante

✘ Incorrecto 
const [userId, setUserId] = useState(1);

useEffect(() => {
  fetch(`/api/users/${userId}`);   // usa userId…
}, []);   // …pero userId NO está en las dependencias
// el efecto siempre usará userId = 1 (el valor del primer render)
✔ Correcto 
useEffect(() => {
  fetch(`/api/users/${userId}`);
}, [userId]);   // userId en dependencias: se re-ejecuta cuando cambia

Error 3: usar useEffect para derivar valores

✘ Incorrecto 
const [items, setItems] = useState([]);
const [count, setCount] = useState(0);   // ✘ estado derivado

useEffect(() => {
  setCount(items.length);   // efecto solo para sincronizar estados
}, [items]);
✔ Correcto 
const [items, setItems] = useState([]);
const count = items.length;   // ✔ derivado en el render: siempre sincronizado

Error 4: no limpiar suscripciones

✘ Incorrecto 
useEffect(() => {
  const ws = new WebSocket("wss://api.example.com/feed");
  ws.onmessage = (e) => setMessages((prev) => [...prev, e.data]);
  // 💥 no hay cleanup: el WebSocket sigue abierto al desmontar
}, []);
✔ Correcto 
useEffect(() => {
  const ws = new WebSocket("wss://api.example.com/feed");
  ws.onmessage = (e) => setMessages((prev) => [...prev, e.data]);

  return () => ws.close();   // ✔ cleanup: cierra la conexión al desmontar
}, []);

7 · Ejercicio guiado

Temporizador que cuenta segundos desde que se montó el componente:

  1. Crea un estado const [seconds, setSeconds] = useState(0);

  2. Añade un useEffect con un setInterval que incremente seconds cada segundo.

  3. Array de dependencias vacío []: solo se ejecuta al montar.

  4. Añade la función de limpieza: return () => clearInterval(id);

  5. Muestra el valor de seconds en un <h1>.

  6. Añade un botón "Reset" que ponga seconds a 0. ¿Se detiene el temporizador? No: el setInterval sigue. Solo cambia el valor.

  7. Añade un botón "Pausar/Continuar" que detenga/reanude el temporizador. Necesitarás otro estado isRunning y ajustar las dependencias.

8 · Reto

🎯 El reloj mundial

Crea un componente WorldClock que muestre la hora actual en tres zonas horarias (Madrid, Ciudad de México, Tokio):

  1. Usa setInterval para actualizar la hora cada segundo.
  2. Usa Intl.DateTimeFormat con timeZone para formatear cada zona.
  3. Limpia el intervalo al desmontar.
  4. Muestra la hora en formato HH:MM:SS con la fecha debajo.
  5. Añade un botón para añadir/eliminar zonas horarias (array en estado).
  6. Bonus: cuando el componente se desmonta (p. ej., al cambiar de página), asegúrate de que no quedan intervalos activos (compruébalo con React DevTools → Profiler).

9 · Resumen

  • useEffect sincroniza tu componente con sistemas exteriores a React (APIs, DOM, temporizadores…).
  • Se ejecuta después del render, no durante.
  • El array de dependencias controla cuándo se re-ejecuta: [] = una vez, [a, b] = cuando cambien a o b.
  • Toda variable externa usada en el efecto DEBE estar en las dependencias.
  • La función de limpieza (return () => …) se ejecuta al desmontar y antes de re-ejecutar el efecto.
  • No uses useEffect para valores derivados: eso va en el render.
  • Maneja el caso "componente desmontado" en efectos asíncronos con banderas o AbortController.

10 · Preguntas frecuentes

¿useEffect se ejecuta en el primer render?

Sí, siempre. Después React decide si lo vuelve a ejecutar según las dependencias. Con [], solo se ejecuta una vez (al montar). Con [a], se ejecuta al montar y cuando a cambia.

¿Puedo hacer async directamente en useEffect?

No: useEffect debe devolver una función de limpieza (o nada). Si lo haces async, devuelve una promesa, no una función. La solución: define una función async DENTRO del efecto y llámala.

¿Por qué mi efecto se ejecuta dos veces en desarrollo?

React 18+ en modo estricto (StrictMode) monta, desmonta y remontar los componentes en desarrollo para ayudarte a detectar efectos sin limpieza. En producción solo se monta una vez. Es una feature, no un bug.

¿Puedo usar useEffect para actualizar el DOM directamente?

Sí, pero es raro. Normalmente usas useRef (próxima lección) para acceder a nodos del DOM. useEffect + useRef es la combinación típica para efectos que tocan el DOM.

¿Cuándo NO usar useEffect?

No lo uses para: calcular valores derivados (hazlo en el render), manejar eventos (usa onClick, onChange…), inicializar estado (usa el valor inicial de useState). useEffect es solo para sincronizar con sistemas exteriores a React.
