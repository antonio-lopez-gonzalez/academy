useMemo

Módulo 6 · Hooks en profundidad ⏱ 30 minutos

1 · Introducción

En el Módulo 4 aprendimos que los valores derivados se calculan en el render. Pero, ¿qué pasa si ese cálculo es costoso (filtrar miles de items, ordenar arrays grandes, cálculos matemáticos complejos)? Se re-ejecutaría en cada render, incluso si las dependencias no cambiaron.

useMemo resuelve esto: memoriza el resultado de un cálculo y solo lo recalcula si las dependencias cambian. Es una optimización para evitar trabajo innecesario.

Advertencia: no uses useMemo por defecto. Solo cuando tengas un problema de rendimiento medido. La memorización tiene un coste (guardar el valor, comparar dependencias) y a veces es mayor que el cálculo que evitas.

2 · Teoría

Anatomía de useMemo

const valorMemorizado = useMemo(() => calculoCostoso(a, b), [a, b]);
//                     │              │                           │
//                     │              └─ función que calcula      └─ dependencias
//                     └─ el resultado (memorizado)
  • Primer argumento: función que calcula y devuelve el valor.
  • Segundo argumento: array de dependencias. Solo se re-ejecuta si cambian.
  • Resultado: el valor calculado (o el memorizado si las dependencias no cambiaron).

¿Cuándo usar useMemo?

  • Cálculos costosos (filtrar/ordenar arrays grandes, cálculos matemáticos complejos).
  • Crear objetos/arrays que se pasan como props a componentes memorizados (Módulo 11).
  • Evitar re-crear funciones que se pasan como props (aunque para eso es mejor useCallback, próxima lección).

¿Cuándo NO usar useMemo?

  • Cálculos simples (sumar dos números, concatenar strings).
  • Por defecto "por si acaso". Primero mide, luego optimiza.
  • Si el cálculo depende de valores que cambian en cada render (no tiene sentido memorizar).

3 · Ejemplo mínimo

src/components/ExpensiveCalculation.jsx
import { useState, useMemo } from "react";

function fibonacci(n) {
  if (n <= 1) return n;
  return fibonacci(n - 1) + fibonacci(n - 2);
}

export default function ExpensiveCalculation() {
  const [count, setCount] = useState(0);
  const [num, setNum] = useState(10);

  // Sin useMemo: se recalcula en cada render (incluso si solo cambia count)
  // Con useMemo: solo se recalcula si cambia num
  const fib = useMemo(() => {
    console.log("Calculando fibonacci…");
    return fibonacci(num);
  }, [num]);

  return (
    <div>
      <p>Fibonacci({num}) = {fib}</p>
      <button onClick={() => setNum(num + 1)}>Cambiar número</button>
      <p>Contador: {count}</p>
      <button onClick={() => setCount(count + 1)}>Incrementar</button>
      {/* Al pulsar "Incrementar", NO se recalcula fibonacci */}
    </div>
  );
}

4 · Ejemplo real

Filtrar y ordenar una lista grande de productos:

src/components/ProductList.jsx
import { useState, useMemo } from "react";

const PRODUCTS = Array.from({ length: 10000 }, (_, i) => ({
  id: i,
  name: `Producto ${i}`,
  category: i % 5 === 0 ? "electrónica" : "ropa",
  price: Math.random() * 100,
}));

export default function ProductList() {
  const [search, setSearch] = useState("");
  const [sortBy, setSortBy] = useState("name");

  // Sin useMemo: filtrar 10000 items en cada tecla sería lento
  const filtered = useMemo(() => {
    console.log("Filtrando productos…");
    return PRODUCTS
      .filter((p) => p.name.toLowerCase().includes(search.toLowerCase()))
      .sort((a, b) => sortBy === "price" ? a.price - b.price : a.name.localeCompare(b.name));
  }, [search, sortBy]);

  return (
    <div>
      <input value={search} onChange={(e) => setSearch(e.target.value)} placeholder="Buscar…" />
      <select value={sortBy} onChange={(e) => setSortBy(e.target.value)}>
        <option value="name">Nombre</option>
        <option value="price">Precio</option>
      </select>
      <ul>
        {filtered.slice(0, 50).map((p) => (
          <li key={p.id}>{p.name} — {p.price.toFixed(2)}€</li>
        ))}
      </ul>
      <p>Mostrando 50 de {filtered.length} resultados</p>
    </div>
  );
}

5 · Buenas prácticas

HazEvita
Usar solo cuando haya un problema de rendimiento medidoMemorizar todo "por si acaso"
Declarar todas las dependenciasOmitir dependencias (valores obsoletos)
Funciones puras (sin efectos secundarios)Funciones que modifican estado o variables externas

6 · Errores habituales

Error 1: dependencias faltantes

const filtered = useMemo(() => {
  return items.filter(i => i.includes(query));
}, []);   // 💥 query no está en dependencias: valor obsoleto

Error 2: memorizar cálculos simples

const total = useMemo(() => price * quantity, [price, quantity]);
// ✘ La multiplicación es más rápida que la memorización

Error 3: efectos secundarios en la función

const result = useMemo(() => {
  console.log("Calculando…");   // ✘ no debe haber efectos secundarios
  return expensiveCalc(a);
}, [a]);

9 · Resumen

  • useMemo memoriza el resultado de un cálculo costoso.
  • Solo recalcula si las dependencias cambian.
  • Úsalo solo cuando haya un problema de rendimiento medido.
  • Siempre declara todas las dependencias.
  • La función debe ser pura (sin efectos secundarios).

10 · Preguntas frecuentes

¿useMemo hace que el componente sea más rápido?
No necesariamente. La memorización tiene un coste. Solo ayuda si el cálculo es realmente costoso.
¿Puedo usar useMemo para evitar re-crear objetos?
Sí, pero solo importa si esos objetos se pasan como props a componentes memorizados (Módulo 11).
¿Cuál es la diferencia con useCallback?
useMemo memoriza un valor; useCallback memoriza una función. Veremos useCallback en la próxima lección.
