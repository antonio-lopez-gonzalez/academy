useRef

Módulo 6 · Hooks en profundidad ⏱ 30 minutos

1 · Introducción

Hasta ahora, para guardar valores entre renders usabas useState. Pero useState tiene un efecto secundario: cada vez que cambias el valor, React re-renderiza el componente. ¿Y si quieres guardar un valor que no debe provocar un re-render? Ahí entra useRef.

useRef te da una "caja" mutable que persiste entre renders. Puedes cambiar su contenido (ref.current = algo) sin que React se entere ni re-renderice. Es perfecto para: acceder a nodos del DOM, guardar IDs de temporizadores, contar renders, almacenar valores anteriores…

En esta lección veremos los dos usos principales de useRef: referencias al DOM y valores persistentes sin re-render.

2 · Teoría

Anatomía de useRef

const ref = useRef(valorInicial);
//    │          │
//    │          └─ valor inicial de ref.current (solo la primera vez)
//    └─ un objeto con una propiedad .current
  • useRef devuelve un objeto con una propiedad: { current: valorInicial }.
  • Puedes leer y escribir ref.current libremente. No dispara re-renders.
  • El objeto ref es el mismo entre renders (React lo conserva por ti).
  • El valor inicial solo se usa en el primer render.

Diferencia clave con useState

useStateuseRef
Cambiar el valor → re-render Cambiar ref.current → NO re-render
El valor es inmutable (usas el setter) ref.current es mutable (lo cambias directamente)
Usar cuando el valor afecta a la UI Usar cuando el valor NO afecta a la UI
Ejemplo: contador visible Ejemplo: ID de temporizador, nodo del DOM

Uso 1: acceder a nodos del DOM

El uso más común de useRef es obtener una referencia directa a un elemento del DOM. React te permite pasar un ref a un elemento JSX y, después del render, ref.current apuntará al nodo DOM real. 

const inputRef = useRef(null);

// Después del render:
inputRef.current;   // → el elemento <input> del DOM

// Puedes llamar métodos del DOM:
inputRef.current.focus();   // pone el foco en el input
inputRef.current.value;     // lee el valor actual

Para "conectar" el ref con el elemento, usas el atributo ref en JSX: 

<input ref={inputRef} />

Uso 2: valores persistentes sin re-render

A veces necesitas guardar un valor entre renders pero no quieres que un cambio dispare un re-render. Ejemplos:

  • Guardar el ID de un setInterval para poder cancelarlo.
  • Contar cuántas veces se ha renderizado un componente.
  • Guardar el valor anterior de una prop o estado.
  • Almacenar una instancia de una clase (un reproductor de vídeo, un mapa…).

useRef y useEffect: la combinación clásica

useRef y useEffect se usan juntos frecuentemente. El efecto necesita acceder a algo que persiste entre renders (un nodo del DOM, un temporizador…), y el ref le da ese acceso.

3 · Ejemplo mínimo

Poner el foco en un input automáticamente al montar el componente:

src/components/AutoFocusInput.jsx
import { useRef, useEffect } from "react";

export default function AutoFocusInput() {
  const inputRef = useRef(null);   // creamos el ref (inicialmente null)

  useEffect(() => {
    // Después del primer render, inputRef.current apunta al <input>
    inputRef.current.focus();   // llamamos al método focus() del DOM
  }, []);   // solo al montar

  return <input ref={inputRef} placeholder="Escribe aquí…" />;
}

Línea por línea:

  1. useRef(null) — creamos un ref. Inicialmente current es null.
  2. ref={inputRef} — conectamos el ref con el elemento <input>.
  3. useEffect — después del primer render, React ya ha asignado el nodo DOM a inputRef.current.
  4. inputRef.current.focus() — llamamos al método focus() del DOM. El input recibe el foco automáticamente.

4 · Ejemplo real

Un reproductor de vídeo con controles personalizados. Usamos useRef para acceder al elemento <video> del DOM y llamar sus métodos:

src/components/VideoPlayer.jsx
import { useRef, useState } from "react";

export default function VideoPlayer({ src }) {
  const videoRef = useRef(null);
  const [isPlaying, setIsPlaying] = useState(false);

  function togglePlay() {
    const video = videoRef.current;
    if (!video) return;

    if (isPlaying) {
      video.pause();
    } else {
      video.play();
    }
    setIsPlaying(!isPlaying);
  }

  function handleTimeUpdate() {
    const video = videoRef.current;
    if (!video) return;
    console.log(`Tiempo actual: ${video.currentTime.toFixed(1)}s`);
  }

  function restart() {
    const video = videoRef.current;
    if (!video) return;
    video.currentTime = 0;
    video.play();
    setIsPlaying(true);
  }

  return (
    <div>
      <video
        ref={videoRef}
        src={src}
        onTimeUpdate={handleTimeUpdate}
        style={{ width: "100%", maxWidth: "600px" }}
      />
      <div>
        <button onClick={togglePlay}>
          {isPlaying ? "Pausar" : "Reproducir"}
        </button>
        <button onClick={restart}>Reiniciar</button>
      </div>
    </div>
  );
}

Decisiones explicadas:

  • videoRef: accedemos al elemento <video> para llamar sus métodos (play(), pause(), currentTime).
  • No necesitamos estado para el tiempo: el vídeo tiene su propio estado interno. Solo leemos currentTime cuando lo necesitamos.
  • isPlaying sí es estado: porque afecta a la UI (el texto del botón cambia).
  • Comprobaciones if (!video): el ref puede ser null antes del primer render. Siempre comprobamos antes de usarlo.

5 · Buenas prácticas

HazEvitaPor qué
Usar useRef para acceder al DOM Usar document.querySelector React gestiona el DOM; querySelector puede fallar si hay múltiples instancias del componente.
Comprobar si ref.current existe antes de usarlo Asumir que siempre está disponible Antes del primer render, ref.current es null.
Usar useRef para valores que NO afectan a la UI Usar useRef para valores que deberían ser estado Si cambias ref.current y esperas que la UI se actualice, no lo hará. Usa useState.
Nombres descriptivos: videoRef, inputRef ref, myRef El nombre debe indicar qué elemento o valor guarda el ref.
Usar refs para IDs de temporizadores Guardar IDs de temporizadores en variables locales Las variables locales se pierden entre renders. El ref persiste.

6 · Errores habituales

Error 1: esperar que cambiar ref.current re-renderice

✘ Incorrecto 
const countRef = useRef(0);

function handleClick() {
  countRef.current++;   // cambia el valor…
  // …pero la UI NO se actualiza. No hay re-render.
✔ Correcto 
const [count, setCount] = useState(0);   // si afecta a la UI, es estado

function handleClick() {
  setCount(count + 1);   // cambia el valor Y re-renderiza
}

Error 2: usar ref antes del primer render

✘ Incorrecto 
const inputRef = useRef(null);
console.log(inputRef.current.value);   // 💥 null.value → error
// En el cuerpo del componente, el ref aún no está conectado al DOM
✔ Correcto 
useEffect(() => {
  // Dentro de useEffect, el render ya terminó y el ref está conectado
  if (inputRef.current) {
    console.log(inputRef.current.value);
  }
}, []);

Error 3: usar useRef para valores que deberían ser estado

✘ Incorrecto 
const nameRef = useRef("");

<input
  value={nameRef.current}   // ✘ la UI no se actualiza al escribir
  onChange={(e) => nameRef.current = e.target.value}
/>
✔ Correcto 
const [name, setName] = useState("");

<input
  value={name}
  onChange={(e) => setName(e.target.value)}
/>

Error 4: no limpiar el ref al desmontar (en casos avanzados)

En la mayoría de casos, React gestiona el ref por ti. Pero si guardas algo complejo (una instancia de una clase, una suscripción), considera limpiarlo en un efecto: 

const playerRef = useRef(null);

useEffect(() => {
  playerRef.current = new VideoPlayer();

  return () => {
    playerRef.current?.destroy();   // limpieza al desmontar
    playerRef.current = null;
  };
}, []);

7 · Ejercicio guiado

Contador de renders con useRef:

  1. Crea un estado const [count, setCount] = useState(0); y un botón para incrementarlo.

  2. Crea un ref const renderCountRef = useRef(0);

  3. En el cuerpo del componente (fuera de efectos), incrementa el ref: renderCountRef.current++;

  4. Muestra el valor: <p>Renders: {renderCountRef.current}</p>. ¿Se actualiza? Sí, porque cada cambio de estado provoca un re-render, y el ref se incrementa en cada render.

  5. Añade otro estado const [other, setOther] = useState(0); con su propio botón. Cambia other y observa cómo el contador de renders también aumenta.

  6. Reflexión: ¿por qué el ref se actualiza pero no provoca re-renders? Porque ref.current es mutable y React no lo rastrea. Solo lees su valor cuando ya hay un re-render por otra razón.

8 · Reto

🎯 El input con historial

Crea un componente InputWithHistory que permita deshacer/rehacer cambios:

  1. Un input controlado con estado value.
  2. Usa useRef para guardar un array con el historial de valores.
  3. Cada vez que el usuario pulse Enter, guarda el valor actual en el historial.
  4. Botones "Deshacer" y "Rehacer" que naveguen por el historial (usa otro ref para el índice actual).
  5. El input muestra el valor del historial en la posición actual.
  6. Bonus: usa useRef para guardar el valor anterior y solo añadir al historial si cambió.

9 · Resumen

  • useRef devuelve un objeto con { current: valorInicial } que persiste entre renders.
  • Cambiar ref.current NO provoca re-renders.
  • Uso principal: acceder a nodos del DOM con <elemento ref={miRef} />.
  • Segundo uso: guardar valores persistentes que no afectan a la UI (IDs de temporizadores, instancias de clases…).
  • Diferencia con useState: si el valor afecta a la UI, es estado; si no, es ref.
  • Siempre comprueba si ref.current existe antes de usarlo (puede ser null).
  • Se combina con useEffect para efectos que tocan el DOM.

10 · Preguntas frecuentes

¿Puedo pasar un ref a un componente personalizado?

Sí, pero el componente debe usar forwardRef para recibirlo y pasarlo a un elemento DOM interno. En React 19, forwardRef es opcional: puedes pasar ref como prop normal.

¿Puedo usar useRef para guardar funciones?

Sí, y es útil para evitar dependencias en efectos. Si un efecto necesita llamar a una función que cambia en cada render, guarda la función en un ref y actualízalo en cada render. Así el efecto siempre llama a la versión más reciente sin re-ejecutarse.

¿Cuál es la diferencia entre useRef y una variable global?

El ref es específico de la instancia del componente. Si renderizas tres <VideoPlayer />, cada uno tiene su propio videoRef. Una variable global sería compartida por todas las instancias.

¿Puedo usar useRef para medir el tamaño de un elemento?

Sí: ref.current.getBoundingClientRect() te da el tamaño y posición del elemento. Pero ten cuidado: las medidas pueden cambiar con el resize. Usa useEffect + ResizeObserver para actualizarlas reactivamente.

¿useRef es lo mismo que createRef?

No. createRef es para clases (crea un ref nuevo en cada render, tienes que guardarlo en this.miRef). useRef es para hooks: persiste el mismo objeto entre renders. En componentes funcionales, siempre usa useRef.
