useCallback

Módulo 6 · Hooks en profundidad ⏱ 30 minutos

1 · Introducción

En la lección anterior vimos useMemo para memorizar valores. useCallback es su hermano gemelo, pero para funciones. Memoriza una función y solo la re-crea si las dependencias cambian.

¿Por qué querrías memorizar una función? Porque en React, cada render crea nuevas funciones. Si pasas una función como prop a un componente hijo, el hijo recibe una función nueva en cada render, lo que puede provocar re-renders innecesarios (si el hijo está memorizado con React.memo, Módulo 11).

Regla general: igual que con useMemo, no lo uses por defecto. Solo cuando pases funciones como props a componentes hijos optimizados con React.memo, o cuando una función sea dependencia de un useEffect.

2 · Teoría

El problema: funciones nuevas en cada render

function Parent() {
  const [count, setCount] = useState(0);

  function handleClick() {   // nueva función en cada render
    console.log("clicked");
  }

  return <Child onClick={handleClick} />;
  // Child recibe una función DIFERENTE en cada render,
  // aunque el código de la función no haya cambiado.

En JavaScript, dos funciones con el mismo código NO son iguales: (() => {}) !== (() => {}). React compara props por referencia, así que ve una prop nueva y re-renderiza el hijo (aunque sea React.memo).

La solución: useCallback

import { useCallback } from "react";

function Parent() {
  const [count, setCount] = useState(0);

  const handleClick = useCallback(() => {
    console.log("clicked");
  }, []);   // memoriza la función: solo se re-crea si cambian las dependencias

  return <Child onClick={handleClick} />;
  // Child recibe la MISMA función entre renders (si las deps no cambian)

Anatomía de useCallback

const fn = useCallback(() => {
  // cuerpo de la función
}, [dependencias]);
  • Primer argumento: la función a memorizar.
  • Segundo argumento: array de dependencias. La función se re-crea solo si cambian.
  • Resultado: la misma función entre renders (misma referencia).

useCallback vs useMemo

// Estas dos líneas son EQUIVALENTES:
const fn1 = useCallback(() => doSomething(a), [a]);
const fn2 = useMemo(() => () => doSomething(a), [a]);

// useCallback es azúcar sintáctica para el caso común de memorizar funciones.

¿Cuándo usar useCallback?

  • Cuando pasas funciones como props a hijos optimizados con React.memo.
  • Cuando una función es dependencia de un useEffect.
  • Cuando una función se usa para crear un objeto que se pasa como prop.

¿Cuándo NO usar useCallback?

  • En funciones que solo se usan dentro del componente (onClick locales).
  • Por defecto "por si acaso".
  • Si el componente hijo no está memorizado (no sirve de nada).

3 · Ejemplo mínimo

src/components/Parent.jsx
import { useState, useCallback } from "react";
import Child from "./Child";

export default function Parent() {
  const [count, setCount] = useState(0);
  const [text, setText] = useState("");

  // Sin useCallback: handleClick sería nueva en cada render
  // Con useCallback: es la misma función mientras no cambíe text
  const handleClick = useCallback(() => {
    console.log(`Texto actual: ${text}`);
  }, [text]);

  return (
    <div>
      <input value={text} onChange={(e) => setText(e.target.value)} />
      <Child onClick={handleClick} />
      <p>Contador: {count}</p>
      <button onClick={() => setCount(count + 1)}>+1</button>
      {/* Al cambiar count, Child NO se re-renderiza (handleClick es la misma) */}
    </div>
  );
}
src/components/Child.jsx
import { memo } from "react";

function Child({ onClick }) {
  console.log("Child render");
  return <button onClick={onClick}>Haz clic</button>;
}

export default memo(Child);   // solo re-renderiza si cambian las props

4 · Ejemplo real

Una lista de tareas donde cada item recibe una función onDelete. Sin useCallback, todos los items se re-renderizarían al añadir uno nuevo:

src/components/TaskList.jsx
import { useState, useCallback } from "react";
import TaskItem from "./TaskItem";

export default function TaskList() {
  const [tasks, setTasks] = useState([]);
  const [text, setText] = useState("");

  // La función depende de tasks (para poder filtrar), así que se re-crea
  // solo cuando tasks cambia (que es justo cuando queremos re-renderizar los items)
  const handleDelete = useCallback((id) => {
    setTasks((prev) => prev.filter((t) => t.id !== id));
  }, []);   // setTasks es estable, no hace falta ponerlo

  function handleAdd() {
    if (!text.trim()) return;
    setTasks((prev) => [...prev, { id: Date.now(), text }]);
    setText("");
  }

  return (
    <div>
      <input value={text} onChange={(e) => setText(e.target.value)} />
      <button onClick={handleAdd}>Añadir</button>
      <ul>
        {tasks.map((task) => (
          <TaskItem key={task.id} task={task} onDelete={handleDelete} />
        ))}
      </ul>
    </div>
  );
}

6 · Errores habituales

Error 1: dependencias faltantes (closure obsoleto)

✘ Incorrecto 
const [count, setCount] = useState(0);
const handleClick = useCallback(() => {
  console.log(count);   // usa count…
}, []);   // …pero count NO está en dependencias: siempre imprime 0
✔ Correcto 
const handleClick = useCallback(() => {
  console.log(count);
}, [count]);   // count en dependencias: se re-crea cuando cambia

Error 2: useCallback sin React.memo en el hijo

// Si Child NO está envuelto en React.memo, useCallback no sirve de nada:
// Child se re-renderiza siempre que el padre lo haga, da igual la prop.

Error 3: usar useCallback para funciones que no se pasan como props

function Counter() {
  const handleClick = useCallback(() => {   // ✘ innecesario
    setCount((c) => c + 1);
  }, []);
  return <button onClick={handleClick}>+1</button>;
  // handleClick solo se usa aquí, no se pasa como prop. No hace falta memorizar.

7 · Ejercicio guiado

  1. Crea un padre con un estado count y un hijo con React.memo.
  2. Pasa una función onClick al hijo SIN useCallback. Añade un console.log en el hijo para ver cuántas veces se renderiza.
  3. Cambia el estado del padre (otro estado, no count). El hijo se re-renderiza.
  4. Ahora envuelve la función en useCallback. Cambia el estado del padre. El hijo YA no se re-renderiza.
  5. Añade una dependencia a useCallback y observa cómo se re-crea la función cuando cambia.

8 · Reto

🎯 La lista optimizada

Crea una lista de 100 items donde cada item tenga un botón "Eliminar". Usa useCallback para la función onDelete y React.memo en cada item. Añade un input de búsqueda que filtre la lista. Comprueba que al escribir en el input, los items no se re-renderizan (si la función onDelete no depende del filtro).

9 · Resumen

  • useCallback memoriza una función: devuelve la misma referencia entre renders.
  • Solo re-crea la función si cambian las dependencias.
  • Úsalo cuando pases funciones como props a hijos con React.memo.
  • Es equivalente a useMemo(() => fn, deps).
  • No lo uses por defecto: primero mide, luego optimiza.

10 · Preguntas frecuentes

¿Puedo usar useCallback con async/await?
Sí: const fn = useCallback(async () => { await … }, deps). La función memorizada es async.
¿useCallback hace que el componente sea más rápido?
No por sí solo. Solo ayuda si el hijo está memorizado con React.memo y evitas re-renders innecesarios.
¿Cuál es la diferencia con useMemo?
useCallback(fn, deps) es equivalente a useMemo(() => fn, deps). useCallback es azúcar sintáctica para el caso común de memorizar funciones.
¿Puedo usar useCallback con funciones que dependen del estado anterior?
Sí, pero normalmente no hace falta: si usas la forma funcional del setter (setCount(c => c + 1)), no necesitas la dependencia count.
