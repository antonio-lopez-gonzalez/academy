React 19.2: el resto de novedades

Módulo 15 · Novedades de React 19.2 ⏱ 30 minutos

1 · Introducción

React 19.2 no solo trajo <Activity>, useEffectEvent y PPR. Hubo mejoras que afectan a todo el ecosistema: seguridad (parches críticos), la versión 1.0 del React Compiler, nuevas herramientas en DevTools y cambios de comportamiento en APIs existentes. Conocerlas te evitará sustos al actualizar un proyecto.

¿Qué problema resuelve? La versión estable no es solo "features nuevas": incluye correcciones de seguridad que debes instalar sí o sí, y cambios que afectan a cómo escribes código (como los IDs de useId).

2 · Teoría

Seguridad: CVE-2025-55182 y los parches

A principios de 2026 se reveló una vulnerabilidad crítica (CVE-2025-55182) en Server Actions y Server Components. Los parches llegaron en las versiones 19.2.x, 19.1.x y 19.0.x de enero de 2026 (vía release "security" de cada rama). Conclusión práctica:

  • Si tu app usa Server Actions o consume Server Components, actualiza ya.
  • Siempre usa el caret (^19.2.x) para recibir parches de seguridad automáticamente.
  • Las versiones 19.2.4+ incluyen mitigaciones DoS adicionales en Server Actions.

React Compiler 1.0

El React Compiler, que viste en el Módulo 11, alcanzó la versión 1.0 en octubre de 2025 (anunciada junto a React 19.2). Compila tu código en el build y aplica memoización automáticamente (useMemo, useCallback, React.memo) donde puede demostrar que es seguro. En la práctica:

  • Menos memoización manual: muchos useCallback/memo se vuelven innecesarios.
  • Funciona con Vite mediante babel-plugin-react-compiler o el plugin del framework.
  • Debes cumplir las reglas de los hooks: el compilador omite silenciosamente código con violaciones.

Performance Tracks en DevTools

React 19.2 añade React Performance Tracks: en el panel Performance de las DevTools del navegador, ves en la línea de tiempo cuándo React renderiza, cuándo se compromete (commit) y cuánto tarda cada fase. Es un complemento directo al Profiler del Módulo 11, útil para detectar cuellos de botella en la propia línea de tiempo.

Cambios de comportamiento

CambioAntes (≤19.1)19.2+
useId IDs con : (p.ej. :r1:) IDs con guion bajo _ (p.ej. _r_1_), más seguros en selectores CSS
Suspense en el cliente Revelaba fallbacks de uno en uno Agrupa (batch) las revelaciones de boundaries, más consistente con SSR
SSR en Node Principalmente APIs de streams de Node Añade Web Streams (renderToReadableStream) para Node.js

3 · Ejemplo mínimo

Actualizar un proyecto a React 19.2+ de forma segura:

terminal
# Desde la raíz del workspace (pnpm):
pnpm up react react-dom --latest

# O fija la versión mínima con caret para recibir parches de seguridad:
# "react": "^19.2.4",
# "react-dom": "^19.2.4"

# Actualiza el plugin de ESLint de hooks (imprescindible para useEffectEvent):
pnpm add -D eslint-plugin-react-hooks@latest

Línea por línea:

  1. pnpm up react react-dom --latest: actualiza a la última versión estable (19.2.x).
  2. Caret ^19.2.4: fija la mínima versión parcheada (seguridad) sin bloquear futuras correcciones.
  3. eslint-plugin-react-hooks@latest: la versión 6+ entiende useEffectEvent y las nuevas reglas.

4 · Ejemplo real

Un flujo de actualización completo de una app que usa Server Actions:

guía de actualización
1. CREA UNA RAMA
   git checkout -b chore/upgrade-react-192

2. ACTUALIZA LAS DEPENDENCIAS
   pnpm up react react-dom --latest
   pnpm add -D eslint-plugin-react-hooks@latest

3. REVISA LOS CAMBIOS DE COMPORTAMIENTO
   - useId: los IDs ya no usan ':' sino '_'.
     Si usabas los IDs en selectores CSS, revísalos.
   - Suspense: las revelaciones ahora van en batch.
     Revisa animaciones de fallbacks.

4. EJECUTA LOS TESTS Y EL LINT
   pnpm test:all
   pnpm build:all

5. AUDITA Server Actions / RSC (seguridad)
   - ¿Estás en 19.2.4+? (incluye mitigaciones DoS)
   - ¿Alguna función con 'use server' que no debería serlo?

6. DESPLIEGA Y MONITORIZA
   - Performance Tracks en DevTools para medir renders.

Decisiones explicadas:

  • Rama separada: el upgrade toca dependencias; aíslalo de tus features.
  • Tests antes de desplegar: los cambios de comportamiento (useId, Suspense) pueden romper cosas sutiles.
  • Auditoría de seguridad: la prioridad real de esta versión.

6 · Errores habituales

Error 1: quedarse en una versión vieja "por si acaso"

✘ Incorrecto 
# "react": "19.0.0"   💥 sin parches de seguridad, sin Activity, sin useEffectEvent
✔ Correcto 
# "react": "^19.2.4"   ✅ estable, parcheada y con las novedades

Error 2: usar los IDs de useId como selectores CSS tras el cambio

✘ Incorrecto 
#\:r1\:  { color: red; }   /* 💥 ya no se generan IDs con ':' */
✔ Correcto 
#_r_1_  { color: red; }   /* ✅ o mejor: añade una clase propia al elemento */

Error 3: actualizar React pero no el plugin de hooks

✘ Incorrecto 
pnpm up react react-dom --latest
# 💥 eslint-plugin-react-hooks se queda en v5 y no entiende useEffectEvent
✔ Correcto 
pnpm up react react-dom --latest
pnpm add -D eslint-plugin-react-hooks@latest   # ✅ v6+

7 · Ejercicio guiado

Audita y actualiza un proyecto de ejemplo:

  1. Elige uno de los proyectos del curso (por ejemplo el buscador de películas).

  2. Ejecuta pnpm up react react-dom --latest dentro de él.

  3. Comprueba la versión instalada con pnpm list react.

  4. Verifica que tu package.json usa caret (^).

  5. Ejecuta pnpm build para confirmar que todo compila.

  6. Si usas useId, revisa que no dependes de su formato exacto.

  7. Ejecuta pnpm test:run si el proyecto tiene tests.

8 · Reto

🎯 Prepara tu proyecto para el React Compiler

Prepara la app TaskFlow para el React Compiler:

  1. Reglas de hooks: ejecuta eslint-plugin-react-hooks@6 y corrige todas las violaciones de reglas de hooks.
  2. exhaustive-deps: revisa los eslint-disable de dependencias y evalúa cuáles son candidatos a useEffectEvent.
  3. Anotación: activa el React Compiler en modo "anotación" (solo reporta) y cuenta cuántos componentes son elegibles.
  4. Memo manual: identifica useCallback/useMemo que podrías eliminar si el compilador estuviera activo.

9 · Resumen

  • React 19.2 incluye parches de seguridad críticos (CVE-2025-55182). Actualiza a ^19.2.x.
  • El React Compiler alcanzó la 1.0: automatiza la memoización.
  • React Performance Tracks dan visibilidad en las DevTools del navegador.
  • Cambios de comportamiento: IDs de useId con _ y batch de Suspense.
  • Actualiza siempre eslint-plugin-react-hooks junto con React.

10 · Preguntas frecuentes

¿Debo actualizar a 19.2 aunque no use Server Actions?

Sí, por dos motivos: recibes las novedades (Activity, useEffectEvent) y todos los fixes de la rama. El upgrade de 19.x a 19.2 es menor y de bajo riesgo.

¿El cambio en useId me rompe algo?

Solo si usabas los IDs directamente en selectores CSS o comparabas su formato. Lo normal es usarlos para htmlFor/aria-*, donde el cambio es transparente.

¿Qué hace exactamente React Performance Tracks?

Marca en la línea de tiempo del panel Performance cuándo React renderiza y hace commit. Es más fino que medir con console.time y complementa al Profiler de React DevTools.

¿El React Compiler reemplaza a React.memo y useCallback?

En la práctica, cuando está activo, puedes eliminar mucha memoización manual porque el compilador la aplica automáticamente. Pero no es magia: respeta las reglas de los hooks y hay casos donde la memoización manual sigue siendo útil.
