🛠 Proyecto: catálogo de productos

Proyecto del Módulo 2 ⏱ 50 minutos

1 · Introducción

Segundo proyecto del curso: un catálogo de productos con grid de tarjetas, precios formateados, etiquetas de stock y estados visuales por categoría. Todo con las tres técnicas del módulo: map(), keys y renderizado condicional.

Código ejecutable en proyectos/m02-catalogo-productos. Además, el ejemplo ejemplos/m02-renderizado contiene el experimento de keys (índice vs id) y la tabla de pedidos de las lecciones.

arrancar el proyecto
cd proyectos/m02-catalogo-productos
pnpm dev

2 · Diseño

PANTALLA OBJETIVO ÁRBOL ───────────────── ────── ┌─────────────────────────────────┐ App │ Catálogo (6 productos) │ └── CatalogPage │ ┌───────┐ ┌───────┐ ┌───────┐ │ ├── ProductGrid │ │ 📷 │ │ 📷 │ │ 📷 │ │ │ └── ProductCard × N │ │Nombre │ │Nombre │ │Nombre │ │ │ ├── CategoryBadge │ │89.9 € │ │24.5 € │ │49.99€ │ │ │ ├── PriceTag │ │🔥Últi.│ │ │ │Sin st.│ │ │ └── StockNotice │ └───────┘ └───────┘ └───────┘ │ └── EmptyState (si no hay datos) └─────────────────────────────────┘

Decisiones:

  • ProductGrid se ocupa del map() y de la lista vacía; ProductCard solo sabe pintar UN producto.
  • Las condiciones visuales (agotado, últimas unidades, oferta) viven cada una en su micro-componente o en clases condicionales: el JSX de ProductCard se mantiene legible.
  • Datos en un array constante (products.js) — en el Módulo 9 vendrán de una API sin tocar los componentes.

src/components/ProductGrid.jsx — map + lista vacía
import ProductCard from "./ProductCard.jsx";

export default function ProductGrid({ products }) {
  // Return temprano: lista vacía tiene su propio mensaje
  if (products.length === 0) {
    return <p className="empty-state">📭 No hay productos disponibles.</p>;
  }

  return (
    <div className="product-grid">
      {products.map((product) => (
        <ProductCard key={product.id} product={product} />
      ))}
    </div>
  );
}
src/components/ProductCard.jsx — condicionales en acción
import PriceTag from "./PriceTag.jsx";
import StockNotice from "./StockNotice.jsx";

const CATEGORY_LABELS = {
  peripherals: "Periféricos",
  monitors: "Monitores",
  cameras: "Cámaras",
  audio: "Audio",
  accessories: "Accesorios",
};

export default function ProductCard({ product }) {
  // La tarjeta entera cambia de aspecto si está agotada
  const cardClass = product.stock === 0
    ? "product-card product-card--soldout"
    : "product-card";

  return (
    <article className={cardClass}>
      <span className="product-card__category">
        {CATEGORY_LABELS[product.category] ?? product.category}
      </span>

      <h3 className="product-card__name">{product.name}</h3>
      <PriceTag price={product.price} onSale={product.onSale} />
      <StockNotice stock={product.stock} />
    </article>
  );
}
src/components/StockNotice.jsx — 3 estados con if + variable
export default function StockNotice({ stock }) {
  // Tres casos: if clásico antes del return (legible y directo)
  if (stock === 0) {
    return <p className="stock stock--out">❌ Agotado</p>;
  }
  if (stock < 5) {
    return <p className="stock stock--low">🔥 ¡Solo quedan {stock}!</p>;
  }
  return <p className="stock stock--ok">✔ En stock</p>;
}
src/components/PriceTag.jsx — ternario para oferta
export default function PriceTag({ price, onSale }) {
  const formatted = price.toLocaleString("es-ES", {
    style: "currency",
    currency: "EUR",
  });

  return (
    <p className="price-tag">
      {onSale ? (
        <>
          <strong className="price-tag--sale">{formatted}</strong>
          <span className="price-tag__badge">OFERTA</span>
        </>
      ) : (
        <strong>{formatted}</strong>
      )}
    </p>
  );
}

4 · Decisiones profesionales aplicadas

  • Diccionario de categorías (CATEGORY_LABELS) en lugar de ternarios en cadena, con ?? por si llega una categoría desconocida del backend.
  • Clase condicional en la tarjeta: el estado «agotado» se refleja con una clase BEM (product-card--soldout) que el CSS atenúa — no con estilos inline mezclados.
  • Cada condición en su componente: StockNotice conoce 3 estados y se testea solo. ProductCard no acumula lógica.
  • Formato de moneda con toLocaleString: jamás price + "€".

5 · Buenas prácticas demostradas

  • El grid delega el map; la tarjeta pinta uno; los avisos se extraen: responsabilidad única por archivo.
  • Lista vacía contemplada SIEMPRE (return temprano en ProductGrid).
  • Keys con product.id: estables, de dominio.
  • Datos separados de la UI (data/products.js): mañana serán un fetch sin tocar componentes.

6 · Errores que este proyecto evita

  • Una sola función gigante con todo el JSX: imposible de leer y de testear.
  • Estilos inline por todas partes: las variantes van en clases CSS condicionales.
  • Olvidar el agotado/vacío: los estados «feos» son parte del diseño, no un parche posterior.

7 · Ejercicio guiado

  1. Arranca el proyecto y añade un producto nuevo al array: verifica que aparece sin tocar componentes.
  2. Pon stock: 0 a dos productos y observa el estado agotado. Pon la lista vacía (products = [] en CatalogPage) y verifica el EmptyState.
  3. Añade al grid un encabezado «X productos» calculado con products.length, que diga «1 producto» en singular cuando solo haya uno (ternario).
  4. Crea el componente CategoryBadge separando la etiqueta de categoría fuera de ProductCard.

8 · Reto

🎯 Filtros por categoría (sin estado aún)

Sin usar useState (es del Módulo 4): define en CatalogPage una constante const selectedCategory = "audio"; y haz que el grid muestre solo esa categoría con filter antes del map. Cambia la constante a mano y recarga para ver cada filtro.

Bonus: muestra además una fila de «pastillas» con TODAS las categorías existentes (calculadas del array con new Set) y marca visualmente la seleccionada. En el Módulo 4 las harás clicables de verdad.

9 · Resumen

  • Catálogo completo con map + keys + condicionales: el 80 % de las pantallas de listado reales son esto.
  • Datos en módulo aparte: preparados para la futura API.
  • Condicionales bien ubicados: ternarios pequeños en JSX, ifs en micro-componentes, clases para variantes visuales.
  • Código: proyectos/m02-catalogo-productos · Experimentos: ejemplos/m02-renderizado.

10 · Preguntas frecuentes

¿Por qué no usamos imágenes reales de productos?

Para centrarnos en el renderizado sin depender de servicios externos. El reto te invita a añadirlas: con https://picsum.photos/seed/{product.id}/300/200 tienes imágenes deterministas gratis.

¿Cómo haría el filtro clicable de verdad?

Necesitas estado (la categoría seleccionada cambia al hacer clic): es EXACTAMENTE el primer ejercicio del Módulo 4 con useState. El proyecto de ese módulo retoma este patrón.
