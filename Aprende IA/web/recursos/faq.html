Preguntas frecuentes

FAQ ❓ Dudas comunes del curso

General

¿Necesito una API key o tarjeta de crédito para hacer el curso?

No. El núcleo del curso corre con un LLM local (Ollama) y embeddings locales, así que puedes seguirlo entero sin clave ni tarjeta. La nube (OpenAI, Anthropic) aparece como alternativa explícita en los módulos de APIs: mismo patrón de código, otros nombres de campo. Si la usas, las claves van siempre en .env o variables de entorno, nunca en el repositorio.

¿Qué necesito saber antes de empezar?

Saber programar en Python y manejarte con la terminal y Git. No se asume ninguna experiencia previa con IA o LLMs: tokens, contexto y «alucinación» se explican desde cero, separando siempre la inferencia del modelo de la lógica determinista de tu código. Si vienes de otro lenguaje, el curso te da el contexto suficiente; si nunca has programado, resultará exigente.

¿Cuánto tiempo requiere el curso?

Son 9 módulos (0-8) con 36 lecciones y 3 recursos. Cada lección está pensada para 30-45 minutos más el reto. Un ritmo razonable es 3-4 lecciones por semana. Los ejercicios construyen piezas reales del proyecto conductor, el Copiloto, así que conviene hacerlos, no solo leerlos.

Entorno y modelos

¿Qué modelo local uso y necesito una GPU?

El curso usa Ollama con modelos que soportan tool calling, como llama3.2 o qwen2.5. No hace falta GPU: modelos pequeños corren en CPU (más lentos). Con GPU la latencia mejora mucho. Los embeddings también van en local (por ejemplo fastembed con multilingual-e5-small), así que no dependes de ningún servicio externo.

¿Por qué Ollama y no directamente la API de OpenAI/Anthropic?

Porque local primero: aprendes sin coste, sin claves y sin depender de un proveedor, y ves de verdad los tokens y la latencia. El curso es provider-neutral en el discurso y concreto en el código. Un mismo patrón (llamar, hacer streaming, declarar tools) se traduce a la nube cambiando el SDK; en el módulo 2 se muestran las equivalencias.

¿Y si mi modelo local no soporta tool calling o responde en texto?

Tres causas típicas: el modelo no soporta tools (usa llama3.2 o qwen2.5), la descripción de la tool es ambigua, o la pregunta se puede responder sin datos externos y el modelo prefiere contestar de memoria. Refuerza la descripción en imperativo y, si hace falta, instruye en el system que use las tools para datos concretos. Lo detallamos en el módulo 2.

Coste y rendimiento

¿Cuánto cuesta el curso? ¿Local o nube?

En local el coste por token es 0 €: pagas hardware, electricidad y tu tiempo. En la nube pagas por millón de tokens, con la salida bastante más cara que la entrada (a menudo 3-4×). La regla del curso es medir antes de optimizar: el mismo código calcula el coste en ambos casos, cambiando solo la tabla de precios. Para volúmenes altos y datos sensibles, local gana; para volúmenes pequeños, la nube suele salir mejor cuando cuentas todo.

¿Cómo controlo el coste de un agente que da muchas vueltas?

Cuatro palancas: recortar el contexto que de verdad se usa, poner un límite de iteraciones (MAX_STEPS) y de tokens de salida (num_predict/max_tokens), cachear respuestas deterministas (incluyendo modelo y parámetros en la clave) y alertar si el coste por petición se dispara. Un bug en el bucle puede multiplicar la factura por 20; sin métricas no te enteras hasta fin de mes.

Decisiones de diseño

¿Por qué Python y no TypeScript, si mi producto está en otro lenguaje?

Python tiene el ecosistema más maduro para IA: SDKs oficiales, pydantic, embeddings, evaluación y MCP. Además, los conceptos que aprendes (tokens, RAG, tool calling, evals) son transferibles: el mismo bucle de agente existe en Node, Go o C#. Dominar el patrón en Python vale aunque luego lo portes: cambia la librería, no la idea.

¿Esto sirve para mi producto real o es una demo de juguete?

Sirve. El proyecto conductor, el Copiloto, es un sistema real: RAG sobre las lecciones de la Academy, tools, agente con memoria, evaluación con juez automático, guardrails y control de coste, expuesto por CLI y una API mínima. Se construye en proyectos/copiloto/ con uv, es ejecutable con Python 3.12+ y sigue las prácticas que aplicarías en producción: nada de claves en el repo, validación de salidas y trazas por todas partes.

¿RAG o fine-tuning? ¿Y si sale un modelo nuevo?

RAG para hechos y conocimiento que cambia; fine-tuning para forma (estilo, formato) y solo si el prompt no basta. Casi siempre quieres RAG: indexas tu corpus y lo actualizas reindexando, sin tocar el modelo. El curso está diseñado para ser provider-neutral: cuando sale un modelo mejor, cambias el nombre del modelo y vuelves a medir, no reescribes el sistema.

¿Qué es MCP y por qué debería importarme?

MCP (Model Context Protocol) es un estándar para conectar un LLM con datos y herramientas externas mediante servidores que exponen tools, resources y prompts. Importa porque estandariza lo que antes era integración a medida: escribes un servidor una vez y cualquier cliente compatible lo usa. En el módulo 6 montas uno que expone las tools del Copiloto, además de una skill (SKILL.md) que enseña cómo hacer un tipo de trabajo.
