Objetos literales, propiedades y métodos

Módulo 1 · Fundamentos ⏱ 30 minutos

1 · Introducción

En JavaScript, casi todo es un objeto. Los objetos son colecciones de pares clave-valor que te permiten agrupar datos relacionados y comportamiento en una sola estructura. Si los arrays son listas ordenadas, los objetos son diccionarios con nombre: en vez de acceder por índice numérico, accedes por nombre de propiedad.

En esta lección aprenderás a crear objetos literales, acceder y modificar sus propiedades, usar la notación de corchetes para propiedades dinámicas, aplicar shorthand properties y computed property names, iterar sobre objetos con Object.keys(), values() y entries(), copiar objetos con spread y Object.assign(), y usar destructuring para extraer propiedades.

¿Por qué existe esta lección? Porque los objetos son la columna vertebral de JavaScript. JSON, las configuraciones, el estado de una app, los parámetros de funciones, las respuestas de API... todo son objetos. Dominar su creación, acceso y manipulación es tan fundamental como respirar para un desarrollador JS.

2 · Teoría

Creación de objetos literales

La forma más común y directa de crear objetos es con la sintaxis literal {}:

// Objeto literal: la forma preferida y más común
const persona = {
  nombre: 'Ana',
  edad: 28,
  esEstudiante: false,
  saludar() {
    return `Hola, soy ${this.nombre}`;
  }
};

Analogía: Un objeto es como una ficha de contacto en tu móvil. Tiene campos con nombre (nombre, teléfono, email) y cada campo tiene un valor. No importa el orden de los campos; importa el nombre de cada uno. Puedes añadir, modificar o borrar campos en cualquier momento.

Acceso a propiedades: notación de punto vs corchetes

const user = {
  name: 'Carlos',
  age: 34,
  'home-address': 'Calle Mayor 1' // Propiedad con guiones (necesita corchetes)
};

// Notación de punto (más común, más legible)
user.name;             // 'Carlos'
user.age;              // 34

// Notación de corchetes (para nombres dinámicos o especiales)
user['name'];          // 'Carlos'
user['home-address'];  // 'Calle Mayor 1' ← la notación de punto no funciona aquí

// Los corchetes son OBLIGATORIOS cuando:
// 1. El nombre de propiedad tiene caracteres especiales (guiones, espacios)
// 2. El nombre de propiedad está en una variable
// 3. El nombre de propiedad es una expresión que se evalúa en tiempo de ejecución

Propiedades dinámicas con corchetes

const key = 'favoriteColor';
const value = 'azul';

const obj = {};
obj[key] = value;           // obj.favoriteColor = 'azul'
console.log(obj[key]);      // 'azul'
console.log(obj.favoriteColor); // 'azul'

// Iterar sobre un array de claves para construir objetos dinámicamente
const keys = ['name', 'email', 'role'];
const values = ['María', 'maria@mail.com', 'admin'];
const dynamicObj = {};
keys.forEach((k, i) => { dynamicObj[k] = values[i]; });
console.log(dynamicObj); // { name: 'María', email: 'maria@mail.com', role: 'admin' }

Shorthand properties (ES6)

Cuando el nombre de la propiedad coincide con el nombre de la variable, puedes omitir el valor:

const name = 'Ana';
const age = 28;

// Sin shorthand (verboso)
const old = { name: name, age: age };

// Con shorthand (limpio y moderno)
const modern = { name, age }; // { name: 'Ana', age: 28 }

// También funciona con desestructuración en parámetros
function createUser(name, age) {
  return { name, age }; // Equivalente a { name: name, age: age }
}

Computed property names (ES6)

Puedes usar expresiones como nombres de propiedad dentro del literal:

const prefix = 'user';
const id = 42;

const obj = {
  [prefix + '_id']: id,               // user_id: 42
  [`${prefix}_name`]: 'Admin',        // user_name: 'Admin'
  [new Date().getTime()]: 'created',  // 1696000000000: 'created'
};

console.log(obj.user_id);   // 42
console.log(obj.user_name); // 'Admin'

Iterar sobre objetos

const producto = {
  nombre: 'Laptop',
  precio: 999.99,
  stock: 25,
  categoria: 'Electrónica'
};

// Object.keys() → array de nombres de propiedad
Object.keys(producto);
// ['nombre', 'precio', 'stock', 'categoria']

// Object.values() → array de valores
Object.values(producto);
// ['Laptop', 999.99, 25, 'Electrónica']

// Object.entries() → array de pares [clave, valor]
Object.entries(producto);
// [['nombre', 'Laptop'], ['precio', 999.99], ['stock', 25], ['categoria', 'Electrónica']]

// Iterar con for...of sobre entries
for (const [key, value] of Object.entries(producto)) {
  console.log(`${key}: ${value}`);
}
// nombre: Laptop
// precio: 999.99
// stock: 25
// categoria: Electrónica

Comprobar existencia de propiedades

const user = { name: 'Ana', age: 28 };

// Operador in (comprueba también propiedades heredadas)
'name' in user;     // true
'email' in user;    // false
'toString' in user; // true (heredado del prototipo)

// hasOwnProperty (solo propiedades propias, no heredadas)
user.hasOwnProperty('name');     // true
user.hasOwnProperty('toString'); // false (es heredada)

// Comparación directa con undefined (cuidado: no distingue propiedad inexistente de valor undefined)
user.email === undefined;  // true
user.name === undefined;   // false

Eliminar propiedades

const obj = { a: 1, b: 2, c: 3 };
delete obj.b;      // Elimina la propiedad 'b'
console.log(obj);  // { a: 1, c: 3 }
console.log('b' in obj); // false

Métodos en objetos

// Sintaxis concisa de método (ES6)
const calculadora = {
  valor: 0,

  sumar(n) {
    this.valor += n;
    return this; // Permite encadenamiento
  },

  restar(n) {
    this.valor -= n;
    return this;
  },

  resultado() {
    return this.valor;
  }
};

calculadora.sumar(5).restar(2).sumar(10);
console.log(calculadora.resultado()); // 13

Copiar objetos: Object.assign vs spread

const original = { a: 1, b: 2 };

// Object.assign (ES5): copia propiedades al primer argumento
const copia1 = Object.assign({}, original);

// Spread operator (ES2018): más moderno y legible
const copia2 = { ...original };

// Ambos hacen copia SUPERFICIAL (shallow copy)
// Los objetos anidados se comparten, no se clonan
const conAnidado = { a: 1, nested: { b: 2 } };
const copiaShallow = { ...conAnidado };
copiaShallow.nested.b = 999;
console.log(conAnidado.nested.b); // 999 ← ¡el original también cambió!

// Para copia profunda en objetos simples:
const copiaProfunda = structuredClone(conAnidado);
copiaProfunda.nested.b = 42;
console.log(conAnidado.nested.b); // 999 ← intacto

Destructuring

Extrae propiedades de un objeto y las asigna a variables con nombre en una sola línea:

const persona = {
  nombre: 'Lucía',
  edad: 30,
  ciudad: 'Barcelona',
  trabajo: {
    empresa: 'TechCorp',
    rol: 'Frontend'
  }
};

// Destructuring básico
const { nombre, edad } = persona;
console.log(nombre); // 'Lucía'
console.log(edad);   // 30

// Con alias (renombrar)
const { nombre: name, ciudad: city } = persona;
console.log(name); // 'Lucía'
console.log(city); // 'Barcelona'

// Con valores por defecto
const { pais = 'España' } = persona;
console.log(pais); // 'España' (persona no tiene propiedad 'pais')

// Destructuring anidado
const { trabajo: { empresa, rol } } = persona;
console.log(empresa); // 'TechCorp'

// Rest en destructuring (ES2018)
const { nombre: n, ...resto } = persona;
console.log(n);      // 'Lucía'
console.log(resto);  // { edad: 30, ciudad: 'Barcelona', trabajo: {...} }

// Destructuring en parámetros de función
function mostrarPerfil({ nombre, edad, ciudad = 'No especificada' }) {
  console.log(`${nombre}, ${edad} años, de ${ciudad}`);
}
mostrarPerfil(persona); // 'Lucía, 30 años, de Barcelona'

3 · Ejemplo mínimo

Todas las operaciones esenciales con objetos en un solo ejemplo:

// Crear
const book = {
  title: 'Eloquent JavaScript',
  author: 'Marijn Haverbeke',
  year: 2018,
  tags: ['programming', 'javascript']
};

// Leer
console.log(book.title);              // 'Eloquent JavaScript' (notación punto)
console.log(book['author']);          // 'Marijn Haverbeke' (notación corchetes)

// Añadir propiedades
book.pages = 472;
book['isbn'] = '978-1593279509';

// Modificar
book.year = 2024;                     // Actualizar existente

// Comprobar existencia
console.log('rating' in book);        // false
console.log(book.hasOwnProperty('title')); // true

// Eliminar
delete book.isbn;

// Iterar
for (const [key, value] of Object.entries(book)) {
  console.log(`${key}: ${value}`);
}

// Destructuring
const { title, author, ...metadata } = book;
console.log(title);    // 'Eloquent JavaScript'
console.log(metadata); // { year: 2024, pages: 472, tags: [...] }

4 · Ejemplo real

Sistema de gestión de configuración de usuario con valores por defecto:

// Configuración por defecto de la aplicación
const DEFAULT_CONFIG = {
  theme: 'light',
  language: 'es',
  notifications: {
    email: true,
    push: false,
    frequency: 'daily'
  },
  privacy: {
    showProfile: true,
    showEmail: false
  }
};

// Configuración que viene del usuario (puede estar incompleta)
const userConfig = {
  theme: 'dark',
  notifications: {
    email: false
    // push y frequency no especificados
  }
  // language y privacy no especificados
};

// Merge profundo: la configuración del usuario sobreescribe los defaults
function mergeConfig(defaults, user) {
  const result = { ...defaults }; // Copia superficial de defaults

  for (const key of Object.keys(user)) {
    // Si el valor es un objeto (y no array), hacer merge recursivo
    if (
      typeof user[key] === 'object' &&
      user[key] !== null &&
      !Array.isArray(user[key]) &&
      typeof result[key] === 'object' &&
      result[key] !== null
    ) {
      result[key] = mergeConfig(result[key], user[key]);
    } else {
      result[key] = user[key];
    }
  }

  return result;
}

const finalConfig = mergeConfig(DEFAULT_CONFIG, userConfig);
console.log(finalConfig);
// {
//   theme: 'dark',           ← sobreescrito por el usuario
//   language: 'es',          ← del default
//   notifications: {
//     email: false,          ← sobreescrito
//     push: false,           ← del default
//     frequency: 'daily'     ← del default
//   },
//   privacy: {               ← del default completo
//     showProfile: true,
//     showEmail: false
//   }
// }

5 · Buenas prácticas

HazEvitaPor qué
Usa notación de punto (obj.prop) para propiedades estáticas Usar corchetes cuando no es necesario: obj['prop'] La notación de punto es más corta, más legible y el intérprete la optimiza mejor. Reserva corchetes para propiedades dinámicas
Usa shorthand { name, age } cuando la clave y la variable se llaman igual Escribir { name: name, age: age } El shorthand reduce la duplicación, evita errores de tipeo y es el estándar en código moderno
Usa spread { ...obj } para copias superficiales Usar Object.assign({}, obj) en código nuevo Spread es más legible, más corto y consistente con la sintaxis de arrays. Ambos hacen copia superficial
Usa destructuring para extraer múltiples propiedades Escribir const a = obj.a; const b = obj.b; const c = obj.c; Destructuring reduce líneas, deja clara la intención de extraer y permite valores por defecto y renombrado en una línea
Usa hasOwnProperty para comprobar propiedades propias Usar obj.prop !== undefined como único chequeo Una propiedad puede existir con valor undefined. hasOwnProperty es la única forma fiable de saber si la propiedad existe realmente

6 · Errores habituales

Olvidar que spread hace copia superficial

// ❌ Creer que spread clona objetos anidados
const original = { user: { name: 'Ana', address: { city: 'Madrid' } } };
const copia = { ...original };
copia.user.name = 'María';
console.log(original.user.name); // 'María' ← ¡el original también cambió!

// ✅ Para modificar objetos anidados sin mutar, haz spread en cada nivel
const copiaSegura = {
  ...original,
  user: {
    ...original.user,
    name: 'María' // Solo modifica este nivel
  }
};
console.log(original.user.name); // 'Ana' ← intacto

Usar for...in en lugar de Object.keys/values/entries

const obj = { a: 1, b: 2 };

// ❌ for...in itera sobre propiedades heredadas
for (const key in obj) {
  console.log(key); // a, b, ... y cualquier propiedad del prototipo
}

// ✅ Object.keys + for...of (solo propiedades propias)
for (const key of Object.keys(obj)) {
  console.log(key, obj[key]); // 'a 1', 'b 2'
}

Intentar acceder a propiedades de null/undefined sin optional chaining

// ❌ Esto falla si config es null o undefined
function getTheme(config) {
  return config.user.settings.theme; // TypeError si algo es null
}

// ✅ Con optional chaining es seguro
function getTheme(config) {
  return config?.user?.settings?.theme ?? 'light';
}

console.log(getTheme(null)); // 'light' — no falla

Confundir notación de punto con corchetes en propiedades dinámicas

// ❌ Intentar acceder a una propiedad dinámica con punto
const prop = 'name';
const obj = { name: 'Ana' };
console.log(obj.prop); // undefined — busca literalmente 'prop', no 'name'

// ✅ Usa corchetes para propiedades dinámicas
console.log(obj[prop]); // 'Ana' — evalúa la variable prop

9 · Resumen

  • Creación: {} (objeto literal). La forma más común y directa.
  • Acceso: notación de punto (obj.prop) para propiedades estáticas; corchetes (obj[expr]) para dinámicas.
  • Shorthand: { name, age } es equivalente a { name: name, age: age }.
  • Computed properties: { [expr]: valor } evalúa la expresión como nombre de propiedad.
  • Iteración: Object.keys(), Object.values(), Object.entries() con for...of.
  • Existencia: in (incluye heredadas), hasOwnProperty() (solo propias).
  • Copias: spread { ...obj } para copia superficial. structuredClone() para copia profunda.
  • Destructuring: const { a, b: alias, c = default } = obj; extrae en variables.
  • Los objetos son mutables: modificar una propiedad afecta a todas las referencias que comparten el mismo objeto.

10 · Preguntas frecuentes

¿Cuál es la diferencia entre un objeto y un Map?

Ambos almacenan pares clave-valor, pero con diferencias importantes: (1) Las claves de un objeto solo pueden ser strings o symbols; las de un Map pueden ser cualquier tipo (objetos, números, funciones). (2) Map mantiene el orden de inserción garantizado. (3) Map tiene una API más limpia (get, set, has, delete, size). (4) Map está optimizado para inserciones/eliminaciones frecuentes. Para datos estructurados con claves fijas y conocidas, usa objetos. Para colecciones dinámicas de pares clave-valor, usa Map.

¿Objeto literal o clase? ¿Cuándo usar cada uno?

Usa objetos literales para datos y configuraciones (data objects): respuestas de API, opciones, estado de la app. Usa clases cuando necesites crear múltiples instancias con el mismo comportamiento (métodos compartidos vía prototipo), encapsulación con #private, o herencia. Regla práctica: si solo necesitas una instancia, objeto literal. Si necesitas muchas instancias iguales, clase.

¿Por qué el orden de las propiedades en un objeto no está garantizado?

Históricamente, las propiedades de los objetos no tenían orden garantizado. Desde ES2015, las reglas son: las claves enteras (strings que son números) van primero en orden ascendente, luego las claves string en orden de inserción, y finalmente los symbols en orden de inserción. Si necesitas orden garantizado en todas las situaciones, usa Map.

¿Qué pasa si hago destructuring de una propiedad que no existe?

La variable recibe undefined. No lanza error. Puedes proporcionar un valor por defecto: const { edad = 0 } = persona. Si la propiedad no existe, edad será 0. Esto hace que el destructuring sea muy seguro para trabajar con datos parciales (como respuestas de API que pueden variar).

¿delete es realmente necesario? ¿No basta con asignar undefined?

delete elimina la propiedad del objeto: la clave desaparece, hasOwnProperty devuelve false, Object.keys no la muestra, e in devuelve false. Asignar undefined mantiene la propiedad con valor undefined. La diferencia importa para serialización (JSON.stringify ignora undefined en ambos casos), iteración y comprobaciones de existencia. delete es más lento que asignar undefined (rompe optimizaciones del motor V8), así que si el rendimiento importa y solo necesitas «marcar como vacío», usa obj.prop = undefined. Si necesitas eliminar realmente la propiedad, usa delete.
