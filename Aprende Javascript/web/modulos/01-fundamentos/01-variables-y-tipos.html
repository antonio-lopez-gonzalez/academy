Variables (let, const, var) y tipos primitivos

Módulo 1 · Fundamentos ⏱ 30 minutos

1 · Introducción

Las variables son la unidad más fundamental de cualquier lenguaje de programación: son contenedores con nombre que almacenan datos. Pero en JavaScript, las variables tienen peculiaridades que las hacen distintas a las de otros lenguajes: no declaras el tipo, el tipo puede cambiar en tiempo de ejecución, y hay tres formas distintas de declararlas (let, const, var) con comportamientos radicalmente diferentes.

En esta lección dominarás las diferencias entre let, const y var, entenderás qué es el scope y el hoisting, conocerás los 7 tipos primitivos de JavaScript, y aprenderás a usar typeof y template literals.

¿Por qué existe esta lección? Porque elegir mal entre let, const y var es la fuente de bugs más silenciosos y difíciles de detectar. Entender los tipos primitivos y su inmutabilidad es la base sobre la que se construye todo lo demás.

2 · Teoría

let, const y var: las tres formas de declarar

JavaScript te da tres palabras clave para declarar variables. No son intercambiables; cada una tiene reglas de scope, redeclaración y hoisting distintas.

Scope (ámbito)

El scope determina dónde es visible una variable. var ignora los bloques {}; solo respeta las funciones. let y const respetan cualquier bloque.

if (true) {
  var a = 'visible fuera';   // Scope de función → accesible fuera del if
  let b = 'solo aquí dentro'; // Scope de bloque → no accesible fuera
}
console.log(a); // 'visible fuera' ← funciona (var ignora el bloque)
console.log(b); // ReferenceError: b is not defined ← let respeta el bloque

Analogía: var es como hablar a gritos en una habitación: todos te oyen, incluso en otras habitaciones (dentro de la misma función). let y const son como susurrar: solo quien está dentro del mismo bloque {} te escucha.

Hoisting (elevación)

JavaScript «eleva» las declaraciones de variables al inicio de su scope durante la fase de compilación. Pero var y let/const se comportan distinto:

console.log(x); // undefined (var se eleva e inicializa a undefined)
var x = 5;

console.log(y); // ReferenceError: Cannot access 'y' before initialization
let y = 10;     // let también se eleva, pero entra en TDZ (Temporal Dead Zone)

La TDZ (Temporal Dead Zone) es la región entre el inicio del scope y la línea donde se declara la variable. Acceder a una variable let/const en su TDZ lanza un ReferenceError. Esto es una característica de diseño, no un bug: previene el uso de variables antes de ser declaradas.

¿Cuándo usar cada una?

  • const por defecto. Si no necesitas reasignar, usa const. Comunica intención: «este valor no cambiará».
  • let cuando necesites reasignar. Contadores de bucles, acumuladores, flags que cambian.
  • var nunca en código nuevo. Existe por compatibilidad histórica. No hay razón para usarlo en 2026.

Los 7 tipos primitivos

En JavaScript, todo valor que no es un objeto es un primitivo. Los primitivos son inmutables: no puedes cambiar un primitivo; solo puedes reemplazarlo con un valor nuevo.

TipoEjemplotypeof
string'Hola', "mundo", `template`'string'
number42, 3.14, Infinity, NaN'number'
bigint9007199254740991n'bigint'

nullnull'object' (⚠ bug histórico)

Nota sobre typeof null: Devuelve 'object'. Es un bug histórico de la primera implementación de JavaScript que no se puede corregir sin romper la web. Para comprobar si algo es null, usa valor === null.

Mutabilidad: primitivos vs objetos

// Primitivos: INMUTABLES
let nombre = 'Ana';
nombre.toUpperCase(); // Devuelve 'ANA', pero 'nombre' sigue siendo 'Ana'
console.log(nombre);  // 'Ana' — el valor original no cambió

// Para «cambiar» un primitivo, lo reasignas:
nombre = nombre.toUpperCase(); // Ahora nombre sí es 'ANA'

// Objetos: MUTABLES
const persona = { nombre: 'Ana' };
persona.nombre = 'María'; // ✅ Funciona: mutas la propiedad del objeto
console.log(persona.nombre); // 'María'
// persona = { nombre: 'Otra' }; // ❌ Error: no puedes reasignar const

La diferencia es crucial: con const no puedes reasignar la variable, pero si contiene un objeto, sí puedes mutar las propiedades de ese objeto. const congela la referencia, no el contenido.

Template literals

Los template literals (delimitados por backticks ``) permiten interpolar variables y expresiones con ${}, además de strings multilínea:

const nombre = 'Ana';
const edad = 28;

// Sin template literal (feo y propenso a errores):
const viejo = 'Hola, me llamo ' + nombre + ' y tengo ' + edad + ' años.';

// Con template literal (limpio y legible):
const moderno = `Hola, me llamo ${nombre} y tengo ${edad} años.`;
const calculo = `El año que viene tendré ${edad + 1} años.`;
const multilinea = `
  Línea 1
  Línea 2
  Línea 3
`; // Sí, respeta los saltos de línea

3 · Ejemplo mínimo

// Declaración con const (no se reasigna)
const PI = 3.14159;
const saludo = 'Hola, mundo';

// Declaración con let (se reasigna)
let contador = 0;
contador = contador + 1; // 1
contador += 2;           // 3

// typeof: descubre el tipo de cualquier valor
console.log(typeof 'texto');    // 'string'
console.log(typeof 42);         // 'number'
console.log(typeof true);       // 'boolean'
console.log(typeof undefined);  // 'undefined'
console.log(typeof null);       // 'object' ← bug histórico
console.log(typeof Symbol());   // 'symbol'
console.log(typeof 10n);        // 'bigint'

// Template literal
const precio = 19.99;
console.log(`El precio final es ${precio}€`);

4 · Ejemplo real

Sistema de configuración de una app con valores por defecto y tipos validados:

// config.js — Configuración de una aplicación
const APP_NAME = 'TaskFlow';          // const: nunca cambia
const VERSION = '2.4.1';

let currentUser = null;               // let: cambia cuando el usuario hace login
let isDarkMode = true;                // let: cambia al pulsar el toggle de tema

function validateConfig(config) {
  // typeof para validar tipos en tiempo de ejecución
  if (typeof config.apiUrl !== 'string') {
    throw new Error('apiUrl debe ser un string');
  }
  if (typeof config.maxRetries !== 'number') {
    throw new Error('maxRetries debe ser un número');
  }
  console.log('✅ Configuración válida');
}

// Template literals para mensajes de estado
function getStatusMessage(user, mode) {
  const theme = mode ? 'oscuro' : 'claro';
  const userName = user ?? 'Invitado';  // Nullish coalescing (próxima lección)

  return `[${APP_NAME} v${VERSION}] Usuario: ${userName} | Tema: ${theme}`;
}

// Uso
validateConfig({ apiUrl: 'https://api.ejemplo.com', maxRetries: 3 });
currentUser = 'María';
console.log(getStatusMessage(currentUser, isDarkMode));
// [TaskFlow v2.4.1] Usuario: María | Tema: oscuro

6 · Errores habituales

Usar var sin entender su scope de función

// ❌ var escapa del bloque
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100);
}
// Imprime: 3, 3, 3 (todas las callbacks ven la misma 'i' que ya vale 3)

// ✅ let respeta el bloque: cada iteración tiene su propia 'i'
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100);
}
// Imprime: 0, 1, 2 (cada callback captura su propia 'i')

Confundir «no reasignable» con «inmutable»

// ❌ Creer que const hace el objeto inmutable
const user = { name: 'Ana', age: 28 };
user.age = 29; // ✅ Funciona: mutas el objeto, no reasignas la variable

// ✅ Si quieres inmutabilidad real, usa Object.freeze():
const frozen = Object.freeze({ name: 'Ana', age: 28 });
frozen.age = 29; // ❌ No lanza error en modo normal, pero no cambia nada
// frozen.age = 29; // En strict mode: TypeError
console.log(frozen.age); // 28 (no cambió)

No entender typeof null

// ❌ Asumir que typeof null === 'null'
const valor = null;
if (typeof valor === 'object') {
  console.log('Es un objeto'); // ← Se ejecuta erróneamente
}

// ✅ La forma correcta de comprobar null
if (valor === null) {
  console.log('Es null'); // ← Correcto
}

// ✅ O comprobar «null o undefined» de una vez:
if (valor == null) {
  // '==' con null captura tanto null como undefined
  console.log('Es null o undefined');
}

Mezclar const y let sin criterio

// ❌ Usar let para todo «por si acaso»
let name = 'Ana';     // name nunca se reasigna
let age = 28;         // age nunca se reasigna
let PI = 3.14159;     // PI nunca se reasigna

// ✅ const por defecto, let solo cuando es necesario
const name = 'Ana';
const age = 28;
const PI = 3.14159;
let contador = 0;     // solo esta necesita let porque se reasigna

8 · Reto

🎯 Validador de tipos en runtime

Crea una función describirValor(valor) que reciba cualquier valor y devuelva un string describiendo su tipo y contenido. Requisitos:

  1. Usa typeof para identificar el tipo.
  2. Si es null, debe decir «Tipo: null — Valor: null» (no «object»).
  3. Si es undefined, debe decir «Tipo: undefined — Sin valor asignado».
  4. Si es bigint, debe mostrar el valor seguido de «n».
  5. Si es symbol, debe mostrar su descripción (pista: symbol.description).
  6. Usa template literals para el string de salida.

Pista: recuerda el caso especial de typeof null === 'object'.

9 · Resumen

  • const: scope de bloque, no reasignable, debe inicializarse. Úsala por defecto.
  • let: scope de bloque, reasignable. Úsala cuando el valor necesite cambiar.
  • var: scope de función, redeclarable, hoisting a undefined. Evítala en código nuevo.
  • Hoisting: las declaraciones se elevan; var se inicializa a undefined, let/const entran en TDZ.
  • 7 tipos primitivos: string, number, bigint, boolean, undefined, null, symbol. Todos inmutables.
  • typeof null devuelve 'object' (bug histórico). Comprueba null con === null.
  • Template literals (``) interpola con ${} y soporta strings multilínea.
  • Primitivos son inmutables, objetos son mutables. const congela la referencia, no el contenido.

10 · Preguntas frecuentes

¿Por qué existe var si es tan problemático?

var es la forma original de declarar variables en JavaScript (desde 1995). Cuando se diseñó, la web era mucho más simple y los scripts eran pequeños. Con el tiempo, los problemas de var (scope de función, redeclaración, fuga a window) se hicieron evidentes. ES6 (2015) introdujo let y const para resolver estos problemas, pero var no se puede eliminar por compatibilidad con la web existente.

¿Cuándo debería usar let en vez de const?

Usa let cuando el valor de la variable necesita cambiar durante la ejecución. Ejemplos típicos: contadores en bucles (let i = 0), acumuladores (let total = 0), flags de estado (let isLoading = true), o variables que se reasignan en condicionales. Si no estás seguro, empieza con const; el intérprete te avisará si necesitas cambiarlo a let.

¿Qué es exactamente la TDZ (Temporal Dead Zone)?

La TDZ es la zona entre el inicio del scope (la llave {) y la línea donde se declara la variable con let o const. Durante ese tramo, la variable existe (el motor sabe que está declarada) pero no se puede acceder a ella. Cualquier intento lanza ReferenceError. Es una protección: evita que uses variables antes de declararlas, forzando un orden lógico en el código. var no tiene TDZ: se inicializa a undefined inmediatamente.

¿Qué diferencia hay entre null y undefined?

undefined significa «no se ha asignado ningún valor». Es el valor por defecto de variables no inicializadas, parámetros no pasados y propiedades inexistentes. null significa «ausencia intencional de valor». Lo asigna el programador para indicar «aquí no hay nada, y es a propósito». Regla práctica: nunca asignes undefined manualmente; usa null para representar vacío intencional.

¿Por qué typeof NaN devuelve 'number'?

Porque NaN (Not a Number) es un valor especial del tipo number que representa el resultado de una operación matemática inválida (0/0, parseInt('hola')). Irónicamente, NaN es de tipo número. Es un valor «centinela» que indica «esta operación numérica no produjo un número válido». Para comprobar si un valor es NaN, usa Number.isNaN(valor), no valor === NaN (porque NaN !== NaN, otra rareza del estándar IEEE 754).
