Funciones declaradas, expresadas y arrow functions

Módulo 2 · Control de flujo y funciones ⏱ 30 minutos

1 · Introducción

Una función es el bloque de construcción más importante en JavaScript. Sin funciones, el código sería una secuencia lineal imposible de mantener. Las funciones encapsulan lógica, permiten reutilización, crean su propio scope, y son la base de la programación funcional, la asincronía y los módulos. En JavaScript, las funciones no son solo subrutinas: son ciudadanos de primera clase, lo que significa que puedes tratarlas como cualquier otro valor: asignarlas a variables, pasarlas como argumento, devolverlas desde otras funciones y almacenarlas en estructuras de datos.

En esta lección explorarás las cuatro formas principales de crear funciones en JavaScript y entenderás exactamente cuándo y por qué usar cada una.

2 · Teoría

Función declarada (Function Declaration)

La forma más clásica. Tiene hoisting completo: el motor de JavaScript eleva toda la declaración al principio de su scope, por lo que puedes invocarla antes de donde aparece en el código.

// Puedes llamarla ANTES de declararla gracias al hoisting
console.log(sumar(3, 4)); // 7

function sumar(a, b) {
  return a + b;
}

Cuando el motor ejecuta el código, primero escanea todas las declaraciones de función y las registra en memoria. Luego ejecuta el código línea por línea. Por eso la llamada a sumar funciona incluso antes de su definición aparente.

Función expresada (Function Expression)

Aquí la función se crea en tiempo de ejecución como parte de una expresión de asignación. No tiene hoisting de la función — solo el hoisting de la variable (var → undefined; let/const → TDZ).

// ❌ Error: Cannot access 'restar' before initialization (con let/const)
restar(10, 3);

const restar = function (a, b) {
  return a - b;
};

Las funciones expresadas pueden ser anónimas (sin nombre) o nombradas (el nombre solo es visible dentro de la propia función, útil para recursión y stack traces):

const factorial = function fact(n) {
  if (n <= 1) return 1;
  return n * fact(n - 1); // 'fact' es visible aquí dentro, no fuera
};
// factorial(5) → 120
// fact(5) → ReferenceError: fact is not defined

Arrow Function (ES6)

Las flechas introducen una sintaxis concisa con tres diferencias fundamentales respecto a las funciones tradicionales:

  1. No tienen su propio this: heredan el this del scope léxico donde se definen.
  2. No tienen arguments: debes usar rest parameters (...args).
  3. No pueden usarse como constructores: lanzan error con new.
// Sintaxis completa
const multiplicar = (a, b) => {
  return a * b;
};

// Retorno implícito (sin llaves, una sola expresión)
const duplicar = x => x * 2;           // un parámetro: sin paréntesis
const sumar2 = (a, b) => a + b;        // múltiples: paréntesis obligatorios

// Devolver un objeto literal: necesita paréntesis adicionales
const crearPersona = (nombre, edad) => ({ nombre, edad });

// Sin parámetros
const saludar = () => "¡Hola!";

Analogía: una función declarada es como un edificio permanente — siempre está ahí desde el inicio de tu código. Una función expresada es como una tienda de campaña que montas cuando pasas por esa línea. Una arrow function es como un espejo: refleja el this y los argumentos del lugar donde la creaste.

IIFE (Immediately Invoked Function Expression)

Una función que se define y se ejecuta inmediatamente. Era el patrón estándar para crear scopes privados antes de que existieran let/const y los módulos ES:

// IIFE clásica
(function () {
  const secreto = "nadie puede verme";
  console.log(secreto); // "nadie puede verme"
})();

console.log(typeof secreto); // "undefined" — el scope está aislado

// IIFE con arrow function
(() => {
  console.log("Ejecutada inmediatamente");
})();

Funciones como ciudadanos de primera clase

En JavaScript, las funciones son objetos. Puedes hacer con ellas todo lo que haces con cualquier otro valor:

// Asignar a variable
const fn = function() { return 42; };

// Pasar como argumento (callback)
function ejecutar(operacion, a, b) {
  return operacion(a, b);
}
console.log(ejecutar((x, y) => x + y, 3, 4)); // 7

// Devolver desde otra función
function crearMultiplicador(factor) {
  return (numero) => numero * factor;  // devuelve una función
}
const doblar = crearMultiplicador(2);
console.log(doblar(5)); // 10

// Almacenar en estructuras de datos
const operaciones = {
  suma: (a, b) => a + b,
  resta: (a, b) => a - b,
};
console.log(operaciones.suma(10, 5)); // 15

Callbacks básicos

Un callback es simplemente una función que se pasa como argumento a otra función para que la ejecute en algún momento. Es el patrón fundamental de la asincronía en JavaScript:

function procesarDatos(datos, callback) {
  const resultado = datos.map(x => x * 2);   // transformar
  callback(resultado);                         // delegar el resultado
}

procesarDatos([1, 2, 3], (resultado) => {
  console.log(`Procesado: ${resultado}`); // "Procesado: 2,4,6"
});

3 · Ejemplo mínimo

// Las tres formas de crear una función que suma dos números:

// 1. Declarada — hoisting, siempre disponible en su scope
function sumaDeclarada(a, b) {
  return a + b;
}

// 2. Expresada — solo existe tras esta línea
const sumaExpresada = function (a, b) {
  return a + b;
};

// 3. Arrow — retorno implícito, no tiene this propio
const sumaArrow = (a, b) => a + b;

console.log(sumaDeclarada(2, 3));  // 5
console.log(sumaExpresada(2, 3));  // 5
console.log(sumaArrow(2, 3));      // 5

Las tres hacen lo mismo. La diferencia está en cuándo existen (hoisting) y en cómo tratan this, arguments y new. Para funciones puras que no usan this, las flechas suelen ser la opción más limpia.

4 · Ejemplo real

Un mini-sistema de eventos con listeners (patrón pub/sub):

// Fábrica de emisores de eventos usando IIFE + closure + callbacks
const crearEventEmitter = () => {
  const listeners = {}; // objeto privado gracias al closure

  return {
    // Arrow function: hereda el this del contexto de creación (el objeto devuelto)
    on: (evento, callback) => {
      if (!listeners[evento]) listeners[evento] = [];
      listeners[evento].push(callback); // callback es una función ciudadano de primera clase
    },

    emit: (evento, datos) => {
      const callbacks = listeners[evento];
      if (callbacks) {
        callbacks.forEach(cb => cb(datos)); // ejecutar cada callback con los datos
      }
    },
  };
};

const emitter = crearEventEmitter();

// Pasamos callbacks como funciones flecha
emitter.on("mensaje", (data) => console.log(`📩 ${data}`));
emitter.on("mensaje", (data) => console.log(`📋 Registrado: ${data}`));

emitter.emit("mensaje", "Hola mundo");
// 📩 Hola mundo
// 📋 Registrado: Hola mundo

Este patrón es la columna vertebral de React (hooks), Node.js (EventEmitter), y prácticamente cualquier arquitectura guiada por eventos. Observa cómo combinamos una IIFE (para encapsular listeners), un closure (el objeto devuelto accede a listeners), y callbacks como ciudadanos de primera clase.

5 · Buenas prácticas

Usa flechas para callbacks y funciones puras Usar flechas como métodos de objeto que necesitan this Las flechas heredan el this léxico; si el método necesita acceder al objeto propietario, usa función tradicional
Usa funciones declaradas en el ámbito global/de módulo Usar flechas para funciones de alto nivel Las declaradas tienen hoisting y nombres en stack traces; las flechas anónimas dificultan el debugging

6 · Errores habituales

1. Usar arrow function como método de objeto

// ❌ MAL: arrow function no tiene su propio this
const persona = {
  nombre: "Ana",
  saludar: () => {
    console.log(`Hola, soy ${this.nombre}`); // this NO es persona
  },
};
persona.saludar(); // "Hola, soy undefined"

// ✅ BIEN: función tradicional como método
const persona2 = {
  nombre: "Ana",
  saludar() {  // sintaxis concisa de método (ES6)
    console.log(`Hola, soy ${this.nombre}`);
  },
};
persona2.saludar(); // "Hola, soy Ana"

2. Intentar usar new con arrow function

// ❌ MAL
const Persona = (nombre) => { this.nombre = nombre; };
const p = new Persona("Ana"); // TypeError: Persona is not a constructor

// ✅ BIEN
function Persona(nombre) {
  this.nombre = nombre;
}
const p = new Persona("Ana"); // OK

3. Olvidar los paréntesis al devolver un objeto

// ❌ MAL: las llaves se interpretan como cuerpo de la función
const crearObj = (nombre) => { nombre };
console.log(crearObj("Ana")); // undefined

// ✅ BIEN: paréntesis adicionales para devolver objeto literal
const crearObj2 = (nombre) => ({ nombre });
console.log(crearObj2("Ana")); // { nombre: "Ana" }

7 · Ejercicio guiado

Enunciado: Crea una función crearCalculadora que devuelva un objeto con cuatro operaciones (suma, resta, multiplica, divide). Cada operación debe poder ejecutarse como calc.suma(5) y también como calc.suma(5, 3). Usa tres estilos distintos: método conciso, función expresada nombrada y arrow function con retorno implícito.

Solución:

  1. Método conciso (ES6) para la operación principal:

    const crearCalculadora = () => ({
  valor: 0,
  suma(a, b) {
    this.valor = b !== undefined ? a + b : this.valor + a;
    return this;
  },
  // ...

  2. Función expresada nombrada para resta:

      resta: function restar(a, b) {
    this.valor = b !== undefined ? a - b : this.valor - a;
    return this;
  },

  3. Arrow function con retorno implícito para multiplica:

      multiplica: (a, b) => {
    // ¡ERROR DIDÁCTICO! Arrow no tiene su propio this
    // this.valor aquí NO es el del objeto calculadora
    // Para que funcione, necesitamos mantener una referencia externa
  },

Solución final corregida (método conciso para todo lo que use this):

const crearCalculadora = () => ({
  valor: 0,
  suma(a, b) {
    this.valor = b !== undefined ? a + b : this.valor + a;
    return this;
  },
  resta(a, b) {
    this.valor = b !== undefined ? a - b : this.valor - a;
    return this;
  },
  get resultado() { return `Resultado: ${this.valor}`; },
});

const calc = crearCalculadora();
calc.suma(10).resta(3);
console.log(calc.resultado); // "Resultado: 7"

8 · Reto

🎯 Sistema de plugins extensible

Crea una función crearPipeline() que devuelva un objeto con estos métodos:

  • .use(plugin): registra una función plugin. Cada plugin es una función que recibe el valor actual y el siguiente plugin (next).
  • .exec(valorInicial): ejecuta todos los plugins en orden, pasando el resultado de uno al siguiente.
  • Los plugins deben poder decidir si llaman a next() o cortan la cadena.
  • Usa callbacks y funciones como ciudadanos de primera clase.

Inspiración: el patrón middleware de Express.js o los hooks de Vite.

9 · Resumen

  • Funciones declaradas: hoisting completo, ideales para funciones de alto nivel con nombre.
  • Funciones expresadas: sin hoisting, útiles para asignación condicional o callbacks nombrados.
  • Arrow functions: sintaxis concisa, retorno implícito, no tienen this, arguments ni new. Perfectas para callbacks y funciones puras.
  • IIFE: ejecutar inmediatamente y aislar scope. Menos necesarias desde ES6 pero aún presentes en patrones legacy.
  • Ciudadanos de primera clase: las funciones son valores: se asignan, se pasan, se devuelven, se almacenan.
  • Callbacks: funciones pasadas como argumento, la base de la asincronía y los patrones de eventos.

10 · Preguntas frecuentes

¿Por qué no puedo usar this en una arrow function?

Porque las arrow functions no crean su propio contexto de ejecución para this. En su lugar, capturan el this del scope donde se definen (scope léxico). Esto es una ventaja para callbacks en clases o componentes, pero un problema si necesitas que this apunte al objeto que invoca la función.

¿Qué sintaxis de función es la más rápida?

Prácticamente idénticas. Los motores modernos (V8) optimizan los tres tipos por igual. La diferencia de rendimiento está en el código que hay dentro, no en cómo declaras la función. Elige basándote en legibilidad y en si necesitas this, arguments o new.

¿Cuándo usar IIFE en código moderno?

Raramente. Desde ES6, los módulos y let/const con scope de bloque cubren los casos de uso de las IIFE. Aún las verás en código legacy, en el patrón módulo revelador, o cuando necesitas un scope aislado dentro de un script inline. En código nuevo, prefiere módulos ES.

¿JavaScript pasa los argumentos por valor o por referencia?

JavaScript siempre pasa argumentos por valor. Pero para objetos y arrays, ese valor es una referencia al objeto. Esto significa que si modificas propiedades de un objeto dentro de una función, el cambio se refleja fuera (porque ambos apuntan al mismo objeto), pero si reasignas el parámetro (obj = {}), no afecta al exterior.
