Bucles (for, while, do-while, for...of, for...in)

Módulo 2 · Control de flujo y funciones ⏱ 35 minutos

1 · Introducción

Los bucles son la herramienta que permite a un programa repetir acciones sin repetir código. En lugar de escribir 100 líneas para procesar 100 elementos, escribes 3 líneas dentro de un bucle. JavaScript ofrece cinco mecanismos de iteración, cada uno diseñado para un escenario distinto. Elegir mal el bucle es como usar un destornillador para clavar un clavo: funciona, pero no es lo óptimo.

En esta lección aprenderás cuándo usar cada tipo de bucle, cómo controlar el flujo con break/continue/labels, y por qué forEach no siempre es la mejor opción a pesar de ser el favorito de muchos.

¿Por qué tantos tipos de bucle? Porque iterar sobre un array es distinto de iterar sobre un objeto, y repetir hasta que se cumpla una condición es distinto de repetir un número fijo de veces. JavaScript te da la herramienta precisa para cada caso.

2 · Teoría

for clásico

El más veterano y el más flexible. Su sintaxis en tres partes es un estándar que comparten C, Java, C# y muchos otros lenguajes:

//    inicialización   ;   condición    ;   actualización
for (let i = 0;         i < 5;           i++) {
  console.log(`Iteración ${i}`);
}
// 0, 1, 2, 3, 4 — se ejecuta MIENTRAS la condición sea true

La inicialización se ejecuta una sola vez. Luego, en cada iteración: evalúa condición → ejecuta cuerpo → ejecuta actualización. Cuando la condición es false, el bucle termina.

while: condición al principio

Ejecuta el bloque mientras la condición sea verdadera. La condición se evalúa antes de cada iteración, por lo que puede que el cuerpo no se ejecute ni una vez.

let saldo = 100;
while (saldo > 0) {
  saldo -= 20;  // retirar 20€ cada iteración
  console.log(`Saldo restante: ${saldo}`);
}
// termina cuando saldo deja de ser > 0

do-while: condición al final

Garantiza que el cuerpo se ejecuta al menos una vez, porque la condición se evalúa después.

let intentos = 0;
do {
  intentos++;
  console.log(`Intento ${intentos}`);
} while (intentos < 3);
// siempre imprime al menos "Intento 1"

Analogía: while es "mira antes de cruzar". do-while es "cruza y luego mira". En el mundo real, do-while se usa mucho menos (quizá un 5% de las veces), pero es perfecto para escenarios como "pedir input al usuario al menos una vez".

for...of: el bucle moderno para iterables

Introducido en ES6, itera sobre valores de cualquier objeto iterable: arrays, strings, Map, Set, NodeList, arguments, generadores...

const frutas = ["manzana", "pera", "uva"];

for (const fruta of frutas) {
  console.log(fruta);  // "manzana", "pera", "uva"
}

for (const letra of "Hola") {
  console.log(letra);  // "H", "o", "l", "a"
}

for...of respeta break y continue, a diferencia de forEach. Si necesitas acceso al índice, usa .entries():

for (const [indice, fruta] of frutas.entries()) {
  console.log(`${indice}: ${fruta}`);  // "0: manzana", "1: pera", "2: uva"
}

for...in: para propiedades de objetos (con precaución)

Itera sobre las claves enumerables de un objeto, incluyendo las heredadas de la cadena de prototipos. Por eso casi siempre debes combinarlo con hasOwnProperty o usar Object.keys() en su lugar:

const persona = { nombre: "Ana", edad: 28 };

// for...in recorre claves (y las heredadas si las hay)
for (const clave in persona) {
  console.log(clave);       // "nombre", "edad"
  console.log(persona[clave]); // "Ana", 28
}

// más seguro: Object.keys(), Object.values(), Object.entries()
Object.entries(persona).forEach(([clave, valor]) => {
  console.log(`${clave}: ${valor}`);
});

Regla de oro: for...of para arrays e iterables. for...in para objetos (con hasOwnProperty). Nunca al revés: for...in sobre arrays itera sobre índices como strings y puede incluir propiedades no numéricas.

break, continue y labels

// break: sale del bucle completamente
for (let i = 0; i < 10; i++) {
  if (i === 5) break;     // sale en la iteración 5
  console.log(i);          // 0, 1, 2, 3, 4
}

// continue: salta a la siguiente iteración
for (let i = 0; i < 5; i++) {
  if (i === 2) continue;  // se salta el 2
  console.log(i);          // 0, 1, 3, 4
}

// label: romper bucles anidados desde dentro
exterior: for (let i = 0; i < 3; i++) {
  for (let j = 0; j < 3; j++) {
    if (i === 1 && j === 1) break exterior;  // sale de ambos bucles a la vez
    console.log(`${i},${j}`);
  }
}

forEach vs for...of

const numeros = [1, 2, 3, 4, 5];

// forEach: NO puedes usar break ni continue
numeros.forEach((num) => {
  if (num === 3) return;  // esto NO rompe el bucle, solo sale del callback actual
  console.log(num);       // 1, 2, 4, 5 — el return actúa como continue
});

// for...of: sí puedes usar break
for (const num of numeros) {
  if (num === 3) break;   // esto SÍ rompe el bucle
  console.log(num);       // 1, 2
}

forEach no puede romperse, no puede usar await correctamente dentro, y es más lento que for...of (aunque la diferencia es mínima en la mayoría de casos). Su ventaja es la legibilidad en cadenas funcionales.

Bucles infinitos

Ocurren cuando la condición nunca se vuelve false. El navegador o Node.js congelarán la pestaña/proceso:

// ❌ BUCLE INFINITO: i nunca cambia
for (let i = 0; i < 10;) {
  console.log(i);  // imprime 0 eternamente
}

// ❌ BUCLE INFINITO: condición siempre true
while (true) {
  // sin break, esto nunca termina
}

Rendimiento básico de bucles

Reglas generales para código no crítico (en perfiles de rendimiento real, la diferencia es ínfima):

  1. Cachea la longitud en bucles for clásicos: for (let i = 0, len = arr.length; i < len; i++)
  2. Nunca uses for...in para arrays: recorre propiedades enumerables, no solo índices
  3. Prefiere for...of sobre forEach si necesitas break, continue o await
  4. Los motores modernos (V8, SpiderMonkey) optimizan for...of casi al nivel de un for clásico

3 · Ejemplo mínimo

const datos = [10, 20, 30, 40, 50];

// Sumar todos los elementos con cada tipo de bucle

// for clásico — explícito y control total
let suma1 = 0;
for (let i = 0; i < datos.length; i++) {
  suma1 += datos[i];
}

// for...of — más limpio, sin índice
let suma2 = 0;
for (const num of datos) {
  suma2 += num;
}

// while — control manual de índice
let suma3 = 0;
let idx = 0;
while (idx < datos.length) {
  suma3 += datos[idx];
  idx++;
}

console.log(suma1, suma2, suma3); // 150, 150, 150

4 · Ejemplo real

Procesar un array de pedidos con distintas reglas de negocio:

const pedidos = [
  { id: 1, total: 25, estado: "pendiente" },
  { id: 2, total: 100, estado: "enviado" },
  { id: 3, total: 50, estado: "cancelado" },
  { id: 4, total: 200, estado: "pendiente" },
];

// Calcular total de pedidos pendientes (no cancelados) y detenerse si pasamos de 300€
let totalPendiente = 0;

for (const pedido of pedidos) {
  if (pedido.estado === "cancelado") continue; // saltar cancelados
  totalPendiente += pedido.total;

  if (totalPendiente > 300) {
    console.log(`Límite de riesgo alcanzado: ${totalPendiente}€`);
    break; // dejar de procesar
  }
}

console.log(`Total procesado: ${totalPendiente}€`); // 325€

Este patrón es real en sistemas de pago o inventario: iteras una lista, aplicas filtros con continue, y tienes un cortafuegos con break por si se supera un umbral de riesgo.

6 · Errores habituales

1. Usar for...in en arrays

// ❌ MAL: recorre claves como strings, incluye propiedades del prototipo
const arr = [10, 20, 30];
for (const i in arr) {
  console.log(typeof i); // "string", no number
}

// ✅ BIEN
for (const val of arr) {
  console.log(val);
}
// o si necesitas índice:
arr.forEach((val, i) => console.log(val, i));

2. Modificar el array mientras se itera

// ❌ MAL: mutar el array durante la iteración produce resultados impredecibles
const items = [1, 2, 3, 4];
for (let i = 0; i < items.length; i++) {
  if (items[i] === 2) items.splice(i, 1); // ¡cuidado! los índices se desplazan
}

// ✅ BIEN: construye un nuevo array o itera al revés
const items2 = [1, 2, 3, 4];
for (let i = items2.length - 1; i >= 0; i--) {
  if (items2[i] === 2) items2.splice(i, 1); // al revés no hay desplazamiento
}

3. Crear funciones dentro de bucles

// ❌ MAL: crear una función en cada iteración es costoso
for (const item of items) {
  document.getElementById("btn").addEventListener("click", () => {
    console.log(item); // cada iteración crea una nueva función
  });
}

// ✅ BIEN: crea la función fuera y pasa el dato como parámetro o usa delegación
function manejarClick(item) {
  return () => console.log(item);
}
const btn = document.getElementById("btn");
for (const item of items) {
  btn.addEventListener("click", manejarClick(item));
}

7 · Ejercicio guiado

Enunciado: Crea una función buscarPrimerPar(numeros) que devuelva el primer número par del array. Si no hay ninguno, devuelve null. Usa tres tipos de bucle distintos para implementarlo y compara.

Solución:

  1. Con for clásico:

    function buscarPrimerParFor(numeros) {
  for (let i = 0; i < numeros.length; i++) {
    if (numeros[i] % 2 === 0) {
      return numeros[i]; // return rompe el bucle automáticamente
    }
  }
  return null;
}

  2. Con for...of:

    function buscarPrimerParForOf(numeros) {
  for (const num of numeros) {
    if (num % 2 === 0) return num;
  }
  return null;
}

  3. Con while (más control manual):

    function buscarPrimerParWhile(numeros) {
  let i = 0;
  while (i < numeros.length) {
    if (numeros[i] % 2 === 0) return numeros[i];
    i++;
  }
  return null;
}

Los tres son válidos. for...of es el más limpio cuando no necesitas el índice. La lección es que return dentro de un bucle es una forma limpia de salir temprano sin break.

8 · Reto

🎯 Torre de control aérea

Crea una función gestionarVuelos(vuelos, pista) que procese un array de objetos vuelo. Cada vuelo tiene { id, origen, altitud, combustible }.

  • Si un vuelo tiene combustible < 10, debe aterrizar de emergencia (imprimir mensaje y usar break porque la pista queda ocupada).
  • Si un vuelo tiene altitud < 1000, está en aproximación (usa continue para saltarlo, aterrizará después).
  • Usa un bucle anidado con label para simular varios intentos de contacto por radio (bucle interior de 3 intentos) antes de dar el vuelo por perdido.
  • La función debe devolver un resumen: { aterrizados, enEspera, perdidos }.

9 · Resumen

  • for clásico: control total del índice. Útil cuando necesitas manipular la posición.
  • while: cuando la condición de salida depende de algo externo o desconocido de antemano.
  • do-while: garantiza al menos una ejecución. Ideal para pedir input.
  • for...of: el bucle por defecto para arrays e iterables. Limpio, legible, soporta break/continue/await.
  • for...in: solo para objetos, y siempre con hasOwnProperty o mejor usa Object.entries().
  • forEach: funcional y encadenable, pero sin break, continue ni buen soporte de await.
  • break sale del bucle, continue salta a la siguiente iteración.
  • Los labels permiten romper bucles anidados desde el interior.
  • Nunca mutar un array mientras se recorre hacia adelante; si tienes que mutar, recórrelo al revés.

10 · Preguntas frecuentes

¿Cuál es la diferencia real entre for...of y forEach?

for...of es una sentencia del lenguaje que itera sobre cualquier iterable y permite break, continue, return (que sale de la función contenedora) y await. forEach es un método de Array que recibe un callback y no puede romperse ni usar await correctamente. Si necesitas control de flujo, usa for...of. Si estás en una cadena funcional (.filter().map().forEach()), usa forEach.

¿Por qué for...in es peligroso con arrays?

Porque for...in itera sobre todas las propiedades enumerables, no solo los índices numéricos. Si alguien añadió un método al prototipo de Array (mala práctica, pero posible), aparecerá en tu bucle. Además, los índices se devuelven como strings ("0", no 0), y el orden no está garantizado.

¿Debería preocuparme por el rendimiento de los bucles?

Solo si procesas más de 100,000 elementos o estás en un hot path (animaciones, WebGL). La diferencia entre for, for...of y forEach es de microsegundos en la mayoría de casos. Prioriza la legibilidad y la corrección. Si necesitas micro-optimizar, mide con performance.now() o el Profiler de Chrome.

¿Se puede usar await dentro de un forEach?

No correctamente. forEach no espera a que las promesas del callback se resuelvan. Todas las iteraciones se disparan a la vez. Si necesitas iteración secuencial con await, usa for...of. Si quieres paralelismo, usa Promise.all(arr.map(async ...)).
