AbortController, timeouts y cancelación de peticiones

Módulo 6 · Asincronía y APIs ⏱ 25 minutos

1 · Introducción

Imagina un buscador con autocompletado: cada vez que el usuario pulsa una tecla, se lanza una petición fetch. Si escribe rápido, puedes tener 10 peticiones volando simultáneamente. La petición de la tecla "a" puede tardar más en responder que la de "ab", y cuando llega, sobrescribe los resultados más recientes. Esto se llama race condition.

Peor aún: si el usuario navega a otra página, todas esas peticiones siguen consumiendo ancho de banda y memoria, aunque sus resultados ya no le importan a nadie.

AbortController (parte de la Web API, estandarizado en 2019) permite cancelar peticiones fetch, timers y cualquier operación asíncrona que acepte una signal. Es el mecanismo canónico para decir "ya no me interesa este resultado".

¿Por qué necesitas cancelar peticiones?

Sin cancelación: (1) consumes ancho de banda innecesario, (2) el rendimiento baja por peticiones huérfanas, (3) tu UI puede mostrar datos obsoletos que llegaron tarde, y (4) en apps React/Vue/SPA, los efectos sin cleanup producen memory leaks y warnings setState on unmounted.

2 · Teoría

AbortController y AbortSignal

AbortController es una interfaz que te permite abortar una o varias operaciones asíncronas. Tiene dos componentes:

  • controller.signal: un objeto AbortSignal que se pasa a la operación asíncrona (a fetch, a addEventListener, a cualquier API que acepte signals).
  • controller.abort(reason?): método que dispara la cancelación. Opcionalmente recibe una razón (string o Error) que será el motivo.

Cuando se llama a abort(), la señal cambia su propiedad signal.aborted a true y dispara el evento abort en el signal. La operación que recibió ese signal (fetch, por ejemplo) rechazará su promesa con un DOMException de nombre 'AbortError'.

Propiedades y métodos del AbortSignal

  • signal.aborted (boolean): true si ya se ha abortado.
  • signal.reason: el motivo del aborto (lo que pasaste a abort(reason)). Por defecto es un DOMException con nombre 'AbortError'.
  • signal.throwIfAborted(): lanza la razón si la señal ya está abortada. Útil al inicio de una función asíncrona.
  • signal.addEventListener('abort', fn): escucha el evento de aborto. Ideal para limpiar recursos.
  • AbortSignal.timeout(ms) (método estático): crea un signal que se auto-aborta tras ms milisegundos. ES2023+.
  • AbortSignal.any([signal1, signal2, ...]) (método estático): combina varios signals; se aborta si cualquiera de ellos se aborta. ES2023+.
AbortSignal.timeout() — la forma moderna de hacer timeout

Antes de AbortSignal.timeout(), tenías que crear manualmente un AbortController y un setTimeout para abortarlo. Ahora puedes hacer fetch(url, { signal: AbortSignal.timeout(3000) }) y la petición se cancelará automáticamente tras 3 segundos. Mucho más limpio que el truco de Promise.race.

Distinguiendo AbortError de otros errores

Cuando cancelas un fetch, este rechaza con un DOMException llamado 'AbortError'. Debes distinguirlo de otros errores (red, HTTP) para no tratar una cancelación intencionada como un error de aplicación:

try {
  const res = await fetch(url, { signal });
} catch (error) {
  if (error.name === 'AbortError') {
    console.log('Petición cancelada intencionadamente');
    return; // No es un error real
  }
  console.error('Error real:', error); // Red, DNS, etc.
}

Race condition: el problema real

Sin AbortController, dos peticiones fetch pueden llegar en orden inverso:

// SIN cancelación: riesgo de race condition
async function buscar(termino) {
  const resultados = await fetch(`/api/search?q=${termino}`).then(r => r.json());
  mostrarResultados(resultados);
  // Si el usuario escribe "a" y luego "ab" muy rápido,
  // los resultados de "a" pueden llegar DESPUÉS de los de "ab"
  // y sobrescribir la UI con datos obsoletos.
}

Cancelación en React (useEffect cleanup)

En React, cancelar peticiones en el cleanup de useEffect evita el temido warning "Can't perform a React state update on an unmounted component":

useEffect(() => {
  const controller = new AbortController();

  fetch(`/api/usuario/${id}`, { signal: controller.signal })
    .then(r => r.json())
    .then(setUsuario)
    .catch(err => {
      if (err.name !== 'AbortError') setError(err);
    });

  return () => controller.abort(); // Cleanup: cancela si el componente se desmonta
}, [id]);

3 · Ejemplo mínimo

// 🧪 Ejemplo mínimo: cancelar un fetch tras 1.5 segundos
const controller = new AbortController();

// Iniciamos un fetch que tarda 5 segundos (simulado)
async function cargarDatos() {
  try {
    const response = await fetch(
      'https://httpbin.org/delay/5', // Esta API tarda 5s en responder
      { signal: controller.signal }   // Pasamos el signal
    );

    const data = await response.json();
    console.log('✅ Datos recibidos:', data);
  } catch (error) {
    if (error.name === 'AbortError') {
      console.log('🚫 Petición cancelada por el usuario');
    } else {
      console.error('❌ Error:', error.message);
    }
  }
}

cargarDatos();

// Cancelamos tras 1.5 segundos (antes de que responda)
setTimeout(() => {
  controller.abort(); // Esto hará que fetch rechace con AbortError
  console.log('📢 Se llamó a abort()');
}, 1500);

// Salida esperada:
// (tras 1.5s) → "📢 Se llamó a abort()"
//              → "🚫 Petición cancelada por el usuario"

4 · Ejemplo real

Buscador con autocompletado que cancela peticiones anteriores

/**
 * Buscador que cancela automáticamente peticiones anteriores
 * y evita race conditions. Patrón profesional para cualquier
 * input de búsqueda en tiempo real.
 */
class BuscadorConCancelacion {
  constructor(inputSelector, onResultados) {
    this.input = document.querySelector(inputSelector);
    this.onResultados = onResultados;
    this.controller = null; // Guardamos referencia al controller actual

    this.input.addEventListener('input', (e) => {
      this.buscar(e.target.value);
    });
  }

  async buscar(termino) {
    // Cancelar la petición anterior si existe
    if (this.controller) {
      this.controller.abort('Nueva búsqueda iniciada');
    }

    // Si el término está vacío, no buscamos
    if (!termino.trim()) {
      this.onResultados([]);
      return;
    }

    // Crear un nuevo controller para esta petición
    this.controller = new AbortController();

    try {
      // Simulamos una API que tarda entre 200ms y 800ms
      const response = await fetch(
        `https://api.ejemplo.com/search?q=${encodeURIComponent(termino)}`,
        { signal: this.controller.signal }
      );

      if (!response.ok) {
        throw new Error(`HTTP ${response.status}`);
      }

      const data = await response.json();
      this.onResultados(data.results);
    } catch (error) {
      // Ignorar AbortError: es una cancelación intencionada
      if (error.name === 'AbortError') {
        console.log(`🛑 Búsqueda cancelada: "${termino}"`);
        return;
      }
      console.error('❌ Error de búsqueda:', error.message);
      throw error;
    }
  }
}

// Uso: instanciamos el buscador conectado a un input de la página
const buscador = new BuscadorConCancelacion('#buscador', (resultados) => {
  console.log(`📋 ${resultados.length} resultados encontrados`);
  // Actualizar el DOM con los resultados...
});

Cancelar múltiples peticiones con un mismo controller

/**
 * Carga un dashboard con 3 métricas en paralelo.
 * Si el usuario sale de la página, cancelamos TODO.
 */
async function cargarDashboard() {
  const controller = new AbortController();
  const { signal } = controller;

  try {
    const [users, sales, alerts] = await Promise.all([
      fetch('/api/metrics/users', { signal }).then(r => r.json()),
      fetch('/api/metrics/sales', { signal }).then(r => r.json()),
      fetch('/api/metrics/alerts', { signal }).then(r => r.json()),
    ]);

    return { users, sales, alerts };
  } catch (error) {
    if (error.name === 'AbortError') {
      console.log('📴 Dashboard cerrado, peticiones canceladas');
      return null;
    }
    throw error;
  } finally {
    controller.abort(); // Limpieza siempre
  }
}

// Señal de cleanup cuando el usuario sale de la página/componente
const dashboardController = new AbortController();
cargarDashboardConCleanup(dashboardController.signal);

// En una SPA, cuando el usuario navega a otra vista:
// dashboardController.abort('Navegación a otra página');

Timeout moderno con AbortSignal.timeout()

async function fetchConTimeout(url, ms) {
  // AbortSignal.timeout se auto-aborta tras 'ms' milisegundos
  return fetch(url, { signal: AbortSignal.timeout(ms) });
}

async function ejemplo() {
  try {
    const res = await fetchConTimeout('https://httpbin.org/delay/5', 2000);
    console.log('OK:', await res.json());
  } catch (error) {
    if (error.name === 'AbortError') {
      console.error('⏰ Timeout: la petición tardó demasiado');
    } else if (error.name === 'TimeoutError') {
      // Algunas APIs (como fetch en Node) pueden lanzar TimeoutError
      console.error('⏰ TimeoutError');
    } else {
      console.error('Error:', error.message);
    }
  }
}

6 · Errores habituales

Error 1: No distinguir AbortError de errores reales

// ❌ MAL: tratar cancelación como error
try {
  await fetch('/api/data', { signal });
} catch (error) {
  alert('Error: ' + error.message); // Muestra "The user aborted a request" al usuario
  console.error(error); // Llena la consola de "errores" que no lo son
}

// ✅ CORRECTO: ignorar cancelaciones
try {
  await fetch('/api/data', { signal });
} catch (error) {
  if (error.name === 'AbortError') return; // Cancelación intencionada, no hacer nada
  console.error('Error real:', error); // Esto sí es un problema
}

Error 2: No cancelar en el cleanup de useEffect (React)

// ❌ MAL: si el componente se desmonta, setData se llama sobre estado inexistente
useEffect(() => {
  fetch(`/api/usuario/${id}`)
    .then(r => r.json())
    .then(setData); // ⚠ Warning si el componente ya no existe
}, [id]);

// ✅ CORRECTO: cancelar en el cleanup
useEffect(() => {
  const controller = new AbortController();

  fetch(`/api/usuario/${id}`, { signal: controller.signal })
    .then(r => r.json())
    .then(data => setData(data))
    .catch(err => {
      if (err.name !== 'AbortError') setError(err);
    });

  return () => controller.abort();
}, [id]);

Error 3: Reutilizar un AbortController ya abortado

// ❌ MAL: un controller abortado no puede reutilizarse
const controller = new AbortController();
fetch('/api/a', { signal: controller.signal });
controller.abort();
fetch('/api/b', { signal: controller.signal }); // Falla inmediatamente: ya está abortado

// ✅ CORRECTO: crea un nuevo controller para cada petición o grupo
let controller = new AbortController();
fetch('/api/a', { signal: controller.signal });
controller.abort();

controller = new AbortController(); // Nuevo controller fresco
fetch('/api/b', { signal: controller.signal }); // OK

Error 4: Olvidar que fetch ya recibió el signal pero sigues esperando

// ❌ MAL: tras abort(), el código después del await nunca se ejecuta
// (porque el catch del AbortError lo captura), pero si tienes lógica
// después del catch que asume datos, fallará.
async function cargar() {
  try {
    const data = await fetch(url, { signal }).then(r => r.json());
    return data;
  } catch (err) {
    if (err.name === 'AbortError') {
      console.log('Cancelado');
      // Si olvidas el return aquí, la función sigue...
    }
  }
  // ...y llega aquí con data undefined
  renderizarDatos(data); // ❌ data es undefined
}

// ✅ CORRECTO: salir explícitamente en caso de cancelación
async function cargar() {
  try {
    const data = await fetch(url, { signal }).then(r => r.json());
    renderizarDatos(data);
  } catch (err) {
    if (err.name === 'AbortError') {
      return; // Salir sin hacer nada más
    }
    console.error('Error real:', err);
  }
}

7 · Ejercicio guiado

Construye un buscador de usuarios con debounce + cancelación

  1. Crea la estructura HTML y referencias. 
    const input = document.querySelector('#search');
const resultsContainer = document.querySelector('#results');
let controller = null; // Guardamos el controller actual
let debounceTimer = null; // Para el debounce
  2. Implementa el listener con debounce. 
    input.addEventListener('input', (e) => {
  const termino = e.target.value.trim();

  // Cancelar el debounce anterior
  clearTimeout(debounceTimer);

  // Cancelar la petición fetch anterior
  if (controller) {
    controller.abort('Nuevo término de búsqueda');
  }

  // Si el input está vacío, limpiar resultados
  if (!termino) {
    resultsContainer.innerHTML = '';
    return;
  }

  // Esperar 300ms de inactividad antes de buscar (debounce)
  debounceTimer = setTimeout(() => {
    buscarUsuarios(termino);
  }, 300);
});
  3. Implementa la función de búsqueda con cancelación. 
    async function buscarUsuarios(termino) {
  controller = new AbortController();

  resultsContainer.innerHTML = '🔍 Buscando...';

  try {
    const url = `https://jsonplaceholder.typicode.com/users?q=${encodeURIComponent(termino)}`;
    const response = await fetch(url, { signal: controller.signal });

    if (!response.ok) {
      throw new Error(`Error HTTP ${response.status}`);
    }

    const usuarios = await response.json();
    mostrarResultados(usuarios);
  } catch (error) {
    if (error.name === 'AbortError') {
      return; // Cancelación intencionada, no mostrar error
    }
    resultsContainer.innerHTML = `❌ Error: ${error.message}`;
  }
}
  4. Renderiza los resultados. 
    function mostrarResultados(usuarios) {
  if (usuarios.length === 0) {
    resultsContainer.innerHTML = '😕 Sin resultados';
    return;
  }

  resultsContainer.innerHTML = usuarios
    .map(u => `
    
      ${u.name}
      @${u.username} — ${u.email}
    
    `)
    .join('');
}

8 · Reto

🎯 Carrusel de imágenes con precarga cancelable

Crea un sistema que precargue imágenes HD en segundo plano mientras el usuario navega una galería. Si el usuario cambia de imagen antes de que termine la precarga de la actual, debes cancelar la descarga en curso y empezar la nueva. Requisitos:

  • Cada imagen se descarga con fetch + blob + createObjectURL.
  • Si el usuario hace clic en "siguiente" rápido, las descargas pendientes se cancelan.
  • Usa AbortController para cancelar los fetch individualmente.
  • Mantén una caché: si una imagen se descargó por completo, no la vuelvas a pedir aunque estuviera cancelada en un intento anterior.

9 · Resumen

  • AbortController permite cancelar peticiones fetch y otras operaciones asíncronas.
  • controller.signal se pasa a la operación; controller.abort(reason?) dispara la cancelación.
  • Un fetch cancelado rechaza con un DOMException de nombre 'AbortError'. Distínguelo siempre de errores reales.
  • El mismo controller puede cancelar múltiples peticiones a la vez (ideal para dashboards).
  • AbortSignal.timeout(ms) (ES2023) crea un signal auto-abortable, más limpio que Promise.race.
  • AbortSignal.any([s1, s2]) (ES2023) combina varias señales en una.
  • En inputs de búsqueda en tiempo real: cancela siempre la petición anterior antes de lanzar la nueva.
  • En React/Vue/SPAs: usa useEffect cleanup (o onUnmounted) para cancelar peticiones al desmontar el componente.
  • Un AbortController no se puede reutilizar después de abort(); crea uno nuevo.

10 · Preguntas frecuentes

¿Cancelar un fetch realmente detiene la petición o solo ignora el resultado?

Realmente la detiene. Cuando abortas un fetch, el navegador envía una señal TCP RST (reset) al servidor, cerrando la conexión. En el lado del servidor, la conexión se interrumpe. No es simplemente ignorar el resultado; los recursos de red se liberan. Sin embargo, si el servidor ya empezó a procesar la petición, ese trabajo no se deshace (el abort es a nivel de conexión, no de lógica de negocio).

¿Puedo usar AbortController para cancelar otras cosas que no sean fetch?

Sí. Cualquier API que acepte un signal puede cancelarse. Ejemplos: addEventListener (pasar signal como opción para remover el listener al abortar), streams (ReadableStream), setTimeout (con un polyfill o implementación propia). También puedes usar signal.addEventListener('abort', fn) para ejecutar tu propia lógica de limpieza.

¿Cuál es la diferencia entre AbortSignal.timeout() y Promise.race() para timeouts?

Promise.race([fetch(url), timeoutPromise]) solo ignora el resultado de fetch si el timeout gana, pero fetch sigue ejecutándose y consumiendo recursos. AbortSignal.timeout(ms) realmente aborta la conexión, liberando el socket TCP. Además, timeout() es más limpio sintácticamente: una línea vs varias. Usa AbortSignal.timeout() siempre que puedas (ES2023+).

¿Puedo saber por qué se abortó una petición?

Sí. Pasa una razón a controller.abort(razon) y luego compruébala con signal.reason (o error en el catch si es un fetch). Ejemplo: controller.abort('Timeout') → signal.reason === 'Timeout'. Con signal.throwIfAborted(), la razón se lanza como excepción directamente.
