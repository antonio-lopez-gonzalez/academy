Fetch API: GET, POST, headers, response

Módulo 6 · Asincronía y APIs ⏱ 35 minutos

1 · Introducción

Antes de fetch, hacer peticiones HTTP en JavaScript significaba usar XMLHttpRequest (XHR), una API verbosa, inconsistente y basada en callbacks. fetch() llegó en ES2015 como la alternativa moderna: basada en promesas, con una sintaxis limpia y capacidades avanzadas como streaming, lectura del cuerpo en múltiples formatos y control de la cache.

fetch() es la API estándar para hacer peticiones HTTP desde el navegador. También está disponible en Node.js desde la versión 18 (con la flag --experimental-fetch antes, estable desde Node 21).

¿Por qué fetch y no XHR o Axios?

fetch es nativo: no necesitas instalar nada, funciona en el navegador y en Node, y es la base sobre la que se construyen librerías como Axios o ky. Aprender fetch te da control total sobre cada aspecto de la petición HTTP sin dependencias externas.

2 · Teoría

La función fetch()

fetch(url, options?) acepta una URL (string o Request) y un objeto opcional de opciones. Devuelve una promesa que se cumple con un objeto Response.

fetch NO rechaza con errores HTTP

A diferencia de lo que podrías esperar, fetch() solo rechaza la promesa en caso de error de red (DNS fallido, conexión denegada, timeout). Una respuesta 404 o 500 se considera un "éxito" para fetch: la promesa se cumple, y eres tú quien debe comprobar response.ok o response.status.

El objeto Response

La respuesta de fetch() es un objeto Response con estas propiedades y métodos clave:

  • response.ok: true si el status está entre 200 y 299. Es la forma más rápida de comprobar éxito.
  • response.status: código HTTP numérico (200, 404, 500...).
  • response.statusText: texto asociado al código ('OK', 'Not Found'...).
  • response.headers: objeto Headers con las cabeceras de la respuesta. Se itera con .entries(), .get(nombre) para acceder a una.
  • response.url: URL final después de redirecciones.
  • response.redirected: true si la petición fue redirigida.
  • response.type: 'basic', 'cors', 'opaque' (según el modo CORS).

Métodos para leer el cuerpo

El cuerpo de la respuesta es un ReadableStream que solo puede leerse una vez. Tienes estos métodos para consumirlo:

  • response.json(): parsea el cuerpo como JSON. Devuelve una promesa con el objeto resultante.
  • response.text(): devuelve el cuerpo como string.
  • response.blob(): devuelve un Blob (útil para imágenes, archivos).
  • response.arrayBuffer(): devuelve un ArrayBuffer (datos binarios crudos).
  • response.formData(): parsea como FormData (si es multipart/form-data).
El cuerpo solo se puede leer una vez

Si necesitas leer el cuerpo más de una vez (por ejemplo, para loguear y también para parsear), usa response.clone() para crear una copia de la respuesta antes de consumir el cuerpo de la original.

Opciones de fetch()

fetch(url, {
  method: 'GET',        // GET, POST, PUT, PATCH, DELETE
  headers: {             // Cabeceras HTTP
    'Content-Type': 'application/json',
    'Authorization': 'Bearer token123',
  },
  body: JSON.stringify({ nombre: 'Ana' }), // Cuerpo (no en GET/HEAD)
  mode: 'cors',          // cors, no-cors, same-origin
  credentials: 'include', // omit, same-origin, include (cookies)
  cache: 'no-cache',     // default, no-store, reload, no-cache, force-cache
  redirect: 'follow',    // follow, error, manual
  signal: abortSignal,   // Para AbortController
});

GET con parámetros: URLSearchParams

URLSearchParams construye query strings correctamente escapadas:

const params = new URLSearchParams({
  q: 'javascript',
  page: 1,
  limit: 20,
  sort: 'stars',
});
const url = `https://api.github.com/search/repositories?${params}`;
// → https://api.github.com/search/repositories?q=javascript&page=1&limit=20&sort=stars

Subida de archivos con FormData

const formData = new FormData();
formData.append('avatar', fileInput.files[0]);
formData.append('nombre', 'Antonio');

fetch('/api/upload', {
  method: 'POST',
  body: formData, // No pongas Content-Type: fetch lo establece con el boundary
});

Streams

response.body es un ReadableStream que permite procesar la respuesta por chunks mientras se recibe, sin esperar a tener todo el cuerpo. Ideal para descargas grandes o respuestas en tiempo real:

const response = await fetch('/api/grande.csv');
const reader = response.body.getReader();
const decoder = new TextDecoder();

while (true) {
  const { done, value } = await reader.read();
  if (done) break;
  console.log('Chunk recibido:', decoder.decode(value, { stream: true }));
}

3 · Ejemplo mínimo

// 🧪 GET con fetch: la petición más simple
fetch('https://api.github.com/users/microsoft')
  .then(response => {
    // Primero comprobamos si la respuesta HTTP es exitosa
    if (!response.ok) {
      throw new Error(`HTTP ${response.status}: ${response.statusText}`);
    }
    return response.json(); // Consumir el cuerpo como JSON (devuelve promesa)
  })
  .then(data => {
    console.log(`👤 ${data.login} — ${data.bio}`);
    console.log(`📦 ${data.public_repos} repos públicos`);
  })
  .catch(error => {
    console.error('❌ Error:', error.message);
  });

Línea a línea:

  1. fetch(url) sin opciones hace un GET. Devuelve una promesa.
  2. En el primer .then() recibimos el objeto Response.
  3. Comprobamos response.ok (true = status 200-299). Si falla, lanzamos error manualmente.
  4. response.json() lee el stream y parsea JSON. Devuelve otra promesa.
  5. En el segundo .then() ya tenemos los datos parseados.
  6. .catch() captura errores de red + los errores lanzados manualmente.

4 · Ejemplo real

Cliente HTTP completo con fetch

/**
 * Cliente HTTP minimalista basado en fetch.
 * Maneja JSON, errores HTTP, timeouts y headers por defecto.
 */
class HttpClient {
  constructor(baseURL = '', defaultHeaders = {}) {
    this.baseURL = baseURL;
    this.defaultHeaders = {
      'Content-Type': 'application/json',
      ...defaultHeaders,
    };
  }

  async request(endpoint, options = {}) {
    const url = `${this.baseURL}${endpoint}`;
    const config = {
      ...options,
      headers: {
        ...this.defaultHeaders,
        ...options.headers,
      },
    };

    const response = await fetch(url, config);

    // Error HTTP controlado por nosotros (fetch no rechaza con 4xx/5xx)
    if (!response.ok) {
      let errorBody = null;
      try {
        errorBody = await response.json();
      } catch {
        errorBody = await response.text();
      }
      const error = new Error(
        `HTTP ${response.status}: ${response.statusText}`
      );
      error.status = response.status;
      error.body = errorBody;
      throw error;
    }

    // Si la respuesta es 204 (No Content), no hay cuerpo que parsear
    if (response.status === 204) {
      return null;
    }

    return response.json();
  }

  get(endpoint, options = {}) {
    return this.request(endpoint, { method: 'GET', ...options });
  }

  post(endpoint, body, options = {}) {
    return this.request(endpoint, {
      method: 'POST',
      body: JSON.stringify(body),
      ...options,
    });
  }

  put(endpoint, body, options = {}) {
    return this.request(endpoint, {
      method: 'PUT',
      body: JSON.stringify(body),
      ...options,
    });
  }

  patch(endpoint, body, options = {}) {
    return this.request(endpoint, {
      method: 'PATCH',
      body: JSON.stringify(body),
      ...options,
    });
  }

  delete(endpoint, options = {}) {
    return this.request(endpoint, { method: 'DELETE', ...options });
  }
}

// Uso del cliente
const api = new HttpClient('https://jsonplaceholder.typicode.com');

async function ejemplo() {
  try {
    // GET — obtener recursos
    const posts = await api.get('/posts?_limit=3');
    console.log('📄 Posts:', posts.length);

    // POST — crear recurso
    const nuevo = await api.post('/posts', {
      title: 'Aprendiendo fetch',
      body: 'Contenido del post',
      userId: 1,
    });
    console.log('✅ Creado:', nuevo.id);

    // PUT — reemplazar recurso completo
    const actualizado = await api.put(`/posts/${nuevo.id}`, {
      id: nuevo.id,
      title: 'Título actualizado',
      body: 'Nuevo contenido',
      userId: 1,
    });
    console.log('🔄 Actualizado:', actualizado.id);

    // DELETE — eliminar recurso
    await api.delete(`/posts/${nuevo.id}`);
    console.log('🗑 Eliminado');
  } catch (error) {
    console.error('❌', error.status, error.message, error.body);
  }
}

Subida de archivo con feedback de progreso

// Aunque fetch no expone progreso nativamente, podemos usar XMLHttpRequest
// para ese caso. Aquí mostramos la alternativa con fetch + FormData.
async function subirArchivo(file, url = '/api/upload') {
  const formData = new FormData();
  formData.append('archivo', file);
  formData.append('fecha', new Date().toISOString());

  try {
    const response = await fetch(url, {
      method: 'POST',
      body: formData,
      // NO establezcas Content-Type manualmente con FormData
      // fetch pondrá automáticamente multipart/form-data con el boundary
    });

    if (!response.ok) {
      throw new Error(`Subida fallida: ${response.status}`);
    }

    const resultado = await response.json();
    console.log(`📤 ${file.name} subido (${file.size} bytes)`);
    return resultado;
  } catch (error) {
    console.error('Error de subida:', error.message);
    throw error;
  }
}

document.querySelector('#fileInput').addEventListener('change', async (e) => {
  const file = e.target.files[0];
  if (!file) return;

  try {
    const resultado = await subirArchivo(file);
    console.log('Respuesta del servidor:', resultado);
  } catch (error) {
    alert('Error al subir el archivo');
  }
});

5 · Buenas prácticas

HazEvitaPor qué
Comprueba siempre response.ok o response.status Asumir que fetch rechaza con errores 4xx/5xx Fetch solo rechaza en errores de red; un 404 se considera éxito a nivel de promesa
Usa URLSearchParams para construir query strings Concatenar parámetros manualmente con + o template literals Los valores necesitan escape (encodeURIComponent); URLSearchParams lo hace automáticamente
Establece 'Content-Type': 'application/json' cuando envíes JSON Enviar JSON sin el header Content-Type El servidor no sabrá interpretar el cuerpo y probablemente devuelva 400 o 415
No establezcas Content-Type manualmente con FormData Poner 'Content-Type': 'multipart/form-data' al usar FormData Fetch establece automáticamente el boundary en el Content-Type; si lo pones manualmente, falta el boundary y la petición falla
Clona la respuesta con response.clone() si necesitas leer el cuerpo más de una vez Llamar a response.json() dos veces sobre la misma respuesta El cuerpo es un stream que se consume una sola vez; la segunda llamada falla con TypeError
Usa variables de entorno o config para URLs base, no las hardcodees Escribir URLs absolutas completas en cada fetch Dificulta cambiar entre entornos (dev, staging, producción)

6 · Errores habituales

Error 1: No comprobar response.ok

// ❌ MAL: el error 404 no se captura
fetch('/api/usuario/999')
  .then(r => r.json()) // Si es 404, r.json() falla porque el body puede no ser JSON
  .then(data => console.log(data))
  .catch(err => console.error(err));
// El error será un SyntaxError de JSON.parse, no un error claro de "Usuario no encontrado"

// ✅ CORRECTO: comprobar antes de parsear
fetch('/api/usuario/999')
  .then(r => {
    if (!r.ok) throw new Error(`HTTP ${r.status}`);
    return r.json();
  })
  .then(data => console.log(data))
  .catch(err => console.error(err.message));

Error 2: Olvidar el Content-Type al enviar JSON

// ❌ MAL: sin Content-Type, el servidor puede no parsear el body
fetch('/api/usuarios', {
  method: 'POST',
  body: JSON.stringify({ nombre: 'Ana' }),
});

// ✅ CORRECTO: especificar Content-Type
fetch('/api/usuarios', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ nombre: 'Ana' }),
});

Error 3: Leer el cuerpo dos veces

// ❌ MAL: el cuerpo ya se consumió en el primer json()
const response = await fetch('/api/datos');
console.log(await response.json()); // OK
console.log(await response.text()); // TypeError: Already read

// ✅ CORRECTO: clonar antes de leer
const response = await fetch('/api/datos');
const clone = response.clone();
const datos = await response.json();
const crudo = await clone.text();
console.log('Como texto:', crudo);
console.log('Como objeto:', datos);

Error 4: Enviar body en GET

// ❌ MAL: GET no debe tener body (TypeError en navegadores)
fetch('/api/usuarios', {
  method: 'GET',
  body: JSON.stringify({ filtro: 'activos' }),
});

// ✅ CORRECTO: usar query params para GET
const params = new URLSearchParams({ filtro: 'activos' });
fetch(`/api/usuarios?${params}`);

7 · Ejercicio guiado

Construye una mini app que busque películas en la OMDb API

  1. Crea una función para buscar películas con fetch. 
    const API_KEY = 'tu-api-key'; // Consíguela gratis en omdbapi.com
const BASE_URL = 'https://www.omdbapi.com';

async function buscarPeliculas(termino, pagina = 1) {
  const params = new URLSearchParams({
    apikey: API_KEY,
    s: termino,
    page: pagina,
    type: 'movie',
  });

  const response = await fetch(`${BASE_URL}?${params}`);

  if (!response.ok) {
    throw new Error(`Error HTTP ${response.status}`);
  }

  const data = await response.json();

  // La API devuelve un objeto con Response: 'False' si no hay resultados
  if (data.Response === 'False') {
    throw new Error(data.Error || 'Sin resultados');
  }

  return data; // { Search: [...], totalResults: '123' }
}
  2. Crea la función para obtener detalles de una película. 
    async function obtenerDetallePelicula(imdbID) {
  const params = new URLSearchParams({
    apikey: API_KEY,
    i: imdbID,
    plot: 'short',
  });

  const response = await fetch(`${BASE_URL}?${params}`);

  if (!response.ok) {
    throw new Error(`Error HTTP ${response.status}`);
  }

  const data = await response.json();

  if (data.Response === 'False') {
    throw new Error(data.Error);
  }

  return {
    titulo: data.Title,
    año: data.Year,
    director: data.Director,
    reparto: data.Actors,
    poster: data.Poster,
    rating: data.imdbRating,
    sinopsis: data.Plot,
  };
}
  3. Crea una función principal que coordine ambas. 
    async function buscarYMostrarDetalles(termino) {
  try {
    console.log(`🔍 Buscando: "${termino}"...`);

    // 1. Buscar películas
    const resultados = await buscarPeliculas(termino);
    console.log(`📊 ${resultados.totalResults} resultados encontrados`);

    if (resultados.Search.length === 0) {
      console.log('😕 No se encontraron películas');
      return;
    }

    // 2. Mostrar lista resumida
    resultados.Search.slice(0, 5).forEach((peli, i) => {
      console.log(`  ${i + 1}. ${peli.Title} (${peli.Year}) — ID: ${peli.imdbID}`);
    });

    // 3. Obtener el detalle de la primera
    console.log('\n📋 Obteniendo detalle de la primera...');
    const detalle = await obtenerDetallePelicula(resultados.Search[0].imdbID);

    console.log(`\n🎬 ${detalle.titulo} (${detalle.año})`);
    console.log(`   Director: ${detalle.director}`);
    console.log(`   Reparto: ${detalle.reparto}`);
    console.log(`   Rating: ⭐ ${detalle.rating}/10`);
    console.log(`   Sinopsis: ${detalle.sinopsis}`);
  } catch (error) {
    console.error('❌', error.message);
  }
}

9 · Resumen

  • fetch(url, options) es la API nativa para HTTP en navegador y Node.js (v18+).
  • Solo rechaza en caso de error de red. Los errores HTTP (4xx, 5xx) deben comprobarse manualmente con response.ok o response.status.
  • Para GET usa query strings con URLSearchParams.
  • Para POST/PUT/PATCH envía el body con JSON.stringify() y header Content-Type: application/json.
  • Con FormData no establezcas Content-Type manualmente; fetch lo gestiona automáticamente.
  • El cuerpo de la respuesta se puede leer como .json(), .text(), .blob(), .arrayBuffer() o .formData().
  • El cuerpo es un stream consumible una sola vez. Usa response.clone() si necesitas leerlo más de una vez.
  • Para descargas grandes o streaming usa el reader de response.body.getReader().

10 · Preguntas frecuentes

¿Por qué fetch no rechaza con 404?

Es una decisión de diseño. Fetch considera "error" solo los fallos de red (no se pudo establecer conexión). Una respuesta HTTP, aunque sea de error, sigue siendo una respuesta válida que el servidor envió correctamente. Esto te da control granular: puedes decidir si un 404 es aceptable o no para tu caso de uso, en lugar de que fetch decida por ti.

¿Cómo cancelo una petición fetch?

Usa AbortController. Creas un controller, pasas su signal en las opciones de fetch, y cuando necesites cancelar llamas a controller.abort(). Fetch rechazará con un AbortError. Esto se trata en detalle en la siguiente lección sobre AbortController.

¿Cómo sé si una respuesta es JSON antes de parsearla?

Comprueba la cabecera: response.headers.get('content-type')?.includes('application/json'). Si no lo es, probablemente quieras usar response.text() en su lugar. Algunas APIs devuelven JSON sin el Content-Type correcto; en ese caso puedes usar response.text() y luego JSON.parse() manualmente con un try/catch.

¿Fetch funciona en Node.js?

Sí, es estable desde Node.js 21 (experimental desde Node 18). Se implementa sobre undici, el cliente HTTP de alto rendimiento de Node. La API es idéntica a la del navegador. Para versiones anteriores de Node, puedes usar node-fetch o axios como polyfill.

¿fetch vs axios: cuál debería usar?

fetch es nativo, no tiene dependencias y te obliga a entender HTTP a bajo nivel (bueno para aprender). axios añade azúcar: interceptores, cancelación basada en promesas, transformación automática de JSON, y mejor manejo de errores HTTP. En proyectos profesionales, cualquiera de los dos es válido. Aprende fetch primero para entender los fundamentos; luego decide si necesitas las comodidades de axios.
