async/await, try/catch y manejo de errores asíncrono

Módulo 6 · Asincronía y APIs ⏱ 35 minutos

1 · Introducción

async/await es azúcar sintáctico sobre las promesas, introducido en ES2017. No añade ninguna capacidad nueva; todo lo que hace async/await puede hacerse con .then() y .catch(). Pero la sintaxis cambia radicalmente la experiencia de desarrollo: el código asíncrono se lee como si fuera síncrono, eliminando por completo el encadenamiento de .then() cuando no lo necesitas.

Donde antes escribías:

fetch('/api/usuario')
  .then(r => r.json())
  .then(u => fetch(`/api/pedidos/${u.id}`))
  .then(r => r.json())
  .then(p => console.log(p))
  .catch(e => console.error(e));

Ahora escribes:

try {
  const u = await (await fetch('/api/usuario')).json();
  const p = await (await fetch(`/api/pedidos/${u.id}`)).json();
  console.log(p);
} catch (e) {
  console.error(e);
}
¿Por qué async/await si ya teníamos .then()?

Porque el cerebro humano lee mejor el código secuencial que las cadenas de callbacks. Con .then(), cada paso es una función separada; con await, todo está en el mismo ámbito, compartiendo variables sin necesidad de pasarlas explícitamente. Además, try/catch es más natural que .catch() para quienes vienen de lenguajes síncronos.

2 · Teoría

async function

La palabra clave async delante de una función hace que esta siempre devuelva una promesa. Si la función retorna un valor (con return), la promesa se cumple con ese valor. Si la función lanza una excepción (con throw), la promesa se rechaza con ese error.

// Estas dos funciones son equivalentes:
async function saludar() {
  return 'Hola'; // implícitamente Promise.resolve('Hola')
}

function saludarConPromesa() {
  return Promise.resolve('Hola');
}

saludar().then(msg => console.log(msg)); // 'Hola'

async function fallar() {
  throw new Error('Algo salió mal'); // implícitamente Promise.reject(...)
}

fallar().catch(err => console.error(err.message)); // 'Algo salió mal'

await

La palabra clave await solo puede usarse dentro de funciones marcadas con async (o en módulos ES con top-level await). await pausa la ejecución de la función async hasta que la promesa se resuelva, y entonces devuelve el valor cumplido.

await NO bloquea el hilo principal

Aunque la sintaxis parezca bloqueante, await solo pausa la función actual. El hilo principal sigue libre para ejecutar otras tareas (eventos, renderizado, otras funciones async). Es azúcar sintáctico sobre .then(), no una llamada bloqueante al estilo de Python o Java síncrono.

try/catch con async/await

Los errores en funciones async se manejan con try/catch exactamente igual que en código síncrono:

async function cargarDatos() {
  try {
    const response = await fetch('/api/inexistente'); // fetch no rechaza con 404
    if (!response.ok) {
      throw new Error(`HTTP ${response.status}: ${response.statusText}`);
    }
    const datos = await response.json();
    return datos;
  } catch (error) {
    // Captura errores de red Y errores lanzados manualmente
    console.error('Error al cargar:', error.message);
    return null; // Valor de respaldo
  }
}

Top-level await

Desde ES2022, puedes usar await en el nivel superior de módulos ES (archivos con type="module" o extensión .mjs). No funciona en scripts comunes (<script> sin type="module").

// En un módulo ES (.mjs o type="module"), esto es válido:
const config = await fetch('/config.json').then(r => r.json());
console.log(config.apiUrl);

Arrow functions async

const obtenerUsuario = async (id) => {
  const res = await fetch(`/api/usuarios/${id}`);
  return res.json();
};

// Incluso en callbacks (con cuidado, ver sección de errores)
document.querySelector('#btn').addEventListener('click', async () => {
  const datos = await obtenerUsuario(1);
  console.log(datos);
});

Ejecución secuencial vs paralela

Uno de los errores más comunes con async/await es ejecutar operaciones independientes de forma secuencial por accidente:

// ❌ SECUENCIAL (lento): cada await espera al anterior
const usuario = await fetch('/api/usuario').then(r => r.json());
const posts = await fetch('/api/posts').then(r => r.json());
// Tiempo total = tiempo(usuario) + tiempo(posts)

// ✅ PARALELO (rápido): ambas promesas empiezan al mismo tiempo
const [usuario, posts] = await Promise.all([
  fetch('/api/usuario').then(r => r.json()),
  fetch('/api/posts').then(r => r.json()),
]);
// Tiempo total = max(tiempo(usuario), tiempo(posts))

async IIFE (Immediately Invoked Function Expression)

En entornos sin top-level await (scripts normales, Node CommonJS), puedes usar una IIFE async:

(async () => {
  const datos = await fetch('/api/config').then(r => r.json());
  console.log(datos);
})();

3 · Ejemplo mínimo

// 🧪 La función async más simple: esperar un valor y retornarlo
function esperar(ms, valor) {
  return new Promise(resolve => setTimeout(() => resolve(valor), ms));
}

async function ejemploMinimo() {
  console.log('⏳ Esperando...');

  const resultado = await esperar(1000, '✅ Completado');

  console.log(resultado); // Se imprime tras 1 segundo
  return resultado;
}

ejemploMinimo().then(r => console.log('Devuelto:', r));

Paso a paso:

  1. esperar(1000, '✅ Completado') crea una promesa que se cumple tras 1 segundo.
  2. await pausa ejemploMinimo hasta que la promesa se cumpla.
  3. Cuando se cumple, resultado recibe '✅ Completado'.
  4. La función continúa, imprime el resultado y lo retorna.
  5. Como ejemploMinimo es async, el return envuelve el valor en una promesa.
  6. El .then() externo recibe '✅ Completado'.

4 · Ejemplo real

Dashboard que carga datos de múltiples fuentes

/**
 * Clase que gestiona la carga de datos de un dashboard.
 * Combina operaciones secuenciales (login) con paralelas (métricas).
 */
class Dashboard {
  constructor(apiBase) {
    this.apiBase = apiBase;
    this.token = null;
  }

  async login(usuario, password) {
    const res = await fetch(`${this.apiBase}/auth`, {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ usuario, password }),
    });

    if (!res.ok) {
      throw new Error(`Login fallido: ${res.status}`);
    }

    const data = await res.json();
    this.token = data.token;
    console.log('🔐 Sesión iniciada');
    return data;
  }

  async cargarDashboard() {
    if (!this.token) {
      throw new Error('No autenticado. Llama a login() primero.');
    }

    const headers = {
      'Authorization': `Bearer ${this.token}`,
      'Content-Type': 'application/json',
    };

    try {
      // Carga paralela de 3 fuentes independientes
      const [metricas, notificaciones, perfil] = await Promise.all([
        fetch(`${this.apiBase}/metricas`, { headers }).then(r => r.json()),
        fetch(`${this.apiBase}/notificaciones`, { headers }).then(r => r.json()),
        fetch(`${this.apiBase}/perfil`, { headers }).then(r => r.json()),
      ]);

      return {
        metricas: metricas.data,
        notificaciones: notificaciones.items,
        perfil: perfil.usuario,
      };
    } catch (error) {
      console.error('Error al cargar dashboard:', error.message);

      // Si el error es de autenticación, limpiamos el token
      if (error.message.includes('401')) {
        this.token = null;
      }
      throw error; // Relanzamos para que el consumidor decida
    }
  }
}

// Uso del dashboard
async function main() {
  const dashboard = new Dashboard('https://api.ejemplo.com/v1');

  try {
    await dashboard.login('admin', '1234');
    const datos = await dashboard.cargarDashboard();
    console.log('📊 Dashboard cargado:', datos);
  } catch (error) {
    console.error('❌ Error fatal:', error.message);
  }
}

main();

Consumiendo una API REST paginada

async function obtenerTodosLosPosts(apiUrl) {
  const todos = [];
  let pagina = 1;
  let hayMas = true;

  while (hayMas) {
    const res = await fetch(`${apiUrl}?_page=${pagina}&_limit=50`);

    if (!res.ok) {
      throw new Error(`Error HTTP ${res.status} en página ${pagina}`);
    }

    const posts = await res.json();
    todos.push(...posts);

    // Si la respuesta tiene menos de 50 items, es la última página
    hayMas = posts.length === 50;
    pagina++;

    console.log(`📄 Página ${pagina - 1}: ${posts.length} posts`);
  }

  console.log(`📦 Total: ${todos.length} posts cargados`);
  return todos;
}

6 · Errores habituales

Error 1: await secuencial en bucles cuando no es necesario

// ❌ MAL: cada iteración espera a la anterior (secuencial lento)
const ids = [1, 2, 3, 4, 5];
const resultados = [];
for (const id of ids) {
  const data = await fetch(`/api/item/${id}`).then(r => r.json());
  resultados.push(data);
}

// ✅ CORRECTO: lanzar todas a la vez y esperar el conjunto
const resultados = await Promise.all(
  ids.map(id => fetch(`/api/item/${id}`).then(r => r.json()))
);

Error 2: No capturar errores — promesas rechazadas silenciosamente

// ❌ MAL: si fetch falla, el error se pierde (UnhandledPromiseRejection)
async function cargar() {
  const res = await fetch('/api/inexistente');
  const data = await res.json();
  console.log(data);
}
cargar(); // Sin .catch() ni try/catch en main

// ✅ CORRECTO: siempre manejar el error en el nivel adecuado
async function main() {
  try {
    await cargar();
  } catch (error) {
    console.error('Error controlado:', error.message);
  }
}
main();

Error 3: Usar await en funciones que no son async

// ❌ MAL: SyntaxError: await is only valid in async functions
function obtener() {
  const data = await fetch('/api');
  return data;
}

// ✅ CORRECTO: marcar la función como async
async function obtener() {
  const data = await fetch('/api');
  return data;
}

Error 4: async en forEach — el await no espera

// ❌ MAL: forEach no espera a las funciones async
[1, 2, 3].forEach(async (id) => {
  await fetch(`/api/${id}`); // Estos fetch se lanzan pero nadie los espera
});
console.log('Fin'); // Se imprime ANTES de que terminen los fetch

// ✅ CORRECTO: usa for...of con await, o Promise.all
for (const id of [1, 2, 3]) {
  await fetch(`/api/${id}`);
}
console.log('Fin'); // Ahora sí, después de todos los fetch

7 · Ejercicio guiado

Construye un cargador de perfil de GitHub usando la API pública

  1. Crea la función que obtiene el perfil básico. 
    async function obtenerPerfilGitHub(username) {
  const res = await fetch(`https://api.github.com/users/${username}`);

  if (!res.ok) {
    if (res.status === 404) {
      throw new Error(`Usuario "${username}" no existe`);
    }
    throw new Error(`Error HTTP ${res.status}`);
  }

  return res.json();
}
  2. Carga los repositorios del usuario. 
    async function obtenerRepos(username, cantidad = 5) {
  const res = await fetch(
    `https://api.github.com/users/${username}/repos?sort=stars&per_page=${cantidad}`
  );
  if (!res.ok) throw new Error(`Error al obtener repos: ${res.status}`);
  return res.json();
}
  3. Carga perfil y repos en paralelo. 
    async function mostrarPerfilCompleto(username) {
  try {
    console.log(`🔍 Buscando "${username}"...`);

    // Carga paralela: perfil y repos no dependen entre sí
    const [perfil, repos] = await Promise.all([
      obtenerPerfilGitHub(username),
      obtenerRepos(username),
    ]);

    console.log(`👤 ${perfil.name || perfil.login}`);
    console.log(`📝 ${perfil.bio || 'Sin bio'}`);
    console.log(`📦 ${perfil.public_repos} repos públicos`);
    console.log(`👥 ${perfil.followers} seguidores`);
    console.log('--- Repositorios más destacados ---');
    repos.forEach(r => {
      console.log(`  ⭐ ${r.stargazers_count} — ${r.name}`);
    });

    return { perfil, repos };
  } catch (error) {
    console.error('❌', error.message);
    throw error;
  }
}
  4. Prueba con varios usuarios usando un wrapper con límite de rate. 
    // La API de GitHub tiene rate limiting. Daremos feedback visual.
async function buscarVarios(usernames) {
  for (const username of usernames) {
    try {
      await mostrarPerfilCompleto(username);
      console.log('---');
    } catch (error) {
      console.warn(`⚠ Saltando ${username}: ${error.message}`);
    }

    // Pequeña pausa para no saturar la API
    await new Promise(r => setTimeout(r, 500));
  }
  console.log('✅ Búsqueda completada');
}

buscarVarios(['microsoft', 'facebook', 'vercel']);

8 · Reto

🎯 Implementa un retry automático con backoff exponencial

Crea una función fetchConRetry(url, opciones = {}, maxIntentos = 3) que reintente automáticamente las peticiones fallidas usando backoff exponencial: espera 1s tras el primer fallo, 2s tras el segundo, 4s tras el tercero, y así hasta maxIntentos. Si todos los intentos fallan, lanza el último error. Si alguno tiene éxito, devuelve la respuesta.

Pistas:

  • Usa un bucle for.
  • Espera 2 ** intento * 1000 ms entre reintentos.
  • Solo reintenta si el error es de red (TypeError) o un 5xx del servidor. No reintentes errores 4xx (cliente).

9 · Resumen

  • async/await es azúcar sintáctico sobre promesas (ES2017). No añade funcionalidad nueva, mejora la legibilidad.
  • Una función async siempre devuelve una promesa. Si retorna valor, se cumple; si lanza error, se rechaza.
  • await pausa la función async pero no bloquea el hilo principal.
  • Los errores en funciones async se capturan con try/catch como en código síncrono.
  • Top-level await funciona solo en módulos ES (soportado desde Node.js 14.8, hoy sin restricción práctica en las LTS modernas).
  • Las arrow functions pueden ser async: const fn = async () => {}.
  • Para paralelismo con await: inicia las promesas, luego await Promise.all([...]); no hagas await secuenciales de operaciones independientes.
  • Una IIFE async (async () => {})() permite usar await en entornos sin top-level await.
  • async/await es compatible con todos los navegadores y Node.js modernos (ES2017).

10 · Preguntas frecuentes

¿Puedo usar await fuera de una función async?

Sí, desde ES2022, en módulos ES (<script type="module"> o .mjs) puedes usar await en el nivel superior del archivo. Se conoce como top-level await. No funciona en scripts normales (.js sin type="module") ni en la consola de DevTools de algunos navegadores más antiguos.

¿Qué es más rápido, async/await o .then()?

En términos de rendimiento, son prácticamente idénticos porque async/await se transpila/compila a código basado en promesas. La diferencia es de legibilidad. En casos muy específicos, las cadenas largas de .then() pueden ser marginalmente más rápidas porque no crean el contexto extra de la función async, pero es una micro-optimización que rara vez importa.

¿Debo usar siempre async/await en lugar de .then()?

No siempre. async/await brilla cuando tienes lógica secuencial con variables compartidas. Pero .then() puede ser más conciso para transformaciones simples de una línea: fetch(url).then(r => r.json()).then(console.log). La regla es: usa lo que haga el código más legible en cada situación.

¿Qué pasa si hago await sobre un valor que no es una promesa?

await 42 es perfectamente válido. await envuelve automáticamente valores no-promesas en Promise.resolve(valor), por lo que await 42 devuelve 42 inmediatamente. Aunque técnicamente pasa por la microtask queue, en la práctica no hay retraso perceptible.
