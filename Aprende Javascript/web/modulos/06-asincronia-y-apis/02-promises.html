Promises: then, catch, finally, Promise.all, Promise.race

Módulo 6 · Asincronía y APIs ⏱ 35 minutos

1 · Introducción

En la lección anterior sufrimos el callback hell: pirámides de código indentado, errores duplicados en cada nivel y pérdida del control sobre nuestra lógica. Las promesas (Promises) llegaron en ES6 (2015) para solucionar exactamente esos tres problemas.

Una promesa es un objeto que representa un valor que puede estar disponible ahora, en el futuro o nunca. Es como el ticket que te dan en un restaurante: no tienes la comida aún, pero tienes un comprobante que te permitirá reclamarla cuando esté lista. Mientras tanto puedes seguir haciendo otras cosas.

¿Por qué promesas y no callbacks?

Las promesas resuelven tres problemas del patrón de callbacks: (1) la inversión de control — tú controlas qué hacer con el resultado, no se lo cedes a una función externa; (2) el encadenamiento plano con .then() en lugar de anidación; y (3) el manejo de errores centralizado con un solo .catch() al final de la cadena.

2 · Teoría

Los tres estados de una promesa

Toda promesa está en uno (y solo uno) de estos tres estados:

  • pending (pendiente): estado inicial. La operación aún no ha terminado.
  • fulfilled (cumplida/resuelta): la operación terminó con éxito. La promesa tiene un valor.
  • rejected (rechazada): la operación falló. La promesa tiene una razón (error).

Una vez que una promesa pasa de pending a fulfilled o rejected, no puede cambiar de estado nunca más. Se dice que la promesa está settled (resuelta en el sentido amplio, cumplida o rechazada). Esta inmutabilidad del estado es una propiedad fundamental que garantiza previsibilidad.

🎫 El ticket del restaurante

Pides una pizza y te dan un ticket con el número 42. Ese ticket (la promesa) está en estado pending mientras preparan la pizza. Cuando el camarero te entrega la pizza, el ticket pasa a fulfilled (valor: la pizza caliente). Si se quema en el horno, el ticket pasa a rejected (razón: pizza quemada). Una vez que tienes la pizza o sabes que se quemó, el ticket no puede volver a cambiar de estado.

Encadenamiento con .then(), .catch() y .finally()

  • .then(onFulfilled, onRejected): recibe dos callbacks opcionales. El primero se ejecuta si la promesa se cumple; el segundo si se rechaza. Devuelve una nueva promesa, lo que permite encadenar.
  • .catch(onRejected): equivalente a .then(null, onRejected). Captura cualquier rechazo en la cadena anterior. Es mucho más legible que .then(null, fn).
  • .finally(onFinally): se ejecuta siempre, tanto si la promesa se cumple como si se rechaza. No recibe argumentos (no sabe si fue éxito o error). Ideal para limpiar loaders, cerrar conexiones, ocultar spinners. finally devuelve una nueva promesa que mantiene el valor o rechazo original.

Métodos estáticos de Promise

Promise.resolve() y Promise.reject()

Promise.resolve(valor) crea una promesa ya cumplida con ese valor. Promise.reject(razon) crea una promesa ya rechazada. Útiles para testing, para convertir valores en promesas, o para iniciar cadenas de promesas con un valor conocido.

Promise.all(iterable)

Recibe un array de promesas y devuelve una nueva promesa que:

  • Se cumple cuando todas las promesas del array se cumplen, con un array de sus valores en el mismo orden.
  • Se rechaza en cuanto una sola promesa se rechaza, con el motivo de ese primer rechazo. Las demás promesas siguen ejecutándose pero su resultado se ignora.
// 🚀 Ejecución en paralelo con Promise.all
const [usuario, posts, config] = await Promise.all([
  fetch('/api/usuario').then(r => r.json()),
  fetch('/api/posts').then(r => r.json()),
  fetch('/api/config').then(r => r.json()),
]);

Promise.allSettled(iterable) — ES2020

Espera a que todas las promesas terminen (cumplidas o rechazadas). Devuelve un array de objetos con { status: 'fulfilled', value } o { status: 'rejected', reason }. Nunca se rechaza. Ideal cuando necesitas el resultado de todas las operaciones sin que un fallo detenga el proceso.

Promise.race(iterable)

Devuelve una promesa que se resuelve con el resultado de la primera promesa que se "settlee" (cumplida o rechazada). Si la primera en terminar es un rechazo, la promesa resultante se rechaza. Útil para implementar timeouts manuales.

Promise.any(iterable) — ES2021

Devuelve una promesa que se cumple con el valor de la primera promesa que se cumpla. Solo se rechaza si todas las promesas se rechazan (devuelve un AggregateError con todos los errores). Es como race pero ignorando los rechazos. Útil para consultar varias réplicas de un servicio y quedarte con la que responda antes.

Promise.try(accion) — ES2025

Ejecuta una función (síncrona o asíncrona) y envuelve su resultado en una promesa cumplida, o su error en una promesa rechazada. Es el "try/catch en versión promesa": con él no necesitas saber de antemano si la función devuelve un valor o una promesa, ni si lanza un error síncrono. Unifica todos los casos en una sola promesa:

// ❌ Sin Promise.try: tienes que manejar el caso síncrono a mano
let resultado;
try {
  resultado = Promise.resolve(miAccion()); // ¿y si miAccion lanza antes?
} catch (err) {
  resultado = Promise.reject(err);
}

// ✅ Con Promise.try (ES2025): siempre obtienes una promesa, sin try/catch manual
Promise.try(miAccion)
  .then(valor => console.log('Éxito:', valor))
  .catch(err => console.error('Fallo:', err));

// miAccion puede ser síncrona, devolver una promesa, o lanzar — da igual.
// Promise.try lo convierte todo en el mismo flujo .then/.catch.

Microtasks

Los callbacks de .then(), .catch() y .finally() se ejecutan en la Microtask Queue, que tiene prioridad sobre la Callback Queue (donde van setTimeout, eventos DOM, etc). Esto significa que el event loop vacía todas las microtasks pendientes antes de procesar cada macrotask.

3 · Ejemplo mínimo

// 🧪 La promesa más simple posible
const promesa = new Promise((resolve, reject) => {
  // resolve y reject son funciones que da el constructor
  const exito = true;

  if (exito) {
    resolve('✅ Datos obtenidos'); // Cumple la promesa con este valor
  } else {
    reject('❌ Error de conexión'); // Rechaza la promesa con esta razón
  }
});

// Consumir la promesa: encadenar reacciones
promesa
  .then(resultado => console.log('Éxito:', resultado))
  .catch(error => console.error('Fallo:', error))
  .finally(() => console.log('Operación terminada (éxito o fallo)'));

// Estado inicial: pending (pendiente)
// Tras resolve: fulfilled, valor = '✅ Datos obtenidos'

Línea a línea:

  1. new Promise(executor) crea el objeto promesa. El executor recibe dos funciones: resolve y reject.
  2. El executor se ejecuta inmediatamente (síncrono). Aquí decides el destino de la promesa.
  3. Si llamas a resolve(valor), la promesa se cumple con ese valor.
  4. Si llamas a reject(razon), la promesa se rechaza con esa razón.
  5. .then(fn) registra una reacción al cumplimiento. Devuelve una nueva promesa, permitiendo encadenar.
  6. .catch(fn) captura rechazos de cualquier punto anterior de la cadena.
  7. .finally(fn) se ejecuta siempre, no recibe valor.

4 · Ejemplo real

Promisificando el descargador de archivos

Convertimos el ejemplo de callbacks de la lección anterior a promesas:

/**
 * Ahora descargarArchivo devuelve una PROMESA en lugar de recibir un callback.
 * Esto elimina la inversión de control: el consumidor decide qué hacer.
 */
function descargarArchivo(url) {
  console.log(`⬇ Iniciando descarga desde ${url}...`);

  return new Promise((resolve, reject) => {
    const tiempo = Math.floor(Math.random() * 2000) + 500;

    setTimeout(() => {
      if (Math.random() < 0.2) {
        reject(new Error(`Fallo de red al descargar ${url}`));
        return;
      }
      resolve(`📄 Contenido de ${url} (${tiempo}ms)`);
    }, tiempo);
  });
}

// ✨ Con promesas: encadenamiento plano, sin anidación
descargarArchivo('/api/fotos/perfil.png')
  .then(archivo1 => {
    console.log('✅ Archivo 1:', archivo1);
    return descargarArchivo('/api/fotos/portada.png'); // Retornar promesa encadena
  })
  .then(archivo2 => {
    console.log('✅ Archivo 2:', archivo2);
    return descargarArchivo('/api/fotos/avatar.png');
  })
  .then(archivo3 => {
    console.log('✅ Archivo 3:', archivo3);
    console.log('🎉 Todas las descargas completadas');
  })
  .catch(error => {
    // Un solo catch captura errores de cualquier paso anterior
    console.error('❌ Fallo en alguna descarga:', error.message);
  })
  .finally(() => {
    console.log('🏁 Proceso de descarga finalizado (éxito o error)');
  });

Promise.all en acción: cargando datos de un dashboard

// Simulamos 3 endpoints de un dashboard que se cargan en paralelo
function obtenerMetrica(nombre) {
  return new Promise(resolve => {
    const ms = Math.floor(Math.random() * 1500) + 300;
    setTimeout(() => resolve({ nombre, valor: Math.round(Math.random() * 1000), ms }), ms);
  });
}

const metricas = Promise.all([
  obtenerMetrica('Usuarios activos'),
  obtenerMetrica('Ventas hoy'),
  obtenerMetrica('Tasa de rebote'),
]);

console.time('⏱ Dashboard cargado en');

metricas
  .then(resultados => {
    console.timeEnd('⏱ Dashboard cargado en');
    console.table(resultados);
    // Las 3 métricas se cargaron en paralelo (~max 1800ms en lugar de ~4500ms)
  })
  .catch(error => console.error('Dashboard falló:', error));

Promise.race: timeout manual

function fetchConTimeout(url, ms) {
  const timeout = new Promise((_, reject) =>
    setTimeout(() => reject(new Error(`Timeout: ${ms}ms excedido`)), ms)
  );

  // La primera promesa que se resuelva (fetch o timeout) gana
  return Promise.race([fetch(url), timeout]);
}

fetchConTimeout('/api/datos-lentos', 3000)
  .then(res => res.json())
  .then(data => console.log('Datos:', data))
  .catch(err => console.error(err.message));

6 · Errores habituales

Error 1: No retornar la promesa en un .then()

// ❌ MAL: no se retorna la promesa
fetch('/api/usuario')
  .then(res => res.json())
  .then(usuario => {
    fetch(`/api/pedidos/${usuario.id}`); // ¡No hay return!
  })
  .then(pedidos => {
    console.log(pedidos); // undefined — el fetch de pedidos se ignora
  });

// ✅ CORRECTO: retornar la promesa
fetch('/api/usuario')
  .then(res => res.json())
  .then(usuario => {
    return fetch(`/api/pedidos/${usuario.id}`); // return encadena
  })
  .then(res => res.json())
  .then(pedidos => console.log(pedidos)); // Ahora sí tiene datos

Error 2: Promise.all rechaza al primer error y las demás se descartan

// ❌ MAL: si una falla, pierdes el resultado de las que sí funcionaron
const [usuarios, pedidos] = await Promise.all([
  fetch('/api/usuarios'),
  fetch('/api/pedidos-que-falla'),
]);

// ✅ CORRECTO si necesitas todos los resultados pase lo que pase:
const resultados = await Promise.allSettled([
  fetch('/api/usuarios'),
  fetch('/api/pedidos-que-falla'),
]);

resultados.forEach((r, i) => {
  if (r.status === 'fulfilled') console.log(`OK ${i}:`, r.value);
  else console.error(`Error ${i}:`, r.reason);
});

Error 3: Crear una promesa innecesariamente (el constructor antipattern)

// ❌ ANTIPATTERN: envolver una función que ya devuelve promesa en new Promise
function obtenerUsuario(id) {
  return new Promise((resolve, reject) => {
    fetch(`/api/usuarios/${id}`) // fetch YA devuelve una promesa
      .then(res => resolve(res))
      .catch(err => reject(err));
  });
}

// ✅ CORRECTO: simplemente devuelve la promesa existente
function obtenerUsuario(id) {
  return fetch(`/api/usuarios/${id}`);
}

8 · Reto

🎯 Implementa Promise.all desde cero

Crea una función promiseAll(promesas) que reciba un array de promesas y se comporte exactamente como Promise.all: devuelve una promesa que se cumple con un array de resultados en orden cuando todas terminan, o se rechaza con el primer error. No puedes usar Promise.all en tu implementación.

Pistas:

  • Devuelve una new Promise().
  • Usa un contador para saber cuántas promesas se han cumplido.
  • Almacena los resultados en un array en la misma posición que la promesa original.
  • En cuanto una promesa falle, rechaza la promesa externa.

9 · Resumen

  • Una promesa es un objeto que representa un valor futuro con 3 estados: pending, fulfilled, rejected.
  • El estado de una promesa es inmutable: una vez settled no cambia.
  • .then() devuelve una nueva promesa, permitiendo encadenamiento plano.
  • .catch() captura rechazos de toda la cadena anterior. Poner uno al final es buena práctica.
  • .finally() se ejecuta siempre, ideal para limpieza de UI (spinners, loaders).
  • Promise.all() ejecuta en paralelo; rechaza al primer error.
  • Promise.allSettled() espera a todas sin rechazar nunca.
  • Promise.race() devuelve la primera en settled (cumplida o rechazada).
  • Promise.any() devuelve la primera fulfilled; solo rechaza si todas fallan.
  • Los callbacks de promesas van a la Microtask Queue, con prioridad sobre la Callback Queue.
  • No envuelvas funciones que ya devuelven promesas en new Promise (constructor antipattern).

10 · Preguntas frecuentes

¿Cuál es la diferencia entre Promise.race y Promise.any?

race se resuelve con la primera promesa que termine, aunque sea un rechazo. Si la primera en terminar es un error, race rechaza. any en cambio ignora los rechazos: se cumple con la primera que tenga éxito y solo rechaza si absolutamente todas fallan (lanzando un AggregateError). race es ideal para timeouts, any para consultar servidores redundantes.

¿Qué pasa si no pongo un .catch() al final de la cadena?

El rechazo no se captura. En navegadores modernos y Node.js, una promesa rechazada sin catch produce el evento unhandledrejection, que en Node 15+ termina el proceso. En el navegador aparece un warning en la consola. Siempre pon un .catch() al final (o un try/catch si usas async/await).

¿Puedo encadenar .then() después de un .catch()?

Sí. .catch() devuelve una promesa. Si el catch maneja el error y retorna un valor, ese valor pasa al siguiente .then(). Esto permite patrones de recuperación: capturas un error, proporcionas un valor por defecto, y la cadena continúa como si nada hubiera fallado.

¿Por qué Promise.all rechaza al primer error en vez de esperar a todas?

Es una decisión de diseño. Promise.all implementa la semántica de "todas o nada": si una dependencia falla, probablemente no puedes completar la operación general. Si necesitas esperar a todas incluso con fallos, usa Promise.allSettled, disponible desde ES2020.
