Ejecución en navegador, Node y Vite

Módulo 0 · Preparación ⏱ 25 minutos

1 · Introducción

JavaScript es un lenguaje interpretado, no compilado. Eso significa que necesitas un programa (un motor) que lea tu código línea por línea y lo ejecute en tiempo real. Pero hay varios motores y varios entornos, cada uno con sus propias APIs y capacidades.

En esta lección aprenderás dónde y cómo ejecutar JavaScript: directamente en el navegador (DevTools), como archivo independiente con Node.js, y dentro del flujo de desarrollo moderno con Vite. Entenderás las diferencias entre cada entorno y cuándo usar cada uno.

¿Por qué existe esta lección? Porque ejecutar JS en el sitio equivocado con las APIs equivocadas es uno de los errores más comunes de principiantes. Saber distinguir entre el entorno del navegador y el de Node.js es fundamental para no perder horas depurando errores como «window is not defined».

2 · Teoría

Los tres entornos de ejecución

JavaScript puede ejecutarse en tres contextos principales. Cada uno tiene un propósito distinto:

1. Navegador (DevTools Console + archivos HTML)

Es el entorno original y nativo de JavaScript. Cada pestaña del navegador es una sandbox aislada con su propio motor JS. Puedes ejecutar código de dos formas:

  • DevTools Console: abre F12 → pestaña Console. Escribe código y pulsa Enter. Ideal para experimentos rápidos y depuración.
  • Archivos HTML con <script>: incluyes JS dentro de un HTML. Es la forma tradicional de añadir interactividad a una página web.

APIs disponibles en el navegador:

  • window — el objeto global. Todo lo que cuelga de él es accesible globalmente.
  • document — el DOM. Manipula HTML y CSS desde JS.
  • fetch — peticiones HTTP.
  • localStorage / sessionStorage — persistencia de datos en el navegador.
  • console — salida de depuración.
  • setTimeout / setInterval — temporizadores.
  • addEventListener — escucha de eventos (clicks, teclas, scroll...).

2. Node.js (REPL + archivos .js)

Node.js ejecuta JavaScript en tu sistema operativo, fuera del navegador. Tiene acceso al sistema de archivos, a la red y a procesos del sistema. También ofrece dos formas de ejecución:

  • REPL: escribe node en la terminal y entra en modo interactivo (Read-Eval-Print-Loop). Cada línea que escribes se evalúa al instante.
  • Archivo: escribe tu código en script.js y ejecuta node script.js.

APIs disponibles en Node.js (y NO en el navegador):

  • global — el objeto global (equivalente a window).
  • fs — sistema de archivos (leer, escribir, borrar archivos).
  • path — manipulación de rutas de archivo.
  • process — información y control del proceso actual (argv, env, exit).
  • Buffer — manejo de datos binarios.
  • require / import — sistema de módulos.

APIs que NO existen en Node.js:

  • window, document, localStorage, fetch (hasta Node 18 no existía fetch nativo; ahora sí, como API experimental estable).

3. Vite (servidor de desarrollo)

Vite no es un entorno de ejecución distinto: es un servidor de desarrollo que ejecuta tu código en el navegador, pero con superpoderes:

  • Servicio de módulos ESM: sirve tus archivos JS como módulos ES nativos al navegador.
  • HMR: recarga módulos individuales sin perder el estado de la app.
  • Pre-procesado: transforma TypeScript, JSX, CSS moderno... en código que el navegador entiende.

Cuando ejecutas pnpm dev, Vite inicia un servidor HTTP en localhost:5173. Tu código se ejecuta en el navegador (no en Node), pero Vite lo sirve de forma optimizada.

Los métodos de console

console es la herramienta de depuración más básica y universal. Funciona en navegadores y en Node.js:

console.log('Mensaje normal');        // Salida estándar
console.error('Esto es un error');    // Sale en rojo, va a stderr
console.warn('Atención');             // Sale en amarillo
console.table([{ a: 1 }, { a: 2 }]); // Tabla formateada para arrays/objetos
console.group('Mi grupo');            // Agrupa mensajes
console.log('Dentro del grupo');
console.groupEnd();                   // Cierra el grupo
console.time('timer');                // Inicia cronómetro
// ... código a medir ...
console.timeEnd('timer');             // Muestra: timer: XXms

Cómo incluir JS en HTML: inline vs externo, defer vs async

FormaEjemploCuándo se ejecuta
Inline <script>console.log('hola')</script> Inmediatamente al encontrarlo en el HTML
Externo sin atributos <script src="app.js"></script> Bloquea el parseo HTML hasta descargar y ejecutar
Externo con defer <script src="app.js" defer></script> Descarga en paralelo, ejecuta después de parsear el HTML, en orden
Externo con async <script src="app.js" async></script> Descarga en paralelo, ejecuta en cuanto se descarga, sin orden garantizado

Regla de oro: Usa defer para tus scripts principales. Se descargan sin bloquear el HTML y se ejecutan en orden. Es el comportamiento que quieres el 99% del tiempo.

3 · Ejemplo mínimo

El mismo código, ejecutado en tres entornos distintos:

En la consola del navegador (F12 → Console)

console.log('Ejecutado en el navegador');
console.log('URL actual:', window.location.href);   // Funciona
console.log('User agent:', navigator.userAgent);     // Funciona

En un archivo .js con Node.js

# Crea un archivo test.js y ejecútalo
node test.js

// test.js
console.log('Ejecutado en Node.js');
console.log('Directorio actual:', process.cwd());   // Funciona
console.log('Versión de Node:', process.version);    // Funciona
// console.log(window.location.href);  // ❌ ReferenceError: window is not defined

En Vite (index.html + main.js)


<script type="module" src="/src/main.js"></script>
// src/main.js
console.log('Ejecutado en Vite (navegador)');
// Vite soporta import nativo de módulos
import './style.css';

4 · Ejemplo real

Un patrón común en desarrollo profesional: tienes un script que debe funcionar tanto en navegador como en Node.js. Necesitas detectar el entorno:

// detectar-entorno.js — Funciona en navegador y en Node.js

// typeof window !== 'undefined' → estoy en un navegador
// typeof process !== 'undefined' → estoy en Node.js

function detectarEntorno() {
  if (typeof window !== 'undefined') {
    console.log('🌐 Entorno: Navegador');
    console.log('   URL:', window.location.href);
    console.log('   Tamaño ventana:', window.innerWidth, 'x', window.innerHeight);
    return 'browser';
  }

  if (typeof process !== 'undefined' && process.versions && process.versions.node) {
    console.log('🖥  Entorno: Node.js');
    console.log('   Versión:', process.version);
    console.log('   Plataforma:', process.platform);
    console.log('   Memoria:', process.memoryUsage().heapUsed, 'bytes usados');
    return 'node';
  }

  console.log('❓ Entorno desconocido');
  return 'unknown';
}

detectarEntorno();

Este tipo de detección es útil al escribir librerías isomórficas (que funcionan en ambos entornos) o al depurar scripts que se comportan distinto según dónde se ejecuten.

6 · Errores habituales

Intentar usar APIs del navegador en Node.js

// ❌ Ejecutando este código con node script.js
// window.alert('Hola');        // ReferenceError: window is not defined
// document.querySelector();    // ReferenceError: document is not defined
// localStorage.setItem();      // ReferenceError: localStorage is not defined

// ✅ Si necesitas funcionalidades similares en Node:
// - alert → console.log
// - document → cheerio o jsdom (librerías)
// - localStorage → archivos en disco o node-localstorage

No entender que la consola del navegador comparte el mismo scope

// En la consola del navegador, escribe línea por línea:
let x = 5;
console.log(x); // 5 ← 'x' existe porque todas las líneas comparten scope
// Esto no pasa al ejecutar node script.js: cada línea es independiente

Olvidar que console.log en Node.js va a stdout, no a un panel gráfico

# ❌ Esperar que console.log en Node muestre colores bonitos
# Por defecto, es texto plano. Puedes usar librerías como chalk o
# aprovechar que Node soporta códigos ANSI:
node -e "console.log('\x1b[32m%s\x1b[0m', 'Verde en Node.js')"

Confundir type="module" con defer


<script type="module" src="app.js" defer></script>


<script type="module" src="app.js"></script>

8 · Reto

🎯 Crea un «detective de APIs»

Escribe un script que, al ejecutarse, imprima en consola una tabla con todas las APIs disponibles en ese entorno. Por ejemplo:

  • Si se ejecuta en el navegador, debería mostrar si window, document, fetch, localStorage están disponibles (typeof no debe ser 'undefined').
  • Si se ejecuta en Node.js, debería mostrar si process, fs, path, Buffer están disponibles.
  • Bonus: usa console.table para mostrar el resultado en formato tabla con columnas «API» y «Disponible».

Pista: typeof window !== 'undefined' es true en navegador, false en Node.

9 · Resumen

  • JavaScript se ejecuta en tres entornos principales: navegador, Node.js y servidor de desarrollo (Vite).
  • El navegador expone APIs como window, document, fetch, localStorage.
  • Node.js expone APIs como process, fs, path, Buffer.
  • Vite no es un entorno distinto: sirve tu código al navegador con HMR y soporte ESM.
  • console funciona en todos los entornos. Métodos útiles: log, error, table, group, time.
  • Usa defer en tus scripts HTML para no bloquear el renderizado de la página.
  • Los scripts type="module" son defer por defecto.

10 · Preguntas frecuentes

¿Puedo ejecutar el mismo código en navegador y Node.js?

Sí, si evitas usar APIs exclusivas de cada entorno. Por ejemplo, un algoritmo puro de JavaScript (ordenar un array, calcular fechas, manipular strings) funciona idéntico en ambos. El problema viene cuando necesitas APIs específicas (leer un archivo, manipular el DOM). Para código isomórfico, detecta el entorno con typeof window y bifurca la lógica.

¿Por qué usar Vite si puedo abrir el HTML directamente en el navegador?

Por tres razones: (1) los módulos ES (import/export) no funcionan al abrir HTML directamente desde el disco (por políticas CORS); necesitas un servidor HTTP. (2) Vite ofrece HMR: cambios instantáneos sin recargar. (3) Vite empaqueta y optimiza tu código para producción con un solo comando (pnpm build).

¿Qué diferencia hay entre REPL de Node y la consola del navegador?

Conceptualmente son iguales: escribes código y se ejecuta línea por línea. La diferencia está en las APIs disponibles. En el REPL de Node puedes usar fs.readFileSync(); en la consola del navegador puedes usar document.querySelector(). El motor JS (V8) es el mismo en ambos.

¿Cuándo usar console.error en vez de console.log?

console.error escribe en stderr (salida de error estándar) en lugar de stdout. En Node.js puedes redirigir stderr y stdout por separado (ej: node app.js 2>errores.log). En navegadores, console.error muestra el mensaje en rojo y a menudo incluye el stack trace. Úsalo para errores reales, no para logs informativos.

¿console.log es sincrónico o asincrónico?

En Node.js, console.log es sincrónico cuando la salida es una terminal, y asincrónico cuando es un pipe. En navegadores, es asincrónico (el mensaje se encola y se muestra en el siguiente ciclo de pintado). Esto puede causar que veas objetos expandidos con valores «futuros» al hacer console.log(obj) y luego mutar obj.
