Entorno: Node.js, pnpm, Vite y VSCode

Módulo 0 · Preparación ⏱ 35 minutos

1 · Introducción

Antes de escribir una sola línea de código productivo, necesitas un entorno de desarrollo profesional. Esta lección te guía paso a paso para instalar y configurar las cuatro herramientas que usarás durante todo el curso: Node.js (el entorno de ejecución), pnpm (el gestor de paquetes), VSCode (el editor de código) y Vite (el servidor de desarrollo).

¿Por qué existe esta lección? Un entorno mal configurado es la causa número uno de frustración al empezar. Dedicar 35 minutos ahora a dejar todo listo te ahorrará horas de problemas más adelante. Un profesional no improvisa su entorno: lo domina.

2 · Teoría

Node.js: JavaScript fuera del navegador

En 2009, Ryan Dahl tomó el motor V8 de Chrome (el mismo que ejecuta JavaScript en el navegador) y lo empotró en un programa que corre en tu sistema operativo. Así nació Node.js: un entorno que permite ejecutar JavaScript en el servidor, en tu terminal, en scripts de automatización — en cualquier sitio fuera del navegador.

Node.js incluye:

  • El motor V8: compila y ejecuta JavaScript.
  • libuv: maneja operaciones de entrada/salida asíncronas (archivos, red).
  • APIs nativas: acceso al sistema de archivos (fs), rutas (path), procesos (process), red (http).
  • npm/pnpm: el gestor de paquetes integrado.

Analogía: Node.js es a JavaScript lo que un coche es a su motor. El motor V8 funciona dentro del coche (Chrome), pero puedes sacarlo y montarlo en una moto (Node.js), un barco (Electron) o un generador (CLI). El motor es el mismo; lo que cambia es el vehículo que lo rodea y las capacidades que ofrece.

pnpm: gestor de paquetes eficiente

pnpm (performant npm) es un gestor de paquetes alternativo a npm y yarn. Sus ventajas:

  • Eficiencia de disco: almacena cada paquete una sola vez en tu disco y usa enlaces simbólicos (symlinks). Con 10 proyectos que usen React, solo descargas React una vez.
  • Estricto: por defecto, un paquete solo puede acceder a las dependencias declaradas en su package.json. Esto evita bugs por dependencias fantasma.
  • Rápido: resuelve e instala dependencias hasta 3 veces más rápido que npm.
  • Compatible: usa el mismo registro de paquetes que npm. Todo lo que funciona con npm funciona con pnpm.

Nota: En este curso usamos pnpm en todos los comandos. Si ves un tutorial que dice npm install, simplemente traduce mentalmente a pnpm add o pnpm install.

VSCode: el editor estándar

Visual Studio Code es el editor más usado del mundo (según la encuesta de Stack Overflow). Es gratuito, open source, multiplataforma y tiene un ecosistema de extensiones enorme.

Extensiones recomendadas para JavaScript:

  • ESLint: análisis estático de código. Detecta errores y malas prácticas antes de ejecutar.
  • Prettier: formateador automático. Todo tu código tendrá el mismo estilo sin que pienses en espacios o comas.
  • Live Server: servidor local con recarga automática para HTML/CSS/JS estático.

Vite: el servidor de desarrollo moderno

Vite (palabra francesa para «rápido») es un servidor de desarrollo y empaquetador creado por Evan You (el creador de Vue.js). A diferencia de Webpack, Vite:

  • Arranca instantáneamente: no empaqueta todo el proyecto antes de servir. Sirve los módulos como archivos individuales usando ESM nativo del navegador.
  • HMR ultrarrápido: Hot Module Replacement: los cambios se reflejan en milisegundos, sin recargar toda la página.
  • Configuración mínima: funciona out-of-the-box para JavaScript vanilla.

Requisitos actuales (Vite 8): Vite necesita Node.js 20.19+ o 22.12+. Se distribuye exclusivamente como módulo ES (ESM), por lo que tu proyecto debe usar "type": "module". Las LTS recientes de Node (22 y 24) lo cumplen sin problema.

Dato clave: Vite usa esbuild (escrito en Go) para pre-empaquetar dependencias. Es entre 10 y 100 veces más rápido que los empaquetadores basados en JavaScript como Webpack o Rollup.

3 · Ejemplo mínimo

Una vez instalado todo, crear un proyecto desde cero toma 30 segundos:

# 1. Crear proyecto con Vite (template vanilla JavaScript)
pnpm create vite mi-primer-app --template vanilla

# 2. Entrar en el proyecto
cd mi-primer-app

# 3. Instalar dependencias
pnpm install

# 4. Iniciar el servidor de desarrollo
pnpm dev

Vite te mostrará algo como:

VITE v8.x.x  ready in 350 ms

➜  Local:   http://localhost:5173/
➜  Network: use --host to expose

Abre http://localhost:5173/ en tu navegador. Verás la página de bienvenida de Vite. Modifica main.js y observa cómo la página se actualiza instantáneamente sin que toques F5.

4 · Ejemplo real

Estructura de un proyecto Vite + vanilla JS profesional:

mi-app/
├── .gitignore          # Archivos que Git debe ignorar
├── index.html          # Punto de entrada HTML
├── package.json        # Metadatos y dependencias del proyecto
├── pnpm-lock.yaml      # Lock file de pnpm (versiones exactas)
├── vite.config.js      # Configuración de Vite (opcional)
├── public/             # Archivos estáticos (favicon, imágenes)
│   └── favicon.svg
└── src/
    ├── main.js         # Punto de entrada JavaScript
    ├── style.css       # Estilos globales
    └── counter.js      # Módulo con lógica de negocio

El archivo package.json típico de un proyecto JavaScript:

{
  "name": "mi-primer-app",
  "private": true,
  "version": "1.0.0",
  "type": "module",
  "scripts": {
    "dev": "vite",
    "build": "vite build",
    "preview": "vite preview"
  },
  "devDependencies": {
    "vite": "^8.0.0"
  }
}

El campo "type": "module" es importante: le dice a Node.js que use módulos ES (import/export) en lugar de CommonJS (require). Todos los proyectos modernos lo usan.

El .gitignore mínimo para un proyecto Vite:

node_modules/
dist/
.env
*.local

6 · Errores habituales

No verificar la instalación de Node.js

# ❌ Asumir que Node.js está instalado sin comprobarlo
# Intentar ejecutar 'node' sin haberlo instalado

# ✅ Verificar siempre después de instalar
node -v   # Debería mostrar algo como v22.x.x
pnpm -v   # Debería mostrar algo como 9.x.x

Instalar dependencias en el directorio equivocado

# ❌ Ejecutar pnpm install sin package.json en el directorio
# pnpm install  # ERR_PNPM_NO_PKG_MANIFEST

# ✅ Asegúrate de estar en el directorio del proyecto (donde está package.json)
cd mi-app
pnpm install

Olvidar que Vite necesita que index.html esté en la raíz

Confundir pnpm con npm en los comandos

# ❌ Usar npm cuando el proyecto se creó con pnpm
# npm install  # Genera package-lock.json, mezclando gestores

# ✅ Sé consistente: si el proyecto usa pnpm, siempre pnpm
pnpm install          # Instalar dependencias
pnpm add paquete      # Añadir un paquete
pnpm remove paquete   # Eliminar un paquete
pnpm dev              # Ejecutar script "dev"

  1. Paso 1 — Crear el proyecto:

cd hello-js

    Abre http://localhost:5173/ y verifica que ves tu mensaje.

8 · Reto

🎯 Instala Node.js con nvm-windows

Si estás en Windows, descarga e instala nvm-windows desde su repositorio oficial en GitHub. Luego:

  1. Instala la última versión LTS de Node.js con nvm install lts.
  2. Actívala con nvm use lts.
  3. Verifica que funciona con node -v.
  4. Habilita pnpm con corepack enable y luego corepack prepare pnpm@latest --activate.
  5. Crea un proyecto Vite nuevo y muestra node -v y pnpm -v en la consola del proyecto para confirmar que todo está correcto.

Si estás en Linux/Mac, usa nvm (no nvm-windows). Los comandos de instalación son similares.

9 · Resumen

  • Node.js es el entorno que ejecuta JavaScript fuera del navegador, usando el motor V8.
  • pnpm es un gestor de paquetes eficiente, estricto y compatible con el ecosistema npm.
  • VSCode es el editor estándar; instala ESLint y Prettier desde el primer día.
  • Vite es un servidor de desarrollo ultrarrápido con HMR nativo y configuración mínima.
  • Un proyecto Vite se crea con pnpm create vite nombre --template vanilla.
  • El archivo package.json define scripts, dependencias y debe incluir "type": "module".
  • Los comandos esenciales: pnpm install, pnpm dev, pnpm build, pnpm preview.

10 · Preguntas frecuentes

¿Por qué pnpm y no npm? ¿No es npm el oficial?

npm es el gestor que viene con Node.js y es perfectamente usable. pnpm es una alternativa que resuelve los mismos problemas pero de forma más eficiente (usa enlaces simbólicos para no duplicar paquetes en disco) y más estricta (no permite acceder a dependencias no declaradas). En este curso usamos pnpm porque es más rápido y enseña buenas prácticas de gestión de dependencias. Pero los conceptos son idénticos: todo lo que aprendas con pnpm funciona igual con npm.

¿Necesito instalar Vite globalmente?

No. Vite se instala como dependencia de desarrollo (devDependencies) de cada proyecto. El comando pnpm create vite usa pnpm dlx internamente, que descarga Vite temporalmente solo para crear el proyecto. Esto significa que cada proyecto tiene su propia versión de Vite, evitando conflictos entre proyectos.

¿Qué pasa si mi equipo usa npm en vez de pnpm?

pnpm usa el mismo formato de package.json que npm. La diferencia está en el lock file: npm genera package-lock.json y pnpm genera pnpm-lock.yaml. Si tu equipo usa npm, puedes usar npm; los conceptos son los mismos. Pero si puedes elegir, pnpm es técnicamente superior.

¿Qué extensión de VSCode es imprescindible para JavaScript?

Además de ESLint y Prettier, recomiendo JavaScript (ES6) code snippets para snippets rápidos, y GitLens para ver el historial de cambios en cada línea. Pero la configuración base con ESLint + Prettier ya cubre el 90% de las necesidades profesionales.

¿Para qué sirve vite.config.js si Vite funciona sin configuración?

Vite funciona con «cero configuración» para casos comunes (vanilla JS, Vue, React). vite.config.js es para personalizar: añadir plugins, configurar alias de rutas, definir variables de entorno, ajustar el build... Lo necesitarás cuando tu proyecto crezca, pero para empezar no hace falta.
