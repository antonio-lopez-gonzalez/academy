Formularios: FormData, validación y tipos de input

Módulo 5 · DOM y Eventos ⏱ 35 minutos

1 · Introducción

Los formularios son el principal mecanismo de entrada de datos en la web. JavaScript ofrece dos APIs complementarias para trabajar con ellos: FormData para recolectar datos sin tocar cada campo individualmente, y la Constraint Validation API para validar los datos de forma nativa, con mensajes de error personalizables y selectores CSS. Combinadas, permiten formularios robustos con muy poco código.

2 · Teoría

FormData API — Recoger datos sin iterar inputs manualmente

const formulario = document.querySelector('#registro');

formulario.addEventListener('submit', (e) => {
  e.preventDefault();

  // Crear FormData a partir del formulario
  const datos = new FormData(formulario);

  // Leer valores individuales
  console.log(datos.get('email'));       // 'usuario@correo.com'
  console.log(datos.get('password'));    // '123456'

  // Campos con múltiples valores (ej. checkbox group, select multiple)
  console.log(datos.getAll('intereses')); // ['música', 'deportes']

  // Iterar todos los campos
  for (const [clave, valor] of datos) {
    console.log(`${clave}: ${valor}`);
  }

  // Verificar si un campo existe
  console.log(datos.has('email')); // true

  // Añadir campos extra
  datos.append('timestamp', Date.now());
  datos.set('email', 'nuevo@correo.com'); // set sobrescribe, append añade

  // Enviar como JSON
  const objeto = Object.fromEntries(datos);
  console.log(JSON.stringify(objeto));

  // O enviar directamente como FormData (para archivos, etc.)
  // fetch('/api/registro', { method: 'POST', body: datos });
});

Constraint Validation API

Cada input tiene propiedades y métodos de validación:

const emailInput = document.querySelector('#email');

// Propiedades de validez
console.log(emailInput.validity);
// ValidityState {
//   valid: true/false,
//   valueMissing: true/false,     // required y vacío
//   typeMismatch: true/false,     // pattern o type no coinciden
//   tooShort: true/false,         // minlength
//   tooLong: true/false,          // maxlength
//   rangeUnderflow: true/false,   // menor que min
//   rangeOverflow: true/false,    // mayor que max
//   stepMismatch: true/false,     // no cumple el step
//   badInput: true/false,         // valor no parseable
//   patternMismatch: true/false,  // no cumple la regex de pattern
//   customError: true/false       // setCustomValidity() activo
// }

// Métodos
console.log(emailInput.checkValidity());   // true/false (dispara 'invalid' si false)
console.log(emailInput.reportValidity());  // true/false (muestra mensaje nativo si false)
emailInput.setCustomValidity('');          // Limpiar error personalizado
emailInput.setCustomValidity('Email no válido para este dominio'); // Establecer error

Validar un formulario completo

const form = document.querySelector('#formulario');

// Validar todo el formulario (sin submit)
if (form.checkValidity()) {
  console.log('Formulario válido');
} else {
  console.log('Formulario inválido');
}

// Reportar visualmente los errores
form.reportValidity();

// Al hacer submit, prevenir y validar manualmente
form.addEventListener('submit', (e) => {
  e.preventDefault();

  if (!form.checkValidity()) {
    form.reportValidity(); // muestra el primer error encontrado
    return;
  }

  // Validación personalizada adicional
  const password = form.querySelector('#password').value;
  const confirmacion = form.querySelector('#confirmacion').value;

  if (password !== confirmacion) {
    form.querySelector('#confirmacion').setCustomValidity('Las contraseñas no coinciden');
    form.reportValidity();
    return;
  }

  // Si llegamos aquí, todo OK
  console.log('Enviando formulario...');
});

input:invalid {
  border-color: #f44336;
}

/* Solo mostrar error después de que el usuario haya interactuado */
input:not(:focus):invalid {
  border-color: #f44336;
  background-color: #fff5f5;
}

/* Ocultar el error hasta que el campo esté "sucio" (usuario lo haya tocado) */
/* Se puede hacer con JS: añadir clase 'tocado' en el evento blur */
input.tocado:invalid {
  border-color: #f44336;
}

Select y checkbox/radio con FormData

// Select simple: get() devuelve el value del option seleccionado
const select = document.querySelector('#pais');
datos.get('pais'); // 'es'

// Select multiple: getAll() devuelve un array
// <select name="categorias" multiple>
datos.getAll('categorias'); // ['tech', 'science']

// Checkbox group (mismo name): getAll() recoge los valores marcados
// <input type="checkbox" name="intereses" value="música">
// <input type="checkbox" name="intereses" value="deportes">
datos.getAll('intereses'); // ['música', 'deportes']

// Radio: get() devuelve el value del radio seleccionado
// <input type="radio" name="plan" value="basico">
// <input type="radio" name="plan" value="premium">
datos.get('plan'); // 'premium'

Validación en tiempo real (input event) vs en submit

const input = document.querySelector('#username');
const mensajeError = document.querySelector('#username-error');

// Validación en tiempo real: inmediata, reactiva
input.addEventListener('input', () => {
  if (input.validity.tooShort) {
    mensajeError.textContent = `Mínimo ${input.minLength} caracteres`;
  } else if (input.validity.patternMismatch) {
    mensajeError.textContent = 'Solo letras y números';
  } else {
    mensajeError.textContent = '';
  }
});

// Validación al perder el foco: cuando el usuario termina de escribir
input.addEventListener('blur', () => {
  input.classList.add('tocado');
  if (!input.checkValidity()) {
    mensajeError.textContent = input.validationMessage;
  }
});

// Validación en submit: validación final antes de enviar
form.addEventListener('submit', (e) => {
  if (!form.checkValidity()) {
    e.preventDefault();
    // Forzar la validación visual de todos los campos
    form.querySelectorAll('input, select, textarea').forEach(el => {
      el.classList.add('tocado');
    });
  }
});

Estrategia recomendada: input para feedback visual en tiempo real (bordes, iconos), blur para mostrar mensajes de error (no interrumpir mientras escribe), y submit para la validación final con reportValidity(). Así el usuario no se frustra con errores mientras teclea.

4 · Ejemplo real

Sistema de registro con validación completa:

class FormularioRegistro {
  constructor(formSelector) {
    this.form = document.querySelector(formSelector);
    this.campos = [...this.form.querySelectorAll('input, select, textarea')];

    this._iniciar();
  }

  _iniciar() {
    // Validación en tiempo real (solo feedback visual, sin mensajes de error)
    this.campos.forEach(campo => {
      campo.addEventListener('input', () => this._actualizarEstado(campo));
      campo.addEventListener('blur', () => {
        campo.classList.add('tocado');
        this._mostrarError(campo);
      });
    });

    this.form.addEventListener('submit', (e) => this._manejarSubmit(e));
  }

  _actualizarEstado(campo) {
    campo.classList.toggle('valido', campo.checkValidity());
    campo.classList.toggle('invalido', !campo.checkValidity() && campo.value.length > 0);
  }

  _mostrarError(campo) {
    const errorEl = document.querySelector(`[data-error="${campo.name}"]`);
    if (!errorEl) return;

    if (campo.validity.valid) {
      errorEl.textContent = '';
      return;
    }

    const mensajes = {
      valueMissing: 'Este campo es obligatorio',
      typeMismatch: campo.type === 'email' ? 'Introduce un email válido' : 'Formato no válido',
      tooShort: `Mínimo ${campo.minLength} caracteres (llevas ${campo.value.length})`,
      tooLong: `Máximo ${campo.maxLength} caracteres`,
      patternMismatch: campo.dataset.errorPattern || 'El formato no es correcto',
      rangeUnderflow: `El valor mínimo es ${campo.min}`,
      rangeOverflow: `El valor máximo es ${campo.max}`,
    };

    for (const [error, mensaje] of Object.entries(mensajes)) {
      if (campo.validity[error]) {
        errorEl.textContent = mensaje;
        break;
      }
    }
  }

  _manejarSubmit(e) {
    e.preventDefault();

    // Marcar todos como tocados para mostrar errores
    this.campos.forEach(c => c.classList.add('tocado'));

    // Validaciones personalizadas
    const password = this.form.querySelector('#password');
    const confirmacion = this.form.querySelector('#confirmacion');

    if (password.value !== confirmacion.value) {
      confirmacion.setCustomValidity('Las contraseñas no coinciden');
      confirmacion.reportValidity();
      return;
    } else {
      confirmacion.setCustomValidity('');
    }

    // Validar formulario completo
    if (!this.form.checkValidity()) {
      this.form.reportValidity();
      // Mostrar errores de todos los campos
      this.campos.forEach(c => this._mostrarError(c));
      return;
    }

    // Recolectar datos y enviar
    const datos = Object.fromEntries(new FormData(this.form));
    console.log('Enviando:', datos);
    this.form.reset();
    this.campos.forEach(c => {
      c.classList.remove('valido', 'invalido', 'tocado');
    });
  }
}

new FormularioRegistro('#registro');

6 · Errores habituales

Error 1: Olvidar limpiar el error personalizado

// ❌ MAL: El error se queda para siempre
password.addEventListener('input', () => {
  if (password.value.length < 8) {
    password.setCustomValidity('Mínimo 8 caracteres');
  }
  // Falta: else { password.setCustomValidity(''); }
});

// ✅ CORRECTO: Siempre limpiar cuando la condición ya no se cumple
password.addEventListener('input', () => {
  if (password.value.length < 8) {
    password.setCustomValidity('Mínimo 8 caracteres');
  } else {
    password.setCustomValidity(''); // Limpiar error
  }
});

Error 2: Checkbox no marcado no aparece en FormData

// ❌ MAL: Esperar que un checkbox no marcado aparezca como false
// Si el checkbox no está marcado, FormData simplemente NO incluye el campo
const datos = new FormData(form);
console.log(datos.get('aceptoTerminos')); // null (no false)

// ✅ CORRECTO: Manejar el caso de ausencia
const aceptaTerminos = datos.has('aceptoTerminos');
// o al convertir a objeto:
const obj = Object.fromEntries(datos);
obj.aceptoTerminos = obj.aceptoTerminos === 'on'; // 'on' → true, undefined → false

Error 3: No prevenir el submit antes de validar

// ❌ MAL: El formulario se envía antes de que la validación termine
form.addEventListener('submit', async (e) => {
  // e.preventDefault() debería ir AQUÍ, antes de cualquier await
  const valido = await validarContraServidor();
  if (!valido) e.preventDefault(); // Demasiado tarde, el submit ya ocurrió
});

// ✅ CORRECTO: Prevenir inmediatamente, luego validar
form.addEventListener('submit', async (e) => {
  e.preventDefault(); // Primero: cancelar el envío nativo
  const valido = await validarContraServidor();
  if (valido) {
    // Enviar manualmente con fetch()
    const datos = new FormData(form);
    await fetch('/api/registro', { method: 'POST', body: datos });
  }
});

    Nota: El atributo novalidate desactiva la validación nativa del navegador para que podamos controlarla totalmente con JS.

  2. Paso 2: Contador de caracteres en textarea

    const textarea = document.querySelector('#mensaje');
const contador = document.querySelector('#contador');

textarea.addEventListener('input', () => {
  const restante = textarea.value.length;
  contador.textContent = `${restante}/${textarea.maxLength}`;
  contador.style.color = restante > textarea.maxLength * 0.9 ? '#f44336' : '';
});

  3. Paso 3: Validación y envío

    const form = document.querySelector('#contacto');
const campos = [...form.querySelectorAll('input, select, textarea')];

const mensajesError = {
  valueMissing: 'Este campo es obligatorio',
  typeMismatch: 'Introduce un email válido',
  tooShort: (campo) => `Mínimo ${campo.minLength} caracteres`,
  tooLong: (campo) => `Máximo ${campo.maxLength} caracteres`,
};

function mostrarError(campo) {
  const errorEl = document.querySelector(`[data-error="${campo.name}"]`);
  if (!errorEl) return;

  campo.setCustomValidity(''); // Resetear error personalizado

  for (const [tipo, mensaje] of Object.entries(mensajesError)) {
    if (campo.validity[tipo]) {
      const msg = typeof mensaje === 'function' ? mensaje(campo) : mensaje;
      campo.setCustomValidity(msg);
      errorEl.textContent = msg;
      return;
    }
  }
  errorEl.textContent = '';
}

campos.forEach(campo => {
  campo.addEventListener('blur', () => mostrarError(campo));
  campo.addEventListener('input', () => {
    if (campo.checkValidity()) {
      document.querySelector(`[data-error="${campo.name}"]`).textContent = '';
    }
  });
});

form.addEventListener('submit', (e) => {
  e.preventDefault();
  let esValido = true;

  campos.forEach(campo => {
    mostrarError(campo);
    if (!campo.checkValidity()) esValido = false;
  });

  if (!esValido) return;

  const datos = Object.fromEntries(new FormData(form));
  console.log('Formulario válido:', datos);
  form.reset();
  contador.textContent = '0/500';
  alert('Mensaje enviado con éxito');
});

8 · Reto

🎯 Formulario multietapa (wizard)

Crea un formulario de registro en 3 pasos, mostrando solo un paso a la vez:

  • Paso 1: Datos personales (nombre, email, teléfono).
  • Paso 2: Dirección (país <select>, ciudad, código postal).
  • Paso 3: Preferencias (checkboxes de intereses, radio de plan).
  • Cada paso se valida antes de avanzar al siguiente.
  • Botones "Siguiente" y "Anterior" para navegar.
  • Al final, usa FormData para recolectar todos los datos del form (que contiene los 3 steps con display none/block).
  • Muestra un resumen antes del envío final con los datos de Object.fromEntries(formData).

9 · Resumen

  • new FormData(formulario) recolecta todos los campos automáticamente. Usa get(), getAll(), has().
  • Constraint Validation API: validity, checkValidity(), reportValidity(), setCustomValidity().
  • CSS: :valid y :invalid se actualizan automáticamente según la validación nativa.
  • Validación en 3 momentos: input (feedback visual), blur (errores), submit (validación final).
  • setCustomValidity('') limpia el error personalizado. Si no lo haces, el campo siempre será inválido.
  • Usa novalidate en el formulario si quieres control total sobre la validación sin interferencia del navegador.

10 · Preguntas frecuentes

¿Por qué usar FormData en lugar de Object.fromEntries(new FormData(form)) para JSON?

Object.fromEntries() es perfecto para convertir FormData a JSON para APIs REST. Pero ten cuidado: (1) si hay checkboxes con el mismo name, solo conserva el último valor (usa getAll() para arrays), y (2) los archivos (<input type="file">) no se serializan bien a JSON — para archivos, envía el FormData directamente con fetch() y content-type multipart/form-data automático.

¿Qué es mejor: validación nativa HTML5 o validación con JS?

Combínalas. Usa los atributos HTML5 (required, type="email", pattern, minlength) para la validación básica que el navegador maneja sin JS. Luego añade JS para personalizar mensajes de error (con setCustomValidity), estilos (con clases .tocado), y validaciones complejas que no cubre HTML5 (confirmación de contraseña, unicidad de username contra servidor).

¿Para qué sirve novalidate en un formulario?

Desactiva la validación automática del navegador. Sin novalidate, al hacer submit el navegador muestra sus propios mensajes de error (que no puedes estilizar). Con novalidate, tú controlas cuándo y cómo se muestran los errores con JS + CSS. Esencial para formularios con diseño personalizado.
