Eventos: addEventListener, propagación y delegación

Módulo 5 · DOM y Eventos ⏱ 35 minutos

1 · Introducción

Los eventos son el mecanismo que permite a JavaScript reaccionar a lo que hace el usuario: clics, tecleo, envío de formularios, scroll... El navegador dispara un objeto Event cada vez que algo ocurre, y tú puedes suscribirte para ejecutar código en respuesta. Entender el sistema de eventos —especialmente la propagación y la delegación— es lo que separa un DOM scripting frágil de uno robusto.

2 · Teoría

addEventListener

// Sintaxis completa
elemento.addEventListener(tipo, handler, opciones);

// opciones puede ser un booleano (useCapture) o un objeto:
elemento.addEventListener('click', handler, {
  capture: true,   // escuchar en fase de captura (por defecto false)
  once: true,      // el handler se auto-elimina tras ejecutarse una vez
  passive: true,   // indica que no llamará a preventDefault() (mejora scroll)
  signal: AbortSignal // para eliminar el listener con un AbortController
});

El flujo de eventos: Captura → Target → Burbujeo

Cuando haces clic en un <button> dentro de un <div> dentro de <body>, el evento no va directo al botón. Recorre el árbol dos veces:

                 ┌──────────────────────────────────────────┐
                 │            FASE DE CAPTURA               │
                 │     (de la raíz hacia el target)         │
                 │                                          │
                 │  window → document → html → body → div   │
                 │                                      │   │
                 │                                 ┌────▼───▼──┐
                 │                                 │  BUTTON   │ ← TARGET
                 │                                 └────┬───┬──┘
                 │                                      │   │
                 │             FASE DE BURBUJEO          │   │
                 │      (del target hacia la raíz)       │   │
                 │                                      │   │
                 │  button → div → body → html → document → window
                 └──────────────────────────────────────────┘

Por defecto, addEventListener escucha en la FASE DE BURBUJEO.
Con { capture: true }, escucha en la FASE DE CAPTURA.
// Demostración de las 3 fases
const div = document.querySelector('div');
const btn = document.querySelector('button');

// Fase de captura (tercer parámetro = true o { capture: true })
div.addEventListener('click', () => console.log('DIV — captura'), true);
document.body.addEventListener('click', () => console.log('BODY — captura'), true);

// Fase de burbujeo (por defecto)
btn.addEventListener('click', (e) => {
  console.log('BOTÓN — target (burbujeo)');
  console.log('event.target:', e.target.tagName);      // BUTTON
  console.log('event.currentTarget:', e.currentTarget.tagName); // BUTTON
});
div.addEventListener('click', (e) => {
  console.log('DIV — burbujeo');
  console.log('event.target:', e.target.tagName);      // BUTTON (el origen)
  console.log('event.currentTarget:', e.currentTarget.tagName); // DIV (quien escucha)
});

// Al hacer clic en el botón, el orden es:
// 1. BODY — captura
// 2. DIV — captura
// 3. BOTÓN — target (burbujeo)
// 4. DIV — burbujeo

target vs currentTarget: event.target es el elemento que originó el evento (el más profundo donde se hizo clic). event.currentTarget es el elemento que tiene el listener (this dentro del handler). Durante el burbujeo, son distintos.

Detener la propagación

btn.addEventListener('click', (e) => {
  console.log('Botón clickeado');

  // Detiene el burbujeo (el div padre no sabrá que se hizo clic)
  e.stopPropagation();

  // stopImmediatePropagation: detiene el burbujeo Y evita que otros listeners
  // en el MISMO elemento para el MISMO evento se ejecuten
  // e.stopImmediatePropagation();
});

div.addEventListener('click', () => {
  console.log('Nunca se ejecutará porque stopPropagation lo impide');
});

Usa stopPropagation con moderación. Detener la propagación puede romper analíticas, menús contextuales o librerías que dependen de eventos en el documento. Solo detenla cuando tengas una razón muy clara (ej. un modal que debe "absorber" todos los clics sin que se filtren al fondo).

preventDefault — Cancelar el comportamiento nativo

// Evitar que un enlace navegue
document.querySelector('a').addEventListener('click', (e) => {
  e.preventDefault();
  console.log('Navegación cancelada — haremos algo con JS');
});

// Evitar que un formulario se envíe (validación personalizada)
document.querySelector('form').addEventListener('submit', (e) => {
  const email = document.querySelector('#email').value;
  if (!email.includes('@')) {
    e.preventDefault();
    console.log('Email inválido, formulario no enviado');
  }
});

Delegación de eventos

En lugar de poner un listener en cada elemento hijo, pones un solo listener en el padre y usas event.target para determinar qué hijo recibió el clic. Esto es más eficiente y funciona con elementos añadidos dinámicamente:

// ❌ MAL: Listener individual en cada elemento
document.querySelectorAll('.item button').forEach(btn => {
  btn.addEventListener('click', () => { /* manejar clic */ });
  // Si añado un nuevo .item luego, su botón NO tendrá listener
});

// ✅ CORRECTO: Delegación en el contenedor
document.querySelector('#lista').addEventListener('click', (e) => {
  // Buscar el botón más cercano al elemento clickeado
  const boton = e.target.closest('button');

  if (!boton) return; // El clic no fue en un botón → ignorar

  // Ahora sabemos qué botón concreto recibió el clic
  const item = boton.closest('.item');
  const id = item.dataset.id;
  console.log(`Clic en botón del item ${id}`);

  if (boton.classList.contains('btn-eliminar')) {
    item.remove();
  } else if (boton.classList.contains('btn-editar')) {
    console.log(`Editando item ${id}`);
  }
});

¿Por qué closest() y no matches()? Porque el clic podría ocurrir en un hijo del botón (ej. un <span> dentro del <button>). closest('button') sube por el árbol hasta encontrar un botón ancestro. matches() solo comprueba el elemento exacto.

Eventos personalizados: CustomEvent

// Crear y disparar un evento personalizado
const evento = new CustomEvent('usuario:login', {
  detail: { id: 42, nombre: 'Ana', rol: 'admin' }, // datos que viajan con el evento
  bubbles: true,   // ¿propagará por el DOM?
  cancelable: true // ¿se puede prevenir con preventDefault?
});

// Escuchar el evento personalizado
document.addEventListener('usuario:login', (e) => {
  console.log('Login detectado:', e.detail.nombre); // 'Ana'
  console.log('Rol:', e.detail.rol);                // 'admin'
});

// Disparar el evento
document.dispatchEvent(evento);

Eliminar listeners

function handler(e) { console.log('click'); }

// Añadir
document.addEventListener('click', handler);

// Eliminar (debe ser LA MISMA referencia de función)
document.removeEventListener('click', handler);

// Con AbortController (moderno, elimina varios listeners de golpe)
const controller = new AbortController();
document.addEventListener('click', handler, { signal: controller.signal });
document.addEventListener('keydown', otroHandler, { signal: controller.signal });

// Eliminar ambos listeners a la vez
controller.abort();

3 · Ejemplo mínimo

// Delegación: un solo listener para una lista dinámica
const lista = document.querySelector('#tareas');

lista.addEventListener('click', (e) => {
  // Solo nos interesan los clics en elementos con clase 'tarea'
  const tarea = e.target.closest('.tarea');
  if (!tarea) return; // clic fuera de una tarea, ignorar

  // Marcar/desmarcar como completada
  tarea.classList.toggle('completada');
  console.log(`Tarea "${tarea.textContent.trim()}" → ${tarea.classList.contains('completada') ? 'hecha' : 'pendiente'}`);
});

// Aunque añadamos tareas después de registrar el listener, funcionan
const nuevaTarea = document.createElement('li');
nuevaTarea.className = 'tarea';
nuevaTarea.textContent = 'Tarea añadida dinámicamente';
lista.appendChild(nuevaTarea);
// ¡El clic en la nueva tarea también funciona gracias a la delegación!

4 · Ejemplo real

Sistema de tooltips usando delegación de eventos:

class TooltipManager {
  constructor() {
    this.tooltipActual = null;
    this._crearContenedor();
    this._iniciar();
  }

  _crearContenedor() {
    this.contenedor = document.createElement('div');
    this.contenedor.id = 'tooltip';
    this.contenedor.style.cssText = `
      position: absolute; display: none; background: #333; color: white;
      padding: 8px 12px; border-radius: 4px; font-size: 14px;
      pointer-events: none; z-index: 9999; max-width: 250px;
    `;
    document.body.appendChild(this.contenedor);
  }

  _iniciar() {
    // Delegación: un solo listener en document
    document.addEventListener('mouseover', (e) => {
      const target = e.target.closest('[data-tooltip]');
      if (!target) {
        this.ocultar();
        return;
      }

      this.contenedor.textContent = target.dataset.tooltip;
      this.contenedor.style.display = 'block';
      this.tooltipActual = target;
    });

    document.addEventListener('mousemove', (e) => {
      if (!this.tooltipActual) return;
      // Posicionar el tooltip cerca del cursor
      this.contenedor.style.left = `${e.pageX + 12}px`;
      this.contenedor.style.top = `${e.pageY + 12}px`;
    });

    document.addEventListener('mouseout', (e) => {
      const target = e.target.closest('[data-tooltip]');
      if (target === this.tooltipActual || !this.tooltipActual) {
        this.ocultar();
      }
    });
  }

  ocultar() {
    if (this.contenedor) {
      this.contenedor.style.display = 'none';
    }
    this.tooltipActual = null;
  }
}

// Uso: añade data-tooltip a cualquier elemento HTML
// <button data-tooltip="Guarda los cambios">💾</button>
new TooltipManager();

6 · Errores habituales

Error 1: No poder eliminar un listener porque se pasó una arrow anónima

// ❌ MAL: Arrow anónima — imposible de quitar después
document.addEventListener('click', (e) => { console.log('click'); });
// document.removeEventListener('click', ???) // No hay referencia

// ✅ CORRECTO: Función nombrada o referencia guardada
function manejarClick(e) { console.log('click'); }
document.addEventListener('click', manejarClick);
document.removeEventListener('click', manejarClick); // Funciona

Error 2: Usar e.target en delegación sin closest

// HTML: <button class="accion"><span>Guardar</span></button>
document.querySelector('.panel').addEventListener('click', (e) => {
  // ❌ MAL: Si el usuario hace clic en el <span>, esto falla
  if (e.target.classList.contains('accion')) {
    console.log('Clic en botón');
  }
  // Solo funciona si se clica justo en el borde del botón, no en su texto

  // ✅ CORRECTO: closest sube hasta encontrar el botón
  const boton = e.target.closest('.accion');
  if (boton) {
    console.log('Clic en botón (o en cualquier hijo suyo)');
  }
});

Error 3: Listeners duplicados por volver a llamar a addEventListener

function inicializarPanel() {
  // ❌ MAL: Si esta función se llama varias veces, acumula listeners
  document.querySelector('#btn-guardar').addEventListener('click', guardar);
}

// ✅ CORRECTO: Eliminar antes de añadir, o usar { once: true }, o controlarlo con flag
let panelInicializado = false;
function inicializarPanel() {
  if (panelInicializado) return;
  document.querySelector('#btn-guardar').addEventListener('click', guardar);
  panelInicializado = true;
}

7 · Ejercicio guiado

Objetivo: Implementar un acordeón (accordion) con delegación de eventos.

  1. Paso 1: HTML de partida

    <div id="acordeon">
  <div class="acordeon-item">
    <button class="acordeon-trigger">Sección 1</button>
    <div class="acordeon-panel">Contenido de la sección 1</div>
  </div>
  <div class="acordeon-item">
    <button class="acordeon-trigger">Sección 2</button>
    <div class="acordeon-panel">Contenido de la sección 2</div>
  </div>
</div>

  2. Paso 2: Delegación y lógica

    const acordeon = document.querySelector('#acordeon');

acordeon.addEventListener('click', (e) => {
  const trigger = e.target.closest('.acordeon-trigger');
  if (!trigger) return; // clic fuera de un trigger, ignorar

  const item = trigger.closest('.acordeon-item');
  const panel = item.querySelector('.acordeon-panel');

  // Cerrar todos los demás paneles
  acordeon.querySelectorAll('.acordeon-item').forEach(otroItem => {
    if (otroItem !== item) {
      otroItem.querySelector('.acordeon-panel').style.display = 'none';
    }
  });

  // Alternar el panel actual
  const estaAbierto = panel.style.display !== 'none';
  panel.style.display = estaAbierto ? 'none' : 'block';
});

  3. Paso 3: Añadir soporte de teclado (accesibilidad)

    acordeon.addEventListener('keydown', (e) => {
  const trigger = e.target.closest('.acordeon-trigger');
  if (!trigger) return;

  // Activar con Enter o Space
  if (e.key === 'Enter' || e.key === ' ') {
    e.preventDefault();
    trigger.click(); // Reutiliza la lógica de clic
  }

  // Navegar entre items con flechas
  const items = [...acordeon.querySelectorAll('.acordeon-trigger')];
  const indice = items.indexOf(trigger);

  if (e.key === 'ArrowDown' && indice < items.length - 1) {
    e.preventDefault();
    items[indice + 1].focus();
  }
  if (e.key === 'ArrowUp' && indice > 0) {
    e.preventDefault();
    items[indice - 1].focus();
  }
});

8 · Reto

🎯 Sistema de atajos de teclado

Crea un sistema de atajos de teclado global usando CustomEvent:

  • Escucha keydown en document.
  • Define un mapa de atajos: Ctrl+S → 'app:guardar', Ctrl+Z → 'app:deshacer', Escape → 'app:cancelar'.
  • Cuando detectes una combinación, dispara un CustomEvent con el nombre correspondiente y detalles (teclas pulsadas, timestamp).
  • Los componentes se suscriben a estos eventos personalizados para reaccionar.
  • Usa preventDefault() para evitar el comportamiento nativo de los atajos.
  • Bonus: permite registrar/eliminar atajos dinámicamente.

9 · Resumen

  • addEventListener(tipo, handler, opciones) es la forma moderna de escuchar eventos.
  • El flujo de eventos tiene 3 fases: captura → target → burbujeo. Por defecto se escucha en burbujeo.
  • event.target = origen del evento. event.currentTarget = quien está escuchando.
  • stopPropagation() detiene el burbujeo. preventDefault() cancela la acción nativa.
  • Delegación de eventos: un listener en el ancestro + e.target.closest() maneja todos los hijos, incluso los añadidos después.
  • CustomEvent permite crear y disparar eventos propios con datos en detail.
  • Usa AbortController o { once: true } para gestionar la limpieza de listeners.

10 · Preguntas frecuentes

¿Cuándo usar la fase de captura en lugar de burbujeo?

En muy pocas ocasiones. La captura es útil cuando necesitas interceptar un evento antes de que llegue a su destino, por ejemplo: un sistema de analíticas global que necesita registrar TODOS los clics antes de que ningún otro handler los procese, o un sistema de permisos que bloquea interacciones en elementos deshabilitados interceptando en la fase de captura y llamando a stopPropagation().

¿Qué diferencia hay entre input y change en formularios?

input se dispara inmediatamente en cada cambio (cada tecla pulsada en un input, cada selección). change se dispara cuando el valor se confirma: al perder el foco (blur) en inputs de texto, o al seleccionar una opción en un <select>. Usa input para validación en tiempo real; change para reaccionar al valor final.

¿Debo usar stopPropagation para que un modal "atrape" los clics?

No es la mejor solución. Aunque funciona, stopPropagation puede romper otras funcionalidades que dependan de eventos en el documento. Una alternativa más limpia es usar un backdrop (capa semitransparente) que cubra toda la pantalla debajo del modal, con su propio listener de clic que cierre el modal, y pointer-events: none en el contenido de fondo.
