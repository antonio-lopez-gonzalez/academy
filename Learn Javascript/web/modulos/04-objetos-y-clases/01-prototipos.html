Prototipos y cadena de prototipos

Módulo 4 · Objetos y Clases ⏱ 35 minutos

1 · Introducción

Todos los lenguajes orientados a objetos necesitan un mecanismo para compartir comportamiento entre objetos. Java y C# usan herencia clásica basada en clases (una clase es un molde; los objetos son instancias). JavaScript, en cambio, usa herencia prototípica: cada objeto tiene un enlace interno a otro objeto, su prototipo. Cuando intentas acceder a una propiedad que no existe en el objeto, el motor busca automáticamente en el prototipo, luego en el prototipo del prototipo, y así sucesivamente hasta llegar a null.

Esta lección es fundamental. Entender prototipos te permite comprender cómo funcionan realmente las clases de ES6 (que es azúcar sintáctico sobre prototipos), por qué métodos como Array.prototype.map funcionan, y cómo depurar problemas de herencia en JavaScript.

Analogía — La cadena de mando en una empresa: Imagina que cada empleado (objeto) tiene un superior directo (prototipo). Si el empleado no sabe cómo hacer algo (no tiene la propiedad), le pregunta a su superior. Si el superior tampoco lo sabe, sube al siguiente nivel. La cadena termina en el CEO (Object.prototype), y si el CEO tampoco sabe, la respuesta es undefined.

2 · Teoría

La propiedad __proto__ (no estándar pero ubicua)

Todo objeto en JavaScript tiene una propiedad interna [[Prototype]], definida en la especificación ECMAScript. Los navegadores y Node.js exponen esta propiedad como __proto__ por motivos históricos (heredada de Netscape). Aunque funciona, no debes usarla en producción; en su lugar usa los métodos oficiales.

Métodos oficiales: Object.getPrototypeOf() y Object.setPrototypeOf()

const gato = { sonido: 'miau' };
const felix = { nombre: 'Félix' };

// Establecer el prototipo de felix como gato
Object.setPrototypeOf(felix, gato);

console.log(Object.getPrototypeOf(felix) === gato); // true
console.log(felix.sonido); // 'miau' — heredado del prototipo

Object.create() — Crear objetos con un prototipo específico

Es la forma más directa y recomendada de crear un objeto con un prototipo determinado:

const animal = {
  comer() { return 'ñam ñam'; }
};

// Crea un objeto cuyo prototipo es animal
const perro = Object.create(animal);
perro.ladrar = function() { return 'guau'; };

console.log(perro.comer());  // 'ñam ñam' — heredado
console.log(perro.ladrar()); // 'guau' — propio

La cadena de prototipos — Diagrama ASCII

Cuando escribes [1, 2, 3].push(4), ocurre esto:

            null
             ▲
             │ [[Prototype]]
     ┌───────────────┐
     │ Object.prototype │   ← { toString, hasOwnProperty, valueOf, ... }
     └───────┬───────┘
             ▲
             │ [[Prototype]]
     ┌───────────────┐
     │  Array.prototype │   ← { push, pop, map, filter, forEach, ... }
     └───────┬───────┘
             ▲
             │ [[Prototype]]
     ┌───────────────┐
     │   [1, 2, 3]    │   ← nuestro array (no tiene push propio)
     └───────────────┘

Búsqueda de [1,2,3].push:
1. ¿Tiene [1,2,3] la propiedad push? → NO
2. Mira en Array.prototype → SÍ, aquí está push
3. Listo, ejecuta Array.prototype.push con this = [1,2,3]

El prototipo de Array, Function y Object

// El prototipo de todo array es Array.prototype
console.log(Object.getPrototypeOf([]) === Array.prototype);       // true

// El prototipo de toda función es Function.prototype
console.log(Object.getPrototypeOf(alert) === Function.prototype); // true
console.log(Object.getPrototypeOf(function(){}) === Function.prototype); // true

// El prototipo de todo objeto literal es Object.prototype
console.log(Object.getPrototypeOf({}) === Object.prototype);      // true

// Array.prototype es un objeto, así que su prototipo es Object.prototype
console.log(Object.getPrototypeOf(Array.prototype) === Object.prototype); // true

// El final de la cadena siempre es null
console.log(Object.getPrototypeOf(Object.prototype));             // null

Por qué [].push funciona: Los arrays no tienen un método push propio. La magia ocurre porque todos los arrays tienen Array.prototype como prototipo, y allí están definidos push, pop, map, etc. Es herencia prototípica pura: un solo objeto compartido por miles de arrays, ahorrando memoria.

Propiedad prototype de las funciones constructoras

No confundir con __proto__. Toda función en JavaScript tiene una propiedad .prototype (un objeto). Cuando usas new con esa función, al objeto creado se le asigna Funcion.prototype como su [[Prototype]]:

function Perro(nombre) {
  this.nombre = nombre;
}
Perro.prototype.ladrar = function() {
  return this.nombre + ' dice guau';
};

const toby = new Perro('Toby');
// toby.__proto__ === Perro.prototype → true

console.log(toby.ladrar()); // 'Toby dice guau'

Object.setPrototypeOf() — Cambiar prototipo en caliente

Es posible, pero muy costoso en rendimiento. Los motores JS optimizan asumiendo que los prototipos no cambian. Cámbialos solo durante la inicialización:

const a = { x: 1 };
const b = { y: 2 };
Object.setPrototypeOf(a, b); // a ahora hereda de b
console.log(a.y); // 2

// ⚠️ Hacer esto con frecuencia degrada el rendimiento drásticamente

Herencia clásica vs. prototípica

3 · Ejemplo mínimo

// 1. Creamos un objeto "base" con un método
const vehiculo = {
  arrancar() { return 'Motor encendido'; }
};

// 2. Creamos un objeto que hereda de vehiculo
const coche = Object.create(vehiculo);
coche.ruedas = 4; // propiedad propia

// 3. Accedemos a una propiedad del prototipo
console.log(coche.arrancar()); // 'Motor encendido' — ¡heredado!

// 4. Verificamos la cadena
console.log(coche.ruedas);                           // 4 — propia
console.log(coche.hasOwnProperty('ruedas'));          // true
console.log(coche.hasOwnProperty('arrancar'));        // false
console.log('arrancar' in coche);                     // true — existe en el prototipo

// 5. Sombreado (shadowing): definir la misma propiedad en el hijo
coche.arrancar = function() { return 'Coche eléctrico arrancando'; };
console.log(coche.arrancar()); // 'Coche eléctrico arrancando' — la propia oculta la del prototipo

4 · Ejemplo real

Un sistema de autenticación con roles usando prototipos para compartir comportamiento:

// Usuario base: todos los usuarios tienen estos métodos
const UsuarioBase = {
  login() { return `${this.nombre} ha iniciado sesión`; },
  logout() { return `${this.nombre} ha cerrado sesión`; },
  tienePermiso(accion) {
    return this.permisos.includes(accion);
  }
};

// Factory para crear usuarios con un rol
function crearUsuario(nombre, rol) {
  const rolesDisponibles = {
    admin:    { permisos: ['leer', 'escribir', 'borrar', 'admin'] },
    editor:   { permisos: ['leer', 'escribir'] },
    visitante:{ permisos: ['leer'] }
  };

  const rolData = rolesDisponibles[rol] || rolesDisponibles.visitante;
  const usuario = Object.create(UsuarioBase);
  usuario.nombre = nombre;
  usuario.rol = rol;
  usuario.permisos = rolData.permisos;

  return usuario;
}

const ana  = crearUsuario('Ana', 'admin');
const juan = crearUsuario('Juan', 'editor');

console.log(ana.login());                    // 'Ana ha iniciado sesión'
console.log(ana.tienePermiso('borrar'));     // true
console.log(juan.tienePermiso('borrar'));    // false

// Ana y Juan comparten el MISMO objeto UsuarioBase como prototipo
console.log(Object.getPrototypeOf(ana) === Object.getPrototypeOf(juan)); // true

¿Por qué funciona esto? login() usa this.nombre. Aunque el método está en UsuarioBase, al llamarlo desde ana, this apunta a ana. Es la combinación perfecta de prototipos + binding implícito de this.

6 · Errores habituales

Error 1: Modificar el prototipo afecta a todas las instancias (existente y futuras)

// ❌ MAL: No esperas que un cambio en el prototipo afecte objetos ya creados
const proto = { color: 'rojo' };
const obj1 = Object.create(proto);
proto.color = 'azul';
console.log(obj1.color); // 'azul' — ¡sorpresa! obj1 se ve afectado

// ✅ CORRECTO: Si quieres inmutabilidad, copia propiedades en lugar de delegar
const obj2 = Object.create(proto);
obj2.color = obj2.color; // crea propiedad propia
proto.color = 'verde';
console.log(obj2.color); // 'azul' — ahora obj2 tiene su propia copia

Error 2: Confundir .prototype con .__proto__

function Fn() {}
const instancia = new Fn();

// .prototype es una propiedad de la FUNCIÓN, usada como molde para new
console.log(Fn.prototype); // { constructor: Fn }

// .__proto__ (o [[Prototype]]) es el enlace interno de la INSTANCIA
console.log(instancia.__proto__ === Fn.prototype); // true

// ❌ MAL: Creer que instancia.prototype existe
// console.log(instancia.prototype); // undefined — las instancias no tienen .prototype

Error 3: Iterar objetos con for...in sin filtrar

const padre = { heredado: 'valor del padre' };
const hijo = Object.create(padre);
hijo.propio = 'valor propio';

// ❌ MAL: for...in recorre TODA la cadena de prototipos
for (const key in hijo) {
  console.log(key); // 'propio', 'heredado'
}

// ✅ CORRECTO: Filtrar con hasOwnProperty
for (const key in hijo) {
  if (hijo.hasOwnProperty(key)) {
    console.log(key); // solo 'propio'
  }
}

// ✅ MEJOR: Object.keys() solo devuelve propiedades propias
console.log(Object.keys(hijo)); // ['propio']

7 · Ejercicio guiado

Objetivo: Implementar un mini-sistema de notificaciones usando prototipos.

  1. Paso 1: Crear el prototipo base

    const NotificacionBase = {
  enviar() { return `Enviando "${this.mensaje}" a ${this.destinatario}`; },
  formatear() { return `[${this.tipo.toUpperCase()}] ${this.mensaje}`; }
};

  2. Paso 2: Crear una factory que produzca notificaciones

    function crearNotificacion(tipo, destinatario, mensaje) {
  const notif = Object.create(NotificacionBase);
  notif.tipo = tipo;
  notif.destinatario = destinatario;
  notif.mensaje = mensaje;
  return notif;
}

  3. Paso 3: Probar el sistema

    const email = crearNotificacion('email', 'ana@correo.com', 'Reunión a las 10');
const sms   = crearNotificacion('sms', '+34123456789', 'Tu pedido ha salido');

console.log(email.formatear()); // '[EMAIL] Reunión a las 10'
console.log(email.enviar());    // 'Enviando "Reunión a las 10" a ana@correo.com'
console.log(sms.formatear());   // '[SMS] Tu pedido ha salido'

// Verifica que comparten prototipo
console.log(Object.getPrototypeOf(email) === Object.getPrototypeOf(sms)); // true

  4. Paso 4: Añade un método al prototipo y observa cómo se propaga

    NotificacionBase.esUrgente = function() {
  return this.mensaje.toLowerCase().includes('urgente');
};

const urgente = crearNotificacion('email', 'jefe@correo.com', 'URGENTE: servidor caído');
console.log(urgente.esUrgente()); // true
console.log(email.esUrgente());   // false — el cambio se propagó automáticamente

9 · Resumen

  • JavaScript usa herencia prototípica, no clásica. Los objetos delegan en otros objetos.
  • La cadena de prototipos termina en Object.prototype, cuyo prototipo es null.
  • Object.create(proto) es la forma moderna de crear objetos con un prototipo específico.
  • Object.getPrototypeOf(obj) y Object.setPrototypeOf(obj, proto) son la API oficial.
  • No confundas Fn.prototype (propiedad de las funciones) con obj.__proto__ (enlace interno del objeto).
  • Los métodos en el prototipo se comparten entre todas las instancias, ahorrando memoria.
  • Las clases de ES6 son azúcar sintáctico sobre este mismo sistema de prototipos.

10 · Preguntas frecuentes

¿Por qué JavaScript usa prototipos y no clases como Java?

Brendan Eich creó JavaScript en 10 días y se inspiró en Self, un lenguaje basado en prototipos. La herencia prototípica es más simple y flexible: no necesitas declarar una clase para crear un objeto que herede de otro. Además, permite patrones que en lenguajes clásicos requieren mucho más código, como cambiar el comportamiento en tiempo de ejecución. La sintaxis class de ES6 se añadió en 2015 para hacer la transición más suave a desarrolladores que venían de Java/C#, pero por debajo sigue siendo prototipos.

¿Es malo usar __proto__ en código moderno?

Sí, por tres razones: (1) no es parte del estándar ECMAScript para acceso directo (solo es un getter/setter opcional en navegadores), (2) puede estar ausente en entornos restringidos, y (3) tiene un rendimiento inferior porque el motor no puede optimizar igual. Usa siempre Object.getPrototypeOf() y Object.setPrototypeOf().

¿Object.create(null) crea un objeto sin prototipo?

Sí. Crea un objeto completamente "limpio", sin heredar toString, hasOwnProperty, ni ningún otro método de Object.prototype. Es útil para usarlo como diccionario o mapa puro (aunque hoy usarías Map).

¿Cuántos niveles de prototipos debería tener mi jerarquía?

Como norma, no más de 2-3 niveles. Cada nivel añade coste de búsqueda en tiempo de ejecución (el motor debe recorrer la cadena). Además, hace el código más difícil de razonar. Si necesitas más, plantéate usar composición en lugar de herencia.
