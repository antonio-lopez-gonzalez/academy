Herencia: extends, super y propiedades privadas

Módulo 4 · Objetos y Clases ⏱ 30 minutos

1 · Introducción

La herencia te permite crear una clase basada en otra, reutilizando y extendiendo su comportamiento. En JavaScript usamos extends para heredar y super para invocar al constructor o métodos de la clase padre. También veremos las propiedades privadas (con #), una adición reciente (ES2022) que permite verdadero encapsulamiento.

Analogía — El menú de un restaurante: Todos los platos (Plato) tienen nombre, precio y método servir(). Un PlatoVegano extiende Plato: añade la certificación vegana y tal vez modifica servir() para incluir una nota de alérgenos. No necesitas reescribir toda la lógica básica; heredas lo común y añades lo específico.

2 · Teoría

extends y super

class Animal {
  constructor(nombre) {
    this.nombre = nombre;
  }

  hablar() {
    return `${this.nombre} hace un sonido`;
  }
}

class Perro extends Animal {
  constructor(nombre, raza) {
    super(nombre); // ⚠️ DEBE llamarse antes de usar this
    this.raza = raza;
  }

  hablar() {
    // Llama al método del padre y extiende su comportamiento
    return `${super.hablar()} — ¡guau guau! (raza: ${this.raza})`;
  }

  moverCola() {
    return `${this.nombre} mueve la cola`;
  }
}

const firulais = new Perro('Firulais', 'Labrador');
console.log(firulais.hablar());    // 'Firulais hace un sonido — ¡guau guau! (raza: Labrador)'
console.log(firulais.moverCola()); // 'Firulais mueve la cola'

// instanceof funciona a través de toda la jerarquía
console.log(firulais instanceof Perro);  // true
console.log(firulais instanceof Animal); // true
console.log(firulais instanceof Object); // true

Regla de oro: super() antes de this

En un constructor de una clase derivada, debes llamar a super() antes de acceder a this. Esta es una restricción del lenguaje que refleja cómo funcionan los prototipos: el objeto no se crea hasta que el constructor padre se ha ejecutado.

class Padre {
  constructor() {
    this.inicializado = true;
  }
}

class Hijo extends Padre {
  constructor() {
    console.log(this.inicializado); // ReferenceError: Must call super constructor
    super(); // Demasiado tarde
  }
}

// ✅ Correcto:
class HijoCorrecto extends Padre {
  constructor() {
    super();                       // Primero el padre
    console.log(this.inicializado); // true — ahora sí existe
  }
}

Override de métodos

Sobrescribir un método del padre es tan simple como redefinirlo en la clase hija. Si aun así quieres invocar la versión del padre, usas super.metodo():

class Vehiculo {
  arrancar() { return 'Motor encendido'; }
}

class CocheElectrico extends Vehiculo {
  // Override: reemplaza completamente el método del padre
  arrancar() { return 'Arranque silencioso — motor eléctrico activado'; }
}

class CocheHibrido extends Vehiculo {
  // Override con super: extiende, no reemplaza
  arrancar() {
    return `${super.arrancar()} + batería conectada`;
  }
}

const tesla = new CocheElectrico();
console.log(tesla.arrancar()); // Arranque silencioso — motor eléctrico activado

const prius = new CocheHibrido();
console.log(prius.arrancar()); // Motor encendido + batería conectada

Propiedades privadas con #

Desde ES2022, JavaScript soporta propiedades y métodos privados reales, no solo por convención (el guion bajo _). El prefijo # hace que un miembro sea inaccesible desde fuera de la clase:

class CuentaBancaria {
  #saldo = 0;        // propiedad privada de instancia
  #titular;          // declaración sin inicializar

  constructor(titular, saldoInicial) {
    this.#titular = titular;
    this.#saldo = saldoInicial;
  }

  depositar(cantidad) {
    if (cantidad <= 0) throw new Error('Cantidad debe ser positiva');
    this.#saldo += cantidad;
    return this.#saldo;
  }

  retirar(cantidad) {
    if (cantidad > this.#saldo) throw new Error('Saldo insuficiente');
    this.#saldo -= cantidad;
    return this.#saldo;
  }

  // Método privado: solo usable dentro de la clase
  #formatearMoneda(cantidad) {
    return `$${cantidad.toFixed(2)}`;
  }

  get balance() {
    return this.#formatearMoneda(this.#saldo);
  }
}

const cuenta = new CuentaBancaria('María', 1000);
console.log(cuenta.balance); // '$1000.00'
cuenta.depositar(500);
console.log(cuenta.balance); // '$1500.00'

// ❌ Esto falla:
// console.log(cuenta.#saldo);        // SyntaxError
// console.log(cuenta.#formatearMoneda(100)); // SyntaxError

Propiedades y métodos estáticos privados

class Configuracion {
  static #instancia = null;  // estático privado (patrón Singleton real)
  #apiKey;

  constructor(apiKey) {
    if (Configuracion.#instancia) {
      throw new Error('Usa Configuracion.obtenerInstancia()');
    }
    this.#apiKey = apiKey;
    Configuracion.#instancia = this;
  }

  static obtenerInstancia(apiKey) {
    if (!Configuracion.#instancia) {
      new Configuracion(apiKey);
    }
    return Configuracion.#instancia;
  }
}

const cfg1 = Configuracion.obtenerInstancia('sk-abc123');
const cfg2 = Configuracion.obtenerInstancia();
console.log(cfg1 === cfg2); // true — misma instancia

No hay herencia múltiple: usa composición

JavaScript no permite heredar de más de una clase. La solución profesional es la composición: un objeto contiene otros objetos que le aportan funcionalidad:

// En lugar de: class Pato extends Animal, Volador, Nadador { ... }  // ❌ No válido

// Usamos composición
const puedeVolar = {
  volar() { return `${this.nombre} está volando`; }
};

const puedeNadar = {
  nadar() { return `${this.nombre} está nadando`; }
};

class Pato {
  constructor(nombre) { this.nombre = nombre; }
}

// "Mezclamos" comportamientos
Object.assign(Pato.prototype, puedeVolar, puedeNadar);

const donald = new Pato('Donald');
console.log(donald.volar()); // 'Donald está volando'
console.log(donald.nadar()); // 'Donald está nadando'

Mixins con funciones

Un mixin es una función que recibe una clase y devuelve una clase extendida:

const ConTimestamp = (Base) => class extends Base {
  constructor(...args) {
    super(...args);
    this.creado = new Date();
    this.actualizado = new Date();
  }

  tocar() {
    this.actualizado = new Date();
  }

  get antiguedad() {
    return Date.now() - this.creado.getTime();
  }
};

// Aplicar el mixin a cualquier clase
class Tarea extends ConTimestamp(Object) {
  constructor(titulo) {
    super();
    this.titulo = titulo;
  }
}

const t = new Tarea('Aprender mixins');
t.tocar();
console.log(t.antiguedad); // milisegundos desde creación (número pequeño)
console.log(t.creado instanceof Date); // true

3 · Ejemplo mínimo

// Clase base con propiedades privadas
class Empleado {
  #salario;

  constructor(nombre, salario) {
    this.nombre = nombre;
    this.#salario = salario;
  }

  get salario() { return this.#salario; }

  describir() {
    return `${this.nombre} gana $${this.#salario}`;
  }
}

// Clase derivada
class Gerente extends Empleado {
  #departamento;

  constructor(nombre, salario, departamento) {
    super(nombre, salario);           // siempre primero
    this.#departamento = departamento;
  }

  // Override del método describir
  describir() {
    return `${super.describir()} — Depto: ${this.#departamento}`;
  }
}

const gerente = new Gerente('Lucía', 60000, 'IT');
console.log(gerente.describir());     // 'Lucía gana $60000 — Depto: IT'
console.log(gerente instanceof Gerente); // true
console.log(gerente instanceof Empleado); // true

4 · Ejemplo real

Sistema de notificaciones multicanal con herencia:

class Notificacion {
  #destinatario;
  #mensaje;

  constructor(destinatario, mensaje) {
    if (new.target === Notificacion) {
      throw new Error('Notificacion es abstracta, no instanciar directamente');
    }
    this.#destinatario = destinatario;
    this.#mensaje = mensaje;
    this.fecha = new Date();
  }

  get destinatario() { return this.#destinatario; }
  get mensaje() { return this.#mensaje; }

  // Método que las subclases deben implementar
  enviar() {
    throw new Error('enviar() debe ser implementado por la subclase');
  }

  formatear() {
    return `[${this.fecha.toISOString()}] "${this.#mensaje}" → ${this.#destinatario}`;
  }
}

class EmailNotificacion extends Notificacion {
  #asunto;

  constructor(email, asunto, mensaje) {
    super(email, mensaje);
    this.#asunto = asunto;
  }

  enviar() {
    return `📧 Email enviado a ${this.destinatario}
Asunto: ${this.#asunto}
Cuerpo: ${this.mensaje}`;
  }
}

class SMSNotificacion extends Notificacion {
  static #CARACTERES_MAX = 160;

  enviar() {
    const truncado = this.mensaje.length > SMSNotificacion.#CARACTERES_MAX
      ? this.mensaje.slice(0, SMSNotificacion.#CARACTERES_MAX - 3) + '...'
      : this.mensaje;

    return `📱 SMS a ${this.destinatario}: "${truncado}"`;
  }
}

// Uso polimórfico: mismo interfaz, distinto comportamiento
function notificar(notificaciones) {
  return notificaciones.map(n => n.enviar());
}

const notas = [
  new EmailNotificacion('ana@correo.com', 'Reunión', 'Sala 3 a las 10:00'),
  new SMSNotificacion('+34123456789', 'Tu pedido ha sido enviado')
];

notificar(notas).forEach(msg => console.log(msg + '\n---'));

6 · Errores habituales

Error 1: Olvidar llamar a super()

class Base {
  constructor() { this.x = 1; }
}

class Derivada extends Base {
  constructor() {
    // ❌ MAL: No se llama a super()
    this.y = 2; // ReferenceError: Must call super constructor in derived class
  }
}

// ✅ CORRECTO
class DerivadaCorrecta extends Base {
  constructor() {
    super(); // Primero el padre
    this.y = 2;
  }
}

Error 2: Confundir #privada con _convencion

class Ejemplo {
  _secreto = 'accesible desde fuera';    // ❌ Convención débil
  #secretoReal = 'inaccesible';          // ✅ Privado real

  revelar() { return this.#secretoReal; }
}

const e = new Ejemplo();
console.log(e._secreto);        // 'accesible desde fuera' — la convención no protege
// console.log(e.#secretoReal); // SyntaxError — verdadero privado
console.log(e.revelar());       // 'inaccesible' — solo accesible vía método público

Error 3: Intentar herencia múltiple directa

// ❌ MAL: JavaScript no soporta esto
// class C extends A, B { } // SyntaxError

// ✅ CORRECTO: usa composición o mixins
const conId = (Base) => class extends Base {
  constructor(...args) { super(...args); this.id = crypto.randomUUID(); }
};

const conLog = (Base) => class extends Base {
  log(msg) { console.log(`[${this.id || '?'}] ${msg}`); }
};

class MiComponente extends conLog(conId(Object)) {
  hacerAlgo() { this.log('haciendo algo'); }
}

const comp = new MiComponente();
comp.hacerAlgo(); // [uuid] haciendo algo

7 · Ejercicio guiado

Objetivo: Implementar una jerarquía de figuras geométricas con herencia y campos privados.

  1. Paso 1: Clase base abstracta

    class Figura {
  #nombre;

  constructor(nombre) {
    if (new.target === Figura) {
      throw new Error('Figura es abstracta');
    }
    this.#nombre = nombre;
  }

  get nombre() { return this.#nombre; }

  area() { throw new Error('area() debe ser implementado'); }
  perimetro() { throw new Error('perimetro() debe ser implementado'); }

  describir() {
    return `${this.#nombre} — Área: ${this.area().toFixed(2)}, Perímetro: ${this.perimetro().toFixed(2)}`;
  }
}

  2. Paso 2: Clases concretas

    class Circulo extends Figura {
  #radio;

  constructor(radio) {
    super('Círculo');
    this.#radio = radio;
  }

  area() { return Math.PI * this.#radio ** 2; }
  perimetro() { return 2 * Math.PI * this.#radio; }
}

class Rectangulo extends Figura {
  #ancho;
  #alto;

  constructor(ancho, alto) {
    super('Rectángulo');
    this.#ancho = ancho;
    this.#alto = alto;
  }

  area() { return this.#ancho * this.#alto; }
  perimetro() { return 2 * (this.#ancho + this.#alto); }
}

  3. Paso 3: Probar polimorfismo

    const figuras = [
  new Circulo(5),
  new Rectangulo(10, 4)
];

figuras.forEach(f => console.log(f.describir()));
// Círculo — Área: 78.54, Perímetro: 31.42
// Rectángulo — Área: 40.00, Perímetro: 28.00

8 · Reto

🎯 Sistema de envíos

Implementa un sistema de envíos con estas reglas:

  • Envio: clase base que recibe paquete y dirección. Tiene calcularPrecio() que lanza Error (abstracto).
  • EnvioEstandar: extiende Envio. calcularPrecio() = peso × 1.5 + distancia × 0.25.
  • EnvioExpress: extiende Envio. calcularPrecio() = peso × 3 + distancia × 0.5. Añade #recargo privado (10% extra si distancia >100).
  • EnvioInternacional: extiende EnvioExpress. calcularPrecio() = método padre + 30% de aduanas. Usa super.calcularPrecio().
  • Crea una mixin ConSeguimiento que añada un #codigo privado generado aleatoriamente y un getter.

9 · Resumen

  • extends crea una clase hija que hereda de una clase padre (establece la cadena de prototipos).
  • super() debe ser la primera línea del constructor hijo. Llama al constructor del padre.
  • super.metodo() invoca la versión del padre de un método, útil para extender (no reemplazar) comportamiento.
  • Las propiedades y métodos #privados son realmente inaccesibles desde fuera de la clase.
  • JavaScript no soporta herencia múltiple. Usa composición o mixins (funciones que retornan clases extendidas).
  • instanceof funciona en toda la jerarquía: un objeto de una subclase también es instancia de la clase padre.

10 · Preguntas frecuentes

¿Por qué JavaScript no tiene herencia múltiple?

Es una decisión deliberada para evitar la complejidad del "problema del diamante" (si dos padres definen el mismo método, ¿cuál se usa?). Los prototipos son una cadena lineal por diseño. La comunidad resolvió esto con composición y mixins, patrones más flexibles y menos propensos a errores que la herencia múltiple clásica.

¿#propiedades son realmente seguras o es "seguridad por oscuridad"?

Son un mecanismo real a nivel del motor JavaScript. No puedes acceder a una #propiedad desde fuera de la clase ni siquiera con notación de corchetes, Object.keys(), o JSON.stringify(). El motor garantiza que solo se accede desde el cuerpo de la clase donde se declaró. Es encapsulamiento fuerte, no solo una convención.

¿Cuándo usar composición en lugar de herencia?

Regla práctica: si puedes decir "X tiene un Y" en lugar de "X es un Y", usa composición. Por ejemplo, un Coche tiene un Motor (composición), no es un Motor. La herencia solo tiene sentido con relaciones "es-un" muy claras y estables. En caso de duda, elige composición: es más fácil refactorizar composición a herencia que al revés.
