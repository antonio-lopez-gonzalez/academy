Web APIs: Geolocation, Notifications, Clipboard, History

Módulo 8 · Web APIs y Producción ⏱ 30 minutos

1 · Introducción

Imagina que JavaScript es un coche. El motor, el volante y los pedales son el lenguaje en sí: variables, funciones, bucles, promesas... Pero un coche sin faros, sin GPS, sin claxon y sin espejos retrovisores no sirve para circular de verdad por la carretera.

Las Web APIs son esos "extras" que el navegador le presta a JavaScript para interactuar con el mundo real. No son parte del lenguaje (no las define el estándar ECMAScript), sino que las proporciona el entorno de ejecución — en este caso, el navegador.

Regla de oro: Si necesitas acceder al hardware del dispositivo (GPS, cámara, micrófono), interactuar con el portapapeles, mostrar notificaciones o manipular el historial del navegador, estás en el territorio de las Web APIs. Node.js tiene sus propias APIs (fs, path, http...) pero esas NO funcionan en el navegador.

En esta lección cubriremos las cuatro Web APIs más usadas en el día a día profesional:

  • Geolocation API: obtener la ubicación del usuario (con su permiso).
  • Notification API: mostrar notificaciones del sistema fuera de la pestaña.
  • Clipboard API: leer y escribir en el portapapeles.
  • History API: manipular el historial del navegador sin recargar la página (base de las SPAs).

También mencionaremos Intersection Observer, Resize Observer y MatchMedia, tres APIs de observación que usamos constantemente en aplicaciones modernas.

2 · Teoría

Geolocation API

El objeto navigator.geolocation es la puerta de entrada al GPS del dispositivo. Antes de usarla, el navegador SIEMPRE pide permiso al usuario mediante un diálogo nativo que no puedes personalizar ni evitar. Esto es por privacidad — ningún sitio web puede saber dónde estás sin tu consentimiento explícito.

La API ofrece dos métodos principales:

MétodoPropósito¿Cuándo usarlo?
getCurrentPosition(success, error, options)Obtiene la posición UNA vezBotón "Usar mi ubicación", encontrar tienda más cercana
watchPosition(success, error, options)Observa la posición CONTINUAMENTEApps de navegación (Google Maps), tracking de repartidores
clearWatch(id)Deja de observarCuando el usuario cierra el mapa o cambia de vista

El objeto de posición que recibes contiene:

// Objeto de posición devuelto por la API
{
  coords: {
    latitude: 40.416775,    // Latitud en grados decimales
    longitude: -3.703790,   // Longitud en grados decimales
    accuracy: 20,           // Precisión en metros (menor = mejor)
    altitude: null,         // Altitud en metros (null en dispositivos sin barómetro)
    altitudeAccuracy: null,
    heading: null,          // Dirección en grados (0-360, null si está quieto)
    speed: null             // Velocidad en m/s
  },
  timestamp: 1717000000000  // Momento de la lectura (epoch millis)
}

¿Por qué accuracy varía tanto? El navegador usa múltiples fuentes: GPS del chip (más preciso, 5-10m), triangulación de torres de telefonía (50-300m), WiFi cercano (20-50m), o simplemente la IP (nivel ciudad). La API no te dice qué fuente usó — solo la precisión estimada. En un sótano sin GPS, accuracy puede ser de 1000m. En exteriores con chip GPS, de 5m.

Notification API

Las notificaciones del navegador aparecen fuera de la pestaña, a nivel de sistema operativo. Son ideales para avisar al usuario aunque no tenga la página abierta (siempre que la pestaña siga viva en segundo plano).

El flujo siempre es: pedir permiso → esperar respuesta → mostrar notificación. El permiso se pide con Notification.requestPermission(), que devuelve una promesa con uno de tres valores: "granted" (concedido), "denied" (denegado para siempre — el usuario tendría que ir a la configuración del navegador para revertirlo), o "default" (el usuario cerró el diálogo sin decidir).

Analogía: Las notificaciones del navegador son como el timbre de una casa. Como visitante (sitio web), primero tienes que pedir permiso para tocar el timbre (requestPermission). Si te dicen que sí ("granted"), puedes tocar (new Notification(...)). Si te dicen que no ("denied"), ya no puedes volver a pedirlo — tendrías que convencer al dueño de que cambie la configuración manualmente.

Clipboard API

El objeto navigator.clipboard te permite leer y escribir en el portapapeles del sistema. Es asíncrona (promesas) porque acceder al portapapeles es una operación potencialmente lenta y sensible.

MétodoPropósito
writeText(text)Copiar texto al portapapeles
readText()Leer texto del portapapeles (requiere permiso)
write(data)Copiar datos arbitrarios (imágenes, HTML, etc.)
read()Leer datos arbitrarios del portapapeles

Importante: readText() y read() requieren que la pestaña esté activa (focused) y, en la mayoría de navegadores, que el usuario haya interactuado previamente con la página. No puedes leer el portapapeles de forma silenciosa en segundo plano — sería un agujero de seguridad enorme.

History API

El objeto window.history te permite manipular el historial del navegador sin recargar la página. Esta es la base técnica sobre la que se construyen todas las SPAs (React Router, Vue Router, etc.).

Los métodos clave son:

// Añade una entrada al historial (cambia la URL pero NO recarga)
history.pushState(state, title, url);

// Reemplaza la entrada actual (útil para corregir URLs sin ensuciar el historial)
history.replaceState(state, title, url);

// Se dispara cuando el usuario navega hacia atrás/adelante
window.addEventListener('popstate', (event) => {
  // event.state contiene el objeto que pasaste a pushState
  console.log(event.state);
});

¿Por qué no cambiar window.location? window.location.href = '/nueva-pagina' provoca una recarga completa de la página: el navegador destruye todo el estado de JavaScript, descarga el HTML nuevo, ejecuta los scripts desde cero... Es como apagar y encender el ordenador para cambiar de aplicación. La History API te permite cambiar la URL en la barra de direcciones sin destruir nada — el usuario ve una URL nueva, puede compartirla y usar los botones de navegación, pero tu código sigue ejecutándose sin interrupción.

Intersection Observer

Esta API te permite saber cuándo un elemento del DOM entra o sale del viewport (o de un contenedor ancestro). Sustituye a los antiguos listeners de scroll con getBoundingClientRect(), que eran terriblemente ineficientes porque se ejecutan en el hilo principal en CADA frame de scroll.

Sus dos casos de uso estrella son:

  • Lazy loading: cargar imágenes solo cuando van a ser visibles.
  • Infinite scroll: cargar más contenido cuando el usuario llega al final de la lista.

Resize Observer

Similar a Intersection Observer pero para cambios de tamaño. Te notifica cuando un elemento cambia sus dimensiones. Mucho más eficiente que un listener de resize en window, ya que solo se dispara para los elementos que observas (no para cada cambio de viewport).

MatchMedia

El método window.matchMedia() te permite evaluar media queries de CSS desde JavaScript. Devuelve un objeto MediaQueryList que puedes observar para reaccionar a cambios (por ejemplo, cuando el usuario gira el móvil o cambia el modo oscuro).

3 · Ejemplo mínimo

Geolocation

// El ejemplo más pequeño posible: obtener la posición una vez
navigator.geolocation.getCurrentPosition(
  // Callback de éxito: position es un objeto GeolocationPosition
  (position) => {
    console.log('Latitud:', position.coords.latitude);
    console.log('Longitud:', position.coords.longitude);
  },
  // Callback de error: siempre debes manejarlo
  (error) => {
    console.error('Error de geolocalización código:', error.code);
    console.error('Mensaje:', error.message);
  }
);

Notification

// Pedir permiso y mostrar una notificación
Notification.requestPermission().then((permission) => {
  // permission puede ser 'granted', 'denied' o 'default'
  if (permission === 'granted') {
    // Solo aquí podemos crear la notificación
    new Notification('¡Hola!', {
      body: 'Esto es una notificación del navegador.',
      icon: '/icono.png'  // Opcional: icono que aparece en la notificación
    });
  }
});

Clipboard

// Copiar texto al portapapeles: una sola línea (asíncrona)
await navigator.clipboard.writeText('Texto copiado al portapapeles');

// Leer texto del portapapeles (requiere foco e interacción previa)
const texto = await navigator.clipboard.readText();
console.log('El portapapeles contiene:', texto);

History

// Cambiar la URL a '/nueva-vista' sin recargar la página
history.pushState({ vista: 'detalle', id: 42 }, '', '/nueva-vista');

// Escuchar cuando el usuario pulse atrás o adelante
window.addEventListener('popstate', (event) => {
  // event.state === { vista: 'detalle', id: 42 } (lo que pasaste a pushState)
  console.log('El usuario ha navegado. Estado:', event.state);
});

Intersection Observer

// Crear un observer que se dispara cuando el elemento es visible al 50%
const observer = new IntersectionObserver(
  (entries) => {
    entries.forEach((entry) => {
      if (entry.isIntersecting) {
        console.log('¡El elemento es visible!');
        // Aquí cargarías una imagen o más datos
      }
    });
  },
  { threshold: 0.5 }  // 0.5 = 50% del elemento visible
);

// Empezar a observar un elemento del DOM
observer.observe(document.querySelector('.mi-elemento'));

MatchMedia

// Detectar si la pantalla es "móvil" (ancho ≤ 768px)
const mediaQuery = window.matchMedia('(max-width: 768px)');

// Consultar el estado actual
console.log('¿Es móvil?', mediaQuery.matches);  // true o false

// Reaccionar a cambios (por ejemplo, rotación del móvil)
mediaQuery.addEventListener('change', (event) => {
  console.log('Cambió. ¿Ahora es móvil?', event.matches);
});

4 · Ejemplo real

Vamos a construir un widget de "tiendas cercanas" que combina geolocalización y una interfaz real:

<!-- Estructura HTML del widget -->
<div id="store-finder">
  <button id="find-stores">🔍 Buscar tiendas cercanas</button>
  <div id="stores-list"></div>
  <div id="location-error" style="display:none; color:red;"></div>
</div>
// Simulamos una base de datos de tiendas (en producción vendría de una API)
const stores = [
  { name: 'Tienda Centro', lat: 40.416775, lng: -3.703790 },
  { name: 'Tienda Norte',    lat: 40.450000, lng: -3.690000 },
  { name: 'Tienda Sur',      lat: 40.380000, lng: -3.720000 },
];

// Calcula la distancia en km entre dos puntos usando la fórmula del Haversine
function getDistance(lat1, lng1, lat2, lng2) {
  const R = 6371; // Radio de la Tierra en km
  const dLat = ((lat2 - lat1) * Math.PI) / 180;   // Convertir grados a radianes
  const dLng = ((lng2 - lng1) * Math.PI) / 180;
  const a = Math.sin(dLat / 2) ** 2
          + Math.cos((lat1 * Math.PI) / 180) * Math.cos((lat2 * Math.PI) / 180)
          * Math.sin(dLng / 2) ** 2;
  return R * 2 * Math.atan2(Math.sqrt(a), Math.sqrt(1 - a));
}

function handleFindStores() {
  // Mostrar feedback inmediato al usuario
  const btn = document.getElementById('find-stores');
  btn.textContent = '⏳ Obteniendo tu ubicación...';
  btn.disabled = true;

  navigator.geolocation.getCurrentPosition(
    (position) => {
      const { latitude: userLat, longitude: userLng } = position.coords;

      // Ordenar tiendas por distancia y quedarnos con las 3 más cercanas
      const nearby = stores
        .map((store) => ({
          ...store,
          distance: getDistance(userLat, userLng, store.lat, store.lng)
        }))
        .sort((a, b) => a.distance - b.distance)
        .slice(0, 3);

      // Renderizar resultados
      const list = document.getElementById('stores-list');
      list.innerHTML = nearby
        .map((s) => `<div class="store-card">
          <strong>${s.name}</strong>
          <span>${s.distance.toFixed(1)} km</span>
        </div>`)
        .join('');

      btn.textContent = '🔍 Buscar tiendas cercanas';
      btn.disabled = false;
    },
    (error) => {
      const errorDiv = document.getElementById('location-error');
      errorDiv.style.display = 'block';

      // Mensajes amigables según el código de error
      const messages = {
        1: 'Permiso denegado. Activa la ubicación en la configuración de tu navegador.',
        2: 'No se pudo obtener la ubicación. Verifica tu conexión GPS.',
        3: 'La solicitud tardó demasiado. Inténtalo de nuevo.',
      };
      errorDiv.textContent = messages[error.code] || 'Error desconocido.';

      btn.textContent = '🔍 Buscar tiendas cercanas';
      btn.disabled = false;
    },
    { enableHighAccuracy: true, timeout: 10000 }
  );
}

document.getElementById('find-stores').addEventListener('click', handleFindStores);

Puntos clave del ejemplo: (1) Siempre da feedback visual inmediato al usuario — el botón cambia de texto y se deshabilita mientras carga. (2) Maneja SIEMPRE el callback de error — si no lo haces y el usuario deniega el permiso, tu app se queda colgada sin explicación. (3) La fórmula del Haversine es el estándar para calcular distancias geográficas — no uses Pitágoras, la Tierra no es plana.

5 · Buenas prácticas

HazEvitaPor qué
Pide permisos justo cuando los necesitas (just-in-time) Pedir todos los permisos al cargar la página El usuario no confía en una web que pide ubicación, notificaciones y cámara sin contexto. Pide el permiso cuando el usuario pulse "Buscar cerca de mí", no al abrir la home.
Maneja SIEMPRE el callback de error en geolocalización Solo pasar el callback de éxito Si el usuario deniega el permiso y no manejas el error, tu app falla silenciosamente — el usuario no sabe qué pasó ni cómo arreglarlo.
Cierra Intersection Observer cuando ya no lo necesites Crear observers y olvidarlos observer.disconnect() libera memoria y evita que el observer siga ejecutando callbacks sobre elementos que ya no existen (memory leaks en SPAs).
Verifica Notification.permission antes de pedir permiso Llamar a requestPermission() cada vez Si el permiso ya es "denied", llamar a requestPermission() no hará nada — el diálogo no se mostrará. Verifica primero: if (Notification.permission === 'granted') { ... }.
Usa history.pushState con una URL real que funcione si se comparte Poner URLs falsas o hashes sin significado semántico Si el usuario comparte la URL, debería cargar la misma vista. Si no puedes hacer que funcione en SSR, al menos usa replaceState para no ensuciar el historial.
Envuelve clipboard.writeText() en try/catch Asumir que siempre funciona En algunos contextos (HTTP en vez de HTTPS, iframes sin permiso, Web Workers) el portapapeles no está disponible. Siempre maneja el error.

6 · Errores habituales

Error 1: No verificar disponibilidad de la API

// ❌ MAL: asumir que la API existe
navigator.geolocation.getCurrentPosition(callback);
// En algunos navegadores antiguos o contextos restringidos, geolocation es undefined

// ✅ BIEN: verificar siempre
if ('geolocation' in navigator) {
  navigator.geolocation.getCurrentPosition(callback);
} else {
  console.warn('Geolocalización no disponible en este navegador');
}

Error 2: No cancelar watchPosition en SPAs

// ❌ MAL: iniciar watchPosition al montar una vista pero no limpiarlo al desmontar
function mountMapView() {
  watchId = navigator.geolocation.watchPosition(updateMap);
}
// Si el usuario navega a otra vista, updateMap se sigue ejecutando para siempre
// consumiendo batería y CPU

// ✅ BIEN: limpiar al desmontar la vista
function mountMapView() {
  watchId = navigator.geolocation.watchPosition(updateMap);
}
function unmountMapView() {
  if (watchId !== null) {
    navigator.geolocation.clearWatch(watchId);
  }
}

Error 3: Mostrar notificaciones sin verificar permiso previo

// ❌ MAL: pedir permiso cada vez que se quiere notificar
async function notifyUser() {
  const perm = await Notification.requestPermission(); // Diálogo cada vez (molesto)
  if (perm === 'granted') new Notification('Algo pasó');
}

// ✅ BIEN: verificar antes, pedir permiso solo si es 'default'
async function notifyUser() {
  if (Notification.permission === 'granted') {
    new Notification('Algo pasó'); // Sin molestar al usuario
  } else if (Notification.permission === 'default') {
    const perm = await Notification.requestPermission(); // Pedir solo la primera vez
    if (perm === 'granted') new Notification('Algo pasó');
  }
  // Si es 'denied', no hacemos nada — el usuario ya dijo que no
}

Error 4: Usar innerHTML con datos del portapapeles

// ❌ MAL: inyectar contenido del portapapeles directamente en el DOM
const texto = await navigator.clipboard.readText();
document.getElementById('preview').innerHTML = texto; // ¡XSS! El portapapeles puede contener HTML malicioso

// ✅ BIEN: usar textContent (escapa el HTML automáticamente)
const texto = await navigator.clipboard.readText();
document.getElementById('preview').textContent = texto;

7 · Ejercicio guiado

Vamos a construir un botón "Copiar al portapapeles" que muestre feedback visual — como los que ves en GitHub, documentaciones y dashboards:

  1. Crea el HTML:

    <div class="copy-wrapper">
  <code id="code-block">pnpm install</code>
  <button id="copy-btn">📋 Copiar</button>
</div>

  2. Implementa la lógica con estados de feedback:

    const btn = document.getElementById('copy-btn');
const code = document.getElementById('code-block');

btn.addEventListener('click', async () => {
  try {
    // Copiar el texto del elemento code
    await navigator.clipboard.writeText(code.textContent);

    // Feedback visual: cambiar texto e icono temporalmente
    const originalHTML = btn.innerHTML;
    btn.innerHTML = '✅ ¡Copiado!';
    btn.disabled = true; // Evitar múltiples clics mientras se muestra el feedback

    // Restaurar el estado original tras 2 segundos
    setTimeout(() => {
      btn.innerHTML = originalHTML;
      btn.disabled = false;
    }, 2000);
  } catch (err) {
    console.error('No se pudo copiar:', err);
    btn.innerHTML = '❌ Error';
    setTimeout(() => { btn.innerHTML = '📋 Copiar'; }, 2000);
  }
});

  3. Añade el fallback para navegadores antiguos:

    btn.addEventListener('click', async () => {
  try {
    if (navigator.clipboard) {
      await navigator.clipboard.writeText(code.textContent);
    } else {
      // Fallback para navegadores sin Clipboard API (IE, Safari viejo)
      const textarea = document.createElement('textarea');
      textarea.value = code.textContent;
      textarea.style.position = 'fixed';  // Evitar scroll
      textarea.style.opacity = '0';        // Ocultar visualmente
      document.body.appendChild(textarea);
      textarea.select();
      document.execCommand('copy');         // API antigua
      document.body.removeChild(textarea);
    }
    btn.innerHTML = '✅ ¡Copiado!';
    setTimeout(() => { btn.innerHTML = '📋 Copiar'; }, 2000);
  } catch (err) {
    btn.innerHTML = '❌ Error';
    setTimeout(() => { btn.innerHTML = '📋 Copiar'; }, 2000);
  }
});

Crea una pequeña aplicación que, al cargar:

  1. Detecte la ubicación del usuario (pidiendo permiso).
  2. Muestre un dashboard con: coordenadas, precisión (accuracy en metros), y un mapa estático (puedes usar la URL https://staticmap.example.com?lat=X&lng=Y como placeholder).
  3. Tenga un botón "Compartir ubicación" que copie las coordenadas al portapapeles en formato "lat, lng" y muestre feedback.

9 · Resumen

  • Las Web APIs no son parte de JavaScript — las proporciona el navegador. Node.js tiene otras APIs distintas.
  • Geolocation: getCurrentPosition() para una lectura, watchPosition() para seguimiento continuo. Siempre pide permiso y maneja errores.
  • Notifications: pide permiso con requestPermission() solo cuando sea necesario. Verifica Notification.permission antes de crear notificaciones.
  • Clipboard: writeText() para copiar, readText() para leer. Ambas son asíncronas y requieren contexto seguro (HTTPS).
  • History: pushState() añade entradas al historial, replaceState() las sustituye. El evento popstate permite reaccionar a la navegación del usuario. Es la base de todas las SPAs.
  • Intersection Observer: detecta visibilidad de elementos. Para lazy loading e infinite scroll. Mucho más eficiente que listeners de scroll.
  • Resize Observer: detecta cambios de tamaño en elementos concretos.
  • MatchMedia: evalúa media queries desde JavaScript. Ideal para reaccionar a cambios de tema o tamaño de pantalla.

10 · Preguntas frecuentes

¿Por qué navigator.geolocation no funciona en HTTP local?

Por seguridad, Chrome y otros navegadores modernos bloquean la API de geolocalización en contextos no seguros (HTTP). Debes servir tu página con HTTPS. En desarrollo local, localhost se considera seguro, pero 127.0.0.1 o la IP local directa no siempre lo son. Si usas Vite (pnpm dev), ya sirve con HTTPS local y funciona sin problemas.

¿Cómo puedo probar notificaciones en desarrollo?

Las notificaciones del navegador funcionan en localhost sin problemas. En las DevTools de Chrome, puedes ir a Application → Service Workers y simular un evento push si estás integrando notificaciones con un service worker. Para la Notification API básica (no push), basta con llamar a new Notification() después de obtener el permiso.

¿Intersection Observer reemplaza completamente los listeners de scroll?

En el 95% de los casos, sí. Si necesitas saber cuándo un elemento entra o sale de la pantalla, usa Intersection Observer. Si necesitas saber la posición exacta de scroll (por ejemplo, para una barra de progreso de lectura), aún necesitas el evento scroll. Pero para lazy loading, animaciones al entrar, o infinite scroll, Intersection Observer es la herramienta correcta.

¿Puedo usar la History API para cambiar el dominio en la URL?

No. pushState() y replaceState() solo pueden cambiar la ruta (path), los parámetros de consulta (query string) y el hash dentro del mismo origen (mismo protocolo + dominio + puerto). Intentar cambiar a otro dominio lanza un error de seguridad (DOMException).
