Parámetros (default, rest, spread) y retorno

Módulo 2 · Control de flujo y funciones ⏱ 30 minutos

1 · Introducción

Los parámetros son el contrato de una función con el mundo exterior: definen qué datos necesita para trabajar. El valor de retorno es la promesa de lo que entrega a cambio. Dominar los parámetros en JavaScript va mucho más allá de listar nombres entre paréntesis: implica entender valores por defecto, el operador rest para capturar argumentos sobrantes, el operador spread para descomponer iterables, y el destructuring para extraer propiedades de objetos.

JavaScript es inusualmente flexible con los parámetros: puedes pasar más o menos argumentos de los declarados sin errores. Esta flexibilidad es poderosa pero peligrosa si no se entiende.

2 · Teoría

Parámetros vs Argumentos

Aunque se usan indistintamente, son conceptos distintos:

  • Parámetro: la variable que nombras en la definición de la función (function foo(a, b) → a y b son parámetros).
  • Argumento: el valor real que pasas al invocar la función (foo(3, 4) → 3 y 4 son argumentos).

Default parameters (ES6)

Permiten asignar un valor por defecto a un parámetro si el argumento es undefined. Solo se disparan con undefined explícito, no con null, 0, o "":

function saludar(nombre = "invitado", saludo = "Hola") {
  console.log(`${saludo}, ${nombre}`);
}

saludar();                    // "Hola, invitado"
saludar("Ana");               // "Hola, Ana"
saludar("Ana", "Buenos días"); // "Buenos días, Ana"
saludar(undefined, "Hey");    // "Hey, invitado" — undefined dispara el default
saludar(null);                // "Hola, null" — null NO dispara el default

Los defaults se evalúan en cada invocación, lo que permite expresiones dinámicas:

function crearId(prefix = "usr", timestamp = Date.now()) {
  return `${prefix}_${timestamp}`; // Date.now() se evalúa en cada llamada
}

Rest parameters (...args)

Captura todos los argumentos restantes en un array. Siempre debe ser el último parámetro:

function log(tag, ...mensajes) {
  // 'tag' recibe el primer argumento; 'mensajes' captura el resto en un array
  mensajes.forEach(msg => console.log(`[${tag}] ${msg}`));
}

log("INFO", "Servidor iniciado", "Puerto 3000", "OK");
// [INFO] Servidor iniciado
// [INFO] Puerto 3000
// [INFO] OK

Rest parameters reemplazan el objeto arguments (array-like, no es un array real) que existía en versiones anteriores de JavaScript:

function vieja() {
  console.log(arguments);     // [Arguments] { '0': 1, '1': 2 } — no es un array
  console.log(arguments.map); // undefined — arguments no tiene métodos de array
}

function moderna(...args) {
  console.log(args);          // [1, 2] — es un array real
  console.log(args.map(x => x * 2)); // [2, 4] — todos los métodos disponibles
}

Spread operator (...)

El mismo operador ... tiene el efecto contrario cuando se usa en la invocación o en literales: expande un iterable en elementos individuales:

// Spread en llamadas a función
const notas = [7, 8, 9];
console.log(Math.max(...notas)); // equivale a Math.max(7, 8, 9) → 9

// Spread en arrays: clonar y fusionar
const original = [1, 2, 3];
const copia = [...original];           // clon superficial
const fusionado = [0, ...original, 4]; // [0, 1, 2, 3, 4]

// Spread en objetos (ES2018)
const defaults = { theme: "dark", fontSize: 14 };
const userConfig = { fontSize: 18 };      // sobreescribe
const config = { ...defaults, ...userConfig }; // { theme: "dark", fontSize: 18 }

Regla nemotécnica: Rest "recoge" (agrupa en un array), spread "esparce" (desempaqueta un iterable). Es el mismo operador, pero su función depende del contexto: en la definición de parámetros es rest, en la invocación o literales es spread.

Return: explícito e implícito

Toda función en JavaScript devuelve algo. Si no hay return explícito, devuelve undefined:

function sinReturn() {
  const x = 42;
  // sin return → undefined
}
console.log(sinReturn()); // undefined

// Arrow con retorno implícito
const doble = x => x * 2;        // sin llaves → retorno implícito
const dobleConLlaves = x => {    // con llaves → necesita return explícito
  return x * 2;
};

Funciones que devuelven funciones

Patrón fundamental en programación funcional (currying, partial application, factory functions):

function crearPregunta(asunto) {
  return function (nombre) {
    return `${nombre}, ¿puedes explicar ${asunto}?`;
  };
}

const preguntarClosures = crearPregunta("los closures");
console.log(preguntarClosures("Ana"));    // "Ana, ¿puedes explicar los closures?"
console.log(preguntarClosures("Carlos"));  // "Carlos, ¿puedes explicar los closures?"

Con arrow functions, la versión point-free es aún más compacta:

const crearPregunta = asunto => nombre => `${nombre}, ¿puedes explicar ${asunto}?`;

Parámetros nombrados vía destructuring

Cuando una función recibe muchos parámetros, pasar un objeto y usar destructuring hace el código más legible y autodocumentado:

// Sin destructuring: orden rígido, fácil equivocarse
function crearUsuario(nombre, email, rol, activo, avatar) {
  return { nombre, email, rol, activo, avatar };
}
crearUsuario("Ana", "ana@email.com", "admin", true, undefined); // ¿cuál es cuál?

// Con destructuring: orden irrelevante, valores por defecto integrados
function crearUsuario({ nombre, email, rol = "lector", activo = true, avatar = "" } = {}) {
  return { nombre, email, rol, activo, avatar };
}
crearUsuario({
  email: "ana@email.com",
  nombre: "Ana",
  // rol y activo toman sus defaults
});
// { nombre: "Ana", email: "ana@email.com", rol: "lector", activo: true, avatar: "" }

El = {} al final es un default para el objeto completo, evitando errores si la función se llama sin argumentos.

3 · Ejemplo mínimo

// Rest: capturar argumentos variables
function sumar(...nums) {
  return nums.reduce((total, n) => total + n, 0);
}
console.log(sumar(1, 2, 3, 4, 5)); // 15

// Spread: desempaquetar array en argumentos
const valores = [1, 2, 3, 4, 5];
console.log(sumar(...valores)); // 15 — mismo resultado

// Default + spread + retorno
function unir(separador = ", ", ...partes) {
  return partes.join(separador); // partes es un array gracias a rest
}
console.log(unir(" - ", "a", "b", "c")); // "a - b - c"
console.log(unir(undefined, "x", "y"));  // "x, y" — usa default

4 · Ejemplo real

Logger de aplicación con niveles, timestamps y formateo:

const crearLogger = (nombreApp = "app", opciones = {}) => {
  // Destructuring con defaults en el parámetro
  const {
    nivelMinimo = "info",
    mostrarTimestamp = true,
    colores = false,
  } = opciones;

  const niveles = { error: 0, warn: 1, info: 2, debug: 3 };
  const formato = (nivel, timestamp) =>
    `${mostrarTimestamp ? `[${timestamp}] ` : ""}[${nombreApp}][${nivel.toUpperCase()}]`;

  // Función que devuelve funciones — factory para cada nivel
  const crearMetodo = (nivel) => (...mensajes) => {
    if (niveles[nivel] <= niveles[nivelMinimo]) {
      const ts = new Date().toISOString();
      console.log(`${formato(nivel, ts)} ${mensajes.join(" ")}`);
    }
  };

  // Devolver un objeto con métodos generados dinámicamente
  return {
    error: crearMetodo("error"),
    warn: crearMetodo("warn"),
    info: crearMetodo("info"),
    debug: crearMetodo("debug"),
  };
};

const log = crearLogger("API", { nivelMinimo: "warn", mostrarTimestamp: true });
log.error("Servidor caído", "código", 500);
// [2025-01-15T10:30:00.000Z] [API][ERROR] Servidor caído código 500
log.info("Petición recibida"); // no se imprime: nivelMinimo es "warn"

Este logger usa rest parameters (...mensajes), destructuring con defaults, factory functions que devuelven funciones, y el spread implícito de console.log. Esencialmente un mini-winston o pino.

6 · Errores habituales

1. Olvidar que spread hace copia superficial

// ❌ MAL: spread solo clona el primer nivel
const obj = { a: 1, b: { c: 2 } };
const copia = { ...obj };
copia.b.c = 99;
console.log(obj.b.c); // 99 — ¡la mutación se refleja en el original!

// ✅ BIEN: clonación profunda con structuredClone (Web API, no parte de ES)
const copia2 = structuredClone(obj);
copia2.b.c = 99;
console.log(obj.b.c); // 2 — intacto

2. Pasar null esperando que dispare el default

// ❌ MAL: null no dispara default parameters
function saludar(nombre = "invitado") { console.log(`Hola ${nombre}`); }
saludar(null); // "Hola null"

// ✅ BIEN: si quieres que null también use el default
function saludar(nombre) {
  console.log(`Hola ${nombre ?? "invitado"}`); // nullish coalescing
}
saludar(null); // "Hola invitado"

3. Modificar rest parameters accidentalmente

// ❌ MAL: mutar el array de rest parameters
function procesar(...items) {
  items.push("extra"); // modifica el array, puede causar bugs sutiles
  return items;
}

// ✅ BIEN: tratar rest como read-only o copiar si necesitas mutar
function procesar(...items) {
  const copia = [...items, "extra"];
  return copia;
}

7 · Ejercicio guiado

Enunciado: Crea una función crearFormateador que reciba un objeto de opciones y devuelva una función capaz de formatear textos aplicando prefijos, sufijos y transformaciones.

Solución paso a paso:

  1. Definir la factory con defaults y rest:

    const crearFormateador = ({
  prefijo = "",
  sufijo = "",
  transformar = (s) => s, // default: identidad, no transforma
} = {}) => {
  // Devolvemos una función que aplica todo
  return (texto, ...extra) => {
    const base = [texto, ...extra].join(" ");
    return `${prefijo}${transformar(base)}${sufijo}`;
  };
};

  2. Usar con distintas configuraciones:

    const grito = crearFormateador({ sufijo: "!!!", transformar: s => s.toUpperCase() });
console.log(grito("hola", "mundo")); // "HOLA MUNDO!!!"

const html = crearFormateador({ prefijo: "<p>", sufijo: "</p>" });
console.log(html("Párrafo importante")); // "<p>Párrafo importante</p>"

const defecto = crearFormateador();
console.log(defecto("Sin formato")); // "Sin formato"

8 · Reto

🎯 Builder de consultas SQL seguro

Crea una función crearQueryBuilder(tabla, { columnas = ["*"], condiciones = {}, orden = "", limite = 0 } = {}) que devuelva un objeto con:

  • .select(...columnas) — usa rest parameters, reemplaza las columnas por defecto
  • .where({ columna: valor }) — usa spread para fusionar con condiciones existentes
  • .build() — devuelve el string SQL construido (simulado, sin conexión real)
  • Los valores en where deben escaparse con comillas simples (ej: "valor" → 'valor')
  • Usa destructuring, rest, spread y defaults en cada método

Ejemplo de salida esperada: SELECT nombre, email FROM usuarios WHERE rol = 'admin' ORDER BY nombre LIMIT 10

9 · Resumen

  • Parámetros son las variables declaradas; argumentos son los valores pasados.
  • Default parameters: solo se disparan con undefined, no con null, 0 o "".
  • Rest ...args: captura argumentos sobrantes en un array real. Siempre el último.
  • Spread ...arr: expande iterables en elementos individuales (llamadas, arrays, objetos).
  • Return implícito en arrows sin llaves; undefined si no hay return en cualquier función.
  • Funciones que devuelven funciones: base de currying, factory functions y HOF.
  • Destructuring en parámetros: objeto + defaults hace el código autodocumentado y flexible.
  • Spread hace copia superficial. Para copia profunda usa structuredClone.

10 · Preguntas frecuentes

¿Por qué el spread solo hace copia superficial?

Por rendimiento y filosofía de diseño. Una copia profunda recursiva sería costosa e impredecible (¿qué haces con funciones, símbolos, referencias circulares?). JavaScript te da la herramienta rápida y segura (...spread) y una explícita para cuando la necesitas (structuredClone). Es un principio de "paga solo por lo que usas".

¿Rest parameters o el objeto arguments?

Siempre rest parameters. arguments es un objeto array-like (no tiene .map, .filter, .reduce), no funciona en arrow functions, y su uso está desaconsejado en ES2025+. ...args te da un array real con todas las ventajas.

¿Puedo usar rest parameters en medio de otros parámetros?

No. ...args debe ser siempre el último parámetro formal. Esto es sintáctico por diseño: el motor necesita saber dónde termina la lista de parámetros nombrados y dónde empieza la captura del resto. function f(a, ...b, c) es un SyntaxError.

¿Cuándo es mejor devolver un objeto vs un array?

Devuelve un objeto cuando los valores tienen significado distinto ({ datos, error, total }). Devuelve un array cuando son una secuencia homogénea ([min, max]) o siguiendo un convenio como [error, resultado] (estilo Go). El objeto es más extensible y autodocumentado.
