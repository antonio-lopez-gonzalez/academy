Condicionales (if, switch, ternario) y valores truthy/falsy

Módulo 2 · Control de flujo y funciones ⏱ 30 minutos

1 · Introducción

Todos los programas toman decisiones. Sin condicionales, nuestro código haría siempre exactamente lo mismo, como un robot incapaz de reaccionar. JavaScript nos ofrece tres herramientas principales para bifurcar la ejecución: if/else, switch y el operador ternario. Pero detrás de cada una hay un mecanismo común: JavaScript evalúa cualquier valor como truthy o falsy dentro de un contexto booleano.

En esta lección dominarás todas las formas de tomar decisiones en JavaScript, entenderás por qué [] es truthy pero "" es falsy, y aprenderás patrones como el cortocircuito && y || que verás en cada código profesional que leas.

¿Por qué existe cada mecanismo? if/else cubre la lógica booleana general. switch optimiza múltiples comparaciones contra un mismo valor usando identidad estricta (===). El ternario permite incrustar decisiones dentro de expresiones, algo imposible con if. Cada uno resuelve un problema distinto de legibilidad y expresividad.

2 · Teoría

El bloque if / else if / else

La estructura más básica. La condición se evalúa como booleana mediante coerción implícita (truthy/falsy). Puedes anidar tantos else if como necesites, pero si son más de 3-4, plantéate usar switch o un objeto de mapeo.

const edad = 20;

if (edad < 13) {
  console.log("Infantil");      // bloque con llaves
} else if (edad < 18) {
  console.log("Adolescente");   // puedes omitir llaves si solo hay una sentencia... pero NO lo hagas
} else {
  console.log("Adulto");        // el else final captura todo lo demás
}

Las llaves {} son obligatorias para múltiples sentencias. Aunque JavaScript permite omitirlas con una sola instrucción, siempre debes usarlas. Apple tuvo un bug de seguridad grave (goto fail) por omitir llaves. No seas ese desarrollador.

switch: comparación estricta (===)

switch compara el valor de la expresión contra cada case usando el operador de identidad estricta ===. No hace coerción de tipos. Sin break, la ejecución "cae en cascada" al siguiente case (fall-through), algo que puede ser útil en casos muy concretos pero suele ser fuente de errores.

const dia = "lunes";

switch (dia) {
  case "lunes":
    console.log("Comienzo de semana");
    break;  // sin break, seguiría ejecutando los siguientes cases
  case "sábado":
  case "domingo":
    console.log("Fin de semana");  // fall-through intencionado
    break;
  default:
    console.log("Día laborable");  // ningún case coincidió
}

Operador ternario ? :

El ternario es el único operador de JavaScript que recibe tres operandos. Es una expresión, no una sentencia, lo que significa que devuelve un valor. Por eso puedes usarlo dentro de un return, una asignación o un template literal.

const acceso = edad >= 18 ? "Permitido" : "Denegado";
// equivalente a:
// let acceso;
// if (edad >= 18) { acceso = "Permitido"; } else { acceso = "Denegado"; }

No anides ternarios. a ? b : c ? d : e es ilegible. Si necesitas más de dos ramas, usa if/else o switch.

Truthy y Falsy: la tabla de la verdad oculta

Cuando JavaScript espera un booleano (en un if, un while, o el primer operando de && / ||), convierte el valor a booleano siguiendo estas reglas:

Valores Falsy (los únicos 8):

false       // booleano false
0           // número cero (y -0, 0n)
""          // string vacío (y '' y ``)
null        // ausencia intencionada de valor
undefined   // variable no inicializada
NaN         // Not a Number
0n          // BigInt cero
document.all // excepción histórica (falsy por compatibilidad)

Todo lo demás es truthy, incluyendo:

"hola"      // strings no vacíos
42          // números ≠ 0
[]          // arrays vacíos (¡cuidado!)
{}          // objetos vacíos (¡cuidado!)
() => {}    // funciones
Infinity    // infinito
new Date()  // instancias de Date

Analogía: imagina que JavaScript es un portero de discoteca. Tiene una lista de 8 personas que NO pueden entrar (los falsy). Cualquiera que no esté en esa lista, entra. Un array vacío [] no está en la lista negra, así que entra. Un string vacío "" sí está vetado.

Operador NOT (!!) para forzar booleano

Un solo ! niega y convierte a booleano. Doble !! solo convierte a booleano sin negar:

!!"hola"     // true  — string no vacío es truthy
!!0          // false — 0 es falsy
!![]         // true  — array vacío es truthy
!""          // true  — negación de falsy es true

Cortocircuito && y || para valores por defecto

Ambos operadores evalúan de izquierda a derecha y devuelven el valor del operando que decidió el resultado, no necesariamente un booleano:

// || devuelve el primer truthy (o el último si todos son falsy)
const nombre = input || "Anónimo";    // si input es falsy, usa "Anónimo"
const port = 0 || 8080;               // ¡ERROR! 0 es falsy, port = 8080

// ?? (Nullish Coalescing) solo salta con null/undefined
const port2 = 0 ?? 8080;              // port2 = 0 (correcto)

// && devuelve el primer falsy (o el último si todos son truthy)
const usuario = isLogged && userName; // si isLogged es truthy, evalúa userName

Comparaciones encadenadas

A diferencia de Python, JavaScript no permite comparaciones encadenadas del estilo 1 < x < 10. Debes usar operadores lógicos:

// ❌ INCORRECTO (JavaScript interpreta (1 < x) < 10, no lo que esperas)
if (1 < x < 10) { }  // (1 < x) da true/false, luego compara true/false < 10

// ✅ CORRECTO
if (x > 1 && x < 10) { }

3 · Ejemplo mínimo

function clasificarValor(valor) {
  if (!valor && valor !== 0 && valor !== false) {
    return `"${valor}" es FALSY (no entraría en un if)`;
  }
  return `"${valor}" es TRUTHY (sí entraría en un if)`;
}

console.log(clasificarValor("hola"));  // "hola" es TRUTHY
console.log(clasificarValor(""));      // "" es FALSY
console.log(clasificarValor(0));       // "0" es FALSY
console.log(clasificarValor([]));      // "[]" es TRUTHY — ¡el array vacío es truthy!
console.log(clasificarValor(null));    // "null" es FALSY

Pega este código en la consola del navegador (F12) y observa cómo cada valor se comporta de forma distinta. Nota especialmente que [] es truthy y que 0 es falsy: dos de las confusiones más comunes.

4 · Ejemplo real

Un sistema de permisos para un panel de administración:

const usuario = {
  nombre: "Ana",
  rol: "editor",      // "admin" | "editor" | "lector"
  activo: true,
  intentos: 0,
};

function puedeAcceder(usuario, seccion) {
  if (!usuario.activo) {
    return { permitido: false, razon: "Cuenta desactivada" };
  }

  switch (usuario.rol) {
    case "admin":
      return { permitido: true, razon: "Acceso total" };

    case "editor":
      // ternario dentro de un objeto: expresivo y conciso
      return {
        permitido: seccion === "configuracion" ? false : true,
        razon:
          seccion === "configuracion"
            ? "Solo admin puede ver configuración"
            : "Acceso permitido",
      };

    case "lector":
      return { permitido: false, razon: "Solo lectura" };

    default:
      return { permitido: false, razon: "Rol desconocido" };
  }
}

console.log(puedeAcceder(usuario, "articulos"));     // permitido: true
console.log(puedeAcceder(usuario, "configuracion"));  // permitido: false

Este patrón es real: combinas if para una condición simple, switch para múltiples variantes de una misma variable, y ternario para expresiones inline. Es el tipo de código que escribirás en cualquier backend o frontend real.

6 · Errores habituales

1. Olvidar que [] y {} son truthy

// ❌ MAL: asumes que un array vacío es falsy
const tareas = [];
if (!tareas) {
  console.log("No hay tareas"); // ¡NUNCA se ejecuta! [] es truthy
}

// ✅ BIEN
if (tareas.length === 0) {
  console.log("No hay tareas"); // esto sí funciona
}

2. Confundir asignación (=) con comparación (===)

// ❌ MAL: asignación dentro del if
if (usuario.rol = "admin") {  // esto ASIGNA "admin", no compara
  console.log("Acceso concedido"); // siempre se ejecuta y además machaca el rol
}

// ✅ BIEN
if (usuario.rol === "admin") {
  console.log("Acceso concedido");
}

3. Usar || donde necesitas ??

// ❌ MAL: 0 es un valor válido pero || lo descarta
function configurar(volumen) {
  const vol = volumen || 50;  // si volumen = 0, vol será 50 (¡error!)
}

// ✅ BIEN
function configurar(volumen) {
  const vol = volumen ?? 50;  // solo salta si volumen es null o undefined
}

7 · Ejercicio guiado

Enunciado: Crea una función calcularPrecio(tipoCliente, precioBase) que devuelva el precio final según:

  • "VIP" → 20% de descuento
  • "frecuente" → 10% de descuento
  • "nuevo" → sin descuento
  • Cualquier otro tipo → error: "Tipo desconocido"
  • Si precioBase no es un número positivo → error: "Precio inválido"

Solución paso a paso:

  1. Validar el precio:

    function calcularPrecio(tipoCliente, precioBase) {
  if (typeof precioBase !== "number" || precioBase <= 0 || Number.isNaN(precioBase)) {
    return { error: "Precio inválido" };
  }
  // ... continuamos

  2. Aplicar descuento con switch:

      let descuento;
  switch (tipoCliente) {
    case "VIP":
      descuento = 0.2;
      break;
    case "frecuente":
      descuento = 0.1;
      break;
    case "nuevo":
      descuento = 0;
      break;
    default:
      return { error: "Tipo de cliente desconocido" };
  }

  3. Calcular y devolver resultado con ternario:

      const precioFinal = precioBase * (1 - descuento);
  return {
    precioOriginal: precioBase,
    descuentoAplicado: descuento * 100 + "%",
    precioFinal: Math.round(precioFinal * 100) / 100, // redondear a 2 decimales
    mensaje: descuento > 0 ? "¡Descuento aplicado!" : "Precio sin descuento",
  };
}

Prueba con console.log(calcularPrecio("VIP", 100)), calcularPrecio("nuevo", 50) y calcularPrecio("desconocido", 10).

🎯 Validador de formulario con puntuación de seguridad

Crea una función validarPassword(password) que devuelva un objeto { valida: boolean, puntuacion: number, fallos: string[] }. Las reglas:

  • Mínimo 8 caracteres (si no, suma un fallo)
  • Al menos 1 mayúscula (si no, suma otro fallo)
  • Al menos 1 número (si no, suma otro fallo)
  • Al menos 1 carácter especial (!@#$%^&*)

9 · Resumen

  • if/else para lógica booleana general. Siempre con llaves {}.
  • switch compara con ===. Usa break salvo fall-through intencionado.
  • Ternario ? : es una expresión que devuelve valor. No lo anides.
  • Solo hay 8 valores falsy: false, 0, "", null, undefined, NaN, 0n, document.all. Todo lo demás es truthy.
  • !! convierte cualquier valor a su equivalente booleano.
  • || devuelve el primer truthy; ?? devuelve el primer valor que no sea null ni undefined.
  • && devuelve el primer falsy o el último operando si todos son truthy.
  • JavaScript no permite comparaciones encadenadas (1 < x < 10). Usa &&.

10 · Preguntas frecuentes

¿Por qué [] == false es true pero [] es truthy?

Porque == (igualdad floja) sigue el Abstract Equality Algorithm que fuerza coerción de tipos paso a paso. [] se convierte a "", luego a 0, y false también a 0, así que 0 == 0 es true. Pero en un contexto booleano (truthy/falsy), [] no está en la lista de los 8 falsy, así que es truthy. Esta inconsistencia es una de las razones por las que siempre debes usar ===.

¿Cuándo usar switch en vez de if/else?

Cuando comparas la misma variable contra múltiples valores concretos (3+ casos). switch comunica "estoy despachando sobre este valor". Si las condiciones son rangos (x > 10) o involucran variables distintas, usa if/else. Con muchos casos (>7), considera un objeto de mapeo o un Map para mejor rendimiento y legibilidad.

¿Es cierto que "0" es truthy?

Sí. "0" es un string no vacío, y el único string falsy es "". Esto confunde a gente que viene de PHP o Python donde "0" puede ser falsy. En JavaScript, cualquier string con al menos un carácter es truthy, sin importar qué carácter sea.

¿if (x) o if (!!x)?

if (x) ya convierte a booleano implícitamente. No necesitas !! dentro de un if. !! es útil cuando quieres almacenar el booleano resultante: const esValido = !!input;.
