Operadores, coerción de tipos y comparaciones

Módulo 1 · Fundamentos ⏱ 35 minutos

1 · Introducción

Los operadores son los verbos de la programación: suman, comparan, asignan y evalúan. Pero JavaScript tiene una particularidad que desconcierta a programadores que vienen de otros lenguajes: la coerción de tipos. JavaScript convierte automáticamente entre tipos cuando usas ciertos operadores, a veces con resultados sorprendentes.

En esta lección dominarás todos los operadores (aritméticos, comparación, lógicos, asignación), entenderás la tabla de valores truthy/falsy, aprenderás a usar ?? (nullish coalescing) y ?. (optional chaining), y sabrás cuándo y cómo hacer conversiones explícitas.

¿Por qué existe esta lección? Porque el 80% de los bugs en JavaScript vienen de comparaciones incorrectas (== en vez de ===) y de no entender la coerción. Un profesional domina esto en la primera semana.

2 · Teoría

Operadores aritméticos

const suma = 5 + 3;        // 8
const resta = 10 - 4;      // 6
const multiplicacion = 3 * 4; // 12
const division = 15 / 3;   // 5
const modulo = 10 % 3;     // 1 (resto de la división)
const exponente = 2 ** 3;  // 8 (2 elevado a 3)

Los operadores + y - tienen comportamiento dual:

// + concatena strings si alguno de los operandos es string
console.log(5 + '5');      // '55' (string)
console.log('Hola' + ' ' + 'mundo'); // 'Hola mundo'

// + como operador unario convierte a número
console.log(+'42');        // 42 (número)
console.log(+true);        // 1
console.log(+'');          // 0

// - como operador unario convierte a número y niega
console.log(-'42');        // -42

Operadores de comparación: == vs ===

Esta es la diferencia más importante que debes interiorizar:

  • === (estricto): compara valor y tipo. Sin coerción. 5 === '5' es false.
  • == (abstracto): compara valor después de coerción. 5 == '5' es true.

Analogía: === es como un portero de discoteca que pide DNI y entrada: comprueba todo. == es el portero que deja pasar a cualquiera que «se parezca» a alguien de la lista.

// Comparaciones con === (predecibles)
0 === 0       // true
0 === '0'     // false (número vs string)
'' === false  // false (string vs boolean)
null === undefined // false

// Comparaciones con == (sorprendentes)
0 == '0'      // true (coerción: '0' → 0)
0 == ''       // true (coerción: '' → 0)
'' == false   // true (ambos se convierten a 0)
null == undefined // true (caso especial en la especificación)

Tabla de truthy / falsy

En JavaScript, todo valor tiene una interpretación booleana cuando se usa en un contexto condicional (if, &&, ||, !).

Valores FALSY (los únicos 8):

TODO lo demás es TRUTHY, incluyendo: [], {}, 'false', '0', ' ', Infinity, -1.

Truco mental: memoriza los 8 falsy. Todo lo demás — absolutamente todo, incluso un array vacío [] o el string 'false' — es truthy.

Operadores lógicos

// AND (&&): devuelve el primer falsy O el último valor si todos son truthy
console.log(true && 'Hola');   // 'Hola'
console.log(false && 'Hola');  // false
console.log(0 && 'nada');      // 0 (primer falsy)
console.log('a' && 'b' && 'c'); // 'c' (último valor)

// OR (||): devuelve el primer truthy O el último valor si todos son falsy
console.log('Hola' || 'Mundo'); // 'Hola' (primer truthy)
console.log(0 || '' || 'valor'); // 'valor' (primer truthy)
console.log(0 || '' || null);   // null (último, todos falsy)

// NOT (!): convierte a booleano y niega
console.log(!true);      // false
console.log(!0);         // true (0 es falsy)
console.log(!!'texto');  // true (doble negación = convertir a booleano)

El comportamiento de && y || de devolver el valor del operando (no necesariamente un booleano) se llama evaluación de cortocircuito (short-circuit evaluation). Es una característica, no un bug, y se usa muchísimo en JavaScript idiomático.

Nullish Coalescing (??)

El operador ?? (ES2020) devuelve el valor de la derecha solo si el de la izquierda es null o undefined. A diferencia de ||, no trata 0, '' o false como «vacío»:

// || trata 0, '' y false como falsy
console.log(0 || 42);        // 42 (0 es falsy → se descarta)
console.log('' || 'default'); // 'default' ('' es falsy)

// ?? solo se activa con null o undefined
console.log(0 ?? 42);        // 0 (0 NO es null ni undefined)
console.log('' ?? 'default'); // '' (string vacío NO es null ni undefined)
console.log(null ?? 42);     // 42 (null sí activa ??)
console.log(undefined ?? 42); // 42 (undefined sí activa ??)

Optional Chaining (?.)

El operador ?. (ES2020) accede a propiedades de forma segura. Si lo que está a la izquierda es null o undefined, la expresión entera devuelve undefined en vez de lanzar un error:

const user = null;

// Sin optional chaining: 💥 TypeError
// console.log(user.name); // TypeError: Cannot read properties of null

// Con optional chaining: seguro
console.log(user?.name);          // undefined (no falla)
console.log(user?.address?.city); // undefined (encadenable)
console.log(user?.getName?.());   // undefined (funciona con métodos)

const realUser = { name: 'Ana', address: { city: 'Madrid' } };
console.log(realUser?.name);           // 'Ana'
console.log(realUser?.address?.city);  // 'Madrid'
console.log(realUser?.phone?.number);  // undefined (phone no existe)

Regla: || para valores por defecto cuando 0, '' o false NO son válidos. ?? cuando 0, '' o false SÍ son valores válidos y solo quieres descartar null/undefined.

NaN, Infinity, -0

// NaN: Not a Number (resultado de operación matemática inválida)
console.log(0 / 0);              // NaN
console.log(parseInt('hola'));   // NaN
console.log(Math.sqrt(-1));      // NaN
console.log(NaN === NaN);        // false ← NaN no es igual a sí mismo
console.log(Number.isNaN(NaN));  // true  ← forma correcta de comprobarlo

// Infinity y -Infinity
console.log(1 / 0);              // Infinity
console.log(-1 / 0);             // -Infinity
console.log(Infinity > 9999999); // true
console.log(Infinity + 1);       // Infinity (sigue siendo infinito)

// -0 (cero negativo, existe en el estándar IEEE 754)
console.log(0 / -1);             // -0
console.log(-0 === 0);           // true (comparación normal)
console.log(Object.is(-0, 0));   // false (única forma de distinguirlos)

Conversión explícita

Siempre es mejor convertir tipos explícitamente que confiar en la coerción implícita:

// A número
Number('42');          // 42
Number('42.5');        // 42.5
Number('');            // 0
Number('hola');        // NaN
parseInt('42px');      // 42 (solo la parte entera inicial)
parseFloat('3.14em');  // 3.14

// A string
String(42);            // '42'
String(true);          // 'true'
(42).toString();       // '42'

// A booleano
Boolean(1);            // true
Boolean(0);            // false
Boolean('');           // false
Boolean('texto');      // true
!!'texto';             // true (atajo idiomático)

Precedencia de operadores

De mayor a menor prioridad:

1. ()       → Agrupación
2. ! ++ --  → Negación, incremento, decremento
3. **       → Exponenciación
4. * / %    → Multiplicación, división, módulo
5. + -      → Suma, resta
6. < > <= >= → Comparación
7. == != === !== → Igualdad
8. &&       → AND lógico
9. ||       → OR lógico
10. ??      → Nullish coalescing
11. =       → Asignación

3 · Ejemplo mínimo

// Operadores en acción: una calculadora de descuento
const precio = 100;
const descuento = 0.15;
const tieneCupon = true;
const descuentoAdicional = 10;

// Cálculo con operadores aritméticos y lógicos
const precioFinal = precio * (1 - descuento) - (tieneCupon ? descuentoAdicional : 0);

// ?? para evitar valores undefined
const mostrarPrecio = precioFinal ?? 'No disponible';

// || para valor por defecto (cuando 0 no es válido)
const etiqueta = mostrarPrecio || 'Sin precio';

console.log(`Precio final: ${etiqueta}€`); // Precio final: 75€

4 · Ejemplo real

Procesador de datos de usuario de una API, con validación y valores por defecto:

// Datos que vienen de una API (pueden ser inconsistentes)
const apiResponse = {
  user: {
    name: 'Carlos',
    age: 0,              // 0 es válido (recién nacido)
    email: '',           // email vacío = no proporcionado
    settings: {
      theme: null,       // null = usar tema por defecto
      notifications: undefined
    },
    tags: null           // null = sin etiquetas
  }
};

function processUser(data) {
  const user = data?.user ?? {}; // Si user no existe, objeto vacío

  // ?? respeta 0 y '' como valores válidos
  const name = user?.name ?? 'Anónimo';
  const age = user?.age ?? 'No especificada';  // age=0 NO se reemplaza
  const email = user?.email || 'Sin email';     // '' sí se reemplaza (||)

  // Optional chaining anidado con fallback
  const theme = user?.settings?.theme ?? 'light';
  const notify = user?.settings?.notifications ?? true;

  // ?? con arrays: si tags es null, usa array vacío
  const tags = user?.tags ?? [];

  return { name, age, email, theme, notify, tags };
}

const result = processUser(apiResponse);
console.table([result]);

6 · Errores habituales

Usar == sin entender la coerción

// ❌ Comportamientos sorprendentes de ==
if ('' == false)    { console.log('true!'); } // Se ejecuta ('' → 0, false → 0)
if (0 == '')        { console.log('true!'); } // Se ejecuta ('' → 0)
if (' \t\n' == 0)  { console.log('true!'); } // Se ejecuta (string whitespace → 0)

// ✅ Siempre ===
if ('' === false)   { /* No se ejecuta. Correcto */ }
if (0 === '')       { /* No se ejecuta. Correcto */ }

Olvidar que || descarta 0 y ''

// ❌ Bug sutil: edad=0 se convierte en 'Sin datos'
function mostrarEdad(edad) {
  return edad || 'Sin datos'; // 0 es falsy → devuelve 'Sin datos'
}
console.log(mostrarEdad(0)); // 'Sin datos' (INCORRECTO, 0 es una edad válida)

// ✅ ?? respeta 0 como valor válido
function mostrarEdad(edad) {
  return edad ?? 'Sin datos'; // 0 es válido → devuelve 0
}
console.log(mostrarEdad(0)); // 0 (CORRECTO)

Pensar que null >= 0 es false

// ❌ Esto parece contradictorio pero es correcto según la especificación
console.log(null > 0);   // false
console.log(null == 0);  // false (== no convierte null a 0)
console.log(null >= 0);  // true  ← ¿¡Qué!?

// Explicación: >= usa el algoritmo de comparación abstracta relacional,
// que convierte null a 0. Pero == usa reglas distintas.
// Moraleja: no compares null con números; comprueba explícitamente.

Sumar sin darse cuenta de la concatenación

// ❌ Bug: + concatena si hay strings
const a = prompt('Número 1'); // Devuelve string: '5'
const b = prompt('Número 2'); // Devuelve string: '3'
console.log(a + b); // '53' (concatenación, no suma)

// ✅ Convierte explícitamente
const a2 = Number(prompt('Número 1')); // 5
const b2 = Number(prompt('Número 2')); // 3
console.log(a2 + b2); // 8 (suma)

7 · Ejercicio guiado

Objetivo: Construir un validador de formulario usando operadores.

  1. Paso 1 — Datos de entrada (simulados): 
    const formData = {
  name: '',
  email: '   ',
  age: null,
  newsletter: false,
  plan: 0,          // 0 = plan gratuito (válido)
};
  2. Paso 2 — Validación con operadores: 
    const errors = [];

// name: debe ser string no vacío después de trim
if (!formData.name?.trim()) {
  errors.push('El nombre es obligatorio');
}

// email: debe contener '@' después de trim
const cleanEmail = formData.email?.trim() ?? '';
if (!cleanEmail || !cleanEmail.includes('@')) {
  errors.push('El email no es válido');
}

// age: null o undefined es válido, pero si tiene valor, debe ser >= 0
if (formData.age !== null && formData.age !== undefined && formData.age < 0) {
  errors.push('La edad no puede ser negativa');
}

// plan: 0 es válido (plan gratuito)
const planName = formData.plan ?? 'sin plan';
console.log(`Plan seleccionado: ${planName}`);
  3. Paso 3 — Resultado: 
    const isValid = errors.length === 0;
console.log(isValid ? '✅ Formulario válido' : `❌ Errores:\n${errors.join('\n')}`);
  4. Paso 4 — Prueba: Cambia los valores de formData (pon name: 'Ana', email: 'ana@mail.com') y verifica que el mensaje cambia.

8 · Reto

🎯 Calculadora de puntuación con truthy/falsy

Crea una función calcularPuntuacion(respuestas) que reciba un array de respuestas de un test y devuelva la puntuación total. Las reglas:

  1. Cada respuesta true suma 1 punto.
  2. Cada respuesta que sea un número positivo suma ese número de puntos.
  3. false, null, undefined, NaN y strings vacíos suman 0 puntos.
  4. Si alguna respuesta no es de un tipo esperado, ignórala (no puntúa).
  5. Usa ?? para manejar null/undefined en el acumulador.
  6. La función debe devolver un objeto: { puntuacion, totalPreguntas, porcentaje }.

Ejemplo: calcularPuntuacion([true, false, 3, null, true, 0, 'correcto', undefined]) debería devolver { puntuacion: 5, totalPreguntas: 8, porcentaje: 62.5 }.

9 · Resumen

  • Operadores aritméticos: +, -, *, /, %, **. El + concatena strings si algún operando es string.
  • === vs ==: usa siempre ===. == aplica coerción impredecible.
  • 8 valores falsy: false, 0, -0, 0n, '', null, undefined, NaN. Todo lo demás es truthy.
  • && y || usan evaluación de cortocircuito: devuelven el valor del operando, no necesariamente un booleano.
  • ?? (nullish coalescing): solo se activa con null o undefined. Úsalo cuando 0 y '' sean valores válidos.
  • ?. (optional chaining): acceso seguro a propiedades. Devuelve undefined si algo es null/undefined.
  • Conversión explícita: Number(), String(), Boolean(), parseInt(), parseFloat().
  • NaN no es igual a sí mismo. Usa Number.isNaN() para comprobarlo.

10 · Preguntas frecuentes

¿Por qué existe == si es tan problemático?

== existe desde la primera versión de JavaScript. En aquella época, la web era principalmente texto (todo eran strings de formularios) y se consideraba útil que '5' == 5 fuera true. Hoy sabemos que fue un error de diseño, pero la web no se puede romper. La comunidad profesional ha llegado a un consenso claro: usa siempre ===.

¿Cuál es la diferencia entre ?? y || exactamente?

a || b devuelve b si a es cualquier valor falsy (0, '', false, null, undefined, NaN). a ?? b devuelve b solo si a es null o undefined. Ejemplo clave: 0 || 42 → 42 (porque 0 es falsy). 0 ?? 42 → 0 (porque 0 no es null ni undefined).

¿Optional chaining funciona con índices de array y llamadas a función?

Sí. arr?.[0] accede al primer elemento de forma segura. func?.() llama a la función solo si no es null/undefined. También funciona con propiedades dinámicas: obj?.['prop-' + name]. Es una herramienta muy versátil introducida en ES2020.

¿Por qué NaN !== NaN?

Es una consecuencia del estándar IEEE 754 (aritmética de punto flotante), que JavaScript implementa. La lógica es: si dos operaciones producen «Not a Number», no hay razón para asumir que son el mismo «no-número». Es un comportamiento heredado de las matemáticas de punto flotante, no un capricho de JavaScript.

¿Puedo encadenar múltiples ?? y ?.?

Sí. Ambos operadores se pueden encadenar: a ?? b ?? c ?? 'default' devuelve el primer valor que no sea null/undefined. user?.profile?.address?.city devuelve undefined si cualquier eslabón de la cadena es null/undefined. Ten cuidado con encadenamientos excesivos: pueden ocultar errores estructurales que deberías arreglar en vez de esquivar.
