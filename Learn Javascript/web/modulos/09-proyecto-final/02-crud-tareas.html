CRUD de tareas con Web Storage + DOM

Módulo 9 · Proyecto Final: TaskFlow Vanilla ⏱ 40 minutos

1 · Introducción

En la lección anterior montaste el esqueleto de TaskFlow: el router, el store y la estructura de archivos. Hoy vas a darle VIDA. Vas a implementar las cuatro operaciones fundamentales de cualquier aplicación de datos: Crear, Leer, Actualizar y Eliminar — el famoso CRUD.

Pero no vamos a hacer un CRUD cualquiera. Vamos a construir uno que:

  • Persiste en localStorage — los datos sobreviven a recargas de página y cierres de navegador.
  • Es reactivo — cuando creas, editas o eliminas una tarea, la vista se actualiza automáticamente sin que tengas que llamar a ninguna función de renderizado manual.
  • Usa BEM-like naming — nombres de clases CSS profesionales que no colisionan y comunican jerarquía.
  • Soporta edición inline — haces doble clic en una tarea y la editas directamente donde está, sin formularios modales.
  • Tiene confirmación antes de eliminar — porque borrar accidentalmente una tarea importante es una de las peores experiencias de usuario.

Analogía: Si el router y el store de la lección anterior eran los planos y los cimientos de un edificio, esta lección construye las paredes, puertas y ventanas. El CRUD es la interfaz entre el usuario y los datos — es donde la arquitectura abstracta se convierte en algo que el usuario puede tocar y usar.

2 · Teoría

El flujo completo del CRUD

En TaskFlow, cada operación CRUD sigue exactamente el mismo patrón:

┌─────────┐     ┌─────────┐     ┌──────────┐     ┌──────────┐
│  EVENTO │ →   │  STORE  │ →   │  STORAGE │ →   │   DOM    │
│ (click, │     │.action()│     │localStore│     │.reRender()│
│ submit) │     └─────────┘     └──────────┘     └──────────┘
└─────────┘
   Usuario      Actualiza       Persiste         La vista se
   interactúa   el estado       los datos        actualiza
                en memoria      en disco         automáticamente

Cada paso está separado por una razón:

  1. Evento → Store: el componente de UI captura el evento del usuario (submit de formulario, clic en botón) y llama a una acción del store. El componente NO manipula datos directamente — solo el store sabe cómo hacerlo.
  2. Store → Storage: cada vez que el estado cambia, el store lo guarda en localStorage. Así, si el usuario recarga la página, los datos se recuperan.
  3. Store → DOM: las vistas están suscritas al store. Cuando el estado cambia, el store notifica a todos los suscriptores, que se re-renderizan automáticamente.

CRUD en detalle

C (Create) — Añadir una tarea

El formulario de creación recoge los datos de la tarea (título, descripción, prioridad, fecha). Al enviar, validamos que el título no esté vacío, generamos un ID único, creamos el objeto tarea y lo pasamos al store.

R (Read) — Mostrar las tareas

La vista de lista de tareas lee el estado del store y renderiza cada tarea como una tarjeta. Aplica filtros (todas, pendientes, completadas) leyendo el filtro activo del store.

U (Update) — Editar una tarea

Usamos contentEditable para edición inline: el usuario hace doble clic en el título o la descripción, el texto se vuelve editable, y al pulsar Enter o hacer clic fuera, el cambio se guarda en el store. También soportamos el toggle de completado (checkbox) y cambio de prioridad.

D (Delete) — Eliminar una tarea

Antes de eliminar, mostramos confirmación. Si el usuario confirma, eliminamos la tarea del store. Implementamos también un "undo" temporal: guardamos la tarea eliminada durante 5 segundos por si fue un error.

localStorage: persistencia en el navegador

localStorage es un almacén clave-valor que persiste incluso cuando el usuario cierra el navegador. Solo almacena strings, así que serializamos con JSON.stringify() al guardar y deserializamos con JSON.parse() al leer.

APICapacidadPersistenciaAcceso desde JS
localStorage~5-10 MBPermanente (hasta que se borra manualmente)Síncrono, cualquier script
sessionStorage~5-10 MBHasta que se cierra la pestañaSíncrono, cualquier script
Cookies~4 KBConfigurable (expiración)Se envía en cada petición HTTP
IndexedDBIlimitada (con permiso)PermanenteAsíncrono, cualquier script

¿Por qué localStorage y no IndexedDB? Para las ~50-200 tareas que tendrá TaskFlow, localStorage es más que suficiente y mucho más simple. IndexedDB es mejor cuando manejas miles de registros o necesitas búsquedas complejas, consultas y transacciones. Para un gestor de tareas personal, localStorage es la herramienta correcta.

BEM-like class naming

BEM (Block, Element, Modifier) es una convención para nombrar clases CSS que comunica la relación entre elementos. TaskFlow usa una versión simplificada:

  • Bloque: componente independiente. Ej: .task-card, .task-form.
  • Elemento: parte de un bloque. Ej: .task-card__title, .task-form__input.
  • Modificador: variante de un bloque o elemento. Ej: .task-card--completed, .task-card__title--editing.

Esta convención evita colisiones de nombres incluso en aplicaciones grandes y hace que el CSS sea auto-documentado: leyendo .task-card__title--editing sabes exactamente qué es y en qué estado está.

Componente TaskForm — Crear tarea

// components/task-form.js
// Componente puro: recibe una función onSubmit y devuelve HTML
export function TaskForm({ onSubmit }) {
  return `
    <form class="task-form" id="task-form">
      <input
        class="task-form__input"
        type="text"
        name="title"
        placeholder="¿Qué necesitas hacer?"
        required
        autofocus
      />
      <div class="task-form__row">
        <select class="task-form__select" name="priority">
          <option value="low">🔵 Baja</option>
          <option value="medium" selected>🟡 Media</option>
          <option value="high">🔴 Alta</option>
        </select>
        <input class="task-form__input" type="date" name="dueDate" />
        <button class="task-form__submit" type="submit">Añadir</button>
      </div>
    </form>
  `;
}

// Función de montaje: crea el HTML y añade el event listener
export function mountTaskForm(container, { onCreate }) {
  container.innerHTML = TaskForm({});

  // Añadir event listener DESPUÉS de insertar en el DOM
  const form = container.querySelector('#task-form');
  form.addEventListener('submit', (event) => {
    event.preventDefault();
    const formData = new FormData(form);

    const task = {
      title: formData.get('title').trim(),
      priority: formData.get('priority'),
      dueDate: formData.get('dueDate') || null,
    };

    if (task.title) {
      onCreate(task);   // Llamar al callback del padre (que llama al store)
      form.reset();     // Limpiar el formulario para la siguiente tarea
      form.querySelector('[name="title"]').focus(); // Volver a enfocar el input
    }
  });

  // Limpieza al desmontar
  return () => {};
}

Componente TaskCard — Mostrar una tarea

// components/task-card.js
// Componente puro: recibe un objeto task y devuelve HTML
export function TaskCard(task) {
  // Clases CSS dinámicas según el estado
  const completedClass = task.completed ? 'task-card--completed' : '';
  const priorityClass = `task-card--${task.priority}`;

  // Formatear fecha para mostrar
  const dueDate = task.dueDate
    ? `<time datetime="${task.dueDate}">📅 ${new Date(task.dueDate).toLocaleDateString()}</time>`
    : '';

  return `
    <article
      class="task-card ${completedClass} ${priorityClass}"
      data-task-id="${task.id}"
    >
      <div class="task-card__header">
        <input
          type="checkbox"
          class="task-card__checkbox"
          ${task.completed ? 'checked' : ''}
          aria-label="Marcar como completada"
        />
        <h3
          class="task-card__title"
          contenteditable="false"
        >${escapeHTML(task.title)}</h3>
      </div>
      ${task.description ? `<p class="task-card__description">${escapeHTML(task.description)}</p>` : ''}
      <div class="task-card__meta">
        <span class="task-card__priority">${task.priority}</span>
        ${dueDate}
      </div>
      <button class="task-card__delete" aria-label="Eliminar tarea">🗑</button>
    </article>
  `;
}

// Helper de escape (anti-XSS — ya lo vimos en el módulo de seguridad)
function escapeHTML(str) {
  const div = document.createElement('div');
  div.textContent = str;
  return div.innerHTML;
}

Store con persistencia en localStorage

// store.js — Versión con persistencia en localStorage
function createStore(storageKey = 'taskflow-state') {
  // Cargar estado inicial desde localStorage (si existe)
  const saved = localStorage.getItem(storageKey);

  let state = saved
    ? JSON.parse(saved)       // Recuperar estado guardado
    : { tasks: [], filter: 'all' }; // Estado inicial por defecto

  const listeners = new Set();

  // Guardar en localStorage cada vez que el estado cambia
  function persist() {
    localStorage.setItem(storageKey, JSON.stringify(state));
  }

  function notify() {
    listeners.forEach((fn) => fn(state));
  }

  return {
    getState() {
      return { ...state };
    },

    subscribe(fn) {
      listeners.add(fn);
      return () => listeners.delete(fn);
    },

    // Cada acción ahora llama a persist() + notify()
    addTask(taskData) {
      const task = {
        id: generateId(),
        ...taskData,
        completed: false,
        createdAt: new Date().toISOString()
      };
      state = { ...state, tasks: [...state.tasks, task] };
      persist();  // Guardar en localStorage
      notify();   // Actualizar vistas
      return task;
    },

    updateTask(taskId, updates) {
      state = {
        ...state,
        tasks: state.tasks.map((t) =>
          t.id === taskId ? { ...t, ...updates } : t
        )
      };
      persist();
      notify();
    },

    deleteTask(taskId) {
      state = {
        ...state,
        tasks: state.tasks.filter((t) => t.id !== taskId)
      };
      persist();
      notify();
    },

    toggleTask(taskId) {
      state = {
        ...state,
        tasks: state.tasks.map((t) =>
          t.id === taskId ? { ...t, completed: !t.completed } : t
        )
      };
      persist();
      notify();
    }
  };
}

4 · Ejemplo real

Aquí está la vista completa de tareas que integra el formulario de creación, la lista con filtros, edición inline, toggle de completado y eliminación con confirmación:

// ===== views/tasks.js =====
import store from '../store.js';
import { TaskCard } from '../components/task-card.js';

export function mount(container) {
  // Array para guardar funciones de limpieza de event listeners
  const cleanups = [];

  // ---- RENDERIZADO PRINCIPAL ----
  function render() {
    const { tasks, filter } = store.getState();

    // Aplicar filtro
    const filtered = filter === 'all'
      ? tasks
      : tasks.filter((t) => filter === 'completed' ? t.completed : !t.completed);

    // Construir el HTML completo
    container.innerHTML = `
      <div class="tasks-view">
        <h2 class="tasks-view__title">Mis Tareas (${tasks.length})</h2>

        <!-- FORMULARIO DE CREACIÓN -->
        <div id="task-form-container"></div>

        <!-- FILTROS -->
        <nav class="tasks-view__filters">
          <button data-filter="all"       class="${filter === 'all'       ? 'active' : ''}">Todas</button>
          <button data-filter="pending"   class="${filter === 'pending'   ? 'active' : ''}">Pendientes</button>
          <button data-filter="completed" class="${filter === 'completed' ? 'active' : ''}">Completadas</button>
        </nav>

        <!-- LISTA DE TAREAS -->
        <div class="tasks-view__list" id="task-list">
          ${filtered.length === 0
            ? '<p class="tasks-view__empty">No hay tareas. ¡Crea la primera!</p>'
            : filtered.map(TaskCard).join('')
          }
        </div>
      </div>
    `;

    // Adjuntar event listeners (delegados o individuales)
    attachEventListeners();
  }

  // ---- EVENT LISTENERS (usando delegación de eventos) ----
  function attachEventListeners() {
    // 1. FORMULARIO DE CREACIÓN
    const form = container.querySelector('#task-form-container');
    // Montar el formulario y guardar su función de limpieza
    cleanups.push(
      mountTaskForm(form, {
        onCreate: (taskData) => store.addTask(taskData)
      })
    );

    // 2. FILTROS (delegación de eventos en el nav)
    const filterNav = container.querySelector('.tasks-view__filters');
    const filterHandler = (event) => {
      const btn = event.target.closest('button');
      if (!btn) return;
      store.setFilter(btn.dataset.filter); // El store notifica → render se vuelve a ejecutar
    };
    filterNav.addEventListener('click', filterHandler);
    cleanups.push(() => filterNav.removeEventListener('click', filterHandler));

    // 3. CHECKBOX DE COMPLETADO (delegación)
    const list = container.querySelector('#task-list');
    const listHandler = (event) => {
      // Detectar clic en checkbox
      const checkbox = event.target.closest('.task-card__checkbox');
      if (checkbox) {
        const taskId = checkbox.closest('.task-card').dataset.taskId;
        store.toggleTask(taskId);
        return;
      }

      // Detectar clic en botón de eliminar
      const deleteBtn = event.target.closest('.task-card__delete');
      if (deleteBtn) {
        const card = deleteBtn.closest('.task-card');
        const taskId = card.dataset.taskId;
        handleDelete(taskId, card);
        return;
      }
    };
    list.addEventListener('click', listHandler);
    cleanups.push(() => list.removeEventListener('click', listHandler));

    // 4. EDICIÓN INLINE CON DOBLE CLIC
    list.addEventListener('dblclick', (event) => {
      const titleEl = event.target.closest('.task-card__title');
      if (!titleEl) return;

      // Activar modo edición
      titleEl.contentEditable = 'true';
      titleEl.classList.add('task-card__title--editing');
      titleEl.focus();

      // Seleccionar todo el texto para que el usuario pueda sobrescribir
      const range = document.createRange();
      range.selectNodeContents(titleEl);
      const selection = window.getSelection();
      selection.removeAllRanges();
      selection.addRange(range);

      // Guardar al perder el foco o pulsar Enter
      const saveEdit = () => {
        const newTitle = titleEl.textContent.trim();
        titleEl.contentEditable = 'false';
        titleEl.classList.remove('task-card__title--editing');

        if (newTitle && newTitle !== titleEl.dataset.original) {
          const taskId = titleEl.closest('.task-card').dataset.taskId;
          store.updateTask(taskId, { title: newTitle });
        }
      };

      // Guardar antes del cambio para poder comparar
      titleEl.dataset.original = titleEl.textContent;

      titleEl.addEventListener('blur', saveEdit, { once: true });
      titleEl.addEventListener('keydown', (e) => {
        if (e.key === 'Enter') { e.preventDefault(); titleEl.blur(); }
        if (e.key === 'Escape') {
          titleEl.textContent = titleEl.dataset.original; // Revertir
          titleEl.blur();
        }
      }, { once: true });
    });
  }

  // ---- ELIMINAR CON CONFIRMACIÓN ----
  function handleDelete(taskId, cardElement) {
    // Mostrar confirmación inline en la tarjeta
    cardElement.classList.add('task-card--confirming');
    cardElement.innerHTML = `
      <div class="task-card__confirm">
        <p>¿Eliminar esta tarea?</p>
        <div class="task-card__confirm-actions">
          <button class="task-card__confirm-yes">Sí, eliminar</button>
          <button class="task-card__confirm-no">Cancelar</button>
        </div>
      </div>
    `;

    cardElement.querySelector('.task-card__confirm-yes').addEventListener('click', () => {
      store.deleteTask(taskId);
      // El store notifica → se re-renderiza toda la vista
    });

    cardElement.querySelector('.task-card__confirm-no').addEventListener('click', () => {
      // Simplemente re-renderizamos para restaurar la vista
      render();
    });
  }

  // ---- MONTAJE INICIAL ----
  render();

  // Suscribirse al store para re-renderizar cuando cambie
  const unsubscribe = store.subscribe(() => render());
  cleanups.push(unsubscribe);

  // Devolver función de limpieza total
  return () => {
    cleanups.forEach((fn) => fn());
    cleanups.length = 0;
  };
}

// Helper: montar el formulario de tarea
function mountTaskForm(container, { onCreate }) {
  container.innerHTML = TaskForm({});

  const form = container.querySelector('#task-form');
  const handler = (event) => {
    event.preventDefault();
    const fd = new FormData(form);
    const task = {
      title: fd.get('title').trim(),
      priority: fd.get('priority'),
      dueDate: fd.get('dueDate') || null,
      description: ''
    };
    if (task.title) {
      onCreate(task);
      form.reset();
      form.querySelector('[name="title"]').focus();
    }
  };
  form.addEventListener('submit', handler);
  return () => form.removeEventListener('submit', handler);
}

Decisiones de diseño importantes: (1) Usamos delegación de eventos en el contenedor de la lista en lugar de añadir listeners a cada tarjeta individual. Esto es más eficiente y no se rompe al re-renderizar. (2) La edición inline usa contentEditable en lugar de inputs — más natural pero requiere manejar bien los eventos blur/Enter/Escape. (3) La confirmación de eliminación reemplaza temporalmente el contenido de la tarjeta en lugar de usar window.confirm(), que es bloqueante y rompe la experiencia SPA. (4) Cada event listener guarda su función de limpieza en el array cleanups para poder desmontar la vista correctamente.

5 · Buenas prácticas

HazEvitaPor qué
Delegación de eventos en el contenedor padre Añadir event listeners a cada tarjeta individual Con 100 tareas, tendrías 100 listeners. Con delegación, solo 1. Además, al re-renderizar (innerHTML), los listeners individuales se pierden. La delegación sobrevive a los re-renders.
Guardar en localStorage en cada cambio de estado Guardar solo al cerrar la página (beforeunload) Si el navegador crashea o se queda sin batería, beforeunload puede no ejecutarse. Guardar en cada cambio asegura que los datos nunca se pierdan.
BEM-like naming para clases CSS Clases genéricas como .title, .button Las clases genéricas colisionan inevitablemente en proyectos grandes. .task-card__title es único y auto-documentado.
Confirmación inline antes de eliminar window.confirm() o eliminar sin confirmar window.confirm() es bloqueante y tiene una UX pobre (no se puede estilizar). Eliminar sin confirmar es peligroso. La confirmación inline es la mejor UX.
Escapar HTML siempre (escapeHTML) Interpolar datos de usuario directamente en template strings Nunca se sabe qué puede escribir un usuario. Un título como <img src=x onerror="alert(1)"> es un XSS si no escapas.

6 · Errores habituales

Error 1: Event listeners que se acumulan al re-renderizar

// ❌ MAL: cada vez que llamas a render(), añades un nuevo listener sin quitar el anterior
function render() {
  container.innerHTML = '<button id="btn">Click</button>';
  document.getElementById('btn').addEventListener('click', handler);
  // Tras 10 renders, tienes 10 listeners ejecutándose en el mismo botón
}

// ✅ BIEN: usar delegación de eventos en el contenedor (se añade una vez)
function render() {
  container.innerHTML = '<button class="js-click-me">Click</button>';
}
container.addEventListener('click', (e) => {
  if (e.target.closest('.js-click-me')) handler();
});
// Solo un listener para siempre, independientemente de cuántas veces renderices

Error 2: No limpiar localStorage (datos huérfanos)

// ❌ MAL: si cambias la estructura de datos, los datos viejos en localStorage rompen la app
// El usuario tiene guardado { tasks: [...] } pero tu nuevo código espera { tasks: [...], projects: [...] }

// ✅ BIEN: versionar el esquema y migrar si es necesario
const SCHEMA_VERSION = 2;
function loadState() {
  const raw = localStorage.getItem('taskflow-state');
  if (!raw) return { tasks: [], filter: 'all' };

  const data = JSON.parse(raw);
  // Migrar esquema v1 → v2 si es necesario
  if (data.version === 1) {
    data.projects = []; // Nuevo campo añadido en v2
    data.version = 2;
  }
  return data;
}

Error 3: contentEditable sin escape al guardar

// ❌ MAL: guardar el innerHTML de un contentEditable (permite inyección de HTML)
const newTitle = titleEl.innerHTML; // Si el usuario pega <script>alert(1)</script>...

// ✅ BIEN: guardar textContent (siempre es texto plano, seguro)
const newTitle = titleEl.textContent.trim();

8 · Reto

🎯 Sistema de "undo" para eliminación de tareas

Implementa un sistema de "deshacer" que, cuando el usuario elimina una tarea:

  1. No la borra inmediatamente — la marca como "pendiente de eliminar" durante 5 segundos.
  2. Muestra un toast/banner en la parte inferior: "Tarea eliminada. [Deshacer]".
  3. Si el usuario pulsa "Deshacer", la tarea se restaura.
  4. Si pasan 5 segundos sin deshacer, la tarea se elimina permanentemente.
  5. Si el usuario elimina otra tarea en ese intervalo, el timer se reinicia para la nueva (solo puede haber un "undo" activo a la vez).

Pista: Guarda la tarea eliminada en un campo state.pendingDelete del store junto con el setTimeout ID. No modifiques el array tasks hasta que el timer expire — simplemente oculta la tarea del renderizado filtrando por pendingDelete.

9 · Resumen

  • CRUD: Create (formulario → store.addTask), Read (store.getState → render), Update (contentEditable → store.updateTask), Delete (confirmación → store.deleteTask).
  • Flujo unidireccional: Evento → Store → Persistencia + Notificación → Re-render. Los datos solo fluyen en una dirección, lo que hace el código predecible.
  • localStorage: persistencia simple clave-valor. Serializar con JSON al guardar, deserializar al cargar. Guardar en cada cambio, no solo al cerrar.
  • Delegación de eventos: un solo listener en el contenedor padre en lugar de listeners individuales. Sobrevive a re-renders y es más eficiente.
  • Edición inline: contentEditable con eventos blur (guardar), Enter (guardar) y Escape (cancelar). Siempre leer textContent, no innerHTML.
  • BEM-like CSS: .block__element--modifier. Nombres únicos, auto-documentados, sin colisiones.
  • Limpieza al desmontar: cada vista guarda sus funciones de limpieza y las ejecuta al cambiar de vista. Previene memory leaks y comportamientos fantasma.

10 · Preguntas frecuentes

¿Por qué no usar innerHTML para todo el renderizado?

innerHTML es rápido para el renderizado inicial pero tiene dos problemas: (1) destruye todos los event listeners existentes al sobrescribir el HTML — por eso usamos delegación de eventos en el contenedor padre. (2) Es vulnerable a XSS si interpolas datos de usuario — por eso siempre escapamos con escapeHTML() o usamos textContent. Para aplicaciones más complejas, considera crear elementos con document.createElement() y appendChild() — es más verboso pero más seguro y eficiente para actualizaciones parciales.

¿Cuántas tareas puedo guardar en localStorage?

localStorage tiene un límite de ~5-10 MB por dominio. Una tarea serializada en JSON ocupa aproximadamente 200-500 bytes. Podrías guardar entre 10.000 y 50.000 tareas sin problemas. El cuello de botella real no es localStorage, sino el renderizado de miles de tarjetas en el DOM. Si tu app llega a manejar miles de tareas, necesitarías virtualización (renderizar solo las visibles), para lo cual existe Intersection Observer (lección 01 del módulo 8).

¿Puedo usar async/await con localStorage?

No. localStorage es síncrono y bloquea el hilo principal. Para la mayoría de aplicaciones esto no es problema porque las operaciones son instantáneas (leer/escribir unos KB). Si necesitas almacenamiento asíncrono (para no bloquear la UI con grandes volúmenes de datos), usa IndexedDB, que es completamente asíncrono y basado en promesas con la API idb o idb-keyval.
