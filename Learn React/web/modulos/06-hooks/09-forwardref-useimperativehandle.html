forwardRef y useImperativeHandle

Módulo 6 · Hooks en profundidad ⏱ 35 minutos

1 · Introducción

En la lección anterior viste useRef para acceder a elementos del DOM. Pero hay un problema: no puedes pasar un ref a un componente funcional de la misma forma que a un elemento JSX nativo. Si escribes <MiComponente ref={miRef} />, React lanza un warning porque ref no es una prop normal — es un atributo especial que React reserva.

forwardRef resuelve esto. Es una función que envuelve un componente funcional y le permite recibir un ref como segundo argumento, para pasarlo a un elemento DOM interno.

useImperativeHandle va un paso más allá: permite al componente hijo decidir qué expone a través del ref. En lugar de exponer todo el nodo DOM (lo que rompería el encapsulamiento), puedes exponer solo los métodos que quieras (focus, validate, reset…).

En React 19, forwardRef se ha simplificado: ya no es necesario envolver el componente; puedes pasar ref como una prop normal gracias a cómo funciona el nuevo compilador. Pero forwardRef sigue siendo compatible y useImperativeHandle sigue siendo la forma correcta de personalizar la interfaz imperativa.

2 · Teoría

El problema

En React, los componentes funcionales no reciben ref como prop. Si intentas pasarlo: 

// ❌ Esto no funciona en React < 19:
<MiInput ref={inputRef} />;   // Warning: Function components cannot be given refs

La razón es que React trata ref como un atributo especial, igual que key. No forma parte de props. Necesitas forwardRef para que el componente lo reciba explícitamente.

forwardRef

import { forwardRef } from "react";

const MiInput = forwardRef((props, ref) => {
//                           │      │
//                           │      └─ el ref que pasa el padre (segundo argumento)
//                           └─ props normales (primer argumento)
  return <input ref={ref} />;
});

forwardRef acepta una función de render. Esa función recibe dos argumentos: props (las props normales) y ref (el ref que pasa el padre). Tú decides dónde "enganchar" ese ref dentro del componente.

useImperativeHandle

import { forwardRef, useImperativeHandle, useRef } from "react";

const MiInput = forwardRef((props, ref) => {
  const inputRef = useRef(null);

  useImperativeHandle(ref, () => ({
// │                  │      └─ objeto con los métodos que se expondrán
// │                  └─ el ref que recibió el componente vía forwardRef
// └─ hook que personaliza la interfaz imperativa
    focus: () => inputRef.current.focus(),
    reset: () => { inputRef.current.value = ""; },
    isEmpty: () => inputRef.current.value === "",
  }));

  return <input ref={inputRef} />;
});

Sin useImperativeHandle, el padre accedería al elemento <input> directamente, pudiendo leer/escribir cualquier propiedad. Con useImperativeHandle, tú controlas exactamente qué métodos expones — el resto del DOM queda encapsulado.

React 19: ref como prop normal

React 19 introduce un nuevo compilador que permite pasar ref como una prop más. Ya no necesitas forwardRef para componentes funcionales: 

// React 19 — forwardRef ya no es obligatorio
function MiInput({ ref, ...props }) {
//                │
//                └─ ref llega como prop normal
  return <input ref={ref} />;
}

// En el padre:
<MiInput ref={inputRef} />;   // ✅ funciona sin forwardRef

Sin embargo, forwardRef sigue siendo válido y útil para mantener compatibilidad con versiones anteriores. useImperativeHandle se usa igual en ambos casos.

3 · Ejemplo mínimo

Un input personalizado que expone un método focus y clear al padre:

src/components/FocusableInput.jsx
import { forwardRef, useImperativeHandle, useRef } from "react";

const FocusableInput = forwardRef((props, ref) => {
  const inputRef = useRef(null);

  useImperativeHandle(ref, () => ({
    focus: () => inputRef.current.focus(),
    clear: () => { inputRef.current.value = ""; },
  }));

  return <input ref={inputRef} defaultValue={props.defaultValue} />;
});

export default FocusableInput;
src/App.jsx
import { useRef } from "react";
import FocusableInput from "./components/FocusableInput";

export default function App() {
  const inputRef = useRef(null);

  function handleFocus() {
    inputRef.current.focus();
  }

  function handleClear() {
    inputRef.current.clear();
  }

  return (
    <div>
      <FocusableInput ref={inputRef} defaultValue="Hola" />
      <button onClick={handleFocus}>Enfocar</button>
      <button onClick={handleClear}>Limpiar</button>
    </div>
  );
}

Línea por línea:

  1. forwardRef((props, ref) => ...) — el componente recibe ref como segundo argumento.
  2. useRef(null) — creamos un ref interno para apuntar al <input> real.
  3. useImperativeHandle(ref, createHandle) — personalizamos qué expone el ref del padre.
  4. focus: () => inputRef.current.focus() — el padre puede llamar inputRef.current.focus().
  5. clear: () => { inputRef.current.value = "" } — el padre puede limpiar el input.
  6. <FocusableInput ref={inputRef} /> — el padre pasa su ref al componente.
  7. inputRef.current.focus() — el padre llama al método expuesto. No puede acceder directamente al DOM.

4 · Ejemplo real

Formulario con validación imperativa

Un formulario de registro donde el padre puede validar todos los campos y enfocar el primer campo con error:

src/components/ValidatedInput.jsx
import { forwardRef, useImperativeHandle, useRef, useState } from "react";

const ValidatedInput = forwardRef(({ label, validator, ...props }, ref) => {
  const inputRef = useRef(null);
  const [error, setError] = useState(null);

  useImperativeHandle(ref, () => ({
    focus: () => inputRef.current.focus(),
    validate: () => {
      const value = inputRef.current.value;
      const msg = validator ? validator(value) : null;
      setError(msg);
      return msg === null;   // true si es válido
    },
    getValue: () => inputRef.current.value,
    reset: () => {
      inputRef.current.value = "";
      setError(null);
    },
  }));

  return (
    <div className="field">
      <label>{label}</label>
      <input ref={inputRef} {...props} />
      {error && <span className="error">{error}</span>}
    </div>
  );
});

export default ValidatedInput;
src/components/RegistrationForm.jsx
import { useRef } from "react";
import ValidatedInput from "./ValidatedInput";

export default function RegistrationForm() {
  const emailRef = useRef(null);
  const passwordRef = useRef(null);

  function handleSubmit(e) {
    e.preventDefault();

    // Validamos todos los campos usando los métodos expuestos
    const isEmailValid = emailRef.current.validate();
    const isPasswordValid = passwordRef.current.validate();

    if (!isEmailValid) {
      emailRef.current.focus();
      return;
    }
    if (!isPasswordValid) {
      passwordRef.current.focus();
      return;
    }

    const data = {
      email: emailRef.current.getValue(),
      password: passwordRef.current.getValue(),
    };
    console.log("Enviando:", data);
  }

  function handleReset() {
    emailRef.current.reset();
    passwordRef.current.reset();
  }

  return (
    <form onSubmit={handleSubmit}>
      <ValidatedInput
        ref={emailRef}
        label="Email"
        type="email"
        placeholder="usuario@ejemplo.com"
        validator={(v) =>
          !v.includes("@") ? "Email inválido" : null
        }
      />
      <ValidatedInput
        ref={passwordRef}
        label="Contraseña"
        type="password"
        validator={(v) =>
          v.length < 6 ? "Mínimo 6 caracteres" : null
        }
      />
      <button type="submit">Enviar</button>
      <button type="button" onClick={handleReset}>Limpiar</button>
    </form>
  );
}

Decisiones explicadas:

  • Encapsulamiento: el padre no puede tocar el DOM del input directamente. Solo usa focus(), validate(), getValue() y reset().
  • Validación dentro del hijo: cada ValidatedInput gestiona su propio estado de error. El padre solo dispara la validación.
  • Método validate: devuelve boolean para que el padre sepa si es válido sin tener que interpretar el mensaje de error.
  • Prop validator: el padre inyecta la lógica de validación como una función. El hijo la ejecuta y muestra el error.

Reproductor de vídeo con controles imperativos

Un componente VideoPlayer que expone play, pause y jumpTo:

src/components/VideoPlayer.jsx
import { forwardRef, useImperativeHandle, useRef, useState } from "react";

const VideoPlayer = forwardRef(({ src }, ref) => {
  const videoRef = useRef(null);
  const [isPlaying, setIsPlaying] = useState(false);

  useImperativeHandle(ref, () => ({
    play: () => {
      videoRef.current.play();
      setIsPlaying(true);
    },
    pause: () => {
      videoRef.current.pause();
      setIsPlaying(false);
    },
    toggle: () => {
      if (videoRef.current.paused) {
        videoRef.current.play();
        setIsPlaying(true);
      } else {
        videoRef.current.pause();
        setIsPlaying(false);
      }
    },
    jumpTo: (time) => {
      videoRef.current.currentTime = time;
    },
    getDuration: () => videoRef.current.duration,
    getCurrentTime: () => videoRef.current.currentTime,
  }));

  return (
    <div>
      <video ref={videoRef} src={src} style={{ width: "100%", maxWidth: 600 }} />
      <p>{isPlaying ? "▶ Reproduciendo" : "⏸ Pausado"}</p>
    </div>
  );
});

export default VideoPlayer;
src/components/Controls.jsx
import { useRef, useEffect } from "react";
import VideoPlayer from "./VideoPlayer";

export default function Controls() {
  const playerRef = useRef(null);

  return (
    <div>
      <VideoPlayer ref={playerRef} src="/video/intro.mp4" />
      <div className="controls">
        <button onClick={() => playerRef.current.toggle()}>
          Play / Pause
        </button>
        <button onClick={() => playerRef.current.jumpTo(0)}>
          Reiniciar
        </button>
        <button onClick={() => {
          const dur = playerRef.current.getDuration();
          playerRef.current.jumpTo(dur / 2);
        }}>
          Mitad
        </button>
      </div>
    </div>
  );
}

5 · Buenas prácticas

HazEvitaPor qué
Usar useImperativeHandle para exponer una API mínima Exponer el nodo DOM directamente (ref.current sin personalizar) Rompe el encapsulamiento. El padre podría modificar propiedades internas que deberían ser privadas.
Limitar el uso a: focus, scroll, animaciones, selección de texto, integración con librerías no-React Usar refs imperativos para controlar el flujo de datos El flujo de datos debe ser declarativo (props + estado). Lo imperativo es para cosas que React no puede abstraer.
Nombrar los métodos expuestos con verbos claros: focus(), validate(), reset() Métodos genéricos como doSomething(), handleStuff() La API imperativa debe ser auto-documentada. El padre debe entender qué hace cada método sin leer la implementación.
Documentar la API imperativa (JSDoc o comentarios) si el componente es compartido Asumir que otros desarrolladores saben qué métodos hay Los métodos expuestos no se ven en las props. Sin documentación, nadie sabe que existen.
En React 19, usa ref como prop normal sin forwardRef si trabajas solo con React 19+ Mezclar ambos estilos en el mismo proyecto sin consistencia Elige una convención y mantenla. Si el proyecto usa React 18 y 19, usa forwardRef para compatibilidad.

6 · Errores habituales

Error 1: Olvidar forwardRef al pasar un ref a un componente funcional

✘ Incorrecto 
function MiInput(props) {
  return <input />;
}

// En el padre:
<MiInput ref={inputRef} />;
// 💥 Warning: Function components cannot be given refs
✔ Correcto 
const MiInput = forwardRef((props, ref) => {
  return <input ref={ref} />;
});

Error 2: No usar el ref recibido en useImperativeHandle

✘ Incorrecto 
const MiInput = forwardRef((props, ref) => {
  const inputRef = useRef(null);

  useImperativeHandle(ref, () => ({
    focus: () => inputRef.current.focus(),
  }));

  // ❌ Olvidaste pasar ref al elemento DOM
  return <input />;
  // inputRef.current siempre será null → 💥 error en focus()
});
✔ Correcto 
const MiInput = forwardRef((props, ref) => {
  const inputRef = useRef(null);

  useImperativeHandle(ref, () => ({
    focus: () => inputRef.current.focus(),
  }));

  return <input ref={inputRef} />;   // ✅ conectar ref interno al DOM
});

Error 3: Olvidar el array de dependencias en useImperativeHandle

✘ Incorrecto 
useImperativeHandle(ref, () => ({
  focus: () => inputRef.current.focus(),
  logState: () => console.log(count),   // count puede estar obsoleto
}));
// Sin dependencias, la función se crea una sola vez y captura valores antiguos
✔ Correcto 
useImperativeHandle(ref, () => ({
  focus: () => inputRef.current.focus(),
  logState: () => console.log(count),
}), [count]);   // ✅ si count cambia, se recrea el objeto

Error 4: Exponer el DOM entero en lugar de una API controlada

✘ Incorrecto 
const MiInput = forwardRef((props, ref) => {
  const inputRef = useRef(null);

  // ❌ forwardRef ya pasa el ref al input directamente
  return <input ref={ref} />;
  // El padre tiene acceso completo al DOM:
  // inputRef.current.value = "hackeado";
  // inputRef.current.style.background = "red";
});
✔ Correcto 
const MiInput = forwardRef((props, ref) => {
  const inputRef = useRef(null);

  useImperativeHandle(ref, () => ({
    focus: () => inputRef.current.focus(),
    getValue: () => inputRef.current.value,
  }));

  return <input ref={inputRef} />;
  // El padre solo ve { focus, getValue }
});

7 · Ejercicio guiado

Crear un componente CounterWithRef que exponga métodos imperativos para controlar un contador desde el padre.

  1. Crea un archivo src/components/CounterWithRef.jsx.

  2. Usa forwardRef para que reciba un ref del padre.

  3. Dentro, usa useState para el valor del contador y useRef para el intervalo.

  4. Usa useImperativeHandle para exponer estos métodos:

    {
  increment: () => setCount((c) => c + 1),
  decrement: () => setCount((c) => c - 1),
  reset: () => setCount(0),
  startAuto: () => {
    // Inicia un setInterval que incrementa cada segundo
    // Guárdalo en intervalRef.current para poder limpiarlo
  },
  stopAuto: () => {
    // Limpia el intervalo con clearInterval
  },
}

  5. Renderiza el valor del contador y un mensaje si está en modo automático.

  6. En el padre (App.jsx), renderiza el CounterWithRef con un ref. Añade botones para cada método expuesto.

  7. Pruébalo: incrementa, decrementa, resetea, inicia auto y detén auto.

Solución del componente:

src/components/CounterWithRef.jsx
import { forwardRef, useImperativeHandle, useState, useRef } from "react";

const CounterWithRef = forwardRef((_, ref) => {
  const [count, setCount] = useState(0);
  const intervalRef = useRef(null);
  const [isAuto, setIsAuto] = useState(false);

  useImperativeHandle(ref, () => ({
    increment: () => setCount((c) => c + 1),
    decrement: () => setCount((c) => c - 1),
    reset: () => setCount(0),
    startAuto: () => {
      if (intervalRef.current) return;
      setIsAuto(true);
      intervalRef.current = setInterval(() => {
        setCount((c) => c + 1);
      }, 1000);
    },
    stopAuto: () => {
      if (intervalRef.current) {
        clearInterval(intervalRef.current);
        intervalRef.current = null;
        setIsAuto(false);
      }
    },
  }), []);

  return (
    <div className="counter">
      <h2>{count}</h2>
      {isAuto && <p>⏩ Modo automático</p>}
    </div>
  );
});

export default CounterWithRef;
src/App.jsx
import { useRef } from "react";
import CounterWithRef from "./components/CounterWithRef";

export default function App() {
  const counterRef = useRef(null);

  return (
    <div>
      <CounterWithRef ref={counterRef} />
      <div className="buttons">
        <button onClick={() => counterRef.current.increment()}>+1</button>
        <button onClick={() => counterRef.current.decrement()}>-1</button>
        <button onClick={() => counterRef.current.reset()}>Reset</button>
        <button onClick={() => counterRef.current.startAuto()}>Auto ▶</button>
        <button onClick={() => counterRef.current.stopAuto()}>Detener ⏹</button>
      </div>
    </div>
  );
}

9 · Resumen

  • forwardRef permite que un componente funcional reciba un ref del padre como segundo argumento de la función de render.
  • useImperativeHandle personaliza qué expone el ref al padre, encapsulando el DOM interno.
  • En React 19, forwardRef ya no es obligatorio: ref se puede pasar como prop normal. Pero sigue siendo compatible.
  • Usa useImperativeHandle(ref, createHandle, deps) con tres argumentos: el ref recibido, una función que devuelve el objeto de métodos, y un array de dependencias opcional.
  • Úsalo solo para casos imperativos que React no puede abstraer: focus, scroll, selección de texto, animaciones, integración con librerías no-React.
  • No abuses de la API imperativa. El flujo de datos debe ser declarativo (props + estado) siempre que sea posible.
  • Siempre conecta el ref interno (inputRef) al elemento DOM; si no, los métodos fallarán porque current será null.

10 · Preguntas frecuentes

¿forwardRef sigue siendo necesario en React 19?

No estrictamente. React 19 permite pasar ref como prop normal: function Input({ ref, ...props }). Pero forwardRef sigue funcionando y es útil para mantener compatibilidad con React 18 o cuando quieres ser explícito sobre que el componente acepta refs.

¿Puedo usar useImperativeHandle sin forwardRef?

No. useImperativeHandle necesita un ref para personalizarlo, y ese ref solo llega al componente a través de forwardRef (o, en React 19, a través de la prop ref). Sin un ref que personalizar, el hook no tiene sentido.

¿Cuándo debería preferir props declarativas sobre useImperativeHandle?

Siempre que puedas. Si algo se puede expresar con props y estado, hazlo. Por ejemplo, en lugar de exponer reset(), pasa una prop key que cambie cuando quieras resetear. En lugar de validate(), pasa isValidated como prop. Usa useImperativeHandle solo para lo que no tiene equivalente declarativo (focus, scroll a una posición, animaciones…).

¿Puedo exponer un ref a un componente que no es un elemento DOM (una clase, un mapa de Leaflet, etc.)?

Sí. useImperativeHandle puede exponer cualquier objeto. Por ejemplo, un componente que inicializa un mapa de Leaflet puede exponer { moveTo, zoomIn, addMarker } sin exponer el objeto L.Map completo.

¿Cómo afecta useImperativeHandle al rendimiento?

El hook se ejecuta en cada render. Si el objeto que devuelves se crea nuevo en cada render, los métodos que el padre haya guardado en variables apuntarán a la versión anterior. Usa el array de dependencias (tercer argumento) para controlar cuándo se recrea. Si no usas dependencias, se crea una sola vez (pero puede capturar closures obsoletos).

¿Puedo combinar forwardRef con React.memo?

Sí. Simplemente envuelve el resultado de forwardRef con React.memo: const Comp = React.memo(forwardRef((props, ref) => ...)); El orden importa: primero forwardRef, luego memo.
