Custom hooks

Módulo 6 · Hooks en profundidad ⏱ 35 minutos

1 · Introducción

Hasta ahora has usado hooks de React: useState, useEffect, useRef, useMemo, useCallback. Pero la verdadera magia de los hooks es que puedes crear los tuyos propios.

Un custom hook es simplemente una función JavaScript que:

  • Empieza por use (convención obligatoria: useLocalStorage, useFetch…).
  • Puede usar otros hooks dentro (useState, useEffect…).
  • Encapsula lógica reutilizable: estado, efectos, memorización…
  • Devuelve lo que necesites: un valor, un objeto, un array.

Los custom hooks son la herramienta más potente de React para reutilizar lógica entre componentes. No crean UI por sí mismos; extraen la lógica que hay detrás de la UI.

2 · Teoría

¿Por qué custom hooks?

Imagina que tienes este patrón repetido en 5 componentes:

// Componente A
const [data, setData] = useState(null);
const [loading, setLoading] = useState(true);
const [error, setError] = useState(null);

useEffect(() => {
  let cancelled = false;
  async function fetchData() {
    try {
      const res = await fetch("/api/a");
      const json = await res.json();
      if (!cancelled) { setData(json); setLoading(false); }
    } catch (err) {
      if (!cancelled) { setError(err.message); setLoading(false); }
    }
  }
  fetchData();
  return () => { cancelled = true; };
}, []);

// Componente B: EXACTAMENTE el mismo código, pero con "/api/b"
// Componente C: EXACTAMENTE el mismo código, pero con "/api/c"

Esto es un horror de duplicación. Con un custom hook, lo escribes UNA vez y lo reutilizas en todos los componentes: 

// hooks/useFetch.js
export function useFetch(url) {
  const [data, setData] = useState(null);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    let cancelled = false;
    setLoading(true);
    fetch(url)
      .then((res) => res.json())
      .then((json) => { if (!cancelled) setData(json); })
      .catch((err) => { if (!cancelled) setError(err.message); })
      .finally(() => { if (!cancelled) setLoading(false); });
    return () => { cancelled = true; };
  }, [url]);

  return { data, loading, error };
}

// Ahora en cualquier componente:
const { data, loading, error } = useFetch("/api/a");

Reglas de los custom hooks

  1. El nombre DEBE empezar por use: es una convención, pero el linter de React la exige. Sin el prefijo, React no puede verificar las reglas de los hooks.
  2. Siguen las reglas de los hooks: solo en el nivel superior, solo en componentes o en otros custom hooks.
  3. Cada llamada tiene su propio estado: si llamas a useFetch en dos componentes, cada uno tiene su propio data, loading, error. Son independientes.

Qué devolver

  • Un array: cuando el orden es importante (como useState: const [value, setValue] = useSomething()).
  • Un objeto: cuando tienes varios valores y quieres nombrarlos (const { data, loading } = useFetch()). Es lo más común.
  • Un valor único: si el hook solo devuelve una cosa.

Custom hooks famosos

  • useLocalStorage(key, initial): estado sincronizado con localStorage.
  • useDebounce(value, delay): retrasa un valor para búsquedas.
  • useFetch(url): carga datos de una API.
  • useMediaQuery(query): detecta si se cumple una media query CSS.
  • useOnClickOutside(ref, handler): detecta clics fuera de un elemento.
  • useInterval(callback, delay): setInterval como hook.

3 · Ejemplo mínimo

Un hook que cuenta los renders de un componente:

src/hooks/useRenderCount.js
import { useRef } from "react";

export function useRenderCount() {
  const countRef = useRef(0);
  countRef.current++;
  return countRef.current;
}
src/components/MyComponent.jsx
import { useRenderCount } from "../hooks/useRenderCount";

export default function MyComponent() {
  const renders = useRenderCount();
  return <p>Este componente se ha renderizado {renders} veces.</p>;
}

4 · Ejemplo real

useLocalStorage

Estado que persiste en localStorage automáticamente:

src/hooks/useLocalStorage.js
import { useState, useEffect } from "react";

export function useLocalStorage(key, initialValue) {
  // Leer el valor inicial de localStorage (solo la primera vez)
  const [value, setValue] = useState(() => {
    try {
      const item = localStorage.getItem(key);
      return item ? JSON.parse(item) : initialValue;
    } catch {
      return initialValue;
    }
  });

  // Sincronizar con localStorage cuando cambia el valor
  useEffect(() => {
    try {
      localStorage.setItem(key, JSON.stringify(value));
    } catch (err) {
      console.error("Error al guardar en localStorage:", err);
    }
  }, [key, value]);

  return [value, setValue];
}
Uso:
import { useLocalStorage } from "../hooks/useLocalStorage";

function ThemeToggle() {
  const [theme, setTheme] = useLocalStorage("theme", "dark");

  return (
    <button onClick={() => setTheme(theme === "dark" ? "light" : "dark")}>
      Tema actual: {theme}
    </button>
  );
}
// Al recargar la página, el tema se mantiene ✔

useDebounce

Retrasa un valor para evitar búsquedas en cada tecla:

src/hooks/useDebounce.js
import { useState, useEffect } from "react";

export function useDebounce(value, delay = 300) {
  const [debounced, setDebounced] = useState(value);

  useEffect(() => {
    const timer = setTimeout(() => setDebounced(value), delay);
    return () => clearTimeout(timer);   // limpieza: cancela el timeout anterior
  }, [value, delay]);

  return debounced;
}
Uso:
import { useDebounce } from "../hooks/useDebounce";

function Search() {
  const [query, setQuery] = useState("");
  const debouncedQuery = useDebounce(query, 500);   // espera 500ms

  useEffect(() => {
    if (debouncedQuery) {
      fetch(`/api/search?q=${debouncedQuery}`);   // solo se dispara 500ms después de dejar de escribir
    }
  }, [debouncedQuery]);

  return <input value={query} onChange={(e) => setQuery(e.target.value)} />;
}

6 · Errores habituales

Error 1: no empezar por use

✘ Incorrecto 
export function fetchData(url) {   // el linter no lo reconocerá como hook
  const [data, setData] = useState(null);   // 💥 error: hooks solo en componentes o hooks
  …
}
✔ Correcto 
export function useFetch(url) {   // empieza por "use"
  const [data, setData] = useState(null);   // ✔ válido
  …
}

Error 2: llamar hooks dentro de condiciones

export function useConfig(enabled) {
  if (!enabled) return null;   // 💥 return temprano antes de los hooks
  const [data] = useState(null);   // orden de hooks roto
}

Error 3: compartir estado entre instancias

let sharedCount = 0;   // ✘ variable fuera del hook: compartida por todas las instancias

export function useCounter() {
  return { count: sharedCount++, inc: () => sharedCount++ };
}
// Dos componentes que usen useCounter compartirían el mismo contador.

La solución: usar useState dentro del hook (cada instancia tiene su propio estado).

7 · Ejercicio guiado

Crea un hook useToggle(initial = false):

  1. Debe devolver [value, toggle, setValue].
  2. toggle invierte el valor: () => setValue(v => !v).
  3. setValue permite establecer un valor concreto.
  4. Úsalo para un componente de acordeón (varias secciones que se abren/cierran).
  5. Úsalo para un modal que se abre y cierra.

8 · Reto

🎯 useMediaQuery

Crea un hook useMediaQuery(query) que devuelva true si la media query CSS se cumple. Usa window.matchMedia y escucha el evento change para reaccionar. Úsalo para mostrar/ocultar un menú lateral en pantallas pequeñas (useMediaQuery("(max-width: 768px)")).

9 · Resumen

  • Un custom hook es una función que empieza por use y puede usar otros hooks.
  • Encapsula lógica reutilizable: estado, efectos, memorización.
  • Cada llamada tiene su propio estado independiente.
  • Devuelve objetos (lo más común) o arrays.
  • Sigue las reglas de los hooks: nivel superior, solo en componentes u otros hooks.
  • Patrones comunes: useLocalStorage, useDebounce, useFetch, useToggle.

10 · Preguntas frecuentes

¿Los custom hooks comparten estado entre componentes?
No. Cada llamada a un custom hook crea su propio estado independiente. Si dos componentes usan useLocalStorage("key"), cada uno tiene su propio useState, aunque ambos se sincronicen con la misma clave de localStorage.
¿Puedo usar custom hooks dentro de otros custom hooks?
Sí, es muy común. useFetch puede usar internamente useLocalStorage para cachear resultados.
¿Puedo exportar un custom hook como default?
Sí, pero la convención es nombrar exports: export function useFetch(). Facilita importar varios hooks del mismo archivo.
¿Cuándo crear un custom hook vs dejar la lógica en el componente?
Cuando la lógica se repite en 2+ componentes, o cuando quieres separar la lógica de la UI para hacer el componente más legible. Si solo se usa en un componente y es simple, déjalo ahí.
¿Puedo probar un custom hook sin un componente?
Sí, con renderHook de @testing-library/react. Lo veremos en el Módulo 12 (Testing).
