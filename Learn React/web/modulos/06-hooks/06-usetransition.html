useTransition

Módulo 6 · Hooks en profundidad ⏱ 35 minutos

1 · Introducción

Hasta ahora, cuando un usuario teclea en un input, React actualiza el estado inmediatamente y re-renderiza el componente. Si ese re-render es rápido, no hay problema. Pero ¿y si cada pulsación desencadena un filtrado pesado de miles de elementos? La UI se congela, el input va lento, la experiencia se vuelve frustrante.

El problema es que todas las actualizaciones de estado tienen la misma prioridad. Escribir en un input y filtrar una lista gigante compiten por el mismo hilo de JavaScript. React 18 introdujo concurrencia (no confundir con paralelismo) y con ella useTransition: un hook que permite marcar ciertas actualizaciones como no urgentes.

Con useTransition le dices a React: «esta actualización puede esperar; si llega otra más urgente (como el input), interrúmpeme y atiéndela primero». El resultado: un input que responde al instante aunque estés filtrando 10 000 elementos al mismo tiempo.

2 · Teoría

El problema del bloqueo del hilo principal

JavaScript tiene un solo hilo (browser main thread). Mientras React está renderizando (calculando el nuevo Virtual DOM y aplicando cambios al DOM real), no puede responder a eventos del usuario: clicks, tecleo, scroll… Todo se bloquea.

SIN useTransition (bloqueo): ────────────────────────── [tecleo]→[render pesado]→[pintar]→[tecleo]→[render pesado]→[pintar] ↑ el input no responde hasta que termina el render CON useTransition (concurrencia): ────────────────────────────────── [tecleo urgente]→[render del input]→[pintar]→[transición]→[pausar transición] ↓ (llega otro tecleo) [atender tecleo urgente] ↓ [reanudar transición]

La clave es que React puede interrumpir un render de baja prioridad para atender uno de alta prioridad. Esto es posible gracias al nuevo reconciliador concurrente (Fiber) introducido en React 18.

Anatomía de useTransition

const [isPending, startTransition] = useTransition();
  • isPending: booleano. true mientras la transición está en curso (React aún no ha terminado de renderizar).
  • startTransition: función. Envuelve la actualización de estado que quieres marcar como no urgente.

Cómo usar startTransition

startTransition(() => {
  setQuery(e.target.value);   // esta actualización es "transicional"
});

Dentro de startTransition solo deben ir actualizaciones de estado síncronas (llamadas a setters de useState). No puedes poner dentro código asíncrono directamente (aunque en React 19 hay mejoras al respecto).

Actualizaciones urgentes vs. no urgentes

TipoEjemplosCómo se marcan
Urgentes Escribir en un input, click, scroll, animaciones Llamadas directas a setState (sin startTransition)
No urgentes (transiciones) Filtrar listas, búsquedas, navegación, actualizar UI secundaria Envueltas en startTransition(() => setState(…))

React procesa primero todas las actualizaciones urgentes y pinta su resultado antes de retomar la transición. Si durante la transición llega una actualización urgente, React descarta el trabajo parcial de la transición y atiende la urgente.

React 19: { timeoutMs } y mejoras

En React 18, useTransition no aceptaba configuración adicional. En React 19 se introdujo un objeto de opciones: 

const [isPending, startTransition] = useTransition({
  timeoutMs: 3000   // tiempo máximo que React esperará antes de forzar la transición
});

timeoutMs define cuánto tiempo puede estar isPending como true antes de que React fuerce la transición como urgente y la pinte. Si no se especifica, React usa el valor por defecto (lo suficientemente grande como para esperar a que el hilo se desocupe).

📘 Nota sobre React 19

En React 19, startTransition también puede envolver código asíncrono (como async/await), manteniendo isPending como true hasta que la función termine. Esto es nuevo y lo exploraremos en el ejemplo real.

Comparación con setTimeout, debounce y throttle

Es tentador pensar que useTransition es lo mismo que estas técnicas, pero no lo es:

TécnicaCómo funcionaLimitación
setTimeout Retrasa la ejecución N ms Sigue bloqueando cuando se ejecuta; no es interrumpible
debounce Espera a que el usuario deje de escribir para ejecutar Retraso artificial; peor responsive inmediato
throttle Ejecuta como máximo cada N ms Pierde eventos intermedios; experiencia entrecortada
useTransition React interrumpe la transición si llega una actualización urgente Solo funciona dentro del ecosistema React (con setState)

La gran ventaja de useTransition es que no pierdes eventos intermedios y React decide cuándo interrumpir y reanudar automáticamente. Con debounce, el usuario nota el retraso. Con useTransition, el input responde inmediatamente y el filtrado llega "cuando pueda".

¿Cuándo usar useTransition?

  • Inputs que actualizan listas filtradas con muchos elementos.
  • Navegación entre pestañas o rutas donde la nueva vista tarda en renderizar.
  • Cualquier actualización de estado que no necesite reflejarse instantáneamente en la UI.

3 · Ejemplo mínimo

Un input de búsqueda que filtra una lista de nombres. Sin useTransition, el input se siente lento porque cada pulsación dispara el filtrado. Con useTransition, el input responde al instante.

src/components/SearchWithTransition.jsx
import { useState, useTransition } from "react";

const ITEMS = Array.from({ length: 5000 }, (_, i) =>
  `Elemento número ${i + 1}`
);

export default function SearchWithTransition() {
  // query: valor del input (URGENTE)
  const [query, setQuery] = useState("");
  // searchQuery: valor usado para filtrar (NO URGENTE)
  const [searchQuery, setSearchQuery] = useState("");

  const [isPending, startTransition] = useTransition();

  function handleChange(e) {
    const value = e.target.value;

    // Actualización urgente: el input debe responder al instante
    setQuery(value);

    // Actualización no urgente: filtrar puede esperar
    startTransition(() => {
      setSearchQuery(value);
    });
  }

  // Filtrado: solo se ejecuta cuando cambia searchQuery (no en cada tecleo)
  const filtered = ITEMS.filter((item) =>
    item.toLowerCase().includes(searchQuery.toLowerCase())
  );

  return (
    <div>
      <input
        type="text"
        value={query}
        onChange={handleChange}
        placeholder="Buscar elementos…"
      />
      {isPending && <p className="hint">Filtrando…</p>}
      <ul>
        {filtered.map((item) => (
          <li key={item}>{item}</li>
        ))}
      </ul>
    </div>
  );
}

Línea por línea:

  1. ITEMS — array de 5000 elementos simulados.
  2. query — estado vinculado al input. Se actualiza fuera de startTransition, por tanto es urgente.
  3. searchQuery — estado usado para filtrar. Se actualiza dentro de startTransition, es transicional.
  4. handleChange — separa las dos actualizaciones: la urgente (input) y la no urgente (filtro).
  5. isPending — muestra un indicador "Filtrando…" mientras React procesa la transición.

Resultado: escribes rápidamente y el input va fluido. El filtrado se actualiza "detrás de escena" y React lo interrumpe si sigues escribiendo.

4 · Ejemplo real

Buscador de productos con 10 000 elementos, usando además timeoutMs de React 19 y un indicador de carga más elaborado.

src/components/ProductSearch.jsx
import { useState, useTransition, useMemo } from "react";

// Simula 10.000 productos
function generateProducts() {
  const categories = [
    "Electrónica", "Ropa", "Hogar", "Deportes", "Libros",
  ];

  return Array.from({ length: 10000 }, (_, i) => ({
    id: i + 1,
    name: `Producto ${i + 1}`,
    category: categories[i % categories.length],
    price: +(Math.random() * 500 + 10).toFixed(2),
    inStock: Math.random() > 0.3,
  }));
}

const PRODUCTS = generateProducts();

export default function ProductSearch() {
  const [query, setQuery] = useState("");
  const [searchTerm, setSearchTerm] = useState("");
  const [category, setCategory] = useState("Todas");

  // useTransition con timeoutMs (React 19)
  const [isPending, startTransition] = useTransition({
    timeoutMs: 2000,
  });

  function handleQueryChange(e) {
    const value = e.target.value;

    // Urgente: actualizar el input
    setQuery(value);

    // No urgente: actualizar el término de búsqueda
    startTransition(() => {
      setSearchTerm(value);
    });
  }

  function handleCategoryChange(newCategory) {
    setCategory(newCategory);

    startTransition(() => {
      setQuery("");
      setSearchTerm("");
    });
  }

  // Filtrado memorizado: solo se recalcula cuando cambian searchTerm o category
  const filtered = useMemo(() => {
    return PRODUCTS.filter((product) => {
      const matchesQuery = product.name
        .toLowerCase()
        .includes(searchTerm.toLowerCase());
      const matchesCategory =
        category === "Todas" || product.category === category;
      return matchesQuery && matchesCategory;
    });
  }, [searchTerm, category]);

  return (
    <div className="product-search">
      <div className="search-controls">
        <input
          type="text"
          value={query}
          onChange={handleQueryChange}
          placeholder="Buscar productos…"
          className="search-input"
          autoFocus
        />
        <select
          value={category}
          onChange={(e) => handleCategoryChange(e.target.value)}
          className="search-select"
        >
          <option value="Todas">Todas las categorías</option>
          <option value="Electrónica">Electrónica</option>
          <option value="Ropa">Ropa</option>
          <option value="Hogar">Hogar</option>
          <option value="Deportes">Deportes</option>
          <option value="Libros">Libros</option>
        </select>
      </div>

      {isPending && (
        <div className="search-indicator">
          Actualizando resultados…
        </div>
      )}

      <p className="result-count">
        {filtered.length} producto{filtered.length !== 1 ? "s" : ""} encontrado
        {filtered.length !== 1 ? "s" : ""}
      </p>

      <ul className="product-list">
        {filtered.slice(0, 50).map((product) => (
          <li key={product.id} className="product-item">
            <span className="product-name">{product.name}</span>
            <span className="product-category">{product.category}</span>
            <span className="product-price">${product.price}</span>
            <span
              className={`product-stock ${
                product.inStock ? "in-stock" : "out-of-stock"
              }`}
            >
              {product.inStock ? "En stock" : "Agotado"}
            </span>
          </li>
        ))}
      </ul>
    </div>
  );
}

Decisiones explicadas:

  • timeoutMs: 2000: si la transición tarda más de 2 segundos, React la fuerza como urgente.
  • useMemo para el filtrado: solo se recalcula cuando searchTerm o category cambian (los estados transicionales), no en cada tecleo.
  • Dos estados separados: query (input inmediato) y searchTerm (filtro transicional). Sin esta separación, la transición no tendría sentido.
  • Indicador visual: isPending muestra un mensaje mientras la transición se procesa. El input nunca se bloquea.
  • filtered.slice(0, 50): mostramos solo 50 resultados para no saturar el DOM, aunque el filtrado se hace sobre los 10 000.

5 · Buenas prácticas

HazEvitaPor qué
Separar el estado urgente del transicional Usar el mismo estado dentro y fuera de startTransition Si actualizas el mismo estado dentro y fuera de la transición, se solapan y pierdes el control de prioridades.
Mostrar feedback visual con isPending Dejar al usuario sin indicación de que algo está pasando isPending es la señal perfecta para mostrar un spinner o mensaje sutil sin bloquear.
Combinar con useMemo para cálculos pesados Hacer el cálculo pesado directamente en el render useMemo evita recalcular en cada render; useTransition evita bloquear; juntos son imbatibles.
Usar useTransition para navegación entre pestañas Bloquear la UI mientras carga la nueva pestaña La pestaña activa debe seguir respondiendo mientras la nueva se renderiza en segundo plano.
Establecer un timeoutMs razonable Usar valores extremadamente altos o no especificarlo Un timeout muy alto puede dejar la UI desactualizada demasiado tiempo.

6 · Errores habituales

Error 1: poner código asíncrono directamente en startTransition

✘ Incorrecto 
startTransition(async () => {
  const data = await fetch("/api/search");
  setResults(data);
  // 💥 En React 18: error. En React 19: permitido, pero puede no comportarse como esperas
});
✔ Correcto (React 18) 
startTransition(() => {
  setLoading(true);
});
const data = await fetch("/api/search");
startTransition(() => {
  setResults(data);
  setLoading(false);
});

Error 2: poner demasiadas cosas dentro de startTransition

✘ Incorrecto 
function handleChange(e) {
  startTransition(() => {
    setQuery(e.target.value);         // 💥 query debería ser urgente (input)
    setFilteredItems(filterItems(e.target.value));
  });
}
// El input se siente lento porque el setQuery está dentro de la transición
✔ Correcto 
function handleChange(e) {
  setQuery(e.target.value);                      // urgente
  startTransition(() => {
    setFilteredItems(filterItems(e.target.value)); // no urgente
  });
}

Error 3: usar useTransition sin separar el estado

✘ Incorrecto 
const [query, setQuery] = useState("");

function handleChange(e) {
  // Solo hay un estado: no puedes marcar unas actualizaciones urgentes y otras no
  startTransition(() => {
    setQuery(e.target.value);
  });
}
// El input va lento igual: no hay separación
✔ Correcto 
const [query, setQuery] = useState("");           // urgente
const [searchQuery, setSearchQuery] = useState(""); // transicional

function handleChange(e) {
  setQuery(e.target.value);
  startTransition(() => {
    setSearchQuery(e.target.value);
  });
}

Error 4: olvidar que useTransition no funciona con efectos

✘ Incorrecto 
useEffect(() => {
  startTransition(() => {
    setData(newData);
  });
}, [newData]);
// 💥 startTransition dentro de useEffect no tiene el mismo efecto:
    la prioridad se define en el evento, no en el efecto
✔ Correcto 
useEffect(() => {
  setData(newData);   // el efecto ya ocurre después del render, no bloquea el evento
}, [newData]);
// Si newData proviene de un evento, aplica la transición en el evento, no en el efecto

9 · Resumen

  • useTransition devuelve [isPending, startTransition].
  • startTransition marca actualizaciones de estado como no urgentes.
  • React puede interrumpir una transición para atender actualizaciones urgentes (input, click, scroll).
  • Necesitas dos estados separados: uno para el valor urgente (input) y otro para el transicional (filtro).
  • isPending es true mientras la transición está en curso; úsalo para feedback visual.
  • React 19 añade { timeoutMs } para limitar cuánto tiempo puede estar pendiente una transición.
  • useTransition NO es lo mismo que setTimeout, debounce ni throttle — es una primitiva de concurrencia de React.
  • Combínalo con useMemo para cálculos pesados y obtendrás UIs fluidas incluso con miles de elementos.

10 · Preguntas frecuentes

¿useTransition funciona si el componente no es concurrente?

Sí, pero necesitas que el árbol de React esté renderizado con el nuevo root concurrente (createRoot), que es el predeterminado desde React 18. Si usas ReactDOM.render (legacy), useTransition no tendrá efecto. Con Vite + React 19, usas createRoot por defecto.

¿Puedo usar varias transiciones a la vez?

Sí, puedes llamar startTransition múltiples veces. React las encola y las procesa según la prioridad. Cada llamada puede envolver actualizaciones de estado diferentes.

¿Cuál es la diferencia entre useTransition y useDeferredValue?

useTransition te da control explícito sobre qué actualizaciones son transicionales (envuelves el setter). useDeferredValue recibe un valor y devuelve una versión "retrasada" del mismo, aplicando la transición automáticamente. La regla: usa useTransition cuando quieras marcar la fuente del cambio; usa useDeferredValue cuando recibas el valor de una prop y no puedas controlar su actualización.

¿useTransition evita re-renders?

No directamente. Lo que evita es que un re-render bloquee el hilo principal. Los re-renders siguen ocurriendo, pero React los puede interrumpir. Si además quieres evitar re-renders innecesarios, combínalo con useMemo y React.memo.

¿Funciona useTransition con Redux o Zustand?

Depende. Si el estado global se actualiza a través de setters de useState/useReducer dentro del componente, sí. Las actualizaciones externas (Redux dispatch, Zustand set) no ocurren dentro del ciclo de render de React, por lo que startTransition no las controla. En esos casos, usa useDeferredValue.

¿Debo usar useTransition para todas las búsquedas?

No. useTransition tiene sentido cuando el filtrado es pesado (miles de elementos en el cliente) o cuando la renderización de la nueva UI es costosa. Para búsquedas ligeras (menos de 100 elementos), la sobrecarga del hook no merece la pena. Mide antes de optimizar.

¿Qué pasa si nunca llega la actualización urgente?

React eventualmente procesa la transición cuando el hilo se desocupa. Si especificaste un timeoutMs, React forzará la transición como urgente al superar ese límite. Si no, la transición se completa en el siguiente frame disponible.
