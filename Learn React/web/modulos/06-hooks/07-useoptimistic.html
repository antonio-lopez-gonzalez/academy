useOptimistic

Módulo 6 · Hooks en profundidad ⏱ 30 minutos

1 · Introducción

Hemos visto que las operaciones asíncronas (enviar un formulario, publicar un comentario, enviar un mensaje en un chat) tienen tres estados: pendiente → éxito → error. La UX típica muestra un spinner mientras esperas la respuesta del servidor. El usuario ve la pantalla congelada, no sabe si pasó algo, y la experiencia se siente lenta.

useOptimistic cambia esto completamente. Es un hook de React 19 que te permite mostrar el resultado esperado inmediatamente, antes de que el servidor confirme. Si la operación real falla, React revierte automáticamente al estado anterior. El usuario ve una interfaz instantánea y —cuando algo sale mal— se entera sin que los datos queden corruptos.

Llega con React 19 junto con las Form Actions (vistas en el Módulo 5) y useActionState. Es la pieza clave para construir UIs que se sientan rápidas incluso cuando el servidor tarda en responder.

2 · Teoría

Anatomía de useOptimistic

const [optimisticState, setOptimistic] = useOptimistic(
  actualState,      // ← el estado real (fuente de verdad)
  (state, payload) => {
    // ← función que combina el estado actual con el valor optimista
    return { ...state, ...payload };
  }
);
  • Primer argumento (actualState): el estado real, normalmente viene de useState o de una prop externa.
  • Segundo argumento (función reductor): recibe el state actual y el payload que pasaste a setOptimistic. Devuelve el nuevo estado optimista.
  • Retorna un array: [optimisticState, setOptimistic].
⚠ useOptimistic NO almacena estado por sí mismo

useOptimistic no tiene estado propio. El actualState es la fuente de verdad. Cuando llamas a setOptimistic, React sobrescribe temporalmente el valor renderizado con el resultado de la función reductor. Cuando el estado real cambia (p. ej. al recibir la respuesta del servidor), el valor optimista se descarta y se muestra el real.

Cómo funciona internamente

FLUJO DE useOptimistic ───────────────────── 1. Usuario envía datos (ej. mensaje de chat) │ ▼ 2. Llamas a setOptimistic(nuevoMensaje) │ ▼ 3. React ejecuta la función reductor: (actualState, payload) => nuevoEstadoOptimista │ ▼ 4. La UI se actualiza INMEDIATAMENTE (el usuario ve su mensaje en el chat) │ ▼ 5. Se envía la petición real al servidor │ ├── ✅ ÉXITO → actualizas el estado real │ useOptimistic lo detecta y usa el real │ └── ❌ ERROR → React revierte automáticamente al estado real (el anterior)

Diferencia clave con setState normal

Con useState, si llamas a setMessages([...messages, msg]), el cambio es inmediato pero definitivo. Si luego el servidor falla, tienes que deshacerlo manualmente. Con useOptimistic, la reversión es automática: React simplemente ignora el estado optimista y vuelve al real.

useOptimistic + Form Actions

useOptimistic se usa a menudo dentro de una Form Action (React 19). La acción envía los datos, setOptimistic muestra el resultado inmediato, y cuando la acción termina actualizas el estado real.

4 · Ejemplo real

Un chat donde los mensajes aparecen al instante, sin esperar al servidor. Este es el caso de uso más común y donde useOptimistic realmente brilla:

src/components/ChatRoom.jsx
import { useState, useOptimistic, useRef } from "react";

const API_URL = "https://api.ejemplo.com/messages";

export default function ChatRoom() {
  const [messages, setMessages] = useState([]);
  const formRef = useRef(null);

  const [optimisticMessages, addOptimisticMessage] = useOptimistic(
    messages,                                                                // estado real
    (state, newMsg) => [...state, { ...newMsg, pending: true }]              // marcar como pendiente
  );

  async function sendMessage(formData) {
    const text = formData.get("message");
    if (!text.trim()) return;

    const tempId = Date.now();
    const optimisticMsg = { id: tempId, text, user: "Yo", pending: true };

    // 1. Mostrar el mensaje inmediatamente
    addOptimisticMessage(optimisticMsg);
    formRef.current?.reset();

    // 2. Enviar al servidor real
    try {
      const res = await fetch(API_URL, {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify({ text, user: "Yo" }),
      });

      if (!res.ok) throw new Error("Error al enviar mensaje");

      const serverMsg = await res.json();

      // 3. Actualizar con el mensaje real (con id del servidor, timestamp real, etc.)
      setMessages((prev) => [
        ...prev,
        { id: serverMsg.id, text: serverMsg.text, user: "Yo", pending: false, timestamp: serverMsg.timestamp },
      ]);
    } catch {
      // ❌ Falla → useOptimistic revierte automáticamente
      alert("No se pudo enviar el mensaje. Inténtalo de nuevo.");
    }
  }

Decisiones explicadas:

  • Mensaje con pending: true: marcamos el mensaje optimista como pendiente para mostrar un spinner. Cuando el servidor confirma, el mensaje real no tiene la bandera.
  • tempId = Date.now(): mientras el mensaje no está en el servidor, usamos un id temporal. Al recibir la respuesta, lo reemplazamos por el id real del servidor.
  • formRef.current?.reset(): limpiamos el input inmediatamente después del envío optimista, antes de la respuesta del servidor.
  • setMessages((prev) => [...prev, serverMsg]): añadimos el mensaje real al estado real. useOptimistic detecta el cambio y descarta el mensaje optimista.
💡 ¿Y si el servidor confirma con estructura diferente?

El mensaje optimista puede tener campos incompletos (sin id real, sin timestamp). Cuando el servidor responde con la estructura completa, actualizas el estado real con esos datos. El mensaje optimista se descarta y se renderiza el real.

5 · Buenas prácticas

HazEvitaPor qué
Siempre tener un try/catch en la operación real Asumir que la operación siempre funciona Si la promesa falla y no hay catch, el estado optimista se queda colgado. React no revierte automáticamente si no detecta un cambio en el estado real.
Marcar elementos optimistas con pending: true Mostrar elementos sin indicador visual de carga El usuario necesita saber que algo está en proceso. Un ligero cambio de opacidad o un spinner mejora la UX.
Usar un id temporal (Date.now(), crypto.randomUUID()) Usar índices del array como key React necesita keys estables para reconciliar la lista. Si usas key={index}, al reemplazar el mensaje optimista por el real se pierde la animación y el foco.
Integrar con Form Actions de React 19 Llamar a setOptimistic fuera de un evento o acción El patrón natural es: acción del formulario → setOptimistic → fetch → actualizar estado real.
Reemplazar el mensaje optimista por el real en setMessages Acumular sin limpiar el optimista Si no eliminas el mensaje optimista al recibir el real, tendrás duplicados. El estado real debe contener solo datos confirmados.

6 · Errores habituales

Error 1: olvidar el try/catch y dejar el estado optimista colgado

✘ Incorrecto 
function handleSubmit(formData) {
  const title = formData.get("title");

  setOptimisticTitle(title);               // muestra inmediato
  updateTitleOnServer(title);              // 💥 si falla, nadie lo captura
  // El estado optimista se queda para siempre
}
✔ Correcto 
async function handleSubmit(formData) {
  const title = formData.get("title");

  setOptimisticTitle(title);
  try {
    const result = await updateTitleOnServer(title);
    setTitle(result);                       // ✔ actualiza el real → se descarta el optimista
  } catch {
    // ❌ useOptimistic revierte automáticamente porque title no cambió
    alert("Error al actualizar");
  }
}

Error 2: usar useOptimistic sin actualState reactivo

✘ Incorrecto 
const [optimistic, setOptimistic] = useOptimistic(
  [],   // estado inicial vacío
  (state, item) => [...state, item]
);
// 💥 Nunca actualizas el estado real. No hay reversión posible.
✔ Correcto 
const [items, setItems] = useState([]);                    // estado real
const [optimisticItems, setOptimisticItems] = useOptimistic(
  items,                                                     // ← fuente de verdad
  (state, item) => [...state, item]
);

Error 3: mutar el estado en la función reductor

✘ Incorrecto 
const [opt, setOpt] = useOptimistic(items, (state, item) => {
  state.push(item);              // 💥 mutación directa del estado
  return state;
});
✔ Correcto 
const [opt, setOpt] = useOptimistic(items, (state, item) => {
  return [...state, item];       // ✔ nuevo array, inmutable
});

Error 4: usar useOptimistic para lógica síncrona (sin servidor)

✘ Incorrecto 
const [count, setCount] = useState(0);
const [optCount, setOptCount] = useOptimistic(count, (s, v) => v);
// 💥 No hay operación asíncrona. useOptimistic es innecesario aquí.
✔ Correcto 
// Para lógica síncrona, usa useState directamente
const [count, setCount] = useState(0);

7 · Ejercicio guiado

Crear un componente de "Me gusta" (like) con actualización optimista:

  1. Crea un estado const [liked, setLiked] = useState(false); y otro const [count, setCount] = useState(0); que representan el estado real del like y el contador.

  2. Añade useOptimistic con el estado real { liked, count }. La función reductor debe devolver { liked: !state.liked, count: state.liked ? state.count - 1 : state.count + 1 }.

  3. Renderiza la UI con el estado optimista. Muestra un botón con el texto "Like ({optimistic.count})" y el estilo cambiado si optimistic.liked es true.

  4. Crea una función handleLike que llame primero a setOptimistic y luego simule una llamada al servidor con setTimeout de 1.5 segundos.

  5. Si el servidor "responde" correctamente, actualiza el estado real con setLiked y setCount.

  6. Simula un fallo aleatorio (30% de probabilidad). Si falla, muestra un mensaje de error. Observa cómo useOptimistic revierte automáticamente.

  7. Prueba a hacer clic rápido varias veces. El estado optimista siempre refleja la última acción, pero el real solo se actualiza si el servidor confirma.

9 · Resumen

  • useOptimistic muestra el resultado esperado inmediatamente mientras esperas la respuesta del servidor.
  • El primer argumento es el estado real (fuente de verdad). useOptimistic no almacena estado propio.
  • El segundo argumento es una función reductor que combina el estado actual con el valor optimista.
  • Si la operación real falla, React revierte automáticamente al estado real. No necesitas deshacer manualmente.
  • Siempre debes tener un try/catch en la operación real y actualizar el estado real solo en éxito.
  • Es un hook de React 19, pensado para usarse con Form Actions y operaciones asíncronas.
  • Funciona con arrays, objetos y cualquier tipo de dato en el estado. Solo debes respetar la inmutabilidad en el reductor.
  • Marcar elementos optimistas como pending mejora la experiencia de usuario.

10 · Preguntas frecuentes

¿useOptimistic reemplaza a useState?

No. useOptimistic funciona junto con useState. El useState sigue siendo la fuente de verdad; useOptimistic es solo una capa de presentación que se sobrepone temporalmente.

¿Qué pasa si hago varias llamadas a setOptimistic antes de que se resuelva la primera?

Cada llamada a setOptimistic ejecuta la función reductor con el valor actual del estado optimista (no el real). El último valor optimista es el que se renderiza. Cuando las operaciones reales se resuelven, el estado real se actualiza y React descarta todo el estado optimista acumulado.

¿useOptimistic necesita un servidor para funcionar?

Conceptualmente sí, porque el hook está diseñado para el patrón "mostrar antes de confirmar en servidor". Pero puedes simular el servidor con setTimeout para practicar. El hook en sí solo compara el estado real con el optimista; no sabe si hay servidor o no.

¿Puedo usar useOptimistic en React 18?

No, useOptimistic es exclusivo de React 19. Si usas React 18, tendrías que implementar el patrón manualmente con useState y revertir en el catch, lo cual es más verboso y propenso a errores.

¿Cuál es la diferencia con useActionState?

useActionState (también de React 19) maneja el estado de una acción asíncrona (datos, error, pendiente). useOptimistic es específico para la actualización optimista de la UI. Se complementan: useActionState para el estado de la acción y useOptimistic para la UI instantánea.

¿Puedo tener múltiples useOptimistic en el mismo componente?

Sí, cada llamada a useOptimistic maneja una parte diferente del estado. Por ejemplo, uno para los mensajes y otro para el estado de "escribiendo…". Cada uno es independiente.
