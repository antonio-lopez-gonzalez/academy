use() — el nuevo hook para Promesas y Context

Módulo 6 · Hooks en profundidad ⏱ 40 minutos

1 · Introducción

Hasta React 18, leer el valor de una Promise requería useEffect + fetch + estados loading/error/data. Y leer un Context solo podía hacerse con useContext, que tenía una limitación importante: no podía usarse dentro de condicionales o bucles.

React 19 introduce use(), un hook revolucionario que rompe las reglas tradicionales de los hooks. Puedes usarlo dentro de if, for, o return temprano. Y, lo más importante, use(promise) se integra de forma nativa con Suspense para manejar la carga de datos asíncronos de manera declarativa.

Qué problema resuelve: elimina la necesidad de useEffect para la mayoría de las lecturas de datos, simplifica el acceso a Context (permitiéndolo en condicionales) y allana el camino para los Server Components, donde las promesas se pasan del servidor al cliente y se resuelven con use().

Cuándo se usa: siempre que necesites leer una Promise directamente (datos de una API, datos de Server Components) o acceder a un Context en situaciones donde useContext no es válido (condicionales, bucles, early returns).

2 · Teoría

Anatomía de use()

use() recibe un único argumento que puede ser de dos tipos: 

const value = use(resource);
// resource puede ser:
//   1. Una Promise → use() se "suspende" hasta que se resuelva
//   2. Un Context  → devuelve el valor actual del Context (como useContext)
  • Con Promise: React suspende el render del componente hasta que la Promise se resuelva. Mientras tanto, se muestra el fallback del <Suspense> más cercano.
  • Con Context: equivale a useContext(Context), pero sin la restricción de estar al inicio del componente.

¿Por qué existe use()?

Históricamente, cargar datos asíncronos en React requería este patrón: 

const [data, setData] = useState(null);
const [loading, setLoading] = useState(true);

useEffect(() => {
  fetch("/api/data")
    .then(r => r.json())
    .then(d => { setData(d); setLoading(false); });
}, []);

if (loading) return <p>Cargando…</p>;
return <pre>{JSON.stringify(data)}</pre>;

Este patrón tiene problemas: necesitas gestionar tres estados manualmente, lidiar con carreras de condiciones (race conditions) y el fetching ocurre después del render, no durante.

Con use(promise), el fetching ocurre en el render. React lo soporta de forma nativa: si la Promise no se ha resuelto, "suspende" el render y muestra el fallback. Cuando la Promise se resuelve, React reanuda el render con el valor.

use() no es un Hook tradicional

Esta es la gran diferencia: use() no sigue las Rules of Hooks. Los hooks clásicos (useState, useEffect, etc.) deben llamarse siempre en el mismo orden, sin condiciones, al inicio del componente. use() puede llamarse:

  • Dentro de if / else
  • Dentro de bucles for o while
  • Después de un return temprano
  • En cualquier orden dentro del componente

Esto lo hace mucho más flexible. Internamente, React identifica las llamadas a use() por el valor que reciben, no por la posición en el código.

Diagrama: flujo de use(promise) con Suspense

use(promise) + SUSPENSE – FLUJO ──────────────────────────────────────────── 1. Componente se renderiza 2. Encuentra use(promise) 3. ¿Promise resuelta? │ ├── NO → React lanza (throw) la Promise │ └─ Suspense la captura │ └─ Muestra fallback (cargando) │ └─ Cuando la Promise se resuelve │ └─ React re-intenta el render │ └─ use() devuelve el valor │ └── SÍ → use() devuelve el valor └─ Render normal del componente

Integración con Server Components

En React 19, los Server Components pueden enviar Promesas al cliente. El servidor empieza a resolver la Promise y pasa el objeto Promise al componente cliente. Este llama a use(promise) para leer el valor. Mientras la Promise no se resuelva, el cliente muestra el fallback de Suspense. Es una forma elegante de hacer streaming de datos del servidor al cliente sin necesidad de fetch del lado del cliente.

3 · Ejemplo mínimo

Leer datos de una API con use() + Suspense:

import { use } from "react";

const API = "https://jsonplaceholder.typicode.com/users/1";

// Función que devuelve una Promise (el fetch)
function fetchUser() {
  return fetch(API).then((res) => {
    if (!res.ok) throw new Error("Error al cargar usuario");
    return res.json();
  });
}

Línea por línea:

  1. import { use } from "react" — importamos el nuevo hook.
  2. fetchUser() — función que devuelve una Promise (el fetch a la API).
  3. const user = use(fetchUser()) — llamamos a use() con la Promise. Si no está resuelta, React suspende el render.
  4. <Suspense fallback={…}> — mientras la Promise no se resuelva, se muestra "Cargando usuario…".
  5. Cuando la Promise se resuelve, React re-renderiza UserData y use() devuelve el objeto user.
⚠ Sin Suspense, use() lanza un error

Si usas use(promise) sin envolver el componente en <Suspense>, React lanzará un error. Suspense es obligatorio para capturar la suspensión y mostrar el fallback.

Decisiones explicadas:

  • use(fetchUser(userId)): la Promise se crea y se pasa a use(). Si userId cambia, se crea una nueva Promise y use() la detecta automáticamente.
  • use(ThemeContext) vs useContext: es equivalente en funcionalidad, pero use() funciona aquí aunque esté después de la llamada a use(fetchUser). Con useContext, violarías las Rules of Hooks.
  • Suspense anidado: el perfil y los posts tienen su propio Suspense. Así, los posts pueden cargarse de forma independiente sin bloquear el perfil.
  • Early return con if (!userId): funciona porque use() no tiene la restricción de estar antes del primer return.

5 · Buenas prácticas

HazEvitaPor qué
Envolver siempre el componente con <Suspense> Usar use(promise) sin Suspense Sin Suspense, React no puede mostrar un fallback mientras la Promise se resuelve y lanzará un error.
Usar Error Boundaries para capturar errores de las Promesas Ignorar el manejo de errores Si la Promise se rechaza, React lanza el error. Necesitas un Error Boundary para capturarlo y mostrar una UI de error.
Usar use(Context) como alternativa moderna a useContext Seguir usando useContext en código nuevo (es válido pero use() es más flexible) use() funciona en condicionales y bucles; useContext no. Además, unifica la sintaxis para Promesas y Context.
Pasar Promesas desde Server Components a Client Components Hacer fetch duplicado en cliente y servidor use() permite que el servidor empiece a resolver la Promise y el cliente la consuma sin fetch adicional.
Usar Suspense anidado para cargas independientes Envolver todo en un único Suspense Suspense anidado permite que partes de la UI se muestren tan pronto como estén listas, mejorando la experiencia percibida.

6 · Errores habituales

Error 1: usar use() sin Suspense

✘ Incorrecto 
import { use } from "react";

export default function User() {
  const user = use(fetchUser(1));
  return <h1>{user.name}</h1>;
}
// 💥 Error: use() lanzó la Promise pero no hay Suspense que la capture
✔ Correcto 
import { use, Suspense } from "react";

function User() {
  const user = use(fetchUser(1));
  return <h1>{user.name}</h1>;
}

export default function App() {
  return (
    <Suspense fallback={<p>Cargando…</p>}>
      <User />
    </Suspense>
  );
}

Error 2: mutar la Promise antes de pasarla a use()

✘ Incorrecto 
const promise = fetchUser(1);
promise.then(console.log);   // 💥 la Promise ya tiene un .then adjunto
const user = use(promise);   // puede que ya esté resuelta o no
✔ Correcto 
const user = use(fetchUser(1));
// La Promise se pasa a use() directamente, sin adjuntarle .then

Error 3: no manejar errores con Error Boundary

✘ Incorrecto 
function User() {
  const user = use(fetchUser(999));   // 404 — Promise rechazada
  return <h1>{user.name}</h1>;
}
// 💥 Sin Error Boundary, la app se rompe
✔ Correcto 
class ErrorBoundary extends React.Component {
  state = { error: null };
  static getDerivedStateFromError(error) { return { error }; }
  render() {
    return this.state.error
      ? <p>Error: {this.state.error.message}</p>
      : this.props.children;
  }
}

function App() {
  return (
    <ErrorBoundary>
      <Suspense fallback={<p>Cargando…</p>}>
        <User />
      </Suspense>
    </ErrorBoundary>
  );
}

Error 4: asumir que use() acepta async functions

✘ Incorrecto 
const data = use(async () => {
  const res = await fetch("/api/data");
  return res.json();
});
// 💥 use() no acepta funciones. Solo acepta Promises o Context.
✔ Correcto 
const data = use(fetch("/api/data").then(r => r.json()));
// La función async se invoca ANTES, y se pasa la Promise resultante

9 · Resumen

  • use(resource) es un nuevo hook de React 19 que acepta Promesas o Context.
  • Con Promesas, se integra con Suspense: suspende el render hasta que la Promise se resuelva y muestra un fallback.
  • Rompe las Rules of Hooks: puede usarse dentro de if, for, return temprano, etc.
  • Como alternativa a useContext: use(Context) es equivalente pero más flexible.
  • Obligatorio: Suspense para Promesas, ErrorBoundary para errores.
  • Es la base para el consumo de Promesas desde Server Components en React 19.
  • Elimina la necesidad de gestionar manualmente estados loading/error/data con useEffect para lecturas simples de datos.

10 · Preguntas frecuentes

¿use() reemplaza por completo a useEffect + fetch?

No completamente. use(promise) es ideal para cargas de datos que ocurren al renderizar y que se benefician de Suspense. Pero useEffect sigue siendo necesario para: efectos secundarios que no son de carga de datos (suscripciones, temporizadores, manipulación directa del DOM), cargas condicionales basadas en interacción del usuario, o cuando necesitas control granular sobre cuándo y cómo se ejecuta la carga.

¿Puedo usar use() varias veces en el mismo componente?

Sí, sin restricciones. Cada use() es independiente. React gestiona cada Promise o Context por separado. Puedes tener múltiples use(promise) y use(Context) en el mismo componente, en cualquier orden.

¿Qué pasa si llamo a use() con una Promise que ya se resolvió?

React devuelve el valor directamente, sin suspender. Es seguro llamar a use() con una Promise resuelta o incluso con un valor que no es Promise (React lo trata como si fuera una Promise ya resuelta). Esto es útil cuando el dato ya está disponible (por ejemplo, desde caché).

¿use(Context) es mejor que useContext?

use(Context) es funcionalmente equivalente a useContext(Context) con una ventaja importante: no está sujeto a las Rules of Hooks. Puedes usarlo en condicionales y bucles. La recomendación de React 19 es empezar a usar use() para Context en código nuevo, pero useContext sigue siendo válido y no está deprecado.

¿Cómo manejo el caso de "refetch" (recargar datos)?

Para recargar, necesitas cambiar la referencia de la Promise. La forma más sencilla es usar un estado que fuerce la recreación de la Promise: 

const [key, setKey] = useState(0);
const data = use(fetchData(key));   // key cambia → nueva Promise → refetch

Al cambiar key, se crea una nueva Promise y use() detecta el cambio, se suspende de nuevo y muestra el fallback.

¿Puedo usar use() en Server Components?

En Server Components no es necesario: los Server Components pueden usar async/await directamente. use() está diseñado para Client Components que reciben Promesas desde Server Components. El patrón típico es: Server Component prepara los datos, pasa la Promise al Client Component, y el Client Component llama a use(promise).

¿use() funciona con React Query o SWR?

use() es una primitiva de React, no un sustituto de librerías de fetching. React Query y SWR siguen siendo recomendados para aplicaciones que necesitan caché, refetch automático, stale-while-revalidate, etc. De hecho, estas librerías ya están explorando cómo integrarse con use() y Suspense para ofrecer lo mejor de ambos mundos.
