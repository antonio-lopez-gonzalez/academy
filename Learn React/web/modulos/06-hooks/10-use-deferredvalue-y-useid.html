useDeferredValue y useId

Módulo 6 · Hooks en profundidad ⏱ 35 minutos

1 · Introducción

En la lección de useTransition viste cómo marcar actualizaciones como "no urgentes" para que React pueda pausarlas y mantener la UI fluida. En esta lección verás dos hooks hermanos que resuelven problemas muy específicos:

  • useDeferredValue — retrasa un valor (no una actualización) para que la UI que depende de él se re-renderice de forma diferida. Es el compañero ideal cuando no controlas la fuente del valor, por ejemplo un input controlado con el estado en el padre.
  • useId — genera identificadores únicos estables para conectar <label>, accesibilidad y atributos que necesitan IDs, sin colisiones y con hidratación correcta en SSR.

¿Qué problema resuelve useDeferredValue? Escribir en un buscador que filtra miles de elementos es costoso. Cada tecla dispara un render. Sin nada, la UI "se atasca". useDeferredValue separa la velocidad de la escritura (urgente) del coste del filtrado (diferido).

¿Qué problema resuelve useId? Los IDs tipo "name" se repiten, los aleatorios (Math.random()) rompen el SSR, y las librerías contadores pueden colisionar. useId genera IDs únicos por componente.

2 · Teoría

useDeferredValue: la firma

import { useDeferredValue } from "react";

const deferredValue = useDeferredValue(value, initialValue?);
  • value — el valor que quieres diferir (normalmente el estado de un input o una prop que cambia con frecuencia).
  • initialValue — React 19. Valor que se usa en el primer render, antes de que el valor diferido esté disponible. Evita renders "vacíos" o costosos al montar.
  • deferredValue — una copia del valor que React retrasa. En el primer render coincide con value; después puede ir "por detrás".

¿Cómo funciona internamente? Durante un render, React re-renderiza el componente con el valor diferido a baja prioridad. Mientras el valor diferido no esté listo, el componente se re-renderiza primero con el valor antiguo y después, cuando la prioridad lo permite, con el nuevo. Es como useTransition, pero en lugar de diferir una actualización, difiere un valor que viene de fuera.

FLUJO DE useDeferredValue ──────────────────────── value (cada tecla) ─── urgente ──► render inmediato del input │ ▼ useDeferredValue(value) ──► deferredValue (baja prioridad) │ ▼ render diferido de la lista filtrada

useId: la firma

import { useId } from "react";

const id = useId();

useId devuelve un string único y estable para el componente actual, por ejemplo ":r1:". No acepta argumentos.

¿Cómo funciona internamente? React genera un identificador jerárquico basado en la posición del componente en el árbol de Fiber. Como la posición es determinista, el mismo árbol en servidor y cliente produce los mismos IDs, lo que garantiza una hidratación correcta. Los IDs no deben usarse como key en listas (no son para rendimiento, son para accesibilidad).

3 · Ejemplo mínimo

src/components/SearchList.jsx
import { useDeferredValue, useState, useMemo } from "react";

const allItems = Array.from({ length: 20000 }, (_, i) => `Item ${i}`);

export default function SearchList() {
  const [query, setQuery] = useState("");
  const deferredQuery = useDeferredValue(query);

  const filtered = useMemo(() => {
    return allItems.filter((item) => item.includes(deferredQuery));
  }, [deferredQuery]);

  return (
    <>
      <input
        value={query}
        onChange={(e) => setQuery(e.target.value)}
        placeholder="Buscar…"
      />
      <ul>
        {filtered.map((item) => (
          <li key={item}>{item}</li>
        ))}
      </ul>
    </>
  );
}

Línea por línea:

  1. const [query, setQuery] = useState(""): el estado "rápido" que actualiza el input en cada tecla.
  2. const deferredQuery = useDeferredValue(query): una copia diferida del valor. El input re-renderiza al instante; la lista espera.
  3. useMemo(..., [deferredQuery]): el filtrado costoso solo se recalcula cuando cambia el valor diferido, no en cada tecla.
  4. filtered.map(...): la lista se renderiza con el valor diferido, manteniendo la UI fluida.

4 · Ejemplo real

Un panel de usuarios con búsqueda y un selector de acceso accesible usando useId para el htmlFor del label:

src/components/UserDirectory.jsx
import { useDeferredValue, useId, useState, useMemo } from "react";

const users = [
  { id: 1, name: "Ana García", role: "admin" },
  { id: 2, name: "Luis Pérez", role: "editor" },
  { id: 3, name: "María López", role: "viewer" },
  { id: 4, name: "Carlos Ruiz", role: "admin" },
];

export default function UserDirectory() {
  const [search, setSearch] = useState("");
  const deferredSearch = useDeferredValue(search);
  const searchId = useId();
  const roleId = useId();

  const filtered = useMemo(() => {
    const q = deferredSearch.toLowerCase();
    return users.filter((u) => u.name.toLowerCase().includes(q));
  }, [deferredSearch]);

  return (
    <section>
      <h2>Directorio de usuarios</h2>

      <div>
        <label htmlFor={searchId}>Buscar por nombre</label>
        <input
          id={searchId}
          value={search}
          onChange={(e) => setSearch(e.target.value)}
          placeholder="Escribe…"
        />
      </div>

      <label htmlFor={roleId}>Filtrar por rol</label>
      <select id={roleId}>
        <option value="">Todos</option>
        <option value="admin">Admin</option>
        <option value="editor">Editor</option>
      </select>

      <ul>
        {filtered.map((user) => (
          <li key={user.id}>
            {user.name} — <strong>{user.role}</strong>
          </li>
        ))}
      </ul>
    </section>
  );
}

Decisiones explicadas:

  • useId() para htmlFor: cada label apunta a su input/select con un ID único, sin riesgo de colisión si el componente se usa varias veces.
  • useDeferredValue: la búsqueda se siente instantánea; el filtrado de la lista se difiere y no bloquea la escritura.
  • useMemo con la dependencia diferida: evita recalcular el filtro en cada render.

5 · Buenas prácticas

HazEvitaPor qué
Usar useDeferredValue con listas grandes y búsqueda Usarlo en actualizaciones baratas Solo aporta cuando el render diferido es más caro que el coste de retrasarlo.
Combinar con useMemo en el cálculo diferido Recalcular el filtro en cada render sin memo El filtrado costoso se ejecuta solo cuando cambia el valor diferido.
Usar useId para htmlFor, aria-labelledby, atributos Usar Math.random(), contadores globales o IDs hardcodeados useId es estable entre renders y entre servidor/cliente, evitando bugs de hidratación y colisiones.
Prefijar los IDs con texto legible Usar el ID crudo directamente en CSS o selectores Los IDs de React son opacos (:r1:). Si necesitas un ancla con nombre, construye {`${id}-search`}.

6 · Errores habituales

Error 1: usar useId para las keys de una lista

✘ Incorrecto 
const id = useId();
{items.map((item) => <li key={`${id}-${item.id}`}>{item.name}</li>)}   // 💥 no
✔ Correcto 
// Las keys deben ser estables y únicas por ítem, no derivadas de un solo id:
{items.map((item) => <li key={item.id}>{item.name}</li>)}   // ✅

Error 2: usar useDeferredValue para "adelantar" trabajo urgente

✘ Incorrecto 
// El input debe reaccionar ya; diferir el estado del input lo entorpece:
const deferred = useDeferredValue(search);
setSearch(deferred);   // 💥 actualiza el input con el valor diferido
✔ Correcto 
// Diferimos SOLO el uso costoso del valor, nunca el estado del input:
const deferred = useDeferredValue(search);
const results = useMemo(() => filter(users, deferred), [deferred]);   // ✅

Error 3: no usar useMemo con el valor diferido

✘ Incorrecto 
const deferred = useDeferredValue(search);
const filtered = allItems.filter((i) => i.includes(deferred));   // 💥 se recalcula en cada render
✔ Correcto 
const deferred = useDeferredValue(search);
const filtered = useMemo(() => allItems.filter((i) => i.includes(deferred)), [deferred]);   // ✅

8 · Reto

🎯 Autocomplete con teclado y accesibilidad

Mejora el buscador para convertirlo en un autocomplete accesible:

  1. useDeferredValue: la lista de sugerencias se filtra de forma diferida.
  2. useId: genera los IDs para el input y el role="listbox" de sugerencias.
  3. aria-activedescendant: resalta la sugerencia activa con flechas del teclado.
  4. Indicador de "en espera": muestra un pequeño estado visual cuando deferred !== actual.
  5. Bonus: usa React.useDeferredValue con un initialValue para no renderizar una lista vacía en el primer render.

9 · Resumen

  • useDeferredValue retrasa un valor para que el trabajo costoso que depende de él se haga a baja prioridad, sin bloquear la escritura del usuario.
  • Es el equivalente a useTransition cuando el valor llega "desde fuera" (una prop o un estado del padre) y no controlas la actualización.
  • Se combina con useMemo para que el cálculo diferido no se ejecute en cada render.
  • useId genera IDs únicos y estables para accesibilidad, sin colisiones y con hidratación correcta.
  • useId no es para keys de listas ni para estilos.

10 · Preguntas frecuentes

¿Qué diferencia hay entre useTransition y useDeferredValue?

useTransition envuelve una actualización de estado que tú disparas (te da isPending). useDeferredValue difiere un valor que puede venir de fuera y no te da isPending (usas deferred !== actual). Si puedes elegir cómo actualizar el estado, useTransition; si solo recibes el valor, useDeferredValue.

¿useDeferredValue siempre retrasa el valor?

No. Si el render diferido es rápido (o el dispositivo no está ocupado), React lo procesa enseguida. El retraso solo se nota cuando hay trabajo caro que bloquearía la interacción. Es un mecanismo de "baja prioridad", no de "espera fija".

¿Puedo usar useId en Server Components?

useId es un hook, así que no se puede usar en Server Components. Tiene sentido en Client Components, donde garantiza que el ID generado en el servidor (durante el prerender) coincida con el del cliente.

¿Qué hace el parámetro initialValue de useDeferredValue en React 19?

Evita que el primer render use el valor real (potencialmente costoso de procesar). Con useDeferredValue(value, initialValue), el primer render muestra initialValue y el valor diferido llega justo después. Ideal para evitar un render "vacío" al montar.
