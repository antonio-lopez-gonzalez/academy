useActionState

Módulo 5 · Formularios ⏱ 40 minutos

1 · Introducción

En las lecciones anteriores viste dos piezas nuevas de React 19 para formularios: action en el <form> (Form Actions) y useFormStatus para leer el estado de envío desde un componente hijo. Pero queda una pregunta importante: ¿qué pasa con el resultado de la action?

Cuando envías un formulario, normalmente quieres saber si el envío funcionó, si el servidor devolvió errores de validación, y si todavía está en marcha. Sin ayuda de React, eso implica varios estados manuales (data, error, isPending) que se repiten en cada formulario.

useActionState es el hook de React 19 que resuelve esto: recibe tu action, el estado inicial y te devuelve el estado resultante, la action envuelta (lista para pasar a action o a formAction) y un booleano isPending. Es el «motor» de gestión de estado para Actions.

¿Qué problema resuelve? Elimina el boilerplate de estados manuales alrededor de cualquier mutación asíncrona (no solo formularios): resultado, error y pendiente quedan gestionados por React.

¿Cuándo se usa? Con Form Actions para mostrar errores del servidor y estados de éxito, con Server Actions (proyecto final) y en cualquier operación asíncrona que quieras exponer como una acción con estado.

2 · Teoría

La firma del hook

import { useActionState } from "react";

const [state, formAction, isPending] = useActionState(fn, initialState, permalink?);

Desglose de cada parte:

  • fn — la action. Es una función que recibe (previousState, payload) y devuelve el nuevo estado (o una Promise que resuelve al nuevo estado).
  • initialState — el estado que se usa en el primer render. Típicamente { error: "", success: false }.
  • permalink (opcional) — un string que se añade a la URL. Habilita la mejora progresiva en Server Components (si el JS aún no ha cargado, el formulario se envía de forma nativa).
  • state — el estado actual: lo que devolvió la action la última vez (o initialState si aún no se ha ejecutado).
  • formAction — la action envuelta. Pásala a la prop action del <form> o a formAction de un botón. No la llames directamente desde un handler.
  • isPending — booleano. true mientras la action se está ejecutando.

¿Cómo funciona internamente?

useActionState ejecuta tu action dentro de una Transition (el mismo mecanismo que startTransition). Eso significa que React marca el estado como pendiente, ejecuta la action en segundo plano y, cuando termina, hace un único commit con el resultado. Si la action lanza un error, React lo propaga a un Error Boundary cercano (puedes también devolver el error como parte del estado, que es el patrón recomendado para validaciones de formulario).

FLUJO DE useActionState ──────────────────────── Usuario pulsa "Enviar" │ ▼ form action={formAction} ← la action envuelta │ ▼ React inicia una Transition │ ├── isPending = true → la UI puede deshabilitar el botón │ ▼ fn(previousState, formData) │ ├── devuelve { error } o { success } │ ▼ React hace commit del estado │ ├── isPending = false ▼ La UI re-renderiza con state y muestra el resultado

useActionState vs useFormStatus

useActionStateuseFormStatus
Se usa en el mismo componente que define la action. Se usa en un componente hijo dentro del <form>.
Devuelve estado, action y isPending. Devuelve pending, data, method y action.
Conecta la action con el estado de resultado. Sirve para feedback visual (spinner) en componentes de UI reutilizables.

Nota sobre el nombre

En las versiones canary de React 19 este hook se llamó useFormState y se importaba de react-dom. En la versión estable pasó a llamarse useActionState y se importa de react. Si ves tutoriales que usan useFormState, es código antiguo: usa useActionState.

3 · Ejemplo mínimo

src/components/RenameForm.jsx
import { useActionState } from "react";

async function rename(previousState, formData) {
  const name = formData.get("name");
  if (!name.trim()) {
    return { error: "El nombre no puede estar vacío" };
  }
  // Simulamos una llamada al servidor
  await new Promise((resolve) => setTimeout(resolve, 1000));
  return { name, error: "" };
}

export default function RenameForm() {
  const [state, formAction, isPending] = useActionState(rename, {
    name: "",
    error: "",
  });

  return (
    <form action={formAction}>
      <input name="name" defaultValue={state.name} />
      {state.error && <span className="error">{state.error}</span>}
      <button type="submit" disabled={isPending}>
        {isPending ? "Renombrando…" : "Renombrar"}
      </button>
    </form>
  );
}

Línea por línea:

  1. rename(previousState, formData): la action recibe primero el estado anterior y después el FormData. Devuelve el nuevo estado.
  2. useActionState(rename, {...}): conecta la action con su estado inicial.
  3. formAction en <form action>: pasamos la action envuelta, no la original.
  4. state.error: se renderiza el error que devolvió la action.
  5. isPending: deshabilita el botón mientras la action se ejecuta.

4 · Ejemplo real

Un formulario de registro con dos campos, validación del servidor simulada y mensajes de éxito/error gestionados íntegramente por useActionState:

src/components/RegisterForm.jsx
import { useActionState } from "react";

async function register(previousState, formData) {
  const email = formData.get("email");
  const password = formData.get("password");

  // Validación del "servidor"
  if (!email.includes("@")) {
    return { ...previousState, error: "Email inválido", success: false };
  }
  if (password.length < 6) {
    return { ...previousState, error: "La contraseña debe tener al menos 6 caracteres", success: false };
  }

  await new Promise((resolve) => setTimeout(resolve, 1500));
  return { error: "", success: true };
}

export default function RegisterForm() {
  const [state, formAction, isPending] = useActionState(register, {
    error: "",
    success: false,
  });

  return (
    <form action={formAction} className="register-form">
      <div>
        <label htmlFor="email">Email</label>
        <input id="email" name="email" type="email" required />
      </div>
      <div>
        <label htmlFor="password">Contraseña</label>
        <input id="password" name="password" type="password" required />
      </div>

      {state.error && <p role="alert" className="error">{state.error}</p>}
      {state.success && <p role="status" className="success">¡Registro completado!</p>}

      <button type="submit" disabled={isPending}>
        {isPending ? "Registrando…" : "Registrarse"}
      </button>
    </form>
  );
}

Decisiones explicadas:

  • { ...previousState, error }: nunca reemplazamos el estado entero; esparcimos el anterior para no perder campos.
  • role="alert" / role="status": accesibilidad. Un lector de pantalla anuncia errores y confirmaciones.
  • isPending: evita envíos duplicados deshabilitando el botón.
  • Errores como estado, no como excepción: la action devuelve el error en el estado. Es el patrón recomendado para formularios.

5 · Buenas prácticas

HazEvitaPor qué
Devolver errores como parte del estado Lanzar excepciones para errores de validación El estado viaja directo a la UI. Lanzar una excepción solo se usa para fallos graves (que van al Error Boundary).
Usar { ...previousState, ... } al devolver estado Devolver solo el campo que cambió Evitas sobrescribir campos previos y el estado se mantiene completo.
Pasar formAction a action / formAction Llamar a la action original directamente Solo la action envuelta ejecuta la lógica de estado y transición.
Usar isPending para deshabilitar la UI Gestionar isSubmitting a mano isPending se actualiza automáticamente y cubre todos los estados (éxito, error, pendiente).
Usar defaultValue en los inputs Usar value sin onChange Con Form Actions los inputs son no controlados. defaultValue es la forma correcta de inicializarlos; value sin handler los congela.

6 · Errores habituales

Error 1: seguir importando useFormState

✘ Incorrecto 
import { useFormState } from "react-dom";   // 💥 no existe en React 19 estable
✔ Correcto 
import { useActionState } from "react";   // ✅ nombre estable

Error 2: llamar a la action original en lugar de formAction

✘ Incorrecto 
const [state, formAction] = useActionState(handleSubmit, initial);

return (
  <form action={handleSubmit}>   {/* 💥 usas la original: no hay estado */}
  </form>
);
✔ Correcto 
const [state, formAction] = useActionState(handleSubmit, initial);

return (
  <form action={formAction}>   {/* ✅ usas la envuelta */}
  </form>
);

Error 3: devolver un objeto que sobreescribe el estado anterior

✘ Incorrecto 
async function handleSubmit(previousState, formData) {
  return { error: "Email inválido" };   // 💥 pierdes el resto del estado
}
✔ Correcto 
async function handleSubmit(previousState, formData) {
  return { ...previousState, error: "Email inválido" };   // ✅ conservas lo demás
}

Error 4: no usar la action dentro de una Transition o un form

✘ Incorrecto 
const [state, formAction] = useActionState(save, initial);

function onClick() {
  formAction();   // 💥 solo debe invocarse desde action/formAction de un form o un startTransition
}
✔ Correcto 
<form action={formAction}>   {/* ✅ React la envuelve en una Transition automáticamente */}
  <button type="submit">Guardar</button>
</form>

9 · Resumen

  • useActionState es el hook de React 19 que conecta una action con su estado resultante: [state, formAction, isPending].
  • La action recibe (previousState, payload) y devuelve el nuevo estado, que React guarda.
  • La action envuelta (formAction) se pasa a la prop action del form (o a formAction de un botón); no se llama manualmente.
  • isPending elimina la necesidad de estados manuales de «enviando» y evita envíos duplicados.
  • Reemplaza al antiguo useFormState (nombre canary). Siempre importa desde "react".
  • Se complementa con useFormStatus (estado del form visto desde un hijo) y useOptimistic (UI instantánea).

10 · Preguntas frecuentes

¿Qué diferencia hay entre useActionState y useState?

useState te da un valor y un setter que actualizas cuando quieras. useActionState enlaza ese ciclo al resultado de una acción asíncrona: ejecuta la action, guarda el resultado en el estado y expone isPending. Para formularios con acciones, es menos código y más correcto.

¿Puedo usar useActionState sin un formulario?

Sí. useActionState no exige un <form>; puedes usarlo con cualquier action, por ejemplo pasando formAction a la prop formAction de un botón. La diferencia es que el formulario te da la mejora progresiva (envío nativo sin JS) y la gestión del FormData.

¿Qué ocurre si la action lanza una excepción?

La excepción se propaga a un Error Boundary cercano. Para errores que esperas (validaciones), devuélvelos como parte del estado en lugar de lanzarlos. Así la UI puede mostrarlos sin romperse.

¿Necesito useFormStatus si uso useActionState?

No necesariamente. isPending de useActionState cubre el estado de envío en el mismo componente. useFormStatus es útil cuando el botón (o el feedback) vive en un componente hijo, como en bibliotecas de componentes.

¿Cómo reinicio el formulario tras el éxito?

Si los inputs son no controlados, React resetea el formulario automáticamente tras completar la action. Para controlarlo manualmente, usa el método reset() de un ref del form, o el key del formulario basado en el estado.
