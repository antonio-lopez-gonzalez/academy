Validaciones

Módulo 5 · Formularios ⏱ 40 minutos

1 · Introducción

Un formulario sin validación es una puerta abierta a datos basura: emails mal formados, contraseñas débiles, campos obligatorios vacíos… La validación es el filtro que asegura que solo datos correctos lleguen a tu backend.

En React, la validación se hace de forma reactiva: el estado cambia, la UI se actualiza, los errores aparecen o desaparecen al instante. No hay que "lanzar" la validación manualmente; es una función del estado, como el filtrado de la lección anterior.

En esta lección veremos cómo validar campos, mostrar errores en tiempo real y deshabilitar el botón de envío hasta que todo sea correcto.

2 · Teoría

Validación = función del estado

El principio es el mismo que con el buscador: si puedes calcular algo a partir del estado, no lo guardes en estado. Los errores de validación son un ejemplo perfecto: se calculan a partir de los valores de los campos. 

const [email, setEmail] = useState("");

// El error es un VALOR DERIVADO: se calcula en cada render
const emailError = email.includes("@") ? "" : "Email inválido";

No necesitas un useState para los errores. Cada vez que email cambia, React re-renderiza y emailError se recalcula. Siempre sincronizado.

Dos momentos para validar

  1. En cada cambio (onChange): validación en tiempo real. El usuario ve el error mientras escribe (o después de la primera edición). Es la más reactiva.
  2. Al enviar (onSubmit): validación final. Solo se comprueba cuando el usuario pulsa "Enviar". Menos intrusiva, pero el usuario puede llenar todo el formulario y ver todos los errores de golpe.

La combinación ideal: validación en tiempo real después de que el usuario haya tocado el campo (para no mostrar errores antes de que empiece a escribir) y validación final al enviar.

El estado "touched"

Para saber si el usuario ya ha interactuado con un campo, necesitamos un estado adicional: touched. Es un objeto (o un Set) que registra qué campos han sido "tocados". 

const [touched, setTouched] = useState({});

// Al perder el foco del campo:
<input
  onBlur={() => setTouched((prev) => ({ ...prev, email: true }))}
/>

// Solo mostramos el error si el campo ha sido tocado:
{touched.email && emailError && <span className="error">{emailError}</span>}
  • onBlur: se dispara cuando el campo pierde el foco. Es el momento ideal para marcar el campo como "tocado".
  • touched.email: si es true, el usuario ya ha estado en el campo. Podemos mostrar el error.
  • Ventaja: no mostramos errores antes de que el usuario empiece a escribir. Menos ruido visual.

Validación de múltiples campos

Cuando tienes varios campos, puedes calcular todos los errores en un objeto derivado: 

const errors = {
  email: email.includes("@") ? "" : "Email inválido",
  password: password.length >= 8 ? "" : "Mínimo 8 caracteres",
  age: age >= 18 ? "" : "Debes ser mayor de 18",
};

// ¿Hay algún error?
const hasErrors = Object.values(errors).some((err) => err !== "");
  • Un objeto con un error por campo: si el error está vacío, el campo es válido.
  • hasErrors: derivado de errors. Es true si hay al menos un error.
  • Deshabilitar el botón: <button disabled={hasErrors}>Enviar</button>.

Expresiones regulares para validación

Para validaciones complejas (emails, URLs, teléfonos), las expresiones regulares son tu herramienta. No entraremos en profundidad (es un tema de JavaScript, no de React), pero aquí tienes las más comunes: 

// Email (simplificado, pero funciona para el 99% de los casos)
const emailRegex = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;
const isValidEmail = emailRegex.test(email);

// Contraseña: mínimo 8 caracteres, al menos una letra y un número
const passwordRegex = /^(?=.*[A-Za-z])(?=.*\d).{8,}$/;
const isValidPassword = passwordRegex.test(password);

// Teléfono español (9 dígitos)
const phoneRegex = /^[6-9]\d{8}$/;
const isValidPhone = phoneRegex.test(phone);

3 · Ejemplo mínimo

src/components/EmailForm.jsx
import { useState } from "react";

export default function EmailForm() {
  const [email, setEmail] = useState("");
  const [touched, setTouched] = useState(false);

  // Error derivado del estado
  const error = email === ""
    ? "El email es obligatorio"
    : !email.includes("@")
    ? "Email inválido"
    : "";

  const isValid = error === "";

  function handleSubmit(e) {
    e.preventDefault();
    if (isValid) {
      alert(`Enviado a: ${email}`);
    }
  }

  return (
    <form onSubmit={handleSubmit}>
      <input
        type="email"
        value={email}
        onChange={(e) => setEmail(e.target.value)}
        onBlur={() => setTouched(true)}   // marcamos como tocado al perder el foco
        placeholder="tu@email.com"
      />
      {touched && error && <span className="error">{error}</span>}
      <button type="submit" disabled={!isValid}>Enviar</button>
    </form>
  );
}

Línea por línea:

  1. Estado: el email y un booleano touched para saber si el usuario ha interactuado.
  2. Error derivado: se calcula en cada render. Si el email está vacío, error; si no tiene "@", error; si no, válido.
  3. onBlur: marca el campo como tocado. Solo entonces mostramos el error.
  4. Botón deshabilitado: si hay error, el botón no se puede pulsar.
  5. handleSubmit: solo envía si isValid es true.

4 · Ejemplo real

Un formulario de registro con múltiples campos, validación en tiempo real y mensajes de error específicos. Es el patrón que usarás en el proyecto del módulo.

src/components/RegistrationForm.jsx
import { useState } from "react";

const EMAIL_REGEX = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;
const PASSWORD_REGEX = /^(?=.*[A-Za-z])(?=.*\d).{8,}$/;

export default function RegistrationForm() {
  const [name, setName] = useState("");
  const [email, setEmail] = useState("");
  const [password, setPassword] = useState("");
  const [touched, setTouched] = useState({});

  // Errores derivados
  const errors = {
    name: name.trim() === "" ? "El nombre es obligatorio" : "",
    email: email === ""
      ? "El email es obligatorio"
      : !EMAIL_REGEX.test(email)
      ? "Email inválido"
      : "",
    password: password === ""
      ? "La contraseña es obligatoria"
      : !PASSWORD_REGEX.test(password)
      ? "Mínimo 8 caracteres, con letras y números"
      : "",
  };

  const hasErrors = Object.values(errors).some((err) => err !== "");

  function handleSubmit(e) {
    e.preventDefault();
    // Marcamos todos como tocados para mostrar todos los errores
    setTouched({ name: true, email: true, password: true });
    if (!hasErrors) {
      alert(`Registro: ${name} (${email})`);
    }
  }

  return (
    <form onSubmit={handleSubmit}>
      <div>
        <input
          value={name}
          onChange={(e) => setName(e.target.value)}
          onBlur={() => setTouched((p) => ({ ...p, name: true }))}
          placeholder="Nombre"
        />
        {touched.name && errors.name && <span className="error">{errors.name}</span>}
      </div>

      <div>
        <input
          type="email"
          value={email}
          onChange={(e) => setEmail(e.target.value)}
          onBlur={() => setTouched((p) => ({ ...p, email: true }))}
          placeholder="Email"
        />
        {touched.email && errors.email && <span className="error">{errors.email}</span>}
      </div>

      <div>
        <input
          type="password"
          value={password}
          onChange={(e) => setPassword(e.target.value)}
          onBlur={() => setTouched((p) => ({ ...p, password: true }))}
          placeholder="Contraseña"
        />
        {touched.password && errors.password && (
          <span className="error">{errors.password}</span>
        )}
      </div>

      <button type="submit" disabled={hasErrors}>Registrarse</button>
    </form>
  );
}

Decisiones explicadas:

  • Tres estados independientes: cada campo tiene su propio estado. Podríamos usar un objeto, pero es más claro así.
  • touched es un objeto: un booleano por campo. Usamos spread para actualizar sin mutar (Módulo 4).
  • Errores derivados: un objeto con un error por campo. Se recalcula en cada render.
  • hasErrors: derivado de errors. Deshabilita el botón si hay algún error.
  • handleSubmit: marca todos como tocados para mostrar todos los errores de golpe si el usuario intenta enviar sin rellenar.
  • Expresiones regulares: validación robusta de email y contraseña.

5 · Buenas prácticas

HazEvitaPor qué
Validar en el render (errores derivados) Guardar errores en estado Estado duplicado = desincronización. Los errores son una función de los valores.
Usar touched para mostrar errores solo después de interactuar Mostrar errores antes de que el usuario escriba Ruido visual: el usuario ve "campo obligatorio" antes de empezar a escribir.
Deshabilitar el botón si hay errores Permitir enviar y mostrar errores después Mejor UX: el usuario sabe que no puede enviar hasta que todo sea válido.
Expresiones regulares para validaciones complejas Validaciones manuales con if anidados Las regex son más concisas y mantenibles. (Pero no te pases: una regex de 200 caracteres no es mantenible.)
Validar también en el backend Confiar solo en la validación del frontend El frontend se puede saltar (DevTools, curl, etc.). El backend es la última línea de defensa.

6 · Errores habituales

Error 1: guardar errores en estado

✘ Incorrecto 
const [email, setEmail] = useState("");
const [emailError, setEmailError] = useState("");   // ✘ estado duplicado

function handleChange(e) {
  const value = e.target.value;
  setEmail(value);
  setEmailError(value.includes("@") ? "" : "Email inválido");   // desincronización
}
✔ Correcto 
const [email, setEmail] = useState("");
const emailError = email.includes("@") ? "" : "Email inválido";   // derivado en el render
// email cambia → re-render → emailError se recalcula. Siempre sincronizado.

Error 2: mostrar errores antes de que el usuario interactúe

✘ Incorrecto 
<input value={email} onChange={(e) => setEmail(e.target.value)} />
{emailError && <span className="error">{emailError}</span>}
// el usuario ve "Email inválido" antes de escribir nada (porque el email está vacío)
✔ Correcto 
<input
  value={email}
  onChange={(e) => setEmail(e.target.value)}
  onBlur={() => setTouched(true)}
/>
{touched && emailError && <span className="error">{emailError}</span>}
// solo mostramos el error DESPUÉS de que el usuario haya interactuado

Error 3: no validar en el onSubmit

✘ Incorrecto 
function handleSubmit(e) {
  e.preventDefault();
  alert(`Enviado a: ${email}`);   // no comprobamos si hay errores
}
✔ Correcto 
function handleSubmit(e) {
  e.preventDefault();
  setTouched(true);   // mostramos todos los errores
  if (!emailError) {
    alert(`Enviado a: ${email}`);
  }
}

Error 4: mutar el objeto touched

✘ Incorrecto 
function handleBlur() {
  touched.email = true;         // 💥 mutación directa
  setTouched(touched);          // React no detecta el cambio
}
✔ Correcto 
function handleBlur() {
  setTouched((prev) => ({ ...prev, email: true }));   // nuevo objeto
}

7 · Ejercicio guiado

Formulario de cambio de contraseña:

  1. Tres campos: currentPassword, newPassword, confirmPassword.

  2. Validaciones: currentPassword obligatorio, newPassword mínimo 8 caracteres con letras y números, confirmPassword debe coincidir con newPassword.

  3. Estado touched (objeto con un booleano por campo). Marca cada campo como tocado en onBlur.

  4. Muestra errores solo si el campo ha sido tocado y hay error.

  5. Deshabilita el botón "Cambiar contraseña" si hay errores.

  6. En handleSubmit, marca todos como tocados y solo envía si no hay errores.

  7. Bonus: muestra un indicador visual de fortaleza de contraseña (débil, media, fuerte) según la longitud y complejidad.

8 · Reto

🎯 El formulario de pago

Crea un componente PaymentForm con validación completa:

  1. Nombre del titular: obligatorio, mínimo 3 caracteres.
  2. Número de tarjeta: 16 dígitos (con espacios cada 4, pero validas solo los dígitos). Usa la regex /^\d{4} \d{4} \d{4} \d{4}$/ para el formato.
  3. Fecha de expiración: formato MM/AA. Valida que sea una fecha futura.
  4. CVV: 3 dígitos.
  5. Email: validación de email con regex.
  6. Muestra errores en tiempo real (después de onBlur).
  7. Deshabilita el botón "Pagar" si hay errores.
  8. Bonus: formatea el número de tarjeta automáticamente (añade espacios cada 4 dígitos mientras el usuario escribe).

9 · Resumen

  • Los errores de validación son valores derivados: se calculan en el render, no se guardan en estado.
  • Usa touched para mostrar errores solo después de que el usuario interactúe.
  • Deshabilita el botón de envío si hay errores.
  • Valida en el onSubmit también: marca todos como tocados y muestra todos los errores.
  • Expresiones regulares para validaciones complejas (emails, contraseñas, teléfonos).
  • Valida siempre también en el backend: el frontend se puede saltar.

10 · Preguntas frecuentes

¿Puedo usar una librería de validación como Yup o Zod?

Sí, y es recomendable en formularios complejos. Zod, por ejemplo, te permite definir un esquema de validación y reutilizarlo en frontend y backend. Pero para formularios simples, la validación manual con derivación es suficiente.

¿Cómo valido un campo que depende de otro (confirmar contraseña)?

En el objeto de errores, calcula el error del segundo campo a partir del primero: confirmPassword: password !== confirmPassword ? "No coincide" : "". Se recalcula en cada render, así que siempre está sincronizado.

¿Cómo valido al enviar pero no en tiempo real?

No uses touched. Solo valida en handleSubmit y guarda los errores en estado (sí, en este caso es válido, porque no son reactivos). O usa touched pero solo lo marcas todo como tocado en el submit.

¿Cómo valido un campo asíncronamente (email ya registrado)?

Necesitas un efecto (useEffect, Módulo 6) que se dispare cuando el campo cambie y haga una petición al backend. Mientras tanto, muestra un spinner o "comprobando…". Es un caso avanzado que veremos en el Módulo 9 (APIs).

¿Puedo reutilizar la lógica de validación entre formularios?

Sí: crea funciones puras que reciban los valores y devuelvan los errores. Por ejemplo: function validateEmail(email) { return email.includes("@") ? "" : "Inválido"; }. Luego úsalas en cualquier formulario. En el Módulo 6 veremos custom hooks para encapsular lógica de formularios completa.
