Form Actions de React 19

Módulo 5 · Formularios ⏱ 35 minutos

1 · Introducción

React 19 introduce una forma nueva y más sencilla de manejar formularios: las Form Actions. En lugar de usar onSubmit con e.preventDefault() y leer manualmente cada campo, puedes pasar una función directamente al atributo action del formulario. React se encarga del resto.

Esta característica es especialmente útil cuando trabajas con Server Components y Server Actions (que veremos en el proyecto final), pero también funciona en Client Components. Simplifica el código, maneja el estado de envío automáticamente y permite usar el hook useFormStatus para mostrar spinners y useActionState para manejar errores del servidor.

En esta lección veremos cómo usar Form Actions, qué ventajas tienen sobre el patrón tradicional y cómo combinarlas con los nuevos hooks de formularios.

2 · Teoría

El patrón tradicional (hasta React 18)

function ContactForm() {
  const [email, setEmail] = useState("");
  const [message, setMessage] = useState("");

  function handleSubmit(e) {
    e.preventDefault();   // evitar el envío nativo
    // enviar email y message al backend
    fetch("/api/contact", {
      method: "POST",
      body: JSON.stringify({ email, message }),
    });
  }

  return (
    <form onSubmit={handleSubmit}>
      <input value={email} onChange={(e) => setEmail(e.target.value)} />
      <textarea value={message} onChange={(e) => setMessage(e.target.value)} />
      <button type="submit">Enviar</button>
    </form>
  );
}

Este patrón funciona, pero tiene inconvenientes:

  • Tienes que crear un estado por cada campo.
  • Tienes que manejar e.preventDefault() manualmente.
  • Tienes que leer cada campo del estado y construir el objeto a enviar.
  • No hay forma fácil de mostrar un spinner mientras se envía (necesitas un estado isSubmitting).

Form Actions: el nuevo patrón

function ContactForm() {
  async function handleSubmit(formData) {
    // formData es un FormData nativo con todos los campos
    const email = formData.get("email");
    const message = formData.get("message");
    // enviar al backend
    await fetch("/api/contact", {
      method: "POST",
      body: formData,   // puedes enviar el FormData directamente
    });
  }

  return (
    <form action={handleSubmit}>
      <input name="email" />           // sin value, sin onChange
      <textarea name="message" />      // sin value, sin onChange
      <button type="submit">Enviar</button>
    </form>
  );
}

Cambios clave:

  • action en lugar de onSubmit: React maneja el envío por ti.
  • formData: React te pasa un objeto FormData nativo con todos los campos. No necesitas estados individuales.
  • Inputs no controlados: no necesitas value ni onChange. Los campos tienen su propio estado interno y React los recoge en el FormData.
  • Async/await: si la action es asíncrona, React espera a que termine antes de permitir otro envío.

useFormStatus: el estado del envío

React 19 introduce el hook useFormStatus para acceder al estado del formulario mientras se envía: 

import { useFormStatus } from "react-dom";

function SubmitButton() {
  const { pending, data, method, action } = useFormStatus();

  return (
    <button type="submit" disabled={pending}>
      {pending ? "Enviando…" : "Enviar"}
    </button>
  );
}

function ContactForm() {
  async function handleSubmit(formData) {
    await fetch("/api/contact", { method: "POST", body: formData });
  }

  return (
    <form action={handleSubmit}>
      <input name="email" />
      <SubmitButton />   {/* debe estar DENTRO del form */}
    </form>
  );
}
  • pending: booleano. Es true mientras la action se está ejecutando.
  • data: el FormData que se está enviando.
  • Debe estar dentro del <form>: useFormStatus solo funciona en componentes descendientes del formulario.
  • Ventaja: no necesitas un estado isSubmitting manual. React lo maneja por ti.

useActionState: errores del servidor

Si tu action devuelve un estado (por ejemplo, errores de validación del servidor), puedes usar useActionState para acceder a ese estado. Este hook se llamó useFormState durante las versiones canary; en React 19 estable se renombró a useActionState y se importa de "react" (ya no de "react-dom"): 

import { useActionState } from "react";

async function handleSubmit(previousState, formData) {
  const email = formData.get("email");
  if (!email.includes("@")) {
    return { error: "Email inválido" };
  }
  await fetch("/api/contact", { method: "POST", body: formData });
  return { success: true };
}

function ContactForm() {
  const [state, formAction, isPending] = useActionState(handleSubmit, { error: "" });

  return (
    <form action={formAction}>
      <input name="email" />
      {state.error && <span className="error">{state.error}</span>}
      <button type="submit" disabled={isPending}>Enviar</button>
    </form>
  );
}
  • useActionState(action, initialState): devuelve tres valores: el estado actual, la action envuelta y el booleano isPending.
  • previousState: el estado anterior (útil para actualizar, no reemplazar).
  • state: el estado actual (lo que devolvió la action la última vez).
  • isPending: true mientras la action se ejecuta. En React 19 estable este tercer valor hace que useFormStatus sea opcional en muchos casos.
  • Ventaja: maneja errores del servidor de forma reactiva, sin estados manuales.

¿Cuándo usar Form Actions vs el patrón tradicional?

Form ActionsPatrón tradicional
Formularios simples (contacto, newsletter) Formularios con validación en tiempo real
Cuando no necesitas controlar cada campo Cuando necesitas formatear mientras el usuario escribe
Con Server Actions (proyecto final) Cuando necesitas deshabilitar el botón según errores del cliente
Cuando el backend valida y devuelve errores Cuando necesitas acceso inmediato a cada campo

3 · Ejemplo mínimo

src/components/NewsletterForm.jsx
import { useFormStatus } from "react-dom";

function SubmitButton() {
  const { pending } = useFormStatus();
  return (
    <button type="submit" disabled={pending}>
      {pending ? "Suscribiendo…" : "Suscribirse"}
    </button>
  );
}

export default function NewsletterForm() {
  async function handleSubmit(formData) {
    const email = formData.get("email");
    // Simulamos una petición al servidor
    await new Promise((resolve) => setTimeout(resolve, 1000));
    console.log("Suscrito:", email);
  }

  return (
    <form action={handleSubmit}>
      <input name="email" type="email" placeholder="tu@email.com" required />
      <SubmitButton />
    </form>
  );
}

Línea por línea:

  1. action={handleSubmit}: React maneja el envío. No necesitas onSubmit ni e.preventDefault().
  2. formData.get("email"): lees el campo directamente del FormData. No necesitas estados.
  3. useFormStatus: el hook te da pending para mostrar un spinner.
  4. SubmitButton dentro del <form>: requisito para que useFormStatus funcione.

4 · Ejemplo real

Un formulario de contacto con validación del servidor y manejo de errores con useActionState:

src/components/ContactForm.jsx
import { useActionState } from "react";
import { useFormStatus } from "react-dom";

// La action: valida y "envía" al servidor
async function handleSubmit(previousState, formData) {
  const email = formData.get("email");
  const message = formData.get("message");

  // Validación del servidor (simulada)
  if (!email.includes("@")) {
    return { ...previousState, error: "Email inválido" };
  }
  if (message.length < 10) {
    return { ...previousState, error: "El mensaje es demasiado corto" };
  }

  // Simulamos una petición al servidor
  await new Promise((resolve) => setTimeout(resolve, 1000));

  return { success: true, error: "" };
}

function SubmitButton() {
  const { pending } = useFormStatus();
  return (
    <button type="submit" disabled={pending}>
      {pending ? "Enviando…" : "Enviar"}
    </button>
  );
}

export default function ContactForm() {
  const [state, formAction] = useActionState(handleSubmit, {
    success: false,
    error: "",
  });

  return (
    <form action={formAction}>
      <div>
        <input name="email" type="email" placeholder="tu@email.com" required />
      </div>
      <div>
        <textarea name="message" placeholder="Tu mensaje…" required />
      </div>
      {state.error && <span className="error">{state.error}</span>}
      {state.success && <span className="success">¡Mensaje enviado!</span>}
      <SubmitButton />
    </form>
  );
}

Decisiones explicadas:

  • useActionState: maneja el estado devuelto por la action. Inicializamos con { success: false, error: "" }.
  • Validación del servidor: la action valida y devuelve errores. No hay validación en el cliente (solo el required de HTML).
  • SubmitButton: componente separado para usar useFormStatus. Muestra un spinner mientras se envía.
  • Mensajes de éxito/error: se muestran según el estado devuelto por la action.
  • Ventaja: no necesitas estados manuales para isSubmitting, error, success. React lo maneja todo.

5 · Buenas prácticas

HazEvitaPor qué
Usar Form Actions para formularios simples Usar Form Actions para formularios con validación compleja en el cliente Form Actions brilla cuando el servidor valida. Si necesitas validación en tiempo real, el patrón tradicional es mejor.
Extraer el botón en un componente para usar useFormStatus Usar useFormStatus fuera del <form> useFormStatus solo funciona en descendientes del formulario.
Validar también en el servidor Confiar solo en la validación del cliente El cliente se puede saltar. El servidor es la última línea de defensa.
Usar useActionState para errores del servidor Guardar errores del servidor en estados manuales useActionState es más limpio y reactivo.
Marcar campos como required en HTML Depender solo de JavaScript para campos obligatorios HTML required funciona incluso sin JavaScript. Mejor accesibilidad.

6 · Errores habituales

Error 1: usar useFormStatus fuera del <form>

✘ Incorrecto 
function App() {
  const { pending } = useFormStatus();   // 💥 no está dentro de un form
  return <ContactForm />;
}
✔ Correcto 
function SubmitButton() {
  const { pending } = useFormStatus();   // dentro de un componente descendiente del form
  return <button disabled={pending}>{pending ? "Enviando…" : "Enviar"}</button>;
}

function ContactForm() {
  return (
    <form action={handleSubmit}>
      <SubmitButton />   {/* dentro del form */}
    </form>
  );
}

Error 2: mezclar onSubmit y action

✘ Incorrecto 
<form onSubmit={handleSubmit} action={formAction}>   // 💥 los dos no
  …
</form>
✔ Correcto 
<form action={formAction}>   // solo action
  …
</form>

Error 3: no manejar el estado anterior en useActionState

✘ Incorrecto 
async function handleSubmit(previousState, formData) {
  return { error: "Email inválido" };   // pierdes el resto del estado
}
✔ Correcto 
async function handleSubmit(previousState, formData) {
  return { ...previousState, error: "Email inválido" };   // conservas el resto
}

Error 4: usar Form Actions para validación en tiempo real

✘ Incorrecto 
// Quieres mostrar errores mientras el usuario escribe, pero usas Form Actions:
<form action={handleSubmit}>
  <input name="email" />   {/* no tienes acceso al valor hasta el submit */}
</form>
✔ Correcto 
// Para validación en tiempo real, usa el patrón tradicional:
<form onSubmit={handleSubmit}>
  <input value={email} onChange={(e) => setEmail(e.target.value)} />
  {emailError && <span>{emailError}</span>}
</form>

Crea un componente ReservationForm con Form Actions:

9 · Resumen

  • Form Actions son la nueva forma de manejar formularios en React 19: action en lugar de onSubmit.
  • Recibes un FormData nativo con todos los campos. No necesitas estados individuales.
  • useFormStatus: te da pending para mostrar spinners. Debe estar dentro del <form>.
  • useActionState: maneja el estado devuelto por la action (errores del servidor).
  • Ideal para formularios simples y Server Actions. Para validación en tiempo real, usa el patrón tradicional.
  • Valida siempre también en el servidor: el cliente se puede saltar.

10 · Preguntas frecuentes

¿Puedo usar Form Actions con Server Components?

Sí, y es donde más brillan. Las Server Actions son funciones que se ejecutan en el servidor y se invocan desde el cliente. Las verás en el proyecto final. Por ahora, las Form Actions funcionan igual en Client Components.

¿Puedo combinar Form Actions con validación en el cliente?

Sí, pero pierdes parte de la simplicidad. Si necesitas validación en tiempo real, el patrón tradicional (estados + onSubmit) es más claro. Las Form Actions son ideales cuando el servidor valida.

¿Qué pasa si la action lanza un error?

React captura el error y lo muestra en consola. Para manejar errores gracefully, devuelve un objeto con el error en lugar de lanzar una excepción. useActionState te permite mostrar ese error en la UI.

¿Puedo resetear el formulario después de enviar?

Sí: si usas inputs no controlados (sin value), puedes resetear el formulario con formRef.current.reset() después de enviar. O usa una key que cambie para forzar un re-mount del formulario.

¿Form Actions reemplaza al patrón tradicional?

No: son complementarios. Form Actions es más simple para formularios que envían datos al servidor. El patrón tradicional es mejor cuando necesitas control total sobre cada campo (validación en tiempo real, formateo, etc.).
