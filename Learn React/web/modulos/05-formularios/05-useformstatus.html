useFormStatus

Módulo 5 · Formularios ⏱ 30 minutos

1 · Introducción

En la lección anterior vimos que Form Actions simplifican el envío de formularios: pasas una función a action y React maneja el FormData por ti. Pero hay un detalle: cuando la action es asíncrona, el usuario no tiene feedback visual de que el formulario se está enviando. El botón de submit sigue activo, el usuario puede pulsarlo varias veces… es un desastre.

React 19 introduce useFormStatus, un hook que te permite leer el estado pendiente de un formulario desde cualquier componente hijo. Con él puedes deshabilitar botones, mostrar spinners, cambiar textos, y en general darle al usuario la tranquilidad de que "algo está pasando".

¿Qué problema resuelve? Antes necesitabas un estado manual (isSubmitting), un onSubmit que lo pusiera a true, y la action tenía que recibir el setter. Era código boilerplate que se repetía en cada formulario. useFormStatus elimina todo eso: React sabe si el formulario se está enviando y te lo dice.

¿Cuándo se usa? Siempre que tengas un formulario con action y quieras mostrar feedback visual durante el envío. Es especialmente útil en botones de submit, pero también puedes usarlo para deshabilitar todos los campos del formulario o mostrar una barra de progreso.

2 · Teoría

La firma del hook

import { useFormStatus } from "react-dom";

const { pending, data, method, action } = useFormStatus();

Cada propiedad devuelve:

  • pending: boolean — true mientras la action del formulario se está ejecutando. Pasa a false cuando la acción termina (tanto si tuvo éxito como si lanzó un error).
  • data: FormData | null — el objeto FormData que se está enviando en la acción actual. Es null si no hay ningún envío activo. Útil para mostrar en la UI qué datos se están procesando.
  • method: "get" | "post" | string | null — el método del formulario (get o post). Es null si no hay un formulario padre.
  • action: (formData: FormData) => void | Promise<void> | null — la función que se está ejecutando. Es null si no hay un envío activo.

¿Cómo funciona internamente?

React mantiene un registro interno del estado de envío de cada formulario en el árbol de componentes. Cuando un formulario con action ejecuta su handler, React marca ese formulario como "pendiente" y cualquier componente descendiente que llame a useFormStatus recibe pending: true. Cuando la acción termina (resuelve la promesa o lanza un error), React limpia el estado y pending vuelve a false.

FLUJO DE useFormStatus ───────────────────── Usuario pulsa "Enviar" │ ▼ form action={handleSubmit} │ ▼ React ejecuta handleSubmit(formData) │ ▼ useFormStatus → { pending: true, data: formData, action: handleSubmit } │ ▼ Componente hijo re-renderiza con pending=true (botón deshabilitado, spinner visible) │ ▼ handleSubmit termina (resolve o reject) │ ▼ useFormStatus → { pending: false, data: null, action: null } │ ▼ Componente hijo re-renderiza con pending=false

Restricción importante

useFormStatus solo funciona en componentes que estén dentro de un <form> (directa o indirectamente). Si llamas a useFormStatus en un componente que no tiene un formulario ancestro, siempre devuelve { pending: false, data: null, method: null, action: null }.

Esta restricción no es un capricho: tiene sentido. El estado de envío es una propiedad del formulario, no del componente que lo aloja. Al obligarte a usar el hook dentro del formulario, React garantiza que siempre estás leyendo el estado correcto.

Comparación: antes vs ahora

// ── ANTES (React ≤18) ──
function ContactForm() {
  const [isSubmitting, setIsSubmitting] = useState(false);

  async function handleSubmit(e) {
    e.preventDefault();
    setIsSubmitting(true);     // manual
    try {
      const formData = new FormData(e.target);
      await fetch("/api/contact", { method: "POST", body: formData });
    } finally {
      setIsSubmitting(false);  // manual, incluso en errores
    }
  }

  return (
    <form onSubmit={handleSubmit}>
      <input name="email" />
      <button type="submit" disabled={isSubmitting}>
        {isSubmitting ? "Enviando…" : "Enviar"}
      </button>
    </form>
  );
}

// ── AHORA (React 19) ──
function SubmitButton() {
  const { pending } = useFormStatus();
  return (
    <button type="submit" disabled={pending}>
      {pending ? "Enviando…" : "Enviar"}
    </button>
  );
}

function ContactForm() {
  async function handleSubmit(formData) {
    await fetch("/api/contact", { method: "POST", body: formData });
  }
  return (
    <form action={handleSubmit}>
      <input name="email" />
      <SubmitButton />
    </form>
  );
}

La versión moderna es más declarativa: el botón se deshabilita solo cuando el formulario lo está enviando, sin necesidad de pasar setters ni manejar finally.

3 · Ejemplo mínimo

src/components/SubscribeButton.jsx
import { useFormStatus } from "react-dom";

function SubscribeButton() {
  const { pending } = useFormStatus();

  return (
    <button type="submit" disabled={pending}>
      {pending ? "Suscribiendo…" : "Suscribirse"}
    </button>
  );
}

export default function NewsletterForm() {
  async function handleSubmit(formData) {
    // Simulamos una petición que tarda 2 segundos
    await new Promise((resolve) => setTimeout(resolve, 2000));
    console.log("Email suscrito:", formData.get("email"));
  }

  return (
    <form action={handleSubmit}>
      <input name="email" type="email" placeholder="tu@email.com" required />
      <SubscribeButton />
    </form>
  );
}

Línea por línea:

  1. useFormStatus() — se llama dentro de SubscribeButton, que está dentro del <form>. Devuelve { pending }.
  2. disabled={pending} — cuando el formulario se envía, el botón se deshabilita. El usuario no puede pulsarlo dos veces.
  3. {pending ? "Suscribiendo…" : "Suscribirse"} — el texto del botón cambia para dar feedback visual.
  4. action={handleSubmit} — el formulario usa la nueva sintaxis de Form Actions.
  5. await new Promise(…) — simula el tiempo de respuesta del servidor. Durante esos 2 segundos, pending es true.

4 · Ejemplo real

Un formulario de registro con múltiples botones de submit, feedback con el email que se está enviando y spinner de carga:

src/components/RegisterForm.jsx
import { useState } from "react";
import { useFormStatus } from "react-dom";

function SubmitButton() {
  const { pending } = useFormStatus();

  return (
    <button type="submit" disabled={pending} className="btn btn--primary">
      {pending ? (
        <>
          <span className="spinner" />
          {" Registrando…"}
        </>
      ) : (
        "Crear cuenta"
      )}
    </button>
  );
}

function SaveDraftButton() {
  const { pending, data } = useFormStatus();
  const isDraft = data?.get("intent") === "draft";

  return (
    <button
      type="submit"
      name="intent"
      value="draft"
      disabled={pending}
      className="btn btn--secondary"
    >
      {pending && isDraft ? "Guardando…" : "Guardar borrador"}
    </button>
  );
}

function FormStatus() {
  const { pending, data, action } = useFormStatus();

  if (!pending) return null;

  const email = data?.get("email") ?? "—";

  return (
    <div className="form-status" role="status" aria-live="polite">
      <p>Enviando registro para <strong>{email}</strong>…</p>
      {action && <p className="text-sm">Action: {action.name || "anónima"}</p>}
    </div>
  );
}

export default function RegisterForm() {
  const [error, setError] = useState(null);

  async function handleSubmit(formData) {
    const intent = formData.get("intent");
    const email = formData.get("email");
    const name = formData.get("name");

    // Validación simulada
    if (!email.includes("@")) {
      throw new Error("Email inválido");
    }

    // Simulamos petición al servidor
    await new Promise((resolve) => setTimeout(resolve, 2000));

    if (intent === "draft") {
      console.log("Borrador guardado para:", email);
    } else {
      console.log("Usuario registrado:", { name, email });
    }
  }

  async function handleSubmitWithError(formData) {
    try {
      setError(null);
      await handleSubmit(formData);
    } catch (err) {
      setError(err.message);
    }
  }

  return (
    <form action={handleSubmitWithError} className="register-form">
      <div>
        <label htmlFor="name">Nombre</label>
        <input name="name" id="name" required />
      </div>
      <div>
        <label htmlFor="email">Email</label>
        <input name="email" id="email" type="email" required />
      </div>

      {error && <p className="error">{error}</p>}

      <FormStatus />

      <div className="form-actions">
        <SaveDraftButton />
        <SubmitButton />
      </div>
    </form>
  );
}

Decisiones explicadas:

  • Múltiples botones: useFormStatus funciona con todos los botones de submit, no solo con el principal. Cada botón puede leer pending y reaccionar.
  • data para identificar el botón: data.get("intent") permite saber qué botón pulsó el usuario gracias al atributo name del botón. Así el botón "Guardar borrador" muestra su propio texto de carga.
  • FormStatus como componente de feedback: muestra el email que se está procesando. Se oculta automáticamente cuando pending es false.
  • role="status" + aria-live="polite": accesibilidad. Los lectores de pantalla anuncian el cambio sin interrumpir.
  • Action con nombre: action.name muestra el nombre de la función. Las funciones nombradas son más fáciles de depurar.

5 · Buenas prácticas

HazEvitaPor qué
Usar useFormStatus en componentes hijo del formulario Usarlo en el mismo componente que contiene el <form> El hook solo funciona dentro del formulario. Si lo llamas en el componente padre, siempre recibe pending: false.
Deshabilitar el botón con disabled={pending} Deshabilitar con CSS pointer-events disabled nativo impide el envío y es accesible. CSS no detiene el evento submit.
Mostrar texto dinámico en el botón Ocultar el botón mientras se envía El botón desaparecido puede confundir al usuario. Es mejor cambiar su texto para mantener el contexto.
Usar aria-live="polite" en mensajes de estado Mostrar spinners sin texto descriptivo La accesibilidad es obligatoria. Los lectores de pantalla necesitan texto para anunciar el progreso.
Leer data para personalizar el feedback Asumir que solo hay un botón de submit Los formularios pueden tener múltiples acciones. data.get("name") te dice qué botón se pulsó.
Manejar errores con try/catch en la action Dejar que el error se propague sin control Si la action lanza un error, pending vuelve a false pero el usuario no ve por qué falló.

6 · Errores habituales

Error 1: llamar a useFormStatus fuera del <form>

✘ Incorrecto 
function App() {
  const { pending } = useFormStatus();   // ← no hay <form> ancestro
  // pending SIEMPRE es false, aunque el formulario se esté enviando
  return <RegisterForm />;
}
✔ Correcto 
function SubmitButton() {
  const { pending } = useFormStatus();   // ← dentro del <form>
  return <button disabled={pending}>{pending ? "…" : "Enviar"}</button>;
}

Error 2: confiar en pending para validar

✘ Incorrecto 
function SubmitButton() {
  const { pending } = useFormStatus();
  if (pending) {
    // El formulario se está enviando: NO hagas nada más aquí
    // useFormStatus es solo lectura, no controlas el envío
  }
}
✔ Correcto 
function SubmitButton() {
  const { pending } = useFormStatus();
  return (
    <button type="submit" disabled={pending}>
      {pending ? "Enviando…" : "Enviar"}
    </button>
  );
  // pending es SOLO para feedback visual, no para lógica de negocio
}

Error 3: no usar name en los botones con data

✘ Incorrecto 
function SaveDraftButton() {
  const { pending, data } = useFormStatus();
  // data?.get("intent") será null porque el botón no tiene name
  return (
    <button type="submit" disabled={pending}>
      Guardar borrador
    </button>
  );
}
✔ Correcto 
function SaveDraftButton() {
  const { pending, data } = useFormStatus();
  const isSaving = pending && data?.get("intent") === "draft";
  return (
    <button type="submit" name="intent" value="draft" disabled={pending}>
      {isSaving ? "Guardando…" : "Guardar borrador"}
    </button>
  );
}

Error 4: asumir que pending se resetea con errores no capturados

✘ Incorrecto 
async function handleSubmit(formData) {
  // Si esto lanza un error, pending → false,
  // pero el usuario no ve el mensaje de error
  throw new Error("Algo salió mal");
}
✔ Correcto 
async function handleSubmit(formData) {
  try {
    // operación que puede fallar
    await saveToServer(formData);
  } catch (err) {
    // Muestra el error en la UI
    setError(err.message);
    // pending se pondrá a false automáticamente
  }
}

9 · Resumen

  • useFormStatus es un hook de React 19 que lee el estado de envío de un formulario desde componentes hijos.
  • Devuelve { pending, data, method, action }.
  • pending es true mientras la action del formulario se ejecuta. Vuelve a false al terminar (éxito o error).
  • data contiene el FormData del envío actual. Útil para saber qué botón se pulsó o qué datos se están procesando.
  • Solo funciona dentro de un <form>: el componente que lo usa debe ser descendiente directo o indirecto del formulario.
  • Elimina la necesidad de estados manuales como isSubmitting y finally blocks.
  • Ideal para deshabilitar botones, mostrar spinners, cambiar textos y dar feedback visual accesible.
  • Maneja los errores en la action con try/catch para que pending se resetee limpiamente.

10 · Preguntas frecuentes

¿Puedo usar useFormStatus con onSubmit tradicional?

No. useFormStatus solo funciona con el atributo action de React 19. Si usas onSubmit, no hay una action que React pueda monitorizar, así que pending siempre será false.

¿Puedo tener múltiples componentes con useFormStatus en el mismo formulario?

Sí. Todos los componentes descendientes del mismo <form> reciben el mismo estado. Puedes tener un botón, un mensaje de estado y una barra de progreso, todos leyendo pending de forma independiente.

¿Qué pasa si la action es una función síncrona?

pending se pone a true al inicio y vuelve a false inmediatamente después (en el mismo ciclo de evento). En la práctica, no verás el estado pendiente porque es instantáneo. El hook está diseñado para actions asíncronas.

¿Puedo modificar el data del useFormStatus?

No. data y action son de solo lectura. Son valores que React proporciona para que puedas mostrar información en la UI, no para que modifiques el envío. Si necesitas modificar los datos antes de enviar, hazlo en la action antes del await.

¿Puedo usar useFormStatus en Server Components?

No. useFormStatus es un hook de React, y los hooks solo funcionan en Client Components (componentes con "use client"). En Server Components puedes usar Server Actions, pero el estado pendiente se maneja con el propio mecanismo de streaming de React.

¿Cómo depuro useFormStatus?

La forma más fácil es añadir un componente que imprima el estado: <pre>{JSON.stringify(useFormStatus(), null, 2)}</pre> dentro del formulario. También puedes usar React DevTools para inspeccionar el estado de los componentes hijos.
