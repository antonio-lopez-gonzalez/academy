La capa de servicios

Módulo 9 · Consumo de APIs ⏱ 30 minutos

1 · Introducción

Hasta ahora hemos hecho peticiones fetch directamente en los componentes. Pero si tienes múltiples componentes que consumen la misma API, terminas duplicando código: la misma URL, los mismos headers, el mismo manejo de errores.

La solución es crear una capa de servicios: un módulo separado que encapsula toda la lógica de comunicación con la API. Los componentes solo llaman a funciones del servicio, sin preocuparse por los detalles de fetch.

2 · Teoría

Ventajas de la capa de servicios

  • Reutilización: un servicio se usa en múltiples componentes.
  • Mantenibilidad: si cambia la API, solo modificas el servicio.
  • Testabilidad: puedes mockear servicios en tests.
  • Separación de responsabilidades: los componentes se enfocan en la UI.

Estructura típica

src/
├── services/
│   ├── api.js          ← configuración base (URL, headers)
│   ├── userService.js  ← funciones para usuarios
│   └── postService.js  ← funciones para posts
├── components/
│   └── UserList.jsx    ← usa userService

Servicio base con configuración

// services/api.js
const API_BASE_URL = "https://api.example.com";

const DEFAULT_HEADERS = {
  "Content-Type": "application/json",
};

export async function apiRequest(endpoint, options = {}) {
  const url = `${API_BASE_URL}${endpoint}`;
  const config = {
    ...options,
    headers: {
      ...DEFAULT_HEADERS,
      ...options.headers,
    },
  };

  const response = await fetch(url, config);

  if (!response.ok) {
    throw new Error(`HTTP ${response.status}: ${response.statusText}`);
  }

  return response.json();
}

Servicio específico

// services/userService.js
import { apiRequest } from "./api";

export const userService = {
  async getAll() {
    return apiRequest("/users");
  },

  async getById(id) {
    return apiRequest(`/users/${id}`);
  },

  async create(userData) {
    return apiRequest("/users", {
      method: "POST",
      body: JSON.stringify(userData),
    });
  },

  async update(id, userData) {
    return apiRequest(`/users/${id}`, {
      method: "PUT",
      body: JSON.stringify(userData),
    });
  },

  async delete(id) {
    return apiRequest(`/users/${id}`, {
      method: "DELETE",
    });
  },
};

Uso en componentes

import { useState, useEffect } from "react";
import { userService } from "../services/userService";

export default function UserList() {
  const [users, setUsers] = useState([]);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    async function loadUsers() {
      try {
        setLoading(true);
        const data = await userService.getAll();
        setUsers(data);
      } catch (err) {
        setError(err.message);
      } finally {
        setLoading(false);
      }
    }

    loadUsers();
  }, []);

  // ... renderizado
}

3 · Ejemplo mínimo

src/services/api.js
const API_BASE = "https://jsonplaceholder.typicode.com";

export async function apiGet(endpoint) {
  const response = await fetch(`${API_BASE}${endpoint}`);
  if (!response.ok) throw new Error("Error en la petición");
  return response.json();
}

export async function apiPost(endpoint, data) {
  const response = await fetch(`${API_BASE}${endpoint}`, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(data),
  });
  if (!response.ok) throw new Error("Error al crear");
  return response.json();
}
src/services/postService.js
import { apiGet, apiPost } from "./api";

export const postService = {
  getAll: () => apiGet("/posts"),
  getById: (id) => apiGet(`/posts/${id}`),
  create: (data) => apiPost("/posts", data),
};
src/components/PostList.jsx
import { useState, useEffect } from "react";
import { postService } from "../services/postService";

export default function PostList() {
  const [posts, setPosts] = useState([]);
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    postService.getAll()
      .then(setPosts)
      .catch(console.error)
      .finally(() => setLoading(false));
  }, []);

  if (loading) return <p>Cargando...</p>;

  return (
    <ul>
      {posts.map((post) => (
        <li key={post.id}>{post.title}</li>
      ))}
    </ul>
  );
}

4 · Ejemplo real

Servicio con autenticación y manejo de tokens:

src/services/api.js
const API_BASE = "https://api.example.com";

function getAuthHeaders() {
  const token = localStorage.getItem("authToken");
  return token ? { Authorization: `Bearer ${token}` } : {};
}

export async function apiRequest(endpoint, options = {}) {
  const config = {
    ...options,
    headers: {
      "Content-Type": "application/json",
      ...getAuthHeaders(),
      ...options.headers,
    },
  };

  const response = await fetch(`${API_BASE}${endpoint}`, config);

  if (response.status === 401) {
    // Token expirado, redirigir a login
    localStorage.removeItem("authToken");
    window.location.href = "/login";
    throw new Error("Sesión expirada");
  }

  if (!response.ok) {
    const error = await response.json().catch(() => ({}));
    throw new Error(error.message || `Error ${response.status}`);
  }

  return response.json();
}
src/services/authService.js
import { apiRequest } from "./api";

export const authService = {
  async login(email, password) {
    const data = await apiRequest("/auth/login", {
      method: "POST",
      body: JSON.stringify({ email, password }),
    });
    localStorage.setItem("authToken", data.token);
    return data;
  },

  async logout() {
    localStorage.removeItem("authToken");
  },

  async getCurrentUser() {
    return apiRequest("/auth/me");
  },
};

6 · Errores habituales

Error 1: mezclar lógica de UI con lógica de API

// ✘ en el componente
async function handleSubmit() {
  const response = await fetch("https://api.example.com/users", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ name, email }),
  });
  // ...
}

// ✔ en el servicio
async function handleSubmit() {
  await userService.create({ name, email });
}

Error 2: no centralizar la configuración

// ✘ URLs duplicadas
fetch("https://api.example.com/users");
fetch("https://api.example.com/posts");

// ✔ configuración centralizada
const API_BASE = "https://api.example.com";
fetch(`${API_BASE}/users`);
fetch(`${API_BASE}/posts`);

8 · Reto

🎯 Servicio con interceptores

Añade interceptores a tu capa de servicios: un interceptor que añada el token de autenticación a todas las peticiones, y otro que maneje errores 401 globalmente (redirigir a login).

9 · Resumen

  • La capa de servicios encapsula la lógica de comunicación con la API.
  • Ventajas: reutilización, mantenibilidad, testabilidad, separación de responsabilidades.
  • Servicio base con configuración común (URL, headers).
  • Servicios específicos por dominio (user, post, auth).
  • Los componentes solo llaman a funciones del servicio.

10 · Preguntas frecuentes

¿Puedo usar clases en lugar de objetos?
Sí, pero los objetos con funciones son más simples y suficientes para la mayoría de casos.
¿Cómo manejo endpoints con query params?
Usa URLSearchParams: const params = new URLSearchParams({ page: 1 }); fetch(`${API}/users?${params}`).
¿Puedo usar la capa de servicios fuera de React?
Sí, los servicios son JavaScript puro, no dependen de React.
¿Cómo testeo servicios?
Mockea fetch con vi.mock() en Vitest o jest.mock() en Jest.
