Mocks y Spies

Módulo 12 · Testing

Introducción

Los mocks y spies son herramientas esenciales para aislar el código que estás testeando. Te permiten:

  • Simular dependencias externas (APIs, bases de datos)
  • Verificar que funciones se llaman correctamente
  • Controlar el comportamiento de funciones
  • Espiar llamadas a funciones reales

Spies: espiando funciones

Un spy envuelve una función real para rastrear cómo se llama, sin cambiar su comportamiento. 

// src/utils/logger.js
export function log(message) {
  console.log(`[LOG]: ${message}`)
}

// Test
import { describe, it, expect, vi } from 'vitest'
import * as logger from '../utils/logger'

describe('Spy', () => {
  it('should spy on log function', () => {
    // Espiar la función
    const logSpy = vi.spyOn(logger, 'log')
    
    logger.log('test message')
    
    // Verificar que se llamó
    expect(logSpy).toHaveBeenCalled()
    expect(logSpy).toHaveBeenCalledWith('test message')
    expect(logSpy).toHaveBeenCalledOnce()
    
    // Restaurar la función original
    logSpy.mockRestore()
  })
})

Mock functions: funciones simuladas

Una mock function reemplaza una función real con una implementación simulada. 

// Crear mock function
const mockFn = vi.fn()

// Definir retorno
mockFn.mockReturnValue(42)
mockFn.mockReturnValueOnce(1)
mockFn.mockReturnValueOnce(2)

// Definir implementación
mockFn.mockImplementation((x) => x * 2)
mockFn.mockImplementationOnce((x) => x * 3)

// Simular error
mockFn.mockRejectedValue(new Error('Failed'))
mockFn.mockRejectedValueOnce(new Error('First call failed'))

// Uso
const result1 = mockFn(5)  // 15 (mockImplementationOnce)
const result2 = mockFn(5)  // 10 (mockImplementation)

// Verificaciones
expect(mockFn).toHaveBeenCalledWith(5)
expect(mockFn).toHaveBeenCalledTimes(2)
expect(mockFn).toHaveReturnedWith(10)

Mock de módulos

// src/api/users.js
export async function fetchUsers() {
  const response = await fetch('/api/users')
  return response.json()
}

// src/components/UserList.jsx
import { fetchUsers } from '../api/users'

export default function UserList() {
  const [users, setUsers] = useState([])
  
  useEffect(() => {
    fetchUsers().then(setUsers)
  }, [])
  
  return (
    <ul>
      {users.map(user => <li key={user.id}>{user.name}</li>)}
    </ul>
  )
}

// Test
import { render, screen } from '@testing-library/react'
import UserList from '../components/UserList'

// Mock del módulo completo
vi.mock('../api/users', () => ({
  fetchUsers: vi.fn()
}))

import { fetchUsers } from '../api/users'

describe('UserList', () => {
  it('should display users', async () => {
    // Configurar mock
    fetchUsers.mockResolvedValue([
      { id: 1, name: 'Alice' },
      { id: 2, name: 'Bob' }
    ])
    
    render(<UserList />)
    
    // Esperar a que se carguen los usuarios
    expect(await screen.findByText('Alice')).toBeInTheDocument()
    expect(screen.getByText('Bob')).toBeInTheDocument()
    
    // Verificar que se llamó a fetchUsers
    expect(fetchUsers).toHaveBeenCalledOnce()
  })

  it('should handle errors', async () => {
    fetchUsers.mockRejectedValue(new Error('Network error'))
    
    render(<UserList />)
    
    // Verificar manejo de errores
    expect(await screen.findByText(/error/i)).toBeInTheDocument()
  })
})

Mock parcial

// Mock solo algunas funciones, mantener el resto
vi.mock('../api/users', async () => {
  const actual = await vi.importActual('../api/users')
  return {
    ...actual,
    fetchUsers: vi.fn()  // Solo mockeamos fetchUsers
  }
})

// Mock global de fetch
global.fetch = vi.fn()

describe('API calls', () => {

    fetch.mockClear()
  })

    fetch.mockResolvedValueOnce({
      ok: true,
      json: async () => ({ data: 'test' })
    })

    expect(fetch).toHaveBeenCalledWith('/api/data')
    expect(result).toEqual({ data: 'test' })
  })

  it('should handle fetch errors', async () => {
    fetch.mockRejectedValueOnce(new Error('Network error'))
    
    await expect(fetchData()).rejects.toThrow('Network error')
  })

Mock de timers

describe('Timer tests', () => {
  beforeEach(() => {
    vi.useFakeTimers()
  })

  afterEach(() => {
    vi.useRealTimers()
  })

  it('should call function after delay', () => {
    const callback = vi.fn()
    
    setTimeout(callback, 1000)
    
    expect(callback).not.toHaveBeenCalled()
    
    vi.advanceTimersByTime(1000)
    
    expect(callback).toHaveBeenCalled()
  })

  it('should work with async timers', async () => {
    const callback = vi.fn()
    
    setTimeout(callback, 1000)
    
    await vi.advanceTimersByTimeAsync(1000)
    
    expect(callback).toHaveBeenCalled()
  })

  it('should run all timers', () => {
    const callback1 = vi.fn()
    const callback2 = vi.fn()
    
    setTimeout(callback1, 1000)
    setTimeout(callback2, 2000)
    
    vi.runAllTimers()
    
    expect(callback1).toHaveBeenCalled()
    expect(callback2).toHaveBeenCalled()
  })
})

Verificaciones de mocks

const mockFn = vi.fn()

mockFn('arg1', 'arg2')
mockFn('arg3')

// Llamadas
expect(mockFn).toHaveBeenCalled()
expect(mockFn).toHaveBeenCalledTimes(2)
expect(mockFn).toHaveBeenCalledWith('arg1', 'arg2')
expect(mockFn).toHaveBeenLastCalledWith('arg3')
expect(mockFn).toHaveBeenNthCalledWith(1, 'arg1', 'arg2')

// Retornos
mockFn.mockReturnValue('result')
mockFn()

expect(mockFn).toHaveReturned()
expect(mockFn).toHaveReturnedWith('result')
expect(mockFn).toHaveReturnedTimes(1)

// Argumentos específicos
expect(mockFn.mock.calls[0]).toEqual(['arg1', 'arg2'])
expect(mockFn.mock.results[0]).toEqual({ type: 'return', value: 'result' })

Limpieza de mocks

import { beforeEach, afterEach } from 'vitest'

// Limpiar después de cada test
afterEach(() => {
  vi.clearAllMocks()
})

// O configurar en vite.config.js
export default defineConfig({
  test: {
    clearMocks: true,
    restoreMocks: true,
    resetMocks: true
  }
})

Mejores prácticas

  • Mockea solo lo necesario: no mockees todo, solo dependencias externas
  • Limpia mocks entre tests: usa clearMocks: true
  • Restaura mocks: usa mockRestore() para spies
  • Sé específico: verifica argumentos y retornos exactos
  • No over-mockees: si mockeas demasiado, el test pierde valor
  • Mockea en el nivel correcto: módulos externos sí, código interno no

Resumen

  • Spies: espían funciones reales sin cambiar su comportamiento
  • Mock functions: reemplazan funciones con implementaciones simuladas
  • Mock de módulos: reemplazan módulos completos
  • Mock de fetch: simula llamadas HTTP
  • Mock de timers: controla setTimeout, setInterval
  • Verificaciones: toHaveBeenCalled, toHaveReturned, etc.
  • Limpieza: clearMocks, restoreMocks entre tests
