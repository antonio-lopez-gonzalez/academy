React.memo

Módulo 11 · Optimización

Introducción

React.memo es una herramienta de optimización que evita re-renders innecesarios en componentes que reciben las mismas props. Es como decirle a React: "si las props no cambian, no necesitas re-renderizar este componente".

Es especialmente útil para componentes que:

  • Son costosos de renderizar (listas grandes, cálculos complejos)
  • Reciben props que no cambian frecuentemente
  • Se re-renderizan porque el padre se actualiza, aunque sus props no cambien

¿Cómo funciona?

React.memo memoriza el resultado del render. Si las props no cambian entre renders, React reutiliza el último resultado en lugar de volver a renderizar. 

import { memo } from 'react';

// Componente normal: se re-renderiza siempre que el padre lo haga
function ExpensiveComponent({ data }) {
  console.log('Renderizando ExpensiveComponent');
  return <div>{data.value}</div>;
}

// Componente memorizado: solo se re-renderiza si cambian las props
const MemoizedComponent = memo(ExpensiveComponent);

// También puedes escribirlo así:
const MemoizedComponent = memo(function ExpensiveComponent({ data }) {
  console.log('Renderizando ExpensiveComponent');
  return <div>{data.value}</div>;
});

Ejemplo práctico

import { useState, memo } from 'react';

// Componente hijo costoso
const ExpensiveList = memo(function ExpensiveList({ items }) {
  console.log('ExpensiveList renderizado');
  
  return (
    <ul>
      {items.map(item => (
        <li key={item.id}>{item.name}</li>
      ))}
    </ul>
  );
});

// Componente padre
function App() {
  const [count, setCount] = useState(0);
  const [text, setText] = useState('');
  
  // items se define fuera o con useMemo para que no cambie
  const items = [
    { id: 1, name: 'Item 1' },
    { id: 2, name: 'Item 2' },
    { id: 3, name: 'Item 3' },
  ];
  
  return (
    <div>
      <button onClick={() => setCount(c => c + 1)}>
        Count: {count}
      </button>
      
      <input 
        value={text} 
        onChange={(e) => setText(e.target.value)} 
      />
      
      {/* ExpensiveList no se re-renderiza aunque cambie count o text */}
      <ExpensiveList items={items} />
    </div>
  );
}

Resultado: Cuando cambias count o text, el padre se re-renderiza, pero ExpensiveList no (porque items no cambia).

Comparación de props

Por defecto, React.memo compara las props con una comparación superficial (===). Esto funciona bien para valores primitivos, pero puede fallar con objetos y arrays. 

// ❌ Problema: objeto nuevo en cada render
function Parent() {
  const [count, setCount] = useState(0);
  
  // style se recrea en cada render
  const style = { color: 'blue' };
  
  return (
    <div>
      <button onClick={() => setCount(c => c + 1)}>
        Count: {count}
      </button>
      
      {/* Memo no funciona porque style es un objeto nuevo */}
      <MemoizedChild style={style} />
    </div>
  );
}

const MemoizedChild = memo(function Child({ style }) {
  console.log('Child renderizado');
  return <div style={style}>Hijo</div>;
});

// ✅ Solución 1: objeto estable fuera del render
const STYLE = { color: 'blue' };

function Parent() {
  const [count, setCount] = useState(0);
  
  return (
    <div>
      <button onClick={() => setCount(c => c + 1)}>
        Count: {count}
      </button>
      <MemoizedChild style={STYLE} />
    </div>
  );
}

// ✅ Solución 2: useMemo para memorizar el objeto
import { useMemo } from 'react';

function Parent() {
  const [count, setCount] = useState(0);
  
  const style = useMemo(() => ({ color: 'blue' }), []);
  
  return (
    <div>
      <button onClick={() => setCount(c => c + 1)}>
        Count: {count}
      </button>
      <MemoizedChild style={style} />
    </div>
  );
}

Comparación personalizada

Puedes proporcionar una función de comparación personalizada como segundo argumento de memo. 

const MemoizedComponent = memo(
  function Component({ data }) {
    return <div>{data.value}</div>;
  },
  // Función de comparación personalizada
  (prevProps, nextProps) => {
    // Retorna true si las props son iguales (no re-renderiza)
    // Retorna false si las props son diferentes (re-renderiza)
    return prevProps.data.id === nextProps.data.id;
  }
);

Nota: Solo usa comparación personalizada si realmente la necesitas. La comparación superficial es suficiente en la mayoría de casos.

Combinando con useCallback

Si pasas funciones como props, necesitas useCallback para que React.memo funcione correctamente. 

import { useState, memo, useCallback } from 'react';

const Button = memo(function Button({ onClick, children }) {
  console.log('Button renderizado');
  return <button onClick={onClick}>{children}</button>;
});

function App() {
  const [count, setCount] = useState(0);
  
  // ❌ Mal: función nueva en cada render
  // const handleClick = () => setCount(c => c + 1);
  
  // ✅ Bien: función memorizada
  const handleClick = useCallback(() => {
    setCount(c => c + 1);
  }, []);
  
  return (
    <div>
      <p>Count: {count}</p>
      <Button onClick={handleClick}>Incrementar</Button>
    </div>
  );
}

¿Cuándo NO usar React.memo?

  • Componentes simples: si el render es rápido, no vale la pena
  • Props que cambian siempre: si las props cambian en cada render, memo no ayuda
  • Componentes que siempre se re-renderizan: si el componente necesita actualizarse siempre, memo es overhead innecesario

Regla: Solo usa React.memo cuando hayas medido un problema de rendimiento y hayas identificado que ese componente se re-renderiza innecesariamente.

Ejercicio

  1. Crea un componente padre con un contador y un input
  2. Crea un componente hijo costoso (con console.log)
  3. Observa cómo se re-renderiza el hijo cuando cambia el padre
  4. Envuelve el hijo con React.memo
  5. Verifica que ahora solo se re-renderiza cuando cambian sus props
  6. Prueba pasar un objeto como prop y observa el problema
  7. Soluciona el problema con useMemo o moviendo el objeto fuera

Resumen

  • React.memo evita re-renders si las props no cambian
  • Usa comparación superficial por defecto (shallow comparison)
  • Para objetos/arrays, asegúrate de que sean estables (fuera del render o con useMemo)
  • Para funciones, usa useCallback
  • Solo úsalo cuando hayas medido un problema de rendimiento
  • No lo uses en componentes simples o que siempre cambian
