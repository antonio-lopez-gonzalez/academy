Estado con arrays y objetos

Módulo 4 · Estado ⏱ 35 minutos

1 · Introducción

Hasta ahora hemos guardado en estado números, strings y booleanos: datos simples. Pero las aplicaciones reales viven de colecciones y objetos: listas de tareas, perfiles de usuario, carritos de compra, tableros Kanban. Hoy aprendemos a manejarlos en React, y aquí es donde la cosa se pone interesante — y donde aparecen los bugs más sutiles.

La diferencia fundamental: los datos simples (números, strings) son copias automáticas en JavaScript; los arrays y objetos son referencias compartidas. Eso cambia TODO. Si haces const b = a con un número, b es independiente. Si lo haces con un array, ambos apuntan al MISMO array en memoria. Y React detecta cambios comparando referencias, no contenido.

⚠ La regla de oro de esta lección

NUNCA mutar el estado directamente. Nada de push, sort, item.done = true. Siempre crear un array/objeto NUEVO (con spread, filter, map). ¿Por qué? Porque React compara referencias para saber si algo cambió. Si mutas, la referencia es la misma y React no se entera.

Al final de esta lección tendrás un toolkit completo: añadir, borrar, actualizar, reordenar — todo sin mutar. Y entenderás por qué funciona así (la próxima lección profundiza en la inmutabilidad; hoy practicamos el «cómo»).

2 · Teoría

Valores vs referencias en JavaScript

JavaScript tiene dos mundos: primitivos (number, string, boolean, null, undefined, symbol, bigint) y objetos (arrays, objetos, funciones, fechas…). La diferencia es crucial: 

// PRIMITIVOS: copias automáticas
let a = 5;
let b = a;      // b es una COPIA independiente
b = 10;
console.log(a); // 5 (a no cambió)

// OBJETOS: referencias compartidas
let arr1 = [1, 2, 3];
let arr2 = arr1;      // arr2 apunta al MISMO array
arr2.push(4);
console.log(arr1);    // [1, 2, 3, 4] (¡arr1 también cambió!)
console.log(arr1 === arr2); // true (misma referencia)

React usa Object.is (o === para la mayoría de casos) para comparar el estado anterior con el nuevo. Si la referencia es la misma, asume que nada cambió y no re-renderiza. Por eso mutar el array del estado es invisible para React: la referencia no cambia.

El toolkit de operaciones inmutables

Para cada operación típica con arrays, hay una forma que crea un array nuevo (inmutable) y otra que muta el original (prohibida en React):

Operación✔ Inmutable (crea nuevo)✘ Mutante (prohibido)
Añadir al final [...arr, item] arr.push(item)
Añadir al inicio [item, ...arr] arr.unshift(item)
Borrar por índice arr.filter((_, i) => i !== index) arr.splice(index, 1)
Borrar por id arr.filter(item => item.id !== id) —
Actualizar uno arr.map(item => item.id === id ? { ...item, done: true } : item) arr[i].done = true
Ordenar [...arr].sort(comparator) o arr.toSorted(comparator) arr.sort(comparator)
Invertir [...arr].reverse() o arr.toReversed() arr.reverse()

Fíjate en el patrón: spread crea una copia superficial, filter y map siempre devuelven arrays nuevos. Los métodos modernos toSorted y toReversed (ES2023) son inmutables por diseño.

Objetos: actualizar una propiedad sin perder las demás

Con objetos, el patrón es siempre el mismo: spread para copiar todo, luego sobrescribir lo que cambia: 

const [user, setUser] = useState({
  name: "Ada",
  email: "ada@example.com",
  plan: "pro",
});

// Cambiar solo el email:
setUser({ ...user, email: "nuevo@example.com" });
// { ...user } copia name y plan; "email:" sobrescribe esa clave.

// Cambiar múltiples:
setUser({ ...user, name: "Grace", plan: "free" });

Importante: el spread es superficial. Si tienes objetos anidados, necesitas spread en cada nivel: 

const [profile, setProfile] = useState({
  personal: { name: "Ada", age: 36 },
  work: { company: "ACME", role: "CTO" },
});

// Cambiar solo el nombre (anidado):
setProfile({
  ...profile,                    // copia el nivel 1 (personal, work)
  personal: {
    ...profile.personal,         // copia el nivel 2 (name, age)
    name: "Grace",               // sobrescribe name
  },
});

Si tienes más de 2-3 niveles de anidación, considera aplanar el estado o usar useReducer (Módulo 10). El estado profundo es difícil de mantener inmutable.

¿Múltiples useState o un objeto?

Pregunta frecuente: ¿uso tres useState separados o uno con un objeto? Regla práctica:

  • Estados independientes (que cambian en eventos distintos): separados. Ejemplo: name, email, age en un formulario — cada input tiene su propio onChange.
  • Estados que cambian juntos (en el mismo evento): agrupados en objeto. Ejemplo: un perfil de usuario que se actualiza completo al guardar.
  • Arrays de objetos: siempre un useState con el array. No intentes un useState por elemento.
📌 Comparación con otros frameworks

.NET (Blazor): usas propiedades del componente y llamas a StateHasChanged(). No hay inmutabilidad forzada: puedes mutar listas y Blazor re-renderiza igual (porque StateHasChanged es explícito).

Angular: la detección de cambios compara referencias por defecto (con OnPush), similar a React. Pero Angular tiene ngModel que muta directamente; React prefiere el flujo unidireccional con setters.

Vue: usa reactividad profunda (proxies). Puedes mutar state.items.push(x) y Vue lo detecta. React no: necesita que le des un array nuevo.

3 · Ejemplo mínimo

Una lista de etiquetas (tags): añadir y borrar. Ejecutable en ejemplos/m04-estado (sección 3, primer demo):

src/components/ArrayStateDemo.jsx (extracto)
import { useState } from "react";

let nextId = 4; // ids fuera del componente: no dependen del render

export default function ArrayStateDemo() {
  const [items, setItems] = useState([
    { id: 1, text: "Aprender useState" },
    { id: 2, text: "Entender el batching" },
    { id: 3, text: "Practicar con arrays" },
  ]);
  const [text, setText] = useState(""); // input controlado

  function addItem(e) {
    e.preventDefault();
    const trimmed = text.trim();
    if (trimmed === "") return; // guard clause
    // AÑADIR sin mutar: array nuevo con spread + el elemento al final
    setItems([...items, { id: nextId++, text: trimmed }]);
    setText("");
  }

  function removeItem(id) {
    // BORRAR sin mutar: filter devuelve SIEMPRE un array nuevo
    setItems(items.filter((item) => item.id !== id));
  }

  return (
    <div>
      <form onSubmit={addItem}>
        <input value={text} onChange={(e) => setText(e.target.value)} />
        <button type="submit">Añadir</button>
      </form>
      <ul>
        {items.map((item) => (
          <li key={item.id}>
            {item.text}{" "}
            <button onClick={() => removeItem(item.id)}>🗑</button>
          </li>
        ))}
      </ul>
    </div>
  );
}

Línea por línea:

  1. nextId fuera del componente: no queremos que se reinicie en cada render. Es un contador global del módulo.
  2. setItems([...items, newItem]): spread copia todos los elementos existentes, y añadimos el nuevo al final. Array nuevo → React re-renderiza.
  3. items.filter(item => item.id !== id): filter siempre devuelve un array nuevo (aunque tenga los mismos elementos). React detecta el cambio.
  4. key={item.id}: la key estable del Módulo 2. Si usáramos el índice y reordenáramos, React perdería la pista de qué elemento es cuál.

4 · Ejemplo real

Una ficha de empleado: objeto con datos personales + array de habilidades. Combina ambos mundos (objeto y array) en un solo componente, con operaciones anidadas:

src/components/EmployeeProfile.jsx
import { useState } from "react";

export default function EmployeeProfile() {
  // Estado 1: objeto con datos personales
  const [employee, setEmployee] = useState({
    name: "Ada Lovelace",
    email: "ada@example.com",
    department: "Engineering",
  });

  // Estado 2: array de habilidades (strings simples)
  const [skills, setSkills] = useState(["JavaScript", "React", "Node.js"]);
  const [newSkill, setNewSkill] = useState("");

  // Actualizar un campo del objeto (sin perder los demás)
  function handleFieldChange(field, value) {
    setEmployee({ ...employee, [field]: value });
    // [field]: value es "computed property name" de ES6:
    // si field = "name", equivale a { name: value }
  }

  // Añadir habilidad (sin duplicados)
  function addSkill(e) {
    e.preventDefault();
    const trimmed = newSkill.trim();
    if (trimmed === "" || skills.includes(trimmed)) return;
    setSkills([...skills, trimmed]);
    setNewSkill("");
  }

  // Borrar habilidad
  function removeSkill(skill) {
    setSkills(skills.filter((s) => s !== skill));
  }

  // Actualizar habilidad (reemplazar una por otra)
  function updateSkill(oldSkill, newSkill) {
    setSkills(skills.map((s) => (s === oldSkill ? newSkill : s)));
  }

  return (
    <div>
      <h2>Ficha de empleado</h2>

      {/* Formulario del objeto: cada input actualiza UNA propiedad */}
      <label>
        Nombre:
        <input
          value={employee.name}
          onChange={(e) => handleFieldChange("name", e.target.value)}
        />
      </label>
      <label>
        Email:
        <input
          value={employee.email}
          onChange={(e) => handleFieldChange("email", e.target.value)}
        />
      </label>
      <label>
        Departamento:
        <select
          value={employee.department}
          onChange={(e) => handleFieldChange("department", e.target.value)}
        >
          <option value="Engineering">Engineering</option>
          <option value="Design">Design</option>
          <option value="Marketing">Marketing</option>
        </select>
      </label>

      {/* Lista de habilidades: añadir, borrar, actualizar */}
      <h3>Habilidades</h3>
      <form onSubmit={addSkill}>
        <input
          value={newSkill}
          onChange={(e) => setNewSkill(e.target.value)}
          placeholder="Nueva habilidad…"
        />
        <button type="submit">Añadir</button>
      </form>
      <ul>
        {skills.map((skill) => (
          <li key={skill}>
            {skill}{" "}
            <button onClick={() => removeSkill(skill)}>🗑</button>
            <button
              onClick={() => {
                const updated = prompt("Nueva habilidad:", skill);
                if (updated && updated !== skill) updateSkill(skill, updated);
              }}
            >
              ✏️
            </button>
          </li>
        ))}
      </ul>
    </div>
  );
}

Decisiones explicadas:

  • Dos estados separados (employee y skills): cambian en eventos distintos (inputs vs botones de habilidades). Agruparlos en un objeto grande complicaría los setters.
  • handleFieldChange(field, value): un solo manejador genérico para los tres inputs. La técnica [field]: value (computed property name) permite reutilizar lógica.
  • Guard clause en addSkill: no añadimos vacíos ni duplicados (skills.includes). Las reglas de negocio van en los manejadores, no en la UI.
  • updateSkill con map: reemplaza un elemento por otro sin mutar. Es el patrón para «editar en línea» (aunque aquí usamos prompt por simplicidad; en producción sería un input inline).
  • Keys por valor (key={skill}): las habilidades son strings únicos, así que el valor mismo sirve como key. Si pudieran repetirse, necesitaríamos ids.

5 · Buenas prácticas

HazEvitaPor qué
Usar id único por elemento de array (UUID, contador global, timestamp) Usar el índice como key si el array se reordena React usa la key para reconciliar: si reordenas con key=índice, React pierde la pista de qué elemento es cuál y puede mostrar datos mezclados.
Spread + sobrescritura para actualizar objetos Mutar propiedades directamente (user.name = "nuevo") React compara referencias: si mutas, la referencia es la misma y no re-renderiza.
filter, map, spread para arrays push, splice, sort sobre el array del estado Los métodos mutantes no crean arrays nuevos: React no detecta el cambio.
Estados separados si cambian en eventos distintos Agrupar todo en un objeto gigante «por si acaso» Estados independientes = setters independientes. Más claro y menos re-renders innecesarios.
Considerar useReducer si el estado es complejo (Módulo 10) Anidar objetos 4+ niveles con spread manual El spread profundo es verboso y propenso a errores. useReducer centraliza la lógica de actualización.

6 · Errores habituales

Error 1: mutar con push/splice/sort

✘ Incorrecto 
function addItem() {
  items.push(newItem);      // ✘ muta el array del estado
  setItems(items);          // misma referencia → React no repinta
}

function sortItems() {
  items.sort();             // ✘ muta in-place
  setItems(items);          // React no ve el cambio
}
✔ Correcto 
function addItem() {
  setItems([...items, newItem]);   // ✔ array nuevo con spread
}

function sortItems() {
  setItems([...items].sort());     // ✔ copia primero, luego ordena
  // o en ES2023: setItems(items.toSorted());
}

Error 2: mutar una propiedad de un objeto anidado

✘ Incorrecto 
function updateName(newName) {
  employee.name = newName;         // ✘ muta el objeto del estado
  setEmployee(employee);           // misma referencia → no repinta
}
✔ Correcto 
function updateName(newName) {
  setEmployee({ ...employee, name: newName });  // ✔ objeto nuevo
}

Error 3: mutar dentro de map

✘ Incorrecto 
function toggleDone(id) {
  setTasks(
    tasks.map((task) => {
      if (task.id === id) {
        task.done = !task.done;    // ✘ muta el objeto task
      }
      return task;                 // devuelve el mismo objeto mutado
    })
  );
}
✔ Correcto 
function toggleDone(id) {
  setTasks(
    tasks.map((task) =>
      task.id === id
        ? { ...task, done: !task.done }  // ✔ objeto nuevo con spread
        : task                            // los demás, sin cambios
    )
  );
}

Error 4: olvidar el spread en objetos anidados

✘ Incorrecto 
// profile = { personal: { name, age }, work: { company } }
function updateAge(newAge) {
  setProfile({
    ...profile,
    personal: { name: profile.personal.name, age: newAge },  // ✘ pierdes
                                                              // otras props
                                                              // si las hubiera
  });
}
✔ Correcto 
function updateAge(newAge) {
  setProfile({
    ...profile,
    personal: {
      ...profile.personal,  // ✔ copia todas las props del nivel 2
      age: newAge,          // sobrescribe solo age
    },
  });
}

Error 5: usar índice como key al reordenar

✘ Incorrecto 
// Si el array se reordena, key={index} confunde a React
{tasks.map((task, index) => (
  <li key={index}>{task.text}</li>  // ✘ si reordenas, React pierde la pista
))}
✔ Correcto 
{tasks.map((task) => (
  <li key={task.id}>{task.text}</li>  // ✔ key estable por id
))}

7 · Ejercicio guiado

Construimos una mini playlist: array de canciones con añadir, borrar y reordenar (subir/bajar). El reordenamiento es el caso más complejo de arrays en React.

  1. Crea Playlist.jsx con estado: const [songs, setSongs] = useState([{ id: 1, title: "Bohemian Rhapsody" }, { id: 2, title: "Imagine" }, { id: 3, title: "Hotel California" }]). Usa un contador nextId fuera del componente.

  2. Formulario para añadir: input controlado + setSongs([...songs, { id: nextId++, title }]). Renderiza con map y key={song.id}.

  3. Botón borrar por canción: setSongs(songs.filter(s => s.id !== song.id)). Comprueba que funciona.

  4. Subir una canción (el reto): dado un index, intercambia con el anterior. Algoritmo: copia el array ([...songs]), usa destructuring para intercambiar posiciones ([copy[i-1], copy[i]] = [copy[i], copy[i-1]]), y setSongs(copy). Añade un botón «↑» que llame a esta función con el índice actual (pásalo desde el map).

  5. Bajar una canción: misma lógica pero intercambia con index + 1. Desactiva el botón si es la última.

  6. Verifica en la consola: cada click debe producir UN solo «RENDER» (si añades un log). El batching funciona también con operaciones complejas de array.

8 · Reto

🎯 Lista de la compra con cantidades

Crea un componente ShoppingList con un array de objetos {'[{ id, name, quantity }]'}:

  1. Formulario para añadir productos (inicialmente con cantidad 1).
  2. Para cada producto: botones «+» y «−» que incrementan/decrementan la cantidad (mínimo 1). Pista: map + spread para actualizar solo ese producto.
  3. Botón borrar por producto.
  4. Valores derivados (sin estado extra): total de productos (reduce de cantidades), número de líneas (length del array).
  5. Bonus: botón «Vaciar lista» que resetea el array a vacío.

9 · Resumen

  • Arrays y objetos son referencias en JavaScript: copiarlos con = no crea uno nuevo, solo otra referencia al mismo.
  • React detecta cambios comparando referencias (Object.is): si mutas el array/objeto del estado, la referencia es la misma y React no re-renderiza.
  • Toolkit inmutable: spread para copiar, filter para borrar, map para actualizar, [...arr].sort() para ordenar.
  • Objetos: {'{ ...obj, key: newValue }'} para actualizar una propiedad sin perder las demás.
  • Objetos anidados: spread en cada nivel (o considera aplanar el estado si es muy profundo).
  • ¿Múltiples useState o un objeto? Separados si cambian en eventos distintos; agrupados si cambian juntos.
  • Keys estables por id, no por índice (especialmente si reordenas).

10 · Preguntas frecuentes

¿No es ineficiente copiar arrays grandes con spread?

No tanto como parece. Copiar un array de 1000 elementos cuesta microsegundos (son referencias, no copias profundas). Lo caro es tocar el DOM, y React solo toca lo que cambió. Si tienes arrays de 100.000+ elementos, considera virtualización (react-window), pero no optimices prematuramente.

¿Puedo usar Immer para simplificar la inmutabilidad?

Sí, Immer es una librería que te permite escribir código «como si mutaras» y produce objetos inmutables por detrás. Redux Toolkit la incluye por defecto (Módulo 10). Para useState puro, el spread es suficiente y no añade dependencias.

¿Por qué filter y map siempre devuelven arrays nuevos?

Por diseño de JavaScript: son métodos «puros» que no modifican el array original, sino que construyen uno nuevo. Por eso son seguros en React: garantizan una referencia distinta.

¿Puedo usar splice si primero copio el array?

Sí: const copy = [...arr]; copy.splice(index, 1); setItems(copy); funciona porque copy es un array nuevo. Pero es más verboso que filter y menos idiomático en React.

¿toSorted y toReversed están soportados en todos los navegadores?

Son de ES2023. Funcionan en navegadores modernos (Chrome 110+, Firefox 115+, Safari 16+). Si necesitas soporte amplio, usa [...arr].sort() o [...arr].reverse().
