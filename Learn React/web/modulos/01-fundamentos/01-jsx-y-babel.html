JSX y el compilador

Módulo 1 · Fundamentos ⏱ 35 minutos

1 · Introducción

En el Módulo 0 vimos que un componente «devuelve una descripción de la UI». Ahora toca mirar esa descripción de cerca: se escribe con JSX, la sintaxis que parece HTML dentro de JavaScript. En esta lección aprenderás qué es JSX de verdad (pista: no es HTML), en qué se convierte antes de llegar al navegador y quién hace esa traducción (antes Babel, hoy Vite usa esbuild).

Por qué existe: porque escribir interfaces como árboles de llamadas createElement anidadas es ilegible. JSX te deja escribir la UI de forma declarativa y familiar, y un compilador la traduce por ti.

Cuándo se utiliza: siempre. Todo componente React se escribe con JSX (podrías no usarlo, pero nadie lo hace). Entender su naturaleza evita los errores más comunes de los primeros meses.

Errores típicos: creer que JSX «es HTML», usar class en lugar de className, olvidar cerrar etiquetas, o devolver varios elementos sueltos.

2 · Teoría

JSX no es HTML: es azúcar sobre JavaScript

Aquí está la verdad que cambia tu comprensión de React para siempre. Este JSX: 

const elemento = <h1 className="titulo">Hola</h1>;

…se compila a una llamada JavaScript pura. Con el compilador moderno (el «automatic JSX runtime» que usa React 19):

import { jsx as _jsx } from "react/jsx-runtime";

const elemento = _jsx("h1", {
  className: "titulo",
  children: "Hola",
});

Y esa función devuelve… un objeto plano de JavaScript: el elemento virtual que vimos en la lección del Virtual DOM. Es decir:

LO QUE ESCRIBES COMPILADOR LO QUE ES EN REALIDAD ─────────────── ────────── ───────────────────── <h1>Hola</h1> ───► jsx("h1", …) ───► { type: "h1", props: { children: "Hola" }, key: null, … } JSX = una SINTAXIS cómoda para crear objetos que describen la UI.

Consecuencias que debes interiorizar:

  • JSX es una expresión de JavaScript: puedes asignarlo a variables, pasarlo como argumento, devolverlo de funciones, meterlo en un if…
  • El navegador nunca ve JSX: ve el JavaScript compilado.
  • Las «etiquetas» minúsculas (<h1>) se compilan a strings ("h1" = elemento del DOM); las mayúsculas (<UserCard />) se compilan a referencias a tus funciones (jsx(UserCard, …)). Por eso la regla de PascalCase del Módulo 0 es obligatoria, no estética.

¿Quién compila JSX? De Babel a esbuild

Babel fue el compilador histórico: traducía JSX y sintaxis moderna a JavaScript que cualquier navegador entendiera. React lo usó desde el principio, y por eso «JSX y Babel» siguen apareciendo juntos en tutoriales antiguos.

Hoy Vite usa esbuild. Esbuild está escrito en Go y es 10-100x más rápido que Babel. Convierte JSX en cada guardado en milisegundos. El concepto es idéntico: existe un paso de compilación entre lo que escribes y lo que ejecuta el navegador. Tú no lo invocas a mano: Vite lo hace por ti en cada guardado (HMR).

TU CÓDIGO VITE (dev) NAVEGADOR ────────── ─────────── ────────── App.jsx (JSX) ──► esbuild transforma ──► JS puro que JSX → js() calls sí entiende (en milisegundos)

Las 6 reglas de JSX (apréndetelas como la tabla de multiplicar)

  1. Un único elemento raíz por return. Una función devuelve UN valor; JSX es ese valor. Para agrupar sin añadir un div al DOM se usa un Fragment (<>…</>, lección 4 de este módulo).
  2. Toda etiqueta debe cerrarse. En HTML puedes escribir <br> o <img …> sin cerrar; en JSX no: <br />, <img … />, <input … />.
  3. JavaScript dentro de llaves { }. Todo lo que va entre llaves se evalúa como expresión JS: {nombre}, {2 + 2}, {user.age > 18 ? "mayor" : "menor"}. (Detalle completo en la lección 3.)
  4. Atributos en camelCase. JSX son propiedades de un objeto JS, no atributos HTML: className (no class, palabra reservada de JS), htmlFor (no for), onClick, tabIndex, readOnly…
  5. Estilos como objeto, no como string. style={{ color: "red", fontSize: 20 }} — doble llave: una para la expresión JS, otra para el objeto. Las propiedades CSS van en camelCase (fontSize, no font-size) y los números son píxeles.
  6. Comentarios dentro de JSX: {/* así */}. El clásico <!-- --> no existe dentro de JSX porque ya estás en tierra de JavaScript.

Comparación con el mundo que conoces

TecnologíaEquivalente a JSX
ASP.NETRazor (@ para mezclar C# con HTML). Misma idea, pero Razor se ejecuta en el servidor y JSX en el cliente/build.
AngularTemplates con directivas (*ngIf). Angular añade sintaxis NUEVA al HTML; JSX usa JavaScript normal dentro de llaves.
VueTemplates con v-if/v-for (o JSX opcional). Vue separa; JSX funde.
PHPMezclar <?php ?> con HTML, pero en servidor y sin componentes.
💡 ¿Por qué React mezcla HTML y JS en vez de separarlos?

Porque en una UI moderna el marcado y su lógica ya están acoplados: el botón y lo que hace el botón cambian juntos. Separar por tecnología (HTML aquí, JS allá) obliga a mantener dos archivos sincronizados a mano. React separa por funcionalidad: todo lo del botón vive junto en un componente. La historia le dio la razón: Vue ofrece JSX opcional, Svelte y Solid nacieron directamente con sintaxis tipo JSX.

3 · Ejemplo mínimo

El componente más pequeño que usa las reglas básicas de JSX:

src/App.jsx
function App() {
  // JSX es una expresión: se puede guardar en una variable
  const saludo = <h1 className="titulo">Hola, JSX</h1>;

  return (
    <div>
      {saludo}                       <!-- regla 3: JS entre llaves -->
      <p>2 + 2 = {2 + 2}</p>      <!-- expresiones evaluadas -->
      <img src="/logo.svg" alt="logo" />  <!-- regla 2: autocierre -->
    </div>
  );                                 <!-- regla 1: UN solo padre (<div>) -->
}

export default App;

Línea por línea:

  1. const saludo = <h1 …>; — demuestra que JSX es una expresión: se asigna como cualquier valor.
  2. className= — regla 4: nunca class en JSX.
  3. {saludo} — dentro de las llaves va JavaScript: aquí, la variable.
  4. {2 + 2} — cualquier expresión válida se evalúa y se pinta su resultado: «4».
  5. <img … /> — las etiquetas vacías SIEMPRE se cierran con />.
  6. El return devuelve un único <div> que envuelve todo lo demás.

4 · Ejemplo real

Una tarjeta de usuario típica aplicando TODAS las reglas (este componente es el germen del proyecto del módulo; el código completo ejecutable está en ejemplos/m01-fundamentos):

src/components/UserCard.jsx
// Tarjeta de perfil: JSX en contexto profesional
function UserCard() {
  // --- Datos (en el Módulo 4 serán estado; hoy son constantes) ---
  const user = {
    name: "Ana García",
    role: "Frontend Developer",
    avatarUrl: "https://i.pravatar.cc/150?img=47",
    isOnline: true,
  };

  // --- Datos calculados ANTES del return: mantén el JSX limpio ---
  const statusText = user.isOnline ? "En línea" : "Desconectada";

  return (
    <article className="user-card">
      {/* regla: comentarios dentro de JSX van entre llaves */}
      <img
        className="user-card__avatar"
        src={user.avatarUrl}
        alt={"Avatar de " + user.name}   // cualquier expresión vale
      />
      <h2>{user.name}</h2>
      <p>{user.role}</p>

      {/* Estilo inline calculado: objeto JS en camelCase */}
      <span style={{ color: user.isOnline ? "green" : "gray" }}>
        ● {statusText}
      </span>
    </article>
  );
}

export default UserCard;

Decisiones explicadas:

  • Datos arriba, JSX abajo: separar la preparación de datos del marcado hace el JSX legible. Los ternarios cortos caben en las llaves; la lógica compleja se calcula antes del return.
  • alt siempre: accesibilidad desde el minuto uno (y es un atributo obligatorio por buenas prácticas web, no cosa de React).
  • El estilo inline es correcto para valores calculados (como este color); para estilos fijos usaremos clases CSS (Módulo 7).
  • Nombres de clase con convención BEM (user-card__avatar): la veremos en el Módulo 7.
🔍 DevTools: ve el árbol de componentes

Con el proyecto arrancado, abre React DevTools (F12 → pestaña Components). Verás el árbol App → UserCard con sus props a la derecha. Acostúmbrate a depurar con esta vista y no solo con «Elements» del navegador: en React piensas en componentes, no en divs.

5 · Buenas prácticas

6 · Errores habituales

Error 1: class en lugar de className

✘ Incorrecto 
<div class="card">Hola</div>
// La consola avisa: "Invalid DOM property `class`. Did you mean `className`?"
✔ Correcto 
<div className="card">Hola</div>

Por qué: class es palabra reservada de JavaScript (clases ES6). Como JSX compila a objetos JS, sus «atributos» son propiedades: className, igual que en el DOM (element.className).

Error 2: return con salto de línea (el bug fantasma de la pantalla en blanco)

✘ Incorrecto 
function App() {
  return          // ← JavaScript inserta aquí un ";" invisible (ASI)
    <div>Hola</div>;  // …y esto nunca se ejecuta. Devuelve undefined.
}
✔ Correcto 
function App() {
  return (          // ← el paréntesis «congela» el ASI
    <div>Hola</div>
  );
}

Error 3: for en un label

✘ Incorrecto 
<label for="email">Email</label>   // for es palabra reservada en JS
✔ Correcto 
<label htmlFor="email">Email</label>

Error 4: estilo como string

✘ Incorrecto 
<p style="color: red; font-size: 20px">Hola</p>
✔ Correcto 
<p style={{ color: "red", fontSize: 20 }}>Hola</p>
//         ↑ expresión JS   ↑ objeto con propiedades camelCase

7 · Ejercicio guiado

Vamos a crear tu primer componente con JSX en el proyecto que montaste en la lección anterior (o crea uno nuevo con pnpm create vite@latest jsx-practica -- --template react):

  1. En src/App.jsx, declara estos datos fuera del return:

    const framework = "React";
const version = 19;
const temas = ["JSX", "componentes", "props"];

  2. Escribe JSX que muestre: un <h1> con «Estoy aprendiendo {framework} {version}» (usa llaves), un párrafo con el número de temas ({temas.length}) y el primero ({temas[0]}).

  3. Añade una clase CSS: crea en src/index.css la regla .titulo { color: #61dafb; } y aplícala al h1 con className.

  4. Provoca a propósito el error de etiqueta sin cerrar (quita un />) y lee el mensaje de Vite en el navegador. Acostúmbrate a leer errores: son tus amigos.

  5. Comprueba la teoría: abre React DevTools → Components y localiza tu App. Todo lo que pintaste es su JSX compilado.

8 · Reto

🎯 JSX sin JSX

Para consolidar que JSX es solo sintaxis:

  1. Abre la consola de tu app (F12) y pega: import("react/jsx-runtime")… mejor: en App.jsx escribe temporalmente el componente SIN JSX, usando jsx() importado de "react/jsx-runtime". ¿Funciona? ¿Es más o menos legible?
  2. Crea un componente SkillBadge que reciba… (adelanto: aún no sabemos props; hardcodea por ahora) un nombre de tecnología y un nivel, y muéstralos con una clase badge y estilo inline con borderRadius: 999.
  3. Explica en un comentario, con tus palabras, por qué <img> se compila a jsx("img", …) pero <SkillBadge /> a jsx(SkillBadge, …).

9 · Resumen

  • JSX es sintaxis que compila a llamadas jsx(), las cuales crean objetos que describen la UI (elementos virtuales).
  • El navegador nunca ve JSX: Vite (esbuild, antes Babel) lo transforma en cada guardado.
  • Minúscula = etiqueta del DOM; Mayúscula = tu componente. No es convención: es cómo compila.
  • Las 6 reglas: un elemento raíz, todo cerrado, JS entre llaves {}, atributos camelCase (className, htmlFor), estilos como objeto, comentarios {/* */}.
  • En las llaves solo caben expresiones (producen valor), no statements (if/for clásicos).
  • JSX mezcla HTML y JS a propósito: separa por funcionalidad (componentes), no por tecnología.

10 · Preguntas frecuentes

¿Puedo usar React sin JSX?

Técnicamente sí (jsx() o React.createElement directamente), pero nadie lo hace: es ilegible para UIs reales. JSX es el estándar universal.

¿Por qué a veces veo imports de React que no se usan?

Código antiguo: antes de React 17, JSX compilaba a React.createElement y había que importar React en cada archivo. Con el «automatic runtime» de React 19 ya no hace falta; Vite lo configura por defecto.

¿JSX valida el HTML? ¿Puedo poner un <p> dentro de otro <p>?

JSX no valida anidación semántica: puedes escribir HTML inválido y compilará, pero el navegador lo «reparará» de formas impredecibles. Sigue las reglas del HTML (un <p> no contiene bloques) igual que siempre.

¿Qué pasa si pongo un objeto dentro de las llaves: {user}?

Error clásico: «Objects are not valid as a React child». React sabe pintar strings, números y elementos; no objetos planos. Debes pintar sus propiedades: {user.name}. (Para depurar objetos: {JSON.stringify(user)}.)

¿Y los booleanos/undefined/null en las llaves?

React no pinta true, false, null ni undefined (los ignora). Parece raro hasta la lección de renderizado condicional del Módulo 2, donde se convierte en tu superpoder: {hayError && <p>Error</p>}.
