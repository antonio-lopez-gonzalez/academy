Children

Módulo 1 · Fundamentos ⏱ 25 minutos

1 · Introducción

Hay una prop especial que React pasa automáticamente y que quizá ya has usado sin saber su nombre: children. Es todo lo que escribes entre la etiqueta de apertura y la de cierre de un componente: 

<Card>
  <h2>Esto es children</h2>   ← todo lo que va ENTRE las etiquetas
</Card>

children es la propiedad que convierte a React en un sistema de composición: permite crear componentes «contenedor» (Card, Modal, Layout, Page) que no saben qué contendrán — y por eso mismo sirven para todo. Es la idea más parecida a los slots de Vue o al RenderFragment de Blazor, y una de las más potentes de React.

2 · Teoría

children es simplemente una prop más (pero automática)

Cuando React compila <Card><h2>Hola</h2></Card>, crea este objeto props: 

// React construye esto por ti:
{
  children: /* elemento virtual de <h2>Hola</h2> */
}

Es decir: children no es magia, es el nombre del «hueco» donde cae todo lo que anidas. El componente Card lo recibe como cualquier otra prop y decide dónde colocarlo en su propio JSX: 

function Card({ children }) {
  return (
    <div className="card">
      {children}   {/* aquí "aterrizan" los hijos que pase el padre */}
    </div>
  );
}
CÓMO VIAJA children ─────────────────── Padre: <Card> Componente Card: <h2>Título</h2> ──► function Card({ children }) { <p>Texto</p> return <div className="card"> </Card> {children} ◄── aterrizan aquí </div>; } HTML: <div class="card"><h2>Título</h2><p>Texto</p></div>

¿Qué puede ser children? Prácticamente todo

El padre anida…children recibe…
Texto: <Button>Guardar</Button>un string
Un elemento: <Card><h2 /></Card>un elemento virtual
Varios elementosun ARRAY de elementos
Expresiones: <p>{nombre}</p>el valor evaluado
Nada: <Card />undefined
Otro componentesu elemento virtual (¡composición!)
💡 ¿Por qué children es tan importante?

Porque permite la inversión de control en la UI: el contenedor define la estructura (borde, sombra, padding) y el padre decide el contenido. Sin children, necesitarías una prop por cada cosa variable (title, body, footer…) y el componente solo serviría para UN diseño concreto. Con children, Card sirve para infinitos contenidos. Es la diferencia entre un «componente para ESTA pantalla» y un «componente de biblioteca».

3 · Ejemplo mínimo

src/components/Card.jsx
// Card es un CONTENEDOR: no sabe qué llevará dentro
export default function Card({ children }) {
  return <div className="card">{children}</div>;
}
src/App.jsx
import Card from "./components/Card.jsx";

export default function App() {
  return (
    <Card>
      <h2>Perfil de Ana</h2>
      <p>Frontend Developer</p>
    </Card>
  );
}

Línea por línea:

  1. function Card({ children }) — el componente declara la prop especial (el nombre children es fijo, no elegido).
  2. {children} dentro del div — el punto exacto donde se insertará el contenido.
  3. En App, todo lo anidado entre <Card> y </Card> viaja como esa prop y aparece dentro del .card.

4 · Ejemplo real

Un Modal genérico: la pieza que mejor demuestra el poder de children, combinada con props normales para lo configurable:

src/components/Modal.jsx
// Modal genérico: la ESTRUCTURA es fija (fondo oscuro, caja, botón
// cerrar) pero el CONTENIDO lo decide quien lo usa, vía children.
export default function Modal({ title, onClose, children }) {
  return (
    // Capa semitransparente de fondo (overlay)
    <div className="modal-overlay" onClick={onClose}>
      {/* stopPropagation: clic dentro NO cierra el modal (Módulo 3) */}
      <div className="modal" onClick={(e) => e.stopPropagation()}>
        <header className="modal__header">
          <h2>{title}</h2>
          <button className="modal__close" onClick={onClose}>✕</button>
        </header>

        <div className="modal__body">
          {children}   {/* ← el contenido lo decide el padre */}
        </div>
      </div>
    </div>
  );
}
dos usos completamente distintos del MISMO Modal
// 1. Confirmación de borrado
<Modal title="Eliminar proyecto" onClose={cerrarModal}>
  <p>Esta acción no se puede deshacer. ¿Continuar?</p>
  <button onClick={borrarProyecto}>Sí, eliminar</button>
</Modal>

// 2. Formulario de alta
<Modal title="Nuevo cliente" onClose={cerrarModal}>
  <ClientForm onSubmit={guardarCliente} />
</Modal>

Decisiones explicadas:

  • Props para lo que varía poco (title, onClose), children para el contenido libre. Esta combinación es EL patrón de los componentes contenedor.
  • El modal no conoce ni el formulario ni la confirmación: mañana alojará un visor de imágenes sin tocar su código. Abierto a extensión, cerrado a modificación (principio OCP de SOLID, en la UI).
  • Si en lugar de children usáramos <Modal content={…}>, funcionaría igual de bien (children ES una prop); la ventaja de children es la sintaxis natural de anidación, idéntica al HTML.

5 · Buenas prácticas

HazEvitaPor qué
Children para contenido libre/variable Props como bodyText para pasar marcado complejo Pasar JSX por children es más legible y flexible que strings gigantes.
Contenedores pequeños y agnósticos (Card, Modal, Section, Stack) Contenedores que asumen qué tipo de hijos recibirán Un buen contenedor funciona con cualquier contenido; si asume, deja de ser reutilizable.
Combinar children + props normales Intentar pasar TODO por children Los datos configurables (title, variant, onClose) son más claros como props con nombre.
Renderizar {children} sin transformarlo Inspeccionar/modificar los children (React.Children.*) salvo necesidad Manipular children rompe el encapsulamiento: casi siempre hay una solución mejor con composición.

6 · Errores habituales

Error 1: olvidar renderizar children

✘ Incorrecto 
function Card() {          // ← no recibe children
  return <div className="card"></div>;   // …ni lo pinta
}

<Card><h2>Hola</h2></Card>   // el h2 se PIERDE silenciosamente 😶
✔ Correcto 
function Card({ children }) {
  return <div className="card">{children}</div>;
}

Síntoma típico: «mi contenido no aparece y no hay ningún error». Primera sospecha: el contenedor no renderiza children.

Error 2: children donde no toca

✘ Confuso 
<img src="a.png">Texto</img>   // <img> no puede tener hijos (HTML)
✔ Correcto 
<img src="a.png" alt="Texto" />  // elementos vacíos HTML: sin children

Error 3: abusar de children para TODO, perdiendo semántica

✘ Poco claro 
// ¿Qué children va primero? ¿Dónde? El padre no tiene ni idea
<Dialog>
  <button>✕</button>
  <h2>Título</h2>
  <p>Contenido</p>
</Dialog>
✔ Correcto 
// Zonas con NOMBRE: props de elementos para las zonas fijas,
// children para el cuerpo libre (lección siguiente: composición)
<Dialog title="Título" onClose={cerrar}>
  <p>Contenido</p>
</Dialog>

7 · Ejercicio guiado

Vamos a crear un contenedor Section reutilizable:

  1. Crea src/components/Section.jsx:

    export default function Section({ title, children }) {
  return (
    <section className="section">
      <h2 className="section__title">{title}</h2>
      <div className="section__content">{children}</div>
    </section>
  );
}

  2. Úsalo dos veces en App con contenidos totalmente distintos: una con un párrafo, otra con una lista <ul>.

  3. Inspecciona en React DevTools: busca la prop children de cada Section y comprueba que contiene los elementos virtuales que anidaste.

  4. Anida una Section dentro de otra. Funciona sin tocar nada: eso es composición.

8 · Reto

🎯 Sistema de pestañas (Tabs) con children

Crea dos componentes:

  • <Tabs>: contenedor que pinta una fila de botones y, debajo, el contenido.
  • <Tab label="…">: recibe por children el contenido de esa pestaña.

Uso esperado:

<Tabs>
  <Tab label="Perfil"><p>Datos del perfil…</p></Tab>
  <Tab label="Ajustes"><p>Preferencias…</p></Tab>
</Tabs>

Pista: es un reto avanzado para este punto (necesitarás estado del Módulo 4 para la pestaña activa; si aún no lo has visto, deja la «pestaña activa» fija en la primera y vuelve aquí tras el Módulo 4). Puedes inspeccionar children como array.

9 · Resumen

  • children es una prop automática: todo lo anidado entre las etiquetas del componente.
  • Puede ser texto, un elemento, un array de elementos, valores evaluados… o undefined.
  • El contenedor decide DÓNDE aterriza ({children} en su JSX); el padre decide QUÉ contiene. Inversión de control en la UI.
  • Es el equivalente a los slots de Vue / ng-content de Angular / ChildContent de Blazor.
  • Patrón contenedor: props con nombre para la configuración, children para el contenido libre.
  • Error nº 1: olvidar renderizar {children} → el contenido desaparece sin errores.

10 · Preguntas frecuentes

¿Puedo tener varios «huecos» de children?

No con la prop children (es una), pero sí con props de elementos: <Layout header={…} sidebar={…}>{contenido}</Layout>. Es la técnica de la próxima lección (composición).

¿Cómo sé si children es uno o varios elementos?

No deberías necesitar saberlo: renderízalo y ya. Si de verdad debes recorrerlo (casos raros como Tabs), existe React.Children.toArray(children) que lo normaliza a array. Evítalo salvo necesidad real.

¿children puede ser una función?

Sí, es el patrón «render props» (el hijo llama a children(datos)). Era popular antes de los hooks; hoy casi todo se resuelve con custom hooks (Módulo 6). Reconócelo si lo ves en código antiguo.

¿Por qué mi texto entre componentes sale «pegado»?

JSX colapsa los espacios en blanco entre etiquetas y expresiones en líneas distintas. Usa {" "} donde necesites un espacio explícito.
