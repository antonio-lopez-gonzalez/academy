Instalación: Node, pnpm y VSCode

Módulo 0 · Preparación ⏱ 35 minutos

1 · Introducción

Antes de escribir una sola línea de React vamos a montar un entorno de trabajo profesional: Node.js (el motor que ejecuta JavaScript fuera del navegador), pnpm (el gestor de paquetes que usaremos en todo el curso) y VSCode (el editor estándar de la industria).

No nos limitaremos a «descarga y pulsa siguiente»: entenderás qué es cada herramienta y por qué la elegimos, porque un profesional debe poder justificar su toolchain. Al final de la lección tu máquina estará lista para todo el curso.

Errores típicos que evitaremos:

  • Instalar «la última versión experimental» de Node en lugar de la LTS.
  • Confundir Node (runtime) con pnpm/npm (gestores de paquetes).
  • Pelearse con PowerShell por no conocer la política de ejecución de scripts.

2 · Teoría

Node.js: JavaScript sale del navegador

JavaScript nació como lenguaje del navegador. Node.js es el motor V8 de Chrome sacado del navegador y convertido en un entorno de ejecución para tu máquina: permite ejecutar JavaScript en la terminal, leer archivos, crear servidores…

¿Y por qué necesitas Node para hacer React si React corre en el navegador? Porque las herramientas de desarrollo (Vite, el compilador de JSX, pnpm…) están escritas en JavaScript y corren sobre Node. Tu código React se construye con Node y luego se ejecuta en el navegador del usuario.

QUIÉN EJECUTA QUÉ ───────────────── Tu máquina (desarrollo): Vite + pnpm + compilador JSX ──► corren sobre NODE.JS │ ▼ genera archivos .js estáticos │ Navegador del usuario (producción): ▼ tu app React ──► corre sobre el MOTOR JS DEL NAVEGADOR

Versión a instalar: la LTS (Long Term Support). Node publica versiones pares (20, 22, 24…) que se convierten en LTS con soporte de ~3 años, e impares experimentales. Para trabajar: siempre LTS. Este curso está verificado con Node 22 LTS.

Gestores de paquetes: npm, yarn y pnpm

El ecosistema JavaScript se organiza en paquetes (librerías publicadas en el registro npm: react, vite, lodash…). Un gestor de paquetes se encarga de descargarlos, versionarlos y resolver sus dependencias (que a su vez tienen dependencias: un proyecto React típico arrastra cientos de paquetes).

npmyarnpnpm (nuestra elección)

¿Qué es eso de las phantom dependencies? npm «aplana» node_modules, así que tu código puede importar paquetes que NO declaraste pero que están ahí porque los necesita otra librería. Funciona… hasta que la librería cambia y tu importación fantasma desaparece. pnpm crea un node_modules donde solo existe lo que tú declaraste: si tu código funciona con pnpm, funciona de verdad.

Corepack: pnpm sin instalar nada global

Node trae desde la versión 16 una herramienta llamada Corepack que gestiona los gestores: con ella activas pnpm sin instalar paquetes globales con npm. Es la forma oficial y limpia, y la que usaremos.

VSCode y las extensiones justas

Visual Studio Code es el editor más usado del mundo para JavaScript (gratuito, de Microsoft, enorme ecosistema). No confundir con Visual Studio (el IDE pesado de .NET): son productos distintos. Instalaremos pocas extensiones pero bien elegidas:

  • Prettier — formatea el código automáticamente al guardar (adiós a discutir por espacios).
  • ESLint — marca errores y malas prácticas mientras escribes.
  • Error Lens (opcional) — muestra los errores de ESLint en la propia línea, en rojo, sin pasar el ratón.
  • Material Icon Theme (opcional) — iconos por tipo de archivo: puramente visual, pero ayuda a navegar proyectos grandes.

Y en el navegador (Chrome/Edge/Firefox): la extensión React Developer Tools. Es IMPRESCINDIBLE: añade a las DevTools dos pestañas (Components y Profiler) para inspeccionar el árbol de componentes, sus props y su estado. La usaremos en todo el curso.

3 · Ejemplo mínimo (instalación paso a paso)

Paso 1 — Node.js LTS

  1. Descarga el instalador LTS desde nodejs.org e instálalo con las opciones por defecto (incluye «Add to PATH», imprescindible).

  2. Cierra y vuelve a abrir la terminal (para que recargue el PATH) y verifica:

    node --version    # v22.x.x  (LTS)
npm --version     # 10.x/11.x  (viene con Node, aunque usaremos pnpm)

Paso 2 — pnpm vía Corepack

# Activa Corepack (gestor de gestores, incluido en Node)
corepack enable

# Fija la versión de pnpm que usaremos en todo el curso
corepack prepare pnpm@latest --activate

# Verifica
pnpm --version    # 11.x
⚠ Windows: «la ejecución de scripts está deshabilitada»

Si PowerShell te bloquea pnpm con un error de ExecutionPolicy, es su política de seguridad. Solución (solo para tu usuario, es segura y estándar): 

Set-ExecutionPolicy -Scope CurrentUser RemoteSigned

Alternativa sin tocar políticas: usar siempre corepack pnpm … o la terminal «Símbolo del sistema» (cmd) en lugar de PowerShell.

Paso 3 — VSCode + extensiones

# 1. Instala VSCode desde code.visualstudio.com
# 2. Instala las extensiones desde la terminal (Ctrl+ñ abre la integrada):
code --install-extension esbenp.prettier-vscode
code --install-extension dbaeumer.vscode-eslint
code --install-extension usernamehw.errorlens
code --install-extension PKief.material-icon-theme

Y en el navegador, instala React Developer Tools desde la tienda de extensiones de Chrome/Edge/Firefox.

4 · Ejemplo real: configuración profesional de VSCode

Un entorno profesional se configura UNA vez y se olvida. Abre VSCode → Ctrl + Shift + P → «Preferences: Open User Settings (JSON)» y pega:

settings.json (usuario)
{
  // Formatear automáticamente al guardar con Prettier
  "editor.formatOnSave": true,
  "editor.defaultFormatter": "esbenp.prettier-vscode",

  // Tabulación de 2 espacios (estándar de la comunidad JS/React)
  "editor.tabSize": 2,

  // Autoguardado suave: al cambiar de archivo o de ventana
  "files.autoSave": "onFocusChange",

  // Emmet funcione también dentro de archivos JSX
  "emmet.includeLanguages": {
    "javascript": "javascriptreact"
  },

  // Sugerencias más útiles dentro de strings y JSX
  "editor.quickSuggestions": {
    "strings": true
  }
}

Qué acabas de ganar con cada línea:

  • formatOnSave: nunca más debatirás sobre formato; el código sale perfecto solo.
  • tabSize: 2: todo el código React del mundo usa 2 espacios; míralo en cualquier repo profesional.
  • autoSave: combinado con el Hot Reload de Vite (próxima lección), escribes y ves el cambio sin guardar manualmente.
  • emmet: escribes div.card>h1 + Tab y se expande a HTML completo, también en JSX.

6 · Errores habituales

Error 1: «node no se reconoce como comando» tras instalar

Causa: la terminal se abrió ANTES de instalar Node y tiene el PATH viejo.

Solución: cierra TODAS las terminales (y VSCode) y ábrelas de nuevo. Si persiste, reinicia sesión de Windows.

Error 2: instalar herramientas de proyecto de forma global

✘ Incorrecto 
pnpm add -g vite        # Vite global: cada proyecto usará
                        # la MISMA versión, la tuya, la de hoy
✔ Correcto 
# Vite vive en las devDependencies de CADA proyecto,
# con la versión que ese proyecto necesita:
pnpm add -D vite

Por qué: un proyecto de 2023 necesita Vite 5; uno nuevo, Vite 7. Con instalación local, cada proyecto es independiente y reproducible. Lo único global aquí es pnpm (vía Corepack).

Error 3: borrar node_modules «para arreglar algo» y reinstalar con npm

Por qué está mal: borrar node_modules es a veces válido, pero reinstalar con OTRO gestor mezcla lockfiles (ver buenas prácticas).

✔ Correcto (proyecto con pnpm) 
# Borrar y reinstalar SIEMPRE con el mismo gestor:
Remove-Item -Recurse -Force node_modules
pnpm install

7 · Ejercicio guiado

Comprobemos que JavaScript corre en tu máquina fuera del navegador:

  1. Crea una carpeta de pruebas y entra en ella:

    mkdir hola-node; cd hola-node

  2. Crea el archivo hello.js:

    // hello.js — JavaScript ejecutándose en TU máquina, no en un navegador
const nombre = process.argv[2] ?? "mundo"; // lee el 1er argumento del comando
console.log(`Hola, ${nombre}, desde Node ${process.version}`);

  3. Ejecuta:

    node hello.js Ada
# → Hola, Ada, desde Node v22.x.x

  4. Reflexiona: no hay navegador, ni HTML, ni document. JavaScript es un lenguaje de propósito general gracias a Node. Las herramientas que usarás (Vite) son programas como este, más grandes.

8 · Reto

🎯 Deja tu entorno de diez

  1. Configura el settings.json del ejemplo real y comprueba que al guardar un archivo JS mal formateado, Prettier lo arregla solo.
  2. Averigua qué hace el comando pnpm dlx y compáralo con npx (lo usaremos en el curso).
  3. Opcional avanzado: instala nvm (Node Version Manager) o fnm y explica qué problema resuelven cuando trabajas en varios proyectos con distintas versiones de Node.

9 · Resumen

  • Node.js ejecuta JavaScript fuera del navegador: lo necesitan las herramientas (Vite, pnpm), no el usuario final.
  • Instala siempre la versión LTS.
  • pnpm es nuestro gestor: el más rápido, ahorra disco (tienda global + enlaces) y es estricto (adiós phantom dependencies). Se activa con Corepack.
  • Un proyecto = un gestor de paquetes = un lockfile que SÍ va al repositorio.
  • VSCode + Prettier (formatOnSave) + ESLint + Error Lens: entorno mínimo profesional.
  • React Developer Tools en el navegador: imprescindible desde el Módulo 1.
  • En Windows, recuerda la política de scripts de PowerShell si pnpm se queja.

10 · Preguntas frecuentes

¿Puedo usar npm o yarn en lugar de pnpm?

Puedes, pero este curso usa pnpm en TODOS los comandos (regla del curso). Los conceptos son idénticos (pnpm add ≈ npm install), así que lo que aprendas se traduce sin esfuerzo si tu empresa usa otro.

¿Necesito WSL (Linux dentro de Windows)?

No. Todo el curso funciona en Windows nativo con PowerShell. WSL es una buena herramienta, pero añade una capa de complejidad innecesaria para aprender React.

¿Qué diferencia hay entre la terminal de VSCode y la de Windows?

Ninguna funcional: la terminal integrada ES PowerShell (o la que elijas) dentro del editor. Su ventaja es abrirse ya en la carpeta del proyecto.

¿Prettier o ESLint? ¿No se pisan?

Tienen misiones distintas: Prettier formatea (espacios, comillas, punto y coma); ESLint detecta errores y malas prácticas (variables sin usar, hooks mal usados). Con la configuración moderna conviven sin conflictos: Prettier manda en el formato.

Mi antivirus se queja al instalar Node/pnpm, ¿es normal?

Algunos antivirus son quisquillosos con los instaladores de herramientas de desarrollo. Descarga SIEMPRE desde los sitios oficiales (nodejs.org, code.visualstudio.com) y no tendrás problemas reales. Si bloquea la instalación, añade una excepción temporal.
