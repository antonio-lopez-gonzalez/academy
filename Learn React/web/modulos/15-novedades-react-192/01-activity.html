<Activity>: ocultar sin perder estado

Módulo 15 · Novedades de React 19.2 ⏱ 40 minutos

1 · Introducción

Hasta ahora, si querías "esconder" parte de tu interfaz usabas renderizado condicional: {show && <Panel />} o un ternario. Pero el renderizado condicional tiene una consecuencia importante: desmonta el componente. Eso significa que todo su estado se destruye. Si el usuario estaba rellenando un formulario en una pestaña y cambia a otra, cuando vuelve, el formulario está vacío.

React 19.2 introduce <Activity>, un componente que permite ocultar una parte de la UI preservando su estado y priorizando su trabajo. Es la alternativa moderna al patrón de "montar/desmontar" para pestañas, modales, navegaciones con "volver atrás" y vistas que quieres mantener vivas.

¿Qué problema resuelve? La pérdida de estado al desmontar, el coste de volver a renderizar todo desde cero al volver, y la imposibilidad de "pre-renderizar" la siguiente vista en segundo plano.

¿Cuándo se usa? Interfaces con pestañas, paneles colapsables que quieres conservar, modales que abres/cierras con frecuencia, o navegación con botón "atrás" donde quieres restaurar scroll e inputs.

2 · Teoría

La diferencia con el renderizado condicional

RENDERIZADO CONDICIONAL (React < 19.2) ──────────────────────────────────────── {active ? <Settings /> : <Analytics />} │ ▼ active cambia ──► Settings se DESMONTA (estado destruido) │ ▼ vuelve active ──► Settings se MONTA de nuevo (todo vacío) ACTIVITY (React 19.2) ───────────────────── <Activity mode={active ? "visible" : "hidden"}> <Settings /> </Activity> │ ▼ mode cambia a hidden ──► se oculta, se desmontan los efectos, pero el ESTADO se conserva │ ▼ mode vuelve a visible ──► se restaura exactamente donde estaba

Los dos modos

import { Activity } from "react";

<Activity mode="visible">
  <SettingsPanel />
</Activity>

<Activity mode="hidden">
  <Dashboard />   {/* oculto: efectos desmontados, estado preservado */}
</Activity>
  • mode="visible" — muestra el contenido, monta los efectos y procesa las actualizaciones con normalidad.
  • mode="hidden" — oculta el contenido, desmonta los efectos y aplaza todas las actualizaciones hasta que React no tenga trabajo pendiente. El estado (inputs, scroll, etc.) se conserva.

¿Cómo funciona internamente?

Cuando un árbol está en modo hidden, React lo mantiene en la fibra (el árbol interno de componentes) pero lo marca como inactivo. No se pinta en el DOM, sus efectos se limpian y sus actualizaciones reciben la más baja prioridad. Cuando pasa a visible, React reactiva el árbol con su estado intacto y vuelve a montar los efectos.

Esto permite un caso de uso potente: pre-renderizar. Puedes tener la próxima vista en mode="hidden" para que cargue datos, CSS e imágenes en segundo plano; cuando el usuario navega, cambia a visible y la vista aparece instantáneamente.

3 · Ejemplo mínimo

src/components/Tabs.jsx
import { useState, Activity } from "react";

function SettingsForm() {
  const [name, setName] = useState("");
  return (
    <form>
      <input value={name} onChange={(e) => setName(e.target.value)} placeholder="Tu nombre" />
      <p>Nombre escrito: {name}</p>
    </form>
  );
}

export default function Tabs() {
  const [tab, setTab] = useState("settings");

  return (
    <div>
      <button onClick={() => setTab("settings")}>Ajustes</button>
      <button onClick={() => setTab("analytics")}>Analítica</button>

      <Activity mode={tab === "settings" ? "visible" : "hidden"}>
        <SettingsForm />
      </Activity>
    </div>
  );
}

Línea por línea:

  1. import { Activity } from "react": componente estable desde React 19.2.
  2. <Activity mode={...}>: envuelve la vista que quieres conservar.
  3. mode según la pestaña activa: visible para la actual, hidden para la otra.
  4. Resultado: si escribes "Ana" en Ajustes, cambias a Analítica y vuelves, "Ana" sigue ahí. Con renderizado condicional, se habría borrado.

4 · Ejemplo real

Una vista de "proyecto" en la app TaskFlow que mantiene vivo el panel de comentarios y pre-renderiza el panel de informes en segundo plano:

src/components/ProjectWorkspace.jsx
import { useState, Activity } from "react";
import { CommentsPanel } from "./CommentsPanel";
import { ReportsPanel } from "./ReportsPanel";

export default function ProjectWorkspace() {
  const [view, setView] = useState("comments");

  return (
    <div className="workspace">
      <nav>
        <button onClick={() => setView("comments")}>Comentarios</button>
        <button onClick={() => setView("reports")}>Informes</button>
      </nav>

      {/*
        Comentarios: siempre montado. Cuando está hidden, su estado
        (texto sin enviar, paginación, etc.) se conserva.
      */}
      <Activity mode={view === "comments" ? "visible" : "hidden"}>
        <CommentsPanel projectId="proyecto-1" />
      </Activity>

      {/*
        Informes: pre-renderizado en segundo plano (hidden). Cuando el
        usuario hace clic, la vista ya tiene sus datos cargados.
      */}
      <Activity mode={view === "reports" ? "visible" : "hidden"}>
        <ReportsPanel projectId="proyecto-1" />
      </Activity>
    </div>
  );
}

Decisiones explicadas:

  • Dos Activity en lugar de condicionales: ambas vistas permanecen montadas; cambia solo el modo.
  • Estado conservado: un comentario a medio escribir en CommentsPanel sobrevive al cambio de pestaña.
  • Pre-render: ReportsPanel cargó sus datos mientras estaba oculto; el clic se siente instantáneo.
  • Coste controlado: los efectos ocultos están desmontados, así que no hay conexiones ni timers activos mientras no se ven.

5 · Buenas prácticas

HazEvitaPor qué
Usar Activity para pestañas y modales con estado que debe perdurar Usar Activity para contenido pesado que el usuario no verá pronto Mantener árboles ocultos consume memoria y trabajo en background. Úsalo con intención.

6 · Errores habituales

Error 1: pensar que Activity es igual que display:none

✘ Incorrecto 
// display:none solo oculta visualmente: los efectos SIGUEN corriendo
<div style={{ display: tab === "x" ? "none" : "block" }}>
  <Timer />   {/* 💥 el timer sigue activo aunque no se vea */}
</div>
✔ Correcto 
// Activity hidden desmonta los efectos y aplaza actualizaciones
<Activity mode={tab === "x" ? "hidden" : "visible"}>
  <Timer />   {/* ✅ en hidden, sus efectos están desmontados */}
</Activity>

Error 2: asumir que el estado oculto es invisible a la lógica del padre

✘ Incorrecto 
// El estado del árbol hidden sigue existiendo; no lo ignores al leer el padre:
<Activity mode="hidden"><FormDraft /></Activity>
// 💥 El texto del formulario oculto sigue en el estado global
✔ Correcto 
// Decide si el estado oculto debe contar: si no, desmonta de verdad con
// renderizado condicional en lugar de Activity.
{showDraft ? <FormDraft /> : null}   // ✅ se destruye al ocultar

Error 3: meter dentro de Activity datos que cambian constantemente

✘ Incorrecto 
<Activity mode="hidden">
  <LiveFeed />   {/* 💥 un feed en tiempo real en hidden seguirá pidiendo actualizaciones diferidas */}
</Activity>
✔ Correcto 
// Contenido verdaderamente dinámico que no se ve debe desmontarse:
{visible ? <LiveFeed /> : null}   // ✅

8 · Reto

🎯 Navegación con "volver" instantáneo

Simula una navegación de una app con listado + detalle:

  1. Lista: al hacer clic en un elemento, muestra el detalle. Mantén la lista montada (hidden) para conservar el scroll.
  2. Detalle: al volver a la lista, el scroll y los filtros deben estar intactos.
  3. Pre-render: pre-renderiza en segundo plano (hidden) el detalle del siguiente elemento probable al hacer hover.
  4. Métricas: mide en Performance el tiempo de "volver" con y sin Activity.

9 · Resumen

  • <Activity> oculta una sub-árbol preservando su estado, a diferencia del renderizado condicional que lo destruye.
  • Dos modos: visible (normal) y hidden (oculto, efectos desmontados, actualizaciones aplazadas).
  • Ideal para pestañas, modales, "volver atrás" y pre-renderizado de la siguiente vista.
  • No es display:none: en hidden los efectos se limpian de verdad.

10 · Preguntas frecuentes

¿Activity preserva el scroll y los inputs?

Sí. Como el árbol no se desmonta, el estado de los inputs, el scroll de los contenedores y cualquier estado interno se conserva. Al volver a visible, la UI aparece exactamente donde estaba.

¿Qué pasa con los useEffect de un árbol hidden?

En mode="hidden" React desmonta los efectos (ejecuta su cleanup) y los vuelve a montar al pasar a visible. Diseña tus efectos con un buen cleanup para que ocultar/volver sea seguro.

¿Cuántos Activity puedo tener anidados?

Puedes anidarlos libremente. Un árbol solo es "activo" si todos sus ancestros Activity están en visible. Es un mecanismo de prioridad/visibilidad acumulativo.

¿Activity sustituye a librerías como keep-alive?

Activity es la respuesta nativa de React al patrón de "keep-alive" de otros frameworks (Vue tiene KeepAlive). No necesitas librerías externas para preservar estado de vistas en React 19.2+.
