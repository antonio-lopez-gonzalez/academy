Context API

Módulo 10 · Estado global ⏱ 40 minutos

1 · Introducción

Hasta ahora, el estado vive en componentes individuales y se pasa hacia abajo con props. Pero cuando muchos componentes necesitan acceder o modificar los mismos datos (usuario autenticado, tema, carrito de compra), pasar props por múltiples niveles se vuelve tedioso: es el "prop drilling".

La Context API de React resuelve esto: te permite crear un "contexto" que cualquier componente del árbol puede consumir directamente, sin pasar props manualmente. Es la solución nativa de React para el estado global.

2 · Teoría

Los tres pasos

  1. Crear el contexto: createContext().
  2. Proporcionar el contexto: <Context.Provider value={...}>.
  3. Consumir el contexto: useContext(Context).

Crear el contexto

import { createContext } from "react";

// Creamos el contexto con un valor por defecto
const ThemeContext = createContext("light");

Provider: proporcionar el valor

import { useState } from "react";

function App() {
  const [theme, setTheme] = useState("light");

  return (
    <ThemeContext.Provider value={{ theme, setTheme }}>
      <Header />
      <Main />
    </ThemeContext.Provider>
  );
}

Consumer: consumir el contexto

import { useContext } from "react";

function Button() {
  const { theme, setTheme } = useContext(ThemeContext);

  return (
    <button
      onClick={() => setTheme(theme === "light" ? "dark" : "light")}
      style={{ background: theme === "light" ? "#fff" : "#333" }}
    >
      Toggle theme
    </button>
  );
}

Patrón con custom hook

// Context + Provider + Hook personalizado
const ThemeContext = createContext();

export function ThemeProvider({ children }) {
  const [theme, setTheme] = useState("light");
  return (
    <ThemeContext.Provider value={{ theme, setTheme }}>
      {children}
    </ThemeContext.Provider>
  );
}

export function useTheme() {
  const context = useContext(ThemeContext);
  if (!context) {
    throw new Error("useTheme must be used within ThemeProvider");
  }
  return context;
}

// Uso en componentes
function Button() {
  const { theme, setTheme } = useTheme();
  // ...
}

3 · Ejemplo mínimo

src/contexts/ThemeContext.jsx
import { createContext, useContext, useState } from "react";

const ThemeContext = createContext();

export function ThemeProvider({ children }) {
  const [theme, setTheme] = useState("light");

  function toggleTheme() {
    setTheme((t) => (t === "light" ? "dark" : "light"));
  }

  return (
    <ThemeContext.Provider value={{ theme, toggleTheme }}>
      {children}
    </ThemeContext.Provider>
  );
}

export function useTheme() {
  const context = useContext(ThemeContext);
  if (!context) {
    throw new Error("useTheme must be used within ThemeProvider");
  }
  return context;
}
src/App.jsx
import { ThemeProvider, useTheme } from "./contexts/ThemeContext";

function ThemedButton() {
  const { theme, toggleTheme } = useTheme();
  return (
    <button
      onClick={toggleTheme}
      style={{
        background: theme === "light" ? "#fff" : "#333",
        color: theme === "light" ? "#000" : "#fff",
      }}
    >
      Tema actual: {theme}
    </button>
  );
}

export default function App() {
  return (
    <ThemeProvider>
      <ThemedButton />
    </ThemeProvider>
  );
}

4 · Ejemplo real

Contexto de autenticación con usuario y login/logout:

src/contexts/AuthContext.jsx
import { createContext, useContext, useState } from "react";

const AuthContext = createContext();

export function AuthProvider({ children }) {
  const [user, setUser] = useState(null);

  async function login(email, password) {
    // Simular petición a API
    const response = await fetch("/api/login", {
      method: "POST",
      body: JSON.stringify({ email, password }),
    });
    const data = await response.json();
    setUser(data.user);
  }

  function logout() {
    setUser(null);
  }

  return (
    <AuthContext.Provider value={{ user, login, logout }}>
      {children}
    </AuthContext.Provider>
  );
}

export function useAuth() {
  const context = useContext(AuthContext);
  if (!context) {
    throw new Error("useAuth must be used within AuthProvider");
  }
  return context;
}
src/components/Header.jsx
import { useAuth } from "../contexts/AuthContext";

export default function Header() {
  const { user, logout } = useAuth();

  return (
    <header>
      {user ? (
        <>
          <span>Hola, {user.name}</span>
          <button onClick={logout}>Cerrar sesión</button>
        </>
      ) : (
        <span>No autenticado</span>
      )}
    </header>
  );
}

5 · Buenas prácticas

HazEvita
Custom hook para consumir el contexto (useTheme)useContext(ThemeContext) directo en componentes

Separar contexto, provider y hook en un archivoTodo mezclado en App.jsx

6 · Errores habituales

Error 1: usar el contexto sin Provider

function Button() {
  const { theme } = useContext(ThemeContext);   // ✘ theme es undefined
  // ...
}

// ✔ Envolver con Provider
<ThemeProvider>
  <Button />
</ThemeProvider>

Error 2: no validar en el hook

export function useTheme() {
  return useContext(ThemeContext);   // ✘ si no hay Provider, devuelve undefined
}

export function useTheme() {
  const context = useContext(ThemeContext);
  if (!context) {
    throw new Error("useTheme must be used within ThemeProvider");   // ✔ error claro
  }
  return context;
}

Error 3: contextos para todo

// ✘ No uses context para estado local de un formulario
const FormContext = createContext();

// ✔ Usa context solo para estado global compartido
const AuthContext = createContext();
const ThemeContext = createContext();

9 · Resumen

  • Context API resuelve el "prop drilling" para estado global.
  • Tres pasos: crear contexto, Provider para proporcionar, useContext para consumir.
  • Patrón recomendado: contexto + provider + custom hook en un archivo.
  • Valida que el contexto existe en el hook personalizado.
  • Úsalo para datos que cambian poco: tema, usuario, idioma.

10 · Preguntas frecuentes

¿Context API re-renderiza todos los consumidores?
Sí, cuando el valor del Provider cambia, todos los consumidores se re-renderizan. Para optimizar, divide en contextos pequeños o usa useMemo.
¿Puedo tener múltiples Providers?
Sí, puedes anidar Providers. El más interno sobrescribe al externo.
¿Context reemplaza a Redux?
Para estado global simple, sí. Para estado complejo con mucha lógica, Redux Toolkit es mejor (próxima lección).
¿Puedo actualizar el contexto desde cualquier componente?
Sí, si proporcionas funciones de actualización en el valor del Provider.
