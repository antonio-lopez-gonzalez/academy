Zustand

Módulo 10 · Estado Global ⏱ 30 minutos

1 · Introducción

Zustand es una librería de gestión de estado global minimalista. En alemán significa "estado", y eso resume bien su filosofía: poco código, cero boilerplate y gran flexibilidad.

¿Por qué usar Zustand? Context API y Redux son válidos, pero a veces necesitas algo más ligero. Zustand se siente como useState global: simple, directo y sin proveedores envolviendo tu app.

2 · Teoría

Zustand crea una store fuera del árbol de React. Cualquier componente puede leer o escribir en ella usando un hook generado por la propia store.

  • No necesitas <Provider>
  • No hay reducers ni action types
  • Selección granular de estado (solo re-renderiza si cambia lo que consumes)
  • Soporta middlewares: persist, devtools, immer

3 · Ejemplo mínimo

pnpm add zustand
// src/store/counterStore.js
import { create } from 'zustand'

export const useCounterStore = create((set) => ({
  count: 0,
  increment: () => set((state) => ({ count: state.count + 1 })),
  decrement: () => set((state) => ({ count: state.count - 1 })),
  reset: () => set({ count: 0 })
}))
// src/components/Counter.jsx
import { useCounterStore } from '../store/counterStore'

export default function Counter() {
  const { count, increment, decrement, reset } = useCounterStore()

  return (
    <div>
      <p>{count}</p>
      <button onClick={decrement}>-</button>
      <button onClick={increment}>+</button>
      <button onClick={reset}>Reset</button>
    </div>
  )
}

4 · Ejemplo real: carrito

// src/store/cartStore.js
import { create } from 'zustand'
import { persist } from 'zustand/middleware'

export const useCartStore = create(
  persist(
    (set, get) => ({
      items: [],
      addItem: (product) => {
        const exists = get().items.find((i) => i.id === product.id)
        if (exists) {
          set({
            items: get().items.map((i) =>
              i.id === product.id ? { ...i, quantity: i.quantity + 1 } : i
            )
          })
        } else {
          set({ items: [...get().items, { ...product, quantity: 1 }] })
        }
      },
      removeItem: (id) => set({ items: get().items.filter((i) => i.id !== id) }),
      clearCart: () => set({ items: [] }),
      total: () => get().items.reduce((sum, i) => sum + i.price * i.quantity, 0)
    }),
    { name: 'cart-storage' }
  )
)

5 · Buenas prácticas

  • Selecciona solo lo que necesitas: useStore((s) => s.count)
  • Usa acciones dentro de la store, no muta el estado desde componentes
  • Combina persist para guardar en localStorage
  • Para lógica asíncrona, usa acciones normales con async/await

6 · Errores habituales

  • Desestructurar todo el store: fuerza re-renders innecesarios
  • Mutar el estado directamente: Zustand necesita inmutabilidad
  • Crear una store por cada componente: una store por dominio es suficiente

7 · Resumen

  • Zustand es una alternativa ligera a Context y Redux
  • No requiere providers ni boilerplate
  • Permite selección granular del estado
  • Ideal para apps medianas con estado global simple
