Listas con map()

Módulo 2 · Renderizado ⏱ 30 minutos

1 · Introducción

Casi todo lo que muestra una aplicación real es una lista de datos: productos, usuarios, mensajes, tareas, pedidos… Los datos llegan como un array (típicamente de una API) y tu trabajo es convertirlos en elementos de interfaz.

En React, renderizar listas se hace con el método de arrays map() de JavaScript. No hay una directiva especial (v-for, *ngFor): solo JavaScript dentro de las llaves. Esta lección conecta tu conocimiento de arrays con el renderizado, y es la base sobre la que se construyen todas las apps del curso.

Errores típicos: usar forEach (no devuelve nada), olvidar el return dentro del map, y usar bucles for clásicos dentro del JSX (imposible: son statements, no expresiones).

2 · Teoría

De datos a UI: la transformación fundamental

Recuerda la lección de expresiones: React sabe pintar arrays de elementos. Y map() es precisamente la función que transforma cada elemento de un array en otro valor y devuelve un array nuevo. Juntas, esas dos piezas son el renderizado de listas:

DATOS (array de objetos) map() UI (array de elementos) ──────────────────────── ────── ─────────────────────── [ { id: 1, name: "Ana" }, ───► por cada user ───► [ <li>Ana</li>, { id: 2, name: "Luis" }, crea un <li> <li>Luis</li>, { id: 3, name: "Marta" } ] <li>Marta</li> ] Array de DATOS ──map()──► Array de ELEMENTOS ──► React los pinta
// La forma canónica:
{users.map((user) => (
  <li key={user.id}>{user.name}</li>
))}

Desmontando la sintaxis pieza por pieza:

  1. { … } — entramos en modo JavaScript dentro del JSX.
  2. users.map((user) => ( … )) — por cada user, devolvemos un elemento. Los paréntesis ( … ) son el return implícito de la arrow function.
  3. <li key={user.id}> — la key: identificador único que React necesita para la reconciliación (próxima lección entera).
  4. {user.name} — dentro del elemento, más expresiones: el nombre del usuario.

¿Por qué map() y no for/forEach?

Porque en las llaves de JSX solo caben expresiones que producen un valor (lección 3 del Módulo 1):

Enfoque¿Funciona en JSX?Por qué
for (let i…)✘Es un statement: no produce valor. No cabe entre llaves.
users.forEach(u => …)✘ (pinta nada)forEach devuelve undefined: ejecuta pero no produce array.
users.map(u => <li />)✔Devuelve un array NUEVO con un elemento por usuario. Es una expresión.
🏭 Analogía de la cadena de montaje

map es una cadena de montaje: entran materias primas (datos) por un lado y sale un producto terminado (elemento UI) por cada una. forEach es un grupo de operarios que hacen cosas con las piezas pero sin cinta de salida: al final no hay nada que entregar. React necesita la cinta.

El ecosistema de arrays que usarás con listas

map raramente viaja solo. El patrón profesional encadena transformaciones antes de renderizar: 

{products
  .filter((p) => p.stock > 0)          // 1. quédate con los que tienen stock
  .sort((a, b) => a.price - b.price)    // 2. ordénalos por precio
  .map((p) => (                          // 3. conviértelos en UI
    <ProductCard key={p.id} product={p} />
  ))}

Esta cadena filter → sort → map es el «SELECT … WHERE … ORDER BY» de React. De hecho, la analogía con SQL es exacta: filter = WHERE, sort = ORDER BY, map = SELECT de columnas.

⚠ sort() muta el array original

sort() ordena modificando el array en el sitio. Si ese array es estado o props (lo será en el Módulo 4), lo habrás mutado: prohibido. Solución moderna (ES2023): .toSorted(), que devuelve una copia ordenada sin tocar el original. O [...products].sort(...). La inmutabilidad se estudia en el Módulo 4; memoriza ya el hábito: toSorted, no sort.

¿Dónde poner la lógica? Las dos escuelas

// a) Inline en el JSX: bien para transformaciones CORTAS
return <ul>{users.map((u) => <li key={u.id}>{u.name}</li>)}</ul>;

// b) Extraída a una variable: bien cuando la cadena crece
const userItems = users
  .filter((u) => u.active)
  .map((u) => <UserRow key={u.id} user={u} />);

return <ul>{userItems}</ul>;

Ambas son correctas. La regla del pulgar: si la expresión supera las 4-5 líneas o tiene filter/sort encadenados, sácala del JSX. El return debe leerse como una plantilla, no como un programa.

3 · Ejemplo mínimo

src/App.jsx
const fruits = ["Manzana", "Plátano", "Cereza"];

export default function App() {
  return (
    <ul>
      {fruits.map((fruit) => (
        <li key={fruit}>{fruit}</li>
      ))}
    </ul>
  );
}

Línea por línea:

  1. const fruits = […] — los datos: un array simple de strings.
  2. {fruits.map((fruit) => ( … ))} — transformamos cada string en un <li>. Resultado: un array de 3 elementos que React pinta en orden.
  3. key={fruit} — como cada fruta es única, el propio string sirve de key (en datos reales usarás un id).
  4. {fruit} — dentro del li, el texto de cada fruta.

4 · Ejemplo real

Una tabla de pedidos con filtro y formato — el patrón exacto de los paneles de administración (ejecutable en ejemplos/m02-renderizado):

src/components/OrderTable.jsx
const orders = [
  { id: "A-001", customer: "Ana", total: 129.9, status: "paid" },
  { id: "A-002", customer: "Luis", total: 59.5, status: "pending" },
  { id: "A-003", customer: "Marta", total: 210.0, status: "paid" },
  { id: "A-004", customer: "Pablo", total: 15.99, status: "cancelled" },
];

const STATUS_LABELS = {
  paid: "✅ Pagado",
  pending: "⏳ Pendiente",
  cancelled: "❌ Cancelado",
};

export default function OrderTable() {
  // 1. Preparamos las filas FUERA del JSX: cadena filter → map
  const visibleRows = orders
    .filter((order) => order.status !== "cancelled") // ocultamos cancelados
    .map((order) => (
      <tr key={order.id}>
        <td>{order.id}</td>
        <td>{order.customer}</td>
        <td>{order.total.toFixed(2)} €</td>
        <td>{STATUS_LABELS[order.status]}</td>
      </tr>
    ));

  // 2. El JSX se lee como una plantilla limpia
  return (
    <table className="order-table">
      <thead>
        <tr>
          <th>Pedido</th>
          <th>Cliente</th>
          <th>Total</th>
          <th>Estado</th>
        </tr>
      </thead>
      <tbody>{visibleRows}</tbody>
    </table>
  );
}

Decisiones explicadas:

  • El mapa de etiquetas (STATUS_LABELS): traducir valores de datos ("paid") a presentación («✅ Pagado») con un objeto-diccionario es infinitamente más limpio que una cadena de ternarios. Si llega un cuarto estado, añades UNA línea al diccionario.
  • El filtro vive en los datos, no en el render: los cancelados ni siquiera se convierten en elementos. Menos trabajo para React.
  • <tbody>{visibleRows}</tbody>: el array de <tr> cae directamente dentro del tbody. JSX acepta arrays de elementos en cualquier posición de children.
  • key={order.id}: los ids de pedido son únicos y estables: la key perfecta (próxima lección).

5 · Buenas prácticas

HazEvitaPor qué
Delegar cada fila a un componente (UserRow, ProductCard) Bloques de JSX de 20 líneas dentro del map El map debe verse de un vistazo: users.map(u => <UserRow … />).
Encadenar filter/sort/map como pipeline de datos Tres bucles separados con arrays intermedios mutables La cadena es declarativa y sin variables temporales que ensuciar.
Usar toSorted()/toReversed() (ES2023) sort() directo sobre arrays que no creaste tú sort() muta el original: peligroso cuando el array viene de props/estado.
Renderizar un mensaje de «lista vacía» Dejar una pantalla en blanco cuando no hay datos El usuario debe saber si está cargando, vacío o roto (próxima lección).
Nombrar el parámetro en singular (users.map((user) => …)) users.map((u) => …) o users.map((item) => …) genérico El singular del plural se lee solo: es documentación gratis.

6 · Errores habituales

Error 1: forEach en lugar de map

✘ Incorrecto 
<ul>
  {users.forEach((user) => (
    <li key={user.id}>{user.name}</li>   // no se pinta NADA:
  ))}                                       {/* forEach devuelve undefined */}
</ul>
✔ Correcto 
<ul>
  {users.map((user) => (
    <li key={user.id}>{user.name}</li>     // map DEVUELVE el array de elementos
  ))}
</ul>

Error 2: olvidar el return (o los paréntesis) dentro del map

✘ Incorrecto 
{users.map((user) => {
  <li key={user.id}>{user.name}</li>   // ✘ llaves sin return: devuelve undefined
})}

{users.map((user) => return <li>…)}      // ✘ "return" no es una expresión
✔ Correcto (las dos formas) 
{users.map((user) => ( <li key={user.id}>{user.name}</li> ))}  // return implícito

{users.map((user) => {                       // o con llaves…
  return <li key={user.id}>{user.name}</li>;  // …pero entonces SÍ hay return
})}

Error 3: JSX duplicado en vez de map

✘ Incorrecto 
// Copiar-pegar para cada elemento: y si son 500?
<li>{users[0].name}</li>
<li>{users[1].name}</li>
<li>{users[2].name}</li>
✔ Correcto 
{users.map((user) => <li key={user.id}>{user.name}</li>)}

9 · Resumen

  • Renderizar listas = transformar un array de datos en un array de elementos con map().
  • React sabe pintar arrays de elementos; forEach y for no producen valor: no sirven en JSX.
  • Patrón profesional: filter → toSorted → map (el «SELECT/WHERE/ORDER BY» de React).
  • Cada elemento de la lista necesita una key única y estable (próxima lección).
  • Delega cada ítem a un componente; el map debe verse de un vistazo.
  • sort() muta; usa toSorted() para arrays que no creaste tú.

10 · Preguntas frecuentes

¿Cuántos elementos puedo renderizar con map sin problemas?

Cientos sin pensarlo. Miles empiezan a notarse (cada elemento es un nodo DOM). Para listas enormes existe la virtualización (renderizar solo lo visible: librerías como @tanstack/react-virtual). La mencionamos en el Módulo 11.

¿Puedo usar map sobre objetos?

map es de arrays. Para objetos: Object.entries(obj).map(([key, value]) => …). Pero si tus datos son un objeto, plantéate si deberían ser un array (las APIs casi siempre devuelven arrays para colecciones).

¿Y el segundo parámetro del map (index)? ¿Puedo usarlo?

Como posición para mostrar (1º, 2º): sí, libremente. Como key: solo en listas estáticas que jamás se reordenan, filtran o editan — la próxima lección explica el desastre que causa en caso contrario.

¿Es lento hacer filter+map en cada render?

Para listas normales (decenas/cientos de items) es despreciable: milisegundos. Si la lista es gigante o la cadena compleja, useMemo (Módulo 6) la memoriza entre renders.
