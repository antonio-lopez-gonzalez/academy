Dashboard y layout principal

Módulo 13 · Proyecto final: TaskFlow 🕐 45 minutos

1 · Introducción

Ya tenemos autenticación, pero la aplicación sigue siendo una sola pantalla. Toda aplicación profesional comparte un marco común: la barra lateral con la navegación, la cabecera con el usuario y un área central donde cambia el contenido. A ese marco lo llamamos layout o app shell.

Qué vamos a aprender hoy: a construir el layout de TaskFlow con rutas anidadas de React Router. La idea es no repetir la barra lateral en cada página: se escribe una vez y las páginas se renderizan «dentro» de ella mediante <Outlet />.

Qué problema resuelve: sin layout, cada página tendría que volver a montar la sidebar, la cabecera y el menú de usuario. Cualquier cambio (añadir un enlace) habría que replicarlo en cada archivo. Con rutas anidadas, el marco se monta una vez y no se desmonta al navegar: la sidebar conserva su scroll, el estado de los menús, etc.

Cuándo se utiliza: en cualquier app con más de dos pantallas relacionadas. Es el patrón de dashboards de administración, paneles y, por supuesto, TaskFlow.

Errores típicos: duplicar la cabecera en cada página, usar <Link> cuando necesitas el estado «activo» de <NavLink>, o encapsular el layout dentro de una página en lugar de cómo ruta contenedora.

2 · Teoría

Rutas anidadas: el layout es una ruta que envuelve

Hasta ahora dibujabas las rutas como una lista plana. React Router 7 permite una ruta sin path (ruta de layout) cuyos hijos se renderizan en el punto donde el componente contenedor pone <Outlet />.

ESTADO DEL ARBOL DE COMPONENTES AL NAVEGAR AppRoutes └── AuthProvider └── AppShell ← ¡NO se desmonta al cambiar de página! ├── Sidebar ← conserva scroll y estado ├── Topbar ← avatar, menú de usuario └── Outlet ────► contenido que SÍ cambia: ├── / → DashboardPage ├── /projects/:id → ProjectPage └── /settings → SettingsPage

Es como un marco de fotos: el marco (layout) permanece; solo cambia la foto (la página hija). Si en lugar de esto pusieras el layout dentro de cada página, el marco se reconstruiría en cada navegación y perderías su estado.

Grid del layout: tres zonas que se adaptan

El layout se resuelve con CSS Grid: dos columnas (sidebar y contenido) y dos filas (topbar y resto). En móvil, la sidebar pasa a ser un panel deslizante controlado por un estado isSidebarOpen.

src/styles/layout.css — rejilla del shell
/* Dos columnas: sidebar fija + contenido fluido */
.app-shell {
  display: grid;
  grid-template-columns: 260px 1fr;
  grid-template-rows: 56px 1fr;
  grid-template-areas:
    "sidebar topbar"
    "sidebar content";
  height: 100dvh; /* dvh: altura real en móvil (sin la barra del navegador) */
}

.app-shell__sidebar { grid-area: sidebar; }
.app-shell__topbar  { grid-area: topbar; }
.app-shell__content { grid-area: content; overflow-y: auto; }

/* En pantallas pequeñas, la sidebar se superpone al contenido */
@media (max-width: 768px) {
  .app-shell {
    grid-template-columns: 1fr;
    grid-template-areas:
      "topbar"
      "content";
  }
  .app-shell__sidebar {
    position: fixed;
    inset: 0 auto 0 0;
    width: 260px;
    transform: translateX(-100%);
    transition: transform 0.2s ease;
    z-index: 20;
  }
  .app-shell__sidebar.is-open { transform: translateX(0); }
}

NavLink: el enlace que sabe si está activo

<NavLink> es un <Link> que añade una clase cuando la ruta coincide. Es exactamente lo que necesitas para resaltar la sección actual en la sidebar (Módulo 8).

uso de NavLink
<NavLink
  to="/"
  end // "end" evita que "/" se marque activo en TODAS las rutas
  className={({ isActive }) => (isActive ? "nav-link nav-link--active" : "nav-link")}
>
  Dashboard
</NavLink>

3 · Ejemplo mínimo

El ejemplo más pequeño posible: una shell con dos zonas y un Outlet. No tiene estilos bonitos todavía; su misión es demostrar la mecánica.

src/components/layout/AppShell.jsx
import { Outlet } from "react-router-dom";

// El layout es una RUTA contenedora. El Outlet marca dónde se pinta
// la página hija (Dashboard, ProjectPage…).
export default function AppShell() {
  return (
    <div className="app-shell">
      <aside className="app-shell__sidebar">
        <h1>TaskFlow</h1>
        {/* Aquí irá la navegación */}
      </aside>

      <header className="app-shell__topbar">Cabecera</header>

      <main className="app-shell__content">
        {/* ← La página hija se renderiza AQUÍ */}
        <Outlet />
      </main>
    </div>
  );
}
src/App.jsx — el layout como ruta contenedora
import { Navigate, Route, Routes } from "react-router-dom";
import ProtectedRoute from "./components/layout/ProtectedRoute.jsx";
import AppShell from "./components/layout/AppShell.jsx";
import LoginPage from "./pages/LoginPage.jsx";
import RegisterPage from "./pages/RegisterPage.jsx";
import DashboardPage from "./pages/DashboardPage.jsx";

export default function App() {
  return (
    <Routes>
      <Route path="/login" element={<LoginPage />} />
      <Route path="/register" element={<RegisterPage />} />

      <!-- 1) ProtectedRoute comprueba la sesión -->
      <Route element={<ProtectedRoute />}>
        <!-- 2) AppShell aporta el marco común -->
        <Route element={<AppShell />}>
          <!-- 3) Estas páginas se pintan en el <Outlet /> -->
          <Route path="/" element={<DashboardPage />} />
        </Route>
      </Route>

      <Route path="*" element={<Navigate to="/" replace />} />
    </Routes>
  );
}

Línea por línea:

  1. Dos rutas contenedoras anidadas: primero protección, luego marco. El orden importa: no tiene sentido montar la sidebar si el usuario no está autenticado.
  2. <Outlet /> aparece en ambos niveles: ProtectedRoute decide si hay sesión; AppShell coloca el marco. Cada Outlet es el «agujero» donde entra el hijo.
  3. La ruta * al final actúa de comodín (404 → redirige al dashboard).

4 · Ejemplo real

Ahora el layout completo de TaskFlow: sidebar con navegación y proyectos, topbar con el usuario, y una página de dashboard con estadísticas y tarjetas. Todo conectado a los datos reales que cargaremos en las siguientes lecciones.

src/components/layout/Sidebar.jsx
import { NavLink } from "react-router-dom";
import { useAuth } from "../../hooks/useAuth.js";

// La sidebar muestra navegación fija + accesos a los proyectos.
// Recibimos la lista de proyectos por props (la cargará el AppShell).
export default function Sidebar({ projects, onClose }) {
  const { user } = useAuth();

  // NavLink nos da isActive para resaltar la sección actual.
  function linkClass({ isActive }) {
    return isActive ? "nav-link nav-link--active" : "nav-link";
  }

  return (
    <nav className="sidebar">
      <div className="sidebar__brand">
        <span className="sidebar__logo">✔</span>
        <span>TaskFlow</span>
      </div>

      <div className="sidebar__section">
        <NavLink to="/" end className={linkClass} onClick={onClose}>
          📊 Dashboard
        </NavLink>
        <NavLink to="/projects" className={linkClass} onClick={onClose}>
          📁 Todos los proyectos
        </NavLink>
      </div>

      <div className="sidebar__section">
        <p className="sidebar__label">Mis proyectos</p>
        <ul className="sidebar__projects">
          {projects.map((project) => (
            <li key={project.id}>
              <NavLink
                to={`/projects/${project.id}`}
                className={linkClass}
                onClick={onClose}
              >
                <span
                  className="sidebar__dot"
                  style={{ background: project.color }}
                />
                {project.name}
              </NavLink>
            </li>
          ))}
        </ul>
      </div>

      <footer className="sidebar__footer">
        <span className="sidebar__avatar">
          {user.displayName.charAt(0).toUpperCase()}
        </span>
        <span className="sidebar__user">{user.displayName}</span>
      </footer>
    </nav>
  );
}
src/components/layout/Topbar.jsx
import { useNavigate } from "react-router-dom";
import { useAuth } from "../../hooks/useAuth.js";

// Barra superior: botón de menú (solo móvil), búsqueda y menú de usuario.
export default function Topbar({ onToggleSidebar }) {
  const { user, logout } = useAuth();
  const navigate = useNavigate();

  function handleLogout() {
    logout();
    navigate("/login", { replace: true });
  }

  return (
    <header className="topbar">
      <!-- aria-label para accesibilidad: el botón no tiene texto visible -->
      <button
        className="topbar__menu"
        onClick={onToggleSidebar}
        aria-label="Abrir menú"
      >
        ☰
      </button>

      <h2 className="topbar__title">TaskFlow</h2>

      <div className="topbar__spacer" />

      <details className="user-menu">
        <summary className="user-menu__trigger">
          <span className="user-menu__avatar">
            {user.displayName.charAt(0).toUpperCase()}
          </span>
          {user.displayName} ▾
        </summary>
        <div className="user-menu__panel">
          <button onClick={handleLogout}>Cerrar sesión</button>
        </div>
      </details>
    </header>
  );
}
src/components/layout/AppShell.jsx — versión completa
import { useEffect, useState } from "react";
import { Outlet } from "react-router-dom";
import Sidebar from "./Sidebar.jsx";
import Topbar from "./Topbar.jsx";
import { projectService } from "../../services/projectService.js";

// AppShell es el marco de toda la zona privada. Carga la lista de
// proyectos (para la sidebar) y gestiona el panel móvil.
export default function AppShell() {
  const [projects, setProjects] = useState([]);
  const [isSidebarOpen, setSidebarOpen] = useState(false);

  // Cargamos los proyectos una sola vez. La lista es compartida por la
  // sidebar; el detalle de cada página hará su propia carga.
  useEffect(() => {
    // Usamos un flag para evitar setState tras desmontar (lección 9 de APIs).
    let activo = true;
    projectService.list().then((data) => {
      if (activo) setProjects(data.items);
    });
    return () => {
      activo = false;
    };
  }, []);

  return (
    <div className="app-shell">
      <aside className={isSidebarOpen ? "app-shell__sidebar is-open" : "app-shell__sidebar"}>
        <Sidebar projects={projects} onClose={() => setSidebarOpen(false)} />
      </aside>

      <!-- El overlay cierra el menú al tocar fuera (solo visible en móvil) -->
      {isSidebarOpen && (
        <div
          className="app-shell__overlay"
          onClick={() => setSidebarOpen(false)}
          aria-hidden="true"
        />
      )}

      <Topbar onToggleSidebar={() => setSidebarOpen((open) => !open)} />

      <main className="app-shell__content">
        <Outlet />
      </main>
    </div>
  );
}

Decisiones del ejemplo: (1) el layout carga una vez la lista de proyectos y la comparte con la sidebar por props; (2) el panel móvil es estado local del shell, no global; (3) usamos <details>/<summary> nativo para el menú de usuario: accesible por teclado sin una línea de JavaScript; (4) 100dvh en lugar de 100vh para que en móvil no se corte por la barra del navegador.

5 · Buenas prácticas

HazEvitaPor qué
Un layout contenedor con <Outlet /> Reescribir la sidebar en cada página El marco no se desmonta: conserva estado y scroll, y se escribe una sola vez.
<NavLink> para la navegación <Link> + lógica manual de «activo» NavLink ya calcula isActive por ti.
end en el enlace a la raíz Olvidar end y marcar «Dashboard» siempre activo Sin end, to="/" coincide con cualquier ruta.
Unidades dvh y cqw para el alto 100vh en móvil vh no descuenta la barra del navegador y provoca cortes.
Un overlay para cerrar el menú móvil Dejar el panel abierto sin forma de cerrarlo fuera UX y accesibilidad: el usuario necesita salir del panel.
Cargar los proyectos compartidos en el layout Que cada página vuelva a pedir la misma lista Menos peticiones; la sidebar y el dashboard comparten datos.

6 · Errores habituales

Error 1: poner el layout dentro de la página

✘ Incorrecto 
// DashboardPage.jsx — la página monta la sidebar y la cabecera
export default function DashboardPage() {
  return (
    <div className="app-shell">
      <Sidebar />
      <Topbar />
      <main>Contenido</main>
    </div>
  );
}
// ProjectPage.jsx tendría que volver a copiar TODO el marco.
✔ Correcto 
// AppShell.jsx (ruta contenedora) monta el marco UNA vez
export default function AppShell() {
  return (
    <div className="app-shell">
      <Sidebar />
      <Topbar />
      <main><Outlet /></main>  {/* solo cambia esto */}
    </div>
  );
}

Error 2: to="/" sin end siempre activo

✘ Incorrecto 
<NavLink to="/">Dashboard</NavLink>
{/* En /projects/42, "Dashboard" sale resaltado porque "/" es prefijo. */}
✔ Correcto 
<NavLink to="/" end>Dashboard</NavLink>
{/* Con "end" solo coincide en la ruta exacta. */}

Error 3: leer user sin proteger el render

✘ Incorrecto 
// Si user todavía es null (auth cargando), esto revienta.
<span>{user.displayName}</span>
✔ Correcto 
// AppShell solo se monta DESPUÉS de que ProtectedRoute confirme la sesión,
// así que aquí user ya existe. Si dudas, usa optional chaining:
<span>{user?.displayName ?? "Invitado"}</span>

8 · Reto

🎯 Migas de pan y layout con título dinámico

Añade a TaskFlow dos mejoras de navegación que usan datos de la ruta actual:

  1. Migas de pan (breadcrumbs): en el área de contenido, muestra Dashboard / Proyecto A / Tarea #12 según la ruta actual. Construye el componente de forma genérica: debe deducir los segmentos de useLocation() y permitir reemplazar un segmento por un texto legible (p. ej. el nombre del proyecto, no su id).
  2. Título de pestaña dinámico: actualiza document.title para que refleje la pantalla actual («Proyecto A · TaskFlow»). Hazlo con un custom hook useDocumentTitle(title) que restaure el título anterior al desmontar.
  3. Indicador de sección activa en el proyecto abierto: cuando estés en /projects/:id, la sidebar debe destacar ese proyecto incluso si el enlace no es el «exact match». Piensa qué opción de NavLink te ayuda.

Pista: para el breadcrumb, useMatches() de React Router 7 permite asociar un handle a cada ruta; es la forma más limpia, aunque construir los segmentos a mano desde pathname también vale.

No lo resuelvas todavía. Un buen breadcrumb parece trivial y casi nunca lo es: merece tu tiempo.

9 · Resumen

  • El layout es una ruta contenedora sin path; las páginas se renderizan en su <Outlet />.
  • Al navegar, el marco no se desmonta: conserva estado, scroll y evita repetir código.
  • Anidamiento en capas: ProtectedRoute (sesión) → AppShell (marco) → página.
  • NavLink aporta isActive; recuerda end en el enlace a la raíz.
  • CSS Grid + media queries resuelven el responsive sin librerías; en móvil la sidebar es un panel deslizante.
  • Datos compartidos (lista de proyectos) se cargan en el shell y se pasan por props a la sidebar.

10 · Preguntas frecuentes

¿Por qué dos rutas contenedoras (ProtectedRoute y AppShell) y no una?

Porque tienen responsabilidades distintas. ProtectedRoute decide si se puede ver la zona privada; AppShell decide cómo se ve. Separarlas permite, por ejemplo, tener un layout público para login (sin sidebar) y otro privado para el dashboard, reutilizando la misma protección.

¿Cómo evito re-renderizar la sidebar en cada navegación?

Con el layout contenedor ya lo evitas: React no desmonta el marco al cambiar de ruta hija. Si además la sidebar es pesada, envuélvela en React.memo (Módulo 11) o divide su estado para que solo se re-renderice cuando cambien sus props reales.

¿Uso useEffect en el layout para cargar datos?

Es válido para datos pequeños y compartidos (los proyectos de la sidebar). Para lógica más compleja (caché, revalidación, paginación) conviene extraer un custom hook o un contexto. En la lección 4 crearemos projectService y un hook de carga reutilizable.

¿Necesito una librería de UI para el layout?

No. Un layout con CSS Grid son ~40 líneas de CSS. Las librerías de componentes (MUI, Chakra…) añaden peso y una API que hay que aprender; para TaskFlow usamos CSS puro, coherente con el Módulo 7. Puedes añadir Tailwind al final si quieres ver el contraste.

¿Cómo manejo el estado «sidebar abierta» en móvil?

Es estado local del AppShell (useState): solo le importa a ese componente y a sus hijos directos. No lo pongas en un contexto global: sería sobreingeniería. La regla es poner el estado en el ancestro común más bajo que lo necesita (Módulo 4).
