Tema oscuro y responsive

Módulo 13 · Proyecto final: TaskFlow 🕐 35 minutos

1 · Introducción

Hoy en día un tema oscuro no es un extra: es una expectativa. Y una app que no funciona en el móvil es una app a medias. En esta lección haremos que TaskFlow tenga tema claro/oscuro (respetando la preferencia del sistema) y que se adapte a cualquier tamaño de pantalla.

Qué vamos a aprender hoy: a implementar el tema con variables CSS y un atributo data-theme en el <html>, gobernado por un ThemeContext, y a resolver el responsive con mobile-first y container queries.

Qué problema resuelve: hay dos formas de hacer un tema oscuro. La mala: duplicar todos los estilos con un selector .dark .card { … } por todo el CSS. La buena: definir variables de color una sola vez y cambiarlas según el tema, de modo que el resto del CSS sea idéntico. Igual con el responsive: en lugar de dos layouts, uno que se adapta.

Cuándo se utiliza: siempre. El tema y el responsive se deciden al principio del proyecto, porque retrofitearlos es doloroso.

Errores típicos: el «flash» blanco al cargar (FOUC), ignorar prefers-color-scheme, o usar píxeles fijos que rompen en pantallas pequeñas.

2 · Teoría

Variables CSS: la base de todo

En lugar de escribir colores «a pelo», los nombramos como variables en :root. Cambiar el tema es reasignar esas variables bajo [data-theme="dark"]. El resto del CSS no sabe que existe un tema: usa var(--bg), var(--text), etc.

src/styles/variables.css
/* Tema CLARO por defecto en :root */
:root {
  --bg: #f6f7fb;
  --surface: #ffffff;
  --surface-2: #eef0f6;
  --text: #1a1d24;
  --text-soft: #5b6270;
  --border: #dfe3ec;
  --accent: #3b82f6;
  --danger: #e5484d;
  --success: #16a34a;
  --radius: 10px;
  --shadow: 0 1px 3px rgb(0 0 0 / 0.08);
}

/* Tema OSCURO: solo cambiamos las variables, nada más */
[data-theme="dark"] {
  --bg: #0f1117;
  --surface: #171a23;
  --surface-2: #1f232e;
  --text: #e6e8ee;
  --text-soft: #9aa3b2;
  --border: #2a2f3a;
  --accent: #61dafb;
  --danger: #ff5370;
  --success: #7dd3a0;
  --shadow: 0 1px 3px rgb(0 0 0 / 0.4);
}

/* El resto del CSS es IDÉNTICO en ambos temas */
body {
  background: var(--bg);
  color: var(--text);
}
.card {
  background: var(--surface);
  border: 1px solid var(--border);
  border-radius: var(--radius);
  box-shadow: var(--shadow);
}

El atributo data-theme y por qué en <html>

El tema lo marcamos en document.documentElement (la etiqueta <html>) con data-theme. Así el navegador puede aplicar el color de fondo antes de que React monte nada, evitando el flash blanco.

index.html — script anti-FOUC (antes de cargar React)
<script>
  // Se ejecuta ANTES de pintar: lee el tema guardado o el del sistema.
  // Evita el "flash" blanco al cargar en modo oscuro.
  (function () {
    var saved = localStorage.getItem("taskflow.theme");
    var system = window.matchMedia("(prefers-color-scheme: dark)").matches
      ? "dark"
      : "light";
    document.documentElement.dataset.theme = saved || system;
  })();
</script>

El ciclo del tema

Usuario pulsa 🌙 │ ▼ ThemeContext.toggleTheme() │ ├── actualiza localStorage["taskflow.theme"] ├── document.documentElement.dataset.theme = "dark" | "light" └── setTheme(state) → re-render │ ▼ El CSS recalcula las variables → TODA la app cambia de golpe
📌 ¿Por qué no guardar el tema en el estado global?

Porque tiene tres hogares mejores: localStorage (persistencia), data-theme en el DOM (que el CSS ya entiende) y un contexto pequeño (para que el botón sepa el valor). Un store global completo sería excesivo.

Responsive: mobile-first y container queries

Diseñamos primero para móvil y ampliamos con min-width. Los container queries permiten que un componente se adapte al tamaño de su contenedor, no al de la pantalla: perfecto para tarjetas que viven en una sidebar estrecha o en un tablero ancho.

TécnicaSe adapta a…Úsala para…
@media (min-width: …)La pantallaLayout global (sidebar, columnas)
@containerEl contenedor del componenteComponentes reutilizables (tarjetas, paneles)
clamp()—Tipografía y espaciados fluidos sin media queries
unidades fluidas y container queries
/* Tipografía fluida: mínimo 16px, ideal 1rem + viewport, máximo 22px */
body { font-size: clamp(1rem, 0.9rem + 0.5vw, 1.375rem); }

/* La tarjeta reacciona al ancho de SU columna, no al de la pantalla */
.board__column { container-type: inline-size; }

@container (min-width: 320px) {
  .task-card__labels { flex-wrap: wrap; }
}

3 · Ejemplo mínimo

El mínimo imprescindible: un hook que lee y escribe el tema, y un botón que lo alterna. Sin contexto todavía.

src/hooks/useTheme.js — versión mínima
import { useEffect, useState } from "react";

const THEME_KEY = "taskflow.theme";

// Lee el tema inicial: localStorage → preferencia del sistema → "light".
function getInitialTheme() {
  const saved = localStorage.getItem(THEME_KEY);
  if (saved === "light" || saved === "dark") return saved;
  return window.matchMedia("(prefers-color-scheme: dark)").matches ? "dark" : "light";
}

export function useTheme() {
  const [theme, setTheme] = useState(getInitialTheme);

  // Cada vez que cambia el tema, actualizamos el DOM y persistimos.
  useEffect(() => {
    document.documentElement.dataset.theme = theme;
    localStorage.setItem(THEME_KEY, theme);
  }, [theme]);

  function toggleTheme() {
    setTheme((current) => (current === "dark" ? "light" : "dark"));
  }

  return { theme, toggleTheme };
}

Línea por línea:

  1. getInitialTheme() — prioridad: lo que eligió el usuario → lo que dice el sistema → claro.
  2. document.documentElement.dataset.theme = theme — escribe data-theme en <html>, activando las variables oscuras.
  3. localStorage.setItem(...) — persistimos la elección para la próxima visita.
  4. El hook no pinta nada: expone theme y toggleTheme para que el botón los use.

4 · Ejemplo real

La versión de producción: un ThemeContext que permite que cualquier componente lea el tema (para iconos, gráficos…), un botón en la topbar y estilos responsive reales.

src/contexts/ThemeContext.jsx
import { createContext, useContext, useEffect, useState } from "react";

const ThemeContext = createContext(null);
const THEME_KEY = "taskflow.theme";

function getInitialTheme() {
  const saved = localStorage.getItem(THEME_KEY);
  if (saved === "light" || saved === "dark") return saved;
  return window.matchMedia("(prefers-color-scheme: dark)").matches ? "dark" : "light";
}

export function ThemeProvider({ children }) {
  const [theme, setTheme] = useState(getInitialTheme);

  // Sincroniza el DOM con el estado del tema.
  useEffect(() => {
    document.documentElement.dataset.theme = theme;
    localStorage.setItem(THEME_KEY, theme);
  }, [theme]);

  // Si el usuario NO ha elegido tema, seguimos la preferencia del sistema
  // aunque cambie en caliente (el SO cambia a modo oscuro por la noche).
  useEffect(() => {
    const media = window.matchMedia("(prefers-color-scheme: dark)");
    function handleChange(event) {
      // Solo seguimos al sistema si no hay elección explícita guardada.
      if (!localStorage.getItem(THEME_KEY)) {
        setTheme(event.matches ? "dark" : "light");
      }
    }
    media.addEventListener("change", handleChange);
    return () => media.removeEventListener("change", handleChange);
  }, []);

  function toggleTheme() {
    setTheme((current) => (current === "dark" ? "light" : "dark"));
  }

  return (
    <ThemeContext.Provider value={{ theme, toggleTheme }}>
      {children}
    </ThemeContext.Provider>
  );
}

export function useTheme() {
  const context = useContext(ThemeContext);
  if (context === null) {
    throw new Error("useTheme debe usarse dentro de <ThemeProvider>");
  }
  return context;
}
src/components/layout/ThemeToggle.jsx
import { useTheme } from "../../contexts/ThemeContext.jsx";

export default function ThemeToggle() {
  const { theme, toggleTheme } = useTheme();
  const isDark = theme === "dark";

  return (
    <button
      className="theme-toggle"
      onClick={toggleTheme}
      // aria-pressed comunica el estado a lectores de pantalla.
      aria-pressed={isDark}
      aria-label={isDark ? "Activar tema claro" : "Activar tema oscuro"}
      title={isDark ? "Tema claro" : "Tema oscuro"}
    >
      {isDark ? "🌙" : "☀️"}
    </button>
  );
}
src/styles/responsive.css — estrategia mobile-first
/* 1) Base: el móvil. Todo apilado en una columna. */
.board {
  display: flex;
  flex-direction: column;
  gap: 1rem;
}

  .board {
    flex-direction: row;
    overflow-x: auto;
  }
  .board__column { flex: 0 0 300px; }
}

/* 3) Desktop (≥ 1024px): aparece la sidebar de 260px. */
@media (min-width: 1024px) {
  .app-shell { grid-template-columns: 260px 1fr; }

/* Componente que se adapta a su propio ancho (no al de la pantalla) */
@container (min-width: 280px) {
  .task-card__meta { display: flex; justify-content: space-between; }
}

/* Respeta a quien pide MENOS movimiento (accesibilidad) */
@media (prefers-reduced-motion: reduce) {
  * { transition: none !important; animation: none !important; }
}

Decisiones del ejemplo: (1) el tema se refleja en data-theme, no en clases sueltas: el CSS cambia «en bloque»; (2) seguimos la preferencia del sistema solo si el usuario no ha elegido; (3) el responsive es mobile-first (base = móvil, mejoramos hacia arriba); (4) usamos grid-template-columns: auto-fill + minmax en lugar de contar columnas a mano; (5) respetamos prefers-reduced-motion.

5 · Buenas prácticas

HazEvitaPor qué
Variables CSS + data-theme Duplicar reglas con .dark .card {} El CSS del componente es uno solo; el tema es «solo» de las variables.
Script anti-FOUC en index.html Dejar que React fije el tema al montar Evita el destello blanco que delata a las apps mal hechas.
Respetar prefers-color-scheme Arrancar siempre en claro Muchos usuarios tienen su SO en oscuro; no les obligues.
Mobile-first (min-width) max-width como estrategia principal Añadir complejidad según crece la pantalla es más limpio y aditivo.
clamp(), minmax(), auto-fill Media queries para cada tamaño Menos CSS y más resistente a tamaños intermedios.
prefers-reduced-motion Animaciones que no se pueden desactivar Hay usuarios a quienes el movimiento les causa mareo o migraña.

6 · Errores habituales

Error 1: el flash blanco al cargar (FOUC)

✘ Incorrecto 
<!-- El tema se pone en React, DESPUÉS de cargar el JS.
     Durante un instante, la página se ve en claro. -->
<body>
  <div id="root"></div>
  <script type="module" src="/src/main.jsx"></script>
</body>
✔ Correcto 
<script>
  // Se ejecuta en el HEAD, antes de pintar: sin destello.
  document.documentElement.dataset.theme =
    localStorage.getItem("taskflow.theme") ||
    (matchMedia("(prefers-color-scheme: dark)").matches ? "dark" : "light");
</script>

Error 2: condicionales de tema por toda la app

✘ Incorrecto 
// La lógica de tema se filtra a cada componente: acoplamiento total.
function Card() {
  const { theme } = useTheme();
  return (
    <div style={{ background: theme === "dark" ? "#171a23" : "#ffffff" }}>
      …
    </div>
  );
}
✔ Correcto 
// El componente no sabe del tema: usa variables CSS.
function Card() {
  return <div className="card">…</div>;
}
// .card { background: var(--surface); }  ← el tema cambia la variable

Error 3: píxeles fijos que rompen el móvil

✘ Incorrecto 
/* 380px de sidebar en una pantalla de 360px = scroll horizontal */
.app-shell { grid-template-columns: 380px 1fr; }
✔ Correcto 
/* Base apilada; la sidebar solo aparece cuando HAY espacio */
.app-shell { grid-template-columns: 1fr; }
@media (min-width: 1024px) {
  .app-shell { grid-template-columns: 260px 1fr; }
}

7 · Ejercicio guiado

  1. Crea src/styles/variables.css con los temas claro y oscuro, e impórtalo desde global.css antes que el resto.

  2. Añade el script anti-FOUC en index.html delante de la carga de React.

  3. Crea src/contexts/ThemeContext.jsx y envuelve la app con ThemeProvider en main.jsx.

  4. Crea ThemeToggle.jsx y colócalo en la Topbar.

  5. Reescribe el CSS de las tarjetas y del layout usando solo variables. Prohibido espiar theme dentro de un componente para colorear.

  6. Comprueba el responsive: abre DevTools → modo dispositivo, prueba a 360 px, 768 px y 1280 px. El tablero debe apilarse, luego ponerse en horizontal con scroll y, al final, mostrar la sidebar fija.

  7. Prueba las preferencias del sistema: en DevTools → Rendering → Emulate CSS media feature prefers-color-scheme, cambia a dark y a light. Sin elección guardada, la app debe seguirlo.

✅ Solución esperada

Al recargar en oscuro no hay destello blanco. El botón alterna el tema y lo recuerda. Sin elección guardada, la app sigue al sistema (y reacciona si cambia en caliente). La interfaz no provoca scroll horizontal a 360 px.

8 · Reto

🎯 Tres modos de tema y transición suave

Lleva el sistema de temas a nivel de producto:

  1. Modo «sistema» además de claro/oscuro: el usuario puede elegir system, light o dark. En system, sigue prefers-color-scheme en vivo; en los otros, gana su elección. Guarda el modo, no el tema resuelto.
  2. Transición suave entre temas: al cambiar, anima los colores (un transition corto sobre background-color y color), pero desactívala si el usuario pide prefers-reduced-motion. Y evita la transición en la primera carga (para no ver una animación desde blanco).
  3. Color de barra del navegador: actualiza el <meta name="theme-color"> al cambiar de tema, para que la barra del navegador móvil combine con la app.
  4. Persistencia por usuario: si hay sesión (lección 2), sincroniza la preferencia con el backend (PATCH /api/auth/me con { themePreference }) para que viaje entre dispositivos.

Pista: separa «modo elegido» (system|light|dark) de «tema resuelto» (light|dark): el primero persiste, el segundo se calcula. Para la transición inicial, añade una clase .no-transitions al <html> y quítala tras el primer frame.

No lo resuelvas todavía. El modo «sistema» y la transición suave son detalles que los usuarios notan y que muy pocas apps hacen bien.

9 · Resumen

  • El tema se implementa con variables CSS y el atributo data-theme en <html>: el resto del CSS no cambia.
  • Un script anti-FOUC en index.html evita el destello blanco al cargar.
  • Prioridad de tema: elección del usuario → prefers-color-scheme → claro.
  • ThemeContext expone el tema solo a quien lo necesita (el botón); los componentes colorean con variables, no con condicionales.
  • Responsive mobile-first con min-width, clamp(), minmax() y container queries.
  • Accesibilidad: aria-pressed en el botón y prefers-reduced-motion respetado.

10 · Preguntas frecuentes

¿Por qué el tema va en data-theme y no en una clase como .dark?

Funcionalmente ambos sirven. data-theme="dark" es más expresivo y permite más de dos temas sin inventar clases combinadas ([data-theme="solarized"]). Además, deja claro que el valor es un dato, no un estilo, y es lo que usan muchas librerías de diseño.

¿Cómo evito el parpadeo del tema al recargar?

Con el script inline en el <head> que fija data-theme antes de pintar (ya lo tienes). React se monta después y encuentra el tema ya aplicado. Este es el detalle que separa un tema bien hecho de uno que «casi» funciona.

¿useDeferredValue sirve para el responsive?

No; son cosas distintas. El responsive es CSS (media y container queries) y no depende de JavaScript. useDeferredValue (lección 7) es para mantener fluida la UI cuando un render de datos es pesado.

¿Cuándo conviene @container en lugar de @media?

Cuando un componente debe adaptarse a donde lo pongas. Una TaskCard puede estar en una columna estrecha o en un panel ancho; con @media no puede saberlo, con @container sí. Regla: @media para el layout global, @container para componentes reutilizables.

¿Debo usar iconos de tema o texto?

Ambos, con aria-label siempre. El icono (🌙/☀️) es compacto, y aria-label garantiza que un lector de pantalla sepa qué hace el botón y cuál es el estado actual (aria-pressed).
