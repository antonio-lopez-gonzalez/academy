WebSockets: Tiempo Real

Módulo 13 · Proyecto Final

Introducción

Cuando varias personas trabajan en el mismo proyecto, nadie quiere recargar la página para ver cambios. Los WebSockets permiten que el servidor avise al frontend cuando ocurre algo, creando una experiencia colaborativa.

¿Por qué no polling?

Técnica Latencia Consumo Complejidad
Polling Alta (segundos) Muchas peticiones HTTP Baja
WebSockets Baja (milisegundos) Una conexión persistente Media

Backend .NET con SignalR

El backend usa SignalR (ver Módulo 14). Cada proyecto es un "grupo" al que se unen los clientes. Cuando alguien crea, mueve o elimina una tarea, el servidor notifica al grupo.

Hook useWebSocket

// src/hooks/useWebSocket.js
import { useEffect, useRef, useCallback } from 'react'
import * as signalR from '@microsoft/signalr'

const HUB_URL = '/hubs/tasks'

export function useWebSocket(projectId, onMessage) {
  const connectionRef = useRef(null)

  useEffect(() => {
    const connection = new signalR.HubConnectionBuilder()
      .withUrl(HUB_URL)
      .withAutomaticReconnect()
      .build()

    connectionRef.current = connection

    connection.on('TaskCreated', (task) => onMessage({ type: 'created', task }))
    connection.on('TaskUpdated', (task) => onMessage({ type: 'updated', task }))
    connection.on('TaskMoved', (task) => onMessage({ type: 'moved', task }))
    connection.on('TaskDeleted', (taskId) => onMessage({ type: 'deleted', taskId }))

    async function start() {
      try {
        await connection.start()
        await connection.invoke('JoinProject', projectId)
      } catch (err) {
        console.error('Error conectando SignalR:', err)
      }
    }

    start()

    return () => {
      connection.invoke('LeaveProject', projectId).catch(() => {})
      connection.stop()
    }
  }, [projectId, onMessage])

  const send = useCallback((methodName, ...args) => {
    connectionRef.current?.invoke(methodName, ...args)
  }, [])

  return { send }
}

Integración con el tablero

// src/components/tasks/TaskBoard.jsx
import { useTasks } from '../../hooks/useTasks'
import { useWebSocket } from '../../hooks/useWebSocket'
import TaskColumn from './TaskColumn'
import styles from './TaskBoard.module.css'

export default function TaskBoard({ projectId }) {
  const { tasks, setTasks, loading } = useTasks(projectId)

  useWebSocket(projectId, (message) => {
    setTasks((prev) => {
      switch (message.type) {
        case 'created':
          return [...prev, message.task]
        case 'updated':
        case 'moved':
          return prev.map((t) => (t.id === message.task.id ? message.task : t))
        case 'deleted':
          return prev.filter((t) => t.id !== message.taskId)
        default:
          return prev
      }
    })
  })

  if (loading) return <div>Cargando tareas...</div>

  return (
    <div className={styles.board}>
      {/* Columnas */}
    </div>
  )
}

Optimismo vs pesimismo

  • Optimista: actualizas la UI primero y luego envías al servidor. Más rápido, pero puede revertirse si falla.
  • Pesimista: esperas la respuesta del servidor antes de actualizar. Más seguro, pero percibido como lento.

En TaskFlow usamos optimismo para movimientos dentro del tablero y pesimismo para creaciones que requieren validación.

Resumen

  • SignalR abstrae WebSockets con reconexión automática
  • Cada proyecto es un grupo; los clientes se unen al entrar
  • useWebSocket escucha eventos y actualiza el estado de React
  • Limpia la conexión al desmontar para evitar fugas
  • Combina actualizaciones locales con notificaciones del servidor
