Comentarios y subtareas

Módulo 13 · Proyecto final: TaskFlow 🕐 45 minutos

1 · Introducción

Una tarea rara vez se hace de golpe. En la vida real una tarea se descompone en subtareas («haz A, luego B, luego C») y se acompaña de comentarios («ojo, que el endpoint cambió»). Estas dos features son las que convierten una lista de tareas en una herramienta de colaboración.

Qué vamos a aprender hoy: a añadir un checklist de subtareas con su barra de progreso y un hilo de comentarios con avatares y fechas. Y, sobre todo, a hacerlo con la herramienta que React 19 trajo para esto: useOptimistic.

Qué problema resuelve: comentar es una acción «social»: el usuario espera que su mensaje aparezca al instante, aunque el servidor tarde 400 ms. Si esperas la respuesta, la sensación es de lentitud. useOptimistic permite mostrar el comentario inmediatamente y «cuadrarlo» con el servidor cuando llega la respuesta, deshaciéndolo automáticamente si algo falla.

Cuándo se utiliza: en cualquier lista de mensajes, «likes», envíos de formularios o checkboxes donde la latencia se nota. Es una de las novedades estrella de React 19.

Errores típicos: guardar subtareas y comentarios dentro del objeto tarea del estado global (inmutabilidad anidada dolorosa), o refrescar todo el panel tras comentar en lugar de insertar el nuevo comentario.

useOptimistic: estado que vive «yendo y viniendo»

useOptimistic es un hook de React 19 que devuelve dos cosas: una versión optimista del estado y una función para añadir un valor optimista temporalmente. Su magia: el valor optimista se descarta automáticamente cuando termina la transición en la que se añadió. Si la acción falla, el valor temporal desaparece solo.

const [optimistic, addOptimistic] = useOptimistic(realComments, reducer) render → se muestra "optimistic" (= real + temporales) 1. usuario envía "Hola" 2. addOptimistic({ id:"temp", body:"Hola", pending:true }) → aparece YA 3. await POST /comments (transición en curso) 4. el servidor responde y actualizas el estado REAL → llega el comentario real 5. al terminar la transición, React DESCARTA el temporal Si el POST falla → la transición termina igual → el temporal desaparece solo.
📌 useOptimistic no sustituye al estado real

El estado optimista es una capa temporal encima del estado real. Tú sigues actualizando el estado real cuando el servidor responde; el optimista solo cubre la ventana de espera. Por eso el segundo argumento (reducer) define cómo combinar lo real con lo temporal.

Inmutabilidad anidada, sin dramas

Marcar una subtarea exige actualizar un array dentro de un objeto dentro de un array (tareas → tarea → subtasks → subtarea). El truco es componer map + spread nivel a nivel: cada nivel devuelve una copia nueva. Es tedioso pero mecánico, y solo se hace en un sitio.

actualización inmutable a 3 niveles
setTasks((current) =>
  current.map((task) =>
    task.id === taskId
      ? {
          ...task,
          subtasks: task.subtasks.map((sub) =>
            sub.id === subId ? { ...sub, done: !sub.done } : sub
          ),
        }
      : task
  )
);

3 · Ejemplo mínimo

El ejemplo más pequeño de useOptimistic: un contador de «me gusta» que sube antes de que el servidor responda.

src/components/tasks/LikeButton.jsx
import { useOptimistic, useTransition } from "react";

// actions.like(id) es una función que habla con la API y actualiza el
// estado real del componente padre.
export default function LikeButton({ likes, onLike }) {
  // useOptimistic(base, reducer): "base" es el estado REAL (likes).
  // El reducer describe cómo aplicar un cambio optimista sobre ese valor.
  const [optimisticLikes, addOptimisticLike] = useOptimistic(
    likes,
    (current, _increment) => current + 1
  );

  const [isPending, startTransition] = useTransition();

  function handleClick() {
    // startTransition es la ventana durante la cual el valor optimista
    // permanece. Al terminar, React lo descarta.
    startTransition(async () => {
      addOptimisticLike();
      await onLike(); // aquí el padre actualiza "likes" real
    });
  }

  return (
    <button onClick={handleClick} disabled={isPending}>
      ❤️ {optimisticLikes}
    </button>
  );
}

Línea por línea:

  1. useOptimistic(likes, reducer) — likes es el valor real; el reducer define qué hacer con el cambio temporal (aquí, +1).
  2. addOptimisticLike() — aplica el cambio temporal; el contador sube al instante.
  3. await onLike() — el padre hace el POST y actualiza el estado real; el optimista y el real convergen.
  4. Al salir de la transición, el valor optimista se descarta. Si onLike hubiera fallado, habría vuelto solo.

4 · Ejemplo real

El panel de detalle completo: lista de subtareas con progreso y hilo de comentarios optimista.

src/services/taskDetailService.js
import { request } from "./apiClient.js";

export const commentService = {
  // GET /api/tasks/{taskId}/comments → { items }
  list: (taskId) => request(`/tasks/${taskId}/comments`),

  // POST /api/tasks/{taskId}/comments → { comment }
  create: (taskId, body) =>
    request(`/tasks/${taskId}/comments`, { method: "POST", body: { body } }),

  // DELETE /api/comments/{id} → 204
  remove: (commentId) => request(`/comments/${commentId}`, { method: "DELETE" }),
};

export const subtaskService = {
  // POST /api/tasks/{taskId}/subtasks → { subtask }
  create: (taskId, title) =>
    request(`/tasks/${taskId}/subtasks`, { method: "POST", body: { title } }),

  // PATCH /api/subtasks/{id} → { subtask }  (cambios parciales: done, title)
  update: (subtaskId, changes) =>
    request(`/subtasks/${subtaskId}`, { method: "PATCH", body: changes }),

  // DELETE /api/subtasks/{id} → 204
  remove: (subtaskId) => request(`/subtasks/${subtaskId}`, { method: "DELETE" }),
};
src/components/tasks/SubtaskList.jsx
import { useState } from "react";

// Lista de subtareas con barra de progreso. El padre (TaskPanel) es
// dueño del array y nos avisa con callbacks.
export default function SubtaskList({ subtasks, onToggle, onAdd, onRemove }) {
  const [draft, setDraft] = useState("");

  // Progreso DERIVADO: no lo guardamos, lo calculamos.
  const done = subtasks.filter((s) => s.done).length;
  const total = subtasks.length;
  const percent = total === 0 ? 0 : Math.round((done / total) * 100);

  function handleAdd(event) {
    event.preventDefault();
    const title = draft.trim();
    if (title === "") return;
    onAdd(title);
    setDraft("");
  }

  return (
    <section className="subtasks">
      <header className="subtasks__header">
        <h4>Subtareas</h4>
        <span className="subtasks__progress-text">
          {done}/{total} · {percent}%
        </span>
      </header>

      <!-- Barra de progreso accesible con role="progressbar" -->
      <div
        className="progress"
        role="progressbar"
        aria-valuenow={percent}
        aria-valuemin={0}
        aria-valuemax={100}
      >
        <div className="progress__bar" style={{ width: `${percent}%` }} />
      </div>

      <ul className="subtasks__list">
        {subtasks.map((sub) => (
          <li key={sub.id} className={sub.done ? "subtask subtask--done" : "subtask"}>
            <label>
              <input
                type="checkbox"
                checked={sub.done}
                onChange={() => onToggle(sub.id)}
              />
              <span>{sub.title}</span>
            </label>
            <button
              onClick={() => onRemove(sub.id)}
              aria-label={`Borrar subtarea ${sub.title}`}
            >
              🗑
            </button>
          </li>
        ))}
      </ul>

      <form className="subtasks__add" onSubmit={handleAdd}>
        <input
          value={draft}
          onChange={(e) => setDraft(e.target.value)}
          placeholder="Nueva subtarea…"
          aria-label="Nueva subtarea"
        />
        <button type="submit" disabled={draft.trim() === ""}>Añadir</button>
      </form>
    </section>
  );
}
src/components/tasks/CommentThread.jsx — optimista con React 19
import { useOptimistic, useState } from "react";

// Formateo relativo sencillo (en la lección 7 lo extraeremos a utils/format.js).
function timeAgo(isoDate) {
  const seconds = Math.floor((Date.now() - new Date(isoDate)) / 1000);
  if (seconds < 60) return "hace un momento";
  if (seconds < 3600) return `hace ${Math.floor(seconds / 60)} min`;
  if (seconds < 86400) return `hace ${Math.floor(seconds / 3600)} h`;
  return new Date(isoDate).toLocaleDateString();
}

// reducer: cómo combinar los comentarios REALES con los OPTIMISTAS.
function commentsReducer(current, newComment) {
  return [...current, newComment];
}

export default function CommentThread({ comments, currentUser, onAdd }) {
  const [draft, setDraft] = useState("");

  // Base = comentarios reales. capa temporal = comentarios pendientes.
  const [optimisticComments, addOptimisticComment] = useOptimistic(
    comments,
    commentsReducer
  );

  async function handleSubmit(event) {
    event.preventDefault();
    const body = draft.trim();
    if (body === "") return;

    setDraft("");

    // Añadimos el comentario "fantasma" con id temporal y flag pending.
    addOptimisticComment({
      id: `temp-${crypto.randomUUID()}`,
      body,
      author: currentUser,
      createdAt: new Date().toISOString(),
      pending: true,
    });

    // El padre hace el POST y actualiza el estado REAL de comentarios.
    await onAdd(body);
  }

  return (
    <section className="comments">
      <h4>Comentarios</h4>

      <ul className="comments__list">
        {optimisticComments.map((comment) => (
          <li
            key={comment.id}
            className={comment.pending ? "comment comment--pending" : "comment"}
          >
            <span className="comment__avatar">
              {comment.author.displayName.charAt(0).toUpperCase()}
            </span>
            <div className="comment__body">
              <header>
                <strong>{comment.author.displayName}</strong>
                <time>{comment.pending ? "enviando…" : timeAgo(comment.createdAt)}</time>
              </header>
              <p>{comment.body}</p>
            </div>
          </li>
        ))}
      </ul>

      <form className="comments__form" onSubmit={handleSubmit}>
        <textarea
          value={draft}
          onChange={(e) => setDraft(e.target.value)}
          placeholder="Escribe un comentario…"
          rows={2}
        />
        <button type="submit" disabled={draft.trim() === ""}>Comentar</button>
      </form>
    </section>
  );
}

Decisiones del ejemplo: (1) el progreso de subtareas es derivado; (2) commentsReducer vive fuera del componente (no se recrea en cada render); (3) el comentario optimista lleva pending: true para pintarlo con opacidad y mostrar «enviando…»; (4) el estado real de comentarios lo actualiza el padre cuando el POST responde, y el optimista se descarta solo.

5 · Buenas prácticas

Comentarios en estado propio (no dentro de la tarea) Anidar task.comments[] en el estado global Los comentarios crecen; aislarlos permite paginar y cargar solo al abrir.

6 · Errores habituales

Error 1: marcar la subtarea mutando el array anidado

✘ Incorrecto 
// Buscar y mutar: React no detecta el cambio (misma referencia).
const task = tasks.find((t) => t.id === taskId);
const sub = task.subtasks.find((s) => s.id === subId);
sub.done = !sub.done;
setTasks(tasks);
✔ Correcto 
setTasks((current) =>
  current.map((task) =>
    task.id === taskId
      ? {
          ...task,
          subtasks: task.subtasks.map((s) =>
            s.id === subId ? { ...s, done: !s.done } : s
          ),
        }
      : task
  )
);

Error 2: usar useOptimistic sin estado real que actualizar

✘ Incorrecto 
// El optimista se descarta al terminar la transición, pero nunca
// actualizamos el estado real: el comentario DESAPARECE.
addOptimisticComment({ body });
await onAdd(body); // onAdd no actualiza "comments" → el comentario se pierde
✔ Correcto 
// onAdd hace el POST y, con la respuesta, actualiza el estado REAL:
async function onAdd(body) {
  const { comment } = await commentService.create(taskId, body);
  setComments((current) => [...current, comment]); // ← estado real
}

Por qué: useOptimistic es una capa temporal sobre un estado real. Si el real no cambia, no hay nada que sostenga el cambio al terminar la transición.

Error 3: cargar todos los comentarios con cada render

✘ Incorrecto 
// Sin array de dependencias: se ejecuta en CADA render → bucle infinito
useEffect(() => {
  commentService.list(taskId).then(setComments);
});
✔ Correcto 
useEffect(() => {
  commentService.list(taskId).then(({ items }) => setComments(items));
}, [taskId]); // solo cuando cambia la tarea abierta

8 · Reto

🎯 Hilo de comentarios con respuestas y actividad

Amplía los comentarios hacia una conversación real:

  1. Respuestas anidadas: permite responder a un comentario (parentId). Renderiza las respuestas indentadas. Piensa cómo modelar el árbol sin anidar indefinidamente (una lista plana con parentId y un agrupado derivado es más escalable que anidar objetos).
  2. Editar y borrar: solo el autor puede editar o borrar su comentario. Muestra «(editado)» cuando ha cambiado.
  3. Registro de actividad: añade un panel que muestre un historial («Ana cambió el estado a Hechas», «Luis añadió las etiquetas»). Estos eventos los emite el backend; tú solo los pintas en orden cronológico descendente.
  4. Optimista también al borrar: al borrar un comentario, quítalo de la lista al instante y restaura si el servidor falla.

Pista: para las respuestas, define const tree = comments.filter(c => c.parentId === root.id) y recurre. Para no pintar respuestas de un comentario ya borrado, el backend debe devolver los borrados «suaves» o reasignar los hijos.

No lo resuelvas todavía. Un sistema de comentarios con respuestas bien modelado es un ejercicio excelente de estructuras de datos y renderizado recursivo.

9 · Resumen

  • Subtareas y comentarios viven «dentro» de la tarea pero se modelan distinto: checklist junto a la tarea, comentarios aparte.
  • useOptimistic (React 19) muestra el cambio antes de la respuesta y lo descarta solo al terminar la transición.
  • El estado optimista complementa al real: siempre actualiza el real con la respuesta del servidor.
  • Inmutabilidad anidada se resuelve componiendo map + spread nivel a nivel.
  • El progreso de subtareas es un valor derivado, nunca estado.
  • Accesibilidad: role="progressbar" con aria-valuenow para que el progreso se anuncie.

10 · Preguntas frecuentes

¿Cuál es la diferencia entre useOptimistic y actualizar el estado a mano?

Hacerlo a mano implica: añadir el elemento, recordar quitarlo si falla, distinguir temporales de reales… useOptimistic automatiza el ciclo de vida del valor temporal (vive dentro de una transición y se descarta solo). Menos código y menos bugs.

¿Puedo usar useOptimistic sin startTransition?

El valor optimista solo persiste mientras dura una transición. Si lo usas dentro de un formulario con action (Form Actions de React 19), la transición la gestiona React. Si no, envuélvelo tú con startTransition como en el ejemplo mínimo.

¿Debo cargar todos los comentarios de golpe?

En tareas con pocos comentarios, sí. Con muchos, pagina o carga bajo demanda («ver 20 más»). Modelar los comentarios en estado propio (no dentro de la tarea) es justo lo que hace posible esa paginación sin tocar el estado global.

¿Cómo evito que las subtareas se reordenen al marcarlas?

Ordena por un campo estable (position) en lugar de por el orden de llegada. Y usa key={sub.id}, nunca el índice: al reordenar, React debe poder seguir cada subtarea por su identidad (Módulo 2).

¿Los comentarios deberían llegar en tiempo real a los demás usuarios?

Sí, y lo haremos con WebSockets en la lección 9. El estado optimista y el tiempo real se complementan: tú ves tu comentario al instante (optimista) y los demás lo reciben por el socket cuando el servidor lo publica.
