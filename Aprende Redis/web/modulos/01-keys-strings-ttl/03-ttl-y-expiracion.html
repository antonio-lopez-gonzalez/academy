TTL y expiración: EXPIRE y presencia

Módulo 1 · Keys, Strings y TTL ⏱ 35 minutos

1 · Introducción

La expiración es el superpoder silencioso de Redis: una key con TTL se borra sola. Es lo que convierte «presencia de conexiones» en algo que se limpia sin cron ni garbage collector manual.

Verás los comandos (EXPIRE/TTL/PERSIST), cómo funciona bajo el capó (lazy + active) y el patrón TTL que se refresca (heartbeat) que usará tu hub.

2 · Teoría

Comandos

EXPIRE key 30           # fija/refresca expiración en s
PEXPIRE key 30000       # en ms
TTL key                 # segundos restantes (-1 sin TTL, -2 no existe)
PTTL key                # ms
PERSIST key             # quita el TTL
SETEX key 30 valor      # crear + TTL en un comando

Cómo expira Redis (bajo el capó)

  • Lazy: al acceder a una key expirada, Redis la borra en ese momento.
  • Active: en segundo plano, Redis muestrea keys con TTL y elimina las vencidas (evita que las expiradas «ocupen» memoria por no leerse nunca).

Implicación práctica: una key expirada no se nota hasta que la tocas; los «contadores de expirados» no son en tiempo real, y una key nunca leída pero vencida tarda un poco en liberar RAM.

El patrón heartbeats / presencia

cliente conecta → SETEX hub:conn:<id> 30 node-1
cada 10-20 s     → EXPIRE hub:conn:<id> 30   (refresh)
si se cae       → nadie refresca → expira sola en ~30 s
¿está vivo?      → EXISTS hub:conn:<id>    (1 = sí)

Es un lease: la existencia de la key significa «visto hace poco». Sin cron, sin listas negras.

3 · Ejemplo mínimo

SET hub:conn:8632 node-1
EXPIRE hub:conn:8632 30
TTL hub:conn:8632          # ~29
EXPIRE hub:conn:8632 60    # refresca a 60
PERSIST hub:conn:8632      # sin TTL (-1) → ¡desconexión nunca limpiada!
EXISTS hub:conn:8632

Nota el peligro de PERSIST en presencia: si dejas de expirar, el registro queda «eterno».

4 · Ejemplo real

El heartbeat del hub, con el refresco en un intervalo mucho menor que el TTL (para aguantar latencias de red):

// En el proyecto redis-ws-hub
const TimeSpan lease = TimeSpan.FromSeconds(30);

// Al conectar:
await db.StringSetAsync($"hub:conn:{connectionId}", _nodeId, lease);

// En el heartbeat del socket (cada 10 s):
await db.KeyExpireAsync($"hub:conn:{connectionId}", lease);

// ¿Vivo? En operaciones: 
bool alive = await db.KeyExistsAsync($"hub:conn:{connectionId}");
if (!alive) { /* el cliente se fue o caducó; cerrar */ }

Si el nodo muere, deja de refrescar; en ~30 s la presencia desaparece sin intervención.

6 · Errores habituales

Renovar después de que venció (raza)

// ❌ KeyExpire puede llegar cuando la key ya no existe → sin efecto
await db.KeyExpireAsync(key, lease);
// ✅ Mejor: al refrescar, también valida con un SET KEEPTTL si aplica
//    o reintenta registrar la presencia si ya expiró.

Toma de decisión con TTL==0

Esperar TTL == 0 para «confirmar» la muerte es frágil: usa EXISTS o trata TTL==-2 (no existe) y -1 (sin TTL) con claridad.

7 · Ejercicio guiado

  1. Paso 1: Crea hub:conn:1 con valor node-1 y TTL 30.
  2. Paso 2: Espera 5 s, refresca con EXPIRE hub:conn:1 30 y anota el TTL.
  3. Paso 3: No toques nada y espera 35 s: EXISTS hub:conn:1 debe dar 0 (expirada).
  4. Paso 4: Comprueba TTL de una key sin TTL (debe dar -1).

8 · Reto

🎯 Presencia en los 3 estados

Diseña con Redis-cli una sesión de prueba que muestre los 4 valores de TTL y su significado correcto (sano, refrescado, sin TTL, no existe) y un mini-heartbeat que no deje la key sin expirar. Escríbelo como guión con comentarios.

9 · Resumen

  • EXPIRE/TTL/PERSIST/SETEX gestionan la vida de las keys.
  • Expiración lazy + active: no percibes la clave hasta que la tocas.
  • Heartbeat = refrescar el TTL → presencia que se limpia sola.
  • Lease ≫ intervalo de refresh para tolerar latencia.

10 · Preguntas frecuentes

¿El TTL consume CPU?

Muy poco: Redis muestrea periodicamente y borra. El coste real está en las keys sin TTL que nunca borras por código.

¿Puedo refrescar el TTL sin reescribir el valor?

Sí: EXPIRE (o KeyExpireAsync) solo toca el TTL; o SET ... KEEPTTL para escribir valor conservando vida.
