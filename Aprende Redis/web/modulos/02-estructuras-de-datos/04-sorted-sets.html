Sorted sets: last-seen y rate limiting

Módulo 2 · Estructuras de Datos ⏱ 35 minutos

1 · Introducción

Un sorted set (zset) es un set donde cada miembro lleva un score (número) que define el orden. Es la estructura perfecta para presencia con tiempo (score = timestamp), rankings y ventanas deslizantes.

Verás los comandos, el patrón «presencia con eviction natural» y cómo responder «¿quiénes están conectados desde hace X?» y «¿cuántos eventos en los últimos 60 segundos?».

2 · Teoría

Comandos

ZADD presence 1750000000 user:42       # añade con score
ZSCORE presence user:42                # su score
ZINCRBY presence 1 user:42             # +1 al score
ZCARD presence                         # nº de miembros
ZRANGEBYSCORE presence -inf +inf [WITHSCORES]
ZRANGEBYSCORE presence 1749913600 +inf # los "después de" un límite
ZRANGE presence 0 2                    # por rango posicional
ZREM presence user:42                  # quitar miembro
ZREMRANGEBYSCORE presence -inf 1749913600   # quitar los viejos (limpieza)

El patrón «presencia con score = timestamp»

ZADD presence <now> user:42
consulta: ¿quiénes están online (últimos 60 s)?
   ZRANGEBYSCORE presence <now-60> +inf
limpieza (cada tanto):
   ZREMRANGEBYSCORE presence -inf <now-60>
conteo:  ZCARD

Doble virtud: ordenada por tiempo y cada miembro puede expirarse/limpiarse individualmente — algo que el set no puede (M2-03 lo dejó abierto).

Rate limiting con ventana deslizante

ZADD rl:user:42 <now_ms1> req1          # cada petición
ZREMRANGEBYSCORE rl:user:42 -inf <now_ms1-60000>  # quitar las viejas
ZCARD rl:user:42                       # peticiones en 60 s
EXPIRE rl:user:42 65                  # evitar deuda de memoria

Es más preciso que el fixed-window (M1-04) aunque algo más caro; un zset por usuario.

3 · Ejemplo mínimo

ZADD scoreboard 100 ana 90 luis 80 carlos
ZREVRANGEBYSCORE scoreboard +inf -inf LIMIT 0 2   # top 2 (orden desc)
ZSCORE scoreboard ana          # 100
ZINCRBY scoreboard 10 ana      # 110
ZCARD scoreboard               # 3
ZREM scoreboard carlos

4 · Ejemplo real

Presencia del hub: «usa el zset como lista de online y el hash para el detalle de cada conexión» (M7 lo monta entero):

long now = DateTimeOffset.UtcNow.ToUnixTimeSeconds();

// Heartbeat de un usuario: refresca su score = "último latido"
await db.SortedSetAddAsync("hub:presence", userId, now);

// ¿Quiénes están online (últimos 60 s)?
long cutoff = now - 60;
var online = await db.SortedSetRangeByScoreAsync("hub:presence", cutoff, double.PositiveInfinity);
// limpieza perezosa
await db.SortedSetRemoveRangeByScoreAsync("hub:presence", double.NegativeInfinity, cutoff);
// tamaño
long count = await db.SortedSetLengthAsync("hub:presence");

Ningún cron externo: la «desconexión» se vuelve «score antiguo» que se limpia y no cuenta.

6 · Errores habituales

Usar ZRANGE como si fuera equivalente a ZRANGEBYSCORE

# ❌ ZRANGE presence 0 -1  devuelve el top por posición, no por tiempo
# ✅ ZRANGEBYSCORE presence <cutoff> +inf  (ventana temporal)

Score con precisión de ms donde era segundos → cuenta distinta

Decide la granularidad del score (s vs ms) y mantenla coherente con el cutoff; mezclar escalas rompe la ventana.

7 · Ejercicio guiado

  1. Paso 1: Crea presence con 4 usuarios y scores de hace 0, 10, 120, 300 s.
  2. Paso 2: Consulta los «de los últimos 60 s» con ZRANGEBYSCORE.
  3. Paso 3: Limpia con ZREMRANGEBYSCORE y comprueba ZCARD.
  4. Paso 4: Simula un rate limit: añade timestamps por segundo y cuenta los de la última ventana.

8 · Reto

🎯 Ranking «online» del hub

Diseña el zset de presencia que muestre «los 10 usuarios más activos de la última hora» usando ZINCRBY cada vez que procesan un mensaje, con limpieza por ventana. ¿Qué consulta usarías y con qué frecuencia la limpiarías? Pruébalo en redis-cli.

9 · Resumen

  • Sorted set = miembros únicos con score que ordena.
  • Score = timestamp → presencia, last-seen y ventanas deslizantes.
  • ZREMRANGEBYSCORE = limpieza natural por antigüedad.
  • Combina con hash para el detalle de cada miembro.

10 · Preguntas frecuentes

¿Cuándo sorted set sobre set?

Cuando el orden/score importe: tiempo, ranking, prioridad. Si solo necesitas membrecía, un set es más barato.

¿Puedo usar decimales en el score?

Sí (doubles), aunque Redis los almacena como integer o double y evita precision losses para enteros. Para timestamps en ms son enteros → perfecto.
