Iteradores y generadores

Módulo 3 · Colecciones avanzadas ⏱ 35 minutos

1 · Introducción

Cada vez que escribes for x in algo, Python está usando el protocolo de iteración: un contrato de dos métodos que permite recorrer cualquier cosa —listas, diccionarios, ficheros, rangos, incluso datos que aún no existen— con la misma sintaxis. En esta lección abrimos esa caja: __iter__, __next__ y StopIteration.

Después conocerás los generadores: funciones que producen valores a demanda con yield. Son la herramienta clave para procesar datos grandes o infinitos con memoria constante, y la base de itertools, asyncio y los pipelines de datos que verás más adelante.

¿Por qué existe todo esto? Porque no siempre quieres —ni puedes— tener todos los datos en memoria a la vez. Un fichero de 10 GB, una lectura de un sensor infinito o una consulta paginada se procesan mejor «de a uno». Los iteradores son la abstracción que hace que un for funcione igual sobre una lista de 5 elementos que sobre un flujo que nunca termina. Sin ellos, cada fuente de datos necesitaría su propia sintaxis de recorrido.

Analogía: una lista es una caja con todas las piezas ya fabricadas. Un iterador es una cinta transportadora: pides la siguiente pieza con next(), te la da, y cuando se acaban salta un StopIteration. Un generador es la fábrica que alimenta esa cinta: fabrica cada pieza justo cuando la pides.

Errores típicos: creer que un generador se puede recorrer dos veces (no: se agota), usar return donde iba yield, olvidar que StopIteration es la señal normal de fin (no un error que haya que capturar), o crear un generador infinito y volcarlo en list() sin condición de parada.

2 · Teoría

Iterable ≠ iterador

Son dos conceptos distintos que a menudo se mezclan:

  • Iterable: objeto del que se puede obtener un iterador. Implementa __iter__. Ejemplos: list, str, dict, range, ficheros abiertos.
  • Iterador: objeto que produce valores uno a uno y recuerda en qué punto va. Implementa __next__ (y también __iter__, que suele devolverse a sí mismo).

Un iterable no es un iterador, pero todo iterador es iterable. El for hace el trabajo de puente:

# Lo que crees que hace el for...
for item in LIBRARY:
    print(item["title"])
# ...es en realidad esto:
iterator = iter(LIBRARY)          # pide un iterador
while True:
    try:
        item = next(iterator)     # pide el siguiente
    except StopIteration:         # se acabó: señal NORMAL, no error
        break
    print(item["title"])

¿Por qué un protocolo y no un tipo base? Porque Python prefiere duck typing: cualquier objeto que implemente __iter__ y __next__ funciona en un for, sin heredar de nada. No hay una interfaz Iterable que «firmar»: si los métodos están, el objeto itera. Eso es lo que permite que bibliotecas y código tuyo se integren sin acoplarse a una jerarquía de clases.

Un iterador a mano

Antes de los generadores, para crear un iterador había que escribir una clase. Aún conviene verlo una vez para entender qué esconde yield:

class Countdown:
    """Iterador que cuenta hacia atrás desde 'start' hasta 1."""
    def __init__(self, start):
        self.current = start          # estado: en qué punto voy
    def __iter__(self):
        return self                   # un iterador se devuelve a sí mismo
    def __next__(self):
        if self.current <= 0:          # condición de fin
            raise StopIteration        # señal de "no hay más"
        value = self.current
        self.current -= 1              # avanzo el estado
        return value
for n in Countdown(3):
    print(n)
# Salida: 3
#         2
#         1

Generadores: iteradores con función

Escribir la clase anterior es verboso. Un generador logra lo mismo con una función que usa yield: Python guarda la posición de la función y la reanuda en cada next().

def countdown(start):
    """Generador: mismo resultado que la clase Countdown, en 4 líneas."""
    while start > 0:
        yield start          # devuelve el valor Y PAUSA aquí
        start -= 1
# Llamar a la función NO ejecuta el cuerpo: devuelve un generador
gen = countdown(3)
print(gen)
# Salida: <generator object countdown at 0x...>
print(next(gen))  # 3  ← empieza a ejecutar y se detiene en el yield
print(next(gen))  # 2
print(next(gen))  # 1
# next(gen)  →  StopIteration

Diferencia clave entre return y yield: return termina la función y entrega un valor único. yield pausa la función, entrega un valor y deja todo como estaba para reanudar. Si una función contiene yield, ya no es una función normal: es una fábrica de generadores.

Pereza (laziness) y memoria

Un generador no calcula todos los valores por adelantado: los produce bajo demanda. Esa es la diferencia fundamental con una lista.

Lista completa Generador (perezoso) ┌──────────────────────────┐ ┌───────────────────────┐ │ ■ ■ ■ ■ ■ ■ ■ ■ │ │ ■ → ■ → ■ → ■ → ... │ └──────────────────────────┘ └───────────────────────┘ Todos los elementos en Un elemento a la vez; memoria desde el principio. memoria constante. 
import sys
# Una lista materializa todo: ocupa memoria proporcional al tamaño
data_list = [n * n for n in range(1_000_000)]
print(sys.getsizeof(data_list))
# Salida: 8448728  (unos 8 MB, solo la lista; los ints van aparte)
# Un generador no guarda los valores: solo su estado
data_gen = (n * n for n in range(1_000_000))
print(sys.getsizeof(data_gen))
# Salida: 208  (el tamaño NO depende del rango)

Expresión generadora: exactamente igual que una list comprehension, pero con paréntesis. Si solo vas a recorrer los valores una vez, quita los corchetes y ahorra memoria: sum(len(t) for t in titles).

# List comprehension: crea la lista [4, 4, 12] entera primero
titles = ["1984", "Dune", "Blade Runner"]
total = sum([len(t) for t in titles])
# Expresión generadora: sin corchetes, produce y consume al vuelo
total = sum(len(t) for t in titles)      # no crea ninguna lista
print(total)
# Salida: 20

Un generador se agota. A diferencia de una lista, una vez recorrido no «rebobina». Si necesitas recorrerlo dos veces, o bien lo conviertes a lista una vez, o bien llamas otra vez a la función generadora (que crea uno nuevo).

3 · Ejemplo mínimo

Un generador que filtra solo las películas del catálogo. No se calcula nada hasta pedir el primer valor.

LIBRARY = [
    {"id": "1", "title": "1984", "kind": "book", "borrowed": False},
    {"id": "2", "title": "Dune", "kind": "book", "borrowed": True},
    {"id": "3", "title": "Blade Runner", "kind": "movie", "borrowed": False},
]
def movies(items):
    """Genera el título de cada ítem que sea una película."""
    for item in items:
        if item["kind"] == "movie":
            yield item["title"]
# Recorrido perezoso: 'yield' se ejecuta vuelta a vuelta
for title in movies(LIBRARY):
    print(title)
# Salida: Blade Runner
# También con next() de uno en uno
gen = movies(LIBRARY)
print(next(gen))
# Salida: Blade Runner

Línea por línea: movies(LIBRARY) no imprime nada todavía; devuelve un generador en pausa. El for pide el primer valor, movies recorre hasta encontrar la película, hace yield y se queda esperando. Al pedir el siguiente, continúa desde donde estaba, no desde el principio.

4 · Ejemplo real

En Biblioteca los datos reales vivirán en data/library.json (Módulo 6), que puede tener miles de ítems. Un generador evita cargar en memoria toda la lista transformada solo para encontrar el primer disponible.

LIBRARY = [
    {"id": "1", "title": "1984", "kind": "book", "year": 1949, "borrowed": True},
    {"id": "2", "title": "Dune", "kind": "book", "year": 1965, "borrowed": False},
    {"id": "3", "title": "Blade Runner", "kind": "movie", "year": 1982, "borrowed": False},
    {"id": "4", "title": "Fahrenheit 451", "kind": "book", "year": 1953, "borrowed": False},
]
def available_after(items, year):
    """Genera (id, título) de los ítems disponibles publicados después de 'year'."""
    for item in items:
        if not item["borrowed"] and item["year"] > year:
            yield item["id"], item["title"]
# 1) Tomar solo el PRIMER resultado válido (sin calcular el resto)
first = next(available_after(LIBRARY, 1950), None)
print(first)
# Salida: ('2', 'Dune')
# 2) Recorrerlos todos y acumular en una lista (cuando sí los quiero)
results = list(available_after(LIBRARY, 1950))
print(results)
# Salida: [('2', 'Dune'), ('3', 'Blade Runner'), ('4', 'Fahrenheit 451')]
# 3) Combinar con un agregador perezoso: ¿hay alguno disponible?
has_available = any(title for _id, title in available_after(LIBRARY, 1900))
print(has_available)
# Salida: True
# 4) Contar sin materializar: sum() consume el generador al vuelo
count_2000 = sum(1 for item in LIBRARY if item["year"] > 2000)
print(count_2000)
# Salida: 0

Decisiones y por qué: next(gen, None) devuelve None en vez de lanzar StopIteration si no hay resultados, lo que hace el código más robusto que un try/except para una simple búsqueda. El generador available_after no se agota antes de tiempo: next solo ejecuta hasta el primer yield. Y en (3) y (4), any y sum se cortocircuitan o consumen al vuelo, sin listas intermedias.

6 · Errores habituales

1. Recorrer un generador dos veces

❌ Incorrecto 
gen = (x * 2 for x in [1, 2, 3])
print(list(gen))   # [2, 4, 6]
print(list(gen))   # []  ← ¡vacío! ya se agotó
✅ Correcto 
# Si necesitas recorrer varias veces, materializa UNA vez
data = list(x * 2 for x in [1, 2, 3])
print(data)  # [2, 4, 6]
print(data)  # [2, 4, 6]

2. Confundir return con yield

# ❌ return corta la función en la primera vuelta
def broken(items):
    for item in items:
        return item["title"]      # sale en el primer ítem
print(list(broken(LIBRARY)))
# Salida: ['1984']
# ✅ yield pausa y continúa con el siguiente
def fixed(items):
    for item in items:
        yield item["title"]
print(list(fixed(LIBRARY)))
# Salida: ['1984', 'Dune', 'Blade Runner']

3. Volcar un generador infinito

❌ Incorrecto 
def ids():
    n = 0
    while True:
        n += 1
        yield n
# list(ids())  ← se queda sin memoria: nunca llega a StopIteration
✅ Correcto 
gen = ids()
# Consumir solo lo que necesito, con un límite explícito
first_three = [next(gen) for _ in range(3)]
print(first_three)
# Salida: [1, 2, 3]

7 · Ejercicio guiado

Objetivo: construir un pequeño pipeline perezoso sobre el catálogo de Biblioteca.

  1. Paso 1 — El generador base: libros publicados después de un año. 
    LIBRARY = [
    {"title": "1984", "kind": "book", "year": 1949, "borrowed": False},
    {"title": "Dune", "kind": "book", "year": 1965, "borrowed": True},
    {"title": "Blade Runner", "kind": "movie", "year": 1982, "borrowed": False},
    {"title": "Fahrenheit 451", "kind": "book", "year": 1953, "borrowed": False},
]
def books_after(items, year):
    for item in items:
        if item["kind"] == "book" and item["year"] > year:
            yield item
  2. Paso 2 — Encadena otro generador que transforme a título en mayúsculas. 
    def upper_titles(items):
    for item in items:
        yield item["title"].upper()
pipeline = upper_titles(books_after(LIBRARY, 1950))
print(list(pipeline))
# Salida: ['DUNE', 'FAHRENHEIT 451']
  3. Paso 3 — Toma solo el primero sin agotar el pipeline. 
    first = next(upper_titles(books_after(LIBRARY, 1950)), None)
print(first)
# Salida: DUNE
  4. Paso 4 — Comprueba la pereza: añade un print dentro del generador. 
    def traced(items):
    for item in items:
        print("procesando:", item["title"])   # se imprime al hacer next
        yield item["title"]
gen = traced(books_after(LIBRARY, 1950))  # aún NO imprime nada
print("generador creado")
print(next(gen))
# Salida: generador creado
#         procesando: Dune
#         Dune
  5. Paso 5 — Cuenta sin materializar con sum. 
    total = sum(1 for item in books_after(LIBRARY, 1900))
print(total)
# Salida: 3

Resultado esperado: las salidas de cada paso, en orden. Fíjate especialmente en el paso 4: es la prueba de que el cuerpo del generador no se ejecuta hasta el primer next. Cómo comprobarlo: ejecuta el script completo y verifica que «generador creado» aparece antes de «procesando: Dune».

8 · Reto

🎯 Buscador perezoso con límite

Implementa dos generadores para el catálogo de Biblioteca:

  1. search(items, query): genera los ítems cuyo title contenga query (sin distinguir mayúsculas/minúsculas).
  2. take(n, iterable): genera como máximo los n primeros valores del iterable recibido, y luego termina. No debe consumir más elementos de los necesarios del iterable original.

Usa take sobre search para obtener, por ejemplo, los dos primeros libros que contengan la letra «e», sin recorrer el catálogo entero.

Pista: take es un generador que lleva un contador y hace return (que en un generador equivale a terminar) cuando llega a n. Para que no consuma de más, debe pedir con next(iterable) dentro de un for y parar justo al alcanzar n. Piensa qué pasa si n <= 0.

9 · Resumen

  • Iterable: implementa __iter__ y devuelve un iterador.
  • Iterador: implementa __next__ y señala el fin con StopIteration.
  • for es azúcar sobre iter() + next() + try/except StopIteration.
  • Generador: función con yield; guarda su estado y reanuda donde se pausó.
  • Pereza: memoria constante; los valores se calculan bajo demanda.
  • Un solo uso: agotado un generador, hay que crear otro.

10 · Preguntas frecuentes

¿Por qué StopIteration no es un error que deba capturar?

Porque es el mecanismo normal con el que un iterador dice «se acabó». El for lo captura internamente y lo traduce en terminar el bucle. Solo lo verás tú si llamas a next() a mano sobre un iterador agotado; en ese caso, lo idiomático es usar next(it, default) en vez de un try/except.

¿Un generador es más rápido que una lista?

Depende de qué midas. Un generador arranca antes y usa menos memoria, porque no construye toda la colección. Pero recorrerlo entero tiene un pequeño sobrecoste por reanudar la función en cada yield. La regla: si solo lo recorres una vez o el conjunto es grande, generador; si lo vas a recorrer varias veces o necesitas indexarlo, lista.

¿Puedo devolver un valor con return dentro de un generador?

Sí, pero con matices: un return (incluso sin valor) termina el generador y su valor queda dentro de la excepción StopIteration. Para la mayoría de casos es más claro usar un if + return para parar el bucle. El valor de retorno solo tiene sentido en yield from (Módulo 8).
