Funciones y parámetros

Módulo 2 · Control de flujo y funciones ⏱ 35 minutos

1 · Introducción

Una función empaqueta un trozo de lógica con un nombre para poder reutilizarlo y probarlo por separado. Ya has usado funciones integradas (print, len, range); ahora escribes las tuyas. En Python, def crea un objeto, no un bloque especial: las funciones son valores de primera clase.

Esta lección cubre def, la diferencia crucial entre return y print, los parámetros por defecto (con su trampa más famosa), los argumentos posicionales frente a los keyword, los docstrings y el hecho de que una función se puede guardar en una variable, pasar y devolver.

¿Por qué existe esta lección? Porque una función mal diseñada se paga durante todo el proyecto. Aquí nace el error de entrevista más típico de Python —el argumento por defecto mutable— y la confusión que más depuración genera: print no es return. Entender ambas cosas te ahorra horas.

2 · Teoría

def: dar nombre a un bloque y sus parámetros

def define la función: crea un objeto función y lo liga a un nombre. El cuerpo no se ejecuta al definir, sino al llamar. La indentación marca dónde acaba el cuerpo (igual que en if).

def greet(name, greeting="Hola"):     <- firma: nombre + parámetros
    message = f"{greeting}, {name}"   <- cuerpo (no se ejecuta aún)
    return message                    <- valor de salida

result = greet("Dune")                <- LLAMADA: aquí sí se ejecuta

return vs print: devolver un valor, no mostrar

Esta es la confusión número uno de quienes empiezan. print muestra algo en pantalla y no produce valor: la función sigue devolviendo None. return entrega un valor a quien llamó, que puede guardarlo, sumarlo o pasarlo a otra función.

printreturn
Qué haceEscribe en la salida estándarTermina la función y entrega un valor
Qué devuelveNoneEl valor indicado (o None si no hay)
Se puede reutilizarNoSí: asignar, sumar, encadenar
Cuándo usarloAl final de un programa o para depurarPara comunicar resultados

Regla: una función de cálculo devuelve; quien orquesta imprime. Si tu función mezcla ambas, pierde testabilidad.

Parámetros por defecto: se evalúan UNA vez

Un parámetro con valor por defecto hace opcional ese argumento. Truco: el valor por defecto se calcula una sola vez, al definir la función, no en cada llamada. Si el default es un objeto mutable (lista, dict, set), todas las llamadas comparten el mismo objeto.

def add(item, items=[]):        # el [] se crea UNA vez, al definir
    items.append(item)
    return items

add("1984")   -> ['1984']       # usa el MISMO []
add("Dune")   -> ['1984','Dune']  # ¡sorpresa! el default recordó el estado

Argumentos posicionales frente a keyword

Al llamar puedes pasar por posición (en orden) o por nombre (param=valor). Las dos formas se pueden mezclar, pero los posicionales van primero. El estilo keyword gana en claridad cuando hay varios parámetros: quien lee no tiene que recordar el orden.

def make_item(title, kind="book", year=None):
    """Construye un ítem del catálogo con valores por defecto."""
    return {"title": title, "kind": kind, "year": year}

print(make_item("1984"))                       # kind y year por defecto
print(make_item("1984", year=1949))            # salta 'kind' usando el nombre
print(make_item(title="Dune", kind="book"))    # todo por nombre

# Salida esperada:
# {'title': '1984', 'kind': 'book', 'year': None}
# {'title': '1984', 'kind': 'book', 'year': 1949}
# {'title': 'Dune', 'kind': 'book', 'year': None}

Docstrings: documentación que viaja con la función

La primera cadena literal dentro de la función es su docstring. Es documentación real, accesible desde help() y func.__doc__, y la que usan IDE y generadores de documentación. Escríbela en presente, describiendo qué hace, qué recibe y qué devuelve.

def item_label(title, year=None):
    """Devuelve 'Título (año)' o solo 'Título' si no hay año."""
    return f"{title} ({year})" if year is not None else title

print(item_label.__doc__)
# Salida esperada:
# Devuelve 'Título (año)' o solo 'Título' si no hay año.

Funciones como objetos de primera clase

Una función es un objeto como cualquier otro: puedes asignarla a una variable, guardarla en una lista, pasarla como argumento y devolverla desde otra función. De aquí saldrán los decoradores (Módulo 8) y los closures (lección 5).

def shout(text):
    return text.upper()

def whisper(text):
    return text.lower()

# Guardamos funciones en una estructura de datos y elegimos cuál usar.
styles = {"loud": shout, "soft": whisper}
chosen = styles["loud"]          # 'chosen' es la FUNCIÓN, sin paréntesis
print(chosen("Dune"))            # DUNE

# Pasarla como argumento es pasar cualquier otro valor.
def apply(func, value):
    return func(value)

print(apply(whisper, "BLADE RUNNER"))   # blade runner

3 · Ejemplo mínimo

La función más pequeña que devuelve algo útil. Observa que no usamos print dentro: devolvemos un valor.

def double(number):
    """Devuelve el doble del número recibido."""
    return number * 2          # entrega el valor; no imprime

result = double(5)             # guardamos lo que devuelve
print(result)                  # recién aquí mostramos

# Salida esperada:
# 10

Línea por línea:

  1. def double(number): define la función con un parámetro llamado number.
  2. El docstring describe el contrato: qué devuelve.
  3. return number * 2 calcula y entrega el resultado al llamador.
  4. double(5) llama con 5; el valor de retorno se liga a result.
  5. print(result) muestra 10. Podríamos haber hecho print(double(5) + 1) y obtener 11: eso print dentro de la función no lo permitiría.

4 · Ejemplo real

En Biblioteca concentramos la creación de ítems en una fábrica. Un único punto de entrada garantiza que todos los ítems tengan la misma forma, y lo hacemos sin mutar listas compartidas.

def make_item(title, kind="book", year=None, borrowed=False):
    """Crea un ítem del catálogo con valores por defecto seguros.

    Args:
        title: título obligatorio del ítem.
        kind: "book" o "movie" (por defecto "book").
        year: año de publicación, o None si se desconoce.
        borrowed: si está prestado (por defecto False).

    Returns:
        Un dict con las claves id, title, kind, year y borrowed.
    """
    # No hay side effects ni estado global: misma entrada -> misma salida.
    return {
        "id": title.lower().replace(" ", "-"),   # id simple derivado del título
        "title": title,
        "kind": kind,
        "year": year,
        "borrowed": borrowed,
    }

print(make_item("1984", year=1949))
print(make_item("Blade Runner", kind="movie", year=1982))

# Salida esperada:
# {'id': '1984', 'title': '1984', 'kind': 'book', 'year': 1949, 'borrowed': False}
# {'id': 'blade-runner', 'title': 'Blade Runner', 'kind': 'movie', 'year': 1982, 'borrowed': False}

Decisiones de diseño:

  • La función es pura: no imprime ni modifica nada externo; devuelve un objeto nuevo. Así se puede testear con un simple assert.
  • Los defaults (kind="book", year=None, borrowed=False) son inmutables. Son seguros porque ninguna llamada puede alterarlos.
  • Para el año usamos None, no 0: «desconocido» y «cero» son cosas distintas, y None es el centinela natural.
  • Los parámetros por defecto cubren el caso común; los nombrados (kind=, year=) documentan la llamada en el lugar donde se lee.

6 · Errores habituales

El argumento por defecto mutable (¡el clásico!)

# ❌ El [] se crea UNA sola vez, al definir. Todas las llamadas lo comparten.
def add_item(item, items=[]):
    items.append(item)      # mutamos el MISMO objeto del default
    return items

print(add_item("1984"))     # ['1984']
print(add_item("Dune"))     # ['1984', 'Dune']  <- deuda oculta entre llamadas

# Puedes ver el default que quedó guardado:
print(add_item.__defaults__)  # (['1984', 'Dune'],)

# ✅ Centinela None + crear dentro de la función
def add_item(item, items=None):
    if items is None:
        items = []          # lista NUEVA en cada llamada
    items.append(item)
    return items

print(add_item("1984"))     # ['1984']
print(add_item("Dune"))     # ['Dune']  <- limpio

# Si quieres compartir de verdad, que sea explícito pasándola:
shared = ["Blade Runner"]
print(add_item("Dune", shared))   # ['Blade Runner', 'Dune']

Por qué es tan traicionero: solo se nota en la segunda llamada y en otra función o en tests, donde el estado «recuerda» cosas. Nunca uses un literal mutable como valor por defecto. Usa None.

Confundir print con return

# ❌ La función imprime, pero devuelve None: no se puede reutilizar
def double_printed(x):
    print(x * 2)

result = double_printed(5)   # imprime 10...
print(result)                # None  <- ¡no guardamos nada!

# ✅ Devuelve el valor
def double(x):
    return x * 2

print(double(5) + 1)         # 11

7 · Ejercicio guiado

Objetivo: escribir una función de búsqueda pura y testeable que use un default inmutable seguro, un docstring y devuelva un valor en vez de imprimir.

  1. Paso 1: define la firma. tags será opcional; como queremos una lista, usamos None como centinela. 
    def find_books(catalog, tag=None):
    """Devuelve los libros del catálogo que tengan la etiqueta indicada.

    Si tag es None, devuelve todos los libros. Nunca modifica el catálogo.
    """
    # Creamos una lista NUEVA dentro; jamás un default mutable.
    matches = []
    for item in catalog:
        if item["kind"] != "book":
            continue
        if tag is not None and tag not in item.get("tags", []):
            continue
        matches.append(item["title"])
    return matches
  2. Paso 2: prepara datos y llama en los dos modos. 
    catalog = [
    {"title": "1984", "kind": "book", "tags": ["distopia"]},
    {"title": "Dune", "kind": "book", "tags": ["scifi"]},
    {"title": "Blade Runner", "kind": "movie", "tags": ["scifi"]},
]

print(find_books(catalog))               # sin filtro: todos los libros
print(find_books(catalog, tag="scifi"))  # solo los etiquetados 'scifi'
  3. Paso 3 (verificación): la salida esperada es: 
    # ['1984', 'Dune']
# ['Dune']

    Comprueba además que el catálogo no cambió (no se mutó ninguna lista compartida) y que llamar dos veces sin tag devuelve siempre lo mismo: eso confirma que no hay estado escondido.

  4. Paso 4: guarda como search.py y ejecuta con python3 search.py (o py search.py en Windows).

8 · Reto

🎯 Una fábrica de ítems sin filtrar estado

Diseña make_catalog(*titles, kind="book") que reciba títulos sueltos y devuelva una lista de ítems, cada uno con una lista de etiquetas propia e independiente. Después demuestra, con dos llamadas, que las etiquetas de un ítem no se comparten con las de otro.

Pista: dentro de la función crea un item nuevo en cada vuelta y una lista tags nueva para cada uno. Si pones tags=[] como default de un helper te volverás a topar con el problema del mutable por defecto.

9 · Resumen

  • def crea un objeto función; el cuerpo se ejecuta al llamar, no al definir.
  • return devuelve un valor; print solo muestra y la función devuelve None.
  • Los valores por defecto se evalúan una sola vez: nunca uses un mutable como default.
  • Puedes llamar por posición o por nombre (keyword); los posicionales van primero.
  • El docstring es documentación accesible por help() y __doc__.
  • Las funciones son objetos de primera clase: se asignan, pasan y devuelven.

10 · Preguntas frecuentes

¿Por qué el valor por defecto se evalúa una sola vez?

Porque el default vive en el objeto función (f.__defaults__), no se recalcula en cada llamada. Para valores inmutables no importa; para mutables, ese objeto único se comparte y acumula cambios entre llamadas. De ahí la regla: None + crear dentro.

¿Puedo devolver varios valores a la vez?

Sí, con una tupla: return title, year. Al llamar, t, y = f(...) la desempaqueta. No son «varios valores» mágicos: es una sola tupla. Lo veremos en detalle en la próxima lección sobre desempaquetado.

¿Cuándo debo usar keyword en la llamada?

Cuando hay más de dos o tres parámetros, o cuando alguno es un número o booleano cuyo significado no se lee (save(data, True) no dice nada; save(data, overwrite=True) sí). Python 3 permite además fijar parámetros keyword-only, como verás en la lección 4.

¿Una función puede modificar la lista que le pasan?

Sí, si la mutas dentro (por ejemplo items.append(x)). Los argumentos se pasan por referencia al objeto: si el objeto es mutable, la función puede cambiarlo y el cambio se ve fuera. Por eso muchas funciones pythonicas devuelven una colección nueva en lugar de mutar la recibida; sé explícito con lo que haces.
