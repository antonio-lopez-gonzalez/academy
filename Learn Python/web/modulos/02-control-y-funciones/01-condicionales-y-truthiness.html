Condicionales y truthiness

Módulo 2 · Control de flujo y funciones ⏱ 30 minutos

1 · Introducción

Hasta ahora el código se ejecuta de arriba abajo sin decidir nada. En esta lección empezamos a tomar decisiones: ejecutar un bloque u otro según una condición. Es la primera pieza de control de flujo y la base de todo lo demás.

Python hace algo que sorprende a quien viene de otros lenguajes: en un if no comparas contra true. Escribes if items: y Python evalúa la verdad del propio valor. Esto es la truthiness (veracidad): todo objeto decide si se comporta como verdadero o falso. Una lista vacía es falsa, un número distinto de cero es verdadero, el texto "" es falso.

¿Por qué existe esta lección? Porque en Python casi nunca escribes == True. Entender la truthiness es lo que separa el código que funciona del código pythonico. Además, aquí aparecen los operadores lógicos con cortocircuito y el operador ternario, que usarás constantemente a partir de ahora.

2 · Teoría

La indentación define el bloque

Python no usa llaves {}. El bloque que se ejecuta cuando se cumple una condición lo marca la indentación (4 espacios por convención, nunca tabuladores mezclados). Esto no es capricho: al no tener llaves, el lenguaje garantiza que un vistazo al código revele su estructura. En otros lenguajes la indentación es decorativa; aquí es sintaxis.

if condicion:            <- cabecera: termina en dos puntos
    print("sí")          <- bloque indentado (4 espacios)
    print("también")     <- sigue dentro del if
print("fuera")           <- vuelve al nivel 0: ya NO está en el if

if / elif / else

La cadena de decisión se lee estrictamente de arriba abajo: se evalúa la primera condición y, en cuanto una es verdadera, se ejecuta su bloque y se ignoran las demás. elif es «si no, comprueba esto otro»; else es «si nada se cumplió». Por eso el orden importa: una condición general colocada antes tapa a las específicas.

        ¿condición 1?
        /           \
     True           False
      |               |
  bloque A      ¿condición 2?
                   /      \
                True      False
                 |          |
             bloque B    bloque else

Truthiness: cada objeto decide su verdad

En un if, Python no compara: aplica la función interna bool() al valor. Si el resultado es True, entra. Estos son los valores falsy (falsos por defecto):

Valor falsyTipoSignificado
FalseboolEl falso evidente
NoneNoneTypeAusencia de valor
0, 0.0, 0jnuméricosCero, en cualquier forma
""strCadena vacía (¡no un espacio!)
[], (), {}, set()coleccionesContenedor sin elementos
range(0)rangeSecuencia sin elementos

Todo lo demás es truthy: cualquier número distinto de cero, cualquier cadena con al menos un carácter (aunque sea "0" o "False"), cualquier lista con elementos. Una clase propia decide su verdad implementando __bool__ o, si no, su __len__.

Analogía: un if no pregunta «¿eres exactamente True?» sino «¿tienes contenido?». Una caja cerrada con algo dentro dice sí; una caja vacía dice no. El tipo de lo que hay dentro da igual.

Comparaciones que devuelven bool

Los operadores de comparación ==, !=, <, <=, >, >= producen un bool. Recuerda la lección de fundamentos: == compara valor y is compara identidad (¿es el mismo objeto en memoria?). Por eso is solo se usa con None, True, False y centinelas; para números y cadenas siempre ==.

and, or, not y el cortocircuito

Los operadores lógicos no devuelven True/False «puros»: devuelven uno de sus operandos. Y evalúan el mínimo necesario:

  • a and b: si a es falsy, devuelve a sin mirar b (cortocircuito). Si a es truthy, devuelve b.
  • a or b: si a es truthy, devuelve a sin mirar b. Si a es falsy, devuelve b.
  • not a: siempre devuelve un bool (True o False).
# El cortocircuito no es un detalle: es un patrón de diseño.
# 'or' sirve para dar un valor por defecto cuando el primero está vacío.
username = ""
display = username or "Anónimo"   # "" es falsy -> devuelve "Anónimo"

# 'and' se usa para acceder a algo solo si el contenedor existe:
item = {"title": "1984"}
title = item and item["title"]    # item es truthy -> devuelve la cadena
print(display)   # Anónimo
print(title)     # 1984

Cuidado: or devuelve el valor falsy si ambos lo son. 0 or 0 es 0, y [] or {} es {}. No son «False mágicos»; saber que devuelven operandos explica estos resultados.

Expresión ternaria

Cuando necesitas elegir un valor entre dos, no escribas un if/else de cuatro líneas: usa el ternario A if condicion else B. Es una expresión, así que se puede asignar y anidar (con moderación).

year = None
# Si year tiene valor, lo mostramos; si no, un texto. Una sola línea.
label = str(year) if year is not None else "año desconocido"
print(label)   # año desconocido

Adelanto: match

Cuando comparas un mismo valor contra muchas formas, la cadena de elif se vuelve repetitiva. Python 3.10+ ofrece match (pattern matching), que estudiaremos a fondo en el Módulo 8. Por ahora quédate con la idea: es un switch mucho más potente, con desestructuración y guardas.

kind = "movie"
match kind:
    case "book":          # primer patrón que encaja
        category = "Libro"
    case "movie":
        category = "Película"
    case _:               # comodín: el "else" del match
        category = "Otro"
print(category)   # Película

3 · Ejemplo mínimo

La condición más pequeña posible: preguntar si una colección tiene contenido. Fíjate en que no escribimos len(items) > 0.

# items es una lista vacía: es falsy.
items = []

# El if se queda con la verdad del valor, no lo compara con nada.
if items:
    print("Hay items en el catálogo")
else:
    print("El catálogo está vacío")

# Salida esperada:
# El catálogo está vacío

Línea por línea:

  1. items = [] crea una lista sin elementos. En un if, bool([]) es False.
  2. if items: no compara; evalúa. Como es falsy, salta al else.
  3. else: se ejecuta solo porque el if no lo hizo.

La forma pythonica: if items: es más corto, más claro y más rápido que if len(items) > 0:. Ambas funcionan; la primera es la idiomática.

4 · Ejemplo real

Aplicado a Biblioteca: clasificar un ítem según su estado. Ordenamos las comprobaciones de lo más específico a lo más general, que es justo lo que exige elif.

def classify(item):
    """Devuelve una etiqueta de estado para un ítem del catálogo."""
    # 'acc' accede a la clave y devuelve None si no existe: nunca lanza error.
    title = item.get("title") or "sin título"   # or: valor por defecto
    if item.get("borrowed"):
        return f"{title}: prestado"
    elif item.get("year") is None:              # is None, nunca == None
        return f"{title}: disponible (año desconocido)"
    else:
        return f"{title}: disponible ({item['year']})"

# Tres ítems con estados distintos del catálogo Biblioteca
catalog = [
    {"title": "1984", "kind": "book", "year": 1949, "borrowed": True},
    {"title": "Dune", "kind": "book", "year": None, "borrowed": False},
    {"title": "Blade Runner", "kind": "movie", "year": 1982, "borrowed": False},
]

for item in catalog:
    print(classify(item))

# Salida esperada:
# 1984: prestado
# Dune: disponible (año desconocido)
# Blade Runner: disponible (1982)

Decisiones de diseño:

  • item.get("borrowed") es True/False/None. La truthiness nos permite no comparar con nada: el if ya entiende None y False como «no prestado». Solo importa el caso en que sea True.
  • title = item.get("title") or "sin título" usa el cortocircuito de or como valor por defecto. Si la clave falta (None) o vale "", cae al texto.
  • item.get("year") is None distingue «año desconocido» (falta el dato) de un año cualquiera. Aquí is None es obligatorio por estilo y por semántica.

Regla mental: si vas a comparar con None, escribe is. Si vas a comprobar si algo está vacío o es cero, escribe simplemente if valor:.

6 · Errores habituales

Comparar con True en vez de confiar en la truthiness

# ❌ Ruidoso y, peor, solo funciona con booleanos estrictos
items = [1, 2, 3]
if items == True:      # [] == True es False, pero [1] tampoco es True!
    print("hay items") # nunca se ejecuta: una lista no es "igual a True"

# ✅ Comprueba la verdad del valor
if items:
    print("hay items")  # se ejecuta

# ✅ Si de verdad quieres comparar identidad con el bool, usa 'is':
flag = True
if flag is True:           # solo si es EXACTAMENTE el objeto True
    print("bandera activa")

Usar is para comparar números

# ❌ 'is' pregunta por identidad, no por valor. Y da SyntaxWarning.
score = 0
# if score is 0:      # no significa "vale cero"
#     ...

# ✅ Para valores usa '=='
if score == 0:
    print("sin puntuación")

# is solo para None / True / False / centinelas
if score is None:
    print("no definido")

Olvidar que 0 y "" son falsy en defaults

# ❌ El usuario pidió mostrar 0 elementos, pero un default tapa el cero
count = 0
label = count or "sin límite"
print(label)   # 'sin límite'  -> ¡hemos perdido el 0!

# ✅ Comprueba explícitamente contra None cuando el falsy es legítimo
count = 0
label = "sin límite" if count is None else str(count)
print(label)   # 0

Objetivo: escribir una función que decida si un ítem se puede prestar, usando truthiness y operadores lógicos. Un ítem es prestable si no está ya prestado, si tiene título y si el año es None o un número mayor que 0.

  1. Paso 1: define la función con docstring. 
    def can_borrow(item):
    """True si el ítem está disponible y tiene datos mínimos."""
    has_title = bool(item.get("title"))       # "" y None -> False
    borrowed = bool(item.get("borrowed"))     # None -> False
    year = item.get("year")
    valid_year = year is None or year > 0     # None es un año válido aquí
    return has_title and not borrowed and valid_year
  2. Paso 2: prueba con cuatro casos que cubran cada rama.
  3. Paso 3: imprime el resultado con su título.

    {"title": "Blade Runner", "year": 0, "borrowed": False},

for item in catalog:

9 · Resumen

  • La indentación define el bloque: sin llaves, la estructura se lee de un vistazo.
  • if/elif/else evalúa de arriba abajo y se queda con la primera condición verdadera.
  • Truthiness: False, None, 0, "" y las colecciones vacías son falsy; todo lo demás es truthy.
  • and/or devuelven un operando y usan cortocircuito; not devuelve siempre bool.
  • El ternario A if cond else B es una expresión para elegir un valor.
  • match/case es el adelanto de un switch potente que verás en el Módulo 8.

10 · Preguntas frecuentes

¿Por qué if items: funciona si no hay un booleano dentro?

Porque en un contexto booleano Python llama a bool(valor). Para las listas, bool([]) es False y bool([1]) es True. No hace falta convertir nada: el if ya hace la conversión por ti.

¿0 es igual a False y 1 a True?

Sí: 0 == False es True y 1 == True es True, porque en Python bool hereda de int. Pero 0 is False es False: son objetos distintos. Compáralos con == si de verdad quieres valor; lo normal es no compararlos en absoluto y usar truthiness.

¿Cuál es la diferencia entre un operador ternario y un if?

El if es una sentencia: controla el flujo y no produce valor. El ternario A if c else B es una expresión: se puede asignar, pasar como argumento o meter dentro de un f-string. Úsalo cuando necesitas un valor, no para ejecutar bloques largos.

¿Cuándo uso match en vez de elif?

Cuando comparas un mismo sujeto contra muchas formas y quieres desestructurarlo (por ejemplo, tuplas o diccionarios). Si solo encadenas dos o tres condiciones sencillas, if/elif se lee mejor. Lo verás a fondo en la lección Pattern matching del Módulo 8.
