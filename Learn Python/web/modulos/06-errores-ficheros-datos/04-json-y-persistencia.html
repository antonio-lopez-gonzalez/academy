JSON y persistencia del catálogo

Módulo 6 · Errores, ficheros y datos ⏱ 35 minutos

1 · Introducción

Ha llegado el momento culminante del módulo: que el catálogo sobreviva al programa. Ya sabemos manejar errores (lección 1), cerrar y publicar recursos con seguridad (lección 2) y leer/escribir ficheros con pathlib (lección 3). Solo falta elegir un formato: usaremos JSON, el formato de intercambio de datos más extendido, y lo guardaremos en data/library.json.

En esta lección verás cómo convertir objetos Python (diccionarios, listas) a texto y vuelta (json.dumps/loads/dump/load), cómo serializar dataclasses con dataclasses.asdict, cómo reconstruirlas al cargar, cómo tratar los dos fallos inevitables —el fichero ausente y el JSON corrupto— y cómo validar los datos contra un esquema para no aceptar basura.

¿Por qué JSON y no otro formato? Porque es texto legible, universal (lo lee cualquier lenguaje), sin dependencias (viene en la stdlib) y con una correspondencia casi 1:1 con dicts, listas y tipos escalares de Python. Frente a pickle, que puede ejecutar código al deserializar (un agujero de seguridad si el fichero no es de confianza), JSON es datos puros. Es exactamente lo que pide el contrato del curso: data/library.json validado por un esquema.

2 · Teoría

Qué es JSON y qué tipos admite

JSON (JavaScript Object Notation) admite seis tipos: objeto, array, string, number, boolean y null. Su correspondencia con Python es directa, pero no total: JSON no tiene tuplas ni conjuntos, y las claves de un objeto JSON son siempre strings.

JSONPython (al cargar)Python (al volcar)
{ "…": … } (objeto)dictdict
[ … ] (array)listlist, tuple
"…" (string)strstr
123 / 12.5int / floatint, float (no Decimal)
true / falseTrue / Falsebool
nullNoneNone

El por qué de esta restricción: JSON está pensado para viajar entre lenguajes; no puede depender de tipos que solo existen en uno. Por eso, para guardar tus Book/Movie (que son clases), primero hay que aplanarlos a dicts y, al cargar, reconstruirlos.

Las cuatro funciones

La stdlib parte el trabajo en dos ejes: string vs fichero y leer vs escribir. La s final de dumps/loads significa «string»: trabajan en memoria y devuelven/reciben un str. json.dump(obj, f) y json.load(f) hacen lo mismo pero sobre un fichero abierto.

⚠️ El argumento clave es ensure_ascii=False. Por defecto vale True y escapa todo lo no-ASCII: "señora" se guarda como "se\u00f1ora". Sigue siendo JSON válido (se lee igual), pero el fichero deja de ser legible para un humano. Como library.json lo va a leer/editar gente, pon ensure_ascii=False junto con encoding="utf-8" al abrir. Los dos, siempre, de la mano.

Otras opciones útiles: indent=2 (formato «bonito», una clave por línea), sort_keys=True (claves ordenadas, útil para comparar en tests y diffs estables) y separators=(",", ":") (compacto, sin espacios, para tamaño mínimo).

Serializar dataclasses con asdict

Un dataclass no es serializable por defecto: json.dumps(book) lanza TypeError: Object of type Book is not JSON serializable. La conversión recomendada es dataclasses.asdict, que produce un dict con los campos en orden de declaración (incluidos los heredados):

from dataclasses import dataclass, asdict

@dataclass
class Book:
    id: str
    title: str
    kind: str = "book"
    year: int | None = None
    borrowed: bool = False
    author: str | None = None

libro = Book(id="b1", title="1984", year=1949, author="George Orwell")
print(asdict(libro))   # {'id': 'b1', 'title': '1984', 'kind': 'book', ...}

En sentido inverso no hay magia: desempaquetas el dict con Book(**data). Como kind decide qué clase usar, una pequeña fábrica reconstruye el objeto correcto. Este ida y vuelta (serializar ↔ deserializar) es el corazón de la persistencia.

Los dos fallos inevitables: ausente y corrupto

Cuando lees datos de disco, hay dos situaciones que debes tratar por separado:

  1. El fichero no existe (FileNotFoundError): la primera vez que se ejecuta la app. No es un error: es un catálogo vacío.
  2. El fichero existe pero no es JSON válido (json.JSONDecodeError): se editó a mano y falta una coma, un corte dejó el fichero a medias, etc. Sí es un error y hay que avisar, nunca «seguir como si nada» (eso borraría el trabajo del usuario).

Analogía: el fichero ausente es una libreta nueva: empiezas de cero, sin drama. El JSON corrupto es una libreta con páginas arrancadas: no la tiras, avisas y conservas lo que puedas. Tratar ambos igual (devolver []) es el pecado capital que borra el catálogo del usuario.

Validar contra el esquema

Cargar JSON puede dar cualquier cosa: un número, una lista de strings, dicts sin las claves que esperas. Antes de usar los datos, valida su forma. El proyecto define schema/library.schema.json; aquí tienes una versión mínima y su validación manual (sin dependencias):

{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "type": "array", "items": {
    "type": "object", "required": ["id", "title", "kind"],
    "properties": {
      "id": {"type": "string"}, "title": {"type": "string"},
      "kind": {"enum": ["book", "movie"]},
      "year": {"type": ["integer", "null"]}, "borrowed": {"type": "boolean"},
      "author": {"type": ["string", "null"]}, "director": {"type": ["string", "null"]}
    }
  }
}

El esquema es la especificación de lo que es un catálogo válido. Validar contra él en código es comprobar exactamente esas restricciones. En un proyecto grande usarías la librería jsonschema; aquí, para no añadir dependencias, escribimos la comprobación a mano —que además te enseña qué significa realmente validar.

3 · Ejemplo mínimo

El viaje completo de un ítem: dict → texto → fichero → texto → dict.

import json

libro = {"id": "b1", "title": "1984", "kind": "book", "year": 1949, "borrowed": False}

# 1) Python → string (lo guardaríamos con json.dump a un fichero)
texto = json.dumps(libro, ensure_ascii=False)

# 2) string → Python (¡los números vuelven como int, no como str!)
recuperado = json.loads(texto)
print(recuperado["title"])        # 1984
print(recuperado["year"] + 1)     # 1950

# 3) Volcado "bonito" (el que usaremos para library.json)
print(json.dumps(libro, ensure_ascii=False, indent=2))

Salida esperada:

1984
1950
{
  "id": "b1",
  "title": "1984",
  "kind": "book",
  "year": 1949,
  "borrowed": false
}

Fíjate: False de Python viaja como false en JSON (minúscula) y vuelve como False. Los números conservan su tipo (podemos sumar 1 a year), algo que no pasaría si los guardáramos como texto. El por qué de indent=2: un fichero que se va a versionar y leer a mano debe ser diffeable, con una clave por línea.

4 · Ejemplo real

Este es, pieza a pieza, el store.py de Biblioteca: cargar el catálogo (tratando ausente y corrupto), reconstruir dataclasses y guardarlo de forma legible. Es el punto donde todo el módulo confluye. La fábrica item_from_dict vive en models.py y decide la subclase según kind:

# src/biblioteca/models.py
def item_from_dict(data: dict) -> Item:
    """Reconstruye el ítem concreto (Book/Movie) a partir de un dict JSON."""
    kind = data.get("kind")
    if kind == "movie":
        return Movie(**data)
    if kind == "book":
        return Book(**data)
    raise BibliotecaError(f"kind inválido en el almacén: {kind!r}")

# src/biblioteca/store.py
import json
from pathlib import Path
from typing import Sequence

from biblioteca.models import BibliotecaError, Item, item_from_dict

# Ruta por defecto, relativa al directorio de trabajo.
DEFAULT_STORE = Path("data/library.json")


def load(path: str | Path = DEFAULT_STORE) -> list[Item]:
    """Lee el almacén y devuelve la lista de ítems (vacía si no existe)."""
    file = Path(path)
    if not file.exists():
        return []                                       # primer arranque: normal
    try:
        raw = json.loads(file.read_text(encoding="utf-8"))
    except json.JSONDecodeError as err:
        # ✅ Traducimos el error conservando la causa (lección 1)
        raise BibliotecaError(f"el almacén {file} no es JSON válido: {err}") from err
    if not isinstance(raw, list):
        raise BibliotecaError(f"el almacén {file} debe ser una lista JSON")
    return [item_from_dict(entry) for entry in raw]     # dicts → dataclasses


def save(items: Sequence[Item], path: str | Path = DEFAULT_STORE) -> None:
    """Escribe la lista de ítems, creando el directorio si hace falta."""
    file = Path(path)
    file.parent.mkdir(parents=True, exist_ok=True)      # asegura 'data/'
    data = [item.to_dict() for item in items]           # dataclass → dict (usa asdict)
    text = json.dumps(data, ensure_ascii=False, indent=2) + "\n"
    file.write_text(text, encoding="utf-8")             # (o escritura atómica, lección 2)

Si guardamos un libro, data/library.json queda así:

[
  {
    "id": "b1",
    "title": "1984",
    "kind": "book",
    "year": 1949,
    "borrowed": false,
    "author": "George Orwell"
  }
]

Decisiones: (1) el fichero ausente devuelve [], pero el corrupto lanza BibliotecaError: jamás sobrescribimos un catálogo dañado con uno vacío; (2) isinstance(raw, list) y la fábrica item_from_dict validan la forma mínima antes de reconstruir, así un dato inválido no genera un objeto a medias; (3) to_dict() (que usa asdict) + Book(**data) cierran el ciclo objeto ↔ JSON; (4) la validación completa contra schema/library.schema.json sería un paso extra: item_from_dict rechaza un kind desconocido, pero no comprueba el resto de campos.

Multiplataforma: en Linux/macOS lanza la CLI con python -m biblioteca.cli list; en Windows, con py -m biblioteca.cli list. El mismo data/library.json se escribe con \n o \r\n según el sistema (traducción automática de saltos de línea), pero json.loads lo lee igual en los tres. Y recuerda: encoding="utf-8" + ensure_ascii=False en ambas direcciones, o «Orwell» con acento se romperá al cambiar de máquina.

6 · Errores habituales

Asumir que el fichero existe

# ❌ En la primera ejecución no hay fichero: FileNotFoundError y fuera.
with open("data/library.json", encoding="utf-8") as f:
    items = json.load(f)

# ✅ El primer arranque es un caso normal: catálogo vacío, sin excepción.
try:
    text = DEFAULT_STORE.read_text(encoding="utf-8")
except FileNotFoundError:
    items = []
else:
    items = json.loads(text)

Tragarse el JSON corrupto

# ❌ Si el JSON está roto, devolver [] y seguir es BORRAR el catálogo
#    en cuanto guardemos. El usuario pierde todos sus datos sin enterarse.
try:
    raw = json.loads(text)
except json.JSONDecodeError:
    raw = []

# ✅ Deja subir un error de dominio con la causa; el borde decide qué hacer.
try:
    raw = json.loads(text)
except json.JSONDecodeError as exc:
    raise BibliotecaError(f"JSON corrupto en {DEFAULT_STORE}") from exc

Serializar el objeto directamente

# ❌ TypeError: Object of type Book is not JSON serializable
json.dumps(Book(id="b1", title="1984", kind="book"))

# ✅ Convierte a dict con asdict (o implementa tu propio .to_dict()).
json.dumps(asdict(Book(id="b1", title="1984", kind="book")))
# '{"id": "b1", "title": "1984", "kind": "book", "year": null, "borrowed": false, "author": null}'

8 · Reto

🎯 Almacén versionado y a prueba de corrupción

Convierte save en un guardado robusto que: (1) envuelva la lista en un objeto con una clave de versión, por ejemplo {"version": 1, "items": [...]}; (2) valide y migre versiones antiguas al cargar (si no hay version, asume la 0 y conviértelo al formato nuevo); (3) escriba con el patrón atómico de la lección 2; y (4) si al cargar detecta JSON corrupto, haga una copia library.corrupt.json antes de lanzar BibliotecaError, para no perder nunca la evidencia.

Pista: en la migración, raw = data.get("items", data) cubre el formato antiguo (lista desnuda) y el nuevo (objeto). Para la copia, lee el texto crudo y escríbelo con Path.write_text a otro nombre. Recuerda: la escritura atómica a un temporal + os.replace en el mismo directorio. Y añade un test mental: ¿qué pasa si el fichero está vacío (0 bytes)? json.loads("") lanza JSONDecodeError — trátalo como corrupto, no como vacío.

9 · Resumen

  • JSON es texto portable y seguro (nunca ejecuta código como pickle); su vocabulario se mapea casi 1:1 con dicts, listas y escalares.
  • json.dumps/loads trabajan con strings; json.dump/load con ficheros.
  • Serializa dataclasses con dataclasses.asdict y reconstruyelas con Clase(**data); una fábrica elige la subclase por kind.
  • Usa ensure_ascii=False + indent=2 + encoding="utf-8" para un library.json legible.
  • Fichero ausente → [] (normal). JSON corrupto → BibliotecaError con raise … from (nunca devolver vacío).
  • Valida la estructura contra el esquema antes de reconstruir: JSON válido no garantiza datos válidos.

10 · Preguntas frecuentes

¿Por qué no guardo objetos Python directamente con pickle?

Porque pickle puede ejecutar código arbitrario al deserializar: si el fichero lo ha tocado alguien malintencionado, es una puerta de entrada. Además sus datos no son legibles ni portables entre versiones/lenguajes. JSON es datos puros, legible y universal. pickle se reserva para usos internos muy controlados, no para el almacén de la app.

¿Por qué ensure_ascii=False y no dejar el valor por defecto?

Con el defecto True, cada carácter no ASCII se escapa a \uXXXX. El JSON sigue siendo válido y se lee igual, pero el fichero deja de ser editable y revisable por humanos, que es justo lo que queremos en data/library.json. Usa ensure_ascii=False junto a encoding="utf-8"; uno sin el otro puede dar problemas de codificación.

¿Qué valido exactamente? ¿No basta con que json.load no falle?

No basta. Que el texto sea JSON válido solo dice que la sintaxis es correcta; no que tenga la forma que esperas. Un JSON válido puede ser un número, un string, o una lista de dicts a los que les falta kind. La validación contra el esquema comprueba tipos, campos obligatorios y valores admitidos, y es lo que evita que un objeto a medias rompa el programa tres capas más arriba.
