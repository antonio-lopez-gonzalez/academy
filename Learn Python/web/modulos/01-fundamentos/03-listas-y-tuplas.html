Listas y tuplas

Módulo 1 · Fundamentos del lenguaje ⏱ 35 minutos

1 · Introducción

Las listas y las tuplas son las dos secuencias ordenadas básicas de Python. Una lista es mutable (puedes añadir, quitar y reordenar), una tupla es inmutable (una vez creada, no cambia). Esa única diferencia decide cuál usar, y arrastra consecuencias profundas: las tuplas pueden ser claves de diccionario y comunican «este registro no cambia»; las listas son la colección de trabajo por excelencia.

Aquí aprenderás a indexar, trocear (slicing), usar sus métodos principales y —lo más importante— a entender el aliasing: por qué dos nombres pueden apuntar a la misma lista y por qué eso provoca bugs legendarios.

¿Por qué existe esta lección? Porque el 90 % de los datos que manipularás son secuencias, y porque la mutabilidad mal entendida genera errores dificilísimos de rastrear. Además, el desempaquetado de tuplas es la base de for a, b in pares y de devolver varios valores de una función (Módulo 2).

2 · Teoría

Una lista frente a una tupla

# Una lista: corchetes, mutable
titles = ["1984", "Dune", "Neuromancer"]
# Una tupla: paréntesis, inmutable
item = ("bk-01", "1984", 1949)
print(type(titles))   # <class 'list'>
print(type(item))     # <class 'tuple'>
titles.append("Blade Runner")   # ✅ la lista cambia
# item[0] = "bk-99"             # ❌ TypeError: las tuplas no se modifican

En otros lenguajes, la lista se parece a un ArrayList o a un array dinámico de JavaScript, y la tupla a un «record» de posición fija (aunque sin nombre de campo). La elección no es estética: una tupla promete que su contenido no cambiará de tamaño ni de posición, y esa promesa la hace apta como clave de diccionario y como elemento de un conjunto.

Índices: positivos y negativos

Las secuencias se indexan desde 0. Los índices negativos cuentan desde el final, de modo que -1 es el último elemento. Acceder fuera de rango lanza IndexError.

titles = ["1984", "Dune", "Neuromancer"]
print(titles[0])      # 1984
print(titles[2])      # Neuromancer
print(titles[-1])     # Neuromancer -> último
print(titles[-3])     # 1984       -> primero
print(len(titles))    # 3
# print(titles[3])    # ❌ IndexError: list index out of range

Slicing: obtener subsecuencias

La sintaxis [inicio:fin:paso] devuelve una copia nueva con los elementos desde inicio (incluido) hasta fin (excluido). Omitir un extremo significa «desde el principio» o «hasta el final».

titles = ["1984", "Dune", "Neuromancer", "Blade Runner", "Solaris"]
print(titles[1:3])     # ['Dune', 'Neuromancer']
print(titles[:2])      # ['1984', 'Dune']            (desde el inicio)
print(titles[3:])      # ['Blade Runner', 'Solaris'] (hasta el final)
print(titles[-2:])     # ['Blade Runner', 'Solaris'] (los dos últimos)
print(titles[::2])     # ['1984', 'Neuromancer', 'Solaris'] (uno sí, uno no)
print(titles[::-1])    # ['Solaris', 'Blade Runner', ...] (invertida)
# El slicing SIEMPRE devuelve una lista nueva: no toca la original.
copy_all = titles[:]   # forma idiomática de copiar una lista
print(copy_all is titles)   # False -> es otra lista

Regla mental: el índice final del slicing es exclusivo. Por eso titles[1:3] da dos elementos (posiciones 1 y 2) y len(titles[1:3]) == 3 - 1 == 2. Esta convención hace que a[:n] + a[n:] reconstruya a sin solapes.

Trampa clásica: titles.sort() ordena la lista y devuelve None. Escribir titles = titles.sort() deja titles valiendo None. Si quieres una lista nueva ordenada sin tocar la original, usa sorted(titles) (función, no método) en el Módulo 3.

Tuplas y desempaquetado

Una tupla agrupa valores de posición fija. Su superpoder es el desempaquetado: repartir sus elementos en nombres en una sola línea.

# Una tupla de 3 campos: id, título, año
item = ("bk-01", "1984", 1949)
item_id, title, year = item     # desempaquetado
print(item_id)   # bk-01
print(title)     # 1984
print(year)      # 1949
# Desempaquetado con intercambio: clásico para ordenar variables
a, b = 1, 2
a, b = b, a                     # intercambio sin variable temporal
print(a, b)      # 2 1
# El guion bajo '_' es la convención para "no me interesa este valor"
item_id, _, _ = item
print(item_id)   # bk-01

El peligro: aliasing (dos nombres, una lista)

Como viste en la lección 1, asignar no copia. Con listas mutables, esto significa que dos nombres pueden modificar «la misma» lista:

original = ["1984", "Dune"]
alias = original            # NO es una copia
alias.append("Solaris")
print(original)             # ['1984', 'Dune', 'Solaris'] -> ¡cambió el original!
# Para tener una lista independiente hay que copiar de verdad:
independent = original.copy()   # o list(original) o original[:]
independent.append("Neuromancer")
print(original)                 # sigue sin 'Neuromancer'

Analogía: una lista es una pizarra. Si dos personas tienen la llave de la misma pizarra, cualquiera de las dos puede borrar y escribir. Copiar la lista equivale a fotografiar la pizarra y dar la foto: la foto es independiente (copia superficial; las copias profundas llegan en el Módulo 3).

3 · Ejemplo mínimo

Añadir, leer y desempaquetar en el mínimo de líneas.

titles = ["1984", "Dune"]   # lista mutable
titles.append("Solaris")    # añade al final
print(titles)               # ['1984', 'Dune', 'Solaris']
print(titles[-1])           # Solaris
item = ("bk-01", "1984", 1949)   # tupla inmutable
item_id, _, year = item          # desempaquetado
print(item_id, year)             # bk-01 1949

Línea por línea:

  1. titles = [...]: crea una lista con dos strings.
  2. titles.append("Solaris"): muta la lista en sitio; no hace falta reasignar.
  3. titles[-1]: indexación negativa: el último elemento.
  4. item_id, _, year = item: reparte la tupla en tres nombres; _ descarta el título.

4 · Ejemplo real

Representamos el catálogo de Biblioteca como una lista de tuplas inmutables. Cada ítem es un registro de posición fija (id, title, kind, year). Es exactamente la forma en la que, más adelante, se serializará a JSON.

# Catálogo: lista (crece con nuevos ítems) de tuplas (registros inmutables).
catalog = [
    ("bk-01", "1984", "book", 1949),
    ("mv-01", "Blade Runner", "movie", 1982),
    ("bk-02", "Dune", "book", 1965),
]
# Añadimos un ítem nuevo: mutamos la LISTA, no las tuplas.
catalog.append(("mv-02", "Solaris", "movie", 1972))
# Recorremos y desempaquetamos cada tupla directamente en el for.
for item_id, title, kind, year in catalog:
    print(f"{item_id} · {title} ({year}) [{kind}]")
# Salida esperada:
# bk-01 · 1984 (1949) [book]
# mv-01 · Blade Runner (1982) [movie]
# bk-02 · Dune (1965) [book]
# mv-02 · Solaris (1972) [movie]
# Filtrar por tipo usando slicing y listas de comprensión llegará en el Módulo 3;
# de momento, una lista auxiliar explícita:
books = []
for item_id, title, kind, year in catalog:
    if kind == "book":
        books.append(title)
print(books)   # ['1984', 'Dune']
# Una tupla puede ser CLAVE de diccionario (una lista no).
by_position = {}
by_position[("shelf", 1)] = "1984"
print(by_position[("shelf", 1)])   # 1984

Decisiones: la lista es la colección mutable (añadimos ítems), y cada tupla es un registro de campos fijos. El bucle for item_id, title, kind, year in catalog funciona porque Python desempaqueta cada tupla automáticamente —es el patrón que usarás sin parar—. Y la última parte muestra la razón técnica de que existan las tuplas: solo lo hashable puede ser clave de diccionario.

6 · Errores habituales

El alias silencioso

# ❌ Creer que esto copia la lista
wishlist = ["1984", "Dune"]
catalog = wishlist              # ¡alias!
wishlist.append("Solaris")
print(catalog)                  # ['1984', 'Dune', 'Solaris'] -> no era una copia
# ✅ Copia explícita
catalog = wishlist.copy()
wishlist.append("Neuromancer")
print(catalog)                  # no incluye Neuromancer

Perder la lista al usar sort()

# ❌ sort() muta y devuelve None
titles = ["Dune", "1984"]
titles = titles.sort()          # titles ahora vale None
# print(titles[0])              # TypeError: 'NoneType' object is not subscriptable
# ✅ Llama a sort() sin reasignar
titles = ["Dune", "1984"]
titles.sort()
print(titles)                   # ['1984', 'Dune']

Modificar una lista mientras la recorres

# ❌ Eliminar durante la iteración salta elementos
titles = ["1984", "Dune", "Solaris"]
for title in titles:
    if title == "Dune":
        titles.remove(title)    # el índice interno se descuadra
print(titles)                   # puede quedar ['1984', 'Solaris']… o saltarse algo
# ✅ Construye una lista nueva (o itera sobre una copia)
titles = ["1984", "Dune", "Solaris"]
kept = [t for t in titles if t != "Dune"]   # idioma del Módulo 3
# Alternativa sin comprensión:
kept = []
for t in titles:
    if t != "Dune":
        kept.append(t)
print(kept)                     # ['1984', 'Solaris']

Usar una lista como clave de diccionario

# ❌ Las listas no son hashables
# d = {["1984"]: "libro"}       # TypeError: unhashable type: 'list'
# ✅ Usa una tupla (inmutable) como clave
d = {("book", "1984"): "disponible"}
print(d[("book", "1984")])      # disponible

Olvidar la coma de la tupla de un elemento

# ❌ Sin coma, no es una tupla
one = ("1984")
print(type(one))                # <class 'str'>
# ✅ Con coma
one = ("1984",)
print(type(one))                # <class 'tuple'>

7 · Ejercicio guiado

Objetivo: construir, ordenar y resumir un catálogo, demostrando aliasing y copia. Paso a paso.

  1. Paso 1: parte de esta lista de tuplas: 
    catalog = [
    ("bk-01", "1984", 1949),
    ("mv-01", "Blade Runner", 1982),
    ("bk-02", "Dune", 1965),
]
  2. Paso 2: crea alias = catalog y copy = catalog.copy(). Añade ("mv-02", "Solaris", 1972) solo a alias. Imprime las longitudes de los tres nombres.
  3. Paso 3: ordena copy por año. Como aún no has visto sorted(key=...), puedes hacerlo con un bucle de selección simple o, si te atreves, con copy.sort(key=lambda it: it[2]) (una lambda es una función anónima; la verás en el Módulo 2).
  4. Paso 4: recorre copy desempaquetando y acumula solo los títulos de los libros (bk-).
  5. Paso 5 (verificación): comprueba la salida esperada.

Solución de referencia:

alias = catalog
copy = catalog.copy()
alias.append(("mv-02", "Solaris", 1972))
print(len(catalog), len(alias), len(copy))   # 4 4 3 -> catalog y alias son el mismo objeto
copy.sort(key=lambda it: it[2])              # ordena por año (posición 2)
titles = []
for item_id, title, year in copy:
    if item_id.startswith("bk-"):
        titles.append(title)
print(titles)                                # ['1984', 'Dune']

Resultado esperado:

4 4 3
['1984', 'Dune']

Cómo comprobarlo: catalog y alias comparten objeto (ambos 4), pero copy se hizo antes del append y quedó con 3. Tras ordenar por año, los libros son 1984 (1949) y Dune (1965), en ese orden.

8 · Reto

🎯 «Deshaz el préstamo» sin efectos colaterales

Dada una lista de tuplas (id, title, borrowed), escribe código que devuelva una lista nueva donde el ítem mv-01 pase a borrowed=False, sin modificar la lista original. Comprueba que la original sigue intacta.

Pista: no puedes modificar la tupla (es inmutable), así que construye una tupla nueva para ese ítem. Recorre y decide con un if/else; recuerda que reasignar el nombre de una tupla dentro del bucle no afecta a la lista. La clave es producir una lista nueva, no editar la existente.

9 · Resumen

  • Una lista es mutable; una tupla es inmutable y por eso puede ser clave de diccionario.
  • Los índices negativos cuentan desde el final; el slicing [a:b:p] devuelve una copia nueva.
  • Los métodos de lista mutan en sitio y casi todos devuelven None (¡cuidado con sort()!).
  • El desempaquetado de tuplas reparte valores en nombres y es la base de for a, b in pares.
  • Asignar una lista crea un alias, no una copia; usa .copy(), list() o [:].
  • Una tupla de un elemento necesita coma: ("x",).

10 · Preguntas frecuentes

¿Por qué las listas no pueden ser claves de diccionario y las tuplas sí?

Porque una clave debe ser hashable (tener un hash estable). Si un objeto mutable cambiara de contenido, su hash cambiaría y el diccionario no lo encontraría. Las tuplas son inmutables, y su hash es estable… mientras no contengan objetos mutables dentro.

¿Una tupla que contiene una lista sigue siendo inmutable?

La tupla en sí no cambia: no puedes añadir ni quitar elementos. Pero si uno de sus elementos es una lista, esa lista sí puede mutar. Y en ese caso la tupla deja de ser hashable, porque su contenido podría cambiar. Regla: inmutabilidad de la tupla es solo de su estructura superior.

¿a[:-1] y a[:] crean copias o vistas?

Copias. A diferencia de los slices de NumPy (que son vistas), el slicing de las listas de Python devuelve siempre una lista nueva con elementos referenciados. Es una copia superficial: los objetos internos se comparten (las copias profundas llegan en el Módulo 3).

¿Cuándo debería preferir una tupla a una lista?

Cuando el registro tiene campos fijos y no vas a cambiar su tamaño ni su orden: coordenadas, filas de una tabla, valores devueltos por una función, claves compuestas. Si la colección crece o se reordena, es una lista.

¿Cómo elimino duplicados de una lista conservando el orden?

La forma rápida y moderna es list(dict.fromkeys(titles)): un diccionario recuerda el orden de inserción (Python 3.7+) y no admite claves repetidas. Los conjuntos (set) eliminan duplicados pero no garantizan el orden; los verás en la siguiente lección.
