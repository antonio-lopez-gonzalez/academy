Variables y tipos: todo es un objeto

Módulo 1 · Fundamentos del lenguaje ⏱ 30 minutos

1 · Introducción

Si vienes de C, Java o C#, tienes una imagen mental muy concreta de lo que es una variable: una caja con un tipo fijo que reserva un trozo de memoria. Escribes int x = 5; y el compilador aparta cuatro bytes para guardar un entero. En Python esa imagen te va a traicionar. Aquí un nombre no es una caja: es una etiqueta pegada a un objeto.

En esta lección entenderás por qué en Python se dice que «los nombres son bindings» (vínculos a objetos), qué implica el tipado dinámico, cómo inspeccionar el tipo de un valor con type() e isinstance(), y la diferencia —fuente inagotable de bugs— entre identidad (is) e igualdad (==). Cierra la idea que da título a la lección: absolutamente todo lo que manipulas en Python es un objeto, incluso los números.

¿Por qué existe esta lección? Casi todos los errores sutiles de Python (mutación compartida, is mal usado, listas que se «contagian») nacen de no tener claro este modelo. Entender que los nombres apuntan a objetos es el cimiento de todo lo demás: mutabilidad, paso de argumentos, copias, POO… Si esto queda claro, el resto del curso se sostiene solo.

El error típico es pensar que asignar copia. Ya lo verás: y = x no duplica nada, solo pega una segunda etiqueta al mismo objeto.

2 · Teoría

Nombres que apuntan a objetos, no cajas

Imagina que cada valor vive en algún lugar de la memoria como un objeto independiente. Un nombre (lo que en otros lenguajes llamarías «variable») es solo una etiqueta que apunta a uno de esos objetos. La sentencia de asignación no mete un valor dentro de un contenedor: crea el objeto si hace falta y ata el nombre a él.

        nombre            objeto en memoria
        ┌──────┐          ┌──────────────┐
  x  ──►│ "x"  │─────────►│  int 42      │
        └──────┘          └──────────────┘
        ┌──────┐
  y  ──►│ "y"  │─────────► (el mismo objeto 42)
        └──────┘

Fíjate en la consecuencia: si dos nombres apuntan al mismo objeto y el objeto es mutable, modificar a través de uno se ve a través del otro. Si el objeto es inmutable, eso nunca puede pasar porque «modificarlo» en realidad crea uno nuevo.

Analogía: en C, una variable es una caja con forma y tamaño fijos donde guardas una cosa. En Python, un nombre es una nota adhesiva: puedes despegarla de un objeto y pegarla en otro cuando quieras. El objeto existe por sí mismo; la nota solo lo señala.

Tipado dinámico: el tipo vive en el objeto

En un lenguaje de tipado estático (Java, C#), el tipo pertenece al nombre y no cambia. En Python, el tipo pertenece al objeto y el nombre puede apuntar a valores de tipos distintos en momentos distintos:

# El mismo nombre puede apuntar a objetos de tipos diferentes en distintas líneas.
value = 42            # ahora 'value' apunta a un int
value = "1984"        # ahora apunta a un str (esto sería un error de tipo en Java)
value = [1, 2, 3]     # ahora apunta a una list

Esto no significa que Python «no tenga tipos»: significa que la comprobación ocurre en tiempo de ejecución, no al compilar. Por eso Python es dinámico pero fuerte: "2" + 2 falla con TypeError en lugar de hacer una conversión silenciosa como JavaScript.

En Python 3.12 puedes anotar el tipo esperado (year: int = 1949). Esas anotaciones no se comprueban en ejecución; sirven para que herramientas como mypy (Módulo 7) y tu editor te avisen antes. Son documentación ejecutable, no un candado.

Inspeccionar el tipo: type() e isinstance()

type(obj) devuelve la clase exacta del objeto. isinstance(obj, Clase) devuelve True si el objeto es de esa clase o de una subclase. Casi siempre quieres lo segundo, porque respeta la herencia.

year = 1949
title = "1984"
print(type(year))                 # <class 'int'>
print(type(title))                # <class 'str'>
print(isinstance(year, int))      # True
print(isinstance(year, str))      # False
print(isinstance(True, int))      # True  -> ¡bool es subclase de int en Python!

Ojo con bool: en Python True y False son enteros disfrazados (True == 1, False == 0). Es cómodo para sumar banderas, pero explica comportamientos que sorprenden a quien viene de otros lenguajes.

Identidad frente a igualdad: is vs ==

  • == pregunta «¿valen lo mismo?» (igualdad de valor).
  • is pregunta «¿son el mismo objeto en memoria?» (identidad).

Cada objeto tiene un identificador único mientras vive, que puedes ver con id(). a is b equivale a id(a) == id(b).

a = [1, 2, 3]
b = [1, 2, 3]     # una SEGUNDA lista, con los mismos valores
c = a             # la MISMA lista, con dos nombres
print(a == b)     # True  -> tienen el mismo contenido
print(a is b)     # False -> son objetos distintos
print(a is c)     # True  -> c es una segunda etiqueta del objeto de a

La regla práctica: usa is solo para comparar contra objetos únicos (singletons) como None, y == para comparar valores. Nunca uses is para enteros o strings: que dos "hola" idénticos compartan objeto es un detalle de implementación (interning) en el que no debes confiar.

Mutabilidad e inmutabilidad

Un objeto es mutable si puede cambiar su contenido sin cambiar de identidad; inmutable si cualquier cambio produce un objeto nuevo.

Tipo¿Mutable?Consecuencia
int, float, boolNoSeguros de compartir; cada operación crea un valor nuevo
strNoNo existe s[0] = "X"; se construye otro string
tupleNoSirve como clave de diccionario
listSíCompartir una lista es compartir sus cambios
dict, setSíMutables; tampoco sirven como clave

¿Por qué importa? Porque el paso de argumentos a funciones es «por referencia al objeto»: si pasas una lista mutable y la modificas dentro, quien la llamó ve los cambios. Eso es potente y peligroso a la vez. Volverás a este concepto en las lecciones 3 y 4.

Todo es un objeto (de verdad)

En Python no hay «tipos primitivos» separados de los objetos. Un entero es una instancia de int con métodos propios:

number = 42
print(number.bit_length())     # 6  -> 42 en binario (101010) usa 6 bits
print("hola".upper())          # HOLA -> los strings también traen métodos
# ¡Incluso las funciones son objetos que puedes asignar a un nombre!
def greet() -> str:
    return "Biblioteca"
alias = greet       # no la llamamos: guardamos el objeto función
print(alias())      # Biblioteca

Que las funciones sean objetos es la base de los decoradores (Módulo 8), y que los números sean objetos explica por qué todo tiene métodos y atributos.

3 · Ejemplo mínimo

El experimento más pequeño que demuestra el modelo: dos nombres, un objeto.

# Asignamos el entero 42 a un nombre.
x = 42
y = x              # 'y' apunta AL MISMO objeto que 'x' (no se copia nada)
print(x, y)        # 42 42
print(type(x))     # <class 'int'>
print(id(x) == id(y))   # True  -> mismo objeto
print(x is y)      # True  -> por eso 'is' también es True
# Al reasignar 'x' NO tocamos el objeto 42 (es inmutable):
# simplemente despegamos la etiqueta 'x' y la pegamos en un objeto nuevo.
x = 7
print(x, y)        # 7 42 -> 'y' sigue apuntando al 42 original

Línea por línea:

  1. x = 42: Python crea (o reutiliza) el objeto int 42 y ata el nombre x.
  2. y = x: no copia el 42; copia la referencia. x e y designan el mismo objeto.
  3. x is y: verdadero, porque ambos nombres apuntan al mismo objeto.
  4. x = 7: como int es inmutable, esto rebindea x a otro objeto; y no se entera.

4 · Ejemplo real

Empezamos a modelar un ítem de nuestra Biblioteca. Aún sin clases (eso llega en el Módulo 5), representamos un ítem con tipos básicos y comprobamos qué son.

# Datos sueltos de un ítem del catálogo (un libro).
item_id = "bk-001"        # str  -> identificador legible
title = "1984"            # str  -> título
year = 1949               # int  -> año de publicación
borrowed = False          # bool -> ¿está prestado?
# Inspeccionamos los tipos: útil al depurar datos que vienen de fuera.
print(type(item_id).__name__)   # str
print(type(year).__name__)      # int
print(type(borrowed).__name__)  # bool
# isinstance respeta la herencia; usamos una tupla para aceptar varios tipos.
print(isinstance(year, int))            # True
print(isinstance(year, (int, float)))   # True
# Dos ítems con el mismo título: mismo VALOR, distinto OBJETO.
other_title = "1984"
print(title == other_title)   # True  -> mismo contenido
# NUNCA compares strings con 'is': el resultado depende del intérprete.

Observa que title == other_title es True aunque sean objetos distintos (probablemente compartidos por el interning de strings). La comprobación correcta por valor es ==; is solo lo usaremos para None (lo verás en la lección 5).

Consejo de depuración: cuando un dato «no es lo que crees», imprime type(x). Un "1949" (string) y un 1949 (entero) se ven parecidos en pantalla pero se comportan muy distinto. Detectar esto a tiempo ahorra horas.

6 · Errores habituales

Creer que la asignación copia

# ❌ Pensar que 'catalog' es una copia independiente
catalog = ["1984", "Dune"]
backup = catalog          # NO copia: es otra etiqueta al MISMO objeto
catalog.append("Blade Runner")
print(backup)             # ['1984', 'Dune', 'Blade Runner'] -> ¡el "backup" cambió!
# ✅ Copia de verdad (superficial; veremos copy en el Módulo 3)
backup = list(catalog)    # o catalog.copy() o catalog[:]
catalog.append("Neuromancer")
print(backup)             # ['1984', 'Dune', 'Blade Runner'] -> independiente

La asignación siempre rebindea, nunca duplica. Si quieres dos listas independientes, tienes que copiar explícitamente.

Usar is donde corresponde ==

# ❌ Comparar valores con 'is'
year = 1949
print(year is 1949)       # True hoy… pero es coincidencia (caching de enteros pequeños)
title = "Dune"
print(title is "Dune")    # Puede ser True o False según el intérprete. Frágil.
# ✅ Compara por valor con '=='
print(year == 1949)       # True
print(title == "Dune")    # True

is responde a «¿es el mismo objeto?». Para valores, la pregunta correcta es ==.

Sombra de builtins (shadowing)

# ❌ Reasignar nombres que Python ya usa como funciones integradas
list = ["1984", "Dune"]   # ahora 'list' es una lista, no el constructor
# new = list(...)          # TypeError: 'list' object is not callable
# ✅ Usa un nombre que describa tu dato
titles = ["1984", "Dune"]
# y deja 'list', 'str', 'id', 'type', 'sum'… intactos

Sombrear builtins funciona hasta que necesitas la función original; entonces el error es confuso. Trátalos como palabras reservadas de facto.

Comparar tipos de forma demasiado estricta

# ❌ type(...) == ... rechaza subclases
value = True
print(type(value) == int)     # False -> bool es subclase de int, pero type es exacto
# ✅ isinstance respeta la jerarquía de clases
print(isinstance(value, int)) # True

9 · Resumen

  • Un nombre en Python es una etiqueta a un objeto, no una caja. Asignar rebindea, nunca copia.
  • El tipo vive en el objeto (tipado dinámico); un nombre puede apuntar a tipos distintos con el tiempo.
  • type() da la clase exacta; isinstance() respeta la herencia y suele ser lo correcto.
  • == compara valor; is compara identidad (mismo objeto). Usa is solo con None.
  • Los objetos mutables (list, dict, set) comparten cambios al compartirse; los inmutables (int, str, tuple) no.
  • Todo es un objeto: los números tienen métodos y las funciones puedes guardarlas en nombres.

10 · Preguntas frecuentes

¿Python es de tipado débil por ser dinámico?

No. Dinámico y débil son ejes distintos. Python es dinámico (los tipos se comprueban en ejecución) pero fuerte (no convierte tipos a la ligera: "2" + 2 lanza TypeError). JavaScript, con "2" + 2 == "22", es dinámico y débil.

Si type() existe, ¿por qué usar isinstance()?

Porque type(x) == int exige coincidencia exacta y falla con subclases (por ejemplo True, que es un bool subclase de int). isinstance(x, int) acepta la clase y sus descendientes, que casi siempre es lo que quieres.

¿Cuándo debo usar is y cuándo ==?

Usa is únicamente para singletons como None (if x is None:). Para cualquier comparación de valores —números, strings, listas— usa ==. Con inmutables pequeños is puede dar True por caching, pero es un detalle interno en el que no debes apoyarte.

¿Las anotaciones de tipo hacen que Python compruebe tipos?

No. year: int = 1949 es solo documentación para humanos y para herramientas estáticas como mypy. En ejecución, Python acepta year = "1949" sin protestar. El chequeo real llega con mypy en el Módulo 7.

¿Por qué se dice que «todo es un objeto» si 5 parece un valor suelto?

Porque 5 es una instancia de int con atributos y métodos: (5).bit_length(), (7).denominator… Incluso las funciones y los módulos son objetos. Esa uniformidad es lo que permite tratar funciones como datos (decoradores) y definir protocolos por comportamiento.
