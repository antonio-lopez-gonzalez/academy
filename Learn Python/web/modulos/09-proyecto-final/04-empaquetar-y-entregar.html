Empaquetar y entregar

Módulo 9 · Proyecto final ⏱ 35 minutos

1 · Introducción

Tenemos el núcleo, los tests y la calidad en verde. Falta el paso que convierte el repositorio en producto: que cualquiera instale el paquete y escriba bib list como una herramienta más. Ahora escribimos la CLI, declaramos el entry point, construimos con uv build, instalamos y verificamos de extremo a extremo.

Por qué un entry point y no un script en el repo

Un script bib.py obliga a saber dónde está y a invocarlo como python /ruta/bib.py. Un entry point declarado en pyproject.toml hace que el instalador cree un ejecutable llamado bib en el PATH del entorno. El usuario no ve rutas: escribe bib.

2 · Teoría

Artefacto de uv buildQué esPara qué
.whl (wheel)Paquete listo para instalarConsumo rápido; es lo que se publica
.tar.gz (sdist)Fuente comprimidaDistribuir el código; construir en destino

El build backend (hatchling) lee pyproject.toml, recoge src/biblioteca/ y produce ambos en dist/. Es reproducible.

Entry points. bib = "biblioteca.cli:main" significa: importa biblioteca.cli y llama a main. El instalador genera el ejecutable; el valor devuelto se usa como código de salida (0 = éxito).

   pyproject.toml [project.scripts] bib = "biblioteca.cli:main"
                     │ el instalador lo lee
                     ▼
   .venv/bin/bib  (o Scripts\bib.exe)  →  biblioteca.cli.main()
                     →  service (funciones)  →  store.load/save  →  data/library.json

Editable vs instalado. pip install -e . enlaza a tu código (desarrollo). Instalar el .whl prueba el artefacto tal como se entrega: si un archivo no se incluyó, el wheel lo revela.

Entregar es documentar. El README debe responder en 30 segundos: qué es, cómo se instala (venv + pip y uv), cómo se usa y cómo se desarrolla. Y semver MAJOR.MINOR.PATCH: MAJOR rompe compatibilidad, MINOR añade, PATCH corrige; este proyecto arranca en 1.0.0.

Un comando propio con el mínimo código: hola.

[project]
name = "hola-cli"
version = "0.1.0"
requires-python = ">=3.12"

[project.scripts]
hola = "hola_cli:main"

[build-system]
requires = ["hatchling"]
build-backend = "hatchling.build"

[tool.hatch.build.targets.wheel]
packages = ["src/hola_cli"]
# src/hola_cli/__init__.py
import sys

def main() -> int:
    """Imprime un saludo y devuelve código de salida 0 (éxito)."""
    print("¡Hola desde un entry point!")
    return 0

if __name__ == "__main__":
    sys.exit(main())
$ pip install -e .
$ hola
¡Hola desde un entry point!
$ echo $?        # código de salida del último comando
0

Línea por línea: el entry point es comando = "módulo:funcion"; main() devuelve 0, que el instalador usa como estado de salida; sys.exit(main()) propaga ese código cuando se ejecuta como script. En PowerShell, el código es $LASTEXITCODE; en CMD, %ERRORLEVEL%.

4 · Ejemplo real

La CLI de Biblioteca (src/biblioteca/cli.py):

"""Interfaz de línea de comandos de Biblioteca (`bib`).

Es una capa fina: interpreta argumentos, llama al servicio y decide el código
de salida. Toda la lógica vive en `service.py`.
"""

from __future__ import annotations

import argparse
import sys

from . import __version__, service, store
from .models import BibliotecaError

DEFAULT_STORE = str(store.DEFAULT_STORE)


def build_parser() -> argparse.ArgumentParser:
    """Construye el parser con los subcomandos de `bib`."""
    parser = argparse.ArgumentParser(
        prog="bib",
        description="Biblioteca — catálogo personal de libros y películas.",
    )
    parser.add_argument("--version", action="version", version=f"bib {__version__}")
    parser.add_argument(
        "--store",
        default=DEFAULT_STORE,
        help="ruta del almacén JSON (por defecto: data/library.json)",
    )

    sub = parser.add_subparsers(dest="command", required=True)

    p_add = sub.add_parser("add", help="añadir un libro o película")
    p_add.add_argument("title", help="título del ítem")
    p_add.add_argument("--kind", choices=("book", "movie"), default="book", help="tipo de ítem")
    p_add.add_argument("--year", type=int, default=None, help="año de publicación/estreno")
    p_add.add_argument("--author", default=None, help="autor (libro)")
    p_add.add_argument("--director", default=None, help="director (película)")

    p_list = sub.add_parser("list", help="listar el catálogo")
    p_list.add_argument("--kind", choices=("book", "movie"), default=None, help="filtrar por tipo")

    p_search = sub.add_parser("search", help="buscar por título o creador")
    p_search.add_argument("term", help="texto a buscar")

    p_borrow = sub.add_parser("borrow", help="marcar como prestado")
    p_borrow.add_argument("id", help="id del ítem")

    p_return = sub.add_parser("return", help="marcar como devuelto")
    p_return.add_argument("id", help="id del ítem")

    return parser


def _format(item) -> str:
    """Una línea legible por ítem, con estado de préstamo."""
    mark = "[prestado]" if item.borrowed else "[disponible]"
    year = f" ({item.year})" if item.year else ""
    creator = f" — {item.creator}" if item.creator else ""
    return f"{item.id}  {item.title}{year}{creator}  {mark}"


def main(argv: list[str] | None = None) -> int:
    """Punto de entrada. Devuelve el código de salida (0 = éxito)."""
    parser = build_parser()
    args = parser.parse_args(argv)

    try:
        if args.command == "add":
            creator = args.author if args.kind == "book" else args.director
            item = service.add(
                args.title,
                kind=args.kind,
                year=args.year,
                creator=creator,
                path=args.store,
            )
            print(f"añadido: {_format(item)}")

        elif args.command == "list":
            items = service.list_items(kind=args.kind, path=args.store)
            if not items:
                print("(catálogo vacío)")
            for item in items:
                print(_format(item))

        elif args.command == "search":
            for item in service.search(args.term, path=args.store):
                print(_format(item))

        elif args.command == "borrow":
            item = service.borrow(args.id, path=args.store)
            print(f"prestado: {item.id}  {item.title}")

        elif args.command == "return":
            item = service.return_item(args.id, path=args.store)
            print(f"devuelto: {item.id}  {item.title}")

    except BibliotecaError as err:
        print(f"error: {err}", file=sys.stderr)
        return 1

    return 0


if __name__ == "__main__":  # permite `python -m biblioteca.cli`
    raise SystemExit(main())

6 · Errores habituales

1. bib: command not found tras instalar. Casi siempre el entorno virtual no está activado o se instaló en otro. Comprueba con which bib (Linux/macOS) o Get-Command bib (PowerShell) y reinstala con el venv activo.

2. Entry point mal escrito.

❌ Incorrecto 
[project.scripts]
bib = "biblioteca.cli:run"    # la función se llama main, no run

Al ejecutar bib no encuentra biblioteca.cli:run; debe apuntar al nombre exacto de la función.

3. Instalar en editable y creer que el wheel está bien. En editable todo parece funcionar porque el código se toma del disco. Solo instalando el .whl en un entorno limpio descubres un ModuleNotFoundError si olvidaste listar el paquete. Prueba siempre el wheel.

4. Versión desincronizada. Si pyproject.toml dice 0.2.0 y la versión que ves sigue en 0.1.0, los usuarios ven versiones distintas. En Biblioteca __init__.py deriva __version__ de importlib.metadata.version("biblioteca"), así que la fuente de verdad es el manifiesto.

8 · Reto

Publicar en TestPyPI

Publica el paquete en TestPyPI (el índice de pruebas) e instálalo desde ahí en un entorno limpio con pip install --index-url https://test.pypi.org/simple/ biblioteca.

Pista: necesitas una cuenta y un API token en test.pypi.org, el módulo build/twine (o uv publish), y que name, version y readme del pyproject.toml sean válidos para el índice. En TestPyPI el mismo nombre+versión no se puede re-publicar: sube la versión. No hace falta resolverlo aquí; es tu siguiente paso real hacia PyPI.

10 · Preguntas frecuentes

¿uv build o python -m build?

Producen artefactos equivalentes. uv build es más rápido y ya está en el flujo del curso; python -m build es la vía estándar sin uv. Elige una y automatízala.

¿Debo subir dist/ a Git?

No. Es una salida generada: va en .gitignore junto a build/, *.egg-info/, __pycache__/ y .venv/.

¿Por qué data/library.json no está dentro del wheel?

Son datos del usuario, no código. Empaquetados podrían no ser escribibles o perderse al actualizar. El almacén vive en una ruta de trabajo, configurable con --store.

¿Cómo añado python -m biblioteca además de bib?

Hoy cli.py acaba en if __name__ == "__main__": raise SystemExit(main()), así que python -m biblioteca.cli ya funciona. Para python -m biblioteca, crea src/biblioteca/__main__.py con from biblioteca.cli import main y raise SystemExit(main()); es lo que Python busca con -m biblioteca.

¿Cuál es el siguiente paso tras empaquetar?

Automatizar: un workflow de CI (GitHub Actions) que ejecute ruff, mypy y pytest en cada push. Después, reutilizar service.py desde una API FastAPI. Y, cuando estés listo, publicar en PyPI.
