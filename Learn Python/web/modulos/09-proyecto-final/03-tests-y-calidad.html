Tests y calidad

Módulo 9 · Proyecto final ⏱ 35 minutos

1 · Introducción

Un núcleo bien separado (lección anterior) es lo que permite testearlo sin arrancar la CLI ni tocar tu data/ real. Ahora escribimos la suite de pytest, la pasamos por mypy y ruff, y hablamos de cobertura con criterio.

El objetivo no es «tener tests», sino confianza: poder cambiar service.py y saber en segundos si rompimos una regla. Un test es código que se ejecuta solo y se queja cuando algo se desvía.

Por qué tmp_path y no data/library.json

Si los tests escriben en el almacén real, se contaminan entre sí, dependen del orden y ensucian tu catálogo. tmp_path da a cada test una carpeta temporal nueva que pytest borra al terminar. Aislamiento = resultados reproducibles.

2 · Teoría

Un test prepara un estado, actúa y comprueba con assert. Pytest descubre solo los archivos test_*.py y las funciones test_*: no necesitas clases ni main.

   Arrange (fixture)  →  Act (add/borrow…)  →  Assert (assert, pytest.raises)

Fixtures. Una función con @pytest.fixture se ejecuta y su resultado se inyecta en cualquier test que la nombre como parámetro. tmp_path ya viene incluida en pytest; en esta suite no necesitamos fixtures propias: cada test construye su ruta temporal y llama a service directamente.

parametrize. Cuando un mismo caso se repite con datos distintos, @pytest.mark.parametrize("x", [a, b]) ejecuta la función una vez por caso e informa cuál falla. Ideal para bordes: mayúsculas, tipos, entradas inválidas.

HerramientaQué compruebaCuándo
pytestComportamiento en ejecuciónAl correr los tests
mypyCoherencia de los tiposAntes de ejecutar nada
ruffEstilo, imports, errores comunes, formatoAl guardar / en CI

Son complementarias: pytest ejecuta, mypy deduce, ruff uniforma.

Cobertura. Mide qué porcentaje de líneas ejecutan los tests. Orientativa: un 100 % no garantiza corrección (puedes ejecutar una línea sin comprobar su resultado). Úsala como brújula, no como meta ciega.

3 · Ejemplo mínimo

Un test con tmp_path: escribe un archivo en una carpeta temporal y compruébalo.

from pathlib import Path

def test_escribir_y_leer(tmp_path: Path) -> None:
    """tmp_path es una carpeta temporal única para ESTE test."""
    archivo = tmp_path / "saludo.txt"
    archivo.write_text("hola", encoding="utf-8")
    assert archivo.read_text(encoding="utf-8") == "hola"
    assert archivo.exists()
$ pytest tests/test_tempfile.py -v
tests/test_tempfile.py::test_escribir_y_leer PASSED
========================= 1 passed in 0.02s =========================

Línea por línea: tmp_path llega inyectada como Path; tmp_path / "saludo.txt" construye la ruta; write_text/read_text prueban el ciclo; los assert son Python puro que pytest inspecciona. Con -v ves cada test; con -x se detiene en el primer fallo.

4 · Ejemplo real

La suite vive en cuatro archivos, uno por módulo. tests/test_models.py — el modelo de datos:

"""Tests del modelo de datos (`models.py`)."""

import pytest

from biblioteca.models import BibliotecaError, Book, Movie, item_from_dict


def test_kind_invalido_lanza_error():
    with pytest.raises(BibliotecaError):
        Book(id="1", title="X", kind="revista")


def test_titulo_vacio_lanza_error():
    with pytest.raises(BibliotecaError):
        Book(id="1", title="   ", kind="book")


def test_creator_devuelve_autor_o_director():
    book = Book(id="1", title="1984", kind="book", author="George Orwell")
    movie = Movie(id="2", title="Dune", kind="movie", director="Denis Villeneuve")

    assert book.creator == "George Orwell"
    assert movie.creator == "Denis Villeneuve"


def test_to_dict_y_roundtrip():
    book = Book(id="1", title="1984", kind="book", year=1949, author="George Orwell")

    data = book.to_dict()
    assert data == {
        "id": "1",
        "title": "1984",
        "kind": "book",
        "year": 1949,
        "borrowed": False,
        "author": "George Orwell",
    }
    # Reconstruir desde el dict da un objeto igual (dataclass implementa __eq__).
    assert item_from_dict(data) == book


def test_item_from_dict_rechaza_kind_desconocido():
    with pytest.raises(BibliotecaError):
        item_from_dict({"id": "1", "title": "X", "kind": "cd", "borrowed": False})

tests/test_store.py — persistencia con tmp_path:

"""Tests de la persistencia (`store.py`) usando `tmp_path`."""

import pytest

from biblioteca import store
from biblioteca.models import BibliotecaError, Book


def test_load_inexistente_devuelve_vacio(tmp_path):
    assert store.load(tmp_path / "no-existe.json") == []


def test_save_y_load_roundtrip(tmp_path):
    path = tmp_path / "library.json"
    items = [Book(id="it_1", title="1984", kind="book", year=1949, author="Orwell")]

    store.save(items, path)

    assert path.exists()
    assert store.load(path) == items


def test_almacen_corrupto_lanza_error(tmp_path):
    path = tmp_path / "roto.json"
    path.write_text("{esto no es json", encoding="utf-8")

    with pytest.raises(BibliotecaError):
        store.load(path)


def test_almacen_que_no_es_lista_lanza_error(tmp_path):
    path = tmp_path / "objeto.json"
    path.write_text('{"no": "es una lista"}', encoding="utf-8")

    with pytest.raises(BibliotecaError):
        store.load(path)

tests/test_service.py — las reglas de negocio:

"""Tests de las reglas de negocio (`service.py`)."""

import pytest

from biblioteca import service
from biblioteca.models import BibliotecaError


def test_add_y_list(tmp_path):
    path = tmp_path / "library.json"

    item = service.add("1984", kind="book", year=1949, creator="George Orwell", path=path)

    assert item.title == "1984"
    assert item.creator == "George Orwell"
    assert service.list_items(path=path) == [item]


def test_add_titulo_vacio_lanza_error(tmp_path):
    with pytest.raises(BibliotecaError):
        service.add("   ", path=tmp_path / "library.json")


def test_add_genera_ids_unicos(tmp_path):
    path = tmp_path / "library.json"

    a = service.add("Dune", path=path)
    b = service.add("Dune", path=path)

    assert a.id != b.id


def test_search_por_titulo_y_creador(tmp_path):
    path = tmp_path / "library.json"
    service.add("Dune", kind="book", creator="Frank Herbert", path=path)
    service.add("Blade Runner", kind="movie", creator="Ridley Scott", path=path)

    assert [i.title for i in service.search("herbert", path=path)] == ["Dune"]
    assert [i.title for i in service.search("blade", path=path)] == ["Blade Runner"]


def test_borrow_y_return(tmp_path):
    path = tmp_path / "library.json"
    item = service.add("Dune", path=path)

    service.borrow(item.id, path=path)
    assert service.list_items(path=path)[0].borrowed is True

    # No se puede prestar dos veces sin devolver.
    with pytest.raises(BibliotecaError):
        service.borrow(item.id, path=path)

    service.return_item(item.id, path=path)
    assert service.list_items(path=path)[0].borrowed is False


def test_operar_sobre_id_inexistente_lanza_error(tmp_path):
    with pytest.raises(BibliotecaError):
        service.borrow("it_no_existe", path=tmp_path / "library.json")

tests/test_cli.py — el borde: formato y códigos de salida, no la lógica:

"""Tests de la CLI (`cli.py`): la interfaz, no la lógica."""

from biblioteca import cli


def test_add_e_list(tmp_path, capsys):
    store = str(tmp_path / "library.json")

    code = cli.main(["--store", store, "add", "1984", "--author", "Orwell", "--year", "1949"])
    assert code == 0
    assert "añadido" in capsys.readouterr().out

    code = cli.main(["--store", store, "list"])
    out = capsys.readouterr().out
    assert code == 0
    assert "1984" in out


def test_add_sin_titulo_falla(tmp_path, capsys):
    code = cli.main(["--store", str(tmp_path / "l.json"), "add", "   "])

    assert code == 1
    assert "error" in capsys.readouterr().err


def test_borrow_de_id_inexistente_falla(tmp_path, capsys):
    code = cli.main(["--store", str(tmp_path / "l.json"), "borrow", "it_nope"])

    assert code == 1
    assert "error" in capsys.readouterr().err
Por qué los tests del núcleo no importan la CLI

Todo se prueba contra service y store: rápido y sin efectos de terminal. Solo test_cli.py importa cli, y lo hace para comprobar el formateo y los códigos de salida, no la lógica —esa ya está cubierta—.

6 · Errores habituales

1. Tests que dependen unos de otros.

❌ Incorrecto 
STORE = "data/library.json"   # estado global compartido

def test_a():
    service.add("1984", path=STORE)

def test_b():
    assert service.list_items(path=STORE)   # pasa solo si test_a corrió antes

El orden de pytest no está garantizado. Cada test prepara su propio estado con tmp_path.

2. Test sin assert. service.borrow(item.id, path=path) sin comprobar el efecto solo verifica que el código no explota. Comprueba service.list_items(path=path)[0].borrowed is True.

3. Tipos que mienten.

❌ Incorrecto 
def add_year(item: Item, year: str) -> None:   # debería ser int
    item.year = year                            # mypy: incompatible type

Las anotaciones no se comprueban en ejecución; por eso hace falta mypy src en strict.

4. Formatear a mano. No gastes energía alineando espacios: deja que ruff format . lo haga. Cuida la lógica; el formato es automático.

8 · Reto

Llegar al 100 % con criterio

Las líneas sin cubrir de service.py y cli.py son caminos de error: escribe los tests que las cubran. Y comprueba el ciclo completo de disco: store.save seguido de store.load debe devolver exactamente los mismos ítems, con el estado borrowed incluido.

Pista: usa pytest --cov=biblioteca --cov-report=term-missing; marca con Missing los números de línea pendientes. Como mejora, implementa escritura atómica (temporal + Path.replace) en store.save y añádele un test. No lo entregues aquí: llévalo a tu repositorio.

9 · Resumen

  • pytest descubre test_*.py y ejecuta funciones test_* con assert.
  • Las fixtures preparan estado; tmp_path aísla cada test.
  • parametrize convierte un test en muchos casos.
  • pytest.raises comprueba errores propios, no Exception a lo bruto.
  • mypy valida tipos y ruff unifica estilo; ambos en pyproject.toml.
  • La cobertura orienta; no es una nota de calidad por sí sola.
HerramientaQué hace
pytestEjecuta los tests y reporta fallos con detalle.
@pytest.fixturePrepara e inyecta dependencias (p. ej. una ruta temporal).
tmp_pathCarpeta temporal única y aislada por test.
parametrizeEjecuta un test con varios conjuntos de datos.

ruff check / ruff formatDetecta y corrige estilo y errores comunes.

10 · Preguntas frecuentes

¿tmp_path o tmp_path_factory?

tmp_path da una carpeta nueva por test (lo normal). tmp_path_factory permite carpetas de ámbito session compartidas, cuando montar el estado es caro. Para Biblioteca, tmp_path.

¿Debo comprobar el JSON exacto del disco?

Mejor comprobar comportamiento: que al volver a llamar a store.load (o a service.list_items) el ítem está con el estado correcto. Comprobar el texto exacto acopla los tests al formato y a la indentación.

¿mypy strict es demasiado para empezar?

Puedes activarlo y luego añadir excepciones por módulo, o empezar con opciones sueltas (disallow_untyped_defs, warn_return_any). En un proyecto pequeño es asumible desde el inicio.

¿Black o ruff format?

ruff incluye un formateador compatible con Black y una sola herramienta hace lint y formato. Si ya usas Black, puedes mantenerlo; el curso usa ruff format.

¿Cuánta cobertura es suficiente?

No hay número mágico. Aquí apuntamos alto porque el núcleo es pequeño y determinista. Lo importante: cada regla de negocio tiene al menos un test.
