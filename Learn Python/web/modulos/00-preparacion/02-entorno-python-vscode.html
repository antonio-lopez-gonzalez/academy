Entorno: Python, VSCode y el REPL

Módulo 0 · Preparación ⏱ 35 minutos

1 · Introducción

Antes de escribir una línea de lógica conviene tener un entorno que no te haga perder tiempo: la versión correcta de Python, un editor que entienda el lenguaje y una terminal donde probar cosas al vuelo. El 80% de los problemas de un principiante en Python no son del lenguaje, sino del entorno: dos Pythons instalados, un PATH mal puesto, el editor usando una versión distinta a la de la terminal.

En esta lección instalamos Python 3.12+ en Linux, macOS y Windows, montamos VSCode con la extensión oficial de Python y Pylance, y aprendemos a abrir el REPL (el prompt interactivo >>>) para experimentar. Al terminar tendrás un entorno reproducible y sabrás por qué cada pieza está ahí.

¿Por qué existe esta lección? Porque un entorno mal montado contamina todo el curso. Si la terminal y el editor no usan el mismo intérprete, verás errores que no comprendes y perderás horas. Configurarlo bien una vez es la mejor inversión del módulo 0.

2 · Teoría

Instalar Python 3.12+

Python corre nativo en los tres sistemas; no hace falta WSL (a diferencia de Docker). Lo importante es instalar una versión 3.12 o superior y saber cómo se invoca en tu sistema.

Linux

Muchas distribuciones ya traen Python 3. Comprueba y, si es antiguo, instala 3.12 desde el gestor del sistema o con pyenv:

# Debian / Ubuntu (añadiendo el PPA deadsnakes para tener 3.12 en LTS antiguas)
sudo apt update && sudo apt install python3.12 python3.12-venv

# Fedora / Red Hat
sudo dnf install python3.12

# Comprueba el resultado
python3.12 --version

macOS

El Python que trae el sistema es antiguo y reservado para macOS; no lo uses para tus proyectos. Instálalo con Homebrew:

# Homebrew instala en /opt/homebrew (Apple Silicon) o /usr/local (Intel)
brew install python@3.12
python3.12 --version

Windows

Descarga el instalador de python.org (marca «Add python.exe to PATH») o usa winget. En Windows el comando canónico es el Python Launcher, py:

# Con winget (PowerShell), o descarga el .exe desde python.org
winget install Python.Python.3.12

# El launcher elige la versión: py -3.12, o la más reciente con solo 'py'
py --version
py -3.12 --version

Multi-OS: el launcher py solo existe en Windows. En Linux/macOS el nombre habitual es python3 (y a veces python). En este curso, cuando un comando sea python3, en Windows puedes usar py.

El PATH: por qué a veces «no encuentra» Python

El PATH es la lista de carpetas donde el sistema busca los ejecutables. Si instalas Python pero su carpeta no está en el PATH, al escribir python la terminal no lo encuentra. En Windows, el instalador ofrece añadirlo automáticamente: márcalo siempre.

  Escribes:  python3 --version
                 |
                 v
  El shell recorre el PATH en orden buscando 'python3':
  /usr/local/bin  ->  /usr/bin  ->  /bin  ->  ...  (Linux/macOS)
  C:\Python312\  ->  C:\Windows\System32  ->  ...    (Windows)
                 |
                 v
  Primer match: se ejecuta. Ninguno: "command not found" / "no se reconoce".

Gestionar varias versiones

En Windows, el launcher py elige versión (py -3.12, lista con py -0). En Linux/macOS, pyenv o asdf permiten fijar la versión global o por proyecto; y uv (módulo 4) también descarga y fija versiones de Python.

VSCode: la extensión Python y Pylance

VSCode por sí solo es un editor de texto. La magia llega con dos extensiones:

  • Python (Microsoft): integración con el intérprete, ejecutar/depurar archivos, entornos, tests.
  • Pylance (Microsoft): análisis estático, autocompletado y avisos de tipos. Se instala junto a la anterior y usa la información de tipos para avisarte mientras escribes.

El paso que casi todos olvidan: seleccionar el intérprete. Abre la paleta de comandos (Ctrl+Shift+P / Cmd+Shift+P) y elige Python: Select Interpreter. Así el editor y la terminal usan el mismo Python.

El REPL: experimentar sin guardar archivos

El REPL (Read–Eval–Print Loop) es un intérprete interactivo: lee lo que escribes, lo evalúa, imprime el resultado y vuelve a empezar. Es perfecto para probar ideas de una línea antes de llevarlas a un .py. Se abre ejecutando python (o python3/py) sin argumentos.

  $ python3
  >>> 2 + 3            <- escribes una expresión
  5                    <- el REPL imprime su valor automáticamente
  >>> name = "Ada"     <- una asignación NO imprime nada
  >>> name.upper()
  'ADA'
  >>> exit()           <- salir (o Ctrl+D; en Windows Ctrl+Z + Enter)

El REPL es un laboratorio, no donde escribes tu proyecto. La ventaja es que los errores no se acumulan: si algo sale mal, reinicias y sigues. Lo compararemos con el script en la lección 3.

Entornos virtuales: solo un anticipo

Instalar paquetes globalmente es un error que veremos a fondo en el módulo 4. La idea: cada proyecto tiene su propio espacio de dependencias (un entorno virtual). Aquí solo dejamos el mapa para que reconozcas los comandos cuando aparezcan:

3 · Ejemplo mínimo

La sesión de REPL más pequeña posible: abrir, calcular, guardar un valor y salir. Fíjate en cómo distingue una expresión (imprime su valor) de una asignación (no imprime nada).

# Esto NO se guarda en un archivo: se escribe en el prompt >>> del REPL.
>>> 7 * 6                 # una expresión devuelve su valor y el REPL lo muestra
42
>>> price = 19.99         # una asignación crea un nombre; no muestra resultado
>>> rate = 0.21
>>> round(price * (1 + rate), 2)   # función de la biblioteca estándar
24.19
>>> import sys
>>> sys.version.split()[0]
'3.12.4'
>>> exit()                # salir del REPL

Qué demuestra cada línea:

  1. 7 * 6: una expresión suelta se evalúa y se imprime sin print. Esa es la gracia del REPL.
  2. price = 19.99: la asignación devuelve None internamente, así que no se muestra nada.
  3. round(...): no hace falta instalar nada; round está siempre disponible (builtin).
  4. sys.version.split()[0]: .split() parte la cadena por espacios y [0] toma el primer trozo, la versión limpia.

4 · Ejemplo real

Vamos a crear el primer archivo del proyecto Biblioteca en VSCode y ejecutarlo, comprobando de paso que el editor y la terminal apuntan al mismo Python.

  1. Paso 1 — la carpeta del proyecto: crea proyectos/biblioteca/ y ábrela en VSCode (File → Open Folder).
  2. Paso 2 — el archivo: guarda este hello_library.py: 
    # hello_library.py — primer arranque del proyecto Biblioteca.
# Muestra la versión del intérprete que VSCode ha seleccionado para esta carpeta.
import sys
from pathlib import Path

print(f"Python {sys.version.split()[0]} en {sys.platform}")   # versión y sistema
print(f"Ejecutando desde: {Path.cwd()}")                       # carpeta de trabajo
print("¡Listos para construir la Biblioteca!")
  3. Paso 3 — ejecutar desde la terminal integrada: abre la terminal de VSCode (Ctrl+`) y lanza: 
    python3 hello_library.py     # Linux / macOS
py hello_library.py          # Windows

    Salida esperada (rutas y versión variarán):

    Python 3.12.4 en linux
Ejecutando desde: /home/ana/proyectos/biblioteca
¡Listos para construir la Biblioteca!
  4. Paso 4 — ejecutar desde VSCode: con el archivo abierto, pulsa el triángulo ▷ Run Python File. Debe salir exactamente lo mismo. Si la versión o la ruta cambian, no tienes el mismo intérprete seleccionado en ambos sitios: vuelve a Python: Select Interpreter.

6 · Errores habituales

Windows: el alias de la Microsoft Store

# ❌ Escribes 'python' y Windows abre la Microsoft Store o no encuentra nada.
# Suele ser el ALIAS de la Store interceptando el nombre 'python'.
where.exe python        # muestra qué se ejecuta con ese nombre

# ✅ Solución A: usa el launcher oficial
py --version

# ✅ Solución B: desactiva el alias en Configuración > Aplicaciones >
#    Configuración avanzada de aplicaciones > Alias de ejecución de aplicaciones.

Dos intérpretes distintos entre VSCode y la terminal

# ❌ En la terminal tienes 3.12, pero VSCode usa 3.9 de otra carpeta
python3 --version        # 3.12.4
# y al ejecutar desde el botón Run, sale un error de sintaxis moderna

# ✅ Selecciona el intérprete en VSCode y comprueba la barra de estado
#    (abajo, a la derecha, aparece la versión activa)
#    Paleta: Ctrl+Shift+P > "Python: Select Interpreter"

Confundir el REPL con ejecutar un script

# ❌ Pegar dentro del REPL el contenido completo de un archivo con print's
#    no es lo mismo que ejecutarlo: el REPL va línea a línea e imprime
#    también expresiones intermedias.

# ✅ Para ejecutar un programa, usa el archivo y pásalo a Python:
#    python3 script.py
#    El REPL es para probar piezas sueltas, no para "lanzar" programas.

Instalar paquetes globalmente sin entorno virtual

# ❌ Instalar todo en el Python del sistema: rompe proyectos entre sí
# pip install requests        # global y sin control de versiones

# ✅ Cada proyecto, su entorno (lo veremos a fondo en el módulo 4)
python3 -m venv .venv
source .venv/bin/activate
python -m pip install requests

Mezclar pestañas y espacios por copiar/pegar

# ❌ Un archivo con tabulaciones mezcladas da TabError en tiempo de ejecución
# ✅ Configura VSCode en espacios (4) y activa "Render Whitespace"
#    El error típico es:
#    TabError: inconsistent use of tabs and spaces in indentation
def greet(name):
    return f"Hola, {name}"   # 4 espacios, siempre

7 · Ejercicio guiado

Objetivo: dejar el entorno verificado y practicar el ciclo REPL → archivo → ejecución.

  1. Paso 1: comprueba la versión en tu terminal: 
    python3 --version     # Linux / macOS
py --version          # Windows

    Esperado: Python 3.12.x o superior. Anota el comando que a ti te funciona: lo usarás en todo el curso.

  2. Paso 2: entra en el REPL y calcula el precio con impuestos: 
    >>> price = 24.90
>>> tax = 0.21
>>> round(price * (1 + tax), 2)
30.13
>>> exit()
  3. Paso 3: lleva ese cálculo a un archivo. Crea tax_calc.py: 
    # tax_calc.py — el mismo cálculo, pero en un archivo reutilizable.
def with_tax(price: float, rate: float = 0.21) -> float:
    """Devuelve el precio con impuestos, redondeado a dos decimales."""
    return round(price * (1 + rate), 2)

if __name__ == "__main__":          # solo si ejecutamos el archivo directamente
    for p in [24.90, 9.99, 120.0]:  # varios precios del catálogo
        print(f"{p:>7.2f} -> {with_tax(p):>7.2f}")

    Ejecútalo con python3 tax_calc.py (o py tax_calc.py).

  4. Paso 4 (resultado esperado): 
      24.90 ->   30.13
   9.99 ->   12.09
 120.00 ->  145.20

    Si un valor no coincide, revisa el redondeo: round usa «redondeo bancario» (al par más cercano) para empates exactos, un detalle que retomaremos en el módulo 1.

  5. Paso 5 (verificación del entorno): ejecuta el mismo archivo con el botón ▷ de VSCode. La salida debe ser idéntica. Si no lo es, vuelve a seleccionar el intérprete.

8 · Reto

🎯 Tu primer punto de interrupción

Abre tax_calc.py, pon un breakpoint en la línea del return (haz clic a la izquierda del número de línea), lanza el depurador de VSCode (Run and Debug, o F5) y detente en la pausa. Inspecciona los valores de price, rate y de la expresión price * (1 + rate). Después, desde la consola de depuración, cambia rate a otro valor y sigue la ejecución.

Pista: el panel Variables muestra los locales en el punto de parada, y el panel Watch evalúa expresiones. El depurador es la herramienta más subestimada por quien viene de lenguajes con menos soporte; aprenderlo ahora te ahorrará muchísimos print de depuración.

9 · Resumen

  • Instala Python 3.12+; en Windows marca «Add to PATH» y usa py; en Linux/macOS usa python3.
  • El PATH es la lista de carpetas donde el shell busca ejecutables: si Python no está, no lo encuentra.
  • VSCode + extensiones Python y Pylance; el paso crítico es Select Interpreter.
  • El REPL (>>>) evalúa expresiones al instante y es ideal para experimentar; no sustituye a los archivos.
  • Editor y terminal deben usar el mismo intérprete: verificado con el mismo script y misma salida.
  • Los entornos virtuales (crear, activar) son el módulo 4; aquí solo reconocimos sus comandos.

10 · Preguntas frecuentes

¿Uso python, python3 o py?

Depende del sistema: en Windows, el launcher oficial es py (y evita el alias de la Store); en Linux/macOS, python3 es lo seguro porque python puede no existir o ser antiguo. Si tras instalar 3.12 tu python ya apunta a 3.12, también vale, pero el curso escribirá python3 y anotará el equivalente py.

¿Por qué VSCode me da errores si en la terminal funciona?

Porque VSCode tiene su propio intérprete seleccionado, distinto del que resuelve tu terminal. Ejecuta Python: Select Interpreter y elige el mismo (verás la versión y la ruta). Es la causa número uno de «errores fantasma» en Python.

¿Necesito un entorno virtual ya para el módulo 0?

No. En el módulo 0 solo usamos la biblioteca estándar, que viene con Python. Los entornos virtuales aparecen en el módulo 4, cuando instalemos dependencias de terceros. Crearlos antes no molesta, pero tampoco es imprescindible todavía.

¿Qué gano usando el REPL si ya sé programar?

Velocidad de exploración: comprobar cómo se comporta un método, explorar un objeto con dir() y help(), probar una expresión de una línea o verificar una versión. Es el equivalente a la consola del navegador en JavaScript: el mejor cuaderno de borrador.
