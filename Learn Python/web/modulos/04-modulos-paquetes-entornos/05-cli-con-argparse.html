La CLI de Biblioteca con argparse

Módulo 4 · Módulos, paquetes y entornos ⏱ 35 minutos

1 · Introducción

Toda la teoría del módulo desemboca aquí: convertir Biblioteca en un comando de terminal de verdad, bib, con subcomandos add, list, search, borrow y return. Para eso usaremos argparse, el analizador de argumentos de la biblioteca estándar.

Aprenderás a declarar argumentos posicionales y opcionales, a construir subcomandos, a generar --help automático, a organizar el punto de entrada con el guard if __name__ == "__main__": y a devolver códigos de salida correctos: la parte que casi nunca se enseña y que separa un script de una herramienta profesional.

¿Por qué existe esta lección? Porque la CLI es la interfaz más común de las herramientas Python y argparse viene incluido en la stdlib: no necesitas instalar nada. Además te da la base para comparar con Click o Typer más adelante.

2 · Teoría

Todo lo que recibe un programa llega en sys.argv: una lista de strings donde argv[0] es el nombre del programa. Parsear eso a mano se vuelve un caos en cuanto hay opciones y valores por defecto. argparse lo hace de forma declarativa y además valida tipos, genera errores claros y produce la ayuda.

Posicionales vs opcionales

TipoSe declaraSe usa
Posicionaladd_argument("title")bib add "1984" (obligatorio, por orden)
Opción con valoradd_argument("--year", type=int)--year 1949
Flag booleanoadd_argument("--verbose", action="store_true")--verbose
Opción con elecciónadd_argument("--kind", choices=[...])--kind book

¿Por qué type=int? Porque sys.argv son siempre strings. Sin él, args.year sería "1949" y cualquier comparación numérica fallaría en silencio. Declarar el tipo hace que argparse convierta y valide: --year mil produce un error claro en vez de un dato corrupto.

Subcomandos: una CLI con varios verbos

Herramientas como git o pip tienen verbos (git commit, pip install). Se implementan con subparsers: cada subcomando es un parser propio con sus argumentos.

import argparse

# Parser raíz: describe el programa en conjunto
parser = argparse.ArgumentParser(prog="bib", description="Catálogo de libros y películas")
subparsers = parser.add_subparsers(dest="command", required=True)  # exige un verbo

# Subcomando "add": su propio parser y sus argumentos
add = subparsers.add_parser("add", help="Añade un ítem")
add.add_argument("title", help="Título del ítem")                  # posicional
add.add_argument("--kind", choices=["book", "movie"], default="book")
add.add_argument("--year", type=int, default=None)                 # opcional con tipo

El patrón set_defaults(func=...)

Un truco idiomático: cada subparser guarda qué función lo atiende con p.set_defaults(func=cmd_add). Así el despacho es una sola línea, args.func(args), sin una cadena de if/elif: añadir un subcomando nuevo es declararlo, y el cuerpo de main no cambia nunca.

Punto de entrada y códigos de salida

El guard if __name__ == "__main__": de cli.py permite ejecutar python -m biblioteca.cli (entrada del módulo); [project.scripts] del pyproject.toml crea el comando bib al instalar (entrada del usuario). El guard solo contiene raise SystemExit(main()); ambos llaman a la misma main.

Un proceso devuelve un número al terminar: 0 es éxito, cualquier otro valor indica fallo. Scripts y CI se basan en esto para saber si algo salió mal.

CódigoSignificadoCómo producirlo
0ÉxitoTerminar normalmente
1Error de ejecución (p. ej. no existe el id)return 1 desde el handler o al capturar BibliotecaError
2Error de uso (argumentos inválidos)Lo genera argparse automáticamente
 
# Comprobar el código de salida de un comando (bash/zsh)
bib borrow 999 ; echo "código: $?"
# Windows PowerShell:  bib borrow 999 ; echo "código: $LASTEXITCODE"
# Salida esperada si el id 999 no existe:
#   error: no existe ningún ítem con id '999'
#   código: 1

Error clásico: imprimir un mensaje de error y terminar con éxito (código 0). Así, un script o un pipeline cree que todo fue bien. Si algo falla, el código de salida debe reflejarlo.

3 · Ejemplo mínimo

Un parser de una opción, para ver el mecanismo completo: declarar, parsear y usar.

# saludo.py — ejemplo mínimo con argparse
import argparse

parser = argparse.ArgumentParser(description="Saluda a alguien")
parser.add_argument("name", help="Nombre a saludar")             # posicional
parser.add_argument("--mayusculas", action="store_true",         # flag
                    help="Imprime el saludo en mayúsculas")

args = parser.parse_args()                    # lee sys.argv y valida
saludo = f"Hola, {args.name}"
if args.mayusculas:
    saludo = saludo.upper()
print(saludo)
  1. ArgumentParser(description=...): crea el parser; la descripción aparece en --help.
  2. add_argument("name"): posicional obligatorio; action="store_true" crea un flag que vale True solo si se escribe.
  3. parse_args(): valida y devuelve un objeto con args.name y args.mayusculas.
python saludo.py Ada                # Salida: Hola, Ada
python saludo.py Ada --mayusculas   # Salida: HOLA, ADA

Ejecuta también python saludo.py --help: no escribiste ni una línea de ayuda y ya existe, generada a partir de las declaraciones. Ese es el valor de argparse.

4 · Ejemplo real

La CLI de Biblioteca con los cinco subcomandos. Es una capa fina sobre service.py: interpreta argumentos, llama al servicio y decide el código de salida (el almacén JSON se detalla en el Módulo 6).

# src/biblioteca/cli.py
"""CLI de Biblioteca con subcomandos (versión del Módulo 4)."""
import argparse                                  # analizador de la stdlib
import sys                                       # para escribir en stderr

from biblioteca import service                   # reglas de negocio
from biblioteca.models import BibliotecaError, Item

DEFAULT_STORE = "data/library.json"              # almacén por defecto

# --- Handlers: uno por subcomando; devuelven un código de salida (int) ---
def _format(item: Item) -> str:
    """Línea legible por ítem, con estado de préstamo."""
    mark = "[prestado]" if item.borrowed else "[disponible]"
    year = f" ({item.year})" if item.year else ""
    creator = f" — {item.creator}" if item.creator else ""
    return f"{item.id}  {item.title}{year}{creator}  {mark}"

def cmd_add(args: argparse.Namespace) -> int:
    creator = args.author if args.kind == "book" else args.director
    item = service.add(args.title, kind=args.kind, year=args.year,
                       creator=creator, path=args.store)
    print(f"añadido: {_format(item)}")
    return 0                                     # 0 = éxito
def cmd_list(args: argparse.Namespace) -> int:
    items = service.list_items(kind=args.kind, path=args.store)
    if not items:
        print("(catálogo vacío)")
    for it in items:
        print(_format(it))
    return 0
def cmd_search(args: argparse.Namespace) -> int:
    for it in service.search(args.term, path=args.store):
        print(_format(it))
    return 0                                       # sin resultados no es error
def cmd_borrow(args: argparse.Namespace) -> int:
    item = service.borrow(args.id, path=args.store)
    print(f"prestado: {item.id}  {item.title}")
    return 0
def cmd_return(args: argparse.Namespace) -> int:
    item = service.return_item(args.id, path=args.store)
    print(f"devuelto: {item.id}  {item.title}")
    return 0

# --- El parser: la CLI como declaración ---
def build_parser() -> argparse.ArgumentParser:
    parser = argparse.ArgumentParser(prog="bib",
        description="Biblioteca: catálogo de libros y películas")
    parser.add_argument("--store", default=DEFAULT_STORE,   # opción GLOBAL
        help="ruta del almacén JSON (por defecto: data/library.json)")
    sub = parser.add_subparsers(dest="command", required=True)   # exige verbo
    p = sub.add_parser("add", help="Añade un ítem")
    p.add_argument("title", help="Título del ítem")
    p.add_argument("--kind", choices=["book", "movie"], default="book")
    p.add_argument("--year", type=int, default=None)   # convertido y validado
    p.add_argument("--author", default=None, help="Autor (libro)")
    p.add_argument("--director", default=None, help="Director (película)")
    p.set_defaults(func=cmd_add)
    p = sub.add_parser("list", help="Lista los ítems")
    p.add_argument("--kind", choices=["book", "movie"], default=None)
    p.set_defaults(func=cmd_list)
    p = sub.add_parser("search", help="Busca por título o creador")
    p.add_argument("term", help="Texto a buscar")
    p.set_defaults(func=cmd_search)
    p = sub.add_parser("borrow", help="Presta un ítem")
    p.add_argument("id", help="Id del ítem")
    p.set_defaults(func=cmd_borrow)
    p = sub.add_parser("return", help="Devuelve un ítem")
    p.add_argument("id", help="Id del ítem")
    p.set_defaults(func=cmd_return)

    return parser

def main(argv: list[str] | None = None) -> int:
    args = build_parser().parse_args(argv)       # None -> usa sys.argv[1:]
    try:
        return args.func(args)                   # despacho uniforme al handler
    except BibliotecaError as err:
        print(f"error: {err}", file=sys.stderr)  # los errores, a stderr
        return 1                                 # 1 = error de ejecución

if __name__ == "__main__":                       # permite: python -m biblioteca.cli
    raise SystemExit(main())                     # propaga el código de salida

# Uso real (tras instalar el paquete, lecciones 03/04)
bib add "1984" --kind book --year 1949
bib add "Dune" --kind book --year 1965
bib list
bib list --kind movie
bib search "1984"
bib borrow it_9f3a1c7b
bib return it_9f3a1c7b
bib --store data/demo.json list  # --store es GLOBAL, antes del subcomando
python -m biblioteca.cli list    # equivalente sin instalar el comando

# Salida esperada (con el almacén persistente del Módulo 6)
añadido: it_9f3a1c7b  1984 (1949)  [disponible]
añadido: it_1b6d0f2a  Dune (1965)  [disponible]
it_9f3a1c7b  1984 (1949)  [disponible]
it_1b6d0f2a  Dune (1965)  [disponible]
(catálogo vacío)
it_9f3a1c7b  1984 (1949)  [disponible]
prestado: it_9f3a1c7b  1984
devuelto: it_9f3a1c7b  1984

Cómo probar la CLI: aceptar argv y devolver int hace que los handlers sean testeables sin sys.argv ni subprocesos; el proceso solo «sale» en el guard if __name__ == "__main__": de cli.py. El código 1 es de ejecución (id inexistente); argparse reserva el 2 para argumentos mal formados.

6 · Errores habituales

No declarar el tipo y comparar mal

# ❌ Sin type=int, args.year es el string "1949"
p.add_argument("--year")
# args.year < 2000  -> TypeError: '<' not supported between 'str' and 'int'

# ✅ Declara el tipo y deja que argparse convierta y valide
p.add_argument("--year", type=int, default=None)

Terminar con éxito tras un error

# ❌ Imprime el error pero el proceso "triunfa" (código 0)
def cmd_borrow(args):
    try:
        service.borrow(args.id, path=args.store)
    except BibliotecaError:
        print("No existe")           # un script creerá que todo fue bien
        return                        # devuelve None -> el proceso sale con 0

# ✅ Devuelve un código distinto de cero (o deja que main capture el error)
def cmd_borrow(args):
    try:
        service.borrow(args.id, path=args.store)
    except BibliotecaError:
        print(f"error: no existe ningún ítem con id {args.id!r}",
              file=sys.stderr)
        return 1
    return 0

Subparsers sin required=True

# ❌ Sin verbo, args.func no existe y el programa revienta con AttributeError
sub = parser.add_subparsers(dest="command")

# ✅ Exige un subcomando: argparse da un error de uso (código 2)
sub = parser.add_subparsers(dest="command", required=True)

Dos errores más: llamar a sys.exit() dentro de un handler (mata el proceso y dificulta los tests; mejor devolver int) y dejar un print de depuración en la salida. Los diagnósticos van a stderr; los datos, a stdout.

7 · Ejercicio guiado

Objetivo: construir una mini-CLI con dos subcomandos (echo y sum), comprobar --help y verificar los códigos de salida.

  1. Paso 1: crea mini_cli.py: 
    # mini_cli.py — CLI mínima con subcomandos y códigos de salida
import argparse

def cmd_echo(args: argparse.Namespace) -> int:
    print(args.text.upper() if args.upper else args.text)
    return 0

def cmd_sum(args: argparse.Namespace) -> int:
    print(args.a + args.b)                        # type=int garantiza enteros
    return 0

parser = argparse.ArgumentParser(prog="mini", description="CLI de ejemplo")
sub = parser.add_subparsers(dest="command", required=True)

p = sub.add_parser("echo", help="Repite un texto")
p.add_argument("text", help="Texto a repetir")
p.add_argument("--upper", action="store_true", help="En mayúsculas")
p.set_defaults(func=cmd_echo)

p = sub.add_parser("sum", help="Suma dos enteros")
p.add_argument("a", type=int, help="Primer entero")
p.add_argument("b", type=int, help="Segundo entero")
p.set_defaults(func=cmd_sum)

def main(argv: list[str] | None = None) -> int:
    args = parser.parse_args(argv)
    return args.func(args)                        # despacho uniforme

if __name__ == "__main__":
    raise SystemExit(main())
  2. Paso 2: prueba los subcomandos y la ayuda: 
    python mini_cli.py echo "hola python"
python mini_cli.py echo "hola python" --upper
python mini_cli.py sum 20 22
python mini_cli.py --help
  3. Paso 3: provoca un error de uso y comprueba el código de salida: 
    python mini_cli.py sum 20 veinte ; echo "código: $?"
# Windows PowerShell: python mini_cli.py sum 20 veinte ; echo "código: $LASTEXITCODE"
# Salida esperada (argparse señala el error de uso con código 2):
#   usage: mini sum [-h] a b
#   mini sum: error: argument b: invalid int value: 'veinte'
#   código: 2
  4. Paso 4 (verificación): las salidas esperadas son hola python, HOLA PYTHON y 42; y en el paso 3, código: 2. Un subcomando inexistente también devolvería 2.

8 · Reto

🎯 Salida JSON y un comando stats

Añade a la CLI de Biblioteca un flag global --json que haga que list y search impriman su resultado como JSON (con el módulo json de la stdlib) en lugar de texto. Añade además un subcomando stats que muestre cuántos ítems hay, cuántos están prestados y el reparto por kind. Cuida que --json no rompa el formato para las personas cuando no se pida.

Pista: para que el flag funcione en todos los subcomandos, añádelo al parser raíz con parser.add_argument("--json", action="store_true") y léelo como args.json. Construye la salida con json.dumps(lista_de_dicts, ensure_ascii=False, indent=2). Recuerda: datos por stdout, diagnósticos por stderr.

9 · Resumen

  • argparse está en la stdlib: parsea, valida y genera --help sin dependencias.
  • Posicionales (obligatorios, por orden) y opcionales (--flag), con type y choices para validar.
  • Los subcomandos se construyen con add_subparsers; el patrón set_defaults(func=…) despacha en una línea.
  • El guard if __name__ == "__main__": permite python -m biblioteca.cli; [project.scripts] crea el comando bib.
  • Los códigos de salida importan: 0 éxito, 1 error de ejecución, 2 error de uso (argparse).
  • Recibe argv como parámetro y devuelve int para que los handlers sean testeables.

10 · Preguntas frecuentes

¿argparse o una librería como Click o Typer?

argparse viene en la stdlib y cubre la gran mayoría de CLIs, incluidos subcomandos. Click y Typer son más ergonómicos, pero son dependencias de terceros. La regla del curso: empieza con la stdlib; si el proyecto lo justifica, salta a Typer/Click.

¿Cómo pruebo una CLI sin lanzar subprocesos?

Como main(argv) acepta la lista de argumentos, puedes llamarla directamente en un test: main(["add", "1984", "--kind", "book"]). Eso evita depender del entorno y es lo que haremos en el Módulo 7.

¿Cuándo uso python -m paquete y cuándo el comando instalado?

El comando instalado (bib) es para el usuario final: corto y sin saber dónde está el código. python -m biblioteca.cli es útil en desarrollo y para asegurarte de usar el Python del entorno. Ambos llaman a la misma función main.

¿Qué diferencia hay entre el código 1 y el 2?

El 2 lo reserva argparse para errores de uso: argumentos mal formados. El 1 lo usas tú para errores de ejecución, como pedir un ítem que no existe. Distinguirlos dice si el usuario escribió mal el comando o si el comando falló aunque estaba bien escrito.
