Cursor IDE y Cursor CLI

Módulo 3 · Cursor 🕐 30 minutos

1 · Introducción

Cursor es dos productos con el mismo motor debajo. Por un lado, un IDE —derivado de VS Code— donde el agente vive en un panel lateral, ve los archivos abiertos y te muestra diffs coloreados. Por otro, una CLI llamada agent que hace casi lo mismo desde la terminal, con un modo interactivo y otro no interactivo pensado para scripts.

Para AI-DLC, ambos son el mismo harness: leen las mismas reglas de .cursor/, escriben en el mismo aidlc/ y ofrecen el mismo comando /aidlc. Lo que cambia es cómo se renderiza la conversación y qué puedes automatizar. Y hay una diferencia que decide arquitecturas: el modo headless no puede aprobar gates.

Esta lección prepara las dos superficies: requisitos, plan, autenticación, confianza del proyecto y el detalle del repositorio Git que, si falta, rompe silenciosamente el registro de aprobaciones.

Por qué existe esta lección

La mayoría de los problemas de Cursor con AI-DLC no vienen de la metodología: vienen de abrir una carpeta que no es un repositorio Git, de no aceptar la confianza del workspace o de lanzar el ciclo en headless esperando que alguien apruebe por ti. Los tres se evitan antes de escribir el primer /aidlc.

Sin Git, los gates se pierden en silencio

No es un fallo intermitente: es el comportamiento documentado. Cursor puede saltarse los hooks de proyecto en una carpeta que no es repositorio Git. El síntoma es desconcertante —el gate se aprueba, pero al reabrir sigue pendiente— y la solución es git init y reiniciar Cursor por completo.

Instalar la CLI

macOS, Linux o WSL:

curl https://cursor.com/install -fsS | bash

Windows, en PowerShell:

irm 'https://cursor.com/install?win32=true' | iex

Después, autentica y comprueba:

agent login     # abre el navegador
agent status    # confirma la cuenta activa
agent --help    # descubre los flags disponibles en tu versión

Para scripts y CI, la CLI acepta una clave de API en el entorno:

export CURSOR_API_KEY="..."     # macOS / Linux
$env:CURSOR_API_KEY = "..."     # PowerShell

La clave de API y la sesión del navegador son credenciales distintas con usos distintos. No mezcles la de producción con la de tu portátil.

Modo interactivo y modo headless

# interactivo: conversación con opciones, como en el IDE
agent

# headless: una instrucción, una respuesta, sin interacción
agent -p "resume la estructura de src/ y dime dónde se valida el stock"

El modo headless es excelente para leer, analizar y producir informes. No sirve para conducir un ciclo con gates, porque un gate exige una respuesta humana y no hay nadie al otro lado para darla. En la práctica, headless se usa para:

  • Consultas de estado y resúmenes de artefactos.
  • Análisis previos que alimentan una etapa que luego ejecutarás en el IDE.
  • Comprobaciones en CI que no requieren aprobar nada.

Headless no es «autónomo»

Un agente sin interfaz no puede pedirte permiso ni registrar tu decisión. Si intentas recorrer un gate en headless, lo normal es que el proceso se detenga o termine sin completar la etapa. Diseña los scripts para que se detengan antes del gate y deja la aprobación para la sesión interactiva.

Confianza del workspace

Al abrir una carpeta por primera vez, Cursor pregunta si confías en ella. Aceptar habilita la ejecución de herramientas del proyecto, incluidas las reglas y los hooks de AI-DLC. Es la misma frontera de seguridad que en Claude Code: no es un clic de bienvenida, es conceder ejecución.

Si el proyecto se abre desde una ruta sincronizada en la nube o desde una unidad de red, revisa el rendimiento antes de culpar al agente: el acceso a archivos es sensiblemente más lento y las etapas con muchos archivos lo notan.

Qué aporta el IDE que la CLI no

Para AI-DLC, el valor del IDE está en la revisión: ver un diff de tres archivos con contexto, abrir el artefacto al lado del código y comparar el plan con la implementación. La CLI gana en velocidad de arranque y en automatización. Un equipo maduro usa las dos: IDE para las etapas con gates, CLI para consultar y para tareas de análisis.

3 · Ejemplo mínimo

Instalar la CLI, autenticar y hacer una consulta de solo lectura.

# 1. Instalar
curl https://cursor.com/install -fsS | bash

# 2. Autenticar
agent login
agent status

# 3. Consulta headless en el proyecto
cd ~/proyectos/inventario
agent -p "lista los archivos de src/ y di en cuál se valida el stock"

La respuesta llega como texto plano, sin panel ni botones. Es útil para saber si el agente entiende el proyecto antes de abrir el IDE.

En el IDE, el equivalente mínimo es abrir la carpeta, aceptar la confianza y preguntar lo mismo en el panel. La diferencia se nota en la segunda pregunta: en el IDE puedes seleccionar el archivo que menciona la respuesta y pedir el cambio ahí mismo.

Comprueba la versión antes de seguir

agent --help lista los flags que existen en tu instalación. AI-DLC y Cursor evolucionan a ritmos distintos; si un flag no aparece, no lo inventes: la documentación de tu versión es la referencia.

4 · Ejemplo real

El equipo de inventario decide que las personas que revisan diseño usen el IDE y que las consultas de estado se hagan por CLI. Antes de instalar AI-DLC, preparan el terreno.

# Bruno, en Windows
irm 'https://cursor.com/install?win32=true' | iex
agent login
agent status          # cuenta de empresa

# Ana, en macOS
curl https://cursor.com/install -fsS | bash
agent login

# Ambas, en el repo
cd ~/proyectos/inventario
git rev-parse --is-inside-work-tree   # debe imprimir true

Después abren la carpeta en Cursor y aceptan la confianza. Ese orden importa: si abren el IDE antes de que exista el repositorio, Cursor puede quedarse con un workspace sin hooks y el problema aparecerá más tarde, cuando un gate no se registre.

Con eso resuelto, el primer /aidlc en Cursor se comportará como en Claude Code: mismas fases, mismos gates, mismo aidlc/. La diferencia visible será el renderizado: opciones numeradas en prosa en la CLI, botones y diffs en el IDE.

La analogía del mismo coche, dos mandos

El IDE y la CLI son el mismo coche con dos juegos de mandos: uno con pantalla táctil y otro con botones físicos. El motor, las normas de circulación y el destino son idénticos. Lo que cambia es cuánto miras la pantalla mientras conduces.

5 · Buenas prácticas

HazEvitaPor qué
git init antes de abrir la carpeta en Cursor. Confiar en que los hooks funcionarán igual. Fuera de un repo, Cursor puede omitirlos y las aprobaciones no se registran.
Usar el IDE para las etapas con gate. Conducir el ciclo completo en headless. Sin interfaz no hay decisión humana, y sin decisión no hay gate.
Separar credenciales interactivas de las de CI. Exportar la clave de producción en tu shell. El gasto y los permisos deben poder atribuirse a un trabajo concreto.
Fijar el plan y el modelo por escrito en aidlc.settings.json. Dejar que cada persona use el modelo que prefiera. El coste y los resultados de una etapa deben ser comparables entre personas.
Trabajar sobre disco local. Repos en carpetas sincronizadas o unidades de red. El agente lee muchos archivos; el acceso lento se convierte en etapas eternas.

6 · Errores habituales

1. Abrir un proyecto sin repositorio Git

Mal — carpeta suelta en el escritorio 
mkdir mi-proyecto
cd mi-proyecto
cursor .          # sin git init
Bien — repositorio desde el minuto cero 
mkdir mi-proyecto
cd mi-proyecto
git init
git add .
git commit -m "Initial commit"
cursor .

Sin repo, los gates pueden aprobarse sin quedar registrados. El usuario ve que «funciona» hasta que reabre la carpeta y descubre que el estado no avanzó.

2. Intentar aprobar un gate en headless

Mal — automatizar la decisión 
agent -p "/aidlc --scope feature implementa la reserva y aprueba todo"
Bien — headless para informar, interactivo para decidir 
agent -p "resume el plan de la iniciativa activa y el estado de sus gates"
# la aprobación se hace después, en el IDE o en `agent` interactivo

El gate es una decisión humana por definición. Pedirle a un proceso sin interfaz que apruebe es pedirle que finja una decisión que nadie ha tomado.

3. Mezclar la cuenta personal con la del equipo

Mal — sesión heredada del portátil 
agent status
# Account: tu-correo-personal@ejemplo.com
Bien — verificar antes de trabajar 
agent logout
agent login
agent status
# Account: tu-correo@empresa.com (Team)

El uso queda atribuido a la cuenta equivocada, el coste se factura a quien no toca y, si el plan personal no incluye el modelo fijado, las etapas fallarán con un error que parece del proyecto.

4. Suponer que Cursor y Claude Code comparten conversación

Mal — «ya lo hablamos ayer en Claude» 
"Continúa la etapa de diseño que aprobamos ayer en la terminal"
Bien — el estado es el canal 
/aidlc --status
→ Intent: reserva-stock · Phase: Inception · Stage: design
/aidlc
→ Reanudando en design con el artefacto anterior como entrada

Lo que se comparte es aidlc/, no el hilo de conversación. Si esperas que el agente recuerde la charla, estarás confundiendo harness con metodología. El estado es el mensaje entre herramientas.

7 · Ejercicio guiado

Objetivo: dejar las dos superficies de Cursor operativas y comprobar que el repositorio cumple los requisitos de AI-DLC.

  1. Paso 1 — Instala la CLI. macOS, Linux o WSL: 
    curl https://cursor.com/install -fsS | bash

    Windows:

    irm 'https://cursor.com/install?win32=true' | iex
  2. Paso 2 — Autentica y verifica. 
    agent login
agent status
agent --help | head -20

    Anota la cuenta y el plan. Si no tienes acceso a modelos con nombre, resuélvelo antes de configurar AI-DLC.

  3. Paso 3 — Prepara el repositorio. 
    cd ~/laboratorio
mkdir cursor-aidlc && cd cursor-aidlc
git init
printf '# Laboratorio Cursor\n' > README.md
git add . && git commit -m "Initial commit"
  4. Paso 4 — Abre el IDE y confía en la carpeta. cursor . desde la raíz del repo. Acepta el aviso de confianza y comprueba que el explorador muestra el .git.
  5. Paso 5 — Prueba las dos superficies con la misma pregunta. En el panel del IDE: «¿qué contiene este repositorio?». En la terminal: agent -p "¿qué contiene este repositorio?". Compara la calidad y el formato de las respuestas.
  6. Paso 6 — Anota la conclusión. Escribe en notas.md qué tarea harías en cada superficie y por qué. Sé concreto: no «el IDE es más cómodo», sino «el IDE para revisar el diff del artefacto X; la CLI para pedir el estado en un script de release».

Resultado esperado

agent status responde con la cuenta correcta, el IDE abre el repo con confianza aceptada y ambas superficies describen el proyecto de forma coherente. Ese es el terreno para aidlc config --harness cursor.

8 · Reto

🎯 El límite del headless

Diseña un script que use agent -p para producir un informe diario del estado de todas las iniciativas activas: fase, etapa, gates pendientes y artefactos modificados en las últimas 24 horas. Debe detenerse antes de cualquier decisión y no modificar el estado.

Después responde: ¿qué parte del informe no puede producir la CLI porque depende de un juicio humano? ¿Cómo evitarías que ese informe se confunda con una aprobación?

Pista: si el script escribe en aidlc/, ya no es un informe. Mantenlo en solo lectura y que su salida viva fuera del estado del ciclo.

9 · Resumen

  • Cursor tiene dos superficies del mismo harness: el IDE y la CLI agent.
  • La CLI se instala con curl https://cursor.com/install -fsS | bash o el instalador de PowerShell en Windows.
  • agent login, agent status y agent logout gestionan la autenticación; CURSOR_API_KEY sirve para scripts.
  • agent -p es headless: útil para analizar e informar, incapaz de aprobar gates.
  • Sin repositorio Git, Cursor puede omitir hooks y las aprobaciones no se registran.
  • El plan de pago determina el acceso a modelos con nombre; fíjalo antes de configurar el proyecto.

10 · Preguntas frecuentes

¿Necesito el IDE para usar AI-DLC en Cursor?

No. La CLI interactiva ejecuta el mismo ciclo y renderiza los gates como opciones numeradas. El IDE aporta revisión visual de diffs y contexto de archivos, que es valioso pero no imprescindible. Lo que sí necesitas en ambos casos es un repositorio Git con hooks funcionando.

¿Por qué el modo headless no puede aprobar un gate?

Porque un gate es una decisión humana explícita y el modo headless no tiene interfaz para presentarla ni para recogerla. El motor no puede inferirla ni autoaprobarla. Si necesitas automatizar, automatiza la preparación y deja la aprobación a una sesión interactiva.

¿Puedo usar mi suscripción de Claude para Cursor?

No. Son productos y facturaciones distintas. Cursor requiere cuenta y plan propios, y el acceso a modelos con nombre depende de ese plan. Mezclar las cuentas solo cambia a quién se le factura el error.

¿Qué hago si Cursor no registra mis aprobaciones?

Comprueba tres cosas en orden: que la carpeta es un repositorio Git, que abriste Cursor en la raíz y no en una subcarpeta, y que reiniciaste el IDE después de git init. Si todo eso está bien, ejecuta el diagnóstico de AI-DLC dentro de la sesión; el mensaje suele nombrar el hook o la comprobación que falla.
