Instalar Claude Code

Módulo 2 · Claude Code 🕐 30 minutos

1 · Introducción

Claude Code no es una extensión del editor ni una ventana de chat con el repositorio en el portapapeles. Es un agente que vive en la terminal, lee tu árbol de archivos, ejecuta comandos, edita código y devuelve el control cuando termina. Esa diferencia —ejecutar en lugar de sugerir— es lo que lo convierte en un buen harness para AI-DLC: el ciclo necesita lanzar procesos, escribir archivos y detenerse en un punto concreto.

La instalación en sí son dos minutos. Lo que suele torcerse es lo de después: la autenticación, el aviso de confianza del proyecto, los permisos y la factura. Esta lección cubre las tres cosas en orden, con los comandos exactos y las comprobaciones que evitan media hora de dudas.

Antes de empezar, una advertencia de encuadre: Claude Code es el harness, no la metodología. Instalarlo no te da AI-DLC. Te da el entorno donde AI-DLC va a proyectarse en la lección siguiente.

Por qué existe esta lección

Sin un harness autenticado y con permisos claros, el primer /aidlc fallará en un sitio que no parece relacionado con AI-DLC: un error de login, un directorio no confiado o un modelo sin acceso. Aislar esa capa ahora te ahorra diagnosticar dos sistemas a la vez.

2 · Teoría

Qué hace exactamente

Claude Code se ejecuta en tu terminal, dentro de un directorio de proyecto. Desde ahí puede leer archivos, buscar en el árbol, proponer ediciones, ejecutar comandos de shell y usar servidores MCP que tengas configurados. Tú apruebas o rechazas las acciones según la política de permisos que hayas definido.

┌───────────────────────────────────────────────────┐
│                    terminal                       │
│  $ claude                                         │
│    ├── lee el árbol del proyecto                  │
│    ├── ejecuta comandos (con tu permiso)          │
│    ├── edita archivos (con tu permiso)            │
│    ├── usa MCP si está configurado                │
│    └── ejecuta hooks en eventos concretos         │
└───────────────────────────────────────────────────┘
              │
              ▼
        modelo (API de Anthropic)
              ▲
              │  contexto: archivos + CLAUDE.md + reglas
              │
        tu suscripción o tu API key

Las cuatro capacidades que importan para AI-DLC son: slash commands (para invocar /aidlc), hooks (para ejecutar sensores en eventos), status line (para mostrar el estado del ciclo sin preguntar) y subagentes (para separar roles de revisión).

El instalador no muestra progreso

Es normal: no hay barra ni porcentaje. Si parece colgado, espera. Al terminar verás un mensaje de éxito. Después, abre una terminal nueva para que el PATH se refresque.

Autenticación: tres caminos y para quién es cada uno

  1. Login interactivo con suscripción. Ejecutas claude, se abre el navegador, inicias sesión y vuelves. Es el camino normal en una máquina de desarrollo. Válido con planes Pro, Max, Team y Enterprise.
  2. Clave de API. Defines la credencial en el entorno y Claude Code factura por consumo. Útil si tu empresa ya tiene contrato de API o si quieres separar el gasto del plan personal.
  3. Token para automatización. claude setup-token genera un token OAuth para entornos donde no hay navegador —CI, contenedores, servidores remotos—. Requiere plan de suscripción, no vale con API key suelta.

Las credenciales se guardan en tu directorio de usuario, no en el repositorio. Si alguna vez ves un archivo de credenciales dentro del proyecto, es un error de configuración y hay que parar.

Primer arranque y el aviso de confianza

Al entrar por primera vez en un directorio, Claude Code pregunta si confías en los archivos de esa carpeta. No es un trámite: es la frontera de seguridad que impide que un repositorio descargado ejecute instrucciones sin que lo hayas autorizado. Aceptar significa que el agente puede leer y ejecutar dentro de ese árbol.

$ cd ~/proyectos/inventario
$ claude

  Do you trust the files in this folder?
  > Yes, proceed
    No, exit

  ✓ Trusted ~/proyectos/inventario

La confianza es por carpeta y se recuerda. Si clonas un repositorio ajeno para revisarlo, entra en modo lectura o no aceptes la confianza hasta haber mirado qué contiene. Un CLAUDE.md malicioso puede pedir cosas razonables en apariencia.

Qué se crea y dónde

RutaContenido¿Se versiona?
~/.claude/Configuración global, credenciales, historial, ajustes de usuarioNo
~/.claude.jsonPreferencias y estado de confianza por proyectoNo
<proyecto>/.claude/Comandos, agentes, hooks y ajustes del proyectoSí, salvo settings.local.json
<proyecto>/CLAUDE.mdInstrucciones del proyecto para el agenteSí

La distinción entre global y proyecto es la que permite que cada repositorio tenga sus reglas sin que tu configuración personal las pise. AI-DLC escribe en las dos, por motivos distintos, y la lección siguiente lo detalla.

Coste: qué estás pagando realmente

Hay dos modelos de gasto y conviene no mezclarlos:

  • Suscripción (Pro, Max, Team, Enterprise): cuota mensual con límites de uso. Para trabajo interactivo diario es lo habitual, y el límite se nota en sesiones muy largas o con modelos grandes.
  • API por consumo: pagas tokens de entrada y salida. Es más caro por sesión típica, pero escala y se factura por proyecto. Tiene sentido en equipos con contabilidad por centro de coste o en automatizaciones.

AI-DLC consume más que un chat porque lee artefactos, ejecuta revisiones y mantiene contexto entre etapas. Un ciclo feature completo puede ser varias veces más caro que pedir el mismo código en un turno. Ese sobrecoste es el precio de la trazabilidad, y se decide por perfil: un poc cuesta una fracción de un enterprise.

El coste no escala con las líneas de código

Escala con el contexto leído y las etapas ejecutadas. Un cambio de tres líneas en un módulo enorme puede costar más que una feature pequeña en un módulo limpio, porque el agente tiene que leer más para entender. Mantener el repositorio navegable es una optimización de coste.

3 · Ejemplo mínimo

Instalar, verificar y abrir una sesión. Nada más.

# 1. Instalar (macOS / Linux / WSL)
curl -fsSL https://claude.ai/install.sh | bash

# 2. Abrir una terminal nueva y comprobar
claude --version

# 3. Entrar en un proyecto y arrancar
cd ~/proyectos/inventario
claude

En Windows, el paso 1 es:

irm https://claude.ai/install.ps1 | iex

Dentro de la sesión, dos comandos te dicen dónde estás:

> /status
  Model: claude-sonnet-4-5
  Account: tu-correo@ejemplo.com (Max)
  Directory: ~/proyectos/inventario
  Permissions: default

> /doctor
  ✓ installation
  ✓ authentication
  ✓ git repository
  ! CLAUDE.md not found — run /init to create one

Si /status responde, el harness está listo. Si /doctor marca la ausencia de CLAUDE.md, no es un problema: es la invitación a ejecutar /init, que inspecciona el proyecto y propone un archivo de instrucciones inicial.

No ejecutes /init a ciegas en un repo grande

Genera un CLAUDE.md razonable, pero lo hace leyendo el proyecto. En un monorepo de doscientos paquetes, revisa el resultado antes de commitear: un archivo de instrucciones mal escrito condiciona todas las sesiones futuras.

4 · Ejemplo real

El equipo de inventario prepara la máquina de Ana, que se incorpora al proyecto. El objetivo del primer día no es escribir código: es que su entorno sea idéntico al de los demás para que el estado de AI-DLC sea compartible.

# Ana, en su portátil con macOS
curl -fsSL https://claude.ai/install.sh | bash
# abre terminal nueva
claude --version          # 2.x

git clone git@github.com:equipo/inventario.git
cd inventario
claude

Primera sesión, con las decisiones que toma:

PasoQué veQué decide
Trust«Do you trust the files in this folder?»Acepta: es el repo de su equipo y lo acaba de clonar.
LoginSe abre el navegadorEntra con la cuenta de empresa (plan Team), no con la personal.
/doctorTodo verde, CLAUDE.md presenteNada que hacer: el repo ya trae el archivo versionado.

Primer comando«Resume la estructura del proyecto»Comprueba que lee el código y respeta las reglas del CLAUDE.md.

Lo importante del día uno es que Ana no instaló nada global que afecte al proyecto. Su configuración personal vive en ~/.claude/; las reglas del equipo viven en el repositorio. Si mañana se va, el proyecto no pierde nada.

La analogía del torno del taller

Instalar Claude Code es montar el torno. Ajustarlo a tu mano es la configuración global. Las instrucciones de la pieza que estás fabricando son el CLAUDE.md del proyecto. Si confundes las tres, cada operario fabrica distinto la misma pieza.

5 · Buenas prácticas

HazEvitaPor qué
Usar el instalador nativo salvo que necesites npm. npm install -g con sudo. Una instalación con sudo no puede autoactualizarse y deja archivos con propietario incorrecto.
Versionar .claude/ y CLAUDE.md; ignorar settings.local.json. Commitear configuración personal o credenciales. Las reglas son del equipo; las preferencias y secretos, de cada máquina.
Autenticarte con la cuenta correcta desde el primer día. Mezclar cuenta personal y de empresa en el mismo proyecto. El uso, el coste y los permisos quedan atribuidos a quien no toca, y el cambio posterior molesta.
Revisar el CLAUDE.md generado por /init. Commitearlo sin leer. Es contexto obligatorio en cada sesión: un error ahí se repite cientos de veces.
Aceptar la confianza solo en repositorios que conoces. Aceptar en un repo de terceros para «ver qué hace». El agente ejecuta lo que el repositorio le indique; la confianza es una decisión de seguridad.

6 · Errores habituales

1. Instalar con sudo

Mal — permisos de root para un paquete de usuario 
sudo npm install -g @anthropic-ai/claude-code
Bien — instalador nativo o npm sin privilegios 
curl -fsSL https://claude.ai/install.sh | bash
# o, si usas npm:
npm install -g @anthropic-ai/claude-code

Con sudo, los archivos quedan propiedad de root y las actualizaciones automáticas fallan con un error de permisos que parece un bug del programa. La solución es desinstalar y reinstalar sin privilegios.

2. Confundir configuración global con configuración de proyecto

Mal — reglas del equipo en tu carpeta personal 
# ❌ escribes las convenciones en ~/.claude/CLAUDE.md
# el resto del equipo no las ve y cada uno hace una cosa
Bien — reglas en el repositorio 
proyecto/
├── CLAUDE.md          ← convenciones del equipo, versionado
├── .claude/
│   ├── commands/      ← slash commands del proyecto
│   └── settings.json  ← permisos y hooks
└── .gitignore         ← ignora .claude/settings.local.json

La configuración global es para tu comodidad. Todo lo que otra persona necesite para trabajar igual debe estar en el repositorio.

3. Aceptar la confianza sin mirar qué hay dentro

Mal — clonar, abrir, aceptar 
git clone https://github.com/alguien/repo-desconocido
cd repo-desconocido && claude
# > Yes, proceed
Bien — inspeccionar antes 
git clone https://github.com/alguien/repo-desconocido
cd repo-desconocido
ls -a
cat CLAUDE.md 2>/dev/null
cat .claude/settings.json 2>/dev/null
# ahora decides si confías

Los archivos de instrucciones y los hooks pueden ejecutar comandos. La confianza no es un clic de bienvenida: es conceder ejecución en tu máquina.

4. Ignorar la diferencia entre suscripción y API hasta la factura

Mal — usar la clave de producción en local 
export ANTHROPIC_API_KEY="sk-ant-..."   # clave del entorno productivo
claude
Bien — separar credenciales por uso 
# desarrollo interactivo: login con suscripción
claude

# automatización o CI: token específico, rotado y con límite
claude setup-token

Una sesión de agente puede consumir mucho en poco tiempo. Usar la credencial equivocada convierte una exploración en un gasto que nadie presupuestó y que además no se puede atribuir.

7 · Ejercicio guiado

Objetivo: dejar Claude Code instalado, autenticado y verificado en un repositorio de prueba, sin tocar el proyecto real.

  1. Paso 1 — Comprueba el entorno. 
    node --version
git --version
echo $SHELL

    En Windows, echo $PSVersionTable.PSVersion y confirma que estás en PowerShell, no en CMD.

  2. Paso 2 — Instala. macOS, Linux o WSL: 
    curl -fsSL https://claude.ai/install.sh | bash

    Windows:

    irm https://claude.ai/install.ps1 | iex
  3. Paso 3 — Abre una terminal nueva y verifica. 
    claude --version

    Si el comando no existe, el directorio de instalación no está en el PATH. Cierra todas las terminales y vuelve a abrir; si persiste, revisa el mensaje final del instalador, que indica la ruta exacta.

  4. Paso 4 — Crea un proyecto de prueba y autentica. 
    mkdir -p ~/laboratorio/claude-code
cd ~/laboratorio/claude-code
git init
claude

    Acepta la confianza, completa el login en el navegador y vuelve a la terminal. Ejecuta /status y anota la cuenta y el modelo.

  5. Paso 5 — Genera y revisa un CLAUDE.md. 
    > /init

    Abre el archivo en tu editor. Debe describir el proyecto, cómo ejecutar pruebas y qué convenciones seguir. Corrige lo que sea incorrecto: ese texto se inyecta en cada sesión.

  6. Paso 6 — Comprueba el aislamiento. 
    git status --short
cat .gitignore 2>/dev/null

    Verifica qué archivos aparecen. La configuración local no debería estar en el índice; si aparece, añádela al .gitignore antes de continuar.

  7. Paso 7 — Cierra con /exit y vuelve a entrar. La confianza y la autenticación deben persistir: si te pregunta otra vez, algo está impidiendo guardar el estado.

Resultado esperado

claude --version responde, /status muestra tu cuenta y directorio, y el CLAUDE.md existe pero no contiene credenciales. Ese es el punto de partida limpio para instalar AI-DLC.

8 · Reto

🎯 Elegir el modelo de facturación del equipo

Tu equipo tiene cinco personas que van a usar Claude Code a diario y un pipeline que ejecutará revisiones automáticas por la noche. Decide si conviene suscripción, API por consumo o una mezcla, y escribe el razonamiento con números: sesiones al día, duración media, etapas de AI-DLC por ciclo y coste estimado por feature.

Después identifica el riesgo de tu elección: qué pasa si un mes se duplica el uso, quién lo detecta y qué se corta primero. Una política de coste sin plan de contención no es una política.

Pista: separa siempre el uso interactivo del automatizado. El primero tolera un límite de plan; el segundo necesita credenciales propias, trazabilidad por trabajo y un tope duro.

9 · Resumen

  • Claude Code es un agente de terminal: lee, ejecuta y edita con tu permiso. Es el harness, no la metodología.
  • Instalación nativa: curl … install.sh | bash en macOS/Linux/WSL y irm … install.ps1 | iex en PowerShell.
  • npm global requiere Node 22+; nunca con sudo.
  • Autenticación por suscripción, API key o token de automatización. Las credenciales viven fuera del repositorio.
  • El aviso de trust es una frontera de seguridad, no un clic de bienvenida.
  • Global (~/.claude/) es tuyo; proyecto (.claude/, CLAUDE.md) es del equipo y se versiona.
  • El coste escala con contexto y etapas, no con líneas: el perfil de AI-DLC es la palanca principal.

10 · Preguntas frecuentes

¿Puedo usar Claude Code sin suscripción de pago?

Necesitas acceso al modelo por alguna vía: suscripción de Claude o clave de API con facturación. No hay un modo gratuito equivalente al chat web. Para probar el flujo sin coste alto, usa sesiones cortas y perfiles pequeños de AI-DLC.

¿Claude Code modifica archivos sin pedirme permiso?

Depende de la política de permisos configurada. En el modo por defecto, las acciones sensibles requieren aprobación; puedes ampliar o restringir ese comportamiento en settings.json. Lo importante es que la política esté escrita y versionada, no improvisada sesión a sesión.

¿Qué diferencia hay entre .claude/ global y de proyecto?

El global (~/.claude/) guarda tu configuración, credenciales e historial: es tuyo y no se comparte. El de proyecto (<repo>/.claude/) guarda comandos, agentes, hooks y ajustes que el equipo necesita: se versiona. AI-DLC usa los dos, con propósitos distintos.

Si cambio de ordenador, ¿pierdo la configuración?

La global sí, salvo que la copies o la gestiones con dotfiles. La del proyecto no: está en el repositorio. Esa es una razón práctica para mover al repositorio todo lo que el equipo necesite, y dejar en global solo lo estrictamente personal.

¿Funciona en WSL?

Sí, con el instalador de Linux dentro de la distribución. Trabaja sobre el sistema de archivos de WSL —/home/…— y no sobre /mnt/c/…: el rendimiento de entrada y salida a través del puente es notablemente peor y afecta a la velocidad del agente.
