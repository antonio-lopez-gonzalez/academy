Cheatsheet de AI-DLC

Referencia rápida 🧭 por intención · AI-DLC 2.x · Claude Code + Cursor

El mapa antes de los comandos

AI-DLC convierte una petición en un ciclo de vida con estado: la intención entra por una fase, cada etapa produce artefactos y termina en un gate humano, y todo queda registrado. El mismo motor corre en Claude Code y en Cursor; solo cambia el shell.

petición ──▶ fase ──▶ etapa ──▶ artefacto ──▶ revisión ──▶ gate humano
                                      │                         │
                                      ▼                         ▼
                                  aidlc/ (estado)          aprobar / cambiar
                                  audit/ (eventos)         saltar / rechazar
                                      │
                                      └──▶ siguiente etapa o fin del workflow
Si buscas…Quién lo garantizaMecanismo
Que el agente no improviseMetodologíaFases, etapas y artefactos obligatorios
Que una decisión no se pierdaHumano + motorGate con registro de aprobación
Que el trabajo sea reconstruibleMotorEstado persistente + audit trail
Que el código cumpla la specRevisores + sensoresEvidencia ligada a fuentes y checks deterministas
Que el proceso se adapte al trabajoEquipoPerfil de workflow, depth y test strategy

La regla del curso: el humano conduce, las herramientas hacen el bookkeeping y el LLM aporta conocimiento. Ningún agente se autoaprueba. Ver Qué es AI-DLC.

Comandos por intención

/aidlc Build a REST API for inventory   # empezar o continuar
/aidlc feature                          # elegir perfil explícito
/aidlc --status                         # ver dónde estás
/aidlc --doctor                         # comprobar la instalación
/aidlc --resume                         # continuar sin sonda
/aidlc space                    # cambiar de espacio
/aidlc jump --stage               # saltar a una etapa (Cursor)
/aidlc scope                    # cambiar de scope (Cursor)

Codex CLI usa $aidlc. En Cursor, /aidlc-status, /aidlc-jump y /aidlc-scope son atajos nativos. En Claude Code la línea de estado muestra el progreso; en Cursor se consulta con --status.

aidlc-lite (proyecto del curso)

Motor didáctico en Node.js que reproduce la mecánica sin llamar a un modelo. Útil para entender estado, gates, reglas y proyección sin coste de tokens.

# Desde proyectos/aidlc-lite
node src/cli.mjs init --dir .demo --harness both
node src/cli.mjs run --dir .demo --profile feature --intent "API de inventario"
node src/cli.mjs status --dir .demo
node src/cli.mjs approve --dir .demo --note "revisado"
node src/cli.mjs reject --dir .demo --note "faltan NFRs"
node src/cli.mjs sync --dir .demo
node src/cli.mjs doctor --dir .demo
node src/cli.mjs sensors --artifact examples/intent.md
node --test
ComandoQué demuestra
initConfiguración, reglas por capas y proyección a ambos harnesses.
run / statusEstado persistente y etapa activa.
approve / rejectGates humanos y audit trail en JSONL.
syncProyección idempotente a CLAUDE.md y .cursor/rules.
sensorsCheck determinista sobre un artefacto Markdown.

Anti-patrones

  • Aprobar sin leer el artefacto. El gate no es un botón de «continuar»: es tu decisión.
  • Usar enterprise para todo. La ceremonia tiene coste; elige el perfil por riesgo.
  • Saltarse la inicialización. Sin estado ni reglas, el resto del ciclo pierde sentido.
  • Editar dist/ o el motor interno. El curso usa AI-DLC como usuario, no como fork.
  • Confundir auditoría con tests. El audit trail registra decisiones; los tests verifican comportamiento.
  • Mezclar reglas de Cursor y Claude a mano. Centraliza y proyecta; si divergen, el equipo se rompe.
