Preguntas frecuentes

FAQ ❓ Dudas comunes del curso

Antes de empezar

¿Necesito pagar Cursor o Claude para seguir el curso?

Para leer el curso, no. Para ejecutar los workflows reales, sí conviene: Cursor necesita un plan de pago para usar modelos con nombre y agent mode; Claude Code necesita autenticación con Anthropic (suscripción o API key). AI-DLC en sí es gratuito y de código abierto (MIT-0). El proyecto aidlc-lite funciona sin ninguna API de IA, así que puedes practicar la mecánica aunque no tengas cuenta.

¿Puedo hacer el curso solo con Cursor o solo con Claude Code?

Sí. Los módulos 0, 1, 4, 5, 6 y 7 son neutrales. Los módulos 2 y 3 son específicos de cada harness; puedes hacer el que tengas y usar el otro como lectura comparativa. El módulo 8 no depende de ninguno de los dos.

¿Qué diferencia hay entre Aprende IA, Aprende SDD y este curso?

Aprende IA enseña capacidades de los modelos: RAG, agentes, tools, MCP, evals. Aprende SDD enseña a escribir especificaciones en Markdown + Git y el ciclo specify → plan → implement → verify. Este curso enseña a operar un ciclo de vida completo con agentes en dos herramientas reales: fases, etapas, perfiles, gates, sensores y auditoría. Se complementan; ninguno sustituye a los otros.

¿Necesito saber Node.js?

Para las lecciones no. Para el proyecto final sí: aidlc-lite es un CLI en Node.js 22 ESM. Si vienes de otro lenguaje, los conceptos (máquina de estados, gates, reglas por capas, proyección) se trasladan; cambia la sintaxis.

Metodología

¿AI-DLC es una herramienta o una metodología?

Las dos cosas. Es una metodología (fases, etapas, gates, agentes) y un motor que la ejecuta dentro de distintos harnesses. El repositorio awslabs/aidlc-workflows contiene el core neutral y las proyecciones para Claude Code, Cursor, Kiro, Codex, opencode y Copilot.

¿En qué se diferencia del vibe coding?

El vibe coding improvisa en un chat: no hay estado, ni artefactos, ni gates, ni auditoría. AI-DLC conserva la velocidad de la conversación, pero añade un ciclo verificable: cada etapa produce algo revisable y cada decisión queda registrada. Para una prueba de concepto, el vibe coding puede bastar; para trabajo de equipo, no.

¿AI-DLC escribe el código por mí sin intervención?

No. El agente ejecuta etapas y genera artefactos y código, pero el humano aprueba en cada gate. La filosofía es: el humano conduce, las herramientas hacen el bookkeeping, el LLM aporta conocimiento y el humano ejerce el juicio. Los perfiles más autónomos reducen la ceremonia, no eliminan la responsabilidad.

¿Puedo saltarme etapas o gates?

Sí, y el motor lo registra. Saltar una etapa o aprobar sin revisar es una decisión humana, no un fallo oculto: queda en el audit trail. La pregunta correcta no es «¿puedo?», sino «¿qué riesgo asumo y quién lo sabe?».

Cursor y Claude Code

¿Puedo usar los dos harnesses en el mismo proyecto?

Depende del harness. Claude Code, Cursor, Codex, Kiro y opencode comparten un bloque neutral en AGENTS.md, pero cada uno tiene su propio directorio de motor y configuración. Lo habitual es configurar uno por proyecto o mantener instalaciones separadas; el curso explica cómo sincronizar reglas y conocimiento cuando el equipo es híbrido.

¿Por qué Cursor no tiene línea de estado?

Porque el harness no expone ese surface. AI-DLC lo suple con /aidlc-status (atajo nativo de Cursor) o /aidlc --status. En Claude Code sí existe una línea de estado propia que muestra el progreso.

¿Puedo aprobar un gate desde la CLI headless de Cursor?

No. La presencia humana se registra con un turno interactivo; en modo agent -p no hay ese turno, así que un gate no puede aprobarse por diseño. Usa la CLI headless para utilidades de solo lectura (--status, --doctor) y ejecuta los workflows con gates en una sesión interactiva.

¿Qué pasa si el proyecto no es un repositorio Git?

Cursor puede omitir los hooks del proyecto si no hay repositorio Git, y sin hooks las aprobaciones no se registran. Ejecuta git init antes de aidlc config --harness cursor. En Claude Code también conviene, aunque el requisito es menos estricto.

Proyecto y verificación

¿Qué es aidlc-lite y qué no es?

aidlc-lite es un motor didáctico en Node.js que reproduce la mecánica de AI-DLC: fases, etapas, gates, estado, auditoría, reglas por capas y proyección a Cursor y Claude. No es un reemplazo del motor real, no llama a un LLM y no pretende competir con AI-DLC. Sirve para entender cómo funciona por dentro y para practicar sin coste de tokens.

¿Cómo verifico que el curso y el proyecto funcionan?

El curso se verifica con node .agents/skills/academy-verify/scripts/verify.mjs "Aprende AI-DLC con Cursor y Claude" desde la raíz de la Academy. El proyecto se verifica con node --test dentro de proyectos/aidlc-lite. La web se sirve con node scripts/serve-web.mjs.

¿Puedo usar aidlc-lite en producción?

No sin trabajo adicional. Es un proyecto educativo: no tiene autenticación, concurrencia distribuida, persistencia robusta ni integración real con harnesses. Úsalo para aprender y como base para experimentar; para producción, usa el motor oficial de AI-DLC o diseña tu propia infraestructura.
