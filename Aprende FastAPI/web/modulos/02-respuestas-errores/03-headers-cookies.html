Cabeceras y cookies

Módulo 2 · Respuestas y errores 🕐 30 minutos

1 · Introducción

Hasta ahora toda tu energía fue al cuerpo de la respuesta: el JSON. Pero una respuesta HTTP es más que un cuerpo. Tiene un código de estado (que viste en el módulo 1), unas cabeceras (metadatos sobre ese cuerpo o esa petición) y, en algunos casos, cookies (pequeños datos que el navegador guarda y reenvía).

Esta lección cubre las tres piezas que aún no has tocado: cómo añadir cabeceras desde la ruta, cómo emitir y borrar cookies de forma segura, y cómo configurar CORS para que un frontend en otro dominio pueda llamar a tu API.

¿Por qué importan las cabeceras? Porque ahí viaja información que el cuerpo no puede expresar: un identificador de traza para depurar, una política de caché, la parte «de sistema» de una respuesta. Un backend profesional no solo devuelve datos: colabora con el cliente y con los proxies intermedios a través de sus cabeceras.

Esta es una introducción a CORS. El tema a fondo —preflight, cabeceras de seguridad, orígenes concretos, credenciales— lo verás en el módulo 5, lección 3 («CORS a fondo y cabeceras de seguridad»). Aquí sentamos las bases para que cuando lo desarrolles ya te suene.

2 · Teoría

Anatomía de una respuesta HTTP

   HTTP/1.1 200 OK                       <- codigo de estado
   Content-Type: application/json        <- cabecera: como interpretar el cuerpo
   X-Trace-Id: 4f3e2d1c                  <- cabecera: metadato propio
   Set-Cookie: session=...; HttpOnly     <- cabecera: ordena guardar una cookie
   Cache-Control: no-store               <- cabecera: no guardes esto

   {"answer": "..."}                     <- cuerpo (el JSON)

Cada línea de cabecera es un par Nombre: valor. FastAPI te deja escribir cabeceras y cookies declarando un parámetro Response en tu ruta. No lo devuelves: FastAPI toma sus cabeceras y cookies y las fusiona con el cuerpo que sí devuelves.

Como viste en la lección 1, si devuelves un objeto normal, FastAPI aplica el response_model. El parámetro Response es solo un objeto temporal donde escribes cabeceras, cookies y el código de estado; el cuerpo lo pones con el return normal.

El parámetro Response

from fastapi import FastAPI, Response

app = FastAPI()


@app.get("/items")
async def items(response: Response):
    response.headers["X-Trace-Id"] = "4f3e2d1c"
    response.headers["Cache-Control"] = "no-store"
    return {"items": []}        # el cuerpo sigue siendo JSON filtrado

Dos usos del código de estado, y conviene no confundirlos:

  • response.status_code = 201 cuando el código puede variar en tiempo de ejecución.
  • status_code=201 en el decorador cuando es fijo para la ruta. Es más declarativo y además lo documenta en el OpenAPI.

Cookies: set_cookie y sus banderas de seguridad

Una cookie es un par clave=valor que el servidor pide al navegador guardar; el navegador la reenvía automáticamente en cada petición a ese dominio. response.set_cookie() genera la cabecera Set-Cookie. Sus banderas no son opcionales si te importa la seguridad:

BanderaQué haceCuándo usarla
httponly=TrueJavaScript no puede leer la cookieCasi siempre (sesiones, tokens): frena el robo por XSS
secure=TrueSolo se envía por HTTPSSiempre en producción
samesite="lax" / "strict"Limita el envío en peticiones cross-siteProtección CSRF; lax es un buen punto de partida
max_age=…Vida útil en segundosSesiones con caducidad
path="/"Ámbito de la cookieRestringe a un prefijo si solo aplica ahí
 
response.set_cookie(
    key="copiloto_session",
    value=session_id,
    httponly=True,
    secure=True,
    samesite="lax",
    max_age=3600,
)
# Y para cerrar sesion:
response.delete_cookie("copiloto_session")

Nunca metas secretos en una cookie. La cookie vive en el navegador del usuario; que sea httponly solo impide que JavaScript la lea, no que el usuario la vea en las herramientas del navegador. Guarda un identificador de sesión opaco, jamás un token con datos sensibles o una contraseña.

CORS en una frase

Los navegadores aplican la same-origin policy: una página de https://app.example.com no puede leer por defecto la respuesta de https://api.example.com, por muy pública que sea la API. CORS es el mecanismo por el que tu API le dice al navegador «está bien, este origen puede llamarme».

  • Para peticiones «no simples» (por ejemplo con Content-Type: application/json y PUT/DELETE), el navegador envía antes una petición OPTIONS de preflight y espera permiso.
  • Tu API responde con Access-Control-Allow-Origin, -Methods, -Headers, etc. Si falta el permiso, el navegador bloquea la respuesta (aunque el servidor haya respondido 200).
  • En FastAPI se configura con CORSMiddleware, un middleware: código que envuelve cada petición antes de llegar a tu ruta.

Analogía: CORS es el portero de un edificio. Tu navegador pregunta «¿puede entrar gente del portal app.example.com?». El portero (tu API) responde con la lista de invitados (Allow-Origin). Sin esa confirmación, el navegador no deja pasar la respuesta. Ojo: el portero solo controla navegadores; curl entra por la puerta de servicio sin preguntar —CORS no es autenticación—.

3 · Ejemplo mínimo

Una ruta que añade una cabecera propia y emite una cookie de sesión segura, devolviendo a la vez un JSON filtrado.

main.py
# main.py — cabecera + cookie en la misma respuesta.
import secrets

from fastapi import FastAPI, Response

app = FastAPI()


@app.post("/session")
async def start_session(response: Response):
    session_id = secrets.token_urlsafe(32)
    # Cabecera propia: util para correlacionar con los logs.
    response.headers["X-Trace-Id"] = session_id[:8]
    # Cookie de sesion con las tres banderas clave.
    response.set_cookie(
        key="copiloto_session",
        value=session_id,
        httponly=True,
        samesite="lax",
        max_age=3600,
        path="/",
    )
    return {"message": "sesion iniciada"}
terminal
uv run fastapi dev main.py
curl -s -i -X POST http://127.0.0.1:8000/session

Salida esperada (recortada): observa la cabecera X-Trace-Id y la línea Set-Cookie con sus banderas:

HTTP/1.1 200 OK
content-type: application/json
x-trace-id: 8f3a1b2c
set-cookie: copiloto_session=Q0h...; HttpOnly; Max-Age=3600; Path=/; SameSite=lax

{"message":"sesion iniciada"}

Línea por línea:

  1. response: Response: declara el objeto temporal donde escribes cabecera y cookie. No lo devuelves.
  2. secrets.token_urlsafe(32): un identificador de sesión opaco y aleatorio. El cuerpo nunca contiene datos sensibles.
  3. response.headers[...]: añade una cabecera personalizada. Los nombres son libres si empiezan por X- o son estándar.
  4. httponly=True: el JavaScript del frontend no podrá leer la cookie. Blindaje anti-XSS.
  5. return {...}: el cuerpo sale como JSON normal; FastAPI fusiona tus cabeceras con él.

4 · Ejemplo real

En Copiloto API hacemos tres cosas con cabeceras y cookies, y una con CORS. Todas en main.py y en las rutas de sesión.

proyectos/copiloto-api/app/main.py
# app/main.py — middleware de CORS y cabeceras de la app.
from fastapi import FastAPI
from fastapi.middleware.cors import CORSMiddleware

from app.config import settings
from app.error_handlers import register_exception_handlers
from app.routers import ask, auth, modules

app = FastAPI(title="Copiloto API", version="0.1.0")
register_exception_handlers(app)

# --- CORS: quien puede llamar a la API desde un navegador ---
app.add_middleware(
    CORSMiddleware,
    allow_origins=settings.cors_origins,   # p. ej. ["https://academy.example.com"]
    allow_credentials=True,                # permitir cookies cross-origin
    allow_methods=["GET", "POST"],         # solo lo que la API usa
    allow_headers=["Content-Type", "Authorization"],
    expose_headers=["X-Trace-Id"],         # cabeceras que el JS PUEDE leer
    max_age=600,                           # cachea el preflight 10 min
)

app.include_router(modules.router)
app.include_router(ask.router)
app.include_router(auth.router)
proyectos/copiloto-api/app/routers/auth.py
# app/routers/auth.py — sesion anonima basada en cookie HttpOnly.
import secrets

from fastapi import APIRouter, Response, status

from app.schemas.auth import SessionOut

router = APIRouter(prefix="/auth", tags=["auth"])

COOKIE = "copiloto_session"


@router.post("/anonymous", response_model=SessionOut, status_code=status.HTTP_201_CREATED)
async def start_anonymous_session(response: Response) -> SessionOut:
    """Crea una sesion anonima. El id vive SOLO en la cookie HttpOnly."""
    session_id = secrets.token_urlsafe(32)
    response.set_cookie(
        key=COOKIE,
        value=session_id,
        httponly=True,
        secure=True,        # en local con http, ponlo a False via settings
        samesite="lax",
        max_age=3600,
        path="/",
    )
    # En el cuerpo NO va el session_id: solo su prefijo, para soporte.
    return SessionOut(anonymous=True, session_prefix=session_id[:8])


@router.delete("/session", status_code=status.HTTP_204_NO_CONTENT)
async def end_session(response: Response) -> None:
    response.delete_cookie(COOKIE, path="/")
proyectos/copiloto-api/app/routers/ask.py
# app/routers/ask.py — cabeceras utiles en la respuesta de /ask.
import time

from fastapi import APIRouter, Request, Response

router = APIRouter(tags=["ask"])


@router.get("/health")
async def health(response: Response) -> dict[str, str]:
    # Salud: nunca cachear, siempre fresco.
    response.headers["Cache-Control"] = "no-store"
    return {"status": "ok"}

@router.post("/ask", response_model=AskOut)
async def ask(payload: AskIn, request: Request, response: Response) -> AskOut:
    trace_id = getattr(request.state, "trace_id", "n/a")
    # Cabeceras de trazabilidad y de cuota (la cuota la llenara el modulo 5).
    response.headers["X-Trace-Id"] = trace_id
    response.headers["X-RateLimit-Remaining"] = "57"

    started = time.perf_counter()
    result = await engine.run(payload.question)
    # Cabecera con el tiempo de proceso, redondeado a milisegundos.
    response.headers["X-Process-Time-Ms"] = f"{(time.perf_counter() - started) * 1000:.1f}"
    return result

Decisiones y porqués:

  • CORS con lista explícita de orígenes: settings.cors_origins trae los dominios permitidos de configuración. Nada de ["*"] en producción, y menos junto a allow_credentials=True (el navegador lo rechaza).
  • expose_headers=["X-Trace-Id"]: por defecto, el JavaScript de otro origen solo puede leer unas pocas cabeceras «seguras». Si quieres que el frontend vea tu X-Trace-Id, hay que exponerla explícitamente.
  • Sesión en cookie HttpOnly: el session_id nunca es accesible desde JavaScript ni aparece en el cuerpo. Máxima superficie reducida.
  • Cache-Control: no-store en /health: un proxy que cachee la salud daría una falsa sensación de «todo ok».
  • X-Process-Time-Ms y X-RateLimit-Remaining: telemetría útil que el cliente puede leer y los dashboards pueden consumir, sin ensuciar el cuerpo de negocio.

secure=True rompe el desarrollo en http://localhost. En local, el navegador no enviará una cookie Secure por HTTP. Gestiona el valor desde tu configuración (por ejemplo settings.cookie_secure): False en local, True siempre en producción. Lo verás con detalle al hablar de settings en el módulo 3.

5 · Buenas prácticas

HazEvitaPor qué
Cookies de sesión con HttpOnly, Secure y SameSite Cookies sin banderas «por comodidad» Reducen el robo por XSS y los ataques CSRF
Guardar en la cookie un id opaco Meter el token o el perfil completo dentro La cookie es visible para el usuario y manipulable

6 · Errores habituales

Devolver un Response y perder el response_model

Mal — construir todo el JSONResponse a mano 
# ❌ Al devolver un Response directo, FastAPI NO valida ni filtra el cuerpo:
#    puedes estar publicando campos internos sin darte cuenta.
from fastapi.responses import JSONResponse

@app.get("/modules/{slug}")
async def get_module(slug: str):
    module = await repo.get_full(slug)
    return JSONResponse(content=module.model_dump())   # ¡el embedding incluido!
Bien — Response solo para cabeceras, cuerpo por el return 
# ✅ El parametro Response anade cabeceras; el return sigue filtrado.
@app.get("/modules/{slug}", response_model=ModuleOut)
async def get_module(slug: str, response: Response) -> ModuleOut:
    response.headers["X-Cache"] = "MISS"
    return await repo.get_full(slug)     # response_model filtra

Cookie de sesión sin banderas y con datos dentro

Mal — legible por JS, sin caducidad, con datos 
# ❌ Sin HttpOnly, sin Secure, sin SameSite: vulnerable y sin caducar.
response.set_cookie("user", json.dumps({"email": "ana@example.com", "role": "admin"}))
Bien — id opaco y banderas completas 
# ✅ Solo un id opaco, con HttpOnly/Secure/SameSite/max_age.
response.set_cookie(
    "copiloto_session", session_id,
    httponly=True, secure=True, samesite="lax", max_age=3600, path="/",
)

CORS abierto a todos con credenciales

Mal — combinación que ni el navegador acepta 
# ❌ Con allow_credentials=True, "*" es invalido y ademas inseguro.
app.add_middleware(
    CORSMiddleware,
    allow_origins=["*"],
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)
Bien — orígenes concretos y métodos acotados 
# ✅ Origenes desde settings y solo los metodos que usas.
app.add_middleware(
    CORSMiddleware,
    allow_origins=settings.cors_origins,   # ["https://academy.example.com"]
    allow_credentials=True,
    allow_methods=["GET", "POST"],
    allow_headers=["Content-Type", "Authorization"],
)

Creer que CORS protege tu API

Mal — confiar en CORS como seguridad 
# ❌ CORS solo lo aplica el NAVEGADOR. curl, scripts y bots lo ignoran.
#    Si el endpoint no exige autenticacion, cualquiera lo llama.
@app.get("/admin/stats")
async def stats():
    return await repo.stats()
Bien — autenticación/de autorización real 
# ✅ La proteccion es auth real (JWT/roles); CORS es solo higiene del navegador.
@app.get("/admin/stats")
async def stats(admin: AdminUser = Depends(get_current_admin)):
    return await repo.stats()

7 · Ejercicio guiado

Objetivo: añadir a Copiloto API una cabecera de trazabilidad en todas las respuestas y una cookie de sesión anónima, y verificar con curl que viajan correctamente.

  1. Paso 1: crea un middleware que asigne un trace_id a cada petición y lo ponga en la respuesta: 
    # app/middleware.py
import uuid

from starlette.middleware.base import BaseHTTPMiddleware
from starlette.requests import Request


class TraceIdMiddleware(BaseHTTPMiddleware):
    async def dispatch(self, request: Request, call_next):
        request.state.trace_id = uuid.uuid4().hex[:8]
        response = await call_next(request)
        response.headers["X-Trace-Id"] = request.state.trace_id
        return response
  2. Paso 2: regístralo antes de incluir routers y añade el CORS para el frontend de la Academy: 
    # app/main.py
from fastapi import FastAPI
from fastapi.middleware.cors import CORSMiddleware

from app.middleware import TraceIdMiddleware

app = FastAPI(title="Copiloto API")
app.add_middleware(TraceIdMiddleware)
app.add_middleware(
    CORSMiddleware,
    allow_origins=["http://localhost:5173"],   # el front en desarrollo
    allow_credentials=True,
    allow_methods=["GET", "POST", "DELETE"],
    allow_headers=["Content-Type"],
    expose_headers=["X-Trace-Id"],
)
  3. Paso 3: añade la ruta de sesión anónima con cookie segura: 
    # app/routers/auth.py
import secrets

from fastapi import APIRouter, Response, status

router = APIRouter(prefix="/auth", tags=["auth"])


@router.post("/anonymous", status_code=status.HTTP_201_CREATED)
async def anonymous(response: Response) -> dict[str, str]:
    session_id = secrets.token_urlsafe(32)
    response.set_cookie(
        "copiloto_session", session_id,
        httponly=True, samesite="lax", max_age=3600, path="/",
    )
    return {"session_prefix": session_id[:8]}
  4. Paso 4 (verificación): arranca y comprueba cabecera y cookie: 
    uv run fastapi dev app/main.py

# La cabecera de traza debe venir en cualquier respuesta:
curl -s -i http://127.0.0.1:8000/health | findstr /I "X-Trace-Id"

# Cookie de sesion:
curl -s -i -X POST http://127.0.0.1:8000/auth/anonymous | findstr /I "Set-Cookie"

# Preflight de CORS (OPTIONS) desde el origen permitido:
curl -s -i -X OPTIONS http://127.0.0.1:8000/ask \
  -H "Origin: http://localhost:5173" \
  -H "Access-Control-Request-Method: POST"

    Resultado esperado: el GET /health trae X-Trace-Id; el POST /auth/anonymous trae Set-Cookie: copiloto_session=…; HttpOnly; SameSite=lax; y el preflight responde 200 con Access-Control-Allow-Origin: http://localhost:5173 y Access-Control-Allow-Credentials: true. Si el preflight falla, revisa que el origen esté exactamente en allow_origins (con esquema y puerto) y que el método pedido esté en allow_methods.

8 · Reto

🎯 Una política de sesión completa y observable

Diseña la gestión de sesión del Copiloto end-to-end: (1) un endpoint de sesión que emita una cookie HttpOnly cuya caducidad y bandera Secure dependan del entorno; (2) un endpoint DELETE /auth/session que la borre de verdad; (3) una cabecera X-Session-Prefix en cada respuesta autenticada; y (4) un middleware que añada X-Trace-Id a todas las respuestas, incluidas las de error (que ya generan su propio trace_id: haz que sean el mismo). Añade un test que verifique que la cabecera X-Trace-Id aparece tanto en un 200 como en un 404.

Pista: los middlewares envuelven todo el flujo, así que el trace_id del middleware y el del handler de error deben compartirse vía request.state.trace_id —asigna el id en el middleware y léelo desde el handler—. Para la cookie, lee la bandera secure de settings y no la cablees en el código.

9 · Resumen

  • Una respuesta HTTP es estado + cabeceras + cuerpo. Cubre los tres.
  • Declara un parámetro Response para escribir cabeceras y cookies sin perder el response_model del cuerpo.
  • Cookies de sesión siempre con HttpOnly, Secure y SameSite; dentro, solo un id opaco.
  • set_cookie() emite, delete_cookie() borra.
  • CORS es del navegador: se configura una vez con CORSMiddleware, con orígenes explícitos.
  • expose_headers es necesario para que el JavaScript de otro origen lea tus cabeceras propias.
  • CORS no es autenticación: la protección real es auth + roles.

10 · Preguntas frecuentes

¿Cookie o cabecera Authorization para el token?

Depende del cliente. Una cookie HttpOnly protege el token de XSS (JavaScript no lo lee) pero exige cuidar CSRF (SameSite y, si hace falta, un token anti-CSRF). Una cabecera Authorization: Bearer … es natural para APIs consumidas por apps móviles o servicios y exige guardar el token en algún sitio seguro en el front. El Copiloto usará cabecera para la API y cookie para el frontend navegable. Lo verás a fondo en el módulo 5.

¿Por qué mi frontend no ve X-Trace-Id aunque la respuesta la traiga?

Porque, en peticiones cross-origin, el navegador solo expone unas pocas cabeceras «seguras» (como Content-Type) salvo que el servidor las declare en Access-Control-Expose-Headers —en FastAPI, el parámetro expose_headers del CORSMiddleware—. La cabecera viaja; simplemente el JavaScript no puede leerla sin permiso explícito.

¿allow_origins=["*"] es siempre malo?

Para una API pública, sin credenciales y de solo lectura, es aceptable. El problema aparece al combinarlo con allow_credentials=True: el navegador rechaza esa combinación y, si lo «arreglas» reflejando el origen de la petición, abres la puerta a cualquier web. Regla práctica: en cuanto haya cookies o tokens, lista los orígenes concretos desde configuración.

¿Response y JSONResponse son intercambiables?

No con la misma intención. El parámetro Response es para añadir cabeceras/cookies y seguir devolviendo datos normales (con response_model aplicado). Devolver un Response —por ejemplo un JSONResponse o un PlainTextResponse— significa «yo controlo la respuesta entera»: te saltas el filtrado y la validación del cuerpo. Úsalo cuando de verdad necesites control total (ficheros, streaming, HTML), no por costumbre.

¿Dónde configuro los orígenes permitidos, en código o en entorno?

En entorno, leído por tu configuración (settings.cors_origins), igual que las claves. Los orígenes cambian entre local, staging y producción; cablarlos en el código obliga a tocar y redesplegar. Lo verás al montar pydantic-settings en el módulo 3.
