Rutas: path y query

Módulo 1 · Rutas y datos 🕐 30 minutos

1 · Introducción

Una petición HTTP llega con información repartida en varios sitios: parte en la URL (la ruta y lo que va después del ?), parte en el cuerpo (el JSON de un POST) y parte en las cabeceras. En esta lección nos centramos en las dos formas más comunes de pasar datos por la URL: los path parameters (trozos de la ruta) y los query parameters (lo que va tras el ?).

Aprenderás a declararlos en tus funciones de ruta, a tiparlos para que FastAPI valide y convierta los valores automáticamente, a darles valores por defecto (y por tanto hacerlos opcionales) y a acotarlos y documentarlos con Path y Query. Es la base sobre la que se construyen todos los endpoints del hilo conductor del curso, Copiloto API.

¿Por qué importa esto? Porque la URL es la interfaz de tu API. Si aceptas limit como texto libre y luego lo usas para consultar una base de datos, cualquier cliente puede pedir un millón de filas con ?limit=999999999. FastAPI convierte un type hint en parseo + validación + documentación: declaras la regla una vez y el framework la hace cumplir en cada petición.

Errores típicos que verás (y aprenderás a evitar): confundir un path param con un query param, aceptar todo como str «por si acaso», no acotar los valores numéricos, o creer que un parámetro sin valor por defecto es opcional. Cada uno se corrige entendiendo qué dice el type hint.

2 · Teoría

Anatomía de una URL

Una URL de una petición a tu API se descompone así:

https://api.copiloto.dev/modules/3/reviews?level=avanzado&limit=10&sort=recent \____/ \_____________/ \________________/ \____/ \___________________________/ esquema host PATH ? QUERY STRING (ruta) (empieza la query)

El path identifica qué recurso quieres; la query string describe cómo lo quieres (filtros, orden, paginación). El path forma parte del «nombre» del recurso: /modules/3 y /modules/4 son recursos distintos. La query, en cambio, matiza la respuesta del mismo recurso: /modules con o sin ?level=avanzado sigue siendo «el listado de módulos».

Path parameters

Declaras un path param escribiendo entre llaves un trozo de la ruta y añadiendo un parámetro con el mismo nombre a la función:

@app.get("/modules/{module_id}")
def read_module(module_id: int):   # {module_id} aparece también aquí
    return {"module_id": module_id}

El type hint (int) no es decorativo: FastAPI lee el valor "3" de la URL, lo convierte a 3 y, si no puede (por ejemplo /modules/foo), devuelve automáticamente un error 422 sin que tú escribas nada.

Analogía — el mostrador de atención: el path es a qué ventanilla te diriges (/modules/3 = «ventanilla del módulo 3»). Si pides una ventanilla que no existe con un formato imposible, el sistema te frena en la puerta. La query son las preguntas que haces una vez en el mostrador: «enséñame lo más reciente», «solo diez». Cambian lo que te dan, no dónde estás.

Query parameters

Un query parameter es cualquier parámetro de la función que no aparece entre llaves en la ruta. FastAPI los detecta solos y los busca en la query string:

@app.get("/modules")
def list_modules(level: str = "basico"):   # ?level=avanzado
    return {"level": level}

Fíjate en la diferencia clave: un parámetro con valor por defecto es opcional; si el cliente no lo envía, se usa el valor por defecto. Un parámetro sin default es obligatorio: si falta, es un 422.

Valores por defecto, opcionales y None

Declaración¿Obligatorio?Significado
q: strSíDebe venir siempre; si falta, 422.
q: str = "hola"NoDefault "hola"; el tipo sigue siendo str.
q: str | None = NoneNoPuede faltar o valer None; el default suele ser None.
q: str = NoneNo⚠️ No recomendado en Pydantic v2: el tipo no admite None.

La regla moderna (Pydantic v2) es: usa str | None = None cuando el valor puede ser nulo, y nunca un default None sobre un tipo que no incluye None.

Booleanos en la query: si declaras activo: bool = False, FastAPI acepta true, True, 1, yes, on… como verdadero y false, 0, no, off como falso. Es cómodo, pero laxo; si quieres un conjunto cerrado de valores usa un Literal (lo veremos en el ejemplo real).

Validar y documentar con Path y Query

Un type hint valida el tipo, pero no los límites. Para reglas como «el ID debe ser mayor que 0» o «el texto debe tener entre 3 y 50 caracteres» se usan las clases Path y Query, envueltas en Annotated:

from typing import Annotated
from fastapi import Path, Query

@app.get("/modules/{module_id}")
def read_module(
    module_id: Annotated[int, Path(ge=1, description="ID del módulo")],
    q: Annotated[str | None, Query(min_length=3, max_length=50)] = None,
):
    ...

Annotated[tipo, metadatos] es la forma actual recomendada: deja el tipo y los metadatos de FastAPI en el mismo sitio, y funciona igual con Path que con Query. Estas restricciones se reflejan en la documentación /docs y en el esquema OpenAPI, que es el contrato de la API.

RestricciónSignificado
gt / gegreater than / greater or equal (mayor que / mayor o igual).
lt / leless than / less or equal.
min_length / max_lengthLongitud mínima/máxima de una cadena (o de una lista).
patternExpresión regular que debe cumplir el valor (p. ej. un slug).
description, examples, titleMetadatos que se publican en OpenAPI y aparecen en /docs.

Path o Query: usa Path para parámetros de la ruta y Query para los de la query string. Ambos comparten casi todas las restricciones; la diferencia es solo dónde se leen. Si te equivocas no pasa nada grave, pero la documentación sería engañosa.

3 · Ejemplo mínimo

El endpoint más pequeño con un path param y un query param. Un path param obligatorio (module_id) y un query param opcional con default (lang).

main.py
# main.py — el ejemplo más pequeño con path y query params
from fastapi import FastAPI

app = FastAPI()


# {lang} NO está entre llaves en la ruta, así que es un QUERY param.
# Tiene default "es": si el cliente no lo manda, se usa el default.
@app.get("/modules/{module_id}")
def read_module(module_id: int, lang: str = "es"):
    return {"module_id": module_id, "lang": lang}

Arranca el servidor y prueba (el Módulo 0 instala uv y uvicorn; aquí se asume hecho):

# -> añade las dependencias si aún no las tienes
uv add fastapi "uvicorn[standard]"

# Arranca con recarga automática al guardar archivos
uv run uvicorn main:app --reload --port 8000

# En otra terminal:
curl "http://127.0.0.1:8000/modules/3"
# -> {"module_id":3,"lang":"es"}

curl "http://127.0.0.1:8000/modules/3?lang=en"
# -> {"module_id":3,"lang":"en"}

curl "http://127.0.0.1:8000/modules/foo"
# -> 422: el type hint int rechaza "foo" (no escribiste ni una línea)

¿Por qué module_id llega como int? Porque lo declaraste así. FastAPI parsea "3" (texto de la URL) a 3 (entero) y valida la conversión. Si el valor no se puede convertir, responde 422 con un mensaje que indica exactamente dónde falló: loc: ["path", "module_id"].

4 · Ejemplo real

En Copiloto API el catálogo de módulos del asistente se expone con dos endpoints: un listado filtrable y un detalle por ID. Fíjate en cómo el tipado (Literal, int) y las restricciones (ge, le) convierten la URL en un contrato validado y autodocumentado.

app/routers/modules.py
# app/routers/modules.py — catálogo de módulos del Copiloto
from typing import Annotated, Literal

from fastapi import APIRouter, Path, Query

# Un router agrupa rutas relacionadas. prefix se antepone a todas.
router = APIRouter(prefix="/modules", tags=["modules"])

# Literal restringe los valores permitidos: si llega otra cosa, 422.
Level = Literal["basico", "intermedio", "avanzado"]


@router.get("")  # -> GET /modules
def list_modules(
    # Query: filtro opcional. None significa "sin filtrar".
    level: Annotated[Level | None, Query(description="Filtra por nivel")] = None,
    # Query acotada: nunca más de 100 filas, nunca menos de 1.
    limit: Annotated[int, Query(ge=1, le=100, description="Filas a devolver")] = 20,
    # Un offset negativo no tiene sentido: ge=0.
    offset: Annotated[int, Query(ge=0, description="Filas a saltar")] = 0,
):
    # (En el Módulo 4 esto vendrá de la base de datos; aquí lo simulamos.)
    modules = [
        {"id": 1, "title": "Que es FastAPI", "level": "basico"},
        {"id": 2, "title": "Rutas y datos", "level": "basico"},
        {"id": 3, "title": "Dependencias", "level": "intermedio"},
        {"id": 4, "title": "Seguridad", "level": "avanzado"},
    ]
    if level is not None:
        modules = [m for m in modules if m["level"] == level]
    return {"total": len(modules), "items": modules[offset : offset + limit]}


@router.get("/{module_id}")  # -> GET /modules/3
def get_module(
    # Path con restricción: el ID de un módulo empieza en 1.
    module_id: Annotated[int, Path(ge=1, description="ID del módulo")],
):
    return {"id": module_id, "title": "Rutas y datos", "level": "basico"}

# Listado con filtro y paginación (el & separa query params)
curl "http://127.0.0.1:8000/modules?level=avanzado&limit=10&offset=0"
# -> {"total":1,"items":[{"id":4,"title":"Seguridad","level":"avanzado"}]}

# Un nivel inválido dispara el Literal:
curl "http://127.0.0.1:8000/modules?level=imposible"
# -> 422 (input no está en la lista permitida)

# Un ID fuera de rango dispara la restricción del Path:
curl "http://127.0.0.1:8000/modules/0"
# -> 422 (ge=1)

El contrato en /docs: abre http://127.0.0.1:8000/docs. Verás level como un desplegable con los tres valores de Literal, y limit con sus cotas. Documentar y validar son la misma declaración: no hay que mantener nada por duplicado.

5 · Buenas prácticas

HazEvitaPor qué
Tipa cada parámetro con su tipo real (int, float, bool, Literal, datetime) module_id: str y convertir a mano dentro El tipo da parseo, validación y documentación gratis; convertir a mano reintroduce errores y código repetido.
Acota los numéricos (ge, le, gt, lt) limit: int = 20 sin cota superior Un cliente puede pedir limit=999999999 y tumbar la base de datos. La cota es defensa básica.
Usa Literal/Enum para conjuntos cerrados de valores Validar con if nivel not in (...) a mano El error 422 y la documentación (desplegable en /docs) salen solos.
Recurre a Path/Query vía Annotated La forma antigua module_id: int = Path(...) como default Ambas funcionan, pero Annotated es la recomendada en Pydantic v2 y no disfraza el default.
Da description y examples a lo público Dejar los parámetros sin explicar OpenAPI es el contrato: quien consume la API lo lee en /docs sin abrir tu código.
Usa str | None = None para lo realmente opcional q: str = None En Pydantic v2 el None por defecto sobre un tipo no nulo es incoherente y avisa.

6 · Errores habituales

Un parámetro sin default después de uno con default

Es un error de Python, no de FastAPI: en una función los parámetros sin valor por defecto deben ir antes que los que sí lo tienen.

# ❌ SyntaxError: non-default argument follows default argument
@app.get("/modules")
def list_modules(limit: int = 10, offset: int):
    ...

# ✅ Reordena (o dale default a offset)
@app.get("/modules")
def list_modules(offset: int, limit: int = 10):
    ...

Confundir path y query

# ❌ Esperas /modules?id=3, pero declaraste un path param
@app.get("/modules/{module_id}")
def get_module(module_id: int):
    ...

# La petición /modules?id=3 NO casa con la ruta anterior: es 404 (ruta != ),
# y si además falta el trozo obligatorio, ni siquiera entra.

# ✅ Si el ID identifica al recurso, va en la ruta:
#    GET /modules/3
# ✅ Si es un filtro del listado, va en la query:
#    GET /modules?level=avanzado

No acotar los valores

# ❌ Cualquier entero pasa, incluso negativos o enormes
@app.get("/modules")
def list_modules(limit: int = 20, offset: int = 0):
    return modules[offset : offset + limit]

# ✅ Cotas explícitas = contrato claro y defensa contra abusos
from typing import Annotated
from fastapi import Query

@app.get("/modules")
def list_modules(
    limit: Annotated[int, Query(ge=1, le=100)] = 20,
    offset: Annotated[int, Query(ge=0)] = 0,
):
    ...

Usar str «por si acaso»

# ❌ El tipo no valida nada y hay que convertir a mano (y adivinar el error)
@app.get("/modules/{module_id}")
def get_module(module_id: str):
    if not module_id.isdigit():
        return {"error": "id inválido"}   # forma de error inconsistente
    module_id = int(module_id)
    ...

# ✅ El tipo correcto hace el trabajo y devuelve un 422 estándar
@app.get("/modules/{module_id}")
def get_module(module_id: int):
    ...

Ojo con bool en la query: activo: bool = False acepta 1, yes y on como verdaderos. Si tu API solo admite true/false, usa Literal["true", "false"] o un Enum: el valor desconocido se convierte en un 422 en lugar de un silencioso «verdadero» inesperado.

7 · Ejercicio guiado

Objetivo: construir el endpoint de lecciones de un módulo de Copiloto API combinando path y query params, y comprobar los 422 en vivo.

  1. Paso 1 — Crea el archivo. 
    mkdir -p copiloto-api/app && cd copiloto-api
uv init --bare   # crea pyproject.toml sin paquete de ejemplo
uv add fastapi "uvicorn[standard]"
  2. Paso 2 — Escribe el endpoint. Ruta /modules/{module_id}/lessons, con module_id de tipo int y ≥ 1, y dos query params: level (opcional, cerrado con Literal) y limit (1..50, por defecto 10).
    app/main.py
    from typing import Annotated, Literal

from fastapi import FastAPI, Path, Query

app = FastAPI(title="Copiloto API")

Level = Literal["basico", "intermedio", "avanzado"]

_LESSONS = [
    {"id": 1, "title": "Que es FastAPI", "level": "basico"},
    {"id": 2, "title": "Rutas y datos", "level": "basico"},
    {"id": 3, "title": "Dependencias", "level": "intermedio"},
    {"id": 4, "title": "Seguridad", "level": "avanzado"},
]


@app.get("/modules/{module_id}/lessons")
def list_lessons(
    module_id: Annotated[int, Path(ge=1, description="ID del módulo")],
    level: Annotated[Level | None, Query()] = None,
    limit: Annotated[int, Query(ge=1, le=50)] = 10,
):
    lessons = _LESSONS
    if level is not None:
        lessons = [x for x in lessons if x["level"] == level]
    return {"module_id": module_id, "count": len(lessons), "items": lessons[:limit]}
  3. Paso 3 — Arranca y prueba los caminos felices. 
    uv run uvicorn app.main:app --reload

curl "http://127.0.0.1:8000/modules/1/lessons"
# -> {"module_id":1,"count":4,"items":[...]}
curl "http://127.0.0.1:8000/modules/1/lessons?level=basico&limit=1"
# -> {"module_id":1,"count":2,"items":[{...}]}   (solo el primero)
  4. Paso 4 — Provoca los errores y comprueba la loc. 
    curl "http://127.0.0.1:8000/modules/0/lessons"     # -> 422: ge=1 en PATH
curl "http://127.0.0.1:8000/modules/x/lessons"     # -> 422: no es int
curl "http://127.0.0.1:8000/modules/1/lessons?limit=999"   # -> 422: le=50
curl "http://127.0.0.1:8000/modules/1/lessons?level=foo"   # -> 422: no está en Literal

    Fíjate en el campo loc de cada error: ["path", "module_id"] frente a ["query", "limit"]. FastAPI te dice dónde leyó el valor, lo que hace el diagnóstico inmediato.

  5. Paso 5 — Verificación final. Abre /docs y comprueba que module_id aparece marcado como obligatorio, level con su desplegable y limit con las cotas 1 y 50. Si lo ves, la lección está dominada.

8 · Reto

🎯 Buscador paginado del catálogo

Añade a Copiloto API un endpoint GET /modules/search que combine varios query params: un texto libre q (opcional, entre 3 y 100 caracteres), un level reutilizando el Literal, un sort que solo admita "recent" o "title" (piensa cómo acotar ese conjunto), y la pareja de paginación limit/offset con cotas sensatas. Cuida el orden de los parámetros: los que no tienen default, primero. Compruébalo abriendo /docs y forzando un 422 con ?sort=lo-que-sea.

9 · Resumen

  • El path identifica el recurso (/modules/3); la query matiza la respuesta (?level=avanzado).
  • Un parámetro de la función que coincide con {nombre} en la ruta es path param; cualquier otro es query param.
  • El type hint da parseo, conversión y validación: module_id: int rechaza "foo" con un 422 automático.
  • Con default = opcional; sin default = obligatorio. Para lo realmente opcional usa str | None = None.
  • Annotated[tipo, Path(...)] y Annotated[tipo, Query(...)] añaden restricciones (ge, le, min_length, pattern) y documentación a la vez.
  • Literal/Enum acotan conjuntos cerrados de valores y generan desplegables en /docs.
  • Las restricciones y el tipado se publican en el contrato OpenAPI: validar y documentar son la misma declaración.

10 · Preguntas frecuentes

¿Cómo sabe FastAPI que un parámetro es de la query y no del cuerpo?

Por su tipo y su origen en la firma. Los parámetros escalares (tipos simples como int, str, bool, Literal, datetime) se leen de la ruta o de la query string; los que son modelos de Pydantic (BaseModel) se leen del cuerpo como JSON. Si el nombre aparece entre {llaves} en la ruta, es path param; si no, query param. Las clases Path, Query y Body lo dejan explícito cuando haga falta.

¿Puedo obligar a que un query param venga aunque sea opcional en lo lógico?

Sí: quítale el valor por defecto. Por ejemplo, level: Literal["basico","intermedio","avanzado"] sin default es obligatorio y su ausencia produce un 422. Ojo con la regla de Python: los parámetros sin default deben ir antes de los que sí lo tienen, así que ordénalos en consecuencia.

¿Qué diferencia real hay entre Path/Query y usar solo el type hint?

El type hint valida el tipo; Path/Query añaden restricciones y metadatos (ge, min_length, pattern, description, examples). Además sirven para desambiguar el origen del parámetro. En Pydantic v2 la forma recomendada es envolverlos en Annotated.

¿Por qué str = None se considera mal estilo?

Porque el tipo dice que el valor es str (nunca nulo), pero el default es None: una contradicción. En Pydantic v2 lo correcto es str | None = None, que declara «cadena o nada» de forma coherente y hace que la validación y la documentación digan la verdad.

¿Los 422 los tengo que programar yo?

No. FastAPI los genera automáticamente cuando un parámetro no valida. El cuerpo del error incluye una lista detail con la loc (dónde), el type y el msg. Verás su forma exacta, y cómo personalizarla, en la lección Validación y tipos del Módulo 1 y en Errores y Problem Details del Módulo 2.
