Tu primer endpoint

Módulo 0 · Preparación 🕐 30 minutos

1 · Introducción

Un endpoint (o «path operation») es la unión de un método HTTP y una ruta con una función que produce la respuesta. En FastAPI se declara con un decorador: @app.get("/"). Es tan simple que parece magia, y precisamente por eso esta lección abre la caja: veremos qué es el objeto app, cómo registra las rutas, de dónde salen /docs y /openapi.json, y qué ocurre por debajo —a nivel ASGI— desde que llega una petición hasta que sale la respuesta.

Entender ese recorrido es lo que distingue a quien «escribe endpoints» de quien diseña una API: sabrás dónde insertar middleware, por qué el orden de las rutas importa o por qué una función async bloqueante hunde el servidor.

¿Por qué existe esta lección? Porque el mismo mecanismo que sirve un GET / sirve también POST /ask con autenticación y base de datos. Si dominas el ciclo de vida de una petición aquí, todos los módulos siguientes son el mismo patrón con más piezas.

2 · Teoría

El objeto app: la aplicación entera en una variable

app = FastAPI() no es un simple contenedor: es un objeto ASGI que representa toda tu aplicación. Guarda la lista de rutas, el esquema OpenAPI, los eventos de ciclo de vida (lifespan), las dependencias globales y un espacio de estado (app.state) para compartir recursos. Cuando uvicorn «llama» a la app, en realidad invoca un método especial de este objeto.

app/main.py
from fastapi import FastAPI

app = FastAPI(title="Copiloto API")


@app.get("/")
def read_root():
    return {"message": "Hello, FastAPI"}


# Inspección: una app de FastAPI se documenta a sí misma.
print(type(app))            # <class 'fastapi.applications.FastAPI'>
print(len(app.routes))      # nº de rutas registradas (incluye /docs, /openapi.json, …)
for route in app.routes:
    print(getattr(route, "path", None), getattr(route, "methods", None))

Si ejecutas esa inspección verás rutas que tú no escribiste: /openapi.json, /docs, /docs/oauth2-redirect y /redoc. Son parte de la app desde el primer instante.

El decorador @app.get("/") por dentro

Un decorador envuelve una función y devuelve otra cosa. Aquí, @app.get("/") hace tres cosas:

  1. Registra la ruta: añade a app.routes un APIRoute que asocia GET / con tu función.
  2. Analiza la firma: inspecciona las anotaciones de tipo para saber qué parámetros validar y qué forma tendrá la respuesta.
  3. Actualiza el esquema: enriquece el OpenAPI para que /docs y /openapi.json reflejen el endpoint.

Un decorador por método. Existen @app.get, @app.post, @app.put, @app.patch, @app.delete, @app.options y @app.head. Comparten la misma mecánica: método + ruta + función.

Qué pasa por debajo: el ciclo ASGI de una petición

ASGI define un contrato de tres cosas que el servidor entrega a tu aplicación y que esta usa para responder:

ElementoQué esSe usa para
scopeUn dict con los metadatos de la conexiónMétodo, ruta, cabeceras, cliente, tipo («http», «websocket»)
receiveFunción awaitable para leer eventos del clienteObtener el body de un POST
sendFunción awaitable para enviar eventos al clienteEnviar http.response.start y http.response.body

Un endpoint GET / recorre estas etapas dentro de FastAPI:

  uvicorn                                    FastAPI (la app ASGI)
    |                                              |
    |  await app(scope, receive, send)             |
    |--------------------------------------------->|
    |                                              |  1. middleware (CORS, etc.)
    |                                              |  2. router: busca "GET /"
    |                                              |  3. resuelve dependencias (Depends)
    |                                              |  4. valida entrada con Pydantic
    |                                              |  5. llama a tu funcion
    |                                              |  6. serializa el retorno a JSON
    |<---------------------------------------------|
    |  send({"type": "http.response.start", ...})   |  7. status + headers
    |  send({"type": "http.response.body", ...})    |  8. body
    |
    v  el cliente recibe 200 OK + JSON

Analogía: scope es la ficha que acompaña a cada cliente en un mostrador (qué quiere, cómo se identifica). receive es el hueco por el que el cliente pasa documentos; send es la bandeja por la que le devuelves el resultado. Tu función es el empleado que decide qué hacer; no abre ni cierra el comercio, solo atiende su turno.

Por qué importa saber esto: porque todo lo que añadiremos después vive en esas etapas. Middleware actúa en (1); las rutas y APIRouter en (2); Depends en (3); los modelos Pydantic en (4) y (6); y el manejo de errores se intercala entre todas. El diagrama es el mapa del curso.

/docs, /redoc y /openapi.json

FastAPI construye el esquema OpenAPI a partir de las rutas registradas. Sobre ese JSON monta dos interfaces y expone el documento en crudo:

URLQué esPara qué sirve
/docsSwagger UIProbar endpoints («Try it out») sin escribir cliente
/redocReDocLectura limpia, ideal para compartir con otros equipos
/openapi.jsonEl contrato OpenAPIGenerar SDKs, validar en CI, alimentar tests

Puedes personalizarlos o desactivarlos al crear la app:

app/main.py
app = FastAPI(
    title="Copiloto API",
    version="0.1.0",
    docs_url="/docs",          # o None para no publicar Swagger UI
    redoc_url="/redoc",        # o None para no publicar ReDoc
    openapi_url="/openapi.json",  # ponlo None en entornos muy restringidos
)

El contrato primero. En una API profesional, /openapi.json se trata como un artefacto versionado. Antes de cambiar una respuesta, mira el contrato: si rompes su forma, rompes a sus consumidores.

Dos formas de arrancar: uvicorn por fuera o uvicorn.run por dentro

Preferimos la primera (separa código de ejecución), pero conviene conocer la segunda porque es la que usan los depuradores de VS Code o PyCharm:

app/main.py
import uvicorn
from fastapi import FastAPI

app = FastAPI()


@app.get("/")
def read_root():
    return {"message": "Hello, FastAPI"}


if __name__ == "__main__":          # solo si ejecutas "python app/main.py"
    uvicorn.run("app.main:app", host="127.0.0.1", port=8000, reload=True)

La forma recomendada sigue siendo uv run uvicorn app.main:app --reload desde fuera: el módulo no contiene la decisión de cómo servirse, y eso lo hace reutilizable en tests y en producción.

3 · Ejemplo mínimo

Un endpoint y su respuesta, explicados línea por línea:

main.py
from fastapi import FastAPI

app = FastAPI()                 # 1. la aplicación ASGI


@app.get("/")                   # 2. registra GET / y devuelve la función decorada
def read_root():                # 3. se ejecuta en cada petición a GET /
    return {"message": "Hello, FastAPI"}   # 4. dict -> JSON + 200 OK

Al arrancar y pedir /:

terminal
uv run uvicorn main:app --reload
curl -i http://127.0.0.1:8000/

Respuesta observada (recortada):

salida HTTP
HTTP/1.1 200 OK
content-type: application/json
server: uvicorn

{"message":"Hello, FastAPI"}
  1. FastAPI(): crea la app y ya registra /docs, /redoc y /openapi.json.
  2. @app.get("/"): decora la función y la registra como manejadora de GET /. read_root queda disponible como función normal y como endpoint.
  3. return {"message": ...}: FastAPI no exige que devuelvas JSONResponse; un dict (o lista, o modelo Pydantic) se serializa solo y el status por defecto es 200.

4 · Ejemplo real

En Copiloto API, la raíz no devuelve un «hello world» decorativo: actúa como puerta de entrada autodescriptiva. Un cliente que llega sin saber nada del servicio descubre ahí qué es, dónde está la documentación y qué versión corre.

app/main.py
from fastapi import FastAPI

app = FastAPI(title="Copiloto API", version="0.1.0")


@app.get("/", tags=["system"])
def read_root():
    # Un "índice" del API: enlaces útiles y versión. Barato de generar.
    return {
        "service": "copiloto-api",
        "version": app.version,
        "docs": "/docs",
        "openapi": "/openapi.json",
        "endpoints": ["/health", "/modules", "/ask"],
    }

Decisiones y porqués:

  • La raíz como índice: cualquiera que abra la URL base obtiene un mapa del servicio. Es un patrón habitual en APIs públicas y cuesta cero.
  • app.version: reutilizamos el metadato en lugar de duplicar una cadena que podría desincronizarse.
  • tags=["system"]: en /docs, los endpoints de sistema quedan agrupados y separados de los de negocio.
  • Sin dependencias externas: un índice no debe depender de la base de datos ni del motor RAG; si esos fallan, al menos la puerta sigue respondiendo.

Fíjate en la coherencia con la lección 1: el mismo esqueleto (app + metadatos + tags) con un endpoint distinto. Copiloto API crece añadiendo rutas a este objeto, no reescribiéndolo.

6 · Errores habituales

1. Confundir la barra final: /items frente a /items/

Mal — redirección inesperada 
@app.get("/items/")          # ruta CON barra final
def list_items():
    return []
# GET /items responde 307 (redirección) a /items/ automáticamente:
# un cliente que no siga redirecciones verá una sorpresa.
Bien — elige una convención y respétala 
@app.get("/items")           # colección sin barra final (convención REST habitual)
def list_items():
    return []

2. Devolver algo que no se puede serializar

Mal — objeto no serializable 
import random

@app.get("/draw")
def draw():
    return {random.random()}   # un SET no es JSON: error 500 al serializar
Bien — estructuras serializables 
import random

@app.get("/draw")
def draw():
    return {"value": random.random()}   # dict con tipos JSON (números, str, bool, list)

3. Creer que @app.get acepta cualquier método

Mal — método incorrecto 
@app.get("/ask")
def ask():                 # usar GET para crear/consultar algo pesado
    return {"answer": "..."}
# Un cliente que haga POST /ask recibirá 405 Method Not Allowed.
Bien — el método comunica la intención 
@app.post("/ask")          # POST para enviar una consulta con cuerpo
def ask():
    return {"answer": "..."}

4. Bloquear el loop en un endpoint async

Mal — trabajo bloqueante en async def 
import time

@app.get("/slow")
async def slow():
    time.sleep(5)          # congela el loop: NINGUNA otra petición avanza
    return {"ok": True}
Bien — sync con def, o await real 
import asyncio

@app.get("/slow")
async def slow():
    await asyncio.sleep(5)   # cede el control: el loop atiende otras peticiones
    return {"ok": True}
# Si el trabajo es bloqueante (I/O de CPU o librería sync), usa "def": FastAPI
# la ejecuta en un hilo del pool sin congelar el loop.

5. Suponer que /docs documenta lo que no declaraste

Mal — sin tipos, docs pobres y sin validación 
@app.get("/items/{item_id}")
def read_item(item_id):        # sin tipo: /docs lo muestra como string genérico
    return {"item_id": item_id}
Bien — tipa y el contrato se describe solo 
@app.get("/items/{item_id}")
def read_item(item_id: int):
    return {"item_id": item_id}
# /openapi.json marca item_id como "integer"; /docs valida en el cliente.

7 · Ejercicio guiado

Objetivo: ver el ciclo ASGI completo y comprobar que /docs y /openapi.json se derivan de tus rutas.

  1. Paso 1: crea main.py con dos endpoints: 
    from fastapi import FastAPI

app = FastAPI(title="Explorando el ciclo ASGI", version="0.1.0")


@app.get("/", tags=["system"])
def read_root():
    return {"service": "explorando", "version": app.version}


@app.get("/items/{item_id}", tags=["items"])
def read_item(item_id: int):
    return {"item_id": item_id}
  2. Paso 2: arranca y observa el log de uvicorn al recibir cada petición: 
    uv run uvicorn main:app --reload
# En otra terminal:
curl -i http://127.0.0.1:8000/

    Resultado esperado en la terminal del servidor: una línea INFO: 127.0.0.1:xxxx - "GET / HTTP/1.1" 200 OK. Ese log lo genera uvicorn al recibir el evento ASGI de respuesta, no tu función.

  3. Paso 3 (el contrato): descarga el esquema y localiza tu endpoint: 
    curl -s http://127.0.0.1:8000/openapi.json

    Resultado esperado: un JSON con openapi, info.title («Explorando el ciclo ASGI») y paths. Incluye / y /items/{item_id}. Fíjate en que item_id aparece con "type": "integer": lo dedujo del tipo.

  4. Paso 4 (las interfaces): abre /docs y /redoc. Ambas se pintan usando el mismo /openapi.json. En /docs, usa «Try it out» sobre /items/{item_id} con abc (verás 422) y con 7 (verás 200).
  5. Paso 5 (ciclo de vida): añade logs a tu función y compáralos con los de uvicorn: 
    import logging

logger = logging.getLogger("uvicorn.error")


@app.get("/")
def read_root():
    logger.info("entrando en read_root")   # esto va ANTES de serializar la respuesta
    return {"ok": True}

    Resultado esperado: tu mensaje aparece antes de la línea 200 OK de uvicorn. Acabas de ver el orden: ruta → tu función → serialización → send de la respuesta.

  6. Paso 6 (verificación): detén el servidor. Abre /docs de nuevo: no carga. Los endpoints existen solo mientras el proceso está vivo; el contrato, en cambio, puedes guardarlo (curl ... > openapi.json) porque es un archivo estático.

8 · Reto

🎯 Un mini balanceador de rutas

Declara GET /items/{item_id} y, además, GET /items/latest. Comprueba qué devuelve /items/latest tal cual y luego invierte el orden de las dos declaraciones. Explica por qué cambia el resultado y qué regla de oro se deduce sobre el orden de las rutas. Después, pásale una petición POST /items/latest y documenta qué status devuelve y por qué (mira /openapi.json para confirmar qué método declaraste).

Pista: el router de Starlette evalúa las rutas en el orden en que se registraron y se queda con la primera que casa. Una ruta dinámica como {item_id} «captura» también la palabra latest si está antes. El método, en cambio, lo valida el propio router: si la ruta existe pero el método no, responde 405.

9 · Resumen

  • app es el objeto ASGI que contiene rutas, esquema OpenAPI, lifespan y estado compartido.
  • @app.get("/") registra una ruta, analiza la firma y actualiza el contrato; hay un decorador por método HTTP.
  • Por debajo, ASGI entrega scope, receive, send: metadatos, entrada y salida de cada petición.
  • El recorrido de una petición es middleware → router → dependencias → validación → tu función → serialización.
  • /docs (Swagger UI), /redoc (ReDoc) y /openapi.json (contrato) se derivan de tus rutas y tipos.
  • Se arranca desde fuera (uvicorn módulo:app); el código no decide cómo se sirve.

10 · Preguntas frecuentes

¿Por qué /docs no aparece en producción y cómo lo activo?

Por defecto /docs siempre existe si no lo desactivas. Muchos equipos lo apagan en producción con docs_url=None para no exponer la superficie del API en abierto. Si lo necesitas, puedes dejarlo pero protegerlo con autenticación, o servirlo en un entorno interno. En este curso lo mantenemos activo: es una herramienta de desarrollo valiosa.

¿Puedo tener dos endpoints en la misma ruta y método?

No de forma útil: el router se queda con la primera coincidencia registrada y la segunda nunca se alcanza. FastAPI no lanza un error por duplicado, así que es un error silencioso fácil de cometer. Revisa app.routes o el propio /openapi.json si sospechas duplicados.

¿Qué diferencia hay entre @app.get y APIRouter.get?

Ninguna en su mecánica: ambos registran rutas. El APIRouter agrupa rutas relacionadas en un módulo aparte que luego «montas» en la app con app.include_router(...). Es la forma de partir una API grande en archivos. Lo veremos en la lección 4 y con más detalle en el módulo 3.

¿Por qué mi endpoint devuelve 500 y no 422?

El 422 (Unprocessable Entity) lo genera FastAPI cuando la entrada no valida respecto a los tipos. Un 500 es un fallo tuyo en ejecución: a menudo algo no serializable en la salida o una excepción no controlada dentro de la función. Mira el traceback del servidor: FastAPI te lo da entero en desarrollo.

¿De verdad necesito entender ASGI para escribir endpoints?

Para escribir el primero, no. Para tomar buenas decisiones (cuándo usar async, dónde va un middleware, por qué un yield en una dependencia cierra recursos al terminar la petición) sí: todas esas preguntas tienen la misma respuesta, «cómo funciona el ciclo ASGI». Por eso está aquí, antes que cualquier lógica de negocio.
