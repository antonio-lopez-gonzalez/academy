Cheatsheet: plantillas SDD

Referencia rápida 📋 Copia y adapta

Plantilla de spec

# <Funcionalidad / Producto>

## Objetivo
<1-2 frases: qué y por qué, con verbos observables>

## No-objetivos
- <explícitamente fuera de alcance>

## Glosario
- <término>: <significado acordado>

## Restricciones
- <stack / compatibilidad / presupuesto / legal>

## Supuestos
- <lo que damos por hecho, dicho para poder impugnarlo>

## Criterios de aceptación
- [ ] Dado <contexto>, cuando <acción>, entonces <resultado observable>

## Fuera de alcance del plan
- <lo que el plan no debe tocar>

Criterios de aceptación (patrón)

# Mal: no se puede demostrar
- El CLI es usable.
- La búsqueda es rápida.

# Bien: contexto + acción + resultado observable
- [ ] Dado el almacén vacío, cuando ejecuto `add "pan"`,
      entonces `list` muestra una nota con id único y título "pan".
- [ ] Dado una nota abierta, cuando ejecuto `close <id>`,
      entonces `list` ya no la muestra.

Plantilla de ADR (8-15 líneas)

# ADR 0001: <decisión>

- Fecha: <aaaa-mm-dd>
- Contexto: <qué nos obliga a decidir>
- Decisión: <qué elegimos>
- Consecuencias: <qué ganamos / qué perdemos / qué queda irreversible>

Plantilla de skill (SKILL.md)

---
name: <nombre-corto>
description: <cuándo usarla, en una frase>
---

# <Título>

<Cómo hacer esta clase de trabajo, paso a paso.
La spec de producto dice QUÉ; la skill dice CÓMO.>

## No hacer
- <límites explícitos>

El ciclo SDD (memoria)

# 1. SPECIFY — escribe la intención (humano dueño)
# 2. PLAN     — camino ordenado con riesgos (agente propone, humano revisa)
# 3. IMPLEMENT— código según spec + plan
# 4. VERIFY   — cada criterio de aceptación, demostrado

# Reglas de oro:
# - Sin plan no hay código.
# - Si la spec estaba mal, se arregla LA SPEC primero (en Git).
# - Definition of done = la spec, no "compila".

Lumen (contrato estable del curso)

# Nota: { id, title, done, createdAt } (+tags solo con el delta)
node src/cli.js add "comprar pan"   # crea una nota con id único
node src/cli.js list                # lista las notas abiertas
node src/cli.js close <id>         # cierra una nota
node src/cli.js --help              # ayuda
