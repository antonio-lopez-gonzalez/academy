Cómo se ejecuta Python: script, -c, -m y REPL

Módulo 0 · Preparación ⏱ 30 minutos

1 · Introducción

Ya tienes Python instalado y un editor. Ahora toca responder una pregunta que parece trivial pero no lo es: ¿cómo se ejecuta un programa Python? Hay cuatro formas de arrancar código y cada una tiene su propósito: un archivo para programas, la opción -c para una línea rápida, la opción -m para ejecutar un módulo como programa, y el REPL para experimentar. Confundirlas es la causa de errores como «no encuentra el archivo» o «el módulo no se ejecuta».

Además veremos qué es realmente un .py, cómo afecta la codificación del archivo, dónde aparecen los .pyc y por qué el famoso if __name__ == "__main__" existe. Es la lección que convierte «ejecuto Python» en «entiendo cómo arranca Python».

¿Por qué existe esta lección? Porque todo el curso —incluido empaquetar la CLI bib en el módulo 9— depende de entender el arranque. Cuando debuguees un ImportError o quieras que tu paquete se ejecute con python -m biblioteca, la respuesta estará aquí.

2 · Teoría

Las cuatro formas de ejecutar Python

  FORMA                 COMANDO                         CUÁNDO
  ─────────────────────────────────────────────────────────────────────
  1. Script             python3 script.py               programas y proyectos
  2. Cadena (-c)        python3 -c "print('hi')"        pruebas de una línea
  3. Módulo (-m)        python3 -m modulo               herramientas y paquetes
  4. REPL               python3                         explorar y experimentar

Todas arrancan el mismo intérprete; cambian qué le pasas para que ejecute.

1. Script: python3 script.py

Es la forma principal. Python abre el archivo, lo compila a bytecode y ejecuta sus instrucciones. El script se ejecuta como módulo __main__: por eso el nombre especial __name__ vale "__main__" cuando arrancas un archivo directamente, y vale el nombre del módulo cuando se importa desde otro sitio.

# main_check.py — demuestra el valor de __name__ según cómo se ejecute.
print(f"__name__ vale: {__name__}")

# Este bloque SOLO corre si el archivo se ejecuta directamente:
#   python3 main_check.py   -> entra (__name__ == "__main__")
#   import main_check       -> NO entra (__name__ == "main_check")
if __name__ == "__main__":
    print("Ejecutando como programa principal")

Salida al ejecutarlo con python3 main_check.py:

__name__ vale: __main__
Ejecutando como programa principal

Este patrón es el que permitirá que un módulo sea a la vez importable y ejecutable, algo que usarás en la CLI de Biblioteca.

Argumentos y código de salida

Un script recibe sus argumentos en sys.argv (0 es el nombre del script; el resto, los argumentos) y termina con un código de salida (0 = éxito) vía sys.exit(). Es exactamente lo que usará la CLI bib.

# args_demo.py — si no hay argumentos, sale con código 1 y muestra el error.
import sys
if not sys.argv[1:]:
    sys.exit("Falta un argumento")   # imprime el mensaje y sale con código 1
print("Argumentos:", sys.argv[1:])

2. Cadena: python3 -c "..."

Ejecuta el código que pasas como texto, sin archivo. Perfecto para comprobaciones de una línea. Solo tiene sentido con fragmentos cortos.

# Comprobar una versión, hacer un cálculo, inspeccionar un módulo:
python3 -c "import sys; print(sys.version_info[:3])"
python3 -c "print(sum(range(1, 101)))"     # suma 1..100

(3, 12, 4)
5050

El -c es para una línea: dentro de -c "..." usa comillas simples para las cadenas de Python.

3. Módulo: python3 -m modulo

Esta es la más interesante. -m le dice a Python: localiza el módulo modulo dentro de sys.path, impórtalo y ejecútalo como __main__. La diferencia con python3 archivo.py es cómo se resuelve el módulo: -m usa el sistema de imports (rutas, paquetes, entornos), no una ruta de archivo literal.

Muchas herramientas de la biblioteca estándar se usan así:

# Servidor web estático en el puerto 8000 (útil para ver esta web del curso)
python3 -m http.server 8000

# Formatear/validar JSON desde la entrada estándar
python3 -m json.tool data/library.json

Y lo más importante para nosotros: un paquete con un archivo __main__.py se puede ejecutar con python3 -m paquete. Eso es exactamente lo que haremos con Biblioteca:

  biblioteca/
  ├── __init__.py
  ├── __main__.py    <- Python lo ejecuta al hacer: python3 -m biblioteca
  ├── models.py
  └── cli.py

  $ python3 -m biblioteca add "1984" --kind book

4. REPL: python3 sin argumentos

Ya lo conoces de la lección anterior. Aquí lo situamos en la comparativa: el REPL no compila a .pyc ni guarda nada, y evalúa expresión a expresión. Es el modo más cómodo para explorar y el menos adecuado para programas.

Bytecode en acción: __pycache__ y .pyc

Cuando importas un módulo (no cuando ejecutas el script principal), CPython lo compila y guarda el bytecode. Por eso aparece __pycache__:

  $ python3 -m biblioteca          # biblioteca/models.py se importa
  biblioteca/
  ├── models.py
  └── __pycache__/
      └── models.cpython-312.pyc   <- cache reutilizable

El nombre incluye cpython-312 porque el bytecode no es portable entre versiones: cambia el formato entre 3.11 y 3.12. Es caché descartable: puede borrarse sin miedo.

Codificación (encoding) de los archivos

Python 3 asume que el código fuente está en UTF-8 (PEP 3120). Guardar acentos en UTF-8 funciona sin declarar nada. Históricamente existía una «cookie» de codificación en la primera línea (PEP 263):

# -*- coding: utf-8 -*-   # declaración histórica; en Python 3 ya es la opción por defecto
name = "Muñoz"
print(name)

Regla práctica: todo en UTF-8, siempre. En Windows, evita guardar con CP1252; VSCode usa UTF-8 por defecto y en la barra de estado puedes verificarlo.

Tres extensiones que verás

.py es el código fuente; .pyi son stubs solo con firmas de tipos (los leen Pylance y mypy, no se ejecutan); .pyc es bytecode cacheado y autogenerado.

3 · Ejemplo mínimo

El mismo resultado por tres caminos: script, -c y REPL. Compararlos es la mejor forma de entender para qué sirve cada uno.

# Camino A — un archivo que se ejecuta (ideal para programas)
echo "print('Hola desde un script')" > hello.py
python3 hello.py

# Camino B — una cadena de una línea (ideal para una comprobación)
python3 -c "print('Hola desde -c')"

# Camino C — el REPL (ideal para explorar; escribe y sal con exit())
python3

Hola desde un script
Hola desde -c

Qué cambia entre ellos:

  1. Script: el código vive en disco, se reutiliza y se versiona. Aquí está __name__ == "__main__".
  2. -c: no hay archivo; el texto es el programa. El __name__ también es __main__.
  3. REPL: escribe, evalúa, imprime, repite. No hay .pyc ni código de salida relevante.

4 · Ejemplo real

El primer paso hacia la CLI de Biblioteca: un módulo catalog_v0.py que se puede importar desde otro código y, a la vez, ejecutar con -m. Fíjate en el patrón completo: datos, funciones con docstring y bloque __main__.

# catalog_v0.py — versión mínima del catálogo, lista para crecer.
# Se puede ejecutar con:  python3 -m catalog_v0
from dataclasses import dataclass   # stdlib: sin instalar nada


@dataclass
class Item:
    """Un ítem del catálogo: libro o película."""
    id: str
    title: str
    kind: str          # "book" | "movie"
    year: int | None   # None si no se conoce


# El catálogo, por ahora, es una lista de Items en memoria.
CATALOG: list[Item] = [
    Item("b-001", "1984", "book", 1949),
    Item("m-001", "Blade Runner", "movie", 1982),
]


def list_items(items: list[Item]) -> None:
    """Imprime el catálogo, una línea por ítem."""
    for item in items:                      # iteramos directo, sin range(len(...))
        year = item.year if item.year is not None else "?"
        print(f"[{item.kind[:4]}] {item.title} ({year})")


# Este bloque solo se ejecuta con:  python3 -m catalog_v0
# Si otro módulo hace 'import catalog_v0', NO se imprime nada (reutilizable).
if __name__ == "__main__":
    print(f"Catálogo con {len(CATALOG)} ítems:")
    list_items(CATALOG)

Ejecútalo así (usa python o py en Windows):

python3 -m catalog_v0

Salida esperada:

Catálogo con 2 ítems:
[book] 1984 (1949)
[movi] Blade Runner (1982)

Decisiones y porqués:

  • dataclass de la stdlib: genera constructor y __repr__ sin escribir boilerplate. En el módulo 5 lo estudiaremos a fondo.
  • python3 -m catalog_v0 funciona porque el módulo está en la carpeta actual, que Python incluye en sys.path al arrancar.
  • El bloque __main__ permite import catalog_v0 sin efectos secundarios: la separación entre «biblioteca» y «programa».
  • item.kind[:4] recorta a 4 caracteres para alinear (book / movi). Pequeño y explícito.

Ejecuta python3 -m catalog_v0 y luego mira la carpeta: aparecerá __pycache__/catalog_v0.cpython-312.pyc. Acabas de ver el bytecode cacheado en vivo.

6 · Errores habituales

Ejecutar un directorio en lugar de un archivo

# ❌ "Can't open file 'biblioteca': [Errno 2] No such file or directory"
# python3 biblioteca          # es una CARPETA, no un archivo

# ✅ Con script, apunta al archivo:
python3 biblioteca/cli.py

# ✅ Con paquete, usa -m y el nombre del paquete (teniendo __main__.py):
python3 -m biblioteca

Olvidar que __pycache__ no se ejecuta ni se edita

# ❌ Editar un .pyc a mano o intentar "arreglar" un módulo desde ahí
#    El .pyc se regenera y tu cambio se pierde.

# ✅ Edita siempre el .py; si el bytecode está corrupto, borra la caché:
python3 -c "import shutil, pathlib; [shutil.rmtree(p) for p in pathlib.Path('.').rglob('__pycache__')]"

Codificación: acentos «rotos»

# ❌ Guardar el archivo en CP1252 (Windows) y compartirlo:
#    SyntaxError o UnicodeDecodeError al leerlo en Linux.
# ✅ Configura VSCode en UTF-8 (esquinas inferiores: "UTF-8") y listo.

7 · Ejercicio guiado

Objetivo: ver las cuatro formas de ejecución sobre el mismo mini-programa y comprobar el bytecode.

  1. Paso 1: crea la carpeta de trabajo y este archivo runner.py: 
    # runner.py — tema del día: ¿cómo me están ejecutando?
import sys

def describe() -> str:
    """Devuelve en qué modo se ejecutó este archivo."""
    return f"__name__={__name__!r}, args={sys.argv[1:]}"

if __name__ == "__main__":
    print(describe())
  2. Paso 2 — como script: 
    python3 runner.py uno dos

    Salida esperada: __name__='__main__', args=['uno', 'dos']

  3. Paso 3 — como módulo: 
    python3 -m runner tres

    Salida esperada: __name__='__main__', args=['tres']. Es el mismo resultado que como script, pero resuelto por el sistema de imports.

  4. Paso 4 — como cadena: 
    python3 -c "import runner; print(runner.describe())"

    Salida esperada: __name__='runner', args=[]. Aquí no se entra en el bloque __main__ (porque el módulo se importa, no se ejecuta) y por eso __name__ es 'runner'. Este es el corazón del patrón.

  5. Paso 5 (verificación): lista la caché generada: 
    ls __pycache__            # Linux / macOS
dir __pycache__           # Windows (PowerShell)

    Esperado: un archivo runner.cpython-312.pyc. Si borras la carpeta y vuelves a importar, se regenera: confirma que es caché.

8 · Reto

🎯 Convierte el módulo en paquete ejecutable

Crea una carpeta saludo/ con __init__.py y __main__.py. El paquete debe poder ejecutarse con python3 -m saludo Ada e imprimir Hola, Ada; si no recibe nombre, debe imprimir Hola, mundo y salir con código 1. Comprueba el código de salida con echo $? (Linux/macOS) o $LASTEXITCODE (PowerShell).

Pista: en __main__.py lee sys.argv; en __init__.py define la función greet(name) y expórtala. Verifica que python3 -m saludo funciona aunque no sea un archivo: es la prueba de que -m usa el sistema de imports. En el módulo 9 harás exactamente esto con biblioteca.

9 · Resumen

  • Hay cuatro modos: script (archivo.py), cadena (-c), módulo (-m) y REPL.
  • python3 -m modulo importa y ejecuta un módulo por su nombre; con __main__.py, un paquete entero se vuelve ejecutable.
  • El script y -c corren como __main__; al importar, __name__ es el nombre del módulo. Ese es el sentido del if __name__ == "__main__".
  • El bytecode se cachea en __pycache__/*.pyc al importar módulos, no al ejecutar el script principal.
  • El código fuente va siempre en UTF-8; la «cookie» de codificación es historia de Python 2.
  • Ext.: .py fuente, .pyi stubs de tipos, .pyc bytecode cacheado.

10 · Preguntas frecuentes

¿Cuándo uso python3 archivo.py y cuándo python3 -m modulo?

Usa la ruta del archivo para ejecutar tus scripts desde donde estén. Usa -m cuando quieras ejecutar un módulo o paquete instalado o una herramienta de la stdlib (como http.server o pytest), porque -m respeta el sistema de imports y funciona aunque el directorio actual cambie. Como regla: si el código forma parte de un paquete con __main__.py, usa -m.

¿Por qué mi acento se ve como un carácter raro?

Casi siempre por la codificación del archivo o de la salida. Guarda siempre en UTF-8 y comprueba la codificación en la barra de VSCode. En consolas de Windows muy antiguas puede ser la página de códigos de la terminal; en Windows Terminal moderno ya no ocurre.

¿Qué significa que un módulo sea «ejecutable e importable a la vez»?

Que puedes usarlo como programa (python3 -m paquete) y también como librería (import paquete) sin que el import dispare la ejecución. El truco es el bloque if __name__ == "__main__":. Esta dualidad es exactamente lo que haremos con la CLI bib: núcleo reutilizable + entrada de programa.
