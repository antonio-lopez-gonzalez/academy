Diccionarios y conjuntos

Módulo 1 · Fundamentos del lenguaje ⏱ 35 minutos

1 · Introducción

Hasta ahora has guardado colecciones por posición (listas y tuplas). Pero muchas veces lo natural es acceder por nombre: dado un identificador, obtener el ítem; dado un título, saber si está en la biblioteca. Para eso están los diccionarios (dict), la estructura más importante de Python después de las listas, y los conjuntos (set), que responden a la pregunta «¿pertenece?» en tiempo constante y evitan duplicados.

El concepto que une a ambos es la hashabilidad: solo los objetos que no cambian de valor pueden ser claves de un diccionario o elementos de un conjunto. Entenderlo resuelve de golpe por qué no puedes usar una lista como clave.

¿Por qué existe esta lección? Porque un dict bien usado convierte código lleno de if y for en una consulta directa, y porque el catálogo de Biblioteca —y prácticamente todo JSON— se modela con diccionarios. Saber cuándo usar dict, set, list o tuple es una de las decisiones más rentables que tomarás.

2 · Teoría

El diccionario: pares clave → valor

Un dict asocia claves únicas con valores. Se escribe con llaves {clave: valor}. Desde Python 3.7 el orden de inserción se conserva, lo cual no es un detalle menor: puedes recorrer un diccionario y obtener los elementos en el orden en que los añadiste.

item = {
    "id": "bk-01",       # clave str -> valor str
    "title": "1984",
    "kind": "book",
    "year": 1949,
    "borrowed": False,   # valor bool
}
# Acceso por clave con corchetes:
print(item["title"])     # 1984
# Las claves son únicas: reasignar sobrescribe, no duplica.
item["year"] = 1950
print(item["year"])      # 1950

Por debajo, un diccionario es una tabla hash: calcula un número (hash) a partir de la clave y lo usa para localizar el valor casi sin buscar. Por eso el acceso es rapidísimo (O(1) de media), sin importar cuántos elementos haya. Y por eso la clave debe ser hashable.

Hashabilidad: qué puede ser clave

Un objeto es hashable si su valor no cambia durante su vida útil. Los inmutables lo son; los mutables, no.

Objeto¿Hashable?¿Puede ser clave / elemento de set?
int, float, boolSíSí
strSíSí
tuple (sin mutables dentro)SíSí
listNoNo → TypeError
dict, setNoNo → TypeError

¿Por qué? El diccionario guarda el valor en la posición que indica el hash de la clave. Si la clave cambiara, su hash cambiaría y el diccionario ya no la encontraría. Permitir claves mutables rompería la estructura. Es una restricción de diseño, no un capricho.

Leer sin romperse: get y setdefault

Acceder a una clave inexistente con [] lanza KeyError. Cuando la ausencia es normal (un valor opcional, un contador que empieza en cero), usa get:

item = {"id": "bk-01", "title": "1984"}
# print(item["author"])        # ❌ KeyError: 'author'
# ✅ get devuelve None (o el valor por defecto) si la clave no existe
print(item.get("author"))              # None
print(item.get("author", "—"))         # —
print(item.get("title", "—"))          # 1984
# setdefault: devuelve el valor si existe; si no, lo crea con el default.
item.setdefault("borrowed", False)     # no existía -> lo crea
item.setdefault("title", "XXX")        # ya existía -> NO lo cambia
print(item)   # {'id': 'bk-01', 'title': '1984', 'borrowed': False}

setdefault es ideal para agrupar: por ejemplo, agrupar títulos por tipo sin comprobar antes si la lista existe.

by_kind = {}
for kind, title in [("book", "1984"), ("movie", "Dune"), ("book", "Solaris")]:
    # Si 'kind' no está, crea la clave con una lista vacía y la devuelve; luego append.
    by_kind.setdefault(kind, []).append(title)
print(by_kind)
# {'book': ['1984', 'Solaris'], 'movie': ['Dune']}

Recorrer: keys, values, items

item = {"id": "bk-01", "title": "1984", "year": 1949}
print(list(item.keys()))     # ['id', 'title', 'year']
print(list(item.values()))   # ['bk-01', '1984', 1949]
# items() da pares (clave, valor): el patrón rey para recorrer un dict.
for key, value in item.items():
    print(f"{key} = {value}")
# id = bk-01
# title = 1984
# year = 1949

Iterar un dict da claves. for k in item: recorre las claves, igual que item.keys(). No es un error, pero para valores o pares hay que ser explícito con .values() o .items().

Pertenencia, borrado y combinación

item = {"id": "bk-01", "title": "1984"}
# 'in' comprueba CLAVES, no valores.
print("id" in item)          # True
print("1984" in item)        # False (1984 es un valor, no una clave)
del item["title"]            # elimina la clave (KeyError si no existe)
print(item)                  # {'id': 'bk-01'}
# pop devuelve el valor y elimina la clave, con default opcional.
year = item.pop("year", None)
print(year)                  # None
# update fusiona otro diccionario (sobrescribe claves repetidas).
item.update({"borrowed": False})
print(item)                  # {'id': 'bk-01', 'borrowed': False}
# | (Python 3.9+) combina SIN mutar: devuelve un dict nuevo.
defaults = {"borrowed": False, "year": None}
merged = defaults | {"title": "1984"}
print(merged)   # {'borrowed': False, 'year': None, 'title': '1984'}

El conjunto: sin duplicados, sin orden, con operaciones

Un set es una colección de elementos únicos y no ordenada. Se escribe con llaves {...} (pero sin :) o con set(). Su gran ventaja: comprobar pertenencia (in) es casi instantáneo, y trae las operaciones matemáticas de conjuntos.

owned = {"1984", "Dune", "Solaris", "Dune"}   # el duplicado se elimina
print(owned)                 # {'1984', 'Dune', 'Solaris'} (el orden no se garantiza)
print("Dune" in owned)       # True  -> pertenencia O(1)
owned.add("Neuromancer")
owned.discard("Solaris")     # elimina si existe, sin error si no
print(len(owned))            # 3
# El set vacío NO es {} (eso es un dict vacío); usa set().
empty = set()
print(type(empty))           # <class 'set'>
OperaciónSímboloResultado
Unióna | bElementos en a o en b
Interseccióna & bElementos en ambos
Diferenciaa - bEn a pero no en b
Diferencia simétricaa ^ bEn uno u otro, pero no en ambos
Subconjuntoa <= b¿Todos los de a están en b?
 
owned = {"1984", "Dune", "Solaris"}
wishlist = {"Dune", "Neuromancer"}
print(owned | wishlist)   # {'1984', 'Dune', 'Solaris', 'Neuromancer'} (unión)
print(owned & wishlist)   # {'Dune'}                    (intersección)
print(owned - wishlist)   # {'1984', 'Solaris'}          (solo en owned)
print(wishlist - owned)   # {'Neuromancer'}
print(owned ^ wishlist)   # {'1984', 'Solaris', 'Neuromancer'} (simétrica)
print({"Dune"} <= owned)  # True  -> {'Dune'} es subconjunto

3 · Ejemplo mínimo

Un ítem como diccionario y un conjunto de títulos disponibles.

item = {"id": "bk-01", "title": "1984", "borrowed": False}
print(item["title"])                 # 1984
print(item.get("author", "—"))       # —  (no lanza error)
available = {"1984", "Dune"}         # set
available.add("Solaris")             # sin duplicados
print("Dune" in available)           # True
print(len(available))                # 3

Línea por línea:

  1. item = {...}: diccionario con tres claves; el orden se conserva.
  2. item["title"]: acceso directo por clave, rapidísimo.
  3. item.get("author", "—"): clave ausente, devuelve el valor por defecto en vez de reventar.
  4. available = {"1984", "Dune"}: conjunto; los duplicados desaparecerían.
  5. "Dune" in available: pertenencia en tiempo constante.

4 · Ejemplo real

Indexamos el catálogo de Biblioteca por id. Un diccionario {id: item} permite buscar un ítem por su identificador sin recorrer toda la lista, y un conjunto nos dice al instante qué ids están prestados.

# Catálogo indexado por id: la clave es el identificador, el valor es el registro.
catalog = {
    "bk-01": {"title": "1984", "kind": "book", "year": 1949},
    "mv-01": {"title": "Blade Runner", "kind": "movie", "year": 1982},
    "bk-02": {"title": "Dune", "kind": "book", "year": 1965},
}
# Consulta directa por id (sin bucles).
print(catalog["bk-02"]["title"])          # Dune
# Ids prestados: un set para responder "¿está prestado?" en O(1).
borrowed_ids = {"mv-01"}
def is_borrowed(item_id: str) -> bool:
    return item_id in borrowed_ids
print(is_borrowed("mv-01"))               # True
print(is_borrowed("bk-01"))               # False
# Agrupar títulos por tipo con setdefault: sin comprobar existencia a mano.
by_kind = {}
for item in catalog.values():
    by_kind.setdefault(item["kind"], []).append(item["title"])
print(by_kind)
# {'book': ['1984', 'Dune'], 'movie': ['Blade Runner']}
# ¿Cuáles de los ids del catálogo siguen disponibles? Diferencia de conjuntos.
all_ids = set(catalog)                     # las claves del dict -> {'bk-01', 'mv-01', 'bk-02'}
available = all_ids - borrowed_ids
print(sorted(available))                   # ['bk-01', 'bk-02']

Decisiones: el dict indexado por id evita bucles de búsqueda (catalog[item_id] es una consulta, no un recorrido); el set de prestados responde al instante si un id lo está; y la resta de conjuntos obtiene los disponibles en una sola expresión, sin bucles. Este es el patrón que reaparecerá en la CLI bib y en la persistencia JSON (Módulo 6).

Patrón de índice: cuando tengas una lista de registros y vayas a buscar por id repetidamente, construye un diccionario {item["id"]: item} una sola vez. Pasas de buscar en O(n) a consultar en O(1).

6 · Errores habituales

Asumir que una clave existe

item = {"id": "bk-01", "title": "1984"}
# ❌ KeyError si la clave no está
# author = item["author"]
# ✅ Default explícito
author = item.get("author", "desconocido")
print(author)   # desconocido

Usar un objeto mutable como clave

# ❌ list/dict/set son unhashable
# cache = {["1984"]: 1}          # TypeError: unhashable type: 'list'
# seen = {{"a": 1}}              # TypeError
# ✅ Usa inmutables: str, int o tuple
cache = {("book", "1984"): 1}
print(cache[("book", "1984")])   # 1

Creer que in busca en los valores

item = {"id": "bk-01", "title": "1984"}
# ❌ 'in' sobre un dict comprueba CLAVES
print("1984" in item)          # False -> '1984' es un valor
print("title" in item)         # True  -> 'title' es una clave
# ✅ Para buscar en los valores, sé explícito
print("1984" in item.values()) # True

Contar con que un set conserva el orden

# ❌ Los sets no garantizan orden de iteración
titles = {"1984", "Dune", "Solaris"}
# print(titles[0])             # TypeError: 'set' object is not subscriptable
# ✅ Si necesitas orden, ordena o usa una lista/dict
print(sorted(titles))          # ['1984', 'Dune', 'Solaris']

7 · Ejercicio guiado

Objetivo: indexar, agrupar y comparar con dict y set. Paso a paso.

  1. Paso 1: parte de esta lista de ítems (cada uno un dict): 
    items = [
    {"id": "bk-01", "title": "1984", "kind": "book"},
    {"id": "mv-01", "title": "Blade Runner", "kind": "movie"},
    {"id": "bk-02", "title": "Dune", "kind": "book"},
]
  2. Paso 2: construye un índice by_id = {item["id"]: item for item in items} (comprensión de dict; la verás a fondo en el Módulo 3). Comprueba que by_id["mv-01"]["title"] es Blade Runner.
  3. Paso 3: agrupa los títulos por kind usando setdefault. Debe dar {'book': ['1984', 'Dune'], 'movie': ['Blade Runner']}.
  4. Paso 4: crea all_ids = set(by_id) y borrowed = {"mv-01", "bk-99"}. Calcula e imprime cuántos ids prestados existen en el catálogo (intersección).
  5. Paso 5 (verificación): comprueba los resultados esperados.

Solución de referencia:

by_id = {item["id"]: item for item in items}
print(by_id["mv-01"]["title"])          # Blade Runner
by_kind = {}
for item in items:
    by_kind.setdefault(item["kind"], []).append(item["title"])
print(by_kind)                          # {'book': ['1984', 'Dune'], 'movie': ['Blade Runner']}
all_ids = set(by_id)                    # {'bk-01', 'mv-01', 'bk-02'}
borrowed = {"mv-01", "bk-99"}           # bk-99 no existe en el catálogo
print(len(all_ids & borrowed))          # 1  -> solo mv-01

Resultado esperado:

Blade Runner
{'book': ['1984', 'Dune'], 'movie': ['Blade Runner']}
1

Cómo comprobarlo: la intersección all_ids & borrowed contiene solo {"mv-01"}; bk-99 se descarta porque no es una clave del catálogo. Esa es la potencia de los conjuntos: comparar dos colecciones sin escribir bucles.

9 · Resumen

  • Un dict asocia claves únicas con valores y conserva el orden de inserción (3.7+).
  • Solo lo hashable (inmutables) puede ser clave: str, int, tuple… nunca list/dict/set.
  • Usa get para claves que pueden faltar y setdefault para agrupar.
  • .items() da pares clave-valor; in sobre un dict comprueba claves.
  • Un set no tiene duplicados ni orden; la pertenencia es O(1) y ofrece unión, intersección y diferencia.
  • Elige la estructura por acceso: posición → list/tuple; nombre → dict; pertenencia/duplicados → set.

10 · Preguntas frecuentes

¿Por qué un diccionario es tan rápido para buscar?

Porque es una tabla hash: convierte la clave en un número y usa ese número para saltar casi directamente a la posición del valor. No recorre los elementos uno a uno. Ese acceso, de media, es constante (O(1)) sin importar cuántas claves haya.

¿Un set conserva el orden en que añadí los elementos?

No es una garantía del lenguaje. La implementación actual de CPython puede mostrar cierta estabilidad, pero no debes depender de ella. Si necesitas orden, usa una lista o un dict (que desde 3.7 sí garantiza el orden de inserción) y, para quitar duplicados conservando el orden, list(dict.fromkeys(...)).

¿Puedo usar una tupla como clave aunque contenga una lista?

No. Una tupla solo es hashable si todos sus elementos lo son. (["1984"],) es una tupla con una lista dentro y lanzará TypeError: unhashable type: 'list' al usarla como clave. Para usarla como clave, su contenido debe ser también inmutable.

¿dict o set para «saber si ya está»?

Depende: si necesitas asociar un valor (por ejemplo, el objeto ítem) a la clave, dict. Si solo te importa la pertenencia y no el valor, set gasta menos memoria y expresa mejor la intención. Ambos dan pertenencia en O(1).

¿Qué pasa si accedo con d["clave"] y la clave no existe?

Lanza KeyError. Si la ausencia es un caso normal, usa d.get("clave", default). Si quieres crear la entrada al consultarla, d.setdefault("clave", default). Y si quieres estructura con valor por defecto automático, collections.defaultdict (Módulo 3) es la herramienta.
