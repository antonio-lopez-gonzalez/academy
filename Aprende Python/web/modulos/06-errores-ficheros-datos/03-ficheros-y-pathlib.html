Ficheros y pathlib

Módulo 6 · Errores, ficheros y datos ⏱ 30 minutos

1 · Introducción

Hasta aquí el catálogo de Biblioteca vivía en memoria. Para persistirlo de verdad necesitamos dos cosas: escribir y leer ficheros y manejar rutas sin romperse en otro sistema operativo. La biblioteca estándar tiene dos herramientas para ello: la función integrada open() (texto/binario, modos, codificación) y el módulo pathlib, que trata las rutas como objetos de primera clase.

En esta lección aprenderás a abrir ficheros con with open(...), por qué siempre hay que decir encoding="utf-8", qué significa cada modo (r, w, a, x), y a usar Path para unir rutas con /, comprobar si existen, crear directorios, listar con glob y leer/escribir texto de una línea.

¿Por qué pathlib y no os.path? Porque con os.path las rutas son strings y las operaciones son funciones sueltas (os.path.join, os.path.exists, os.path.basename…). Con pathlib son objetos con métodos, el operador / une rutas de forma portable y el código se lee como se piensa. En Python moderno, pathlib es la opción por defecto.

2 · Teoría

Texto vs bytes, y el problema de la codificación

Un fichero en disco es, siempre, una secuencia de bytes. El texto es una interpretación de esos bytes según una codificación. UTF-8 es la codificación de facto de la web y de Python moderno: representa los acentos y los emojis usando entre 1 y 4 bytes. El problema es que cada sistema tiene una codificación por defecto distinta:

SistemaCodificación por defecto de open()Riesgo
LinuxUTF-8 (normalmente)Bajo, pero varía con el locale
macOSUTF-8Bajo
Windowscp1252 / cp850 (según idioma)Alto: un «ñ» o «á» guardado aquí se ve como Ã± al leerlo con UTF-8

⚠️ Regla de oro del curso: pasa SIEMPRE encoding="utf-8" al abrir texto. No confíes en el valor por defecto del sistema. Si lo omites, tu programa guardará acentos de forma distinta en la máquina de desarrollo (Linux/macOS) que en la del usuario (Windows). En Python 3.12 el defecto sigue dependiendo del locale; se está migrando a UTF-8 por defecto, pero hasta que llegue, sé explícito.

# ❌ Depende del sistema: en Windows puede ser cp1252
with open("data/library.json", "r") as f:
    text = f.read()

# ✅ Igual en Linux, macOS y Windows: UTF-8 explícito
with open("data/library.json", "r", encoding="utf-8") as f:
    text = f.read()

¿Y errores de codificación? Si un fichero tiene bytes que no son UTF-8 válido, read() lanza UnicodeDecodeError. El argumento errors= controla qué hacer: "strict" (por defecto, lanza), "replace" (sustituye con �) o "ignore" (los descarta). Para datos que tú controlas, quédate con "strict": enterarte del problema es mejor que corromper datos.

La función open() y sus modos

open(path, mode, encoding=…) devuelve un objeto fichero que puedes leer, escribir o ambos. El modo es una cadena; los importantes:

ModoQué haceAtención
"r"Leer (por defecto). Falla si no existe.El más seguro para leer
"w"Escribir. TRUNCA el fichero o lo crea.Peligroso: borra el contenido anterior
"a"Añadir al final (append). Crea si no existe.Ideal para logs
"x"Crear de forma exclusiva. Falla si ya existe.Evita sobrescrituras accidentales
"b"Modo binario (se combina: "rb", "wb"). Sin encoding.Para imágenes, PDFs, cualquier no-texto

El modo "w" es el gran incomprendido: no añade, reemplaza todo. Si abres un fichero existente con "w" y algo falla antes de escribir, lo dejaste vacío. Por eso, en la lección anterior vimos la escritura atómica: escribir en un temporal y renombrar. La forma segura de «crear sin pisar» es "x".

# Añadir una línea a un log sin perder lo anterior
with open("data/activity.log", "a", encoding="utf-8") as log:
    log.write("2026-01-15T10:00:00 — préstamo b1\n")   # \n explícito

Saltos de línea. Al escribir, incluye tú el \n: Python no lo añade. Al leer, el modo texto traduce automáticamente \r\n (Windows) y \r (macOS clásico) a \n; por eso el texto se ve igual en los tres sistemas. Si necesitas control total, existe newline="", pero rara vez lo querrás.

pathlib: rutas que son objetos

Un Path representa una ruta (absoluta o relativa) sin tocar el disco hasta que lo pides. El operador / une segmentos de forma portable: en Windows produce data\library.json y en Linux data/library.json, sin que tú escribas ningún separador.

from pathlib import Path

# Unir rutas con /: portable y sin backslashes ni escapes
path = Path("data") / "library.json"
print(path)                    # En Linux/macOS: data/library.json
                               # En Windows:     data\library.json

# Inspeccionar partes de la ruta
print(path.name)               # library.json   → último componente
print(path.stem)               # library         → sin extensión
print(path.suffix)             # .json           → extensión
print(path.parent)             # data            → directorio padre
print(path.is_absolute())      # False (relativa)

# Comprobar existencia y tipo (no lanza: devuelve True/False)
print(path.exists())           # False si aún no está en disco
print(path.is_file())          # True si existe y es fichero
print(path.is_dir())           # True si existe y es directorio

Las operaciones más útiles, agrupadas:

Método / atributoQué hace
p / "sub"Une rutas de forma portable
p.exists()¿Existe la ruta?
p.mkdir(parents=True, exist_ok=True)Crea el directorio (y los padres), sin fallar si ya está
p.read_text(encoding="utf-8")Lee todo el texto de un fichero (abre y cierra solo)
p.write_text(text, encoding="utf-8")Escribe texto (equivalente a "w", trunca)
p.read_bytes() / p.write_bytes(b)Igual para datos binarios
p.glob("*.json")Itera ficheros que casan el patrón, en ese directorio
p.rglob("*.json")Como glob pero recursivo (subdirectorios incluidos)
p.resolve()Ruta absoluta y canónica (resuelve .. y enlaces)

read_text/write_text vs with open: para leer o escribir todo el contenido de golpe, los métodos de Path son más cortos y cierran solos. Cuando procesas línea a línea (ficheros grandes, logs) o necesitas control fino, usa with open(...): iterar el objeto fichero no carga todo en memoria.

Rutas relativas: el enemigo silencioso

Una ruta relativa como Path("data/library.json") se resuelve contra el directorio de trabajo (Path.cwd()), que es desde donde lanzas el comando, no donde vive tu código. Lanza el mismo script desde ~/proyectos/biblioteca o desde /tmp y obtendrás ficheros distintos —o FileNotFoundError. La solución robusta es anclar la ruta al propio módulo con Path(__file__):

from pathlib import Path

# __file__ es la ruta del fichero .py actual; .parent es su carpeta
PACKAGE_DIR = Path(__file__).resolve().parent      # carpeta del paquete
PROJECT_DIR = PACKAGE_DIR.parents[1]               # sube dos niveles: raíz
DATA_PATH = PROJECT_DIR / "data" / "library.json"  # ruta independiente del cwd

Así el módulo encuentra sus datos vengas de donde vengas. Este detalle es la diferencia entre un script que «funciona en mi máquina» y uno que funciona en cualquier sitio.

3 · Ejemplo mínimo

Escribir un fichero y volver a leerlo, con pathlib y UTF-8 explícito:

from pathlib import Path

path = Path("demo.txt")

# Escribe todo el texto de una vez (crea o trunca el fichero)
path.write_text("Título: Dune\nAño: 1965\n", encoding="utf-8")

# Lee todo el texto de una vez
contenido = path.read_text(encoding="utf-8")
print(contenido)                 # imprime con un \n extra por el print

# Leer línea a línea sin cargar todo en memoria
with path.open(encoding="utf-8") as f:
    for num, line in enumerate(f, start=1):
        print(num, line.rstrip())    # rstrip quita el \n final

# Salida esperada:
# Título: Dune
# Año: 1965
#
# 1 Título: Dune
# 2 Año: 1965

Línea por línea: write_text abre en modo "w", escribe y cierra (equivale a un with open(..., "w", encoding="utf-8")). read_text abre en "r", lee todo y cierra. El bucle sobre f explota la iteración por líneas del objeto fichero: no carga el fichero entero, algo que importa con logs de cientos de MB. El por qué de rstrip(): cada línea incluye su \n, y si no lo quitas, el print añade otro salto y verás una línea en blanco entre medias.

4 · Ejemplo real

En Biblioteca, las rutas viven en store.py y este se asegura de que el directorio de datos exista antes de escribir. Así el resto del código nunca escribe nombres de fichero «a mano».

# src/biblioteca/store.py (extracto centrado en rutas)
from pathlib import Path

# Ruta por defecto, relativa al directorio de trabajo.
DEFAULT_STORE = Path("data/library.json")

def load(path: str | Path = DEFAULT_STORE) -> list:
    """Lee el almacén y devuelve la lista de ítems (vacía si no existe)."""
    file = Path(path)
    if not file.exists():                      # comprobación barata y estable
        return []                              # primer arranque: normal
    text = file.read_text(encoding="utf-8")    # abre, lee todo y cierra
    ...
    return [item_from_dict(entry) for entry in ...]   # (detalle: lección 4)

def save(items, path: str | Path = DEFAULT_STORE) -> None:
    """Escribe la lista de ítems, creando el directorio si hace falta."""
    file = Path(path)
    file.parent.mkdir(parents=True, exist_ok=True)   # crea 'data/' y lo que falte
    ...
    file.write_text(text, encoding="utf-8")          # escribe todo de una vez

# Cómo se ve trabajando con Path
path = DEFAULT_STORE
print(path)                 # data\library.json (Windows) / data/library.json (POSIX)
print(path.name)            # library.json
print(path.suffix)          # .json
print(path.parent)          # data
path.parent.mkdir(parents=True, exist_ok=True)
path.write_text("[]", encoding="utf-8")     # crea/trunca y cierra solo
print(path.exists())        # True

Decisiones: (1) la ruta por defecto es relativa al directorio de trabajo y configurable con --store, así el proyecto funciona desde su raíz y admite otros almacenes; (2) Path(path) acepta tanto str como Path; (3) file.parent.mkdir(parents=True, exist_ok=True) es idempotente: llamarla mil veces no molesta; (4) exists() antes de leer distingue «no hay fichero» (normal) de «JSON corrupto» (error, lección 4). Si necesitas inmunidad al cwd, ancla la ruta con Path(__file__), como viste en la teoría.

Multiplataforma: ejecuta con python -m biblioteca.cli list en Linux/macOS; en Windows usa el launcher py -m biblioteca.cli list. Gracias a pathlib, el mismo código produce data/library.json en POSIX y data\library.json en Windows. Nunca escribas rutas con \\ a mano: en Python, "data\new" interpreta \n como salto de línea (por eso existe el prefijo r"..."), y el código deja de ser portable.

6 · Errores habituales

Olvidar la codificación (mojibake en Windows)

# ❌ En Windows, "Dune" con acentos guardado en cp1252 y leído como UTF-8
#    dará UnicodeDecodeError; al revés, aparecen "Ã¡" en lugar de "á".
Path("libro.txt").write_text("Título: La señora Dalloway")

# ✅ UTF-8 en escritura y en lectura: siempre explícito.
Path("libro.txt").write_text("Título: La señora Dalloway", encoding="utf-8")
texto = Path("libro.txt").read_text(encoding="utf-8")

Depender del directorio de trabajo

# ❌ Esta ruta se resuelve desde donde lances el comando.
#    `python biblioteca/cli.py` desde la raíz vs desde otra carpeta → distinto resultado.
path = Path("data/library.json")

# ✅ Anclada al módulo: inmune al cwd.
path = Path(__file__).resolve().parents[1] / "data" / "library.json"

Abrir con "w" creyendo que añade

# ❌ Cada ejecución BORRA el catálogo anterior y escribe solo este libro.
with open("data/library.json", "w", encoding="utf-8") as f:
    f.write("[]")

# ✅ Si quieres conservar lo previo, lee → modifica → escribe átomico.
#    Si quieres crear sin pisar, usa "x":
with open("data/library.json", "x", encoding="utf-8") as f:
    f.write("[]")            # FileExistsError si ya existe (protección)

Backslashes en rutas hardcodeadas

# ❌ En Linux '\' es un carácter válido en un nombre: no encontrarás el fichero.
#    Además "data\nuevo" no es "data\\nuevo": \n es un salto de línea.
path = "data\\library.json"       # solo funciona en Windows

# ✅ pathlib une y traduce separadores por ti.
from pathlib import Path
path = Path("data") / "library.json"

7 · Ejercicio guiado

Objetivo: crear el directorio de datos de Biblioteca, escribir un fichero de notas y listar los ficheros .txt con glob, comprobando que la codificación UTF-8 es correcta.

  1. Paso 1 — preparar la carpeta: usa mkdir idempotente. 
    from pathlib import Path

data_dir = Path("ejercicio_data")
data_dir.mkdir(parents=True, exist_ok=True)   # no falla si ya existe
print("carpeta lista:", data_dir)
  2. Paso 2 — escribir con acentos: crea un fichero con caracteres no ASCII y UTF-8 explícito. 
    nota = data_dir / "nota.txt"
nota.write_text("Préstamo de 1984 — George Orwell\n", encoding="utf-8")
print("bytes escritos:", nota.stat().st_size)
  3. Paso 3 — leer y comprobar la codificación: vuelve a leer e imprime. 
    texto = nota.read_text(encoding="utf-8")
print(repr(texto))   # la ñ y el — deben verse tal cual, no como \xe2\x80\x94
  4. Paso 4 — crear otro fichero y listar con glob: 
    (data_dir / "backup.txt").write_text("respaldo\n", encoding="utf-8")

for fichero in sorted(data_dir.glob("*.txt")):
    print(fichero.name)
  5. Paso 5 — resultado esperado: 
    carpeta lista: ejercicio_data
bytes escritos: 36
'Préstamo de 1984 — George Orwell\n'
backup.txt
nota.txt
    Comprueba dos cosas: que repr muestra Préstamo y — como caracteres (no como secuencias \x.., señal de que la decodificación fue correcta) y que glob("*.txt") devuelve ambos ficheros en orden estable gracias a sorted. El tamaño en bytes depende de la codificación y del fin de línea: en Linux/macOS verás 36; en Windows, con la traducción a \r\n, 37. No es un error, es la traducción de saltos de línea.

8 · Reto

🎯 Respaldos con nombre de fecha

Escribe una función backup_catalog() que copie data/library.json a data/library-AAAA-MM-DD.json (fecha del día con datetime.date.today()), sin sobrescribir un respaldo que ya exista (si existe, añade -1, -2… al nombre). Después, otra función cleanup_backups(keep=5) que conserve solo los 5 respaldos más recientes y borre el resto con Path.unlink().

Pista: usa Path.replace() o shutil.copy2() para copiar. Construye el nombre con un bucle que incremente un contador mientras candidate.exists(). Para listar respaldos, sorted(Path("data").glob("library-*.json")) da orden alfabético, que para fechas ISO AAAA-MM-DD coincide con el cronológico. Cuidado con borrar el catálogo principal: filtra por el patrón y nunca por "library.json" a secas.

9 · Resumen

  • Un fichero son bytes; el texto aparece al decodificar. Usa UTF-8 explícito siempre.
  • open(path, mode, encoding=…): modos r (leer), w (truncar), a (añadir), x (crear sin pisar), b (binario).
  • with open(...) as f garantiza el cierre; los métodos Path.read_text/write_text abrevian leer/escribir de golpe.
  • pathlib.Path modela rutas como objetos: une con /, consulta exists/is_file/is_dir, crea con mkdir, lista con glob/rglob.
  • Las rutas relativas dependen del cwd; ancla las importantes con Path(__file__).
  • pathlib sustituye a os.path en código moderno: portable, legible y con operador /.

10 · Preguntas frecuentes

¿Por qué hay que poner encoding="utf-8" si Python ya usa UTF-8?

Porque el valor por defecto de open() no es UTF-8: depende del locale del sistema, y en Windows suele ser cp1252 o cp850. Python 3.15 cambiará el defecto a UTF-8, pero en 3.12 hay que ser explícito. Escribir siempre encoding="utf-8" hace que tu programa se comporte igual en todas las máquinas y evita el «mojibake» (Ã¡ en vez de á).

¿Cuál es la diferencia entre Path.read_text() y with open(..., encoding="utf-8")?

read_text() es un atajo: abre, lee todo y cierra. Perfecto para ficheros pequeños y medianos. with open(...) te da un objeto fichero que puedes iterar línea a línea (memoria constante) o al que puedes pedir trozos con read(n). Regla práctica: contenido pequeño → método de Path; flujo o ficheros grandes → with open.

¿Debo usar pathlib o os.path?

pathlib en todo código nuevo. os.path sigue existiendo y lo encontrarás en código heredado y en APIs de la stdlib que aceptan rutas como str; de hecho, Path es aceptado por casi toda función que espera una ruta (open(Path(...)) funciona). La ventaja de pathlib: rutas como objetos con métodos, union portable con / y mejor legibilidad.

¿Cómo evito borrar un fichero por accidente al escribir?

No usando "w" a la ligera: ese modo trunca. Para crear sin pisar, usa "x" (lanza FileExistsError si ya existe). Para actualizar con seguridad, aplica lectura → modificación → escritura atómica (temporal + os.replace, lección 2). Y antes de borrar, comprueba el patrón: nunca borres library.json por error al hacer limpieza de respaldos.

¿Qué pasa con \r\n de Windows al escribir texto?

En modo texto, Python traduce automáticamente: al escribir, \n se convierte en el fin de línea del sistema (en Windows \r\n); al leer, cualquier \r\n o \r se normaliza a \n. Por eso len(text) no siempre coincide con los bytes del fichero. Si necesitas bytes exactos, abre en binario o usa newline="". Para JSON y código, esta traducción no afecta al contenido lógico.
