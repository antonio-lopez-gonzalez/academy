Clases y objetos

Módulo 5 · Programación orientada a objetos ⏱ 35 minutos

1 · Introducción

Hasta ahora el catálogo de Biblioteca lo hemos descrito con colecciones de datos sueltos: un diccionario con "title", "kind", "year"… y funciones que reciben ese diccionario por parámetro. Funciona, pero el conocimiento de qué es un ítem, qué operaciones tiene y qué datos son válidos queda disperso por todo el programa. Cuando el proyecto crece, eso se convierte en un caos de claves mal escritas y validaciones repetidas.

La programación orientada a objetos (POO) agrupa datos y comportamiento en una misma pieza: la clase. Cada ítem del catálogo pasará a ser un objeto que sabe qué datos tiene y, más adelante en el módulo, qué puede hacer (prestarse, devolverse, representarse, compararse).

¿Por qué existen las clases? Porque Python es un lenguaje en el que todo es un objeto (lo viste en Módulo 1: los int, las list, incluso las funciones son objetos). Las clases son el mecanismo que tenemos para fabricar nuestros propios objetos con el mismo modelo que los de la biblioteca estándar. En vez de inventar una estructura paralela, usamos la misma: definir una clase, crear instancias y llamar métodos.

Al terminar sabrás definir una clase con class, crear instancias, escribir un constructor __init__, entender el papel de self, y —muy importante— distinguir atributos de instancia de atributos de clase, la fuente de uno de los bugs más famosos de Python.

2 · Teoría

Clase = molde · Objeto = pieza fabricada

Una clase es una plantilla: declara qué atributos tendrán sus objetos y qué métodos podrán ejecutar. Un objeto (o instancia) es una pieza concreta fabricada a partir de esa plantilla, con sus propios valores. La clase Item es la idea de «ítem de catálogo»; 1984 es un ítem concreto.

CLASE Item -> molde (una sola vez) atributos: id, title, kind declaración de lo que tendrá cada ítem métodos: is_borrowable() lo que cada ítem sabrá hacer | | Item("1", "1984", "book") -> instanciar (fabricar) v INSTANCIA 1 INSTANCIA 2 id="1" id="2" title="1984" title="Dune" kind="book" kind="book"

En otros lenguajes (Java, C#) una clase es también un tipo estático en tiempo de compilación. En Python las clases son objetos y se crean en tiempo de ejecución: puedes crear una clase dentro de un if, guardarla en una variable o pasarla como argumento. Esa es la razón de que type() sobre una instancia te devuelva la clase, y type() sobre la clase te devuelva type.

Definir una clase y crear instancias

La palabra clave es class. Por convención el nombre va en PascalCase (Item, Book, Movie), no en snake_case como las funciones. La clase más simple posible es una con pass:

# Una clase vacía: no declara nada todavía.
class Item:
    pass

# Cada llamada a la clase CREA un objeto nuevo y distinto.
item = Item()

# type() nos dice de qué clase es el objeto.
print(type(item))       # <class '__main__.Item'>

self: el primer parámetro, siempre

Dentro de un método, self es la instancia sobre la que se llamó el método. Python no lo pasa «por magia»: lo pasas tú de forma implícita. Escribir item.describe() es exactamente lo mismo que escribir Item.describe(item); fíjate en que la instancia viaja como primer argumento.

class Item:
    def describe(self):
        # self es la instancia concreta que recibe esta llamada.
        return "un ítem del catálogo"

item = Item()
print(item.describe())     # un ítem del catálogo
# Lo anterior es equivalente a:
print(Item.describe(item)) # un ítem del catálogo

¿Por qué self es explícito y no una palabra reservada? Porque Python prioriza la transparencia: ves exactamente qué objeto estás manipulando. En Java o C#, this existe pero está oculto. En Python self es solo un nombre convencional para el primer parámetro (podrías llamarlo this, pero nunca lo hagas: PEP 8 lo desaconseja). Al declarar el método, tú decides cómo se llama el parámetro; al llamarlo, Python pone la instancia como primer argumento.

__init__: el constructor

__init__ es un método especial (dunder) que Python ejecuta automáticamente justo después de crear el objeto. Su trabajo es dejar la instancia con un estado inicial válido: normalmente asignar los atributos. No devuelve nada (devolver None es obligatorio; si devuelves otra cosa, obtienes TypeError).

class Item:
    def __init__(self, id, title, kind):
        # Asignar atributos de INSTANCIA: viven en cada objeto.
        self.id = id
        self.title = title
        self.kind = kind          # "book" o "movie"

# Al llamar a Item(...), Python crea el objeto y ejecuta __init__.
item = Item("1", "1984", "book")
print(item.title)                 # 1984
print(item.kind)                  # book
print(item.id)                    # 1

Analogía — el formulario: la clase es el formulario en blanco; __init__ es el trámite de rellenarlo al darlo de alta; la instancia es el formulario relleno y archivado. Si al rellenar falta un dato obligatorio, el trámite falla con un TypeError («faltan argumentos»).

Atributos de instancia vs atributos de clase

Un atributo de instancia se asigna con self.x = … y vive en el objeto. Un atributo de clase se declara directamente en el cuerpo de la clase (fuera de __init__) y es compartido por todas las instancias mientras no se sobrescriba:

class Item:
    kind = "book"                 # atributo de CLASE (compartido)

    def __init__(self, id, title):
        self.id = id              # atributos de INSTANCIA (propios)
        self.title = title

a = Item("1", "1984")
b = Item("2", "Dune")

print(a.kind, b.kind)             # book book  (leen el mismo atributo de clase)
a.kind = "movie"                  # esto CREA un atributo de instancia en "a"
print(a.kind, b.kind)             # movie book  (b sigue leyendo el de clase)
print(Item.kind)                  # book       (la clase no cambió)

La resolución de un atributo en Python es: primero la instancia, luego la clase, luego las clases base (el MRO, que verás en la lección 3). Por eso a.kind = "movie" no modifica la clase: añade una entrada en el namespace de la instancia que oculta a la de clase. La clase solo cambia si escribes Item.kind = … o type(a).kind = ….

El atributo de clase mutable es una trampa. Si el atributo de clase es un valor mutable (una lista o un dict) y lo modificas desde una instancia, la modificación afecta a todas las instancias, porque no estás reasignando: estás mutando el único objeto compartido. Es el mismo mecanismo que el famoso def f(x=[]) de las funciones: el valor por defecto se evalúa una sola vez y se reutiliza. Lo verás con detalle en la sección de errores.

Métodos

Un método es una función definida dentro de la clase. Se comporta igual que una función, pero su primer parámetro es self y puede leer y escribir los atributos de la instancia.

class Item:
    def __init__(self, id, title, borrowed=False):
        self.id = id
        self.title = title
        self.borrowed = borrowed

    def mark_borrowed(self):
        # Mutación del estado del objeto.
        self.borrowed = True

    def describe(self):
        state = "prestado" if self.borrowed else "disponible"
        return f"{self.title} ({state})"

item = Item("1", "1984")
print(item.describe())    # 1984 (disponible)
item.mark_borrowed()
print(item.describe())    # 1984 (prestado)

3 · Ejemplo mínimo

El fragmento más pequeño que ya aporta algo: una clase Counter que cuenta las veces que se llama a un método. Fíjate en self y en cómo el estado vive en la instancia.

counter.py
# La clase define el molde del contador.
class Counter:
    def __init__(self):
        # Estado inicial: cada instancia arranca su propio contador a 0.
        self.count = 0

    def increment(self):
        # self.count es el atributo de ESTA instancia.
        self.count += 1

# Fabricamos dos contadores independientes.
a = Counter()
b = Counter()
a.increment()
a.increment()
b.increment()

print(a.count)   # 2  (solo "a" recibió dos incrementos)
print(b.count)   # 1  (el estado de "b" es suyo, no compartido)

Línea por línea: class Counter: declara el molde. __init__ crea self.count = 0 en cada instancia nueva. increment modifica ese atributo de instancia, no una variable global. El resultado demuestra que a y b son objetos distintos: cada uno guarda su propio count.

Si ejecutas python counter.py obtienes exactamente la salida comentada. Prueba a borrar __init__ y ejecutar: increment fallará con AttributeError: 'Counter' object has no attribute 'count', porque el atributo nunca se creó.

4 · Ejemplo real

Aplicamos todo al dominio de Biblioteca: un Item con los campos que maneja el catálogo (id, title, kind, year, borrowed) y un par de métodos con sentido.

biblioteca/models.py (versión de esta lección)
class Item:
    """Un ítem del catálogo: un libro o una película."""

    # Atributo de CLASE: valor por defecto para todo ítem.
    # Es inmutable (str), así que compartirlo es seguro.
    default_kind = "book"

    def __init__(self, id, title, kind=None, year=None):
        # Atributos de INSTANCIA: cada ítem guarda los suyos.
        self.id = id
        self.title = title
        # Si no nos dan kind, usamos el valor por defecto de la clase.
        self.kind = kind if kind is not None else Item.default_kind
        self.year = year
        self.borrowed = False

    def mark_borrowed(self):
        """Marca el ítem como prestado."""
        self.borrowed = True

    def mark_returned(self):
        """Marca el ítem como devuelto."""
        self.borrowed = False

    def describe(self):
        """Devuelve una línea legible del ítem."""
        state = "prestado" if self.borrowed else "disponible"
        year = self.year if self.year is not None else "sin año"
        return f"[{self.id}] {self.title} ({self.kind}, {year}) — {state}"


# --- Uso desde la CLI / los tests ---
book = Item("1", "1984", kind="book", year=1949)
movie = Item("2", "Blade Runner", kind="movie", year=1982)
unknown = Item("3", "Dune")

print(book.describe())     # [1] 1984 (book, 1949) — disponible
book.mark_borrowed()
print(book.describe())     # [1] 1984 (book, 1949) — prestado
print(movie.describe())    # [2] Blade Runner (movie, 1982) — disponible
print(unknown.describe())  # [3] Dune (book, sin año) — disponible

# Cada objeto tiene identidad propia:
print(book is movie)       # False

Decisiones explicadas:

  • default_kind es un atributo de clase porque es un dato inmutable y común a todos los ítems: una constante con nombre, no una copia por objeto.
  • kind=None en la firma permite distinguir «no me han dado kind» de «me han dado el string vacío». Es el mismo patrón que se usa en funciones para evitar valores por defecto mutables: usar None como centinela y decidir dentro.
  • borrowed se inicializa siempre a False dentro de __init__: es estado de instancia, no algo que el llamador deba recordar.
  • Los métodos mutadores (mark_*) y los de consulta (describe) tienen nombres de verbo en inglés, como manda la convención del curso.

Este Item es el germen del módulo. En la lección 2 le añadiremos propiedades y validación; en la 3, jerarquía (Book/Movie); en la 4, lo convertiremos en dataclass; en la 5, definiremos su igualdad e impresión. Guarda esta versión para comparar la evolución.

6 · Errores habituales

Atributo de clase mutable compartido

El error estrella. Se declara tags = [] en la clase, se añade una etiqueta desde una instancia y «aparece» en todas.

# ❌ La lista vive en la CLASE: todas las instancias la comparten.
class Item:
    tags = []                          # mutable a nivel de clase

    def __init__(self, title):
        self.title = title

    def add_tag(self, tag):
        self.tags.append(tag)          # MUTA la lista compartida


a = Item("1984")
b = Item("Dune")
a.add_tag("clásico")

print(a.tags)   # ['clásico']
print(b.tags)   # ['clásico']  <- ¡sorpresa! b nunca pidió esa etiqueta
print(a.tags is b.tags)   # True: es EL MISMO objeto lista
        
# ✅ La lista se crea DENTRO de __init__: una por instancia.
class Item:
    def __init__(self, title):
        self.title = title
        self.tags = []                 # estado de instancia, recién creado

    def add_tag(self, tag):
        self.tags.append(tag)


a = Item("1984")
b = Item("Dune")
a.add_tag("clásico")

print(a.tags)   # ['clásico']
print(b.tags)   # []          <- correcto
print(a.tags is b.tags)   # False

Por qué ocurre: el cuerpo de la clase se ejecuta una sola vez, cuando se define. tags = [] crea una única lista y se guarda en el namespace de la clase. a.tags no la copia: la encuentra en la clase. Y .append() no reasigna, muta ese único objeto. Este es exactamente el mismo problema que def f(x=[]): el valor por defecto se evalúa una vez y se reutiliza entre llamadas. La solución en ambos casos es crear el valor dentro (self.tags = [] o if x is None: x = []).

Conexión con el Módulo 2: ya viste def f(x=[]) como anti-patrón. Los atributos de clase mutables son el mismo concepto en el mundo de los objetos: estado compartido creado antes de que exista ninguna instancia.

Olvidar self al declarar el método

# ❌ El método no declara self pero usa un atributo de instancia.
class Item:
    def __init__(self, title):
        self.title = title

    def describe():            # falta self
        return self.title      # NameError: name 'self' is not defined

item = Item("1984")
item.describe()                # TypeError: describe() takes 0 positional arguments but 1 was given
        
# ✅ Declara self como primer parámetro.
class Item:
    def __init__(self, title):
        self.title = title

    def describe(self):
        return self.title

Creer que __init__ «devuelve» el objeto o puede devolver algo

# ❌ __init__ intenta devolver un valor.
class Item:
    def __init__(self):
        return 42     # TypeError: __init__() should return None, not 'int'

# ✅ __init__ solo inicializa; el objeto lo devuelve Python al llamar Item().
class Item:
    def __init__(self):
        self.ready = True

Confundir el objeto con su nombre

# ❌ "a" y "b" parecen copias, pero son el MISMO objeto (alias).
a = Item("1984")
b = a
b.mark_borrowed()          # muta el objeto que ambos nombres señalan
print(a.borrowed)          # True  <- "a" cambió también

# ✅ Si quieres otro ítem independiente, instancia de nuevo.
a = Item("1984")
b = Item("1984")            # objeto distinto, mismos datos
print(a is b)               # False

Recuerda del Módulo 1: asignar no copia, enlaza. Solo a is b te dice si son el mismo objeto; a == b compararía valor (y en esta lección aún no hemos definido igualdad, así que sigue siendo identidad por defecto: llegará en la lección 5).

9 · Resumen

  • Una clase es un molde; una instancia es un objeto fabricado con ese molde y con su propio estado.
  • self es el primer parámetro de los métodos y referencia a la instancia concreta; item.m() equivale a Item.m(item).
  • __init__ se ejecuta al crear el objeto y sirve para asignar los atributos de instancia; no devuelve nada.
  • Los atributos de instancia (self.x) viven en cada objeto; los de clase (en el cuerpo) se comparten y solo deben usarse para constantes inmutables.
  • Un atributo de clase mutable (lista/dict) es el mismo bug que def f(x=[]): estado compartido creado una sola vez. Solución: crear dentro de __init__.
  • Asignar un objeto a otro nombre no copia: enlaza. Usa is para identidad.

10 · Preguntas frecuentes

¿Por qué self es un parámetro y no una palabra clave?

Porque es una simple convención de nombre. Python no tiene un this oculto: cuando llamas item.describe(), el intérprete busca describe en la clase y lo invoca pasando item como primer argumento posicional. Por eso la definición debe declarar un primer parámetro que lo reciba. Llamarlo self lo hace legible y es lo que esperan las herramientas (ruff, Pylance); cambiarlo por this funcionaría pero rompe la convención.

¿Cuándo uso un atributo de clase y cuándo uno de instancia?

Si el valor es igual para todos los objetos y no va a cambiar (o cambiar solo de forma global y consciente), es de clase: una constante, un contador global, un nombre de tabla. Si es estado propio de cada objeto (el título de un libro, si está prestado, sus etiquetas), es de instancia y se inicializa en __init__. Regla rápida: si dudas, de instancia. El bug por compartir de más es mucho más común que el contrario.

¿__init__ es el «constructor»? ¿No hay __new__?

__new__ es quien realmente crea el objeto (casi siempre la clase base object se encarga). __init__ es el inicializador: se ejecuta después, sobre el objeto ya creado, para darle estado. En el 99 % de los casos solo escribes __init__. __new__ aparece con patrones avanzados (singletons, subclases de tipos inmutables) y no lo necesitas en este curso.

¿Puedo crear atributos nuevos en un objeto después de crearlo?

Sí: item.rating = 5 funciona aunque rating no estuviera en __init__. Python crea el atributo en ese momento. Pero es mala práctica: el estado del objeto deja de estar documentado en un solo sitio y cualquier método que lo use puede fallar con AttributeError si se llama antes. Si un atributo importa, inicialízalo siempre en __init__ (aunque sea a None). Más adelante verás __slots__, que prohíbe crear atributos fuera de una lista fija.

¿Por qué print(type(item)) muestra <class '__main__.Item'>?

type(obj) devuelve la clase del objeto. __main__ es el nombre del módulo que ejecutas (python item_clase.py); Item es el nombre de la clase dentro de ese módulo. Si la clase viviera en biblioteca/models.py, verías <class 'biblioteca.models.Item'>. En la lección 5 aprenderás a controlar ese texto con __repr__.
