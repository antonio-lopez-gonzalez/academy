Implementar el núcleo

Módulo 9 · Proyecto final ⏱ 35 minutos

1 · Introducción

Con la arquitectura fijada, escribimos el núcleo: los tres módulos que no saben nada de terminales ni de print. Son la parte testeable y reutilizable. Si mañana aparece una API web o un script de importación, hablarán con este núcleo tal cual.

  • models.py — qué es un ítem: Item, Book y Movie como dataclasses.
  • store.py — cómo persiste: leer/escribir data/library.json reconstruyendo cada entrada.
  • service.py — qué se puede hacer: add, list_items, search, borrow, return_item.
Por qué separamos datos, disco y reglas

Cada capa cambia por un motivo distinto. El modelo cambia si cambia el dominio (añadir rating); el almacén, si cambia el formato (JSON → SQLite); las reglas, si cambian las normas («no prestar dos veces»). Separarlos evita que un cambio en el formato arrastre a toda la aplicación.

2 · Teoría

Dataclasses. Una @dataclass genera __init__, __repr__ y __eq__ a partir de campos anotados. Usamos herencia: Book añade author, Movie añade director. El campo kind es un discriminador: dice qué subclase reconstruir al leer el JSON; sin él se perdería el tipo.

Serializar. asdict() convierte el objeto en un diccionario plano listo para json.dumps. A la inversa, item_from_dict mira el kind y construye la subclase correcta. El propio constructor valida (__post_init__), así que un objeto no puede nacer inválido.

Escritura directa. save serializa la lista con json.dumps(..., ensure_ascii=False, indent=2), crea el directorio si hace falta y escribe el fichero de una vez. Para un catálogo personal es suficiente; si te preocupa una interrupción a mitad, la técnica profesional es escribir en un temporal y hacer Path.replace() (atómico).

   save(items, path)
      ├─ Path(path).parent.mkdir(parents=True, exist_ok=True)
      ├─ payload = json.dumps([item.to_dict() …], ensure_ascii=False, indent=2)
      └─ Path(path).write_text(payload)      →  data/library.json actualizado

El servicio como funciones. service.py no guarda estado: cada función carga el almacén, aplica la operación y lo guarda. add genera un id con secrets.token_hex; las reglas («no prestar dos veces», «no devolver lo que no está prestado») viven aquí y los tests las comprueban sin tocar la CLI.

Errores sin logging. Lanzamos BibliotecaError con mensajes concretos en vez de Exception a pelo. El núcleo no imprime nada: la CLI (el borde) decide qué se muestra y con qué código de salida.

3 · Ejemplo mínimo

El patrón de serialización en su forma más pequeña: una dataclass que va y vuelve de JSON.

from dataclasses import asdict, dataclass
import json

@dataclass
class Punto:
    x: int
    y: int

punto = Punto(3, 4)
texto = json.dumps(asdict(punto))       # objeto → dict → texto JSON
print(texto)
restaurado = Punto(**json.loads(texto)) # texto → dict → objeto
print(restaurado == punto)
{"x": 3, "y": 4}
True

Línea por línea: asdict(punto) da {"x": 3, "y": 4}; json.dumps lo serializa y json.loads hace lo inverso; Punto(**{…}) reparte las claves como argumentos; == es True porque la dataclass genera __eq__ campo a campo.

Ojo con Punto(**data) en un modelo real

Con varios tipos no puedes repartir todas las claves a ciegas: un Book no acepta director. Por eso item_from_dict decide la subclase a partir de kind antes de construir el objeto.

4 · Ejemplo real

src/biblioteca/models.py — el dominio:

"""Modelo de datos de Biblioteca."""

from __future__ import annotations

from dataclasses import asdict, dataclass
from typing import Any

# Tipos de ítem admitidos. Un `kind` fuera de esta lista es un error de negocio.
KINDS = ("book", "movie")


class BibliotecaError(Exception):
    """Error de negocio de Biblioteca (entrada inválida, ítem inexistente…)."""


@dataclass
class Item:
    """Ítem de catálogo (base). No usar directamente: crear Book o Movie."""

    id: str
    title: str
    kind: str
    year: int | None = None
    borrowed: bool = False

    def __post_init__(self) -> None:
        # Validación en el constructor: un objeto nunca nace en estado inválido.
        if self.kind not in KINDS:
            raise BibliotecaError(f"kind inválido: {self.kind!r} (usa {KINDS})")
        if not self.title.strip():
            raise BibliotecaError("el título no puede estar vacío")

    @property
    def creator(self) -> str | None:
        """Autor o director; None si no se conoce."""
        return None

    def to_dict(self) -> dict[str, Any]:
        """Convierte el ítem a un dict serializable a JSON."""
        return asdict(self)


@dataclass
class Book(Item):
    """Libro: además tiene `author`."""

    author: str | None = None

    @property
    def creator(self) -> str | None:
        return self.author


@dataclass
class Movie(Item):
    """Película: además tiene `director`."""

    director: str | None = None

    @property
    def creator(self) -> str | None:
        return self.director


def item_from_dict(data: dict[str, Any]) -> Item:
    """Reconstruye el ítem concreto (Book/Movie) a partir de un dict JSON."""
    kind = data.get("kind")
    if kind == "movie":
        return Movie(**data)
    if kind == "book":
        return Book(**data)
    raise BibliotecaError(f"kind inválido en el almacén: {kind!r}")

src/biblioteca/store.py — la persistencia:

"""Persistencia del catálogo en un fichero JSON."""

from __future__ import annotations

import json
from pathlib import Path
from typing import Sequence

from .models import BibliotecaError, Item, item_from_dict

# Ruta por defecto, relativa al directorio de trabajo.
DEFAULT_STORE = Path("data/library.json")


def load(path: str | Path = DEFAULT_STORE) -> list[Item]:
    """Lee el almacén y devuelve la lista de ítems (vacía si no existe)."""
    file = Path(path)
    if not file.exists():
        return []
    try:
        raw = json.loads(file.read_text(encoding="utf-8"))
    except json.JSONDecodeError as err:
        raise BibliotecaError(f"el almacén {file} no es JSON válido: {err}") from err
    if not isinstance(raw, list):
        raise BibliotecaError(f"el almacén {file} debe ser una lista JSON")
    return [item_from_dict(entry) for entry in raw]


def save(items: Sequence[Item], path: str | Path = DEFAULT_STORE) -> None:
    """Escribe la lista de ítems, creando el directorio si hace falta."""
    file = Path(path)
    file.parent.mkdir(parents=True, exist_ok=True)
    data = [item.to_dict() for item in items]
    text = json.dumps(data, ensure_ascii=False, indent=2) + "\n"
    file.write_text(text, encoding="utf-8")

src/biblioteca/service.py — las reglas:

"""Reglas de negocio de Biblioteca.

Estas funciones cargan el almacén, aplican la operación y lo guardan. La CLI
es una capa fina por encima; así el núcleo se puede probar sin terminal.
"""

from __future__ import annotations

import secrets
from typing import Iterable

from . import store
from .models import BibliotecaError, Book, Item, Movie


def _new_id(existing: set[str]) -> str:
    """Genera un id corto y único que no colisione con los existentes."""
    while True:
        candidate = "it_" + secrets.token_hex(4)   # p. ej. it_9f3a1c7b
        if candidate not in existing:
            return candidate


def add(
    title: str,
    kind: str = "book",
    year: int | None = None,
    creator: str | None = None,
    path: str = store.DEFAULT_STORE,
) -> Item:
    """Añade un ítem nuevo al catálogo y devuelve el ítem creado."""
    if not title or not title.strip():
        raise BibliotecaError("el título es obligatorio")
    items = store.load(path)
    item_id = _new_id({item.id for item in items})

    if kind == "book":
        item: Item = Book(id=item_id, title=title.strip(), kind="book",
                          year=year, author=creator)
    elif kind == "movie":
        item = Movie(id=item_id, title=title.strip(), kind="movie",
                     year=year, director=creator)
    else:
        raise BibliotecaError(f"kind inválido: {kind!r} (usa 'book' o 'movie')")

    items.append(item)
    store.save(items, path)
    return item


def find(items: Iterable[Item], item_id: str) -> Item:
    """Devuelve el ítem con ese id o lanza BibliotecaError si no existe."""
    for item in items:
        if item.id == item_id:
            return item
    raise BibliotecaError(f"no existe ningún ítem con id {item_id!r}")


def list_items(kind: str | None = None, path: str = store.DEFAULT_STORE) -> list[Item]:
    """Lista el catálogo, opcionalmente filtrando por tipo."""
    items = store.load(path)
    if kind is None:
        return items
    if kind not in ("book", "movie"):
        raise BibliotecaError(f"kind inválido: {kind!r}")
    return [item for item in items if item.kind == kind]


def search(term: str, path: str = store.DEFAULT_STORE) -> list[Item]:
    """Busca por título o creador (autor/director), sin distinguir mayúsculas."""
    needle = term.strip().lower()
    if not needle:
        raise BibliotecaError("el término de búsqueda no puede estar vacío")
    results = []
    for item in store.load(path):
        haystack = f"{item.title} {item.creator or ''}".lower()
        if needle in haystack:
            results.append(item)
    return results


def borrow(item_id: str, path: str = store.DEFAULT_STORE) -> Item:
    """Marca un ítem como prestado."""
    items = store.load(path)
    item = find(items, item_id)
    if item.borrowed:
        raise BibliotecaError(f"el ítem {item_id!r} ya está prestado")
    item.borrowed = True
    store.save(items, path)
    return item


def return_item(item_id: str, path: str = store.DEFAULT_STORE) -> Item:
    """Marca un ítem como devuelto."""
    items = store.load(path)
    item = find(items, item_id)
    if not item.borrowed:
        raise BibliotecaError(f"el ítem {item_id!r} no estaba prestado")
    item.borrowed = False
    store.save(items, path)
    return item
Por qué return_item y no return

return es palabra reservada: no puede ser nombre de función. El subcomando de la CLI sí se llama return (es una cadena), pero la función del servicio es return_item.

6 · Errores habituales

1. Mutable por defecto en una dataclass.

❌ Incorrecto 
@dataclass
class Item:
    tags: list[str] = []      # todas las instancias comparten la MISMA lista

Python evalúa el defecto una vez, al definir la clase. Lo correcto es field(default_factory=list). En nuestro modelo usamos str/bool (inmutables), así que no aplica; memorízalo.

2. Capturar Exception y tragarse el error.

❌ Incorrecto 
try:
    data = json.loads(text)
except Exception:
    data = []                 # el JSON estaba roto y nadie se enteró

Captura lo específico (json.JSONDecodeError) y relanza con contexto: raise BibliotecaError(...) from err.

3. Buscar con == en vez de subcadena. bib search "orwell" debe encontrar a George Orwell; usamos term.lower() in texto.lower(). Comparar con == solo encuentra coincidencias exactas.

4. Perder el estado al reconstruir. Si item_from_dict olvidara borrowed, al recargar el catálogo todo aparecería disponible. Por eso se pasa el dict completo (Book(**data)), no solo los campos obligatorios.

9 · Resumen

  • models define el dominio con dataclasses y sabe ir a/desde JSON.
  • store lee y escribe el JSON; aísla el formato de disco.
  • service contiene las reglas como funciones de módulo: cargan, mutan y guardan.
  • BibliotecaError es el único error del dominio; el núcleo no imprime nada.
  • Los ids se generan con secrets.token_hex (it_<hex>) y no colisionan.
FunciónQué hace
service.add(title, kind, ...)Crea un ítem con id único y lo guarda.
service.list_items(kind=None, ...)Devuelve todos los ítems o los de un tipo.
service.search(term, ...)Busca por título o creador.
service.borrow(id, ...)Marca como prestado; falla si ya lo estaba.
service.return_item(id, ...)Devuelve el ítem; falla si no estaba prestado.

10 · Preguntas frecuentes

¿Por qué guardar tras cada operación y no al salir?

Si el programa muere inesperadamente no pierdes cambios confirmados. El coste es una escritura por comando, irrelevante para un catálogo personal.

¿No debería store.load validar con jsonschema?

Sería correcto, pero añade una dependencia de terceros. Priorizamos la stdlib: la validación la hace el propio modelo en __post_init__ y el despacho de item_from_dict, en espejo con schema/library.schema.json, que queda como contrato legible. Si quieres validación formal, jsonschema es la opción natural.

¿Qué pasa si dos ítems tienen el mismo título?

Nada: el título puede repetirse. _new_id reintenta con secrets.token_hex hasta obtener un it_<hex> que no esté en uso; el id es la clave de borrow/return.

¿Por qué service carga el almacén en cada función?

Es la versión más simple: sin estado en memoria y sin riesgo de quedarse desincronizado. Cada llamada ve el disco tal cual; para un catálogo personal el coste es irrelevante.
