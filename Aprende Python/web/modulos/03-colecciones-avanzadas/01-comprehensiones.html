List, set y dict comprehensions

Módulo 3 · Colecciones avanzadas ⏱ 35 minutos

1 · Introducción

Una comprehension (comprensión) es una forma compacta de construir una colección a partir de otra: filtrar, transformar o combinar elementos en una sola expresión. En otros lenguajes escribirías un bucle con append; en Python escribes la intención en una línea.

En esta lección verás las tres variantes que usarás a diario —lista, conjunto y diccionario—, cómo añadir una condición de filtro, cómo anidar comprehensions para recorrer estructuras bidimensionales, y sobre todo cuándo NO usarlas: una comprehension larga o con demasiada lógica deja de ser legible y se convierte en un anti-patrón.

Las usaremos sobre el catálogo de Biblioteca: por ejemplo, obtener los títulos de los libros publicados después de 1950, el conjunto de tipos de ítem o un índice id → título.

¿Por qué existe esta construcción? Porque el patrón «crear una colección vacía + recorrer + append» es tan común que merece una sintaxis propia. Las comprehensions expresan el qué (qué colección quiero) en vez del cómo (cómo la voy rellenando), igual que en matemáticas se escribe un conjunto por comprensión: { x² | x ∈ ℕ, x > 0 }. Python copia esa notación casi literalmente.

Analogía: un bucle es un operario que va colocando piezas una a una en una caja. Una comprehension es una máquina: le dices qué piezas entran, qué transformación sufren y cómo se llaman, y ella devuelve la caja llena. Menos ruido, misma pieza final.

Errores típicos de esta pieza: usar una comprehension solo por sus efectos secundarios (¡devuelve una lista que nadie usa!), anidar tres niveles y volverla ilegible, confundir la comprehension de diccionario con la de conjunto (ambas usan {}), o crear una lista enorme cuando un generador bastaría.

2 · Teoría

Anatomía de una comprehension

Toda comprehension tiene esta forma general:

#   [ expresión  for  variable  in  iterable  if  condición ]
#     ^^^^^^^^^      ^^^^^^^^      ^^  ^^^^^^^^  ^^  ^^^^^^^^^
#     transforma     recorre      cada  fuente   filtra lo que pasa

Se lee de dentro hacia fuera: «para cada variable en iterable, aplica expresión, siempre que se cumpla condición». El if final es opcional. La variable puede llamarse como quieras; si no la usas, la convención es _.

De bucle a comprehension, paso a paso

Con bucle (imperativo)Con comprehension (declarativo)
out = []
for n in nums:
    out.append(n * 2)		 out = [n * 2 for n in nums]
out = []
for n in nums:
    if n > 0:
        out.append(n)		 out = [n for n in nums if n > 0]

Las tres variantes

LIBRARY = [
    {"id": "1", "title": "1984", "kind": "book", "year": 1949, "author": "George Orwell", "borrowed": False},
    {"id": "2", "title": "Dune", "kind": "book", "year": 1965, "author": "Frank Herbert", "borrowed": True},
    {"id": "3", "title": "Blade Runner", "kind": "movie", "year": 1982, "director": "Ridley Scott", "borrowed": False},
    {"id": "4", "title": "Fahrenheit 451", "kind": "book", "year": 1953, "author": "Ray Bradbury", "borrowed": False},
    {"id": "5", "title": "The Matrix", "kind": "movie", "year": 1999, "director": "Lana Wachowski", "borrowed": True},
]
# LIST comprehension: devuelve una lista (respeta el orden y los duplicados)
titles = [item["title"] for item in LIBRARY]
print(titles)
# Salida: ['1984', 'Dune', 'Blade Runner', 'Fahrenheit 451', 'The Matrix']
# SET comprehension: devuelve un conjunto (sin duplicados, sin orden garantizado)
kinds = {item["kind"] for item in LIBRARY}
print(kinds)
# Salida: {'book', 'movie'}  (el orden puede variar)
# DICT comprehension: devuelve un diccionario (clave: valor)
by_id = {item["id"]: item["title"] for item in LIBRARY}
print(by_id)
# Salida: {'1': '1984', '2': 'Dune', '3': 'Blade Runner', '4': 'Fahrenheit 451', '5': 'The Matrix'}

Diferencia clave: la de lista usa [], la de diccionario {clave: valor ...} y la de conjunto {expresión ...}. Unas llaves con dos puntos son diccionario; sin dos puntos, conjunto. {x for x in data} es un set, no un dict.

Filtro (if) y transformación (expresión)

El if descarta elementos antes de transformarlos. Es equivalente a poner un if dentro del bucle, no un if/else de ramas. Para ramas usa el operador ternario en la expresión.

# Solo los libros publicados después de 1950 (filtro puro)
modern_books = [
    item["title"]
    for item in LIBRARY
    if item["kind"] == "book" and item["year"] > 1950
]
print(modern_books)
# Salida: ['Dune', 'Fahrenheit 451']
# Ternario en la expresión: no filtra, etiqueta
labels = ["prestado" if item["borrowed"] else "disponible" for item in LIBRARY]
print(labels)
# Salida: ['disponible', 'prestado', 'disponible', 'disponible', 'prestado']

Comprehensions anidadas

Cuando la fuente es una estructura bidimensional (una matriz, o ítems con listas dentro), puedes recorrer dos niveles. El orden de los for se lee de izquierda a derecha y es el mismo orden que tendrían los bucles anidados.

# Aplanar una matriz (lista de listas)
matrix = [[1, 2, 3], [4, 5, 6]]
flat = [n for row in matrix for n in row]
print(flat)
# Salida: [1, 2, 3, 4, 5, 6]
# Producto cartesiano: todas las parejas (fila, columna)
cells = [(r, c) for r in range(2) for c in range(3)]
print(cells)
# Salida: [(0, 0), (0, 1), (0, 2), (1, 0), (1, 1), (1, 2)]

Legibilidad: dos for ya es el límite cómodo. Tres o más, o varios if, casi siempre se leen mejor con bucles normales. La meta no es «caber en una línea», es que otro (o tú mañana) entienda qué colección se está construyendo.

Comprehensions frente a map y filter

Antes de que existieran las comprehensions se usaban map y filter con lambda. Siguen existiendo, pero en Python la comprehension es la forma idiomatica cuando hay una transformación y/o un filtro:

TareaCon map / filterComprehension (preferida)
Transformarlist(map(f, xs))[f(x) for x in xs]
Filtrarlist(filter(p, xs))[x for x in xs if p(x)]
Filtrar y transformarlist(map(f, filter(p, xs)))[f(x) for x in xs if p(x)]

¿Por qué la comprehension gana? Porque map y filter devuelven iteradores perezosos (lo verás en la lección 2) que hay que envolver en list(...), y porque componer map(filter(...)) invierte el orden mental (leer el filtro antes que la transformación). La comprehension lee en el mismo orden en que piensas. Usa map/filter cuando ya tienes la función hecha (map(str.strip, lines)) o dentro de un pipeline con sum/any/all.

3 · Ejemplo mínimo

El fragmento más pequeño que muestra filtro + transformación. Fíjate en que la variable n no «escapa» de la comprehension.

# Cuadrados de los números pares del 1 al 6
squares_of_even = [n ** 2 for n in range(1, 7) if n % 2 == 0]
print(squares_of_even)
# Salida: [4, 16, 36]
# La variable del bucle tiene su PROPIO ámbito (Python 3): no contamina fuera
n = "soy de fuera"
_ = [n for n in range(3)]
print(n)
# Salida: soy de fuera

Línea por línea: range(1, 7) produce 1..6; el if n % 2 == 0 deja pasar 2, 4 y 6; n ** 2 los eleva al cuadrado → [4, 16, 36]. En la segunda parte, la variable n de dentro de la comprehension no sobrescribe la n de fuera: desde Python 3 cada comprehension crea su propio scope. Esto es una mejora deliberada respecto a Python 2, donde sí se filtraba la variable y causaba bugs difíciles de ver.

4 · Ejemplo real

Preguntas típicas sobre el catálogo de Biblioteca, resueltas con comprehensions. Observa cómo cada una expresa una pregunta de negocio distinta.

LIBRARY = [
    {"id": "1", "title": "1984", "kind": "book", "year": 1949, "author": "George Orwell", "borrowed": False},
    {"id": "2", "title": "Dune", "kind": "book", "year": 1965, "author": "Frank Herbert", "borrowed": True},
    {"id": "3", "title": "Blade Runner", "kind": "movie", "year": 1982, "director": "Ridley Scott", "borrowed": False},
    {"id": "4", "title": "Fahrenheit 451", "kind": "book", "year": 1953, "author": "Ray Bradbury", "borrowed": False},
    {"id": "5", "title": "The Matrix", "kind": "movie", "year": 1999, "director": "Lana Wachowski", "borrowed": True},
]
# 1) Títulos disponibles (no prestados) de libros publicados después de 1950
available_modern_books = [
    item["title"]
    for item in LIBRARY
    if item["kind"] == "book" and not item["borrowed"] and item["year"] > 1950
]
print(available_modern_books)
# Salida: ['Fahrenheit 451']
# 2) Índice id -> título, para buscar rápido por identificador
index_by_id = {item["id"]: item["title"] for item in LIBRARY}
print(index_by_id["3"])
# Salida: Blade Runner
# 3) Conjunto de autores de libros (los que tienen 'author'), sin repetir
authors = {item["author"] for item in LIBRARY if "author" in item}
print(authors)
# Salida: {'George Orwell', 'Frank Herbert', 'Ray Bradbury'}  (orden variable)
# 4) Título en mayúsculas solo de las películas
movie_titles = [item["title"].upper() for item in LIBRARY if item["kind"] == "movie"]
print(movie_titles)
# Salida: ['BLADE RUNNER', 'THE MATRIX']
# 5) Longitud del título para cada ítem: dict título -> nº de caracteres
title_lengths = {item["title"]: len(item["title"]) for item in LIBRARY}
print(title_lengths["Dune"])
# Salida: 4

Decisiones y por qué: usamos set en (3) porque «qué autores hay» no admite duplicados y no importa el orden; usamos dict en (2) y (5) porque queremos buscar por clave, no recorrer; y usamos not item["borrowed"] en vez de item["borrowed"] == False porque en Python cualquier valor es evaluable como booleano (truthiness, Módulo 2) y la primera forma es más directa.

6 · Errores habituales

1. Comprehension por efectos secundarios

❌ Incorrecto 
# Construye una lista de None sin usar... y encima es confuso
[print(item["title"]) for item in LIBRARY]
# Salida: 1984
#         Dune
#         (…y devuelve [None, None, None, None, None])
✅ Correcto 
# Para efectos secundarios, un bucle normal y explícito
for item in LIBRARY:
    print(item["title"])

2. Confundir set con dict

# ❌ Pensabas crear un diccionario, pero sin ':' esto es un CONJUNTO
wrong = {item["title"] for item in LIBRARY}   # {'1984', 'Dune', ...}
# ✅ Con clave:valor sí es diccionario
right = {item["id"]: item["title"] for item in LIBRARY}

3. Sobrescribir un builtin

❌ Incorrecto 
list = [item["title"] for item in LIBRARY]  # oculta el builtin list
# A partir de aquí list(...) deja de funcionar: la sombra rompe el resto del archivo
✅ Correcto 
titles = [item["title"] for item in LIBRARY]  # nombre descriptivo, no un builtin

4. Materializar lo que no hace falta

❌ Incorrecto 
# Construye una lista gigante solo para sumarla: memoria de más
total_chars = sum([len(item["title"]) for item in LIBRARY])
✅ Correcto 
# Sin corchetes: expresión generadora, se consume sin crear la lista
total_chars = sum(len(item["title"]) for item in LIBRARY)
print(total_chars)
# Salida: 44

7 · Ejercicio guiado

Objetivo: construir un pequeño informe del catálogo de Biblioteca usando comprehensions, paso a paso.

  1. Paso 1 — Prepara el catálogo. 
    LIBRARY = [
    {"id": "1", "title": "1984", "kind": "book", "year": 1949, "borrowed": False},
    {"id": "2", "title": "Dune", "kind": "book", "year": 1965, "borrowed": True},
    {"id": "3", "title": "Blade Runner", "kind": "movie", "year": 1982, "borrowed": False},
    {"id": "4", "title": "Fahrenheit 451", "kind": "book", "year": 1953, "borrowed": False},
]
  2. Paso 2 — Lista de títulos ordenados alfabéticamente (comprehension + sorted). 
    titles = sorted(item["title"] for item in LIBRARY)
print(titles)
# Salida: ['1984', 'Blade Runner', 'Dune', 'Fahrenheit 451']
  3. Paso 3 — Conjunto de años para ver la antigüedad del catálogo. 
    years = {item["year"] for item in LIBRARY}
print(sorted(years))
# Salida: [1949, 1953, 1965, 1982]
  4. Paso 4 — Índice id → title y comprobación con get. 
    index = {item["id"]: item["title"] for item in LIBRARY}
print(index.get("4", "desconocido"))
# Salida: Fahrenheit 451
  5. Paso 5 — Informe como dict: cuántos ítems hay de cada tipo. 
    kind_count = {kind: sum(1 for it in LIBRARY if it["kind"] == kind)
              for kind in {it["kind"] for it in LIBRARY}}
print(kind_count)
# Salida: {'book': 3, 'movie': 1}  (el orden puede variar)

Resultado esperado: al ejecutar el script completo deberías ver las cuatro líneas de salida anteriores. Cómo comprobarlo: compara con los comentarios # Salida:; y verifica que kind_count suma 4 (el total de ítems).

8 · Reto

🎯 Índice por tipo y por década

Partiendo del mismo LIBRARY, produce dos estructuras sin usar bucles for explícitos (solo comprehensions):

  1. by_kind: un diccionario que asocie cada kind con la lista de títulos de ese tipo. Por ejemplo by_kind["book"] == ["1984", "Dune", "Fahrenheit 451"].
  2. by_decade: un diccionario que asocie cada década (1940, 1950, 1960, 1980…) con la lista de títulos publicados en ella.

Pista: una comprehension de diccionario sola no agrupa elementos repetidos; piensa cómo obtener primero la lista de claves únicas y luego, para cada clave, la lista de valores que le corresponden. Puedes ayudarte de una comprehension anidada dentro de la de fuera.

9 · Resumen

  • Sintaxis: [expr for x in it if cond]. La expr transforma, el if filtra.
  • Tres variantes: lista [], conjunto {} (sin :), diccionario {k: v}.
  • Ámbito propio: la variable de la comprehension no sale de ella (Python 3).
  • Anidar: dos for máximo; mismo orden que los bucles anidados.
  • No es para efectos secundarios: si no usas el resultado, escribe un for.
  • Pereza: quita los corchetes y tienes una expresión generadora (lección 2).
ConstrucciónDevuelvePara qué sirve

{f(x) for x in xs}setValores únicos, tests de pertenencia in
{k(x): v(x) for x in xs}dictÍndices y proyecciones con búsqueda por clave
[n for row in m for n in row]listAplanar estructuras anidadas
(f(x) for x in xs)generadorConsumir una vez sin materializar (lección 2)

10 · Preguntas frecuentes

¿Una comprehension es siempre más rápida que un bucle?

Casi siempre algo más rápida, porque se ejecuta en bytecode optimizado para el patrón (no hay llamada a append desde el nivel de Python en cada vuelta). Pero la diferencia es pequeña y la razón para usarla es la claridad, no el rendimiento. Si un bucle se lee mejor, el bucle gana. Nunca sacrifiques legibilidad por micro-optimización.

¿Puedo modificar la lista original dentro de una comprehension?

Técnicamente sí, pero no lo hagas: modificar la colección que estás recorriendo (o desde la expresión) lleva a resultados confusos y a bugs difíciles de reproducir. La comprehension está pensada para construir una colección nueva a partir de una fuente. Si necesitas mutar, usa un bucle explícito.

¿Cuándo uso map/filter en vez de una comprehension?

Cuando ya tienes la función hecha y no necesitas un lambda, por ejemplo map(str.strip, lines). También dentro de agregadores perezosos: any(sale for sale in sales), sum(map(len, words)). Si tuvieras que escribir un lambda para algo tan simple como x + 1, la comprehension es más legible. Regla práctica: sin lambda, map/filter; con lambda, comprehension.

¿Por qué {} es un dict vacío y no un set vacío?

Por razones históricas: {} se reservó para el diccionario desde el principio. Para crear un conjunto vacío hay que usar set(). Un set con elementos sí se escribe con llaves: {1, 2, 3}. Este detalle confunde a mucha gente que llega de otros lenguajes.

¿Se pueden anidar comprehensions de tipos distintos?

Sí: la expresión puede ser cualquier cosa, incluida otra comprehension. Por ejemplo, para obtener para cada tipo la lista de títulos: {kind: [it["title"] for it in LIBRARY if it["kind"] == kind] for kind in {it["kind"] for it in LIBRARY}}. Funciona, pero fíjate en que ya cuesta leerlo: es justo el límite que mencionamos en las buenas prácticas. Si la usas, fórmateala en varias líneas.
