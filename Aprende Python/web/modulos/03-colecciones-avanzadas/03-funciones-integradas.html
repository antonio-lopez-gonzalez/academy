Funciones integradas: sorted, zip, any/all

Módulo 3 · Colecciones avanzadas ⏱ 30 minutos

1 · Introducción

La biblioteca estándar de Python viene con un puñado de funciones que sustituyen a bucles escritos a mano: sorted, min, max, sum, enumerate, zip, any, all, map, filter. Conocerlas bien es la diferencia entre un código que parece de principiante y código idiomático.

Además, el módulo functools añade dos herramientas de orden superior —reduce y partial— muy potentes, pero que conviene usar con criterio: casi siempre sum o una comprehension se leen mejor que reduce.

¿Por qué existen? Porque en Python el bucle es el último recurso, no el primero. Cuando una operación es tan común como «ordenar por un criterio» o «¿hay alguno que cumpla X?», la función integrada comunica la intención mejor que el bucle y suele estar optimizada en C. En el catálogo de Biblioteca las usarás para ordenar por año, buscar el más antiguo, validar que todos los ítems son correctos o comprobar si queda algo prestado.

Errores típicos: confundir sorted() (devuelve una lista nueva) con .sort() (muta y devuelve None), olvidar que zip se corta en el más corto, llamar a min/max sobre una secuencia vacía sin valor por defecto, o usar reduce para lo que sum resuelve.

2 · Teoría

sorted y el parámetro key

key recibe una función de un argumento: la clave por la que comparar. No recibe dos (no es un comparador como en otros lenguajes). Fíjate en que sorted no toca la lista original.

LIBRARY = [
    {"id": "1", "title": "1984", "kind": "book", "year": 1949, "borrowed": False},
    {"id": "2", "title": "Dune", "kind": "book", "year": 1965, "borrowed": True},
    {"id": "3", "title": "Blade Runner", "kind": "movie", "year": 1982, "borrowed": False},
    {"id": "4", "title": "Fahrenheit 451", "kind": "book", "year": 1953, "borrowed": False},
]
# Por año ascendente (lambda = función anónima de un parámetro)
by_year = sorted(LIBRARY, key=lambda item: item["year"])
print([item["title"] for item in by_year])
# Salida: ['1984', 'Fahrenheit 451', 'Dune', 'Blade Runner']
# Descendente con reverse=True (NO negando el número)
newest_first = sorted(LIBRARY, key=lambda item: item["year"], reverse=True)
print([item["title"] for item in newest_first])
# Salida: ['Blade Runner', 'Dune', 'Fahrenheit 451', '1984']
# Varios criterios: la key devuelve una TUPLA; se compara en orden
by_kind_year = sorted(LIBRARY, key=lambda item: (item["kind"], item["year"]))
print([(item["title"], item["year"]) for item in by_kind_year])
# Salida: [('1984', 1949), ('Fahrenheit 451', 1953), ('Dune', 1965), ('Blade Runner', 1982)]

¿Por qué key y no un comparador cmp(a, b)? Porque comparar parejas invoca la función ~n·log(n) veces, mientras que calcular la clave se hace una sola vez por elemento. Además, las tuplas permiten ordenar por varios campos sin escribir lógica de comparación. El resultado es código más rápido y más claro. (Python 3 eliminó el parámetro cmp; si lo necesitas, existe functools.cmp_to_key.)

min, max y sum

# min/max aceptan key: devuelven el ELEMENTO, no la clave
oldest = min(LIBRARY, key=lambda item: item["year"])
print(oldest["title"])
# Salida: 1984
# También con un valor por defecto si la colección puede estar vacía
print(min([], key=int, default=None))
# Salida: None
# sum: suma números o longitudes; start opcional
years_total = sum(item["year"] for item in LIBRARY)
print(years_total)
# Salida: 7849
print(sum([1, 2, 3], start=10))
# Salida: 16

enumerate: índice y valor sin range(len())

# ❌ El anti-patrón clásico (Módulo 2) y su versión idiomática
for i in range(len(LIBRARY)):
    print(i + 1, LIBRARY[i]["title"])
for position, item in enumerate(LIBRARY, start=1):
    print(position, item["title"])
# Salida: 1 1984
#         2 Dune
#         3 Blade Runner
#         4 Fahrenheit 451

zip: recorrer en paralelo

titles = ["1984", "Dune", "Blade Runner"]
years = [1949, 1965, 1982]
for title, year in zip(titles, years):
    print(f"{title} ({year})")
# Salida: 1984 (1949)
#         Dune (1965)
#         Blade Runner (1982)
# zip se detiene en el más corto, no lanza error
print(list(zip([1, 2, 3], ["a", "b"])))
# Salida: [(1, 'a'), (2, 'b')]
# Objetivo inverso: separar parejas en dos listas
pairs = [("1984", 1949), ("Dune", 1965)]
names, ys = zip(*pairs)      # el '*' desempaqueta las parejas como argumentos
print(names, ys)
# Salida: ('1984', 'Dune') (1949, 1965)

any y all: cuantificadores

any es «¿existe alguno?» y all es «¿todos?». Ambos cortocircuitan: en cuanto conocen la respuesta, dejan de mirar.

# ¿Hay algo prestado?
print(any(item["borrowed"] for item in LIBRARY))
# Salida: True
# ¿Todos los ítems tienen título no vacío y año?
print(all(item["title"] and item["year"] for item in LIBRARY))
# Salida: True
# all() sobre vacío es True; any() sobre vacío es False (lógica de cuantificadores)
print(all([]), any([]))
# Salida: True False

map y filter

Son perezosos (devuelven iteradores, lección 2). Úsalos cuando ya tienes la función o dentro de un agregador; si haría falta un lambda trivial, la comprehension se lee mejor.

# map con una función ya existente: la forma canónica
raw = ["1984 ", " Dune", "Blade Runner "]
clean = list(map(str.strip, raw))
print(clean)
# Salida: ['1984', 'Dune', 'Blade Runner']
# filter con predicado simple
borrowed = list(filter(lambda item: item["borrowed"], LIBRARY))
print([item["title"] for item in borrowed])
# Salida: ['Dune']
# Equivalente más legible con comprehension (preferido aquí)
borrowed = [item for item in LIBRARY if item["borrowed"]]

functools: reduce y partial

from functools import reduce, partial
# reduce: pliega la colección acumulando un resultado
# (suma acumulada de los años, con valor inicial 0)
total = reduce(lambda acc, item: acc + item["year"], LIBRARY, 0)
print(total)
# Salida: 7849
# ↑ funciona, pero sum(item["year"] for item in LIBRARY) es más claro: úsalo solo
#   para plegados que no tienen función integrada.
# partial: congela argumentos para crear una función nueva
def is_modern(item, kind, min_year):
    return item["kind"] == kind and item["year"] > min_year
modern_books = partial(is_modern, kind="book", min_year=1950)
print([item["title"] for item in LIBRARY if modern_books(item)])
# Salida: ['Dune', 'Fahrenheit 451']

Criterio: usa partial cuando reutilizas la misma función parametrizada (por ejemplo como key o predicate) y quieres nombrarla. Usa reduce solo para plegados que no sean suma/producto/conjunción; para eso ya tienes sum, math.prod, all y any.

3 · Ejemplo mínimo

Tres preguntas mínimas sobre una lista de tuplas, resueltas con funciones integradas.

# (título, año) — una proyección sencilla del catálogo
catalog = [("1984", 1949), ("Dune", 1965), ("Blade Runner", 1982)]
# 1) Ordenar por año
print(sorted(catalog, key=lambda pair: pair[1]))
# Salida: [('1984', 1949), ('Dune', 1965), ('Blade Runner', 1982)]
# 2) ¿Todos se publicaron en el siglo XX?
print(all(year < 2001 for _title, year in catalog))
# Salida: True
# 3) Enumerar con posición
for i, (title, year) in enumerate(catalog, start=1):
    print(f"{i}. {title} ({year})")
# Salida: 1. 1984 (1949)
#         2. Dune (1965)
#         3. Blade Runner (1982)

Línea por línea: en (1) key extrae la segunda posición de cada tupla; en (2) all recorre perezosamente y para en el primer False; en (3) enumerate da la posición y el desempaquetado (title, year) separa la tupla en el mismo for.

4 · Ejemplo real

Un informe del catálogo de Biblioteca: listados ordenados, validación y estadísticas, todo con funciones integradas.

LIBRARY = [
    {"id": "1", "title": "1984", "kind": "book", "year": 1949, "borrowed": False},
    {"id": "2", "title": "Dune", "kind": "book", "year": 1965, "borrowed": True},
    {"id": "3", "title": "Blade Runner", "kind": "movie", "year": 1982, "borrowed": False},
    {"id": "4", "title": "Fahrenheit 451", "kind": "book", "year": 1953, "borrowed": False},
]
# 1) Listado ordenado por tipo y, dentro de cada tipo, por año
listing = sorted(LIBRARY, key=lambda item: (item["kind"], item["year"]))
for position, item in enumerate(listing, start=1):
    print(f"{position:>2}. [{item['kind']:>5}] {item['title']} ({item['year']})")
# Salida:  1. [ book] 1984 (1949)
#          2. [ book] Fahrenheit 451 (1953)
#          3. [ book] Dune (1965)
#          4. [movie] Blade Runner (1982)
# 2) Validación: todo ítem debe tener id, título y año
is_valid = all(
    item.get("id") and item.get("title") and item.get("year")
    for item in LIBRARY
)
print("catálogo válido:", is_valid)
# Salida: catálogo válido: True
# 3) ¿Queda algo disponible?
everything_borrowed = all(item["borrowed"] for item in LIBRARY)
print("no queda nada disponible:", everything_borrowed)
# Salida: no queda nada disponible: False
# 4) Estadísticas: total de años, el más antiguo y el más moderno
oldest = min(LIBRARY, key=lambda item: item["year"])
newest = max(LIBRARY, key=lambda item: item["year"])
print(f"más antiguo: {oldest['title']} ({oldest['year']})")
print(f"más moderno: {newest['title']} ({newest['year']})")
# Salida: más antiguo: 1984 (1949)
#         más moderno: Blade Runner (1982)

Decisiones y por qué: en (1) el key devuelve una tupla (kind, year) para ordenar por dos campos de una vez; en (2) all expresa una validación como un cuantificador y cortocircuita al primer ítem inválido; en (4) min/max con key devuelven el elemento, no la clave.

6 · Errores habituales

1. sorted no muta; sort sí

❌ Incorrecto 
nums = [3, 1, 2]
result = nums.sort()      # ¡mutó nums y devolvió None!
print(result)
# Salida: None
print(nums)
# Salida: [1, 2, 3]
✅ Correcto 
nums = [3, 1, 2]
result = sorted(nums)     # nueva lista, nums intacta
print(result, nums)
# Salida: [1, 2, 3] [3, 1, 2]

2. Cruzar zip con longitudes distintas

❌ Incorrecto 
# zip NO rellena: descarta el sobrante silenciosamente
names = ["1984", "Dune", "Blade Runner"]
years = [1949, 1965]
print(list(zip(names, years)))
# Salida: [('1984', 1949), ('Dune', 1965)]  ← 'Blade Runner' desaparece
✅ Correcto 
# Comprueba las longitudes si la pérdida de datos sería un bug
assert len(names) == len(years), "listas de distinta longitud"
print(list(zip(names, years)))

3. Creer que map/filter devuelven una lista

# ❌ En Python 3 son iteradores perezosos, no listas
result = map(str.upper, ["a", "b"])
print(result)
# Salida: <map object at 0x...>
# ✅ Envuélvelos si necesitas la lista (y podrás recorrerla de nuevo)
print(list(map(str.upper, ["a", "b"])))
# Salida: ['A', 'B']

9 · Resumen

  • sorted con key: una clave por elemento; tuplas para varios criterios; reverse para descendente.
  • Orden estable: los empates conservan el orden previo, permite encadenar ordenaciones.
  • enumerate y zip: índice+valor y recorrido paralelo; zip corta en el más corto.
  • any/all: cuantificadores que cortocircuitan; all([]) == True, any([]) == False.
  • map/filter: perezosos; úsalos con funciones ya hechas, si no, comprehension. functools: partial para congelar argumentos; reduce solo cuando no hay función integrada.

10 · Preguntas frecuentes

¿Cuándo uso sort() y cuándo sorted()?

Usa list.sort() cuando quieras ordenar esa lista y no necesites el original (es ligeramente más eficiente por no copiar). Usa sorted() cuando quieras conservar el original, cuando la fuente no sea una lista (tuplas, dicts, generadores) o cuando quieras asignar el resultado a otra variable. Recuerda: sort() devuelve None», así que x = data.sort() es un bug silencioso.

¿Cómo ordeno ignorando mayúsculas/minúsculas?

Con una clave normalizada: sorted(names, key=str.lower). Para texto con acentos o casefold más agresivo, str.casefold. La clave no tiene por qué ser el valor mismo: es lo que se compara, el valor original se conserva.

¿zip puede rellenar con un valor por defecto en vez de cortar?

Sí, desde Python 3.10 con strict=True lanza error si las longitudes no coinciden (útil para detectar bugs), y desde 3.10 también puedes usar itertools.zip_longest(*its, fillvalue=…) para emparejar hasta el más largo rellenando el hueco. La función zip a secas se queda en el más corto por diseño.

¿any y all evalúan toda la colección?

No: cortocircuitan. all para en el primer valor falsy y any en el primer valor truthy. Por eso son ideales para validaciones y búsquedas sobre generadores: no consumen más de lo necesario. Si les pasas una lista ya construida, el ahorro es de evaluación, no de memoria.
