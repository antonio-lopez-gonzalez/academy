Glosario de Docker y Kubernetes

Referencia 📖 Términos clave

A

Dockerfile
Archivo de texto con las instrucciones para construir una imagen de una sola capa tras otra. Cada instrucción (FROM, RUN, COPY…) produce una capa que se cachea por separado.
apiVersion
Campo de un manifiesto Kubernetes que indica la versión de la API usada (apps/v1 para Deployment, v1 para Pod/Service…). Define qué campos son válidos y cuándo caduca la versión.

B

Buildx
Plugin de Docker basado en BuildKit que permite builds multi-plataforma (linux/amd64, linux/arm64…), caché compartida en registry y builds paralelos.
Bind mount
Montaje que comparte una ruta concreta del host con el contenedor. Rápido y cómodo en desarrollo, pero dependiente del sistema de archivos del host (cuidado con /mnt/c en WSL).

C

Contenedor
Proceso aislado que comparte el kernel del host pero con su propio sistema de archivos, usuarios y red (namespaces) y límites de recursos (cgroups). No es una máquina virtual.
COMPOSE · compose.yaml
Archivo que declara un stack multi-contenedor (servicios, redes, volúmenes) para orquestarlo con el comando docker compose. La infraestructura local como código.
ConfigMap
Objeto de Kubernetes que separa la configuración (env vars o ficheros) de la imagen. Permite cambiar la config sin reconstruir ni redeployar el pod.
Control plane
Conjunto de componentes del clúster que toman las decisiones (kube-apiserver, etcd, scheduler, controller-manager). Son "el cerebro" de Kubernetes; los nodos ejecutan la carga.
CronJob
Recurso de Kubernetes que ejecuta Jobs con una cadencia de cron (schedule: "*/5 * * * *"). Útil para limpiezas, backups o sincronizaciones periódicas.

D

Daemon / daemon Docker
Proceso que gestiona imágenes, contenedores, redes y volúmenes. La CLI (docker) es solo un cliente que le habla por una API REST local.
Deployment
Recurso declarativo de Kubernetes que gestiona ReplicaSets y rollouts: define el estado deseado (imagen, réplicas, probes) y el clúster reconcilia hasta alcanzarlo.

E

ENTRYPOINT
Instrucción del Dockerfile que fija el proceso principal del contenedor. Al combinar ENTRYPOINT (comando) con CMD (argumentos por defecto), los argumentos de docker run reemplazan solo los CMD.
etcd
Base de datos clave-valor distribuida donde Kubernetes guarda todo el estado del clúster. Es la "memoria persistente" del control plane y requiere copias de seguridad.

H

Helm
Gestor de paquetes de Kubernetes. Un chart es un conjunto de plantillas Go y valores (values.yaml) que genera los manifiestos YAML y los instala como una release versionada.
HPA (HorizontalPodAutoscaler)
Recurso que ajusta automáticamente el número de réplicas de un Deployment según métricas (CPU, memoria o métricas personalizadas).

I

Imagen
Plantilla inmutable y lista para ejecutar con el sistema de archivos, dependencias y configuración del proceso. Se construye con un Dockerfile y se distribuye desde registries.
Ingress
Objeto de Kubernetes que expone servicios HTTP/S hacia fuera con reglas de host y path. El tráfico lo enruta un Ingress Controller (p. ej. ingress-nginx).

J

Job
Tarea de Kubernetes que debe completarse (no quedarse corriendo): se relanza si falla (backoffLimit) y permite paralelismo (parallelism). Ideal para migraciones y procesos puntuales.

K

kubectl
CLI principal para hablar con la API de Kubernetes: get, describe, apply, logs, exec, port-forward…
kind (Kubernetes in Docker)
Herramienta que corre un clúster de Kubernetes como contenedores Docker en tu máquina. Ideal para desarrollo, CI y para cerrar el círculo Docker→K8s.
kubelet
Agente que corre en cada nodo: comunica con el API server, arranca y vigila los pods, y reporta salud y estado.

N

Namespace
Mecanismo de agrupación y aislamiento de recursos dentro de un clúster. Separa entornos (dev/prod) o equipos y limita el alcance de permisos (RBAC).
Node / Nodo
Máquina (física, VM o contenedor en kind) que ejecuta pods. Cada nodo corre el kubelet, kube-proxy y un runtime de contenedores.

P

Pod
La unidad mínima de Kubernetes: uno o más contenedores que comparten red y storage. K8s podría reiniciarlo en otro nodo, así que nada de estado dentro del pod.
Probe
Chequeo periódico que hace el kubelet: liveness (¿sigo vivo? releer el pod si no), readiness (¿listo para recibir tráfico?), startup (arranques lentos).
PVC / PV
PersistentVolumeClaim: petición de almacenamiento. PersistentVolume: pieza de almacenamiento disponible en el clúster. El claim se engancha a un volumen.

R

Registry
Servidor que almacena y sirve imágenes (Docker Hub, GHCR, ECR…). Las imágenes se etiquetan con registry/usuario/imagen:tag.
RBAC
Control de acceso basado en roles: quién (ServiceAccount) puede hacer qué (Role/ClusterRole) sobre qué recursos, mediante bindings.
ReplicaSet
Garantiza que haya siempre el número deseado de pods idénticos. Lo usa internamente el Deployment; no se suele crear a mano.
Rolling update
Actualización progresiva de un Deployment: los pods nuevos suben mientras los viejos bajan, sin downtime (controlado por readiness y maxSurge/maxUnavailable).

S

Secret
Como un ConfigMap pero para datos sensibles (contraseñas, tokens). Se codifica en Base64, que NO es cifrado: hay que limitar acceso y usar gestores externos en producción.
Service
Dirección estable y DNS (ClusterIP) que apunta a un conjunto de pods seleccionados por etiqueta, repartiendo el tráfico (ClusterIP, NodePort, LoadBalancer).

V

Volumen
Almacenamiento gestionado por Docker (en /var/lib/docker/volumes o en la VM de Docker Desktop) que sobrevive al contenedor. La forma recomendada de persistir datos.
Vista declarativa / reconciliación
K8s no ejecuta comandos imperativos: tú declaras el estado deseado y los controllers comparan con el estado real, arreglando la diferencia en el control loop.

W

WSL2
Sistema WSL de segunda generación en Windows: una VM ligera con un kernel Linux real. Docker Desktop lo usa para correr contenedores Linux en Windows, y es el entorno recomendado para este curso en Windows.
