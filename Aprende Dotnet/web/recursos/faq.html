FAQ general del curso

Recurso

En esta página respondemos las preguntas más frecuentes sobre el curso, la instalación, las tecnologías de .NET 8 y recomendaciones de aprendizaje. Si no encuentras tu duda, repasa el módulo correspondiente o pregunta en el foro de la comunidad.

Instalación y entorno

¿Cómo sé si tengo instalado .NET 8?

Abre una terminal y ejecuta:

dotnet --version

Debe mostrar un número que empieza por 8., por ejemplo 8.0.303. Si no, descarga el SDK desde la web oficial de Microsoft.

¿Puedo seguir el curso en Linux o macOS?

Sí. .NET 8 es multiplataforma. En el curso usamos Visual Studio Code o Rider, y la CLI de dotnet, que funcionan en Windows, Linux y macOS. Algunos atajos de teclado de VS Code pueden variar, pero los comandos son idénticos.

Visual Studio Code me dice que no encuentra el SDK

Posibles causas:

  • No has reiniciado la terminal después de instalar el SDK.
  • La variable de entorno PATH no incluye la carpeta de dotnet.
  • Tienes instalado el runtime pero no el SDK.

Verifica con dotnet --list-sdks y reinicia VS Code.

¿Necesito instalar Docker para todo el curso?

No para los primeros módulos. Docker se usa a partir del módulo de Entity Framework Core (PostgreSQL) y se vuelve imprescindible en el módulo de despliegue. Instálalo cuando llegues a esas lecciones.

Tecnologías y cuándo usarlas

¿Minimal APIs o Controller-based APIs?

Minimal APIs: ideales para microservicios pequeños, funciones serverless y endpoints muy concretos. Menos ceremonia, más velocidad.

Controller-based: mejor para APIs grandes con muchos endpoints, filtros, versionado y estructura de equipo. El curso enseña ambas para que elijas con criterio.

¿Cuándo usar Entity Framework Core y cuándo SQL directo?

Usa EF Core para el 90 % de las operaciones CRUD y consultas que se mapean bien a objetos. Reserva SQL crudo o Dapper para consultas muy complejas, reportes masivos o hot paths donde el SQL generado no es óptimo.

¿Por qué PostgreSQL y no SQL Server?

PostgreSQL es open source, funciona igual en local y en la nube, y tiene un excelente provider para EF Core con Npgsql. Además, se integra muy bien con contenedores Linux, que es el entorno de despliegue más común hoy en día.

¿Debo usar AutoMapper o mapeo manual?

Para proyectos grandes con muchos DTOs, AutoMapper ahorra código repetitivo. Para proyectos pequeños o críticos, el mapeo manual (métodos de extensión o constructores) es más explícito y fácil de depurar. El curso muestra ambos enfoques.

¿Cuándo usar Redis?

Redis brilla en caching distribuido, sesiones compartidas entre instancias, backplane de SignalR y rate limiting distribuido. No lo uses como base de datos primaria para datos transaccionales complejos.

Carrera y trayectoria profesional

¿Vale la pena aprender .NET en 2026?

Sí. .NET 8 es LTS, multiplataforma y muy utilizado en empresas medianas y grandes para backend, APIs, microservicios y cloud. La demanda de desarrolladores .NET senior sigue siendo alta y bien remunerada.

¿Necesito saber C# antes de aprender ASP.NET Core?

Es recomendable. ASP.NET Core se escribe en C# y aprovecha conceptos como LINQ, async/await, genéricos y POO. Si saltas directamente a la API, entenderás la superficie pero no el "porqué" de las decisiones de diseño.

¿Qué diferencia a un desarrollador junior de uno senior en .NET?

Un senior suele dominar:

  • Diseño de software: SOLID, patrones, arquitectura limpia.
  • Diagnóstico de problemas: logs, métricas, trazas, profiling.
  • Operación: Docker, CI/CD, observabilidad, seguridad.
  • Decisiones técnicas con contexto de negocio y equipo.

Versiones de .NET

¿Cuál es la diferencia entre .NET Framework, .NET Core y .NET 8?

.NET Framework es el runtime antiguo, ligado a Windows. .NET Core fue la reescritura multiplataforma. .NET 5, 6, 7 y 8 son la evolución unificada: .NET 8 es LTS, con soporte extendido y las últimas mejoras de rendimiento.

¿Debo actualizar a .NET 9 cuando salga?

Para aprender, prueba la nueva versión en proyectos personales. Para producción, evalúa el ciclo de vida: las versiones LTS (.NET 6, 8, 10...) suelen ser más seguras para sistemas críticos. Las versiones STS (.NET 7, 9...) caducan antes.

Herramientas y productividad

¿Visual Studio Code o Rider?

VS Code es gratuito, ligero y muy configurable. Rider de JetBrains es de pago, pero ofrece refactorizaciones, navegación de código y análisis estático superiores. Ambos son válidos para el curso.

¿Qué extensiones recomiendas para VS Code?
  • C# Dev Kit (depuración, IntelliSense, tests).
  • NuGet Gallery (gestión de paquetes).
  • EditorConfig for VS Code (formato consistente).
  • Docker (si usas contenedores).

Debugging y diagnóstico

Mi aplicación se cuelga al hacer una llamada HTTP

Revisa estos puntos:

  • No uses .Result o .Wait() en código asíncrono.
  • Configura timeouts en HttpClient.
  • Usa HttpClientFactory para evitar agotar sockets.
  • Activa logs de System.Net.Http para ver la petición.
¿Cómo depuro lentitud en consultas de EF Core?

Usa var sql = query.ToQueryString(); para ver el SQL generado, activa el logging sensible a datos en desarrollo y revisa el problema N+1 con Include o proyecciones selectivas.

Rendimiento y optimización

¿Cómo mejoro el rendimiento de una API?
  1. Mide primero: no optimices sin datos.
  2. Usa AsNoTracking() para consultas de solo lectura.
  3. Implementa caching (memoria o Redis).
  4. Reduce al mínimo las columnas con proyecciones Select.
  5. Usa paginación obligatoria en listados.
  6. Comprime respuestas y habilita output caching.
¿Qué herramientas uso para medir rendimiento?

BenchmarkDotNet para comparar microbenchmarks, dotnet-counters para métricas en tiempo real, dotnet-trace para perfiles de CPU y memoria, y OpenTelemetry para trazas distribuidas en producción.

Ruta de aprendizaje

¿En qué orden debo estudiar los módulos?

Sigue el orden propuesto: primero fundamentos de C#, luego POO y SOLID, después arquitectura, EF Core, ASP.NET Core, testing y finalmente producción. El proyecto CMS se construye incrementalmente, por lo que saltar módulos puede dejarlo inconsistente.

¿Debo hacer todos los ejercicios?

Al menos intenta el ejercicio guiado y el reto de cada lección. No es necesario resolver todos los retos a la perfección, pero el esfuerzo activo acelera mucho más el aprendizaje que solo leer o copiar código.

¿Cuánto tiempo debo dedicar al curso?

Depende de tu ritmo. Una estimación conservadora es 5-8 horas semanales: ver la teoría, escribir el código, resolver el ejercicio y revisar el proyecto CMS.
