Encapsulación

Módulo 2 · POO en C# 40 minutos

1 · Introducción

Imagina que cualquiera pudiera escribir en el Saldo de tu cuenta bancaria directamente. Nada impediría poner Saldo = -5000. La encapsulación es el pilar de la POO que protege el estado interno de un objeto, exponiendo solo una API segura.

Objetivo

Ocultar el estado interno, entender los modificadores de acceso y diseñar APIs de clase seguras.

2 · Teoría

¿Qué es la encapsulación?

Es ocultar el estado interno y la implementación, exponiendo solo lo que el mundo exterior necesita. El objeto controla cómo se modifica su estado.

Modificadores de acceso

ModificadorVisible desde
publicCualquier código
privateSolo dentro de la misma clase
protectedLa clase y sus derivadas
internalTodo el proyecto/ensamblado actual
protected internalDerivadas O mismo ensamblado
private protectedDerivadas Y mismo ensamblado

Los tres primeros son los que más usarás. internal y combinados aparecen en librerías y proyectos grandes.

Campos privados y setters privados

class CuentaBancaria
{
    private decimal _saldo;          // campo privado: nadie lo toca directamente

    public decimal Saldo
    {
        get => _saldo;
        private set => _saldo = value;   // solo la propia clase puede asignar
    }

    // Métodos públicos para modificar el estado de forma segura
    public void Depositar(decimal cantidad)
    {
        if (cantidad <= 0) throw new ArgumentException("Cantidad inválida");
        Saldo += cantidad;
    }

    public void Retirar(decimal cantidad)
    {
        if (cantidad > Saldo) throw new InvalidOperationException("Saldo insuficiente");
        Saldo -= cantidad;
    }
}

El usuario de la clase no puede hacer Saldo = -5000; debe usar Retirar(500), que valida el estado.

Diseñar APIs de clase

Regla de oro

Haz private todo lo interno y expón public solo los métodos/propiedades que el consumidor necesita. El estado cambia siempre a través de métodos que validan.

// Evitar (estado expuesto):
// persona.Saldo = -5000;

// Preferir (método que valida):
// persona.Retirar(500);

3 · Ejemplo mínimo

class Contador
{
    public int Valor { get; private set; }   // lectura pública, escritura privada

    public void Incrementar() => Valor++;
}

var c = new Contador();
c.Incrementar();
c.Incrementar();
Console.WriteLine(c.Valor);   // 2
// c.Valor = 10;              // Error: setter privado

4 · Ejemplo real

Un Usuario cuyo email debe ser válido, protegido por encapsulación:

class Usuario
{
    private string _email = "";

    public string Email
    {
        get => _email;
        private set
        {
            if (!value.Contains('@'))
                throw new ArgumentException("Email inválido");
            _email = value;
        }
    }

    public Usuario(string email)
    {
        Email = email;   // pasa por la validación del setter
    }
}

var usuario = new Usuario("ana@mail.com");
Console.WriteLine(usuario.Email);   // ana@mail.com

6 · Errores habituales

Error 1: exponer setters públicos sin validar

// Incorrecto: cualquiera puede poner un estado inválido
public decimal Saldo { get; set; }

// Correcto
public decimal Saldo { get; private set; }

Error 2: campos públicos

// Incorrecto
// public decimal Saldo;

// Correcto: usa propiedad o campo privado

Error 3: validar fuera de la clase

// Incorrecto: la validación la repite cada consumidor
// if (cuenta.Saldo >= 500) cuenta.Saldo -= 500;

// Correcto: la clase valida internamente
cuenta.Retirar(500);

9 · Resumen

  • Encapsulación = ocultar estado e implementación.
  • Modificadores: public, private, protected, internal.
  • Campos privados + propiedades/setters privados.
  • El estado cambia mediante métodos que validan.

10 · Preguntas frecuentes

¿Por qué no dejar todo público?

Porque pierdes el control del estado: cualquier código podría dejarlo inconsistente. La encapsulación concentra la validación en un solo lugar.

¿Qué es internal?

Visible dentro del mismo proyecto (ensamblado), pero no desde otros. Útil para clases internas de una librería.

¿Setter privado es encapsulación?

Sí: permite leer el estado pero solo modificarlo a través de los métodos públicos de la clase.
