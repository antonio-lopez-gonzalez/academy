Records y POO moderna

Módulo 2 · POO en C# 40 minutos

1 · Introducción

Muchas clases solo existen para transportar datos: DTOs, resultados, configuraciones. Para esos casos, C# tiene los records: tipos pensados para la inmutabilidad y la igualdad por valor, con muy poco código.

Objetivo

Crear records, entender su igualdad por valor y usar with para copias inmutables.

2 · Teoría

¿Qué es un record?

Un record es un tipo de referencia (o de valor, con record struct) que añade automáticamente:

  • Igualdad por valor (dos records con los mismos datos son iguales).
  • Inmutabilidad por convención (con propiedades init).
  • Un método ToString() legible.
public record Persona(string Nombre, int Edad);

var a = new Persona("Ana", 30);
var b = new Persona("Ana", 30);

Console.WriteLine(a == b);     // True (igualdad por valor)
Console.WriteLine(a);          // Persona { Nombre = Ana, Edad = 30 }

record class vs record struct

record classrecord struct
TipoReferencia (heap)Valor (stack)
IgualdadPor valorPor valor
UsoDTOs, modelosDatos pequeños y efímeros

record es equivalente a record class.

Inmutabilidad y with

Los records son inmutables: para "modificar", creas una copia con los cambios usando with:

public record Persona(string Nombre, int Edad);

var ana = new Persona("Ana", 30);

// with crea una copia modificada (ana NO cambia)
var anaMayor = ana with { Edad = 31 };

Console.WriteLine(ana.Edad);        // 30
Console.WriteLine(anaMayor.Edad);   // 31

Records vs clases

classrecord
IgualdadReferenciaValor
MutabilidadMutableInmutable por convención
IdentidadSí (entidades)No (valores)
Regla de oro

Usa record para valores (DTOs, value objects) y class para entidades con identidad (un cliente concreto).

DTOs y Value Objects

  • DTO (Data Transfer Object): objeto que solo transporta datos entre capas. Ideal para records.
  • Value Object: objeto sin identidad definida por sus valores (ej. Dinero, Direccion). Los records los modelan de forma natural.
// DTO
public record CrearUsuarioRequest(string Nombre, string Email, int Edad);

// Value Object
public record Dinero(decimal Cantidad, string Moneda);

3 · Ejemplo mínimo

public record Persona(string Nombre, int Edad);

var p = new Persona("Ana", 30);
Console.WriteLine(p);   // Persona { Nombre = Ana, Edad = 30 }

4 · Ejemplo real

Usar records como DTOs y value objects en un caso real:

// Value object inmutable
public record Direccion(string Calle, string Ciudad, string CodigoPostal);

// DTO de respuesta
public record UsuarioResponse(int Id, string Nombre, Direccion Direccion);

var casa = new Direccion("Calle Mayor 1", "Madrid", "28001");
var usuario = new UsuarioResponse(1, "Ana", casa);

// Copia con dirección modificada
var usuarioMudado = usuario with
{
    Direccion = casa with { Ciudad = "Barcelona" }
};

Console.WriteLine(usuarioMudado);

9 · Resumen

  • record = tipo con igualdad por valor e inmutabilidad.
  • record class (referencia) vs record struct (valor).
  • with crea copias modificadas.
  • Ideales para DTOs y value objects.

10 · Preguntas frecuentes

¿Un record puede heredar?

Los record class sí pueden heredar de otros records. Los record struct no (son tipos de valor).

¿Cuándo no usar records?

Cuando el objeto tiene identidad propia, es mutable por diseño o necesita herencia de clases normales.

¿Los records son solo para DTOs?

No, también para value objects, configuraciones, resultados de operaciones y cualquier dato inmutable.
