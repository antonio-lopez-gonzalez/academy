Hubs, Groups y Connections

Módulo 14 · Tiempo real30 min

1 · Introducción

En la lección anterior vimos cómo enviar mensajes a todos los clientes conectados. En la mayoría de aplicaciones reales necesitas dirigirte a un conjunto más específico: a un usuario concreto, a una sala de chat, a los editores de un CMS o a los administradores.

En esta lección aprenderemos a usar groups y connections para segmentar a los clientes. También veremos cómo identificar usuarios mediante claims y cómo asociar un ConnectionId con un usuario autenticado.

¿Qué problema resuelve?

Permite enviar notificaciones selectivas sin mantener una lista manual de clientes. SignalR gestiona internamente qué conexiones pertenecen a cada grupo o usuario, incluso cuando un usuario tiene varias pestañas abiertas.

Errores típicos

  • Guardar ConnectionId en base de datos pensando que es estable para siempre.
  • Asumir que un usuario tiene una sola conexión; puede tener múltiples dispositivos o pestañas.
  • Enviar a un grupo sin haber añadido nunca al usuario a ese grupo.
  • Intentar usar Context.User sin haber configurado autenticación en el hub.

2 · Teoría

Contexto del hub

Cada instancia del hub tiene una propiedad Context de tipo HubCallerContext que ofrece información sobre la conexión actual:

  • Context.ConnectionId: identificador único de la conexión actual. Cambia en cada reconexión.
  • Context.User: el ClaimsPrincipal del usuario autenticado, si la autenticación está configurada.
  • Context.UserIdentifier: el identificador de usuario que SignalR usa por defecto (claim NameIdentifier).
  • Context.Items: diccionario de objetos por conexión, útil para cachear datos temporales.

¿Cómo funciona un grupo?

SignalR mantiene un diccionario interno grupo → lista de connectionIds. Cuando llamas a Groups.AddToGroupAsync(connectionId, "nombre"), la conexión se añade a la lista. Luego, Clients.Group("nombre") envía el mensaje a todas las conexiones de esa lista. Los grupos son volátiles: si una conexión se cierra, SignalR la elimina automáticamente.

Autenticación en hubs

Los hubs pueden usar el mismo middleware de autenticación JWT que el resto de la API. El token se envía generalmente en la query string de la conexión SignalR porque los navegadores no permiten cabeceras personalizadas en el handshake de WebSockets.

Consejo de diseño

Preferir Clients.User(userId) sobre Clients.Client(connectionId) cuando quieres llegar al usuario, no a la conexión. Así cubres múltiples dispositivos y reconexiones automáticas.

3 · Ejemplo mínimo

Crearemos un hub de chat con salas. El cliente se une a una sala y solo los miembros de esa sala reciben los mensajes.

dotnet new web -n RoomsDemo -o RoomsDemo
cd RoomsDemo
dotnet run --project .
RoomsHub.cs
using Microsoft.AspNetCore.SignalR;

public sealed class RoomsHub : Hub
{
    public async Task JoinRoom(string roomName)
    {
        // Añade la conexión actual al grupo
        await Groups.AddToGroupAsync(Context.ConnectionId, roomName);
        await Clients.Group(roomName).SystemMessage($"{Context.ConnectionId} se unió a {roomName}");
    }

    public async Task LeaveRoom(string roomName)
    {
        await Groups.RemoveFromGroupAsync(Context.ConnectionId, roomName);
        await Clients.Group(roomName).SystemMessage($"{Context.ConnectionId} salió de {roomName}");
    }

    public async Task SendToRoom(string roomName, string user, string message)
    {
        // Solo los miembros del grupo reciben el mensaje
        await Clients.Group(roomName).ReceiveMessage(user, message);
    }

    public async Task SendToUser(string userId, string message)
    {
        // Envía a todas las conexiones de ese usuario
        await Clients.User(userId).ReceiveMessage("Sistema", message);
    }
}

public interface IRoomClient
{
    Task ReceiveMessage(string user, string message);
    Task SystemMessage(string message);
}
Program.cs
var builder = WebApplication.CreateBuilder(args);
builder.Services.AddSignalR();

app.Run();

¿Qué ocurre aquí?

El cliente se une al grupo "dotnet". El servidor añade su ConnectionId al grupo. Cualquier mensaje enviado a Clients.Group("dotnet") llega a todas las conexiones de ese grupo, sin importar en qué servidor estén (si hay backplane).

4 · Ejemplo real

En una aplicación con autenticación JWT, los usuarios se identifican por claims. Configuramos SignalR para leer el token de la query string y usamos grupos por roles.

Program.cs
using Microsoft.AspNetCore.Authentication.JwtBearer;
using Microsoft.IdentityModel.Tokens;
using System.Text;

var builder = WebApplication.CreateBuilder(args);

builder.Services.AddAuthentication(JwtBearerDefaults.AuthenticationScheme)
    .AddJwtBearer(options =>
    {
        options.TokenValidationParameters = new TokenValidationParameters
        {
            ValidateIssuer = true,
            ValidateAudience = true,
            ValidateLifetime = true,
            ValidateIssuerSigningKey = true,
            ValidIssuer = "CmsIssuer",
            ValidAudience = "CmsAudience",
            IssuerSigningKey = new SymmetricSecurityKey(Encoding.UTF8.GetBytes("clave-super-secreta-de-32-caracteres!")
        };

        // WebSockets no permite cabeceras personalizadas, así que leemos el token de la query
        options.Events = new JwtBearerEvents
        {
            OnMessageReceived = context =>
            {
                var accessToken = context.Request.Query["access_token"];
                if (!string.IsNullOrEmpty(accessToken))
                {
                    context.Token = accessToken;
                }
                return Task.CompletedTask;
            }
        };
    });

builder.Services.AddAuthorization();
builder.Services.AddSignalR();

var app = builder.Build();
app.UseAuthentication();
app.UseAuthorization();

app.MapHub("/hubs/authenticated")
   .RequireAuthorization();

app.Run();

public sealed class AuthenticatedHub : Hub
{
    public async Task JoinRoleGroup(string role)
    {
        if (Context.User?.IsInRole(role) != true)
        {
            throw new HubException("No tienes el rol necesario para unirte a este grupo.");
        }

        await Groups.AddToGroupAsync(Context.ConnectionId, role);
        await Clients.Group(role).MemberJoined(Context.User?.Identity?.Name ?? "anónimo", role);
    }

    public async Task NotifyRole(string role, string title, string body)
    {
        await Clients.Group(role).ReceiveNotification(title, body);
    }

    public async Task NotifyCurrentUser(string message)
    {
        // UserIdentifier por defecto es el claim NameIdentifier
        var userId = Context.UserIdentifier;
        await Clients.User(userId).ReceiveNotification("Privado", message);
    }
}

public interface IAuthClient
{
    Task ReceiveNotification(string title, string body);
    Task MemberJoined(string userName, string group);
}
Cliente JavaScript con token
const token = localStorage.getItem("access_token");

const connection = new signalR.HubConnectionBuilder()
    .withUrl("/hubs/authenticated?access_token=" + encodeURIComponent(token))
    .withAutomaticReconnect()

await connection.invoke("NotifyRole", "Editor", "Nuevo artículo", "Se ha publicado un post.");

Seguridad del token en query string

Es seguro si usas WSS (WebSocket seguro) o HTTPS. Sin embargo, el token puede quedar en logs de servidor o proxy. Alternativas: usar SSE/Long Polling donde sí puedes enviar cabeceras, o un endpoint de negociación que cree un cookie segura.

5 · Buenas prácticas

  • Identifica por usuario, no por conexión. Usa Clients.User(...) para notificaciones personales; así cubres múltiples sesiones.
  • Valida antes de unir a un grupo. No permitas que un cliente se una a cualquier grupo; verifica roles, suscripciones o permisos.
  • Usa nombres de grupo predecibles y seguros. Evita concatenar datos del usuario sin sanitizar; podría permitir unirse a grupos ajenos.
  • No almacenes ConnectionId como clave primaria. Es efímero; si necesitas persistir, guarda el userId y el timestamp.
  • Protege los hubs con autorización. Un hub abierto puede filtrar datos si olvidas RequireAuthorization o [Authorize].
  • Maneja HubException. Cuando lances una excepción de negocio, usa HubException para controlar el mensaje que llega al cliente.

6 · Errores habituales

6.1. Enviar a un grupo sin verificar membresía

Incorrecto
public async Task JoinRoom(string roomName)
{
    // Cualquiera puede unirse a cualquier sala
    await Groups.AddToGroupAsync(Context.ConnectionId, roomName);
}
Correcto
public async Task JoinRoom(string roomName)
{
    if (!await _roomService.CanJoin(Context.UserIdentifier, roomName))
    {
        throw new HubException("No tienes acceso a esta sala.");
    }

    await Groups.AddToGroupAsync(Context.ConnectionId, roomName);
}

6.2. Usar ConnectionId como identificador de usuario

Incorrecto
public async Task SendToUser(string connectionId, string message)
{
    await Clients.Client(connectionId).ReceiveMessage(message);
}
Correcto
public async Task SendToUser(string userId, string message)
{
    await Clients.User(userId).ReceiveMessage(message);
}

6.3. Olvidar que Context.User puede ser null

Incorrecto
public async Task JoinAdminGroup()
{
    if (Context.User.IsInRole("Admin")) { ... }
}
Correcto
public async Task JoinAdminGroup()
{
    if (Context.User?.IsInRole("Admin") == true) { ... }
}

7 · Ejercicio guiado

Crea un hub de "notificaciones por equipo". Cada usuario pertenece a un equipo que lee de un servicio. Al conectarse, el usuario se une automáticamente al grupo de su equipo. Solo los usuarios del mismo equipo reciben mensajes.

TeamNotificationHub.cs
using Microsoft.AspNetCore.SignalR;

public sealed class TeamNotificationHub : Hub
{
    private readonly ITeamService _teamService;

    public TeamNotificationHub(ITeamService teamService)
    {
        _teamService = teamService;
    }

    public override async Task OnConnectedAsync()
    {
        var userId = Context.UserIdentifier;
        if (string.IsNullOrEmpty(userId))
        {
            throw new HubException("Usuario no autenticado.");
        }

        var teamId = await _teamService.GetTeamIdAsync(userId);
        if (!string.IsNullOrEmpty(teamId))
        {
            await Groups.AddToGroupAsync(Context.ConnectionId, teamId);
            // Guardamos el equipo en Items para usarlo en OnDisconnectedAsync
            Context.Items["TeamId"] = teamId;
        }

        await base.OnConnectedAsync();
    }

    public override async Task OnDisconnectedAsync(Exception? exception)
    {
        if (Context.Items.TryGetValue("TeamId", out var teamId) && teamId is string team)
        {
            await Groups.RemoveFromGroupAsync(Context.ConnectionId, team);
        }

        await base.OnDisconnectedAsync(exception);
    }

    public async Task NotifyTeam(string title, string body)
    {
        if (Context.Items.TryGetValue("TeamId", out var teamId) && teamId is string team)
        {
            await Clients.Group(team).TeamNotification(title, body);
        }
    }
}

public interface ITeamClient
{
    Task TeamNotification(string title, string body);
}

public interface ITeamService
{
    Task GetTeamIdAsync(string userId);
}

¿Por qué almacenar TeamId en Context.Items?

En OnDisconnectedAsync no deberías volver a consultar el servicio porque el usuario ya no está en el contexto operativo. Guardar el valor en Items asegura que puedas eliminarlo del grupo correctamente al desconectarse.

8 · Reto

Reto: historial de presencia

Implementa un servicio que rastree quién está conectado en cada sala. Cuando un usuario se une, el servidor le envía la lista de usuarios actualmente en la sala. Considera cómo evitarías duplicados si un usuario tiene dos pestañas abiertas.

9 · Resumen

  • Context.ConnectionId identifica una conexión efímera; Context.UserIdentifier identifica al usuario.
  • Clients.User(userId) envía a todas las conexiones de ese usuario.
  • Los grupos son colecciones de conexiones gestionadas por SignalR; se usan para salas, canales o equipos.
  • Usa Groups.AddToGroupAsync y Groups.RemoveFromGroupAsync para gestionar membresía.
  • Protege los métodos de unión a grupos con autorización y validación de negocio.
  • El token JWT en SignalR se envía típicamente por query string debido a las limitaciones de WebSockets.

10 · Preguntas frecuentes

¿Un usuario con dos pestañas recibe dos veces el mismo mensaje?

Si usas Clients.User(userId), SignalR envía el mensaje a cada conexión de ese usuario. Por tanto, sí, dos pestañas recibirán dos mensajes. Si quieres deduplicación, debe hacerse en el cliente o usando un identificador de mensaje.

¿Qué pasa si el servidor se reinicia mientras hay grupos?

Los grupos se almacenan en memoria por defecto. Al reiniciar se pierden. Los clientes intentan reconectar automáticamente con withAutomaticReconnect, pero deben volver a unirse a los grupos porque OnConnectedAsync se vuelve a ejecutar.

¿Puedo usar roles para enviar a grupos?

Sí, pero no de forma nativa. Debes crear un grupo por rol (p. ej. "role-admin") y añadir a los usuarios cuando se conectan. Luego envías a Clients.Group("role-admin").

¿Los grupos distinguen mayúsculas y minúsculas?

Sí, los nombres de grupo son sensibles a mayúsculas. Normaliza siempre los nombres (p. ej. .ToLowerInvariant()) o usa identificadores como GUIDs.

¿Cómo evito que un cliente se una a un grupo que no le pertenece?

Valida en el servidor antes de llamar a AddToGroupAsync. No confíes en el nombre enviado por el cliente; consulta la base de datos o los claims.
