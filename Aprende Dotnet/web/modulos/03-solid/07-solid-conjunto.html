Cómo aplicar SOLID conjuntamente

Módulo 3 · SOLID en C# 40 minutos

1 · Introducción

Los cinco principios no se aplican de uno en uno: se refuerzan entre sí. En esta lección vemos cómo se relacionan, y —muy importante— qué NO significa SOLID para no caer en la sobre-ingeniería.

Objetivo

Ver SOLID como un sistema, evitar sus malas interpretaciones y conocer principios complementarios.

2 · Teoría

Cómo se relacionan los principios

CombinaciónCómo se apoyan
SRP + OCPClases con una responsabilidad son más fáciles de extender sin modificar
OCP + polimorfismoEl polimorfismo es la herramienta para extender sin tocar
LSP + herenciaSolo hereda si la derivada sustituye correctamente a la base
ISP + diseño de interfacesInterfaces pequeñas = contratos claros y sin sobrantes
DIP + Dependency InjectionDepender de abstracciones se materializa inyectándolas

En conjunto buscan alta cohesión y bajo acoplamiento, mediante abstracciones, composición y diseño orientado a interfaces.

Qué NO significa SOLID

Malas interpretaciones frecuentes
  • NO significa crear una interfaz para cada clase.
  • NO significa clases de 5 líneas obligatoriamente.
  • NO significa eliminar todos los if.
  • NO significa evitar completamente la herencia.
  • NO significa crear abstracciones para todo.
  • NO significa usar patrones de diseño "porque sí".

SOLID es un criterio de diseño, no una lista de reglas absolutas.

Principios complementarios

PrincipioSignificado
KISSKeep It Simple, Stupid: hazlo lo más simple posible
DRYDon't Repeat Yourself: no dupliques código
YAGNIYou Aren't Gonna Need It: no construyas lo que no necesitas
Separation of ConcernsSepara responsabilidades en módulos distintos
Composition over InheritancePrefiere composición a herencia

4 · Ejemplo real

Una clase que aplica varios principios a la vez de forma natural:

// SRP: una responsabilidad (crear pedidos, orquestando)
// DIP: depende de abstracciones, no de concreciones
// OCP: acepta cualquier IDescuento sin modificar
class CrearPedidoService
{
    private readonly IPedidoRepository _repository;
    private readonly INotificador _notificador;

    public CrearPedidoService(IPedidoRepository repository, INotificador notificador)
    {
        _repository = repository;
        _notificador = notificador;
    }

    public void Ejecutar(Pedido pedido, IDescuento descuento)
    {
        pedido.Aplicar(descuento);
        _repository.Guardar(pedido);
        _notificador.Notificar(pedido.Cliente, "Pedido creado");
    }
}

8 · Reto

Reto

Explica con un ejemplo cómo una violación de LSP puede hacer que DIP no funcione bien, y por qué los principios se necesitan mutuamente.

9 · Resumen

  • SOLID es un sistema: los principios se refuerzan.
  • Busca alta cohesión y bajo acoplamiento.
  • No es un dogma: evita la sobre-ingeniería.
  • Complementa con KISS, DRY, YAGNI y Separation of Concerns.

10 · Preguntas frecuentes

¿Puedo violar SOLID a veces?

Sí, con criterio. Si un if/else simple es más claro que 5 clases, úsalo. SOLID es una guía para sistemas que crecen, no una camisa de fuerza.

¿Qué es KISS?

"Mantenlo simple". Diseña la solución más simple que resuelva el problema, sin complejidad innecesaria.

¿Qué es YAGNI?

"No lo vas a necesitar": no construyas funcionalidad o abstracciones especulativas hasta que realmente hagan falta.
