Introducción a SOLID

Módulo 3 · SOLID en C# 35 minutos

1 · Introducción

Ya sabes escribir clases. Ahora el reto es diseñarlas para que el código sea mantenible, extensible y testeable. SOLID es un conjunto de cinco principios de diseño que te guían para conseguirlo.

Objetivo

Entender qué es SOLID, por qué importa, y los conceptos de cohesión, acoplamiento y code smells.

2 · Teoría

¿Qué es SOLID?

Es un acrónimo de cinco principios de diseño orientado a objetos, formulados por Robert C. Martin ("Uncle Bob") a principios de los 2000:

LetraPrincipioIdea central
SSingle ResponsibilityUna clase, una razón de cambio
OOpen/ClosedAbierto a extensión, cerrado a modificación
LLiskov SubstitutionDerivadas sustituibles por su base
IInterface SegregationInterfaces pequeñas y específicas
DDependency InversionDepender de abstracciones

¿Por qué importa SOLID?

Porque el coste real del software está en mantenerlo, no en escribirlo. SOLID produce código:

  • Mantenible: fácil de entender y cambiar.
  • Extensible: añadir funcionalidad sin romper lo existente.
  • Testeable: piezas aisladas que se pueden probar.

Cohesión y acoplamiento

  • Cohesión: cuán relacionadas están las responsabilidades dentro de un módulo. Quieres cohesión alta.
  • Acoplamiento: cuánto depende un módulo de otros. Quieres acoplamiento bajo.
La meta

Alta cohesión + bajo acoplamiento = código fácil de mantener. SOLID es el camino para lograrlo.

Dependencias y code smells

Un code smell es un síntoma de mal diseño: clases gigantes ("god classes"), métodos kilométricos, cadenas de if/else, dependencias rígidas. SOLID te da criterio para detectarlos y corregirlos.

Refactoring

Es el proceso de mejorar el diseño del código sin cambiar su comportamiento. Aplicar SOLID casi siempre implica refactorizar.

3 · Ejemplo mínimo

// Code smell: una clase que hace demasiado
class PedidoService
{
    public void CrearPedido() { /* valida + guarda + envía email + loggea */ }
}

El resto del módulo te enseñará a dividirla en piezas cohesivas y desacopladas.

4 · Ejemplo real

Los síntomas típicos de un diseño sin SOLID, que verás refactorizados a lo largo del módulo:

class Reporte
{
    public void Generar(string tipo)
    {
        if (tipo == "PDF") { /* ... */ }
        else if (tipo == "Excel") { /* ... */ }
        else if (tipo == "Word") { /* ... */ }
        // Cada tipo nuevo obliga a MODIFICAR esta clase (viola OCP)
    }
}

9 · Resumen

  • SOLID = 5 principios de diseño orientado a objetos.
  • Busca mantenibilidad, extensibilidad y testeabilidad.
  • Claves: alta cohesión, bajo acoplamiento.
  • Code smells señalan dónde refactorizar.

10 · Preguntas frecuentes

¿SOLID es obligatorio?

No es una ley, sino guías. Aplicadas con criterio mejoran el diseño; aplicadas a ciegas pueden sobre-ingenierar.

¿Qué es un code smell?

Un indicio de que algo está mal diseñado (métodos largos, clases gigantes, duplicación). No es un bug, pero sugiere refactoring.

¿Qué es refactoring?

Cambiar la estructura interna del código para mejorar su diseño, sin alterar su comportamiento externo.
