Asincronía: async y await

Módulo 1 · Fundamentos de C# 50 minutos

1 · Introducción

Muchas operaciones son lentas: leer un archivo, consultar una API, acceder a una base de datos. Si las haces de forma síncrona, tu programa se queda "congelado" esperando. La asincronía permite lanzar la operación y seguir trabajando mientras llega el resultado.

Si vienes de JavaScript, async/await te sonará a Promises; si vienes de Python, a asyncio.

Objetivo

Entender Task, escribir métodos async, y manejar múltiples tareas y cancelación.

2 · Teoría

El problema: síncrono vs asíncrono

// Síncrono: el hilo se bloquea esperando
Console.WriteLine("Leyendo...");
string datos = LeerArchivoGrande();   // bloquea hasta terminar
Console.WriteLine("Terminado");

// Asíncrono: no bloquea; devuelve una Task (promesa)
Console.WriteLine("Leyendo...");
Task<string> tarea = LeerArchivoGrandeAsync();
// el programa puede seguir haciendo otras cosas...
Console.WriteLine("Mientras tanto, sigo trabajando");
string datos = await tarea;   // aquí sí esperamos el resultado

¿Qué es una Task?

Una Task representa una operación en curso. Es la "promesa" de un resultado futuro:

  • Task: operación sin resultado (equivale a void).
  • Task<T>: operación que producirá un valor de tipo T.

async y await

async Task<string> ObtenerDatosAsync()
{
    await Task.Delay(1000);       // "espera" sin bloquear el hilo
    return "datos listos";
}
  • async: marca el método como asíncrono.
  • await: pausa el método hasta que la tarea termina, sin bloquear el hilo (devuelve el control al llamador).
¿Qué hace await de verdad?

No es un Thread.Sleep. await libera el hilo para que haga otra cosa mientras espera la operación asíncrona, y retoma cuando esta termina. Por eso tu UI o tu servidor no se congelan.

Llamar a un método async

async Task Main()
{
    string resultado = await ObtenerDatosAsync();
    Console.WriteLine(resultado);
}

En top-level statements (Program.cs) puedes usar await directamente.

Task.Run: ejecutar en otro hilo

Para trabajo pesado de CPU, mueve la operación a un hilo del pool:

Task<int> tarea = Task.Run(() =>
{
    // trabajo intensivo de CPU
    int suma = 0;
    for (int i = 0; i < 1_000_000; i++) suma += i;
    return suma;
});

int resultado = await tarea;

Task.WhenAll y Task.WhenAny

// WhenAll: espera a TODAS las tareas
Task<string> t1 = Descargar("https://api1.com");
Task<string> t2 = Descargar("https://api2.com");

string[] resultados = await Task.WhenAll(t1, t2);

// WhenAny: espera a la PRIMERA que termine (carrera)
Task<string> ganadora = await Task.WhenAny(t1, t2);
Console.WriteLine(await ganadora);

Cancellation con CancellationToken

using System.Threading;

async Task TrabajarAsync(CancellationToken token)
{
    for (int i = 0; i < 100; i++)
    {
        token.ThrowIfCancellationRequested();   // lanza si se cancela
        await Task.Delay(100);
    }
}

var cts = new CancellationTokenSource();
var tarea = TrabajarAsync(cts.Token);

cts.CancelAfter(500);   // cancela tras 500 ms

Excepciones en async

try
{
    await ObtenerDatosAsync();   // las excepciones se capturan con await
}
catch (Exception ex)
{
    Console.WriteLine($"Error: {ex.Message}");
}

Con await, las excepciones se propagan de forma natural y se capturan con try/catch normal. Si no haces await, quedan guardadas en la Task.

3 · Ejemplo mínimo

async Task<string> ObtenerDatosAsync()
{
    await Task.Delay(1000);   // simula una operación lenta
    return "datos";
}

string resultado = await ObtenerDatosAsync();
Console.WriteLine(resultado);

4 · Ejemplo real

Descargar varias URLs en paralelo y esperar a que todas terminen:

using System.Net.Http;

async Task DescargarTodasAsync(string[] urls)
{
    using var client = new HttpClient();

    // Lanza una tarea por URL
    var tareas = urls.Select(url => client.GetStringAsync(url));

    // Espera a todas
    string[] resultados = await Task.WhenAll(tareas);

    for (int i = 0; i < urls.Length; i++)
        Console.WriteLine($"{urls[i]} → {resultados[i].Length} caracteres");
}

await DescargarTodasAsync(new[]
{
    "https://example.com",
    "https://httpbin.org/get"
});

6 · Errores habituales

Error 1: olvidar await (fire-and-forget sin control)

// Incorrecto: la excepción se pierde y no esperas el resultado
// ObtenerDatosAsync();

// Correcto: espera con await (dentro de un método async)
var resultado = await ObtenerDatosAsync();

Error 2: usar .Result en vez de await

// Incorrecto: bloquea y arriesga deadlock
// var r = ObtenerDatosAsync().Result;

// Correcto
var r = await ObtenerDatosAsync();

Error 3: async void

// async void solo es válido para manejadores de eventos.
// Para métodos normales, usa async Task. Las excepciones en async void
// no se pueden capturar con try/catch.

9 · Resumen

  • Task = operación en curso; Task<T> con resultado.
  • async marca el método; await espera sin bloquear.
  • Task.Run (CPU), WhenAll/WhenAny (varias tareas).
  • CancellationToken para cancelar; excepciones se capturan con try/catch.

10 · Preguntas frecuentes

¿await bloquea el hilo?

No. await libera el hilo para que haga otras tareas mientras la operación asíncrona está en curso, y retoma el método cuando termina.

¿Cuándo uso Task.Run?

Para trabajo intensivo de CPU que no quieres que bloquee el hilo actual. Para I/O (archivos, red, BD), usa APIs asíncronas nativas, no Task.Run.

¿Qué es un deadlock?

Cuando dos o más operaciones se bloquean esperándose mutuamente. En async, suele ocurrir por mezclar código síncrono (.Result/.Wait()) con asíncrono.
