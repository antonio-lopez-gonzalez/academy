HttpClientFactory en profundidad

Módulo 4 · C# Avanzado30 min

1 · Introducción

En esta lección aprenderemos a usar IHttpClientFactory correctamente. Veremos por qué crear new HttpClient() a mano es peligroso, cómo gestionar sockets y DNS, cómo configurar clientes con nombre y tipados, y cómo encadenar handlers para logging, resiliencia y auth.

¿Por qué existe? Porque HttpClient esconde un HttpClientHandler, que a su vez esconde un SocketsHttpHandler con un pool de conexiones. Si creas un HttpClient por cada request y lo descartas, agotas el pool de sockets del sistema operativo y causas SocketException tras miles de requests. Si reutilizas un HttpClient estático, no se refrescan los DNS. La factory resuelve ambos problemas.

¿Cuándo se utiliza? En cualquier aplicación .NET que haga llamadas HTTP salientes: APIs, workers, microservicios, clientes de terceros.

Errores típicos: using var client = new HttpClient(), no configurar PooledConnectionLifetime, no usar handlers de resiliencia, descartar el cliente tras cada uso.

2 · Teoría

2.1. El problema del socket exhaustion

Cada HttpClient mantiene conexiones TCP abiertas durante un tiempo. Cuando instancias y descartas un cliente por cada request, el sistema operativo acumula conexiones en estado TIME_WAIT. Tras un volumen alto, no puedes abrir más sockets. El error típico es "Only one usage of each socket address is normally permitted".

2.2. El problema del DNS stale

Si reutilizas un HttpClient estático, el SocketsHttpHandler subyacente no detecta cambios de DNS hasta que caduca la conexión. Si un microservicio cambia de IP tras un redeploy, tu cliente seguirá apuntando a la IP antigua. La solución es limitar la vida útil del pool de conexiones.

2.3. IHttpClientFactory

La factory crea y recicla handlers de forma controlada. Mantiene un pool de handlers (HttpMessageHandler) y rota cada uno cuando expira su vida útil. El HttpClient que te devuelve es de corta duración, pero el handler subyacente es reutilizado y renovado. Así evitas tanto el agotamiento de sockets como el DNS stale.

2.5. Named clients, typed clients y factory directa

Named clients: se registran con un nombre y se resuelven con CreateClient("name"). Útiles cuando tienes varias APIs externas.

Typed clients: encapsulan la configuración en una clase propia inyectada en tu servicio. Son más testeables y type-safe.

Factory directa: inyectas IHttpClientFactory y creas clientes ad-hoc. Es flexible pero menos declarativo.

2.6. DelegatingHandler

Un DelegatingHandler envuelve otro handler y puede inspeccionar o modificar la request/response. Es el mecanismo para añadir logging, auth, resiliencia, headers, etc.

3 · Ejemplo mínimo

Creamos un API web que consume un servicio externo usando IHttpClientFactory.

dotnet new webapi -n HttpClientFactoryDemo -o ejemplos/m04-csharp-avanzado/httpclient-factory-demo/src/HttpClientFactoryDemo

Program.cs:

// Configuración de HttpClientFactory con un cliente nombrado
var builder = WebApplication.CreateBuilder(args);

builder.Services.AddHttpClient("jsonplaceholder", client =>
{
    client.BaseAddress = new Uri("https://jsonplaceholder.typicode.com/");
    client.DefaultRequestHeaders.Add("Accept", "application/json");
    client.Timeout = TimeSpan.FromSeconds(10);
})
    .SetHandlerLifetime(TimeSpan.FromMinutes(5));

builder.Services.AddControllers();

var app = builder.Build();
app.MapControllers();
app.Run();

Controlador:

[ApiController]
[Route("api/[controller]")]
public class UsersController : ControllerBase
{
    private readonly IHttpClientFactory _factory;

    public UsersController(IHttpClientFactory factory)
    {
        _factory = factory;
    }

    [HttpGet]
    public async Task<IActionResult> GetUsers()
    {
        // Creamos un cliente corto; el handler se recicla internamente
        var client = _factory.CreateClient("jsonplaceholder");
        var response = await client.GetAsync("users");
        response.EnsureSuccessStatusCode();
        var content = await response.Content.ReadAsStringAsync();
        return Content(content, "application/json");
    }
}

Explicación línea por línea:

  • AddHttpClient("jsonplaceholder", ...): registra un cliente con nombre y configuración.
  • SetHandlerLifetime: define cada cuánto tiempo se rota el handler subyacente para refrescar DNS.
  • _factory.CreateClient("jsonplaceholder"): crea un HttpClient con la configuración registrada. No uses using para descartarlo.
  • EnsureSuccessStatusCode: lanza si la respuesta no es 2xx.

4 · Ejemplo real

Typed client + delegating handler para añadir un header de correlación y reintentos con Polly.

public class CorrelationIdHandler : DelegatingHandler
{
    private readonly IHttpContextAccessor _httpContextAccessor;
    private readonly ILogger<CorrelationIdHandler> _logger;

    public CorrelationIdHandler(IHttpContextAccessor httpContextAccessor, ILogger<CorrelationIdHandler> logger)
    {
        _httpContextAccessor = httpContextAccessor;
        _logger = logger;
    }

    protected override async Task<HttpResponseMessage> SendAsync(HttpRequestMessage request, CancellationToken cancellationToken)
    {
        var correlationId = _httpContextAccessor.HttpContext?.Request.Headers["X-Correlation-Id"].FirstOrDefault()
                            ?? Guid.NewGuid().ToString();

        request.Headers.TryAddWithoutValidation("X-Correlation-Id", correlationId);
        _logger.LogInformation("Enviando request {Method} {Uri} con correlation {CorrelationId}",
            request.Method, request.RequestUri, correlationId);

        var response = await base.SendAsync(request, cancellationToken);
        return response;
    }
}

Typed client:

public interface IJsonPlaceholderClient
{
    Task<List<UserDto>> GetUsersAsync(CancellationToken cancellationToken = default);
}

public class JsonPlaceholderClient : IJsonPlaceholderClient
{
    private readonly HttpClient _client;

    public JsonPlaceholderClient(HttpClient client)
    {
        _client = client;
    }

    public async Task<List<UserDto>> GetUsersAsync(CancellationToken cancellationToken = default)
    {
        var response = await _client.GetFromJsonAsync<List<UserDto>>("users", cancellationToken);
        return response ?? new List<UserDto>();
    }
}

public record UserDto(int Id, string Name, string Email);

Registro en DI:

builder.Services.AddHttpContextAccessor();

builder.Services.AddTransient<CorrelationIdHandler>();

builder.Services.AddHttpClient<IJsonPlaceholderClient, JsonPlaceholderClient>(client =>
{
    client.BaseAddress = new Uri("https://jsonplaceholder.typicode.com/");
    client.DefaultRequestHeaders.Add("Accept", "application/json");
})
.AddHttpMessageHandler<CorrelationIdHandler>()
.AddPolicyHandler(GetRetryPolicy())
.SetHandlerLifetime(TimeSpan.FromMinutes(5));

static IAsyncPolicy<HttpResponseMessage> GetRetryPolicy()
{
    return HttpPolicyExtensions
        .HandleTransientHttpError()
        .WaitAndRetryAsync(3, retryAttempt =>
            TimeSpan.FromSeconds(Math.Pow(2, retryAttempt)));
}

Con este patrón el código de negocio no sabe nada de HTTP ni resiliencia; todo se configura declarativamente en DI.

5 · Buenas prácticas

  • Nunca uses new HttpClient() en código de producción.
  • Configura SetHandlerLifetime para refrescar DNS (2-5 minutos es habitual).
  • Prefiere typed clients para encapsular APIs externas.
  • Usa DelegatingHandler para cross-cutting concerns: headers, logging, auth, resiliencia.
  • Configura timeouts razonables; nunca dejes el valor por defecto de 100 segundos.
  • Para resiliencia, usa PolicyHttpMessageHandler de Polly.
  • Evita using var client = factory.CreateClient(...); el factory gestiona la vida útil.

6 · Errores habituales

6.1. HttpClient estático

// ❌ MAL: no refresca DNS y puede agotar conexiones si cambia la configuración
public static readonly HttpClient Client = new HttpClient();

Correcto:

// ✅ BIEN: la factory gestiona ciclos de vida y pooling
public class MyService
{
    private readonly IHttpClientFactory _factory;
    public MyService(IHttpClientFactory factory) => _factory = factory;
}

6.2. Descartar el cliente con using

// ❌ MAL: descartar el cliente no libera el handler correctamente
using var client = _factory.CreateClient("api");
var response = await client.GetAsync("...");

Correcto:

// ✅ BIEN: el cliente es de corta vida pero no necesita dispose explícito
var client = _factory.CreateClient("api");
var response = await client.GetAsync("...");

6.3. No configurar timeout ni lifetime

// ❌ MAL: configuración por defecto puede causar requests colgados
builder.Services.AddHttpClient("api", client =>
{
    client.BaseAddress = new Uri("https://api.example.com");
});

Correcto:

// ✅ BIEN: timeout y handler lifetime configurados
builder.Services.AddHttpClient("api", client =>
{
    client.BaseAddress = new Uri("https://api.example.com");
    client.Timeout = TimeSpan.FromSeconds(10);
})
.SetHandlerLifetime(TimeSpan.FromMinutes(5));

7 · Ejercicio guiado

Crea un DelegatingHandler que añada automáticamente un header de autorización Bearer obtenido de un ITokenProvider inyectado. Regístralo en un typed client.

Solución:

public class AuthHandler : DelegatingHandler
{
    private readonly ITokenProvider _tokenProvider;

    public AuthHandler(ITokenProvider tokenProvider) => _tokenProvider = tokenProvider;

    protected override async Task<HttpResponseMessage> SendAsync(HttpRequestMessage request, CancellationToken cancellationToken)
    {
        var token = await _tokenProvider.GetTokenAsync(cancellationToken);
        request.Headers.Authorization = new AuthenticationHeaderValue("Bearer", token);
        return await base.SendAsync(request, cancellationToken);
    }
}

// Registro
builder.Services.AddTransient<AuthHandler>();
builder.Services.AddHttpClient<IApiClient, ApiClient>(client =>
{
    client.BaseAddress = new Uri("https://api.example.com");
})
.AddHttpMessageHandler<AuthHandler>();

9 · Resumen

  • IHttpClientFactory resuelve socket exhaustion y DNS stale.
  • Los clientes son de corta duración; los handlers se reciclan y renuevan.
  • Existen named clients, typed clients y factory directa.
  • Los typed clients encapsulan la API externa y mejoran la testabilidad.
  • Los DelegatingHandler añaden cross-cutting concerns de forma declarativa.
  • Polly se integra fácilmente con PolicyHttpMessageHandler.

10 · Preguntas frecuentes

¿Puedo usar HttpClient en un using dentro de un método?
Sí, pero si lo creas con new HttpClient() causarás problemas de sockets. Si lo creas con IHttpClientFactory, no es necesario ni recomendable usar using.
¿Cuánto debe durar SetHandlerLifetime?
Depende de tu entorno. Entre 2 y 5 minutos es habitual. Si tus endpoints cambian de IP frecuentemente, reduce el valor. Si las conexiones son estables y costosas de establecer, aumenta el valor.
¿Es HttpClient thread-safe?
Sí, HttpClient es thread-safe para enviar requests, pero no para modificar sus headers durante el uso. Si necesitas headers dinámicos, usa un handler.
¿Puedo usar HttpClientFactory en un BackgroundService?
Sí, inyecta IHttpClientFactory en el constructor del BackgroundService y crea clientes dentro del método de trabajo.
¿Qué paquete necesito para Polly?
Microsoft.Extensions.Http.Polly integra Polly con IHttpClientFactory.
